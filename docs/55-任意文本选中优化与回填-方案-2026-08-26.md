# 55 · 任意文本选中优化与回填 · 方案

- 日期：2026-08-26
- 状态：方案设计（未实现）
- 关联：`TextNode` / `PromptNode` / `FullscreenEditor` / `PromptInput` / `chatCompletions` / `nodePrefs`

---

## 一、需求背景

用户希望在画布上 **任意一段可编辑文本** 都能：

1. **选中**一段文字
2. 触发一个「优化」入口，弹出浮层
3. 在浮层 **左侧输入修改意见**（如"更口语化""缩短一半"）
4. 点击 **右侧发送按钮**，交由 AI 按修改意见优化选中的文本
5. **回填覆盖** 原选中段，其余文本保持不变

关键诉求：**任意一段文本**（不限于文本节点的 textarea），且 **模型复用文本节点选择的模型**。

---

## 二、可行性结论

**完全可以，且实现代价低。**

项目里几乎所有可编辑文本都使用 **原生 `<textarea>` / `<input>`**（`PromptInput`、`FullscreenEditor`、各节点 prompt 输入框、文本节点内容区）。它们原生自带选区能力：

- `selectionStart` / `selectionEnd`：选中文本的**精确字符范围**
- `setSelectionRange()`：把光标/选区定位回原位置

因此 **一套全局逻辑即可覆盖所有文本输入框**，无需针对每个节点单独实现。

---

## 三、方案对比

### 方案 A：全局事件监听（推荐）

在 `App.jsx` 顶层挂载一个全局 hook，统一捕获**当前聚焦的 textarea/input** 的选区。

```js
function getActiveSelection() {
  const el = document.activeElement
  if (el instanceof HTMLTextAreaElement || el instanceof HTMLInputElement) {
    const start = el.selectionStart
    const end = el.selectionEnd
    if (end > start) {
      return { el, start, end, text: el.value.slice(start, end) }
    }
  }
  return null
}
```

- **优点**：一套代码覆盖所有节点，组件层零改动，真正"任意文本"。
- **做法**：全局捕获选中 → 显示浮动「优化」按钮 → 打开优化浮层 → 回填时直接操作目标输入框并 `setSelectionRange` 定位。

### 方案 B：每个输入控件内嵌

在每个 textarea 上写 `onSelect` + 浮动按钮。

- **缺点**：需在每个节点重复挂载，不符合"可复用 + 任意文本"目标。

> **结论：采用方案 A（全局 hook）**。

## 四、架构设计

```

```

### 1. `useTextOptimize`（全局，App 挂载一次）

职责：
- 监听 `selectionchange` / `mouseup` / `keyup`，通过 `document.activeElement` 判断当前是否为 textarea/input
- 当有选中（`selectionEnd > selectionStart`）时，记录选区并显示浮动「优化」按钮
- 点击「优化」→ 弹出 `OptimizePromptPopup`
- 收到优化结果 → 回填覆盖原选区

返回值 / 事件：

```js
useTextOptimize({
  onSubmit: async (instruction, selectedText) => {
    // 复用 chatCompletions + resolveProviderModel，模型取自文本节点记忆（见第六节）
    const r = await chatCompletions({
      provider, model: modelId,
      messages: [
        { role: 'system', content: '你是一个文本优化助手。请严格按用户要求优化文本，仅返回优化后的结果，不要任何解释。' },
        { role: 'user', content: `用户要求：${instruction}\n\n待优化文本：${selectedText}` },
      ],
    })
    return r // { ok, content }
  },
  onApply: ({ el, start, end }, optimized) => {
    // 精确回填覆盖
    const next = el.value.slice(0, start) + optimized + el.value.slice(end)
    // 更新 DOM + 触发 React onChange（受控组件处理，见第七节）
  },
})
```

### 2. `OptimizePromptPopup`（浮层组件）

Props：

```js
OptimizePromptPopup({

  onClose,     // 关闭回调
  onSubmit,    // (修改意见) => Promise<{ok, content}>，AI 调用
```

## 五、回填覆盖原理（关键）

```js
// 记录选区时保存：{ el, start, end }
// 优化后：
const nextText = el.value.slice(0, start) + optimizedText + el.value.slice(end)
```

- 用 `start` / `end` 精确替换选中段，其余文本不动。
- 光标默认定位到新文本末尾（或可按需 `el.setSelectionRange(newEnd, newEnd)`）。

## 六、模型复用文本节点选择的模型

> 需求点：优化功能**复用文本节点选择的模型**。

### 现状机制

文本节点模型记忆来自 `nodePrefs.js`：

- 存储键：`yimao_node_prefs`（localStorage / KV）
- 结构：`{ textNode: { model: 'providerId::modelId' } }`
- `TextNode` 用 `useNodePrefs('textNode', { model: '' })` 读写
- 模型 value 格式：`providerId::modelId`（双冒号分隔，兼容 `modelId` 含 `/`）
- 解析：`resolveProviderModel(providers, selectedValue, primary)` → `{ provider, modelId }`

### 复用方案

全局优化 hook 不依赖具体节点（无"当前节点"概念），因此 **直接从文本节点记忆读取模型**：

```js
import { getNodePrefs } from './nodePrefs.js'

// 取文本节点上次选择的模型 value（providerId::modelId），无记忆则回退主供应商
const { model } = getNodePrefs('textNode', { model: '' })
const { provider, modelId } = resolveProviderModel(providers, model, primary)
```

- 用户在某文本节点选过模型后，全局优化自动沿用该模型，**无需单独配置**。
- 未选过时：回退主供应商模型（与 `TextNode` 默认 `gpt-4o-mini` / `resolveProviderModel` 回退逻辑一致）。

### 与 TextNode 选模型的一致性

- 若用户在浮层内不提供模型选择（推荐），则完全复用 `textNode` 记忆，做到"所见即所得"。
- 后续若需在浮层内手动换模型，可用 `setNodePrefs('textNode', { model })` 写回同一记忆，保持全局一致。

## 七、技术难点与解法

### 1. 受控组件回填

多数 textarea 是 **React 受控组件**（`value` 由 state 管理）。直接改 `el.value` 不会触发 React 更新。

**解法（二选一）：**

- **优先**：用 `nativeInputValueSetter` + 派发 `input` 事件，触发 React 的 `onChange`：
  ```js
  const setter = Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype, 'value').set
  setter.call(el, next)
  el.dispatchEvent(new Event('input', { bubbles: true }))
  ```
- **更稳（推荐）**：把优化结果通过回调交给宿主层，由节点已有的 `setTextPersist` / `setPromptPersist` 落盘，走既有防抖写回 `node.data` 链路。

### 2. 浮动按钮夺焦

点击浮动「优化」按钮时 textarea 会失焦（`activeElement` 改变）。**解法**：在记录选区时保存输入框引用（`getActiveSelection` 返回 `el`），而非依赖触发瞬间的 `activeElement`。

### 3. 触发检测范围

目前只处理 `<textarea>` / `<input>`。若未来出现 contentEditable（富文本），需改用 `window.getSelection().getRangeAt(0)`，本项目暂无，暂不支持。

## 九、交互流程

1. 用户在**任意文本输入框**（节点 prompt、全屏编辑器、文本内容区等）选中一段文字
2. 选区上方浮现 **浮动「优化」小按钮**
3. 点击 → 弹出 `OptimizePromptPopup`
4. 左侧输入修改意见，右侧点「优化」→ AI 处理
5. 回填覆盖原选中段，光标定位到新文本后
6. 新文本随节点防抖落盘机制持久化，刷新不丢
