## 0. 判定标准（来自 CLAUDE.md 决策铁律）

- 日志统一走 `logger`（`logger.info / warn / error`，见 `src/components/base/logger.js`）。
- 用户可见提示走 `Toast`（`src/components/base/ToastContainer.jsx`，业务用 `showToast` / `toastWarning`，见 `src/components/base/toastStore.js`）。
- 关键链路（网络请求、文件读写、生成、同步、存储、资源加载）出错时，必须至少做到以下之一：
  - (a) `logger.error/warn` 记可追溯日志；
  - (b) 弹 `toast` 提示用户；
  - (c) 向上 `throw`，由明确的上层处理（带日志或 toast）。
- **禁止**：
  - 关键路径上用空的 / 只 `return null` 的 `.catch(() => {})`、`.catch(() => null)` 静默吞错；
  - 用假的 / 占位 error 文案（假装成功、报错文案与实际错误无关）。

## 1. 审计方法

用 code-explorer 子代理全量扫描 `src/` 下所有 `.js/.jsx`（排除 director3d）：

1. 搜索静默吞错模式：`.catch(() => {})`、`.catch(() => null)`、`.catch(() => undefined)`、空 `catch (e) {}`、只 `console.log` 不处理的弱处理。
2. 对每个命中读取上下文（±20 行），区分「关键链路」与「非关键 best-effort（debug 埋点 / 可丢失统计 / 清理）」。
3. 对照 `toast` 正确用法，判定：✅已正确处理 / ⚠️静默吞错需补 / ❌虚假报错 / ➖非关键可忽略。
