## 二、注册表读写（normalize / load / save）

### `normalize_provider(item)`(1254) —— 清洗+校验+锁协议，返回标准结构
- id：`PROVIDER_ID_RE`(`^[a-zA-Z0-9_-]{2,40}$`) 校验，非法 400
- name：空白归一（`\s+`→单个空格），截 60 字
- base_url：rstrip `/`；非 http(s) 开头 400
- protocol：非法回退 `openai`
- image_request_mode：`normalize_image_request_mode`(1176) 非法回退 `openai`；`detect_image_request_mode`(4342) 按 base_url 嗅探（agnes→openai-json）
- 平台锁死：
  - `volcengine` id → protocol=volcengine，base 补 `ark.cn-beijing.volces.com/api/v3`，region/project 补默认
  - `jimeng` → protocol=jimeng，base 置空
  - `codex`/`gemini-cli` → base 置空
  - `runninghub` id → protocol=runninghub，base 补 `www.runninghub.cn`
- `locked_recommended_provider_rule`(1197)：按 id/name/base_url 域名匹配已知站（exellome→apimart+openai-video-proxy；fhl→openai+openai-responses），命中锁死 protocol+request_mode
- 模型清单：`model_list_from_values`(936) 去重
- 各专属字段走各自 normalize（见第十块）

### `load_api_providers()`(1313)
文件不存在 → 返回默认；存在 → 每项 normalize → `merge_default_api_providers` 合并；解析失败回退默认。

### `save_api_providers(providers)`(1326)
`GLOBAL_CONFIG_LOCK` 锁 + 写回 json（`ensure_ascii=False, indent=2`）。

## 七、异步轮询（wait_for_image_task）

### `wait_for_image_task(client, task_id, provider=None)`(6173)
- `is_apimart` 决定差异化超时/间隔：apimart 用 `APIMART_IMAGE_TASK_TIMEOUT/POLL_INTERVAL/INITIAL_POLL_DELAY`，否则普通
- 循环到 `deadline`：
  - `fetch_image_task_payload` 取状态
  - `image_task_status` 归一状态词
  - status 无值但 `extract_image` 能出图 → 直接返回（兼容非标准返回）
  - 命中 `IMAGE_TASK_SUCCESS_STATUSES` → 返回
  - 命中 `IMAGE_TASK_FAILED_STATUSES` → 502（带 fail reason）
  - 否则 sleep(interval)
- 超时 → 504（带最后 payload 摘要）

> **我们要复用**：现有 `apimart-gateway/TaskService.check_and_fire_task`(main.py:731) 已是同类轮询；把「取状态/归一状态/抽结果」抽象成 provider 可注入即可。

## 八、端点拼接（provider_endpoint_url）

### `provider_endpoint_url(provider, key, default_path)`(1221)
- 有 override（`image_generation_endpoint`/`image_edit_endpoint`）：
  - http(s) 开头 → 直接用
  - 否则拼到 base_url 的 scheme://netloc
- 无 override → **前缀吸收**：base 已以 `/api/v3`/`/v1beta`/`/v1`/`/v2` 结尾且 default_path 同前缀 → 去掉重复前缀（如 base 已含 `/v1`，则 `/v1/images/generations`→`{base}/images/generations`）
- 否则 `{base_url}{default_path}`

> 移植时必须带上前缀吸收，否则 base 已含 /v1 会拼出 404。

### 13.1 openai 兼容站 · 6 种请求分支（generate_ai_image 内 10528-10693）

按 `effective_image_request_mode(provider, model)` 分流，具体发什么 body：

| 分支 | 触发 | 请求构造 | 参考图 |
|---|---|---|---|
| **openai-video-proxy** | request_mode=openai-video-proxy | `POST {base}/videos`（把生图伪装成视频提交），body `{model,prompt,aspect_ratio}` | 本地图 multipart `files=images`，网络图放 `body.images[]` |
| **openai-responses** | request_mode=openai-responses | `POST {endpoint}/v1/responses`，body `{model, input:[{role:user,content:[{type:input_text},{type:input_image}]}], tools:[{type:image_generation,action:generate/edit,size,quality}], tool_choice:{type:image_generation}}` | `input_image.image_url` |
| **openai-json** | request_mode=openai-json（Agnes 等） | `POST /images/generations`，body `{model,prompt,size,extra_body:{response_format:url}}`，**绝不走 /images/edits** | `extra_body.image:[base64,≤1536px]` |
| **apimart** | is_apimart_provider | `POST /images/generations`，body `{model,prompt,n:1,size,resolution,official_fallback:false}` | `image_urls:[base64,≤1536px]` |
| **gpt-image-2 文生图** | is_gpt_image_2_model 且无参考图 | `POST /images/generations`，body `{model,prompt,size,quality}`；失败且 `images_api_unsupported` → 回退 `/images/edits` | — |
| **标准图生图/编辑** | 有 image_refs | `POST /images/edits` multipart，files `image`+`mask`；**失败回退**（非 GPT-2）`/images/generations`+`image:[base64]` JSON | multipart file |

**通用收尾**（10696-10739，所有分支统一）：
```
response.raise_for_status() → 失败抛 provider 名 + HTTP 码 + 响应片段
raw = response.json()
try: return extract_image(raw), raw                      # 同步直出
except HTTPException:
    task_id = extract_task_id(raw)                        # 异步：拿 task_id
    task_result = await wait_for_image_task(client, task_id, provider)   # 轮询
    return extract_image(task_result), task_result
```

**特例**：
- fhl 站响应含 `_worker_keepalive` → 明确报错"未完成的 keepalive"，不当 JSON 解析失败（10710）
- GPT-Image-2 编辑失败**不自动重试**（避免重复扣费，10665-10669）
- openai-responses 无图 → `responses_output_text_image` 兜底，再不行友好报错（10722-10730）

## 十六、真出图补充机制（素材吞入 / 鉴权头 / 状态归一 / 模型分类）

### 16.1 素材吞入 `reference_to_data_url(ref, max_size=None)`(7528)
把本地参考图转成上游可用的 data URL：
```
path = output_file_from_url(ref.url)          # 本地文件
若无本地路径 → 原样返回 ref.url（外网 URL 直接透传）
若 max_size（如 1536）：
  PIL 打开，最长边 > max_size → thumbnail(LANCZOS)
  非 RGB/RGBA → convert RGB
  RGBA → PNG，否则 → JPEG(quality=88)
  返回 data:{mime};base64,{encoded}
否则：直接读文件 base64 → data:{content_type_for_path};base64,{encoded}
```
> 图生图参考图都走这个（`reference_to_data_url(ref, max_size=1536)`）。apimart 还要先 `upload_image_for_apimart` 传成公网 URL。

### 16.2 鉴权头 `api_headers(json_body=True, provider=None, model="")`(3584)
```

effective_protocol=="gemini" → {"Accept":"application/json","x-goog-api-key":key}
否则 → {"Accept":"application/json","Authorization":"Bearer {key}"}
json_body → 加 Content-Type: application/json
```
> 方舟用 `runninghub_app_headers` 式的专属头（`Host: www.runninghub.cn` + Bearer）。

### 16.3 异步 task_id 抽取 `extract_task_id(data)`(3940)

### 16.6 模型拉取分类 `fetch_models_from_upstream`(13027) + `classify_upstream_model`(12719)

## 十八、补充机制（二）— 连接探测 / 异步探测 / 产物落盘 / chat 分派

### 18.1 `test-connection` 完整链路（`POST /api/providers/test-connection`，12768）

`protocol_from_payload`(12548) 推断协议：
```
provider_id==volcengine/runninghub/jimeng → 直接定协议
base_url 含 runninghub.cn/ai → runninghub
否则用 payload.protocol（非法回退 openai）
```
按协议分派：
- **codex/gemini-cli/jimeng** → 直接返回本机 CLI 状态（不 HTTP）
- **runninghub** → `runninghub_models_payload`（工作流注册表）
- **其余**：
  ```
  url = upstream_models_url(base_url, protocol)
      # gemini→{base}/v1beta/models 方舟→{base}/api/v3/models openai→{base}/v1/models
  GET url (Bearer/x-goog-api-key)
    301/302/307/308 → 400"请填 API Base URL，勿填网页登录地址"
    HTML → 400"返回网页 HTML"
    ≥400 → 方舟→probe_volcengine_auto_detect 自愈；openai→probe_volcengine_auto_detect（嗅到方舟自动切协议）
    <300 → parse_upstream_models 分类 + apply_agnes_model_defaults + apply_locked_recommended_model_rules
  httpx.HTTPError → 方舟再试 probe 自愈；否则 ok:false
  ```
  返回：`{ok, status, model_count, image_models, chat_models, video_models, all, image_request_mode}`。

### 18.2 `probe-async`（`POST /api/providers/probe-async`，12881）— 异步端点嗅探

用**假 task_id** 请求 `GET {base}/v1/tasks/healthcheck_probe_do_not_submit`：
```
400 + 错误含 "invalid task id" → 端点存在且 Key 有效（apimart 异步协议确认）
401/403 → Key 无效
404 → 平台不支持 /v1/tasks/（非 apimart）
方舟 → 先 probe_volcengine_task_endpoint，再 probe_openai_compat_bearer_endpoint
否则 fallback：探 /v1/models → 不行探 /v1/chat/completions（可达判 OpenAI 兼容）→ 再不行 probe_volcengine_auto_detect
```

### 18.3 `probe_volcengine_auto_detect`(12698) — 双路自愈

```
probe_volcengine_task_endpoint(方舟 /api/v3 任务端点) → 可达判"方舟/Ark 任务协议"
否则 probe_openai_compat_bearer_endpoint(/v1/chat/completions 空 messages) → 可达判"Bearer 兼容透传"
否则 → 两路都不通，报详细 raw
```
配套端点：
- `upstream_models_url`(12580)：按协议拼 models 端点
- `probe_volcengine_task_endpoint`(12618)：探 `{base}/api/v3/contents/generations/tasks/healthcheck_probe_do_not_submit`
- `probe_openai_compat_bearer_endpoint`(12643)：POST `{root}/v1/chat/completions` 空 messages
- `probe_openai_models_endpoint`(12665)：GET `/v1/models`，含 301/HTML/分类

> **这是"接国内聚合站"能否成功的命门**：很多不暴露 `/v1/models`，靠这段自愈嗅到方舟或 OpenAI 兼容，否则误判不可用。

### 18.4 产物落盘（不丢图）

- `output_url_for(filename, category)`(6206)：本地文件 → 画布可用 `/assets/{rel}` 或 `/api/storage-files/{kind}/{rel}`。
- `save_remote_video_to_output(url, prefix, category)`(8839)：下载远程视频落盘：
  ```
  已是 /output/ 或 /assets/ → 直接返回
  非 http(s) → 原样返回
  下载 → 校验 content-type 非 html/json → 按 ext/content-type 定扩展名（mp4/webm/mov/mkv/flv）
  落盘 → output_url_for 返回画布路径
  失败 → 删临时文件，降级返回原 url（绝不抛 500 阻断）
  ```
  > 对应我们 localTool 的 `saveRemoteUrl`（files.ts，`[download]` 日志 + 降级策略）。这块我们的已具备，可直接复用/对齐。

### 18.5 chat 能力多 provider 分派（`resolve_chat_provider`，3522）

```
provider==modelscope → 专用 base/key/model
否则 get_api_provider(provider)：
  codex/gemini-cli → 400"用本机登录态"
  protocol=gemini → base 补 /v1beta
  protocol=volcengine → base 补 /api/v3
  protocol=runninghub → base=RUNNINGHUB_LLM_BASE_URL
  否则 base 补 /v1
  hdrs = api_headers(provider, model)   # 鉴权头
```
> chat 不只有 openai 一个通道：gemini/volcengine/runninghub 各有 base 拼接 + 专属头。多 provider 的聊天也要按 `effective_protocol` 分派。

### 18.6 网络错误全链路日志（`log_net_error`，3553）
