## 分步执行（每步细化，做完一步、验证、你审核，再走下一步）

### 第 1 步 · 抄 provider 注册表到网关（`providers.py`）
**目标**：网关有 provider 数据结构与读写，默认 seed 我们 9004。
- 新建 `apimart-gateway/providers.py`，**照抄** Infinite-Canvas `main.py` 这些函数：
  - `SUPPORTED_PROVIDER_PROTOCOLS`（317）/ `SUPPORTED_IMAGE_REQUEST_MODES`（318）
  - `PROVIDER_ID_RE`（id 校验）
  - `normalize_provider(item)`（1254）：清洗+校验+锁协议（volcengine/jimeng/runninghub/codex/gemini-cli 分支照抄）
  - `normalize_image_request_mode` / `detect_image_request_mode` / `normalize_endpoint_override` / `model_list_from_values` / `normalize_model_name_map` / `normalize_model_protocols` / `normalize_ms_loras` / `normalize_runninghub_entries`
  - `default_api_providers()` / `merge_default_api_providers`（默认注册表，**改成 seed 我们 9004 Lovart**）
  - `load_api_providers()`（1313）/ `save_api_providers()`（1326）
  - `public_provider()`（1332，key 脱敏）/ `public_api_providers()`（1367）
  - `get_primary_provider_id()`（1370）/ `get_api_provider()`（1381）/ `get_api_provider_exact()`（1394）
  - `effective_protocol()`（4316，单模型覆盖）
  - `locked_recommended_provider_rule`（已知站锁协议）
- 新建 `apimart-gateway/providers.json`，初始只含 **1 条 = 我们 9004**：
  ```json
  [{"id":"lovart","name":"Lovart(自托管)","base_url":"http://127.0.0.1:9004",
    "protocol":"apimart","image_request_mode":"openai","enabled":true,"primary":true,
    "image_models":["gpt-image-2-low","nano-bn-pro"],"video_models":["seedance-2.0-fast"],
    "chat_models":["lovart-chat"]}]
  ```
- **改动点**：把 Infinite-Canvas 默认 seed（modelscope/runninghub/volcengine）换成我们的 9004；`API_PROVIDERS_FILE` 指向 `apimart-gateway/providers.json`；`DATA_DIR` 指向网关自身目录。
- **验证**：`python -c "from providers import load_api_providers; print(load_api_providers())"` 能读到 9004 那条，且字段完整。

### 第 2 步 · 抄管理 API 到网关（`/v1/providers*`）
**目标**：前端能通过网关存取供应商。
- `main.py` 照抄 Infinite-Canvas 路由（改前缀 `/api`→`/v1`）：
  - `GET /v1/providers`（12457）→ 返回 `public_api_providers()`（key 脱敏）
  - `PUT /v1/providers`（12461）→ 整表保存 + primary 唯一化 + 写 key 到 env + `reload_env_globals()` 热更新
  - `POST /v1/providers/test-connection`（12768）→ 探测连通 + 嗅探协议 + 返回分类模型
  - `GET /v1/providers/{id}/fetch-models`（13164）→ 拉上游模型按关键词分类 image/chat/video
- **鉴权沿用**：这几个接口也走现有 `Bearer user_key`（`get_lovart_client`）或加白名单，避免暴露给未授权。
- **验证**：`curl GET 127.0.0.1:9004/v1/providers` 返回含 9004 那条的脱敏列表；`curl PUT` 能存第二条。

### 第 3 步 · 抄协议分派骨架（`generate_ai_image`），先只接 Lovart
**目标**：网关所有生成入口按 `provider_id` 分派；Lovart 零回归。
- `main.py` 照抄 Infinite-Canvas `generate_ai_image`（10482）的分派结构：
  - 读请求 `provider_id` → `get_api_provider(provider_id)` → 按 `protocol` 分流
  - 先只实现 `apimart`/`lovart` 分支 = 现有 `LovartClient`（`lovart_client.py`）逻辑，**原样搬进**，保证零回归
  - 其余协议（openai/volcengine/runninghub/gemini/CLI）先留 stub，抛"尚未接入"或由前端禁用
- 现有 `/v1/images|videos|chat` 路由改为调用分派器；`/api/proxy`（localTool）透传时把 `provider_id` 带上。
- **验证**：老功能照常出图；`/v1/images?provider_id=lovart` 正常，`provider_id=openai` 返回"未接入"。

### 第 4 步 · 抄第一个非 Lovart 协议 client（openai 兼容站）
**目标**：网关能切 Lovart 和一个 OpenAI 兼容站都出图。
- 新建 `apimart-gateway/openai_client.py`，照抄 Infinite-Canvas `generate_ai_image` 里 openai 分支 + `extract_image`（3882）+ `wait_for_image_task`（6173）：
  - 4 种 `image_request_mode`：openai / openai-json / openai-video-proxy / openai-responses
  - 同步直接取 `data[0].url`；异步拿 `task_id` → 轮询
  - `extract_image` 兼容多格式（`data[].url`/`b64_json`/`result.images`）
- 分派器加 `openai` → `OpenAIProvider`。
- **验证**：注册表加一条 openai 兼容站（填 base_url+key），curl 实测出图。

### 第 5 步 · localTool 加 `/api/providers` 透传
**目标**：前端通过 localTool 拿/存供应商。
- `localTool/src/routes/` 新建 `providers.ts`，把 `GET/PUT /api/providers`、`POST /api/providers/test-connection`、`GET /api/providers/:id/fetch-models` 转发到网关 `/v1/providers*`（复用 `system.ts` 的 fetch 透传模式 + 剥信封）。
