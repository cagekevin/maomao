# 多供应商接入 · 执行计划 v2（TS 重写 IC 能力）

> **核心思路（用户定调）**：Infinite-Canvas 的多供应商能力是 **Python** 写的，我们把它**翻译成你们已有的 TS 架构（localTool）**，不绕开、不另起炉灶。
> **链路**：前端 react-nodes → **localTool:18080(TS，多供应商注册表+分派+管理API)** → 按 provider 转发（Lovart→apimart-gateway:9004 PY 网关；openai 站→直连）。
> **PY 网关保持不动**：它继续只当 Lovart 的翻译层。

---

## 一、为什么放 localTool(TS)，而不是 PY 网关

- **localTool 是画布请求唯一入口**（index.ts 的 `/api/proxy`，catch-all 兜底），天经地义做分派。
- 它已是 **TS**，IC 的能力翻译成 TS 正好落在 localTool，符合"把 PY 改成 TS"。
- PY 网关（apimart-gateway）只有 Lovart 一种能力，让它继续当"Lovart 翻译层"，多供应商逻辑放 localTool 上层，职责清晰。
- 前端画布 + localTool 同是前端生态（JS/TS），配置、转发、管理 API 一处搞定。

## 三、落地步骤（TS 重写 IC 能力）

### 阶段 0 · 先把原型接上真实后端（前置，否则多供应商无从谈起）
1. `useGenerate` 假实现 → 改真实请求：`POST /api/proxy` → localTool → 9004 → Lovart，拿图显示。
2. `ModelSelect` 模型列表写死 → 改读 localTool 返回的模型（`/api/public/platform/models` 或新接口）。
3. 验证：原型点"生成"能真实出图。

### 阶段 1 · localTool(TS) 加多供应商地基（照抄 IC PY，翻译成 TS）
新建 `localTool/src/routes/providers.ts`，把 IC `providers.py` + `/api/providers` 管理 API 翻译成 TS：
- `SUPPORTED_PROTOCOLS` / `SUPPORTED_IMAGE_REQUEST_MODES`（8 协议 × 4 请求形态，照抄 IC 317/318）
- `normalizeProvider`（翻译 IC `normalize_provider`(1254)：校验+锁协议+归一）
- `loadProviders` / `saveProviders`（读写 `localTool/data/api_providers.json`，照抄 IC 1313/1326）
- `getApiProvider` / `getPrimaryProviderId`（照抄 IC 1381/1370）
- `effectiveProtocol`（照抄 IC 4316，单模型覆盖）
- 默认 seed = 我们 9004 Lovart（`protocol:"apimart"`，裁剪 IC 的 modelscope/runninghub/volcengine 死分支）

管理 API（index.ts 注册，TS 版）：
- `GET /api/providers` → 列表（key 脱敏 `has_key/key_preview`）
- `PUT /api/providers` → 整表保存（primary 唯一化，key 写 env）
- `POST /api/providers/test-connection` → 探测 + 嗅探协议（照抄 IC 12768）
- `GET /api/providers/:id/fetch-models` → 拉模型分类（照抄 IC 13164 + classify）

### 阶段 2 · localTool 分派器（翻译 IC generate_ai_image）
- `system.ts` 的 `/api/proxy` 加 `X-Provider-Id` 头解析：
  - `providerId == "lovart"` → 转发到 9004（现有 Lovart 链路，**零回归**）
  - `providerId` 是 openai 兼容站 → localTool 直接转发到该站 base_url（OpenAI 形态）
- 按 `effectiveProtocol` + `image_request_mode` 分派（翻译 IC 10528-10693 的 6 分支请求构造）
- 异步 task_id → 轮询（localTool 已有 `handleGatewayTask` 可复用/对齐 IC `wait_for_image_task`）

### 阶段 3 · 前端
- 全局"供应商"下拉（providerStore，localStorage + 后端拉取）
- `ProviderSettings.jsx`：照抄 IC `api-settings.js` 逻辑（RECOMMENDED_APIS/CLI_PROTOCOLS/applyCliProtocolDefaults），React 重写，原型配色
- 请求带 `X-Provider-Id`

### 阶段 4 · 逐个扩展
- volcengine / runninghub / gemini / CLI（各加一个 TS client，翻译 IC 对应 `generate_xxx`）

## 五、铁律
- 端口 18080/9004 不变，`proxyMode=local-tool` 入口不变。
- PY 网关（apimart-gateway）**零改动**，Lovart 零回归。
- 字段契约照 `02-provider字段契约.md`，协议名统一 `apimart`（区分站靠 `provider_id`）。
- localTool 改动跑 `cd localTool && npm test`。
