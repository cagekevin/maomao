## 2. 最终契约（以代码为准，doc 更新后参考实现）

### 2.1 三态模式 → 底层映射（AgentPanel.jsx `workMode`）

| 按钮 | workMode | inputMode | runMode | 真生成那一下 |
|---|---|---|---|---|
| 直接生图 | `image` | `image` | 沿用（默认 `auto`） | 受积分闸 * |
| 分步确认 | `semi` | `agent` | `semi` | 受积分闸 * |
| 完全自主 | `auto` | `agent` | `auto` | 受积分闸 * |

> *：积分闸是否生效只由全局 `creditSwitch` 决定，**与模式/runMode 完全无关**（见 2.2）。PRD §3.2「通用总闸一视同仁」即此义。

### 2.2 积分闸判定（唯一收敛点：`useCanvasAgentTools.js` executePlanTool）

```js
creditHit = getCreditSwitch()        // 全局总闸，与 runMode/模式正交
autoRun   = creditHit ? false : (args.auto_run !== false)
```

- 命中（开关开）→ 强制 `autoRun=false`：只建节点（免费，status=`ready`），置 per-conv `creditGate`，返回 `{ awaited:'credit' }`；由用户点确认 → `runExistingPlanTool` 补跑真正烧积分。
- 未命中（开关关）→ 按原 `autoRun` 放行，直接生成。
- 三路（agent 工具循环 / `sendImageMode` / `executePlanDirect`）都汇入此一处判定，不各写一遍。

### 2.3 关键回归防线（设计意图）

- `getCreditSwitch()`：读 `contentStore` 的 `agent_credit_switch`（backend `local`），默认 `true`（安全）；`undefined`/`null` → `true`。
- per-conv `creditGate = { pending, gens, map(stepId→nodeId) }`：随对话持久化，刷新/切会话可恢复；补跑成功清、失败保留待重试（置位/清除成对）。
- 补跑唯一入口 `runExistingPlanTool`（→ `execute_plan` 工具名 `run_existing_plan`）：必须 `creditGate.pending===true` 且 `map` 存在，否则拒绝（幂等防线，连点只一次）。

## 4. Bug A：残留 `semi` 短路积分闸（用户实测复现）

### 现象
用户从「分步确认」切回「直接生图」后，即使积分开关是**开**，直接生图仍自动生成（不该直出却直出）。

### 根因
原判定 `creditHit = runMode !== 'semi' && creditSwitch` 把「分步确认专属语义 semi」与「直接生图」用同一个 `runMode` 变量混为一谈。用户切过分步确认后 `runMode` 残留 `semi`（`setWorkMode('image')` 只改 inputMode，不改 runMode）→ `runMode !== 'semi'` 为 `false` → 积分闸被永久短路，开关开也直出。

### 修复（架构简化）
判定收敛为 `creditHit = getCreditSwitch()`，删掉 `runMode!=='semi'` 分支。心智模型回到最简单：**积分开关就是全局总闸，开了就拦、关了就放，与模式正交**。副作用：分步确认在开关开时也会再经一次积分确认（不再「不叠」，换来少一条规则、永不短路）——这是 PRD §3.2「一视同仁」的直接结果。

### 验证
- 新增 `tests/unit/creditGateModes.test.js`（7 用例）：三模式 × 开关两态 + 残留 semi 回归防线，全部通过。
- `canvasAgentTools.test.js` T4/T5 同步改口径（命中由 creditSwitch 决定，非 runMode）。

## 5. Bug B：直连单图参考图不挂节点（用户实测复现）

### 现象
直接生图传「一张图 + 文字」做图生图，参考图没有出现在生图节点的引入槽。

### 根因
`sendImageMode` 构造的单图 generation（[useAgentChat.js]）**缺 `use_attachments`**；而用户参考图是由 `execute_plan` 的参考图解析分支③（`useCanvasAgentTools.js`）处理的：当一步既无 `attachment_indices` 也无 `use_attachments:true` 时，被强置 `use_attachments:false` → 执行器 `createGenNode` 遇 `step.use_attachments===false` 分支**不写任何图**到 `data.images` → 参考图丢失。多图路径 `buildPerReferenceGenerations` 每步带了 `use_attachments:true` + `attachment_indices:[i]`，所以多图正常、单图丢图。

### 修复
直连单图 generation 在有参考图时补 `use_attachments:true`（整批共享，无 `attachment_indices`，execute_plan 按 `use_attachments=true` 全量挂 refPool），对齐多图路径语义；无参考图时不带（纯文生图，不误挂）。

### 验证
- `useAgentChat.hook.test.js` 新增 3 用例：直连带单图 → generation `use_attachments:true`；直连无图 → 不带；credit 命中处理。全部通过。

## 6. 现象三：「部分数据保存失败」排查结论（与本次改动无关）

### 现象
直连生图时弹 toast「部分数据保存失败，请检查浏览器存储空间/权限」，**每次直连都出现**。

### 排查结论
重启 dev 后消失 → 根因是**本地引擎服务（网关 9004 / localTool）未重启，KV 写不可用**，非代码 bug，与本次三态/积分闸改动无关（git diff 证实 `kvStore.js`/`storageAdapter.js`/`contracts.js` 存储逻辑未变，仅新增 credit 常量）。

### 触发链（已用测试固化：`tests/unit/persistFailedChain.test.js`）
```
画布变化（如直连生图建节点）→ projectStore.saveCanvasState
  → contentSetAsync(canvas-state-v1-{projectId})   // KV 键，走 /api/kv/set
  → kvSet 失败（本地引擎未起）
  → storageSet 降级 → sSet 写 localStorage 大字节副本   // kvStore.js:95-102
  → 若 localStorage 写也失败 → reportPersistFailure → persist:failed
  → App 节流 toast「部分数据保存失败」
```
- 仅 KV 失败 + 降级写成功 → 只降级，**不发** persist:failed（数据未丢，不该报「保存失败」）。
- KV 失败 + 降级 localStorage 写也失败 → 才发 persist:failed。

### 经验
改动存储/持久化前先确认本地引擎服务在跑；「KV 降级写本地」会随画布节点增长放大 localStorage 占用。若复现先重启 dev/引擎，再排查 localStorage 配额。
