## 二、状态模型（重点）

### 2.1 架构定性

剧本盒**没有独立存储层**。全部状态即 `node.data`，随画布快照 `canvas-state-v1-{projectId}` 一起序列化进 KV。
`contracts.js:446-448` 明文规定剧本盒**禁止独立持久化**。

这一设计的直接后果：**所有中间态（含 loading、abort 状态）都混在同一份 `node.data` 里，与业务数据同生共死。**

## 三、执行流逐阶段拆解

### 3.1 架构定性：阶段边界未分离

`scriptBoxEngine.js` 虽 1315 行，但**不是**「解析→计划→执行→落盘」的管线结构。实际形态：

- **解析**：无独立阶段。`parseJsonText`（L14/L232/L517/L615）在每次响应后**内联调用**；
  schema 归一化外置在 `scriptBoxSchema.js:88`，经 `useScriptBoxEngine.js:68` 的 `getData()` **每次读取时兜底**
- **计划/编排**：无显式计划态。三步靠 `data.step`（`ScriptBoxNode.jsx:110`）由 UI 手动切换，引擎不自动连跑
- **执行**：每个 `onXxx` 回调 = 一个生成端点
- **落盘**：解析/校验/写回/落盘**全在每个回调的 async 函数体内线性展开**（典型：L217-309）

> 判定：84KB 实为 **15 个并列回调**，而非分层管线。这是本模块最大的结构性可维护性问题。

## 四、并发与生命周期

### 4.1 abortMap 设计

| 项 | 值 | 证据 |
|---|---|---|
| 定义 | `scriptBoxEngine.js:75` `const abortMap = new Map()` | 每引擎实例一个 Map |
| 注册 | L161 `abortMap.set(key, ac)` | |
| 清除 | L173 `finally { abortMap.delete(key) }` | |
| 键设计 | 脚本级用固定键 `'script'`；分镜级用 `shot-${id}`；资产级用 `asset-${assetId}` | L161/L344/L848 |

### 4.2 【高风险】单键覆盖 → 重入丢失

`onGenerateScript`（L180）**没有任何 running 守卫**，且 abortMap 用固定键 `'script'`：

```js
// scriptBoxEngine.js:161
abortMap.set(key, ac)          // key = 'script'，无条件覆盖
// scriptBoxEngine.js:215
updateData({ genMask: true })  // 无 running 判断
```

**后果链**：
1. 用户快速双击「生成剧本」→ 第二次 `set('script', ac2)` 覆盖 `ac1`
2. `ac1` 泄漏，旧请求失去中止能力
3. 两个请求并发跑完，各自 L298 覆写 `shots`/`assets`
4. **后写覆盖先写，用户前次结果整组丢失**

对比：`onGenerateShotPrompts` 按 `shot-${id}` 分键，多镜并发安全；**仅脚本级是单键**。

### 4.3 【中风险】abortMap 注册了但 signal 未传

`onGenerateAssetImage` L341 注释自承：

```
// 不传 AbortSignal、无中止分支
```

但 L344 仍把 controller 注册进 `abortMap`。于是 `onStopScriptItem('asset', id)`（L708）会：
- abort 一个**底层请求并未使用**的 controller
- 清除 UI loading

**后果**：UI 显示"已停止"，**后台请求继续跑完并计费**（详见问题 #5）。

### 4.4 中断后不可恢复

- 所有进度**只存内存 `node.data`**，引擎无 checkpoint
- `onStopScriptItem` 全停（L693-703）后，已生成分镜虽在 `data.shots` 中
- 但**无"已完成到哪一镜"的记录**
- 重跑 `onGenerateScript` → L298 **整体覆写** `shots`/`assets`

**后果**：50 镜长剧本中断即全丢。

### 4.5 引擎实例与 React 生命周期绑定

| 项 | 值 | 证据 |
|---|---|---|
| 实例创建 | `useRef` 缓存，**只创建一次** | `useScriptBoxEngine.js:64-97` |
| 回调注入 | `useEffect` 依赖 `[nodeId]`，**仅挂载时注入一次** | `:102-106` |
| 闭包陈旧风险 | 引擎实例持有创建时刻的 `getData/updateData` 闭包 | `:64-97` |

> ⚠️ 引擎实例只创建一次，但 `useEffect` 依赖 `[nodeId]`——若 `nodeId` 变化（节点重建/画布切换项目），
> 回调会被重新注入，而引擎实例仍是旧的，其闭包内的 `getData` 可能指向旧节点。**需人工复核此路径。**

## 九、问题清单

### 🔴 高

#### #1 剧本生成无重入锁，重复触发导致结果整组丢失

- **位置**：`scriptBoxEngine.js:180`（`onGenerateScript`）、`:161`（`abortMap.set`）、`:215`（`updateData`）
- **证据**：

```js
// :161 —— key='script' 无条件覆盖，旧 ac 泄漏
abortMap.set(key, ac)
// :215 —— 无 running 守卫
updateData({ genMask: true })
// :298 —— 响应回来后整体覆写
updateData({ shots, assets })
```

- **影响**：并发/重复触发生成剧本 → 后写覆盖先写 → 用户前次 `shots`/`assets` **整组丢失**，且旧请求失控无法中止
- **建议**：① 加模块级 `runningScript` 布尔锁，进入前置位、`finally` 清除；② `abortMap` 脚本级改用递增 token 而非固定键；③ 覆写前做一次快照以便回滚

#### #2 中断后不可恢复，长剧本全量丢失

- **位置**：`scriptBoxEngine.js:298`（覆写）、`:693-703`（`onStopScriptItem` 全停）
- **证据**：进度只存内存 `node.data`，无 checkpoint；重跑 `onGenerateScript` 会 L298 整体覆写
- **影响**：50 镜长剧本中断即全丢，用户无续跑手段
- **建议**：增加 `scriptProgress`（已完成镜序号）字段并纳入 schema；重跑时询问"续跑/重来"

#### #3 阶段边界未分离，1315 行无分层

- **位置**：`scriptBoxEngine.js` 全文（典型 L217-309）
- **证据**：解析/校验/写回/落盘全在每个回调 async 函数体内线性展开；`parseJsonText` 在 L232/L517/L615 三处内联调用
- **影响**：无法对单阶段做独立测试与替换；任何改动都得读完整个回调；新增能力只能继续堆回调
- **建议**：抽出 `parsePhase` / `executePhase` / `persistPhase` 三层，回调只做编排

### 🟡 中

#### #4 abortMap 单键覆盖致首次中止能力丢失

- **位置**：`:161`（set）、`:173`（delete）、`:705-706`
- **证据**：同键二次进入时第二次 `set` 覆盖第一次，第一个 ac 再也无法被 `onStopScriptItem` 命中，且 `delete` 删的是第二个
- **影响**：快速双击同一分镜 → 第一次请求永久失控
- **建议**：改为 `Map<key, Set<AbortController>>` 或键内自增序号

#### #5 资产生图未传 signal，UI 停止但后台继续计费

- **位置**：`:341`（注释自承）、`:344`（注册 controller）、`:708`（停止）
- **证据**：L341 注释明说"不传 AbortSignal、无中止分支"，但 L344 仍注册，L708 会 abort 未使用的 controller 并清 loading
- **影响**：用户以为已停止，实际请求继续跑完并计费
- **建议**：把 signal 透传到底层请求，或在未支持中止时禁用停止按钮

#### #6 三大长任务不进任务中心

- **位置**：`reportGenerate` 仅 L334 出现
- **影响**：生成剧本/分镜提示词/合并视频在任务中心不可见、不可重试
- **建议**：三个回调补 `reportGenerate` + `saveResultToTasks`

#### #7 尾帧生图失败却提示"生成完毕"

- **位置**：`:1010-1029`（失败仅写 `errorMsg`）、`:1033`（无条件 success toast）
- **影响**：用户被误导，失败无感
- **建议**：L1033 改为按成功/失败计数分别 toast

### 🟢 低

#### #8 schema 未登记字段导致静默降级

- **位置**：`scriptBoxEngine.js:447-449` 读 `customGlobalConstraint`/`imageGlobalConstraint`/`videoGlobalConstraint`/`imageNegative`/`videoNegative`；`scriptBoxSchema.js:13-30` 未登记
- **影响**：新节点读到 `undefined`，靠 `String(undefined)` 兜底
- **建议**：补进 schema 默认值

#### #9 双套约束并存

- **位置**：`:447-449` 同时读 `globalConstraints[]` 与 `imageNegative`/`videoNegative`
- **影响**：语义重叠，UI 改一处不生效
- **建议**：收敛为一套

#### #10 静默 catch

- **位置**：`:695`、`:706` `catch { /* ignore */ }`
- **建议**：至少 `logger.debug` 记录

#### #11 节点类型/handle 名硬编码

- **位置**：`:842-843`（`promptNode`/`discountVideoNode`）、`:848`（`shot-${id}`）、`:333`（任务伪 ID）、`:966`（文件夹名）
- **建议**：登记进 `contracts.js` 的 `NODE_TYPES` 或新增常量表

#### #12 `shotCount` 默认值与引擎分支语义不一致

- **位置**：`scriptBoxSchema.js:21`（`'auto'`）vs `scriptBoxEngine.js:203`（`'custom'` 分支）
- **建议**：对齐语义并加测试锁定
