## 1. 代码现状核对表（施工以「现状」为基准，勿被 PRD 描述误导）

| PRD 表述 | 代码实际 | 影响 |
|---|---|---|
| `runModeRegistry.js`（新文件） | 文件**已存在但 0 字节占位** | 只填充内容，勿重复建 |
| workMode 值 `direct` | 现有 direct 模式取值是 **`image`**（`AgentPanel.jsx#L226` 推导式） | **必须加 `image→direct` 迁移收敛**（PRD `normalizeWorkMode` 只写了 `semi`，漏了这一条） |

| AgentPanel 三态选择器「待接注册表」 | **已有**三态选择器，但 workMode 是推导值 + 写 inputMode/runMode 两处（`AgentPanel.jsx#L226-232`） | 收口为单一存储值 + 注册表读写 |

> 结论：PRD 大方向正确且与现有「三态收敛」(08-27) 对齐；真正要新增的是——①注册表内容填充、②`agent_work_mode` 单值存储、③`image→direct` 迁移、④三态提示词注入、⑤`send` 单入口、⑥测试收敛。

## 2. 施工步骤（严格按序，勿跳步）

### Step 1 · M1 填充 `runModeRegistry.js`（先测，纯函数）
- **文件**：`agent/runtime/runModeRegistry.js`
- **改动**：
  - 常量：`RUN_MODE_IDS = { DIRECT:'direct', STEP_CONFIRM:'step-confirm', AUTO:'auto' }`；`DEFAULT_WORK_MODE='auto'`；`WORK_MODE_DEFS`（label + systemPrompt 片段，`direct.systemPrompt=null`）
  - 纯函数：`normalizeWorkMode(wm)` **收敛 `image→direct`、`semi→step-confirm`、非法→默认 `auto`**；`resolveWorkMode(raw)`；`getSystemPromptForWorkMode(wm)`（direct 返回 `''`）；`resolveInputMode(wm)`（direct→`'image'`，其余→`'agent'`）；`resolveConvRunMode(wm)`（direct→`'auto'`）；`isAgentWorkMode(wm)`（`wm!=='direct'`）
  - 存储访问注入：`getWorkMode/setWorkMode` 的 storage 读写做成**可注入**（默认读 `contracts` 的 `agent_work_mode` 键），便于单测
- **校验**：`npm run test:unit tests/unit/runModeRegistry.test.js`
- **风险/把关**：无依赖其它模块，纯函数先行；L1 迁移 case 在此固测

### Step 2 · M2 契约登记 `agent_work_mode`
- **文件**：`base/contracts.js` → `STORAGE_KEYS`
- **改动**：登记 `agent_work_mode:`（domain 全局 / backend `local` / note 注明「workMode 三态单一真源」，参照 `agent_input_mode` 条目风格）
- **校验**：`npm run check:keys`（唯一强制入口，禁裸字面量）
- **风险**：不登记会挂 check:keys → 必须先登记再用

### Step 3 · M3 读写/迁移层
- **文件**：`runModeRegistry.js`（`getWorkMode/setWorkMode` 实装）+ `base/contracts.js`
- **改动**：
  - `setWorkMode(wm)`：**原子写三处** = `agent_work_mode`(全局) + `agent_input_mode`(全局) + 当前会话 `conv.runMode`(per-conversation)
  - `getWorkMode()`：读 `agent_work_mode` → `normalizeWorkMode` 归一 → **唯一真源**
  - **首次启动迁移**：`agent_work_mode` 缺席时，用遗留 `inputMode/runMode` 推导初始值（`inputMode==='image'? 'direct' : runMode==='step-confirm'?'step-confirm':'auto'`）并回写，老用户无缝迁移
  - **L3 读一致性**：切会话时 `getWorkMode` 不依赖会话残留；会话切换处（`conversationState/AgentPanel`）显式 re-assert 全局 workMode，防 per-conversation 残留反向污染
- **校验**：`npm run test:unit tests/unit/conversationStore.test.js` + 手工三字段一致性
- **风险**：L3（作用域不一致）是本步核心，须固化「三字段一致」测试

### Step 4 · M4 状态层接入
- **文件**：`conversation/conversationState.js`、`conversation/conversationAiState.js`、`conversation/conversationStore.js`
- **改动**：
  - `conversationAiState.getCurrentRunMode()`：改为返回 `resolveConvRunMode(getWorkMode())`（保留导出，兼容）
  - `setCurrentRunMode(mode)`：改走 `setWorkMode(mode==='step-confirm'?'step-confirm':'auto')`（保留导出，兼容）
  - `conversationStore`：透出 `getWorkMode/setWorkMode`；`normalizeConversation` 保持现 runMode 收敛逻辑不动
- **校验**：`npm run test:unit`（回归红色检查）

### Step 5 · M5 提示词注入（显式传参）
- **文件**：`agent/runtime/agentCore.js`、`agent/runtime/useAgentChat.js`
- **改动**：
  - `buildRequestMessages(..., workMode = 'auto')`：加第 10 参；在 `CANVAS_AGENT_RULES` 注入后（现 `#L282` 一带）追加 `getSystemPromptForWorkMode(workMode)` 独立 system 段
    - `step-confirm`：调 `show_plan_for_confirm` 展示策划，**等用户确认**后再 `execute_plan`
    - `auto`：可用 `show_plan_for_confirm` 展示规划（**不卡确认**），然后直接 `execute_plan` 执行 —— **措辞必须同时写「可调 plan」与「不卡确认」两个动作（防 R2）**
  - `SKILL_EXECUTION_RULES`：阶段2「等你确认」改**按三态自适应** —— 三态=auto 时 Skill 阶段2 展示策划后直接进阶段3，不等待；三态=step-confirm 时才等待（R1/R6）
  - 唯一调用点 `useAgentChat.js#L511`（及 `#L527`）传 `workMode: getWorkMode()`
- **校验**：`npm run test:unit agentCore/agentLogic` 相关 + 四象限 prompt 快照
- **风险**：R1/R2 均在本步，四组合 case（Skill×auto / Skill×step-confirm / 非Skill×auto / 非Skill×step-confirm）必须逐个固化

### Step 6 · M6 工具层门禁
- **文件**：`agent/canvas/useCanvasAgentTools.js`
- **改动**：`presentPlanTool` 的 `needConfirm`（现 `#L828`）`getCurrentRunMode()==='step-confirm'` → **`getWorkMode()==='step-confirm'`**（换真源）。`execute_plan` 的 creditSwitch 逻辑**一律不动**（L5）
- **校验**：`npm run test:unit tests/unit/canvasAgentTools.test.js`（import `RUN_MODE_IDS`）
- **风险**：L5 正交红线，勿顺手改积分闸

### Step 7 · M7 发送单入口
- **文件**：`agent/runtime/useAgentChat.js`
- **改动**：
  - `send` 第一行读 `getWorkMode()`；`isAgentWorkMode` 为 false（direct）→ 走**内部 direct 分支**（原 `sendImageMode` 正文整体搬入），**bypass LLM 工具循环，直接 `execute_plan`（auto_run）**后 return
  - 从 hook 返回对象（现 `#L863`）**移除 `sendImageMode` 导出**；`executePlanDirect` 保留原样（prompts 通道）
- **校验**：直接分支确认「调一次 execute_plan、不触发 roundTrip」；`npm run test:unit tests/unit/useAgentChat.hook.test.js`
- **风险**：L2——防止把 direct 塞进 send 的 LLM 循环；R8——移除导出后全局搜 `sendImageMode` 引用杜绝残留

### Step 8 · M8 UI 接入
- **文件**：`panels/AgentPanel.jsx`
- **改动**：
  - workMode：由推导（`#L226`）改为 `getWorkMode()` 读取（订阅）
  - 本地 `setWorkMode`（`#L228-232`）改为调注册表 `setWorkMode`；删除 `'image'/'agent'/'step-confirm'/'auto'` 裸字面量，统一 `RUN_MODE_IDS`
  - 发送处（现 `#L382-394`）删掉 `inputMode==='image'? sendImageMode : send` 分支 → **一律 `send`**；`sendImageMode` 从解构（`#L177`）移除
- **校验**：`npm run test:unit tests/unit/AgentPanel.test.jsx`（固化「切换后三字段一致」）
- **风险**：R3（三字段同步）在本步 UI 收敛验证

### Step 9 · M9 测试收敛
- **改动**：
  - 新建 `tests/unit/runModeRegistry.test.js`：normalize（`image→direct`、`semi→step-confirm`、非法→auto）、resolve×3、prompt 片段
  - 改 `creditGateModes.test.js` / `canvasAgentTools.test.js` / `AgentPanel.test.jsx` / `useAgentChat.hook.test.js` 的裸字面量 → `import { RUN_MODE_IDS, DEFAULT_WORK_MODE }`（R5）
  - **补 case**：四组合 prompt；迁移（遗留 image/semi 首次初始化）；三字段一致性；send 单入口（direct 零 LLM roundTrip）
