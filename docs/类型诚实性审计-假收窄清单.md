# 类型诚实性审计 — 假收窄清单

> 目的：找出代码中「假装知道运行时形状」的假收窄（含 `as never` / `as unknown as X` / `as any` / 未定型却断言具体结构等），逐一登记，后续有空逐个修。
> 判定标准（诚实原则）：
>
> - 诚实收窄 = 类型真实反映运行时形状，或有运行时校验兜底（如 `child as THREE.Mesh` 后 `.isMesh`）。
>
> - 假收窄   = 类型声明比运行时「更确定」，且两端无真连接（消费方单方面声称、或构造参数被 `as never` 强塞、或变量标 `any` 让下游失类型）。
>   每轮发现追加在文末，不覆盖。

***

## 第一轮（2026-09-02）

### F1. `src/components/base/videoEngine.ts:324-329` — `videoSink: any` + `as never` 双重假收窄【高危】

```ts
const videoSink: any = new VideoSampleSink({
  codec: 'avc',
  bitrate: 5000000,
  sizeChangeBehavior: 'contain',
  transform: { width: outW, height: outH, fit: 'contain', frameRate: outFps }
} as never)
```

- 问题：① 变量声明 `any`，下游 `outputTarget.addVideoTrack(videoSink, ...)` 完全失类型；② 构造参数用 `as never` 强塞，绕过 mediabunny 官方 `VideoSampleSink(InputVideoTrack)` 签名校验。

- 注释自称「组件 API 错配」，但 `any` 连「错配」都没收住——它是最该修的一种（比 `ToolResult.data:any` 信封更糟，因为信封消费方本就只读、不 narrow；这里 videoSink 直接当对象传给 addVideoTrack）。

- 修复方向：定义本地 `VideoSampleSinkOptions` 接口匹配实际组件 API 形态，变量改 `VideoSampleSink`（或 `InstanceType`），去掉 `as never`；若确为库错配，在接口上注释理由而非 `any`。

### F19. `src/components/base/api/chatApi.ts:65` — `(messages[userIdx] || {}) as ChatMessage`【空对象假断言·高危】

```ts

```

- 问题：`messages` 为空时 `messages[userIdx]` 为 `undefined`，`|| {}` 得到**空对象** **`{}`**，却断言成完整 `ChatMessage`。`{}` 没有 `.content`/`.role` 等字段，断言是虚假的。

- 修复：`messages[userIdx]` 真实存在时才用；空时走独立分支（如直接 `return messages`），不要 `{} as ChatMessage`。
