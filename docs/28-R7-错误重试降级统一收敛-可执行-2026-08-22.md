# 28-R7 · 错误重试 / 降级统一收敛（可执行）

> 配套售后计划：`docs/27-API中转层售后收口计划-2026-08-22.md`（R7）。
> 来源：CONTEXT §六.C 已知待办「统一节点错误降级/重试收敛」。
> 定位：**独立任务，中风险，需谨慎**。本次 API 收口已统一了后端错误信封（`{error:{code,message}}`）+ 前端 `extractErrorDetail` + `classifyError`/`GEN_ERRORS`，本项是**把节点级 catch 的错误处理收敛到一个统一入口**。

---

## 1. 现状（代码审计修订版，2026-08-22 code-explorer 实测）

### 1.1 已有的统一基础（本次 API 收口产物）
- **后端**：`sendError`（localTool/src/utils/helpers.ts:22-25）——`code` 为**可选**参数，传 code 输出 `{error:{code,message}}`，不传则兼容旧形态 `{error: message}`（B0 冻结兼容）。**并非"统一信封"，是"支持 code 时信封、否则旧形态"**。
- **前端**（均核实真实存在）：
  - `extractErrorDetail(data)`（httpClient.js:51）
  - `classifyError(e)`（genErrors.js:22）
  - `GEN_ERRORS`（contracts.js:346）
  - `reportDegrade(args)`（degrade.js:23）

### 1.2 错误出口现状（⚠️ 与原文档重大出入）
- **已接入 `useNodeGeneration` 的 4 个节点（TextNode/PromptNode/DiscountVideoNode/TemplateNode）几乎无散落错误展示**：grep `setState({error` 返回 0；仅 TextNode/PromptNode 有 `.catch(e=>logger.warn)` 用于任务持久化/恢复容错（非错误展示）。它们的错误出口**已在 `useNodeGeneration.js` 内统一**（L141 `setError`+`taskCtl.fail`+`showToast`、L148-163 `catch` 统一处理 AbortError 与其余异常）。
- **真正散落错误的是未接入节点**：如 `VideoExtractNode.jsx:285` `setErrorMessage(err.message||'抽帧失败...')`（用 `errorMessage` state，非统一错误链）。`ImageNode/VideoProcessNode` 等亦无统一错误处理。
- 结论：**原文档"替换 4 个已接入节点的散落 catch"目标不成立**（它们已统一）；R7 应改为"把未接入/尚散落节点的错误态切到统一链"。

---

## 2. 目标（修订）

统一节点错误出口：以 `useNodeGeneration` 已有的统一错误出口为基底，把 **R2 收口后的节点**（及尚散落的未接入节点如 VideoExtractNode 的 `setErrorMessage`）的错误态收敛到 `classifyError` + `GEN_ERRORS` + `reportDegrade`，消灭真正散落的 `errorMessage` 类自写状态。

---

## 3. 方案（修订）

### 3.1 抽统一错误处理 hook（如 `useNodeErrorHandling`）
- 输入：`classifyError` 分类结果 + 降级策略
- 输出：统一的错误提示（toast/节点 error 状态）+ 可重试判定（`GEN_ERRORS.retryable`）
- 复用：`base/degrade.js` 的 `reportDegrade`（降级透明度红线）
- **不新造**：`useNodeGeneration` 内部已用 `setError`，hook 仅作为节点侧调用约定，避免与已有出口冲突

### 3.2 接入生成链路
`useNodeGeneration` 错误出口**已统一**，无需重写；仅在其内确保 `classifyError` 分类被记录（便于排查）。

### 3.3 收敛真正散落的对象（修订重点）
把 **未接入/尚散落节点** 的 `setErrorMessage`/`setError` 类自写状态，在 R2 把它们接入 `useNodeGeneration` 后，统一走 hook；VideoExtractNode 收口时一并改 `setErrorMessage` → 统一错误链。

---

## 4. 执行步骤（修订）

1. （可选）抽 `useNodeErrorHandling` hook（复用 classifyError/GEN_ERRORS/reportDegrade），仅作节点侧约定
2. 确认 `useNodeGeneration` 错误出口已用 `classifyError`（无则补一行记录）
3. **随 R2 收口顺序**：VideoExtractNode 接入时，把 `:285 setErrorMessage` 改为统一错误链；其余未接入节点在 R2 收口时同改
4. 跑测试 + 手动验证各类错误（网络/超时/业务/上游 4xx）提示与重试行为一致
