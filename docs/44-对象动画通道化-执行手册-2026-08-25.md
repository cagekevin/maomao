> 权威契约是《docs/43-对象动画通道化重构-PRD-2026-08-25.md》，**本手册是流程引导，PRD 是逐条要遵守的细则**——两者冲突时以 PRD 为准。

## 0. 一句话讲清这个任务在做什么

现在 `director3d` 的对象动画是「一份整快照关键帧数组」承载一切（位置/旋转/缩放/动作/骨骼全冻在一格里），这导致：想单独 K 一个属性不行、画线路径被迫把整份姿态也写进关键帧、求值端要「猜」左右帧是不是同一动作才能决定骨骼是插值还是硬切（一走一停的根源）。

**重构目标：按属性域拆分成独立「通道」，每条通道自己一条轨、单一数据源、可单独求值；再让路径只当「位置来源」，不再污染动作/骨骼；最后把所有写入口统一掉、并把旧数据无损迁移过来。** 全程不改现网能看到的播放行为。

实体上看，这是纯内部重构 + 数据迁移，不新增用户功能，用户感知不到变化（除了更顺滑、未来可单属性 K）。

## 1. 前置必读（按顺序，缺一不可）

1. 通读 PRD 全文一遍，只看懂「根因、模块分工、约束编号」即可，不必记细节——写码时逐条查。
2. 看懂现状的三个落点，一眼能翻到：
   - 整快照关键帧是怎么产生的 → project.js 的 `objectKeyframeFromObject`
   - 求值端怎么猜状态 → project.js 的 `objectAtFrame`（`sameState` / `motionEnabled` / `stateStartFrame`）
   - 路径 bake 怎么污染姿态 → App.jsx 的 `applyPathBake`（对象分支里 `{...objectKeyframeFromObject(...), position}`）
3. 认准验证三件套命令（见 §6），动手前先各跑一遍确认当前是绿的，作为你的基线。

## 2. 铁律（违反任何一条都会被退回重做）

有序号，写码时逐条对照。

| # | 铁律 | 为什么 |
|---|---|---|
| T1 | **严格按 M1→M2→M3→M4 串行开发**，上一个模块的验证全绿才进下一个。**M3 绝不单独上线**「路径只写 position」。 | 变换目前是整块插值，只改写入不改求值端会把动作/骨骼锁死，属于拿半成品上线。 |
| T2 | **所有写入口统一走 M4.1 唯一写 API**。重构后禁止再直接 `setCharacterKeyframes(...)` 拼装式写入。 | 分散拼装 = 可能越域写错通道、丢撤销、回归（M4-C1）。 |
| T3 | **通道名 / 字段名 / 存储键走统一登记，禁散写新字面量**。 | 项目有 `.director3d` 序列化与既有检查脚本，散写字面量会漏归一化、漏检查（M1-C4）。 |
| T4 | **关键帧数组永远不可变更新**，沿用 `filter + spread + sort((a,b)=>a.frame-b.frame)`，绝不原地 mutate。 | 撤销/自动保存依赖引用变化，mutate 会让历史整体失灵。 |
| T5 | **撤销/自动保存全自动，绝不手动调 recordChange**。数据放进现有 state 即可，`currentProject` 防抖自动入栈。 | 项目历史就是这样接线的，多调一次反而错。 |
| T6 | **求值热路径：单通道轨预排序 + 二分定位 + 结果缓存**，杜绝「每帧把整条轨全量 sort」。 | 相机轨和对象变换轨都在播放热路径上，全量 sort 会让播放/拖动卡顿（M2-C5/C6）。 |
| T7 | **骨骼通道不自己猜状态**：插值 or 硬切的决策从「派生上下文」读动作通道算出的状态段，禁止在骨骼通道里重复推断 `sameState`。 | 否则等于把「猜状态」老毛病换个地方又写一遍，走走停停会回来（M2-C7）。 |
| T8 | **路径时空绝不写 pose/joints/rigRoot**，只产出 position。 | 这是 M3 的核心解耦点，写姿态就让路径再次污染动作/骨骼（M3-C2）。 |
| T9 | **迁移只读源、写新建、不就地污染；必须幂等**。 | 防止迁移误伤旧数据、防重复切分后 key 叠两层（M4-C2/C3）。 |

## 3. 每个模块解锁前先确认「我懂了什么」

别急着写码，先能用自己的话讲清楚这个模块的边界，再动手。

- **M1 通道模型与数据契约**（一切的地基，延期返工最贵）
  要能讲清：三实体（摄像机 / 普通物体 / 人物）各有哪些通道；摄像机和物体为什么通道少；人物 = 变换 + 动作 + 骨骼三个通道，每通道对应哪些字段；「轨」长什么样；什么样的 key 叫「部分字段 key」（未来单属性 K 用的）。
  **交付物**：实体通道注册表 + 轨数据结构 + 归一化/反序列化入口 + 「key 未含字段 → 该帧不解接管该字段」的语义。
  关卡：源文件里不应再出现「整快照 8 字段」的对象关键帧形态作为唯一结构；新属性只要登记进唯一通道即生效、不动求值器。

- **M2 逐帧求值与合成引擎**（替换整快照求值）
  要能讲清：单通道求值器输出什么；实体合成器按什么优先级把各通道结果并到底层基线；「派生上下文」是什么（当前帧的动作状态段起点/时间这类中间量，不落通道字段）。
  要替换掉的三个旧函数：`objectAtFrame` / `objectsAtFrame` / `cameraAtFrame`。
  **关卡**：旧手动 K 帧场景下，新旧求值逐帧输出一致（这个校验就是全项目的「迁移验证锚」）；改动作切换状态段时骨骼 hard 切的行为跟以前一模一样。

- **M3 路径独立化**（路径当纯位置来源）
  要能讲清：路径「存在且启用」时 position 唯一由路径给、位置关键帧被忽略（显式二选一）；「有路径」就视为位置来源存在，变换轨为空也不回落基线坐标；曲线几何/匀速/平滑直接复用现有采样函数，**不重写算法**。
  **关卡**：路径时空不再新增任何动作/骨骼 key；路径帧只有 position，没有姿态残留。

- **M4 采集入口与兼容迁移**（收口 + 搬家）
  要能讲清：唯一写 API 覆盖「手动 K / 未来单属性 K / 路径 bake」三处；整快照旧轨怎么无损拆进对应通道；**现网真实存在的「手动 K + 路径帧」混合轨怎么拆**（这是最容易漏的坑）；撤销如何每批原子入栈。
  **关卡**：三处写入口都走唯一 API；迁移幂等（同数据跑 N 次结果一致）；迁移后逐帧 diff 与旧求值全等；一次路径 bake 撤销后整批 key 一起消失、不残留半批。

## 4. 最容易翻车的 6 个点（先看再写）

1. **M3 单独上线** → 动作/骨骼被锁死。对策：永远先 M2，M3 只做「改写入 + 改来源判定」，求值端必须已经是通道化的。
2. **骨骼又自己猜状态** → 走走停停回归。对策：状态段边界永远产自动作通道、走派生上下文。
3. **迁移碰上「手动 K 帧 + 路径帧」混合轨** → 不知道拆哪份。对策：按 PRD M4-C6 三动作走——剥路径姿态残留 / 手动帧原样入对应通道 / 路径启用时其范围内手动 position 帧显式忽略。
4. **路径 bake 又写姿态快照** → M3 白做。对策：bake 产物只有 position 来源标识。
5. **热路径全量 sort** → 播放卡。对策：轨预排序 + 二分，一次排序多次查询。
6. **性能/正确性盲跑** → 出 bug 找不到锚。对策：每模块的断言都落到纯逻辑单测（放 project 纯函数域），能脱离 UI 跑。

## 5. 建议的动手节奏（小步、每步可回退）

每步结束都满足两件事：`check:jsx` 过、该模块带的断言单测过，才进入下一步。

1. 建 Git 基线 / 记当前分支，确认三个验证命令全绿（这是你的「没动坏」基准）。
2. M1：只补数据契约与登记表，**不改任何求值**。跑通「部分字段 key 序列化后不含未给字段」这类断言。
3. M2：新求值器与旧「逐帧 diff 全等」单测同时落地，diff 全等之后再让它接管写入口。**这是全项目最关键的里程碑，别赶。**
4. M3：把 bake 改成只产 position 来源，接通来源判定，跑「路径空不新增动作/骨骼 key」断言。
5. M4：收紧写入口到唯一 API，做迁移，跑幂等 + 逐帧全等 + 撤销原子性断言。
6. 收尾：全套 `check:jsx` / 相关单测 / `build`，手动在 UI 上过一遍「手动 K 帧、画路径、改参数重烘焙、撤销」都不崩。

## 6. 验证与验收命令（动手前先跑一遍确认基线是绿的）

```bash
npm run check:jsx          # JSX 结构检查（每步必过）
npm run check:api          # API 契约（build 前置，重要）
npm run test:unit:logic    # 纯逻辑单测（含路径相关，你的主要验证带）
npm run build              # 产物构建（每模块收尾必过）
```

补代码时，优先把可验证的逻辑放进 project 纯函数域写单测；UI 层的走手动点一遍。

## 7. 验收标准（全部满足才算完成）

- [ ] `check:jsx`、`check:api`、`build` 全绿，纯逻辑单测全过。
- [ ] 旧手动 K 帧场景：新求值输出与旧 `objectAtFrame` 逐帧全等（浮点容差内）。
- [ ] 路径只作位置来源：路径时空不产生任何 pose/joints/rigRoot key。
- [ ] 路径不存在时现网播放行为逐帧不变；存在路径时 position 走路径、动作/骨骼照旧插值。
- [ ] 混合轨（手动 K + 路径帧）迁移后：路径帧无姿态残留、手动帧字段完整、路径启用时忽略其范围内手动 position 帧。
- [ ] 手动 K、画路径、改参数重烘焙、撤销四操作在 UI 上验证不报错、不残留半截图。

## 8. 心态纪律

- 这是**重构不是加功能**：目标是「换内部结构且用户无感知」，凡是要改变用户可见行为的地方先停下问一句「真的必要吗」。
- **小步提交、单测兜底**，不要一次性把 M1~M4 写完再验证——那样排错成本极高。
- 不要顺手改无关代码，保持 diff 聚焦在本次模块。
- 有把握就持续推进；卡在一处超过一小段时间就停下来，对照 PRD 对应约束复读一遍再动手，别硬撞。
