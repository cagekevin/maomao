## 0. 一句话定位

**不是纯前端，也不是桌面壳（无 Electron/Tauri）。是「Web SPA + 本地 Node 服务 localTool」双端架构**，
localTool 是**唯一出站网关 + 文件落盘服务 + SQLite 数据库 + 静态托管**，托管前端 `dist/` 并代理所有第三方 AI 请求。

```

│  浏览器（Vite + React 19 SPA，dist/ 由 localTool 托管）                    │

│   base/store/*    ── zustand 多 slice 状态                                 │
│   base/storage/*  ── KV 分流（localTool SQLite / 浏览器 localStorage）      │
```

## 1. 分层与职责

### 前端（Web SPA）

- 技术栈：Vite 5 + React 19 + TS 5.6；`@xyflow/react`（节点画布）、`three`/R3F（3D导演）、`zustand`（状态）、`tailwindcss`。

- AI 出口纪律：所有生成请求只走统一入口 `POST /api/generate`（前端经 `base/api/{imageApi,videoApi,chatApi}` 门面 → `relayProxy`，发 GenIntent：capability/providerId/model/参数）。**禁止另写 fetch/轮询/SSE**（relay 是唯一 relay 客户端）。`/api/proxy` 已退役删除。

- 配置：`base/config.ts` 的 `API_BASE = VITE_API_BASE || http://127.0.0.1:18080`。

### localTool（本地 Node 服务）

- 角色：**唯一出站网关 + 文件落盘 + SQLite + 静态托管**。无 Electron/Tauri，纯 Node `http.createServer`。

- 端口：`127.0.0.1:18080`（`PORT` env 可覆盖）。启动检查端口占用、读 `apimart-gateway/.env`（Lovart AK/SK）、自动开浏览器、每日备份。

- 请求五阶段（`handleRequest`）：CORS 预检 → `/files/*` 静态 → 具名路由 → `dist/` 托管 → catch-all passthrough 转发官方。

- **CORS 解法**：每个响应都加 `Access-Control-Allow-Origin: *`。所有第三方跨域在 Node 服务端（不受浏览器同源限制）完成，前端零直连。

### 上游

- `apimart-gateway`：Python，端口 **9004**，Lovart 生图/视频网关，需真实 `LOVART_ACCESS_KEY/SECRET_KEY`（占位符不生效）。

- openai 兼容站：可直连或经 localTool 注入 Bearer Key。

- 官方兜底：`routes/official.ts` 转发 `www.1mao.cc`，`routes/passthrough.ts` 转发未接管请求。

## 2. AI 生成链路（当前生效：统一生成入口 `POST /api/generate`）

**capability 是入参，一个入口按能力走各自数据流（不按模态拆端点）。** 老 `/api/proxy`、`proxyGenerate`、前端自轮询已退役（清理中）。

### 2.1 image / video —— 异步句柄（后端驱动，根治刷新丢结果）

```
前端 imageApi/videoApi → relayProxy.relayGenerate
  → POST /api/generate（capability=image|video，frontTaskId 必填）→ 立即返 {taskId}
  → localTool relay-poll.submitGenerateTask：
      协议出站(kit)拿上游 task_id → tasks 表落在途行(running) → 注册常驻轮询句柄(可 attach/重启恢复)
  → 常驻 poll 到终态：
      completed → saveRemoteUrl 落盘 /files/tasks/ + upsertTask 写 result_url/completed_at
      failed    → upsertTask 写 failed
  → 前端 GET /api/generate/{frontTaskId} attach（或 relayAttachUntilDone 低频轮询）取结果
```

- 查询：`GET /api/generate/{frontTaskId}` → running(progress) / completed(url) / failed / not-found

- 取消：`POST /api/generate/{frontTaskId}/cancel`

### 2.2 chat —— 同步 / 流式（按 provider 分流出站）

```
chatApi → relayChat → POST /api/generate（capability=chat，frontTaskId 透传不消费）
wantStream = stream===true 或 带 tools：
  - 流式：relayChatStream —— 上游 SSE 原样透传前端（打字机 + tool_calls delta）；
          上游非 SSE（不支持流式/报错）→ 读文本包 data: 行，前端降级非流式解析。
  - 同步：relayGenerate 按 provider 分流：
        非 9004/lovart → kit.chat()（标准 OpenAI）
        9004(lovart)   → LOVART preset（剥 data. 双信封）
        带 tools       → chatWithTools（返回 {text, toolCalls}）
```

### 2.3 出站 / 落盘契约要点

- `resolveBaseUrl` = **先读用户配置文件** **`base_url`** **→ 兜底内置 defaultBaseUrl**（modelscope 等纯配置厂商靠它，别只读内置目录否则报「未配置接口地址」）。

- 参考图统一 `resolveLocalImages` 内联 base64；落盘 `saveRemoteUrl`；`result_url` 由后端 `upsertTask` 写（后端是真源，前端只读）。

- key 只进 `.env`；base\_url / 模型走 `config/providers/<id>.json`。

- 刷新恢复：前端重新 GET attach 到同一后端句柄（后端进程 + DB 落库），不再前端自轮询。

## 3. 文件落盘（重点：图生图/图生视频的素材怎么来）

**落盘是真实磁盘写（经 localTool），不是只能存浏览器默认目录。** 自动化、可入库、可素材库检索的落盘一律走 localTool disk。

- 前端唯一桥：`base/api/filesApi.ts`，只打 `POST ${API_BASE}/api/files/upload` 一个端点，两种模式：

  - multipart FormData（`file` + `subfolder`）→ 直接存本地文件。

  - JSON（`{fileUrl, subfolder, filename}`）→ 后端 `saveRemoteUrl` 代下载（fetchWithProxy，绕 CORS）+ sha1 幂等去重。

- 落盘函数：`saveInlineToLocal(dataUrl)` / `uploadFileToLocal(file)` / `downloadRemoteToLocal(url)` / `saveResultToTasks(url,type)` / `saveTextToTasks(text)`。

- 后端实现：`routes/files.ts` `handleUpload` → `utils/fileStore.ts` `writeUploadBuffer/ensureDir/resizeImage`（jimp 缩略图）写 `uploads/{subfolder}`。

- 读回：`GET /files/<subfolder>/<name>`（`handleStaticFile`，路径遍历防护 + MIME + 长期缓存）。

- 落盘子目录中央表 `UPLOAD_DIRS`：`tasks / web / canvas / canvas/drop / canvas/video-process / migrated / director3d`（**禁止散写字面量**）。

### 图生图 / 图生视频的参考素材（关键设计）

- **两种形态并存**（对应原仓库 uploadService 的 publicUrl / dataUrl 双模式）：

  - **base64 内联**：`resolveLocalImages.ts` 把请求体里本机 `/files/` 图在出站前读盘、压缩≤1920、内联成 `data:`，喂给模型。这是当前主力路径（无图床依赖）。

  - **公网 URL**：远程图经 `downloadRemoteToLocal` 代下载落 `uploads/`，再当 `/files/` URL 被内联。

- 递归深遍历请求体，同 filePath 缓存避免重复转换；转换失败**保留原 URL 由上游显性失败**（docs/72 教训：静默丢参考图会无报错退化成文生图）。

- **未做**：独立图床上传（原仓库 `uploadToRemote` 走 uguu.se/APIMart）。当前靠 base64 内联 + 本地落盘兜底，超大图/视频参考走内联有体积上限风险。

## 4. 状态管理与持久化

- 状态：`zustand` v5，多 slice 组合（`projectStore/assetStore/contentStore/skillStore/...`，`director3d/storage.ts` 独立）。

- 持久化双层（`base/storage/kvStore.ts` 按 `contracts.ts` `STORAGE_KEYS.backend` 分流）：

  - 业务共享（画布态/账号/active\_api\_endpoint）→ **localTool KV**（SQLite `/api/kv/*`，跨端共享）。

  - 纯本机（projects/app\_settings/configs）→ 浏览器 `localStorage`。

  - 降级：KV 写失败 → 落 localStorage 并 toast；KV 读失败 → 回退本地副本。

  - tasks/resources/projects 直接存 localTool SQLite（`/api/tasks|resources|projects`）。

- **未用 IndexedDB**（仅 localStorage + chrome.storage + SQLite）。

***

## 5. 数据库（localTool 侧）

- 引擎：**sql.js（SQLite WASM）**，文件 `~/.maomao-localtool/localtool.db`。

- 表：`kv / tasks / resources / projects / project_meta`。

- 安全机制：原子写（`.tmp`→rename）、VACUUM(>50MB)、损坏自动重建(`.corrupt`)、每日备份+JSON 导出(留 7 份)。

- 封装：`queryAll/queryOne/run/execMulti` + 事务。

- Providers 配置在每个独立 JSON `~/.maomao-localtool/providers/<id>.json`（elastic：一个厂商一个文件，含 base\_url/模型/enabled）；API Key 只进 `localTool/.env`（`API_PROVIDER_{ID}_KEY`，不落 JSON）。

- 前端可在设置页做「用户配置层」增删：启用/移出厂商（enabled）、模型清单手输增删 + 拉取勾选合并去重、编辑 base\_url；save() 写回 config JSON（后端唯一数据源）。

- 路径真源 `paths.ts`：`getDataDir()=~/.maomao-localtool`、`getUploadDir()=~/.maomao-localtool/uploads`。

## 6. relay / ai-relay 层（当前生效，已接入）

- **`localTool/src/ai-relay/`** **= 自研中转协议引擎**（已接入 main，非 PoC）：内置平台目录 `BUILT_IN_PROVIDER_DEFINITIONS`（14 平台，含真实 id 如 lovart/apimart/modelscope/xai/google/…）+ 声明式协议引擎（`protocol.executeModelProtocol`）+ 配套 kit（`chat`/`chatWithTools`/`streamChat`/`generateImage`/…）。

- **统一生成入口** **`POST /api/generate`**（`routes/generate.ts`）→ `relay-poll`（异步句柄）+ `relay.ts`（chat 同步/流式）。

- `/api/relay` 已并入 `/api/generate`，**路由已删**。老 `/api/proxy`、`proxyGenerate` 整文件、前端自轮询已退役（清理收尾见交接文档）。

- **provider 配置型**：每厂商一个 `config/providers/<id>.json`；`resolveBaseUrl` 读配置 `base_url` 优先；**key 只进** **`.env`**。

- `testConnection` / 模型拉取对**无内置目录定义但有 base\_url 的纯配置厂商**（modelscope/自定义）也按通用 OpenAI 探测/拉取，不再报「未知厂商目录」。

## 7. 能力边界（做不到什么 / 风险点）

1. 非桌面应用：必须 localTool 在跑且托管 dist；关 18080 前端不可用。
2. ~~relay 未落地~~（已接入）：AI 中转统一走 `/api/generate`。遗留清理：老 /api/proxy、proxyGenerate、前端自轮询死代码待删（见交接文档 §2.1）。
3. 依赖外部网关与凭据：9004(lovart) 生图/视频需真实 LOVART AK/SK；境外厂商（如 api.apimart.ai）后端直连常 fetch failed，需走代理（7897）。
4. 剪映集成是空壳：`/api/jianying/send` 仅记日志（`_meta.stub=true`）。
5. 无 ffmpeg：`/api/status` 返回 `ffmpeg:false`；本地视频处理靠 mediabunny/three，无系统级转码。
6. 云同步明文：cloudSync 的 GAS 终点是明文 POST，无鉴权/加密（注释自陈）。
7. 无服务端推送：仅 HTTP 轮询 + SSE，无 WebSocket。
8. CORS 强绑定 localTool：所有跨域由 18080 解决；前端直连第三方需改协议。
9. 数据隔离依赖单用户：SQLite 在 `~/.maomao-localtool`，无多用户/权限体系。
10. 图床上传缺失：参考图靠 base64 内联兜底，超大图/视频参考有体积上限风险。
