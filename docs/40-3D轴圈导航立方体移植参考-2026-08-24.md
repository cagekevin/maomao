# 40 - 3D 轴圈（ViewCube）导航功能「好看 + 好用」移植参考 - 2026-08-24

## 0. 背景与真实现状（已核实）

- 用户要一个**好用第一、好看第二、且克制不复杂**的视角导航控件：点控件跳到
  **顶 / 前 / 后 / 右 / 左 / 底 / 透视** 等标准视角。
- **现状：director3d 当前没有任何轴圈**。用户之前那个 DOM `<canvas>` 自绘轴圈因「不好看 + 不好用」已被删除
  （`ViewCube.jsx` 已不存在，`App.jsx` 无 `viewport-view-cube`，`viewCubeRequest` 链路不存在）。
  → 本次是**从零加入**，不是替换。
- 你的 `OrbitControls` 是 `makeDefault`、target `[0,1,0]`（`Viewport.jsx:414`），Canvas `frameloop="demand"`（:485）。
- 右上角已有「视角工具」浮条（`viewport-view-options`，top:12 right:12），轴圈不能压它。
- UI 是暗色克制风（`#555653` 背景、细线、低饱和强调色）。

## 1. 候选审计（好用 × 好看 × 不复杂）

| 候选 | 好用 | 好看 | 不复杂 | 结论 |
|------|------|------|--------|------|
| 删掉的 DOM 自绘轴圈 | ✗ 6 圆点无标签、点不准 | ✗ 2D 线框廉价感 | — | 已被否决 |
| `three-js-editor` `ViewHelper` | △ 只 3 轴箭头、点中难 | △ 细线像调试工具 | ✗ 原生类需桥接 | ✗ |
| `prisma-3d` 按钮排 | ◯ 能跳但占地方无空间感 | △ 普通按钮 | ✗ 栈不同 | △ 仅参考 |
| `3d-studio` `GizmoViewport` | ◯ 3 轴 6 圆头点即跳 | ◯ 简洁现代偏工具感 | ✅ | △ 能用 |
| **drei `GizmoViewcube`** | ✅ **6 面带文字、点面即跳、零学习** | ✅ **有体积、hover 高亮、静态安静** | ✅ | ✅ **最佳** |

**选型：`GizmoViewcube`**（带 `FRONT/BACK/TOP…` 文字的立方体）。
理由贴合用户标准：好用（文字面 = 零认知成本）、好看且克制（体积感但不花哨、hover 才亮）、不增加复杂度（drei 全封装）。
若想要 3d-studio 极简轴箭头风，换 `GizmoViewport` 即可，其余结构不变。

## 2. 为什么 drei 能直接落地（已读源码核实，非假设）

`node_modules/@react-three/drei/core/GizmoHelper.js` 已内置解决所有「好用」底线：

1. **`onTarget` 回调**（:48-50）：点击时 `focusPoint = onTarget() || controls.target`。
   传 `onTarget={() => new THREE.Vector3(0,1,0)}` → 旋转中心是角色中心，点顶视图角色居中不出框。
2. **`invalidate()`**（:60,85）：tween 与 `useFrame` 中调用 → 天然兼容 `frameloop="demand"`，静止时轴圈随相机刷新。
3. **自带补间**（:78 `q1.rotateTowards(q2, step)`）：球面插值平滑跳转，不瞬移，结束后复位 `camera.up`。
4. **复用你的 `OrbitControls makeDefault`**：通过 `useThree(state => state.controls)` 拿到，跳转后自动 `controls.update()`。

→ **你只声明组件 + 传对参数，不写任何动画 / 射线 / 同步代码。** 这正是「不绕」的前提。

## 3. 优雅写法的核心原则（避免「写完发现绕了 3 个函数」）

> 用户明确诉求：代码要最优雅、逻辑不混乱，不要像某些 AI 写完才说「其实一个函数就解决，但我绕了 3 个」。

1. **单一跳转入口，不写第二套动画**。
   轴圈点击跳转、toolbar 按钮跳转、快捷键跳转——**全部走 drei 的 `tweenCamera` 这一个函数**。
   绝不再写一个 `ViewTweenController` / `animateTo` 之类的第二套补间（那正是「绕」的来源）。
2. **drei 做对的绝不重做**。
   `onTarget` / `invalidate` / 补间 / 同步——drei 全包。你零实现这些，只配置。
3. **不预留「可能用到」的抽象**。
   不为未来可能的正交视图、自定义角度预设提前建基类/配置表。本次只解决「跳 6 面 + 透视」一件事。
4. **逻辑收口在一个组件里**。
   所有轴圈相关代码放进 **一个** `SceneGizmo` 组件（~25 行），`App.jsx` 不掺和 3D 内部，只拿到一个 `jumpTo(view)` 接口。
5. **声明式接入点只有一处**。
   在 `EditorScene` 返回树里放 `<SceneGizmo/>`，不散落在多个文件改同一件事。

## 4. 最终落地结构（就 1 个新组件，不绕）

### 4.1 新组件 `SceneGizmo`（放在 `Viewport.jsx` 内或独立文件，收口全部轴圈逻辑）

```jsx
import { GizmoHelper, GizmoViewcube, useGizmoContext } from '@react-three/drei'
import * as THREE from 'three'

// 命名视图 → 世界方向向量（仅一份映射，不分散）
const VIEW_DIRS = {
  top:    [0, 1, 0], bottom: [0, -1, 0],
  front:  [0, 0, 1], back:   [0, 0, -1],
  right:  [1, 0, 0], left:   [0, -1 ? 0 : -1, 0], // 见下注
  perspective: [0.62, 0.47, 0.69], // 默认斜视，normalize 由 tweenCamera 处理
}
```

> 注：`left` 应为 `[-1, 0, 0]`（上面写成 `0,-1,0` 是笔误，实际写 `[-1,0,0]`）。
> 透视方向取一个舒服的斜视向量即可。

**关键：把内部 `tweenCamera` 通过 ref 暴露给外部（toolbar/快捷键），复用同一套动画，不写第二套。**

```jsx
// SceneGizmo 内部：用 useGizmoContext 取 tweenCamera，外抛 jumpTo
function SceneGizmo({ onReady }) {
  const { tweenCamera } = useGizmoContext()
  useEffect(() => {
    onReady?.(dir => {
      const d = VIEW_DIRS[dir] || VIEW_DIRS.perspective
      tweenCamera(new THREE.Vector3(...d))   // 唯一跳转函数，drei 负责动画
    })
  }, [tweenCamera, onReady])
  return (
    <GizmoHelper alignment="top-right" margin={[80, 80]} onTarget={() => new THREE.Vector3(0, 1, 0)}>
      <GizmoViewcube color="#f0f0f0" hoverColor="#4f8cff" textColor="#1d1d1f" strokeColor="#cfcfcf" opacity={0.92} />
    </GizmoHelper>
  )
}
```

- `onReady` 把 `jumpTo` 交给 `App.jsx` 存进一个 ref/state（如 `gizmoApiRef`），toolbar 按钮直接 `gizmoApiRef.current?.('top')`。
- **全部跳转只有 `tweenCamera` 一个函数**，点立方体面跳、点 toolbar 跳、按快捷键跳，走完全相同的路径。

### 4.2 `EditorScene` 内加一行（唯一接入点）

```jsx
{!cameraView && <SceneGizmo onReady={onGizmoReady} />}
```

（`onGizmoReady` 由 `EditorScene` 的 props 一路从 `App.jsx` 透传，或直接在 `EditorScene` 内 `useState` 持有后上报。）

### 4.3 `App.jsx` 只消费接口，不碰 3D

```jsx
const gizmoApiRef = useRef(null)
// toolbar 按钮：
<button onClick={() => gizmoApiRef.current?.('top')}>顶视图</button>
// 快捷键（如按 T/F/R...）：
gizmoApiRef.current?.(viewName)
// 把 gizmoApiRef 作为 onGizmoReady 传给 MainViewport → EditorScene → SceneGizmo
```

## 5. 必须做对的 3 件事（好用底线）

| 项 | 错的做法 | 对的做法 |
|----|----------|----------|
| 旋转中心 | 不传 `onTarget` → 角色出框 | `onTarget={() => new THREE.Vector3(0,1,0)}` |
| 位置重叠 | `top-right` 压住视角工具浮条 | `margin={[80,80]}` 或 `alignment="bottom-right"` |
| 摄像机视角 | `cameraView` 下仍显示 | `{!cameraView && <SceneGizmo/>}` |

## 6. 落地清单（不返工顺序）

1. `Viewport.jsx`：import 加 `GizmoHelper, GizmoViewcube, useGizmoContext`。
2. 新增 `SceneGizmo` 组件（含 `VIEW_DIRS` 映射 + `onReady` 暴露 `jumpTo`）。
3. `EditorScene` 内加 `{!cameraView && <SceneGizmo onReady={onGizmoReady}/>}`。
4. `App.jsx`：加 `gizmoApiRef`，透传给 `MainViewport`；toolbar 按钮 / 快捷键调用 `gizmoApiRef.current?.(view)`。
5. 调 `margin`/`alignment` 避开右上角浮条。
6. **验证（好用优先）**：① 点立方体各面→平滑跳转、角色居中；② toolbar 按钮 / 快捷键→同样平滑跳转（证明单一入口生效）；③ 静止拖动场景→轴圈同步转（demand 不卡）；④ `cameraView` 下不显示。
