## 背景

「域」= **用户能指着说的东西**（一个能力/一个界面物件）。一个件归哪个域，只看 **① 它在界面上长在哪 ② 它的数据落到哪** —— **不看它现在住在哪个目录、叫什么名字**。

本项目刚做完一轮搬迁，**搬进来的件可能搬错了域**。你的任务是**反向检查**：不问"横切层里有没有漏搬的"，而问 **"已经住在域 A 里的件，是不是其实属于域 B"**。

业务域清单（**以代码实际为准**）：`agent` · `canvas` · `image` · `video` · `text` · `resource` · `task` · `generate` · `prompt` · `settings` · `creative` · `scriptbox` · `videoEditor` · `director3d`。

## 判断标准（按此自己找，没有人给你清单）

1. 对**域内每一个件**跑 `refs`，取消费方，统计「业务域集合」（`src/App.tsx`、`base/**`、`tests/**` 不计入业务域）。
2. 与它**当前所在域**比对，判：
   - **消费方集合 ⊆ 当前域** ⇒ 正常（写"合规"）。
   - **消费方集合 = 另一个单一域**（且本域没人用）⇒ **放错域** → 给出正确的域与子目录落点。此时**必须再补一条界面位置证据**（例如它被哪个界面组件渲染），否则不算。
   - **消费方集合跨 ≥2 域** ⇒ **跨域消费不改归属**（ADR-0040 L6）：**不要因为"别的域在用"就建议搬**。只有当你还能证明"它界面位置/数据落点在别的域"时才判放错。
3. **假子域**：若某个子目录里 **<3 个件**，判"假子域"（不该单独成子域，应并回父级或并进同形态的兄弟子域）。反向：某个子目录件数很多但**没有任何门面 `index.ts` 或门面不露该露的符号**，也记下来。
4. **同名/近名混淆**：不同域下出现**同名文件**，或两个文件**只差一个字符**（如 `asset.ts` vs `assets.ts`），记下来（易误判归属）。
