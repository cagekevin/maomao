## 一、背景
项目有统一存储分流：key 以 `canvas-state-v1-` 开头的画布类数据应走 localTool KV（/api/kv/*，SQLite，跨端共享），其余走 localStorage。实际出现过画布快照被塞进 localStorage 撑爆 5MB 配额的问题。你的任务：**自己去 src/ 探索，找出所有"本应走 KV 却没走 KV"、或"本应持久化/跨端共享却只在本地"的缺口**。

## 二、判断标准（你按此自己找）
- 画布/节点/边这类核心数据，本应跨端共享 → 应走 KV；若落 localStorage / 只在内存 / 刷新即丢，是缺口。
- 任何 key 前缀写错、漏带 `canvas-state-v1-`，导致分流失效落到 localStorage，是缺口。
- 大数据（base64 图、大快照）被塞进 localStorage，是缺口。

## 三、怎么做
1. 通读 `src/components/base/` 下存储相关模块，理解 KV/localStorage 分流机制。
2. grep `storageSet|kvSet|sSet|saveJSON|setItem|canvas-state` 全 `src`，找出所有画布类数据写入点。
3. 逐一判断每个写入点该走哪条路、实际走了哪条路、是否有缺口。
4. 也要找"漏缺"：本该有持久化/跨端共享机制，但完全没有实现（只在内存、没落盘）。

## 四、输出规范
表格：`| # | 写入点/缺口 | 文件:行 | 本该走 | 实际走 | 后果 | 是否缺陷 |`
