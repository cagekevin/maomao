## 0. 本批要你们回答的唯一问题

> **你这一亩地里，哪些文件「不是我的人」？它们本来属于哪个域、该落在对方哪个子目录？**

**不设计边界**，不做域与域之间的协商。边界由**各域各自申报 + 对方复核**拼出来。

| 做 | 不做 |
| --- | --- |
| 逐件判本域文件的**域籍**（是本域 / 不是本域） | 重新设计域名或域清单 |
| 不是本域的 → 报出「应属域 + 应属域内落点 + 证据」 | 自己动手把它搬出去（**本轮禁止**） |
| 属于本域但子目录错的 → 登记「域内错位」（**本轮也不搬**） | 改 `docs/plan/**` · `daily/**` · 别的域的文件 |
| 收到别域送来的件 → **交叉验证**（认领 / 不认 / 并案） | 修改任何判据 / ADR |

## 2. 铁律（违反重做）

1. **只写你自己那本任务书文件**。碰任何其他文件（含 `src/**`）视为失败 —— **本轮不许 `git mv`、不许改源码**。
2. **不许新建脚本文件**（`.mjs`/`.cjs`/`.sh`/`.js`）；仓内唯一搬迁/取证工具是 `scripts/mv-sync-refs.mjs`。
3. **不许 `move-dir`**（已知会写坏兄弟 `import`、留残留副本）。
4. **不许 `debt.mjs add`**（登记由裁判做）。
5. **不许按名字 / 目录名判归属**（ADR-0040 L2 明禁，本项目已因此判错 4 次）。每条结论必须附实测证据。
6. **不许读** `daily/架构日志/债务*.md` 和其它 `TASK-*` 的产出文件（防抄别人结论）。`docs/plan/域归位-最终执行计划.md` 与 `docs/DOMAIN-MODULES.md` **可以读**，但它们只是「目标」，**现状一律以 `refs`/`ls`/`grep` 实测为准**。

## 3. 判据（唯一来源 · 不许自造）

**归属 — ADR-0040**
- **L1（唯一归属判据）**：① 它的**界面长在哪** ② 它的**数据落到哪**。不按目录名/文件名/文档标签。
- **L2**：按名字判归属 = 明禁。
- **L3**：真横切件 = **≥3 个业务域消费 + 零业务语义**。
- **L4**：只被**一个业务域**消费的件，不许留在横切层（`base/{core,utils,ui,api,storage}`）。

**深模块 — ADR-0042**（用于判"这件该不该独立存在/受保护"，不用于判域籍）
- **D1**：深模块 = ① 接口窄 ② 实现厚 ③ **被域外消费**（三条全中才算）。
- **判据 5**：fan-in 只有域内 / 为零 ⇒ 不是深模块。
- **判据 6**：归属先于深浅。

**可判目标域全集（只能填这些）**：
`agent` · `canvas` · `image` · `video` · `videoEditor` · `director3d` · `scriptbox` · `text` · `prompt` · `settings` · `creative` · `resource` · `task` · `generate` · **`base`（横切层 / 非域）** · **`并案（共享件）`**

## 4. 🔴 判定「非本域」的**四件证据**（缺一即不合格）

每条"应属 X 域"的结论必须凑齐：

1. **界面位置**：它在哪个界面被渲染 / 被用？给 `文件:行`（JSX 里渲染它、或事件处理器调用它的那一行）。
2. **数据落点**：它的数据写进哪个 store / key / schema？给 `文件:行`。
3. **`refs` 实测原文**：`node scripts/mv-sync-refs.mjs refs <文件>` 的「① 模块引用」段**原样粘贴**（文件名列表）。
4. **反证检查（门闩 · 必做）**：**本域里有没有任何一处**直接渲染它、或本域 schema 声明它的字段？
   - **有一处 ⇒ 降级为 `待核`**（说明它仍在被本域用），**不许**报成"非本域"。
   - **零处 ⇒ 才成立**。

> 为什么要有第 4 条：本项目前 4 次判错的形态都是"看着不像 → 就送走"，结果人家还在用。

**禁写**：「它叫 xxx 所以不像本域的」·「它在 xxx 目录所以是某域的」·「文档说它属于 X」。

## 5. 域内落点基准（判"域内错位"用）

- **D1 · 域根散件 = 0**：域根只许留 ① 门面 `index.ts` ② 计划写明「留域根」的例外（你的任务书里会列）③ 被 `App.tsx` 直接消费的装配入口（须有「装配契约，非内部件」注释）。
- **D2 · 子域门槛 ≥3 件**：不足 3 件**不许建子目录**；并进职责最近的现成子目录。
- **D3 · 子目录职责单一**：`nodes/`(节点) · `editors/`(编辑器) · `lib/`(纯能力，**禁 JSX**) · `parts/`(零件) · `shell/`(外壳/工具栏) · `contract/`(schema/常量) · `structure/`(结构算法) · `topology/`(连接) · `store/`(状态) · `data/`(静态数据) · `ui/`(域内 UI kit) · `sections/`(设置分节)。混了两种职责 ⇒ 登记「假子域」。
- **D4 · 域内分层方向**：视图层(`nodes/editors/shell/ui/sections`) → 机制层(`parts/structure/topology`) → 能力层(`lib/contract/data/store`)。**反向禁止**（`lib/` 不许 import `nodes/`）。判定：对该件跑 `refs`，看出向 import 落在本域哪一层。

## 8. 交叉验证协议（你要知道会发生什么）

1. **第一波（现在）**：7 本任务书各出「域籍台账」。
2. **裁判汇总**：合成 **from→to 迁移矩阵**；把"送到 X 域"的件整理成 X 域的**待复核清单**。
3. **第二波（交叉验证）**：X 域域主独立复核，只许回三种：
   - `认领` —— 我域收，落点 = `X/子目录`
   - `不认` —— 附反证（为什么它仍属送出域）
   - `并案` —— 它其实是共享件 / 横切件，两边都不独占
4. **裁判裁定**：对 `不认` / `并案` / `待核`，由裁判**直接判**（不再往返）；然后**逐域串行**执行搬迁，每域搬完跑 `npx tsc --noEmit` + `node scripts/check-arch.mjs`。

**只有「一方报出 + 对方认领」才允许搬。** 其余挂「待裁定」由裁判落判。
