## 背景

本项目做了多轮「域归位」搬迁（`git mv` + 同步 import）。**搬迁最容易出的不是"没搬"，而是"搬了一半"**：
旧目录残留副本、旧路径引用没清、门面没同步、闸/基线/测试里的硬编码路径没跟着改（改了这些没跟着改 ⇒ 闸**假红**或**假绿**）。

本次任务是**交叉核对**：把**已经搬过的件**拿出来，逐条验"搬得对不对、搬干净了没"。

## 判断标准（按此自己找，没人给你清单）

**第一步：自己从 git 取核对对象**（不要问、不要猜）：

```bash
git log --diff-filter=R -M --name-status --oneline -80
```

这条会列出最近的**重命名/搬迁**记录（`R100 old -> new` 形态）。取最近的几十条作为核对对象。
若记录太多，**优先核对被改动的目录是 `src/components/**` 或 `src/hooks/**` 的那些**。

**第二步：对每条记录核对 6 项**（缺哪项写哪项，不合格要写明）：

| # | 核对项 | 怎么验 | 不合格的样子 |
| --- | --- | --- | --- |
| ① | **落点对不对** | 对新位置的件跑 `refs`，看消费方是否全在同一域（跨域消费不改归属，别误判） | 消费方全在另一个域 ⇒ 搬错了 |
| ② | **旧目录是否清干净** | `ls <旧目录>` + `git status --short` | 旧目录还在（空目录也算）/ 出现**未跟踪的旧路径副本**（= 同一文件两份） |
| ③ | **旧路径引用是否清零** | `grep -rn "<旧路径片段>" src tests scripts --include=*.ts --include=*.tsx --include=*.mjs --include=*.cjs` | 还有命中（**注释里的也算**，要区分"真引用"与"过期注释"） |
| ④ | **门面是否同步** | 新所在域有没有 `index.ts`；跨域消费者是否走门面 | 域外消费方直连内部件 / 门面没露新件 |
| ⑤ | **闸与基线是否同步** | `grep -rn "<旧路径片段>" scripts/*.mjs scripts/*.cjs scripts/*.json` | 闸/基线里还写旧路径 ⇒ 闸**假红或假绿** |
| ⑥ | **测试与 mock 是否同步** | `grep -rn "<旧路径片段>" tests`，特别是 `vi.mock(` / `vi.importActual(` / 手写的 `readFileSync('src/...')` | 测试指向旧路径 ⇒ 收集期 `ENOENT`（测试**长期红**却没人发现） |
