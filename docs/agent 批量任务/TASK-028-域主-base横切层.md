## 1. 你的领地和别人不一样：`base` **不是业务域**

`base/` 是**横切层 + 域容器 + 宿主层**的混装目录。所以你的判据**不是**"这件属不属于 base 这个域"，而是：

> **这件是不是「真横切原语」？不是 ⇒ 它本来属于哪个业务域？**

**四条判据（ADR-0040）**：
- **L3**：真横切件 = **≥3 个业务域消费 + 零业务语义 + 不隶属任何"能指着说的东西"**。三条全中 ⇒ **留原地（合规）**。
- **L4**：只被**一个业务域**消费的件，不许留横切层 ⇒ 报 `非横切件·应属 X 域`。
- **L1**：判"应属哪个域"仍只用 ① 界面长在哪 ② 数据落到哪。
- **L2**：不许按名字/目录名判。

**🔴 物理约束（本片最容易出错的地方 · 必查）**：
若某件的消费方里有文件落在 `base/{core,utils,ui,api,storage}` 内，**且那个消费方本身是真横切件**（它自己被 ≥3 业务域消费）⇒ **该件不能搬**：搬走会让横切层反向依赖业务域，架构闸 `scripts/check-arch.mjs` 规则 2 当场红。
判定方法：**对那个横切消费方再跑一次 `refs`**，数它的业务域。
这类判 **`待核（被真横切件锁死）`**，并把那个消费方的域数写进依据，**不要**报成"非横切件"。

## 2. 领地（逐件，不许抽样）

```
src/components/base/**         # 约 85 件，递归全部
```

实测子目录：`core/` · `utils/` · `ui/` · `api/` · `storage/` · `media/` · `panels/`，+ `base/` 域根（若有裸散件）。

**注意各子目录规则不同**：
- `core/` `utils/` `ui/` `api/` `storage/` = **横切 5 目录**（`check-arch` 规则 2 直接管它们）⇒ 主力判定区。
- `media/` · `store/` · `prompt/` = **域容器**，**不在** `BASE_CROSS_CUTTING` 集合里 ⇒ 它们**本来就允许**出向依赖业务域。判它们时用 L4（单域件不许留），但**不要**用"它依赖了业务域"当违规。
- `panels/` = **宿主 / app-shell 层** ⇒ 里面的件**默认判 `本域·合规（宿主层）`**；只有"明明属于某业务域、却借宿主层存放"的才报 `非横切件·应属 X`。

## 4. 本片特有事项（必须逐条给结论）

1. **`base/{core,utils,ui,api,storage}` 逐件跑 `refs`**，按 L3/L4 判，输出域集合（`src/App.tsx` · `base/**` · `src/hooks/**` · `tests/**` **不计入业务域**）。
2. **物理约束清单**：把所有"被横切件锁死"的件单列一节，**每个都附那个横切消费方的域数**。
3. **域根散件**：`base/` 一层若有裸文件 ⇒ 逐件给去处。
4. **域容器里的单域件**（`media/` · `store/` · `prompt/`）：
   - `base/prompt/` 计划要求**搬空即删** ⇒ 里面每件都要给"应属域"。
   - `base/store/` 里若仍有只服务单一业务域的件 ⇒ 报出。
5. **`base/utils/` 里的「能力成片」**（成因 H）：本片最可能的形态是"一整组能力散在 utils"（例：图片媒体处理一组、音视频一组）。**按"一片"整体登记**，写清片名 + 件数 + 大约行数 + 应属域/子域，**不要**拆成 N 行零散件。
6. **`base/api/` 是否是前端协议层全集**：若里面混了"业务编排"（请求组装 / 轮询 / 代理转发）而非"协议"，按第 5 条同法按片登记。
7. **深层浅壳**：若发现某件只是 re-export 常量（零实现）⇒ 登记为 `非横切件·应删壳`（写明常量的真源在哪）。
