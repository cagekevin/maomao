## 背景

本项目正在做「域归位」：文件归属只看 **① 它在界面上长在哪 ② 它的数据落到哪**（不看名字）。
`src/components/base/` 是「横切层 + 域容器」混装目录，其中 **五个横切子目录** 是：

```
src/components/base/{core, utils, ui, api, storage}
```

横切层只该放**通用原语**（≥3 个业务域在用、零业务语义）。**只服务一个业务域的件留在横切层 = 放错位置**。

业务域清单（供归域用，**以代码实际为准**）：`agent` · `canvas` · `image` · `video` · `text` · `resource` · `task` · `generate` · `prompt` · `settings` · `creative` · `scriptbox` · `videoEditor` · `director3d`。

## 判断标准（按此自己找，没有人给你清单）

对 `base/{core,utils,ui,api,storage}` 下的**每一个文件**，跑 `refs` 取消费方，然后：

1. **统计「业务域集合」**（把消费方路径归到上面的域名；`src/App.tsx`、`base/**`、`src/hooks/**`、`tests/**` **不计入业务域**）。
2. 判定：
   - 集合 **≥2 个业务域** ⇒ 真横切，**合规**（记为"非债"）。
   - 集合 **= 1 个业务域** ⇒ **放错了** → 给出建议落点（该域）。
   - 集合 **= 0**（只被 `base/**` 或 `App.tsx` 消费）⇒ 看下面的**物理约束**再判。
3. **🔴 物理约束（必须查，否则会给出"搬了会红"的错建议）**：
   若该件的消费方里**有文件落在 `base/{core,utils,ui,api,storage}` 内**，且**那个消费方本身是真横切件**（它自己被 ≥3 个业务域消费）⇒ **这一件不能搬**（搬走会让横切层反向依赖业务域，架构闸会红）。这类判 **"被横切件锁死 ⇒ 非债"**，也要登记。
   验证方法：对那个消费方**再跑一次 `refs`**，数它的业务域。
4. 真横切的定义：**≥3 个业务域消费 + 零业务语义 + 不隶属任何"能指着说的东西"**（ADR-0040 L3）。
