## 背景

「域」= **用户能指着说的东西**。「一个能力**散在多处**」= 该能力还没有一个自己的家 —— 这是**成片搬迁**（不是搬一件）的机会，收益比单件大。

本次**不做单件扫描**（那是别的 AI 的活）。你找的是 **「能力级」的散落**：同一件事的实现/UI/类型/常量被切碎放在 ≥2 个不同目录里。

## 判断标准（按此自己找，没有人给你清单）

一个「能力」算**散落**，当它同时满足：

1. 有**明确的用户可指对象**（一个面板 / 一个节点上的功能 / 一种编辑器 / 一条链路，**不是**"一堆工具函数的集合"）；
2. 它的**实现、UI、类型/常量**分布在 **≥2 个不同的目录**（最好是跨"域"与"横切层"，或跨两个不相干的域）；
3. 用 `refs` 能证明这几处**互相引用、同属一件事**（互相 import，或共同被同一个界面组件消费）。

**反例（不算）**：纯粹"按类型分的目录"（所有 `.d.ts` 在一起）不算能力；一个域内部的正常分层（`nodes/` + `lib/` + `editors/`）不算散落。

**额外要找的第二类**：**同一件事有两份实现/两个入口**（SSOT 第二份）——例如同一逻辑在 A 域与 B 域各写一份、或同一张表在两个文件里各维护一份。这类要给出"哪一份该留、哪一份该删/改委托"。
