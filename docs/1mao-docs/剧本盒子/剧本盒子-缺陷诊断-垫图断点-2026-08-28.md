### 5.5 测试实证结果（2026-08-28 已用用户真实镜头数据确认）

测试落点：`tests/unit/scriptBoxPrompts.boundaryDiag.test.js`（27 用例，全绿，含「§0 真实镜头1数据」分组）。运行：`npx vitest run tests/unit/scriptBoxPrompts.boundaryDiag.test.js`。

**实证 1 · 断点唯一且确定：`matchAsset` 的边界规则（`@名` 后一位是否中英数），与图片/URL 无关。**
用户三次实验（换已落盘老素材、重新上传新素材）均测了与断点**正交**的量——`collectAssets` 不看 URL/图，只看 `@名` 匹配。所以换图永远无法改变结果。

**实证 2 · 用用户真实镜头1数据，逐资产结果（`description`+`prompt` 合并扫描）：**

| 资产 | description 里 | prompt 里 | 合并后是否被垫 |
|---|---|---|---|
| 场景 `卧室` | `@卧室内`（后接中文`内`）→ false | 出现为 `深夜卧室内`（无 `@`）→ false | ❌ **永远漏** |
| 角色 `骷髅A` | 有多处 `@骷髅A,`（逗号）→ true | true | ✅ 垫上 |
| 角色 `骷髅B` | 每处 `@骷髅B突/开/更…` 后中文 → false | 有 `@骷髅B,`（`眼窝半睁看向@骷髅B,颅骨放松`）→ true | ✅ 垫上（靠 prompt 的逗号兜着） |

**实证 3 · "为什么别的都正常、就场景不行"的真相：**
`matchAsset` 会**遍历该资产所有 `@名` 出现位置**，任一后一位是标点/空格/结尾即命中。角色 `骷髅A/骷髅B`、道具 `HKH精华瓶` 在真实合并文本里**总有一处 `@名` 后紧跟逗号/引号/空格**，于是被垫上；而场景 `卧室` 在此剧本全字段里唯一的 `@` 是 **`@卧室内`**（名字紧贴方位词"内"，后一位是中文`内`），再无第二处安全边界 → **必然不匹配 → 场景永远垫不上，且与换图无关**。

**实证 4 · H2 对场景成立；角色/道具当前"正常"是因为它们有逗号兜着，并非结构性免疫。** 若任意角色/道具某镜被写成 `@骷髅A站`（名字紧贴动词，无标点），同样会漏（文档 §5.3 的边界矩阵已证明该机制）。场景之所以【必现、且仅场景】断，是因为中文场景名词习惯紧贴方位词（内/里/全景/背景）书写、无标点间隔，命中该误杀规则的频率最高且无兜底。

> 结论：根因= `matchAsset` 边界规则误杀中文场景（`@卧室内`）。修复建议直接采用 §2.4 **思路1**（放宽边界：存在 `@名` 即命中）或 **思路2**（`category==='scene'` 走 `text.includes(场景名)` 宽松匹配，保留角色/道具的严格边界防误中）。两者皆不改接收端 `PromptNode`。

## 二、缺陷②：生成图片时场景没有被垫图

### 2.1 确证事实（来自代码，非推断）

**事实 1 · 垫图收集的唯一入口与唯一匹配条件**
`collectAssets`（`scriptBoxPrompts.js:316-327`）：

```js
export function collectAssets(shot, assets) {
  const list = Array.isArray(assets) ? assets : []
  if (!shot || list.length === 0) return []
  const text = `${shot.description || ''} ${shot.prompt || ''} ${shot.videoPrompt || ''} ${shot.dialogue || ''}`
  const out = []
  list.forEach((a) => {
    if (a?.name && a.imageUrl && matchAsset(text, a.name)) {   // 条件 = 有图 且 文本里 @名
      out.push({ id: `script-asset-${a.id}`, url: a.imageUrl })
    }
  })
  return out
}
```

即：一个资产要成为某镜垫图，**必须同时满足**
- (a) `a.imageUrl` 非空（用户已确认资产全出图，此条满足）；
- (b) 该镜 `description/prompt/videoPrompt/dialogue` 文本中**出现 `@资产名`**（`matchAsset`，`scriptBoxPrompts.js:254-264`）。

**事实 2 · `category` 不参与匹配**
`collectAssets` 对 `character/scene/prop` 一视同仁，只看 `@名`。场景没有任何"自动纳入"逻辑。

**事实 3 · 系统 prompt 要求"每镜必须 `@` 场景"，但仅为软约束**
`scriptBoxPrompts.js:31-32`：
- "场景内的普通陈设…用普通文字描述，不 `@`"
- "每个分镜的 description **必须 @ 引用其发生的场景**"
- 代码层面**没有任何强制或兜底**保证 AI/用户真的写了 `@场景名`。

**事实 4 · 接收端正确**
`PromptNode.run` 生图：`refUrls = mergeRefImages(connected.images, data.images).map(i=>i.url)` → `generateImage({ images: refUrls })`（`PromptNode.jsx:69, 203-215`）。`data.images` 为空就无垫图，但接收端本身无 bug。

**事实 5 · 连线即冻结，但此点对"已全出图"场景不构成主因**
`onConnectShot`（`scriptBoxEngine.js:818-843`）在连线时一次性 `collectAssets` 写入 `data.images`。用户已确认资产生图在前，故"连线早于出图"在此 case 不成立。是否存在"连线后新增/改名资产导致快照过期"属另一类问题，本文不预设。

### 2.2 用户提供的真实镜头文本（实测案例，已确证）

用户提供了一段实际镜头 description，作为确证样本：

```
皮克斯3D风格,卡通骷髅角色,柔和蓝紫色调温馨喜剧氛围。
深夜@卧室内,柔和蓝紫色环境光从窗外透入,床头柜木质纹理清晰。
@骷髅A站在床边...右手举起@HKH精华瓶至胸前位置...
@骷髅B坐在床上...视线锁定@HKH精华瓶...
```

文本中出现的 `@` 引用：`@卧室`(场景)、`@骷髅A`(角色)、`@骷髅B`(角色)、`@HKH精华瓶`(道具，两处)。

**确证结论 A（代码级，无需再疑）：`@卧室` 一定被 `matchAsset` 漏收。**
`matchAsset(text,'卧室')` 检查 `@卧室` 后一位字符。文本为 `深夜@卧室内`，`@卧室` 后一位是 **`内`**（中文，`\u4e00-\u9fa5`）。边界规则要求"@名后一位必须是结尾或非中英数"，`内` 命中中文 → 返回 **false**。所以场景 `@卧室` 不被 collectAssets 收集，必然不垫图。**此点已从真实文本 + 代码确证，H1 不成立（场景确实被 `@` 了，只是被边界规则误杀 → 实为 H2）。**

**待澄清的矛盾点（由 §5.5 测试实证 + 用户实测共同解开）：**
按 §二 中重建的示例文本，`@骷髅A站`/`@骷髅B坐`/`@HKH精华瓶至` 后接中文本应也被判 false。**但用户实测：`骷髅A`/`骷髅B`/`HKH精华瓶` 实际都正常垫图**。二者不矛盾的关键：**文档 §2.2 的"真实镜头文本"是重建示例，并非运行时真正喂给 matchAsset 的那份字段**。运行时 collectAssets 扫描的是 `description+prompt+videoPrompt+dialogue` 合并文本，而角色/道具在这些字段里恰好都有 `@名` 后接非中英数（标点/空格/句尾）的命中点；场景 `卧室` 却因 `@卧室内`（后接中文 `内`）成为唯一被咬的资产。即：**边界规则 + 每资产"是否有安全边界"共同决定，纯属数据依赖**。

### 2.3 假设清单（按测试实证 + 用户实测修订）

| # | 假设 | 实证后状态 |
|---|---|---|
| H1 场景没 `@` | ❌ **已证伪**：文本确有 `@卧室` |
| H2 `@名`后紧跟中文被边界规则误杀 | ✅ **机制已证真**：`matchAsset` 遇 `@卧室`+`内` 返回 false（测试复现）；**但对角色/道具当前不生效**——用户实测其 `@名` 在运行时文本里都有安全边界 |
| H3 资产名与 `@` 字面不一致 | ❌ 用户实测角色/道具能命中，说明 `name` 与 `@` 一致，H3 不成立 |
| H4 场景 imageUrl 为空 | ❌ 用户已否认 |
| H5 连线早于出图 | ⚠️ **独立偶发源**：连线时快照 `data.images` 一旦为空则永不补（§5.5-②）|
| H6 偶发根因 = 数据依赖 | ✅ **已证真**：是否漏收取决于该资产在合并文本里「是否每处 `@名` 后都是中英数」（§5.5-③）；当前数据里仅场景 `卧室` 触发 |

### 2.4 客观结论（已由测试实证 + 用户实测确认）

- 垫图收集 = "有图 + 合并文本里**至少一处 `@名` 后一位非中英数**"（事实1、2 + matchAsset 边界 + 遍历语义）。
- **场景 `卧室` 因 `@卧室内` 后接中文 `内` 被漏收，测试复现** —— 这是当前真实数据里唯一被咬的资产。
- **角色/道具当前正常**（用户实测）：其 `@名` 在运行时合并文本里都有安全边界。但它们并非结构性免疫——`matchAsset` 对它们是同一套规则，若某镜把 `@骷髅A` 直接写成 `@骷髅A站`，同样会被咬（测试证明该机制，属潜在风险）。
- 接收端 `PromptNode` 无 bug（事实4）。

### 2.4 修复方向（根因已锁 `matchAsset` 边界规则，待确认后实施）

**根因 = `matchAsset` 的边界规则过严**：要求 `@名` 后一位必须是"结尾或非中英数"，但真实剧本里 `@卧室` 后紧跟 `内`（中文）被误判为"更长的词"，导致场景漏收。

两个修复思路：

**思路 1（修 `matchAsset` 边界，推荐·治本）**：放宽边界判定。`@名` 后接中文时，应允许（中文常是名词后缀如"内/里/中/旁"），仅当后一位是**英文/数字且能续接成更长的字母数字串**时才视为"词的一部分"。或更简单：只要文本中存在 `@名` 即视为引用，去掉后一位限制。
  ```js
  export function matchAsset(text, name) {
    if (!text || !name) return false
    // 简化：存在 '@name' 即命中（场景 '@卧室内' 也能命中 '@卧室'）
    return text.includes(`@${name}`)
  }
  ```
  ⚠️ 此简化会让 `@骷髅` 也命中资产 `骷髅A`？不会——`includes('@骷髅A')` 要求完整名。但 `@骷髅` 单独不会误中 `骷髅A`（因为要完整 `@骷髅A`）。需回归测试避免子串误中（如资产 `瓶` 与 `@瓶身`）。

**思路 2（场景走独立宽松匹配，规避边界）**：`collectAssets` 中 scene 类不靠 `matchAsset`，改用"description 含场景名子串"或"scene 自动纳入"：
  ```js
  list.forEach((a) => {
    if (!a?.name || !a.imageUrl) return
    const isScene = a.category === 'scene'
    const hit = isScene ? text.includes(a.name) : matchAsset(text, a.name)
    if (hit) out.push({ id: `script-asset-${a.id}`, url: a.imageUrl, category: a.category })
  })
  ```
  场景用 `includes(场景名)`（如"卧室"出现在"@卧室内"即命中），不受边界规则误杀；角色/道具仍用严格 `matchAsset` 避免误中。

**需先核对再定方案**：请你确认 assets 里 `骷髅A`/`骷髅B`/`HKH精华瓶` 的 `name` 是否也让 `@名` 后接中文（如 `@骷髅A站`）。若是，则角色/道具其实也中招，说明你"其他都可以"是指提示词层面而非垫图注入，此时思路1（统一放宽）更彻底；若角色/道具 name 后接非中文、确能命中，则仅场景出问题，思路2 即可。

- 上述均不改动接收端 `PromptNode`。

## 三、剧本盒子数据流 · 契约检查

### 3.1 数据流（实测代码）

```
剧情 story
  → onGenerateScript(Ar)        → data.shots[] + data.assets[]（assets 仅含 prompt，无 imageUrl）
  → onGenerateAssetImage(Pr/Fr) → data.assets[].imageUrl
  → onGenerateShotPrompts(Ir)   → data.shots[].prompt / videoPrompt
  → onConnectShot(li)           → 新建 promptNode，data.images = collectAssets(shot, assets)   ← 收集点
  → promptNode.run()            → generateImage({ images: refUrls })                            ← 读 data.images
```

### 3.2 契约符合性（确证）

| 契约点 | 实测 | 结论 |
|---|---|---|
| `node.data.images` 作参考图源 | ✅ PromptNode 正确 `images: refUrls` | 接收端成立 |
| `asset.imageUrl` 为有图标志 | ✅ `collectAssets` 以 `a.imageUrl` 过滤 | 成立 |
| 9 回调端点签名 | ✅ 与地基文档一致 | 成立 |
| `@资产名` 软连接 | ✅ `matchAsset` 复刻官方 `Fa` | 成立 |
| `category` 语义 | ✅ 资产确有 `category`，`assetFolderOf` 按类归库 | ⚠️ 但 `collectAssets` 忽略 `category` |

### 3.3 契约空白（确证）

1. **`category==='scene'` 未被定义为"镜头级环境垫图"**：与"scene=角色站进去的完整空间"语义冲突，却要求与角色/道具一样显式 `@`。
2. **场景 `@` 软约束无代码兜底**：系统 prompt 要求"每镜必须 @场景"，但无强制/校验。
3. `collectAssets` 返回 `{id,url}` **丢弃 `category`**，不利调试与分层。

## 四、一句话结论

1. 缺陷①（右键重复）：已修，代码确证。
2. 缺陷②（场景不垫图）：**根因已用真实数据 + 测试双重确证（§5.5）**——`matchAsset` 边界规则误杀中文场景。真实镜头1 里场景 `卧室` 唯一的 `@` 是 `@卧室内`（后接中文 `内`），被判"更长词"→ 永远不匹配 → 永远垫不上；角色/道具因合并文本里**总有一处 `@名` 后是逗号**（如 `@骷髅A,`/`@骷髅B,`）而正常。**换图/换 URL 不影响结果，因为断点与图片无关、只在文本 `@` 匹配。** 修复方向：思路1 放宽 `matchAsset`（存在 `@名` 即命中）或思路2（scene 走 `includes` 宽松）。均不改接收端 `PromptNode`。
