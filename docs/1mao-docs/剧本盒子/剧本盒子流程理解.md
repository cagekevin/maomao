# 剧本盒子流程理解（以 UI 原型为骨架）

> **目的**：以 `剧本盒子原型.html`（可交互 UI 原型，95%）为**视觉骨架**，逐界面讲清「这个界面是什么、背后对应什么数据/引擎/链路」，让后续 AI 看着原型就能读懂剧本盒子整个运作。原型显示的是 UI 长什么样；本文补充它背后是什么。
> **素材**：UI 以原型为准；引擎/数据/连线以 `docs/33` + `docs/40` + `c_.jsx` 代码核实为准。**源码才是最终真相，原型只代表视觉形态。**
> **关系**：`docs/33`（理解全集）→ 本文（以 UI 为序的可视化理解）→ `docs/40`（引擎重构权威）。三者互补。

---

## 一、一句话定位

剧本盒子（`scriptBoxNode`）是画布里的**剧本编排复合节点**：输入一段剧情 → AI 生成「分镜序列 + 角色/场景/道具资产表」→ 为资产生成参考图 → 为每个分镜生成「生图提示词 + 生视频提示词」→ 通过 `shot-*` 手柄连到下游 `promptNode`（生图）/ `discountVideoNode`（生视频）产出成片。

```
剧情 → ①确认镜头 → ②准备资产 → ③合成提示词 → 连线 → 下游成片
     (分镜+资产)    (资产参考图)   (生图/生视频prompt)
```

- 节点 type：`scriptBoxNode`
- 渲染组件：`c_.jsx`（约 2800 行）
- 引擎（挂到 `node.data` 的回调）：`H_.jsx`
- 原型：`docs/剧本盒子/剧本盒子原型.html`（覆盖三步 UI + 设置弹窗 + 全屏）

## 二、数据模型（node.data）——原型每个界面读写的对象

剧本盒子的一切 UI 都是对 `node.data` 的读写。两个核心数组 + 一组配置：

### 2.1 `shots[]` 分镜数组（原型步骤1表格 / 步骤3卡片，每行/每卡一个）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `${节点id}-shot-${序号}`（生成）或时间戳（手加） |
| `index` | number | 分镜序号（1 起） |
| `duration` | string | 时长 `"Ns"`（原型时长秒输入 1~60，写回 `"Ns"`） |
| `description` | string | 画面描述；`@资产名` 是资产绑定标记（青色高亮） |
| `shotType` | string | 景别（原型下拉：大远景/远景/全景/中近景/近景/特写…） |
| `lighting` | string | 光影氛围（原型下拉：自然光/暖光/冷光/月光…） |
| `dialogue` | string \| array | **双态**：存储可为字符串，也可为数组。引擎 `Ar` 生成时是大模型返回的字符串（多行，行内用 `[台词\|角色]` / `[旁白]` / `角色: 文本` 格式）；UI 展示/编辑时 `at()` 解析成 `[{kind,role,text}]` 数组，写回时 `ot()` 序列化回字符串。运行时以数组为准 |
| `sound` | string | 音效（原型下拉） |
| `motion` | string | 运镜（原型下拉：推/拉/摇/移/跟/升降…） |
| `prompt` | string | 生图提示词（步骤3生成，仅可见画面，不含对白音效） |
| `videoPrompt` | string | 生视频提示词（步骤3生成，以 `【时长 N秒】` 开头） |
| `promptLoading` | boolean | 步骤3生成中标记 |
| `gridMode` | number | 宫格模式（0单图/4四宫格/9九宫格，原型步骤3宫格按钮） |

### 2.2 `assets[]` 资产数组（原型步骤2资产卡，按类分三栏）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `${节点id}-asset-${序号}` |
| `category` | `character`\|`scene`\|`prop` | 角色/场景/道具（决定原型三栏分组） |
| `name` | string | 资产名（`@名称` 引用依据；改名联动见 §7.5 `J` 函数） |
| `description` | string | 主体外观描述（原型抽屉里可编辑） |
| `prompt` | string | 生成参考图的完整提示词（`Zg` 拼装；原型抽屉里可编辑） |
| `imageUrl` | string | 参考图 URL（本地化到 `/files/`） |
| `thumbnailUrl` | string | 缩略图 URL |
| `loading` | boolean | 生成中标记 |
| `videoStatus` | string | 视频上传状态（原型徽标：uploading/failed/uploaded） |

### 2.3 配置字段（原型齿轮设置弹窗读写）

| 字段 | 说明 |
|---|---|
| `step` | 当前步骤 1/2/3 |
| `story` | 用户输入剧情（原型步骤1剧情框） |
| `globalStyle` | 全片统一风格（原型「统一风格」输入框 + 预设 chips） |
| `shotCount` | 分镜数量（原型步骤1档位：自动/10/20/30/50/自定义） |
| `aspectRatio` / `customAspectRatio` | 下游宽高比（原型设置弹窗「画面比例」） |
| `imageGlobalConstraint` / `videoGlobalConstraint` / `customGlobalConstraint` | 生图/生视频全局约束（原型设置弹窗两个约束框） |
| `customScriptPrompt` | 自定义剧本生成提示词（原型设置弹窗「剧本生成提示词」） |
| `customShotPrompt` | 自定义分镜提示词生成提示词（原型设置弹窗「分镜/视频提示词生成」） |
| `customAssetTemplates` | 资产生成模板（原型设置弹窗「角色参考模板」） |
| `assetModelSettings` | 资产生图模型设置（`globalModel/globalAspectRatio/globalSize`） |

## 二·五、单一数据源机制（核心，务必先读）

> **一句话**：`node.data` 是剧本盒子的**唯一数据源（唯一真相）**。引擎写、组件读、编辑写——**所有读写都汇聚到 `node.data`**，且全部用**不可变更新**（新数组/新引用），绝不产生第二份数据副本。

### 为什么必须单一数据源

剧本盒子数据会被**三方**操作：引擎生成、组件编辑、连线读取。若各自维护一份拷贝，必然互相覆盖/失同步（这正是 `docs/33` 强调"数据只存 node.data"的原因）。真实代码用一套统一的"写回通道"锁死唯一性。

### 写回通道（两条，最终都落到 `node.data`）

| 来源 | 写回函数 | 机制 | 代码 |
|---|---|---|---|
| **引擎生成**（`Ar/Pr/Fr/Ir`） | `K` = `setNodes` setter | 构造 `{...t, data:{...t.data, shots:y, assets:C, ...}}` **整体替换** shots/assets 引用，触发 React 重渲染 | H_.jsx L5367-5389 |
| **组件编辑**（改字段/改名/对白） | `He` / `J`（内部用 `r` = `updateNodeData`） | `updateNodeData(id, {shots: f.map(...)})` 把更新后的 shot/assets **整体写回** | c_.jsx L234(L248) L15 |

### 读（组件）——永不写

- `c_.jsx` 通过 `let d = t`（data prop）读 `node.data`，`shots/assets` 用 `useMemo` 派生（`d.shots||[]`、`d.assets||[]`，依赖 `[d.shots]`/`[d.assets]` **引用变化**触发重渲染）。
- 组件**从不在本地拷贝** shots/assets，只在渲染时派生。
- 组件唯一局部 state：`v`（story 输入框），但提交时传给引擎，**不是数据源**。

### 引擎回调注入（让组件能触发引擎）

- 引擎回调（`onGenerateScript` 等）在**节点创建时**（H_.jsx L8734）和**运行注入**（L1149-1170）挂到 `node.data.onXxx`。
- 组件只调 `d.onGenerateScript?.(e, ...)`，不关心实现；引擎内部再通过 `K` 写回。

### 为什么这样设计（对引擎重构的意义）

- **UI（`c_.jsx`）对引擎（`H_.jsx`）零耦合**：组件只读写 `node.data`，改引擎不碰 UI。
- **引擎拆独立文件时**（`docs/40` Step 2），`createScriptBoxEngine(deps)` 的 `deps` 必须包含 `K`（setNodes）和 `updateNodeData` 这两个写回通道，否则引擎无法把结果写回 `node.data`。
- 任何新数据（loading、进度、错误）都经 `{...data, field}` 追加到 data，**不新增全局状态**。

### dialogue 双态转换（at / ot）

- `shot.dialogue` 存储形态不固定：**字符串**（引擎产出）或**数组**（编辑后序列化）。
- `at(dialogue)`（c_.jsx L567）：把任意形态**解析成数组** `[{kind,role,text}]`，识别多种行格式（`[台词|角色]text`、`[旁白]text`、`台词(角色): text`、`角色: text`、裸文本）。
- `ot(arr)`（c_.jsx L627）：把数组**序列化回字符串**，编辑后写回。
- **影响**：理解文档 §5/§7 里凡是"读对白"都先过 `at`；凡是"写对白"都先过 `ot` 再进 `updateNodeData`。

## 三、三步状态机（原型顶部圆环导航）

原型顶部三步圆环进度，**可点击切换，但三步是三个独立按钮，不会自动连跑**：

| 步骤 | 标题 | 进度含义 | 主要动作（触发引擎） |
|---|---|---|---|
| 1 | 确认镜头 | 有镜头即 1 | 输入剧情 → `onGenerateScript`（`Ar`）生成分镜+资产 |
| 2 | 准备资产 | 已出图/总资产 | `onGenerateAssetImage`（`Pr`）/批量 `onGenerateAllAssetImages`（`Fr`）生成参考图 |
| 3 | 合成提示词 | 已生成/总提示词分镜 | `onGenerateShotPrompts`（`Ir`）为每镜生成生图+生视频提示词 |

> **UI 落点**：原型 `.steps` 区域 = 顶部圆环导航；点击切换 `step` 渲染对应视图（`renderV1/V2/V3`）。

## 四、三层数据的产生时序（关键澄清，常被误解）

| 数据 | 何时产生 | 独立请求 | 并行/串行 |
|---|---|---|---|
| `asset.prompt`（资产参考图提示词） | **步骤1** `Ar` 返回时 `Zg()` 同步拼好 | 否（内嵌剧本响应） | 串行，零额外请求 |
| `asset.imageUrl`（资产参考图） | **步骤2** `Pr`/`Fr` | 是（每资产一个图生图 `Mr`） | 并行（`Promise.all`） |
| `shot.prompt` / `shot.videoPrompt`（分镜提示词） | **步骤3** `Ir` | 是（每分镜一个文本请求） | 并行（`Promise.all`） |

> **一句话**：步骤1 只产出 `shots` + `assets`（含 `prompt`），**不产出** `imageUrl`，也**不产出**分镜的 prompt/videoPrompt。后面两步要手动触发。
> **影响**：`Promise.all` 全量并行无并发上限，N 大时对上游瞬时高并发，注意限流。

## 五、原型界面逐块 → 背后的引擎/链路

### 5.0 顶部导航（原型 `.hd` + `.steps`）

- 左上标题「剧本盒子」；右上 **齿轮 ⚙️**（开设置弹窗）、**全屏 ⤢**、**生成中计时**（`⟳ 生成中 Xs`）。
- 齿轮 = 读 `data.customScriptPrompt/customShotPrompt/customAssetTemplates/各约束/aspectRatio`。
- **代码**：c_.jsx L2526-2535（设置/全屏按钮）；计时由引擎生成中置 `loading` 驱动。

### 5.1 步骤1 确认镜头（原型 `renderV1`：左控制区 + 右分镜表格）

**左侧控制区（`kt`）**，自上而下：
- **统一风格**：输入框 `globalStyle` + 预设 chips（原型 styleChips）
- **剧情**：textarea（可全屏，双击/右下角按钮）
- **镜头数量**：档位 `自动/10/20/30/50` + 自定义 number（1~300）
- **模型**：下拉选文本模型
- **生成按钮** → `onGenerateScript`（`Ar`）

**右侧分镜表格（`jt`）**：
- 真实 `c_.jsx` 表头 **8 列**：`镜号/时长/画面描述/景别/光影氛围/对白/旁白/音效/运镜`（原型为 9 列，多「操作」，**以代码为准**）
- 列宽可拖（`lt` 状态）；每页 10 镜分页
- 行内：镜号只读；时长秒 input；画面描述可编辑含 `@资产名`；景别/光影/对白/音效/运镜下拉或点击弹层

### 5.2 步骤2 准备资产（原型 `renderV2`：三栏资产 + 右侧抽屉）

- **三栏分组**：按 `category` 分 角色/场景/道具（原型 CATS）。每栏资产卡：缩略图 / 名称 / 描述 / 生成参考图按钮 / 视频上传状态徽标 / 批量生成按钮。
- **顶部工具栏**：统一风格输入框 + 统一生图模型下拉 + `上传全部素材`（`onUploadAllVideoAssets`/`ai`）+ `批量生成`（`onGenerateAllAssetImages`/`Fr`）。
- **右侧抽屉（`Ct`）**：点资产卡弹出，编辑 名称/主体描述/完整生图提示词 + `从资源选择` / `用此提示词生成`（`onGenerateAssetImage`/`Pr`）。

### 5.3 步骤3 合成提示词（原型 `renderV3`：列表/单镜头双视图）

- 顶部 tab：`列表`/`单镜头`（`le` 状态，持久化 localStorage `script-box-view-${id}`）。
- 列表模式右侧批量操作：`⚡提示词 / 连接生图 / 连接视频`。
- **列表视图**：每个分镜一张卡，卡片两栏——左「生图」（标题 + 宫格按钮单图/四宫格/九宫格 + 可编辑生图提示词），右「生视频」（标题 + 可编辑生视频提示词）。
- **单镜头视图**：聚焦单镜，含 引用资产缩略图条 / 时长 / 景别 / 运镜 / 光影 / 音效 / 对白旁白 / 画面描述 / 生图(宫格) / 生视频。

### 5.4 齿轮设置弹窗（原型 `openSettings`）

单页 6 区块（真实线上为单页，与官方一致）：
1. **画面比例**（16:9/9:16/4:3/3:4/1:1/自定义）
2. **生图限制约束** / **生视频限制约束**（两个并排框）
3. **剧本生成提示词**（`customScriptPrompt`，[填入默认]）
4. **分镜/视频提示词生成**（`customShotPrompt`，[填入默认]）
5. **角色参考图模板**（`customAssetTemplates.character`，[填入默认]）
6. **场景参考图模板**（`customAssetTemplates.scene`，[填入默认]）
7. **道具参考图模板**（`customAssetTemplates.prop`，[填入默认]）
   > 注：官方参考模板共 3 个（角色/场景/道具），各独立 textarea + 各自「填入默认」。

## 六、专属生成引擎（挂到 `node.data` 的回调）

| 回调 | data 字段 | 引擎 | 作用 |
|---|---|---|---|
| 生成剧本 | `onGenerateScript` | `Ar` | 剧情 → shots+assets+globalStyle+projectName |
| 生成单个资产图 | `onGenerateAssetImage` | `Pr` | 单资产 → 参考图并本地化 |
| 批量生成资产图 | `onGenerateAllAssetImages` | `Fr` | 并行生成参考图 |
| 生成分镜提示词 | `onGenerateShotPrompts` | `Ir` | 每分镜 → prompt + videoPrompt |
| 停止单项 | `onStopScriptItem` | `Un` | 中止指定生成（AbortController） |
| 重试视频上传 | `onRetryVideoAssetUpload` | `oi` | 单失败资产重新上传 |
| 批量上传视频资产 | `onUploadAllVideoAssets` | `ai` | 全部资产上传到视频网关 |
| 连接单分镜 | `onConnectShot` | `li` | 建下游 promptNode/discountVideoNode 并连线 |
| 连接全部分镜 | `onConnectShots` | `ui` | 批量建下游节点 + 分组容器 |

### 引擎链路（各引擎走哪条请求）

- **`Ar`（步骤1 剧本）**：`Bl` → `/v1/chat/completions`（SSE 流式）→ `/api/proxy` → 网关 → Lovart。system = `customScriptPrompt`(或默认编剧模板) + 镜头数要求 + `globalStyle`；user = 剧情原文。
- **`Pr`/`Fr`（步骤2 资产图）**：调 `Mr`（图生图引擎）→ OpenAI `/v1/images/generations` 或 Gemini `generateContent` → 本地化 `ci/hi`（`/files/migrated/人物|场景|道具/`）+ 缩略图 `mi`。
- **`Ir`（步骤3 分镜提示词）**：每分镜一条 `/v1/chat/completions`，system = `customShotPrompt`(或默认导演模板) + `Qg`(不可覆盖规则)，user = `Nr(分镜,资产,风格)` + 各约束。并行 `Promise.all`。
- **`ii`（视频素材上传）**：连生视频节点前，把命中的资产图经 `wr` 上传到视频网关换远程 URL，回填下游 `uploadedAssets`。

### 单发 vs 批发：触发参数（`c_.jsx` 怎么调）

> **核心**：单发和批发是**同一个引擎**，靠**参数形态**区分（引擎 `Ir/Fr` 内部用 `n`（单id）/`i`（数组）/undefined 分派）。没有两套引擎。

| 操作 | c_.jsx 调用 | 参数 | 引擎行为 |
|---|---|---|---|
| 单镜生成提示词 | `onGenerateShotPrompts(e, a.id)` L2255 | 第2参=**单 id** | `Ir` 只处理该镜 |
| 单镜重新生成 | `onGenerateShotPrompts(e, t.id)` L1825 | 单 id | 同上 |
| 批量提示词 | `onGenerateShotPrompts(e, undefined, t)` L2144 | 第2参=undefined, 第3参=**数组** | 处理选中或全部 |
| 批量资产生图 | `onGenerateAllAssetImages(e, n)` L1143 | 第2参=资产id数组或 undefined | `Fr` 处理选中或全部无图 |
| 单资产生图 | `onGenerateAssetImage(e, t.id)` L1224/L1393 | 第2参=资产 id | `Pr` 处理单资产 |

**`Ir` 分派逻辑（H_.jsx L5817-5821）**：
```
n ? 过滤单镜(id===n) : (i?.length ? 过滤数组(i.includes(id)) : 全部)
```
**`Fr` 分派逻辑（H_.jsx L5790-5794）**：
```
选中数组 ? 过滤选中 : 全部「无 imageUrl 的资产」（自动跳过已出图）
```

> ⚠️ **并发**：`Ir`/`Fr` 都用 `Promise.all` **全量并行**，无并发池/限流。镜头数或资产多时对上游瞬时高并发（`docs/40` 已知风险）。

## 六·五、提示词模板 → 发送 → 生成（每个模板用在哪、怎么发、生成什么）

> **核心认知**：6 类提示词模板里，**只有 3 个会"发"出去（文本 chat 请求），3 个只是"拼接"（不发请求）**。别把"模板"都当成"发出去的提示词"。

### 模板清单与去向

| # | 模板 | 字段 | 环节 | 是否发送 | 发送形式 |
|---|---|---|---|---|---|
| 1 | 剧本生成提示词 | `customScriptPrompt` | 步骤1 | ✅ 发文本 | chat system |
| 2 | 分镜/视频提示词生成 | `customShotPrompt` | 步骤3 | ✅ 发文本 | chat system |
| 3 | 角色参考图模板 | `customAssetTemplates.character` | 步骤2 | ⚪ 不发，拼接 | 拼进 `asset.prompt` |
| 4 | 场景参考图模板 | `customAssetTemplates.scene` | 步骤2 | ⚪ 不发，拼接 | 拼进 `asset.prompt` |
| 5 | 道具参考图模板 | `customAssetTemplates.prop` | 步骤2 | ⚪ 不发，拼接 | 拼进 `asset.prompt` |
| 6 | 生图/生视频限制约束 | `imageGlobalConstraint`/`videoGlobalConstraint` | 步骤3 | ⚪ 不发，拼接 | 追加进 chat 的 user |

### 逐条链路

**① 剧本生成提示词（customScriptPrompt）→ 发 chat → 产出分镜+资产**
```
步骤1点生成 → onGenerateScript → Ar
Ar: system = customScriptPrompt(或默认编剧模板) + 镜头数要求 + globalStyle
    user   = 剧情原文
→ POST /v1/chat/completions (SSE流式, json_object)
→ 返回 JSON { shots[], assets[], globalStyle, projectName }
   （此时 asset.prompt 已由 Zg 用参考图模板拼好，不额外请求）
```

**② 分镜/视频提示词生成（customShotPrompt）→ 发 chat → 产出最终生图/生视频提示词**
```
步骤3点生成 → onGenerateShotPrompts → Ir
Ir(每个分镜一条，并行 Promise.all):
    system = customShotPrompt(或默认导演模板) + Qg(不可覆盖规则)
    user   = Nr(分镜,资产,风格) + imageGlobalConstraint / videoGlobalConstraint
→ 每条 POST /v1/chat/completions
→ 返回 { prompt, videoPrompt } → 存到 shot.prompt / shot.videoPrompt
```

**③ 角色/场景/道具参考图模板 → 不发文本，拼进资产图请求**
```
步骤1: Zg(category, desc, globalStyle, customAssetTemplates)
       = [视觉风格：xx] + 描述 + 。 + 参考图模板 → asset.prompt
步骤2点资产生成 → onGenerateAssetImage → Pr → Mr(图生图)
Mr: prompt = asset.prompt
→ OpenAI /v1/images/generations 或 Gemini generateContent（发的是【图像】请求，不是文本）
→ 返回图片 → ci/hi 本地化 → asset.imageUrl / thumbnailUrl
```

**④ 生图/生视频约束 → 拼进步骤3的 prompt**
```
imageGlobalConstraint  追加到 Ir 请求的 user（影响 prompt）
videoGlobalConstraint  追加到 Ir 请求的 user（影响 videoPrompt）
```

### 一句话记忆

- **发文本 chat 的**：`customScriptPrompt`（步骤1）、`customShotPrompt`（步骤3）
- **不发请求、只拼接的**：3 个资产参考图模板（拼成 `asset.prompt`）、2 个约束（拼进 chat user）
- **真正的"生成"**：资产参考图走**图像请求**（Mr）；分镜生图/生视频提示词走**文本请求**（Ir）

## 六·六、逐步交互流细节（每个引擎从点按钮到写回的全过程）

> 这一节把「框架」落到「细节」：每个引擎点按钮后**逐环节**发生什么。基于 `c_.jsx` 触发点 + `H_.jsx` 引擎实现核实。

### ① 步骤1 剧本生成（`Ar`，H_.jsx L5164）

```
点「生成分镜脚本」按钮
→ onGenerateScript(e, v, Ve)   // e=节点, v=story, Ve=触发者标识 (c_.jsx L333)
→ Ar:
  1. 校验: 找节点; 取 story / shotCount / globalStyle / 模型 / customScriptPrompt
  2. 校验模型: 不在模型列表 → k(提示); 无 API Key → k(请先配置) 并 return
  3. 拼接 system = customScriptPrompt(或内置编剧模板) + 镜头数要求 + globalStyle
  4. K() 写回 data: {loading:true, step:1}   ← 触发组件显示「生成中」遮罩
  5. Bl → POST /v1/chat/completions (SSE流式, json_object), user=story
  6. 流式读 delta.content 逐段累积
  7. 流结束 → 去掉 ```json 围栏 → 截取 {…} → JSON.parse
  8. 解析失败 → 提示重试; 成功 → 对 shots 补默认字段(duration/shotType等)、assets 补默认(Zg 拼 prompt)
  9. K() 整体写回: {shots:[...], assets:[...], globalStyle, projectName, loading:false, step:1}
  → 组件 useMemo([d.shots]) 刷新 → 右侧分镜表格出现新数据
```

**细节要点**：
- 生成中：**全节点遮罩**（`data.loading`）+ 右上角计时（`generateStart`/`generateEnd`）。
- 校验失败或解析失败：遮罩清除 + `k()` 顶部提示，**不写回任何数据**。
- AbortController：`zt.current.set("generateScript", ac)`，停止走 `onStopScriptItem`→`Un` abort。

### ② 步骤2 单资产参考图（`Pr`，H_.jsx L5635）

```
点资产卡「生成」/抽屉「用此提示词生成」
→ onGenerateAssetImage(e, t.id)   // e=节点, t.id=资产id (c_.jsx L1224/L1393)
→ Pr:
  1. 找节点 → 找资产 (id===t); 无 → return
  2. 解析模型: data.assetModelSettings.globalModel; 若是指派调度 → ka(模型)解析 → xa()找启用项 → Aa()取首个
  3. 取 aspectRatio(默认16:9) / size(默认2K)
  4. K() 写回 assets[{id, loading:true}]   ← 资产卡转圈
  5. 拼 prompt: i.prompt 有值 → Yg(i.prompt, globalStyle)   // 用户改过就用 Yg 包装
                  无值 → Zg(category, [name,desc]join'，', globalStyle, customAssetTemplates)  // 默认模板拼装
  6. Mr(prompt, {model, aspectRatio, imageSize, noProxy, signal})  → 图像请求
  7. 成功: 本地化 — 远程URL→ci(subfolder='migrated/人物|场景|道具') + mi(缩略图 maxDim480); 或blob→hi
         本地化失败 → console.warn 回退原始地址 f
  8. K() 写回 assets[{id, loading:false, imageUrl:f, thumbnailUrl:p}]
  → 资产卡显示缩略图
```

**细节要点**：
- **单个/批量共用 `Pr`**：`Fr` 批量只是 `Promise.all(r.map(a => Pr(e, a.id)))`。
- **prompt 优先级**：资产已编辑过 prompt（`i.prompt` 非空）→ 用 `Yg` 包装（保留用户内容+风格）；未编辑 → `Zg` 用模板现拼。**所以手动编辑过的资产，参考图模板不生效**。
- 本地化目录按类别：`migrated/人物`(character) / `migrated/场景`(scene) / `migrated/道具`(prop)。
- AbortController key：`${e}_asset_${t}`。

### ③ 步骤3 单/批量分镜提示词（`Ir`，H_.jsx L5804）

```
单镜: 点「生成提示词」→ onGenerateShotPrompts(e, shotId)          (c_.jsx L1825/L2255)
批量: 勾选镜头点「⚡提示词」→ onGenerateShotPrompts(e, undefined, [ids])  (c_.jsx L2144)
→ Ir:
  1. 找节点; 取 shots/assets/globalStyle/globalConstraints/imageGlobalConstraint/videoGlobalConstraint
  2. 分派目标: n(单id)?过滤单镜 : i(数组)?过滤选中 : 全部        ← 单发vs批发唯一区别在这
  3. 校验: 无分镜 → k("没有可生成的分镜"); 模型非法 → 提示; 无 API Key → 提示
  4. 拼 system = customShotPrompt(或默认导演模板) + Qg(不可覆盖规则)
  5. K() 写回 shots[命中].promptLoading:true   ← 卡片转圈
  6. Promise.all(每个分镜):
     a. 拼 user: Nr(分镜, 资产(按 @名 Fa匹配), globalStyle)
        + [imageGlobalConstraint → 生图约束]
        + [videoGlobalConstraint ?? globalConstraints] → 生视频约束
        + [videoPrompt 硬性要求: 必须以「【时长 N秒】」单独一行开头]
     b. AbortController key `${e}_shot_${shotId}` 存 zt
     c. Bl → POST /v1/chat/completions {model, messages:[system,user], temperature:0.7, json_object(非deepseek/claude)}
     d. 非ok → 清理abort, 抛错(401/403→未登录, 其他→API Error+状态码+前120字符)
     e. json → 去围栏 → 截取{…} → 得 {prompt, videoPrompt}
     f. K() 写回该镜: {prompt, videoPrompt, promptLoading:false}
  7. 单镜失败: 清理abort, K() 写回 promptLoading:false (该镜转圈停, 不影响其他)
```

**细节要点**：
- **单发/批发同一 `Ir`**，只是参数 `n` vs `i`。
- **每镜独立请求 + 独立 AbortController**，失败互不影响。
- **`Fa` 按 @资产名 匹配**当前镜引用的资产 → 传给 `Nr` 让模型知道该镜有哪些资产。
- `temperature:0.7`；`json_object` 仅非 deepseek/claude 时用。
- videoPrompt 强制以 `【时长 N秒】` 开头（单行）。

### ④ 停止生成（`Un`，中止）

- 所有生成（Ar/Pr/Ir/上传）都注册 AbortController 到 `zt.current`（key 见上）。
- `onStopScriptItem(e, key)` → `Un` → `zt.current.get(key)?.abort()` + 清除 loading + 删 key。
- 遮罩「停止」按钮 → `stopGen()` → `onStopScriptItem`。

### ⑤ 连线（`li` 单镜 / `ui` 批量）

- 单镜 source 手柄 `shot-{shotId}` → 拖到下游 promptNode/discountVideoNode。
- `li`(单) 建下游节点 + 边 + 预填（宽高比/时长/selectedSeconds/durationFromScript）。
- `ui`(批量) 建多个下游 + 分组容器。
- 生视频节点连接时触发 `ii` 上传命中资产图（详见 §7）。

## 七、@连线机制（核心，易误解）

### 7.1 核心结论

> **资产图不是靠真实连线连到下游的，而是靠「`@资产名` 文本匹配 + 下游生成时动态收集」。**

- 分镜文本（`description/prompt/videoPrompt/dialogue`）里写 `@资产名` = **软连接标记**。
- 下游生图/生视频时：`Fa`（shared.js，匹配 `@资产名`，防 `@小红帽` 误匹配 `@小红帽子`）→ `Ra`（shared.js，收集命中且有 `imageUrl` 的资产为参考图）。
- **没写 `@` 或资产没出图 → 带不上参考图。**

### 7.2 连接 vs 资产生成解耦

- **连接动作 = 无条件自动建立**（创建下游节点 + 连线 + 预填宽高比/模型）。
- **带参考图 = 依赖资产已生成图**（有 `imageUrl`）。

### 7.3 生图 vs 生视频差异

- **生图（promptNode）**：连接不触发上传；资产图靠生成时 `Ra` 动态收集。
- **生视频（discountVideoNode）**：连接时触发 `ii` 把命中资产图上传到视频网关换远程 URL，回填下游 `uploadedAssets`。

### 7.4 连线到下游预填

- 每个分镜右侧 source 手柄 `shot-${分镜id}`（`Kt`）。
- 从 `shot-*` 拉出的边**只允许**连 `promptNode` 或 `discountVideoNode`。
- 连接时预填：宽高比（`4:4`→`1:1`，`custom`→`customAspectRatio`）；视频额外预填 `selectedSeconds`（分镜时长）+ `durationFromScript:true`。

### 7.5 资产改名联动（`J` 函数）

- 真实代码 `J(t, n)`（c_.jsx L248）：改资产 name 时，用 `s = e => e && e.split(旧名).join(新名)` **全局替换**（不只 `@旧名`，是替换所有出现该名字的文本）到所有分镜的 `description/prompt/videoPrompt/dialogue`，以及该资产自己的 `prompt`；然后 `updateNodeData` 整体写回。
- 与原型差异：原型 `renameAsset` 用 `@旧名` 正则（只替换带 `@` 前缀的），**更精确**（避免误替换正文里的同名词）；真实 `J` 用 `split/join`（替换所有出现）。以代码为准，但原型的精确替换更符合 `@资产名` 引用约定，接入时可保留。
- **单一数据源体现**：改名也是走 `updateNodeData`（`r`）写回 `node.data`，不是组件本地改。

## 九、一句话速记（给后续 AI）

1. **三步串行、手动点**：步骤1→2→3 独立按钮，不会自动连跑。
2. **三层数据时序不同**：`asset.prompt` 步骤1同步拼好（零请求）、`asset.imageUrl` 步骤2每资产一请求并行、`shot.prompt/videoPrompt` 步骤3每分镜一请求并行。
3. **`@资产名` 是软连接**：靠文本匹配 + 生成时 `Fa`/`Ra` 动态收集，不是真实连线；没写 `@` 或没出图就带不上。
4. **引擎链路**：`Ar`(剧本)/`Pr`,`Fr`(资产图)/`Ir`(分镜提示词)/`ii`(视频上传)，走 `/api/proxy` → 网关 → Lovart。
5. **单一数据源**：`node.data` 是唯一真相；引擎经 `setNodes(K)`、组件编辑经 `updateNodeData` 都不可变更新写回，组件 `useMemo` 从 data 派生读，无第二份数据。
6. **UI 不直接写 data**：组件只调 `d.onXxx?.(...)` 走引擎，改引擎（`H_.jsx`）对 UI（`c_.jsx`）零改动；`dialogue` 是双态（字符串/数组），读走 `at`、写走 `ot`。
