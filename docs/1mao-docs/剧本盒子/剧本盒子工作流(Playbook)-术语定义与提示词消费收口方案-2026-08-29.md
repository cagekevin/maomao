## 一、命名裁定（最高优先，先读本节）

### 1.1 裁定结果

| 项 | 取值 |
|---|---|
| **中文正式名** | **剧本盒子工作流** |
| **代码标识符** | `playbook`（❌ 禁用 `workflow` 作任何标识符） |
| **存储键** | `scriptbox_playbooks` |
| **节点字段** | `playbookId`（替换现行 `workflowId`） |
| **预设常量** | `SCRIPT_BOX_PLAYBOOKS` |
| **Store 文件** | `src/components/scriptbox/scriptBoxPlaybookStore.js` |
| **解析层文件** | `src/components/base/scriptBoxPromptResolver.js` |

### 1.2 为什么代码里禁用 `workflow`

系统内已存在一个**同名但完全无关**的后端概念，混用会导致后续 AI 与开发者误判：

```627:627:src/components/base/contracts.js
  workflowApps:          { fn: '(前端零消费)',                          method: 'GET',    path: '/api/workflow-apps/by-project/{id}', envelope: 'stub', status: 'RESERVED' },
```

`/api/workflow-apps/` 是**应用市场**域（后端空壳 stub，前端零消费），与剧本盒子的提示词预设毫无关系。若沿用 `workflow`，则 `grep -r workflow` 会同时命中两者，且 `contracts.js:576` 的 RESERVED 组注释会进一步误导。

### 1.3 为什么选 `playbook`

对象不是"提示词模板"，而是**一整套制片打法**：切一次 = 剧本生成 / 分镜提示词 / 审计改写 / 不可覆盖规则 / 资产生图模板 / 生图类型模板 / 约束 / 负面词 **八项同时换**。`preset`、`template`、`config` 都只表达"片段"，`playbook`（标准化打法手册）才表达"整套方法论"，且与"剧本"主题呼应。

**下文所有「剧本盒子工作流」均指本对象，代码一律写 `playbook`。**

## 二、审计结论（本次改动的依据）

### 2.1 全景：7 个生成入口

| # | 入口 | 请求位置 | system 来源 | user 来源 |
|---|---|---|---|---|
| ① | `onGenerateScript` 步骤1 | `scriptBoxEngine.js:233` | `customScriptPrompt` → `wf.script` → 常量 | **内联拼接** `:200-202`（无纯函数） |
| ② | `onGenerateShotPrompts` 步骤3 | `:514` | `customShotPrompt` → `wf.shot` → 常量，+ `qgRule` | `assembleShotUser` + 4 段追加 |
| ③ | `onGenerateShotImage` AI生图 | `:620` | `getImageGenSys(type, customImageGenTemplates)` | `buildShotImageUser` |
| ④ | `onReviewShotPrompt` 审计改写 | `:675` | `customAuditPrompt` → 常量（**漏 wf.audit**） | `buildAuditUser` |
| ⑤ | `onGenerateMergedVideo` 合并视频 | `:977` | `MERGE_VIDEO_SYSTEM`（**纯常量，无覆盖入口**） | `buildMergedVideoUser` |
| ⑥ | `onGenerateAssetImage` 资产生图 | `:360` | — | `asset.prompt` 或 `ZgPrompt` |
| ⑦ | `onGenerateTailFrameVariants` 尾帧变体 | `:1079` | — | `buildTailComposePrompt`（**全硬编码**） |

### 2.2 根因：两套互斥机制在打架

- **机制甲（回退链）**：引擎写 `data.customXxx || getWorkflow(id).xxx || 常量`，语义是「工作流 = **动态默认值**」。
- **机制乙（填表）**：`GearSettings.jsx:71-89` 的 `applyWorkflow` 把工作流值**填进文本框**，保存时固化进 `data.customXxx`，语义是「工作流 = **初始化模板**」。

后果：工作流定义改进后老节点永远享受不到；回退链形同虚设；切工作流后生效的是"固化值 + 错误兜底"的混合体。

**本方案两套都不要：取消覆盖层，单一数据源归 playbook**，见 §4.2。

> 保留任何一层覆盖，都意味着同一语义存在两处可写（playbook 本体 + 节点覆盖），**单一数据源即不成立**。
> 代价是失去「本片临时微调」能力，补偿路径见 §4.6。

### 2.3 缺陷清单

| 级 | 缺陷 | 位置 |
|---|---|---|
| P0 | 生图类型模板兜底**恒为漫剧**，与当前工作流无关 | `scriptBoxPrompts.js:496` |
| P0 | 审计提示词**缺 `wf.audit`** 一级，切工作流不跟着变 | `scriptBoxEngine.js:664` |
| P0 | `customGlobalConstraint` **保存一次即永久失效**（`??` 兜底被 `''` 顶掉） | `GearSettings.jsx:108` + `scriptBoxEngine.js:464` |
| P1 | system 回退链 **4 种形态**（三段/两段漏 wf/两段按 type/零段） | ①②③④⑤ 各异 |
| P1 | 约束与负面**只作用于 ②**，③④⑤⑥⑦ 完全不施加 | `scriptBoxEngine.js:509-510` |
| P1 | 漫剧特化的产品决策**硬编码**在通用函数（禁 NPC 入画、禁恋爱糖感特效、四段戏剧曲线、风格锚定、眼线锁定） | `scriptBoxEngine.js:1262-1263/1308/1312/1323-1324` |
| P1 | ① 的 user 是唯一不走纯函数的请求 | `scriptBoxEngine.js:200-202` |
| P1 | `mergeShotsForVideo` 的 `prompt` 返回值被丢弃 | `scriptBoxEngine.js:964` |
| P2 | schema **漏登记 7 个字段** | `scriptBoxSchema.js:13-31` |
| P2 | 死字段：`globalConstraints`（仅测试写）、`styleChips`（有读无写）、`customQGPrompt`（有读无写） | 见 §6.2 |
| P2 | `buildShotPrompts(shot, {imageConstraint, videoConstraint})` 死参数，唯一调用点不传参 | `scriptBoxPrompts.js:404/464` |

### 2.4 5 处 manga 硬绑定（最易复发的坑）

以下模块级常量把漫剧焊死为**所有工作流的第三级兜底**，新增第三套工作流也无法脱离：

```

scriptBoxPrompts.js:24   SCRIPT_WRITER_SYSTEM   = SCRIPT_BOX_WORKFLOWS.manga.script
scriptBoxPrompts.js:35   SHOT_DIRECTOR_SYSTEM   = SCRIPT_BOX_WORKFLOWS.manga.shot
```

**结论：工作流名义 2 套，实际 1.5 套——漫剧是地基，其余只是覆盖层。**

## 三、数据模型

### 3.1 Playbook 结构（一套 = 八项）

```js
{
  id: 'manga',                    // 稳定标识，内置项只读
  label: '漫剧',
  builtin: true,                  // 内置 vs 用户自定义（内置不可删改，只可另存为）
  script: '',                     // ① 剧本生成
  shot: '',                       // ② 分镜提示词
  audit: '',                      // ④ 审计改写
  qg: '',                         // ② 不可覆盖规则（追加在 shot 之后）
  assetTemplates: {},             // ⑥ 资产生图 { character, scene, prop }
  imageGenTemplates: {},          // ③ 生图类型模板 { [type]: { label, sys } }
  constraints: { image, video },  // ② 正向约束（无 custom 键，见 §4.3）
  negative: { common, image, video }, // ② 负面词（新增 common，见 §4.4）
}
```

### 3.2 节点字段（随画布走，不云同步）

**铁律：`node.data` 只存「本片内容」与「工作流选择」，不存任何提示词配置副本。**
任何一项提示词配置的唯一真相源 = 选中的 playbook，**无第二处可写**。

**A. 方法论层 —— 不存 node.data，一律读 playbook**

`script` / `shot` / `audit` / `qg` / `assetTemplates` / `imageGenTemplates` / `constraints` / `negative`

→ 现 `node.data` 上的 `customScriptPrompt`、`customShotPrompt`、`customAuditPrompt`、`customQGPrompt`、
`customAssetTemplates`、`customImageGenTemplates`、`imageGlobalConstraint`、`videoGlobalConstraint`、
`customGlobalConstraint`、`imageNegative`、`videoNegative` **全部删除**。

**B. 本片内容层 —— 存 node.data，per-node**

| 字段 | 语义 |
|---|---|
| `playbookId` | 选中的剧本盒子工作流 id |
| `playbookLabel` | 选中时的名称快照，供悬挂检测提示（§5.4） |
| `story` / `upstreamStory` / `globalStyle` | 本片剧情与风格 |
| `shotCount` / `customCount` | 本片分镜数 |
| `aspectRatio` / `customAspectRatio` | 下游宽高比（透传给下游节点） |
| `textModel` / `assetModelSettings` | 本片选用的模型 |
| `shots` / `assets` | 本片产出（**提示词生成结果在此，是快照**） |

> **划分判据**：「换一部片子要不要变」→ 要变 = 本片内容层（per-node）；不变 = 方法论层（playbook）。
> `globalStyle` 虽名为「风格」，但由 AI 生成、随剧情走、per-project，判为本片内容层。

## 四、收口规范

### 4.1 单一解析层（新增 `scriptBoxPromptResolver.js`）

所有入口**禁止**再自行拼回退链，一律经解析层：

```js
resolveSystem(playbookId, 'script' | 'shot' | 'audit' | 'qg')  // 单一数据源，无优先级链
resolveImageGenSys(playbookId, type)                            // 修 P0-1：取当前 playbook
resolveConstraints(playbookId)  // → { image, video }
resolveNegatives(playbookId)    // → { common, image, video }
```

### 4.2 单一数据源（无优先级链）

```
getPlaybook(playbookId)[key]
```

**没有第二级、没有回退、没有「留空即跟随」的隐式语义。** 引擎不再读取任何 `data.customXxx`——那些字段已被删除。

> 原「用户覆盖 → playbook → 内置常量」三级链**整体取消**。
> 保留任何一级覆盖，都会让同一语义存在两处可写，单一数据源即不成立。

**配套语义变更**：

| 对象 | 可写性 | 想改怎么办 |
|---|---|---|
| 内置（漫剧 / 达人种草） | **只读** | 「另存为」成自己的，再改 |
| 自定义 | **可写** | 直接改，保存写 `scriptbox_playbooks`，全局生效 + 云同步 |

切换 playbook = 换整套方法论，**不做任何值填充/清空**（已无覆盖层可操作）。

> 迁移影响：老节点 data 中已固化的 `customXxx` 需处置，见 §6.2。

### 4.3 约束：砍掉第三个框

`constraints` 去掉 `custom` 键，UI 删「自定义」框。理由：该框语义黑洞，实现上只是视频通道的 `??` 兜底且一保存即失效（P0-3）。

```
旧：imageGlobalConstraint / videoGlobalConstraint / customGlobalConstraint（+ 死数组 globalConstraints）
新：imageGlobalConstraint / videoGlobalConstraint，各自独立，留空即不注入
```

### 4.4 负面词：新增 `common`

硬编码的通用负面从 `assembleShotUser` 下沉到 playbook 配置。现状这一坨是**漫剧特化规则**（禁 NPC 入画、禁恋爱糖感特效），却强制所有工作流继承——「达人种草」里人群入画是正常需求。

```
negative.common   ← 承接 scriptBoxEngine.js:1324 的内容，manga 填原值，seeding 自定义
negative.image    ← 仅作用于 prompt
negative.video    ← 仅作用于 videoPrompt
```

### 4.5 各入口接入后的约束覆盖

| 入口 | 正向约束 | 负面 |
|---|---|---|
| ② 分镜提示词 | ✅ image / video 分通道 | ✅ |
| ③ AI 生图提示词 | ✅ image | ✅ image |
| ④ 审计改写 | ✅ 按 `field` 取对应通道 | ✅ 对应通道 |
| ⑤ 合并视频 | ✅ video | ✅ video |
| ① 剧本生成 | ❌（产出的是分镜描述，非提示词） | ❌ |

### 4.6 失去「本片临时微调」的补偿路径

覆盖层取消后，临时调整走这三条，**均不落盘到配置项**，因而不破坏单一数据源：

1. **生成后直接编辑** `shot.prompt` / `shot.videoPrompt`（`StepPrompt.jsx` 已支持）
2. **重新生成时带意见**：`onGenerateShotPrompts(shotIds, feedback)` 第二参（`scriptBoxEngine.js:448`），运行时参数不落盘
3. **沉淀为方法论**：确需长期复用 → 另存为新的 playbook

> **为何敢让 playbook 全局可写**：`shots[].prompt` / `videoPrompt` 是生成结果的**快照**（存于 `node.data.shots`），
> 改动 playbook 不会改写任何已生成内容，只影响「下次点生成」。这是取消覆盖层仍然安全的依据。

## 五、存储与云同步

### 5.1 存哪

用户自定义 playbook 存 **localStorage**（键 `scriptbox_playbooks`），**不随画布走**。

依据 —— 画布快照被云同步显式排除：

```14:15:src/components/base/cloudSync.js
 * 【不同步】画布/会话性/本机临时数据：
 *  - 所有项目画布快照（canvas-state-v1-*）：画布内容属业务数据，仅留在本机 localTool，不同步。
```

### 5.2 怎么做才自动进云同步

`contracts.js` 的纪律：

```405:407:src/components/base/contracts.js
  // 已统一从本表 getLocalKeys() 生成，禁止再手写清单（防漂移漏备份）：
  //   backupStore 全量导出；cloudSync 用 SYNC_EXCLUDE 显式排除
  // 新增本表 local 键即自动进入备份与同步。
```

即：**在 `STORAGE_KEYS` 登记 `backend: 'local'` 即自动获得云同步 + 全量备份**，`cloudSync.js` 一行都不用改。

登记要求：
- `backend: 'local'`
- 读写走 `storageAdapter`（sGet/sSet），**禁裸 localStorage**（`CLAUDE.md` §5.4.5，编译期 `npm run check:keys` + dev 运行时 `contentStore.checkRegistered` 双重拦截）

### 5.3 ⚠️ 领域开关陷阱

`SYNC_DOMAIN_SWITCHES` 里 `project: false`（防云端覆盖丢新项目，见 `cloudSync.js:286-289`）。未登记领域由 `domainSwitchEnabled` 默认放行（`cloudSync.js:292-296`）。

→ 本键**绝不能标 `domain: 'project'`**，标 `'settings'`。

### 5.4 悬挂引用处理（必须做）

节点只存 `playbookId` 字符串。若设备未同步或 playbook 被删，现行 `getWorkflow` 会**静默回退 manga**，用户无感知。

要求：节点额外记 `playbookLabel`；解析时未命中 → 显式提示「剧本盒子工作流「X」缺失，当前回退漫剧」，并在日志留痕。

### 6.2.1 ⚠️ 老节点 `customXxx` 的迁移（不可直接丢弃）

覆盖层取消后，老节点 data 里已固化的 `customXxx` 若直接删除，**等于丢弃用户此前的编辑**。

**策略：归一化时转存为自定义 playbook 副本**

1. 检测到某节点存在任一非空 `customXxx`
2. 按 `原 playbook + customXxx 覆盖` 合成完整配置
3. 写入 `scriptbox_playbooks`，`id = legacy-<hash>`，`label = 「<原工作流名> 副本」`
4. 节点 `playbookId` 指向该副本，清空 `customXxx`
5. 首次触发时 toast 提示：`检测到 N 个剧本盒子使用过自定义提示词，已转存为 N 个工作流副本，可在「管理」中合并或删除`

> 每个老节点各生成一个副本，可能重复——刻意选择：宁可让用户后续自行合并，也不静默丢弃数据。

### 6.3 验收标准

新增/更新单测（`tests/unit/`）：
- 解析层四函数：**只读 playbook，无任何回退**；断言「引擎不读 `data.customXxx`」（防覆盖层复活）
- 切换 playbook 后 ①②③④ 的 system 全部随之改变（锁死 P0-1/P0-2 回归）
- 约束/负面在三处入口的注入与不注入边界
- 悬挂 `playbookId` 触发显式降级而非静默回退
- `normalizeScriptBoxData` 迁移：`workflowId → playbookId`；非空 `customXxx` 转存 playbook 副本（§6.2.1），转存后节点 `customXxx` 必须为空

## 七、UI 形态设计

### 7.1 设计原则：可写性由「谁的」决定，不由位置决定

**没有覆盖层。** 设置面板里看到的就是 playbook 本体，改什么写什么，不存在「跟随 / 已覆盖」两态。

| 选中 | 各 Tab 可编辑 | 保存写入 | 顶部条文案 |
|---|---|---|---|
| 内置（漫剧 / 达人种草） | ❌ 只读 | — | `内置工作流 · 只读 · 想改请「另存为」` |
| 自定义 | ✅ 可编辑 | `scriptbox_playbooks`（全局 + 云同步） | `我的工作流 · 全局生效 · 已随云端同步` |

**只读态的实现**：所有 textarea 加 `disabled` + `opacity-60`，页脚「保存」按钮隐藏，仅保留「另存为」。
不做"可编辑但保存时提示"——那是让用户白干活的假可写。

> 为何敢让自定义可写：**已生成的 `shots[].prompt` / `videoPrompt` 是快照**（§4.6），改 playbook 不影响任何历史产出。

### 7.5 D · 另存为流程（沉淀路径）

```
┌─ 另存为我的工作流 ─────────────────────┐
│ 名称                                   │
│ [ 古风短剧___________________ ]        │
│                                        │
│ 基于：漫剧 + 本片 3 项修改              │
│ 保存后本片的这 3 项修改将被清空，        │
│ 改为跟随新工作流。                      │
│                        [取消] [保存]    │
└────────────────────────────────────────┘
```

要点：
- 取的是**当前编辑态**（含未保存改动），不是已落盘值——所见即所得
- 合并规则：`playbook 值` ← 被 `覆盖层非空值` 覆盖，逐字段合成新 playbook
- 保存后清空被合并进去的覆盖项，避免同一份内容两处冗余
- 名称校验：非空、不与内置同名、不与已有自定义重名

### 7.6 E · 删除与悬挂引用

删除前统计引用数（扫描所有 `scriptBoxNode` 的 `playbookId`）：

- 无引用 → 普通二次确认
- 有引用 → 警示：`有 N 个剧本盒子正在使用「X」，删除后它们将回退到漫剧。`

运行期悬挂（`playbookId` 指向不存在项）：按 §5.4，**不静默回退**，在 GearSettings 顶部显示缺失警示条 + `logger.warn` 留痕。
