# 剧本盒子职责划分（谁负责什么 / 谁不该做什么）

> **目的**：把剧本盒子这个功能拆成清晰的角色，讲清**每个角色负责什么、绝不做什么、依赖谁**，让后续 AI（尤其引擎重构时）不越界、不重复、不产生循环依赖。
> **素材**：基于真实代码核实（`c_.jsx`/`H_.jsx`/`shared.js`/下游 `As.jsx`/`bo.jsx`/`localTool`），与 `剧本盒子流程理解.md`（数据/流程）、`剧本盒子完整重构计划.md`（重构计划）、`docs/33`（探索全集）、`docs/40`（SOP）互补。
> **核心观**：**数据归 `node.data`，UI 只读不写，引擎只算不改渲染，纯函数无副作用**——职责即边界。

---

## 一、一句话职责观

> **`node.data` 是唯一数据源**；`c_.jsx` 只负责「读 data + 渲染 UI + 触发回调」；引擎回调只负责「算 + 用 setNodes/updateNodeData 写回 data」；`shared.js` 只提供无副作用纯函数；连线只负责「建节点/连边/预填」；真正取参考图是**下游节点**的事。谁都不碰不属于自己的数据。

---

## 二、角色职责总表

| 角色 | 载体 | 负责什么 | 绝不做什么 |
|---|---|---|---|
| **节点** | `scriptBoxNode` | 承载数据 `node.data`；在画布中存在、可选中/删除/复制；是剧本盒子的「身份」 | 不实现具体逻辑（逻辑在回调里） |
| **渲染组件** | `c_.jsx`（`_cmp_c_`） | 读 `node.data` → 渲染三步 UI；捕获用户输入（story/风格/模型/各字段）；调 `d.onXxx?.(...)` 触发引擎；编辑时经 `updateNodeData` 写回 | **绝不直接改 `d.shots/d.assets`**；不做生成/请求；不缓存 shots/assets 副本（只 useMemo 派生） |
| **专属生成引擎** | `H_.jsx`：`Ar/Pr/Fr/Ir/Un/oi/ai` | 生成剧本/资产图/分镜提示词；上传视频；中止任务；走 `/api/proxy` 发请求；结果用 `setNodes(K)` 写回 `node.data` | 不碰渲染 DOM；不产生独立数据副本；不做 UI 交互 |
| **引擎回调注入** | `H_.jsx` L8734/L1149/L1170 | 把引擎回调挂到 `node.data.onXxx`（创建时 + 运行时） | — |
| **纯函数层** | `shared.js`：`Fa/Ra/Ia/Zg/Xg/Qg/Yg` | 提供可复用的纯计算：`Fa`@资产匹配、`Ra`资产收集、`Ia`分镜→媒体提取、`Zg`资产生图提示词拼装、`Xg`资产模板常量、`Qg`不可覆盖规则 | **无副作用**：不读 `node.data`、不发请求、不 setState（`docs/40` 可安全抽取） |
| **连线** | `H_.jsx`：`li/ui/di` | 从 `shot-*` 手柄建下游 `promptNode`/`discountVideoNode` + 连边；预填宽高比/时长；批量建分组 | 不做参考图上传（那是下游/`ii` 的事） |
| **数据写回** | `setNodes(K)` / `updateNodeData(r)` | 引擎与编辑**唯一**的写回通道（不可变更新整体替换引用） | — |
| **下游节点** | `promptNode`（`bo.jsx`）/ `discountVideoNode`（`As.jsx`） | 生成时调 `Fa`/`Ra` 收集命中 `@资产名` 的参考图；生视频连 `ii` 上传资产图 | 不关心剧本盒子内部结构 |
| **中继** | `localTool`：`files.ts`/`system.ts` | `/api/files/upload` 本地化资产图；`/api/proxy` 转发文本/图片请求到网关 | 不参与剧本盒子业务逻辑 |

## 三、依赖方向（单向，避免循环）

```
c_.jsx (UI) ──读──▶ node.data ◀──写── H_.jsx (引擎, 经 K)
    │ 调 d.onXxx?.(...)                 │  经 deps 注入
    ▼                                   ▼
H_.jsx 引擎 ──调用──▶ shared.js 纯函数 (Fa/Ra/Zg/Qg…)   ← 纯函数不反向依赖任何人
H_.jsx 连线 ──建节点──▶ 下游 promptNode / discountVideoNode
下游生成 ──调──▶ shared.js 纯函数 收集参考图
引擎/组件 ──请求──▶ localTool ──转发──▶ 网关/Lovart
```

**依赖铁律**：
1. **UI 依赖引擎**（通过 data 回调），**引擎不依赖 UI**。
2. **纯函数层只被调用，不调用任何人**（无副作用 → 可安全抽取/复用/测试）。
3. **下游依赖 shared.js 纯函数，不依赖 scriptBox 内部**（解耦关键）。
4. **写回只走 `K`/`r` 两条通道**，不新增第三条，否则破坏单一数据源。

## 四、边界红线（谁不该做什么，易踩）

| 越界行为 | 后果 | 正确做法 |
|---|---|---|
| 组件直接 `d.shots.push(...)` | 改了引用但 React 不感知（useMemo 依赖引用）→ 不刷新 | 引擎经 `K`、编辑经 `updateNodeData` 整体替换 |
| 引擎回调里操作 DOM / 直接 setState 渲染 | UI 与引擎耦合，破坏可拆性 | 引擎只返回数据 + 写回 data |
| `shared.js` 纯函数读 `node.data` 或发请求 | 副作用破坏纯函数性，无法安全抽取 | 保持纯：入参出参，无 IO |
| 下游节点读 `scriptBoxNode` 内部私有结构 | 强耦合，改内部就崩下游 | 只调 `Fa`/`Ra` 通用纯函数 + 读 `node.data` 公开字段 |
| 引擎用局部变量长期持有数据副本 | 与 node.data 失同步（单一数据源被破坏） | 结果即刻经 `K` 写回 data |
| 复制 `data` 时用浅拷贝且共用子数组引用 | 一处改全部受影响 | 不可变更新 `{...data, shots:[...new]}` 保证新引用 |

## 五、与引擎重构的对应（职责 → 文件拆分）

`docs/40` 引擎拆 3 个文件，正是按**职责边界**切分：

| 职责 | 拆到 | 原因 |
|---|---|---|
| 提示词模板 + 拼装（`SCRIPT_WRITER`/`DIRECTOR`/`Zg`/`Qg`） | `scriptBoxPrompts.js` | **纯**：无副作用，零依赖，必抽 |
| 生成引擎 + 端点契约 + `createScriptBoxEngine(deps)` | `scriptBoxEngine.js` | 需 `K`（setNodes）与 `updateNodeData` 两个写回通道；`Mr/di/ii` 经 deps 注入 |
| `li/ui` 连线纯计算 | `scriptBoxConnect.js` | 强依赖本地 `di`/`ii`，纯计算抽出、宿主薄封装 |

**拆分边界判断依据**：凡是**无副作用**的（纯函数）→ 抽到独立文件；凡是**需要写回 `node.data` 或依赖宿主符号**的 → 留在 `H_.jsx` 或经 deps 传入。

## 六、速记（给后续 AI）

1. **数据只存 `node.data`**，UI 读、引擎写、编辑经 `updateNodeData`，方向单一。
2. **UI 不直接写 data**，只调 `d.onXxx?.()` 走引擎；改引擎不动 UI。
3. **纯函数（`Fa/Ra/Zg/Qg`）无副作用**，可安全抽取，下游也靠它们解耦。
4. **写回只有 `K`（setNodes）和 `r`（updateNodeData）两条通道**，别开第三条。
5. **参考图是下游的事**：剧本盒子只提供 `@资产名` 软连接，下游生成时收集。
6. **依赖单向**：UI→引擎→纯函数；引擎不依赖 UI，纯函数不依赖任何人。
7. **引擎重构按职责切**：纯的抽 `scriptBoxPrompts.js`/`scriptBoxConnect.js`，要写回/依赖宿主的留 `H_.jsx`。
