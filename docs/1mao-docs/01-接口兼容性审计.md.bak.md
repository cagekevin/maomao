> 审计方式：全面读取自研后端源码（`localTool/src`、`apimart-gateway/main.py`）与契约文档，同时分析 `dist/` 前端实际调用的全部接口，逐一比对。

## 〇、核心架构事实：localTool 是一切请求的唯一入口 + 中继翻译层

> **架构定调（已确认）**：localTool 是**所有请求的唯一入口**，浏览器从不直连任何外部服务（第三方 9004、官方 kkidc、画布助手等全部经 `/api/proxy`），
> 并由 localTool 承担**协议翻译**（将后端响应转换为画布前端期望的形状）。画布里 kkidc/官方接入点是**可配置的默认值**，
> 用户将所有基址（视频 `d`、节点 `apiUrl`、AI 应用基址等）指向 `127.0.0.1:18080` 即可全部经 localTool 中继。

### 统一数据流（一切请求经 localTool）

```
浏览器/画布 ──(proxyMode=local-tool，唯一出口)──> localTool :18080 /api/proxy
                                              │  x-proxy-url    = 目标地址(9004/kkidc/官方接入点)
                                              │  x-proxy-headers= { Authorization, Content-Type }
                                              └─(Node fetch 转发 → 协议翻译)──> 目标后端(9004/kkidc)
```

- 画布 `proxyMode` 判定 `(localPort||localToolBaseUrl ? 'local-tool' : 'server-proxy')`，`de` 默认 `local-tool`。
- 画布里的第三方地址（`d`、`e.apiUrl`、`apiKey` 等）是**可配置变量**，全部填入 localTool 地址即实现统中继。
- 画布硬编码的官方接入点（`1mao.cc`/`kkidc` 等）仅在 localTool 未启动时作 fallback；**启动后画布所有生成/轮询/助手请求发到 localTool**。
- **CORS 不构成任何路径的风险**：浏览器只打 `127.0.0.1:18080`（同源），localTool 以服务端身份转发所有外部请求。
- localTool 的 `/api/proxy` 当前**只是透传**，尚未实现协议翻译，这即核心 P0 缺口（见 4.3）。

### 由此修正的结论

| 项目 | 旧判断 | 修正 |
|---|---|---|
| localTool 角色 | 本地服务，可选代理 | ✅ **一切请求唯一入口 + 协议翻译层** |
| `/api/proxy` 状态 | 已覆盖（路由存在） | 🔴 **P0 双缺陷**：15s 超时 + 非流式 + **纯透传无翻译** |
| 网关端点（G1–G7） | 需补 | 仍成立：localTool 转发到网关，由 localTool 翻译后端响应形状 |
| CORS | 曾误判 P0 | ❌ **全面撤销**：浏览器只连 localTool（同源），所有外部请求经服务端转发 |

## 三、方法论

原版引擎为闭源二进制，无法直接读取。以**前端 `dist/` 实际调用的接口路径**作为「原版契约」的权威来源（消费者视角即契约），逐条比对：

- 本地服务（18080）→ `localTool/src/index.ts` 已注册路由
- 第三方 API（用户在「自定义 API 配置」面板填的 `apiUrl`，如 `http://127.0.0.1:9004`，经 localTool `/api/proxy` 转发）→ `apimart-gateway/main.py` 已实现端点
  （注：`active_api_endpoint` 默认值是官方 `www.1mao.cc`，属官方平台直连，非此网关；见七·B1–B5）

接口归属判定依据（`endpointConfig` / `background.js`）：

- `/api/...`、`/plugin/...` → 本地引擎 18080 → 由 `localTool` 提供（直连）
- `/v1/...`（含 `/v1/gateway/...`）→ **逻辑上由 `apimart-gateway` 提供，但浏览器并非直连网关**：画布默认 `proxyMode=local-tool`，
  所有 `/v1/...` 请求先发到 `localTool/api/proxy`，由 localTool 服务端转发（见〇节）。即网关仍是端点实现方，**唯一到达网关的通道是 `/api/proxy`**。
- 无前缀的 `/workflow-apps/*`、平台类 `sync/default`/`upload/app-asset` → **非经 `/api/proxy`**：代码实证为浏览器裸 `fetch` **直连官方接入点**（见七·B2–B4），属官方平台接口，当前无人接管。

注：`/api/objects` 经上下文核验为 three.js 文档 URL 误命中，**非接口**，已排除。

### 4.3 localTool `/api/proxy` 致命缺陷（P0 × 3）

> 见〇节。一切请求经此通道，故它的缺陷会**连带让所有生成/对话失败**，优先级最高。

| 缺陷 | 位置 | 影响 |
|---|---|---|
| **15s 硬超时（双路径）** | `handleProxyFormData`(`:67`) + `handleProxyJson`(`:126`)：`setTimeout(() => controller.abort(), 15000)` | 视频生成提交、流式对话 >15s 被掐断，504。所有耗时请求必败。 |
| **非流式转发（双路径）** | 两路径均 `Buffer.from(await fetchRes.arrayBuffer())` 整段缓冲后一次性回写 | 不转发 SSE 流；`chat/completions` 的 `stream:true` 收不到增量 |
| **纯透传，无协议翻译** | `handleProxy` 仅原样转发 header + body，不做任何形状转换 | 后端返回格式（`{code,data}` 信封、嵌套字段名等）若与画布前端解析器不匹配，响应即使到达也无法被正确解析。localTool 作为"翻译层"**尚未实现翻译**。 |

**修复方向**：
1. 超时：改连接阶段计时 / 长超时（如 10min）。
2. 流式：改用 `pipe`/`pipeline` 透传（含 `text/event-stream` + `Cache-Control: no-cache`）。
3. **翻译**（新增）：为每种后端响应格式到画布期望格式实现映射（提交→顶层 `task_id`/`id`、轮询→对应节点期望形状等）。

### 7.3 断点清单（B1–B7）

- **B1 画布助手直连官方**：`ar()` 裸 `fetch` 到 `Je`（官方）。官方不可达/自托管时无兜底，且依赖官方 CORS。
- **B2 `/api/sync/default` 无本地兜底**：画布拿到节点/模型配置的**唯一来源**。官方不可达 → 画布拿不到 apiConfig → 节点库空白。localTool/gateway 均不实现它（见第六节）。
- **B3 `/api/workflow-apps` 无本地兜底**：工作流分发/授权依赖官方，无兜底。
- **B4 `/api/upload/app-asset` 无本地兜底**：应用资产上传依赖官方。
- **B5 画布默认视频基址指向官方（需重定向）**：画布 `video`/`sd2Video`/`discountVideo` 节点默认基址 `d` = `https://ai-api.kkidc.com`（字节 Seedance，`seed-2`/`seedance_2_fast`），`e.apiUrl` 等也可配。**须用户将所有视频基址与节点 apiUrl 统一指向 `127.0.0.1:18080`**，即可通过 localTool `/api/proxy` 中继到后端，由 localTool 翻译协议格式。默认指向官方时用户直连官方，不走 localTool。
- **B6 CORS 已全面撤销**：因一切请求经 localTool `/api/proxy` 转发，浏览器只连 `127.0.0.1:18080`（同源），**无任何路径受 CORS 约束**。原"官方/kkidc 直连 CORS 风险"随用户将基址重定向到 localTool 而消除。
- **B7 硬编码默认接入点**：即便用户改 `active_api_endpoint`，O1（`154.219.102.152:3012`）等仍作 fallback 残留，离线/内网环境会静默尝试连公网。

- **B8 自检脚本漏检**：`verify_gateway.py` 未覆盖 G1/G2/G3。补端点后须扩自检：直接对端点发 GET、断言关键字段存在即可（localTool 翻译层负责格式映射，网关自身格式不限）。

### 7.4 关键注意事项

1. **画布默认指向官方**：视频基址/节点 `apiUrl` 等默认填官方（kkidc/1mao.cc）。用户须将所有外部地址统一指向 `127.0.0.1:18080`，方可全部经 localTool 中继。
2. **协议翻译归 localTool**：所有后端返回格式由 localTool `/api/proxy` 翻译为画布期望形状。网关/后端自身无需改 `{code,data}` 信封或字段名。
