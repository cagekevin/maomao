# 10. 头像菜单「上传云端 / 从云端下载」功能说明

> 探查日期：2026-07-31
> 探查范围：`dist/assets/App-BX6o9fW5.js`、`dist/assets/httpClient-BknZwXjG.js`、`dist/assets/endpointConfig-Bt85xi8d.js`、`script/output.js`
> 结论要点：这两个按钮是**原版一毛账号云同步**，只搬「配置类 KV 数据」，**不搬画布图片/视频素材**，且**不经过自研的 `localTool` / `apimart-gateway`**。

---

## 1. 按钮位置与触发

位于头像下拉菜单的「同步设置」分组（`同步设置` 标题下），两个按钮：

| 按钮 | 处理函数（混淆名） | 文案 | 前置条件 |
|---|---|---|---|
| 上传云端 | `ba` | ` 上传云端` | 已登录（有 auth token），未在执行中 |
| 从云端下载 | `xa` | ` 从云端下载` | 已登录，未在执行中 |

两个函数开头都先 `if(!_t.getCurrentToken()){ 提示“请先登录”; return }`，即**必须登录一毛账号**才能用。

---

## 2. 上传云端（ba）做了什么

1. 本地存储（`z` = 走 `window.localTool.getKV` 的 KV 封装）读取以下 9 类配置键：

   | KV 键 | 含义 |
   |---|---|
   | `app_settings` | 应用设置 |
   | `api_configs` | API 配置（含各引擎/多开配置） |
   | `users` | 用户 |
   | `membership` | 会员信息 |
   | `projects` | 项目 |
   | `presetPrompts` | 预设提示词 |
   | `customNodeTemplates` | 自定义节点模板 |
   | `modelSchedules` | 模型调度/排程（走函数 `Re()` 直接取值，不走 getObject） |
   | `cloud_storage_config` | 云存储配置 |

2. 把取值非 `null` 的键收集成对象 `e`；若 `e` 为空 → 提示「本地没有可同步的配置数据」并退出。
3. 调用 `_t.post('/sync/upload', { type:'cloud_config', data:e })`。
   - 成功（`success`）→ 提示「【配置】已同步到云端」；
   - 失败 → 提示「同步失败，请重试」，并 `console.error('[云端同步] 同步失败:', e)`。

> 即：**把以上 9 类 KV 配置打包成 `{type:'cloud_config', data:{...}}` 推到云端账号**。不含任何画布节点图片、视频、音频等媒体素材。

---

## 3. 从云端下载（xa）做了什么

1. 调用 `_t.get('/sync/download')` 拉取云端配置。
2. 若 `!(e.success && e.data && e.data.hasData===true)` → 提示「云端没有配置数据」并退出。
3. 取出 `t = e.data.data.cloud_config || e.data.data`，取键列表：
   - 为空 → 提示「云端没有新的配置数据」并退出；
   - 否则逐项写回本地：
     - `modelSchedules` → 走函数 `Tt(n)` 写回；
     - 其余键 → `z.setObject(e, n)`（走 `window.localTool.setKV`）；
     - 计数 `r`。
4. 提示「【配置】已从云端同步到本地 (r项)」，并在 1 秒后 `window.location.reload()` 重新加载页面使配置生效。

> 即：**把云端账号里存的 `cloud_config` 配置覆盖写回本地 KV**，覆盖本地同名配置（含 api_configs / 多开 / 视频模型等），随后刷新页面。

---

## 4. 请求打到哪个后端？（关键）

`/sync/upload`、`/sync/download` 通过 `_t`（httpClient 模块 `$_`）发出，最终 URL 由 `U_()` 拼接：

- base = `Wn = Nn()`，其中 `Nn` 来自 `endpointConfig` 的导出 `r`（= 本地函数 `g`），返回值是**当前生效的 API 接入点**：
  - 优先 `sessionStorage.active_api_endpoint`；
  - 否则默认接入点列表第一项：`https://www.1mao.cc` / `https://1mao.16iai.com` / `http://154.219.102.152:3012`。
- 拼接为 `${接入点}/api/sync/upload`（或 `/download`），并带 `Authorization: Bearer <token>` 头（`getCurrentToken`）。

**结论**：这两个接口打的是**原版一毛云服务器**，不是本仓库自研的 `localTool(:18080)` 或 `apimart-gateway(:9004)`。在 `proxyMode=local-tool` 的自研架构下，它们与画布生图/聊天的链路完全解耦——自研后端未实现 `/sync/*`，因此：

- 若用户登录的是**真实一毛账号**且接入点指向原版服务器 → 功能可用（配置上云/下云）；
- 在纯自研、未配置原版账号接入点的环境 → 这两个按钮会因连不上原版 `/api/sync/*` 而失败（提示「同步失败，请重试」），**不影响**生图/聊天等走 localTool 的功能。

---

## 5. 与「画布素材」的关系（易混淆点）

- **只同步配置，不同步素材**：上传/下载的对象是 `app_settings / api_configs / users / membership / projects / presetPrompts / customNodeTemplates / modelSchedules / cloud_storage_config` 这 9 类**文本/对象配置**，不含画布上的图片、视频、音频结果（这些结果是 Lovart CDN 外链，且在本地是 `transitResources` 等，不在同步清单内）。
- 文档 `script/output.js` 中已有提示词明确说明：「云端可以备份你的 api/多开/视频模型等信息，你换了设备也可以马上用，而本地资源你需要手动备份」——印证云端同步范围就是配置类信息。
- 视频/图片素材如需「不丢图」，靠的是 `localTool` 侧的 `saveRemoteUrl` 落盘（见 CLAUDE.md §6），与头像菜单的云端同步是**两套互不相干**的机制。

---

## 6. 数据流图（简）

```
头像菜单
  ├─ 上传云端(ba)
  │    local KV(getKV) → 9类配置 {cloud_config}
  │    → POST {接入点}/api/sync/upload   ← 原版一毛云服务器（非自研后端）
  │    → 提示「已同步到云端」
  │
  └─ 从云端下载(xa)
       GET {接入点}/api/sync/download     ← 原版一毛云服务器
       → cloud_config 写回 local KV(setKV) → 1s 后页面 reload
```

---

## 7. 风险与注意事项

- 下载会**覆盖**本地同名配置（尤其是 `api_configs` 多开/视频模型、`cloud_storage_config`），操作后自动刷新页面，谨慎执行。
- 该功能依赖原版一毛账号与接入点可用；自研 `localTool` / `apimart-gateway` 不提供该接口。
- 同步内容不含画布素材，换设备不会自动带上本地图片/视频，需另行手动备份（或用 localTool 落盘）。
