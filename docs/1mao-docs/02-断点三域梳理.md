# 接口断点三域梳理（先搞清断点，再谈修复）

> 范围：替换原版三个闭源引擎（`一毛本地引擎Win端.exe` / `一毛AI画布引擎Mac端Arm版` / `一毛AI画布引擎Mac端Intel版`）。
> 方法：已对 `localTool/src`、`apimart-gateway/main.py` 源码与 `dist/` 前端实际调用做代码实证核对。
> 核心定调：**localTool 是画布一切请求的唯一入口 + 协议翻译层**。浏览器只认 `127.0.0.1:18080`，CORS 全面撤销，所有外部地址（官方 / kkidc / 第三方）经 `/api/proxy` 服务端转发后由 localTool 翻译协议格式。
> 本文**只列断点，不含修复方案**。

---

## 〇、一句话架构

```
浏览器/画布 ──(proxyMode=local-tool, 唯一出口)──> localTool :18080
                                              │  /api/proxy
                                              │  x-proxy-url     = 目标地址(第三方API / 官方接入点 / kkidc)
                                              │  x-proxy-headers = { Authorization, Content-Type }
                                              └─(Node fetch 转发 → 协议翻译)──> 目标后端
```

三个域的边界：

| 域 | 是什么 | 当前代码位置 | 角色 |
|---|---|---|---|
| **A. 官方平台** | `www.1mao.cc` / `1mao.16iai.com` / `154.219.102.152:3012` / kkidc 视频 | 画布硬编码的接入点默认值 | 账户/云同步/工作流分发/画布助手/Seedance 视频 |
| **B. localTool** | 本地服务 `127.0.0.1:18080` | `localTool/src` | **唯一入口 + 中继翻译层**（本自研） |
| **C. API 网关** | 第三方 AI 生成后端 | `apimart-gateway/main.py` | 生图/生视频/对话/任务轮询的实现方 |

### A.3 断点（A 域）

- **A1 画布助手直连官方**：`ar()` 裸 `fetch` 到官方接入点。官方不可达 / 自托管时无兜底。
- **A2 `/api/sync/default` 无本地兜底**：这是画布拿到节点/模型配置的**唯一来源**。官方不可达 → 节点库空白。当前 localTool / 网关均未实现。
- **A3 `/api/workflow-apps` 无本地兜底**：工作流分发/授权依赖官方；另本地 `/api/workflow-apps/*`（非 by-project）返回形状亦未核对（见 B L6）。
- **A4 `/api/upload/app-asset` 无本地兜底**：应用资产上传依赖官方。

- **A7 O5 `0.1mao.cc` 真实用途未确认**（待挖，可能非关键）。

> 注：按"全走 localTool"架构，A1–A5 的可行去向是把这些官方接入点/基址**重定向指向 localTool 地址**，由 localTool 兜底或转发。这属于修复侧决策，本文不展开。

### B.3 响应形状未核对（B 域隐藏断点）

原审计只核对"路由是否存在"，未核对返回字段是否匹配前端解析：

| # | 接口 | 当前返回 | 风险 |
|---|---|---|---|
| S1 | `/api/files/upload`、`/api/files/thumbnail` | `url`/`thumbnailUrl` 为相对路径 `/files/...` | 方式二（插件/`chrome-extension://`）下被解析成 `chrome-extension://.../files/...` → 404 破图（方式一同源 OK） |
| S2 | 缩略图生成 | `fs.copyFileSync` 直接复制原图（无 sharp 时） | 功能降级：大图缩略图=原图 |
| S3 | `/api/tasks`、`/api/resources` | `{items,total,page,...}` | 前端列表取字段名（`items` vs `list`/`data`）未核对，不一致则列表空白 |
| S4 | `/api/kv/get` | 裸 JSON 值或 `null`（非 `{value}` 信封） | 前端是否用 `.value` 待核 |

### B.4 `/api/proxy` 致命缺陷（P0 × 3，最高优先）

> 一切请求经此通道，缺陷会连带让所有生成/对话失败。

| 缺陷 | 位置 | 影响 |
|---|---|---|
| **15s 硬超时（双路径）** | `handleProxyFormData`（`:67`）+ `handleProxyJson`（`:126`）：`setTimeout(...15000)` | 视频提交、流式对话 >15s 被 abort，504 |
| **非流式转发（双路径）** | 两路径均 `Buffer.from(await fetchRes.arrayBuffer())` 整段缓冲后一次性回写 | 不转发 SSE 流，`chat/completions` 的 `stream:true` 收不到增量 |
| **纯透传，无协议翻译** | `handleProxy` 仅原样转发 header+body | 后端返回格式（`{code,data}` 信封、嵌套字段名）若与画布前端解析不匹配，响应即使到达也无法被正确解析 |

### B.5 平台/依赖盲点（B 域）

| # | 盲点 | 严重度 |
|---|---|---|
| I1 | 缺合并启动器：根目录无脚本把 localTool(18080) + 网关 + 打开 `dist/index.html` 一起编排（原版"双击→自动进画布"体验缺失） | 高（部署就绪度） |
| P1 | `/api/files/open`、`/api/files/open-dir` 在 Linux 用 `open`（应为 `xdg-open`），`files.ts:277,304` | 低（目标 Mac/Win） |
| P2 | **ffmpeg 依赖未审计**：`system.ts:18` 返回 `ffmpeg:false`，localTool 无 ffmpeg 集成；需确认原版是否内置 ffmpeg、前端后处理是否依赖 | 中 |
| I3 | localTool 未预编译（`node_modules` 已装但无 `dist/`，须走 `start.sh` 或先 `npm run build`） | 中 |
| I4 | 若开放局域网，`OPEN_RELAY=true` 无鉴权 + 绑 `0.0.0.0` 风险 | 低/安全 |
| C1 | CORS 实际为通配 `*`（非"本机"），结合 I4 任意跨域页可调用 | 信息修正 |

## 七、此前"悬而未决"项——已通过读代码澄清（待实施，非谜）

> 以下原属"需拍板/抓包确认"事项，现已用前端 `dist` + localTool 源码实证，按规则"连官方的用官方、本地存素材用 localTool"定性。仅剩实施。

1. **A 域归谁兜底（A2/A3/A4）——已定性**：
   - `A2 /api/sync/default` → **localTool**。代码实证它返回基线 `apiConfigs`（节点/模型默认目录，含 `{VITE_API_BASE_URL}` 占位符，前端就地替换）。属"本地默认配置"，非用户云备份；localTool 应打包默认 apiConfigs 并把占位符换成 `127.0.0.1:18080`。
   - `A3 /api/workflow-apps/{id}?licenseToken=` → **官方市场（可选）**。带 licenseToken 去官方拉取已授权工作流（分发+授权）。自托管不重做应用市场；与 localTool 已实现的本地 `by-project` 工作流不是一回事。
   - `A4 /api/upload/app-asset` → **localTool**。代码实证为"传文件拿回 url"的本地素材存储；做成 `/api/files/upload` 别名、返回 `{success:true,data:{url}}` 即可。
2. **ffmpeg（P2）——已定性，非硬阻塞**：localTool `system.ts:55`（函数 `handleStatus` 50-58 行，旧文档误记 `:18`）硬 `ffmpeg:false` 且无集成；前端从 `/api/status` 读取 `ffmpeg` 字段后**直接丢弃**（无效语句，无任何 `if` 分支探测），不按 false 自适应（S2 缩略图降级为 `copyFileSync` 原图兜底，详见 19 号文档）。能力对等项若对齐原版才需 localTool 带 ffmpeg 并上报 true，当前自研端无需。
3. **`/v1/gateway/ai-app/*`（G5）——已定性，真用但可选**：`Jn(` 调 16 次、`Yn(` 调 11 次，AI 应用功能已接进画布；但核心生图/生视频/对话节点不依赖。要做完整功能才实现 G5（含 base 级 `/api/ai-apps`）；只跑核心可暂缓。

## 八、各域一句话总结

- **官方平台（A 域）**：画布硬编码的账户/同步/视频默认值，默认直连官方；按"全走 localTool"需重定向到 localTool，否则官方不可达即断。
- **localTool（B 域）**：唯一入口 + 翻译层，但 `/api/proxy` 有 3 个 P0 缺陷（超时/非流式/无翻译），且缺页面宿主、kv/delete、sync 等本地接口，ffmpeg 依赖未明。
- **API 网关（C 域）**：生图/生视频/对话主体已覆盖，缺口集中在 2 个视频轮询别名（G1/G2）、draw 生图（G3），及若干中低优先端点；网关自身格式由 localTool 翻译，无需改信封。
