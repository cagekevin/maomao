# 38 · 剧本盒子「编辑已生成提示词」崩溃排查与安全方案

> **日期**：2026-08-11
> **状态**：✅ 已定位根因（前端 `c_.jsx` 的 contentEditable 受控编辑 + 每次按键全量重渲染），给出安全编辑方案，未改码。
> **定位**：`src/bundle/httpClient-BknZwXjG_components/c_.jsx`（剧本盒子渲染组件）
> **性质**：纯前端运行时崩溃（整页白屏/React 树卸载），非接口/非网关问题。

---

## 一、现象

- 在剧本盒子 **步骤3「合成提示词」** 页面（`提示词自定义` 面板，`c_.jsx` L2616 的弹层），**编辑已经由 AI 生成的提示词**（分镜行的 `完整生图提示词` / `生视频提示词`，或分镜表格里的 prompt/videoPrompt 字段）时，**整页崩溃**（白屏，React 整树卸载）。
- 只"编辑已生成的内容"崩溃；空字段正常输入到一定长度也可能触发（条件触发）。
- 与接口无关：不涉及 localTool / 网关 / Lovart，VPN 状态不影响崩溃复现。

---

## 二、复现路径

1. 剧本盒子节点，输入剧情 → 步骤1「生成剧本」→ 得到 `shots`/`assets`。
2. 切到步骤3「合成提示词」，为某个分镜点「生成提示词」，得到 `shot.prompt` + `shot.videoPrompt`。
3. 在分镜行的 prompt/videoPrompt 编辑框（`rt` 渲染的 contentEditable 区域）内**直接键入/删除/改字**。
4. 敲到关键节点（内容含 `@资产名`、或触发 React 对 contentEditable 内部 DOM 的重排）→ **整页白屏**。

> 说明：`description`（画面描述）与 prompt/videoPrompt 用的是同一个 `rt` 编辑渲染器，理论上同样会崩；用户反馈集中在"提示词"是因为那是 AI 生成的长文本、命中率高。

---

## 三、根因（一句话）

**`c_.jsx` 的 `rt()` 把 React 受控子节点（`_cmp_a_` 返回的 string + `<span>`）渲染进一个 `contentEditable` 的 `<div>` 里，同时每次按键的 `onInput` 立刻 `updateNodeData` 回写 node.data → 触发整个 2805 行组件全量重渲染 → React 对"正在被浏览器编辑中的 contentEditable 内部 DOM"做 reconciliation → DOM 突变冲突抛错 → 未捕获 → React 卸载整树 → 白屏。**

根因拆成三个叠加因素，缺一不可：

| # | 因素 | 代码落点 |
|---|---|---|
| ① | contentEditable 内放 **React 受控子节点**（非纯文本），浏览器编辑态与 React 虚拟 DOM 双源冲突 | `rt()` L544-606，子节点 `_cmp_a_(i, p)`（a_.jsx） |
| ② | 每次按键 **`onInput` → `updateNodeData` → data.shots 新引用 → 全组件重渲染**（2805 行，含数百个 JSX 分支），重渲染即重排 contentEditable 子节点 | `rt()` L556-576 `onInput` → `He()` L231-244 → `updateNodeData` |
| ③ | `onKeyDown` 里 **`@资产名` 联想/替换直接写 `r.innerText`**（`nt()` L511-540：`r.innerText = a.text`），与 React 管理冲突叠加 | `nt()` L496-543 |

> 关键点：**①是"原罪"**（React 官方明确反对在 contentEditable 内托管受控子节点）；②把它放大成每次按键都全量重排；③是"扣扳机"的高危路径（Backspace 删除 `@资产` 时，`go()` 计算出删除后文本、直接 `r.innerText = ...`，随后 `He()` 回写，React 再重渲染，DOM 双重写入必崩）。

---

## 四、崩溃机制详解

### 4.1 编辑链路（一次按键发生了什么）

```
用户按键
  └─ onInput (rt L556)
      ├─ i = innerText 提取
      ├─ He(e.id, {[field]: i})        // L558-561
      │    └─ updateNodeData(e, {shots: f.map(...)})   // shared.js store
      │         └─ node.data.shots = 新数组引用
      │              └─ React Flow 触发 nodes state 变更
      │                   └─ 剧本盒子组件（Z.memo）因 data 引用变化 → 重渲染
      │                        └─ rt 重新生成 contentEditable 子节点
      │                             └─ React 尝试 diff/remove/insert 该 div 内部
      └─ 若内容含 @ 联想逻辑 → j(a)/N({...})   // 联想浮层
```

### 4.2 为什么 React 重排 contentEditable 会崩

- `contentEditable` 让浏览器拥有对 DOM 的**直接编辑权**（用户敲字时浏览器插入/删除文本节点、`<br>`、span 等）。
- React 的 reconciliation 假定"DOM 是 React 虚拟 DOM 的影子"，当浏览器在 contentEditable 内部擅自改动节点后，React 在下一帧要 diff 的 DOM 结构与虚拟 DOM 不一致 → 执行 `removeChild`/`insertBefore` 时找不到预期节点 → 抛 DOM 异常（典型 `NotFoundError: Failed to execute 'removeChild' on 'Node'`）。
- 该组件**没有 Error Boundary**，且异常发生在 React 渲染/提交阶段 → React 抛"渲染崩溃" → **卸载整棵 React 树** → 白屏。
- 每次按键都 `updateNodeData` → 全组件重渲染，把"崩溃概率"放大到必然触发。

### 4.3 为什么"空字段输入"相对安全

- 空字段 `_cmp_a_('', p)` 返回 `''`，子节点极简，重排时冲突面小。
- 一旦内容变长、含 `@资产名`（`_cmp_a_` 拆成 string+`<span>` 混合数组），或用户在 `@` 附近 Backspace/空格（触发 `go`/`_o` 直接写 `innerText`），冲突面骤增 → 崩溃。

## 五、安全编辑提示词方案（对比与推荐）

> 目标：**编辑提示词（prompt/videoPrompt/description）不再崩溃**，同时保住现有 `@资产名` 联想/替换体验。

### 方案 A（推荐 · 根治）：双击进独立弹窗编辑，保存回写原字段

> **一句话**：把分镜行/分镜详情里的 prompt/videoPrompt/description 从「原地 contentEditable 编辑」改成「**双击 → 独立弹窗里用受控 textarea 编辑 → 保存 → 一次性写回原字段**」。编辑态彻底脱离 React 重排区，从根上消灭①+②+③三个崩溃因素。

**交互设计**：

1. 分镜的 prompt / videoPrompt / description 字段区域**默认只读展示**（渲染成普通 `<div>` 或只读 textarea，展示 `_cmp_a_` 高亮或纯文本均可，不再 `contentEditable`）。
2. **双击**该字段区域 → 打开一个**独立 portal 弹窗**（复用现有 `c_.jsx` L2555 那类 `Fn.createPortal` + 遮罩风格），弹窗内是**受控 `<textarea>`**，初值 = 当前字段内容。
3. 弹窗内编辑**只更新弹窗自己 `useState`**，绝不触发 `updateNodeData`/剧本盒子重渲染 → 每敲一个字不再全量重排。
4. 弹窗底部「**保存**」→ 一次性 `updateNodeData(e, { shots: ...改该镜对应字段 })` 写回；「取消」/点遮罩 → 丢弃不写。

**「双击哪里」精确入口地图**（`rt()` 的可编辑 contentEditable 区，共 3 处调用，全部要换成"双击开弹窗"）：

| 视图 | 位置 | 字段 | 代码行 | 说明 |
|---|---|---|---|---|
| **single（单镜头）** | 分镜详情·画面描述 | `description` | `c_.jsx` L2083 | 含 `@资产` 引用 |
| **single（单镜头）** | 分镜详情·「生图」框 | `prompt` | `c_.jsx` L2102 | ⚠ **提示词**，AI 生成长文本，最易崩 |
| **single（单镜头）** | 分镜详情·「生视频」框 | `videoPrompt` | `c_.jsx` L2106 | ⚠ **提示词**，AI 生成长文本，最易崩 |
| **list（列表）** | 分镜表格·画面描述列 | `description` | `c_.jsx` L757 | 默认表格视图 |

> 现状这些区域是 **contentEditable、点击即可直接编辑**（`rt()` L556 `role=textbox contentEditable`）。用户"编辑已生成的提示词"崩溃，主要发生在 **single 视图的「生图」/「生视频」两个提示词框**（`prompt`/`videoPrompt`，L2102/L2106）。改造后这些区域全部变成：**双击 → 弹窗编辑 → 保存写回**。

**为什么能根治（对照崩溃三因素）**：

| 崩溃因素 | 本方案如何消除 |
|---|---|
| ① contentEditable 内放 React 受控子节点 | 编辑区改为独立弹窗内的 `<textarea>`，完全受控、天然稳定，无浏览器/React 双源 |
| ② 每按键 `updateNodeData` → 2805 行组件全量重渲染 | 弹窗编辑只改弹窗内部 state，**保存前不碰 node.data**，不触发剧本盒子重渲染 |
| ③ `@资产` 删改直写 `innerText`（`nt`/`go`/`_o`/`tt`） | 弹窗内纯文本编辑，不再有 contentEditable 键处理；`@资产` 高亮/联想改为弹窗内的**纯展示辅助** |

**`@资产` 体验保留**（不必丢掉）：弹窗内 textarea 下方/旁边列出所有资产名，点资产名 → 在光标处插入 `@资产名 `（textContent 拼接，非 DOM 直写）；高亮改为弹窗外的只读展示区用 `_cmp_a_` 渲染。**注意**：下游连线的 `@资产` 收集走 `Fa` **纯字符串匹配**（见 `docs/33` §5），与编辑 UI 无关——只要最终写回文本里保留 `@资产名`，连线后照样自动带参考图，不受本改造影响。

**优点**：根治；改动边界清晰（只在 `c_.jsx` 加一个弹窗组件 + 改 `rt()` 展示态）；可复用现有 portal/弹层风格与 `_cmp_a_` 高亮。
**代价**：① 双击/保存交互与"原地即改"体验不同（但符合你提出的交互）；② 新增一个弹窗子组件（走 §三.3.1 新建自研 SOP，语义命名如 `_cmp_ShotFieldEditModal.jsx`，不 import 顶层大 chunk，用事件总线/受控回传）。

### 方案 B（最小改动 · 止血，可与 A 叠加）：contentEditable 去受控化 + 节流回写 + 去掉内联高亮子节点

不换 textarea，只做三处小改：

1. **`rt()` 的 contentEditable 子节点不再随输入重建**：把 `{_cmp_a_(i, p)}` 改成只挂**一次**（用 `useRef` 存 DOM、初始 `innerText = i`），编辑期间 React 不再重排该 div 内部，从根上消除 React 重排冲突。
2. **`onInput` 回写节流/去重**：用 `useRef` 缓存当前正在编辑的 `(id, field)`，同一字段未失焦前**不重复触发全量 `updateNodeData`**；失焦（`onBlur`）时才一次回写。把"每次按键重渲染"降为"编辑完再渲染"，消除②。
3. **`onKeyDown` 的 `@资产` 联想写 `innerText` 前，先中止 React 对该节点重排**：或直接禁掉编辑态下的 `go`/`_o` 直写，改为联想浮层选中后写 `textContent` 并 `preventDefault`，不再 `setTimeout` 里 `tt()` 动光标。

- **优点**：改动局部（都在 `c_.jsx` 的 `rt`/`nt` 内），不引入新组件，风险最小、符合项目"最小差异改动混淆码"纪律。
- **代价**：仍是 contentEditable，属"绕开"而非根治；`@` 高亮与联想体验需针对性保留。

### 方案 C（兜底）：给剧本盒子组件挂 Error Boundary

- 在 `c_` 外层（或 `_cmp_c_` 消费处）包一层 class ErrorBoundary，捕获渲染异常，弹提示"该分镜字段渲染异常，已重置"，避免整页白屏。
- **仅兜底，不解决崩溃本身**（崩溃仍会清掉该组件局部 UI），但能保住画布其它节点与整页可用。

### 推荐

- **首选（根治）**：**方案 A「双击进弹窗编辑」**——最符合你提的交互，且从根上消灭三个崩溃因素，改动边界清晰，可作为主方案落地。
- **叠加**：**方案 C** ErrorBoundary 兜底，任何遗漏的分镜字段编辑都不会再整页白屏。
- **备选（不想加弹窗/想最小改）**：方案 B 的三处小改止血，立即不崩但仍是 contentEditable。

## 六、落地建议（方案 A「双击弹窗编辑」改码对照）

1. **先跑 `npm run test:smoke` 记基线**，改完重跑 + `npm run build` 回灌 `dist/`（CLAUDE.md §三/§五.4）。
2. **改动集中在 `c_.jsx`**：
   - 新增一个弹窗子组件（**新建自研**，语义名如 `_cmp_ShotFieldEditModal.jsx`，放 `httpClient-BknZwXjG_components/`，走 §三.3.1 新建 SOP：CSS 字符串自包含、不 import 顶层大 chunk、通信用 props/受控回传）。
   - 改 `rt()`（L544）为**只读展示态**：双击打开弹窗，不再 `contentEditable`/`onInput`/`onKeyDown`。三处调用（L757 description、L2102 prompt、L2106 videoPrompt）自动跟随。
   - 弹窗「保存」→ `He(e.id, {[field]: value})`（L231，现有回写函数）一次性写回，别的都不动。
   - `@资产` 插入用 textarea 光标处 `textContent` 拼接（不复用 `go`/`_o`/`tt` 直写）。
3. 若叠加方案 C：在 `_cmp_c_` 消费处包 ErrorBoundary（新建 class 组件，语义名）。
4. **别动 `_cmp_a_`（a_.jsx）导出契约**（只读高亮仍可用）；`nt`/`go`/`_o`/`tt` 的 contentEditable 专用逻辑改为只读态不再触发，可保留不删（避免删多引入回归）。
5. 真机验证：生成若干分镜提示词 → **双击**各字段 → 弹窗内反复编辑/删除含 `@资产` 文本 → 保存回写 → 确认不再白屏、原文位置显示更新；再确认下游连线后生成仍自动带参考图（`@资产` 纯字符串匹配不受影响）。

## 附：一句话给用户

剧本盒子"编辑已生成的提示词"整页白屏，是因为该编辑框用了 `contentEditable` 且每次按键都会 `updateNodeData` 触发全量重渲染 + React 重排其内部 DOM，一旦内容含 `@资产` 或改动光标位置就触发 DOM 冲突异常、React 卸载整树。**根治办法：双击该字段 → 弹窗里用受控 textarea 编辑 → 保存才写回原位置**（编辑态彻底脱离 React 重排区），再加个 Error Boundary 兜底，任何遗漏都不会再整页白屏。
