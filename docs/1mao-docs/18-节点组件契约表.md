## 1. 类型注册表

### 1.1 任务 type（任务列表分类，7 种）

任务中心（全局任务列表）中每条任务的 `type` 取值共 **7 种**，其与中文面板名、图标的对应来自 `App-BX6o9fW5.js` 中的 `Tn`：


| 任务 type      | 面板 label | 说明                          | 结果媒体类型 | 是否支持轮询 |
| -------------- | ---------- | ----------------------------- | ------------ | ------------ |
| `text`         | 文本       | 文本/对话生成                 | text         | 否（同步）   |
| `image`        | 生图       | 文生图                        | image        | 否（同步）   |
| `video`        | 视频       | 文生视频（标准视频节点）      | video        | 是           |

| `discountVideo`| 特惠视频   | 特惠视频（独立网关 + 特惠规格）| video        | 是           |
| `custom`       | 万能       | 自定义 HTTP 请求节点          | 由 `customOutputType` 决定 | 否（由节点自身轮询，见 §5.1） |
| `rhWebapp`     | AI应用     | 一毛 AI 应用                  | 由 `customOutputType` 决定 | 是           |

> **`En` 集合的真实用途**：`var En = /* @__PURE__ */ new Set(["discountVideo","sd2Video"])`。
>
> 全文件中 `En` 仅出现 **2 次**——1 次定义、1 次使用，因此它只有一个用途：任务卡片上**渠道名（channelName）的显示回退**。
>
> ```js

>   if (t.id === `tehuishipin` || t.id === `yimaoAiApp`) {
>     let e = t.url.replace(`{VITE_API_BASE_URL}`, $e(Je));
>     return { ...t, key: We(), url: lt(e, !0) };

> ```
>
> 即：`apiConfigs` 中 id 为 `default`（内置模型）、`tehuishipin`（特惠视频）、`yimaoAiApp`（AI 应用）三项的 `url`/`key` 由服务端登录态动态回填。任务 type 侧只用 `rhWebapp`，**不存在 `aiApp` 这个任务 type**。

> **节点标题解析函数 `Gn(node)`**（原文）：
>
> ```js
> function Gn(e2) {
>   let t2 = e2?.data?.label || e2?.data?.name || e2?.data?.title || e2?.label;
>   if (t2) { return String(t2); }
>   let n2 = String(e2?.type || "");
>   return Wn[n2] ? Wn[n2] : e2?.id || n2 || "参数";
> }
> ```
>
> 实际优先级为：`data.label` → `data.name` → `data.title` → `node.label` → `Wn[node.type]` → **`node.id`** → 原始 `type` 字符串 → 字面量 **`"参数"`**。
>
> 原文档把回退链写成"…→ `Wn[node.type]` → 原始 `type` 字符串"，漏了两级：`Wn` 未命中时**先取 `node.id`**，`id` 与 `type` 都为空时还有兜底字符串 `"参数"`。这两级差异会直接影响未注册 type 的节点在任务列表中的显示文案（显示的是节点 id，而非 type）。
>
> 另注：前四项走的是 `||` 短路，因此**空字符串、`0`、`false` 等假值会被跳过**而非采用；命中后统一 `String()` 转换。

> 说明：`httpClient` 中另有 `{text:{label:"文本"},image:{label:"生图"},video:{label:"生视频"}}` 形式的三分类聚合，用于"任务生成"入口按大类分组，与上述两套 type 枚举均不同。

## 3. 预定义字段类型表（字段类型契约）

节点配置字段的**强类型映射** `Bn`（源：`App-BX6o9fW5.js`，原文如下，共 16 项）：

```js
var Bn = {
  selectedSeconds: `number`, videoDurations: `text`,
  discountVideoModel: `text`, sd2VideoModel: `text`,
  videoModel: `text`, selectedModel: `text`,
  videoDuration: `number`, duration: `number`,
  videoUrl: `video`, audioUrl: `audio`, imageUrl: `image`,
  referenceImage: `image`, referenceVideo: `video`, referenceAudio: `audio`,
  maskUrl: `image`, fileUrl: `text`
};
```

这里的"类型"是**控件类型**（渲染成哪种输入组件），不是 JS 数据类型。取值域为：`text` / `number` / `boolean` / `image` / `video` / `audio` / `json`。

| 字段名 | 类型 | 说明 |
| ------ | ---- | ---- |
| `selectedSeconds` | number | 时长（秒） |
| `videoDurations` | text | 可选时长列表 |
| `discountVideoModel` | text | 特惠视频模型 |
| `sd2VideoModel` | text | SD2 视频模型 |
| `videoModel` | text | 视频模型 |
| `selectedModel` | text | 选中模型（通用） |
| `videoDuration` | number | 视频时长 |
| `duration` | number | 时长 |
| `videoUrl` | video | 视频地址 |
| `audioUrl` | audio | 音频地址 |
| `imageUrl` | image | 图片地址 |
| `referenceImage` | image | 参考图片 |
| `referenceVideo` | video | 参考视频 |
| `referenceAudio` | audio | 参考音频 |
| `maskUrl` | image | 蒙版地址 |
| `fileUrl` | text | 文件地址 |

**字段类型推断函数 `Vn(field, value)`**（原文）：

```js
function Vn(e, t) {
  return Bn[e] ? Bn[e]
    : typeof t == `boolean` ? `boolean`
    : typeof t == `number`  ? `number`
    : /\b(image|cover|thumb|mask)\b/i.test(e) ? `image`
    : /\b(video|gif)\b/i.test(e)              ? `video`
    : /\b(audio|voice)\b/i.test(e)            ? `audio`
    : /\b(json|config|body)\b/i.test(e)       ? `json`
    : `text`;
}
```

优先级：`Bn` 命中 → boolean → number → 字段名正则（image / video / audio / json）→ 默认 `text`。

> **易错点**：正则使用了单词边界 `\b`，因此 `imageUrl`、`videoUrl` 这类**驼峰连写**的字段名**匹配不到**（`\bimage\b` 不匹配 `imageUrl`）。它们之所以能得到正确类型，靠的是 `Bn` 表命中而非正则。真正依赖正则的是形如 `image_1`、`cover url`、`my.mask`、`ref-video` 这类以非字母字符分隔的字段名。

## 4. 各节点 API 绑定方式（API 来源契约）

**核心机制其实是统一的**：所有内置类节点的 url/key 都来自同一份 `apiConfigs` 列表（状态变量 `Y`），差别只在于"选中哪个配置项的 id 是否允许用户改"。

### 4.1 选中项 id 的状态与持久化

六类各持有一个"当前选中的 apiConfig id"状态，初值从 localStorage 读取，缺省 `default`：

```js
[ai,oi] = useState(() => localStorage.getItem(`apiConfigId_text`)     || `default`);
[si,ci] = useState(() => localStorage.getItem(`apiConfigId_image`)    || `default`);
[li,ui] = useState(() => localStorage.getItem(`apiConfigId_video`)    || `default`);
[di,fi] = useState(() => localStorage.getItem(`apiConfigId_sd2Video`) || `default`);
[pi]    = useState(`tehuishipin`);   // 特惠视频：常量，无 setter
[mi]    = useState(`yimaoAiApp`);    // AI 应用：常量，无 setter
[hi,gi] = useState(() => localStorage.getItem(`apiConfigId_audio`)    || `default`);
```

| 类别 | localStorage 键 | 服务端预设字段 | 默认/固定值 | 用户可改 |
| ---- | --------------- | -------------- | ----------- | -------- |
| text | `apiConfigId_text` | `textApiConfigId` | `default` | 是 |
| image | `apiConfigId_image` | `imageApiConfigId` | `default` | 是 |
| video | `apiConfigId_video` | `videoApiConfigId` | `default` | 是 |
| sd2Video | `apiConfigId_sd2Video` | `sd2VideoApiConfigId` | `default` | 是 |
| audio | `apiConfigId_audio` | `audioApiConfigId` | `default` | 是 |
| discountVideo | `apiConfigId_discountVideo` | 无 | **`tehuishipin`**（硬编码常量） | **否** |
| aiApp | 无 | 无 | **`yimaoAiApp`**（硬编码常量） | **否** |

> 修正两处：①`apiConfigId_discountVideo` 这个键确实存在且会被写入 localStorage，但它的值恒为 `tehuishipin`，写入纯属副作用，读取时并不使用；②AI 应用的选中 id `mi` 只存在于内存，**不落 localStorage**。

服务端预设仅在**用户未手动设置过**时生效（源 `App`）：

```js
e.textApiConfigId     && !localStorage.getItem(`apiConfigId_text`)     && oi(e.textApiConfigId)
e.imageApiConfigId    && !localStorage.getItem(`apiConfigId_image`)    && ci(e.imageApiConfigId)
e.videoApiConfigId    && !localStorage.getItem(`apiConfigId_video`)    && ui(e.videoApiConfigId)
e.sd2VideoApiConfigId && !localStorage.getItem(`apiConfigId_sd2Video`) && fi(e.sd2VideoApiConfigId)
e.audioApiConfigId    && !localStorage.getItem(`apiConfigId_audio`)    && gi(e.audioApiConfigId)
```

> 同一份服务端配置里还一并下发默认模型：`defaultTextModel`、`defaultDrawingModel`、`defaultVideoModel`、`defaultSd2VideoModel`、`defaultAudioModel`、`videoDurations`、`sd2Token` 等。

### 4.2 由选中 id 解析出 url / key

一个 `useEffect` 把 id 解析成实际的 url/key 对，**text/image/video 与其余三类的回退策略不同**：

```js
let e = Y.find(e => !e.readonly);                    // 第一个非只读配置
let t = t => {                                        // text/image/video 专用解析
  let n = Y.find(e => e.id === t);
  return n && !n.readonly ? n : e || n || Y[0];      // 命中但只读 → 改用非只读项
};
let n = t(ai); n && (Nn(n.url), Fn(n.key));          // text
let r = t(si); r && (Bn(r.url), Hn(r.key));          // image
let i = t(li); i && (Kn(i.url), Jn(i.key));          // video

let a = Y.find(e => e.id === di) || Y[0]; a && (nr(a.url), ir(a.key));  // sd2Video
let o = Y.find(e => e.id === pi) || Y[0]; o && (lr(o.url), dr(o.key));  // discountVideo
let s = Y.find(e => e.id === mi) || Y[0]; ...                            // aiApp
```

关键差异：

- **text / image / video**：若选中项被标记 `readonly`，会**自动改用第一个非只读配置**——即只读配置不能作为这三类的生效通道。
- **sd2Video / discountVideo / aiApp**：直接 `find(id)`，找不到就退到 `Y[0]`，**不检查 `readonly`**。

因此第 6 节中 `discountVideoApiUrl` / `aiAppApiUrl` 等"全局字段"，本质是上述 `useEffect` 从 `apiConfigs` 中 id 为 `tehuishipin` / `yimaoAiApp` 的配置项解析出来的产物，而非独立写死的常量。

### 4.3 `tehuishipin` / `yimaoAiApp` 配置项的动态回填

这两项（连同 `default`）的 url/key 在登录态刷新时由服务端回填（见 §1.1 代码）：`default` 只换 `key`；`tehuishipin` 与 `yimaoAiApp` 会把 url 中的 `{VITE_API_BASE_URL}` 占位符替换为当前环境域名，并统一换成用户 token。

### 4.4 特惠视频可选模型

`discountVideo` 的模型下拉不来自 `apiConfigs`，而来自服务端拉取的 `catalog.discountVideoSpecs`，与内置 `builtinFavorites` 中的同名结构做字段级合并（保留 `speed` / `stability` 等规格字段）。

### 4.5 万能节点

`custom` 不参与上述任何解析，请求完全由节点自身 `config` 决定（见 §5.1）。

## 5. 各节点配置契约（config 字段）

### 5.1 custom（万能）节点 config

执行入口为 `httpClient` 中的 `Qr(nodeId)`（`useCallback`），前置校验为 `node.type !== "customNode" || !node.data.config` 则直接返回。

**`executionMode` 有两种取值：`sync` 与非 `sync`（异步轮询）**。原文档仅列出 `sync` 是错误的，异步分支占了该函数一大半逻辑。

#### 配置字段全集

| 字段 | 适用模式 | 说明 |
| ---- | -------- | ---- |
| `apiUrl` | both | 接口地址，支持 `{{var}}` 占位符替换 |
| `method` | both | 请求方法 |
| `headers` | both | 请求头（JSON 字符串），支持占位符 |
| `body` | both | 请求体（字符串），支持占位符 |
| `outputType` | both | `text` / `image` / `video` / `audio` |
| `executionMode` | — | `sync` = 一次请求拿结果；其它值 = 提交后轮询 |
| `resultPath` | both | 从响应 JSON 提取结果的路径（异步下作为 `pollingResultDataPath` 的回退） |
| `rawTextOutput` | both | 为真且结果是纯量数组时，用 `\n` 连接而非 `JSON.stringify` |
| `variables` / `variableFormats` | both | 变量表；`variableFormats[k]==="json"` 时按原始 JSON 注入（不转义） |
| `taskIdPath` | async | 从提交响应中提取 task id 的路径，**提取不到直接抛错** |
| `pollingUrl` | async | 轮询地址，未配置则回退 `apiUrl`；支持 `{{task_id}}` |
| `pollingMethod` | async | 轮询方法，默认 `GET` |
| `pollingHeaders` | async | 轮询请求头（JSON 字符串） |
| `pollingBody` | async | 轮询请求体；仅当方法非 `GET` 且非空时携带 |
| `pollingResultPath` | async | 取"状态值"的路径 |
| `pollingCompletedValue` | async | 状态值 **全等** 该值 → 完成 |
| `pollingFailedValue` | async | 状态值全等该值 → 失败（配置了才判定） |
| `pollingResultDataPath` | async | 完成后取结果的路径，回退 `resultPath` |
| `pollingProgressPath` | async | 进度路径，取到后剥离非数字字符再转 number |
| `pollingErrorPath` | async | 失败时的错误信息路径 |

> `pollingUrl` / `pollingBody` / `pollingResultPath` / `pollingResultDataPath` / `pollingProgressPath` / `pollingErrorPath` 均支持 `{{task_id}}` 占位符替换。

#### 占位符与输入聚合规则

- 上游连线按 `targetHandle` 分流：`var-{name}` 开头 → 写入变量 `name`；无 handle / `default` / 空 → 再按内容二次分流。
- 二次分流规则：源节点非 `fileToUrlNode` 且（有 `imageUrl`/`videoUrl` 或值以 `http`、`data:image/` 开头）→ 归入**图片数组**；否则归入**文本数组**。
- 图片数组按序替换 `{{image_1}}`、`{{image_2}}` …
- 文本数组在变量表无 `prompt` 时，整体以 `\n` 连接替换 `{{prompt}}`；若变量表**有** `prompt`，则文本数组内容会**前置拼接**到该变量值之前。
- 变量值若为 `http` 开头且变量名以 `image`/`audio`/`video` 开头，会先 `fetch` 并转为 **base64 data URL** 再注入。
- 占位符语法支持默认值写法 `{{name|default}}`（正则 `\{\{name(?:\|[^}]+)?\}\}`）。
- 注入 `body` 时默认对 `"` 与换行做转义；`variableFormats[k]==="json"` 时不转义，直接原样注入。

#### 轮询节奏（异步模式）

```js
let l = Math.ceil(re / B);            // 最大轮询次数 = 总超时 / 间隔
for (; !a && o < l; ) {
  if (y.signal.aborted) throw Error(`已取消`);
  await new Promise(e => setTimeout(e, B * 1e3));   // 间隔 B 秒
  o++;
  ...
}
if (!a) throw Error(`轮询超时`);
```

- 间隔 `B` 秒、总超时 `re` 秒均来自用户设置，最大次数 `Math.ceil(re / B)`。
- 轮询响应 `!res.ok` 时**静默 `continue`**（不计失败，仅消耗一次次数）。
- 未取到 `pollingProgressPath` 时，进度按 `Math.min(99, 轮询次数 * 2)` 估算。
- 支持 `AbortSignal` 取消（`y.signal`），取消时抛 `已取消` 且 `AbortError` 不弹错误提示。

#### 结果写回

成功后同时写两处：

1. **全局任务**：`status:"completed"`、`progress:100`、`customResultData`、`customRawResponse`；任务的 `modelName` 固定为 `万能节点`，`channelName` 由 `I_(apiUrl)` 从域名推导。
2. **节点 `data`**：`resultData` + 按 `outputType` 分派——`text→data.text`、`image→data.imageUrl`（数组取 `[0]`）、`video→data.videoUrl`、`audio→data.audioUrl`，URL 均经 `An()` 规整。

失败时写 `status:"failed"` / `errorMsg`，节点侧写 `data.errorMsg` 并置 `loading:false`。

> 附带行为：`outputType==="text"` 且本地工具已连接时，结果会以 `custom_text_{时间戳}.txt` 上传到本地 `tasks` 目录；`outputType==="video"` 时结果视频会经 `si()` 转存后回调入库。

> 节点落库/导出时额外保留：`customResultData`、`customRawResponse`、`requestData`、`responseData`、`customOutputType`、`mediaMeta`。其中 `requestData` 结构为 `{ method, url, body }`。

### 5.2 discountVideo（特惠视频）节点 config

## 6. 任务刷新 URL 与鉴权契约

源为 `App` 的 `Pt` 这一 Hook，签名如下（形参已还原）：

```js
function Pt({
  isLoaded: e, globalTasks: t, handleUpdateGlobalTasks: n, showToastMessage: r,
  localPort: i, localToolConnected: a,
  sd2VideoApiUrl: o,      sd2VideoApiKey: s,
  videoApiUrl: c,         videoApiKey: l,
  discountVideoApiUrl: u, discountVideoApiKey: d,
  aiAppApiUrl: f,         aiAppApiKey: p
}) { ... return { handleRefreshTask: g }; }
```

内部核心是 `g(task, silent)`（对外暴露为 `handleRefreshTask`），`silent=true` 时不弹 toast。

### 6.1 URL 拼法与鉴权

任务 id 取 `task.taskId || task.id`。四类之外的 type 会提示"仅支持刷新视频任务状态"并直接返回。

| 任务 type | 方法 | URL 拼法 | 鉴权头 | URL 来源 | Key 来源 |
| --------- | ---- | -------- | ------ | -------- | -------- |
| `sd2Video` | GET | `{base}/v1/video/generations/{taskId}` | `Bearer {key}` + `Accept: */*` | `task.apiUrl \|\| sd2VideoApiUrl` | `task.apiKey \|\| sd2VideoApiKey` |
| `video` | GET | `{base}/v1/videos/{taskId}` | `Bearer {key}` | `task.apiUrl \|\| videoApiUrl` | `task.apiKey \|\| videoApiKey` |
| `discountVideo` | GET | `{base}/v1/gateway/task/{taskId}` | `Bearer {key}` + `Accept: */*` | **仅** `discountVideoApiUrl` | **仅** `discountVideoApiKey` |
| `rhWebapp` | GET | `ht(lt(aiAppApiUrl), "/task/{encodeURIComponent(taskId)}")` | `Bearer {key}` + `Accept: */*` | **仅** `aiAppApiUrl` | **仅** `aiAppApiKey` |

原始代码：

```js
if (e.type === `sd2Video`)
  m = `${(e.apiUrl||o).replace(/\/$/,``)}/v1/video/generations/${g}`,
  h = { Authorization:`Bearer ${e.apiKey||s}`, Accept:`*/*` };
else if (e.type === `video`)
  m = `${(e.apiUrl||c).replace(/\/$/,``)}/v1/videos/${g}`,
  h = { Authorization:`Bearer ${e.apiKey||l}` };
else if (e.type === `discountVideo`)
  m = `${(u||``).replace(/[`\s]/g,``).replace(/\/$/,``)}/v1/gateway/task/${g}`,
  h = { Authorization:`Bearer ${d}`, Accept:`*/*` };
else if (e.type === `rhWebapp`)
  m = ht(lt(f), `/task/${encodeURIComponent(g)}`),
  h = { Authorization:`Bearer ${p}`, Accept:`*/*` };
else { t || r(`仅支持刷新视频任务状态`); return; }
```

要点：

- **只有 `sd2Video` 与 `video` 支持实例级回退**（`task.apiUrl || 全局`）；`discountVideo` 与 `rhWebapp` **URL 和 Key 都强制走全局字段**，完全不读实例值。原文档称"节点实例可自带 apiUrl/apiKey，为空则回退"是以偏概全，已更正。
- 所有 base URL 都会剥掉结尾 `/`；`discountVideo` 还额外剥除反引号与空白字符（`/[`\s]/g`），这是对脏配置的防御。
- 请求经 `mt(url, { headers, localPort })` 发出，本地工具已连接时会带上 `localPort` 走本地代理。

### 6.2 响应解析

先尝试 `res.json()`；解析失败且 `!res.ok` 时抛 `HTTP Error {status}: {statusText}`。只要 `res.ok` 或响应体可解析就继续走状态映射；`!res.ok` 时先预置 `failed`，错误信息按 `errorMsg → errorMessage → error → message → 请求失败 ({status})` 顺序回退。

| 任务 type | 命中条件 | 完成 | 失败 | 结果 URL |
| --------- | -------- | ---- | ---- | -------- |
| `sd2Video` | `code==="success" && data` | `data.status` ∈ `SUCCESS`/`succeeded` | ∈ `FAILED`/`failed`/`FAILURE` | `data.data?.content?.video_url` |
| `discountVideo`（包裹式）| `code===1 && data` | `data.status` ∈ `3`/`success`/`SUCCESS`/`completed` | ∈ `4`/`failed`/`FAILED`/`error` | `data.video_url \|\| data.result_url \|\| data.data?.content?.video_url \|\| data.result?.url` |
| `discountVideo`（扁平式）| `status!==undefined && !data` | `status` 同上 | 同上 | `video_url \|\| result_url \|\| result?.url` |
| `rhWebapp` | `type==="rhWebapp"` | `status.toUpperCase()==="SUCCESS"` | `==="FAILED"` | `results.find(r=>r?.url)?.url` |
| 通用回退 | 以上都不命中 | `status` ∈ `completed`/`success`/`succeeded` | ∈ `failed`/`error` | `video_url \|\| video \|\| result_url \|\| result?.url \|\| url` |

进度处理：

- `sd2Video`：`parseInt(data.progress.replace("%",""))`，失败则 `50`。
- `discountVideo`：`parseInt(String(progress).replace("%",""))`，失败则 `50`。
- `rhWebapp`：无数值进度，`PENDING`/`QUEUED` → `10`，其余运行中 → `50`。
- 通用回退：`progress || 50`。

其他细节：

- 所有结果 URL 都会执行 `.replace(/[`\s]/g,"")` 去除反引号与空白；通用回退分支还解析 `thumbnail_url || cover_url || thumbnail` 写入 `thumbnailUrl`。
- **无变化短路**：若 `status`/`progress`/`errorMsg`/`resultUrl` 四项均未变，则只更新 `responseData`/`customRawResponse` 并提示"任务状态暂无变化"，不做其余写入。
- `errorMsg` 为对象时会 `JSON.stringify`，失败则退化为 `未知错误`。
- `rhWebapp` 完成时额外回填 `customResultData = resultUrl`，并按 `results[0].outputType` 推断 `customOutputType`（含 `video`/`audio`/`text` 关键字则对应，**否则默认 `image`**）。
- 任务完成或失败且带 `nodeId` 时，派发全局事件 `mutiwindow-task-completed`，detail 为 `{ taskId, nodeId, resultUrl, type, status, errorMsg }`，供画布节点同步结果。

### 6.3 自动轮询调度

```js
var jt = 6e4, Mt = 3e4, Nt = 5;
```

| 常量 | 值 | 含义 |
| ---- | -- | ---- |
| `jt` | 60000 ms | **全局节流**：两轮扫描的最小间隔（60 秒） |
| `Mt` | 30000 ms | **单任务冷却**：同一任务两次刷新的最小间隔（30 秒） |
| `Nt` | 5 | **单轮上限**：一次扫描最多刷新 5 个任务 |

调度逻辑（`useEffect`，依赖 `[globalTasks, g, isLoaded]`）：

1. 前置门槛：`isLoaded && localToolConnected` 均为真才执行——**本地工具未连接时不会自动轮询**。
2. 距上轮不足 `jt`（60s）直接返回。
3. 遍历任务，同时满足四条才入选，且累计满 `Nt`(5) 个即停：
   - type ∈ `sd2Video`/`video`/`discountVideo`/`rhWebapp`
   - status ∈ `running`/`pending`
   - 存在 `taskId`
   - 距该任务上次刷新 ≥ `Mt`(30s)
4. 入选任务按 `pending` 优先排序。
5. 逐个错峰派发：第 `i` 个延迟 `i * 5000 + random(0,1000)` ms，均以 `silent=true` 调用。

> 即稳态下每分钟最多刷新 5 个任务，彼此间隔约 5 秒，单任务实际刷新周期不快于 60 秒。**没有失败重试机制**——失败任务状态置为 `failed` 后即退出轮询集合。

## 7. 契约要点速查（海关审计视角）

1. **两套 type 枚举不可混淆**：任务 type 7 种（`text/image/video/sd2Video/discountVideo/custom/rhWebapp`）vs `Wn` 节点中文名映射 24 项（带 `Node` 后缀）。`tehuishipin` / `yimaoAiApp` / `default` 则是第三套东西——`apiConfigs` 的配置项 id。
2. **三张字段表分工明确**：`Rn`(42) 判定是否通用字段 → `Hn`(42) 给中文名 → `Bn`(16) 定控件类型，未命中由 `Vn()` 按值类型 + 字段名正则推断；正则带 `\b` 边界，对驼峰字段无效。
3. **API 来源本质只有一条链路**：`apiConfigs` 列表 + 一个"选中 id"。差别在于 text/image/video/sd2Video/audio 的 id 用户可改并持久化，而 `discountVideo`/`aiApp` 的 id 被硬编码为 `tehuishipin`/`yimaoAiApp`；text/image/video 额外有 `readonly` 规避逻辑。
4. **特惠视频模型**来自服务端 `catalog.discountVideoSpecs`，与内置 `builtinFavorites` 字段级合并，不走 `apiConfigs`。
5. **任务轮询**仅 `sd2Video/video/discountVideo/rhWebapp` 四类；节奏为全局 60s 节流、单任务 30s 冷却、单轮最多 5 个、错峰 5s，**依赖本地工具连接且无失败重试**。
6. **仅 `sd2Video`/`video` 支持实例级 apiUrl/apiKey 回退**，`discountVideo`/`rhWebapp` 强制走全局值。
7. **万能节点有 sync 与 async 两种执行模式**（原文档漏了 async）：async 需配 `taskIdPath` + `polling*` 系列共约 10 个字段，轮询次数 = `ceil(总超时/间隔)`，失败响应静默重试，无进度路径时按 `min(99, 次数*2)` 估算。
8. **结果写回是双写**：全局任务列表（`status/progress/customResultData/customRawResponse`）+ 节点 `data`（按 `outputType` 分派到 `text/imageUrl/videoUrl/audioUrl`），并通过 `mutiwindow-task-completed` 事件跨组件同步。
