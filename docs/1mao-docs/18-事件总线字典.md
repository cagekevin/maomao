# 18 - 事件总线字典

> 范围：发布包 `一毛AI画布多端合一版本1.4.2` 的**跨组件 / 跨窗口 / 跨标签页 / 跨进程通信事件全集**。
> 目标：把散落在 `dist/assets/*.js` 中的"事件总线"摸清楚，形成可查的字典。
> 说明：本文档只做梳理与记录，不改动任何代码。所有条目均来自对压缩产物的静态反查（grep / 正则），事件名以产物中出现的字符串或反混淆常量值为准。

---

## 0. TL;DR（速查表）

本应用**没有引入第三方 EventBus 库**（grep `EventBus`/`mitt`/`tiny-emitter` 均无命中）。
它实际用了 **3 套原生通信机制**，外加 Web Worker 内部消息：

| 机制 | API | 用途 | 命名风格 |
|---|---|---|---|
| ① 自定义事件总线 | `window.dispatchEvent(new CustomEvent(name, {detail}))` + `window.addEventListener(name, ...)` | 应用内 / 跨窗口组件通信（主力） | `mutiwindow-*`、`canvas-*`、`*-modal` 等 kebab-case |
| ② 跨标签页同步 | `BroadcastChannel("yimao_canvas_sync")` | 多标签页画布状态同步 | `type: "CANVAS_SAVED"`（SNAKE_CASE） |
| ③ 父子窗口消息 | `window.parent?.postMessage({type, payload}, targetOrigin)` | 内嵌 iframe → 宿主（如导演台截图回传） | `type: "storyai:*"` |
| ④ Web Worker 消息 | `worker.postMessage({id, ...})` / `self.onmessage` | 离屏计算（计时器、音视频、MP3 编码） | 内部协议，非用户态事件 |

## 1. 机制一：浏览器原生 CustomEvent 总线（主力事件总线）

这是应用真正意义的"事件总线字典"。所有事件都挂在全局 `window` 上，发 (`dispatchEvent`) 与收 (`addEventListener`) 解耦，跨 React 组件树 / 跨窗口通信。

### 1.1 事件总表

> **反查结论（2026-08 复核）**：在 `dist/assets/*.js`（`App-BX6o9fW5.js`、`httpClient-BknZwXjG.js`、`ShareAppPage-C4RerI9i.js` 等）中全量扫描 `new CustomEvent(...)`、`addEventListener(...)` 与共享常量定义，确认下列 **25 个"可读字符串事件名"真实存在**（含以共享常量形式出现的 `yimao:*`、`modelSchedules:*`、`rhwebapp-*` 等）；另有 **2 个跨 chunk 共享事件**（`V`/`ce` 注入事件、`yt`/`ie` 重载事件）其字符串值在压缩产物中未以可读字面量暴露（见 §1.1.5）。
> **易混淆误报（已从事件字典剔除，非 `CustomEvent` 事件名）**：
> - `canvas-assistant`（实为 AI 助手 `agentKey` 字符串，常量 `fr`，非事件）
> - `canvas-frame`（实为 CSS `className`）
> - `canvas-state-v1-` / `canvas-state-v1-default`（实为 IndexedDB / 存储键前缀，`OURCES||e2.startsWith("canvas-state-v1-")` 判断，非事件——文档旧版误作 `canvas-state-v` 事件）
> - `script-box-view-*`（`script-box-view-${id}`，实为 localStorage 视图模式键，非事件——文档旧版误作脚本盒视图事件）
> - `custom-edge-flow-style` / `custom-handle-hover-style`（实为 CSS 样式字符串常量 `kg`/`Sr`，非事件）
> 以上虽能被正则匹配到，但均不是 `CustomEvent` 事件名。
> **方向约定**：`App` 为宿主/控制层，`httpClient` 为画布渲染/执行层。`request`/`open-*`/`run-*` 类多发自 `App` 或 `httpClient` 触发侧，`done` 回执类多从执行侧回到 `App`。个别项已在备注标注"需源码核对"。

### 1.2 脚本盒事件载荷（`script-box-connect-shot(s)`）

由 `httpClient` 在分镜编辑场景内部自产自销，用于把"脚本盒"节点与"分镜"节点连线：

- `script-box-connect-shot`：`{ shotId, boxId }` 级别的单条连接
- `script-box-connect-shots`：`{ shots: [...], boxId }` 级别的批量连接

> 旧版文档此处还列有 `script-box-view-*` 并描述为"脚本盒查看/定位事件"。经复核，**它不是事件**：`script-box-view-${id}` 实为 `localStorage` 记录脚本盒视图模式（`"single"` / `"list"`）的存储键，已从事件字典移除（见 §5 误报清单）。脚本盒域目前确认的真实 CustomEvent 仅上述两条。

### 1.3 使用范式（代码事实）

- **发**：`window.dispatchEvent(new CustomEvent("事件名", { detail: {...} }))`
- **收**：
  ```js
  window.addEventListener("事件名", (e) => { const detail = e.detail; /* ... */ });
  // 组件卸载时务必 removeEventListener，App 中多处使用了返回清理函数的 useEffect 模式
  ```
- 监听端集中在 `App-BX6o9fW5.js` 与 `httpClient-BknZwXjG.js`；少数原生 DOM 事件（`mousemove`/`keydown`/`paste`/`storage`/`resize` 等）也挂在 `window` 上，需注意与业务事件区分（见 §3 注意事项）。

## 5. 注意事项与反查方法

1. **命名空间冲突风险**：业务事件（`mutiwindow-*`、`canvas-*`、`script-box-*`）与原生 DOM 事件（`mousemove`、`keydown`、`paste`、`storage`、`resize`、`load`、`error`）都挂在同一个 `window` 上。此外 `vendor-Z-adA07W.js`（three.js）内部会向 `__THREE_DEVTOOLS__` 派发 `CustomEvent("observe")` / `CustomEvent("register")`，**这是 three.js 调试工具事件，不是本应用业务事件**，反查时务必排除。监听业务事件时一定要用精确事件名 + 组件卸载清理，避免与原生/第三方事件混淆。
2. **事件名是"契约"**：跨 chunk（`App` ↔ `httpClient` ↔ `ShareAppPage`）通过 `window` 事件解耦，发收双方必须**字符串完全一致**。产物中部分事件名被提取为共享常量，集中在 `httpClient-BknZwXjG.js` 顶部定义并 re-export 给其他 chunk：
   - `A_=canvas-run-workflow-request`、`j_=canvas-reset-workflow-runtime`、`M_=canvas-run-workflow-done`、`N_=canvas-force-save-request`、`P_=canvas-force-save-done`、`Hn=canvas-add-resource-request`
   - `io=yimao:openPromptSettings`、`so=yimao:promptRecent`、`ma=modelSchedules:change`（`pa=modelSchedules` 为命名空间基础常量）、`zs=rhwebapp-run-request`
   - 注入/重载事件的共享常量经 re-export：`V`/`ce` 源自 `u`、`yt` 源自 `s`、`ie` 源自 `c`（字符串值未在产物中暴露）
   改名需同步所有引用点（含 `App` / `ShareAppPage` 的 import 别名）。
3. **反查命令**（供后续维护，POSIX `grep` 或 PowerShell 均可）：
   ```bash
   # 列出所有 CustomEvent 事件名（双引号字面量）
   grep -rhoE 'new CustomEvent\("[^"]+"' dist/assets/*.js
   # 列出所有 addEventListener 监听名
   grep -rhoE 'addEventListener\("[^"]+"' dist/assets/*.js
   # 列出 BroadcastChannel 通道
   grep -rhoE 'new BroadcastChannel\("[^"]+"' dist/assets/*.js
   # 列出 window.postMessage 的 type
   grep -rhoE 'type:"[^"]+"' dist/assets/*.js
   ```
   PowerShell 等价写法（在仓库根目录执行）：
   ```powershell
   Get-ChildItem dist/assets/*.js | ForEach-Object {
     (Get-Content $_.FullName -Raw | Select-String -AllMatches 'new CustomEvent\("([^"]+)"').Matches |
       ForEach-Object { $_.Groups[1].Value }
   } | Sort-Object -Unique
   ```
   > 注：旧版文档称"本项目提供 `scripts/_t_eventprobe.ps1` 可复现提取结果"，经核实该脚本**并不存在于 `scripts/` 目录**。请以本节命令为准自行复现。
4. **未覆盖项**：`V`/`ce`（注入事件）与 `yt`/`ie`（重载事件）这两个跨 chunk 共享常量的**精确字符串值**仍未在压缩产物中暴露（它们经 `httpClient` re-export 后在 `App`/`ShareAppPage` 中以变量别名引用，字符串值未以可读字面量出现）。`canvas-add-resource-request` / `canvas-run-workflow-*` / `canvas-force-save-*` / `canvas-reset-workflow-runtime` 等 `request`/`done` 事件的 `detail` 精确字段因压缩未直接可读，需对照未压缩源码（`src`）确认。建议后续在 `src/` 中核对对应常量定义与 `detail` 结构。
5. **反查易误报**：正则扫描 `"(mutiwindow-|canvas-|script-box-|custom-|...)"` 会命中非事件字符串。已确认需剔除的误报（均**不是** `CustomEvent` 事件名）：
   - `canvas-assistant`：实为 AI 助手 `agentKey` 字符串（常量 `fr`，如 `ar("canvas-assistant")`）
   - `canvas-frame`：实为 CSS `className:"canvas-frame"`
   - `canvas-state-v1-` / `canvas-state-v1-default`：实为 IndexedDB / 存储键前缀（旧版文档误作 `canvas-state-v` 事件）
   - `script-box-view-*`：实为 `localStorage` 视图模式键 `script-box-view-${id}`（旧版文档误作脚本盒视图事件）
   - `custom-edge-flow-style` / `custom-handle-hover-style`：实为 CSS 样式字符串常量（`kg` / `Sr`）

   以上虽能被正则匹配到，但均不是业务事件，反查时务必排除。

## 6. 结论

- 本项目的"事件总线" = **全局 `window` 上的 `CustomEvent` 发布订阅**，是真正的主总线；辅以 `BroadcastChannel`（跨标签页）和 `window.postMessage`（跨窗口 iframe）。
- 事件字典分两大域：**画布/任务协同域**（`mutiwindow-*`、`canvas-*`、`script-box-*`）与 **UI 面板/设置域**（`*-settings`、`*-modal`、`import/export-project`、`yimao:*`、`modelSchedules:*`、`rhwebapp-*`）。经 2026-08 全量复核，确认存在 **25 个可读字符串事件名**（含以共享常量形式出现的 `yimao:*` / `modelSchedules:*` / `rhwebapp-*` 等）+ **2 个跨 chunk 共享事件**（`V`/`ce` 注入事件、`yt`/`ie` 重载事件，字符串值未暴露），并已剔除 `canvas-assistant` / `canvas-frame` / `canvas-state-v1-` / `script-box-view-*` / `custom-*-flow-style` 等正则误报（详见 §5）。
  > 计数口径说明：旧版"28 个"为粗略估计且混入了误报（`canvas-state-v`、`script-box-view-*`、`mutiwindow-task` 均非真实事件）。本版按"产物中真实出现且确属 `CustomEvent` 事件名"的标准重新清点：mutiwindow-* 8、canvas-* 7、script-box-* 2、UI/跨窗口 8（`builtin-panel-switch-schedule`、`open-shortcuts-modal`、`import-project`、`export-project`、`yimao:openPromptSettings`、`yimao:promptRecent`、`modelSchedules:change`、`rhwebapp-run-request`）= 25。
- 没有中心化的"事件名常量文件"暴露在产物中，事件名分散在发收两端（且跨 chunk 通过 re-export 常量解耦）；维护时务必以 §1.1 总表为单一事实来源，改动事件名需全局核对（含 `App` / `ShareAppPage` 的 import 别名）。
