## 0. 背景速览（先读这段，避免踩坑）

给画布加自研节点，本质上是在一条**已经定死的请求链**上插一个「新请求源」。要理解怎么插，必须先理解这条链：

```
浏览器画布 (src/bundle/ → npm run build 回灌 dist/)
   │  proxyMode=local-tool，所有请求的唯一出口
   ▼
localTool :18080 (localTool/src/index.ts 路由表 + localTool/src/routes/*.ts)
   ├─ /api/proxy ─────────► 转发到 apimart-gateway :9004（Python/FastAPI）
   │                        或透传外部上游（如 kkidc）
   ├─ /api/xxx 具名路由  ──► localTool 自己实现（自研能力落点）
   └─ 未匹配路由 ─────────► catch-all 兜底透传官方 1mao
```

**关键结论（本项目铁律，来自 CLAUDE.md）**：

1. **前端只能改 `src/bundle/`，不能直接手改 `dist/`**。改完必须 `npm run build` 回灌 `dist/`，并跑质量门（`npm run test:smoke` / `npm run health`）。
2. **请求唯一入口是 localTool**。任何新节点的请求都要能落到 `127.0.0.1:18080`。
3. **协议信封**：画布硬编码读 `{code, data}` 信封的 `t.data[0].url`。localTool 负责「剥信封对齐画布」（见 `system.ts` 的 `handleProxy`）。
4. **新增跨端字符串契约要登记**：新节点涉及任何新的 URL 路径/字段名，若被多处引用，须同步到 `scripts/contracts.json` 并跑 `npm run contracts`（详见 CLAUDE.md §5.7/5.8）。

> 这四条决定了「加自研节点」的所有工作，都围绕 **①前端节点组件 + ②localTool 路由 + ③请求协议** 三处展开。

## 0.5 前端调用机制全景（真实代码链路 · 先看这段，你就懂「怎么在前端调用」了）

> 本节是本次补充的核心。把「前端到底怎么调用」用**真实源码落点**讲清楚。所有混淆符号均来自 `src/bundle/` 现版本，官方更新重打补丁时需重新对照（见 CLAUDE.md §五.4）。

**一句话总结**：前端节点是一个 **React Flow 节点对象**，它的 `data` 上被注入了一个**回调句柄**（如 `onGenerateCustom`），点按钮时画布调用这个句柄 → 句柄内部做「输入聚合 + 占位符替换 + 发请求 + 解析响应 + 写回」，发请求统一走 `Bl()` 这个函数，`Bl()` 根据 `proxyMode` 决定走 `/api/proxy` 还是直连。

### 0.5.1 节点是怎么「创建」的（拖拽进画布那一刻）

在 `src/bundle/httpClient-BknZwXjG_components/H_.jsx` L8604 有一个节点创建函数 **`di`**（混淆名，console 打 `addNodeWithData`；**不是 `createNode`**——全仓没有叫 createNode 的画布函数，`createNode` 只出现在 React Flow 底层库 vendor 里，与本项目无关）。从工具栏拖一个节点进来时它生成节点对象，L8634 是它内部的节点对象字面量：

```js
let c = {
  id: s,              // `${type}-${时间戳}-${随机}`
  type: e,            // 节点 type，如 videoConfuseNode
  position: {...},    // 画布坐标
  style: e === `faceMosaicNode` ? { width: 360, height: 300 } : ...,  // 节点尺寸
  data: {
    ...a,             // 该节点的默认 config 字段（来自工具栏列表项的 data）
    hasChanged: true,
    onGenerate: e === `promptNode` ? Hr : undefined,        // 生图节点回调
    onGenerateVideo: e === `videoNode` ? Gr : undefined,    // 普通视频回调
    onGenerateSD2Video: e === `sd2VideoNode` ? qr : undefined,
    onGenerateCustom: e === `customNode` ? Qr : undefined,  // 万能节点回调 ★
    onGenerateDiscountVideo: e === `discountVideoNode` ? Jr : undefined,
    onStop: ..., onRefresh: ..., onShowToast: ...,          // 通用控制回调
    // ... 各节点专属字段也在这里注入
  }
}
```

**关键理解**：
- 节点**不是**一个独立注册的组件类，而是「工具栏列表项 + 一段 `di` 分支」共同决定的。工具栏列表项在 H_.jsx 约 L9400 起，每项形如 `{ type, label, icon, cat, data }`。
- `data` 上挂的 `onGenerate*` **就是前端调用的入口**。你想加一个能触发的自研节点，就要给它的 type 新增一个回调句柄分支。
- **`style` 分支**、**工具栏列表项**、**回调注入分支**、**节点默认 `data`**，这四处是"新增一个节点 type"在前端必须改的最小集合。

### 0.5.2 点「生成」按钮后发生了什么（以 custom 万能节点为范本）

`onGenerateCustom: Qr`，`Qr` 在 H_.jsx L7107。这是最完整的"节点调用"范本，全程可抄：

```
Qr(nodeId)
  ├─ 校验：node.type === "customNode" && node.data.config（不满足直接 return）
  ├─ 置 loading:true / progress:0 / 清 errorMsg、resultData
  ├─ 输入聚合：
  │   遍历所有连线 target === nodeId
  │     ├─ targetHandle 以 "var-" 开头 → 写入变量表 variables[name]
  │     ├─ targetHandle 为 default/空 → 按内容二次分流：
  │     │    源节点有 imageUrl/videoUrl 或以 http/data:image/ 开头 → 图片数组 image_{n}
  │     │    否则 → 文本数组 prompt
  │     └─ 变量值以 http 开头且变量名以 image/audio/video 开头 → fetch 转 base64 data URL
  ├─ 占位符替换：{{var}}、{{name|默认}}、{{image_1}}、{{prompt}}（对 body/apiUrl/headers/pollingHeaders 全替换）
  ├─ body 特殊处理：
  │    Content-Type: multipart/form-data → 把 JSON body 转 FormData（data: 前缀转 Blob 上传）
  ├─ 发请求：let b = await Bl(f, { method, headers, body, ...Ee })
  │   （f = apiUrl，Ee = proxyMode/localPort 等运行上下文）
  ├─ 解析响应：
  │    响应 content-type 是 audio/image/video/octet-stream → 转 base64 data URL
  │    否则 → b.json()
  │    按 executionMode 分支：
  │      sync  → resultPath 提取结果，写回节点 data + 全局任务
  │      async → taskIdPath 取 task_id，轮询 pollingUrl 直到完成（见 docs/18 §5.1）
  └─ 写回：node.data.resultData + 按 outputType 分派
       text→data.text、image→data.imageUrl、video→data.videoUrl、audio→data.audioUrl
       + 写全局任务列表（type:"custom", status, customResultData, ...）
       + 派发 mutiwindow-task-completed 事件（跨组件同步）
```

### 0.5.3 发请求统一走 `Bl()`（决定走不走 localTool 的核心）

`Bl(e, t)` 在 `src/bundle/httpClient-BknZwXjG_components/shared.js` L6092。**这是所有节点最终发请求的唯一出口**，逻辑：

```js
async function Bl(e /* url */, t /* {method, headers, body, proxyMode, localPort, ...} */) {
  let isFormData = t.body instanceof FormData;
  let isBlob = t.body instanceof Blob;
  // 判断是否走 local-tool 代理：
  //   proxyMode === "local-tool"（或存在 localPort/localToolBaseUrl 时默认 local-tool）
  if ((t.proxyMode || (t.localPort || t.localToolBaseUrl ? "local-tool" : "server-proxy"))
        === "local-tool" && (t.localPort || t.localToolBaseUrl)) {
    let base = (t.localToolBaseUrl || Mn()).replace(/[\s`]/g,"").trim().replace(/\/$/,"");
    // 相对路径（非 http/data/blob 开头）→ 走 /api/files/read
    if (!e.startsWith("http") && !e.startsWith("data:") && !e.startsWith("blob:"))
      return fetch(`${base}/api/files/read?path=...`);
    // body 是 FormData/Blob → 形态①：X-Proxy-* 头
    //   fetch(`${base}/api/proxy`, { headers: { X-Proxy-Url: e, X-Proxy-Method, X-Proxy-Headers } , body })
    // body 是 JSON → 形态②：JSON body {url, method, headers, body, cookie}
    //   fetch(`${base}/api/proxy`, { body: JSON.stringify({ url: e, method, headers, body, cookie }) })
  }
  // 否则 server-proxy 模式：直连 + X-Proxy-Url 头
  ...
}
```

**这就是文档 §3「发请求」的前端半程**：前端只需把请求交给 `Bl()`，`Bl()` 自动根据 `proxyMode` 决定打到 localTool 的 `/api/proxy`（JSON 或 FormData 形态），再由 localTool 转发到后端。**前端自己不用关心最终连的是 9004 还是外部上游**。

> ⚠️ 对照 localTool 侧：`Bl()` 的两种形态，正好对应 `localTool/src/routes/system.ts` `handleProxy` 的两种分支——`X-Proxy-Url` 头（`handleProxyFormData`）和 JSON body `{url,...}`（`handleProxyJson`）。**前端形态和后端分支是一一对应的**，改一头必改另一头。

### 0.5.4 新增节点的最小改动集合（前端四件套）

要在画布新增一个「能拖、能配、能触发」的自研节点 type（如 `videoConfuseNode`），前端至少要动：

| # | 改动 | 落点 | 作用 |
|---|---|---|---|
| 1 | 工具栏列表项 | H_.jsx 约 L9400 的节点数组加 `{ type, label, icon, cat, data }` | 让节点能拖进画布 |
| 2 | `di` 分支 | H_.jsx L8604 的节点对象字面量（L8634），加 `style` 分支 + 给 `data` 注入回调句柄（如 `onGenerateVideoConfuse`）| 定义节点尺寸 + 挂上触发入口 |
| 3 | 触发回调实现 | 新增一个函数（仿 `Qr`），或复用 `Qr` 改成固定发往本节点的路由 | 点「生成」时真正发请求 |
| 4 | 节点渲染/字段面板 | 节点的 React 组件里渲染 `config` 字段面板 + 把「生成」按钮绑定到回调 | 让用户能填参数、能看到按钮 |

## 1. 整体思路（三处改动，缺一不可）

新增一个自研节点，需要在前端、中继、请求协议三处各做改动，它们是**串行依赖**的：

```
[前端] 加节点组件         → 画布上出现新节点、有字段面板、有「生成」按钮
   │   src/bundle/*_components/
   ▼
[请求] 节点发请求         → 请求打到 localTool（可能经 /api/proxy 或具名路由）
   │   httpClient 的 onGenerate* / custom 节点逻辑
   ▼
[中继] localTool 接住     → 转发到后端 py（:9004 网关 或 localTool 自实现）
   │   localTool/src/routes/*.ts + index.ts 路由注册
   ▼
[后端] 处理并返回        → 【本文不涉及】后端 py 实现算法，返回 {code,data} 信封
```

**三种「自研节点」的接入档次（按复杂度从低到高，先想清楚你要哪种）**：

| 档次 | 做法 | 适合场景 | 改动面 |
|---|---|---|---|
| A. 复用**万能节点** | 不改前端，用户配 `custom` 节点填 apiUrl/method/body 直发后端 | 一次性、验证用 | 仅后端 |
| B. 新增**专属字段节点** | 前端加一个带固定字段面板的节点 type，把请求发到 localTool 的具名路由 | 想做正式、可复用的自研能力 | 前端 + localTool + 后端 |
| C. 新增**专属字段节点 + 模型下拉** | 在 B 基础上，走 `apiConfigs.baseline.json` 注册模型，让节点能选模型 | 想让节点像内置生图/视频节点一样有模型选择 | 前端 + localTool + baseline + 后端 |

> **建议**：先用 A（万能节点）把后端接口调通、验证协议正确，再决定要不要做 B/C 的前端专属节点。这符合 CLAUDE.md 的「奥卡姆剃刀：如无必要勿增实体」。

【待补充】后续 AI 可把 B 或 C 的完整 diff 级实施步骤补到 §4，每个文件列「改动位置 + 伪代码 + 验证方式」。

## 1.5 可选步骤：独立 dev 原型先行，验证通过再接回

> **这是什么**：在真正动 `src/bundle/` 混淆码（前端四件套）之前，先做一个**独立的原型或 dev 版本**（纯 HTML / 独立组件，不碰现有系统），把「UI 长什么样、交互顺不顺、流程对不对」验证通过，再回到 §4 接真实代码。
>
> **定位**：本步骤是「自研功能接入」的**可选前置**。针对**界面复杂的自研功能**（多步骤 / 多视图 / 弹窗多，如剧本盒子三步状态机）尤其有价值；纯逻辑改动或已有现成 UI 可直接对照时，跳过本步骤直接进 §4。

### 1.5.1 流程

| 阶段 | 做什么 | 剧本盒子案例 | 风险 |
|---|---|---|---|
| 1.5.1 | 用独立文件搭出目标 UI + 交互 | `剧本盒子原型.html`（独立 HTML，三步 UI + 设置弹窗 + 全屏） | 🟢 不碰系统 |
| 1.5.2 | 交互做成可真实操作（填信息/点击生成/遮罩/停止），不必真连后端 | 生成剧本/资产/提示词，用本地假引擎模拟 | 🟢 假数据 |
| 1.5.3 | 对照真实源码，把原型的数据结构、提示词模板等**对齐源码** | 资产 `Zg` 拼装、分镜导演模板与 `c_.jsx` 逐字对齐 | 🟢 只改原型 |
| 1.5.4 | **冒烟验证**原型交互链路不崩（Node 最小 DOM 桩跑一遍） | 交互链路 `ALL PASSED` | 🟢 只测原型 |
| 1.5.5 | 产出「原型 → 接入」衔接结论，明确哪些可参考、哪些只是假交互 | 原型 → 引擎重构 Step 1-4（`docs/40`） | ⚠️ 关键边界 |

### 1.5.2 关键边界（务必遵守）

- **原型是"纸样/模型"，验证的是外观与交互；接入系统是"真功能"，验证的是行为**。两者目的、交付物不同。
- **不要**把原型的假交互（`setTimeout` 模拟）、假数据池、占位图直接当实现搬进 `src/bundle/`——那违反 CLAUDE.md §3.1（新建自研 SOP）与 §5.6（最小差异）。
- 原型验证通过后，接入仍走 §4 前端四件套 + §3 请求链路，每步小步、可回退、跑质量门（`npm run test:smoke` / `contracts` / `build`）。
- 冒烟测试能验证「逻辑不崩」，**不能验证「视觉对」**——最终视觉效果仍需浏览器/真机确认。

**产物**：独立原型文件（+ 可选冒烟测试脚本，测完即删）+ 一份「原型 → 接入」衔接结论。

## 2. 节点体系是什么（先搞清楚「注册」注册到哪里）

本项目有两套 type 枚举，**不能混淆**（详见 `docs/18-节点组件契约表.md`）：

- **任务 type**（任务中心分类，7 种）：`text / image / video / sd2Video / discountVideo / custom / rhWebapp`
- **节点 type**（画布渲染组件，24 种，带 `Node` 后缀）：`promptNode / videoNode / customNode …`

要新增自研节点，至少要决定它的 **节点 type**（如 `videoConfuseNode`）和**结果媒体类型**（视频混淆 → `video`），这会决定：

- 字段面板渲染（`config` 里有哪些字段，字段控件类型）
- 结果写回到节点的 `data.videoUrl`
- 是否需要「任务轮询」（长耗时 → 需要异步提交 + 轮询，像 `video` 那样）

**「注册」的真实含义**（本项目没有独立的注册中心，靠以下四处共同识别一个节点）：

1. **节点组件实现**：在 `src/bundle/` 对应 chunk 的 `*_components/` 下，实现节点 React 组件 + 字段面板 + 生成函数。画布据此渲染。
2. **中文名映射 `Wn`**：在 `App-BX6o9fW5_components/*.jsx` 的 `Wn` 表里加 `videoConfuseNode: "视频混淆"`（否则标题回退成 node.id）。
3. **（若走模型下拉，档次 C）`apiConfigs.baseline.json`**：在 `localTool/data/apiConfigs.baseline.json` 的对应 provider 下加模型条目。
4. **（若需要任务轮询）任务 type 与刷新/轮询逻辑**：在 `App` 的 `handleRefreshTask`（`Pt` hook）加分支，决定刷新 URL 与响应解析。

> 换句话说，新节点「能否被画布识别」，取决于**前端代码里有没有这个 type 的组件 + 映射**；「能否发请求」，取决于**请求能不能落到 localTool 具名路由**；「能否出结果」，取决于**响应形状是否对齐画布硬编码**。

【待补充】后续 AI 需要把「在哪一个 chunk 的哪一个文件加节点组件」精确定位出来（先 `npm run map` 读 `src/bundle/BUNDLE_MAP.md` 反查落点，再对照 `component_map.json`），补到 §4。

## 3. 怎么发请求（请求链路的三种路径）

新节点发请求到后端 py，本质上只有三种落点。**先把后端接口按下列某种路径设计好，前端就照着配**：

### 路径 ①：直接走 `/api/proxy`（透传/中继）
`localTool/src/routes/system.ts` 的 `handleProxy` 支持两种形态：
- **FormData/Blob + `X-Proxy-Url` 头**：body 原样转发到目标 url。
- **JSON body `{url, method, headers, body, cookie}`**：按 body.url 转发。

会做协议翻译（剥 `{code,data}` 信封、SSE 流式、异步转同步 `?wait=1` 等）。**适合**：后端 py 挂在 `:9004` 网关，或外部上游，节点把请求丢给 `/api/proxy` 让它转发。

### 路径 ②：localTool 新增具名路由（自研能力落点，推荐）
在 `localTool/src/routes/` 新建（或扩展）一个 handler，在 `index.ts` 的 `handleRequest` 里**在 catch-all 透传之前**注册具名路由。示例（视频混淆）：

```ts
// localTool/src/routes/videoConfuse.ts
import { json, parseJsonBody, sendError } from '../utils/helpers.js';

export async function handleVideoConfuse(req, res) {
  const body = await parseJsonBody(req);
  if (!body || !body.videoUrl) return sendError(res, 'Missing videoUrl', 400);
  // TODO: 转发到后端 py 处理，再返回结果。当前先返回 stub。
  return json(res, {
    code: 0,
    data: { video_url: body.videoUrl, message: '视频混淆 stub（待接后端）' },
  });
}
```

```ts
// localTool/src/index.ts  handleRequest 内、handlePassthrough 之前：
if (pathname === '/api/video/confuse' && method === 'POST') {
  return await handleVideoConfuse(req, res);
}
```

> ⚠️ **路由顺序是铁律**：所有具名路由必须在 `catch-all passthrough` **之前**注册（`index.ts` 里 `await handlePassthrough` 那一行）。否则未接管请求会被透传官方 1mao。

**适合**：后端 py 作为 localTool 的子进程/子服务，或 localTool 内部自己实现（如调 ffmpeg、调开源 py 脚本）。localTool 从后端拿到 `{code,data}` 信封后，**保持信封返回**（或按画布需要剥信封）。

### 路径 ③：localTool 内部直接调后端 py
在路径 ② 的 handler 内部，localTool 用 `fetch` 调后端 py（假设 py 服务起在 `:9005` 或作为脚本 spawn），把结果转成画布要的形状。这是「后端用开源 py 实现」的典型接法：

```
localTool :18080/api/video/confuse
   → handler 内 fetch http://127.0.0.1:9005/process   （后端 py 服务）
   → 取回 { code, data: { video_url } }
   → 按画布需要返回 { code:0, data:{...} }
```

> **协议对齐**：无论走哪条路径，**最后回给画布的形状必须让前端能取到结果 URL**。视频类节点前端硬编码读 `t.data[0].url`（对普通视频）或 `data.video_url`（对特惠）。做专属节点时，**先决定前端读哪个字段，再让后端/中继对齐它**，这是最容易踩的坑（详见 `docs/17-前后端契约海关审计.md`、`CONTRACTS.md` 的 `envelope_code_data`）。

### 请求鉴权与凭证
- localTool 转发时通常带 `Authorization` 头透传，或由 localTool 注入后端凭证。
- 若后端 py 需要 key/token，可放 `localTool/.env`（`loadDotEnv` 已支持）或 KV，**不要硬编码进前端**。

- 决定该节点是否需要「任务轮询」（长耗时建议异步：先 `POST` 提交拿 task_id，再 `GET` 轮询），若需要，补 `handleRefreshTask` 的分支实现。

### 4.3 生成函数（onGenerate / 提交）——前端「怎么调用」落地

**这是 §0.5 的落地版。** 点「生成」按钮 → 触发 `data` 上注入的回调（如 `onGenerateVideoConfuse`）→ 回调里做三件事。

**做法一（推荐，最省事）：直接复用 `customNode` 的执行函数 `Qr`（H_.jsx L7107），把 apiUrl 从「用户手填」改成「节点固定指向本地具名路由」。**

`Qr` 已经写好了全套逻辑，做专属节点只需在 `di` 分支里给新 type 也挂上 `onGenerateCustom: Qr`（或一个包装函数），并在节点默认 `config` 里把 `apiUrl` 预填成你 localTool 的路由：

```js
// di 分支新增（示意）
onGenerateCustom: e === `customNode` || e === `videoConfuseNode` ? Qr : undefined,
// 节点默认 config（示意）：
//   apiUrl: `http://127.0.0.1:18080/api/video/confuse`
//   method: `POST`
//   body: JSON.stringify({ videoUrl: `{{video_1}}`, strength: `{{strength}}` })
//   outputType: `video`
```

这样节点的「输入聚合、占位符替换、发请求、写回 videoUrl、任务列表同步」全部白拿，你只需改 `apiUrl` 固定值。

> ⚠️ **致命坑（必须改 `Qr` 的校验，否则点生成无反应）**：`Qr` 第一行硬校验了 `t.type !== "customNode"`（H_.jsx L7111）：
> ```js
> if (!t || t.type !== `customNode` || !t.data.config) return;
> ```
> 所以**只要你的节点 type 不是 `customNode`，即使挂了 `onGenerateCustom: Qr` 也会直接 `return`，毫无反应**。做法一若给新 type 挂 `Qr`，**必须把这一行校验条件一起放宽**：
> ```js
> if (!t || (t.type !== `customNode` && t.type !== `videoConfuseNode`) || !t.data.config) return;
> ```
> （同理 `Qr` 内部的 `!j`/`outputType` 分支、占位符聚合等其余逻辑都对 `videoConfuseNode` 通用，无需改。）

> ⚠️ 用 `Qr` 的前提：你的后端返回形状要能被 `Qr` 解析。视频类 `outputType` 会 `An(t)` 规整后写 `data.videoUrl`，所以后端**最终要返回一个视频 URL 字符串**（或 `resultPath` 能提取到它）。

**做法二：新写一个专属回调函数（仿 `Qr` 精简版）**。若不想让节点走 `custom` 那套「用户手填 config」，想做成固定字段面板，就仿 `Qr` 但把 config 读法固定化：

```js
// 简化骨架（示意，非完整实现，后续 AI 补齐）
const onGenerateVideoConfuse = useCallback(async (nodeId) => {
  const node = getNode(nodeId);
  if (!node || node.type !== `videoConfuseNode`) return;
  setNodeLoading(nodeId, true);
  // 1. 从 config + 上游连线聚合出入参（抄 Qr 的聚合逻辑）
  const body = { videoUrl: aggregatedVideoUrl, strength: node.data.config?.strength };
  // 2. 发请求（抄 Qr，走 Bl → localTool 具名路由）
  const res = await Bl(`http://127.0.0.1:18080/api/video/confuse`, {
    method: `POST`, headers: {}, body: JSON.stringify(body), ...Ee,
  });
  // 3. 解析：后端返回 { code:0, data:{ video_url } } → 取 video_url 写 data.videoUrl
  const json = await res.json();
  const url = json?.data?.video_url || json?.data?.url;
  setNodeData(nodeId, { loading: false, videoUrl: An(url) });
  // 4. 写全局任务 + 派发 mutiwindow-task-completed（见 docs/18 §6）
}, [/* deps */]);
```

**两种做法的共同点（前端调用必走的四步）**：
1. **输入聚合**：读节点 config + 遍历上游连线（`target===nodeId`）按 `targetHandle` 分流（见 §0.5.2）。
2. **发请求**：统一 `await Bl(url, { method, headers, body, ...Ee })`。`Ee` 是 `proxyMode/localPort/localToolBaseUrl` 等运行上下文，`Bl` 据此决定走 `/api/proxy` 还是直连（见 §0.5.3）。
3. **解析响应**：media content-type → base64；否则 `json()`；按 `resultPath`/`outputType` 提取结果。
4. **写回**：`data.videoUrl`（视频）+ 全局任务列表 + `mutiwindow-task-completed` 事件。

> **长耗时（视频处理几乎必然）→ 必须异步**：`Qr` 的 `async` 分支（`taskIdPath` + `pollingUrl/pollingResultPath/pollingCompletedValue`…）就是现成轮询，配好 `pollingUrl` 指向 localTool 的轮询路由即可，不用自己写轮询循环。详见 `docs/18` §5.1 的 async 模式。

| 画布运行调度 | `H_.jsx` ~L7844 `n.type === "customNode" ? await Qr(e)` | 批量运行节点时触发执行 |

### 9.1 做法A：彻底套壳 custom（改动最小，但节点行为 == custom）

**不新增节点 type**，而是直接复用 `customNode`，把它做成「预设好的万能节点」：新建时把 `config` 预填成固定指向后端路由。只需在 `di`（H_.jsx L8604，节点创建函数，console 打 `addNodeWithData`）分支里给 customNode 预填 config 一处。

```js
// H_.jsx di 分支里，customNode 的 data 注入处，给默认 config 预填（示意）：
// 做法A = 不新增 type，拖的仍是 customNode，仅把默认 config 预填成指向自研路由
// （可在工具栏 customNode 列表项的 data 里预填，或 di 里对 customNode 特判）
if (e === `customNode`) {
  data.config = {
    apiUrl: `http://127.0.0.1:18080/api/video/confuse`,   // 固定指向 localTool 具名路由
    method: `POST`,
    headers: `{"Content-Type":"application/json"}`,
    body: JSON.stringify({ videoUrl: `{{video_1}}`, strength: `{{strength}}`, type: `{{type}}` }),
    outputType: `video`,
    executionMode: `sync`,        // 若后端同步返回结果视频 URL
    // 若后端异步：executionMode: `async` + taskIdPath/pollingUrl/...（见 docs/18 §5.1）
  };
}
```

**优点**：零新增逻辑，`Qr` 全白拿，且 `Qr` 的 `type === "customNode"` 校验天然满足（type 就是 customNode），**无硬校验坑**。**缺点**：面板是「万能节点」那套（用户能看到 apiUrl/method/body 可编辑），不像是专用节点；且无法在工具栏单独列出「视频混淆」。

### 9.2 做法B：加专属 type + 复用 Qr（推荐，但必须同步改 3 处校验/调度）

新增真正的 `videoConfuseNode` type，但**生成按钮回调仍挂 `Qr`**（复用执行引擎），节点默认 config 固定指向后端。需要改 **5 处**：

**① `H_.jsx` 工具栏节点数组**（L9465 `customNode` 条目附近）新增：

```js
}, {
  type: `videoConfuseNode`,
  label: `视频混淆`,
  icon: <_Component45 size={15} className={`text-white`} />,  // 换一个合适图标
  cat: `video`
}, {
```

**② `H_.jsx` `di` 分支**（L8691 `onGenerateCustom` 附近）让新 type 也挂 `Qr`：

```js
onGenerateCustom: e === `customNode` || e === `videoConfuseNode` ? Qr : undefined,
```

并把 `style` 分支、`data` 默认 config 补上（`videoConfuseNode` → 一定尺寸 + 预填 config）。

**③ `H_.jsx` `Qr` 入口硬校验必须放宽（否则点生成无反应）**：`Qr` 第一行 `if (!t || t.type !== \`customNode\` || !t.data.config) return;`（H_.jsx L7111），type 不是 `customNode` 会直接 return。**必须改成**：

```js
if (!t || (t.type !== `customNode` && t.type !== `videoConfuseNode`) || !t.data.config) return;
```

> ⚠️ **这是做法 B 最容易漏、漏了必挂的坑**：文档早期版本漏了这个，导致"新 type 挂 Qr 但点了生成毫无反应"。后续 AI 落地时务必先确认 `Qr` 这一行是否已放宽。

**④ `shared.js` nodeTypes 映射 `O_`**（L11441）给新 type 挂渲染组件：

```js
var O_ = {
  ...
  customNode: _cmp_Rs,
  videoConfuseNode: _cmp_Rs,   // 复用 custom 的渲染组件（字段面板即 custom 面板）
  ...
};
```

> ⚠️ **复用 `_cmp_Rs` 是"能跑"的最短路径**，但面板文案还是「万能节点」。若要做**专属字段面板**（只显示视频混淆的字段），需新建一个渲染组件（仿 `_cmp_Rs`）再挂 `O_` 的 `videoConfuseNode`，这属于做法C，工作量明显上升。

**⑤ `H_.jsx` 运行调度**（L7844）让批量运行也能触发新 type：

```js
} else if (n.type === `customNode` || n.type === `videoConfuseNode`) {
  await Qr(e);
}
```

> ⚠️ 这一行也要加 `videoConfuseNode`，否则在「运行工作流」批量执行时，`videoConfuseNode` 不在这条分支，**点了运行也不会触发**（只在节点面板单点"生成"按钮才走 `onGenerateCustom`）。

### 9.3 做法C：专属字段面板（最像"正式自研节点"，工作量最高）

在 9.2 基础上，**新建一个渲染组件**（仿 custom 的 `_cmp_Rs`，只留视频混淆字段的输入框 + 生成按钮），并挂到 `O_` 的 `videoConfuseNode`。要点：
- 字段面板只读/写节点的 `data.config`（strength、type 等），不暴露 apiUrl/method/body。
- 生成按钮绑定 `data.onGenerateCustom`（即 `Qr`）。
- 结果展示复用 custom 的「videoUrl 预览 + 进度 + 错误」部分。
- `Bn/Hn/Rn` 字段表登记新字段中文名与控件类型（见 §4.2）。

【待补充】做法 C 的新渲染组件 `_cmp_Rs` 是混淆组件，需后续 AI 用 `npm run map` 定位其源码、理解 custom 面板结构后，才能仿写。这是前端部分唯一需要真正读大文件的地方。

### 9.4 三种做法对比

| 做法 | 新增节点 type | 专属字段面板 | 改动面 | 适用 |
|---|---|---|---|---|
| A 套壳 custom | 否（预设 config） | 否（仍是万能面板） | 最小（1 处） | 快速验证后端接口 |
| B 专属type+复用Qr | 是 | 否（复用 custom 面板） | 小（4 处） | 想有独立节点名，又不愿写面板 |
| C 专属type+专属面板 | 是 | 是 | 中-大（需仿写 `_cmp_Rs`） | 正式交付自研能力 |

> **建议**：先 A 调通后端 → 升 B 让节点名独立 → 有精力再升 C 做专属面板。符合「奥卡姆剃刀」。

### 9.5 localTool 侧配套（必须同时做）

无论 A/B/C，前端最终都发到 `http://127.0.0.1:18080/api/video/confuse`，localTool 必须接住（见 §3 路径②）。骨架：

```ts
// localTool/src/routes/videoConfuse.ts
export async function handleVideoConfuse(req, res) {
  const body = await parseJsonBody(req);
  if (!body?.videoUrl) return sendError(res, 'Missing videoUrl', 400);
  // 1. 把 videoUrl（可能是 localTool /files/ 本地文件或 CDN）传给后端 py
  // 2. 后端 py 处理完返回结果视频 URL
  // 3. 按前端期望返回 { code:0, data:{ video_url } }（Qr 的 outputType=video 会 An() 规整）
  return json(res, { code: 0, data: { video_url: body.videoUrl } }); // stub
}
```

```ts
// localTool/src/index.ts handleRequest 内、handlePassthrough 之前：
if (pathname === '/api/video/confuse' && method === 'POST') {
  return await handleVideoConfuse(req, res);
}
```

> ⚠️ **关键对齐**：前端 `Qr` 的 `outputType: "video"` 会用 `An(t)` 规整后写 `data.videoUrl`。所以后端/中继**最终必须把结果视频 URL 提取出来**（`json.data.video_url`），否则画布拿不到结果。协议字段见 §5。

## 10. 现有节点「接入做法」归类

> **数量口径**：`shared.js` 的 nodeTypes 映射 `O_`（L11441）共 **29 项** = **27 个业务节点** + `group` + `ghostTarget` 两个非业务占位节点。你说的"上个版本 27"对应的就是**业务节点数**（`O_` 里除 `group`/`ghostTarget` 外正好 27 个）。归类基于 `di`（H_.jsx L8604）注入的执行引擎（~L8677）与渲染组件（`O_`），混淆符号为现版本，官方更新需重对照。

### 10.1 归类维度

现有节点不是"清一色一种做法"，而是**按执行引擎归属**分五类。你在 §9 想新增的自研节点，本质上是往「类 ② 或 ④」里加，或造一个「类 ① 风格」的新生成节点：

| 类 | 接入做法 | 核心特征 | 执行引擎 |
|---|---|---|---|
| ① 生成类（走 apiConfigs + 模型下拉） | ≈ §9 档次 C | 有模型下拉、走 `/public/platform/*` + apiConfigs 的 url/key，请求经 `Bl` | `onGenerate*` 各专属函数 |
| ② 专属后端通道 | §9 档次 B/C 的高级版 | 锁死特定上游/协议，不走通用 apiConfigs 下拉 | 专属函数 |
| ③ 万能/可配路由 | §9 档次 A/B | 用户可填 apiUrl/method/body，直接发任意后端 | `Qr` |
| ④ 本地处理（前端/本地工具） | 非 §9 范畴（前端自带） | 纯前端逻辑或走本地工具/代理，无 `onGenerate*` 主引擎 | 节点自身处理函数 |
| ⑤ 纯 UI / 容器 | 非节点（不执行） | 承载/展示，不触发请求 | 无 |

### 10.2 逐个归类（27 业务节点 + 2 占位）

#### 类 ① 生成类（走 apiConfigs + 模型下拉）—— 5 个

## 11. 核心方法论：找功能相近的节点，抄它的「端点接口写法」（用户确认的最佳路径）

> 这是加自研节点**最稳、最省事**的路径：**先找一个功能相近的现成节点，吃透它的「端点接口写法」，然后照着改**。不要在 `src/bundle/` 里另起炉灶——那会踩 React 单实例 / 契约漂移的坑。下面把「怎么选、怎么抄」讲死。

### 11.1 选参考对象的判断标准（不是随便找个相近的就抄）

加新节点前，先回答「我的节点属于哪一类、像哪个现有节点」，然后**按类选范本**：

| 你的新节点想要… | 应该参考的节点（类） | 关键点 |
|---|---|---|
| 有模型下拉、像内置生图/视频 | `promptNode` / `videoNode`（类①） | 走 apiConfigs + `/public/platform/*` |
| 锁死一个自研后端路由、专属字段 | `discountVideoNode`（类②）| **最值得抄**：锁死 base + 专属端点 + 异步轮询 + 写回 videoUrl |
| 用户能填任意接口 | `customNode`（类③） | 复用 `Qr` 全套引擎 |
| 本地处理、不调远端 | `faceMosaicNode` / `videoProcessNode`（类④） | 前端/本地工具，无 `onGenerate*` 主引擎 |

> **判断要点**：先看你的节点是「调远端生成」（类①②③）还是「本地处理」（类④）。视频混淆 → 调后端 py → **属于类②**（锁死自研路由）最合适，所以**抄 `discountVideoNode`**。

### 11.2 参考对象要「抄」哪些东西（全套「端点接口写法」清单）

以 `discountVideoNode` 的执行函数 `Dr`（H_.jsx L3995）为范本，我把它挖出来了，**新增自研后端节点时照这个清单逐项对齐**：

| 抄什么 | 特惠视频怎么写（现成范本） | 你的「视频混淆」照抄改什么 |
|---|---|---|
| **端点拼法** | `const S = base.replace(/[`\s]/g,"").replace(/\/$/,"") + "/v1/gateway/generate"` | 改成你的自研路由，如 `base + "/api/video/confuse"` |
| **发请求函数** | `await Bl(S, { method:'POST', headers:{ Authorization:'Bearer '+key, 'Content-Type':'application/json', Accept:'*/*' }, body: JSON.stringify(M), ...Ee })` | **`Bl` 不用改**，改 `S`/`key`/`M` |
| **请求体结构** | `{ model, prompt, ratio, duration, resolution, aspect_ratio, video_length, messages:[{role,content:[image_url...,text]}], files }` | 换成你的入参（videoUrl/strength/type） |
| **响应解析** | `const P = await N.json(); const taskId = P.task_id \|\| P.id`（异步拿 task_id） | 对齐你后端的 task_id 字段 |
| **写全局任务** | `type:'discountVideo'`、`status:'pending'`、存 `taskId`、`requestData` | 改成你的 type |
| **异步轮询** | 提交后 GET `/v1/gateway/task/:id`（localTool `handleGatewayTask` 已接） | 对应你的轮询路由（localTool 加） |
| **鉴权** | `Bearer ${m}`（m=特惠 key） | 用你的后端 key |

> **核心结论**：`Dr` 里唯一要动的就是**①端点字符串 `S`、②请求体 `M`、③响应字段解析、④任务 type**，其余（`Bl` 发请求、输入聚合、写回 videoUrl、轮询）**全都不用改**。这就是"抄相近节点"的最大价值。

### 11.3 抄的步骤（落地顺序）

1. **定位参考节点**：按 §11.1 选对类 → 在 `di`（H_.jsx L8604，回调注入在 ~L8677）找到它的执行引擎函数（如 `discountVideoNode` → `Jr` → `Dr`）。
2. **读透它的执行函数**：把 §11.2 那 8 项「端点接口写法」从函数里摘出来（端点、Bl、请求体、解析、任务type、轮询、鉴权）。
3. **复制成新节点**：按 §9 做法 B/C，新 type + 挂 `Qr` 或新写执行函数 + 加进 `O_`。
4. **只改差异项**：端点、请求体、解析、type。
5. **localTool 配套**：加具名路由接住新端点（§9.5），必要时加轮询路由。
6. **验证**：§7 验收清单。

### 11.4 常见误区（别抄错）

- ❌ **抄了类①却按类④的思路**：本地处理节点（`faceMosaic`）没有 `onGenerate*`，照抄会没有生成入口。
- ❌ **照搬 `customNode` 却不改 apiUrl**：custom 的 apiUrl 是用户手填的，你不预填/锁死，节点会发到空地址。
- ❌ **改了 `Bl`**：`Bl` 是全项目共享的请求出口，**永远不要改它**，改的是传进去的 `url`/`method`/`body`/`headers`。
- ❌ **改了 `O_` 映射不挂渲染组件**：type 只在 `O_` 里有映射但没对应组件会白屏。
- ❌ **忘了 localTool 具名路由要放在 catch-all passthrough 之前**（§3 铁律）。
