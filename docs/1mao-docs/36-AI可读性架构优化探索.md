# 36 · AI 可读性架构优化探索（面向 AI 读者的逆向源码重构方向）

> **文档定位**：**探索/方向稿**，非实施计划。目的是回答一个问题——**`src/bundle/` 这套逆向混淆源码，架构上怎么优化，才能让后续 AI 改得动、找得到、不漏改**。本文只给方向与取舍，不给具体 diff；具体方案待立项后另开文档细化。
>
> **状态**：探索中（draft）。问题诊断（§二）基于当前 `src/bundle/` 实测；方向对比（§三）与方案（§四）为权衡后的候选，**均未实施**。
>
> **核心约束（全文前提，来自 CLAUDE.md）**：`src/bundle/` 是官方 `dist/` 逆向还原的可编辑源码，`npm run build` 回灌 `dist/`；改它受三条硬约束牵制——**① React 单实例不可破、② 字符串契约零损伤、③ 跨 chunk 引用钉死**。任何可读性优化**不能破坏这三点**，否则能跑得好好的代码会直接白屏/崩。**「降低复杂度优先」是既有铁律（CLAUDE.md §五.4 铁律 9）**，本文是这条铁律的展开。
>
> **一句话结论（TL;DR）**：当前的痛不是「代码写错了」，而是**反向工程把"引用关系"打散成了无法从名字反推结构的巨型聚合文件**。真正能落地的优化**不是重命名全仓**（风险极高、收益边际），而是**建立「语义化检索层」**——在不改运行时语义的前提下，把「名字」和「职责/落点」的映射做出来、做成工具化的、让 AI 靠查不靠猜。重命名只对**本地可改的短名**做小步增量。

---

## 一、问题本质：为什么 AI 找代码难、改一处漏一处

先别急着想"怎么重命名"。先搞清楚**根源**在哪。`src/bundle/` 不是手写工程，是官方混淆 `dist/` 经还原流水线拆出来的。它保留了混淆阶段的三个致命特征：

### 1.1 巨型聚合导出（barrel 反模式到极致）

混淆器把大量不相关的模块合并进少数几个文件，还原时被迫用**一个文件当总出口**，于是出现：

| 文件 | 行数 | 被引用次数 | 性质 |
|---|---|---|---|
| `src-_qSScO88_components/shared.js` | **34,659** | 146 | 聚合导出（helper/工具） |
| `httpClient-BknZwXjG_components/shared.js` | **11,727** | **203** | 聚合导出（HTTP/状态/请求） |
| `App-BX6o9fW5_components/shared.js` | 3,088 | 31 | 聚合导出（App 状态） |

**后果**：AI 看到一个组件文件里 `import { A, B, C, ... } from "./shared.js"`，**完全无法从名字判断 `A` 是干嘛的**。要搞清楚 `A` 是什么，得回到 `shared.js` 去搜定义——而 `shared.js` 本身 1 万+ 行，搜到定义后还得顺着它再跳转。**每一步都在烧 context。**

### 1.2 混淆短名（无语义命名）

facade 文件 `httpClient-BknZwXjG.js` 的 re-export 就是活标本——**74 个导出，全部是 `A`~`Z` / `a`~`z` / `at`~`zt` 这种**：

```js
export { cr as $ } from './httpClient-BknZwXjG_components/shared.js';
export { Wi as A } from './httpClient-BknZwXjG_components/shared.js';
export { aa as B } from './httpClient-BknZwXjG_components/shared.js';
// ... 共 74 行
```

而组件文件（如 `App-BX6o9fW5_components/Vr.jsx`）一次从 `shared.js` 导入**近 200 个符号**，全是 `A, B, C, ... at, bt, ct...`。这行 import 本身就有几千字符，占满 AI 的注意力，**却传达零语义**。

### 1.3 同名影子文件 + 交叉引用重名映射

- **同名影子**：`shared.js` 在 4 个 `_components` 目录重复；`Tr.jsx` / `_Component19.jsx` / `_Component24.jsx` / `_Component40.jsx` 各在 2 个目录重复（BUNDLE_MAP.md 第六章）。AI 搜「`Tr`」会命中多处，**改错目录 = 改漏/改错**。
- **重名映射**：`component_map.json` 里 `Bo → Bo_1`、`Es → Es_1`、`Kl → Kl_1`（BUNDLE_MAP.md 提到的 `.jsx` 里 `_cmp_Kl_1`），说明**同一逻辑名在不同 chunk 各自独立存在**，还原时靠后缀区分。AI 若只改其中一处，另一处是独立的，很容易漏。

> **一句话**：这个代码库对 AI 不友好的根子，是**「语义信息（名字）与结构信息（文件边界/引用关系）脱节」**。AI 读它是「靠猜」，而不是「靠查」。优化方向就是**把「猜」变成「查」**。

## 二、问题量化（先看清规模，再定优化目标）

> 数据来自当前 `src/bundle/` 实测（`BUNDLE_MAP.md` + grep）。

| 指标 | 数值 | 对 AI 的影响 |
|---|---|---|
| `_components` 总文件数 | ~178（174 jsx + 4 js） | 定位目标文件靠文件名猜（都是混淆名） |
| 最大文件 `src-_qSScO88_components/shared.js` | 34,659 行 | 单文件超出一次能完整读完的 context |
| 高危聚合文件被引用 | `httpClient/shared.js` 203 次 | 「改它一处 = 影响 200+ 引用方」 |
| facade 无语义导出 | `httpClient` 74 个单/双字母 | import 语句本身不传达语义 |
| 单组件单次导入量 | `Vr.jsx` ~200 符号 | import 行烧掉大量 context 且无语义 |
| 同名影子文件组 | 4 组（`shared.js` 等） | 搜同名会命中多处，改错目录即改漏 |
| 重名映射 | `Bo→Bo_1` / `Es→Es_1` / `Kl→Kl_1` | 同逻辑名跨 chunk 独立，改一漏一 |

**由此定优化目标（按对 AI 收益排序）**：
1. **让 AI 能「靠查不靠猜」定位**（最高优先级，纯增量、零风险）。
2. **减少 import 行的无语义噪音**（让 AI 每次读代码省 context）。
3. **降低高危文件的影响面**（把「改一处漏一处」从源头缓解）。
4. **本地短名逐步语义化**（低风险小步增量，非一次性大改）。

## 三、优化方向对比（先看全景，再选落点）

> 四类方向，**风险从低到高**。低风险的可直接做，高风险的只建议小步试点。

| 方向 | 做什么 | 风险 | 对 AI 收益 | 是否推荐 |
|---|---|---|---|---|
| **A. 语义化检索层（查）** | 不碰运行代码，把「混淆名 ↔ 职责/落点/参数」做成工具生成、AI 改前必读的检索表 | 🟢 极低（不动运行时） | ⭐⭐⭐ 直接解决「找代码难」 | **首选** |
| **B. 代码内语义注释（读）** | 在每个大文件/函数顶部加「语义 + 原名」注释 | 🟢 低 | ⭐⭐ 让 AI 读文件时不迷茫 | **推荐**（局部做） |
| **C. 拆聚合导出（解耦）** | 把 `shared.js` 拆成按职责分组的多个小 barrel | 🟠 中-高（`shared.js` 被 200+ 引用，跨 chunk 引用钉死，拆错即 TDZ/悬空引用） | ⭐⭐⭐ 根治「import 无语义」 | **慎做**（只拆本地可改、非被钉死的） |
| **D. 全仓重命名** | 把 `A`→`httpClient`、`Vr`→`CanvasEditor` 等全仓改 | 🔴 极高（`component_map.json`/契约/跨 chunk 引用全钉死，官方更新重打补丁会全崩） | ⭐⭐⭐ 最理想但代价最大 | **❌ 不做**（违背"最小差异"与官方更新重打流程） |

> **关键判断**：**方向 D（全仓重命名）是最直觉但最错误的答案**。因为官方每次发新版，混淆符号会整体重排（CLAUDE.md §五.3），我们做的每次改名都会被官方更新冲掉、还得重打。所以「给混淆码一个稳定的语义名」这个目标，**不能靠改源码实现，只能靠源码外的检索层实现**——这就是方向 A 的立足点。

## 四、候选方案细化

### 方案 A1：增强 `BUNDLE_MAP.md` 为「职责→落点」反向索引（✅ 已落地）

现状：`BUNDLE_MAP.md` 已有「特征→文件」的**功能域速查**（第七章），已经很好了。缺的是**粒度到函数/导出符号**。

**目标**：让 AI 改某个功能（如「改生图请求」）时，能查到「这个功能涉及哪几个符号、各在哪文件哪行、被谁引用」，而不是自己 grep 一堆短名。

**做法（不动运行时，已实施）**：
- `gen_bundle_map.cjs` 已**解析顶层 `function/const/let/var` 声明 + 函数内调用的 API 路径/hooks/契约键/数据字段**，生成「导出符号 → 职责标签 → 行号」。
- `BUNDLE_MAP.md` 已增「**八、符号级索引**」：按用途质量排序内嵌前 40 个高价值符号（如 `Bl → 发请求 /api/proxy`、`Gl → local-tool 状态`、`Vr → 画布编辑器 hooks 组件`），并标注「⚠同名×N」影子警示。
- 保持「工具生成、禁止手改」铁律。

**收益**：AI 改前 `npm run map` 重建，按「我要改发请求」→ 查 `BUNDLE_MAP.md` 第八章 → 直接定位到符号和行，**不靠猜**。

**验证**：AI 拿「改生图请求超时」等真实任务，走查能否仅靠 `BUNDLE_MAP.md` 定位到正确文件/行。实测 `Bl`（发请求出口）已能反查到 `httpClient-BknZwXjG_components/shared.js:6097`。

### 方案 A2：符号别名映射文件（`symbol_map.json`）（✅ 已落地）

**做法**：`gen_bundle_map.cjs` 已解析顶层函数/变量声明，生成工具产出的 `symbol_map.json`（格式见下，实测 1104 个符号）：
```json
{
  "Bl": [
    { "file": "httpClient-BknZwXjG_components/shared.js", "line": 6097, "role": "api:/api/files/read,/api/proxy · local-tool · proxyMode · ... · fetch", "apis": ["/api/jianying/send", ...] },
    { "file": "src-_qSScO88_components/shared.js", "line": 24043, "role": "字段:length,writeBits,..." }
  ]
}
```
- 由 `gen_bundle_map.cjs` 自动生成，随 `npm run map` 重跑；同名符号（影子文件）用**数组**存全部落点。
- AI 改前先查它：`Bl` 是啥 → 一眼看 `role` 字段（含 api/hooks/UI/fetch/local-tool/proxyMode 强信号）。

**收益**：把「一个符号是干嘛的」从「人肉 grep + 读上万行」压缩成「查一行」。**纯增量，不碰运行代码，官方更新只需重跑脚本**。

**注意**：官方更新重打补丁时，混淆符号可能重排 → 该映射会自动刷新（因为是工具生成），**不依赖人肉维护**，这是它优于手写文档的地方。`contract_scan.cjs` 已排除它（生成物非契约扫描源）。

### 方案 B1：大文件顶部「语义总览」注释（推荐，局部做）

**做法**：只给**最高危的几个大文件**（`httpClient/shared.js`、`src-_qSScO88/shared.js`、`H_.jsx`、`Vr.jsx`、`App-BX6o9fW5/shared.js`）在**文件顶部**加一段注释，说明「这个文件是干嘛的、里面有哪些职责域、关键函数名及行号」。示例：

```js
/**
 * httpClient-BknZwXjG_components/shared.js
 * 聚合导出：本 chunk 的请求/状态/任务逻辑总出口。
 * 关键符号：Bl(发请求, L6092) · In(剪映发送) · Ln(取文件名) · Rn(...)
 * 被 200+ 文件引用，改 export 前务必全文 grep 所有引用方。
 * ⚠️ 字符串契约见 CONTRACTS.md；勿拆散被跨 chunk 钉死的部分。
 */
```

**为什么只加顶部注释、不逐行改**：逐行加注释会撞上「最小差异」「官方更新重打」约束，且几千行加注释本身是巨大且低效的活。**顶部一个总览注释，成本最低、收益最大**——AI 打开文件 3 秒就知道该从哪读起。

### 方案 B2：`_Component128` 这类匿名组件给「用途注释」

`_Component128` / `_Component131` / `_Component15` 这类**匿名编号组件**是最难猜的。在**文件顶部**加一行「这个组件是干嘛的」，比重命名安全得多：

```js
// _Component128 = 设置面板弹窗（vendor shared.js Lxx 引用）
```

**风险提示**：给匿名组件加注释**不会破坏任何引用**（注释不是代码），是最安全的增量。但**不要改它的导出名**（`O_` nodeTypes 映射等靠名字定位）。

### 方案 C1：只拆「本地可改、非被钉死」的聚合导出（慎做）

`shared.js` 全拆**不可行**（被 200+ 引用 + 跨 chunk 引用钉死）。但**局部可拆**：
- 若某组函数**只被少数文件引用、且不跨 chunk 钉死**，可抽到新文件 `httpClient-BknZwXjG_components/xxx.js`，原处 re-export 兼容。
- 判断标准：用 `npm run contracts` + `npm run test:smoke` 的 `checkImportGraph` 验证**拆后引用不悬空**。

**收益**：逐步把「一个 1 万行的聚合文件」拆成「按职责的多个小文件」，AI 读每个文件更聚焦。

**风险**：拆错即 TDZ / 悬空引用 → **必须小步、单次拆一组、拆完立即 `npm run build` + `test:smoke`**。CLAUDE.md 明确「整块迁移几千行必翻车（store+helper 不可分割）」，所以**每次只拆几行、只拆低耦合的**。

### 方案 D1：本地短名的语义化（不推荐做，仅记录）

对**只在本文件内使用的局部混淆短名**（`let _st = ...` 这类），改成语义名**理论上安全**。但收益低、风险高：
- 混淆短名在官方更新时本来就重排，改了下次也失效；
- 局部改名易误伤（同名遮蔽如 `Wn`）。
- **结论**：CLAUDE.md §五.4 铁律 9 允许「本地可改的短名改语义长名」，但**优先级低**，不建议单独立项。把精力放在 A/B 方向。

## 五、推荐执行路径（分阶段，每阶段可独立验收）

> 全部符合「不破坏 React 单实例 / 字符串契约 / 跨 chunk 引用」三铁律。每阶段做完跑质量门。

| 阶段 | 动作 | 产出 | 状态 |
|---|---|---|---|
| **P1（最快见效）** | 生成 `symbol_map.json`（A2）+ 扩 `BUNDLE_MAP.md` 符号级索引（A1） | `src/bundle/symbol_map.json` 自动生成 | ✅ **已落地（2026-08-09）** |
| **P2（低成本）** | 给 5 个最高危大文件加顶部「语义总览」注释（B1）+ 给匿名 `_Component*` 加用途注释（B2） | 注释版 `shared.js`/`H_.jsx`/`Vr.jsx` 等 | ⬜ 待做 |
| **P3（中风险，慎做）** | 拆 1~2 组低耦合聚合导出（C1），每次一组、拆完即验 | 拆分后的 barrel | ⬜ 待做 |
| **P4（不建议）** | 全仓重命名（D1） | — | ❌ 否决，除非官方不再更新 |

> **P1 已实施**（2026-08-09）：`gen_bundle_map.cjs` 新增符号级解析（顶层函数/变量 + 行号 + 用途推断），输出 `symbol_map.json`（1104 个符号），并在 `BUNDLE_MAP.md` 追加第八章「符号级索引」。`npm run map` 一次生成三者。用途推断纯正则零依赖，借鉴 `scripts/archived/tools/summarize.cjs` 思路。`contract_scan.cjs` 已将 `symbol_map.json` 纳入排除（它是生成物，非契约扫描源）。P1 不碰运行代码、零风险，直接命中「AI 找代码难」痛点。P2 顺带做，P3 看精力。
>
> **P1 增量（同日）：自动生成物 AI 友好化**。诊断发现 BUNDLE_MAP/symbol_map/CONTRACTS 都是"被动数据库"，AI 不会主动浏览，于是加了两件"让 AI 自然而然想用"的东西：
> - **`npm run ask`（`scripts/ai_ask.cjs`）**：AI 检索总入口，把"查短名/契约/文件"变成一条命令出人话答案（`symbol`/`contract`/`file` 三查），零记忆成本，问即答。
> - **`src/bundle/AI_NAVIGATION.md`**：自动生成的"AI 改代码第一站"极简决策表（改 X → 看/跑什么），放 `src/bundle/` 下（AI 改码必进目录），让 AI 开场就知从何查起。
>
> **让 AI 主动用的关键**：不是造更多数据库，而是 (a) 给统一查询入口（`npm run ask`，触发即答）、(b) 给决策导航（`AI_NAVIGATION.md`，告诉 AI 何时用哪个）、(c) 在 CLAUDE.md 显眼处指引。三者闭环，AI 才"自然而然"会用。
