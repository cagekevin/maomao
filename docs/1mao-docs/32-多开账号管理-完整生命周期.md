## 〇、一句话定位

前端「多开」页签（`V === 'accounts'`）管理一批**「环境」（账号）**，每个环境是一组 Cookie。运行在 **Chrome 扩展端**（`k` 为真）时，可用 `chrome.cookies.*` API 读取 / 注入 / 删除浏览器 Cookie；运行在普通浏览器端（`k` 为假）时，多开退化为纯列表管理，无实际 Cookie 读写能力。

- **存储位置**：KV 键 `users`（`B.USERS`，见 `httpClient-BknZwXjG_components/shared.js` 的 `Ar` 常量）。
- **运行端判断**：`k = !!chrome.runtime?.id`（`Vr.jsx` L1112，`A(!!e)` 写入）。
- **唯一端口**：本地引擎 `127.0.0.1:18080`（`localTool`），但多开 Cookie 读写**不经过它**，走 `chrome.cookies` 扩展 API。

> ⚠️ 抓取 Cookie 的宿主 = **当前激活的浏览器标签页**（`chrome.tabs.query({active:true,currentWindow:true})`）。在 `127.0.0.1:18080` 本地工具页抓取，只会拿到该域名下的 Cookie（如仅 1 个百度统计 `Hm_lvt_*`）；要抓即梦（`jimeng.jianying.com`）登录态，必须先把标签页切到已登录的即梦网页。

## 二、环境对象结构

环境对象存于 `rn`（持久化为 `users` 键），字段：

```js
{
  id: String(Date.now()),      // 新建时唯一 id
  name: string,                // 用户起的名称（如「即梦小号」）
  siteName: string,            // 来源站点名（手动=「手动添加」/ 抓取=标签页 title 前 5 字）
  siteUrl: string,             // 站点 URL（用于切换时跳转）
  avatar: string,              // 头像 URL（默认 dicebear 生成）
  cookies: [{ name, value, domain, path, secure, httpOnly, expirationDate, sameSite, storeId }]
}
```

### 1. 创建（Sa，L1824）

输入三态：
1. **手动 Cookie 输入框非空**（`gn`）：优先解析 `gn`。支持两种格式：
   - JSON 数组（或单对象）；解析失败且含 `=` → 按 `key=value; key2=value2` 拆分（domain 兜底 `example.com`）。
   - 非法 → `alert('Cookie 格式错误…')` 中断。
   - 手动时 `siteName='手动添加'`，`siteUrl='https://example.com'`（或已有 `bn` 的 favIcon/title）。
2. **Chrome 扩展端（k）且未手动输入**：抓当前激活标签页 → `chrome.cookies.getAll({ url })`。
3. **非扩展端（k=false）**：写入测试数据（`{name:'test',value:'123'}`），`siteUrl='http://localhost:3000'`。

空 Cookie 处理：抓到 0 个时 `confirm('当前页面未检测到 Cookie…')` 确认才继续。

落库：`rn` 中按 `id` 存在则**合并修改**（保留原有 `isFavorite`/`siteName`/`siteUrl`），否则**追加新环境**。最终 `fa(c)` 落库。

### 2. 切换 / 激活（ga，L1724）

```js
let ga = async e => {
  await pa(e);            // 1. 同步 cookies 到当前标签页
  if (k && e.siteUrl) {   // 2. 扩展端：跳转到环境站点
    chrome.tabs.update(activeTab, { url: e.siteUrl });
  }
  cn(e);                  // 3. 标记激活
};
```

**`pa`（L1588）同步逻辑**（仅扩展端 k 有效）：
1. `chrome.tabs.query(active)` 取当前标签页 URL `n`。
2. `chrome.cookies.getAll({url:n})` 得到当前页面已存在的 cookie 集合。
3. **先删多余**：当前页面有、但环境 `cookies` 里没有的 → `chrome.cookies.remove`。
4. **再逐个设**：遍历环境 `cookies`，用 `chrome.cookies.set` 注入（带上 domain/path/secure/httpOnly/expirationDate/storeId/sameSite 全字段，保证登录态完整）。
5. 完成后再跳转 `siteUrl`，让目标站点读到已注入的登录 Cookie。

> 关键：**切换是「覆盖当前标签页域名下的 Cookie 集合」**。所以同一站点多账号，靠「先清当前、再注入目标套」实现。非扩展端 `pa` 静默跳过（无副作用）。

### 3. 清除 Cookie（ha，L1666）

- 菜单「**清除全部 Cookies**」：`ha(env, true)` → 删除当前标签页全部 cookie。
- 菜单「**清除登录态**」（未在菜单，由删除流程 `ma` 白名单触发）：`ha(env, false)` → 仅删 `ma` 白名单内的登录 cookie。
- 清除后 `chrome.tabs.reload` 刷新页面。

### 4. 删除（Na，L2002）

卡片菜单「删除」，需**两次点击确认**（第一次变「确认删除?」，3 秒内再点一次）：
- `fa(rn.filter(t => t.id !== e))` 落库。
- 若删除的是当前激活环境（`on?.id === e`）→ `cn(null)` 取消激活。
- ⚠️ **删除环境不自动清浏览器 Cookie**。环境删除后，之前注入到站点的 Cookie 仍在浏览器里，需手动用「清除全部 Cookies」清理。

### 5. 其他维护

- **修改**：菜单「修改」→ 预填 `Sa` 表单（name + `JSON.stringify(env.cookies)`）→ 保存走 `Sa`。
- **复制 Cookie**：`navigator.clipboard.writeText(JSON.stringify(env.cookies))`。
- **拖拽排序**：`Da/Oa/ka/Aa`，drop 后 `fa(n)` 落库。
- **收藏**：`Pa` → toggle `isFavorite` + 调 `jr` 同步远端。

### 6. 云端同步（ba / xa，L1747 / L1781）

多开环境（`users` 键）是云端配置同步的 9 类键之一，**会被同步**。前置：需登录（`_t.getCurrentToken()`），否则提示「请先登录」中断。

**上传（`ba`，备份）**：
```js
for (let t of [`app_settings`, `api_configs`, `users`, `membership`, `projects`,
               `presetPrompts`, `customNodeTemplates`, `modelSchedules`, `cloud_storage_config`]) {
  e[t] = await z.getObject(t);        // users 取到的是完整环境数组（含 Cookie 明文）
}
_t.post(`/sync/upload`, { type: `cloud_config`, data: e });
```

**下载（`xa`，恢复）**：
```js
let t = (await _t.get(`/sync/download`)).data.data.cloud_config;
for (let key of Object.keys(t)) {
  await z.setObject(key, t[key]);     // users 整表覆盖写回本地
}
window.location.reload();             // 1s 后刷新，多开环境生效
```

> ⚠️ **整表覆盖**：`xa` 下载是直接把云端 `users` 覆盖本地 `users`，**非合并**。若本地有云端没有的新环境，会被冲掉。
> ⚠️ **安全**：`users` 内的 Cookie（含 `sid_tt`/`sessionid` 等登录凭据）**明文上传**，经 `/sync/upload` 存到云端。云端是否加密取决于后端实现，前端此处明文透传。见 §五.7。

## 五、已知边界与坑（务必阅读）

1. **Cookie 作用域**：`chrome.cookies.getAll({url})` 只返回该 URL 域名下 cookie。抓即梦登录态，激活标签页必须在 `jimeng.jianying.com`；在 `127.0.0.1:18080` 本地页只会抓到该域 Cookie（如 `Hm_lvt_*` 百度统计时间戳）。
2. **httpOnly Cookie 可读**：`chrome.cookies.getAll` 能读 httpOnly Cookie（这正是本功能能搬登录态的前提）；但普通网页 JS `document.cookie` 读不到 httpOnly，所以多开必须依赖扩展端。
3. **非扩展端无实际能力**：`k=false` 时新建只写测试数据，`pa` 静默跳过 —— 多开只是「存着」，切了不生效。
4. **删除不清 Cookie**：环境删除 ≠ 登出站点。残留登录态需手动「清除全部 Cookies」。
5. **切换会跳标签页**：`ga` 会 `chrome.tabs.update` 跳转到环境 `siteUrl`，可能打断用户当前浏览。
6. **Cookie 会过期**：注入的 Cookie 带 `expirationDate`，到期后登录态失效，需重新抓取/更新环境。
7. **云同步含登录凭据明文**：`users` 存的是完整 Cookie（含 `sid_tt`/`sessionid` 等登录 token），且 `ba` 会明文上传 `/sync/upload`。若担心凭据泄露云端，可：① 从 `ba` 的 9 类键列表剔除 `users`（L1755）；② 上传前对 `cookies` 加密/脱敏。**恢复是整表覆盖**，本地新环境可能被云端旧数据冲掉。

## 六、适用场景与用户边界

> 这一章面向**用户**（而非技术），回答：这个功能到底解决了什么问题、适合谁用、什么情况下用不了、怎么用好。

### 6.1 核心价值（它帮你解决什么）

一句话：**把「多套账号的登录状态」存下来，一键换号，不用每次手动登录 / 登出。**

对普通用户来说，多开解决的是这些烦恼：

- **免去反复输入账号密码**：即梦、Midjourney 等网站登录麻烦（验证码、扫码、设备校验），多开把登录好的状态快照存下来，换号一键切。
- **多账号收藏复用**：小号、白嫖号、多个平台的账号，各自保存一套 Cookie，像「收藏夹」一样管理，换设备还能云端恢复。
- **一键切换**：点一下环境卡片，自动注入该账号登录态并跳到对应站点，省去手动登出→登录。

### 6.2 适合哪些场景

| 场景 | 是否适合 | 说明 |
|---|---|---|
| 多平台账号集中管理（即梦/抖音/其他） | ✅ 适合 | 每个平台一套环境，卡片化管理 |
| 同一平台多账号「轮着用」 | ✅ 适合 | 小号轮流用，点卡片切换 |
| 需要**同时**用两个账号（并排对比/双开） | ❌ 不适合 | 同一时间只能保持一个登录态，切换会覆盖并跳页 |
| 换设备想**恢复**多开账号 | ✅ 适合（有条件） | 走云端同步，但需先登录、且是整表覆盖 |
| 长期不登录、靠 Cookie 挂着 | ⚠️ 有风险 | Cookie 会过期，过期后得重新登录再抓 |
| 高价值/主账号频繁用 | ⚠️ 谨慎 | 登录态明文存本地/上云，有泄露风险 |

### 6.3 用户视角的「边界」——它做不到什么

1. **不能真「多开」并行**：它是一次只能用一个账号的「快速切换」，不是同时开两个登录态。想并排用两个号，这个功能帮不了。
2. **切换会跳转页面**：点环境卡片会把你当前标签页跳去对应站点，正在做的事会被打断。
3. **依赖 Chrome 扩展插件环境**：如果没装/没开插件的普通网页里打开，这个功能「存了但切了不生效」。
4. **登录态会过期**：Cookie 有时效，过期后要重新登录、重新抓取保存，否则环境失效。
5. **换设备恢复是「覆盖」**：新设备上有新环境时，从云端恢复会把本地新的覆盖掉，别在有新环境时乱恢复。

### 6.4 使用建议

- **想清楚是不是要「并行双开」**：如果是，这个功能满足不了，别抱期望。
- **主账号尽量手动登录**，小号/临时号才用多开，降低凭据泄露影响。
- **环境过期了**就去对应站点重新登录一次、再更新该环境即可。
- **换设备恢复前**，先确认本地没有更重要的新环境（避免被云端旧数据覆盖）。
