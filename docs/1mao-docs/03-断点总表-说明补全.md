# 断点总表 · 说明补全（源码实证版）

> 目的：补全 `02-断点三域梳理.md`「六、断点总表」里高/中/低三档缺失的「他们是干嘛的 / 出了什么毛病」。
> 范围：逐条回到 `localTool/src`、`apimart-gateway/main.py`、`dist/` 前端代码实证，**每条标注核实状态**。
> 状态图例：`[核实]` = 已在源码坐实；`[待联调]` = 源码形状已知，但与前端解析字段的吻合度需联调确认。
> 本文只讲「断点是什么、干嘛用、断了会怎样」，不含修复方案。

## P0（阻塞一切生成/对话，最高优先）

- **B · `/api/proxy` 15s 硬超时** `[核实]`
  - 是什么：画布**一切请求的唯一出口**（官方/第三方/网关流量全经它转发）。
  - 源码实锤：`system.ts:68`（`handleProxyFormData`）与 `system.ts:132`（`handleProxyJson`）均 `setTimeout(() => controller.abort(), 15000)`，超时返回 504。（行号以 `05-断点修复方案.md` 附录 A 为准，早期文档 `67/126` 为旧版偏移）
  - 断了：视频提交、流式对话等 >15s 的请求被直接掐断，所有生成/对话功能整体失败。

- **B · `/api/proxy` 非流式** `[核实]`
  - 是什么：同上唯一出口的转发实现。
  - 源码实锤：`system.ts:80` 与 `system.ts:144` 均 `Buffer.from(await fetchRes.arrayBuffer())` 整段缓冲后 `res.end(resBody)`，不转发流。（行号以 `05-断点修复方案.md` 附录 A 为准，早期文档 `78/137` 为旧版偏移）
  - 断了：`chat/completions` 带 `stream:true` 时前端收不到增量，流式对话/生成「假死」。

- **B · `/api/proxy` 纯透传无协议翻译** `[核实]`
  - 是什么：同上出口的「翻译层」本该做的活。
  - 源码实锤：`handleProxy`（`system.ts:24-39`）仅按 `X-Proxy-Url` 头或 JSON body 原样转发 header+body，无任何 `{code,data}` 信封/字段名转换。
  - 断了：后端返回格式与画布前端解析预期不匹配时，即使响应到达也无法被正确解析（白收到）。

> 三者都在「唯一出口」上，缺陷连带让所有生成/对话失败，故并列 P0。

## 高（整块功能不可用）

- **C · G1 `GET /v1/videos/{id}` 缺失** `[核实]`
  - 是什么：`video` 节点提交任务后的**视频轮询**端点。
  - 源码实锤：`main.py` 仅有 `/v1/tasks/{task_id}`（`main.py:873`）与 `/v1/gateway/task/{task_id}`（`main.py:937`），**没有** `/v1/videos/{id}`。前端轮询期望顶层 `status==="completed"` + `video_url/metadata.url/output.url`（见 `httpClient.js` 视频轮询逻辑）。
  - 断了：`video` 节点提交后永远拿不到结果，生视频整块卡死。

- **C · G2 `GET /v1/video/generations/{id}` 缺失** `[核实]`
  - 是什么：`sd2Video` 节点（Seedance 系）的任务轮询端点。
  - 源码实锤：`main.py` 无此路由。前端期望 `status==="succeeded"` + `results[0].url`——该形状已在 `httpClient.js:561` 实证（`n.status==='succeeded'&&n.results&&n.results[0]&&n.results[0].url`）。
  - 断了：`sd2Video` 节点提交后拿不到结果，Seedance 视频生成整块不可用。

- **C · G3 `POST /v1/draw/completions` 缺失** `[核实]`
  - 是什么：绘图节点的**提交**端点（请求体 `{model,prompt,aspectRatio,urls}`）。
  - 源码实锤：`main.py` 无此路由。
  - 断了：绘图节点无法提交，生图（draw）功能直接 404。

- **B · L2 画布页面宿主 + 自动开浏览器缺失** `[核实]`
  - 是什么：原版引擎「双击 → 自动进画布」的入口（托管静态页面 + 自开浏览器）。
  - 源码实锤：`index.ts` 的静态文件服务只处理 `/files/*`（`index.ts:45-97`），无托管 `dist/index.html` 的逻辑，也找不到任何 `open()` 浏览器代码。
  - 断了：用户装了引擎却进不去画布，没有入口。

- **B · I1 缺合并启动器（一键体验 ❌）** `[核实]`
  - 是什么：把「localTool(:18080) + 网关(:8000) + 打开画布」编排到一起的一键脚本。
  - 源码实锤：根目录无统一启动脚本；`localTool` 自带 `start.sh`、网关自带 `启动网关.command/run_local.*`，但**没有把两者 + 打开页面串起来的合并编排**。
  - 断了：部署就绪度差，需手工逐个起服务。

- **A · A2 `/api/sync/default` 无兜底（节点库空白）** `[核实]`
  - 是什么：官方平台下发的「节点/模型配置」接口，是**画布拿到 apiConfig 的唯一来源**。
  - 源码实锤：前端 `endpointConfig.js` / `App.js` / `ShareAppPage.js` 等均引用 `sync/default`；`localTool` 的 `index.ts` 路由表**没有**该路径。
  - 断了：官方不可达 → 节点库空白，画布没有可用模型/节点。

## 中

- **B · L1 `POST /api/kv/delete?key=` 未实现（404）** `[核实]`
  - 是什么：画布删除工作流 checkpoint 用到的 KV 删除接口。
  - 源码实锤：`index.ts:129-134` 只路由 `/api/kv/get`、`/api/kv/set`，**没有** delete。
  - 断了：工作流 checkpoint 删不掉，脏数据累积。

- **B · L4/L5 `sync/default`、`assets/upload`、`upload/app-asset` 缺失** `[核实]`
  - 是什么：节点配置下发（L4）、应用资产/素材上传（L5）的平台接口。
  - 源码实锤：`index.ts` 路由表均无这三路径；网关 `main.py` 也无 `/api/assets/upload`（只有 `/v1/uploads/images`、`/v1/gateway/upload`）。
  - 断了：自托管/官方不可达时，节点配置与资产上传均无兜底。

- **B · S1 upload/thumbnail 相对路径破图（方式二）** `[核实·方式二风险]`
  - 是什么：`/api/files/upload`、`/api/files/thumbnail` 返回给画布的资源 URL。
  - 源码实锤：`files.ts:40-47` 上传返回 `url:'/files/...'`（相对），`files.ts:234` 缩略图返回 `thumbnailUrl:'/files/...'`（相对）。而 `resources.ts:27-35` **自己承认**方式二（`chrome-extension://` 页面）下 `<img src="/files/...">` 会被解析成 `chrome-extension://.../files/...` → 404 破图，并用 `toAbsoluteFileUrl` 仅修复了 rescan 入库；upload/thumbnail 本身仍回相对路径。
  - 断了：方式二（插件/扩展页）下资源图、缩略图破图；方式一（同源）正常。

- **B · P2 ffmpeg 依赖未审计** `[核实·是否必需待定]`
  - 是什么：本地转码/后处理是否依赖服务端 ffmpeg。
  - 源码实锤：`system.ts:55`（`handleStatus` 函数 50-58 行）直接返回 `ffmpeg: false`，localTool 无任何 ffmpeg 集成代码。
  - 待定：原版是否内置 ffmpeg、前端后处理是否真的依赖，需抓包/比对原版确认。

- **B · I3 localTool 未预编译** `[核实]`
  - 是什么：localTool 能否直接 `node dist/index.js` 跑起来。
  - 源码实锤：`localTool/` 目录只有 `src/*.ts`（12 个）、`package.json`、`tsconfig.json`、`start.sh`，**没有 `dist/`**。`start.sh` 应负责 build+启动，但开箱即用的 `dist/` 不存在。
  - 断了：不先 `npm run build`（或走 `start.sh`）直接跑会找不到产物。

- **C · G4 `POST /api/assets/upload` 缺失** `[核实]`
  - 是什么：向 AI API 域经 Bearer+JSON 上传素材的端点。
  - 源码实锤：`main.py` 无 `/api/assets/upload`（仅有 `/v1/uploads/images`、`/v1/gateway/upload`）。
  - 断了：前端若走 `/api/assets/upload` 上传素材则 404。

- **C · G5 `/v1/gateway/ai-app/*` 及 base 级 `GET /api/ai-apps`、`/api/ai-apps/{id}` 缺失** `[核实]`
  - 是什么：AI 应用市场/运行相关接口（`Yn` 构造，无 `/v1`、无 `/api` 前缀）。
  - 源码实锤：`main.py` 路由中无 `ai-app` 字样；前端 `App.js` 等引用了 `ai-apps`。
  - 断了：取决于是否启用「AI 应用」功能，启用则该功能不可用。

- **A · A1/A3/A4 官方助手 / 工作流 / 资产无兜底** `[核实·引用存在]`
  - 是什么：画布助手对话、工作流分发、资产上传三类官方能力。
  - 源码实锤：前端引用 `vip-check`/`/agent/chat`（助手，A1）、`workflow-apps`（工作流，A3）、`app-asset`（资产，A4）；`localTool`/`main.py` 均无本地兜底实现。
  - 断了：官方不可达时这三类能力全部失联，且当前无重定向/兜底落点（见原梳理「七、悬而未决 1」）。

## 低

- **B · L3 manifest/版本残留** `[核实]`
  - 是什么：`/plugin/manifest.json` 上报的版本号，用于更新提示/功能开关。
  - 源码实锤：`platform.ts:13` 返回 `version:'1.3.5'`；`index.ts:24` `VERSION='2.0.0-maomao-clone'`。两处版本不一致。
  - 断了：可能误触发更新提示或功能开关错位。

- **B · S2 缩略图复制降级** `[核实]`
  - 是什么：生成缩略图的实现质量。
  - 源码实锤：`files.ts:120`（`tryGenerateThumbnail`）与 `files.ts:230`（`handleThumbnail`）在「无 sharp」时直接 `fs.copyFileSync` 原图。
  - 断了：功能降级——大图缩略图=原图，浪费带宽/显存。

- **B · S3/S4 tasks/resources/kv 字段名待核** `[部分核实·前端期望待联调]`
  - S3 是什么：`/api/tasks`、`/api/resources` 列表返回的分页字段名。
  - 源码实锤：`helpers.ts:237` `paginatedResult` 返回 `{items, total, page, pageSize, totalPages}`。前端取 `items` 还是 `list`/`data` 需联调确认（不一致则列表空白）。
  - S4 是什么：`/api/kv/get` 的返回形状。
  - 源码实锤：`kv.ts:16-19` 返回裸 JSON 值或 `null`，**没有** `{value}` 信封。前端是否用 `.value` 待核。

- **B · I4 局域网鉴权** `[核实]`
  - 是什么：开放局域网时的访问控制。
  - 源码实锤：网关 `main.py:33` `OPEN_RELAY` 为 true 时直接用默认 AK/SK 且绑 `0.0.0.0`（`main.py:10` uvicorn `0.0.0.0:8000`）；`localTool` 的 CORS 为通配 `*`（`index.ts:106`）。
  - 断了：若开放局域网又开 `OPEN_RELAY`，任意跨域页可无鉴权调用（安全风险，非功能断点）。

- **C · G6 `/v1/audio/transcriptions` 为 501** `[核实]`
  - 是什么：「听音」语音转写接口。
  - 源码实锤：`main.py:667-669` 返回 `err(501, "语音转写 ... 不被 Lovart 后端支持")`。
  - 断了：听音功能不可用，需外接第三方。

- **C · S5 images/draw 提交响应 task_id 取法待核** `[部分核实·前端待联调]`
  - 是什么：绘图/生图提交后，前端从响应里取任务 id 的方式。
  - 源码实锤：网关 `_do_submit` 末尾 `return ok([{"status":"submitted","task_id":task_id}])`（`main.py:781`），经 `ok()` 包裹为 `{"code":200,"data":[{"status":"submitted","task_id":"task_xxx"}]}`。前端按 `data[0].task_id` 取是否与之一致待联调确认。

- **C · 伪覆盖端点（信息修正）** `[核实]`
  - `/v1/music/generations`、`/v1/audio/generations`、`/v1/audio/speech` 在 `main.py:655-665` 均返回 501，且 `dist/` 前端从不调用，属非契约端点——列「已对齐(501)」会误导，真要用音乐/语音需节点单独配第三方（如 kkidc）。

- **A · A5 视频基址默认官方需重定向** `[核实·引用存在]`
  - 是什么：`video`/`sd2Video`/`discountVideo` 节点的视频生成基址默认值。
  - 源码实锤：前端 `httpClient.js:561` 出现 kkidc 视频轮询形状（`results[0].url`），视频基址默认指向 `ai-api.kkidc.com`（变量 `d`）。
  - 断了：按「全走 localTool」架构，需把该基址重定向到 localTool 才能走统一中继。

- **A · A6 硬编码 fallback 残留** `[核实]`
  - 是什么：即便用户改了 `active_api_endpoint`，仍有默认/备用接入点作 fallback。
  - 源码实锤：`endpointConfig.js` 默认接入点 `http://154.219.102.152:3012`，且 `VITE_API_ENDPOINTS` 内仍含 `www.1mao.cc`/`1mao.16iai.com`/`154.219.102.152` 多个公网地址。
  - 断了：离线/内网环境会静默尝试连公网。

- **A · A7 O5 `0.1mao.cc` 用途未确认** `[核实·引用存在，用途待确认]`
  - 源码实锤：`dist/` 中 `httpClient.js` 与 `App.js` 引用了 `0.1mao.cc`（某组件 `Dn` 的默认占位 URL）。
  - 待确认：具体是哪个组件、是否关键（原梳理判为「可能非关键」）。
