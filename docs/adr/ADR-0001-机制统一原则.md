# ADR-0001: 跨切面机制统一原则

- 状态：Accepted
- 日期：2026-08-17
- 提出：架构5步法 command（选项 A 回流纪律）

## 背景

项目中多次出现"同一机制在每个地方写法不一样"的问题，典型受害者：Toast 通知（28 个文件、137 处调用，见 `docs/07-Toast分级设计`）、实时总线 Event Bus（6 事件并存于 `src/components/base/eventBus.js` 与原生 window 事件）、存储键（3 种风格并存，见 `docs/08`）、中信类接入。根因不是缺流程，而是：规范散落 `docs/` 未被 command 强制前置加载，且每次任务做完未回流成强制约定。

## 决策

1. 相同语义的跨切面机制（事件总线、Toast、存储键、外部系统接入等）全仓只允许一套实现。
2. 新增/修改此类机制前，必须先查 `spec/CONTEXT.md` 索引与对应 `docs/*-设计|-规范|-全解` 文档。
3. 当某机制在 ≥2 处出现写法不一致时，必须收口为单一实现，并提炼强制约定进 `spec/CONTEXT.md` + 立 ADR。
4. 规范寻址：索引在 `spec/CONTEXT.md`；详细约定在 `docs/*.md`；已确立决策在 `docs/adr/`。

## 后果

- 正向：消除重复实现，降低人类与 AI 的决策心智负担；未来任务前置加载即可遵守。
- 负向：回流动作增加少量任务收尾成本（State 5 强制第 4 步）。
- 风控：若某次任务因临时原因未收口，不立 ADR；仅当该理由对未来探索者确有必要以避免重复建议时才立。
