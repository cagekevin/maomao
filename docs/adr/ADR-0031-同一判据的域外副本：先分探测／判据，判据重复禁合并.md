# ADR-0031 · 同一判据的域外副本：先分探测／判据，判据重复禁合并

- **状态**：生效
- **结论**：同一判据出现在域外时，先分「探测重复」（收口）与「判据重复」（禁合并）；域外副本各带域内语义差异（disabled／SELECT／activeElement+自由区），合并必削能力。ADR-0029 §决议6 据此改判「不收口」。
- **日期**：2026-09-18
- **裁定人**：用户
- **触发**：TD-18-10/11/12/13：18 区横推把 ADR-0029 的域外副本登记成违反（2026-09-18）

## 背景

ADR-0029 立「编辑器内的交互一律归编辑器」，把画布侧的判据收口为 `base/core/uiHooks.ts:16::isEditableTarget`。
收口清单末尾留了一笔尾巴 —— **§决议6「域外副本待收口（不在本轮）」**，点名三处：
`director3d/panels/Timeline.tsx:382` · `videoEditor/utils/browser.ts:2` · `videoEditor/hooks-cutia/use-keybindings.ts:44`。

**这笔尾巴立刻被当成了待办**：同日区 18「ADR 判据合规横推」**照着它**把三处登记成
TD-18-10（母体）/ TD-18-11 / TD-18-12 三笔违反，外加 TD-18-13（注释自称「唯一一份」）。
即：**一条写错的"待收口"，会稳定地生产出下一轮的假债**。

用户 2026-09-18 裁定：**不收**。「这么小个东西收它有什么价值？」

## 判据（它凭什么成立 / 为什么不成立）

**取证（四处代码实读，非推断）** —— 四处的判据**确实互异**，且每处差异都是域内必需的：

| 实现 | 判据 | 域内语义 |
| --- | --- | --- |
| `uiHooks.ts:16 isEditableTarget` | `INPUT ∨ TEXTAREA ∨ isContentEditable ∨ closest('input, textarea, [contenteditable="true"]')`；**不看 `disabled`** | 「事件的地盘在编辑区吗」（判 `ev.target`） |
| `videoEditor/utils/browser.ts:1 isTypableDOMElement` | `isContentEditable ∨ (INPUT／TEXTAREA ∧ !disabled)`；入参是 `{element}` **不是事件** | 「这个元素**能不能真打字**」 |
| `director3d/panels/Timeline.tsx:382` | `INPUT ∨ **SELECT** ∨ TEXTAREA ∨ isContentEditable` | 多一个 `SELECT`：**`<select>` 里按 Delete 不该删关键帧** |
| `videoEditor/hooks-cutia/use-keybindings.ts:44` | 判 **`document.activeElement`**（不是 `ev.target`），前置还有 `closest('[data-keybinding-free]')` 自由区 | 「**焦点**在哪」+ 该区免绑 |

**逐处判收口的收益／代价**：

1. `Timeline.tsx` 删 `SELECT` → **引入真 bug**（下拉框内 Delete 删关键帧）⇒ 收口是**负收益**。
2. `use-keybindings.ts` 改判 `ev.target` → 把「焦点在哪」偷换成「事件打在谁身上」，**改语义**⇒ 收口是**负收益**。
3. `browser.ts` 删 `disabled` → 改的是它对外导出的契约（可被任意元素调用，不绑事件语义），
   且入参形态不同（`{element}` vs 事件）⇒ 合并要动 `keybindings-store.ts:7,170,179` 三处调用点。
   **零行为收益 + 非零改动半径** ⇒ 不该做。

**这是「判据重复」，不是「探测重复」** —— 7 步法 Step 3 的判别原文：
探测重复（**怎么读**数据）强制收口为底层纯函数；**判据重复（要不要放行／动作）严禁合并**，
必须保留在拥有真相的层级，**合并会削掉某层的必要能力**。上表第 1、2 行就是被削掉的那两种能力。

⇒ ADR-0029 §决议6 **立错了**：它把「判据重复」当「探测重复」记了尾巴。

## 决议

1. **ADR-0029 §决议6 就地回改**：「待收口」→「**不收口**」（本 ADR）。原判据正文其余部分不变。
2. **四处各自保留**，禁止合并进 `isEditableTarget`；禁止为"份数一致"删 `SELECT` / `disabled` 判据。
3. **登记侧**：账本 TD-18-10 / TD-18-11 / TD-18-12 / TD-18-13 改判非债。
4. `videoEditor/utils/browser.ts` 补 JSDoc，写明「域内语义：判 `disabled`；与 `isEditableTarget` **有意不合并**」
   —— 它是导出函数，最容易被误认成共享判据的第二份。
5. `src/hooks/useAssetDropPaste.ts:119` 的「**唯一一份**」假声明收窄为「**画布内唯一一份**」。
6. **判据化推广（本条的可复用部分）**：任何「同一判据在域外有副本」的候选债，
   **登记前必须先分探测／判据两类**；属判据重复者**一律不登记为债**，改记一条"有意不合并"的指针。

## 后果

- ✅ 收益：账本净减 4 笔；18 区待办 9 → 5；**切断"顺着上一轮的待办把它当债补"这条回潮路径**
  （本轮实证：18 区横推正是照 §决议6 的尾巴登记的）。
- ⚠️ 代价 / 回潮风险：**判据份数在这一族仍为 4（有意）** ⇒「份数 > 1」在这一族**不再是复杂度指标**，
  后人若拿它当判据会误报（本 ADR 就是为堵这个而写）。`isTypableDOMElement` 的 `disabled` 分支
  在 keydown 场景实际不可达 —— 它保的是**契约**（"能不能打字"），不是当下的行为，故留着。
- 📌 违反时的判据（怎么发现"又回去了"）：
  - **机器**：无（本族不收口，按「建闸前置评审」不建闸）。
  - **人工**：① 账本里再出现把 `Timeline.tsx:382` / `browser.ts` / `use-keybindings.ts`
    登记为「可编辑判据违反」的行 ⇒ 违反本条；② 出现"删掉 `SELECT` 或 `disabled` 判据以求与
    `isEditableTarget` 一致"的改动 ⇒ 违反本条。

## Lessons Learned

- **「待收口」是一张会自己兑现的欠条**：写进 ADR 的尾巴会被下一轮当成待办照办。
  立判据时若决定"这轮不做"，必须写清是**"留着不做"还是"不做"** —— 前者要附解锁条件，后者要附理由。
  本条原稿只写了「不在本轮」，于是"本轮"结束的瞬间它自动变成"该做"。
- **「同一判据」不等于「同一实现」**：判断能否合并的唯一入口是 **Step 3 的探测／判据二分**，
  不是"两段代码长得像"。四处代码长得像，但服务的是四个不同问题。
