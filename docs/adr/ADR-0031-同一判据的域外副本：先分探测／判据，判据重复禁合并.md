# ADR-0031 · 同一判据的域外副本：先分探测／判据，判据重复禁合并

- **状态**：生效
- **结论**：同一判据出现在域外时，先分三类：探测重复（收口）· 判据重复（禁合并）· 物理不可收口（非债）；域外副本各带域内语义差异，合并必削能力。ADR-0029 §决议6 据此改判「不收口」。
- **日期**：2026-09-18
- **裁定人**：用户
- **触发**：TD-18-10/11/12/13：18 区横推把 ADR-0029 的域外副本登记成违反（2026-09-18）

## 背景

ADR-0029 立「编辑器内的交互一律归编辑器」，把画布侧判据收口为 `base/core/uiHooks.ts:16::isEditableTarget`；
收口清单末尾留了一笔尾巴 —— **§决议6「域外副本待收口（不在本轮）」**，点名 `Timeline.tsx:382` · `browser.ts:2` · `use-keybindings.ts:44`。

**这笔尾巴立刻被当成待办**：同日区 18 横推**照着它**把三处登记为 TD-18-10/11/12 三笔违反（外加 TD-18-13）
—— 即：**一条写错的"待收口"，会稳定地生产出下一轮的假债**。用户 2026-09-18 裁定：**不收**。

## 判据（它凭什么成立 / 为什么不成立）

**取证（四处代码实读，非推断）** —— 四处的判据**确实互异**，且每处差异都是域内必需的：

| 实现 | 判据 | 域内语义 |
| --- | --- | --- |
| `uiHooks.ts:16 isEditableTarget` | `INPUT ∨ TEXTAREA ∨ isContentEditable ∨ closest('input, textarea, [contenteditable="true"]')`；**不看 `disabled`** | 「事件的地盘在编辑区吗」（判 `ev.target`） |
| `videoEditor/utils/browser.ts:1 isTypableDOMElement` | `isContentEditable ∨ (INPUT／TEXTAREA ∧ !disabled)`；入参是 `{element}` **不是事件** | 「这个元素**能不能真打字**」 |
| `director3d/panels/Timeline.tsx:382` | `INPUT ∨ **SELECT** ∨ TEXTAREA ∨ isContentEditable` | 多一个 `SELECT`：**`<select>` 里按 Delete 不该删关键帧** |
| `videoEditor/hooks-cutia/use-keybindings.ts:44` | 判 **`document.activeElement`**（不是 `ev.target`），前置还有 `closest('[data-keybinding-free]')` 自由区 | 「**焦点**在哪」+ 该区免绑 |

**逐处判收口的收益／代价**：① `Timeline.tsx` 删 `SELECT` → **引入真 bug**（下拉框内 Delete 删关键帧）⇒ 负收益。
② `use-keybindings.ts` 改判 `ev.target` → 把「焦点在哪」偷换成「事件打在谁身上」，**改语义** ⇒ 负收益。
③ `browser.ts` 删 `disabled` → 改的是对外契约且入参形态不同，合并要动 `keybindings-store.ts:7,170,179`；**零行为收益 + 非零改动半径** ⇒ 不该做。

**这是「判据重复」，不是「探测重复」** —— 7 步法 Step 3 判别原文：探测重复（**怎么读**数据）强制收口为底层纯函数；
**判据重复（要不要放行／动作）严禁合并**，必须保留在拥有真相的层级。上表第 1、2 行就是会被削掉的两种能力。

⇒ ADR-0029 §决议6 **立错了**：它把「判据重复」当「探测重复」记了尾巴。

**第三类：物理不可收口**（2026-09-21 收编自 `ADR-0032`）：注入**页面主世界**执行的函数体**物理上引用不到模块内原语**
（不同作用域、无 import 链）⇒ 它连"能不能合并"都不成立，这类"副本"**不是债**，登记为「未收口」= 假债。
**判别顺序（三步，不可跳）**：① 引用得到原语吗？引用不到 ⇒ 第三类 · 非债 ② 是"怎么读"（探测）⇒ **收口** ③ 是"要不要放行"（判据）⇒ **禁合并**。

## 决议

1. **ADR-0029 §决议6 就地回改**：「待收口」→「**不收口**」（本 ADR）。原判据正文其余部分不变。
2. **四处各自保留**，禁止合并进 `isEditableTarget`；禁止为"份数一致"删 `SELECT` / `disabled` 判据。
3. **登记侧**：账本 TD-18-10 / TD-18-11 / TD-18-12 / TD-18-13 改判非债。
4. `videoEditor/utils/browser.ts` 补 JSDoc，写明「域内语义：判 `disabled`；与 `isEditableTarget` **有意不合并**」
   —— 它是导出函数，最容易被误认成共享判据的第二份。
5. `src/hooks/useAssetDropPaste.ts:119` 的「**唯一一份**」假声明收窄为「**画布内唯一一份**」。
6. **判据化推广**：任何「同一判据在域外有副本」的候选债，**登记前必须先按三步判别分类**；
   属判据重复者**一律不登记为债**，改记一条"有意不合并"的指针。
7. **第三类已并入本条**（2026-09-21）：`ADR-0032` 的「注入主世界 ⇒ 引用不到原语」**不是 catch-ok 特有的**，
   已上提为本条第 6 条的第 1 步；`ADR-0032` 转**已取代**（被本条取代）。

## 后果

- ✅ 收益：账本净减 4 笔；18 区待办 9 → 5；**切断"顺着上一轮的待办把它当债补"这条回潮路径**。
- ⚠️ 代价 / 回潮风险：**判据份数在这一族仍为 4（有意）** ⇒「份数 > 1」在这里**不再是复杂度指标**，
  后人若拿它当判据会误报。`isTypableDOMElement` 的 `disabled` 分支在 keydown 场景实际不可达 —— 它保的是**契约**而非当下行为，故留着。
- 📌 违反时的判据（怎么发现"又回去了"）：
  - **机器**：无（本族不收口，按「建闸前置评审」不建闸）。
  - **人工**：① 账本里再出现把 `Timeline.tsx:382` / `browser.ts` / `use-keybindings.ts` 登记为「可编辑判据违反」
    ⇒ 违反本条；② 出现"删掉 `SELECT` 或 `disabled` 以求与 `isEditableTarget` 一致"⇒ 违反本条；
    ③ 把**注入主世界、引用不到原语**的站点登记为「未收口」债 ⇒ 违反本条（第三类 · 非债）。

## Lessons Learned

- **「待收口」是一张会自己兑现的欠条**：写进 ADR 的尾巴会被下一轮当成待办照办。立判据时若决定"这轮不做"，
  必须写清是**"留着不做"还是"不做"** —— 前者要附解锁条件，后者要附理由。
- **「同一判据」不等于「同一实现」**：判断能否合并的唯一入口是 **Step 3 的探测／判据二分**，不是"两段代码长得像"。
- **二分会漏掉"根本收不了"的那一类**：探测／判据二分隐含前提是"它引用得到原语"。注入主世界的函数体**物理上引用不到**
  —— 塞进二分里怎么判都是假债。⇒ **凡二分，先问它的隐含前提成不成立。**

## 落点

- **判据本体**：本条（三步判别：物理不可收口 / 探测重复 / 判据重复）。
- **已收编**：`ADR-0032`（已取代，被本条取代）—— 通用判据已上提为 §决议 7，具体取证留该条存档。
- **四处不收口的实现**：`uiHooks.ts:16` · `browser.ts:1` · `Timeline.tsx:382` · `use-keybindings.ts:44`。
- **与 `ADR-0029` 的边界**：那条管「交互归谁」；本条管「那条判据的域外副本要不要收」。**禁合并**（判据重复）。
- **取代**：ADR-0032
