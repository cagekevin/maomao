# ADR-0024 · 机制类内容的落点：判据进-ADR，现状进-DATAFLOW，细节进代码注释

- **状态**：已取代
- **结论**：机制类内容按类别归位：判据进 ADR、现状与拓扑进 DATAFLOW、细节进代码文件头、物理红线进 CLAUDE、流程动作进 SOP；CONTEXT 不再承载任何一类。
- **日期**：2026-09-18
- **裁定人**：架构师
- **触发**：spec/CONTEXT.md §三 catch 豁免契约段 · §五 生成链路真相源 / 复制安全隔离 / 会话图片真值契约

## 背景

**旧约定：机制性内容「就近写」—— 谁先写到就在谁那，没有落点规则。**

`spec/CONTEXT.md` 因此积累了一批**机制描述段**（既不是判据、也不是路由）：

| 段 | 实质 | 与谁重复 |
| --- | --- | --- |
| §三「catch 豁免契约 —— 机制已删除」 | ADR-0011 的**复述** | `docs/adr/ADR-0011` |
| §三 幂等/去重/唯一键纪律 | **判据** | 无 ADR（本次补 ADR-0020） |
| §三 类型契约（判别联合形状） | **判据** | 无 ADR（本次补 ADR-0021） |
| §五「生成链路真相源契约」 | `useNodeGeneration` 的**现状** | `spec/DATAFLOW.md §一` + 文件头 |
| §五「复制安全隔离 + 瞬态归属」 | 机制**现状** | `spec/DATAFLOW.md` + `nodeRuntimeStore.ts` 文件头 |
| §五「会话图片真值契约」 | 机制**现状** | `spec/DATAFLOW.md §二` |

它们**内容正确但位置错**。最直接的证据：`grep -n "adr" spec/CONTEXT.md` 曾只有 **3 处**命中（且全为 2026-09-18 新加）—— **两边内容重叠却零交叉引用**，说明它们互相不知道对方存在。

⇒ 根因是一条从未被写下的默认：**CONTEXT 是"以上皆可"的兜底容器**。而按 ADR-0019 的判据，**兜底必被填满** —— 任何"哪都能放"的位置最终都会堆积。

## 判据（它凭什么成立）

**判据是「内容属于哪一类」，分类依据全部来自既有文档的自述：**

| 内容类别 | 唯一归属 | 依据（不是我编的） |
| --- | --- | --- |
| **判据**（凭什么成立 / 被谁推翻） | `docs/adr/` | ADR README §一 边界表 + ADR-0017 |
| **现状与拓扑**（链路怎么走 / 谁引用谁） | `spec/DATAFLOW.md` | 其 §维护规矩自述「**本文件只写当前真相**」+ `refs` 实证 |
| **物理红线**（撬不动的契约） | `CLAUDE.md` | ADR-0017 归位表 |
| **机制细节**（这个函数怎么用） | **代码文件头 JSDoc** | CONTEXT 自述「**代码即知识**」 |
| **流程动作**（怎么做） | `.codebuddy/commands/**` | SOP 定义 |

**⇒ CONTEXT 不在上表中** —— 它承担的不是"内容类别"，而是"内容之间的**指向关系**"（见 ADR-0023）。这正是本 ADR 的核心发现。

**为什么"就近写"不成立（可测）**：同一机制在两处各写一份后**必然漂移**。本仓实证：同一 `deriveNodes` 的"唯一走它"在 **CONTEXT 内部**就写了两遍（`:89` 与 `:272`），**详略还不一致**。这是 `CLAUDE.md §5.4·9` 单一规则原则的直接实例。

**为什么不需要建闸**：判据要能被机器检查才有意义，而"这段该放哪"**不可机器验证**（需要理解语义）⇒ 建闸前置评审第 6 问不过（声索靠人解释 = 形态④）。故本条**以判据 + 落点问句**落地，**不建闸**。

## 后果

- ✅ **每个内容类别有唯一归属**："就近写"不再可能 —— 落点由**内容类别**决定，不由"谁先写"决定。
- ✅ CONTEXT 的篇幅与它的职责**恢复匹配**（337 行 → 约 120 行）。
- ⚠️ **代价 / 回潮风险**：**"就近写"零成本，按类别归位要走 CLI / 换文件** ⇒ 施工时最省力的路仍是往 CONTEXT 塞。**回潮动因与 ADR-0017 同源**，故防线也必须同源：把判据写成**可执行的问句**（"这段是判据吗？→ 走 `adr.mjs`"），而不是"应该注意"。
- ⚠️ **一个真实的代价**：`spec/CONTEXT.md` 曾兼当"新人先读的那份最全的地图"。删减后**新人阅读路径变长**（CLAUDE → CONTEXT → DATAFLOW → ADR）。这是**正确的代价** —— 那本"最全的地图"之所以全，是因为它抄了别人；抄来的部分既不准（会漂移）也无人负责更新。
- 📌 **违反时的判据**（怎么发现"又回去了"）：
  1. `spec/CONTEXT.md` 出现**判决句**（禁止 / 必须 / 不得）而 `adr.mjs search <关键词>` **0 命中**；
  2. 同一机制在 CONTEXT 与 DATAFLOW **各有一份可执行描述**（而不是指针）；
  3. `grep -c "adr" spec/CONTEXT.md` 长期不增长（= 它在重新积累判据而不引用）；
  4. 某段自述"已删除 / 已收口"却仍占**正文段落**（而非一行指针）。
- **被取代于**：ADR-0025
- **毕业去向**：合并入 ADR-0025
