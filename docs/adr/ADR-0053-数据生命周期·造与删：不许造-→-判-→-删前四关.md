# ADR-0053 · 数据生命周期·造与删：不许造 → 判 → 删前四关

- **状态**：生效
- **结论**：删只走这条线：不许为设想消费方铺路 → **报零 ≠ 没人用**（先定位本该消费处 · ②/ADR-0063）→ 过四关（目的／能力／消费／**红线**），查不清 ⇒ 改为修。**死代码＝替换的过渡产物**：功能写完再清，禁为过闸删新码。
- **日期**：2026-09-21（④ 清偿时机 09-21 · 红线关 09-22 · ①-b 豁免 09-23）
- **裁定人**：架构师（取证后自定）/ 用户（④ · 红线关 · ①-b）
- **触发**：ADR-0030 与 ADR-0047 是「什么情况可以删」被切成两条（互抄维持一致）。三轮用户裁定与实证过程见 `daily/架构日志/`（弯路汇编 §「白删」·「detectSkillDrift」·「CSS 词汇表」三处）。

## 背景

旧约定：`ADR-0030`（零消费 ⇒ 删，**缺能力关** ⇒ `move-dir` 被整条删除 = 砍功能，TD-17-27）· 7 步法把「删」写成**首选手法且不带前提**（Step 6「删比改便宜」· 心法 §③）· 死代码一出现就被当"违规"清。三者与 0030/0047 互抄史见弯路汇编（「白删」·「detectSkillDrift」·「CSS 词汇表」）。

## 判据（它凭什么成立）

删除的收益必须**可数且指向「深模块 + 窄接口」**，不是「少一层」（`ADR-0042`：搬家 ≠ 消灭）；②-a 报零**不证"不该被消费"** —— 同一个 0 对应六种成因（`ADR-0063`）。

## 决议

**① 不许造（前瞻）**：不许为设想的消费方铺路，也不许补消费方（补 = 制造新需求）；真要用时按**当时的真实消费方**重建。「不许补消费方」**仅指**不许为**设想的**消费方补；**已存在的消费方改道不算补**（`ADR-0030` §补充②）。

**①-b 豁免：同一文件内的「语义词族」＝设计词汇表，不算幽灵预留（2026-09-23 用户裁定）。**

- **判据（三条同时满足）**：① **同一文件内**；② **同一语义**；③ 取值**全部挂同层令牌** ⇒ 该族整体视为**词汇表**，不因个别档暂无调用点而删（① 防的是**逻辑**层幽灵预留；表达层缺档只会让下个需求点手写第二套样式）。
- **适用面（只此一处，扩大须另裁）**：`src/components/settings/settings.css`（前缀 `st-`，文件头「留白条款」列预留档 + 三条新增约束）。
- **边界（最易退化处）**：只覆盖**已成族**的词；**为单页临时造的新类不在内**；**不适用于逻辑层**（TS/TSX 仍走 ②③）；「魔法数字进类名」不是词汇表（详见 §违反判据 8）。

**② 判（什么算"真的没人用"）—— 两段，缺一不算查清：**

- **②-a 存在性** = **多口径一致报零**：模块引用（AST）· 字符串裸引用 · 桶与门面再导出 · 运行时串，**四口径缺一不算查清**。`refs` 报 0 **单独不成立**（工具修过两次盲区）⇒ 先问「证明它没人用的工具，我验过它的盲区吗？」
- **②-b 落点定位**：**报零 ≠ 没人用** —— 先定位「本该消费它的地方」、看那里现在是什么，再决定删 / 摘 `export` / 接上 / 豁免。**细则（六类落点）见 `ADR-0063`**（本子步骤的唯一执行者）。

**③ 删前四关（缺一即不许删）**

| 关 | 判据 | 不过 ⇒ |
| --- | --- | --- |
| **目的关** | 复杂度**降在哪一项**（须给改前 / 改后同一项） | 答不出 ⇒ **不删** |
| **能力关** | **用户能做的事没变少吗** | 变少 ⇒ **不许删** → 摆 A/B/C 交用户 |
| **消费关** | ② 两段全过：四口径报零（②-a）**且**落点已定位（②-b） | 查不清 ⇒ **不许删，改为修** |
| **红线关**（2026-09-22 补） | **删了它，哪条已成立的红线会失去执行者？**（对照 CLAUDE §5.1 那族：不静默 / 失败必须可见 / 成功必须为真 / 只有生产者才有权呈现错误…） | 答得出 ⇒ **不许删**；确要删 ⇒ **先给那条红线换执行者**，再删 |

**能力关对照表**：死代码 / 重复实现 / 幽灵预留 / 假抽象 / 兜底 ⇒ 用户能做的事**没变少** ⇒ ✅ 可删（删优于改）；**命令 / 入口 / 功能 / 能力 / 对外契约** ⇒ **变少了** ⇒ 🚫 不许删 → 摆 A/B/C 交用户。

**④ 清偿时机（2026-09-21 用户裁定）**：**先把功能写完、跑通，再清偿死代码。** 本条的死代码＝替换时被替代的**旧实现 / 旧路径 / 旧调用点**（替换动作的必然后果，非施工违规）。
- **禁止**为让闸变绿而**删掉本次新写的代码 / 退回老实现**；正确形态是**同批完成**（新接上 + 旧删除 ⇒ 闸自然不报「基线外新增」）。
- 过渡态只许存在于**本次施工内**，落账前清干净（7 步法 Step 6 动作 3）；**"过渡态"不是永久豁免**，不许塞进基线（见 ⑤）。

**⑤ 举证责任在"删"这一方**；四关全过才可删，**默认动作是「修对」**。**禁循环论证**：不得拿「规程 / 文档明令禁用」既当"它坏了"的证据、又当"修好也没人用"的证据。
**`--update-baseline` 红线**：闸报「基线外新增」时**不许**直接 `--update-baseline`（= 把回潮塞进基线、发合法证）；必须先判「这份零消费实现该不该存在」。

## 后果

- ✅ **收益**：「删」从**默认**降回**有条件结论**；堵住"砍用户能力"、"白删"、"为过闸删新代码"三条路；造 / 判（含 ②-b 落点定位）/ 删合成一条线，不再互抄。
- ⚠️ **代价 / 回潮风险**：门槛变高。**反风险**三处：① 拿"能力"当借口留真死代码 · ② 拿"过渡态"当永久豁免 · ③ 拿 ②-b 的"该接上"当留死代码的挡箭牌（故 ③④ 类**必须指得出具体调用点 / 内联份**）。①-b 松动则词汇表退化成"什么都能塞"。
- 📌 **违反时的判据（怎么发现"又回去了"）**：
  1. 删掉的东西含**命令 / 入口 / 导出 API / 对外契约**，而 `git diff` 里**没有"用户已裁定"的痕迹** ⇒ 违规。
  2. 交付说明写「删了 X」却答不出「复杂度降在哪一项」⇒ 违规（白删）。
  3. 仅**单口径**报零就删 · 4. 拿「规程禁止它」同时充当"它坏了"与"修了也没用"⇒ 循环论证。
  5. `check:dead-code` 报「基线外新增」⇒ 先判"该不该存在"，不得直接 `--update-baseline`。
  6. `git diff` 出现「为过死代码闸而删掉 / 回退**本次新写**的功能代码」⇒ 违规（违 `ADR-0016`）。
  7. 删掉的是某条红线的**唯一执行者**，而答不出"谁接替它" ⇒ 违规（红线关不过）。
  8. 违反 ①-b 边界（按"零消费者"删成族词档 · 反向拿它保逻辑死代码 / 为单页造新类）⇒ 违规。
  9. **报零即删、未过 ②-b**：答不出"本该消费它的地方在哪、那里现在是什么" ⇒ 违规；反向（把该**接上 / 摘 export** 的当幽灵预留删掉）同样违规。
  ⚠️ **诚实边界**：可机判的只有 1、5 两条；2、3、4、6、7、8、9 须人工核对（`ADR-0052` 第 6 级：写明"不能"，不许硬凑 grep）。

## Lessons Learned

- **「删 > 改」是结论，不是前提** —— 凡"X 优先"都要补"什么时候不适用"（它被执行成砍掉用户能力）。
- **互抄是合并信号，不是加固**：`ADR-0030:8` 把 0047 两关抄回自己 ⇒ 方向反了（后来者补先立者），补丁方向一反就该合并。
- **清偿是收尾动作，不是准入门槛** —— 当成"施工中必须为零"，最便宜的过法就是删掉刚写的代码（判据反过来生产它要禁止的行为 · `ADR-0016`；同款：`check:catch` 贴标记买绿）。
