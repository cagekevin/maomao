# ADR-0059 · 任务行真源：镜像只反映不筛除，节点是单结果槽

- **状态**：生效
- **结论**：任务行真源 = 后端 `tasks` 表；前端 `taskStore.tasks` 是**只读反映**（不得筛除）；节点是**单结果槽**（末次广播胜出）
- **日期**：2026-09-23
- **裁定人**：用户
- **触发**：同节点连生 3 次，第 2 次结果未上屏（`taskStore | 终态落地时任务已不在（可能已被删除），跳过写回`）
- **落地**：`docs/plan/144-生成链路-任务行真源与两处终态丢弃点收口-2026-09-23.md`（已施工）

## 背景

`reportGenerate` 在提交同 nodeId 新任务时执行「结束同 nodeId 之前未完成的任务」，
但实现只是 `tasks = tasks.filter(t => t !== old)` —— **只删内存**：不取消后端、不删 DB 行、不清轮询句柄。

于是同一 nodeId 上：后端**两支任务都在跑**（前端"停止"≠ 后端"停止"，见下），而镜像被删成一支。
旧那支跑到终态时，唯一原语 `completeTask` 第一句 `const cur = tasks.find(t => t.id === id)` 找不到承载
⇒ `logger.warn` + `return` ⇒ **写行 / 落库 / 广播三件事全不做**，结果静默丢失。

实测三层证据：后端 DB 该行 `completed` + `result_url` 完整；磁盘 21.2MB 文件在位；
丢的只是**镜像里的一行 + 一次广播**。

## 判据

1. **任务行真源 = 后端 `tasks` 表**；前端 `taskStore.tasks` 是它的**镜像**。
2. **镜像只反映，不筛除**：镜像层不得删除/改写后端仍存在的行（含"同 nodeId 只留一条"这类按节点去重）。
   「结束旧任务」若确有需要，属**提交/取消层**（真取消后端句柄 / 置终态），**不在镜像层做**。
3. **任务中心是扁平列表**，本来就不按节点分组（`getSnapshot` 只滤 `nodeId` 为空的垃圾行）
   ⇒ 同一节点出现多条是**正常形态**，不是重复提交。
4. **节点是单结果槽**：`useNodeGeneration` 的回填判据只有 `detail.nodeId === 本节点`
   ⇒ **末次广播胜出**；「被旧结果覆盖」是单结果槽的正常性质，**不新增新旧 taskId 判据**。
5. **终态不得因镜像缺行而静默丢弃**：`completeTask`/`failTask` 的 `!cur` 分支必须**可分两类事实**——
   本会话被用户显式删除（`removeTask`/`clearTasksBy`/`clearAllTasks` 登记）→ 不复活、`debug`；
   否则（镜像缺行）→ **`warn` + `reason: 'not-in-mirror'`**，不许伪装成"可能已被删除"。

## 决议

- `reportGenerate` **不再从镜像删行**（同 nodeId 的旧行如实留着，直到它自己走到终态）。
- 会话级 `deletedIds` 只服务于判据 5 的二分；它**只增不落**（存 string id，量级可忽略）。
- 违反判据的写法（一律视为回归）：镜像层 `tasks.filter(...)` 按节点/状态筛除；按 nodeId 去重；
  给节点回填加"只认最新 taskId"；把 `!cur` 的二分合回一句失实 warn。

## 后果

- ✅ **收益**：同节点连续生成时，**每一个已提交任务的结果都能在任务中心被看到/下载**；
  「结果没上屏」这条静默路径由"缺行必 warn"兜住；镜像与真源不再静默分叉。
- ⚠️ **代价（用户可感知，已声明）**：同节点在旧行终态前会**并存两条**（任务中心 + 「生成中」角标都会是 2）
  —— 这不是"多显示"，是后端**真有两支在跑**（`useNodeGeneration.stop` 只停前端等待，
  `pollTask.ts` 的恢复 attach 明写 `cancelOnAbort: false`）。
- ⚠️ **副作用（已声明，当前无害）**：旧行终态也会发一次 `upstream:updated`（`taskCompletionBus` 只判 `nodeId` 非空）。
  `AUTO_TRIGGER_DOWNSTREAM` 默认 `false` ⇒ 不触发下游；开关打开时同节点会触发下游两次。
- 📌 **本 ADR 不管**：`persist` 无重试（落库可靠性）、"停止"是否该真取消（提交/取消层）、
  镜像是否该可重复刷新（形态债）—— 均为独立事项。
