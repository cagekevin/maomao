# ADR-0011 · catch 豁免标记机制已删除：禁静默吞退回判据层

- **状态**：生效
- **结论**：catch-ok 标记表与静默吞闸已按用户裁定整体删除、不可恢复；静默吞由「判别联合透传＋消费者只转发」判据守，禁以标记合法化。
- **日期**：2026-09-18
- **裁定人**：用户
- **触发**：TD-02-26 · TD-02-45 · TD-16-22
- **补充（2026-09-20 · 引自 ADR-0031）**：前置条件已**回改进正文**（§后果「违反时的判据」第 3 条 · 2026-09-21 回改）—— 只挂头部的那份会漂移（读者读到正文就停）。另：存量 `// catch-ok:` 注释（实测 43 处）**无任何机器校验**，是装饰不是防线，按它登记违规 = 假债。**存量处置（2026-09-20 补）**：它是**注释性留痕**、不是判据载体 ⇒ ① **不批量删**（删掉理由会丢"为什么不吞"的信息）② **不重建闸**（ADR-0016 已论证删得对）③ **数量只降不升**：`grep -rn "catch-ok" src | wc -l` 须 **≤ 43**，新增即违规；新写只能落在"预期内失败 + 已有明确降级语义"处，且写前回读被 catch 的代码。

## 背景

旧约定：空 catch 必须标 `// catch-ok: <CODE>`，CODE 取自 `src/components/base/core/catchOk.ts` 单一登记表（11 码），由 `scripts/check-silent-catch.mjs`（`npm run check:catch`）双向校验，挂在 `pre-push` + CI。

它当初这么定，是为了止血「静默吞异常」高频复发（本仓问题形态统计「静默吞/失败伪装成功」71 条）—— 逻辑是：既然拦不住人手写空 catch，至少要求他留一个可审计的理由码。

## 判据（它凭什么成立 / 为什么不成立）

**不成立。它凭的是「标记存在性」，而不是任何物理判据**（铁律 6：答不出「它凭什么成立」= 待消灭的对象）：

1. **标记是自由文本、理由永不验证** —— 贴一句 `// catch-ok: X` 即可合法通过，成本低于真正改造 ⇒ **闸在生产它本要禁止的行为**（附 A12 / 闸成本守恒律）。
2. **实测被滥用**：99 处标记中 **7 处贴在非空 catch 上**（标记与它所豁免的代码不对应）。
3. **判据冲突**：本轮新判据是「错误必须由产生它的那层以**判别联合**透传（含可展示信息）；消费者只转发、禁止自己显示/加工」（TD-16-33 全局失败吸收层 + `CLAUDE.md §5.1` 三铁律）—— 它要求**改造结构**，而标记机制要求**贴标签**，两者方向相反。
4. **假绿风险**：只判存在性的闸，其绿灯不构成证据（同上「建闸前置评审」形态⑥）。
5. **连带发现**：`catchOk.ts` 本身在闸删除后成为 M6 幽灵预留（零消费）；依赖它的测试是**锁着已被撤销设计的假绿测试**（测试通过 ≠ 那件事存在）。

## 决议

**按用户裁定整体删除，且不可恢复。** 删净清单（逐项已办）：

- 闸脚本 `scripts/check-silent-catch.mjs`
- `package.json` 的 `check:catch` script
- `scripts/gates.manifest.json` 条目
- `src/components/base/core/catchOk.ts`（幽灵预留）
- `catchOk.test.ts`（假绿测试）
- 流程文档逐处回改（`架构师改码7步法` / `架构师心法`）；历史日志不改。

**现行判据（唯一）**：

- 失败必须由**产生它的那层**以判别联合透传（含可展示信息）；**消费者只转发**，禁止自己显示/加工 —— 落 `CLAUDE.md §5.1`「生产者给全 / 消费者只转发 / 不越权」三铁律 + `架构师改码7步法` Step 4。
- `// catch-ok:` 作为**注释性留痕**仍可写，但**无任何机器校验**，写前必须回读被 catch 的代码；同一「吞」语义手写 ≥3 次 → 收口成原语（自带理由＋测试＋唯一实现），**禁止复制标记**。
- 预期内失败一律 `catch + reportDegrade / logger.warn`；守卫只管 contract 违约 → fail-fast（用前置守卫防运行时意外 = **假守卫**）。

**落点**：`CLAUDE.md §5.1`（三条红线）· `.codebuddy/commands/架构师改码7步法.md` Step 4 / 附 A12 · `spec/CONTEXT.md §三`（**本轮就地回改**，原文仍写旧机制为现状 = 漂移，A7）· `spec/DATAFLOW.md:623`（同）。

## 后果

- ✅ 收益：删掉一道「一句话即可绕过」的假护栏；静默吞从「贴标签合法」退回「改结构」，与判别联合判据同向。删闸不是失败，**留一道假护栏才是**。
- ⚠️ 代价 / 回潮风险：**禁静默吞退回只写在注释与判据层（无机器守卫）** → 回潮成本低，是新登记债的高发形态。若将来要重建守卫，**必须先过「建闸前置评审」6 问**，且不能用自由文本标记作豁免通道。
- 📌 违反时的判据（怎么发现「又回去了」）：
  - 出现 `scripts/check-silent-catch.mjs` / `check:catch` script / `catchOk.ts` 任一复活 → 直接失败；
  - 见 `.catch(() => {})` / `catch { return {} | [] | null }` 零留痕，且理由只是「已标 catch-ok」→ 违规；
  - **同一「吞」语义**（经 `ADR-0031` 的探测／判据二分判为**探测重复**）在 ≥3 处**手写**、未收口为原语 → 违规。
    ⚠️ **更正（2026-09-21 回改 · 原文有错）**：本条原写「同一 catch-ok **文案**在 ≥3 处**逐字重复** → 违规」—— 把**文案份数**当判据，**已作废**：文案逐字重复本身不构成违规（`ADR-0031` 先分探测／判据，判据重复禁合并）。按原样执行会把同义改写与"逐字重复的探测"误登记成债（TD-18-14 事故即此）。
