# ADR-0040 · 代码文件的归属判据：按界面位置与数据落点，不按目录名与既有标签

- **状态**：生效
- **结论**：代码文件归属只看「它在界面上长在哪 + 数据落到哪」；目录名/前缀/文档标签不作判据（ADR-0001）。横切门槛＝≥3 域消费+零业务语义，只被一域用的件不许留横切。
- **日期**：2026-09-19
- **裁定人**：架构师（取证后自定）
- **触发**：2026-09-19 域模块化施工；连续 4 次因「按目录名 / 文档既有标签判归属」判错（`base/prompt` 当一域 · `editors` 当独立域 · `agentKeys` 当横切契约 · `ResourceStrip` 归素材域）

## 背景

**旧约定**：文件归哪个域，看**它在哪个目录、叫什么名字**，以及**文档里把它登记成什么**。
这套默认源于「目录即分类」的直觉，仓里从未写成立条判据，却被反复当作依据。

**它为什么一直没被质疑**：规模小时，目录名恰好等于归属（名字是好的初始近似），所以看起来"一直没问题"。

**2026-09-19 域模块化把它们全暴露了** —— 四次判错，每次都是同一个根：

| 判错的件 | 按「名字/标签」判成 | **实测（取证后）** |
| --- | --- | --- |
| `base/prompt/*`（6 件） | 「提示词域」一域 | 实为**两块**：4 件是**画布节点输入控件**（`PromptInput`/`promptChips`/`promptLayout`/`promptMention`）；2 件（`PromptHub`/`promptHubStore`）才是左栏提示词页签 |
| `base/editors/`（10 件） | 「图像编辑域」独立域 | 实测**全挂在图片类节点上** ⇒ 是**图片能力的工具**，不是独立域 |
| `base/core/agentKeys.ts` | 「横切契约」（§7 登记「App/agent/backupStore 三处共用」） | **`backupStore` 消费数 = 0** ⇒ 三处共用**是假前提**；真实 **agent 5 / App 1** |
| `base/panels/ResourceStrip.tsx` | 「素材域」（名字带 Resource） | 它是 **`PromptInput` 输入区里的素材条** ⇒ 跟 `PromptInput` 走 |

⇒ 四次都是 **ADR-0001 的违反**：引用了既有标签，却没先答「它凭什么成立」。

## 判据（它凭什么成立 / 为什么不成立）

1. **「名字」不是物理事实** —— 名字是**人起的初始近似**，会随代码演化而过期；只有**界面位置**和**数据落点**是可观测、可复现的物理事实。
   反证：`nodeImage.ts` 头注自述「坐落于 `src/components/base/`（通用地基）」，但实测消费者 `AssetNode` + `ImageGenerate` **全 image**；头注本身就已过期。
2. **「域 = 用户能指着说的东西」**（`DOMAIN-MODULES §2.0-bis`）⇒ 一个件归哪儿，取决于**它在界面上属于那个东西的哪一部分**，不取决于它叫什么。
   - 用户判例（本次施工定下）：`PromptInput` 是画布节点上的东西；相机是**图片生成节点下面的一个按钮**；深度视频是**视频节点上的 hover 工具**。
3. **「数据落点」定唯一真源** —— 一个件写的数据最终落在谁那儿（`node.data`？自己的存储键？别人传进来的参？），它就跟谁同域。
4. **横切层的门槛是物理的，不是感觉** —— 真横切 = **被 ≥3 个域消费** **且** **零业务语义** **且** 不隶属任何「能指着说的东西」。**承 ADR-0039 N6**（横切层不放域专用物）。
   ⇒ 反过来说：**只被一个域用的件留在横切层 = 违规**（它在生产"找它要去横切层翻"的成本）。
5. **为什么不采「按目录名判」**：它会让**目录名成为自我实现的预言** —— 放在 `base/prompt/` 就判提示词域，判了就不搬，不搬就一直"看起来对"。
6. **边界 —— 不得与 ADR-0038 冲突**：本 ADR 判**归属**（文件该去哪），改名/搬迁时**运行时字符串默认不改**（ADR-0038）。

## 决议

| # | 规则 | 判据 / 反例 |
| --- | --- | --- |
| **L1** | 归属只看 **① 它在界面上长在哪 ② 它的数据落到哪** | 用户判例见判据 2 |
| **L2** | **目录名 / 文件前缀 / 文档既有标签一律不作判据**；引用文档标签前**必须自证**（ADR-0001） | 四次判错实证（背景表） |
| **L3** | **真横切 = ≥3 域消费 + 零业务语义 + 不隶属任何能指着说的东西**；三条全中才算 | 承 ADR-0039 N6 |
| **L4** | **只被一个域消费的件，不许留在横切层** | `attachmentCover`(agent 2) · `volumePolicy`(agent 2) · `agentKeys`(agent 5/App 1) |
| **L5** | **同形态不拆** —— 展开态/子部件/配套件与主件同处一域 | `FullscreenEditor` 是 `PromptInput` 的全屏展开态；`ResourceStrip` 是输入区的素材条 |
| **L6** | **跨域消费不改归属** —— A 的件被 B 用 ⇒ 走 A 的门面，不搬到 B | 承 ADR-0039 N5 |
| **L7** | **判据 1（界面位置）优先于「被 `App.tsx` 消费 ⇒ 横切」**；后者只对**不长在任何域界面内**的件成立 | `CanvasToolbar`/`EmptyCanvasGuide`（长在画布上）vs `LeftPanel`/`TopNav`（不是） |

**落点**：判据本体 = 本条；执行计划 = `docs/plan/域归位-最终执行计划.md`；域清单 = `docs/DOMAIN-MODULES.md §2.0-bis`；命名 = `ADR-0039`；字符串边界 = `ADR-0038`。

## 后果

- ✅ **收益**：归属判断**有唯一物理依据**（界面位置 + 数据落点），不再各判一次；**目录名过期不再导致误判**；横切层不再堆积"只被一域用"的件。
- ⚠️ **代价 / 回潮风险**：
  - **取证成本** —— 每件都要跑 `refs` + 追数据流，比"看名字"慢；**但判错的返工成本更高**（本次四次判错全部返工）。
  - **「看名字」的惯性极强** —— 最危险的回潮是"这次看着像就直接判"。
  - **文档标签会过期** ⇒ 本 ADR 不消灭标签，只规定**引用前必须自证**。

- 📌 **违反时的判据**（怎么发现"又回去了"）：

```bash
# ① 只被一个域消费、却留在横切层 ⇒ 违规（承 ADR-0039 N6）
#    对每个 base/{core,utils,ui,api,storage}/*：取非测试消费方，按域归并，若 |域集合| == 1 ⇒ 违规
#    （本次实证命中：attachmentCover · volumePolicy · agentKeys）

# ② 引用文档标签却没自证 ⇒ 违规（ADR-0001）
#    判归属时若依据写成「§X 说它是 Y」而非「refs 实测消费者 = …」⇒ 违规

# ③ 同形态被拆开 ⇒ 违规
grep -rn "PromptInput" src --include='*.tsx'   # FullscreenEditor / ResourceStrip 应与它同域
```
