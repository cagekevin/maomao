# ADR-0040 · 代码文件的归属判据：按界面位置与数据落点，不按目录名与既有标签

- **状态**：生效
- **结论**：归属只看「界面位置 + 数据落点」；目录名/前缀/文档标签不作判据。横切＝≥3 域消费＋零业务语义；计域数须并入「经 barrel 消费的域」（L1-bis）；L4 的「域」= 业务域（根装配/横切管线不算，L4-bis）。
- **日期**：2026-09-19
- **裁定人**：架构师（取证后自定）
- **触发**：域模块化施工中连续 4 次「按目录名 / 文档既有标签判归属」判错（`base/prompt` · `base/editors` · `agentKeys` · `ResourceStrip`）；2026-09-19 第一波域籍台账（311 件）又暴露 4 处边界无据可依（见判据 7–9）。

## 背景

**旧约定**：看文件**在哪个目录、叫什么名字、文档登记成什么**。它源于「目录即分类」的直觉，从未写成立条判据，却反复被当依据；规模小时目录名恰好等于归属，所以看起来一直没问题。

**四次判错是同一个根**（明细见 `daily/架构日志/25-跨区-域籍判定与搬迁-2026-09-19.md`）：`base/prompt/*`（6 件）被判成"提示词域"一域，实为**两块**；`base/editors/`（10 件）被判成独立域，实为**图片能力的工具**；`agentKeys` 被当横切契约，而登记的"三处共用"前提**假**（backupStore 消费 0 处）；`ResourceStrip` 被判素材域，实为 **`PromptInput` 输入区里的素材条**。⇒ 都是 **ADR-0001 的违反**：引用了既有标签，却没先答「它凭什么成立」。

## 判据（它凭什么成立 / 为什么不成立）

1. **「名字」不是物理事实** —— 名字是人起的初始近似，会过期；只有**界面位置**与**数据落点**可观测、可复现。反证：`nodeImage.ts` 头注自述"坐落于 `base/`"，而实测消费者 `AssetNode`+`ImageGenerate` **全 image**。
2. **「域 = 用户能指着说的东西」**（`DOMAIN-MODULES §2.0-bis`）⇒ 件归哪儿取决于**它在界面上属于那个东西的哪一部分**。用户判例：`PromptInput` 是画布节点上的东西；相机是**图片生成节点下面的一个按钮**；深度视频是**视频节点上的 hover 工具**。
3. **「数据落点」定唯一真源** —— 一个件写的数据最终落在谁那儿（`node.data`？自己的存储键？传入参？），它就跟谁同域。
4. **横切门槛是物理的** —— 真横切 = **≥3 域消费** **且** **零业务语义** **且** 不隶属任何能指着说的东西（承 ADR-0039 N6）；**只被一个域用的件留横切 = 违规**（它在生产"去横切层翻"的成本）。
5. **为什么不采「按目录名判」**：目录名会成为**自我实现的预言** —— 放 `base/prompt/` 就判提示词域，判了就不搬，不搬就一直"看起来对"。
6. **边界 —— 不与 ADR-0038 冲突**：本 ADR 判**归属**（文件该去哪），搬迁时**运行时字符串默认不改**。
7. **fan-in 会被 barrel 折叠** —— 桶（纯 re-export 的 `index.ts`）把多个域的消费折叠成 1 处直连 ⇒ 只数直连**系统性少报**域数。已致一次真实误迁：`TD-25-21` 把 `backupStore` 迁出 `base/store/`，而实测其数据落点是**全量 localStorage**（不认识任何单域），2026-09-19 已回迁。
8. **L4 的「域」是业务域** —— `App.tsx` 是**根装配层**，不是业务域。规则 2 的管辖范围由**闸本体**界定（`check-arch.mjs:403-405`：`BASE_CROSS_CUTTING={core,utils,ui,api,storage}` + `BASE_PREFIX='src/components/base/'`）⇒ **`src/hooks/` 不在其内**；且 `:752-753` 把 `src/hooks/{useNodeData,useEdgeData}.ts` 定为**写回唯一入口** ⇒ 横切层铁件，迁走即让规则 8 失效。
9. **2 域件不能只按 L3 卡** —— L3 的 ≥3 本意是防"**有业务语义**的件被误判成横切"；**零业务语义**件 ≥2 域已足以说明：任一域独占都会逼另一域绕门面私取（违 L6）。

## 决议

| # | 规则 | 判据 / 反例 |
| --- | --- | --- |
| **L1** | 归属只看 **① 界面位置 ② 数据落点** | 判例见判据 2 |
| **L1-bis** | **计域数 = 直连消费域 ∪ 经 barrel(`index.ts`) 消费的域**；判 L3/L4 前**必须对 barrel 本身跑一次 `refs`** | `base/api/generate.ts` 直连 1 处（仅 type import），经桶实被 **6 域**调用 ⇒ 按直连会判成"单域件" |
| **L2** | **目录名/文件前缀/文档既有标签一律不作判据**；引用文档标签前**必须自证**（ADR-0001） | 四次判错实证 |
| **L3** | **真横切 = ≥3 域消费 + 零业务语义 + 不隶属能指着说的东西** | 承 ADR-0039 N6 |
| **L3-bis** | **零业务语义**件 ≥2 域消费即归横切；**有业务语义**的 2 域件留主力域 + 门面头登记"第二消费域" | `JianyingIcon`（image/video 各 1 处渲染 · 零数据落点）⇒ `base/ui/` |
| **L4** | **只被一个业务域消费的件，不许留在横切层** | `attachmentCover`(agent 2) · `volumePolicy`(agent 2) |
| **L4-bis** | L4 的「单域」= **业务域**：`App.tsx` 根装配消费、被**横切管线条**（`src/hooks/` 内 ≥2 域消费的 hook）消费的件**不触发 L4** | `src/hooks/` 8 件实测：消费方只有 `App.tsx` 或 `useGenerateNode`/`useAssetDragToCanvas` ⇒ 一件都不迁 |
| **L4-ter** | **契约原语例外**：键构造 SSOT / 契约常量（导出面**不随功能增长**）即使单域消费也不迁 | `agentKeys`(agent 5) · `videoEditorKeys`(TD-25-7)；判据同 ADR-0042，机器形态 = `mockPartialSpread.test.ts` 的 `WATCHED` |
| **L5** | **同形态不拆** —— 展开态/子部件/配套件与主件同域 | `FullscreenEditor` 是 `PromptInput` 的全屏展开态 |
| **L6** | **跨域消费不改归属** —— A 的件被 B 用 ⇒ 走 A 的门面，不搬到 B | 承 ADR-0039 N5 |
| **L7** | **界面位置优先于「被 `App.tsx` 消费 ⇒ 横切」**；后者只对不长在任何域界面内的件成立 | `CanvasToolbar`（长在画布上）vs `LeftNav`/`TopNav`（不是） |

**落点**：判据本体 = 本条；执行计划 = `docs/plan/域归位-最终执行计划.md`；域清单 = `DOMAIN-MODULES §2.0-bis`；命名 = ADR-0039；字符串边界 = ADR-0038。

## 后果

- ✅ 归属判断有**唯一物理依据**；目录名过期不再致误判；横切层不再堆"只被一域用"的件。
- ⚠️ **取证成本**：每件都要跑 `refs` + 追数据流（判错返工更贵）；**「看名字」惯性极强**（最危险的回潮）；**文档标签会过期** ⇒ 只规定"引用前必须自证"。
- 📌 **违反时的判据**：

```bash
# ① 只被一域消费却留横切层：对 base/{core,utils,ui,api,storage}/* 取非测试消费方按域归并，|域集合|==1 ⇒ 违规（承 ADR-0039 N6）
# ② 依据写成「§X 说它是 Y」而非「refs 实测消费者 = …」⇒ 违规（ADR-0001）
grep -rn "PromptInput" src --include='*.tsx'   # ③ 同形态被拆开：FullscreenEditor/ResourceStrip 应与它同域
node scripts/mv-sync-refs.mjs refs src/components/base/api/index.ts   # ④ 判「单域件」前先看桶（L1-bis）
grep -n "BASE_CROSS_CUTTING\|BASE_HOST_LAYER" scripts/check-arch.mjs  # ⑤ 判 L4 前先核管辖范围（L4-bis）
```
