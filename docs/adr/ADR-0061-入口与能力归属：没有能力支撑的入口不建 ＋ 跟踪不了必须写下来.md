# ADR-0061 · 入口与能力归属：没有能力支撑的入口不建 ＋ 跟踪不了必须写下来

- **状态**：生效
- **结论**：入口只在背后真有可执行的能力时才许存在；能力不归你时不许有入口、更不许替拥有者判死；而"我跟踪不了它"必须写下来（不得谎报进度）。
- **日期**：2026-09-23（由「生成链路不提供中止入口」**泛化**为通用处理方式——用户指示：面向"入口／能力"这类问题）
- **裁定人**：用户
- **触发**：146 删除停止／取消设施（用户裁定 丁1b＋甲）；泛化动因 = 本仓"入口"很多（按钮／端点／命令／工具），
  "这个入口背后真有那个能力吗"会在每个新入口上重演。
- **前身（留痕）**：本条由「生成链路不提供中止入口」**泛化**而来 —— 那是一条**构想号 ADR-0060，未曾落盘、已删号作废**（故不列 `取代`，无可连的对方）；`docs/plan/145`、`146` 里「新增 ADR-0060」是当时快照，按过程文档不回改。

## 背景

「生成中」的节点原有一个「停止」胶囊：点击 → abort → 通知后端 cancel → 后端置 `failed`。
**看起来**能终止任务，六轮取证却发现它从未终止过任何东西：

| 点「取消」的时点 | 真实效果 |
| --- | --- |
| 前端正在 POST | ❌ 拦不住（提交请求不接 signal） |
| 已入队、尚未出站 | ⚠️ 窗口 ≈ 0（句柄首轮立即跑） |
| 正在上传参考图／建任务 | ❌ **最亏**：内部无 `stopped` 检查 ⇒ 上传跑完、任务照样创建 ⇒ 钱花了 + 结果拿不到 |
| 上游生成中 | ⚠️ 只停本地轮询 ⇒ 主动丢掉已付费的结果 |

⇒ **没有任何时点，取消优于"什么都不做"**。而这条空链路的"成功"是伪装出来的（前端恒返 `ok:true`，不读后端 `ok`）。

**为什么升为通用条**："能力不归你却给了入口"是**可复发的形态**（换个场景就是"没有撤销能力的撤销键"、
"不掌握生命周期的删除键"）；同理，"跟踪不了某条数据"也不止发生在任务行上。

## 判据（它凭什么成立）

1. **入口的权力来自能力**：没有能力支撑的入口是**空概念** —— 它不改变任何真实状态，只改变用户的认知（误导）；
   最贵的代价不是"没用"，是让人以为已止损而丢掉本可拿到的结果。
2. **判死权属拥有真相的一方**：不掌握句柄／凭证／生命周期 ⇒ 无权写终态；让消费者写终态 = 越权（`CLAUDE §5.1` 三铁律）。
3. **伪装的成功比失败更贵**：恒返 `ok:true` 让"没做成"永不暴露 ⇒ 空链路长期无人发现（违反 `ADR-0048`）。
4. **"跟踪不了"是确定的事实**：必须落终态，否则消费者只能无限等（报 `running` = 谎报进度）。
   选 `unknown` 还是 `failed` **按后果**：可能已产生外部副作用 → `unknown`（防重复动作）；确定没做 → `failed`。
5. **删入口必须同时补出口**（`ADR-0053` 红线关）：删掉用户出口却不给系统出口 = 把坑挖得更深
   （实证：删取消后，"后端从未持有"的行会永久 `running`，而既有清理入口够不着）。

## 决议（照着走）

新增／删除任何"入口"（按钮、命令、HTTP 端点、对外契约、工具）前：

1. **先答"它背后是哪个能力、归谁"**：能力不归本层 ⇒ **不建入口**；连"改名／搬家"也不做（那只是把空概念换个位置）。
2. **禁止用"只有本地副作用"的实现冒充入口**：清 loading／改本地 state 这类动作**不得**被命名为
   "停止／取消／结束"等**改变外部世界**的词 —— 命名必须与真实效力一致。
3. **消费者不许自造成功**：调外部动作时成功判据来自**对方**（读 `ok`／判别联合），禁"没抛异常即成功"。
4. **删入口时同批补出口**：先问"用户原来靠它离开的**状态**，现在靠什么离开？"答不出 ⇒ 先补出口。
5. **"跟踪不了"必须落终态**：任何"我不再掌握它"的时刻（恢复扫描跳过／快照损坏／句柄丢失）都要**写下来**，禁静默 `continue`。
6. **落 `unknown` 还是 `failed` 按后果**：可能已产生外部副作用 → `unknown`（引导核对，防重复计费）；
   确定没做 → `failed`；两者不得合并。
7. **违反判据要能机判**：写成对账测试／编译期／契约闸，而不是只写文档。

## 后果

- ✅ 空概念入口消失 ⇒ 误解源归零；接口宽度实减（首次落实：Props 8→6、少 1 出口）；
  "跟踪不了"从静默变可见终态 ⇒ 用户有出口。
- ⚠️ **代价／回潮风险**：删除对外端点是**对外契约**变更 ⇒ 必须交用户裁定（本仓：丁1b＋甲）。
  若确需"提前放弃且**真省钱**"，唯一诚实落点 = 能真正阻止副作用发生的那一步**之前**
  （实证：素材出站之后、上游任务创建之前）—— 跨层，另批。
- **落点**：首次落实 = `plan/146`（已施工）→ `canvas/parts/GenerateButton.tsx`（Props 面）·
  `localTool/src/relay-poll.ts`（D16／D17）· `localTool/src/db/relaySnapshot.ts`；判据登记 = `spec/判据登记表.md` §八 #14。

## 违反时的判据

1. 组件在"进行中"状态渲染出操作按钮 → 违反决议 1（对账测试红）；
2. 前端出现指向不存在能力的调用（如 `/cancel`）→ 违反决议 1／3；
3. `apiRegistry` 重新登记该端点 → 违反决议 1（`check:api` 红）；
4. 后端对"不归自己跟踪的数据"报"进行中"，或跳过而不写终态 → 违反决议 5（对账测试红）；
5. 调用外部动作时"没抛错即成功" → 违反决议 3。
