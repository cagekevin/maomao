# ADR-0059 · 镜像与真源：只反映不筛除 ＋ 缺行必二分 ＋ 消费者是槽不是账本

- **状态**：生效
- **结论**：前端持有后端数据的副本时它是**只读镜像**：不得做减法（筛除／去重／改写），缺行必须二分（用户删除 vs 竞态缺失），消费端是槽不是账本。
- **日期**：2026-09-23（同日由「任务行真源」**泛化**为通用处理方式——用户指示：面向"镜像／真源"这类问题，不局限于那次改动）
- **裁定人**：用户
- **触发**：144 批实证「同节点连生 3 次、第 2 次结果未上屏」；泛化动因 = 本仓有多个"后端数据的前端副本"，各自凭经验处理缺行／不一致，缺统一配方。

## 背景

`reportGenerate` 原在提交同 nodeId 新任务时"结束旧任务"，实现只是 `tasks.filter(t => t !== old)` ——
**只删内存**（不取消后端、不删 DB 行、不清句柄）。⇒ 后端两支都在跑而镜像只剩一支；
旧那支到终态时 `if (!cur)` 找不到承载 ⇒ `warn` + `return` ⇒ **写行／落库／广播全不做**，结果静默丢失
（后端 DB `completed` + 磁盘 21.2MB 都在，丢的只是镜像一行 + 一次广播）。

**为什么升为通用条**：镜像不止任务中心一处（素材库 `resourceStore` 的镜像、节点冷启动回填…）；
"一次事故的结论"若不抽象，下一个镜像会重踩同类坑（`ADR-0057` 判据 4：同一判据被反复收口 = 上一轮没收完的征兆）。

## 判据（它凭什么成立）

1. **真源在后端**：跨会话／跨刷新仍须存在的真相只有后端持有 ⇒ 前端副本**永远是镜像**，不是"另一个真源"。
2. **镜像做减法 = 替真源判死**：镜像层删行不改变后端（后端照跑），只让前端"看不见" ⇒ 必然"后端有、前端丢"的静默分叉。
3. **不一致有两种、必须分开**（可机判）：**用户显式删除**（自己登记的集合）vs **竞态／未水合缺失**。
   合成一句"可能已被删除"既**失实**又**不可报警**。
4. **消费者是"槽"不是"账本"**：展示位（节点结果）本是单值槽 ⇒ 同 key 多条终态**末次胜出**是正常性质；
   加"只认最新 taskId"= 第二份真相。
5. **缺陷是"静默"不是"并存"**：镜像并存两条（后端真有两支）是**如实反映**；真缺陷是"终态到了却什么都没发生且不报警"。

## 决议（照着走）

处理任何"前端持有后端数据副本"的地方时：

1. **先问要不要镜像**：消费者只需"当前值"且可直读真源（如按 `nodeId` 精确查后端）⇒ **不建**；
   要建就建**可重复水合**的形态（照 `resourceStore.refreshFromBackend` 写，禁一次性整表盲替换）。
2. **镜像只反映、不做减法**：不得筛除／按业务键去重／改写真源仍存在的行。"要不要结束旧的"属**提交／取消层**，不属镜像层。
3. **缺行必二分、且收口唯一实现**：终态落地"行不在镜像" ⇒ 已显式删除 → `debug`（不复活）；未删除 → `warn` + `reason`。
   两处 `!cur` 分支都调它，禁各写一份。
4. **删除登记是"只增不落"的会话级集合**（存 string id，量级可忽略；与 `progressCancels` 同款）。
5. **消费者是槽，不加新旧判据**：回填只认归属（`detail.nodeId === 本节点`），末次胜出。
6. **并存是真相的形态，必须显式声明**：镜像并存会改变 UI（列表条数／角标）⇒ 属用户可感知，落账必须进"零炸三问"。
7. **失败级别按两类事实选**（复用 `ADR-0048` 决议 7）：用户操作 → `debug`；系统缺口 → `warn` + 可机判 `reason`。

## 后果

- ✅ 镜像与真源不再静默分叉；每个已提交任务的结果都能被看到／下载；"缺行"从失实 warn 变成**可机判 + 可报警**。
- ⚠️ **代价（已声明）**：同 key 在旧行终态前**并存两条**（列表与「生成中」角标都是 2）—— 不是"多显示"，
  是后端**真有两支在跑**（前端从来没有停后端的能力，见 `ADR-0061`）。
- ⚠️ **已知副作用（已声明，当前无害）**：旧行终态多发一次 `upstream:updated`；`AUTO_TRIGGER_DOWNSTREAM` 默认 `false`。
- **落点**：首次落实 = `plan/144`（已施工）→ `base/store/taskStore.ts`（`onTerminalRowMissing` · `deletedIds` · 不筛除段）；
  判据登记 = `spec/判据登记表.md` §八 #13。
- **本 ADR 不管**：`persist` 无重试（落库可靠性）· "停止"是否该真取消（→ `ADR-0061`）· 镜像可否重复刷新（形态债）。

## 违反时的判据

1. 镜像层出现 `tasks.filter(...)` 按业务键／状态筛除 → 违反决议 2；
2. 给节点回填加"只认最新 taskId" → 违反决议 5；
3. `!cur` 二分被合回一句失实 warn，或新增第三处 `!cur` 各写一份 → 违反决议 3；
4. 新镜像一次性整表盲替换、不可重复水合 → 违反决议 1；
5. 并存形态未在落账里声明 → 违反决议 6。
