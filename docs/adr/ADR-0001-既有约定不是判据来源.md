# ADR-0001 · 既有约定不是判据来源

- **状态**：生效
- **结论**：引用既有约定前先答「它凭什么成立」；答不出 → 它就是待消灭的对象。**判据冲突时排序：正确性 ＞ 复杂度 ＞ SSOT ＞ 既有约定**
- **日期**：2026-09-18
- **裁定人**：**用户**（原话：「既有约定小于正确性，小于合理性；既有约定未必就是对的，他有可能就是我们正要消灭的对象」）
- **触发**：TD-18-8 施工中，我用 `PromptHub.tsx:15` 的 `'—'` 当"仓内既有约定"给 `formatBytes` 的非法值兜底背书 —— 用户追问「这个合理么」。

## 背景

仓内长期存在"照抄既有写法"的惯性：施工理由里出现「与现有写法保持一致 / 仓里一直这么写」时，往往**没人再问它为什么成立**。
`formatBytes` 的非法值兜底（`!isFinite(n) || n <= 0 → '0 B'`）就是一条"历来如此"的约定 —— 它把**非法值伪装成真实的 0 字节**。

## 判据（它凭什么成立 / 为什么不成立）

**回读原文后，我引的"约定"根本不存在**：

| 我当时的说法 | 回读原文的事实 |
| --- | --- |
| 「`'—'` 是仓内既有约定（`PromptHub.tsx:15`）」 | 该处 `'—'` 的语义是「**值缺失**」（`const fmtDate = (s) => { if (!s) return '—'; ... }`）—— 与「**非法**」不是一回事 |
| （隐含）仓内对非法值统一用 `'—'` | **同文件对非法日期是 `return s`（原样暴露）** —— 仓内对「非法」原本是**另一种口径** |

⇒ 结论：**「既有约定」本身不构成判据** —— 它既不是物理红线，也不是类型层约束，也不是唯一入口，更没有对账测试支撑。
⇒ 更危险的是：引用未经回读的"约定"，会**亲手造出一条不存在的规则**（附 A13 实证）。

## 决议

**判据冲突时的排序（一切动作通用）：正确性 ＞ 复杂度 ＞ SSOT ＞ 既有约定。**
（原句「既有约定 ＜ 正确性 · 既有约定 ＜ 合理性」只覆盖两端 —— 现补全中间两层；冲突时**逐层判，高者胜**。）
**判据（引用任何既有约定之前先问）：「它凭什么成立？」**

- 答得出（有物理红线 / 类型层 / 唯一入口 / 对账测试支撑）→ 可沿用；
- 答不出（只是"历来如此"）→ **它就是要被消灭的对象**，按正确形态重写。

**落点**（`.codebuddy/commands/架构师改码7步法.md`）：

- 🎯 其余全局铁律 **6**（本条本体）
- 铁律 **1** 取舍顺序 → 末位补「既有约定」（比"兼容性"还低）
- **Step 0** 普查 → 增加「先过 `docs/adr/README.md` 索引」
- 附：**退回与熔断速查** → 新增一行「理由是『既有约定如此』→ 退回取证 + 落一条 ADR」
- 附：**速查决策树** → 新增一支
- 附 A → 新增 **A13**

## 后果

- ✅ 把"照抄"变成"取证"；既有约定从"挡箭牌"降级为"待验证的线索"。
- ⚠️ **代价 / 回潮风险**：取证有成本，「历来如此」最省力 —— 若判据不写成**可执行的问句**，很快会被绕回。
- ⚠️ **反滥用**（已写进铁律 6）：不许拿「既有约定」当挡箭牌；也**不许拿「正确性」当借口做无证据的重写** —— 两边都要取证。
- 📌 **违反时的判据**：施工理由里出现「既有约定 / 仓里一直这么写 / 与现有写法保持一致」**而没有支撑证据**。
