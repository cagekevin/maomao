# ADR-0013 · 纯查询禁止有副作用

- **状态**：生效
- **结论**：查询接口只返回映射，不得写他人 store；镜像完整性必须由拥有者自己的填充入口承担，不得退化成「用户打开过哪个界面」的副作用。
- **日期**：2026-09-18
- **裁定人**：架构师
- **触发**：TD-02-59（provider.list 内直写 resourceStore）

## 背景

旧形态：可引用媒体源 provider（`librarySource.list`）在自己的**查询**实现里调 `mergeResourcesFromBackend`，直接写 `resourceStore`（**他人的真相**）。

它当初这么定，是为了「打开导入弹窗时顺手把素材库镜像拉全」—— 用一个查询的副作用替代一个明确的填充步骤。

## 判据（它凭什么成立 / 为什么不成立）

**不成立。它是一条越权 + 一条时序赌注**：

1. **越权**：`resourceStore` 的所有方是它自己，provider.list 是**消费者**。消费者执行所有方的动作 = 结构错误（7 步法铁律②，不是风格问题）。
2. **镜像完整性退化成偶发**：store 填不填满，取决于**用户有没有打开过导入弹窗** ⇒ `contentId → url` 解析**随时序静默失效**（用户看不到任何报错，只看到"图不见了"）。
3. **纯查询不许有副作用**是接口语义的基本约束：`list` 的调用方有权假设它只读。
4. `spec/DATAFLOW.md:205` 早已写明 `base/media` 不持久化 —— 该写入**本就违反本层红线**。

## 决议

**越权拆除 + 填充归位**（落点 `src/.../mediaRef/librarySource.ts` · `resourceStore.ts` · `onStorageReady`）：

1. `librarySource.list` 删掉 `mergeResourcesFromBackend` 调用及其 import —— **返回纯映射**，纯查询零副作用。
2. `resourceStore` 新增**自有填充入口** `refreshFromBackend`（`fetchAllResourcePages({})` 全量 → `mergeResourcesFromBackend`），在 `onStorageReady` 时调用（已就绪则同步立即回调）⇒ **镜像完整性不再取决于用户打开过哪个界面**。
3. 填充失败 `logger.warn` 留痕，不静默。

## 后果

- ✅ 收益：`contentId → url` 解析不再时序依赖；「查询有没有副作用」这条契约重新可依赖；镜像完整性有了明确的、与 UI 无关的触发点。
- ⚠️ 代价 / 回潮风险：填充改在 `onStorageReady` 全量拉取 —— 若后端资源量增大，首屏会承担拉取成本（当前量级可接受）。回潮形态：日后为「让弹窗更快出图」又在 `list` 里塞一次写入。
- 📌 违反时的判据（怎么发现「又回去了」）：
  - 在 `*.list()` / `listXxx()` / `get*()` 等查询签名里见 `store.set/merge/write` 类调用 → 违规；
  - 「某 store 的内容取决于用户打开过哪个界面」的症状复现 → 违规；
  - 新增镜像填充不再走 `onStorageReady` 而是搭在某个 UI 入口上 → 违规。
