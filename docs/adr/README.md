# ADR · 架构判据决议（Architecture Decision Records）

> **一句话**：本目录记录**已裁定的判据与约定** —— 尤其是**推翻了某条既有约定**的那些。
> **为什么要读它**：**既有约定未必是对的，它可能正是我们要消灭的对象**（`架构师改码7步法` 铁律 6）。
> **读债 / 普查 / 想引用任何"仓里一直这么写"之前，先过一遍本文件末尾的索引** —— 免得把已被推翻的旧约定当依据。

## 二 · 什么时候**必须**写一条 ADR（判据）

> **资格前置见下表「落笔前 6 问」⓿**：ADR 只收「涉及多个面」的判据。

1. **推翻了一条既有约定**（或推翻了一条旧 ADR）—— **必须写**，否则后人照着旧约定再来一遍；
2. **确立了一条新约定**（含"默认不建闸""该闸不可放宽"这类治理判据）；
3. **用户裁定**（业务性拍板）—— **须先过下表 6 问 ⓿**；
4. **被否决的方案**（行业共识：**Don't hide failures — 被否决的决定也有价值**）
   —— 考虑过但没采纳的方案要留档 + 写明**否决理由**，否则后人会把同一方案再提一遍（`状态: 已否决`）。

> **不必写**：一次性操作（改个名、补个类型）、已被现有 ADR 覆盖的重复结论、**只影响一处的边界裁定 / 一次性产品取舍**。

**"写 / 不写"（写ADR前必须经过6个问题，即使用户裁定也要能经过这6个问题）**

| # | 问 | 不通过 ⇒ 处置（禁止写 ADR） |
| --- | --- | --- |
| **⓿** | **只影响一处吗？**（换个地方还会不会遇到它） | 只影响一处（一个组件 / 入口 / 一次性取舍）→ 它是**死日记** → 记 `daily/架构日志/`，**不写 ADR** |
| ① | **它凭什么成立？**（推翻了什么 / 确立了什么） | 答不出「它凭什么成立」⇒ 那个约定就是**待消灭的对象**（ADR-0001）；**"仓里一直这么写"不是依据** |
| ② | **能不用 ADR 守吗？**（ROI 判据） | 类型约束 / 结构隔离 / 唯一入口 / 对账测试能让"误用写不出来" ⇒ 去改代码、升 fitness function，ADR 判过期或毕业。**改动半径小且能根治 ⇒ 不许拿 ADR 守** |
| ③ | **有同义 / 近义的现行 ADR 吗？** | 有 ⇒ **必合并**（禁把同一语义抄 N 份买绿灯）；属**判据重复** ⇒ 只钉边界、不合并。**先收编再谈新增** |
| ④ | **违反时写得出判据吗？** | 写不出「📌 违反时的判据」⇒ 它是**没有防线**的声明，不许落盘。不能机判 ⇒ 须写明"不能" + 给人工判据（ADR-0052），**禁硬凑假 grep** |
| **⑤** | **写下它之后，下一个 AI 的具体动作会变吗？** | 答不出"我该做什么 / 不该做什么" ⇒ **不写**（记 `daily/架构日志/` 留痕，**不占编号**）。⚠️「判过期 / 改写成更好的判据」是 `Step 1/2` 对已**存在** ADR 的收编动作；落笔前只有"写 / 不写"两种出口，谈不上过期 |

> 这 6 问是落笔前的自觉检查：`node scripts/adr.mjs add` 会把**全部 6 问打出来**（`--dry` 同样打）。
> 🔴 **答卷人是 AI（要逐条答），用户的角色是「决策：同意 / 不同意」** —— 别把"命令跑过了"当成"六问答过了"
> （2026-09-20 实证：AI 自答一遍就落了 ADR-0050，前提错——把一次性能妥协升格成架构维度，当场 `rm` 撤回。⚠️ **该号已删号作废**，勿复用 —— 编号回收会让这条历史引用指向另一条 ADR）。
> ⚠️ **2026-09-21 改了什么**：原门槛要求 `--q6 "<AI 逐条回答>"` + 校验含 6 个标记。
> **`--q6` 已删** —— 理由是它**不落盘、无人读**（只在校验时看一眼、回显一次就丢），
> 而用户已在对话里看过答卷 ⇒ 命令行那份是**第二份没人读的副本**；且"含 6 个标记"只证明**敲了 6 个符号**，
> 证明不了答得对、更证明不了用户看过 ⇒ **假防线**（本仓铁律「提示 ≠ 拦住」；`ADR-0052` 第 6 级）。
> **落盘门槛（写入口校验）**：真落盘只需 `--user-approved`（用户已决策"同意"）。缺 ⇒ `exit 2` **拒绝落盘**（`--dry` 不要求）。
> **诚实边界**：它拦不住"AI 答完不展示就自报同意"（用户看没看过**无法机器验证**）—— 故这是**第 6 级诚实声明**，
> 不硬凑检查；真正的防线是**把 6 问 + 答卷贴进对话**这个动作本身（用户当场能看见）。
>
> **流程：AI 逐条答 6 问 → 把 6 问 + 答卷贴进对话给用户看 → 用户决策 → 加 `--user-approved` 落盘。**


## 三 · 模板与状态

### 生命周期

```
草案 ──裁定──▶ 生效 ──┬──▶ 已取代   （被另一条 ADR 取代 · 必须写「被取代于」+ 取代方写「Lessons Learned」）
   │                    ├──▶ 已弃用   （只是不再相关 · **没有**取代者）
   └──▶ 已否决           ├──▶ 已毕业   （判据升为 fitness function · 必须写「毕业去向」）
     （考虑过但没采纳）  └──▶ （原地不动，直到退役）
```

- **本仓特有的旁支**：`已毕业` —— 行业没有这一态（见 §6.3）；`已否决` 来自 `草案`（**不是**从 `生效` 来）。

### 状态枚举（6 态）

| 状态 | 图标 | 含义 | 机器校验（`audit`） |
| --- | --- | --- | --- |
| `草案` | 📝 | 待裁定（本仓多数场景是"裁定后落账"，故 `add` 默认 `生效`） | — |
| `生效` | ✅ | 现行判据 | 必须有「📌 违反时的判据」 |
| `已取代` | 🔄 | **被另一条 ADR 取代** | 必须写「被取代于」，且取代方必须写「取代」 |
| `已弃用` | 🗑 | **不再相关，但没有取代者**（与上一条是**两件事**，行业区分 Superseded / Deprecated） | **不得**写「被取代于」 |
| `已否决` | ❌ | 考虑过但**没采纳**的方案（留档防重提） | — |
| `已毕业` | 🎓 | 判据已升为 **fitness function**（可自动检查的载体） | 必须写「毕业去向」 |

### 文件模板

> **别手写** —— 走 `node scripts/adr.mjs add --title "…" --conclusion "…"`，它会取号、建文件、重生成索引。

```md
# ADR-NNNN · <一句话标题>

- **状态**：草案 ／ 生效 ／ 已取代 ／ 已弃用 ／ 已否决 ／ 已毕业
- **结论**：<一句话，≤120 字 —— 直接进索引表，所以别写成段落>
- **日期**：YYYY-MM-DD
- **裁定人**：用户 ／ 架构师（取证后自定）
- **触发**：<哪个债 / 哪次施工 / 哪条旧约定>
- **取代**：（可选）ADR-XXXX —— 本 ADR 取代了谁
- **被取代于**：（可选）ADR-YYYY —— 谁取代了本 ADR（由 `status --by` 自动写）
- **毕业去向**：（可选）<升到哪个可自动检查的载体 · 文件:行>（由 `status --to 已毕业 --note` 写）

## 背景
<旧约定是什么、它当初为什么这么定>

## 判据（它凭什么成立 / 为什么不成立）
<取证：物理红线？类型层？唯一入口？对账测试？—— 答不出就是待消灭的对象>

## 决议
<新约定是什么；落点（文件:行）>

## 后果
- ✅ 收益
- ⚠️ 代价 / 回潮风险
- 📌 违反时的判据（怎么发现"又回去了"）

## Lessons Learned
<**取代别的 ADR 时必填**（`audit` 会校验）：从被取代那条学到什么 —— 原来那个想法哪里被高估 / 低估了？
  行业原话：Don't hide failures —— 只写"换了个做法"、不写"为什么原来那样想也有道理"，后人会重走一遍。>
```

### 结论建议写成 Y-statement

> 在 **<上下文>** 下，面对 **<约束>**，我们选择 **<X>** 而否决 **<Y>**，以达成 **<目标>**，接受 **<代价>**。

### 不可变性（行业共识 · **本仓改了一条：修正在先，改主意在后**）

行业原话是「accepted 之后正文冻结 —— 改主意就写新 ADR 取代它」；**本仓 2026-09-21 用户裁定修正为**：
**「冻结」保护的是这条判据的历史，不是这几个字的墓碑** —— 原文**本身写错了**（写错 / 漏 / 口径不准 / 自相矛盾 / 与实测不符），**修正它才是唯一合理的动作**（A7 本就是「修正必须回改原文」）。

| 情形 | 判据（怎么分） | 动作 |
| --- | --- | --- |
| **修正** | 把原文**按原样执行**会导出**错动作** ⇒ 原文有错 | **回改原文**（就地改）—— 不许只在新文档里打补丁（那是 SSOT 第二份） |
| **改主意** | 原文没写错，只是**决策变了**（推翻结论 / 换方案） | **写新 ADR 取代**（旧条留档 + 取代链 + Lessons Learned） |

- **顺序：先问「能不能修」，修不了（结论本身被推翻）才写新条 —— 修正 > 改主意。**
- **回改必须留痕**：标日期 + 「原作 X ⇒ 现作 Y + 为什么」（范式见 §6.1 的「⚠️ 更新(2026-09-21) 回改」）。**静默改写才是真正被禁的"改历史"**。
- **头部状态行**（`状态` / `取代` / `被取代于` / `毕业去向`）任何情形都可改。

## 五 · CLI（**唯一入口 · 禁手改文件与索引**）

```bash
node scripts/adr.mjs list [--all] [--json]    # 默认只列**现行**；--all 含已退出
node scripts/adr.mjs show <NNNN>              # 单条全文
node scripts/adr.mjs search <关键词>           # 全文匹配（多词 AND，**含已退出**）
node scripts/adr.mjs index [--write]          # 索引过期则自动重生成（**幂等 · 非闸**，不阻断）
node scripts/adr.mjs audit [--json]           # 只读**对账**（**不是闸**）：有没有违规
node scripts/adr.mjs hygiene [--json]         # 只读**体检**（**不是闸**）：这些 ADR 还值不值得留着
node scripts/adr.mjs stats                    # 状态分布
node scripts/adr.mjs add --title "…" --conclusion "…" --user-approved
                        [--status 生效] [--decider 架构师] [--trigger "…"] [--supersedes NNNN] [--dry]
                        # ⚠️ --user-approved 真落盘时**必填**（--dry 不要求）：缺 ⇒ exit 2 拒绝落盘
                        # ⚠️ 答卷人是 AI，但**答卷必须先贴进对话给用户看**，用户决策后才加 --user-approved
                        # ⚠️ 原 `--q6` 已于 2026-09-21 删除（不落盘、无人读 = 假防线，见 §二 末行）
node scripts/adr.mjs status <NNNN> --to <状态> [--by <NNNN>] [--note "…"]
                        # 状态：草案|生效|已取代|已弃用|已否决|已毕业
                        # --by：被哪条 ADR 取代（双向连线）
                        # --to 已毕业 必须给 --note「升到哪个**可自动检查**的载体」
node scripts/adr.mjs rm <NNNN> --reason "…"   # 只用于误建/重复（正常退役走 status，不删）
```

- **索引是产物**：真源 = 各 ADR 文件的头部字段；下方表格由 `index`（幂等）生成，**手改无效**。读取方**直接读本文件即可**（无需任何前置动作）。
- **`audit` vs `hygiene`（两个只读，各答一件事）**：
  - `audit` = **对账** —— "**有没有违规**"（必填字段 / 篇幅 / 结论重复 / 近义 / 空壳 / 取代链完整性）。**全绿是底线。**
  - `hygiene` = **体检** —— "**这些 ADR 还值不值得留着**"。**全绿也可能已经很胖。** 四个可数指标：

    | # | 指标 | 口径 |
    | --- | --- | --- |
    | ① | **空壳率**（占位符 / 缺段） | **必须为 0**（硬伤） |
    | ② | **近义簇** | **必须为 0**（同义就该合并 —— 这是"ADR 滥用"的量化形态） |
    | ③ | **未毕业率** | 高不一定是病，但**长期不降**要问"是不是该升级为自动检查了"（§6.3） |
    | ④ | **今日新增** | ≥3 条的**预警** —— 一天写多条时回头问 ADR-0025 的归位表：这几条属于**同一类**吗？ |

    ```bash
    npm run adr:hygiene     # 或 node scripts/adr.mjs hygiene
    ```
- **状态白名单（6 态）**：`草案` ／ `生效` ／ `已取代` ／ `已弃用` ／ `已否决` ／ `已毕业`（写别的会被拒 —— 表单校验，不是门禁）。
- ⚠️ 参数值里**别用 ASCII 双引号**（PowerShell 会当引号边界截断）—— 用中文引号「」。

## 六 · 维护 SOP（**ADR 会越来越多 · 且会变垃圾**）

> **ADR 唯一的失败模式**：长成一堆没人读的长文 —— **或更早一步：长成一堆同义的、空壳的、没人敢删的短条**。
> 后者的成因是本仓实证过的：**写 ADR 比就地写文档麻烦，但"懒得想类别"比两者都省事**。
> **四类增长，四条防线**，每条都有对应的机器判据（`adr.mjs audit` / `hygiene`）。
>
> **⚠️ 本 SOP 明确不上闸**：按「建闸前置评审」第 6 问，"该不该写"**不可机器验证**（需理解语义）。
> 故这一层靠**记录纪律 + 可数体检**，不靠闸 —— **一道靠人解释的闸 = 形态④（改声索让它继续绿）**。

### 6.1 条数增长 —— 靠**默认过滤**，不靠"少写"

- `list` **默认只列现行**（`生效` / `草案`）；**已退出**（`已取代` / `已弃用` / `已否决` / `已毕业`）要 `--all` 才见。
- README 索引**分三张表**：生效 / **🎓 已毕业** / 已退出。
- ⚠️ **「已毕业」≠「已退出」**（2026-09-20 拆表）：毕业 = 判据**仍现行**，只是载体从文档升为**自动检查**
  （闸 / 类型层 / 唯一入口 / 对账测试）。若把它与「已取代 / 已弃用」并入同一张表并统一标"勿再引用为现行判据"，
  读者会把**正被闸强制**的判据读成已作废 —— 实测反证：ADR-0046 正引用**已毕业**的 ADR-0035 作同族判据 ·
  ADR-0042 引用 ADR-0030。故三表分列，各自标正确口径。
  *（两者在 `list` 里都算"非现行" ⇒ 默认不列；但在**索引**里必须分开读 —— 前者是"载体升级"，后者是"判据退役"。）*
- **不搬家**：已退出的 ADR 留在原路径（搬家会断链）。这与 `债务.md` 的「活账/死账分离」**不同** —— 因为 ADR 是**记录**，不是**待办**。
- ⚠️ **更新(2026-09-21) 回改**：本节原文写「已退出（`已废止` / `已毕业`）」+「索引**分两张表**」——
  两处**均已过期**且会误导：`已废止` 这个状态名 2026-09-18 已拆成 `已取代` / `已弃用`（`STATUS` 白名单里没有它）；
  索引 2026-09-20 已由两张表拆为三张表（原因即上一条的误读风险）。

### 6.2 正文膨胀 —— 靠**行数上限**

- `结论` ≤ 120 字（它要进索引）。
- 正文 ≤ **80 行**（`MAX_BODY_LINES`），`audit` 超限即报。
- 判据：正文只放 **背景 / 判据 / 决议 / 后果**；**过程记录归区域日志**（`daily/架构日志/`）。

### 6.3 根本手段：**毕业 = 升为 Fitness Function**（控制规模的关键）

ADR 属本仓「建闸前置评审」里的**手段优先级 5（文档留痕）**：

> 结构上不可能 ＞ 类型层 ＞ 唯一入口 ＞ 对账测试 ＞ **文档留痕** ＞ 机器闸

行业把「把架构决定变成**可自动执行的自检**」叫 **fitness function**（*Building Evolutionary Architectures* 一脉；ArchUnit 式测试 / 类型约束 / lint 规则）。
⇒ **ADR 是「判据的孵化器」，不是「判据的永久仓库」**：判据一旦能升为 fitness function，就该毕业：

```bash
node scripts/adr.mjs status 0002 --to 已毕业 --note "对账测试：tests/unit/degrade.test.ts 断言裸三元零留痕"
```

- **判据收紧（2026-09-18）**：**能被自动检查的才算毕业** —— 只写进文档的不算。故 `--note` 必须写清**载体 + 文件:行**。
- 毕业后：状态 `🎓 已毕业`；默认 `list` 不再列它。
- **规模上界**：`现行集大小 = 尚未被自动检查承担的判据数` —— 这是**有上界**的量，不会无限膨胀。
- `audit` 会拦：已毕业却没写毕业去向 · 生效 ADR 缺「📌 违反时的判据」（没有它 = 发现不了回潮）。

### 6.4 写入门槛（`add` 已拦 · 但**拦不住的才是重点**）

**机器能拦的（落盘前 exit=2）**：

- 拒**标题重复**、拒**结论重复**、拒**结论近义**；
- 拒**模板占位符残留**、拒**缺必填段落**（背景/判据/决议/后果）—— 见下"空壳"一节。

**机器拦不住的（落盘前 `exit=2` 之外的那层）—— 见 §二「落笔前 6 问」（SSOT：落笔前自觉检查，任一不过 ⇒ 禁止 `node scripts/adr.mjs add`）。**


**空壳检测（2026-09-18 补 · 实证催生）**：`add` 一直**打印**"占位符留着 = 假账"却从不**检查**它。
实测：造一条正文全是 `<新约定是什么>` 的空壳 ADR ⇒ `audit` 报 **0 问题**（假绿灯）。
补上后 **立刻抓到一条真实空壳**（`ADR-0008` —— 只有标题与结论，四段全是占位符，却显示"生效"）。⇒ 已按 TD-17-14 的原始证据补全。

**近义检测（2026-09-18 补 · 同一轮催生）**：原先只比**字符串全等** ⇒ 结论改一个字即绕过。
于是同一天里连写出 3 条讲同一件事的 ADR（`ADR-0017` / `0023` / `0024`，后合并为 `ADR-0025`）。
现在 `add` / `audit` 用**归一化后的字符集 Dice 系数**判近义，阈值 **0.55** —— 标定依据（对本仓全量现行 ADR 两两实测）：

| 情形 | 实测得分 |
| --- | --- |
| 已确认的同义对（合并前的 0010 vs 0020） | **0.547** |
| 当前最相似的一组**不同**判据（ADR-0005 vs 0006） | **0.436** |
| 无关判据 | ~0.23 |

> **为什么不用 bigram**：中文同义改写会换掉大量相邻字对，bigram 把 0.55 的同义对压到 **0.16**（抓不到）；字符集 Dice 有 0.55 vs 0.23 的分隔度。
> **误报怎么办**：`add ... --force` 跳过（确属不同判据时，顺手把两者措辞改到判据分明）。**误报代价只是多看一眼，漏报代价是生效集虚胖。**

**`add` 仍拦不到的一类重复（只能人工判）**：两条 ADR **标题不同、结论也不同，但正文大面积同源**
（例：ADR-0023 与 ADR-0024 都曾各写一份"逐段落点表"）。
⇒ 处置：**后来者写指针，不写第二份**（"见 ADR-XXXX §决议"）。这是 `audit` 里「正文 ≤80 行」那条检查的**真实用途** —— 篇幅超限往往不是话多，是**把别人的内容又抄了一遍**。
⇒ 判据：删掉这一段，读者还能靠指针找到同样的信息吗？能 ⇒ 该删。

### 6.5 **Find 升级触发器**（索引表会随条数失效）

行业实测：**80 条链接的 README 可导航 / 300 条不可导航 / 200 个文件的扁平目录查找性近零**。
本目录的索引表就是那个 README ⇒ **必须在到上限之前换载体**，由 `audit` 到点报警：

| 条数 | `audit` 动作 | 该做什么 |
| --- | --- | --- |
| ≥ **60**（`FIND_WARN`） | 报警 | 启动 Find 升级：索引按 `状态` / tag 分表 + `list --tag` |
| ≥ **150**（`FIND_CRITICAL`） | 报警（"已不可导航"） | 必须换载体：发布站点（Log4Brains 一类）或拆多索引 |

> **明确不做的**：现在就引入站点。本仓读者是 AI agent + 用户，CLI 的 `list/search` 更贴；且站点会引入新失效模式（构建链依赖 → 站点"变暗"）。
>
> **⚠️ 也不要学 `adr generate toc > docs/adr/README.md`**：它**整份覆盖** README ⇒ 会**冲掉 guidelines 段**（边界 / 何时写 / 维护 SOP 全没了）。
> 本仓用**标记块**（`<!-- ADR-INDEX:BEGIN -->` … `END`）只替换表格、保留手写段，并自带漂移校验（`index` / `audit`）—— 这是**比它好**的地方，别退回去。

### 6.6 **Review Checklist**（写 / 改 ADR 前自查）

- [ ] **裁定人**写短（角色 / 人名），原话与细节放**背景**？（长文本会把 `stats` 一行撑爆）
- [ ] **背景**说清了"旧约定是什么、它当初为什么这么定"？
- [ ] **判据**回答了「它凭什么成立？」—— 有物理红线 / 类型层 / 唯一入口 / 对账测试支撑？（答不出 ⇒ 它就是待消灭的对象）
- [ ] **否决的方案**也写了吗？（行业共识：Rejected decisions are valuable）
- [ ] **后果**里有「⚠️ 回潮风险」和「📌 违反时的判据」吗？（没有 = 发现不了回潮）
- [ ] **落点**给了 `文件:行` 吗？（"某模块已有 X"只有文档编号 = **未实现**，附 A2）
- [ ] **是修正还是改主意**？把原文按原样执行会不会导出错动作 —— 会 ⇒ **回改原文 + 留痕**（**修正优先**）；原文没写错、只是决策变了 ⇒ **写新 ADR 取代**（§三 不可变性）
- [ ] 若本 ADR **取代**了别的 ADR：写了 **`## Lessons Learned`** 吗？（从被取代那条学到什么 —— `audit` 会校验）
- [ ] **正文有没有大面积复述另一条 ADR**？有 ⇒ 改写成指针（§6.4 末条；`audit` 的「≤80 行」正是为此报警）
- [ ] 这条判据**能不能升为 fitness function**？能 ⇒ 直接升，别停在文档层（§6.3）
