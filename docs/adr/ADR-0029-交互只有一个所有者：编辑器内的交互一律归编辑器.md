# ADR-0029 · 交互只有一个所有者：编辑器内的交互一律归编辑器

- **状态**：生效
- **结论**：交互只有一个所有者：焦点在编辑区（INPUT／TEXTAREA／contenteditable）内时，一切交互归编辑区，画布级监听一律让位；判据只有一条（事件在谁的地盘），禁按载荷分类。**域外副本属判据重复，禁合并**（ADR-0031）
- **日期**：2026-09-18
- **裁定人**：用户
- **触发**：TD-04-34 输入框聚焦粘贴复制的节点双处理

## 背景

**旧做法（不是明文约定，是"看起来更聪明"的写法）**：window 上的全局粘贴监听对 contenteditable
**按载荷分类放行** —— 剪贴板里是图片或节点组 JSON 就交给画布建节点，其余留给编辑区。
它还有一个变体（787ca25）：input/textarea 内也按载荷放行，理由是「否则 JSON 文本塞进编辑框 =
复制节点粘贴不上」。

**两条理由都看着正当，但都漏了同一件事**：编辑区**自己也处理**这些事件。于是同一个事件被两个
所有者各处理一次：

```
粘贴（焦点在 prompt 输入框，剪贴板 = 复制的节点）
  → PromptInput.handlePaste：preventDefault + 把 JSON 文本插入输入框（只 preventDefault，不 stopPropagation）
  → 事件继续冒泡到 window → A 闸：载荷是组 JSON ⇒ 放行 → B 闸 handleTextPaste → 建出 textGenerateNode
  ⇒ 用户看到「既多了一个节点，框里还落进一堆 JSON」
```

**关键取证**：`ImageBoxNode` 的 window paste 监听（`:386-415`）**早就是对的** —— 它第一件事就是
「焦点在编辑区 ⇒ 粘贴不归我」。**本仓已有正确判据，只有几处用了"按载荷猜"或自写的替代品。**

**同一条判据被写成 7 份，且完整性不一**（这就是本轮真正要治的母体）：
完整清单见 `daily/架构日志/04-跨区-PromptInput粘贴未stopPropagation双建节点-2026-09-18.md §8.2`（不在此复述）。
摘要：1 份共用原语 + 4 处正确消费 + 3 处手写副本 + 1 处**漏 contenteditable** + 1 处**无守卫（唯一入口）** + 2 处**按载荷**。

## 判据（它凭什么成立 / 为什么不成立）

1. **同一个交互事件不能有两个所有者** —— 这不是偏好，是"双处理"的**充分原因**。
2. **归属由"事件发生在谁的地盘"决定，不由"载荷长什么样"决定** —— 载荷分类是**间接判据**，
   必然漏（本轮漏的正是"编辑区自己也会处理"）。
3. **已有现成载体，无需新造**：`isEditableTarget` 覆盖 INPUT／TEXTAREA／contenteditable；
   且**判据该放在唯一入口**，而不是"每个消费者各自记得加"（实证：`VideoProcessNode` 那份漏了
   contenteditable ⇒ 输入框里按 Delete/Backspace **既删文字又删片段**）。

## 决议

1. **判据单点**：一切"编辑器内让位"的判断走 `base/core/uiHooks.ts:16::isEditableTarget`，**禁自写**。
2. **判据上移到唯一入口**：`canvasHotkeys.ts::useCanvasKeydown` 内置该守卫（`:57`）
   ⇒ 画布内组件"忘加"在结构上不可能；`VideoProcessNode` 的自写守卫**删除**（`:744-746`）。
3. **手写副本改走原语**：`ImageBoxNode:391` · `PanoramaNode:463` · `OverlayEditor:644`。
4. **粘贴侧判据塌缩为一条**：A 闸 `useAssetDropPaste.ts:613` 与 B 闸 `:447` 都改为
   `if (isEditableTarget(e)) return;`；`PromptInput.handlePaste` 补 `stopPropagation`（`PromptInput.tsx:633`）。
5. **删净派生原语**：`hasImageClipboardItem` / `isOnlyPlainTextClipboard` / `isContentEditableEvent` /
   `isCanvasGroupJson` / `readClipboardText` 全部失去消费者，**已删**（不留幽灵逻辑）。
6. **域外副本不收口**（2026-09-18 回改原文：原写「待收口（不在本轮）」，用户裁定推翻）：
   `director3d/panels/Timeline.tsx:382` · `videoEditor/utils/browser.ts:2` ·
   `videoEditor/hooks-cutia/use-keybindings.ts:44` 三处**各自保留、禁止合并** —— 取证判定属
   **判据重复**（差异均为域内必需：`SELECT` 判据防"下拉框内 Delete 删关键帧"、`disabled` 是
   `isTypableDOMElement` 的对外契约、`use-keybindings` 判的是 `document.activeElement` 且带
   `[data-keybinding-free]` 自由区），按 7 步法 Step 3「判据重复严禁合并」处理。判据本体见 **ADR-0031**。
   ⚠️ 原措辞曾于同日被区 18 横推**当成待办照办**，登记出 TD-18-10/11/12 三笔假债（见 ADR-0031 §背景）。

## 后果

- ✅ 收益：判据实现 **7 份 → 1 份**；`useAssetDropPaste.ts` **净 −61 行**（+32/−93），5 个原语清零；
  守卫从"每个消费者各自记得加"变成"唯一入口强制"；修掉 2 个真 bug（输入框内 Delete/Backspace 删片段、
  输入框内粘贴双处理）。
- ⚠️ 代价 / 回潮风险：**能力有变（有意，用户裁定）** —— 编辑区聚焦时粘贴图片 / 复制的节点**不再建节点**，
  input/textarea 内粘贴节点 JSON 也不再建节点（787ca25 的路径取消，改为先点画布再粘贴）。
  风险：按载荷分类的写法"看起来更聪明"，容易被后人重新发明。
- 📌 违反时的判据：
  - **机器**：`tests/unit/editorOwnership.test.tsx` 变红（粘贴侧 5 例 + 键盘侧 4 例，同一条判据）。
  - **人工**：任何 window/document 级交互监听里出现**按载荷/内容分支**来决定"要不要接管"，
    或出现**手写的** INPUT/TEXTAREA/contenteditable 判断 ⇒ 违反本条。

## Lessons Learned

本条初稿（同日数分钟前）标题写的是「**粘贴**不归画布」，**范围写窄了** —— 用户当即指出
「删除、全选同理，编辑器里的任何操作都是自己的」。这不是改主意，是**把同一裁定写全**：
归属判据天然**按事件类推广**，只治一种事件等于留下"下一个事件再犯一次"。
**教训：立判据时要问「这条判据的完整外延是什么」，而不是「用户这次报的是哪种事件」。**
