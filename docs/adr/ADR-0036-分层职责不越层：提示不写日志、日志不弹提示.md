# ADR-0036 · 分层职责不越层：提示不写日志、日志不弹提示

- **状态**：已毕业
- **结论**：弹提示→toast、记日志→logger、广播→事件总线、存数据→contentStore、算/转换→工具层、下载→clipboard.downloadUrl；禁止越层代劳。新增事件/存储键/错误类型先登记 contracts.ts。
- **日期**：2026-09-19
- **裁定人**：架构师（归位取证；规则原文见 `spec/CONTEXT.md:156`）
- **触发**：TD-18-20 —— 该判决句长期只存在于 CONTEXT，`adr.mjs search` **0 命中**（违反 ADR-0025 判据 1）
- **已毕业的部分**：「新增事件/存储键先登记 `contracts.ts`」已由闸 `check:events` / `check:keys` 强制 ⇒ 该子项已是 fitness function

## 背景

「协作规则（不越层）：弹提示→②、记日志→③、广播→①、存数据→④、算/转换→⑤⑥、下载→⑦。
**禁止越层**（toast 不写日志、logger 不弹提示）」此前只写在 `spec/CONTEXT.md:156`。

**本仓有两次真实的越层代价，都留下了注释证据**（2026-09-19 取证）：

1. `agent/canvas/canvasPlanExecutor.ts:365-372` —— 消费方替**宿主**记日志：
   「我先前在此写 `logger.warn('日志回调失败')` = 消费方替所有方决定错误形态（**越权＋末端打补丁**）。
   正解：**透传** —— 若宿主希望"日志失败不阻断执行"，那是**宿主在自己 `onLog` 实现内部**该处理的事
   （它拥有该回调的完整语义）。」
2. `base/utils/videoEngine.ts:665-667` —— 消费方替**生产者**压平结果：
   「本层**不再自造 try/catch**：`uploadFileToLocal` 已是判别联合（含生产者 message），直接**转发**即可 ——
   原来的 `catch → logger.warn → return null` 把原因压平，再叠一层 `{url}|null`，等于信息被扔两次。」

两次的共同形态：**某一层替另一层"好心"补了一手，结果是信息被压平 / 责任被挪走**。

## 判据（它凭什么成立）

1. **每一层只拥有自己那部分的语义**。回调是否可失败、失败了要不要阻断 —— **只有提供回调的宿主知道**；
   消费方替它决定，就是把"决策权"和"责任"一起搬走了（上面证据 1）。
2. **越层的输出是"压平"**：替别人兜底必然把结构化结果压成标量（`{ok,message}` → `null`），
   信息在**每一层各丢一次**（上面证据 2）。
3. **可机器检查的那部分已经毕业**：事件名与存储键必须先登记 `contracts.ts`
   —— 由 `check:events` / `check:keys` 两个闸强制 ⇒ 不是靠自觉。

## 决议

1. **职责表（谁干什么，只干这个）**：

   | 意图 | 唯一落点 |
   | --- | --- |
   | 弹提示 | `toast`（`base/core/toastStore.ts`） |
   | 记日志 | `logger`（`base/core/logger.ts`） |
   | 广播 | 事件总线（`EVENTS`，登记于 `contracts.ts`） |
   | 存数据 | `contentStore`（键登记于 `contracts.ts`） |
   | 算 / 转换 | 工具层（`base/utils/**`） |
   | 下载 | `clipboard.downloadUrl` |

   **「弹提示」的入口分工（2026-09-20 补 · 消歧）**：`toastStore` 有两个层级，别再猜——
   · **业务代码**（节点 / 面板 / 编辑器交互提示）→ **`toastSuccess` / `toastError` / `toastWarning` / `toastInfo`**；
     语义化、不记 type 字符串、分级默认时长自动生效。
   · **`showToast`（底层出口）只给两个消费者**：`log/degrade.ts`（需 `coalesceMs` 合并窗口防刷屏）·
     `videoEditor/lib/toast.ts`（cutia `sonner` 适配壳，需转手 `duration`）。业务代码不直调它。
   · **不要在调用点手写 `duration`** —— 分级默认值（error 4s > warning 3.5s > success/info 2.5s）已是判据，
     要改就改 `DEFAULT_DURATION` 一处。`coalesceMs` 同理（只服务降级刷屏）。

2. **禁止越层代劳**：`toast` 的实现里不写 `logger`；`logger` 的回调里不弹 `toast`；
   消费方不为宿主/生产者的失败"补一手"（应**透传**，把决策权留给拥有该语义的一层）。
3. **新增事件 / 存储键 / 错误类型** → 先登记 `contracts.ts`（已由 `check:events` / `check:keys` 强制）。
4. **CONTEXT 只留一行指针**（不抄判据正文）—— 见 ADR-0025。

## 后果

- ✅ 判据有了主场与检索入口（`adr.mjs search 越层` 可命中，此前 0 命中）。
- ✅ 存量零违反（两处越层**都已修好并留下注释**）⇒ 本条**零行为变化**，是"立判据"不是"改代码"。
- ⚠️ **代价**：透传比"顺手补一手"写起来更麻烦，且**问题会暴露在更外层**（看起来像是"没人处理"）。
  这是正确的代价 —— 真正该处理它的那层才拥有完整语义。
- ⚠️ **回潮风险**："这里加个 `logger.warn` 免得线上查不到" —— 诱惑最大，也最典型的越层。
  判据问句：**这一层拥有这个失败语义吗？** 不拥有 ⇒ 透传。

📌 **违反时的判据（怎么发现"又回去了"）**：

1. `toast` / `logger` 的实现内部出现对另一者的调用；
2. 消费方为**宿主注入的回调**或**生产者的判别联合**补 `try/catch` + `logger.warn`（应为透传）；
3. 某层把结构化结果压成 `null` / `''` 再往上传（信息被压平）；
4. 新增 `EVENTS` / `STORAGE_KEYS` 未登记 `contracts.ts` ⇒ `check:events` / `check:keys` 直接红
   （**这已是闸，不靠人**）。
