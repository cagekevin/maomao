# ADR-0041 · 机器可判定性：每条结构规则须可写成检查，并用负例探针证明它真会红

- **状态**：生效
- **结论**：每条结构规则先答「能不能机器判定」：能 ⇒ 附检查命令并用负例探针证明真会红；**不能 ⇒ 必须写明"不能" + 给人工判据**，不许硬凑假 grep。闸绿不算证据。
- **日期**：2026-09-19
- **裁定人**：架构师（取证后自定）
- **触发**：2026-09-19 域模块化；同一批里「闸绿」与「实际已炸」并存 —— `check:arch` 绿的两条规则 2 违规是**执行后实测才冒出来**的；计划文档里 4 处写成「验收：check:arch ✅」却被照抄

## 背景

**旧约定**：规则写成一句自然语言（「域目录必须有门面」「横切层不放域专用物」），验收写「跑 `check:arch`」。

**它为什么不够**：

1. **「闸绿」被当成证据，其实只是"没被检查到"** —— 2026-09-19 执行 A1 后，全仓冒出
   `base/api/pollTask.ts → components/task/taskStore.ts` 与 `base/utils/assetUrl.ts → components/settings/appSettings.ts`
   两条规则 2 违规；**它们在搬之前不存在**（因为 `base/store` 不在横切集合里，出向依赖合法），**搬完才成立**。
   ⇒ 计划里写「验收：check:arch ✅」是**空头支票**：不搬就永远绿，搬了才红，而红的时候已经是返工。

2. **"验收"被照抄** —— 计划文档 4 个批次都写「`check:arch` ✅」，执行者直接复制该行当结论，没真跑。

3. **规则写不出检查 = 没有防线**（`docs/adr/README.md` 立条判据 ④）。

**相关旧约定**：`ADR-0016`（闸不许凌驾正确性；闸的合法通过成本必须 ≤ 绕行成本）—— 本 ADR 是它**在结构规则上的具体化**：一条不能自证会红的规则，等于"通过成本 = 0 且绕行成本 = 0"，它在生产它本要禁止的行为。

## 判据（它凭什么成立 / 为什么不成立）

1. **「绿」有两种成因** —— ① 真的合规 ② **根本没被检查到**（规则没写 / 写成了不可执行）。二者从输出上**不可区分** ⇒ 必须靠**负例探针**区分：故意造一个违规，看它是否变红。
2. **负例探针是唯一能证伪的检查** —— `ADR-0039` 后果段已明写「`check:arch` 绿**不算证据**，须带负例探针证它**真会红**」。本 ADR 把这条从"某条 ADR 的提醒"升为**通用判据**。
3. **目标是「AI 能自动发现并定位」** —— 结构的最终目标不是"人看着整齐"，是**下一次改动时 AI 能直接找到并判断对不对**（`DOMAIN-MODULES §1` 提升改码效率）。写不成检查 ⇒ AI 只能读散文 ⇒ 达不到目标。
4. **反证（"每条规则都配一个闸"不成立）** —— 会闸泛滥 + 维护成本（ADR-0016）。
   ⇒ 本 ADR 要求的是**「写得出检查命令」**，不要求**「一定建成常驻闸」**；一次性规则可以是脚本/命令，只要能跑。
5. **边界 —— 不授权放宽闸**：要改的是**规则的表述与前置条件**，不是把闸调松（ADR-0016「收窄不放宽」）。

## 决议

| # | 规则 | 判据 / 反例 |
| --- | --- | --- |
| **M1** | 每条结构规则**必须先答「它能不能机器判定」**：能 ⇒ 必须附检查命令（grep / 脚本 / 现成闸）并用负例探针证它会红；**不能 ⇒ 必须写明"不能" + 给出人工判据与落点**，**不许硬凑一个假 grep**（假防线比无防线更坏）。⚠️ **2026-09-20 收窄**：原句「写不出 ⇒ 该规则不成立」是**绝对句**，与 ADR-0046 自认「本项没有机器防线、且硬凑的 grep 更坏」直接对撞，按字面还会让现行集里 ≥9 条语义判据（0025 内容落点、0046 让 AI 不猜等）全部"不成立" ⇒ 收窄在此。**收窄不是放宽**："不许假装有防线"这条比原来更严 | 立条判据 ④ · ADR-0046 §后果 |
| **M2** | **闸绿不算证据** —— 必须用**负例探针**证明它真会红（造一个违规 → 观察变红 → 撤销） | ADR-0039 后果段 |
| **M3** | 计划文档的**验收行禁止写「跑 X ✅」当结论** —— 必须写**判定命令 + 期望输出**；执行者须**真跑并贴结果** | 4 处空头支票 |
| **M4** | 搬迁类规则要写**前置条件**（搬之前就该判，不是搬完才判） | A1 两条违规：搬前合法、搬后才红 |
| **M5** | 计数/清单类断言**必须机器复算**，禁止沿用旧数 | 本轮件数栽 3 次：563→564→491→504 |
| **M6** | 检查命令本身**也要先自检**（拿已知答案验一遍） | 本会话验证脚本自己错 2 次（前缀漏配 / 扩展名漏配） |

**落点**：判据本体 = 本条；归属判据 = `ADR-0040`；命名/门面 = `ADR-0039`；执行计划 = `docs/plan/域归位-最终执行计划.md`。

## 后果

- ✅ **收益**：规则**可证伪**；"绿"不再被误当作合规；AI 下次能**自己跑命令判定**，不必读散文或问人。
- ⚠️ **代价 / 回潮风险**：
  - **写检查比写散文慢** —— 但写不出检查的规则本来也不该立。
  - **负例探针可能被跳过**（嫌麻烦）⇒ 退化回"绿即合规"。
  - **计数类断言易失效**（改一次表就过期）⇒ M5 强制复算。

- 📌 **违反时的判据**（怎么发现"又回去了"）：

```bash

#    扫 docs/ 与 docs/adr/ 里的规则条目：缺 ```bash 检查块 的 ⇒ 列出

# ② 只有"跑 X ✅"、没有期望输出 ⇒ 违规（M3）
grep -rn "验收.*check:arch ✅" docs/plan/          # 命中即为待补（须换成判定命令+期望）

# ③ 没跑负例探针 ⇒ 违规（M2）
