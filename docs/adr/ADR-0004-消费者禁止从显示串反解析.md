# ADR-0004 · 消费者禁止从显示串反解析

- **状态**：生效
- **结论**：生产者给结构化出口（`formatBytesParts`）；`.split(' ')` 反解析 = 越权
- **日期**：2026-09-18
- **裁定人**：架构师（取证后自定）
- **触发**：TD-18-8 施工中，`StorageMonitor.tsx:761/771` 的 `formatBytes(total).split(' ')`

## 背景

`StorageMonitor` 的环形图要把「数字 / 单位」**分两行**渲染，此前的写法是：

```tsx
{formatBytes(total).split(' ')[0]}
/ {formatBytes(total).split(' ')[1] || 'B'}
```

⇒ 等于给 `formatBytes` 加了一条**未文档化的结构契约**（返回值必须**恰好两段、空格分隔**）。
这条契约没有任何地方写明，却在两个消费点上被**依赖**。

## 判据（它凭什么成立）

1. **三铁律③「消费者不越权 / 不自造」**：能调用生产者，却从生产者的**产物（显示字符串）**里反解析数据 = 从下游拼第二份真相。
2. **它让上游的显示格式变成隐式接口**：`formatBytes` 一旦改格式（本次就改了 —— 非法值从 `'0 B'` 变 `'—'`），
   消费者**静默错**（渲染成「— / B」），且**没有任何闸/类型能拦住**（`.split(' ')` 对任何 string 都合法）。
3. 实证：本次施工就踩了它 —— 我先只数了 fan-in（21 处），**没读用法**，于是漏掉了这条结构契约。

## 决议

**生产者给结构化出口，消费者禁止从显示串反解析：**

- 新增 `formatBytesParts(n): { value: string; unit: string } | null` —— 字节渲染的**唯一真源**（非法 → `null`）；
- `formatBytes(n)` 改为 `formatBytesParts` 的**渲染**（`p ? \`${p.value} ${p.unit}\` : '—'`）—— 一份真源，不可能漂移；
- `StorageMonitor` 改委托 `formatBytesParts`，**禁止** `formatBytes(...).split(' ')`。

## 后果

- ✅ 显示串格式不再是隐式契约；非法值有了结构化表达（`null`），消费方可自行决定呈现。
- ✅ `formatBytes` 与 `formatBytesParts` 同源（对账测试锁定：`formatBytes(n) === \`${p.value} ${p.unit}\``）。
- ⚠️ **回潮风险**：新消费方图省事再 `.split(' ')`（因为显示串看起来"正好能拆"）。
- 📌 **违反时的判据**：全仓 grep `formatBytes(` 后接 `.split(` 或 `.replace(`。
  （本次收口后实测：`src/**` 内该形态 **0 处** —— 仅剩 `utils.ts` 注释里的历史记述。）
