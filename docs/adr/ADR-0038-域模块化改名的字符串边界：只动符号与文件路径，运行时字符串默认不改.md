# ADR-0038 · 域模块化改名的字符串边界：只动符号与文件路径，运行时字符串默认不改

- **状态**：生效
- **结论**：改名只动「符号名 + 文件路径」；运行时字符串（存储键、节点类型串、uploads 子目录、URL）默认不改——改键＝存量数据失联，属业务破坏（依据红线「目录名不改，防存量 URL 破链」）。
- **日期**：2026-09-19
- **裁定人**：架构师
- **触发**：—

## 背景

域模块化（把每个域构造成深模块）要求**大规模改名与移位**。计划里引入的命名规范 **N8** 原文写作
「改名两套身份一起改：**符号 + 字符串标识**」—— 该措辞在"节点重命名"场景是对的
（`docs/节点重命名安全操作手册-2026-09-08.md`：节点有符号与运行时字符串标识两套身份，只改一套会运行时断链）。

但它被**外推成通用默认动作**后变得危险：把 `STORAGE_KEYS`／KV 键／`NODE_TYPES`／prefs 键／
`uploads` 子目录／URL 也"一起改" ⇒ **存量数据失联**（旧键读不到 = 用户数据看起来"消失"）。

## 判据（它凭什么成立 / 为什么不成立）

本仓既有红线已有同向判据，且是**物理事实**级：

1. **「目录名不改，防存量 URL 破链」** —— `src/components/base/api/filesApi.ts` 文件头原文。
   存量 URL 存在数据库与磁盘上，改目录名即断链 ⇒ 同理，改键名即断链。
2. **类型层/唯一入口**：键名是 `contracts.ts` 的 `STORAGE_KEYS` / `EVENTS` / `NODE_TYPES` 登记项，
   是**跨版本共享的持久化标识**（不是本次重构的内部符号）⇒ 它属于**对外契约**，不属"结构"。
3. **反证（把"结构与数据"混起来的代价）**：若允许随手改键，则每次重构都要写迁移器/双读，
   这正是本仓明确**禁止**的"为存量做兼容"（7步法 铁律 2）——不与旧数据兼容的前提是**根本不去动它**。

⇒ 结论：**键名不该跟着符号改**；需要独立成批、由用户接受数据重置。

## 决议

**改名/移位只保证「符号名 + 文件路径」两套身份一致；运行时字符串默认不改。**
运行时字符串清单（默认冻结）：`STORAGE_KEYS` / KV 键 · `EVENTS` 事件名 · `NODE_TYPES` 节点类型串 ·
`useNodePrefs` 的 prefs 键 · `UPLOAD_DIRS` uploads 子目录 · 已落盘 URL。

**落点**：
- 计划侧：`docs/DOMAIN-MODULES.md` §5.1 铁律 **F5** + §4 **D19**。
- 操作侧：改名四步法见 `docs/节点重命名安全操作手册-2026-09-08.md`（其 §2 `kind: string_fragment` 规则
  **仅用于"字符串值恰好等于该 token"且该 token 不是运行时键**的情形）。
- 例外通道：确实要改键 ⇒ **单独成批** + 用户显式接受数据重置 + 该批 diff 只含键相关改动。

## 后果

- ✅ 收益：结构重构与持久化契约**解耦** —— 改名不再有"用户数据失联"的风险面；改名批的 diff 可纯由
  「符号 + 路径」解释。
- ⚠️ 代价 / 回潮风险：符号名与键名**长期不一致**（如符号改成 `videoEditorXxx` 而键仍是 `cutia-xxx`）⇒
  读者会误以为"忘了改"；**需在 `contracts.ts` 登记行注明「键名冻结（ADR-0038）」**，否则下一个人会来"顺手统一"。
- 📌 违反时的判据（怎么发现"又回去了"）：

```bash
# ① 改名批的 diff 里出现了键名/事件名/节点类型串变化 ⇒ 违规
git diff -U0 -- src/components/base/core/contracts.ts \
  | grep -nE "^[+-].*(STORAGE_KEYS|EVENTS|NODE_TYPES)" 
# ② uploads 子目录常量被动过
git diff --name-only | grep -E "uploadDirs\.ts$"
# ③ prefs 键与节点类型串同时改（节点重命名手册 §5 第 3 步的对象键规则）
grep -rn "useNodePrefs('" src/components/nodes | head
```
