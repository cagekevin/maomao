# ADR-0050 · 决策门槛的形态：门槛全达 + 择优（排序不再是一条线）

- **状态**：生效
- **结论**：决策留两个观察点（拍板时每选项各带留痕 / 落账时轮次文件 §九），都按三关判：资格筛（红线／既有约定答不出「凭什么成立」即出局）→ 门槛全达（正确性／职责边界／SSOT，任一不过＝停）→ 择优（复杂度须量化）；线性「高者胜」会放开越权。
- **日期**：2026-09-21
- **裁定人**：用户
- **触发**：`ADR-0001` 加档（插入「不越权」）后用户要求审视排序形态（「从架构来说，这个排序合理么，有漏洞吗」）→ 裁定「新写一条 ADR」

## 背景

`ADR-0001` 把判据冲突写成**一条线性序**（高者胜），并被复制到 5 处、3 个版本。实测与取证过程见 `daily/架构日志/26-跨区-决策门槛形态与排序副本收敛-2026-09-21.md`。

**与 `ADR-0001` 的关系（2026-09-21 归位）**：本条**接管其排序段**（排序元素 + 门槛形态 + 决策留痕）；`ADR-0001` 回归单一主题「既有约定不是判据来源」= 本条的第 0 关。**不是 supersede**（`ADR-0001` 本体仍生效），故不用 `取代` 字段，用双向指针。

## 判据（它凭什么成立）

- **与停手规则冲突 ⇒ 不成立**：7 步法底线②「越权就是结构错误，不是风格问题 → **停**」（`.codebuddy/commands/架构师改码7步法.md:19-21`）—— 越权不该被更高层买走。
- **仓内判据本就是合取**：`ADR-0044` §9（复杂度变低 **+** SSOT 变好）· 三铁律（给全 + 只转发 + 不越权）· `ADR-0053`（「用户能做的事不变少」是删的前置关）。
- **「既有约定」不构成判据**（`ADR-0001`）⇒ 只能当资格筛，不能占排序一格。
- **只有子集可机判**：可机判 = 门槛三层的**排列副本数**与**落账凭证**；「该由哪层做 / 复杂度降了没」须人判（`ADR-0052`）。

## 决议

**① 形态（本条为唯一真源）**

| 关 | 内容 | 规则 |
| --- | --- | --- |
| **第 0 关 · 资格筛** | 物理红线（`CLAUDE.md`）；「既有约定」→ 先答「凭什么成立」（`ADR-0001`） | 答不出 ⇒ **出局**，不参与排序 |
| **第 1 关 · 硬门槛** | ① 正确性（含「用户能做的事不变少」，`ADR-0053`）② 职责边界③ SSOT（一份真相、无第二同步点） | **全达才谈下一步；任一不过 ⇒ 停，不许被收益买** |
| **第 2 关 · 择优** | 复杂度（须给改前 / 改后同一项量化）＞ 工期 ＞ 兼容性 | 仅门槛全过后，允许此消彼长 |

- **职责边界（第 1 关②）的口径**：每层只做自己那层的事 —— 生产者给全、消费者只转发、不替别人下结论、不替所有方宣布 / 呈现 / 回收。依据 `CLAUDE.md §5.1` 三铁律③ · `ADR-0036` · `ADR-0053` · `ADR-0004`。
- **复杂度（第 2 关）必须带口径**：给不出"改前 / 改后同一项"的对比 ⇒ 该关视为**未举证**（不是"降了"）。

**② 决策留痕 —— 只留两个"有观察点"的时机**（2026-09-21 用户裁定）

| 时机 | 谁观察 | 要求 |
| --- | --- | --- |
| **请用户拍板时** | **用户本人**（看不到留痕就驳回） | 每个 A/B/C 选项**各带一份留痕**：`正确性`｜`职责边界`｜`复杂度`｜`SSOT` 各一行 + 证据 |
| **本轮落账时** | 轮次文件 + 凭证命令（可机判） | 在 `daily/架构日志/*.md` 的 **§九 决策留痕** 里补上本轮**有取舍的决定**（骨架见 `_template.md` 该节） |

- 只填词（"复杂度降低"而无口径）**不算**留痕；**缺留痕 ⇒ 不许动手 / 不许问**。
- ⚠️ **「每个 A/B/C 选项各带留痕」的前提是"确实存在真备选" —— 备选本身的合法性另判（`ADR-0051`）**：
  **禁把单一结论包装成 A/B/C**（「推荐／能接受／别做」是同一答案的三张脸）。
  顺序是：先按 `ADR-0051` 判「该给结论+代价，还是给代价等价的真备选」⇒ **再**按本表给每个选项配留痕。
  （2026-09-21 补指针：本表原写法把 A/B/C 当默认形态，与 `ADR-0051` 对撞。）
- **不挂「AI 内部每个决定」**：该时机**没有观察点、不可判** ⇒ 是假判据（挂多处必漂）。纯结构动作（改名 / 补类型）在 §九 写一行「无取舍」即可。
- **不能机器判定**（语义对错须人判，`ADR-0052`）⇒ 防线就是上面两个观察点；可机判的只有 ④ 的 1、4 两条。

**③ 副本收敛（排序表全仓只留一份）**：下列各处只写「插入位置 + 指针」：

- `.codebuddy/commands/架构师改码7步法.md:41` 铁律 1
- `.codebuddy/commands/架构师心法.md:44` §4
- `.codebuddy/commands/ADR守护者.md:46` 铁律 4
- `docs/adr/ADR-0044-域内落点的四条边界口径.md:59` §9

**④ SOP（发现违反后怎么做）**

1. **副本（可机判 · 扫描范围 `docs .codebuddy spec`）**：`grep -rnE "正确性.{0,40}职责边界.{0,40}SSOT" docs .codebuddy spec` → 允许的命中只有：**本条**（含 SOP 自指）· `docs/adr/README.md` 的**自动索引块**（同源产物）。
   - **`daily/**` 不在扫描范围**（与 `refs --check` 同款口径）：轮次文件与弯路汇编是**历史快照 / 提取产物**，回改反失真。
   - **算副本的是「判据语句」，不是「列名」**：`grep -rn "不许被收益买" docs .codebuddy spec` 应**只命中本条**；`_template.md` §九 的表头列名属**格式**，允许。
   ⚠️ 两个已实测的坑：① `第 0 关` 不能当判据串（`ADR-0053` 有同名的「目的关」⇒ 假红）；② 只用 `正确性／职责边界／SSOT`（含分隔符）**会漏掉换分隔符写的副本**（实测：模板 §九 表头就漏了）。
2. **留痕**：留痕里缺 `正确性｜职责边界｜复杂度｜SSOT` 任一行（或只填词、无证据）⇒ **退回重判**（不许动手 / 不许问用户）。
3. **买账**：见到「虽然越权（或多一个同步点），但正确性更高 / 复杂度更低，所以做」⇒ 按第 1 关判 **停**。
4. **落账凭证（可机判 · 弱判据 · 非闸）**：节标题 **+ 节后 10 行内 ≥1 个数据行** ——
   `grep -A10 "## 九、决策留痕" daily/架构日志/<本轮>.md | grep -cE '^\| [1-9]'` → 应 **≥ 1**。
   ⚠️ ① 只 `grep "## 九"` **不算**：写个空标题就能过 = 「合法通过成本 < 绕行成本」（`ADR-0016`）；② 它是**弱判据**（占位一行也能过），语义对错仍须人判（`ADR-0052`）。

## 后果

- ✅ 越权 / SSOT 缺口不再能被「正确性更高 / 复杂度更低」买走；既有约定回到筛子；排序只剩一份真源。
- ⚠️ **代价**：门槛全达更贵（三层都要举证）⇒ 留痕必须轻量（一行 + 证据），否则退化成填词。
- ⚠️ **回潮风险**：把门槛写回「一条 5 档线」（"反正意思差不多"）；或把「门槛全达」读成「顺序比较」；或把留痕挂回"每个决定"。
- 📌 **违反时的判据**：见 ④ SOP 1–4 条；其中 1、4 可机判，2、3 人工核对。
