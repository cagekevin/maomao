# ADR-0026 · 幂等的边界：不许替代可判状态，也不许替代唯一键纪律

- **状态**：生效
- **结论**：「反正幂等」不得充当两件事的替代品：① **不许替代可判状态**（有状态位就必须判它）；② **不许替代唯一键纪律**（可能重复触发的写必须带全局唯一键）。**唯一键是纪律，幂等是手段，顺序不可颠倒；两者都要。**
- **日期**：2026-09-18
- **裁定人**：架构师（取证后自定）
- **触发**：TD-01-25（剧本盒资产重复归档）· CONTEXT §三 幂等/去重/唯一键纪律
- **取代**：ADR-0010
- **取代**：ADR-0020

## 背景

**旧约定：「反正幂等，重复到达没关系」—— 把幂等当免死金牌。**

只要写操作「重复执行结果一样」，就认为不必再保证「它只被执行一次」。但这两件事**不等价**：

| | 幂等（结果一致） | 唯一键纪律（只执行一次） |
| --- | --- | --- |
| 保证什么 | 重复执行**最终状态**相同 | **副作用次数**正确 |
| 拦得住重复建任务吗 | ❌ | ✅ |
| 拦得住重复计费吗 | ❌ | ✅ |
| 拦得住 webhook 重放吗 | 部分 | ✅ |

**两个实证**：**A（① 面）** 剧本盒「生成完自动归类进素材库」的旧判据是本会话内存 ref，其正确性论证写在注释里「幂等：后端按 sha1 去重」⇒ `taskStore.done()` 总会广播完成事件 → recover handler 再**盲补**一次 ⇒ 同一资产归档两遍（靠后端 sha1 兜住）。**B（② 面）** 「至少一次」语义的入口（webhook / 重试 / 刷新回填）会重复触发副作用，而每个入口都以为"反正幂等，别人会处理"。

## 判据（它凭什么成立）

**① 面 —— 幂等不构成状态判据的替代：**

- **幂等只承诺"不产生第二份"，不承诺"没多做"** —— 重复调用照付网络往返、落盘、`rescanUploads`、`relocateToFolder`、`emitResourceSent` 的成本；
- **它掩盖"谁是归档真相"**：排查「素材库里少了一张」时，要看生成路径、recover 补库、手动上传三条路，而三条路都不记状态；
- **幂等是后端实现细节**：把"sha1 去重"当**前端正确性判据**，是拿未契约化的跨层行为当依据（换后端/换存储即失效）；
- 且 `imageStatus === 'uploaded'` 这个**状态位本来就存在**，另两条归档路径**都在写它** —— 生成路径与 recover 补库不写 = 同族已写、本处漏改的**部分收口**。

**② 面 —— 幂等不构成唯一键纪律的替代：**

- **"至少一次"是协议事实，不是实现选择**：webhook 投递、HTTP 重试、轮询回填在语义上**都允许重复到达**（ADR-0018 已确立"只有网络错误才能重试"，而重试本身即"至少一次"）⇒ 入口必须**假定会重复**，否则就是把自己的不变量建立在对方的善意上；
- **副作用 ≠ 状态**：`Date.now()` 当幂等键之所以是本仓明令禁止的，是因为**每次调用产生新键** ⇒ 查重永远查不到自己 ⇒ 幂等**结构上失效**。可见**键的来源本身就是判据**（可测：同一逻辑键必须产出同一字符串）；
- **收口判据（Step 3「有几种实现」）**：原先各处各自判重 ⇒ N 份判重逻辑，且**必然漂移**（一份按 URL 判、一份按内容判、一份按时间戳判）。判重是**探测**不是**判据** ⇒ 按 Step 3 强制收口为底层原语。

## 决议

**（一）不许用幂等替代可判状态。**

1. **「已归档素材库」的唯一状态位 = `ScriptBoxAsset.imageStatus === 'uploaded'`**，由**所有**归档路径写入：生成 `settle`（**仅当**本地化真的发生）/ 手动上传 / recover 补库。
2. **补库的判据只认该状态位**（`imageStatus !== 'uploaded'` 才补）；内存 ref 降级为**同会话在途去重**（补库是 fire-and-forget，状态位写入前可能再来一条广播）—— 两把锁管两件事，不是同一真相两份。
3. **生产者给全**：`generationContract.settle` 新增第 4 参 `ctx: { localized: boolean }` —— 「本地化是否真的发生」由契约如实交出；`localize` 抛错/返空必须报 `localized:false`（消费方据此**不**标已归档，禁谎报）。

**（二）可能重复触发的写必须带全局唯一键。** 适用范围：提交生图、落盘、webhook 收结果、事件入库、外部回调。

1. **唯一键来源统一**：`base/idGen.ts` 的 `generateId`，或上游 `task_id` / `thread_id`。**禁止业务各处手写 `Date.now()` 当幂等键**。
2. **落库前先按唯一键查重**：命中即返回**既有结果**，不新建。
3. **判重收口到唯一入口**，**禁止散落各调用方各自判重**。
4. **"至少一次"语义的入口默认按唯一键去重**：webhook / 重试 / 刷新回填。

**落点**：`generationContract.ts`（`settle` 签名 + `localized`）· `scriptBoxEngine.ts`（写状态位）· `useScriptBoxEngine.ts`（recover 判据）· `contracts.ts`（登记）· `useNodeGeneration.ts`（提交 Seam）· `localTool /files/`（落盘入口）。另：项目 R1~R4（存储事件化 / 子图事务 / 防重入 UUID / 统一超时）是本纪律的落地批次。

## Lessons Learned（从被取代的两条学到什么）

1. **同一个词（"幂等"）在两层各被滥用一次，拆成两条反而是错的切法。** ADR-0010 治的是**前端正确性层**（拿跨层行为当前端判据），ADR-0020 治的是**后端副作用层**（拿结果一致当次数正确）。写 0020 时我已写明"与 ADR-0010 是同一族的两个面"—— **既然当时就看出是一族，就该当场合并**，而不是留一句互相引用。教训：**当你在 ADR 里写"与 ADR-XXXX 是同一族的两个面"时，那通常就是"应该只有一条"的信号。**
2. **判据的适用边界（层）不应拆条，应在同一条内分面写。** 合并后反而更完整：反滥用条款（"不许把加唯一键当成不需要幂等实现的理由"）只有在两层同处时才有意义。
3. **被取代的判据保留原文**，因为"曾经把它当两件事"这件事本身对后人有用（提醒别按"前端/后端"这种位置维度切分同一条判据）。

## 后果

- ✅ **同一会话的冗余归档归零**；「已归档」在三条路上**判据唯一**（状态位）；降级（localize 失败）不再被误标为已归档。
- ✅ **重复副作用归零**：webhook 重放、网络重试、刷新回填三个方向都能被唯一键拦住（这是"幂等"本身拦不住的）。
- ✅ 与 `spec/CONTEXT.md §六.B` 的文件域去重真源（`contentId = <alg>:<hex>`）**同源**：「同内容 → 同行」正是唯一键纪律在存储层的实例。
- ⚠️ **代价 / 回潮风险**：后端 sha1 去重**仍保留**（层内合理，继续兜住并发/重放）—— 本约定约束的是**前端的正确性判据**，不是禁止幂等。唯一键要求调用方**知道自己的逻辑身份**（"我这次提交代表哪一次用户意图"），比"随手 `Date.now()`"多一步思考。最可能的回潮：有人图省事又写「反正幂等，补一次也没事」。
- ⚠️ **反滥用**：不许把"加了唯一键"当成**不需要幂等实现**的理由 —— **两者都要**（唯一键拦重复触发，幂等实现拦并发竞态）。**顺序不能颠倒**：唯一键是纪律，幂等是手段。
- 📌 **违反时的判据**（怎么发现"又回去了"）：
  1. 出现「**先调用、再判断要不要做**」的补偿式代码（`needsArchive` 判据被删或绕过）；或某条归档路径**不写** `imageStatus`（多条路必须一致）；或 `settle` 拿到 `ctx.localized` 却恒报 `true`；
  2. `grep -rn "Date.now()"` 出现在**写操作/落库路径**且被当作幂等键；
  3. 同一写操作在 ≥2 个调用方各自判重（判重逻辑份数 ≥2）；
  4. webhook / 重试 / 回填入口**没有唯一键查重**而直接写；
  5. 代码注释或施工理由出现「反正幂等」而**未给出唯一键**。
