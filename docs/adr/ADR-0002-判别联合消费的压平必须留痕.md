# ADR-0002 · 判别联合消费：压平必须留痕

- **状态**：生效
- **结论**：判别联合消费走唯一出口 `tryParseOr`；裸 `r.ok ? v : x` 丢掉 err = 静默吞。**例外**：**探测语义**站点（坏输入与"不是"对调用方同答案）**不套原语**（留痕＝噪音，判非债）
- **日期**：2026-09-18
- **裁定人**：架构师（取证后自定）＋ 用户（"要不要升机器闸"的裁定）
- **触发**：TD-16-49（母体）· TD-16-50（高息）

## 背景

`tryParse` 契约收紧（**TD-16-36**）只改了**生产者**（`T | undefined` → 判别联合 `{ok:true,value} | {ok:false,error}`），
**没同步改消费者** ⇒ **半截收口**：判别联合消除了"不可区分"，却**没有消除"静默"** ——
消费者 `r.ok ? r.value : <空值>` 一压，原始 `err` 就蒸发了。

## 判据（它凭什么成立）

1. **仓内自述的反模式**（`asyncGuard.ts:261`）：「调用方拿到 `{ok:false}` 后**丢弃 err 且不留痕** = 静默吞（code review 必查）」—— 判据不是我编的。
2. **但"压平必留痕"不是对所有站点成立**（实测**非同质**）：
   - `drag-data.ts:64-66` 那条判据的语境是**时间轴拖拽数据**（那里坏 JSON 确＝写入侧 bug）；**横推到全部 12 处属推断、非取证**。
   - **探测语义**站点（"粘贴内容是不是画布 JSON"）里，坏输入与"不是"对调用方答案相同 ⇒ 留痕只会把**正常路径刷成噪音** → **判非债**。

## 决议

1. **唯一出口原语**：`tryParseOr(parser, fallback, { layer, key, toast })`（`src/components/base/core/degrade.ts`）——
   「压平 + 留痕」收口为**一份实现**，调用点各 1 行，禁止再手写裸三元丢掉 `err`。
2. **探测语义站点判非债**，不套原语（留痕＝噪音）。
3. **不加机器闸**（`check:parse-flatten`）：建闸前置评审 6 问中
   **第 2 问不过**（有更根本手段 = 收口原语，手段优先级 3 ＜ 6）、
   **第 6 问不过**（"压平是否携带留痕"不可机器验证 ⇒ 声索靠人解释 = **形态④**，与已删 `check:catch` 同款）。
   与 2026-09-17 用户裁定「删 `check:catch`」同向。
4. **失败必须由生产者发布**（用户裁定）：生产者一次给全（可展示文案 + 原因 + 证据）；**消费者只转发，零自造文案**。

## 后果

- ✅ 真债 4 处改委托；12 处裸三元 → 4 处委托 1 份原语；新增兜底 0。
- ⚠️ **回潮风险**：`tryParse` 仍可被直接消费（`parseSSEChunk` 需要判别联合本身）⇒ 裸三元会回潮；且**没有机器闸**兜底。
- 📌 **违反时的判据**：全仓出现 `r.ok ? … : …`（或 `re.ok &&`）且失败分支**无**留痕调用。
