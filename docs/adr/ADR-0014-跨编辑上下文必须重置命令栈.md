# ADR-0014 · 跨编辑上下文必须重置命令栈

- **状态**：生效
- **结论**：切场景／切作品＝切编辑上下文，必须重置命令栈与选择态；全局单栈无法表达跨上下文撤销，不重置即跨工程数据污染。
- **日期**：2026-09-18
- **裁定人**：架构师
- **触发**：TD-22-32 · TD-22-45 · TD-22-46

## 背景

旧形态：视频剪辑器的 `CommandManager` 是**全局单栈**（`EditorCore` 单例），而 `command.clear` 与 `EditorCore.reset` **全代码零调用**：

- `switchToScene` 不清命令栈与选择；
- 切作品时 `loadProject` 只清 `media + scenes`，`selection / audio / thumbnail` 的清理 API 存在却未调用。

结果：在 B 作品按撤销，会把 A 作品的 `tracks` 快照**写回 B**（跨工程数据污染）；选择残留导致误删、旧音频继续占用。

## 判据（它凭什么成立 / 为什么不成立）

**旧形态不成立。** 判据是物理的、可举反例：

1. **撤销栈的语义是「当前编辑上下文的操作历史」** —— 上下文换了，历史就不再是对这个世界的历史，**重放它必然写错对象**。
2. **全局单栈无法表达跨上下文撤销**（技术判据）：栈里只有「操作序列」，没有「它作用于哪个上下文」的身份证。这不是"要不要补一段清理函数"的问题，而是**栈的粒度定义错了**。
3. **「清理 API 存在却零调用」是典型的地基缺位**（附 A6）：有原语、没有唯一编排点 ⇒ 每个切换路径都靠人记得调 ⇒ 必漏。
4. 用户**能做的事没变**（切场景/切作品本来就存在）⇒ 属结构问题，架构师直接定（铁律④）。

## 决议

**切上下文 = 重置编辑上下文，收口为唯一编排点**（落点 `EvaluatorCore.releaseProjectContext()` · `ScenesManager.switchToScene`）：

1. 新增 **`EditorCore.releaseProjectContext()` 唯一编排点**（原 4 处手写 `media + scenes` 清理合并到此），含 `selection.clearSelection` / `audio.reset` / render 清理。
2. `ScenesManager.switchToScene` **清命令栈 + 清选择**（切场景 = 切编辑上下文）。
3. 「切作品」必须走 `releaseProjectContext()`，**禁止各路径手写清理子集**。

## 后果

- ✅ 收益：跨作品/跨场景撤销串台根除；选择残留误删、旧音频残留一并清掉；「重置编辑上下文」有了唯一入口，新增切换路径零成本继承。
- ⚠️ 代价 / 回潮风险：撤销历史**按上下文隔离**后，用户无法跨场景撤销上一步操作（这是正确行为，但与"全局一个栈"的直觉相反，容易被后人当作"丢失功能的 bug"再改回去）→ 必须保留本 ADR 与 `releaseProjectContext` 头部注释作为依据。
- 📌 违反时的判据（怎么发现「又回去了」）：
  - 新增/改动任何「切换作品或场景」的路径，却不经 `releaseProjectContext()` → 违规；
  - 在 A 上下文撤销后，B 上下文内容发生改变 → 违规（可直接作为回归断言）；
  - `command.clear` / `EditorCore.reset` 重新变成零调用 → 违规。
