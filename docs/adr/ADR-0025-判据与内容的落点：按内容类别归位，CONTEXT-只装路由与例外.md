# ADR-0025 · 判据与内容的落点：按内容类别归位，CONTEXT 只装路由与例外

- **状态**：生效
- **结论**：内容落点由**类别**定（不由「谁先写的」）：判据→ADR；现状拓扑→DATAFLOW；红线→CLAUDE；细节→代码头；流程→SOP；**CONTEXT 只装路由表与例外**——它不装内容，只装内容之间的指向关系。
- **日期**：2026-09-18
- **裁定人**：用户（归位口径）+ 架构师（落点表取证）
- **触发**：①「决策记哪」三处各说一套；② CONTEXT 与 ADR/DATAFLOW 三重重复；③ 机制段「就近写」无落点规则
- **取代**：ADR-0017
- **取代**：ADR-0023
- **取代**：ADR-0024

## 背景

**旧约定：决策/机制内容「就近写」—— 谁先写到就在谁那。** 这条默认从未被写下，但它制造了三重后果（取证明细见区域日志 §一）：

**① 治理元层的 SSOT 第二份**：「决策记哪」这条规则自己有三份 —— `CLAUDE.md:66` 说记 CONTEXT（主场）、`spec/CONTEXT.md:251-253` 说记 CONTEXT 且"允许" ADR（**附庸**）、`docs/adr/README.md §一` 说已裁定判据归 ADR（主场）。

**② CONTEXT 的定位声明自己没有边界**：旧自述「决策地图 —— 只回答 `这个功能放哪 / 该调哪个唯一入口 / 哪些红线不能碰`」，**三个答案都有别的主人** —— 「放哪」确实独有；「该调哪个唯一入口」**DATAFLOW 已在做**（`spec/DATAFLOW.md:357` 已列 `**唯一入口**`）；「哪些红线不能碰」归 `CLAUDE.md §5.1`。⇒ **根因不是 CONTEXT 抄了别人，而是它的定位声明允许它抄** —— "决策地图"把判据、路由、现状、红线全收进来 ⇒ 必然与所有文档重叠。

**③ 可测证据**：`grep -n "adr" spec/CONTEXT.md` 改前只有 **3 处**命中（且全为当日新加）—— 内容重叠却**零交叉引用**。且同一机制在 CONTEXT **内部**就写了两遍（`deriveNodes` 在 `:89` 与 `:272`，**详略不一致**）。

## 判据（它凭什么成立）

**判据一：内容的唯一归属由「内容类别」决定 —— 分类依据全部来自既有文档的自述，不是本 ADR 自造。**

| 内容类别 | 唯一归属 | 依据 |
| --- | --- | --- |
| **判据**（凭什么成立 / 被谁推翻） | `docs/adr/` | ADR README §一/§二 |
| **现状与拓扑**（链路怎么走 / 谁引用谁） | `spec/DATAFLOW.md` | 其 §维护规矩自述「本文件只写当前真相」 |
| **物理红线**（撬不动的契约） | `CLAUDE.md` | §5.1 四条红线 |
| **机制细节**（这个函数怎么用） | **代码文件头 JSDoc** | CONTEXT 自述「代码即知识」 |
| **流程动作**（怎么做） | `.codebuddy/commands/**` | SOP 定义 |

**⇒ CONTEXT 不在上表中** —— 没有哪一类内容**只**属于它。它承担的是"内容之间的**指向关系**"。

**判据二（减法实验）：CONTEXT 全 16 段逐段判定归属，只剩两项在别处找不到承载**（判定表见区域日志 §二）：

- ✅ **按「场景需求」反查的路由表** —— DATAFLOW **按链路组织**，回答"这条链路怎么走"，但**回答不了"我手上这个需求该走哪条路"**。⇒ 这是**唯一**按"用户意图"而非"模块名"组织的内容。
- ✅ **规则适用性的例外** —— 本仓多处"规则说要 A，但这里**不适用**"（`SSE 三件套豁免 httpClient` · `时序敏感处保留手写` · `director3d 不纳入收口` · `contentStore` 的有意裸调）。这些**必须与规则同址**（否则读规则的人不知道有例外），**但不能进 ADR**（ADR 是判据的**判定层**，例外是判据的**适用层**）。

**两项的共同点 —— 都不是内容，而是"内容之间的关系"**：路由是"需求 ↔ 入口"，例外是"规则 ↔ 场景"。⇒ **CONTEXT = 关系地图，不是内容仓库。**

**判据三：为什么"就近写"必然漂移（可测）。** 同一机制两处各写一份后**必然漂移**，本仓实证即 §背景③ 的内部自我拷贝（`CLAUDE.md §5.4·9` 单一规则原则的直接实例）。**判据四（生命周期相反不能同居）：CONTEXT 目标是"越短越不过时" ⇒ 必须删旧；判据恰恰不能删（被推翻的留着才能防后人重提）。**

## 决议

**内容落点由内容类别决定。CONTEXT 只装两样：① 按场景反查的跨模块路由表 ② 规则适用性的例外与边界。**

**四份文档的分工（按「回答什么问题」切）**：`CLAUDE.md` = 红线是什么（物理契约 / 撬不动的红线）· `docs/adr/` = 凭什么这么定、被谁推翻过（判据 + 由来 + 违反判据）· `spec/DATAFLOW.md` = 这条链路怎么走（现状链路图 + 关键边）· **`spec/CONTEXT.md` = 我这一处该走哪条路、哪条规则在这不适用（路由表 + 例外）** · 代码文件头 JSDoc = 这个函数怎么用 · `.codebuddy/commands/**` = 怎么做（流程动作）。各自禁写：CLAUDE 禁可推翻的判据 · ADR 禁实现细节 · DATAFLOW 禁结论 / 判据 / 日期 / 叙事段 · **CONTEXT 禁判据正文 / 模块清单 / fan-in**。

**归位判据（写作前先问，顺序不可颠倒）**：**撬不动** ⇒ `CLAUDE.md` 红线；**撬得动但要有代价** ⇒ `docs/adr/` 判据；**能机器检查** ⇒ 毕业为 fitness function（ADR README §6.3）。

**CONTEXT 目标结构（约 120 行，现 337 行）—— 保留项只有 4 处**：§一A/B 路由表（核心 ①）· §五·五 director3d 边界（核心 ②）· §六A 决策记录渠道（指向本 ADR）· §六B 已收口清单。其余 18 段的**完整处置表见区域日志 §二**（不在本 ADR 写第二份）；要点：§三 各判据段 → **ADR-0011 / 0026 / 0021 / 0018**；§五 各契约段 → **ADR-0009·0012·0013 / `CLAUDE.md §5.4.4` / DATAFLOW §一·§二·§三**；§一·五A 编排 6 区 → **DATAFLOW §六**（删）；§一C 重型重构 SOP → **7 步法**（搬）；§二 横切七块表 → 降级为"场景→入口"索引（删「核心规则」「严禁行为」两列）；§六C/D/E → `daily/`；§六F knip → ADR。以上均**删正文留一行指针**。

**`§六B` 为什么保留极瘦版**：DATAFLOW 是**描述性**的，它**按构造不该承载指令**（其 §维护规矩明令"只写当前真相"）。而"**改前先认领这些唯一入口，别重复收口**"是一条**动作指令** ⇒ 必须由 CONTEXT 承担：DATAFLOW 说"现在是什么"，CONTEXT 说"所以你别再写一个"。

**为什么不需要建闸**：判据要能被机器检查才有意义，而"这段该放哪"**不可机器验证**（需理解语义）⇒ 建闸前置评审第 6 问不过（声索靠人解释 = 形态④）。故本条**以判据 + 落点问句**落地，**不建闸**。

## Lessons Learned（从被取代的三条学到什么）

1. **同一天连写三条讲同一件事的 ADR，是"就事论事"而非"就类别论事"的产物。** ADR-0017 从"决策记哪"出发、0023 从"CONTEXT 定位"出发、0024 从"机制段放哪"出发 —— 三个**入口**，答案却是同一个**落点表**，于是三份表必然重复。**教训：先把"这件事属于哪个类别"想清楚，再决定写几条。**
2. **`add` 的重复检测是字符串全等，挡不住改写措辞的同义条目**（本轮已实测：结论改一个字即绕过）。"是否重复"最终只能由**人**在落笔前判。
3. **被取代的判据不要就地改写**（不可变性）。三条原文保留、只改状态行，读者仍能追到"当初是怎么从三个入口收敛到一张表的"—— 本例是 Superseded（有明确取代者），不是 Deprecated。

## 后果

- ✅ **判据有唯一主场**（`adr.mjs list/search/status` 可点名检索）；**每个内容类别有唯一归属**（落点由类别决定，不由"谁先写"决定）。
- ✅ **CONTEXT 有了不可被替代的位置**：两条判据都能通过"别处有没有"的测试；篇幅与职责恢复匹配（337 → 约 120 行）。
- ✅ **新人路径变清晰**：红线看 CLAUDE → 路由看 CONTEXT → 链路看 DATAFLOW → 挑判据看 ADR。**每份文档都可被独立读完**。
- ⚠️ **一个真实的代价**：CONTEXT 曾兼当"新人先读的那份最全的地图"，删减后**阅读路径变长**。这是**正确的代价** —— 那本地图之所以全，是因为它抄了别人；抄来的部分既不准（会漂移）也无人负责更新。
- ⚠️ **回潮风险**："决策地图"这个定位听起来更好、更全，且写 ADR 比就地写 CONTEXT 麻烦 ⇒ 会有人以"方便查找"为由把内容加回来。防线必须是**可执行的问句**（上方归位判据），而不是"注意别乱加"。
- 📌 **违反时的判据**（怎么发现"又回去了"）：
  1. CONTEXT 出现**判决句**（禁止 / 必须 / 不得）或**判据正文**，而 `adr.mjs search <关键词>` **0 命中**；
  2. 某条判据**只**存在于 CONTEXT 而不在 ADR；或同一条两处各有一份**且内容不同**（= 制造 SSOT 第二份）；
  3. CONTEXT 出现**模块清单 / fan-in / 链路图**（→ 该在 DATAFLOW），或出现"允许 `docs/adr/`"这类**把 ADR 当附庸**的表述；
  4. 新增段落的**组织维度是「模块名」而非「场景需求」或「例外」** ⇒ 方向已经错了；
  5. `wc -l spec/CONTEXT.md` 增长而其"独有内容"未增长；或 `grep -c "adr" spec/CONTEXT.md` 长期不增长；
  6. 某段自述"已删除 / 已收口"却仍占**正文段落**（而非一行指针）。
