# ADR-0052 · 判据的防线形态：六级落点，禁停在文档层

- **状态**：生效
- **结论**：判据必须有防线——按六级落点从上往下取第一个能做的：删／类型层／唯一入口／目录／检查+负例探针／诚实声明「不能」+人工判据。禁停在文档层；第6级才允许，且不许硬凑假 grep。
- **日期**：2026-09-21
- **裁定人**：架构师（取证后自定）
- **触发**：ADR-0041 与 ADR-0046 对撞：0041 给「写明不能+人工判据」的合法出口，0046 四选一里没有它且禁停文档层；两条各自改对，读者同时读仍被迫猜（2026-09-21 合并判定）

## 背景

**旧约定有两条，各自成立，合起来打架：**

| 条 | 原话 | 隐含的出口 |
| --- | --- | --- |
| `ADR-0041` | 每条结构规则先答「能不能机器判定」；能 ⇒ 附检查 + 负例探针 | **不能 ⇒ 写明"不能" + 给人工判据**（合法） |
| `ADR-0046` | 判据落点四选一：删 / 类型层 / 唯一入口 / 目录 | **禁止**以「把文档写详细」结案（四选一里无出口） |

**对撞（2026-09-20 双方各自取证）**：一条语义判据（如「该不该写 ADR」）按 0041 **合规**、按 0046 **违规**。
- `ADR-0041:39` M1 自记：原句「写不出 ⇒ 该规则不成立」是**绝对句**，「与 ADR-0046 自认『本项没有机器防线、且硬凑的 grep 更坏』**直接对撞**」⇒ 已自行收窄。
- `ADR-0046:61` 自认：「本条第 3 项**没有机器防线**」。

**它们当初为什么各自这么定**：0041 从「闸/规则」入口问（绿有两种成因：真合规 vs 没被检查到，须负例探针区分）；
0046 从「AI 会不会猜」入口问（判据里出现「视场景/必要时」即违规）。**两个入口，同一张落点表** —— 这就是按发现入口切而非按内容类别切。

## 判据（它凭什么成立 / 为什么不成立）

**一句话：违背这条判据的代码，写得出来吗？**

- 写不出来 ⇒ 已守住（第 1–4 级）。
- 写得出来但能被发现 ⇒ 有防线（第 5 级）。
- 写得出来且发现不了 ⇒ 只许诚实声明，不许假装（第 6 级）。

**凭什么成立**：这是**可证伪的事实判断**（能不能写出来 / 会不会变红），不依赖「判据说得对不对」的主观评价。
**反证（绝对句不成立）**：0041 原句「写不出 ⇒ 该规则不成立」按字面会让现行集里 ≥9 条语义判据（0025 内容落点、0046 让 AI 不猜等）全部"不成立"。
⇒ 凡绝对句，先列出按它应当出局的条目；若列出的都是最有价值的判据 ⇒ **错的是绝对句自己**。

## 决议

**六级落点表（本条为唯一真源）—— 从上往下取「第一个能做」的：**

| 级 | 落点 | 手段 | 判定（怎么知道守住了） |
| --- | --- | --- | --- |
| **1** | **删** | 该能力/开关零生产消费 ⇒ 删掉 | 结构上不可能用 |
| **2** | **类型层** | 必填参数 / 字段移出类型 / 判别联合 | 写不出来（`tsc` 即探针） |
| **3** | **唯一入口** | 收口成一个函数，外部拿不到底层 | 绕不过去 |
| **4** | **目录** | 判据本就是「文件在哪」⇒ 直接写出目录名 | 可机械判定 |
| **5** | **检查 + 负例探针** | grep / 脚本 / 闸；造一个违规验它真会红 | 能发现 |
| **6** | **诚实声明** | 写明「不能机器判定」+ 给人工判据与落点 | **不许硬凑假 grep** |

- **禁止停在文档层** —— 第 6 级是唯一例外，且**必须写明"不能"**。**五个改造信号**（命中任一 ⇒ 该判据要改造）：① 两条路看起来都对 ② 量词模糊（必要时／视场景／通常／原则上）③ 只写禁止、不写替代 ④ 可选开关零生产调用方显式传值 ⑤ 判据写在读者不会打开的文件里。
- **沿用 `ADR-0041` 的 M2–M6**（原样并入，不重写）：**M2** 闸绿不算证据 —— 负例探针证它会红（造违规 → 变红 → 撤销 → 回绿）·
  **M3** 验收行禁止写「跑 X ✅」当结论 —— 须写判定命令 + 期望输出并真跑贴结果 · **M4** 搬迁类规则要写前置条件（搬前判，
  不是搬完才判）· **M5** 计数 / 清单类断言必须机器复算 · **M6** 检查命令本身也要先自检。
- **判据写在读者一定会打开的那个文件头**（原 `ADR-0046` §决议 3）：判断「画布写走哪条」的人会打开 `agentCanvasHost.ts`
  ⇒ 判据表就放那里，不藏在 DATAFLOW。**边界 —— 不授权放宽闸**：要改的是**规则的表述与前置条件**，不是把闸调松（`ADR-0016`「收窄不放宽」）。

## 后果

- ✅ **收益**：违背判据的代码**写不出来**（1–4 级）或**能被发现**（5 级），而非"写了但被劝"；0041/0046 的对撞消失，同一件事只剩一张表。
- ⚠️ **代价 / 回潮风险**：类型层改造会破坏调用方签名（`timeoutMs` 必填本次补 43 处）；为免改动而保留可选参数 ⇒ 本条被架空。计数类断言改一次表就过期 ⇒ M5 强制复算。
- 📌 **违反时的判据（怎么发现"又回去了"）**：
  1. **新增可选开关零生产调用方传值** ⇒ `grep -rn "<参数名>" src` 只命中定义处（+ 自己的测试）即违规（处置：删）。
  2. **字段本应不可达却可读** ⇒ 误用 `tsc` 应报「属性不存在」；能通过 ⇒ 失守。
  3. **判据写成需推断的说法**（"AI 侧 / 人工侧"而非目录名）⇒ 人工 review 判，**无机器判据**。
  4. **只写「跑 X ✅」无期望输出**（M3）⇒ `grep -rn "验收.*check:arch ✅" docs/plan/`。
- ⚠️ **诚实边界**：第 3 项**没有机器防线** —— 它靠 review + 落点示例（`agentCanvasHost.ts`）示范。不假装有闸：硬凑的 grep 会把"说这条规矩的句子"自己也抓进去（假防线比无防线更坏）。

## Lessons Learned

- **两条 ADR 各自改对，不等于同一件事只有一个答案。** 0041 收窄、0046 加诚实边界，都是**正确的补丁**；但补丁只能让两条各自自洽，读者同时打开两条仍被迫猜。⇒ **对撞的两条不能靠互打补丁解决，只能合并。**
- **绝对句会反向淘汰最有价值的判据。** 「写不出检查 ⇒ 该规则不成立」按字面淘汰的全是语义判据 —— 而语义判据恰恰是最该留的。处置是**收窄 + 给合法出口**，不是删掉规则。
- **落点的价值排序是「结构上不可能」>「能被发现」。** 0046 比 0041 强，因为它要求前者。合并时取强者为干，弱者的条款降级为其子集（第 5、6 级），**不是并列**。

## 落点

- **判据本体**：本条（取代 `ADR-0041` / `ADR-0046`）。**相邻判据**：归属 = `ADR-0040`；命名 / 门面 = `ADR-0039`。
- **三级示例（本条首次落实处）**：`agent/canvas/agentCanvasHost.ts`（画布写判据 = 目录，第 4 级）· `generate/lib/generationOrchestration.ts`（删零消费开关 `saveToTasks`，第 1 级）· `base/utils/genErrors.ts`（`retryable` 移出 `ClassifiedError`，第 2 级）。
- **与 `ADR-0016` 的边界**：那条管「闸不许凌驾正确性 / 不许为过闸而重复」；本条管「判据的防线落在哪一级」。本条是它在落点上的具体化，**不重复那条**。
