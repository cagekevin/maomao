# ADR-0015 · 批量操作的入栈粒度由场景定，禁循环单条入栈

- **状态**：生效
- **结论**：批量操作入栈粒度收口为 executeBatch(0=不入栈／1=直用／N=BatchCommand)；一次用户意图＝一次撤销，禁循环调用单条命令。
- **日期**：2026-09-18
- **裁定人**：架构师
- **触发**：TD-22-51（转场批量应用循环入栈 N 条）

## 背景

旧形态：`applyTransitionToAdjacentPairs` 在 UI 层循环调用单条 `addTransition` ⇒ 用户**一次点击**入栈 **N 条**命令，**撤销要按 N 次**；且批量判据（"要不要入栈、入几条"）散在 UI 层。

## 判据（它凭什么成立 / 为什么不成立）

**旧形态不成立。** 判据是「**一次用户意图 = 一次撤销**」这条可举反例的物理判据：

- 撤销栈的粒度应对齐**用户的意图单元**，不是内部实现的循环次数。用户点一次「批量加转场」，心里是一个动作。
- 「循环调 N 次单条」把**批量判据**留在了 UI 层 —— 判据归实现方，不归调用方（铁律②）。
- `TimelineManager` 与 `hooks` 两侧各写一套"怎么算批量"⇒ SSOT 第二份（M3）。

## 决议

**入栈粒度收口为唯一原语 `CommandManager.executeBatch`，批量判据下沉**（落点 `engine/commands/CommandManager.ts` · `TimelineManager.updateElements` · `use-editor-actions` · 转场批量应用）：

1. 新增 **`CommandManager.executeBatch`**：**0 = 不入栈 / 1 = 直用单条 / N = BatchCommand**（三分支即唯一判据）。
2. `TimelineManager.updateElements` 与 `use-editor-actions`(freeze frame) 改委托。
3. 转场批量应用**从 UI 层下沉为** `TimelineManager.addTransitionsToAdjacentPairs`，命令构造经 `buildAddTransitionCommand` 单点；`transitions.tsx` 只表达意图 + 报结果。
4. 加注释「**不重造第二个 executeBatch**」。

## 后果

- ✅ 收益：一次用户意图 = 一次撤销（3 片段 = 2 邻接对 → 整批一条 → 撤销一次全回）；批量判据收口一份；UI 层不再持有批量逻辑。
- ⚠️ 代价 / 回潮风险：`executeBatch` 成为命令入栈的**必经判据** —— 日后新增批量操作若直接循环调单条命令，会静默退回 N 次撤销（无机器守卫，需靠 `buildAddTransitionCommand` 这类单点与注释拦）。
- 📌 违反时的判据（怎么发现「又回去了」）：
  - 新增批量操作直接 `for (...) { cmdManager.execute(...) }` → 违规（一次点击撤销 N 次即是症状）；
  - 同一"批量入栈"判据在两处以上各写一份 → 违规；
  - 出现第二个 `executeBatch` 类原语 → 违规。
