# ADR-0063 · 零消费等于 export 与实际消费位置不匹配：先定位本该消费它的地方

- **状态**：生效
- **结论**：零消费不是「没人用」，而是 export 面与实际该消费它的位置不匹配。诊断只有一个动作：先定位本该消费它的地方，看那里现在是什么（空／内联第二份／漏接／边界外／词汇表），据此决定删、摘 export、接上或豁免。
- **日期**：2026-09-24
- **裁定人**：架构师（取证后自定）
- **触发**：抠图接入收尾时对 4 个 `check:dead-code` 报零的导出做审计，发现它们**不是同一种东西**：`normalizeInto`（内联处有第二份真相）· `toModelCoords`/`toPromptPoint`（有调用点但传了未被使用的参数 ⇒ 接线断在半路）· `MATTING_EMBEDDING_SHAPE`（声称守契约、实际无人读的**假守卫**）· `MattingSourceImage.scale`（真的谁也用不上）。同一条「零消费」标签下藏着四种处置，而处置方向**互相冲突**（该删 vs 该接）。

## 背景

旧约定**只有一句**：`ADR-0030` 的读法「零生产消费 ⇒ 幽灵预留 ⇒ 删」。它被写成一条**结论**，没有配「怎么判它属于哪一类」的前置动作。`ADR-0053` 后来补了「**怎么删**」（四关 + 时机 + 词汇表豁免），但同样**没回答「零消费是什么」**。

于是每次闸报零，动作只剩一个：删。而本次 4 个导出的审计证明这个动作会**犯两个方向的错**：

- **删错方向（把该接的删了）**：`normalizeInto` 被内联处硬编码的 `MEAN`/`STD` 取代 —— 删掉它，第二份真相就永久合法化，「同一语义只允许一种实现」当场破功。**正确动作是接上，不是删。**
- **留错方向（把伪装留着）**：`MATTING_EMBEDDING_SHAPE` 在**没人读**的情况下仍自称「守 embedding 契约」。单看"零消费即删"它该删，但**真正的病**是它骗过了所有人（读的人以为有人守）。

⇒ 病根不是"它没人用"，是**它的 export 面与它实际该被消费的位置对不上**。同一个报零信号，对应**六种**不同的位置关系。**诊断的第一步永远是：找到"本该消费它的地方"，看那里现在是什么。**

## 判据（它凭什么成立 / 为什么不成立）

判据成立的依据是**本仓可实证的四次审计**（`docs/plan/148 §十二`），不是推演：

- **六类落点各不相同，且已各有处置实证**（详见 §决议 表）：
  - `normalizeInto`：`mattingEngine.ts` 内联处写出了同一套 `MEAN/STD` ⇒ 位置不空，**已有第二份** ⇒ 接上（删掉内联那份）。
  - `toModelCoords`/`toPromptPoint`：调用点存在，但实参**传了函数体从不使用的参数** ⇒ 位置不空但**接线断在半路** ⇒ 接上；删掉即等于承认"接了但没通"是终态。
  - `MATTING_EMBEDDING_SHAPE`：无人读 ⇒ 位置**真空**，但它的注释声称守契约 ⇒ 它属于**假守卫**，不是普通幽灵预留。**必须靠负例探针**（改坏它、看闸红不红）才能证明它"空"。
  - `MattingSourceImage.scale`：无人读、也无"本该读它的地方" ⇒ 真幽灵预留 ⇒ 删。
  - 类型别名（如编辑器 Props 类型）：**同文件内自用**，只是 `export` 面过宽 ⇒ **摘 `export`**，不是删。
  - 词族（表达层）：缺档 ⇒ 豁免（`ADR-0053` ①-b）。
- **为什么不能只用 ADR 守（诚实边界）**：其中**"假守卫"可机器判**（负例探针强制变红即证），**"内联有第二份"可机器判**（`check:catch` 族 / 死代码闸），但**"位置是空的 / 是第二份 / 在边界外"结构上不可判** —— 没有任何闸会红。故本条与 `ADR-0062` 同款：**靠"下一个 AI 读到它先去找那个位置"起效**，不以闸为主防线。
- **为什么与 `ADR-0053` 不是同一条**：本条管「**零消费是什么**（该不该被消费、该在哪被消费）」，0053 管「**怎么删**（四关 / 时机 / 词汇表豁免）」。两者是同一族的两级，但**不互抄**（0053 头部曾把 0047 两关抄回自己，方向反了 —— 那是反面教材，本条不复制该形态）。

## 决议

**零消费的诊断，先定位「本该消费它的地方」，再看那里现在是什么。** 六类落点与处置：

| # | 本该消费处现在是什么 | 类型 | 处置 |
|---|---|---|---|
| ① | **空**，且谁也用不上 | 幽灵预留 | **删** |
| ② | **空**，但**同一文件内自用**（含组件导出的 Props 类型） | 导出面过宽 | **摘掉 `export`**（不删） |
| ③ | 不空，同段逻辑**已存在第二份**（内联实现） | 被内联取代 | **接上**，删掉内联那份 |
| ④ | 不空，**有调用点但漏接**（如传了函数体不使用的参数） | 接线未完成 | **接上**（补上缺失参数与链路） |
| ⑤ | **消费在 knip 边界外**（生成物的消费者 / 宿主 / 外部宿主） | 跨边界 | **标注豁免**（`knip.json` 或注释写明消费方） |
| ⑥ | **表达层缺档**（同一文件内的语义词族） | 设计词汇表 | **豁免**（`ADR-0053` ①-b，仅表表达层） |

**横切警示 —— 假守卫**（`MATTING_EMBEDDING_SHAPE` 型）：**声称守契约、实际无人读**。它是第 ① 类（空）的**伪装**：单看报零与幽灵预订无异，但它会**骗过所有读它的人**（"有人守着呢"）。识别动作唯一：**写一个负例探针**（故意改坏它），看闸是否变红；不红 ⇒ 它就是空的，按 ① 处置并**销掉那条契约声明**。本条不做新的守卫机制，只要求**凡"守卫"必须能被负例探针证明会红**（`ADR-0041`）。

**落点**：

- **判据本体**：本条。
- **诊断动作**：`.codebuddy/commands/架构师改码7步法.md` Step 6 顶部「删的前置动作」—— 在"四关"之前插一步「**先定位本该消费它的地方**」。
- **闸 / 探针**：`npm run check:dead-code`（报零后走本条诊断，禁止直接 `--update-baseline`，见 `ADR-0053` ⑤）；假守卫用一次负例探针（改坏 → 看红 → 回退）取证。
- **实证留痕**：`docs/plan/148` §十二（4 个导出的审计 = 六类落点中 4 类的现场）。
- **与 `ADR-0053`**：本条定"是什么"，0053 定"怎么删"。冲突时以 0053 的四关为准（它是动作关），本条提供其输入。
- **与 `ADR-0042` / `ADR-0045`**：`toModelCoords`/`toPromptPoint` 型的处置**默认是"接上"而非"删掉内联那份"** —— 先按 0042/0045 判哪一份是正确形态（见 0053 落点同款口径）。

## 后果

- ✅ **收益**：把「零消费 ⇒ 删」这个**单动作**拆成**先定位、再分类、后处置**；本次直接避免了两类反向错误（删掉 `normalizeInto` 放任第二份真相、留着假守卫继续骗人）；`MattingEditor` 的消费面从 14 符号收敛到 6 符号，且**每一处收敛都有落点依据**，不是"看着多余就删"。
- ⚠️ **代价 / 回潮风险**：
  - **分类靠人**：六类中只有"假守卫"和"内联第二份"可机器判，其余四类要人工看"本该消费处"。**反风险** = 未做诊断就删，等于退回单动作（那正是本条要禁止的）。
  - **"接上"被滥用**：把真幽灵预留也说成"位置不空 / 将来会接"，从而保留死代码。**反风险** = ③④ 两类**必须指得出具体的那个调用点 / 那份内联实现**（文件:行），指不出 ⇒ 归 ① 删。
  - **假守卫不探针**：声称"我会守契约"但从不改坏试一次 ⇒ 与 `MATTING_EMBEDDING_SHAPE` 同病。
- 📌 **违反时的判据**（怎么发现"又回去了"）：
  1. 闸报零消费后**未给出"本该消费位置"的定位**就删 / 就 `--update-baseline` ⇒ 违规（退回单动作）。
  2. 称某导出属 ③④（该接上）却**指不出具体的调用点或内联第二份**（文件:行）⇒ 违规（滥用"接上"）。
  3. 某文件内自用的工具**为消除报零而整条删除**，而它的同文件消费者仍在 ⇒ 违规（应摘 `export`，第 ② 类）。
  4. 某符号自称"守卫 / 契约"却**答不出负例探针结果**（改坏了会不会红）⇒ 疑似假守卫。
  5. 把 knip 边界外的消费者当成"没人用"⇒ 违规（应标注豁免，第 ⑤ 类）。
  ⚠️ **诚实边界**：可机判的只有第 3 条（删了而消费者仍在 ⇒ 编译/类型红）。1、2、4、5 须人工核对（`ADR-0052` 第 6 级：写明"不能"，不许硬凑 grep）。

## Lessons Learned

- **"零消费"是一个症状，不是一个诊断。** 同一个报零信号背后是六种完全不同的位置关系；把症状当诊断，处置方向必然随机（本次差点反向删掉 `normalizeInto`）。
- **假守卫是最贵的空**：幽灵预留只是白占维护面，假守卫让人**以为有人守着**，从而永久放弃真正的守卫。**所有"守卫"都要能被负例探针证明会红。**
- **`export` 面过宽 ≠ 死代码**：一个符号在本文件内被用了十次、只在文件外零消费，正确动作是**摘 `export`** 而不是删符号。删掉它是在砍内部实现。
- **"接上"必须有收据**：能说"该接上"却指不出那个调用点，等于说"我不确定但我想留着"——与幽灵预留是一回事。
