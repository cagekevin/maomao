# ADR-0020 · 幂等不许当唯一键纪律的替代：可能重复触发的写必须带全局唯一键

- **状态**：已取代
- **结论**：任何可能重复触发的写（提交生图/落盘/webhook/事件入库/外部回调）必须带全局唯一键并幂等落库；唯一键来源统一，禁止各处手写 Date.now()，判重收口到唯一入口。
- **日期**：2026-09-18
- **裁定人**：架构师
- **触发**：spec/CONTEXT.md §三 幂等/去重/唯一键纪律（P0 全局收口红线）—— 判据只写 CONTEXT，无 ADR 承载

## 背景

**旧约定：「反正幂等，重复到达没关系」——用幂等实现的存在，替代唯一键纪律的执行。**

「幂等」这个词在本仓被当成**免死金牌**：只要写操作「重复执行结果一样」，就不必再保证「它只被执行一次」。但这两件事**不等价**：

| | 幂等（结果一致） | 唯一键纪律（只执行一次） |
| --- | --- | --- |
| 保证什么 | 重复执行**最终状态**相同 | **副作用次数**正确 |
| 拦得住重复建任务吗 | ❌ | ✅ |
| 拦得住重复计费吗 | ❌ | ✅ |
| 拦得住 webhook 重放吗 | 部分 | ✅ |

⇒ 把两者混为一谈的代价：**「至少一次」语义的入口（webhook / 重试 / 刷新回填）会重复触发副作用**，而每个入口都以为"反正幂等，别人会处理"。

与 ADR-0010 是**同一族的两个面**：ADR-0010 说的是"**有可判状态就不许用幂等替代判断**"（前端正确性层），本 ADR 说的是"**可能重复触发的写必须带唯一键**"（后端副作用层）。

## 判据（它凭什么成立）

1. **"至少一次"是协议事实，不是实现选择**：webhook 投递、HTTP 重试、轮询回填在语义上**都允许重复到达**（ADR-0018 已确立"只有网络错误才能重试"，而重试本身即"至少一次"）。⇒ 入口必须**假定会重复**，否则就是把自己的不变量建立在对方的善意上。
2. **副作用 ≠ 状态**：`Date.now()` 当幂等键之所以是本仓明令禁止的，是因为**每次调用产生新键** ⇒ 查重永远查不到自己 ⇒ 幂等**结构上失效**。可见键的来源本身就是判据（可测：同一逻辑键必须产出同一字符串）。
3. **收口判据（Step 3「有几种实现」）**：原先各处各自判重 ⇒ N 份判重逻辑，且**必然漂移**（一份按 URL 判、一份按内容判、一份按时间戳判）。判重是**探测**不是**判据** ⇒ 按 Step 3 强制收口为底层原语。

## 决议

**任何"可能重复触发"的写操作必须带全局唯一键并幂等落库**（提交生图、落盘、webhook 收结果、事件入库、外部回调）：

1. **唯一键来源统一**：`base/idGen.ts` 的 `generateId`，或上游 `task_id` / `thread_id`。**禁止业务各处手写 `Date.now()` 当幂等键**（它每次都产出新键 ⇒ 查重形同不存在）。
2. **落库前先按唯一键查重**：命中即返回**既有结果**，不新建。
3. **判重收口到唯一入口**（`useNodeGeneration` 提交 Seam、localTool `/files/` 落盘），**禁止散落各调用方各自判重**。
4. **"至少一次"语义的入口默认按唯一键去重**：webhook / 重试 / 刷新回填。

**落点**：

- 契约登记：`contracts.ts`（`STORAGE_KEYS` / `apiRegistry`）；
- 前端提交 Seam：`src/hooks/useNodeGeneration.ts`；
- 后端落盘入口：`localTool` `/files/`（`writeUploadDedup` + `contentId`，见 `spec/CONTEXT.md §六.B` 文件域去重条目）；
- 方法论：项目 R1~R4（存储事件化 / 子图事务 / 防重入 UUID / 统一超时）即本纪律的落地批次。

## 后果

- ✅ **重复副作用归零**：webhook 重放、网络重试、刷新回填三个方向都能被唯一键拦住（这是"幂等"本身拦不住的）。
- ✅ 与 `spec/CONTEXT.md §六.B` 的文件域去重真源（`contentId = <alg>:<hex>`）**同源**：「同内容 → 同行」正是唯一键纪律在存储层的实例。
- ⚠️ **代价 / 回潮风险**：唯一键要求**调用方知道自己的逻辑身份**（"我这次提交代表哪一次用户意图"）—— 比"随手 `Date.now()`"多一步思考。回潮动因 = 有人图省事又写 `Date.now()`。
- ⚠️ **反滥用**：不许把"加了唯一键"当成**不需要幂等实现**的理由 —— 两者都要（唯一键拦重复触发，幂等实现拦并发竞态）。**顺序不能颠倒**：唯一键是纪律，幂等是手段。
- 📌 **违反时的判据**（怎么发现"又回去了"）：
  1. `grep -rn "Date.now()"` 出现在**写操作/落库路径**且被当作幂等键；
  2. 同一写操作在 ≥2 个调用方各自判重（判重逻辑份数 ≥2）；
  3. webhook / 重试 / 回填入口**没有唯一键查重**而直接写；
  4. 代码注释或施工理由出现「反正幂等」而**未给出唯一键**。
- **被取代于**：ADR-0026
- **毕业去向**：合并入 ADR-0026：幂等两面的完整判据在同一条
