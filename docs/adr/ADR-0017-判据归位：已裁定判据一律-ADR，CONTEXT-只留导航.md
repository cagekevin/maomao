# ADR-0017 · 判据归位：已裁定判据一律 ADR，CONTEXT 只留导航

- **状态**：已取代
- **结论**：已裁定的判据（含推翻既有约定/用户裁定/处置口径）一律落 docs/adr/，禁止只写 CONTEXT；CONTEXT 只留导航与仍有效的红线；SOP 只留流程动作。
- **日期**：2026-09-18
- **裁定人**：用户
- **触发**：CLAUDE.md:60-74 决策记录铁律 与 docs/adr/README.md §一 边界表 各说一套（CONTEXT vs ADR）

## 背景

**旧约定：已裁定的判据写 `spec/CONTEXT.md`，`docs/adr/` 只是"允许"的补充。**

三处文档各说一套（`grep` 实证）：

| 落点 | 原文 | 口径 |
| --- | --- | --- |
| `CLAUDE.md:66` 决策记录铁律 | 横跨 ≥2 处 / 全库级决策 → 记 **`spec/CONTEXT.md`** | **CONTEXT 是主场** |
| `spec/CONTEXT.md:251-253` | 记 CONTEXT，且"允许 `docs/adr/` 轻量决策记录" | **ADR 是附庸**（"允许"= 非必选） |
| `docs/adr/README.md §一` | 已裁定的判据 → **`docs/adr/`** | **ADR 是主场** |

⇒ **同一件事（决策记哪）在三处有三个口径** —— 这本身就是 **M3 SSOT 第二份**，而且是**治理元层**的第二份（错的是"规则该写哪"这条规则）。

它当初为什么这么定：CONTEXT 是"写码前必读唯一入口"，把决策就地记在旁边最省事、最容易被下一个 AI 读到。但代价在 2026-09-17~18 暴露 —— `catch-ok` 机制被用户裁定删除后，判据只活在不同文档的不同段落里，**没有一处能回答"这条判据还在不在、被谁推翻过"**。

## 判据（它凭什么成立 / 为什么不成立）

**旧约定不成立。** 判据来自**文档的可检索性与不可变性**：

1. **CONTEXT 是可变的现状描述，ADR 是不可变的判据历史**。CONTEXT 的设计目标是"越短越不过时"（其 §六.A 保鲜机制③自述），所以它必须**删旧**；判据恰恰**不能删** —— 被推翻的判据留着才能防后人重提（ADR README §二 第 4 类「被否决的方案」）。**两种生命周期相反的东西不能同居一个载体。**
2. **可检索性实测**：`adr.mjs` 提供 `list/search/show/status/audit` + 索引自动生成 + 状态机（含`已取代`/`已毕业`）；CONTEXT 是**自由 markdown**，无索引、无状态、无「这条被谁取代」的连线。**判据要能被"点名检索"，CONTEXT 结构上做不到。**
3. **ADR README §二 第 2 类**已把"确立一条新约定（含治理判据）"列为**必须写 ADR**，而"决策记哪"正是一条治理判据 ⇒ 按现有规则它本就该有 ADR，只是从没写。
4. 反向确认**不成立的理由**：若维持二选一的另一边（判据只写 CONTEXT），则 ADR README 整份失效（它 §二 的四个必写条件都指向"判据进 ADR"）—— 两套规则打架，必删一个（`CLAUDE.md §5.4·9` 单一规则原则）。

## 决议

**已裁定的判据一律落 `docs/adr/`，禁止只写 CONTEXT。**

**归位判据（写作前先问，顺序不可颠倒）：**

| 判据 | 问 | 落点 |
| --- | --- | --- |
| **撬得动吗** | 撬不动（端口 / 对外契约 / 登记表 / 物理不变量） | **`CLAUDE.md`** 红线 |
| **撬得动吗** | 撬得动但**要有代价**（tradeoff、可被正确性证据推翻） | **`docs/adr/`** 判据 |
| **能不能自动查** | 能机器检查 → **毕业为 fitness function**（ADR README §6.3） | 手段序 1–4 的载体 |

**分工（不是"二选一"里的可选，是职责不同）：**

- **`docs/adr/`** = **判据**（裁定 + 由来 + 违反判据 + 被谁取代）。**唯一主场**。
- **`CLAUDE.md`** = **物理红线**（撬不动）+ 判据的**一行索引**。
- **`spec/CONTEXT.md`** = **导航与仍有效的红线**（"这个功能放哪 / 该调哪个唯一入口"）+ 当前机制现状。**不再承担判据存储**。
- **SOP**（`.codebuddy/commands/**`）= **流程动作**（怎么做，非判据本身）。

**落点**（本次回改，A7）：

- `spec/CONTEXT.md:251-253` §六.A → 三档表按上文重写，删除"允许 `docs/adr/`"的附庸表述
- `CLAUDE.md:60-74` 决策记录铁律 → 表中两处补 ADR，并加"已裁定判据走 ADR"一行
- `.codebuddy/commands/架构师改码7步法.md` Step 7 → 新增 CONTEXT 维护动作（回改原文）

## 后果

- ✅ **判据有唯一主场**：`adr.mjs list/search/status` 可点名检索，能回答"这条判据还在不在、被谁推翻过"。
- ✅ **CONTEXT 回到本职**：只留导航 + 仍有效红线，其 §六.A 自述的"越短越不过时"才可能成立。
- ⚠️ **代价 / 回潮风险**：**写 ADR 比就地写 CONTEXT 麻烦**（要走 CLI、要写 4 个段、要过 Review Checklist）⇒ 施工时"顺手记在 CONTEXT"是最省力的路。这正是本 ADR 要治的行为，故**判据必须写成可执行的问句**（同上表），而不是"应该写 ADR"。
- ⚠️ **与 `CONTEXT.md §六.B`「已收口」清单的关系**：那份清单是**当前架构事实**（有边界、有唯一入口实现），**不是判据** —— 它**留在 CONTEXT**，不搬。判据与现状是两件事，别把清单也搬走。
- 📌 **违反时的判据**（怎么发现"又回去了"）：
  1. `grep` 到某条判据**只**存在于 `spec/CONTEXT.md`，且 `adr.mjs search <关键词>` 0 命中；
  2. `CLAUDE.md` 或 CONTEXT 出现"允许 `docs/adr/`"这类**把 ADR 当附庸**的表述；
  3. 同一条判据在 CONTEXT 与 ADR 各有一份而内容不同（= 制造 SSOT 第二份）。
- **被取代于**：ADR-0025
- **毕业去向**：合并入 ADR-0025（与 ADR-0023 / ADR-0024 同为「内容落点」一事的三面）
