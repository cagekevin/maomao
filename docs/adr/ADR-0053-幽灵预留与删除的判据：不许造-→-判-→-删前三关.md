# ADR-0053 · 幽灵预留与删除的判据：不许造 → 判 → 删前三关

- **状态**：生效
- **结论**：删只在这条线上走：不许为设想的消费方铺路 → 多口径一致报零即假接缝 → 删前过三关（目的：复杂度降在哪一项／能力：用户能做的事不许变少／消费：四口径查清）。查不清 ⇒ 改为修，不许删。
- **日期**：2026-09-21
- **裁定人**：架构师（取证后自定）
- **触发**：ADR-0030 与 ADR-0047 是「什么情况可以删」被切成两条：0047 第二关「多口径报零」即 0030 本体判据，且 0030:8 已把 0047 两关抄回（反向补丁）；另 move-dir（用户能用的命令）被按「删>改」整条删除 = 砍功能

## 背景

**旧约定一（造的侧）**：本仓"为将来铺路的零消费实现"极多 ⇒ 立 `ADR-0030`：零生产消费 = 假接缝（幽灵预留），处置是删。
**旧约定二（删的侧）**：7 步法把「删」写成**首选手法且不带前提**（Step 6「删比改便宜」· 心法 §③「能删 > 能收敛 > 能下沉」）。

**两条各自都缺一块，于是互相补**：
- `ADR-0030` 只写「零消费 ⇒ 删」，**没写能力关** ⇒ `move-dir`（一条**用户能用的命令**：搬整目录 + 一键回退）被按「删 > 改」整条删除 = **砍功能**，用户未被问过（TD-17-27）⇒ 补立 `ADR-0047`。
- `ADR-0047` 的第二关「多口径一致报零」**就是 0030 的本体判据** ⇒ `ADR-0030:8` 头部又把 0047 的两关**抄回**（**反向补丁**）。

⇒ **同一件事「什么情况可以删」被切成两条、靠互抄维持一致** —— 这不是两份互补判据，是**一条线被切成两截**。

## 判据（它凭什么成立 / 为什么不成立）

**第 0 关 · 目的关（最先过）：删了它，能解决什么问题？系统整体复杂度下降在哪一项？**

- 答不出「解决什么问题」或答不出「下降在哪一项」⇒ **不删**。
- **反例（2026-09-20 实证）**：按 `ADR-0044` §3 删掉 `videoEditor/engine/commands/` 下 5 处"纯中转"子门面、父门面改直连 ⇒ 父门面暴露面**仍是 25 项**、3 个消费者只用 **7 项** ⇒ **接口宽度一项没变**。**白删，已全量回退。**
- ⇒ **目标是「深模块 + 窄接口」，不是「少一层 / 少几个文件」。次要收益（少一个同步点）不足以单独构成删的理由。**
  **凭什么成立**：删除的收益必须**可数且指向架构目标**，否则只是把复杂度搬到看不见的地方（`ADR-0042`：搬家 ≠ 消灭）。

## 决议

**一条线：不许造 → 判 → 删前三关。**

**① 不许造（前瞻）**：不许为设想的消费方铺路，也不许补消费方（补 = 制造新需求）；真要用时按**当时的真实消费方**重建。
「不许补消费方」**仅指**不许为**设想的**消费方补；**已存在的消费方改道不算补**（`ADR-0030` §补充②）。

**② 判（什么算"真的没人用"）** = **多口径一致报零**：模块引用（AST）· 字符串裸引用 · 桶与门面再导出 · 运行时串，**四口径缺一不算查清**。
`refs` 报 0 **单独不成立**（该工具修过两次盲区：① `@/…` 别名 import 被静默丢弃 ② 仓库根级件不在扫描根）⇒ 盲区下的 0 会诱导删活代码。先问：**「证明它没人用的那个工具，我验过它的盲区吗？」**

**③ 删前三关（缺一即不许删）**

| 关 | 判据 | 不过 ⇒ |
| --- | --- | --- |
| **目的关** | 复杂度**降在哪一项**（须给改前 / 改后同一项） | 答不出 ⇒ **不删** |
| **能力关** | **用户能做的事没变少吗** | 变少 ⇒ **不许删** → 摆 A/B/C 交用户 |
| **消费关** | 四口径一致报零（见 ②） | 查不清 ⇒ **不许删，改为修** |
**能力关的对照表**：
| 删的对象 | 用户能做的事 | 处置 |
| --- | --- | --- |
| 死代码 · 重复实现 · 幽灵预留 · 假抽象 · 兜底 | **没变少** | ✅ 可删（删优于改） |
| **命令 · 入口 · 功能 · 能力 · 对外契约** | **变少了** | 🚫 **不许删** → 摆 A/B/C 交用户 |

- **举证责任在"删"这一方**；三关全过才可删，**默认动作是「修对」**。**禁循环论证**：不得拿「规程 / 文档明令禁用」既当"它坏了"的证据、又当"修好也没人用"的证据。
- **`--update-baseline` 红线**：闸报「基线外新增」时**不许**直接 `--update-baseline`（= 把回潮塞进基线、发合法证）；必须先判「这份零消费实现该不该存在」。

## 后果

- ✅ **收益**：「删」从**默认**降回**有条件结论**；堵住"用一条错的约定砍掉用户能力"与"白删"两条路；幽灵预留的造 / 判 / 删合成一条线，不再互抄。
- ⚠️ **代价 / 回潮风险**：门槛变高。**反风险**是把"能力"当借口保留真死代码 —— 故目的关与消费关仍要求可数举证。波形算法 `audioPeaks`、刻度抽稀 `rulerTicks` 将来要用时**要重写**。
- 📌 **违反时的判据（怎么发现"又回去了"）**：
  1. 删掉的东西含**命令 / 入口 / 导出 API / 对外契约**，而 `git diff` 里**没有"用户已裁定"的痕迹** ⇒ 违规。
  2. 交付说明写「删了 X」却答不出「复杂度降在哪一项」⇒ 违规（白删）。
  3. 仅**单口径**（如只跑 `refs`）报零就删 ⇒ 违规。4. 拿「规程禁止它」同时充当"它坏了"与"修了也没用"⇒ 循环论证。
  5. `npm run check:dead-code` 报「基线外新增」⇒ 命中，先判"该不该存在"，不得直接 `--update-baseline`。
  ⚠️ **诚实边界**：可机判的只有 1、5 两条；2、3、4 须人工核对（`ADR-0052` 第 6 级：写明"不能"，不许硬凑 grep）。

## Lessons Learned

- **「删 > 改」是结论，不是前提。** 它写进心法时没带适用边界 ⇒ 被拿来砍掉一条用户能用的命令。**结论不能当前提**，凡"X 优先"都要补"什么时候不适用"。
- **互抄是合并信号，不是加固。** `ADR-0030:8` 把 0047 的两关抄回自己头部 —— 方向反了（后来者补回先立者）。补丁方向一反就该合并，而不是继续补。
- **白删比不删更贵**：删 5 处"纯中转"门面，实测接口宽度一项没变，全量回退。⇒ 删除必须答「**降在哪一项**」；"少一层 / 少几个文件"不是答案。

- **判据本体**：本条（取代 `ADR-0030` / `ADR-0047`）。
- **动作**：`.codebuddy/commands/架构师改码7步法.md` **Step 6 顶部「删的前置动作」**（含四口径表）· 同文件心法 §③ / 附 B 数据结论② / 手法排行 #3（各一行指针）。
