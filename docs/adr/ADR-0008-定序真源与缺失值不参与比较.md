# ADR-0008 · 定序真源与缺失值不参与比较

- **状态**：生效
- **结论**：定序真源 = 「进入系统的顺序」（git 首次加入时间），不是 mtime（会被 A7 回改污染）；缺失值不得当数值参与比较。**实施禁令**：可判据到位前**禁改**既有排序（`listRounds` 两版试修皆错，⛔ 禁重提）
- **日期**：2026-09-18
- **裁定人**：架构师（取证后自定）
- **触发**：TD-17-14（index 最新轮次指错：roundNo=-1 与有号轮比大小 + 只用 mtime）

## 背景

**旧约定：定序取 mtime（文件修改时间）** —— `scripts/arch-index.mjs::listRounds` 用 mtime 判断"本区最新轮次"。

它当初为什么这么定：mtime 是**现成的**、免维护、无额外登记成本，对"刚写完的轮次"直觉上就该是最新的。

代价在 2026-09-17 暴露（TD-17-14）：**mtime 会被 A7 回改污染** —— 回改原文（本仓的常态化动作：修正必须回改原文）会让**旧文件**的 mtime 变新 ⇒ 旧轮被误判为最新。**已试修两版、各错一边（⛔ 反例 · **禁重提**；根因见 §判据 3：是信息缺失，不是算法问题）**：

| 试修（⛔ 禁重提） | 结果 |
| --- | --- |
| ① 把 mtime 提到 roundNo 之前 | 07 区「二/三轮」被指反（文件被后编辑 ⇒ mtime 变新） |
| ② 「有号/无号分开判」 | 15 区**无号旧**文件（首轮）因 mtime 较新被误判最新 ⇒ **"无号旧文件"与"无号新文件"在当前信息下不可区分** |

⇒ 两版均回退。**SOP：禁止第三次按同一思路重提**（要修排序，先引入「跨区轮序号」或「最近写入」栏 —— 见 §决议 3）；过程细节归区域日志。只在 `listRounds` 留"已知限制"注释指向该债。

## 判据（它凭什么成立 / 为什么不成立）

**旧约定不成立。** 判据来自**「真源」与「比较」两个层面**：

1. **定序的真源是「进入系统的顺序」，不是「最后被写入的时间」。** 二者在**只追加**的场景下等价，但本仓的常态动作（A7 回改原文）**专门打破**这个等价 —— 回改是**修改旧内容**，必然把 mtime 推到最新。⇒ 拿 mtime 当"顺序"，等于假设"没人回改过"，而这个假设与本仓的规范**直接冲突**。
2. **mtime 被污染是结构性的，不是偶然的**：污染率 = 回改率。回到本仓：A7 要求"修正必须回改原文"，故回改**越多**、mtime 越不可信 —— **规矩越被遵守，这个判据越坏**。
3. **为什么试修两版都失败（可测）**：① 是把一个有污染的键提前，污染仍在；② 想用"有无序号"绕过，但**序号缺失时退化的信息维度不足** —— "无号旧文件"与"无号新文件"在所有可用字段上**完全同形**，不是算法问题、是**信息缺失**。⇒ 近似解不可得（这正是"答不出就不硬修"的实例）。
4. **缺失值不参与比较（同一母体的另一半）**：`roundNo = -1` 是**哨兵值**，它被拿去和真实序号**比大小** ⇒ 恒排最前。**"缺失"与"最小"是两件事**，把缺失编码成一个数就必然被当成那个数参与运算（与 ADR-0003「真空与非法必须分离」同源）。

## 决议

1. **定序类判据的真源 = 「进入系统的顺序」**（如 git 首次加入时间 `git log --diff-filter=A --format=%at -- <file>`），**不是 mtime**。任何用 mtime 的地方必须显式回答"这里会不会被回改污染"。
2. **缺失值不参与比较**：`roundNo` 缺失时**不得**退化为 `-1` 再进 `sort` 与真实序号同台比较；应**分桶**（有号组 / 无号组各自排序）或**显式标注不可比**。
3. **可判据到位前禁改排序**：`scripts/arch-index.mjs::listRounds` 已知限制**保持注释**指向 TD-17-14；候选可判据 = ① 跨区轮统一带「跨区 N 轮」序号（改 `_template` / 命名约定），或 ② index **增列「最近写入」栏**与「最新轮次」并列（**不互相取代**）。
4. **落点**：`scripts/arch-index.mjs`（`listRounds` 排序；已知限制注释）· 修复后须跑 `--write` + 校验（该脚本自带一致性校验，可作回归）。

## 后果

- ✅ **判据从"现成字段"改为"语义真源"**：不再假设"没人回改过"，与本仓 A7 规范一致。
- ✅ **诚实标注取代了错误绿灯**：承认"当前信息下不可区分"，比强行选一个键更安全（试修两版各错一边即为反例）。
- ⚠️ **代价 / 回潮风险**：mtime **零成本**，git 首次加入时间要**执行子进程**、要处理浅克隆/未提交等边界 ⇒ 最省力的路仍是回去用 mtime。回潮动因 = "这个文件没被回改过，用 mtime 就行"（**单点自证**，不可推广到全量）。
- ⚠️ **尚未毕业**：本 ADR 尚无机器闸校验（`roundNo` 分桶与 git-time 排序都靠人写对）⇒ 属"文档留痕"层，可考虑毕业为对账测试（造两个 mtime 与 git-time 相反的 fixture，断言排序取 git-time）。
- 📌 **违反时的判据**（怎么发现"又回去了"）：
  1. `sort` / 比较表达式里出现 `mtime` / `statSync(...).mtime` 且**未附**"此处不会被回改"的论证；
  2. 哨兵值（`-1` / `0` / `''` / `null`）与真实值进入**同一次比较**（可用 grep 找 `|| -1` / `?? -1` 后接比较）；
  3. `arch-index.mjs` 的「最新轮次」与人工读目录得出的最新轮不一致（**该脚本自带校验可发现**）；
  4. 有人再次尝试"修排序"而未先引入**跨区轮序号**或**「最近写入」栏**（= 重踩 TD-17-14 的两个失败版本）。
