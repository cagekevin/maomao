# ADR-0027 · uploads 子目录的分域判据：用户数据根开放、系统产物根封闭

- **状态**：生效
- **结论**：uploads 两个顶层根本性不同：用户数据根子目录开放（用户可自建，枚举即功能死）；系统产物根子目录封闭（须登记）。推翻旧约定「只查顶层根、子目录一律放行」。
- **日期**：2026-09-18
- **裁定人**：用户
- **触发**：TD-03-15 · TD-03-18 · 静态清单的隐含假设过期

## 背景

**旧约定：`subfolder` 校验只查顶层根，`parts[1+]` 一律放行。** 它写在 `localTool/src/utils/fileStore.ts` 的注释里，理由只讲了一半：

> 「uploads 下有**动态分类**的根（`migrated` 下用户会自建目录）⇒ 不能枚举。」

这句话对 `migrated` **是对的**，但它被写成了**全局规则** —— 于是 `tasks` / `web` / `canvas` 这些**名字由代码决定**的根，子目录也一并免检了。

**成因不是懒，是这条约定写下时世界还不是这样**：那时素材只来自「用户手动导入」，顶层根就是全部可能性。此后 `落盘即入库` 上线 —— 系统产出**自动变成 resources 行**，可能性从「用户导入」扩张到「任意代码路径落盘」，而**校验没跟着扩张**。⇒ **静态清单的隐含假设会过期**，这是本条 ADR 要连根拔掉的东西（TD-03-15 的母体）。

**代价已经发生**（2026-09-18 全量取证，磁盘 4954 文件 / DB 1967 行）：

| 根 | 事实 |
| --- | --- |
| `canvas/` | 顶层 186 文件，但子目录里躺着 **`cleaned`(125) · `template`(2) · `upload`(1) = 128 个孤儿文件** |
| 这 128 个文件 | 前后端**全仓零引用**，时间戳 2026-07-30 ~ 08-25 ⇒ 历史遗留，无人认领 |
| 它们怎么进去的 | 旧约定放行 `parts[1+]` ⇒ **写进去时没人拦，也就没人需要登记** |

即：**孤儿目录正是在「系统产物根也开放」这条缺口里长出来的**。

## 判据（它凭什么成立 / 为什么不成立）

**旧约定不成立** —— 它把两个**本性相反**的根类别套进了同一条规则。

| 根类别 | 成员 | 子目录该开放还是封闭 | 为什么 |
| --- | --- | --- | --- |
| **用户数据根** | `migrated` | **开放** | 目录名由**用户**决定（`颜色` / `HKH其他产品` …）。**枚举即功能死** —— 用户新建一个目录就落不了盘。 |
| **系统产物根** | `tasks` · `web` · `canvas` · `director3d` · `local-patch` | **封闭**（须登记） | 目录名由**代码**决定 ⇒ **可枚举**。可枚举而不枚举 = 放弃唯一一处能拦住孤儿的地方。 |

**判据一句话：子目录能否枚举，取决于「目录名由谁决定」—— 不由「它在 uploads 里」决定。**

- 用户决定 ⇒ 不可枚举 ⇒ 只能开放（**这个开放是代价，不是疏忽**）；
- 代码决定 ⇒ 可枚举 ⇒ 封闭是**唯一能提前拦住孤儿**的位置（不是"顺手加个校验"）。

⇒ **两个类别共用一条规则，必然错一半**：要么把用户的功能掐死，要么给系统产物开后门。这正是旧约定的形态（选了后者）。

**可测判据（已取证）**：把 `canvas/cleaned` / `canvas/template` / `canvas/upload` 三个孤儿喂给校验 —— 旧约定**全部放行**，新判据**全部拒绝**；把 `migrated/颜色` / `migrated/HKH其他产品` / `migrated/任意新目录` 喂进去 —— **新旧都放行**（新判据在此处必须与旧行为一致，否则就是掐死了功能）。18 例探针全数符合预期。

**被否决的方案**：**全路径枚举白名单**（列举所有合法 `subfolder` 全路径，含 `migrated/*`）—— 否决理由：**它会把"用户自建目录"这个正当功能冻死**，等于用一个白名单换掉一个功能。这是旧约定当初"对了一半"的地方 —— 它拒绝枚举是对的，错在**把拒绝的理由推广到了不需要它的根上**。

## 决议

**按根域分治：`subfolder` 判据先取顶层根 → 查根的类别 → 用户数据根放行 / 系统产物根须在登记表内。**

**落点（单一真源 = `src/components/base/utils/uploadDirs.ts`，前后端共用同一张表）**：

1. `UPLOAD_ROOT_KIND: Record<root, 'user'|'system'>` —— **类别表**（`migrated` 是唯一 `user`）；
2. `KNOWN_SUB_DIRS` / `SUB_DIR_ALLOW` —— **系统产物根的合法子目录**（前后端两份由闸校验等价）；
3. `isKnownUploadDir()`（前端 `uploadDirs.ts`）+ `normalizeSubfolder()` 分域分支（后端 `fileStore.ts`）—— 判据实现；
4. **落盘三出口自检**：`src/components/base/api/filesApi.ts` 的 `uploadFileToLocal` / `uploadInlineDataUrl` / `uploadRemoteUrl`（三处均走，`uploadRemoteUrl` 是 `downloadRemoteToLocal` / `saveResultToTasks` / `persistUrlToUploads` 的公共入口）；
5. **闸**：`scripts/check-upload-dirs.mjs`（`gates.manifest.json` id `upload-dirs`，phase `build`）—— 判据是**「代码里实际的 subfolder 字面量 ⊆ 登记表」**，即**只检查真会泄漏的那一侧**。

> **为什么不给用户数据根建闸**：它的子目录**结构上不可枚举**（用户决定）⇒ 建闸即掐死功能。这正是本 ADR 与 ADR-0016「手段优先级」的关系 —— 能上类型层 / 对账测试的才上，不能的就停在**判据 + 分域表**这一层。

## 后果

- ✅ 收益：**孤儿目录在写入那一刻就被拒**，不再需要事后全盘扫描认领；用户的动态分类功能**一行代码未动**（8 个 `migrated/*` 用例全绿）；本轮据此**抓到两处早已存在、从未登记的裸字面量** —— `canvas/face_mosaic`（2 处）· `migrated/脚本/尾帧变体`（2 处，**三级嵌套**）—— 均证明"放行"不等于"合法"。
- ⚠️ 代价 / 回潮风险：
  - **分域表是人工维护的**：新增一个系统产物根（或它的子目录）必须**同时**登记 `UPLOAD_ROOT_KIND` + `KNOWN_SUB_DIRS` + 后端 `SUB_DIR_ALLOW`，漏一处即回落成静默放行（未登记的根 ⇒ `UPLOAD_ROOT_KIND[root] === undefined` ⇒ 拒绝，此时**表现为"落盘突然 400"**，是**正确**行为，别改判据，去补登记）；
  - **最容易的回潮是"顺手放行"**：撞到 400 的人第一反应是"给 `subfolder` 加个例外"，而正确动作是**登记**。防线是闸（红）+ 区域日志里的成因链。
- 📌 违反时的判据（怎么发现「又回去了」）：
  - `isKnownUploadDir` / `normalizeSubfolder` 出现「只看顶层根」或「`parts[1+]` 不查」的分支 ⇒ 违规（回到旧约定）；
  - 代码里出现目录形态字面量而**不在** `UPLOAD_DIRS` / `KNOWN_SUB_DIRS` / `CODE_GENERATED_USER_SUB_DIRS` 中 ⇒ `check-upload-dirs` 报红（**这道闸的判据就是为这条判据设的**）；
  - 前后端 `KNOWN_SUB_DIRS` ≠ `SUB_DIR_ALLOW`（不等价）⇒ 闸报红；
  - `migrated` 之外出现 `'user'` 类别；或 `migrated` 被要求枚举 ⇒ 违规（分域表被改坏）；
  - 新增系统产物根只改了 `UPLOAD_DIRS` 而没登记类别 / 子目录 ⇒ 会在落盘时 400（**症状正确，别当 bug 修**）。
