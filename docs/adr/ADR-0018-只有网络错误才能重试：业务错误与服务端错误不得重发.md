# ADR-0018 · 只有网络错误才能重试：业务错误与服务端错误不得重发

- **状态**：生效
- **结论**：重试只用于「请求没送达/响应没拿到」（连接失败/重置/超时/DNS）；业务错误与 HTTP 状态码（4xx/5xx）不得重试，除非调用方显式声明并给出该码的瞬态证据。
- **日期**：2026-09-18
- **裁定人**：架构师
- **触发**：CLAUDE.md §5.1「只有网络错误才能重试」（2026-09-17 立）· TD-08-41（stableRequest 缺省按状态码重试）

## 背景

**被推翻的旧约定：重试工具按"可重试状态码默认集"自动重发。**

本仓曾有一处实证（TD-08-41）：Lovart 直连 POST 经裸包装进 `ai-relay/httpTransport.stableRequest`，该函数**缺省按状态码集合判定可重试** ⇒ 429 / 5xx 会被**静默重发最多 3 次**。对**非幂等 POST** 而言，这不是"多试一次"，而是**重复建任务**。

前端 `base/api/httpClient.ts` 同期是另一种口径（`HttpError` 一律不重试，仅网络/超时重试）⇒ **两端各写一套重试判据**（M3 SSOT 第二份）。

## 判据（它凭什么成立）

1. **语义层**："重试"的前提是**这次尝试没有产生效果**。但 HTTP 状态码**恰恰是说明了效果的** —— 4xx = 请求被理解且被拒；5xx = 服务端处理过并失败。二者都是"这次就是失败了"的结论，重发只是把失败重复一遍。
2. **副作用可判**：判据必须能回答「**这次重发会有什么副作用**」。非幂等请求（建任务/计费/上传）重发的副作用是**重复产生实体**，且这个代价**不可回滚**。程序 bug（`TypeError`）重试同理 —— 永远会再抛同样的错，只是多花 N 倍资源。
3. **与 ADR-0001 的关系**：旧"可重试状态码默认集"是典型的**既有约定**（"业界都这么写"）—— 追问「它凭什么成立？」答不出（它假设了幂等，而 HTTP 状态码不携带幂等信息）⇒ **它就是要被消灭的对象**。
4. **`cause`/堆栈不得丢弃**：重试路径若重分类错误，等于把根因埋掉（同 ADR-0003 的"真空与非法必须分离"）。

## 决议

**重试只用于「请求根本没送达 / 响应没拿到」这一类别**：连接失败、连接重置、超时、DNS。

**业务错误与服务端错误（HTTP 状态码，含 4xx/5xx）不得重试。**

**例外（须显式，不许默认）**：调用方要按状态码重试 ⇒ **必须显式声明**，并给出该码**在本场景的瞬态证据**。已确立的先例：CDN「已发布但尚未可读」窗口的 403，且必须是**只读 GET**。

**禁止**：

1. 把程序 bug（`TypeError` 系代码错误）当网络错误重试；
2. 用"可重试状态码默认集"给**所有**请求自动开后门（`stableRequest` 缺省曾如此）；
3. 重试时丢弃原始 `cause` / 堆栈，或重分类错误。

**协议层轮询不算重试**：`isRetryableHttpStatus` → 下轮续查，是**再次查询**而非同请求重发，不在本 ADR 范围内。

**落点**：

- 前端 `src/components/base/api/httpClient.ts`（`HttpError` 一律不重试，仅网络/超时重试）—— **已合规，作正例基准**；
- 后端 `localTool` `ai-relay/httpTransport.stableRequest` —— 2026-09-17 已改为「**缺省不按状态码重试，须显式 `retryStatuses`**」；
- `CLAUDE.md §5.1` 红线本体保留，**展开归本 ADR**。

## 后果

- ✅ **非幂等请求不再被静默重发**（TD-08-41 消除）；两端重试判据收口为同一语义。
- ⚠️ **代价 / 回潮风险**：缺省不重试会让"偶发 5xx"的**表面成功率下降**（原本被重试掩盖的失败现在暴露出来）—— 这是**正确的代价**（假成功变真失败），但容易被误读为"改坏了"。回潮动因 = "成功率掉了，加回自动重试吧"。
- ⚠️ **与 ADR-0003 的分工**：本 ADR 管**要不要重发**；ADR-0003 管**失败怎么表达** —— 两者都不许用"归一 null"实现（那是兜底，违 **减一** 闸）。
- 📌 **违反时的判据**（怎么发现"又回去了"）：
  1. 出现"可重试状态码默认集"（一个数组/枚举，`429/5xx` 直接进重试分支）而**无显式 `retryStatuses` 声明**；
  2. 非幂等请求（POST 建任务/计费）出现在带重试的调用链上；
  3. 重试逻辑里 `catch` 后重新 `throw new Error(自定义 message)` 而**未挂 `cause`**；
  4. `grep` 到 `TypeError` 被 `isNetworkError` 一类判定函数判为可重试。
