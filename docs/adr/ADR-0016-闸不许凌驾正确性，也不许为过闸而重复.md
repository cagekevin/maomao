# ADR-0016 · 闸不许凌驾正确性，也不许为过闸而重复

- **状态**：生效
- **结论**：闸拦住收口／下沉／去重时改闸（收窄不放宽），不许把同一语义抄 N 份买绿灯；闸的合法通过成本必须 ≤ 绕行成本，否则它在生产它本要禁止的行为。
- **日期**：2026-09-18
- **裁定人**：用户
- **触发**：TD-02-26 · TD-02-45 · TD-16-28 · 附 A12（check:catch 删闸事件）

## 背景

旧约定（本仓两次真实翻车）：**闸一旦立了，就被当成不可侵犯的约束** —— 碰到闸拦住正确动作时，默认动作是「绕过去 / 让代码满足闸」，而不是质疑闸。

两次实证：

1. `check:arch` 曾把作者逼到「文件头写严禁重写、正文内联重写 7 处」—— 漏 1 处 = 静默错（附 A12）。
2. `check:catch` 要求「空 catch 必须带 `catch-ok:` 标记」→ 贴一句话即可合法通过，**成本低于真正改造** ⇒ 闸在生产它本要禁止的行为，2026-09-17 被用户裁定删除（见 ADR-0011）。

## 判据（它凭什么成立 / 为什么不成立）

**旧约定不成立。** 判据是成本守恒律，可算：

> **任何闸的「合法通过成本」必须 ≤ 「绕行成本」。** 否则这道闸就在**生产它本要禁止的行为**（重复 N 份 / 静默吞 / 贴假标记 / 绕开账本，都比走正道便宜时，被治理者必然绕）。

推论（缺一不可）：

1. **闸不许凌驾正确性**：闸拦住收口 / 下沉 / 去重时 —— **改闸（收窄不放宽）**，不许把同一语义抄 N 份买绿灯。
2. **闸分两类，处置不同**：**红线闸**（机器化物理契约 / 唯一入口 / 安全 / 登记表一致性）不可自行放宽，放宽须交用户；**结构偏好闸**（分层 / 目录白名单 / 命名）可被「正确性 / 复杂度」证据推翻 → 架构师直接改。
3. **拿不出 `CLAUDE.md` 级红线证据的闸，就是默认值，不是红线**（否则连真红线也不被信任 = 狼来了）。

## 决议

**建闸默认不建，且必须过「建闸前置评审」6 问**（落点 `.codebuddy/commands/架构师改码7步法.md`「🚧 建闸前置评审」· 附 A12 · 附 B）：

- **手段优先级**：结构上不可能 ＞ 类型层 ＞ 唯一入口 + 收口原语 ＞ 对账测试 ＞ 文档留痕 ＞ **机器闸**。能用前 4 项解决的，不许用闸。**加错闸 > 不加闸**（一道没人信任的绿灯，会让后人不再查这条路）。
- **6 问任一答不出 → 不建**。其中**第 5 问（合法通过成本是否落在高频动作上）一票否决** —— 这正是 `check:catch` 与本仓「成功必须为真」「失败不得伪装成空」两条红线**都不建闸**的原因（合法通过成本落在"每写一次成功文案 / 每次读 KV"这类高频动作上 ⇒ 必被绕）。
- **覆盖不足时只能二选一：补覆盖 或 删闸；改声索让它继续绿 = 绕过。**
- **删闸也是合法动作，且必须删干净**（脚本 + `gates.manifest.json` + 元层登记 + `package.json` script + 所有引用它的文档与代码注释逐处回改）；删完必须写明代价与回潮风险。

## 后果

- ✅ 收益：闸从「不可质疑的约束」降级为「最后手段」，正确动作不再被闸逼成绕行；「闸在生产它本要禁止的行为」这类隐性损害有了明确判据。
- ⚠️ 代价 / 回潮风险：**主动删闸 / 不建闸会被误读为"放松治理"** —— 本 ADR 必须与 ADR-0011 同读：删掉假护栏之后，对应红线退回**只写在注释与判据层**（如禁静默吞），回潮成本上升，必须靠 Step 4 逐点核对而非依赖机器。
- 📌 违反时的判据（怎么发现「又回去了」）：
  - 为让闸变绿而把同一语义抄 ≥2 份 → 违规（直接违 **一归** 闸）；
  - 新增闸却答不出 6 问 / 无负例探针 → 视为未验收；
  - 闸覆盖不足时改的是**声索**（"我只覆盖 X 类"）而不是覆盖本身 → 违规（形态④）；
  - 红线闸被就地放宽而未交用户 → 违规。
