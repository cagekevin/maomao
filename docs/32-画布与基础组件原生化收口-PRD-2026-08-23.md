# 32-画布与基础组件原生化收口 PRD — 2026-08-23

> 性质：**PRD 骨架（第 1 层）**，配套步进式细化（PRD 5步法）逐层展开。
> 目标：把排查出的**一批"非原生/可收口/低效"写法**系统性收口到既有单一出口，同时提升画布性能。
> 原则：**基于系统原生方案 + 现有收口机制**，不新增平行实现。
> 说明：只依据**当前代码真实状态**撰写。

---

## 一、全局定位

让 React Flow 画布在**大画布 + 长链路**下流畅，并把**分散/重复的手写实现收口**到既有单一出口（React 原生能力、React Flow 官方能力、项目已收口的 base 组件）。

**已排查出 40+ 处"非原生/可收口"问题**，按类别归并为 5 大模块（见下）。

**当前已具备的收口基础（复用目标，不重做）**：
- 单一出口：`imageUrl.js`、`useConnectedInputs`、`LazyImage`、`toastStore`、`clipboard.js`、`filesApi.js`、`mediaType.js`、`StorageKeys`、NodeShell。
- 画布 props：`onlyRenderVisibleElements`、`elevateNodesOnSelect/Edges`、`nodeOrigin`、`performance-large-canvas`。
- React 官方能力：`useStore` 选择器、`React.memo`、`loading="lazy"`、`useMemo/useCallback`。

---

## 二、核心模块

| # | 模块 | 一句话职责 |
|---|------|-----------|
| **M1** | 状态订阅收口 | 收窄 `useConnectedInputs` 全量 nodes/edges 订阅，消除一节点变动全画布重算 |
| **M2** | 手写实现收口 | 把手写 toast/复制/缩略图/上传/URL 归一/媒体判断/存储键，收敛到既有单一出口 |
| **M3** | 图片解码与网格优化 | base64 大图走缩略图；GridSplit/GridMerge 切片/格子降载 + lazy |
| **M4** | 渲染反模式修正 | 修正 effect 派生同步、memo 失效（render 内联对象/数组）、缺 lazy、index key |
| **M5** | 样式与细节规范化 | 收敛裸色值到 tailwind token、内联 style 对象、裸 z-index |

**模块依赖**：M1（基础，影响面最大）→ M2（收口面最大）→ M3（性能应用）→ M4/M5（横向兜底）。

---

## 三、约束清单（第 1 层跨模块）

- **C-M1**：订阅从"全量 nodes/edges"改为按需/选择器订阅，**不改变上游产出语义**。
- **C-M2**：手写实现一律收敛到既有出口（`toastStore`/`clipboard`/`imageUrl`/`mediaType`/`StorageKeys`/`filesApi`），**不新增平行实现**。
- **C-M3**：所有 `<img>` 走缩略图出口；base64 大图降载；格子 lazy。
- **C-M4**：消除 effect 派生同步与 memo 失效，不引入死循环/状态抖动。
- **C-M5**：裸色值→token；内联 style 对象抽成常量；z-index 用 token。
- **C-跨-收口**：**复用既有单一出口，不新增平行机制**；改动需过 lint + 相关单测 + 回归。

---

## 四、翻车点（第 1 层沙盒推演）

1. **M1 订阅收窄过头** → 破坏"实时反映上游"语义，下游不刷新。
2. **M2 批量收口** → 手写与收口行为有细微差异（如 toast 样式/超时），冒然替换可能改变交互。
3. **M3 base64 转缩略图** → 引入额外解码成本，处理时机/缓存不当反而更卡。
4. **M4 修 memo/effect** → 依赖改错导致闭包过期或无限循环。
5. **M5 大范围样式改 token** → 视觉回归，需逐个肉眼核对。
