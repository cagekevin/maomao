# 画布 AI 助手排查手册

> **给排查者/接手者的说明书**：本文把「画布里的 AI 助手」（即右侧聊天面板「画布助手」，`agentKey=canvas-assistant`）的完整运行面讲清楚，覆盖四个维度：
> 1. 它现在工作的所有**场景**（在哪出现、对谁生效、什么前提）
> 2. 它能做到的**所有能力**（前端侧 + 工具层 + 触发生成）
> 3. **生命周期**等运行时信息（挂载/对话循环/历史/状态）
> 4. 后端它能做的**契约**（LLM 中转、proxy、供应商、任务、KV、日志）
>
> 配套：`BASE-CAPABILITIES.md` §二.5/§二.6（能力清单）、`docs/27-AI操控画布-定稿方案.md`（设计依据）、`localTool/src/routes/agentChat.ts`（后端核心）。

## 〇、一句话定位

「画布 AI 助手」= 一个复刻官方 `_Component40.jsx` 的右侧聊天面板（`AgentPanel.jsx`），挂载在 `App.jsx`。它把用户自然语言，经 LLM（function calling）转成「画布工具调用」，实时改 ReactFlow 内存画布。核心闭环是：

```
用户输入 → useAgentChat（SSE + 多轮工具循环 ≤8 轮）
        → 调用 useCanvasAgentTools 的工具层（建/删/改/连/查）
        → 写回 ReactFlow → 画布实时变化
```

它不是「纯问答机器人」，而是**会动手操作画布的 Agent**。

## 一、工作场景

### 1.1 出现位置与开关

| 项 | 说明 |
|----|------|
| 挂载点 | `src/App.jsx` 内 `<AgentPanel open={agentOpen} agentKey="canvas-assistant" />`（右上角 AI 按钮控制 `agentOpen`） |
| 形态 | 右侧浮出面板（320~720px 可拖拽，localStorage 记忆宽度） |
| 标题 | 顶部「AI 助手 / 画布助手」 |
| agentKey | 默认 `canvas-assistant`（与后端 `/api/agent/:id/chat` 的 `:id` 对齐） |
| systemPrompt | 由 `App.jsx` 以空串传入；实际画布操作准则由**后端** `agentChat.ts` 注入（见 §四.1） |

### 1.2 三种对话模式（按优先级生效，非平等开关）

实际走哪条链路，由 `AgentPanel` 的 `agentProvider` 取值 + `VITE_AGENT_DEMO` 共同决定，**优先级从高到低**：

| 优先级 | 模式 | 触发条件 | 行为 |
|--------|------|----------|------|
| ① 最高 | **Demo** | `VITE_AGENT_DEMO=1` | 本地规则引擎 `demoPlan()` 模拟 LLM：识别「创建/连接/删除/查看/适配」意图 → 调工具。零 API key |
| ② 默认 | **走 localTool `/api/proxy`** | `providers` 加载成功（挂载时 `loadProviders()` 幂等拉取），`agentProvider` 命中 `modelscope`（优先）或主供应商 `isPrimary` | LLM 请求经 `useAgentChat` → `POST /api/proxy`（openai 协议拼 `openai://chat/completions` 并注入 Bearer key）→ 上游。这是**默认生产形态** |
| ③ 兜底 | **直连 OpenAI 兼容** | `providers` 加载失败（如 localTool 未起，`GET /api/providers` 失败）导致 `agentProvider` 为空，且前端设了 `VITE_LLM_CHAT_BASE_URL` | 前端 `useAgentChat` 直接打该端点 `/v1/chat/completions`，绕过 localTool |

> ⚠️ 注意：**直连模式只是兜底**，不是「配了 env 就直连」。只要 `providers` 能拉到，`agentProvider` 就不为空，请求永远走 ② `/api/proxy`。想强制直连需先让 `GET /api/providers` 失败（或临时把 provider 列表清空）。
>
> 配置在根目录 `.env`（参考 `.env.example`）：`VITE_AGENT_DEMO` / `VITE_LLM_CHAT_*` / `VITE_AGENT_MODELS` / `VITE_AGENT_VISION_MODELS`。

### 1.3 生效前提（排查「助手不动」先看这）

1. **LLM 端点可达**：默认模式依赖 localTool 的 `agentChat.ts`，要求 `localTool/.env` 里有 `LLM_CHAT_BASE_URL`（支持 tools 的 OpenAI 兼容端点）。否则后端直接 `500: LLM_CHAT_BASE_URL not configured`。
2. **供应商需支持 function calling**：面板实际用的 provider = `modelscope`（优先）或主供应商（`isPrimary`）。选的模型必须支持 `tools`（`tool_calls`）。魔搭 Qwen3-14B 已实测可用。
3. **视觉模型校验**：发送/上传图片前，面板校验当前模型是否在 `VISION_MODELS`（`gpt-4o`/`gpt-4o-vision-preview`/`Qwen/Qwen3-14B` 等）。不支持视觉的模型上传图会被拦截并提示切换。
4. **原型无登录**：官方 `ar(e)` 校验 VIP，原型 `allowed/enabled` 恒 `true`，默认放行（见 `AgentPanel.jsx` 注释）。

### 1.4 用户侧交互场景（面板内）

- 文字输入（回车发送 / Shift+Enter 换行）
- 图片上传（仅视觉模型可：发送前 `blob→dataURL`，原型未走后端上传；接真系统应改 `/api/files/upload`）
- 模型切换（下拉，内置列表或供应商 `chat_models`，localStorage 记忆）
- 清空会话（确认后 `clear`）
- 停止生成（`AbortController`）
- 宽度拖拽（左边缘手柄）

## 二、能做到的所有能力

### 2.1 画布操作能力（核心 —— 24 个工具）

工具层在 `src/components/base/useCanvasAgentTools.js`，每个工具契约统一返回信封 `{ ok, data | error }`，`error` 永远是人话（可直接喂 LLM）。
> 工具数：17 → 24（补齐 `zoom_in`/`zoom_out`/`focus_node` 消除幽灵工具漂移；新增 `lock_node` 真实锁定、`undo_ai` AI 独立撤回、`execute_plan` 多步编排、`present_plan` Skill 阶段1策划展示）。

**只读（看清画布）**
| 工具 | 作用 |
|------|------|
| `list_nodes` | 列出所有节点 id/type/label/坐标 |
| `list_edges` | 列出所有连线 source/target |
| `get_node_details` | 读单个节点完整 data（提示词/模型/尺寸/生成结果 URL） |
| `read_canvas` | 读整张画布（节点+连线+生成结果 URL），供 Agent 一次看清 |

**修改（动手操作）**
| 工具 | 作用 |
|------|------|
| `create_node` | 建节点（`type` 枚举：`textNode`/`promptNode`/`imageNode`/`discountVideoNode`/`scriptBoxNode`/`group`）；可带 `prompt`/`label`/`position`/`connectFrom` |
| `batch_create_nodes` | 批量建多个节点（搭整条流程） |
| `delete_node` | 删除节点 + 连带删除相连边 |
| `batch_delete_nodes` | 批量删节点 |
| `update_node` | 改节点**白名单**字段：`prompt`/`label`/`selectedModel`/`aspectRatio`/`resolution`/`seconds`/`text`/`locked` |
| `update_node_raw` | 改节点任意原始 data 字段（高级，谨慎用） |
| `connect_nodes` | 连两个节点（source→target 数据流） |
| `batch_connect_nodes` | 批量连线 |
| `delete_edge` | 删连线（按 `edgeId` 或 `source+target`） |
| `move_node` | 移动节点到新坐标 |
| `lock_node` | 锁定/解锁节点：传 `nodeId` 锁单个，传 `type`（如 `promptNode`）锁该类型全部；锁定后节点不可拖动/不可编辑（`draggable`/`selectable=false`） |

**其他**
| 工具 | 作用 |
|------|------|
| `trigger_generation` | 触发某节点生成并 **await 拿到已落盘 resultUrl**（走 `useNodeGeneration` 统一契约；节点须已注册 start） |
| `execute_plan` | **多步编排**：接收 `generations` 数组，按 `depends_on_previous` 分批建节点+连线+触发生成，返回每步 resultUrl。是 Skill（大批量套图）的执行引擎（见 `docs/08` 第 2 步） |
| `present_plan` | **Skill 阶段1策划展示**：LLM 规划后调它把策划+generations 呈现给用户确认（前端展示为一条 assistant 消息，generations 暂存供 execute_plan 用）。对齐大雄三阶段（见 `docs/08` 第 4 步） |
| `fit_view` | 缩放视图显示所有节点 |
| `zoom_in` / `zoom_out` | 放大 / 缩小视口（`ctx.zoomIn/zoomOut`，可传 `factor` 倍数） |
| `focus_node` | 居中视口到指定节点并放大（`ctx.setCenter`，可传 `zoom`） |
| `undo_ai` | **撤回 AI 刚才那步操作**：恢复画布到 AI 最近一次写操作之前。与用户 Ctrl+Z 完全隔离，只影响 AI 自己的改动 |
| `group_nodes` | 把 ≥2 个节点编入一个编组（复用右键「编组」） |

> **写回铁律**：所有写操作「不可变局部更新」——只改目标节点，非目标节点引用不变，不触发全局重渲染。
> **改节点白名单**：`update_node` 只允许上面 8 个字段，防 LLM 乱改 data 失同步；要改任意字段才用 `update_node_raw`。

> **AI 独立撤回（undo_ai）设计**：与用户撤销（`useCanvasHistory`/Ctrl+Z）**完全隔离**。用户撤销管用户手动操作；AI 通过工具改画布走 `setNodes/setEdges` 不进用户撤销栈，故单独用 `aiLastSnapshot` 存「AI 最近一次写操作前」快照，`undo_ai` 恢复它。只存一步（用户说"撤回刚才那步"语义即最近一步），不做完整撤销栈以降低复杂度。实现集中在 `buildCanvasAgentTools` 的 `MUTATING_TOOLS` 统一 wrap（见文件头注释）。

### 2.2 对话/推理能力

- 流式输出（SSE，`content` + `reasoning_content` + `tool_calls` 分片累积）
- 多轮工具循环：每轮解析 LLM 的 `tool_calls` → 调工具层 → 回填 `tool` 结果 → 下一轮，**硬上限 8 轮**（`MAX_TOOL_ROUNDS`，复刻官方 `ur=8`）
- 思考过程折叠（`reasoning` 字段，`AgentMessage` 的 `Reasoning` 组件）
- 工具调用标签展示（紫色 chip：`ToolCallChip`，显示 `name(args)`）
- 三种消息态：`user`（含 attachments 图片）/ `assistant`（content+reasoning+tool_calls+streaming）/ `tool`（content 为 JSON 结果）

### 2.3 Demo 模式规则引擎能力（`demoPlan`）

仅 `VITE_AGENT_DEMO=1` 时，本地规则把一句话映射成工具调用，覆盖意图：

| 意图关键词 | 调用工具 |
|-----------|---------|
| 创建/新建/生成/画 + 节点类型（生图/视频/文本/剧本/编组） | `create_node` |
| 连接/连到/connect | `connect_nodes` |
| 删除/移除/delete | `delete_node` |
| 看看/列出/结构 | `read_canvas` |
| 适配/全览/fit | `fit_view` |

> ⚠️ 这是原型演示用的**简化规则**，真实对话应走 `roundTrip`（真实 LLM）。不认识的意图返回 `[]` → assistant 纯文字答复。

### 2.4 做不到 / 目前是假实现的地方（排查「点了没反应」）

- `trigger_generation`：若节点未通过 `useNodeGeneration` 注册 start，`runNodeGeneration(id)` 返回 falsy → 工具报 `ok:false "节点未注册生成契约"`。
- 图片上传：原型以 `dataURL` 作 url，**不走后端上传**；接真系统需改 `localTool /api/files/upload` 拿 CDN url（`AgentPanel.handleFiles` 注释已标注）。
- 模型列表：原型用内置列表或供应商 `chat_models`；官方从后端动态取（见 `VITE_AGENT_MODELS`）。

> ✅ **幽灵工具漂移已修复**：早期 `agentChat.ts` 准则末尾列举 `zoom_in`/`zoom_out`/`focus_node`，但前端工具层未实现 → LLM 调用时报「未知工具」空转。现前端已补齐这三个工具（`useCanvasAgentTools.js`），与准则一一对应。

### 2.5 健壮性边界（已处理，排查时不用再踩）

- **准则单一来源 = 前端**（`useAgentChat.js` 的 `CANVAS_AGENT_RULES`）：默认路径走 `/api/proxy`（后端 `agentChat.ts` 不参与），故准则在前端 `buildRequestMessages` 注入，覆盖 proxy/agent 两条路径；后端仅在消息无 system 时兜底，不重复。
- **并发双发防护**：`sendingRef` 同步锁，快速双击不会并发两个请求（`sending` state 是异步更新，靠 ref 兜底）。
- **错误路径历史不丢**：`saveHistory` 在 `finally` 落盘（无论成功/失败/中止），LLM 中途失败时的增量历史也保住；catch 会清理所有 `streaming:true` 残留占位（不只最后一个）。
- **8 轮工具循环上限有提示**：走满 `MAX_TOOL_ROUNDS` 仍未收敛时追加一条 assistant 提示，不再"静默停住"。
- **roundTrip 错误解析统一**：proxy / agent 两条路径共用 `parseAgentError`，错误信息格式一致，排查不用分两处看。
- **AI 独立撤回（`undo_ai`）**：只撤 AI 自己的操作，与用户 Ctrl+Z（`useCanvasHistory`）完全隔离；只存最近一步快照，实现集中在工具层 `MUTATING_TOOLS` 统一 wrap（见 §2.1 设计说明）。
- **AI 主动聚焦**：准则引导生成/创建/修改节点后主动调 `focus_node` 聚焦结果节点给用户看。
- **异步安全·节点消失兜底重建**（`PromptNode.jsx` `onRecover`）：异步生成完成广播 `mutiwindow-task-completed` 时，若原节点已在异步期间被删除/合并而消失，则用结果 **重建节点**（复用原 id 保持任务关联），避免「任务中心有图、画布没图」错位。吸收自大雄 canvas-agent 的「live 节点消失 → 结果重建」经验。

## 三、生命周期等运行时信息

### 3.1 挂载与销毁

| 阶段 | 行为 |
|------|------|
| 挂载 | `AgentPanel` 读 `useProviders()`；若 providers 为空，调 `loadProviders()` 幂等拉取（保证 Agent 能用支持 function calling 的模型） |
| 打开 | `open=true` 时渲染面板；通知父级 `onWidthChange(width)`、`onEnabledChange(true)`（原型恒放行） |
| 卸载/关闭 | `open=false` → `return null`；`useAgentChat` 的卸载 effect 调 `abortRef.current?.abort()` 中止进行中的请求 |

### 3.2 一次对话的完整生命周期

```
1. 用户 send(text, attachments)
2. 组装 userMsg（attachment 图经 normalizeImageUrlForSend 归一化：blob→dataURL / 相对→绝对；
   若 provider.refFormat==='base64' 则统一转 base64）
3. 进入多轮工具循环（最多 8 轮）：
   a. 追加 assistant 流式占位（streaming:true）
   b. roundTrip：POST LLM（含 messages+tools+tool_choice:'auto'+stream:true+temperature:0.6）
      - 有 provider → 走 /api/proxy 转发（保留 function calling + SSE）
      - 无 provider → 走 localTool /api/agent/:id/chat
   c. SSE 解析：节流 50ms 刷新 content/reasoning/tool_calls
   d. 若无 tool_calls → 结束本轮
   e. 有 tool_calls → 逐个 callTool(name,args) → 回填 tool 消息（{ok,data|error} JSON）
4. 循环结束 → saveHistory(agentKey, msgs)
```

### 3.3 历史与会话持久化

| 存储 | key | 说明 |
|------|-----|------|
| localStorage | `agent_history_${agentKey}` | 同步兜底（localTool 断开也能用） |
| KV（localTool） | 同 key | 跨端/多窗口共享；异步 fire-and-forget，失败静默回退 localStorage |
| 输入草稿 | `agent_draft` | 未发送内容落盘，刷新不丢 |
| 面板宽度 | `agent_panel_width` | 320~720 记忆 |

- 初始加载：先读 localStorage（快速渲染）→ 异步读 KV，若 KV 历史更全则覆盖。
- 清空：`clear()` 中止请求 + 存空历史。
- 停止：`stop()` = `abortRef.current?.abort()`，错误态显示「已停止」。

### 3.4 消息契约（排查「消息结构异常」对照）

```js
user:      { role:'user', content, attachments?:[{type,url}], createdAt }
assistant: { role:'assistant', content, reasoning?, tool_calls?:[{id,type:'function',function:{name,arguments}}], streaming?, model, createdAt }
tool:      { role:'tool', content: JSON字符串({ok,data|error}), tool_call_id, createdAt }
system:    { role:'system', content }
```

### 3.5 关键常量速查（定位 bug 用）

| 常量 | 值 | 位置 |
|------|----|----|
| `MAX_TOOL_ROUNDS` | 8 | `useAgentChat.js` |
| `MIN_WIDTH` / `MAX_WIDTH` / `DEFAULT_WIDTH` | 320 / 720 / 380 | `AgentPanel.jsx` |
| `CHAT_MODEL` 默认 | `gpt-4o-mini` | `useAgentChat.js`（可被 env/provider 覆盖） |
| `LLM_CHAT_TIMEOUT_MS` | 120000 | 后端 `agentChat.ts` |
| SSE 流式刷新节流 | 50ms | `useAgentChat.js` `scheduleFlush` |

## 四、后端能做的契约

> AI 助手在后端涉及的契约分两类：**① 它直接调用的 LLM 中转**；**② 它改画布时依赖的「生成/任务/资源」链路**（`trigger_generation` 触发节点 → 走 localTool 任务系统，最终落 `tasks` 表 + 磁盘 + 任务中心）。

### 4.1 LLM 中转契约（`POST /api/agent/:id/chat`）

- 处理器：`localTool/src/routes/agentChat.ts` `handleAgentChat`
- 入参（前端组装）：`{ model, messages, tools, tool_choice, temperature }`
  - ⚠️ **画布操作准则单一来源 = 前端**（`useAgentChat.js` 的 `CANVAS_AGENT_RULES` 常量，`buildRequestMessages` 在消息无 system 时 unshift）。默认路径（provider 存在走 `/api/proxy`）后端 `agentChat.ts` 不参与，故准则必须在**前端**注入才能覆盖两条路径。
  - 后端 `agentChat.ts` **不再默认 unshift**：仅当 `AI_CANVAS_ENHANCE='1'` 且消息里没有 `system` 时才兜底注入本地 `cfg.rules`（`CANVAS_AGENT_RULES`，可用 `AI_CANVAS_SYSTEM_PROMPT_FILE` 外部文件覆盖），避免与前端注入重复。
- 出参：**SSE 原样透传**上游（含 `tool_calls` delta）；上游非 SSE（如 JSON 错误体）会被包成 `data: {json}\n\n` 再写回。
- 配置（`localTool/.env`，换模型零改码）：
  | env | 说明 |
  |-----|------|
  | `LLM_CHAT_BASE_URL` | 支持 function calling 的 OpenAI 兼容端点（**必配**，否则 500） |
  | `LLM_CHAT_API_KEY` | 端点密钥 |
  | `LLM_CHAT_MODEL` | 模型 ID（覆盖前端传来的 defaultModel） |
  | `LLM_CHAT_TIMEOUT_MS` | 上游总超时，默认 120000 |
  | `AI_CANVAS_ENHANCE` | `'0'` 关闭后端兜底注入；默认开，但仅当消息**没有** system 时注入（前端 `useAgentChat` 已注入则跳过，不重复） |
  | `AI_CANVAS_SYSTEM_PROMPT_FILE` | 外部准则提示词文件路径 |
- 失败码：`400 invalid json` / `400 messages required` / `500 LLM_CHAT_BASE_URL not configured` / `502 upstream error`。
- 前置铁律：现有 `apimart-gateway /v1/chat` 是 Lovart 纯中转、**不返回 tool_calls**，无法驱动工具循环。必须配支持 function calling 的端点。

### 4.2 供应商契约（`/api/providers` 等）

AI 助手实际 provider 选择逻辑（`AgentPanel.jsx`）：优先 `modelscope`（openai 协议、支持 tools），否则主供应商（`isPrimary`）。

- `GET /api/providers`：返回脱敏列表（`has_key`/`key_preview`，key 不回明文）
- `PUT /api/providers`：全量保存（`api_key` 有值写 env，绝不落 json）
- `POST /api/providers/test-connection`：连接测试（按协议表驱动探测 `/v1/models` 或 `/health`）
- `POST /api/providers/:id/fetch-models`：拉取模型列表（按协议分类 image/chat/video）
- 协议：`apimart`（Lovart 异步 task_id 轮询）/ `openai`（直连兼容）
- 模型分类：`image_models` / `chat_models` / `video_models`（snake_case）
- **魔搭特殊兜底**：若未单独配 `API_PROVIDER_MODELSCOPE_KEY`，复用 `LLM_CHAT_API_KEY`（AI 助手在 `.env` 已填的唯一一份魔搭 key），避免 401。

### 4.3 代理转发契约（`POST /api/proxy`）

当 `useAgentChat` 传了 `provider`（即默认生产形态，见 §1.2 ②）时，LLM 请求走 `/api/proxy`。实际靠 `localTool/src/routes/system.ts` 的 `handleProxy` + `providers.ts` 的 `resolveProviderTarget` 分派：

- 前端 url 用相对形式 `openai://chat/completions` → 后端 `resolveProviderTarget` 拼成 `${base_url}/v1/chat/completions` 并注入 `Bearer key`（从 env 读，魔搭兜底复用 `LLM_CHAT_API_KEY`）。
  - AI 助手默认命中的 `modelscope` 是 **`openai` 协议**，所以**走的就是这条「拼路径 + 注入 key」分支**。
- `apimart` 协议（如 Lovart 主供应商）：url 原样透传，不注入本地 key（走网关自身鉴权）。但注意 AI 助手默认**不会**选 apimart 作为对话 provider（见 §1.3.2），该分支对画布助手而言通常不触发。
- 自指网关重写：目标 host 是 localTool 自身 18080 且路径 `/api/v1/gateway/*` → 重写到 apimart-gateway 9004（特惠视频专用，与画布助手 LLM 中转无关，但同走 `/api/proxy`）。

### 4.4 任务 / 生成契约（`/api/tasks`）

`trigger_generation` 触发节点 → 节点经 `useNodeGeneration` 注册 start → 走 localTool 任务系统：

- `GET /api/tasks`：分页查询（按 `created_at` 倒序，支持 `task_id`/`node_id`/`prompt` 等模糊搜索列）
- `POST /api/tasks`（save / batch-save）：UPSERT（合并已有行，不抹诊断字段）
- `DELETE /api/tasks?id=` / `batch-delete` / `clear`：删任务 + 删本地文件（`result_url`/`thumbnail_url` 落盘文件一并删）
- `persistThreadId(threadId, taskId, meta, frontTaskId)`：把 Lovart 上游 `thread_id` 关联进前端任务行（**只为前端 frontTaskId 行补 thread_id，绝不再建网关 task_id 垃圾行**）
- 字段契约：snake_case 存库，`tasks` 表白名单列见 `tasks.ts` `ALLOWED_TASK_COLUMNS`；`id === taskId`（前端 diff 去重键）。

### 4.5 KV / 资源 / 日志契约（间接相关）

| 端点 | 与 AI 助手的关系 |
|------|-----------------|
| `GET/PUT /api/kv` | 历史跨端共享（`agent_history_*`）；画布快照 `canvas-state-v1-<projId>` |
| `GET /api/resources` 等 | 生成结果落资源面板（`migrated`/`materials`），与磁盘一一对应 |
| `POST /api/files/upload` | 接真系统后图片上传应走这里（原型未用） |
| `POST /api/logs` | 前端日志上报（body 带 `taskId`/`nodeId`，以 `[frontend]` 前缀落 `localtool_18080.log`）——做全链路排查用 |

### 4.6 后端排查工具（排查画布助手触发的生成故障）

`localTool/scripts/task-inspect.mjs`（只读安全，AI 改 bug 首选）：

```bash
cd localTool
node scripts/task-inspect.mjs <id>            # 贴 task_id/thread_id/node_id → 全链路（DB+后端+前端日志）
node scripts/task-inspect.mjs --lifecycle <id>
node scripts/task-inspect.mjs --task <node_id>   # 某节点历次生成比对
node scripts/task-inspect.mjs --canvas-health [proj]   # 画布节点/边体检（助手改坏画布时查）
node scripts/task-inspect.mjs --consistency [proj]    # 三层一致性（画布↔任务中心↔磁盘）
node scripts/task-inspect.mjs --lost-check           # 丢图体检
node scripts/task-inspect.mjs --logs [关键词]         # 查日志（download/upload/proxy/error）
```

## 五、排查决策树（快速定位）

| 现象 | 先查 |
|------|------|
| 面板打不开 | `agentOpen` 状态（`App.jsx` 右上角 AI 按钮）；面板 `open` prop |
| 发送报错 `LLM_CHAT_BASE_URL not configured` | `localTool/.env` 缺 `LLM_CHAT_BASE_URL` |
| 图片发不出去 | 当前模型是否在 `VISION_MODELS`；非视觉模型需切换 |
| 助手「说做了」但画布没变 | 看 `tool` 消息是否 `ok:false`；查工具白名单/节点是否存在；Demo 模式只覆盖有限意图 |
| 生成没反应 | 节点是否 `useNodeGeneration` 注册；`trigger_generation` 返回 `ok:false`？用 `task-inspect --task <node_id>` |
| 历史丢了 | `agent_history_*` 的 localStorage / KV；`task-inspect --kv agent_history` |
| 模型下拉空 | `providers` 是否加载；`chat_models` 是否为空 |
| 工具循环卡死 | 多轮上限 8 轮；检查 LLM 是否陷入反复 tool_call 不自收敛 |

## 六、接真系统路径（设计预留）

- **工具层**：当前操作 ReactFlow 内存画布；接真引擎时把 `setNodes/setEdges` 换成调 localTool 状态接口即可，**工具签名与返回信封不变，LLM 侧无感知**（`useCanvasAgentTools.js` 注释）。
- **图片上传**：`AgentPanel.handleFiles` 的 `blobToDataURL` 改为调 `localTool /api/files/upload` 拿 CDN url。
- **LLM 端点**：默认 localTool 中转；直连模式只需设 `VITE_LLM_CHAT_BASE_URL` 等 env。
- **会员/启用**：原型恒放行；接真系统把 `onEnabledChange`/VIP 校验接回官方 `ar(e)`。
