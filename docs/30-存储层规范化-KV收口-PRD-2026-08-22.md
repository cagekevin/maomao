## 二、S1 后端判定统一

### 为什么做（根因 R1）
`kvStore.isKvKey` 只认 `canvas-state-v1-` 前缀，而 `contentStore.getBackend` 认 `STORAGE_KEYS.backend`。两套不一致 → 登记为 `kv` 的键（如 `yimao_accounts`）在 `kvStore.storageSet` 里被当成 local，写进浏览器存储而非 KV。**收口 = 让 isKvKey 也认 STORAGE_KEYS。**

### 官方参照
官方没有 isKvKey，但官方存储抽象 `setObject/getObject` 用 `Br`（localTool）作为**唯一后端**（除 disableLocalTool 走内存）。本项目有 local/kv 双后端，需统一"哪些键走 kv"的判定。

### 改动点（kvStore.js）
**现状**：
```js
export function isKvKey(key) {
  return typeof key === 'string' && key.startsWith(CANVAS_STATE_PREFIX)
}
```
**改为**：
```js
/** pattern 模板 → 正则缓存（对齐 contentStore.getPatternRegex） */
const patternRegexCache = new Map()
function getPatternRegex(k) {
  let re = patternRegexCache.get(k)
  if (!re) {
    const parts = k.split(/\{[^}]+\}/)
    const escaped = parts.map((p) => p.replace(/[.+^$()|[\]\\]/g, '\\$&')).join('.+')
    re = new RegExp('^' + escaped + '$')
    patternRegexCache.set(k, re)
  }
  return re
}

export function isKvKey(key) {
  if (typeof key !== 'string' || !key) return false
  const entry = STORAGE_KEYS[key]
  if (entry) return entry.backend === 'kv'
  for (const [k, v] of Object.entries(STORAGE_KEYS)) {
    if (!v.pattern || v.backend !== 'kv') continue
    if (getPatternRegex(k).test(key)) return true
  }
  return false
}
```
需要 import `STORAGE_KEYS`：`import { CANVAS_STATE_PREFIX, STORAGE_KEYS } from './contracts.js'`。

### 验收标准（tests/unit/kvStore.test.js 新增，断言）
1. `isKvKey('canvas-state-v1-proj-1') === true`（pattern 回归）
2. `isKvKey('canvas-state-v1-proj-1_version') === true`（pattern 回归）
3. `isKvKey('active_api_endpoint') === true`（backend:'kv' 精确键）
4. `isKvKey('projects') === false`（local 键）
5. `isKvKey('yimao_accounts') === true`（改 kv 后，S3 完成才通过）
6. `isKvKey('') === false`、`isKvKey(123) === false`

## 三、S2 读写降级对称

### 为什么做（根因 R2/R3）
- `storageSet` 写 KV 失败会降级到本地 `sSet`（有降级）。
- 但 `storageGet` 读 KV 失败**不**降级读本地 → 降级写进 localStorage 的数据读不回。
- `storageDelete` 删 KV 失败也**不**降级删本地 → 本地副本残留。
**收口 = 让读/删与写对称。**

### 官方参照
官方 `getObject` 对 KV 读失败会**回退** localforage / localStorage 历史数据（shared.js L1163-1190），这正是"降级读"的官方语义。本项目对齐它：KV 读失败 → 降级读本地副本。

### 改动点（kvStore.js）
```js
export async function storageGet(key) {
  if (isKvKey(key)) {
    try {
      return await kvGet(key)
    } catch (e) {
      // 降级读本地副本（与 storageSet 降级写对称）
      const raw = sGet(key)
      if (raw === null) return null
      try { return JSON.parse(raw) } catch { return raw }
    }
  }
  const raw = sGet(key)
  if (raw === null) return null
  try { return JSON.parse(raw) } catch { return raw }
}

export async function storageDelete(key) {
  if (isKvKey(key)) {
    try {
      return await kvDelete(key)
    } catch { /* KV 删失败：降级删本地副本 */ }
  }
  sRemove(key)
  return { ok: true }
}
```

### 验收标准（tests/unit/kvStore.test.js）
1. mock `kvSet` 抛错 → `storageSet('yimao_accounts', v)` 后，本地 `sGet('yimao_accounts')` 有降级副本。
2. mock `kvGet` 抛错 → `storageGet('yimao_accounts')` 返回降级副本数据。
3. mock `kvDelete` 抛错 → `storageDelete('yimao_accounts')` 后本地副本被 `sRemove`。
4. KV 正常时 `storageGet` 走 `kvGet`，不读本地。

## 四、S3 账号走 KV + 云同步

### 为什么做（根因 R3/R6）
- 账号存浏览器存储（local）+ `load()` 写空覆盖 → 关闭插件重开丢。
- 官方账号存 localTool KV + 空值保护（shared.js L1198-1222）→ 磁盘持久化不丢。
- 账号改 KV 后 `getLocalKeys()` 不含它 → 云同步失效（死配置）。需让 cloudSync 专门处理账号。
**收口 = 账号走 KV + accountsStore 异步落盘 + cloudSync 支持账号。**

### 官方参照
- 官方保存：`_a` → `B.setObject(V.USERS, users)`（localTool KV）。见 docs/31。
- 官方空值保护：拒绝 null/空数组/空对象/空串（shared.js L1198-1222）。

### 改动点

#### 4.1 contracts.js
`yimao_accounts` backend `local` → `kv`，note 注明走 KV 持久化（对齐官方 users）。

#### 4.2 accountsStore.js（改异步，移除写空覆盖）
- `load()`：改 `await contentGetAsync(STORAGE_KEY)`；**删除** `contentSet(STORAGE_KEY, [])` 写空覆盖分支。
- `persist()`：改 `await contentSetAsync(STORAGE_KEY, state.envs)`。
- `saveEnvs(next)`：改 `async`，`await persist()`。
- 调用 `saveEnvs` 处（saveEnvironment/requestDelete/moveEnv/toggleFavorite）加 `await`。
- `reloadFromStorage()`：改 `await contentGetAsync(STORAGE_KEY)`。
- 模块级 `state = { envs: [], ... }`（不再同步 load，因 KV 异步）。

```js
// load 改为异步
async function load() {
  try {
    const parsed = await contentGetAsync(STORAGE_KEY)
    if (Array.isArray(parsed)) {
      // 保留演示假数据清理
      return parsed.filter((e) => !String(e.id||'').startsWith('env_demo_') && !(e.siteName==='开发测试网' && (e.cookies||[]).every(c=>c.name==='test')))
    }
    return []  // 读不到返回空，不写空覆盖
  } catch { return [] }
}
```

#### 4.3 cloudSync.js（支持账号 KV 键上传/下载）
- `collectLocal()`：新增（受 `accounts` 开关控制，见 S4）：
  ```js
  if (syncAccountsOn) {
    const acc = await contentGetAsync('yimao_accounts')
    if (Array.isArray(acc) && acc.length) ls.accounts = acc
  }
  ```
- `restoreLocal(cloud)`：新增：
  ```js
  if (syncAccountsOn && Array.isArray(cloud.data.accounts)) {
    await contentSetAsync('yimao_accounts', cloud.data.accounts); written++
  }
  ```
- `version` 4 → 5（新增 accounts 字段；旧云端无 accounts 则跳过，向后兼容）。
- 需要 import `contentGetAsync, contentSetAsync`。

### 验收标准（tests/unit/cloudSync.test.js + accountsStore.test.js）
1. 上传（开关开 + 本地有账号）→ `ls.accounts` 为数组。
2. 上传（开关关）→ 无 `ls.accounts`。

## 五、S4 清单/登记规范化

### 为什么做（根因 R6/R7/R8）
- cloudSync 若沿用 `getLocalKeys()`（只含 local），账号走 KV 后永不进云同步（死配置）。
- backupStore 注释称备份账号但实际不含（账号走 KV 后不在 LS_KEYS）。
- contracts 把 `hideFromViewportCapture`（非存储键，是 3D object.userData）登记为 native 误导。
**收口 = 领域开关 + backupStore 账号 + 移除误导登记。**

### 改动点

#### 5.1 cloudSync.js 领域开关
把 `SYNC_EXCLUDE` 升级为领域开关表（开发者配置常量）：
```js
const SYNC_DOMAIN_SWITCHES = { accounts: true, projects: false, /* 其余领域按需 */ }
```
- `accounts` 开 → S3 的账号上传/下载生效。
- `projects` 关 → 项目不进 cloudSync（saveProjects 未传 version，云下载覆盖会丢新项目，先关堵风险）。

#### 5.2 backupStore.js 纳入账号
- `exportAll()`：额外 `await contentGetAsync('yimao_accounts')` → `backup.accounts`。
- `importAll()`：读 `backup.accounts` → `await contentSetAsync('yimao_accounts', ...)`。
- 头注释更新：备份含账号。

#### 5.3 contracts.js 移除误导登记
删除 `hideFromViewportCapture`（backend 'native'，实为 3D object.userData，非存储键）。
- 验证：`grep -rn "hideFromViewportCapture" src/` 确认无 sGet/sSet/contentGet 引用（仅 DirectorCanvas/SceneRoot 的 `userData.HIDE_FROM_VIEWPORT_CAPTURE_KEY` 是 three 属性，不是存储）。

### 验收标准
1. backupStore 导出含 `accounts`（本地有账号时）。
2. backupStore 导入恢复 `accounts` 到 KV。
3. `grep -rn "hideFromViewportCapture" src/components/base/contracts.js` 无该键。
4. cloudSync `projects` 领域关 → 上传/下载不含 projects。
