## 〇、为什么必须删（三个真实理由，不删就会一直复发）

### 理由 1（本次事故根因）：Radix 用 `hidden` **属性**隐藏非激活面板，会被任何作者 `display` 类压掉

- 取证：`node_modules/@radix-ui/react-tabs/dist/index.mjs:170` → `hidden: !present`。
- 它依赖的是 **UA 样式表**里的 `[hidden] { display: none }`；而 **UA 样式会被作者样式覆盖**。
- 于是「非激活面板」只要被调用点写上 `className="flex …"`，那个**空容器**就继续以 `display:flex` 参与布局；
  再叠加 `flex-1`，它会与激活面板**平分高度** ⇒ N 个 tab 时"内容只占 1/N，其余是空白"，且
  **空白出现在内容上方还是下方取决于当前是第几个 tab** —— 这就是「左上角各 tab 参差 / 互相遮挡 / 内容前空一截」的真身。
- 只要还用 Radix Tabs，这个坑就**必须靠"记得别写 display 类"来规避** —— 而"靠人记得"正是本仓已判定的母体缺陷（M2：唯一入口无机器守卫）。

### 理由 2：Portal 渲染到 `document.body`，落在 `.ve-scope` 之外 → 拿不到 `--ve-*` token

- 现状证据：`EditorShell.tsx` 里挂了 `document.body.classList.add('ve-scope','dark')` 这个**补丁**，
  就是为了让 Radix 弹层能拿到主题变量。`ve-theme.css` §6 还有一大段 `[data-radix-popper-content-wrapper]` 专用规则。
- 这是"用附随复杂度补，而非源头收敛"：弹层该渲染在编辑器**自己的层根**里。

### 理由 3：状态语言是两套

- Radix 用 `data-state="active|inactive|open|closed"`；`ve-theme.css` 用 `data-active`（`.ve-tab` / `.ve-tbtn` / `.ve-clip-selected`…）。
- 同一个 UI 里两套状态属性 → 样式作者每次都要先查"这个是 Radix 的还是我们的"。

## 三、「新语言」的硬约束（每个新原语都要满足）

1. **样式来源唯一**：只用 `.ve-scope` 的 token（`--ve-bg/fg/border/...`）与 `ve-theme.css` 的 `.ve-*` 语义类；
   **禁止**用画布侧 token（`bg-popover` / `text-muted-foreground` 这类在 `ve-scope` 内是**没人定义的回落值**）。
2. **状态属性唯一**：用**自有** `data-active` / `data-open` 等；**禁止**再引入 `data-state`。
3. **非激活内容 = 不渲染**（本计划最重要的一条）。
   - 反例（本次事故）：`<div hidden className="flex">` —— `hidden`（UA 样式）被 `.flex`（作者样式）压掉。
   - 正例：`if (!isActive) return null;` —— 不渲染就不存在布局，无需与 CSS 优先级搏斗。
4. **弹层渲染进「编辑器自己的层根」**，不要 `document.body`。
   - 做法：`EditorShell` 根节点内放一个 `<div id="ve-layer-root" className="contents" />`（或 `position:fixed; inset:0; pointer-events:none` 的容器，子层自开 `pointer-events:auto`），
     弹层用 `createPortal(node, layerRoot)`。
   - 收益：`.ve-scope` 天然命中 ⇒ **可删掉 `document.body.classList.add('ve-scope','dark')` 补丁**，也可删 `ve-theme.css §6` 里 `[data-radix-popper-content-wrapper]` 那整段。
5. **API 兼容优先**：导出名与 props 形状保持与现状一致（组件名 + `className` + Radix 风格的 `asChild` 语义），
   让 `importers` 尽量零改动；确需改调用点时，一次性改完并记入轮次文件。
6. **不加新依赖**：定位/焦点/键盘全靠浏览器原生 API 自研（**禁止**引入 `floating-ui`、`headlessui`、`ark-ui` 等替代库 —— 那只是换一个黑盒）。

## 四、分级与逐个替换方案

### A 级 —— 原生元素包装，**直接重写**（低风险，建议第一个 PR 做完）

| 原语 | 新实现要点 | 必须保住的行为 |
| --- | --- | --- |
| `aspect-ratio` | `<div style={{ aspectRatio }} />` | 一个 prop 透传 |
| `label` | `<label>` + 点击聚焦（原生即可） | htmlFor 关联 |
| `separator` | `<div role="separator" data-orientation>`（样式已在 `ve-theme.css`） | 横/纵两向 |
| `progress` | `<div role="progressbar" aria-valuenow>` + 内层宽度 | value/indeterminate |
| `checkbox` | `<button role="checkbox" aria-checked>` 或原生 `<input type=checkbox>` + 样式 | 受控 `checked`/`onCheckedChange`、键盘 Space |
| `switch` | `<button role="switch" aria-checked data-active>`；样式已有 `.ve-switch`（**注意它按 `data-state` 写，要改成 `data-active`**） | 点击/Space 切换 |
| `radio-group` | `<div role="radiogroup">` + `<button role="radio" aria-checked>` | 方向键移动、受控 |
| `slider` | 原生 `<input type="range">` + `.ve-scope` 样式（最省且无 a11y 损失） | 受控 value、min/max/step、键盘 |

### B 级 —— `tabs.tsx`（中等，**优先做**，因为它是本次事故的主角）

**新实现（建议形态）**

```tsx
// 上下文：value / setValue / baseId
<Tabs value defaultValue onValueChange className>
  <TabsList role="tablist"> <TabsTrigger role="tab" data-active aria-selected aria-controls id> …
  <TabsContent value>  →  if (ctx.value !== value) return null;   // ★ 非激活不渲染
```

- `TabsContent` **不渲染**非激活内容（等价于 Radix 的 `present && children`，行为不变）。
- 键盘：左右方向键在 tab 间移动 + `Home`/`End`；`aria-controls`/`aria-labelledby` 成对。
- **样式**：把现有 `.ve-scope .ve-tab`（那是**左栏图标 tab**，勿混）之外，给 pill 形态的 `[role=tab]` 补一节
  `ve-theme.css` 规则（当前 pill 样式散在 `ui/ui/tabs.tsx` 的 className 里，可保留为 className，因为它是 Tailwind 作者样式、无优先级冲突）。
- **必须同步改的守卫**：`tests/unit/vePanelLayoutContract.test.ts` 现有判据是「`ui/ui/tabs.tsx` 含 `data-[state=inactive]:hidden`」——
  自研落地后该判据**改为**「`TabsContent` 实现体里存在"非激活即不渲染"的提前 return，且 `ui/ui/tabs.tsx` 不再出现 `radix-ui`」。
  （判据要判"代码做了什么"，不是"文件里出现了什么词"。）

### C 级 —— 弹层 / 焦点 / 键盘（重头，建议**一个原语一个 PR**）

**共用基座（先做，其余复用）**：建议新增 `ui/ui/layer/`（唯一层根与定位原语）：

```
ui/ui/layer/
├─ layer-root.tsx      # 层根：EditorShell 内挂一个，供 createPortal
├─ use-anchored-position.ts   # 触发元素 rect → 计算 fixed 坐标 + 视口碰撞翻转（top/bottom、start/end）
└─ use-dismissable.ts  # Escape + 点击外部（pointerdown capture，需排除触发元素自身）
```

| 原语 | 自研要点 | 危险点（必须验） |
| --- | --- | --- |
| `tooltip` | hover + focus 触发；`delayDuration`；`side`/`align`/`sideOffset`（现有 4 处用到）；非 Portal 也可（放在层根更稳） | 不要吞掉子元素事件；`TooltipProvider` 提供 delay 上下文 |
| `popover` | 点击触发 + 定位 + dismissable | 内部点击不关闭；关闭后焦点归还触发元素 |
| `dropdown-menu` | `role=menu/menuitem`；上下键 + Home/End + Escape；点击项后关闭并**归还焦点** | **绝不把需要用户手势的命令式动作（如 `input.click()`）挂在菜单项上** —— Radix 时代已踩过（菜单选中同步关层 + FocusScope 归还焦点 → 手势栈失效 → 浏览器静默丢弃）。`assets/views/media.tsx` 的「导入」已改为直连，**不要回退** |
| `context-menu` | 右键坐标定位（`clientX/Y`）+ 同上键盘 | 与 `dropdown-menu` 共用一份列表实现（**别写第二份**） |
| `select` | `role=listbox/option`；触发键（Enter/Space/方向键）+ 键盘高亮 + 点击外部关闭；受控 `value/onValueChange`；`SelectValue` 的 placeholder 行为 | 需要"面板内展开不 Portal"的变体 → 已有先例 `font-picker.tsx`（**照它写，不要另立一套**）；滚动到选中项 |
| `dialog` | 层根 Portal + 遮罩 + **焦点陷阱**（首个可聚焦 + Tab 循环）+ Escape + 关闭归还焦点；`role=dialog` + `aria-labelledby` | 与画布 `modalLayer` 的关系：编辑器是全屏层，**不要**误改画布侧判据（`isCanvasSuppressed()` 已收口，见 TD-22-19） |
| `button.tsx` 的 `asChild` | 自研 `Slot`：`React.cloneElement(children, mergedProps)` 合并 className/props（**18 个消费方零改动**） | `Slot` 要合并 onClick 与 className（不是覆盖） |

## 七、风险与回退

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 弹层 a11y 回归 | 自研易丢 aria/焦点管理 | 每个原语保留 `role` + `aria-*` 清单（见四.C），并加行为锁测试 |

| 一次改太大 | 回归难定位 | 按第五节 6 步，一步一 PR；每步全绿再动下一步 |
| 回退 | 某原语自研失败 | 该原语**单独**回退到 Radix（保留依赖），其余不受影响 —— 所以**最后一步才删依赖** |
