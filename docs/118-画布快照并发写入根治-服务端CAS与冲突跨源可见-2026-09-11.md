## 〇、先说清楚这个方案管什么、不管什么

→ `117 §4.4`（"裁剪/扩图看起来像没变"）已被用户明确否决，**不作为结论**，本文与 117 同步撤回。

**顺带收口**：本计划把「版本真源」「画布落盘调度」「图片写回出口」三项**与本次根因同源**的收口一并做掉（见 §七 档 1）；

## 一、治本判据（三条不变量，做完了必须成立）

| # | 不变量 | 保障手段 |
|---|---|---|
| **I1** | 陈旧实例**永远写不进**快照（无论触发点是"平移视窗"还是"改节点"，无论内容多大） | 服务端**原子 CAS**：`POST /api/kv/set { ifVersion }`，版本不符 → 409 且**一个字节都不写** |
| **I2** | 冲突在**所有形态**下可见（跨源/跨浏览器/打包进程/多设备） | 服务端版本轮询兜底（3s）+ 同源 `BroadcastChannel` 即时 |
| **I3** | 快照里**不出现 MB 级 dataURL** | 编辑器保存出口与压缩/放大统一走 `saveInlineToLocal` → 快照只留 `/files/` 路径 |

**现状为什么三条都不成立**：
1. `saveCanvasState` 用 `Date.now()` 比大小当"防旧覆盖新"（`projectStore.ts:362-373`）——两实例后写的一定更大 → **永远通过**；且读版本/写版本是两次独立请求，本身有 TOCTOU 窗口。
2. `useCanvasSync` 只靠 `BroadcastChannel`（`hooks/useCanvasSync.ts:39-62`）——**不跨 origin**；红条（`App.tsx:1459`）跨源恒不出现（实测 `false`）。
3. `handleEditorSave` 把 `toDataURL('image/png')` 的 MB 级字符串直接塞进 `node.data.imageUrl`（`useImageHoverActions.tsx:69-76`），靠后端 `base64Externalize` 兜底。

## 二、设计总览

```
写路径（改）
  App.persistCanvas  ← autoSave(600ms) / viewportMoveEnd(600ms)
        │
        ▼
  projectStore.saveCanvasState(req)
   ├─ ① 同窗口串行化：单飞队列（防自己撞自己 → 假冲突红条）
   ├─ ② kvSet(key, payload, { ifVersion: loadedVersion })      ← 唯一裁决点（服务端）
   └─ ③ 结果落地
        ok       → loadedVersion = data.version ；返回 { success:true }
        conflict → 不重写、不重试 → 返回 { success:false, skipped:true, conflict:true, conflictVersion }
                    App 收到 → setCanvasConflict(true) → 红条（点击刷新，保持现状）

读路径（改）
  projectStore.loadCanvasState(projectId)
   ① GET <key>_version → v1
   ② GET 快照
   ③ GET <key>_version → v2
      v1 !== v2 → 重试（≤3 次）；仍不稳 → 置冲突态、loadedVersion 取最后一次 v2（宁假冲突不假通过）
   → loadedVersion = v1

冲突可见（新增）
  useCanvasSync：页面 visible 时每 3s  GET /api/kv/version?key=<canvas key>
                 remote > getLoadedVersion() → setCanvasConflict(true)
  BroadcastChannel：保留（同源 <1s 即时）

服务端原子原语（唯一能真正防住的地方）
  POST /api/kv/set { key, value, ifVersion? }
    ifVersion === undefined  → 无条件写（导入/迁移/强制），版本自增，返回新版本
    ifVersion !== 当前 <key>_version → 409 { error:{code:'conflict'}, current }，不写
    ifVersion === 当前版本            → 写 value；<key>_version = max(Date.now(), cur+1)；返回 { ok, version }
```

### ★ 原子性红线（必须写进代码注释）

`const db = await getDb()` **之后**再读版本 → 比较 → 写 value → 写版本，**全程不得出现任何 `await`**。
sql.js 是内存库、API 全同步，Node 单线程事件循环保证这段不被其它请求插入 → 天然 CAS。
**一旦中间插了 `await`（包括 `fetch`/文件 IO/`contentSetAsync`），就退化成 TOCTOU，本方案失效。**

### S1. `localTool/src/routes/kv.ts` — `handleKvSet` 支持 `ifVersion`，并新增 `handleKvVersion`

```ts
export async function handleKvSet(req: IncomingMessage, res: ServerResponse): Promise<void> {
  const body = (await parseJsonBody(req)) as
    | { key?: string; value?: unknown; ifVersion?: number }
    | null;
  if (!body || typeof body.key !== 'string') return sendError(res, 'Missing key field', 400);

  const db = await getDb();
  const versionKey = `${body.key}_version`;

  // ★★★ 以下到 return 之间禁止任何 await：原子 CAS 全部依赖这段同步执行 ★★★
  const curRow = queryOne(db, 'SELECT value FROM kv WHERE key = ?', [versionKey]) as
    | { value?: string }
    | undefined;
  const cur = curRow?.value ? parseInt(String(curRow.value), 10) || 0 : 0;

  if (body.ifVersion !== undefined && body.ifVersion !== cur) {
    // 冲突：value 与 version 都不动（一个字节都不写）
    return json(res, { error: { code: 'conflict', message: '版本冲突' }, current: cur }, 409);
  }

  const value = typeof body.value === 'string' ? body.value : JSON.stringify(body.value);
  const finalValue = externalizeBase64InValue(value); // 保持现状（同步）
  const next = Math.max(Date.now(), cur + 1);

  run(db, 'DELETE FROM kv WHERE key = ?', [body.key]);
  run(db, 'INSERT INTO kv (key, value, updated_at) VALUES (?, ?, unixepoch())', [body.key, finalValue]);
  run(db, 'DELETE FROM kv WHERE key = ?', [versionKey]);
  run(db, 'INSERT INTO kv (key, value, updated_at) VALUES (?, ?, unixepoch())', [versionKey, String(next)]);
  debouncedSaveDb();
  return json(res, { code: 0, data: { ok: true, version: next } });
}

/** GET /api/kv/version?key=<key> → { code:0, data:{ version } }（轻量：只读 _version，不拉整包） */
export async function handleKvVersion(req: IncomingMessage, res: ServerResponse, url: URL): Promise<void> {
  const key = url.searchParams.get('key');
  if (!key) return sendError(res, 'Missing key parameter', 400);
  const db = await getDb();
  const row = queryOne(db, 'SELECT value FROM kv WHERE key = ?', [`${key}_version`]) as
    | { value?: string }
    | undefined;
  const version = row?.value ? parseInt(String(row.value), 10) || 0 : 0;
  return json(res, { code: 0, data: { version } });
}
```

- **信封保持 `code-data`** → `apiRegistry.kvSet` 的 `envelope` 不用改。
- `ifVersion` 缺省 = 旧行为（无条件写 + 版本自增）→ **现有 `kvSet` 调用点全部零改动**。
- 409 用 `json(res, …, 409)` 而非 `sendError`：前端要读 `current`。

```ts
/** kv 写入结果（信封 code-data；version = 服务端写入后的快照版本） */
export interface KvSetResult {
  code?: number;
  data?: { ok?: boolean; version?: number };
}

// POST /api/kv/set { key, value, ifVersion? }
// ifVersion 传入 = 乐观并发写入（CAS）：服务端版本不等于它时返回 409 且不写任何内容。
export async function kvSet(
  key: string,
  value: unknown,
  opts: { ifVersion?: number } = {},
): Promise<KvSetResult> {
  return httpRequest(`${API_BASE}/api/kv/set`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ key, value, ...(opts.ifVersion !== undefined ? { ifVersion: opts.ifVersion } : {}) }),
    label: 'kvSet',
  });
}

/** GET /api/kv/version?key=… → 版本号（读不到按 0；轻量端点，别用 kvGet 拉整包做心跳） */
export async function kvGetVersion(key: string): Promise<number> {
  const res = await httpRequest<{ data?: { version?: number } }>(
    `${API_BASE}/api/kv/version?key=${encodeURIComponent(key)}`,
    { label: 'kvGetVersion' },
  );
  const v = res?.data?.version;
  return typeof v === 'number' && Number.isFinite(v) ? v : 0;
}
```

- `kvSet` 返回类型由 `OkResult` 变 `KvSetResult`：**现有调用点都忽略返回值**（`await kvSet(...)`），无破坏。
- 冲突识别统一用 `httpClient` 已导出的 `HttpError.status === 409`（4xx 不重试，已是现状）。

### C1. `projectStore.ts` — CAS 基线 `loadedVersion` + 读路径

`loadCanvasState(projectId)`：在原有读快照前后各读一次版本（**先版本、后内容、再版本**）：

```ts
const key = CANVAS_STATE_PREFIX + (projectId || currentProjectId);
let v1 = await kvGetVersion(key);
let v = await contentGetAsync(key);
let v2 = await kvGetVersion(key);
for (let i = 0; i < 3 && v1 !== v2; i++) {          // 读期间被人改过 → 重读（≤3 次）
  v1 = v2;
  v = await contentGetAsync(key);
  v2 = await kvGetVersion(key);
}
loadedVersion = v2;                                  // 不稳时取最新，宁假冲突不假通过
```

> **顺序为什么是「先版本后内容」**：这样 `loadedVersion ≤ 我持有的内容版本`，最坏是**假冲突（拒绝写 + 提示刷新）**；反过来会出现"我把别人的新写入当自己的基线 → CAS 通过 → 又覆盖别人"，那是**静默丢数据**。
> 副作用：页面加载瞬间若恰好有人写入，首次保存可能被拒 → 红条提示刷新。属预期（fail-closed）。

> 需要的导入：`projectStore.ts` 既有 `import { fetchProjects, saveProjects, … } from '../api/localToolApi.ts'` → 追加 `kvGetVersion`（`kvSet` 同文件）。

### C2. `projectStore.ts` — `saveCanvasState` 改走服务端 CAS

```ts
interface SaveCanvasResult {
  success: boolean;
  skipped?: boolean;
  conflict?: boolean;        // ★ 新增：因版本冲突被拒（当前窗口本次改动未落盘）
  conflictVersion?: number;
}

let saveChain: Promise<SaveCanvasResult> = Promise.resolve({ success: false, skipped: true });

/**
 * 保存画布快照。
 * ★ 串行化：同一窗口单飞，后到的排队（执行时才读 loadedVersion）——避免自己两次写互相判冲突。
 * ★ CAS：ifVersion = loadedVersion；服务端不符 → 409 → 本次不落盘（fail-closed，绝不覆盖别人的新数据）。
 * @param opts.force 无条件覆盖（仅备份导入用；服务端仍会把版本自增）
 */
export function saveCanvasState(projectId, nodes, edges, viewport?, opts: { force?: boolean } = {}) {
  const run = async (): Promise<SaveCanvasResult> => {
    // …空画布跳过（保持现状）、sanitize/normalize（保持现状）…
    try {
      const res = await kvSet(key, payload, opts.force ? {} : { ifVersion: loadedVersion });
      loadedVersion = res?.data?.version ?? loadedVersion;   // ★ 成功即成为新基线
      return { success: true, skipped: false };
    } catch (e) {
      if (e instanceof HttpError && e.status === 409) {
        const remote = Number((e.data as { current?: number })?.current) || 0;
        logger.warn('projectStore', '画布快照版本冲突，已拒绝覆盖', { key, remote, loaded: loadedVersion });
        return { success: false, skipped: true, conflict: true, conflictVersion: remote };
      }
      logger.warn('projectStore', '保存画布快照失败（KV 不可用？）', e?.message);
      return { success: false, skipped: false };
    }
  };
  saveChain = saveChain.then(run, run);                 // 单飞：串起来，别并发
  return saveChain;
}
```

**同时删除**（形成两份真相的东西）：
- 需要新增 `import { HttpError } from '../api/httpClient.ts';`（409 判定用；`httpRequest` 对 4xx 不重试，是现状行为）；
- 旧的 `const remoteVer = await contentGetAsync(key_version); if (remoteVer > version) …`；
- 客户端自己算版本 + 单独写 `<key>_version` 的两行（版本所有权移交服务端）；
- 模块级 `lastSavedVersion`（不再需要）。

### C2b. `projectStore.ts` — 落盘调度收口 `scheduleCanvasSave`（档 1 ②）

**收什么**：`App.tsx` 现有**两个 600ms 防抖入口**（`autoSave` 内容变更 `:426`、`handleViewportMoveEnd` 视窗变更 `:440`）各自持一个 timer + 各自直调 `persistCanvas`。收成一个调度器 → "何时写、写什么、写哪个版本"只剩一个答案点。

```ts
// ── 画布落盘调度器（唯一落盘入口）──
interface CanvasSaveReq {
  projectId: string;
  nodes: unknown[];
  edges: unknown[];
  viewport: unknown;
}
let saveTimer: ReturnType<typeof setTimeout> | null = null;
let pendingReq: CanvasSaveReq | null = null;

/** 请求落盘（防抖合流 + 最新胜）。内容变更与视窗变更共用同一个定时器，语义与现状的 600ms 一致。 */
export function scheduleCanvasSave(req: CanvasSaveReq, delayMs = 600): void {
  pendingReq = req;
  if (saveTimer) clearTimeout(saveTimer);
  saveTimer = setTimeout(flushCanvasSave, delayMs);
}
/** 立即落盘（pagehide / 切项目 / 卸载兜底）。 */
export function flushCanvasSave(): Promise<SaveCanvasResult> | void {
  if (saveTimer) { clearTimeout(saveTimer); saveTimer = null; }
  const r = pendingReq;
  pendingReq = null;
  if (!r) return;
  return saveCanvasState(r.projectId, r.nodes, r.edges, r.viewport).then((res) => {
    broadcastCanvasSaved(r.projectId); // ★ 原来的 BroadcastChannel 广播挪到这里（同源即时冲突提示别丢）
    return res;
  });
}
```

### C4. `useCanvasSync.ts` — 服务端版本轮询（跨源兜底）

```ts
// 3s 轮询远端版本；仅页面可见时轮询（后台窗口不轮询，避免把挂着的旧窗口当冲突源）。
// 用途：BroadcastChannel 不跨 origin（打包版 18080 ↔ 开发口 5180、不同浏览器、多设备），

    const pid = getProjectIdRef.current?.();

    try {
      const remote = await kvGetVersion(CANVAS_STATE_PREFIX + pid);

  return () => {

    document.removeEventListener('visibilitychange', tick);
```

```ts
const handleEditorSave = useCallback(
  async ({ dataUrl, width, height }) => {
    if (!dataUrl) return;
    const dims = width && height ? { width, height } : undefined;
    onImageReplaced?.(dataUrl, dims);                       // ① 立即生效（不等网络）
    setEditor(null);
    const saved = await saveInlineToLocal(dataUrl, 'canvas'); // ② dataURL → /files/ 持久 URL（幂等）
    if (saved && saved !== dataUrl) onImageReplaced?.(saved, dims); // ③ 快照只留 KB 级路径
  },
  [onImageReplaced],
);
```

- 与压缩/放大**完全同构**（同一出口、同一幂等语义、失败保留原 dataURL）；
- 就地裁剪 `handleCropSave` 一并同构（它现在同样把 dataURL 直接写回节点）；
- 收益：快照体积从 MB 降到 KB → CAS 上报体积小、冲突窗口小、不再依赖后端外置兜底；
- 两次 `onImageReplaced` 必须幂等（现状已是覆盖写；`dims` 相同 → `fitByRatio` 第二次被 4px 守卫拦住，无副作用）。

### C5b. `nodeImage.ts` — 图片写回收口 `replaceNodeImage`（档 1 ③）

**收什么**：现在"把新图写回节点"有 **2 处各自实现**（`ImageGenerate.onImageReplaced`、`AssetNode.replaceImage`），且字段已经漂移（前者只写 `imageUrl`，后者 `imageUrl` + `url` 双写）。

**新建 `src/components/nodes/nodeImage.ts`**：

```ts
import type { Node } from '@xyflow/react';

export interface NodeImageWrite {
  id: string;
  dataUrl: string;
  dims?: { width: number; height: number };
  /**
   * 存量兼容开关：该节点历史上写过 data.url（AssetNode 渲染读 url）→ 传 true 同步写 url。
   * 读侧目前仍兼容 4 形态（getNodeImageUrl），所以本提交**不停止写 url**；
   * 「字段唯一化」属档 2（先改读侧，再停写侧），别在这里一次删干净。
   */
  legacyUrlField?: boolean;
}

/**
 * 节点「主图」唯一写入口。只做两件事：写字段 + （可选）回传 dims 给调用方自己的尺寸模型。
 * ⚠️ 不统一尺寸/比例逻辑：ImageGenerate 用 fitByRatio + aspectRatio:'Auto' + editedRatioRef，
 *    AssetNode 用 mediaRatio（`${w}:${h}`）——两者模型不同，硬合并会改行为。尺寸仍由调用方在
 *    afterWrite(dims) 里处理。
 */
export function replaceNodeImage(
  { id, dataUrl, dims, legacyUrlField }: NodeImageWrite,
  setNodes: (updater: (ns: Node[]) => Node[]) => void,
  afterWrite?: (dims?: { width: number; height: number }) => void,
): void {
  setNodes((ns) =>
    ns.map((n) =>
      n.id === id
        ? {
            ...n,
            data: { ...n.data, imageUrl: dataUrl, ...(legacyUrlField ? { url: dataUrl } : {}) },
          }
        : n,
    ),
  );
  afterWrite?.(dims);
}
```

**接入点（4 处，全部经它 → 结构上不可能"某条路径忘了落盘"）**：
| 接入点 | 改动 |
|---|---|
| `ImageGenerate.onImageReplaced` | 内部改调 `replaceNodeImage(..., afterWrite: (d) => { if (d) { editedRatioRef.current = true; fitByRatio(d.width, d.height); setAspectRatio('Auto'); } })`；`patchData({aspectRatio:'Auto'})` 保留（它写的是 aspectRatio 不是图） |
| `AssetNode.replaceImage` | 改调 `replaceNodeImage({ ..., legacyUrlField: true }, ..., afterWrite: (d) => d && setMediaRatio(`${d.width}:${d.height}`))` |
| `useImageHoverActions.handleEditorSave` | 不直接写节点：先 `onImageReplaced` 立即生效 → `saveInlineToLocal` → 再 `onImageReplaced`（C5 已定） |
| `useImageHoverActions.handleCropSave` | 同上（就地裁剪也要落盘，否则又是"两条改对两条忘"） |

> 护栏（档 2 一起加更合适，但建议本次就先加一条 grep 门禁/单测）：`src/components/nodes/*` 内**不得再出现** `imageUrl:` 直写，必须走 `replaceNodeImage`。

### 7.2 档 1：与本次**同一个根因**，一起做

| 项 | 为什么必须一起做 |
|---|---|
| **① 版本真源归服务端** | 本方案主体（§三/§五 C1·C2）：两份版本 = 两份真相，且客户端那份永远通过 |
| **② 落盘调度收口成一个** | 收口形态：`projectStore.scheduleCanvasSave(req)`——store 内**单防抖 + 单飞**，内容变更与视窗变更**合流成一次写**；App 只说"我要保存"。收益：删掉 App 两个 timer/两个 ref，"何时写、写什么、写哪个版本"**只剩一个答案点**。而"平移视窗就整包覆盖别人"正是从这个双入口面漏出来的 |
| **③ 图片写回收口成 `replaceNodeImage`** | 新增 `src/components/nodes/nodeImage.ts`：`replaceNodeImage({ id, dataUrl, dims, setNodes })` 唯一负责"写 imageUrl（+读侧兼容的 url）+ 按 dims 自适应节点比例"。两个节点的 `onImageReplaced` 与 `handleEditorSave`/`handleCropSave` 全部经它 → **结构上不可能出现"某条路径忘了落盘"**（历史漂移：生图节点 crop 按钮漏写 onClick） |

### 7.3 档 2：顺手做，但**独立提交**（机械替换、可单测、无行为变化）

| 项 | 做法与边界 |
|---|---|
| ④ 9 处内联 `patchData` → 复用 base `useNodeData` | 先 `ImageGenerate`/`AssetNode` 试点，验证后批量替换；纯等价替换 |
| ⑤ 图片字段唯一化（**分层收口**） | 读侧**保留** 4 形态兼容（存量快照里真有 `url`/`images`，删就读丢）；**写侧只允许走 `replaceNodeImage`**，并加护栏测试锁死"新增写不得绕过它"。不是"一次删干净" |

### 7.4 档 3：**不混进来**（另开专项）

- ❌ **68 处节点 data 直写全量统一**：爆炸半径 = 全节点回归。与"协议级数据丢失修复"混在一个提交里，出事**无法二分**（是 CAS 的锅还是收口的锅）。
- ❌ 快照拆表 / 字段级版本 / CRDT（见 §十）。

### 7.5 顺序：**先上 CAS（把门装上），再收口（把门挪到对的位置）**

反向的风险很具体：收口是重构、会产生大量改动；先重构再修数据丢失，**中间任何一次提交都可能把丢失面扩大**，且故障无法二分。
所以：档 1 的第 ① 项先落地，②③ 紧随（同一批改动的自然延伸）；档 2 延后。

## 九、风险与取舍

| 风险 | 说明 | 处置 |
|---|---|---|
| **冲突后本窗口改动确实不落盘** | 治本的必要代价（宁可显式失败，不可静默覆盖） | 红条文案明说"本次改动未落盘 + 点击刷新"；后续可做"节点级合并"或"冲突后另存为新项目" |
| **假冲突**（页面加载瞬间别人正好写入） | 概率低（ms 级窗口）+ 只影响首次保存 | fail-closed 是刻意选择；重试 3 次已覆盖大部分抖动 |
| **自撞假冲突**（autoSave 与 viewport 落盘并发） | 会误弹红条 | 用 C2 的**同窗口单飞**消掉 |
| **轮询开销** | 3s 一次轻量 GET，仅可见页面 | 端点只读 `_version`（不拉整包）；已入 `SILENT_LOG_PATHS`；必要时可拉长到 5s |
| **旧打包版前端 + 新后端** | 旧前端不传 `ifVersion` → **仍可无脑写**（兼容期存在） | 服务端 `ifVersion` 缺省=旧行为是**刻意**的兼容；上线后尽快更新打包版；若要强推，可加"仅当请求带 ifVersion 才允许写 canvas 前缀键"的开关 |
