# 测试覆盖补齐计划（2026-08-17）

> 基于前一轮「测试覆盖缺口梳理」结果制定。整体原则：**优先补齐高风险、纯逻辑、易落地的模块**，
> 对依赖浏览器重环境（mediabunny / mediapipe / canvas 渲染）的模块只测「可纯逻辑剥离」的部分，
> React 组件交互测试放到最后阶段（依赖 jsdom + RTL 环境搭建）。

## 背景

当前测试体系（`tests/unit/` 40 文件 + `localTool/test/` 3 文件 + `tests/e2e/` 4 spec）偏向纯函数/store 层。
经排查，以下大类**基本无测试**，按风险排序：

1. localTool 后端路由/工具（logs/projects/fileStore/logWriter/netProxy/index）
2. base 纯算法/逻辑模块（videoEngine/faceMosaic/promptManager/pollTask/resourcesApi 等）
3. 业务桥接 hook（useAssetDropPaste/useArrangeCanvas/useContextMenu 等）
4. settings 整目录
5. 大型业务节点组件（12+ 个零单测）
