## 0. 背景与目标（先读，理解为何这么改）

### 0.1 为什么补 schema 严谨度

我方 22 个画布工具喂给 LLM 的 `parameters`（OpenAI function calling schema）**普遍偏宽松**：

- 顶层几乎都不写 `additionalProperties: false` → LLM 会塞入没定义的字段、字段名打错。
- `batch_create_nodes.nodes`、`execute_plan.generations` 等数组的 `items` 多是空壳 `{ type: 'object' }` → 模型只能靠 `description` 文字猜每个字段，命中率低。
- `required`/`enum`/`minLength` 用得参差。

**这是纯提示层优化**：经核验，`buildCanvasAgentToolSchemas()` 只把 `t.parameters` 透传给 LLM，**全仓无任何代码在 execute 前用 `parameters` 对 args 做本地校验**（搜 `additionalProperties` / `validateAgentToolInput` / `parameters.required` 均零命中）。所以补严谨**绝不改变执行行为**，只改变喂给模型的约束文本。

### 0.2 参考对象怎么写的（借鉴点）

AI-Canvas-tauri 的工具 schema（`toolRegistry.ts` + `tools/*.ts`）几乎每个都带：

```ts
parameters: {
  type: 'object',
  additionalProperties: false,      // ← 核心：只许列出的字段
  required: ['assetId'],             // ← 真必填
  properties: {
    assetId: { type: 'string', minLength: 1, maxLength: 160 },
    kind:     { type: 'string', enum: ['character', 'scene', 'prop'] },  // ← 封闭集合用 enum
  },
}
```

其 description 风格（对比 `media_generate`、`dramaAssetTools`）：
- 一句话讲清「这个工具做什么」；
- **带负向边界**，明确「何时**不要**用」（如 `media_generate` 描述末句「普通问答不得调用」）；
- 能用 schema 结构约束的（enum/required/minLength）就**不再用长 description 罗列取值范围**。

> ⚠️ 注意：本仓库 `useCanvasAgentTools.ts` 文件头有既定「**工具描述平等原则**」（所有工具句式、详略一致，只讲「AI 该怎么用」，不泄露内部机制）。**学习对方的是「加负向边界 + 用 schema 而非长文约束取值」的精神，不是照搬对方的极简篇幅或中英混排风格**。改 description 必须在既有"一句讲清做什么 + 何时用"的基础上，**只增补「何时不用」一句**，不做整句推翻。

### 0.3 铁律（任何一条破防即返工）

1. **零行为改动**：只改 `parameters` 对象字面量 + 工具 `description` 字符串；**绝不动** `execute` / `name` / 注册表顺序 / `MUTATING_TOOLS` / 各工具内部校验逻辑。
2. **单一文件**：只在 `src/components/agent/canvas/useCanvasAgentTools.ts` 改；不新增文件、不引依赖。
3. **开放字段不锁 enum**：`resolution`（720p/1080p/1440p/2K/4K 会被 `normalizeResolution` 归一到 1K/2K/4K）与 `aspectRatio`（任意比例）**不设 enum**，否则误伤用户自定义值；这类继续用 description 说明可选值，只加 `additionalProperties:false`。
4. **description 只增负向边界**，不删既有「怎么做/传什么」信息（对齐文件头"描述平等原则"），避免过度精简丢信息。
5. **格式合法**：`additionalProperties` 与 `type/properties/required` 平级；空 `properties: {}` 的工具（read_canvas 等）也加 `additionalProperties:false`（语义=该工具不接受任何参数）。
6. **改完跑门禁**：`npm run type-check` + `npm run test:unit`（含 `useCanvasAgentTools.test.ts` / `canvasAgentTools.test.ts` / `useAgentChat.hook.test.ts`）+ `npm run build`，确认无回归。
7. **文件头 JSDoc 补一行决策记录**（对齐 CLAUDE.md 铁律）：注明本次批量 schema 补严 + 描述负向边界，标注「零行为改动，纯提示层」，附背景编号。

## 1. 改动契约（逐工具）

> 每个工具下面给「①加 `additionalProperties:false`（凡带 properties 的 object 顶层必加）」；「②description 若标『+边界』则在其末尾补一句『何时不用』」。除特别标注外，`required`/已有 `enum` 保持现状，不新增字段、不改字段名。

**改什么**：这几个 `parameters` 形如 `{ type: 'object', properties: {}, required: [] }`。补成：

```ts
{ type: 'object', additionalProperties: false, properties: {}, required: [] }
```

**description**：现已有说明，**不加边界**（本身无参、语义清晰）。

### 1.1 `get_node_details`（读单节点）

**改什么**：顶层加 `additionalProperties:false`（现为单行 `{ type: 'object', properties: { nodeId: { type: 'string' } }, required: ['nodeId'] }`）。
**description**：已带「⚠️ 只返回结构化数据，不含画面内容；分析图片请直接看图，不要调用本工具」——已是负向边界范例，**保持**。

### 1.2 `read_storyboard`

**改什么**：顶层加 `additionalProperties:false`；`rowId` 补 `minLength: 1`（可选，防空串）。
**description**：已带「仅当需要查看当前选中行以外内容时才调用；一般场景无需调用」——已有边界，**保持**。

### 1.3 `create_node`

**改什么**：顶层加 `additionalProperties:false`（现为多行对象）。`type` 已有 enum **保持**；`resolution`/`aspectRatio` 开放（铁律 3），继续 description 说明。

### 1.7 `update_node`

### 1.13 `execute_plan`（重点）

**改什么**：
- 顶层加 `additionalProperties:false`。
- `generations.items` 由空壳 `{ type: 'object' }` 收敛为子 schema，覆盖既有 description 已承诺的字段：`id` / `title` / `prompt`(必填) / `ratio` / `resolution` / `depends_on_previous`(boolean) / `dependency_mode`(enum: `none|product_reference|fusion`) / `use_attachments`(boolean) / `attachment_indices`(array<int>) / `direct_refs`(array)。给这些字段补 `additionalProperties:false` 与合理 `required`（`prompt` 建议必填；其余可选）。⚠️ **子 schema 必须与 execute 侧实际解析的字段完全一致**（见 execute 里 `g.depends_on_previous / g.use_previous_results / g.dependency_mode / g.direct_refs / g.attachment_indices / g.prompt / g.id / g.title`），**不要**把 execute 不读的字段（如 count/type/role）写进去，避免误导。
- `artifacts.items` 由空壳收敛：`{ type:'object', additionalProperties:false, properties:{ id, type, title, description, nodeId?, url? } }`（对齐既有 description 已承诺结构）。
- `auto_run` / `model` / `referenceImages` 保持，顶层 additionalProperties 已覆盖。
- `required` 保持 `[]`（generations 主通道是阶段1暂存，勿改为必填——见 execute 内注释与 show_plan 描述）。

**description**：**这是本批重点优化对象**。现 description 极长（约 5 行、信息密度高但几乎无负向边界）。学习对方精神，做「保留信息 + 加边界 + 略瘦身」：
1. 首句保留「按计划批量建节点并生成（多图/多步骤）」。
2. 保留「引用参考图两种方式（attachment_indices / direct_refs）」这一段（这是执行关键，删了模型会乱）。
3. **末尾追加负向边界**（对齐 CANVAS_RULES 与 execute 内逻辑）：「一次只针对用户当前要的那批图/那件事；若阶段1已完成策划暂存，这里可不传 generations（系统自动从暂存读取）；不要重复触发已提交的生成。」（后半句对齐既有注释「生成即完成，不要重复触发」。）
4. 不改内部执行细节描述过多的问题——只增边界、控篇幅，**不逐句重写**（铁律 4）。

### 1.14 `show_plan_for_confirm`

**改什么**：顶层加 `additionalProperties:false`；`generations.items`/`artifacts.items` 收敛逻辑同 execute_plan（可复用同一份子 schema 结构，但注意本工具 generations 是「仅冗余兜底」，见其 description）。

## 2. description 增补的「边界句」措辞对照

> 统一风格、句式平等（文件头"描述平等原则"）。给执行 AI 一个可直接复制的措辞池，避免每个 AI 写出不同风格。

| 工具 | 建议追加的负向边界句（放 description 末尾） |
|---|---|
| `create_node` | 「只按用户明确要求建对应类型的节点，不擅自批量建同类节点。」 |
| `update_node` | 「只改用户要求改的字段；不改白名单之外的 data。」 |
| `generate_node` | 「节点须已有提示词才触发生成；不要为空白节点盲目生成。」 |
| `execute_plan` | 「一次只针对用户当前要的那批图；若阶段1已暂存策划则可不传 generations，系统自动取；提交后不要重复触发。」 |

> 其余工具 description 已自带边界或语义天然清晰，**不再改动**（避免大改破坏平等句式，铁律 4）。

## 3. 关键防线（红线）

1. **零行为改动**：凡改到会改变执行结果的地方（execute 内、字段名、新增参数导致 execute 读错）都算翻车。`additionalProperties` 只进 `parameters` 对象。
2. **不误伤开放字段**：`resolution`/`aspectRatio`/`patch`/`model` 一律不设 enum、不设 additionalProperties=false（如 `update_node_any_field.patch` 语义即任意字段）。
3. **子 schema 字段与 execute 读字段严格一致**：尤其 `execute_plan.generations.items` 只写 execute 实际解析的键，多写一个 execute 不认识的键 = 误导模型。
4. **`execute_plan` 的 `required` 保持 `[]`**：generations 主通道是阶段1暂存（回复正文/show_plan），改成必填会让模型把 11 个长 prompt 硬塞 tool_calls.arguments 导致 SSE 解析失败（既有注释红线）。
5. **description 只增不推倒**：学习对象「负向边界」精神，但遵守本仓库"描述平等 + 只讲怎么用"原则；逐句重写对方极简风格 = 违背文件头决策注释。
6. **无副作用依赖**：不引第三方 schema 库；`parameters` 仍是纯对象字面量，`buildCanvasAgentToolSchemas()` 无需任何改动。
7. **门禁**：`npm run type-check` + `npm run test:unit` + `npm run build`；尤其 `useCanvasAgentTools.test.ts`（断言 tools 行为 + schema 顶层 function 格式，不被 additionalProperties 影响）、`canvasAgentTools.test.ts`、`agentLogic.test.ts`（断言 `你是猫猫画布助手` system 文本，无关本文件）。
