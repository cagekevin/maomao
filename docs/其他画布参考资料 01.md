# AIFISHER 开发踩坑记录（实战故障版）

> 这不是一份功能说明，而是把 AIFISHER 作者**在线上真实踩过的坑**按"故障场景"拆开：
> 什么条件下触发、当时会怎样崩/错、他最后怎么修的、我们做类似东西时要注意什么。
> 所有结论都来自源码里的防御性代码与注释，不是猜的。
> 配套总览见各模块注释；这里只挑"会咬人"的。

## A. 媒体本地化：工作流输出进素材库的一整条雷区

文件：`server/workflowRuntime/workflowOutputLocalizer.js` + `workflowMediaCompatibility.js`
+ `comfySavedOutputs.js`

这是踩坑最密集的一块。作者的目标：把 ComfyUI / RunningHub 跑出来的东西安全、可播地
存进画布素材库。

### A.1 RunningHub CDN 竞态：任务完成 ≠ 文件可读
```js
// RunningHub can publish the task result before its CDN object is readable.
// Retrying this download is safe: it never resubmits the paid workflow task.
for (let attempt = 1; attempt <= 3; attempt += 1) { ... await wait(400 * (2 ** (attempt - 1))); }
```
**触发**：任务状态已经 success，但 CDN 对象还没同步好，`openOutput` 拿到 403/超时。
**坑**：如果重试会"重提付费任务"就完了（重复烧钱）。作者特意确认 RunningHub 的输出
下载是**幂等只读**的，才敢重试 3 次、指数退避（400/800/1600ms）。
**对我们的启示**：任何"先标记完成、后文件可见"的远程存储，下载都要幂等重试，且必须
先证明"重试不会触发二次计费"再加重试。

### A.2 浏览器播不了的格式：源格式只在转换层收
```js
// Extra source formats are accepted only here. Published assets still use browser formats.
```
作者列举了所有"ComfyUI 可能吐出来、但画布/浏览器播不了"的格式，单独处理：
`TIFF` / `AVIF`（图像）、`AIFF` / `CAF` / `AC3`（音频）、`AVI` / `ASF` / `FLV` /
`MPEG` / `TS`（视频容器）、`Ogg`（可能含 Theora 视频）。
**坑**：ComfyUI 自定义节点输出什么格式都有可能。如果直接当成品存，前端要么播不了，
要么把 `application/octet-stream` 当视频渲染。
**修法**：`inspectWorkflowMedia` 按文件头魔数识别这些格式，标成 `.source-video` /
`.source-audio` / `.tiff` / `.avif`，再在 `prepareWorkflowCompatibility` 里用 ffmpeg /
sharp 转成浏览器格式（mp4 / m4a / png / webp）。**发布的资产永远是浏览器格式**，
源格式只在"本地化"这一步被接受。

### A.3 libvips 在 Windows 上持句柄导致 rename 失败
```js
// A bounded source buffer avoids libvips retaining a Windows file handle
// across the output transaction's rename/cleanup boundary.
const image = sharp(await readFile(inputPath), { limitInputPixels: 40_000_000, animated: true });
```
**触发**：在 Windows 上，`sharp`（libvips）默认会保留输入文件的句柄；如果转换输出后
紧接着做事务性 `rename` / 清理，会因文件仍被占用而失败。
**修法**：先 `readFile` 把整个源文件读进内存（bounded，限 4000 万像素），再让 sharp
从内存 buffer 转，释放文件句柄。
**对我们的启示**：Windows 上凡是用 libvips/sharp 后又要做文件 rename/删除，**先整文件
读进内存**而不是直接传路径，否则偶发"文件被占用"很难复现。

### A.4 动画图静默丢帧
```js
if ((metadata.pages || 1) > 1) {
  // Preserve animation/pages as a single animated WebP rather than silently dropping frames.
  await image.toColourspace('srgb').webp({ lossless: true, loop: ..., delay: ... }).toFile(outputPath);
}
```
**坑**：TIFF/AVIF 可能是多页（动画）。早期的简单转换会只取第一页，其余帧"静默丢失"，
用户还以为生成的就是单图。
**修法**：检测到 `pages > 1` 就转成 animated WebP 保留全部帧和 delay/loop。

### A.5 预览节点绝不可当成品 + 输出防泄密
- 收集与本地化两层都 `if (isComfyPreviewNode(...)) continue;` ：`PreviewAny` 等预览节点
  的输出直接丢弃。
- `assertSafeInlineStrings` 递归扫描所有内联输出（字符串/数组/对象，深度 ≤32）：
  拒绝本机路径、拒绝 `api_key`/`token`/`secret`/`sk-...`/`rk-...` 等凭证字样、拒绝
  **外部 URL**（只放行 `127.0.0.1`/`localhost`）。
**坑**：自定义 ComfyUI 节点可能把密钥或本地路径写进输出文本。如果不拦，前端展示出来
就是一次信息泄露。
**对我们的启示**：任何"执行用户自定义工作流后展示其输出"的场景，输出都要按"疑似密钥/
路径/外链"过滤，绝不能原样渲染。

### A.6 事务化暂存 + 崩溃可恢复
`localizeWorkflowOutputs` 不是直接写最终位置，而是：
1. 在 `output-staging/<runId>/` 下写 `manifest.json`（原子写），逐文件 `rename` 进素材库，
   每步都更新 manifest 的 `publishedFile` / `publishedMetadata`；
2. 全程 try/catch：任何失败把 `temporaryPaths` + `publishedPaths` + `runDirectory` 全删，
   返回 `rollback()` / `commit()`；
3. `recoverWorkflowOutputStaging` 在服务启动时扫暂存目录：已 `committed` 的清理暂存区，
   未提交的把半成品从素材库删掉回滚。

**坑**：本地化到一半进程崩了，会留下半截文件 + 半截 manifest，下次启动要么重复写、
要么素材库里出现损坏文件。
**修法**：manifest 是"已发布到哪一步"的账本；重启时按账本对账——`requireReceipt(runId)`
确认提交过才清暂存，否则回滚删除。

## B. 生成租约与崩溃恢复：服务重启后任务怎么办

文件：`server/generation/generationCoordinator.js` + `generationTaskRecovery.js`

### B.1 "unknown" 终态：绝不自动重提
```js
function finalizeUnknown(nodeId, details = {}, expectedAttemptId) {
  return transition(nodeId, 'unknown', {
    code: 'COMFYUI_SUBMISSION_UNKNOWN',
    error: '无法确认工作流是否已提交，系统不会自动重提。',
    retryable: false,
    remoteMayContinue: true,   // 远端可能还在跑
    ...details,
  }, ...);
}
```
**触发**：提交请求发了，但没收到确认（网络断、进程崩、上游没回）。此时**不知道任务到底
提交没提交**。
**坑**：如果按"失败"自动重试，而远端其实已经收到了，就会**重复生成、重复烧钱**。
**修法**：状态置为 `unknown`，`retryable: false`，`remoteMayContinue: true`，提示用户
"先核对任务记录，避免重复生成"。后续由 `generationTaskRecovery` 去轮询远端确认，而不是
盲目重提。这是作者明确踩过"重复计费"后定的铁律。

### B.2 lease 租约 + adopt 重启续命
每个生成任务有一个 lease（租约），带 `absoluteDeadlineAt`。两种超时处理不同：
```js
function expire(leaseId) {
  if (task.remoteTask || task.remoteSubmissionStarted) {
    // 已经提交/在提交：标 unknown，去核对，不重提
    finalizeUnknown(...);
  } else {
    // 还没提交：标 failed，可重试
    transition(..., 'failed', { code: 'GENERATION_LEASE_EXPIRED', retryable: true });
  }
}
```
**崩溃重启**：`adopt` 接管 `loading` 状态、且 deadline 还没过的任务，续租 lease 继续观察；
**deadline 已过**则直接判 `WORKFLOW_RUN_TIMEOUT`（`retryable: true`），不让僵尸任务永远挂着。
**对我们的启示**："超时"不能一刀切。已经把钱花出去的（remoteTask 存在）和还没花的，
终态与重试策略完全相反。

### B.3 心跳续租
`heartbeat` 每次把 lease 定时器重置为 `min(heartbeatMs, remainingMs)`。观察中的长任务
靠心跳活着，不心跳就 expire——防止"卡死的任务永久占着并发名额"。

### B.4 远程引用只存指纹，且查询前后各核对手设一次
`generationTaskRecovery` 的 `canRecover` + `matchesRemoteTask`：存的是
`sha256(modelId)` / `sha256(submitUrl)` / `sha256(apiKey)`，不存明文。
恢复时重新算指纹比对；**查询前核一次、查询到结果写回前再核一次**（`isCurrent()`）：
因为用户在轮询的几十秒里可能切了 Key/通道，点了新通道就不能把结果落到旧任务上。
`settings_changed` 时只 `waiting`，绝不写回。

## C. 价格比价：错套价位的真实 bug

文件：`server/generation/modelSourceRouter.js` + `modelAvailability.js`

### C.1 视频模式不能只按分辨率比
```js
// resolution 和 mode 必须带上：视频参考、视频编辑等模式本来就不是同一个价，
// 只按分辨率比会把 Kling O3 的文生价错套到视频编辑。
```
**触发**：前端只传了 `resolution`，没传 `mode`。
**坑**：Kling O3 的"文生视频"和"视频编辑"价格不同，只按分辨率匹配会把文生价错套到
视频编辑，用户看到错误的低价，实际被多扣。
**修法**：`/generation/model-availability` 强制解析 `mode` / `resolution` / `aspectRatio` /
`duration` / `speed` / `generateAudio` / `inputImageCount` 全套参数，比价键是
`mode|resolution|duration[|images|audio]` 的完整签名。

### C.2 厂商直连价"宁可不显示"
`modelAvailability.js`：画布里那份厂商价是**历史遗留写死值**，没证据证明等于真实账单。
三个数并排显示会让用户以为可信度相同 → **宁可不显示**，统一标"以官方价为准"。

### C.3 价格服务挂了不能拖垮整个下拉
```js
try { relayPricing = await relayPricingClient.getSnapshot({ waitForFresh: false }); }
catch (error) {
  // 价格服务失效不该让整个模型下拉 500。下游会保留画布基准价，
  // 同时明确标注“实时估价暂不可用”。
}
```
价格快照失败被吞掉，下拉照常渲染（用基准价 + "暂不可用"标注），而不是 500。

### C.4 缓存会被"未配 Key"结果污染
```js
// This response contains per-user key availability. Never cache an old
// unconfigured result after a provider key is saved.
response.set('Cache-Control', 'no-store');
```
**坑**：如果缓存了"未配置 Key"的响应，用户填了 Key 后可能看到旧的不可用状态。
**修法**：`no-store`，每次实时算密钥可用性。

## D. 错误分类：retryable 是人工判的，不是读的

文件：`server/generation/generationErrors.js`

retryable 不来自上游字段，而是按错误性质硬编码（见下表）。两个真实坑：

| 错误 | retryable | 为什么 |
| --- | --- | --- |
| MJ 提示词过长 | ❌ | "系统**不会自动截断或重提**"——自动截断会改用户意图 |
| 参考素材上传鉴权失败 401/403 | ❌ | 归到 502 而非 401，提示"**登录画布账号不能替代服务商 API Key**" |
| 内容审核未过 | ❌ | 提示可切"API宽审核"线路 |
| 限流 429 / 超时 504 / 网络 502/503 | ✅ | 可重试 |
| 缺密钥 / 余额不足 / 模型未开通 / 参数非法 | ❌ | 重试无意义 |

`confirmedGenerationFailure`：**绝不外抛原始 `error.message`**——上游 message 可能含密钥
或带签名 URL。只透出归一的 `code` + `message`。`status` 只取上游 HTTP 边界
（`getUpstreamStatus`），本地校验状态不算"上游状态"。

## E. 更新：状态机 + 30 分钟 stale + 常量时间 token

文件：`apps/desktop/src/updates/*`

### E.1 defer 必须在取单实例锁之前
`shouldDeferLaunch()` 在 `requestSingleInstanceLock()` 之前调用。否则 probation 期间
用户手动启动会抢走锁，把正在验证的候选版本挤掉 → 更新永远卡在"验证中"。
**30 分钟 stale**：正常更新单态（拷贝/校验/探测/回滚）最长几分钟，超 30 分钟没推进
`updatedAt` 即视为助手已死，放行普通启动。

### E.2 启动确认防伪造
`confirmUpdateStartup` 用 `timingSafeEqual` 常量时间比 token；`targetVersion` 必须等于
候选实际跑起来的版本；确认文件禁止写进安装根目录（`inside-install-root` 拒绝）。
五个 handoff 环境变量确认后一律从 `environment` 删除，防泄漏到子进程。

## F. 路径与文件安全：四道防线

- **下载防穿越**（`mediaDownloadRouter`）：`resolve` → `isInside` → 拒符号链接 →
  `realpath` 再 `isInside` 一次。符号链接能把真实文件指到库外，所以必须 realpath 后
  再判一次。
- **原子写**全仓库通用：写 `.tmp`（`flag:'wx'`）+ `rename` 覆盖；Windows 上 `chmod 0o600`
  失败静默忽略（POSIX 模式不被支持）。进程崩溃/磁盘满也不会留半截配置。
- **保存对话框仅 Windows**：`selectSavePathWithSystemDialog` 跨平台无等价实现，非 win32
  直接 501。

## G. 给"我们"的复用清单（按风险排序）

1. **任何远程付费任务**：提交确认丢失时，绝不直接重试 → 用 `unknown` + 远端核对；
   远端引用只存指纹，不存 key。
2. **任何"执行用户自定义工作流并展示输出"**：输出必须按密钥/路径/外链过滤，预览节点
   绝不入库。
3. **任何媒体格式转换（Windows + libvips）**：转换后要做 rename 的，先整文件读内存再转，
   躲开句柄占用；多页图要保留帧。
4. **任何价格/比价 UI**：比价键必须带全参数（mode/resolution/...），不能只按一个维度；
   厂商价无依据时宁可不显示。
5. **任何下载带符号链接风险**：`realpath` 后二次 `isInside`。
6. **任何 Electron 更新**：单实例锁之前先判 defer；确认 token 常量时间比；stale 判定要
   基于"最长单态耗时"而非拍脑袋。
7. **任何遥测**：fire-and-forget，永不 await 生成主路径；401 重取 token、429 退避、422 删
   未知字段重发。
