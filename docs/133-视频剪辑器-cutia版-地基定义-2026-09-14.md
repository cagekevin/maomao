## 一、数据地基

### 1.1 唯一数据模型：cutia `TProject`（**真源，不得镜像**）

```
TProject                                        ← 一个「剪辑工程」
├─ metadata { id, name, thumbnail?, duration, createdAt, updatedAt }
├─ scenes: TScene[]                             ← ★ 多场景（我们只用 main，见 §1.2）
│   └─ TScene { id, name, isMain, tracks: TimelineTrack[], bookmarks, createdAt, updatedAt }
│       └─ TimelineTrack = VideoTrack | TextTrack | AudioTrack | StickerTrack
│           └─ elements: TimelineElement[]      ← ★ 叫 elements，**不叫 clips**
├─ currentSceneId: string
├─ settings { fps, canvasSize{width,height}, originalCanvasSize?, background }
├─ version: number                              ← ★ 字段名是 `version`，**不是** `schemaVersion`
├─ timelineViewState? { zoomLevel, scrollLeft, playheadTime }
└─ agentMessages?                               ← 随 AI 域删除，见 §1.5
```

**TElement（片段）形状**：
```
BaseTimelineElement { id, name, duration, startTime, trimStart, trimEnd }

VideoElement  { type:'video', mediaId, muted?, hidden?, transform, opacity, playbackRate?, reversed? }
ImageElement  { type:'image', mediaId, hidden?, transform, opacity }
AudioElement  { type:'audio', volume, muted?, buffer?, playbackRate?, sourceType:'upload'|'library', ... }
TextElement   { type:'text', content, fontSize, fontFamily, color, ..., transform, opacity, stroke?, shadow? }
StickerElement{ type:'sticker', iconName, hidden?, transform, opacity, color? }
Transform     { scale, position{x,y}, rotate, flipX?, flipY? }
```

**纪律 D-1（SSOT）**：**禁止**在外部（画布 / store / 组件）维护任何 `TProject` 的副本或字段镜像。
所有读写经 `EditorCore` 的 managers（`editor.project` / `editor.scenes` / `editor.timeline`）。

> **反面教材已实证**：`_legacy/core/types.ts` 曾定义 `Project/Track/Clip` 描述同一件事
> → 那就是 SSOT 第二份（本仓头号母体），故被废弃。**不要再引入第二套模型。**

### 1.2 我们只用一个 scene（**纪律**）

`TScene` 是 cutia 的「多场景」（同一部片子分场景，**共享 `TProject.settings`**）。
我们**不需要**它表达「多个剪辑工程」——那是另一个层次（§二）。

| 规则 | 内容 |
| --- | --- |
| **S-1** | **永远只用 main scene**：调用一律走 `getMainScene()` / `ensureMainScene()`（`engine/core/managers/scenes-manager.ts`） |
| **S-2** | **禁止调用** `createScene` / `switchScene` / `deleteScene`（多场景 API 保留但不用） |
| **S-3** | 若将来真要「一部片子分场景」→ 那时再启用，**不提前抽象**（心法 §铁律 5） |

### 1.3 时间语义（**与 `123` 一致，此条仍成立**）

| 记法 | 定义 | 字段 |
| --- | --- | --- |
| 工程时间 | 片段在时间轴上的位置 | `element.startTime` |
| 源时间 | 从素材取用的区间 | `trimStart` / `trimEnd` |
| 时长 | 派生 | `element.duration` |

**纪律 T-1（唯一单位）**：一切时间字段 = **秒（float）**。帧只是显示与采样，**不进存储**。
**纪律 T-2（派生不落盘）**：`clipEnd` 等派生量现算，不存（存了必与源字段漂移）。

### 1.4 媒体素材（**双通道存储**）

| 数据 | 存哪 | 键 / 位置 |
| --- | --- | --- |
| 素材**元数据** | IndexedDB | `MediaAssetData`（`IndexedDBAdapter`） |
| 素材**文件本体** | OPFS | `media-files-{projectId}`（`OPFSAdapter`） |
| 素材**引用**（片段指向谁） | 存在 `element.mediaId` | — |

**⚠️ 这是与 `120` 契约不一致的地方（必须知道）**：
`120 C2.5` 要求「只存元数据与 URL，禁内联 base64」+「唯一文件入口 = localTool `/files/`」。
而 cutia 现在**素材文件存 OPFS**（浏览器本地），**不走 localTool `/files/`**。

| 现状 | 是否违红线 |
| --- | --- |
| 素材存 OPFS（浏览器本地） | **不违** —— 它不在 `STORAGE_KEYS` 登记体系内（OPFS 不是「存储键」），是**独立通道** |
| 但 **换电脑素材就丢**（OPFS 只在本机） | ⚠️ **真实后果** → **已定改为 localTool `/files/`**，见 §3.2 |

### 1.5 AI 域已删除（**不要复活**）

已删：`engine/lib/ai/` · `engine/lib/tts/` · `panels/assets/views/{agent,ai.tsx,captions,sounds}` ·
`stores/{agent,ai-*,character,sounds}-store` · `types/{character,sounds}`。
`TProject.agentMessages` 字段**保留但不写**（向后兼容，防旧数据加载失败）。

## 二、多剪辑工程（用户需求 ③ 的核心）

### 2.1 语义（用户裁定）

```
画布项目 (proj-xxx)                    ← 顶层唯一
    └─ 剪辑工程 01 / 02 / 03 …          ← 各自独立的片子，互不相干
          每个 = 一个完整 TProject
```

| 规则 | 内容 | 依据 |
| --- | --- | --- |
| **M-1** | 多个剪辑工程**各自独立**（各自 `settings`，含 fps / 画布尺寸） | 用户：**"各自独立的片子，互不相干"** |
| **M-2** | 承载层 = **`TProject`**（**不是** `TScene`） | `TScene` 共享 `TProject.settings` → 无法表达"不相干的片子" |
| **M-3** | 编辑器**画布级常驻**，内部切换 01/02 | 用户裁定 |
| **M-4** | `editorId` = **UUID**（`engine/utils/id.ts` 的 `generateUUID`） | 用户裁定 |
| **M-5** | **素材来源仍是画布节点**（点选入轨），编辑器不绑节点 | 用户裁定 |

**M-2 的推理**（不可逆决策，写清为什么）：
`TScene` 的设计意图是「同一部片子分场景」（电影的不同场次），它**不含 `settings`** —— fps / 画布尺寸在 `TProject` 上。
若拿 `TScene` 当「多个剪辑工程」，就会出现「两部不相干的片子**被迫共用**画布尺寸」，
在第一次"这两部尺寸不同"时爆炸。故用 `TProject`。

### 2.2 存储定义（**照 AI 助手机制 · 方案 B**）

> **先例**：AI 助手 = `agent_conversations_{agentKey}` + `agent_active_conversation_id_{agentKey}`，
> 其中 `agentKey = canvas-assistant-{projectId}`（键构造收口在 `base/core/agentKeys.ts`）。
> 本节**照搬该机制**，并按体积差异做**一处修正**（见 §2.3）。

**三个键**（全部 `backend: 'kv'`）：

| 键模板 | 内容 | 用途 |
| --- | --- | --- |
| `video_editor_projects_{projectId}` | 工程**列表**（轻）：`[{ id, name, createdAt, updatedAt }]` | 切换列表 |
| `video_editor_active_project_{projectId}` | 当前活跃 `editorId` | 刷新后恢复 |
| `video_editor_project_{projectId}_{editorId}` | **单个工程本体**（重）：完整 `TProject` | 实际编辑对象 |

**键构造必须收口**（照 `agentKeys.ts` 先例）：
```
待建 src/components/base/core/videoEditorKeys.ts
  videoEditorProjectsKey(projectId)        → 'video_editor_projects_' + projectId
  videoEditorActiveProjectKey(projectId)   → 'video_editor_active_project_' + projectId
  videoEditorProjectKey(projectId, editorId) → 'video_editor_project_' + projectId + '_' + editorId
```
> **为什么收口**：`agentKeys.ts` 头注释已实证 —— 前缀硬编码在三处 → 一旦漂移 → **备份静默漏备且零报错**。
> 禁任何模块再拼 `video_editor_` 字面量。

### 2.3 ★相对 AI 助手的**一处修正**（体积差异）

| 项 | AI 助手 | 剪辑工程 | 后果 |
| --- | --- | --- | --- |
| 单位体积 | 消息文本，有 60 条上限 | 完整 `TProject`（含全部 elements） | **差 2~3 个数量级** |
| 结构 | 一个键装**全部**会话 | ⚠️ **不能照搬** | 工程多时，保存一个 = 重写全部 → 卡 |

**故修正为**（= 用户已确认的**方案 B**）：
```
列表（轻）与工程本体（重）**分键**：
  video_editor_projects_{projectId}              ← 列表，只存元信息
  video_editor_project_{projectId}_{editorId}    ← 每个工程独立一个键
```
**收益**：保存「工程 02」只写 `..._proj-xxx_{02 的 uuid}` 一个键，**不触碰工程 01/03**。

### 2.4 引擎单例与切换（**不变式 I-1**）

`EditorCore` 是**进程单例**（`engine/core/index.ts`：`private static instance`）。

| 规则 | 内容 |
| --- | --- |
| **I-1** | 切换剪辑工程**必须** `editor.project.closeProject()` → `editor.project.loadProject({ id })` |
| **I-2** | 禁止「直接改 `editor.project` 的 active」绕过 load（会残留上一个工程的 scenes / media） |
| **I-3** | 挂载点必须 `key={editorId}`（强制重挂载，`130` 已在 `EditorShell` 用 `key={activeProjectId}`，需改为 `editorId`） |

### 2.5 与画布节点的关系

```
画布项目 (proj-xxx)
    │
    ├─ 编辑器（画布级常驻，底部/全屏）
    │     ├─ 工程切换器 [01, 02, …]
    │     └─ 当前工程 = TProject
    │
    └─ 画布节点（素材来源）：点选 → 入轨（**读方向**）
                          导出 → spawnAndCommit 新节点（**写方向**）
```

| 规则 | 内容 |
| --- | --- |
| **B-1（读）** | 画布节点 → 素材：经 `base/canvas/nodeMedia.ts` 的 `getNodeMedia`，**不另写一份** |
| **B-2（写）** | 导出产物 → 画布：经 `base/canvas/deriveNodes.ts` 的 `spawnAndCommit` |
| **B-3（方向）** | 画布 → 工程**单向**；画布节点**不持有、不回写**编辑工程数据 |
| **B-4（隔离）** | 剪辑工程数据**不进**画布快照（`canvas-state-v1-*`），二者独立键 |

## 三、后端接口预留（用户需求 ②）

### 3.1 现状：**零后端依赖**（这是优势，不是缺陷）

| 环节 | 现在怎么走 | 有无后端 |
| --- | --- | --- |
| 工程持久化 | `StorageService` → **IndexedDB** | ❌ 纯浏览器 |
| 素材文件 | **OPFS**（浏览器本地文件系统） | ❌ 纯浏览器 |
| 导出 | `SceneExporter`（mediabunny，内存 buffer） | ❌ 纯浏览器 |

> `125 §三.1` 已证实：cutia 编辑器主链路**不碰任何自建服务器**。

### 3.2 ✅ 素材通道：**改走 localTool `/files/`**（已定 2026-09-14）

**用户裁定**：「和 localTool 一样，`120` 红线用一样的。」

| 项 | 定论 |
| --- | --- |
| 素材文件通道 | **localTool `/files/`**（唯一文件入口），**不走 OPFS** |
| 上传原语 | `base/api/filesApi.ts:256 uploadFileToLocal(file, subfolder, filename?, projectId?)` → `Promise<string \| null>` |
| 落盘目录 | `UPLOAD_DIRS.videoEditor = 'canvas/video-editor'`（**已登记**，`uploadDirs.ts:12`） |
| 传 `projectId` | ✅ **必须传**（第 4 参）—— 后端据此写 `resource` 行 `project_id`（TD-12-5 项目隔离写入链） |
| 红线对齐 | 与 `120 C2.5`「只存元数据与 URL，禁内联 base64」+ `C3`「唯一文件入口」一致 |

**为什么必须改**（缺口实证）：
```
工程记录 → KV（跨端跟着人走）
素材文件 → OPFS（只在本机）
→ 换电脑后：工程在、素材不在 = 全部断链（且无提示）
```

**纪律 D-3（素材通道唯一）**：
- 编辑器素材落盘**只准**经 `uploadFileToLocal(..., UPLOAD_DIRS.videoEditor, ..., projectId)`；
- **禁** OPFSAdapter 写新素材（`OPFSAdapter` 保留仅为读取迁移期存量）；
- **禁**在编辑器内自行拼 `/files/` URL（走 `filesApi` 返回的 URL）。

> ⚠️ **实现去向**（供后续施工）：`engine/services/storage/service.ts` 的
> `saveMediaAsset()` / `loadMediaAsset()` 需从 IndexedDB+OPFS 改为：
> 元数据 → KV 或 IndexedDB（轻），文件本体 → `uploadFileToLocal` + 存 URL。
> **具体形状属施工决策，本文不定义。**

### 3.3 后端接口的分层预留（若将来要接）

**唯一写者**原则（实测）：工程落盘**只经** `storageService.saveProject()`（4 处调用点，全在 `engine/core/managers/project-manager.ts`）。

```
未来换后端 = 替换 StorageService 的 4 个方法：
  saveProject / loadProject / deleteProject / (listProjects)
    ↓
  保持签名不变（入参 TProject，出参 OpResult 语义）
    ↓
  引擎 / UI / 桥 全部零改动
```

**纪律 D-2**：**不得**在 UI 层或桥层直接调 `fetch` / `contentStore` 写工程数据；
一切经 `StorageService`（未来它内部换实现）。

**参考先例**（`129 §二` 已设计）：`ProjectStorageAdapter` 窄接口
```
loadProject(id) → OpResult<TProject>
saveProject(id, tproject) → OpResult<void>
loadMedia(id) → OpResult<Blob>
saveMedia(id, blob) → OpResult<string>
```

### 3.4 存储通道速查（实测）

| 通道 | 机制 | 特征 | 现有用例 |
| --- | --- | --- | --- |
| `local` | `localStorage` | 同步、只在本机 | 项目列表、`app_settings` |
| **`kv`** | **localTool KV**（`:18080/api/kv/*`） | 异步、**跨端共享**、有 CAS | **画布快照**、**AI 会话**、← **剪辑工程** |
| `native` | 原生 `localStorage` | 绕过 contentStore | `director3d` 专属 |

**两族 API**（`contentStore.ts`）：
- **严格族** `contentKvSetCas` / `contentKvGetVersion`：**用户主数据**，fail-closed，绝不降级写副本
- 尽力族 `contentSetAsync` / `contentSetKvWithFallback`：成功即清本地副本（AI 会话用这族）

### 3.5 ✅ 写族：**严格族 CAS**（已定 2026-09-14）

**用户裁定**：「写盘那就用严格的。」

| 环节 | 原语 | 语义 |
| --- | --- | --- |
| 取 CAS 基线 | `contentKvGetVersion(key)` → `Promise<number>` | 读服务端当前版本 |
| 条件写 | `contentKvSetCas(key, value, { ifVersion })` → `Promise<KvCasWriteResult>` | `ifVersion` 不符 → **抛 `HttpError(409)`，一个字节不写** |
| 缺省写 | `contentKvSetCas(key, value)` | 无条件（备份导入 / 强制覆盖用） |

**纪律 D-4（不静默覆盖）**：
- 剪辑工程**三个键全部**走严格族（列表 / 活跃 id / 工程本体）；
- **409 必须被消费**（`120 C2.7`）：调用方须把冲突**显式暴露**（提示 / 重载 / 用户选择），
  **禁**静默重试覆盖、**禁**降级写本地副本；
- **禁**用 `contentSetAsync` 写剪辑工程（它是尽力族，会让「别人刚改过」这一事实消失）。

> ⚠️ **与 AI 助手的差异（有意为之）**：AI 会话用尽力族即可（丢一条会话影响小）；
> 剪辑工程是用户主数据，**丢一次编辑 = 丢一段劳动**，故取更严的一族。

## 三补 · 导出能力（**以 cutia 原始能力为准**）

> **方向修正（2026-09-14 用户裁定）**：**`docs/120` 已作废，不再作为衡量基准**。
> 本节只**如实描述 cutia 能做到什么**，不用本仓旧契约去裁剪它。

### 3b.1 导出契约（实测 `types/export.ts`）

```ts
ExportOptions {
  format: 'mp4' | 'webm'          // mp4=H.264（兼容好）· webm=VP9（体积小）
  quality: 'low' | 'medium' | 'high' | 'very_high'
  fps?: number                     // 缺省 = 工程 settings.fps
  includeAudio?: boolean
  onProgress?: ({ progress }: { progress: number }) => void
  onCancel?: () => boolean         // ★ 轮询式取消（调用方返回 true 即中止），非 AbortSignal
}

ExportResult {                     // 已收敛的返回值
  success: boolean
  buffer?: ArrayBuffer             // ★ 产物是内存 buffer（非落盘 URL）
  error?: string
  cancelled?: boolean
}
```

### 3b.2 三个导出入口（实测 `engine/core/managers/renderer-manager.ts`）

| 方法 | 行 | 用途 |
| --- | --- | --- |
| `exportProject({ options })` | :25 | 导出**整个工程** |
| `exportSelectedClip({ options })` | :38 | 导出**选中片段** |
| `exportCurrentFrame(...)` | `ui/editor/panels/preview/index.tsx:218` | 导出**当前帧**（走 `tempCanvas.toBlob`，非引擎方法） |

**mime / 扩展名**由 `lib/export.ts` 的 `getExportMimeType({format})` / `getExportFileExtension({format})` 决定。

### 3b.3 ✅ 出片桥的定论（不需要 `OpResult`）

`ExportResult` **本身就是可用的收敛形态**（有 `success` / `error` / `cancelled`），
**不必**包成 `OpResult` 三态（那是 `120` 的旧要求，已作废）。

**出片桥要做的事**（唯一动作）：
```
ExportResult.buffer (ArrayBuffer)
    ↓ 包成 Blob（mime 取 getExportMimeType({format})）
    ↓ uploadFileToLocal(blob, UPLOAD_DIRS.videoEditor, `${name}.${ext}`, projectId)
    ↓ spawnAndCommit（base/canvas/deriveNodes.ts:152）生成新画布节点
```

**纪律 E-1**：`buffer` 是**内存对象**，**必须**先落盘（`/files/`）再生成节点 URL；
**禁**把 `ArrayBuffer` 直接塞进节点 data（违反"禁内联二进制"且刷新即丢）。

### 3b.4 已知能力边界（诚实标注，不掩饰）

| 项 | 现状 |
| --- | --- |
| **进度粒度** | 只有 `{ progress: number }`（0~1），**无阶段名**（不分"混音/画面/写容器"） |
| **取消机制** | `onCancel()` **轮询式**（引擎周期性询问调用方），**不是** `AbortSignal` |
| **有损告知** | **无** —— `ExportResult` 不区分"成功"与"有损成功" |
| **画质档位语义** | `low/medium/high/very_high` 是**档位名**，具体码率由 mediabunny 内部决定 |

> ⚠️ 上表是**现状**，不是**缺陷待补**。若将来要"阶段进度 / 有损告知"，
> 那是**扩引擎能力**（改 `engine/services/renderer/scene-exporter.ts`），需单独排期。

## 三补之二 · 媒体素材与入轨（**以 cutia 原始能力为准**）

### 3c.1 素材元数据（实测 `engine/services/storage/types.ts:19`）

```ts
MediaAssetData {
  id, name, type: MediaType, size, lastModified,
  width?, height?, duration?, fps?,        // ★ 探测得到的媒体信息
  ephemeral?,                              // ★ 临时素材（不落盘，用于"从 URL 导入"）
  thumbnailUrl?,                           // ★ 缩略图（胶片条 / 素材网格用）
}
```

**关键**：`duration` / `width` / `height` / `fps` **都是可选**（探测可能失败）。
→ **纪律 P-1**：入轨时**不得**假设这些字段存在；缺失时按"未知"处理（**不猜默认值**）。

### 3c.2 素材处理入口（实测）

| 能力 | 位置 | 签名 |
| --- | --- | --- |
| 处理文件（探测 + 缩略图） | `engine/lib/media/processing.ts:199` | `processMediaAssets({files, onProgress?})` → `Promise<ProcessedMediaAsset[]>` |
| 从 URL 导入 | `engine/lib/media/url-import.ts` | `fetchRemoteMediaAsFile({url})` → `File` |
| 缩略图服务 | `engine/services/timeline-thumbnail/service.ts` | 内部缓存 `Map<string, Promise<ImageBitmap\|null>>` |

### 3c.3 入轨路径（**画布节点 → 编辑器**）

```
画布节点
  ↓ getNodeMedia(node) → { type, url }        （base/canvas/nodeMedia.ts:49）
  ↓ fetchRemoteMediaAsFile({url}) → File       （engine/lib/media/url-import.ts）
  ↓ editor.media.addMediaAsset({projectId, asset})
  ↓ editor.timeline.insertElement({ element, placement:{mode:'auto'} })
```

**纪律 P-2**：
- 画布节点的素材**必须**经 `fetchRemoteMediaAsFile` 转成 `File`（cutia 的素材模型基于 `File`）；
- **禁**把画布 URL 直接当 `element.sourceUrl` 用（cutia 的 `element` 靠 `mediaId` 关联，不是 URL）。

### 3c.4 探测失败的处理（**诚实**，不静默）

| 情况 | 处置 |
| --- | --- |
| 探测不到 `duration` | 按 0 处理并**在 UI 标记未知**（**禁**猜一个默认时长） |
| 类型不支持 | `processMediaAssets` 已 `toast.error`（cutia 原生行为，保留） |
| 画布节点断链 | 由**画布侧**判定（编辑器不重复实现断链逻辑） |
