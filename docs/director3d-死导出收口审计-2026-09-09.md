## 二、⚠️ 陷阱（执行前必读）

### 陷阱 1：4 个 `default` 是「具名导出在用，default 冗余」——**不是没人用这个文件**

knip 把 `export default` 也当成一个叫 `default` 的导出符号来报。这 4 个文件**都通过具名导出被正常使用**：

| 文件 | 真正的消费方 | 正确处置 |
|---|---|---|
| `director3d/Director3DOverlay.tsx` | `nodes/Director3DNode.tsx:9` `import { Director3DOverlay }` | 删 `export default`，保留具名 |
| `director3d/App.tsx` | `Director3DOverlay.tsx:3` `import { Director3DApp }` | 同上 |
| `director3d/ErrorBoundary.tsx` | `Director3DOverlay.tsx:4` `import { ErrorBoundary }` | 同上 |
| `director3d/panels/GlobalSettingsPanel.tsx` | `panels/Inspector.tsx:26` `import { GlobalSettingsPanel }` | 同上 |

**绝对不要**因为「default 未使用」而删除这些文件或它们的类/函数定义，否则导演台直接崩。

### 陷阱 2：`ease` 是同名陷阱
`project.ts:257` 的 `ease` 与 `base/editors/ImageZoomDialog.tsx`、`base/ui/GeneratingOverlay.tsx` 里的 `ease` 是**同名不同实现**。本条属于 B 类（仅 `project.ts` 内使用），不要因为别处有 `ease` 就以为它被跨文件引用。

### 陷阱 3：director3d 无测试保护
`spec/CONTEXT.md` §五·五：改 director3d **不强制补单测**。因此 C 类删除没有测试兜底，
每一条删除都要靠「人工确认零引用 + 跑通门禁」来保证，不要批量盲删。

### 陷阱 4：`normalize*` 系列是数据归一化入口
`normalizeCamera` / `normalizePerson` / `normalizeShot` / `normalizePathPoint(s)` 虽然当前只在 `project.ts` 内被调用，
但它们是**工程数据加载的归一化契约**（`spec/CONTEXT.md` §五·五 指定 `project.ts` 为领域类型真相源）。
即便摘掉 `export` 也要保证 `normalizeProjectData` 能调到它们。
