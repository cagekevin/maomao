## State 1：定契约（输入 / 输出 / 边界 / 文件归属）

### 1.1 一句话需求复述

在 AI 助手面板 `AgentPanel` 左侧开一个**分镜表格工作区**，与右侧 AI 对话并排协作：
- 表格数据两个来源：① 外部粘贴纯文字（首行为表头，其余为数据行）；② **在对话区发「需求 + Skill」让 AI 生成整表**（顶层 `globalStyle` + 行数组，AI 按 Skill 设计列/填行）。
- 选中某一行（可加选画布图作参考）→ 作为上下文随对话发给 AI；AI 精简结构化返回 → **对话框确认后写回该行**，可反复打磨。
- 某行定稿后可"发送到画布"落成节点去生图/视频（**可选出口**）。
- **表格完全可定义**：AI 生成/粘贴只是起点，落表后点格改字、加删行、调序、改列都可自由编辑（见 §1.6）。
- **表格归属 = 当前 AI 对话**：一个对话一份表，新建对话=新空表，回看旧对话=表还在。不做多项目管理。

### 1.2 输入源 → 输出目标 → 副作用（本步只定边界，链路归属 State 2）

| 能力 | 输入源 | 输出目标 | 副作用(Side Effects) |
|---|---|---|---|
| A. 粘贴成表 | 剪贴板 `clipboardData`（TSV 文本 / HTML `<table>`），**表格入口显式拦截** | 内存态分镜表（表头 `columns[]` + 行 `rows[]`），经会话持久化 | 写会话记忆字段；走 `contentStore` 落盘（会触发 `persist:failed` 可观测） |
| B. AI 生成初始表 / 改单行 | 需求文本 / 选中行文字 + globalStyle +（可选）参考图 | AI 精简结构化 JSON → **渲染成可视化预览 → 用户确认 → 写回表** | 发一次 LLM 调用；确认后才写表，预览不改数据 |
| C. 选行(+画布图)作上下文发 AI | 表内选中行、画布选中节点图 | 对话框新增一轮 user 消息（携带选中行 + globalStyle + 参考图） | 调 `useAgentChat.send`；会话历史 + 落盘 |
| D. 单行落画布节点（出口） | 定稿行文字 | 画布上一个文本节点（承载行内容） | 走 `canvasHost` 唯一写入口建节点（禁裸 `setNodes`） |

### 1.3 收口检索：复用 vs 新增

**已有可复用（标记"复用/扩展既有件"，勿新造）**：
- **会话隔离/持久化**：`conversationState.ts` 按 agentKey 隔离 + KV 落盘 + 水化时序守卫 → **分镜表挂在当前会话记忆字段**（与 `global_contract`/`artifacts` 并列），顺着现有隔离走，**不另建存储体系**。
- **AI 结构化输出契约**：剧本盒 `scriptBoxPrompts.ts` 的 `SCRIPT_WRITER_FORMAT`（"只返回纯 JSON"输出契约）+ 顶层 `globalStyle` + shots/行数组形态 → **照抄为工作区生成/改行的 schema**。
- **globalStyle 通道**：会话 `memory.global_contract.unified_style_prompt` 是既有"统一风格→自动注入 LLM"通道 → 工作区 globalStyle 映射到它（见 State 2），不造新字段名。
- **选中画布图→参考图**：`App.tsx` 传 `selectedImageNodes` + `useCanvasAgentTools.getNodeImageUrl` → AgentPanel 现有 `pendingImageNodes/confirmPendingImages` 附件链路。**去掉"附件卡片/防误触" UI**，保留"选中行/图作上下文随对话发"的底层带图能力。
- **确认交互范式**：`AgentConfirmCard` + `conversationStore` 的 `setAwaitingConfirm/getAwaitingConfirm` 是现成"AI 返回后需用户确认"的卡片 → 改单行/生成初始表的"确认写回"借鉴此范式（非复制整套 runMode 门禁）。
- **「发送到画布」= 既有工具 + 既有按钮**：`useCanvasAgentTools.ts` 的 `create_node` 工具（L382，`text` 参数把内容落 textNode 的 `data.text`）就是 AI 建文本节点的现成工具，走 `canvasHost` 唯一入口；`useAgentChat.sendContentToCanvas`（L946）已是"把一段文本建成 textNode"的**现成按钮函数**，AgentPanel 已持有。表格"某行发到画布"**直接复用 `sendContentToCanvas`**（入参 = `storyboardModel.rowToText` 拼出的行文字），不新造落画布函数。

**确属新增（无同类件，需新建，归属见 §1.4）**：
- 分镜**表格数据结构 + 归一化**（`columns`/`rows`/`selectedRowId`/`preview`）——项目无现成可编辑表格数据。
- 表格**渲染 + 单元格编辑**（点格改字、加删行、上下移、复制）——`clipboard.sanitizePastedText` **会压平 `\t` 不能用于 TSV 解析**（已核对 `clipboard.ts:37-56`），需在表格入口内**自行解析 TSV(`\t`) / HTML(`<table>`)**。
- 表格内**显式粘贴入口**（与画布级 `useAssetDropPaste` 分流）。
- **行↔JSON 双向映射**（row ↔ `{列名:值}` 对象、`rows[]↔顶层 globalStyle 结构`）。

### 1.5 额外检查（边界矛盾点）

- **确认才写回是数据真相**：改单行/生成初始表都是"AI 出 JSON → 预览 → 确认 → 才写表"。**预览与正式表是两份不同状态**，确认动作是唯一写回闸口，需防"预览误当正式表"。
- **表格归属切换**：切对话/新建对话时，左侧表格必须跟随 `activeConversationId` 变（空表/旧表），不能串话。
- **图只读、不带回**：AI 参考图 URL 只在发出时带上，AI 返回不含图字段；回填只覆盖文字。
- **globalStyle 空值**：随内容自然发 AI（空则 AI 补、有则守），**不加"空则填/非空则守"这类刻意义务逻辑**（需求定稿 §1.4 决策 14）。

### 1.6 表格承载批量：AI 生成整表（需求 + Skill，走对话区）

> **需求补充（2026-09-05）**：表格是**完全可定义**的结构化容器，是将来**批量的承载者**。
> 用户原话："我需要这个表格是完全可定义的。一开始我发一个需求加一个 skill（如'如何把一句话变成一个完整的分镜脚本'），AI 就帮我生成了整个表格。"

**① 生成整表 = 需求 + Skill，走对话区**：
- 入口在 **AI 对话区**（不是表格工具条单独造 Skill 选择 UI）：你在对话框里（已选 Skill / 发一段 Skill 内容 + 一句话需求）→ AI 理解 → **返回整个表格结构 JSON**（列名由 AI 按 Skill 设计 + N 行内容，顶层可带 globalStyle）。
- 表格只承接：AI 返回的 JSON → 渲染成**可视化预览表格** → 你确认 → 落表成可编辑数据。
- **Skill 在这里的角色** = "如何把 X 变成完整 Y"的**方法论指令**，让 AI 知道按什么结构去填表（列/行/内容组织）。它不再是"AI 直接批量跑 N 个 generation 图"的依据。
- **「AI 生成整表」与「改单行」共用同一套 JSON schema**（顶层 globalStyle + 行数组），仅行数/范围不同（整表 vs 单行）。

**② 高度自定义（表生成后可任意改）**：
- 生成只是起点。落表后**完全可编辑**：点格改字、加行/删行/上移/下移/复制、改列名、（后续可按列类型化支持图片列）。
- **选中单行 → 交给 AI 优化/补齐该行**（走对话区，AI 只改该行文字，图只读参考）→ 预览 → 确认写回，可反复打磨。
- 不预设列模板——列/行全由 Skill+需求或粘贴决定，AI 生成后你仍可自由调整结构。

**③ 承载批量（与 AI 助手"批量编排删除"的衔接）**：
- AI 助手现有一套"Skill 三阶段 / AI 规划多 generation 批量执行"将删除（见 `docs/AI助手-执行模型精简方案-2026-09-05.md`）。
- 批量由**本表格承接**：Skill + 需求 → AI 产出**结构化内容行**（非直接生成图）→ 落表 → 你编辑确认 → **逐行/整表触发生成**。
- 表格的"逐行触发生成"走"单行内容 → 建节点 → 生成"的底层（execute_plan 单 gen 能力保留给交互式生成），不需要 AI 现场造 generation 数组。
- **确认 UI**：AI 生成整表 / 改单行的"确认写回"沿用现有 `AgentConfirmCard` 类确认交互；该确认卡将来也服务表格的"整表/批量确认后生成"（`docs/AI助手-执行模型精简方案` §保留清单里确认卡 UI 先保留、注明改造即为此）。

**数据流一句话**：对话区发「需求 + Skill」→ LLM 返回表结构 JSON → `storyboardModel.jsonToSb` → 渲染预览 → 确认 → `setCurrentStoryboard` 落表(可编辑) → 之后逐行打磨/逐行触发生成。

## State 2：定数据流（链路 / 唯一入口 / 契约登记）

### 2.1 数据从哪来、经哪些模块、落哪

核心链路（单向，无环，对齐 `agent/index.ts` 顶部全景）：

```
[分镜表状态] StoryboardPanel(左栏)
   │ 读写
   ▼
session-memory 字段 storyboard(per-conversation)   ←── 唯一数据真相源
   │ setCurrentStoryboard(…)  →  conversationStore.commit → contentStore 落盘(自动)
   │
   ├── [粘贴] StoryboardPanel.onPaste ──► storyboardModel.parsePasted(clipboardData) 纯函数
   │                                              │ 产出 { columns, rows }
   │                                              ▼  (State1 A)
   ├── [生成初始表 / 改单行] StoryboardPanel ─► send(带 storyboardPrompt.user) 
   │                                        → useAgentChat.send(text) → LLM
   │                                              │ 返回 精简 JSON
   │                                              ▼
   │                               StoryboardPanel: renderPreview(json) → 确认 → setCurrentStoryboard(写回)
   │
   ├── [选中行作上下文] 点选行(+画布图) → send(拼入选中行文字 + globalStyle + refImage)
   │
   └── [单行落画布] StoryboardPanel.onSendRowToCanvas(row)
        → storyboardModel.rowToText(row) 拼成文字
        → 复用 useAgentChat.sendContentToCanvas(text)   ← 既有「发到画布」按钮同一函数
        → callTool('create_node', { type:'textNode', text }) → canvasHost 建 textNode
```

**每条链路的输入 / 输出 / 失败拦截点**：

| 链路 | 输入 | 模块 | 输出/副作用 | 失败在哪拦截 |
|---|---|---|---|---|
| 会话记忆读写 | patch `{ storyboard }` | `conversationSnapshot/aiState` + `conversationStore.commit` | 落盘 KV（防抖 300ms + pagehide flush） | `commit` 内 `reportDegrade` 可见；异步由 `withTimeout` 兜 |
| 粘贴解析 | `clipboardData` | `storyboardModel.parsePasted`（纯函数） | `{ columns, rows }` 或 `null`(非法) | 解析失败返回空/显式错误，UI toast，不落半成品 |
| AI 生成/改行 | user prompt | `useAgentChat.send` → LLM | AI 返回 JSON → 预览 | `send` 已有 error/sending 态；JSON 解析失败停在预览（透传原因） |
| 确认写回 | 预览确认 | StoryboardPanel → `setCurrentStoryboard` | 表行更新 | 写回即 commit，失败经 logger/toast 可见 |
| 单行落画布 | 定稿行 | `storyboardModel.rowToText` + 复用 `sendContentToCanvas` | 画布 textNode | `sendContentToCanvas` 内部 `callTool('create_node')` → canvasHost，失败返回 `{ok:false,error}`，不静默 |

### 2.2 统一解析/序列化：强制复用既有统一器，禁就地 parse

- **JSON 精简契约**：生成初始表 / 改单行，都走**同一套"顶层 `globalStyle` + 行数组"输出格式**，形态**照抄** `scriptBoxPrompts.ts` 的 `SCRIPT_WRITER_FORMAT`（"只返回纯 JSON 不解释不 Markdown"）——**不新造一套**。可把该输出契约抽成工作区自己的 `storyboardPrompt.ts`，但**形态/措辞对齐剧本盒**，禁止另起风格。
- **TSV/HTML 解析**：项目**没有**能保留 `\t` 的现成表格解析统一器（`clipboard.sanitizePastedText` 会压 Tab）。这是**新增能力层唯一入口**：`storyboardModel.parsePasted`，只此一处解析表格粘贴，禁止在组件里 `split('\t')` 各写各的。
- **信封剥离/存储路由**：分镜表不新增 KV 键（走会话记忆字段），故**不新增中央解析器**；行↔JSON 映射是**领域内纯函数**（`rowToObj`/`objToRow`），属 `storyboardModel`，不污染全局信封解析。
- **会话字段落盘**：沿用 `normalizeMemory`/`normalizeConversation` 体系——新增 `storyboard` 字段必须在 `conversationState.ts` 的 `emptyMemory`/`normalizeMemory`/`RawMemory` **成对登记**，反序列化入口统一归一，防历史字段/脏数据。

### 2.3 契约常量先查登记（禁裸字面量）

| 用途 | 契约登记处 | 动作 |
|---|---|---|
| 会话存储键 `agent_conversations_{agentKey}` / `agent_active_conversation_id_{agentKey}` | `contracts.ts` `STORAGE_KEYS`（已登记，backend:kv） | **复用，不改** |
| 记忆字段 `global_contract`/`artifacts`/新增 `storyboard` | `conversationState.ts` `ConversationMemory`/`RawMemory`/`normalizeMemory` | **登记**：把 `storyboard` 字段类型 + 归一加进去 |
| globalStyle 通道 | `memory.global_contract.unified_style_prompt`（`conversationAiState` 已有 `set/getCurrentGlobalContract`） | **复用**：工作区 globalStyle 映射该字段，不造第二个全局风格字段 |
| （若需）面板/子模块事件 | `contracts.ts` `EVENTS` | 仅当确有发布↔订阅才登记；**默认不新增事件**（面板内部 state 自洽即可，避免死事件） |

> 结论：本功能**几乎不新增全局契约**——存储键复用会话 key、globalStyle 复用既有字段、不新增事件。新增的仅是 `storyboard` 这一**会话记忆内聚字段**（单一数据源，顺着 `global_contract`/`artifacts` 的既有一致写清）。

### 2.4 幂等 / 去重 / 时序

- **行 id**：新增行/粘贴行必须带**稳定唯一 id**（复用 `uid('row')` 即 `conversationState.uid` / `idGen.generateId`），禁 `Date.now()` 当键、禁数组 index 当 key（增删行会串）。对齐 `normalizeConversation` 对消息补 id 的幂等写法。
- **会话跟随**：表格读当前 `activeConversationId`；切对话/新建对话时 `useEffect` 重新从该会话记忆读 `storyboard`，并**清本地预览/选中态**（防跨对话串）。
- **防抖**：点格编辑只改本地编辑态；落表走 commit（既有 `persistDebounced` 已防抖落盘）。大量 `columns/rows` 变更**不裸奔**逐字落盘。

### 2.5 避交叉 / 避黑盒

- 单向：StoryboardPanel → `storyboardModel`(纯函数) / `conversationStore`(读写会话) / `useAgentChat`(发 AI)。不反向 import 大模块，无环。
- 不静默吞错：`send` 走 async + 原样透传 error（对齐现有 `handleSend` 的 `Promise.resolve(send()).catch(logger.error)` 模式）；JSON 解析失败停在预览并透传原始原因，**禁止 `catch(()=>{})` 或抛泛化"出错了"**。
- 全异步总超时：AI 调用与任何网络都在 `useAgentChat`/`roundTrip` 侧有总超时（复用既有 `withTimeout`），表格自身不新增裸 fetch。

## State 3：构思测试（细化契约 + 数据流 → 可断言）

> 判定红线：断言须"实现一变必红"，禁自证式（仅验不崩 / mock 被调用无效）。

### 3.1 `storyboardModel` 纯函数单测（核心，重仓）

1. **parsePasted(TSV 文本)**：给 `"列A\t列B\n中景\t人物走入"` → 得 `{ columns:['列A','列B'], rows:[{…首个数据行}] }`；**首行为表头，其余为数据行**；空剪贴板/无表头返回 `null`/空（契约：粘贴空数据不落表）。
2. **parsePasted(HTML `<table>`) 保留 Tab 不被压平**：断言多格多行还原正确（区别于 `sanitizePastedText` 会压 `\t`——本实现必须自解析）。
3. **rowToObj / objToRow 带列名**：行转 `{列名:值}` 后，改单行发给 AI 时**每值带列名**（`列A:…`），可还原不丢字段。
4. **rowsToJson / jsonToRows（顶层 globalStyle + 行数组）**：`{ globalStyle, rows:[…] }` → AI 生成/改行共用同一 schema，roundtrip 数据不丢；`globalStyle` 空时照常序列化（不进内容、不加约束）。
5. **增删/上下移/复制行**：返回**新数组、原行引用不动**（不可变），行 id 稳定不重生成；删行后行序正确。

### 3.2 会话记忆字段（conversationState/aiState）测试

6. **normalizeMemory 含 storyboard**：给定宽松 `RawMemory`（缺 storyboard / 旧字段）→ 归一结果 `storyboard` 字段形状齐全；空则默认空表（对齐 `emptyMemory`）。
7. **per-conversation 隔离**：`setCurrentStoryboard(表A)` → `switchConversation(另一会话)` → 读回为空/旧会话的表；切回 A → 表 A 仍在。断言不跨对话串表。
8. **setCurrentStoryboard 幂等**：重复写同值不产生多余消息对象/行 id 漂移。

### 3.3 AgentPanel / 交互（组件关键路径 + 防崩）

9. **选行上下文**：点某行 + （选画布图）→ 断言传给 `send` 的 user 文本**含该行（带列名）与 globalStyle**；画布图 URL 进入参考图附件链路。
10. **确认才写回**：AI 返回 JSON → 先渲染预览（**不改正式表**）→ 未点确认时 `storyboard` 不变；点确认后才写回该行。断言"预览改数据"这一违规路径被拦。
11. **切对话重置**：`activeConversationId` 变化 → 表格/预览/选中态重置为对应会话，不残留上一会话。

### 3.4 写不出断言的即退回

凡某条链路写不出「给定输入→期望经链路→期望输出」断言，说明契约或数据流没定清 → **退回 State 1/2 补边界/补链路**，不硬施工。

```ts
/** 表格单元格（数据层是字符串；编辑态由 UI 层持有） */
export type CellValue = string

/** 一列：列名 = 粘贴首行 / AI 设计，顺序即显示顺序 */
export interface StoryColumn { id: string; label: string }

/** 一行：稳定 id + 各列值；值以「列 id → 文本」映射（列增删不毁行） */
export interface StoryRow {
  id: string                      // uid('row')，稳定唯一，禁 index/Date.now()
  values: Record<string, CellValue>  // [columnId]: text
}

/** 分镜表模型（会话记忆内聚字段） */
export interface Storyboard {
  columns: StoryColumn[]
  rows: StoryRow[]
  // 全局风格映射到会话 memory.global_contract.unified_style_prompt，不在本表重复存
}

/** 宽松/反序列化形态（供 normalizeStoryboard 归一，兼容历史/脏数据） */
export interface RawStoryboard {
  columns?: unknown[]
  rows?: unknown[]
  [key: string]: unknown
}

/** AI 生成初始表/改行的统一精简 JSON（对齐剧本盒「顶层 globalStyle + 行数组」） */
export interface StoryboardJson {
  globalStyle?: string
  rows: Array<Record<string, unknown>>  // 每行：{ 列名: 值 }
}
```

### 4.4 防返工自检（每步过一遍）

- 代码是否偷偷引入 State2 未声明的依赖/状态？——分镜表数据只从当前会话记忆来，不新造本地 store。
- 是否偏离已定链路？——发 AI 只经 `useAgentChat.send`；落画布只经 `canvasHost`；落盘只经 `commit`/`setCurrentStoryboard`。
