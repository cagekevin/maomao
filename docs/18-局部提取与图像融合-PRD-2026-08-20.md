## 0. 定位（全局基线）

**项目定位**：在猫猫画布（`src/` React 原型）复刻「局部提取与图像融合」能力——用户从原图框选局部区域，独立处理（改图/放大/生成）后，携带裁剪上下文无缝融合回原图，支持多选区、颜色匹配、羽化边缘。

**使用对象**：99% 单人自用（与项目产品定位铁律一致），操作流畅第一要求，不做过度防御。

**核心价值**：解决「局部改动原图某一块，又不破坏全图」的痛点——局部改、整体合，可追溯上下文防止融合错原图。

**架构红线（继承自项目）**：cropContext 契约是跨模块唯一锚点；错误必须真实透传不归一化；不覆盖任何输入文件；新节点按 NEW-NODE-GUIDE 三同步；新增存储键/事件/节点类型先在 `contracts.js` 登记。

**后端处理确认**：图像处理算法（裁剪/融合/指纹）**全部由后端承担**（对照插件 `backend.py` + `local_patch_ops.py`），前端只发请求、拿结果、做编排。映射到本项目：算法收口到 **localTool（Node/TS，复用 Jimp 类图像库）**，前端经既有代理链路调用（`proxyMode=local-tool` → `:18080` → `/api/proxy`）。**不塞进 apimart-gateway（网关是中继职责）**。插件三接口 `/crop` `/merge` `/fingerprint` 翻译为本项目 localTool 新路由（`contracts.js` 的 `BACKEND_ROUTES` 需登记）。

**插件与项目「文件域」映射**：插件 `resolve_image` 只处理 `/assets/` 或 `/output/` 图片；本项目原图在 `/files/` 落盘。裁剪/融合的源图 URL 以本项目 localTool 文件 URL 为准，映射关系写码时在 localTool 侧收敛（不引入新文件域）。

## 1. 模块拆解（第 1 层全局骨架，已确认）

### 1.1 模块列表（4 个互不重叠模块）

| # | 模块 | 一句话职责 |
|---|------|-----------|
| **M1** | 裁剪上下文管理 | 提取选区时生成 `cropContext`（选区 rect + paddedRect + 原图指纹 + 宽高），随局部图传播/持久化/恢复，融合前校验归属 |
| **M2** | 选区提取（前端交互） | 画布图片节点「提取选区」入口 + 裁剪交互，裁剪出局部图并注入上下文 |
| **M3** | 图像融合节点 | 新增「图像融合」节点：左连原图、右连局部图（多连线/多图切换），执行融合算法并输出结果 |
| **M4** | 融合算法引擎（后端） | 裁剪/校验/羽化/颜色匹配/多图合并算法，前端经代理调用 |

### 1.2 依赖关系（互不重叠校验）

- M2→M1（裁剪时生成上下文）、M3→M1（融合前读上下文校验）、M3→M4（执行融合）、M4→M1（消费上下文契约）。
- **唯一共享依赖** = M1 的 cropContext 数据结构（全局契约锚点）。无环、无重叠。

### 1.3 三大翻车点（全局）

1. **cropContext 传播断裂**：局部图经多轮处理/刷新后上下文丢失 → 融合被拒。核心是数据契约完整性。
2. **原图溯源校验边界**：指纹 + 尺寸校验边界处理不好 → 误拒或误合错原图。
3. **前端画布与后端引擎衔接**：插件是 Python+WebSocket 体系，不能直接搬运，需翻译进 React 原型 + localTool 代理架构，照抄会踩项目红线。

## 2. M1 裁剪上下文管理（✅ 已细化，已确认）

### 2.1 M1 边界

纯数据层：定义/生成/传播/校验 cropContext。**不涉及 UI**（M2）、**不涉及融合执行**（M3/M4）。

### 2.2 M1 子模块（6）

| # | 子功能 | 职责 |
|---|--------|------|
| M1-1 | 上下文结构契约 | 定义 cropContext 字段 + 版本号（constants 登记） |
| M1-2 | 上下文生成 | 由原图指纹 + EXIF 修正尺寸 + 选区 rect + paddedRect 生成 |
| M1-3 | 上下文注册表 | `contextRegistry`：`byUrl` / `byFingerprint` 双向注册 + `urlFingerprints`，同文件不同 URL 可恢复同一上下文 |
| M1-4 | 传播/继承 | 上下文沿连线向下游输出传播：遮罩图清空、边界图清空、多上下文冲突标记、单上下文继承 |
| M1-5 | 持久化/恢复 | 挂节点 data + 文件元数据 + 注册表，刷新/复制/拖回/导入同指纹恢复 |
| M1-6 | 上下文校验 | 融合前校验版本/结构/rect/指纹/尺寸，输出明确错误 |

### 2.3 M1 翻车点

- **M1-a 上下文挂载分散**：节点 data、文件元数据、注册表三处协同，同指纹互恢复，防刷新丢失。
- **M1-b 指纹计算成本与时机**：提取算一次，融合重算对比，大图走后端。
- **M1-c 数组型输出归一化**：多张图各自携带 contextId，不丢不串。
- **M1-d 继承规则遗漏**：遮罩图/边界图/冲突图各自的上下文处理规则不实现，会导致遮罩图误融合、冲突未标记、边界未清除。

### 2.4 M1 约束 + 验证标准

| 约束 | 原文 | 验证标准 | 支撑跨模块 |
|------|------|---------|-----------|
| C1.1 | cropContext 字段+版本登记为全局契约，禁裸字段 | grep 无裸字段；check:keys 覆盖 | X1 |
| C1.2 | 上下文注册表：`contextRegistry`（byUrl/byFingerprint/urlFingerprints），同文件不同 URL 恢复同一上下文 | 单测：同指纹经不同 URL/拖入/导入，恢复相同 contextId | X1 + 核心价值 |
| C1.3 | 上下文双挂节点 data + 文件元数据 + 注册表，同指纹刷新/复制/拖回恢复 | 单测：复制→新节点→同指纹恢复相同 contextId；刷新被覆盖能从文件/注册表回填 | X1 + 核心价值 |
| C1.4 | 数组型输出每张图各自携带/恢复上下文 | 单测：2 图各带不同 contextId，归一后逐一对应 | X1 |
| C1.5 | 继承规则：遮罩角色图清空上下文；边界图（完整图标记）清空；多上下文打冲突标记；单上下文下游继承 | 单测：遮罩图不传播；边界图清除局部上下文；混合上下文置 conflict；单一上下文下游继承 | X1 + M1-d |
| C1.6 | 校验错误明确透传，禁归一化 | 单测：版本/指纹/尺寸/rect 各错各报明确原因；前端不吞错 | X2 |

## 3. M2 选区提取（前端交互）（✅ 已细化，已确认）

### 3.1 M2 边界

在画布图片节点上提供「提取选区」入口与裁剪交互，用户框选原图局部区域，确认后调用后端裁剪出局部图，并为该局部图注入 cropContext（由 M1 生成）。**不涉及**上下文结构定义（M1）、融合（M3/M4）。

### 3.2 M2 子模块（4）

| # | 子功能 | 职责 |
|---|--------|------|
| M2-1 | 入口收敛 | 图片节点统一工具栏「提取选区」+ 预览编辑器入口，指向既有预览/编辑器 |
| M2-2 | 选区交互 | 复用原项目裁剪框/比例/缩放/拖动能力，返回选区 rect + 原图尺寸 |
| M2-3 | 裁剪落盘 | 把原图路径 + 选区 rect 提交后端，生成局部图新文件，并调用 M1 生成 cropContext |
| M2-4 | 上下文注入 | 裁剪结果节点 data 挂 cropContext，成为后续处理链的「上下文起点」 |

**依赖**：M2-1 → M2-2 → M2-3 → M2-4；M2-3 依赖 M1（生成上下文）、M4（裁剪算法）。无环。

### 3.3 M2 翻车点

- **M2-a 复用既有 ImageEditor 的侵入**：评估扩展现有编辑器加模式 vs 独立入口，遵守「重构边界铁律」，避免破坏现有预览/裁剪或引入回归。
- **M2-b 裁剪选区与原图尺寸基准不一致**：前端选区 rect 必须经 EXIF 修正尺寸换算后提交，禁止拿预览缩放坐标直接提交，否则裁剪偏移。
- **M2-c 上下文起点注入时机**：裁剪落盘与上下文注入必须原子完成，注入到裁剪结果节点，避免「有图无上下文」中间态导致后续融合报「局部图没有上下文」。

### 3.4 M2 约束 + 验证标准

| 约束 | 原文 | 验证标准 | 支撑跨模块 |
|------|------|---------|-----------|
| C2.1 | 入口收敛：图片节点工具栏「提取选区」+ 预览编辑器入口，复用既有机制最小侵入 | 现有 ImageEditor/预览/裁剪回归无变化；新增入口后原功能可用 | X1 + 操作流畅 + 重构边界 |
| C2.2 | 选区 rect 经 EXIF 修正尺寸换算后提交，禁拿预览缩放坐标直接提交 | 单测：EXIF 旋转原图，断言换算后 rect 与后端源尺寸一致；尺寸不符报「原图尺寸已变化，请重新框选」 | X1 + M2-b + X2 |
| C2.3 | 裁剪落盘 + 上下文注入原子完成 | 单测/回归：裁剪成功后新节点必有 cropContext；失败无孤立文件或正确清理 | X3 + X1 |
| C2.4 | 裁剪结果一律保存为新文件，不覆盖原图 | 断言原图文件指纹不变；新文件路径不同于原图 | X3 |
| C2.5 | 裁剪错误（选区<32px/越界/尺寸变化）明确透传，禁归一化 | 单测：各错误各报明确信息；前端 toast 不吞错 | X2 |

## 4. M3 图像融合节点（✅ 已细化，已确认）

### 4.1 M3 边界

新增「图像融合」节点：左连完整原图、右连一张或多张局部修改图（多连线/多图切换），调用 M4 融合算法，把局部图按各自 cropContext 无缝融合回原图，输出新结果节点，不覆盖任何输入。**不涉及**上下文结构定义（M1）、选区提取（M2）、算法实现（M4）。

### 4.2 M3 子模块（4）

| # | 子功能 | 职责 |
|---|--------|------|
| M3-1 | 节点骨架 | 按 NEW-NODE-GUIDE 建 NodeShell + Palette 注册 + NODE_OUTPUTS 三同步 |
| M3-2 | 端口与多图输入 | 左端口收完整原图、右端口收局部图（多连线 + 每图独立切换），端口不覆盖预览 |
| M3-3 | 融合编排与校验 | 收集所有输入 cropContext，委托 M1 校验归属，冲突/不符则阻止并报明确错误 |
| M3-4 | 融合执行与输出 | 调 M4 融合算法，结果作为新节点/输出，不覆盖任何输入 |

**依赖**：M3-1 → M3-2 → M3-3 → M3-4；M3-3 依赖 M1（校验）、M3-4 依赖 M4（算法）。无环。

### 4.3 M3 翻车点

- **M3-a 上下文冲突判定粒度**：所有局部图须来自同一原图（同指纹+同尺寸）、允许不同选区；判定须精确到「原图指纹+尺寸」层而非 contextId 个体，避免误拒或融错原图。
- **M3-b 数组型输入每图选择与上下文对应**：右侧多连线 × 连线内多图，每图选择 + 自身 cropContext 要一一对应，不能错配。
- **M3-c 结果「新原图」语义**：融合结果清除局部上下文并标记「完整图边界」，可再作新原图提取，不追溯上一轮局部图。
- **M3-d 端口连接语义遗漏**：original 端口只允许单连线（重复连线替换），patch 端口允许多连线（每条独立 connectionKey + 独立图选择索引）；混淆会导致原图被覆盖或图选择错乱。

### 4.4 M3 约束 + 验证标准

| 约束 | 原文 | 验证标准 | 支撑跨模块 |
|------|------|---------|-----------|
| C3.1 | 节点范式三同步：NodeShell + Palette + NODE_OUTPUTS；节点类型/参数命名空间在 contracts 登记 | check:node-types / regression 通过；节点出现在 Palette，下游能拿到结果 | X1 + 节点体系红线 |
| C3.2 | 端口连接语义：original 端口单连线（重复替换）；patch 端口多连线，每条独立 connectionKey + 独立图选择索引 | 单测/回归：重复连 original 替换而非新增；patch 多条连线各自维护选择索引不互相覆盖 | X1 + M3-d |
| C3.3 | 多图输入 + 每图独立选择，每个选中图带自身 cropContext | 单测：数组 2 图各带不同 contextId，切换后断言送审上下文与选中图一一对应 | X1 + M3-b |
| C3.4 | 上下文冲突精确判定（原图指纹维度）：同原图不同选区可融合，不同原图判冲突阻止 | 单测：同原图不同选区可融合；不同原图局部图报「上下文冲突」阻止 | X1 + M3-a + 核心价值 |
| C3.5 | 融合数量上限：一个融合节点一次最多融合 16 张局部图 | 单测：>16 张报「一次最多融合 16 张局部修改图」阻止 | X2 |
| C3.6 | 结果不覆盖输入 + 新原图语义：结果新文件、清局部上下文、标记完整图边界、可再提取 | 单测：输入指纹不变；结果节点无 cropContext（或完整图标记）；可再提取新选区 | X3 + M3-c |
| C3.7 | 结果「对比原图」功能：结果节点附带原图引用（comparisonOriginalUrl），预览支持原图/结果滑杆对比 | 回归：点击结果进入预览有「对比原图」；滑杆可拖动对比；无原图引用则不显示该按钮 | 核心价值（可视化融合效果） |
| C3.8 | 融合错误明确透传并阻止，禁归一化 | 单测：冲突/指纹/宽高比/遮罩各错各报明确原因；前端不吞错；未成功不产生结果 | X2 |

## 5. M4 融合算法引擎（后端）（✅ 已细化，已确认）

### 5.1 M4 边界

提供图像融合核心算法服务：裁剪局部图、溯源校验（指纹/尺寸/宽高比）、羽化边缘、颜色匹配、多图合并回原图。前端经 localTool 代理调用，算法收口独立模块。**不涉及**上下文结构定义（M1）、前端交互（M2）、节点 UI（M3）。

### 5.2 M4 子模块（4）

| # | 子功能 | 职责 |
|---|--------|------|
| M4-1 | 裁剪算法 | 按选区 rect + padding 从原图裁出局部图（EXIF 修正、尺寸校验） |
| M4-2 | 溯源校验 | 校验 cropContext：原图指纹 + EXIF 修正尺寸 + paddedRect 范围 + 局部图宽高比 |
| M4-3 | 融合算法 | 羽化边缘（smoothstep）+ 可选颜色匹配 + 多图顺序合并回原图 |
| M4-4 | 服务接入 | 在 localTool 暴露裁剪/融合接口，前端经代理调用，结果保存为新文件 |

**依赖**：M4-1 → M2 调用；M4-2 → M4-3 前置；M4-3 依赖 M4-2；M4-4 编排三者对外暴露。整体消费 M1 契约。无环。

### 5.3 M4 翻车点

### 5.5 M4 接口错误码语义（写码对照）

- **409**：`SourceChangedError`（原图尺寸/指纹与裁剪来源不一致，用户换错原图）。
- **400**：`LocalPatchValidationError`（选区过小/越界/宽高比改变/超过 16 张/缺上下文等校验类）。
- **500**：兜底异常（裁剪/融合/指纹计算失败）。
- 错误信息必须**真实透传**，前端展示原文（如「原图指纹与裁剪来源不一致」「局部图宽高比已改变，无法安全还原」），禁归一化。
