## 一、根因：间距全在给「量不到的悬浮面板」让位

输入面板 `ExpandablePanel` 定位是 `absolute top-full left-1/2 -translate-x-1/2`（`ExpandablePanel.tsx:51`）——**它是悬浮层，不占节点尺寸**：

- dagre 量到的只有主框（生图/文本宽 `420`，视频 `baseSize=380`；见 `NodeShell.tsx:266-270`）；
- 但面板实际 `minWidth=500`（生图/视频）或 `420`（文本）、`max-w-[920px]`、高约 300~360px，**向下压在下一行节点上**；
- 所以 `nodesep/ranksep=300`、`GAP_X=300`、`GAP_Y=400` 本质是在给这条"量不到的尾巴"留安全距离。

**后果**：图被撑开 → `fitView` 后 `zoom` 被压得很小 → 节点小到看不清。这就是"整理完不舒服"的直接原因。

---

## 二、目标：Ctrl+L = 清爽总览，Tab = 回到编辑

| 键 | 语义 | 行为 |
|---|---|---|
| **Ctrl+L** | 清爽总览 | 收起全部输入面板 → 按"收起后的干净盒子"紧密排版 → 按视窗比例择优换行 → `fitView` 后节点最大最清晰 |
| **Tab** | 回到编辑 | 展开面板，继续写提示词 |

一句话：**Ctrl+L 排的是"收起后的样子"，所以不需要再给面板留位置。**

## 三、方案正文

### 步骤 1：整理前先收面板（已有，需修正范围）

`arrange()` 写回时已做 `data.expanded = false`（`useArrangeCanvas.ts:216/232`）——**这一步已有，不新增逻辑**，只需修正作用范围（见步骤 2）。

### 步骤 2：收口「哪些节点有输入面板」，修 Tab 与 Ctrl+L 不对称

**现状问题**：

- `Tab`（`App.tsx:994-1006`）只处理 `textNode / promptNode / discountVideoNode` 三类；
- `arrange` 对**所有节点**无差别写 `expanded:false`；
- `TemplateNode` 也有 `ExpandablePanel`（`TemplateNode.tsx:416`）但不在 Tab 范围内 → **Ctrl+L 收了、Tab 展不回**。

**修法**：在 `src/components/base/canvas/nodeDefaults.ts` 导出唯一常量：

```ts
/** 有输入面板（ExpandablePanel）的节点类型：Tab 折叠与 Ctrl+L 整理共用同一范围 */
export const INPUT_PANEL_NODE_TYPES = [
  'textNode',
  'promptNode',
  'discountVideoNode',
  'templateNode',
] as const;
```

- `App.toggleInputPanels` 的 `targetTypes` 改用它；
- `useArrangeCanvas` 写 `expanded:false` 时只对该集合内的类型生效（其它节点 `data` 原样透传，不再无差别改）。

**⚠️ 配套必改（否则 D3 白做）**：`TemplateNode` **缺外部同步**。
`TextNode:122-125` / `PromptNode:238-241` / `DiscountVideoNode:168-171` 都有 `useEffect` 把 `data.expanded` 同步回本地 `state`，而 `TemplateNode:181` 只有 `useState(data.expanded…)`、**没有同步 effect** → 外部改 `data.expanded` 对它无效（Ctrl+L 收不掉、Tab 也展不开）。
补一个与另三类一致的同步 `useEffect` 即可。

> `ImageBoxNode:100` 是 `const expanded = data.expanded ?? false`（不用本地 state），无此问题，且它没有 `ExpandablePanel`，不纳入集合。

### 步骤 3：按"干净盒子"收紧间距（D1 紧凑档）

面板收起后，节点视觉尺寸 ≈ 主框尺寸，间距从"给面板让位"降为"纯视觉呼吸"。

| 参数 | 现状 | 改为 | 理由 |
|---|---|---|---|
| `nodesep`（dagre 同层间距） | 300 | **80** | 收起后无面板，只需呼吸感 |
| `ranksep`（dagre LR 层间距） | 300 | **180** | 要容下横向连线与端口，比行距大 |
| `GAP_X`（分量横向） | 300 | **180** | 与 `ranksep` 对齐，一套视觉节奏 |
| `GAP_Y`（分量换列纵向） | 400 | **120** | 收起后无需给面板留 340px |
| `COL_MAX_W`（换列阈值） | 2500 绝对值 | **删除** | 改为按视窗比例择优（步骤 4） |

> dagre 的 `nodesep`/`ranksep` 是**边到边的净间距**（不含节点自身尺寸），故 80/180 就是净空隙。

### 步骤 4：按视窗比例择优换行

**动机**：`fitView` 实际缩放 = `min(vw / W, vh / H, maxZoom=1)`。换列方式决定整体包围盒 `(W, H)`，直接决定整理后节点有多大。

**算法**（纯函数 `packComponents`，新建 `src/components/base/utils/arrangePack.ts`，便于单测）：

```
输入：boxes[]（各连通分量包围盒 w/h）、viewport（画布视窗 w/h）、gapX/gapY、maxZoom
对 perRow = 1..n 逐个试排：
    · 逐行放置，每行至多 perRow 个分量；行内 x 递增，行 y = 上一行底部 + gapY
    · 行宽 = 该行 Σw + gapX*(k-1)；行高 = 该行分量最大 h
    · 得到整体包围盒 (W, H) 与各分量 placement
    打分：scale = min(vp.w / W, vp.h / H, maxZoom)   ← 即 fitView 后的真实缩放
取 scale 最大的 perRow（同分取更大的 perRow：行更少，更贴近"从左到右"阅读流向）
```

- **收益**：宽屏（1600×900）自动选接近 16:9 的行列分布，避免"一行长龙"或"一列到底"，`fitView` 后节点最大化。
- **复杂度**：`O(n²)`，`n` = 连通分量数（常规几十），可忽略。
- **兜底**：视窗尺寸不可用退化为 `1600×900`；`n=1` 直接返回单点。

**视窗尺寸来源**：`App` 内用 `useStoreApi().getState()` 读 `store.width/height`（ReactFlow store 已有，`@xyflow/react/dist/esm/types/store.d.ts:5-6`）。
用 `useStoreApi`（引用稳定）而**不用** `useStore(selector)`——避免 App 因视窗尺寸变化重渲染（P0-C 性能红线，同 `App.tsx:128-133` `ZoomPercent` 的处理）。

### 步骤 5：删除编组折叠状态（D4）

**为什么现在删**：折叠态 group 渲染成 40px 小胶囊，但 `useArrangeCanvas.groupSize()` 仍按子节点外接矩形算尺寸 → **折叠态 group 的排版尺寸算错**。间距收紧后这个误差会被放大。既然编组不需要第二种形态，整套下线最干净。

#### 5.1 影响面（已全量 grep 确认，共 5 处源码 + 4 处测试）

| # | 位置 | 改动 |
|---|---|---|
| S1 | `src/components/nodes/GroupNode.tsx` | 删折叠态胶囊分支（`:82-103`）、`toggleCollapse`（`:39-79`）、`GroupNodeData` 的 `collapsed/expandedWidth/expandedHeight`（`:20-23`）；随之清理不再用的 import（`Handle`/`Position`/`useReactFlow`/`FoldVertical`/`ChevronsUpDown`）与 `titleRight` 折叠按钮 |
| S2 | `src/App.tsx:1217-1228` | 删 `visibleNodes` 的 `collapsedGroups` 兜底 → 该 `useMemo` 整体删除，`ReactFlow` 的 `nodes={visibleNodes}`（`:1312`）改回 `nodes={nodes}` |
| S3 | `src/App.tsx:173-187` | 删快照加载时的 `collapsedById` hidden 对齐兜底 → 简化为直接 `setNodes(rawNodes)` |
| S4 | `src/components/base/canvas/groupNodes.ts:225` | 候选 group 过滤去掉 `&& !n.data?.collapsed`，保留 `n.type === 'group' && n.id !== draggedNode.id` |
| S5 | `src/components/base/canvas/nodeDefaults.ts:50-60` | **保留只读、不再写入**：`expandedWidth/expandedHeight` 兜底逻辑不动（存量快照仍靠它救回尺寸），只是 GroupNode 不再写这两个字段 |

> S5 说明：折叠时记录的 `expandedWidth/expandedHeight` 是"刷新后编组大小变了"的历史修复（见该文件注释）。删折叠后不再产生新值，但存量值仍有效——**保留读取零风险、删掉会让存量编组尺寸退化**，故保留。

#### 5.2 ⚠️ 存量快照迁移（必做，否则丢数据）

存量快照里可能存在：group `data.collapsed:true` + 子节点 `hidden:true`。删掉折叠渲染后，group 会正常显示，但**子节点因残留 `hidden:true` 而永久消失**。

**迁移做法**（放在 S3 同一处，即 `applyNodeTypeDefaults` 之后）：

```
加载快照时：凡 parentId 指向 group 的子节点，一律 hidden: false
（group 不再折叠 → 其子节点不应存在 hidden:true）
```

同时清除 group `data` 里的 `collapsed` 字段（可选，不清也不影响渲染，因已无读取方；清掉更干净）。

#### 5.3 编组在排版中的既有保障（不要动）

以下已实现且正确，本次保持不变：

- group 作为**顶层节点整体**进 dagre，尺寸 = 子节点外接矩形 + `GROUP_PAD(40)×2`（`useArrangeCanvas.ts:95-110`）；
- 子节点不进 dagre、不 `setParent` → **组内摆放原封不动**，父框移动后子节点随 React Flow 父子关系整体平移；
- 连通分量邻接表含 `parentId` 双向边 → group 与子节点不会被拆成两个分量（`:150-155`）；
- **不跳变**机制：以首个顶层节点为锚做最小平移（`:240-254`）。

**额外收益**：group 折叠用的字段是 `data.collapsed` 而**不是** `data.expanded`（`GroupNode.tsx:33`），所以步骤 2 的 `expanded:false` 本来也不会误折叠编组；删掉折叠后这条顾虑彻底消失。

## 六、明确不做

- **不动 `ExpandablePanel` 的定位方式**（`absolute top-full`）。改成占布局会牵动所有节点的尺寸/端口/自适应链路，风险远大于收益。
- **不引入新依赖**。`packComponents` 是纯 JS。
- **不改 dagre 选型与 `rankdir=LR` 主方向**（与官方一致，源码注释已记抉择）。
- **不改「不跳变」机制**（`useArrangeCanvas.ts:240-254`）。新方案只在"分量如何摆"这一层改。
- **不碰 `src/components/director3d/` 下的 `collapsed`**。那是 3D 编辑器（`Inspector.tsx`/`ReferenceOverlay.tsx`/`styles.css`）自己的折叠，与画布编组无关。
- **删 `nodeDefaults.ts` 的 `expandedWidth/expandedHeight` 读取**（见 S5：保留只读以兼容存量）。
