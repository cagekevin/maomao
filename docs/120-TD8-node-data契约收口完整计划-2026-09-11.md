### 阶段 1 · 清空遗留字段 5 处（⛔ 验证否决：全部为功能性清空，禁止删除）

**验证结论（2026-09-11 实测，全只读 grep）**：`check-node-data.mjs` 表 2b 的"清空遗留字段"是启发式（"写 undefined = 退役残留"），对以下 5 处产生**误报**——它们都是有目的的功能性清空，删除会引入真实 bug：

| 字段 | 写点 | 为何必须清（删了会怎样） |
|---|---|---|
| `assetNode.imageUrl` | AssetNode.tsx:232 | 切文本态时清空主图；不删 → `data.imageUrl \|\| data.url` 兜底读回旧图，文本态节点显示旧图 |
| `assetNode.url` | AssetNode.tsx:233 | 存量兼容字段（写侧已只写 imageUrl，见 nodeImage.ts:9 / Director3DNode.tsx:176）；旧快照带 `url` 的节点切文本态须清，否则经 `url` 兜底显示旧图。保留 |
| `videoProcessNode.errorMessage` | VideoProcessNode.tsx:605/950/1095/1138/1254/1292 | 成功/取消后消除错误 UI；不删 → 错误提示在成功后仍滞留（App.tsx:802 仅保存时删，会话内仍靠此清）。保留 |
| `videoProcessNode.videoUrl` | VideoProcessNode.tsx:1095/1256 | `genericOutput` 读 `d.videoUrl` 作 videoProcessNode 产出（useConnectedInputs.ts:128）；真产出经 spawn 子节点交付。不删 → 上游重算后 genericOutput 把过期 `videoUrl` 漏给下游。保留 |
| `videoProcessNode.audioUrl` | VideoProcessNode.tsx:1096/1256 | 与 videoUrl 同动机（extractAudio spawn）；不删 → 下游拿到过期音频。保留 |

**处置**：本阶段原定的"删除"行动**取消**。这 5 处不是 TD-8 债，是正确实现。

**附带改进（可选，非债）**：`check-node-data.mjs` 的"清空遗留字段"检测器无法区分"退役字段清空"与"功能性清空"，建议加 `CLEAR_INTENTIONAL` 允许表（仿 `RESULT_EXEMPT`），把上述写点登记为"功能性清空"，避免后续误报、也防误删。登记前需逐条附原因 + 过期自检（仿 RESULT_EXEMPT 表尾自检）。

### 阶段 2 · 4 节点手写 setNodes → `useNodeData` 收口（M5 类，中风险）

**目标**：把档 A 的 4 个节点（`assetNode`/`gridSplitNode`/`gridMergeNode`/`videoProcessNode`）里**本节点 own 写回**的裸 `setNodes(ns => ns.map(n => n.id===id ? {...n, data:{...n.data, X}} : n))` 统一改走 `useNodeData`（node.data 写回唯一入口，CLAUDE.md §5.4.9），消除"每节点各写一套不可变更新"的漂移面。

**涉及文件**：上述 4 个节点文件 + `src/hooks/useNodeData.ts`（先读其实现与签名）。

步骤（**每节点独立一个 commit**，不要 4 个混改）：
1. 读 `useNodeData.ts` 文件头，确认其 patch 调用形态（预期 `useNodeData(nodeId).patch({field: val})` 或等价，内部做不可变更新 + 引用变更，满足 docs/106 F1 约束）。
2. 在目标节点内，把**own 写回**点（守卫 `n.id === id`）逐一替换为 `useNodeData(...).patch({...})`：
   - 仅替换「本节点 own」写；**跨节点写**（`n.id !== other`）与**子节点 data 规格**（`data:{...}` spawn）保持原 `setNodes`，不碰。
   - 保持值、触发时机、副作用完全等价（先小范围：`gridMergeNode` 2 处试水 → 跑单测 → 再推其余）。
3. 每节点改完：
   ```bash

   node scripts/check-node-data.mjs   # 本节点「自写」应降为 0（或转间接），不新增缺口
   ```
4. 若该节点 own 写回含「清空字段」语义（如 `videoProcessNode` 的 `{...n.data, errorMessage: undefined}`），改用 `useNodeData` 的清空等价写法，勿丢语义。

验收：`check-node-data.mjs` 表 3 中这 4 个节点的 `setNodes写` 列归 0（或仅剩跨节点/子节点行）；`test:unit` 全绿；`check:health` 绿。

### 阶段 3 · 结果字段语义显式化（治 TD-8②，中风险）

**目标**：让「读侧认识什么产出」从 `genericOutput` 的三魔法字段名（`imageUrl>videoUrl>resultUrl`）隐式兜底，变为**每个产出节点在 `NODE_OUTPUTS` 显式声明**。使 `genericOutput` 退化为纯安全网，不再承担契约；新增节点漏声明会被 dev `[P2-G]` 告警即时发现。

**涉及文件**：`src/hooks/useConnectedInputs.ts`（`NODE_OUTPUTS` / `genericOutputOk` / dev 校验段）。

背景（为何是债）：当前 9 个节点（`assetNode`/`imageGenerateNode`/`videoGenerateNode`/`panoramaNode`/`templateNode`/`faceMosaicNode`/`loopNode`/`videoProcessNode`/`director3dNode`）靠 `genericOutput` 的 3 个魔法字段名命中产出。**若某节点把产出写到 `myResult` 而非 `resultUrl`，genericOutput 静默返回空**——dev 校验只查"是否登记进 NODE_OUTPUTS"，不查"字段名是否匹配启发式"，故该风险无自动拦截。

步骤：
1. 为 `genericOutputOk` 的 9 个节点各加一条 `NODE_OUTPUTS` 显式声明，语义等价于当前启发式（单图/单视频/单结果 → 对应 `NodeOutputGroup` 通道），可抽一个 `singleOutput(d, id)` helper 包 `genericOutput` 或直接字段映射，让"产出字段名"在声明里显式出现。
2. 删 `genericOutputOk` 集合（职责被 `NODE_OUTPUTS` 全覆盖）；`noOutput`（`group`/`ghostTarget`）保留。
3. 强化 dev `[P2-G]` 校验：覆盖集 = `specialHandled ∪ NODE_OUTPUTS.keys ∪ noOutput`；任何 `NODE_TYPES` 类型不在内即 dev 报警（已是现状，确认无遗漏）。
4. 验证：
   ```bash
   npm run dev        # 控制台应无 [P2-G] warning（17 类型全覆盖）
   npm run test:unit  # useConnectedInputs 相关用例绿（tests/unit/useConnectedInputs.test.ts）
   node scripts/check-node-data.mjs   # 结果字段读侧不认仍 0
   ```

验收：`genericOutputOk` 集合删除、`NODE_OUTPUTS` 覆盖全部产出节点；dev 无 `[P2-G]` 告警；`useConnectedInputs.test.ts` 绿。
风险：**中**（声明写错会改变下游取数）。缓解：声明语义严格等价于现有启发式、不引入新字段名；单测锁定 `getNodeOutput` 契约（已有 `useConnectedInputs.test.ts`）。
