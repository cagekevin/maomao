## 1. 全局定位

`director3d`（3D 导演台，画布 overlay）是 maomao 面向业余创作者的分镜工具。核心价值 = 用「关键帧（Timeline）+ 画线路径」两套轻交互，驱动摄像机与对象运动，产出 3D 场景动画，无需 3D 软件基础。

当前风险根因：对象（人物）属性横跨多个独立域（变换、动作、骨骼），却用「一份整快照关键帧数组」统一承载，导致：
1. 每份快照 8 个维度一次全冻，无法单独 K 某一属性；
2. 路径系统想只管 position，却被迫注入整份对象姿态快照，污染动作/骨骼域；
3. 求值端每帧需「猜」左右帧是否同一动作状态才能决定骨骼插值还是硬切 → 走走停停/定格类 bug 的根源。

核心诉求：**按属性域拆独立通道 + 每通道单一数据源**；并**保留可扩展性**——未来可对任意单一属性单独 K 帧，不影响其它维度的现网行为。

## 2. 模块分解

| # | 模块 | 职责 |
|---|---|---|
| M1 | 通道模型与数据契约 | 定义**实体通用**（摄像机/物体/人物）的通道划分、每通道独立轨数据结构，作为全系统唯一数据契约；人物只是通道最多的实体，非特例。 |
| M2 | 逐帧求值与合成引擎 | 对一帧按通道各自求值、按固定优先级合并出最终对象状态；替代整快照 `objectAtFrame`。 |
| M3 | 路径独立化 | 画线路径改为「变换通道」的独立位置来源，与关键帧位置显式二选一，不再写 pose/joints。 |
| M4 | 采集入口与兼容迁移 | 统一所有写入口（手动K帧/未来单属性K/路径bake），并提供既有整快照→通道结构的无损迁移。 |

依赖判断：M1 ← M2/M3/M4 均依赖；M2 ← M3；M4 ← M1 与 M3（M4 的迁移须产出 M3 定义的新 position 来源格式，故亦依赖 M3）。单向，无循环，无职责重叠。

实施顺序（写死，防返工）：**M1 → M2 → M3 → M4**，严格串行。M3 依赖 M2 的通道化求值先落地，故 **M3 不得单独上线「路径只写 position」**（当前变换是整块插值，只改写入不改求值端会锁死动作，见 M3-C6）；M4 只能在 M1 契约定稿后实施迁移。

## 3. 主要翻车点

1. **破坏现网行为 / 回归**：数据契约一变，`objectAtFrame`/手动K帧/Timeline 全得跟着动；M4 迁移须无损，且有纯逻辑测试兜底（复用 `test:unit:logic`）。
2. **hold/interpolate 语义打架**：单属性 K 时，未被 K 的维度该「保持上一帧」还是「继承基线不动」；模型若未定义「通道内无该字段→不接管」，会在单属性 K 时悄悄改到别的东西。
3. **路径/变换双来源冲突演化为越改越复杂**：M3 若只是再叠一层 override 而非明确 position 单一来源，等于没解耦。

## 4. 约束清单

### 核心约束（按模块）
- M1-C1：对象动画 = 组件独立通道；每通道一条独立轨，轨内关键帧只含该通道字段，并为「单属性 K」预留「通道内可只含部分字段的 key」。
- M1-C2：通道名/字段名统一登记（契合既有契约登记规范，禁散写字面量）；一条新通道仅登记即生效，不改求值器。
- M2-C3：按通道各自求值、按固定优先级合并出最终对象状态；「通道内未出现的关键帧字段 → 该帧不解接管该字段」。
- M2-C4：同通道左右关键帧插值沿用既有语义；「改动作即切状态段/骨骼硬切」的现网行为保持，仅把实现从「猜状态」改为「按通道解释」，不动现网动效。
- M3-C5：路径只作「变换通道.position」的一路独立来源，与位置关键帧显式二选一；路径存在时绝不再写 pose/joints/rigRoot 快照。
- M3-C6：路径自身依旧沿弧长匀速、转折平滑（沿用已过单测的 `pathPositionAtFraction/pathSamplePoints`），只改「怎么落进通道」，不改曲线几何结果。
- M4-C7：所有写入口（手动 K 帧、未来单属性 K、路径 bake）统一走同一通道写接口，禁止各处手写 `setCharacterKeyframes` 拼装。
- M4-C8：既有整快照对象关键帧可无损迁移为通道结构，迁移后播放结果与迁移前完全一致（有断言可验）。

### 跨模块约束
- X1 单一数据源：对象每类字段只有一个归属通道，轨道构成该字段的唯一数据源；任何域只写自己的通道，禁越域。
- X2 可扩展：新增任意单一属性通道（或往现通道加字段）不改求值器、不改其它通道、不破坏旧数据（可验证：加新单属性通道改动行数可控且零回归）。
- X3 兼容现网：迁移前后 `check:jsx` + `build` 过，且 M2 求值对既有手动K帧场景输出逐帧一致。

## 5. 模块细化（第二层起逐模块追加）

### 5.1 M1 通道模型与数据契约

**State 1 边界**：定义所有可被动画实体（摄像机/普通物体/人物）的通道划分 + 每通道独立轨数据结构；是 M2 求值、M3 路径、M4 采集迁移共同依赖的唯一数据契约。

**State 2 子结构**：M1.1 实体·通道注册表（每种实体允许哪些通道+字段，新增即登记不改求值器）；M1.2 轨数据结构（`{frame, interpolation, fields:{…本通道字段}}`，支持部分字段 key）；M1.3 归一化/序列化契约（统一入口+裸键禁写+旧快照兼容反序列化）；M1.4 通道内因果语义（key 未含字段→求值不解接管）。

**实体·通道草案**：摄像机=变换+镜头(focalLength)；普通物体=变换；人物=变换+动作(pose·poseTime·loop)+骨骼(joints·rigRoot)。

**State 3 翻车点**：①通道抽太碎破坏现网「一次 K 整个变换」心智；②「部分字段 key」未含字段的语义不严→求值漂移；③派生量(motionStartTime)误当字段存取；④旧快照按实体类型拆包定位出错。

**State 4 约束 + 验证标准**
- M1-C1 对象动画=组件独立通道；每通道独立轨，轨内 key 只含本通道字段。→ 三实体各构造一轨，断言 fields 无跨通道混入。
- M1-C2 通道粒度贴合「现实一起 K 的单位」，不做无谓拆分；单属性 K 未来走「通道内部分字段 key」。→ 字段草案逐格可解释，每字段属且只属一通道。
- M1-C3 每通道 key 支持部分字段；未含字段该帧不求值接管。→ 构造仅含 position 的 key，序列化后 fields 不含 rotation。
- M1-C4 通道名/字段名/存储键走统一登记，禁散写字面量。→ 审计新增未引用裸键；check:api 覆盖。
- M1-C5 派生量(motionStartTime)不落通道字段，仅作 M2 中间量。→ 迁移后断言 fields 无派生键。
- M1-C6 旧整快照→通道结构无损迁移，播放逐帧一致。→ 三实体旧数据迁移后，逐帧输出与旧 objectAtFrame 完全一致。

→ 支撑跨模块：M1-C1/C2/C6→X1 单一数据源；M1-C2/C3/C4→X2 可扩展；M1-C6→X3 兼容现网。

**▶ 实施状态**：已实施（2026-08-25）。验证锚：`tests/unit/channelContract.test.js`（26 用例）。产出：`project.js`（ENTITY_CHANNELS 登记表 / snapshotToChannelKeys / channelsToSnapshotKeys / upsertChannelKeys / removeChannelFrames / moveChannelFrames / normalizeObjectTracks / normalizeCameraKeyframes）。

### 5.2 M2 逐帧求值与合成引擎

**State 1 边界**：输入实体 + 各通道轨 + 帧号，按通道各自求值、按注册顺序合成，输出最终实体状态；替代 `objectAtFrame/objectsAtFrame/cameraAtFrame` 整快照求值。只读 M1，不写轨道。

**State 2 子结构**：M2.1 单通道求值器（输出该帧 key 中存在的字段，未含→不接管）；M2.2 实体合成器（按注册顺序把各通道结果合并到底层基线）；M2.3 一帧派生上下文（动作状态段起点/时间等中间量，不落通道字段）。

**State 3 翻车点**：①合成顺序/基线被污染——部分字段 key 未含的字段被乱改；②动作状态段界定漂移→平滑/硬切行为悄悄变，重现走走停停；③同通道数值字段(变换)被拆开各自插值→位移/旋转对不上；④热路径每帧全排序→播放/scrub 卡。

**State 4 约束 + 验证标准**
- M2-C1 单通道求值只输出该帧 key 存在的字段；未含不解接管。→ 构造部分字段轨，断言输出精确=key 所含字段集。
- M2-C2 合成按注册通道顺序/优先级合并，每字段恰来自唯一通道，无重复写/跨通道覆盖。→ 断言每字段唯一归因一个通道；两通道可能写同字段时后序接管，无脏拼。
- M2-C3 既有手动 K 帧场景新旧求值逐帧一致。→ 同组旧数据跑旧 objectAtFrame 与新 M2 逐帧 diff 全等（浮点容差内）。
- M2-C4 复用既有插值：同通道数值字段同 t lerp；改动作切状态段骨骼 hard 切行为保持。→ pose 切换场景断言骨骼按状态段规则处理，与旧行为一致。
- M2-C5 求值为纯函数；同通道轨预排序+二分+结果缓存，热路径不抖。→ 同轨同帧多次求值一致；按帧号二分定位段，避免每帧全量排序。
- M2-C6 摄像机轨与对象变换轨共用同一套「轨预排序+二分求值」查询基元（现网 cameraAtFrame 与 objectAtFrame 都在每次求值全量 sort，属同一条热路径）。→ 相机轨热路径不再每帧全量 sort；cameraAtFrame 与对象轨复用同一查询基元。
- M2-C7 跨通道只读依赖一律走 M2.3 派生上下文，禁通道自猜：骨骼通道的「插值 or hard 切」决策必须消费「动作通道算出的状态段边界」（即现网 sameState 判定上移为派生量，由动作通道产生、经派生上下文供骨骼通道只读），骨骼通道不得自行再猜 sameState。→ 改动作切换状态段场景，断言骨骼决策来源是派生上下文而非骨骼通道内重新推断；与 M2-C4 的 hard 切行为一致。

→ 支撑跨模块：M2-C2→X1；M2-C1/C4→X2；M2-C3→X3（迁移验证锚）。

**▶ 实施状态**：已实施（2026-08-25）。验证锚：`tests/unit/channelEvaluation.test.js`（17 用例）。产出：`project.js`（locateChannelKey 查询基元 / evaluateNumericChannel / evaluateActionChannel / evaluateSkeletonChannel / synthesizeObjectState / 通道化重写的 objectAtFrame / cameraAtFrame / objectsAtFrame）。

### 5.3 M3 路径独立化

**State 1 边界**：把画线路径从「注入整份对象快照」改为「变换通道 position 的一路独立来源」，与位置关键帧显式二选一；路径存在时不再写 pose/joints/rigRoot。曲线几何/匀速/平滑沿用既有 `pathSamplePoints/pathPositionAtFraction`，不重写。

**State 2 子结构**：M3.1 路径来源判定（有路径且启用→position 由路径提供，二选一互斥）；M3.2 路径→合成接入（弧长位置作为变换通道 position 求值结果喂给 M2）；M3.3 关键帧产物解耦（只产出 position，不残留 bake 姿态快照）。

**State 3 翻车点**：①路径「存在/启用」判定不严→路径+关键帧双写 position 回到双来源；②旧路径数据残留姿态快照→迁移未剥掉则 M3 仍脏；③Timeline 仍显示路径生成的关键帧→误以为路径在 K 动作/骨骼；④仅路径无位置关键帧时合成误判空轨回落到基线坐标→路径不生效。

**State 4 约束 + 验证标准**
- M3-C1 路径存在且启用时 position 唯一由路径提供，位置关键帧被忽略（显式二选一）。→ 构造路径+位置关键帧均在，断言输出 position=路径位。
- M3-C2 路径时空绝不写 pose/joints/rigRoot，只产出 position。→ 迁移后断言无路径产生的姿态快照字段。
- M3-C3 「有路径」即视为位置来源存在；变换轨为空时 position 也走路径，不回落基线。→ 仅路径无关键帧，断言 position=路径位置。
- M3-C4 曲线几何/匀速/平滑沿用既有采样函数，不重写。→ 相同路径数据输出与既有实现一致（复用既有单测）。
- M3-C5 Timeline 不再把路径设为「生成动作/骨骼关键帧」；路径只作位置来源标识，不产生姿态关键帧事件。→ 断言路径时空不新增动作/骨骼 key 事件。
- M3-C6 捆绑依赖：M3 必须与 M2 通道化求值一起上线，不得单独实施「路径只写 position」。现网变换是整块插值（同段内 position 连同 interpolateJointPose 一起算），若只改写入不改求值端，路径帧会把 pose/joints 锁死在 source 当前值、动作在路径段丢失插值。→ 仅路径、无手动 pose 帧场景，断言动作/骨骼通道仍按状态段规则插值，不锁死在 source 当前值。

→ 支撑跨模块：M3-C1/C2/C5→X1；M3-C4→X3。

**▶ 实施状态**：已实施（2026-08-25）。验证锚：`tests/unit/channelPath.test.js`（13 用例）。产出：`project.js`（pathActive / pathPositionAtFrame / 路径帧只产 position）；`App.jsx`（applyPathBake 只写 position 来源标识）。

### 5.4 M4 采集入口与兼容迁移

**State 1 边界**：统一所有写入口（手动 K / 未来单属性 K / 路径 bake）走同一套通道写接口（禁各处手写 `setCharacterKeyframes` 拼装），并提供既有整快照 → 通道结构的无损迁移与回读兼容。M1/M2/M3 为只读消费方，与 M4 以 M1 契约为界。

**State 2 子结构**：M4.1 统一写入口（建/改/删 key、排序、去重、撤销入栈，手动/单属性/路径统一走它）；M4.2 整快照→通道迁移（拆包到对应通道并剥掉路径姿态快照）；M4.3 通道→旧格式回读（新逻辑只读新结构，旧视图兼容展示）；M4.4 撤销/历史集成（通道写操作原子入栈，对齐 currentProject 防抖机制）。

**State 3 翻车点**：①写入口被绕过→越域写错通道+丢撤销；②迁移误伤或拆错通道（实体类型判定错）→丢字段；③迁移不幂等→重复 key；④回读兼容层掩盖真实状态→重影两套结构；⑤路径 bake 批量写不作为原子变更入栈→撤销乱。

**State 4 约束 + 验证标准**
- M4-C1 所有写入口统一走 M4.1 唯一写 API；禁直接 setCharacterKeyframes 拼装。→ 审计手动 K/单属性 K/路径 bake 三处均调用唯一写 API。
- M4-C2 迁移按实体类型正确拆包到对应通道，并剥掉路径残留姿态快照（配合 M3）；只读源、写目标，不就地污染。→ 三实体旧数据迁移，每字段落唯一正确通道，无路径快照残留。
- M4-C3 迁移幂等：同一旧数据多次迁移产出完全一致结果。→ 同输入跑 N 次，输出逐字段相等。
- M4-C4 迁移后依赖 M2 逐帧一致验证：旧 objectAtFrame vs 新求值全等。→ 三实体逐帧 diff 全等（浮点容差内）。
- M4-C5 每批导入（如一次路径 bake）作为一个原子变更入历史，遵循既有 currentProject 防抖入栈机制。→ 一次路径 bake 撤销后整批 key 一并移除，不残留半批。
- M4-C6 混合轨迁移规则（现网数据真实存在）：已存在「手动 K 的各类字段帧 + 路径帧」共存的整快照轨。迁移动作：①剥掉路径帧的姿态残留（pose/joints/rigRoot/rotation/scale），路径帧只保留 position 来源标识；②用户在非路径帧上手动 K 的变换/动作/骨骼字段原样迁入对应通道；③position 遵循 M3 二选一——路径启用时，路径帧范围内手动 K 的 position 帧被显示忽略（规则显式化，不静默丢帧）。→ 对含路径的旧轨迁移，断言：①路径帧无姿态残留字段；②手动非路径帧字段完整迁入对应通道；③路径启用时输出 position=路径位置，且未丢失手动动作/骨骼帧。

→ 支撑跨模块：M4-C1/C2/C3→X1；M4-C1→X2；M4-C4→X3。

**▶ 实施状态**：已实施（2026-08-25）。验证锚：`tests/unit/channelWrite.test.js`（12 用例）+ `tests/unit/tracks.test.js`（8 用例）。产出：`project.js`（writeObjectTrack 统一写入口 / setChannelInterpolation / 迁移剥路径姿态残留）；`tracks.js`（轨道写操作领域模块：对象轨 + 相机轨全部纯 updater）；`App.jsx`（12 处轨道写点收敛为 setState 接线）。
