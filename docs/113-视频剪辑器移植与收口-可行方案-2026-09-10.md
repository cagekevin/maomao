## 〇、结论（先看这一段）

**先收口、后移植；不整包搬。** 参考包是 Tauri 桌面端的一个窗口，它的依赖（`@tauri-apps/api`、`fileService`、IndexedDB、Iconify、以中文为 key 的 `t()`）在本仓库**全部不存在或不适用**，直接拷进来必然编译不过；即使强行补依赖，也会引入第二套落盘通道、第二套素材 URL 解析、第二套状态管理——这正是本项目反复治理过的东西。

移植拆成 5 个 Gate，**每个 Gate 有独立验收**，前一 Gate 不过不进下一 Gate：

| Gate | 内容 | 产出 | 预估 |
| --- | --- | --- | --- |
| **G0** 契约登记 | 存储键 / 事件 / API 三张表先登记 | `contracts.ts` 增量 | 0.5h |
| **G1** 纯逻辑 + 单测 | 类型、时间轴运算、吸附、刻度 | `core/*` + `tests/unit/videoEditor/*` | 4h |
| **G2** 数据层收口 | 工程持久化、素材 URL 唯一出口 | `data/*` | 4h |
| **G3** UI 骨架 | portal overlay + 四段骨架 + 面板 | `panels/*` | 1.5d |
| **G4** 预览与导出 | 先直通、后合成；复用 `videoEngine` | `export/*` | 2d |
| **G5** 体验项 | mockup 舞台 5 的 P0 五条 | 交互补丁 | 1d |

**合计约 5 人日**（不含「多轨实时预览合成」的深度优化，那部分见 §7 风险）。

## 二、为什么必须先收口（原包的 10 个数据流问题）

> 每条给「问题 → 证据 → 收口动作」。这些不是风格问题，是会直接复制到本仓库的架构债。

| # | 问题 | 证据（参考包） | 收口动作（本仓库） |
| --- | --- | --- | --- |
| ① | **上帝组件**：加载、导出、AI 转场、历史栈、选中态、持久化、窗口控制全在一个组件 | `VideoEditorWindow.tsx` 1462-1664 行渲染 + 上方 1400 行逻辑 | 拆 4 层：`core`（纯逻辑）/ `data`（存储与素材）/ `panels`（UI）/ `export`（导出管线）；UI 只读状态 |
| ② | **素材 URL 双通道**：`resolveClipUrl` + Tauri `fileService`，与本仓库 `/files/` 落盘是两套 | `useVideoEditorSources.ts`、`window.tsx` import `fileService` | 唯一出口 `data/sourceResolver.ts`：`node.data` 的 URL → 经 `videoEngine`/`/files/` 解析；**禁止第二落盘通道**（CLAUDE.md §四.2） |
| ③ | **持久化双通道**：IndexedDB repository 与项目落盘并存 | `services/indexedDb/videoEditorRepository.ts` | 一律走 `contentStore`（`contentGetAsync`/`contentSetAsync`），键先登记 `STORAGE_KEYS`（`contracts.ts` L177），否则 `check:keys` 直接红 |
| ④ | **AI 转场依赖「主窗口仍开着」**：模型目录与主窗口 postMessage 双向通信 | `videoEditorWindowService.ts`、`postVideoEditorModelsRequest` | 改走 `localTool` `/api/generate`，端点在 `contracts.ts apiRegistry` 登记并跑 `check:api`；无主窗口依赖 |
| ⑤ | **窗口能力**：`@tauri-apps/api/window` 的 minimize / close | `window.tsx` L1452-1460 | 删除；改 `createPortal` + `fixed inset-0 z-ceiling`（照抄 `ImageEditor.tsx` L951-952） |
| ⑥ | **i18n 以中文为 key**（`t('属性')`） | `i18n/index.ts` | 直接写中文，与 `ImageEditor` 一致 |
| ⑦ | **图标库 Iconify**（`@iconify/react`） | 全组件 | 换 `lucide-react`（已是依赖，`ImageEditor` 在用） |
| ⑧ | **样式自建体系**：5 个 CSS + `--theme-*` / `--brand-*` 变量 | `styles/video-editor*.css` | 全部换成 `tailwind.config.ts` 语义 token；参考 `mockup/mockup-kit.css` 的 token 命名 |
| ⑨ | **导出两条路各自为政**（无损直通 vs 合成重编码）+ 取消逻辑散落 | `exportComposite` / `exportLosslessConcat` / `VideoExportCanceledError` | 收成 `export/exportPipeline.ts`：策略单一入口 + `AbortController` + 阶段事件（探测/合成/混音/封装，见 mockup 舞台 3「导出中」） |
| ⑩ | **状态源分散**：`tracks` / `selectedClipIds` / `playhead` / `sources` / `probe` 各自 useState | `window.tsx` 多处 `useState` | 单一 `useReducer` 编辑器 store（撤销栈随 reducer 走，参考包 `useTimelineHistory` 思路保留，但合并进 reducer） |

**另外两个交互债**（不修就不能用，见 mockup 舞台 4 审计表）：

- **假禁用**：`分割` 在播放头不在片段上就灰掉且不解释 → 用户判定"功能坏了"。收口：补刀片工具（点哪切哪）+ 播放头自动吸到最近边界。
- **隐性无反馈**：轨道 flag（锁/隐/静音）改了状态但界面看不出 → 等同没点。收口：锁=斜纹、隐藏=虚线+灰度、静音=降饱和，且三态必须作用于导出。

## 三、五个 Gate：动作 / 验收

### G0 · 契约登记（先登记再写代码）
1. `src/components/base/core/contracts.ts` 的 `STORAGE_KEYS`（L177）新增：`video_editor_project`（动态键按 `CANVAS_STATE_PREFIX` 模板 L191 风格，`video_editor_project:{projectId}:{nodeId}`）。
2. 若剪辑器与画布需要通信（如「导出为新节点」），事件名登记进 `EVENTS`（`check:events` 双向校验，禁止裸字符串）。
3. 若新增视频模型端点，登记进 `apiRegistry`（`check:api`）。
- **验收**：`npm run check:keys && npm run check:events && npm run check:api` 全绿。

### G1 · 纯逻辑 + 单测（最容易、也最该先做）
1. `core/types.ts`：搬 `types/videoEditor.ts`，删 Tauri 痕迹（`AssetFileEntry` 等改本仓库素材类型）。
2. `core/timelineOps.ts` / `core/snap.ts` / `core/rulerTicks.ts`：搬纯函数；新增**吸附计算**（片段边界 / 播放头 / 0 点 / 其他轨道边缘）与**波纹删除后的重排**。
3. `tests/unit/videoEditor/*.test.ts`：断言必须"源码一变必红"（CLAUDE.md §3.0，禁止自证式断言）。
- **验收**：`npx vitest run tests/unit/videoEditor` 通过 + `npm run type-check`。

### G2 · 数据层收口
1. `data/projectRepository.ts`：工程记录读写走 `contentStore`（`contentGetAsync` L379 / `contentSetAsync` L389），键用 G0 登记的常量；失败降级同 `d3dPersistence.ts` L260-269 的做法（local 兜底，不阻断）。
2. `data/sourceResolver.ts`：素材 URL 唯一出口——画布节点图源 / `localTool /files/` / 本机导入，统一成可播放 URL；与 `videoEngine.uploadResult`（L597）对齐。
- **验收**：单测覆盖"URL 三种来源 → 同一出口"；`npm run test:smoke` 绿。

### G3 · UI 骨架（照 mockup 主屏）
1. `VideoEditor.tsx`：`createPortal` + `fixed inset-0 z-ceiling`，`onClose` / `onSave` 语义同 `ImageEditor`。
2. 入口：视频节点 hover 工具栏加「剪辑」按钮（与 `useImageHoverActions.tsx` L138-143 的「标记」同级），组件级 state 控制（L63 模式）。
3. 四段骨架：抬头（取消 / 导出到本地 / 导出为新节点）· 三栏（素材 224 / 预览 / 检查器 264）· 底部时间轴 258。
4. **画布与时间轴区必须标 `nodrag`**，否则拖动会被画布节点拖拽吞掉。
- **验收**：`npm run build` + `npm run test:smoke` + 手点一遍 mockup 舞台 3 的四种状态（空态 / 导出中 / 轨道三态 / 多选）。

### G4 · 预览与导出（复用本仓库能力，不引新依赖）
1. 预览：单轨优先；叠加层（画中画/贴图/字幕）用 CSS transform 叠在 `<video>` 上，先不做全合成实时预览。
2. 导出两策略（同一入口 `exportPipeline`）：
   - **无损直通**：同分辨率 + 同编码 + 无转场/叠加 → `videoEngine.concatVideos`（L312）。
   - **合成重编码**：其余情况 → 归一到主画布尺寸（参考 `concatVideos` 的归一语义），分段进度可中断。
3. 抽帧/缩略图复用 `VideoSampleSink`（`videoEngine.ts` L29），不搬参考包 `videoCompositor.ts`。
- **验收**：三种工程（纯直通 / 混合需合成 / 含转场）各导出一次；取消能真中断且无残留。

### G5 · 体验项（mockup 舞台 5 的 P0）
刀片工具 · 删除二态（留洞 / 波纹）+ 一键闭合空隙 · 键盘走带（空格 / ←→ / ⇧←→ / Home-End / I-O）· ⌘滚轮缩放跟随指针 + 播放时自动跟随播放头 · 选中即联动（点片段 → 播放头跳起点、预览显示该段首帧）。
- **验收**：`npm run test:unit` + 人工按清单走一遍。

## 五、与既有能力的边界（先划清，防重复建设）

| 能力 | 归谁 |
| --- | --- |
| 单素材转码 / 抽帧 / 转 GIF / 改分辨率 | **`VideoProcessNode`**（已有 5 模式 + toGif） |
| 多素材拼接 / 转场 / 字幕 / 画中画 / 音频轨 | **视频剪辑器**（本方案） |
| 3D 预演 / 镜头调度 | **`Director3DNode`**（不重叠） |
| 图片裁剪 / 涂鸦 / 扩图 | **`ImageEditor`**（不重叠） |
| AI 文生 / 图生视频 | **生成链路**（`useNodeGeneration`），剪辑器只消费产物 |

判定口诀：**单素材加工走节点，多素材编排走剪辑器。**

## 六、红线（不可违反）

1. 不改 `18080` 端口与 `config.ts` 的 `apiBase`；不改 `{code,data}` 信封与 `t.data[0].url`。
2. **存储键禁止裸字符串**（P0）：必须 `STORAGE_KEYS` 登记项，运行时 `contentStore.checkRegistered` 会 throw。
3. **事件名禁止裸字符串**（P0）：必须 `EVENTS` 登记项。
4. **唯一落盘通道**：`localTool /files/`；剪辑器不得自建第二通道。
5. 不引入 Tauri 依赖、不新增 React 实例、不新增第二个 i18n/图标体系。
6. 画布与时间轴交互区必须 `nodrag`。
7. 不手改 `dist/`；改完 `npm run build` 出包。
8. 每 Gate 收尾跑：`npm run type-check` → `npm run test:smoke` → `npm run test:unit` → `npm run build`（较大改动加 `npm run check:health`）。
