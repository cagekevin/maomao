## 零、一句话结论与变更清单

**给「画布上每个会产出/展示图片、视频的节点」建立统一命名能力（名字落进产出媒体的 `label`），
让 `@名` 在下游 PromptInput 里按 label 精确匹配并自动变成缩略图芯片。**
（视频/音频产出也统一带 `label` 字段，本次仅图片参与 `@名` 匹配，视频为数据完备性预留。）

核心机制（**不逐点补丁，建统一链路**）：

| 机制 | 落点 | 说明 |
|---|---|---|
| **① 统一命名入口** | `NodeTitle` 加 `onRename` 回调 | 复用现有「双击改名」UI，改名写回节点数据（`data.label`）；不传 `onRename` 的节点零影响 |
| **② 产出统一带 label** | `useConnectedInputs.js` | `genericOutput`（图片+视频+音频）/ `collectAssets` 产出统一补 `label`，让「名字」流向下游候选列表 |
| **③ 名字匹配唯一入口** | `promptChips.js` | 新增 `autoLinkAssetsByName` 纯函数（`@名` → `@{id:label|thumb}`），`PromptInput` 渲染前调用 |
| **④ 触发时机防重算** | `PromptInput.jsx` | 用 `nameSignature`（素材名字签名）做依赖，仅名字变化才重转换，普通交互零重跑 |
| **⑤ 缩略图协议不变** | `promptChips.js` | `@{id:label|thumb}` 序列化协议保持，存量零迁移 |

| 文件 | 动作 | 说明 |
|---|---|---|
| `src/components/base/NodeTitle.jsx` | **改** | 加可选 `onRename` 回调（commit 时调用） |
| `src/components/base/useConnectedInputs.js` | **改** | `genericOutput` 产出图片+视频+音频带 `label: d.label`；`imageBoxNode` 已带；`collectAssets` 带 `label: a.name` |
| `src/components/base/promptChips.js` | **改** | 新增 `autoLinkAssetsByName`；`resolvePromptChips` 已按 id 匹配（不变） |
| `src/components/base/PromptInput.jsx` | **改** | 渲染入口调 `autoLinkAssetsByName`（`@名` 自动转芯片）；加 `nameSignature` 控触发时机 |
| `src/components/nodes/ImageNode.jsx` | **改** | `NodeShell` 传 `onRename` 写 `data.label` |
| `src/components/base/scriptBoxPrompts.js` | **改** | `collectAssets` 产出带 `label: a.name` |
| `tests/unit/promptChips.test.js` | **新增/改** | `autoLinkAssetsByName` 表驱动单测 |
| `spec/CONTEXT.md` + `contracts.js` | **改** | 登记「图片命名唯一入口」与「名字匹配唯一入口」（按决策铁律） |

**不改动**：`@{id:label|thumb}` 序列化协议、`MaterialStrip`、`ImageBoxNode`（用户明确不命名盒内单图）、`ScriptBoxNode` 的 NodeTitle（它不参与素材命名）。

## 一、目标与非目标

### 1.1 目标（用户原始诉求 → 可验收指标）

| # | 目标 | 可观测指标 |
|---|---|---|
| G1 | **画布上每个图片节点都能命名** | 所有「产出/展示图片」节点（§二全表）均可在 UI 上给图片改名，名字持久化进节点数据 |
| G2 | **名字流入下游候选列表** | 连线后，PromptInput `@` 候选列表里的图片条目显示用户改的名字，而非「图片 1」兜底 |
| G3 | **`@名` 自动变缩略图** | 输入 `@猫` 回车（或失焦），名字命中候选时自动变成 `猫` 的缩略图芯片 |
| G4 | **不误伤正常文本** | 只有 `@名` 精确命中素材才转换；普通词、`@` 后非素材名不转换（§六用例） |
| G5 | **生成语义正确** | 芯片解析后，`图片N` 占位与参考图顺序一一对应（`resolvePromptChips` 现有行为保持） |

### 1.2 非目标（明确不做）

- **不改** `@{id:label|thumb}` 序列化协议、不做存量数据迁移。
- **不给 ImageBoxNode 盒内单图命名**（用户明确：图片拖出即成 ImageNode，单图命名走 ImageNode）。
- **不给 ScriptBoxNode 的 NodeTitle 接 onRename**（它是外壳名，不参与素材匹配；素材命名已走 `AssetPanel`）。
- **不引入模糊/部分匹配**（只做 `@名` 全等匹配，见 §5.3 边界）。
- **不改** `69` 文档已定的候选层定位/层级/生命周期（那是独立已定稿方案）。

> 依据 `NodePalette.jsx` 节点目录 + `useConnectedInputs.js` 的 `NODE_OUTPUTS` + `genericOutput`，穷举「画布上会出现图片/视频」的节点。
> **统一原则：图片、视频、音频三类的产出都带 `label` 字段**（视频/音频暂时不用 `@名` 匹配，但字段先带上，保持三个产出分支数据形态一致）。

| 节点 | 类型 | 是否产出图片 | 图片字段 | 名字字段 | 是否需命名 | 命名入口 |
|---|---|---|---|---|---|---|
| 图片素材节点 | `imageNode` | ✅ 产图 | `data.imageUrl` | `data.label` | ✅ **核心** | NodeTitle 双击 |
| 生图节点 | `promptNode` | ✅ 产图 | `data.imageUrl` | `data.label` | ✅ | NodeTitle 双击 |

| 图片切分 | `gridSplitNode` | ✅ 产图(多) | `data.extractedImages[]` | 固定 `切片 N` | ⚠️可选 | — |
| 图片拼图 | `gridMergeNode` | ✅ 产图(多) | `data.extractedImages[]` | 固定 `图 N` | ⚠️可选 | — |
| 全景图 | `panoramaNode` | ✅ 产图 | `data.imageUrl` | `data.label` | ✅ | NodeTitle 双击 |
| 人脸打码 | `faceMosaicNode` | ✅ 产图(多) | `data.imageUrls[]` | `data.label` | ⚠️可选 | NodeTitle 双击 |
| 视频抽帧 | `videoExtractNode` | ✅ 产图(多) | `data.extractedImages[]` | 固定 `帧 N` | ⚠️可选 | — |
| 视频生成 | `discountVideoNode` | ✅ 产图(海报/结果)+产视频 | `data.imageUrl`/`resultUrl`+`videoUrl` | `data.label` | ✅ | NodeTitle 双击 |
| 视频处理 | `videoProcessNode` | ✅ 产图(结果)+产视频 | `resultUrl`+`videoUrl` | `data.label` | ✅ | NodeTitle 双击 |
| 文本生成 | `textNode` | ❌（产文本） | — | — | — | — |
| 循环生成 | `loopNode` | ✅ 产图(透传) | `resultUrl` | `data.label` | ✅ | NodeTitle 双击 |
| 剧本盒子 | `scriptBoxNode` | ✅ 产图(资产) | `data.assets[].imageUrl` | `data.assets[].name` | ✅（已有命名） | AssetPanel 名称框 |
| 3D导演台 | `director3dNode` | ✅ 产图 | `resultUrl` | `data.label` | ✅ | NodeTitle 双击 |

> **视频说明**：`imageNode` 支持视频态（`data.videoUrl` + `mediaType:'video'`），`discountVideoNode`/`videoProcessNode` 产视频（`resultUrl`/`videoUrl`）。这些节点产出 `videos` 时，`genericOutput` 统一给 `label: d.label`（见 §7.3）。**当前 `@名` 只匹配图片**，视频 label 仅作数据完备性预留，不参与候选列表转换。

**收敛结论**：绝大多数节点走 **`genericOutput`（单图/单视频，`data.imageUrl`/`resultUrl`/`videoUrl`）** 或 **NodeTitle（`data.label`）**。因此只需：

1. **统一让 `genericOutput` 产出（图片+视频+音频）带 `label: d.label`**（覆盖 imageNode/promptNode/panorama/faceMosaic/discountVideo/videoProcess/loop/director3d）。
2. **统一让 `NodeTitle` 支持 `onRename` 写 `data.label`**（覆盖所有单图/单视频节点命名）。
3. **剧本盒子**单独已走 `collectAssets` → 补 `label: a.name`。
4. 多图数组节点（gridSplit/gridMerge/videoExtract）的固定 `切片/图/帧 N` **本次不命名**（非核心，留 M3 可选）。

## 三、现状链路与根因

### 3.1 链路现状（断在 3 处）

```
[命名] NodeTitle 双击改名 → 只改本地显示，不写 data.label（NodeTitle.jsx:15-19 注释「原型里不做 store 写入」）
   ↓ 断点①：名字根本没落盘
[传递] genericOutput → { id, url } 无 label（useConnectedInputs.js:104）
   ↓ 断点②：即使有 label 也流不到下游
[候选] PromptInput 候选列表 all[] → item.label（PromptInput.jsx:52-64）
   ↓ 断点③：候选有 label，但「@名」纯文本不会被解析成芯片（PROMPT_CHIP_RE 只认 @{id:label}）
[芯片] renderPromptToNodes 只认 @{id:label|thumb} 格式
```

### 3.2 根因（系统性）

1. **命名与数据解耦**：`NodeTitle` 有改名 UI 但无写回能力，导致「用户改了名，系统不知道」。
2. **产出与名字解耦**：`getNodeOutput` 产出图片时丢 label，导致「上游名字流不到下游」。
3. **输入与素材无关联**：`@名` 纯文本不经过任何「名字→素材」解析，永远是普通文字。

**这三点是系统性根因，必须建统一机制，而非在 4 个节点里各打补丁。**

## 四、State 1 · 契约

### 4.1 输入源 / 输出目标 / 副作用

| 能力 | 输入源 | 输出目标 | 副作用 |
|---|---|---|---|
| 命名写回 | NodeTitle 双击输入框文本 | `node.data.label`（或 `assets[].name`） | setNodes 不可变更新，持久化进画布快照 |
| 产出带 label | 上游节点 `data` | 下游 `useConnectedInputs` 聚合的 `images[].label` | 无（纯派生） |
| `@名` 自动转芯片 | PromptInput 的 value 字符串 | 含 `@{id:label|thumb}` 的芯片字符串 | 仅渲染层转换，不改用户原始 value 语义之外的东西 |

### 4.2 边界与文件归属

| 能力 | 归属 | 判据 |
|---|---|---|
| `onRename` 回调 | **并入** `NodeTitle.jsx` | 现有组件，加一个可选 prop，零新文件 |
| 产出带 label | **并入** `useConnectedInputs.js` | 唯一产出调度入口，正是缺 label 的地方 |
| `autoLinkAssetsByName` | **并入** `promptChips.js` | 芯片纯逻辑层，与 `resolvePromptChips`/`renderPromptToNodes` 同职责 |
| 收集资产 label | **并入** `scriptBoxPrompts.js` `collectAssets` | 唯一资产收集纯函数 |
| ImageNode 接 onRename | **并入** `ImageNode.jsx` | 单图节点范本，其余单图节点照抄 |

**判定**：全部「复用/扩展既有件」，**零新增文件**。

### 4.3 需求自相矛盾/边缘检查

- `@名` 命中多个同名素材？→ **取第一个**（候选 `filtered` 语义一致），且改名 UI 建议引导唯一名。
- 名字含空格？→ 序列化 `@{id:label}` 允许 label 含空格（`PROMPT_CHIP_RE` 已兼容）；但 `@名` 匹配时空格会提前截断，**建议名字不含空格**（文档约束，不强制）。
- 图片未命名（label 空）？→ 保持 `图片N` 兜底，`@名` 匹配不命中（安全）。
- 节点删了名字又恢复？→ `data.label` 空回退 `defaultTitle`（NodeTitle 现有行为）。

## 五、State 2 · 数据流

### 5.1 唯一入口裁定

| 数据流 | 唯一入口 | 禁止旁路 |
|---|---|---|
| 名字写回节点数据 | **`NodeTitle` 的 `onRename` prop → 节点内 `setNodes`/`updateData`** | 禁止各节点手写另一套改名 |
| 产出图片带 label | **`useConnectedInputs.js` 的 `getNodeOutput`（含 `genericOutput`/`NODE_OUTPUTS`/`collectAssets`）** | 禁止在 `PromptInput` 或 `MaterialStrip` 里手动补 label |
| `@名` → 芯片字符串 | **`promptChips.js` 的 `autoLinkAssetsByName`** | 禁止在 `PromptInput` 组件里手写 `lastIndexOf('@')`/正则 |
| 资产收集带 label | **`scriptBoxPrompts.js` 的 `collectAssets`** | 禁止在别处再解析资产 |

### 5.2 数据流全图（单向、可追溯）

```
┌─ 命名链 ──────────────────────────────────────────────┐
│ NodeTitle 双击改名 → onRename(新名)                    │
│   → ImageNode.updateData({ label: 新名 })             │  ← 落盘 data.label
│   → ScriptBox.AssetPanel 名称框 → updateData({ assets })│  ← 落盘 asset.name（已有）
└──────────────────────────────────────────────────────┘
                    ↓ 上游产出
┌─ 传递链 ──────────────────────────────────────────────┐
│ getNodeOutput(上游节点)                                │
│   → genericOutput: images/videos/audios              │  ← 新增 label（三态统一）
│       = [{id,url,label:d.label}]                      │
│   → imageBoxNode:    images=[{...label:im.label}]     │  ← 已有
│   → scriptBoxNode:   collectAssets → {label:a.name}   │  ← 新增 label
│   → 聚合进 downstream.refImages[]（带 label）          │
│     （videos/audios 也带 label，预留，暂不参与匹配）     │
└──────────────────────────────────────────────────────┘
                    ↓ 下游 PromptInput
┌─ 匹配链 ──────────────────────────────────────────────┐
│ PromptInput value（含 @名 纯文本）                      │
│   → autoLinkAssetsByName(value, allAssets)            │  ← 新增唯一入口
│      把 @名 替换成 @{真实id:名|thumb}                   │
│   → renderPromptToNodes → 芯片（缩略图）               │  ← 协议不变
│ 生成时 → resolvePromptChips → 图片N + refImages        │  ← 协议不变
└──────────────────────────────────────────────────────┘
```

### 5.3 匹配边界（`autoLinkAssetsByName`）

- **只做全等匹配**：候选素材 `label` 完全相等才替换，不部分/模糊匹配。
- **带 `@` 前缀才触发**（用户已确认「必须带@」）：`@猫` 命中「猫」；裸词「猫」不触发，避免误伤描述性文本。
- **只命中候选列表内的素材**（`PromptInput` 的 `all` 数组），不引入更大范围。
- 多素材同名：取候选列表第一个命中项。

### 5.4 与 `69` 文档的关系

- `69` 管「候选层弹得对、不被挡、快消失」；本文管「素材有名字 + `@名` 自动转换」。**正交、互补**。
- `autoLinkAssetsByName` 的输入是 **value 字符串**（序列化前），`69` 的 `detectMentionQuery` 处理的是**光标前文本**（交互中）。两者不冲突。
- 触发时机：本文采用**回车/失焦时**对整段 value 做一次 `autoLinkAssetsByName`（配合 `69` 的回车选中候选路径）；或 `69` 的候选列表里已有「`@名` 完全命中→自动选中」的等价逻辑。**统一在渲染入口做**，与交互层解耦。

```js
  // commit(text)：text.trim() || defaultTitle → setVal(next)；若 onRename 则 onRename(next)
  // 其余（editing/onBlur/onKeyDown Enter/Esc）不变
}
```

### 7.3 `useConnectedInputs.js` — `genericOutput` 带 label（图片 + 视频 + 音频统一）

> **视频/音频也加 label**（用户确认：就算暂时不用，字段先带上，保持三个产出分支一致）。
> `genericOutput` 是 `images`/`videos`/`audios` 三者的唯一兜底入口，一处补 label 三态统一受益。

```js
function genericOutput(d, id) {
  const empty = { images: [], texts: [], videos: [], audios: [] }
  const candidates = [
    { url: d.imageUrl, mediaType: d.mediaType },
    { url: d.videoUrl, mediaType: d.mediaType },
    { url: d.resultUrl, mediaType: d.mediaType },
  ].filter((c) => c.url && typeof c.url === 'string')
  for (const { url, mediaType } of candidates) {
    const kind = resolveMediaType(url, mediaType)
    // label 统一带上 d.label（图片/视频/音频都带，供下游候选列表显示 / 未来 @名 匹配视频）
    const item = { id, url, label: d.label }
    if (kind === 'video') return { ...empty, videos: [item] }
    if (kind === 'audio') return { ...empty, audios: [item] }
    return { ...empty, images: [item] }
  }
  return empty
}
```

### 7.6 `PromptInput.jsx` — 渲染入口调用（`nameSignature` 防重算优化）

> **优化根因**：`all` 是每次 render 新建的数组（`PromptInput.jsx:52-64`），若直接把它当依赖，
> 每次渲染（连鼠标 hover 都算）都会重跑 `autoLinkAssetsByName`——浪费。
> 解法：用「素材名字签名」做依赖，**只对名字变化敏感**，名字没变就不重跑。

```jsx
// ① 名字签名：把素材的 label 拼成签名，改名 → label 变 → 签名变 → 才触发重转换
const nameSignature = React.useMemo(
  () => [...refImages.map(i => i.label || ''), ...refTexts.map(t => t.label || '')].join('\u0001'),
  [refImages, refTexts]
)

// ② value 变化重建 DOM 的 useEffect：
React.useEffect(() => {
  const el = editorRef.current
  if (!el) return
  normalizeChipSlots(el)
  if (serializeDOM(el) === value) return
  const sel = window.getSelection()
  const cursor = sel && sel.rangeCount ? saveCursor(el) : null
  syncingRef.current = true
  el.innerHTML = ''
  // ← 先 autoLinkAssetsByName 把「@名」转成 @{id:label|thumb}，再渲染成芯片
  for (const node of renderPromptToNodes(autoLinkAssetsByName(value || '', all), chipMetaMap)) el.appendChild(node)
  normalizeChipSlots(el)
  syncingRef.current = false
  if (cursor !== null) restoreCursor(el, cursor)
  // 依赖：value 变（用户输入）或 nameSignature 变（改名）→ 重跑；名字不变则零重跑
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, [value, chipMetaMap, nameSignature])
```

> **注意**：`autoLinkAssetsByName` 入参仍是 `all`（纯函数只管转换，不管触发时机）；
> 触发时机由 `nameSignature` 在 useEffect 依赖里精准控制。职责分离、互不耦合。
> `nameSignature` 用 `\u0001`（控制字符）连接，杜绝 label 内容冲突。

### 7.7 可变性纪律

- 全部走不可变更新（`setNodes` map 生成新数组）；`autoLinkAssetsByName` 是纯函数（不改入参）。
- **防重算**：触发时机由 `nameSignature` 控制，名字不变则转换零重跑；`autoLinkAssetsByName` 内部只建一次 `label→asset` 映射、循环匹配一次，O(名×素材) 可忽略。
- `chipMetaMap` 依赖 `[refImages, refTexts]` 引用，改名时引用变 → 会重算，但它是 Map 构建，成本低，可接受。

## 十一、决策记录 ADR

| # | 决策 | 备选 | 为什么选它 |
|---|---|---|---|
| A1 | **`NodeTitle` 加可选 `onRename`** | 各节点自写改名 UI | 复用现有双击改名 UI，一处机制，向后兼容；符合「统一机制防补丁」 |
| A2 | **`genericOutput` 统一带 label** | 各节点手补 label | 唯一产出调度入口，一处覆盖所有单图节点，杜绝散写 |
| A3 | **`autoLinkAssetsByName` 抽纯函数** | 组件内写正则 | 可单测、可追溯、唯一入口；是「可观测」的基础 |
| A4 | **只 `@名` 全等匹配** | 部分/模糊匹配 | 用户确认「必须带@」+「只在候选列表选」；避免误伤，范围收敛 |
| A5 | **不改序列化协议** | 改 `@{id:label}` 加名字字段 | 存量零迁移，`PROMPT_CHIP_RE` 兼容；名字复用 `label` 而非新字段 |
| A6 | **ImageBoxNode 盒内不命名** | 给每张图命名 | 用户明确「拖出成单图即可」；避免多图命名复杂度 |
| A7 | **ScriptBoxNode 走既有 AssetPanel** | NodeTitle 接 onRename | 素材命名已存在（AssetPanel），只需 `collectAssets` 带 label；NodeTitle 是外壳名，无谓 |

| A9 | **`nameSignature` 控触发时机** | 直接依赖 `all` 数组引用 | `all` 每次 render 新建数组，裸依赖必重跑；用 label 签名只对「名字变化」敏感，改名即时生效且普通交互零重算 |
