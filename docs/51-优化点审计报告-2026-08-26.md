## 三、重复实现

经引用图追踪，**base 与 director3d 之间无重复实现**（d3dPersistence 在 base 单一实现，director3d 复用）。但有两处移植遗留的"两套机制"：

1. **两套 toast / confirm**：`base/toastStore.js`（全局 `showToast`）+ `director3d/useToast.js` + `director3d/ConfirmDialog.jsx`（组件内 useState 队列 + 自定义 useConfirm）。director3d 未复用 base，自带一套（注释称"视觉对齐 maomao 统一通知"）。
   - 证据：`director3d/App.jsx:130,232,234`；`base/toastStore.js:41`。
   - 建议：长期可统一到 base，属重构，优先级低。
2. **两套 logger**：`base/logger.js`（带后端上报）+ `director3d/log.js`（轻量 configureErrorReporting + log）。属移植隔离，可接受。

## 四、依赖体积与分包（vite.config.js + package.json）

### 4.1 manualChunks 评估（vite.config.js:23-39）

按 node_modules 顶层包名归组：`@react-three`/`three` → vendor-3d；`mediabunny`/`gifenc` → vendor-media；`lucide-react` → vendor-ui；`dagre` → vendor-layout；含 react → vendor-react。

**问题**：vendor-3d 注释标"隔离不阻塞首屏"，但因 `Director3DNode`（App.jsx:20 静态 import）→ `Director3DOverlay` → director3d/App → models.jsx(useGLTF) 这条**静态**引用链存在，主 index chunk 会静态 import vendor-3d，**首屏仍需下载 three/drei 整包（~1MB）**。所谓"隔离"只是分了 chunk，未"懒加载"，首屏仍阻塞。

### 4.2 drei 是否全量

全工程对 `@react-three/drei` 的 import 仅 12 个 helper（ContactShadows/Grid/OrbitControls/TransformControls/Hud/OrthographicCamera/useGLTF + PerspectiveCamera/useTexture）。drei 走 ESM，Rollup 会 tree-shake，不会全量；但其内部依赖 three-stdlib 使 vendor-3d 仍偏大。
→ 可省 200~400KB 的方向：从 `three/examples/jsm` 精确引入替代 drei（中风险，见 docs/50 第五节）。
