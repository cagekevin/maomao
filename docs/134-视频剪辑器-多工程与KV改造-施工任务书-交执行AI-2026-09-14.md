## T3 · StorageService 改走 KV 严格族 CAS

### 前置
- 读 `docs/133` §3.4 / §3.5（写族已定：**严格族**）
- 读 `_legacy/data/projectRepository.ts`（**已实现的 KV 写者，可直接借鉴其形态**）
- 读 `src/components/base/store/projectStore.ts:338`（CAS 基线取法的先例）

### 关键事实（已取证）
`engine/services/storage/service.ts` 的**写点只有 4 处**：
| 行 | 方法 | 现状 |
| --- | --- | --- |
| `:91` | `saveProject` | `projectsAdapter.set(...)`（IndexedDB） |
| `:125` | `loadProject` | `projectsAdapter.get(id)` |
| `:210` | `deleteProject` | `projectsAdapter.remove(id)` |
| `:173/190` | `listProjects` / `getAll` | `projectsAdapter.list()` / `.getAll()` |

### 动作

> ⚠️ **这是本文最需要谨慎的一卡。** 引擎的 `ProjectManager` 调 `storageService.saveProject/loadProject`，
> **签名必须保持不变**（入参 `TProject` / 出参语义），否则引擎要跟着改（违反纪律 3）。

**① `saveProject({ project })`** → 改走 CAS：
```
键 = videoEditorProjectKey(projectId, project.metadata.id)
基线 = contentKvGetVersion(键)
写 = contentKvSetCas(键, 序列化(project), { ifVersion: 基线 })
409 → 抛错（**不重试、不降级**；由调用方决定怎么办 —— 见下面「409 的消费」）
```

**② `loadProject({ id })`** → 改走 `contentGetAsync` + `contentKvGetVersion`（读前后各取版本，不一致重读）；
`null` → 返回 `null`（**保持现有语义**：`ProjectManager:134` 靠 `!result` 抛 `not found`）。

**③ `deleteProject` / 列表相关** → 同样换 KV。

**⚠️ `projectId` 从哪来？**
`StorageService` 的方法**现在只收 `projectId`（= cutia 的工程 id）**，而我们要的是
**（画布 projectId, editorId）**。**这是本卡的核心设计点**：

- **方案 X（推荐）**：`StorageService` 增加一个**模块级 setter**：
  `setEditorContext({ canvasProjectId, editorId })`，由 `EditorProvider` 在挂载时调用。
  之后内部键构造用这两个值。
- **方案 Y**：改所有方法签名加参数 —— **会牵动引擎**（违反纪律 3），**不推荐**。

> 🔴 **执行 AI 注意**：若你觉得方案 X 有更好的实现，**停下回报**，不要自行改引擎签名。

**④ 409 的消费**（`docs/133` §3.5 纪律 D-4）：
409 必须**在 UI 侧可见**（提示「工程已在别处被修改」），**禁**静默重试。
> 本卡只保证"抛得出去"；**UI 提示**属 T5 的一部分。

## E.2 U-2 论证：为什么元数据不放 KV

| 维度 | 放 KV | 留 IndexedDB（**采纳**） |
| --- | --- | --- |
| 一致性 | 与工程本体同源，但**每加一个素材就写一次 KV**（CAS 语义对"追加型小记录"过重） | 素材元数据是**按 id 的独立小记录**，天然适合 IndexedDB 的 key-value |
| 配额 | KV 由后端 SQLite 承载，**不适合堆大批素材条目** | IndexedDB 由浏览器配额承载，与媒体域同生命周期 |
| 迁移 | 需为存量素材做二次迁移 | 复用 cutia 既有 `mediaMetadataAdapter`，**零迁移** |
| 结论 | ✗ | ✓ 二进制走 `/files/`（跨设备可用），元数据留本地（与工程同机）。**若未来要跨设备同步素材，需把元数据也迁 KV** —— 这是已知边界。 |
