## 背景与痛点

全屏 `ImageEditor` 内有「裁剪」和「扩图」两个独立动作。当前存在三个问题：

1. **节点比例不变（核心 bug）**：扩图保存后，画布虽变大，但节点显示用的 `renderUrl` 走缩略图端点（`buildThumbnailUrl` 压到最长边 640），等比外扩后整图比例与原图一致，压回 640 后比例不变 → `fitByRatio` 判定变化 <4px 直接 return → 节点形状"看起来没变"，不像裁剪那样自动自适应。
2. **默认外扩量不该是 50%**：`outpaintAmount` 初始值写成了 `0.5`，需求是默认 `0`（无白边、原图铺满、即 `toOutpaintZoom(0)=1`）。
3. **底图用完即焚，链路断裂**：`applyCrop` 与 `applyOutpaint` 确认后都执行 `imgRef.current = null`。扩图依赖 `imgRef.current`（原始图）重画，一旦先裁剪把 `imgRef` 置空，再进扩图就拿不到底图（用 placeholder 1×1），流程不可重复。

## State 1: 定契约（输入/输出/边界）

### 核心需求
- 裁剪、扩图保存后，节点比例都要按真实画布尺寸自动变（与裁剪现有行为一致）。
- 扩图默认外扩量 = 0。
- 裁剪 ↔ 扩图可任意先后、可重复，互不吞底图。

### 输入源
- 用户在 `ImageEditor` 内的裁剪选区（`completedCrop`）/ 扩图参数（`outpaintRatioKey`, `outpaintAmount`, `outpaintOffset`）。

### 输出目标
- `canvas` 像素（裁剪裁切 / 扩图画白边）。
- `handleSave` 回传 `{ dataUrl, width, height }`。
- `ImageNode` 写回 `data.imageUrl/url` 并按 `{width, height}` 调 `fitByRatio` 自适应形状。

### 副作用
- 节点 `data` 不可变更新（`setNodes`）。
- `imgRef.current` 底图状态在裁剪/扩图后「回填结果图」，而非焚毁。

### 收口检索（同类既有实现，全部复用，无新增文件）
| 能力 | 既有件 | 本次动作 |
|---|---|---|
| 节点比例自适应 | `useFitNodeRatio.fitByRatio` / `fitFromImage` | 复用；`ImageNode` 补解构 `fitByRatio` |
| 图片写回入口 | `useImageHoverActions.onImageReplaced` | 扩展签名加 `dims?` |
| 缩略图端点 | `buildThumbnailUrl`（`imageUrl.ts`，maxDim=640） | 不改；用显式 `width/height` 绕过其尺寸吞没 |
| 扩图纯函数 | `computeOutpaintTarget` / `computeOutpaintDrawPos` / `toOutpaintZoom` | 复用 |

### 文件归属
全部并入既有文件，不新建：
- `src/components/base/ImageEditor.tsx`（底图回填、handleSave 回传尺寸、默认值）
- `src/components/base/useImageHoverActions.tsx`（`onImageReplaced` 透传 dims）
- `src/components/nodes/ImageNode.tsx`（`replaceImage` 收 dims → fitByRatio）
- `src/components/nodes/PromptNode.tsx`（onImageReplaced 签名兼容，忽略 dims）

## State 2: 定数据流（链路 / 唯一入口）

```
[ImageEditor]
  applyCrop / applyOutpaint
    └─ commitCanvasToImgRef()
         canvas.toDataURL('image/png') → new Image() → imgRef.current = img
         （唯一底图真相源，统一回填，消除两处 `= null` 分叉）
    └─ canvas 已是最终结果像素
  handleSave（唯一保存出口，不分支）
    └─ onSave({ dataUrl: canvas.toDataURL('image/jpeg',0.9),
                width: canvas.width, height: canvas.height })
         ↓
[useImageHoverActions.handleEditorSave]（透传，不改链路）
    └─ onImageReplaced(dataUrl, width&&height ? {width,height} : undefined)
         ↓
[ImageNode.replaceImage]（落点）
    ├─ setNodes 不可变更新 data.imageUrl/url
    └─ if (dims) fitByRatio(dims.width, dims.height)   ← 绕过缩略图尺寸还原
```

### 唯一入口判定
- **底图真相源**：`imgRef`，统一由 `commitCanvasToImgRef` 收口（消除「裁剪置 null / 扩图置 null」两处分叉）。
- **写回**：`onImageReplaced`（既有，已扩展 `dims?`；`PromptNode` 忽略 dims，`ImageNode` 消费）。
- **比例自适应**：`fitByRatio`（既有唯一函数，必须在 `ImageNode` 解构出来，否则 `ReferenceError`）。

### 边界 / 失败拦截
- `commitCanvasToImgRef` 用 `img.onload` 异步回填。极端时序下（确认后立刻再开扩图），`imgRef` 可能尚未回填 → `renderOutpaint` 增加兜底：底图为空时回退用 `canvasRef.current` 当前内容（`drawImage(canvas, ...)`），避免卡空白。
- 数据流向单向：`ImageEditor → hook → Node`，无循环依赖；`imgRef` 仅 ImageEditor 内部消费，不外泄。

## State 3: 构思测试（断言）

纯函数/可验证断言（实现一变必红）：

1. **底图收口**
   - 给定 `applyCrop` 后 → 断言 `imgRef.current` 非 null 且 `naturalWidth === 裁后宽`。
   - 给定 先 crop 再 expand → 断言 `renderOutpaint` 以 crop 结果为底图（画布 = 扩图目标尺寸，内容含裁后图，非空白）。

2. **尺寸回传绕过缩略图**
   - 给定 原图 800×600，扩图 `ratio='1:1'` `amount=0` → 目标画布 800×800（zoom=1 无白边）。
   - 断言 `handleSave` 回传 `width=800, height=800`；`replaceImage` 调 `fitByRatio(800,800)` → 节点高 = 宽。

3. **默认值**
   - 断言 `outpaintAmount` 初始 = 0（非 0.5）。

4. **引用完整性**
   - 断言 `ImageNode` 解构含 `fitByRatio`，调用不抛 `ReferenceError`。
