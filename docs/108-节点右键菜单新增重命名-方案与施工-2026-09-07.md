# 节点右键菜单新增「重命名」—— 方案与施工任务书

> **日期**：2026-09-07
> **状态**：~~方案已与需求方确认，未改代码~~ → **已实施（2026-09-07）**：按 §四 施工（MenuActionCtx.renameNode + buildNodeMenuItems 首项 + RenameDialog.tsx + App.commitRename/openRenameDialog + 测试）
> **结论**：在单选节点右键菜单 `buildNodeMenuItems` 增加「重命名」菜单项，点击后关闭菜单、弹出**轻量输入弹窗**（预填当前名），提交后统一写回节点 `data` 并进撤销栈（`history.record`）。普通节点写 `data.label`，编组节点（group）写 `data.name`。
> **关联文档**：`docs/70-画布图片命名与@名匹配-全节点方案-2026-08-28.md`（命名语义）、`docs/39-节点外壳与样式收敛-Handoff-2026-08-24.md`（NodeShell 范式）、`src/components/base/ui/NodeShell.tsx` 头部「§5 数据状态统一范式」

---

## 一、需求一句话

给节点的右键菜单加「重命名」：现在已有「复制」「删除」，补上改名入口，让所有节点（含编组）都能改标题并持久化。

**已拍板（2026-09-07 与需求方确认）：**

| 决策点 | 结论 |
|---|---|
| 交互形态 | **轻量改名弹窗**（点菜单 → 弹小输入框预填当前名 → 回车/确定写回）。不做就地编辑，避免动公共 NodeShell/NodeTitle |
| 是否进撤销栈 | **要**：写回时调 `history.record`，与「复制/删除」一致，可 Ctrl+Z 回退 |

## 二、现状梳理（代码事实）

### 2.1 菜单链路（全是事实，先读一遍）

| 环节 | 位置 | 角色 |
|---|---|---|
| 菜单项生成 | `src/components/base/canvas/canvasContextMenu.tsx` → `buildNodeMenuItems`（`194-240`） | **要改的核心函数** |
| 动作回调类型 | 同文件 `MenuActionCtx`（`40-67`） | **要新增 `renameNode`** |
| 动作真实现 | `src/App.tsx` → `menuCtx` 组装（`947-985`） | **要加 `renameNode` 实现** |
| 菜单渲染 | `src/components/base/ui/ContextMenu.tsx` | 不动。叶子项 `closeOnClick` 默认 `true`，点完自动关菜单 |
| 节点标题/双击改名 | `src/components/base/ui/NodeTitle.tsx` + `NodeShell.tsx` | 复用其样式语义，但本方案**不进入其编辑态**，只用它确认「label 是展示来源」 |

`buildNodeMenuItems` 现状（`canvasContextMenu.tsx:194-240`）——单选节点菜单结构：

```ts
// 目前条目顺序：
//   复制                    （所有节点，duplicate → ctx.duplicateSelected(node.id)）
//  [复制图片]               （仅 imageNode/promptNode → ctx.copyNodeImage）
//  [取消编组]               （仅 group → ctx.applyUngroup）
//   ─ divider ─
//   删除                    （danger → ctx.deleteNode(node.id)）
```

### 2.2 节点名字存哪（改名写回的分叉依据）

- **普通节点**：名字 = `node.data.label`（ImageNode / PromptNode / TextNode / DiscountVideoNode / …）。空时 UI 显示各节点 `defaultTitle`（如「生图节点」）。
- **编组节点 group**：名字 = `node.data.name`（`src/components/nodes/GroupNode.tsx:28`：`data?.name || '编组'`，GroupNode 把 `label={name}` 传给 NodeShell）。
- 未命名默认值在 Node 组件内（各节点 `defaultTitle`），App 层不可知 → 弹窗预填用 `data.label ?? data.name`，空则输入框留空 + placeholder。

### 2.3 改名现状缺口（为什么要在 App 层做，而不是塞给各节点）

- 已有部分节点把「双击标题改名」接到 `onRename` 写回 `data.label`（PromptNode/ImageNode/VideoProcessNode 等），**但它们的写回都不进 `history.record`，且走裸 setNodes**。
- 仍有节点**没接 onRename**（TextNode / ImageBoxNode / GroupNode 等），双击改名只本地显示、不落 data。
- 没有任何「右键菜单 → 改名」入口。

→ 结论：**在 App 层统一实现改名写回**（一个 handler + `setNodes` + `history.record`），一次覆盖全部节点类型与 group，无需逐节点补 onRename，还能顺手补上撤销。

### 2.4 没有现成的「文本输入弹窗」基座

- 全局确认框：`confirmStore.ts`（`askConfirm` → Promise<boolean>）+ `ConfirmContainer.tsx` —— **只有确定/取消，没有输入框**。
- 全局 toast：`toastStore.ts`。均属「模块级 store + App 挂一次容器」范式。
- 全仓搜 `askInput / RenameDialog / PromptDialog` 等：**0 命中**。
- → 弹窗需要一个轻量新组件（见 §4.3）。不建通用 input store（避免过度设计），先做专用 `RenameDialog`。


### 4.2 App 层实现 `renameNode` + 提交写回

文件：`src/App.tsx`

**a)** 在 `menuCtx`（`947-985`）中新增字段：

```ts
renameNode: (id) => openRenameDialog(id),
```

`openRenameDialog` 用 `nodesRef.current` 找节点当前显示名做预填（group 取 `data.name`，其余取 `data.label`），并把弹窗状态 set 进一个 App state（见 4.3）。

**b)** 提交写回 handler（改名统一落点，可放在 `deleteNode`(`611`) 附近，风格对齐）：

```ts
// 统一改名写回：普通节点写 data.label，group 写 data.name；空值 = 不改；进撤销栈。
const commitRename = useCallback(
  (id: string, name: string) => {
    const next = name.trim();
    const cur = nodesRef.current.find((n) => n.id === id);
    if (!cur) return;
    const field = cur.type === 'group' ? 'name' : 'label';
    if (!next || cur.data?.[field] === next) return;   // 空名/未变 = 忽略
    // P0-B 红线：setNodes 不可变更新（见 NodeShell.tsx 头注释 / docs/106），禁止原地 mutation
    const nextNodes = nodesRef.current.map((n) =>
      n.id === id ? { ...n, data: { ...n.data, [field]: next } } : n,
    );
    setNodes(nextNodes);
    history.record({ nodes: nextNodes, edges: edgesRef.current });
  },
  [setNodes, history],
);
```

要点：
- **普通/group 字段分叉只此一处**；不依赖节点组件内部 onRename（所有节点/编组一次覆盖）。
- 用 `history.record`（`useCanvasHistory` 在 `App.tsx:346`），可撤销。
- `edgesRef.current` 传现时引用（改名不动边，但 record 需完整快照，对齐 `applyDeleteSelected` 等现有写法）。
- 空输入 / 与原名相同 → 静默不写、直接关弹窗。

### 4.3 轻量改名弹窗组件（新增）

没有现成输入弹窗基座，新增一个专用小组件。视觉/交互对齐 `ConfirmContainer`（遮罩、`z-ceiling-2`、surface token），但多一个输入框：

新文件：`src/components/base/ui/RenameDialog.tsx`

```ts
interface RenameDialogProps {
  open: boolean;
  initial?: string;                 // 预填当前名（可能为空）
  placeholder?: string;             // 默认「未命名节点」
  onCancel: () => void;
  onSubmit: (name: string) => void; // 已 trim，空值由调用方决定忽略
}
```

交互契约（与全仓弹窗心智一致）：
- autoFocus 输入框；`Enter` 提交、`Esc`/遮罩点击/取消按钮 = `onCancel`；
- 输入框标 `nodrag`，防拖拽冒泡（React Flow 画布内弹窗如将来浮在节点上也不误拖节点）；
- 提交即调 `onSubmit(name)`，由 App 侧 `commitRename` 判空并写回；
- 卸载/关闭时清空本地 state（下次打开用新 initial，不要残留）。

App 侧状态承载（最小侵入，不引全局 store）：

```ts
const [renameTarget, setRenameTarget] = useState<{ id: string; label: string } | null>(null);
// openRenameDialog(id)：由 nodesRef 取当前名 → setRenameTarget({id, label})
// 提交：commitRename(renameTarget.id, name) → setRenameTarget(null)
```

> 备选（若后续想供非 React 模块/Agent 调用）再升级为 `renameStore + askRename()` 模块级 store 范式（对齐 confirmStore/toastStore）。本次不扩，避免过度设计。

### 4.4 菜单挂载处渲染 RenameDialog

在 `App.tsx` 渲染 `<ContextMenu>` 的同层（原 `1425-1430` 附近）加：

```tsx
<RenameDialog
  open={!!renameTarget}
  initial={renameTarget?.label}
  onCancel={() => setRenameTarget(null)}
  onSubmit={(name) => {
    if (renameTarget) commitRename(renameTarget.id, name);
    setRenameTarget(null);
  }}
/>
```

## 八、风险与边界（写清，施工别越界）

1. **不改 NodeShell / NodeTitle**：本方案用独立弹窗而非就地编辑，公共外壳零改动，回滚面最小。
2. **不建通用输入 store**：先做专用 `RenameDialog`；若未来出现多处「输入类弹窗」需求，再升级为 `askRename/askInput` 模块级 store（对齐 confirm/toast 范式）并统一容器。
3. **不改重名唯一性**：同名节点允许存在；与 docs/70 的 `@名` 全等匹配语义相关，属独立议题，不混入本次。
4. **不逐节点补 onRename**：本次只在 App 层统一收口；已接 onRename 节点的双击链路保留不动，避免双写冲突。
5. **历史记录**：`history.record` 需要 edges 完整快照，用 `edgesRef.current`（对齐现有 applyDeleteSelected 写法），别传旧闭包值。
