## 3 · 判据沉淀（本会话最值的方法产出，**接手者直接照用**）

```
① 死导出（零外部 import）⇒ 去 export 收私有（ADR-0030）        零 churn   ← 用了 5 处
② 同形同义（探测重复）   ⇒ 收口复用（ADR-0031）                 非改名     ← FlowPosition
③ 判据重复（形状互异）   ⇒ 禁合并、各加域前缀                              ← ChatMessage ×3
④ 纯位置搬动             ⇒ 无判据依据则不做（收益不可测）                  ← S1-3 整批
```

**改名出口的决策顺序**：先问「能不能不导出」（①）→ 再问「是不是重复」（②③）→ 都不是才改名。

## 5 · 🔴 硬坑清单（本会话实踩，接手必读）

1. **`rename-symbol` 不动 `vi.mock` 的对象键** —— 改名后 mock 静默失效（假绿或真红）。
   本会话 S1-1c-1 为此红了 6 例。**每批改名后必查**：`grep -rn "vi.mock.*<被改模块>" tests`，核对 mock 是否提供新名。
2. **`type` 改名无 mock 风险**（运行时被擦除）—— 值级改名才有。
3. **`mv-sync-refs` 三处工具缺口（TD-17-22/23，未修）**：
   - `rename` 对 `.css` **丢扩展名**（`main.tsx` 的 import 变无扩展名，Vite 解析失败）
   - **不改写无扩展名 import**（如 `tailwind.config.ts` 的 `./src/.../ve-tailwind-colors`）
   - **`move-dir` 不搬 CSS**（只认"源码文件"）且**被搬文件的兄弟导入会写成指向旧目录的别名路径**（S1-6 实踩，7 处手工修）
   ⇒ **每批 move/rename 后必做**：`grep -rn "旧路径片段" src tests` 残留复扫 + 人工核对 CSS 与无扩展名 import。
4. **`check-arch` 规则 2 的方向**：`base/` 的件**被**业务域消费 = 正确单向、零违规；
   **把它们迁出 base 才会制造违规**（base 内常还留着消费者）。
5. **D20 前提**：目标形态未定死 ⇒ 不许开工（S1-3 整批因此不做；S2-1 定画布域落点后，S1-3 的 5 件延后项随批处理）。
6. **登记/计划里的数字与结论不可照抄**：本会话 6 处被推翻，其中 **D7 若照登记执行 = 删掉素材库落盘调度（数据丢失级）**。
   照抄前必跑 `refs` + grep 实测。
7. **N1 判据 = 撞名**，不是"所有导出都加前缀"——域内唯一名加前缀 = 违反减二闸（`formatTimeCode` 实例）。
8. **闸**：`pre-commit` = lint-staged + `test-affected.cjs`（**按源码→同名 stem 测试反查，会漏跨 stem 的测试**）+ 3 个秒级 SSR 门禁；
   代码闸（tsc/arch/any/…）**只在 pre-push 跑一次**。别在提交时重复跑（浪费感情），但跨 stem 的 mock 测试要手工点名跑。
