## 一、Phase 1 · 溯源与对齐

### 1.1 有罪推定：真需求是什么

| 表面诉求 | 追问 | 根因 |
| --- | --- | --- |
| "搬 cutia 过来" | 为什么？ | 自建成本高、质量不确定（"自己写太累"、"交互不够对"） |
| "core 可以不要" | 为什么舍得？ | 自建 core 只做时间轴运算，**不含属性/K帧**（用户指出） |
| "先搬再改造" | 为什么？ | 需要"什么是对的"由成熟实现锚定，而非自己摸索 |

**诊断**：痛点 = **"从 0 定义正确交互/属性形态"的成本与不确定性**，不是"缺某功能"。

### 1.2 目标重塑

```
业务目标：用 cutia 替代我的编辑器
    ↓
系统目标：获得一个「可长期维护」的视频编辑器，
          交互/属性形态由成熟实现锚定；
          且改造能力与上游演进能力互不干扰。
```

**「长期维护」+「不跟踪上游」两个约束合起来，推出本章最重要的结论** → 见 §2.3。

### 1.3 ★对 `125` 的取证推翻（必读）

`125` 结论："内核（core/managers/services/renderer/lib）纯 TS、零 next 依赖、**可整体 import**"。

**实测：前半为真，后半为假。**

```bash
# core/managers/*.ts 的真实外部依赖（实测，非推测）
"@/lib/export"                     ← 导出域
"@/services/video-cache/service"   ← 视频缓存域
"@/stores/agent-store"             ← ★AI 状态（project-manager / save-manager 均 import）
"sonner"                           ← toast 库
"@/lib/media/audio"
"@/services/storage/service"
"@/services/renderer/{canvas-renderer,nodes/root-node,scene-builder,scene-exporter}"
"@/utils/id"   "@/lib/scenes"   "@/lib/timeline"   "@/constants/timeline-constants"
```

`services/storage/types.ts:8` 更进一步：
```ts
import type { AgentMessage } from "@/lib/ai/agent/types";
```

**结论**：
- ✅ "零 `next/` 依赖" **成立**（可搬，这个前提没变）；
- ❌ "自包含内核、可整体 import" **不成立** —— 引擎的依赖图**向后延伸到 AI/导出/缓存/toast**。

**这条修正的架构含义**：引擎的依赖图是**既成事实**（不变式 I3），**不可"净化"**。强行切掉 `agent-store` 会改坏引擎（那是真实功能耦合，不是脏依赖）。

## Phase 2 · 筑基与定海

### 2.1 三条不变式（本计划的地基）

| # | 不变式 | 取证 | 违背后果 |
| --- | --- | --- | --- |
| **I1** | `EditorCore` 是**进程单例** | `core/index.ts`：`private static instance` + `static getInstance()` | 多工程串数据；切工程必须 `loadProject` + `closeProject` |
| **I2** | cutia 的 `TProject/TScene/TimelineElement` 是**唯一数据模型** | `types/timeline.ts`（239 行） | 在外部维护 `Project` 副本 = **SSOT 第二份**（本仓头号母体） |
| **I3** | 引擎依赖图是**既成事实**，不可净化 | §1.3 实测 | 强行切依赖 = 改坏引擎 |

### 2.2 探流：SSOT 在哪（核心发现）

```
真源链（实测）：
  UI 组件 → useEditor() → EditorCore.getInstance() → managers
                                   ↓
                    ScenesManager.getActiveScene().tracks
                                   ↓
                    StorageService（IndexedDB + OPFS）
```

**结论**：SSOT = `EditorCore` 单例 + `StorageService`。

→ **`docs/120`/`123` 规划的 `core/types.ts` 的 `Project/Track/Clip`，一旦并存就是 SSOT 第二份**（同一件事的两份描述，且都进持久化）。

→ **这从架构上证明 D1（core 全弃）是正确的**，不是沉没成本妥协。**是消除根因。**

### 2.3 ★探底：这个项目你在维护什么（本计划最重要的判断）

**D5（不跟踪上游）改变了`125`/`129` 的隐含前提。** 两者的隐含目标都是"能跟随 cutia 演进"；D5 明确**不跟**。

| 层 | 谁维护 | 改动频率 | 处置 |

### 4.1 ★守卫的处置（纠正前两轮的错误）

**前两轮的错误**：
- 首轮说"改名会让守卫失效，代价很大" → **把闸当红线**（心法 §零.4.1 点名批判）；
- 次轮说"改锚点" → **错得更隐蔽**：锚点改了，但闸守的东西已经不存在了。

**正确推演（心法 §零.4.2 判据）**：

```
第一步：定性
  VE_CORE_REL（规则 4）· VE_HOOKS_REL（规则 6）
  → 拿得出 CLAUDE.md 级红线证据吗？不能。
  → 它们守的是「videoEditor/core 只准 import 谁」= 结构偏好闸
  → 结论：可被正确性/复杂度证据推翻，架构师直接改

第二步：这两条闸还有什么守护对象？
  规则 4 守 src/components/videoEditor/core/   ← 自建 core，将被删（D1）
  规则 6 守 src/components/videoEditor/hooks/  ← 自建 hooks，将被删（D1）
  → 删完后两条闸「扫 0 文件」= 空转（心法 §零.4.1：闸在假装工作）

第三步：新结构里哪条边界值得守？
  唯一值得守的边界 = 引擎区 不得被 改造区 反向依赖（§2.3）
```

**裁决**：

## 三、K 帧地基契约（唯一自研部分）

**事实**：cutia **没有 K 帧**（实测 `grep -rln "keyframe|animations" → 0 命中`）。其 `types/timeline.ts` 的属性全是**静态值**（`opacity: number`、`transform: Transform`）。属性**面板**（3494 行）白拿，**动画层必须自建**。

**设计（窄接口深模块，心法 §Phase 3）**：

```ts
// 契约（草案，待用户审）
type Seconds = number;

type Easing = 'linear' | 'ease-in' | 'ease-out' | 'ease-in-out';

interface Keyframe<T> {
  t: Seconds;          // 工程时间轴时间
  value: T;
  ease?: Easing;       // 从本帧到下一帧的插值
}

/** 可动画属性：静态值 或 关键帧序列（唯一形状，不做第二种） */
type Animatable<T> = T | { keyframes: Keyframe<T>[] };

/** 唯一求值入口（预览 = 导出共用，防第二套采样） */
function evaluate<T>(prop: Animatable<T>, t: Seconds): T;
```

**不变量**：
- **A1** 关键帧按 `t` 升序（写入时排序，读取时不假设有序）；
- **A2** `t < 第一帧` → 取第一帧值；`t > 末帧` → 取末帧值（**钳制，不外推**）；
- **A3** 单帧或静态值 → `evaluate` 恒等（无分支特例）；
- **A4** 采样点唯一：预览与导出**都调 `evaluate`**，不得各自实现。

**验证**：`tests/unit/videoEditor/animations.test.ts` — 线性/缓动/首尾钳制/单帧恒等/乱序输入。

**落点**：`src/components/videoEditor/core/animations.ts`（**注意**：此处 `core/` 是**你的改造区**，与 S7 要删的旧 `core/` 冲突）。

> ⚠️ **命名冲突（需你决定）**：S7 要删旧 `core/`，而 K 帧要新建 `core/`。建议 K 帧落 **`src/components/videoEditor/animations/`**（独立域，避免"删了又建同名目录"的混淆）。**若你偏好 `core/`，可在 S7 之后再创建。**
