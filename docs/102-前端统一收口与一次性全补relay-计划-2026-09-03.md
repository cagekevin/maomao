# 前端统一收口 + 一次性全补 relay（计划）

> 性质：可执行计划（先收口 → 再一次性全补）。用户定：老通道(/api/proxy)不是目标，最终删；先前端统一，后并后端 relay/API。
> 目标：image/video/chat 三条通道**一次**切到 relay（/api/generate + /api/relay），前端只发统一 GenIntent(providerId=13服务商JSON之一)，无遗漏、无回归、可回退。

---

## 阶段 A · 收口（不切线，先让「统一数据 + 客户端 + 后端承载」到位且可编译）

### A1. 统一数据契约（已部分完成）
- [x] `src/components/base/api/genIntent.ts`：`GenIntent` / `GenOutput`（capability/providerId/model/taskId/prompt/messages/size/images）——**已建，tsc 过**。

### A2. 统一 relay 客户端 `relayProxy`（补齐缺口）
- [x] `relaySubmit` / `relayPoll` / `relayCancel` / `relayGenerate`（image/video 后端驱动，收 GenIntent 形状）。
- [ ] **补 `relayChat(intent, {signal})`**：打 `/api/relay`（后端已真机验通 chat 非流式），返回 `{ok,content}`。**缺失**。
- [ ] **补 `relayCancel` 的取消语义**：image/video 中途取消要调 `/api/generate/:id/cancel`（后端置 failed），relayGenerate 的 signal abort 目前只断 GET，没通知后端 cancel → 后端句柄会续跑到终态。**需对齐**。

### A3. 任务号/节点归属贯穿（修复我埋的 bug）
- [ ] proxyGenerate 里 relay 分支 `nodeId: provider?.id` 是**错的**（把 node_id 写成 'lovart'）。DB 的 node_id 应由 taskStore 提供。方案：门面不再经 proxyGenerate 拼 intent，而是**门面直接调 relayProxy 并传正确 nodeId**（由 useGenerateNode 通过 taskId 反查 taskStore 的 nodeId，或门面入参直接带 nodeId）。**收口时把这条理顺**。

### A4. 后端参数承载（让 relay 能接住前端全参数，属 lovart 基础能力非平台协议）
- [ ] relay-poll.submitGenerateTask：入参补 `resolution?/duration?`（video 用），透传 preset variables。
- [ ] `lovart-video` preset body 补 `resolution`/`duration`（当前只 model/prompt/size → video 切 relay 丢清晰度/时长）。参考图 images 已由 resolveLocalImages 归一。
- [ ] `/api/relay`(chat) 后端已通；确认 `stream`(true 流式) 与 responses 形态在 relay 侧有承接或前端切 relay 时 chat 走非流式即可（TextNode 默认非流式？剧本盒/AI 助手有 stream:true → **需确认**：切 relay 后这些 stream 场景是否仍非流式兜底）。

### A5. 前端门面收口
- [ ] `imageApi.generateImage` / `videoApi.generateVideo` / `chatApi.chatCompletions`：入参统一收 GenIntent（providerId 替代 provider），内部只做「参数归一 + 参考图归一」，出站一律走 relayProxy（不再 import proxyGenerate）。→ 这是把「散参数+provider富对象」收进统一入口。
- [ ] 把 genBody 里 image/video 的差异参数（video resolution/duration）纳入 GenIntent/relayProxy 传递（A4 兜底）。

## 阶段 B · 一次性全补 relay（切线 + 退役老通道）

### B1. 门面切 relay（image/video/chat 一次切）
- 门面内部固定走 relayProxy：image/video → `relayGenerate`(/api/generate 后端驱动)；chat → `relayChat`(/api/relay)。
- 删除 proxyGenerate 的调用（chatProxy/imageProxy/videoProxy 不再被门面 import）。`RELAY_ASYNC_SUBMIT` 开关 → 置 true 或移除（直接切）。
- 保留：参考图归一、尺寸查表、错误中文降级、进度映射（relayGenerate/relayChat 内）。

### B2. 刷新恢复（前端切 relay 后必须）
- 前端加载时从 DB(`/api/tasks`) 读 running 且 poll_task_id 非空的任务 → 逐个 `GET /api/generate/:id` attach 到后端句柄 → 完成后回填节点（替代 pollTask/initTaskRecovery 前端自轮询）。
- `useNodeGeneration` 的落盘：relay 已返回 /files/，saveResultToTasks 对本地 url 已 no-op（filesApi 已改）→ 保持。

### B3. 退役 proxy 旧链路
- 删 proxyGenerate 的 proxy 出站段 / pollTask.ts / taskStore ensurePolling 系 / 前端恢复落盘。
- `/api/proxy` 前端零消费 → registry RESERVED→删；check:api 归零。

## 执行顺序与验证
1. A2/A3/A4 收口（tsc + localTool 测试过；后端 /api/generate、/api/relay 真机已验 image/chat）。

## 红线
- 能力零退化：进度/取消(需 A2 对齐 cancel)/参考图/错误中文/刷新恢复，逐个有人兜住。
- providerId 为主键：前端不塞 base_url/protocol/refFormat 给后端（老通道兼容期仅内部查回）。
- 每步 tsc；后端改动跑 localTool 测试；前端切线需你本地真机手测（本环境无法起前端）。
- video 依赖 A4（后端 preset 补 resolution/duration）才切，否则丢参数。

## 待确认（已定方向：chat 流式由 config 驱动，不靠前端传）
1. **chat 流式 = config 驱动**（用户定）：在 config/providers/<id>.json 里给该 provider/chat 模型配 `streaming` 标记；
   后端 relay 出站按它决定走 `streamChat`(流式) 还是 `chat`(非流式)。前端 GenIntent **不传 stream**，只发 providerId/model，
   流式与否由后端读 JSON 决定。→ 这是「换 JSON = 换行为」，落在统一数据契约里。
   - 需在后端 A4 补：config/providers schema 支持 chat 模型级 `streaming`；relay /api/relay 按 providerId 读该标记选流式/非流式。
   - 前端剧本盒/AI助手的流式 UI 依赖后端流式返回；config 标该模型 streaming:true 即得流式。
2. 刷新恢复（B2）是否本轮一并做，还是切 relay 后下一轮再补（切 relay 前无恢复会丢刷新场景）。
