### 🔴 硬性执行纪律（防烂尾，最高优先）

**本计划不允许"做一半发现难就跳过去"。遇到任何障碍，按此处理：**

1. **卡住 ≠ 跳过**。遇到无法推进的问题，**停下来回报**，不要静默略过某个 Step 或某个约束。
2. **每改 3-5 个工具就跑一次 `npm run test:unit`**，出错立即定位回滚到上一个绿点，不积压。
3. **每个 Step 一个独立 commit**，commit message 前缀 `[架构]`。commit 前跑 `npm run type-check && npm run test:unit`。
4. **只按计划范围改**，不顺手重构计划外的代码（避免范围膨胀导致做不完）。
5. **全量回归（`npm test`）是唯一"完成"判据**，某 Step 的局部测试绿但全量崩 → 该 Step 未完成。

**已预埋的卡点 + 明确下一步（执行时先读这节，不临时瞎猜）：**

| 卡点 | 现象（会遇到） | 明确下一步 |

### 🛡️ 回退风险防线（改坏了怎么回，最高优先）

**核心原则：把大重构切成"可独立回退的小步"，每一步留一个绿点。**

**第 1 层：分支隔离（最根本）**
```bash
git checkout -b feat/agent-architecture   # 不要在 main 上直接改
```
> main 始终是干净绿点。重构期间随时 `git checkout main` 回到稳定态。**这是回退第一保险**——即使重构全废，main 毫发无损。

**第 2 层：每 Step 一个独立 commit（可回退单元）**
```bash
git commit -m "[架构] M0 代码收口：AI助手迁到 agent/"
git commit -m "[架构] M4 事件收口：移除死事件"
git commit -m "[架构] M1 CanvasHost 画布原语层"
git commit -m "[架构] M2 Workflow 状态机"
git commit -m "[架构] M3 useAgentChat 瘦身"
```
- 回退单步：`git revert <该commit>`（保留历史，只撤销该步）
- 回退多步：`git reset --hard HEAD~N`

**第 3 层：每步验证 = 回退触发器**
```bash
npm run type-check && npm run test:unit && npm run check:health
```
- 全绿才算完成；哪步没绿就回退哪步。
- 未提交时回退：`git checkout -- <该步文件>`
- 已提交时回退：`git revert <该commit>`

**第 4 层：M0 搬移的双保险回退**
- 用 `git mv` 搬移（git 追踪历史），回退 M0 只需 `git revert M0commit`（git 自动搬回 + 恢复路径）。
- **M0 必须原子完成**：所有搬移 + 所有路径替换 + index.js 一次做完再验证，不要"搬一半歇一会"（半搬移状态运行直接崩）。

**第 5 层：CI 兜底（自动化）**
- 项目 CI（.github/workflows/ci.yml）在 push main 时自动跑 type-check + test:unit。
- 推送 main 前：本地 `npm run check:health` 全绿才 push。
- push 后 CI 红 → **立即 `git revert` 最后那个 commit**，不带着红进 main。

**⚠️ A 方案特有的回退风险（import 路径大改）**：
- M0 改到一半（部分文件搬了、部分没搬）→ 代码"半搬移"态，**运行直接崩**，验证都跑不了。
- 防法：M0 一次做完再验证；若验证发现漏改，**补改**而非回退（搬移本身对，只是漏路径）。

## 四、Step M1：CanvasHost 画布适配层（底层地基）

> **设计目标（审计确认）**：工具层已有 `buildCanvasAgentTools(ctx)` 的"句柄注入"抽象（ctx 经 useReactFlow 传入，:1222/:1224），工具执行统一走 `execute(args, ctx)`。**本步不是为了"消除裸 useReactFlow"（那已不存在），而是把工具 execute 里重复的底层写法**（`setNodes([...getNodes(), x])` / `setNodes((ns)=>ns.map(...))` / `deleteNodesWithCascade(getNodes(), getEdges(), id)`）**封装成语义清晰、可复用、可批量、可回滚的画布原语**。这才是"可维护性/可扩展性"的真正来源。

**新文件：`src/components/agent/canvas/canvasHost.js`（纯 JS 工厂，无 React hook）**

```js
// 伪代码骨架，具体按此实现
import { deleteNodesWithCascade } from './groupNodes.js'
import { runNodeGeneration } from './taskStore.js'
import { generateId } from './idGen.js'

/**
 * 画布操作原语层（纯 JS，注入 ctx 可测）。
 * 目标：把「底层 ReactFlow 写法」收敛成「语义动作」，供工具层/执行器复用。
 * @param {object} ctx 画布句柄：{ getNodes, setNodes, getEdges, setEdges, addNodes, addEdges, screenToFlowPosition, setCenter, ... }
 * @param {object} [ops] 注入的非 ctx 依赖（host 是纯 JS，不直接依赖 React hook）：
 *  - cancelRun?: (nodeId)=>void  取消单节点生成（来自 useNodeGeneration 的 stop；taskStore 无独立函数，见卡点 K1）
 */
export function createCanvasHost(ctx, ops = {}) {
  // ── 读 ──
  const getNode = (id) => ctx.getNodes().find((n) => n.id === id) || null
  const getNodes = () => ctx.getNodes()
  const getEdges = () => ctx.getEdges()

  // ── 写（语义原语，内部封装 ReactFlow 写法）──
  // 追加一个新节点（薄封装 buildCreateNode 的写侧）
  const appendNode = (newNode) => ctx.setNodes((ns) => [...ns, newNode])
  // 追加一批节点 + 可选边（P11 批量合并：一次 setNodes/setEdges，避免 N 次全量重渲染）
  const appendMany = ({ nodes, edges }) => {
    if (nodes?.length) ctx.setNodes((ns) => [...ns, ...nodes])
    if (edges?.length) ctx.setEdges((es) => [...es, ...edges])
  }
  // 更新单个节点 data（不可变局部更新，非目标引用不变不重渲染）
  const updateNodeData = (id, patch) =>
    ctx.setNodes((ns) => ns.map((n) => (n.id === id ? { ...n, data: { ...n.data, ...patch } } : n)))
  // 替换单个节点（保留 id，整体替换对象，用于回填 resultUrl 等）
  const replaceNode = (node) => ctx.setNodes((ns) => ns.map((n) => (n.id === node.id ? node : n)))
  // 删除节点（级联删子孙 + 相连边）
  const deleteNodes = (ids) => {
    const idArr = Array.isArray(ids) ? ids : [ids]
    const { nodes, edges, deleted } = deleteNodesWithCascade(ctx.getNodes(), ctx.getEdges(), idArr)
    ctx.setNodes(nodes); ctx.setEdges(edges)
    return deleted
  }
  // 追加边（批量一次写回）
  const appendEdges = (edges) => ctx.setEdges((es) => [...es, ...edges])

  // ── 事务（对齐大雄 beginTransaction/rollback）：记录本次 host 创建的节点 id，rollback 只删这些 ──
  let txCreated = null
  const beginTransaction = () => { txCreated = [] }
  const commitTransaction = () => { txCreated = null }
  const rollbackTransaction = () => {
    if (txCreated?.length) deleteNodes(txCreated)
    txCreated = null
  }
  // appendNode/appendMany 里若在事务中，记录 id（实现时在 appendMany 内部 push ids）

  // ── 生成 ──
  const runNode = (id, opts) => runNodeGeneration(id, opts)   // 复用现有，勿重写轮询
  const cancelNodeRun = (id) => ops.cancelRun?.(id)            // 注入的取消函数（见卡点 K1）

  // ── 视口 ──
  const focus = (ids) => ctx.setCenter?.((ids?.[0] && getNode(ids[0])?.position) || { x: 0, y: 0 }, { zoom: 1 })
  const toFlowPos = (x, y) => ctx.screenToFlowPosition({ x, y })

  return { getNode, getNodes, getEdges, appendNode, appendMany, updateNodeData, replaceNode, deleteNodes, appendEdges, beginTransaction, commitTransaction, rollbackTransaction, runNode, cancelNodeRun, focus, toFlowPos }
}
```

// 伪代码骨架
import { getCurrentWorkflow, patchCurrentWorkflow } from './conversationStore.js'

// 状态迁移规则（以现有 useAgentChat 实际迁移为准，不臆造）
