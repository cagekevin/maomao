# 新增 Lovart 模型操作手册

> 日期：2026-10-28
> 适用：`localTool/src/ai-relay/providers/lovart/` 直连 adapter 下的模型增删改
> 状态：已按本流程落地 `gemini-omni-1.1-flash`（VIDEO），`npm run test` 全绿

---

## 0. 一句话结论

一个模型在代码里有 **一个身份（模型 id）** 和 **五处清单**。id 是唯一真源：前端传什么名字，后端就用它查规格表、查别名表、拼 prompt、下发工具名。**新增模型 = 加一条别名规则 + 加一行规格 + 补四处清单 + 改测试计数**，不新增分支、不改调用链。

| 你要表达的东西 | 写在哪 |
|---|---|
| 这个 id 是图片/视频/对话 | `LOVART_MODEL_SPECS`（category） |
| 这个 id 对应上游哪个工具 | `LOVART_IMAGE_RULES` / `LOVART_VIDEO_RULES`（别名表） |
| prompt 里叫它什么 | `LOVART_PROMPT_MODEL_NAMES`（可读名） |
| 是否带质量档位 | `LOVART_QUALITY_MODELS`（可选，仅质量模型） |
| 前端/第三方能不能看见它 | `manifests/lovartModelManifest.ts`、`routes/platform.ts`、`providers.default.json`、`data/apiConfigs.baseline.json` |

## 1. 开工前必须先定三件事

| 问题 | 为什么必须先定 | 定错了会怎样 |
|---|---|---|
| **类别**：IMAGE / VIDEO / CHAT | 决定走 `generateImageLovart` / `generateVideoLovart` / chat 路，`assertCategory` 会硬拦 | 选错类别 → 一调就抛「模型 X 不是视频模型」，或视频参数拼不进 prompt |
| **上游工具名**：拿不到就留空串（如 `''`） | 结构化路 `tool_config.prefer_tool_categories` 只认工具名 | 工具名错 → 提交期**不报错**（`/chat` 照常返回 thread_id），产物期才 `unknown tool_hint "…"` 失败且已扣一次任务（2026-10-28 实证，比"静默降级"更坑） |
| **是否 prompt_only**：上游有没有对应生成工具 | 没有工具时不下发 `prefer_tool_categories`，只靠 prompt 硬约束 | 硬塞无效工具名 → 上游可能直接失败 |

工具名怎么拿到（按可靠性排序）：

1. Lovart 官方工具清单 / API 文档，或抓一次真实请求的 `tool_config`。
2. 发一次任务后看 result 的 `data.failures[]`——里面带 `tool` / `tool_hint` 原始工具名（读取口见 `lovart_task.ts` 的 `extractLovartFailureText`，日志会被打出来）。
3. 都没有时按命名惯例推断，**并在交付说明里写清「工具名未验证」**，别默认它对。

命名惯例（对齐上游，勿自创）：模型名转下划线、点号转下划线、不带质量后缀。

| 模型 | 工具名 |
|---|---|
| `seedance-2.0-fast` | `generate_video_seedance_v2_0_fast` |
| `kling-v3-omni` | `generate_video_kling_v3_omni` |
| `nano-bn-2.1` | `generate_image_nano_banana_2_1` |
| `gemini-omni-1.1-flash` | **未知 → 留空串走 prompt_only**（2026-10-28：曾填 `generate_video_gemini_omni_1_1_flash`，上游产物期报 `unknown tool_hint`；没有上游权威清单，任何写死都是猜） |

## 2. 改动清单（四处 + 一张表 + 一处测试）

以新增一个**普通视频模型** `xxx-v1`、工具名 `generate_video_xxx_v1` 为例。

### 2.1 `src/ai-relay/providers/lovart/lovart_config.ts`（三处，必改）

**① 别名表**——`LOVART_VIDEO_RULES`（图片模型则是 `LOVART_IMAGE_RULES`）：

```ts
  [['xxx-v1', 'xxx v1', 'xxxv1'], 'generate_video_xxx_v1'],
```

- 别名至少覆盖：带连字符（前端 id）、带空格（用户/Agent 自然语言）、无分隔符（历史写法）。
- 匹配逻辑是 `keys.some((k) => m.includes(k))`，输入先做 `lower()` + `_`→`-` 归一化。
- **顺序敏感**：短别名是长别名的子串时，长的必须排前面（见 §4）。

**② 可读名**——`LOVART_PROMPT_MODEL_NAMES`：

```ts
  'xxx-v1': 'XXX V1',
```

拼进 prompt 的是这个名字（`using the XXX V1 model`）。不登记则回退成 id 原串（如 `using the xxx-v1 model`），能跑但可读性差、Agent 解析更容易出错。

**③ 规格**——`LOVART_MODEL_SPECS`：

```ts
  'xxx-v1': { category: 'VIDEO', readableName: 'XXX V1' },
```

- 除 `lovart-chat` 外**不要填 `tool` 字段**：工具名统一由别名表解析，两处都写就是两个真相源。
- `readableName` 目前只用于断言与人工排查，prompt 走的是 ②。

### 2.2 `src/ai-relay/manifests/lovartModelManifest.ts`（必改）

追加一条 `CatalogModel`，`category` 用小写的 `image` / `video` / `text`：

```ts
  {
    id: 'xxx-v1',
    name: 'XXX V1',
    category: 'video',
    provider: 'lovart',
    description: 'Lovart XXX V1 文生视频',
  },
```

这份清单是 `providerCatalog` 里 lovart 连接的模型目录（`listModels` 的离线来源）。漏了它 → 目录里看不到该模型。

### 2.3 `src/routes/platform.ts`（必改）

```ts
  video: [..., 'xxx-v1'],
  discountVideo: [..., 'xxx-v1'],          // 特惠视频与普通视频共用同一套模型
  // 以及 BUILTIN_MODEL_SERIES
  { name: 'xxx-v1', seriesKey: 'xxx', seriesLabel: 'XXX 系列' },
```

`/public/platform/builtin` 与 `/public/platform/models` 是本地模式给前端的静态兜底清单。漏了它 → 前端下拉里没有这个模型。

`seriesKey` 决定前端按系列分组，同系列模型必须用同一个 key。

### 2.4 `providers.default.json`（必改）

lovart 连接的 `video_models` / `image_models` 里加一条：

```json
        {
          "id": "xxx-v1",
          "label": "XXX V1",
          "streaming": false,
          "promptOnly": false
        }
```

`promptOnly` 与 §1 的「是否有上游工具」一致：无工具填 `true`。

> ⚠ 本文件是**只读出厂种子**：仅当 `<数据目录>/providers/lovart.json` 不存在时才播种一次，播种后运行态真源就是那个文件（默认 `~/.maomao-localtool/providers/lovart.json`，可用 `MAOMAO_DATA_DIR` 覆盖）。已经在跑的机器改这里**不会生效**——要在前端设置里保存一次，或删掉该平台的运行态文件让它重新播种（删文件会丢用户对 lovart 连接的改动）。

### 2.5 `data/apiConfigs.baseline.json`（必改）

前端连接配置的初始基线（`/api/sync/default` 的本地兜底），两处：

- `models[]` 里加 `{ "id": "xxx-v1", "type": "video", "label": "XXX V1" }`；
- 视频模型再加进 `discountVideoModel` 的换行分隔字符串。

> 这份基线只在首次同步/重置时被读走；前端若已保存过自己的模型配置，改动不会自动覆盖，需要在设置页重置或重新同步。

### 2.6 `test/lovart_prompt.test.js`（必改）

A4 两条用例硬编码了分组计数，新增任何模型都要同步改，否则 `npm test` 红：

```js
  assert.equal(byCat.VIDEO, 6);   // 原 5 → 新增 1 条
```

manifest 与规格表的一致性由第二处计数 + 「每 id 都有规格」断言守住。

### 2.7 不用改的地方（避免重复改）

| 位置 | 为什么不用改 |
|---|---|
| `src/routes/openaiCompat.ts` 的 `/v1/models` | 直接从 `LOVART_MODEL_SPECS` 派生 |
| `index.ts` 的 `assertCategory` / 生成函数 | 按 ① ③ 的表自动生效 |
| `lovart_prompt.ts` / `lovart_client.ts` / `lovart_task.ts` | 模型差异全部收敛在 `lovart_config.ts` 的表里 |

## 3. 三种形态的写法对照

### 3.1 普通模型（无质量档位）

按 §2 全做一遍即可，参考 `seedance-2` / `kling-v3-omni`。

### 3.2 质量模型（同一工具、多档质量）

模型 id 带 `-low/-medium/-high` 后缀，工具名**不带**后缀，质量单独成句下发：

```ts
// 别名表：所有质量档位都指向同一个基础工具名
[['gpt-image-2.5-sunburst-low', ...], 'generate_image_gpt_image_2_5_sunburst'],

// 质量派生表：base + quality
'gpt-image-2.5-sunburst-low': { base: 'GPT Image 2.5 Sunburst', quality: 'low' },
```

命中 `LOVART_QUALITY_MODELS` 后，prompt 会多出中文句「用 X，质量 low」与英文句 `, quality low`，**不要**再往 `LOVART_PROMPT_MODEL_NAMES` 里重复登记（会产生第二真相源）。§2 里 ② 的可读名登记可跳过。

### 3.3 prompt_only 模型（上游暂无对应工具）

别名表里工具名写空串 `''`：

```ts
[['minimax-h3', 'minimax h3', 'hailuo h3'], ''],
```

`buildLovartToolConfig` 命中空串即返回 `undefined`（不下发 `prefer_tool_categories`，避免上游收到无效工具名），prompt 路仍然生效。`providers.default.json` 里 `promptOnly` 填 `true`。

## 4. 顺序陷阱：前缀子串会被误吞

匹配是**不使用边界的子串包含**，`any(k in m)`，命中第一条就返回。因此：

- `gpt-image-2` 会吞掉 `gpt-image-2-low`、`gpt-image-2.5-sunburst` → 长别名必须排在 `gpt-image-2` 之前。
- `seedance-2` 会吞掉 `seedance-2.0-mini` → mini 必须排在`seedance-2` 之前。
- `gemini-omni-1.1-flash` 会吞掉将来的 `gemini-omni-1.1-flash-ext` → 上游若上线 ext，**ext 规则要插在 flash 之前**。

新加规则时自查一遍：把新别名和表里每一条比一次，谁是谁的前缀。

## 5. 验证（缺一不可）

### 5.1 静态 + 单测

```powershell
cd G:\01画布项目\maomao\localTool
npx tsc --noEmit
node --test --import tsx test/lovart_prompt.test.js test/lovart_index.test.js
```

重点看两件事：

- `buildLovartToolConfig('<新id>').prefer_tool_categories.<CATEGORY>` 是否等于你写的工具名（§4 的误吞在这个断言上最直观）；
- A4 计数是否已同步（没改就红，不要靠改断言「放过」）。

建议顺手在 `test/lovart_prompt.test.js` 的别名回归用例里补一条新模型的断言，防止将来加前缀规则时回归。

### 5.2 真机（必须做，单测不能替代）

1. 重启 localTool（`npm run dev`）。如果这台机器之前已经跑过，确认 `<数据目录>/providers/lovart.json` 的 `video_models` 里已有新模型（没有就在设置页保存一次让它落盘，见 §2.4 的说明）。
2. 前端下拉能看到新模型、系列分组正确。
3. 触发一次真实生成，面板日志确认：
   - `[lovart] chat 已提交，threadId=...`；
   - **没有** `[lovart] 未知模型「...」` 告警（有 = 别名表或规格表没命中）；
   - 产物 URL 正常返回。
4. 若上游报错，先看 `data.failures[].message` 原文，判断是工具名无效、参数不支持还是内容审核。

## 6. 常见错误对照表

| 现象 | 原因 | 修法 |
|---|---|---|
| 日志打「未知模型」，上游按默认模型出图 | `SPECS` 或别名表没命中 | 补 §2.1 ①②③ |
| 前端下拉里没有新模型 | `platform.ts` / `apiConfigs.baseline.json` 漏改 | 补 §2.3 §2.5 |
| `listModels` 目录里没有 | manifest 漏改 | 补 §2.2 |
| 调用直接抛「模型 X 不是视频模型」 | `SPECS` 的 `category` 写错，或前端选了别类的模型 | 改 §2.1 ③ |
| 上游一直用别的模型出图，无报错 | 工具名错（不存在的工具名被静默忽略） | 用真实工具名替换 §2.1 ① |
| 质量总是默认档 | 把质量后缀烤进了工具名，或没进 `LOVART_QUALITY_MODELS` | 工具名去后缀 + 补质量派生表 |
| `npm test` 报 A4 计数不符 | 忘了同步测试计数 | 改 §2.6 |
