## 2. 方案总览：曲线与关键帧分工并存（不学 nomi 另建引擎）

用户确认的分工模型（最简、最贴合我们现有系统）：

- **上面的 3D 曲线** = 管**位置 / 方向 / 距离**（摄像机在哪儿走、往哪拐、走多远）。
- **下面的 Timeline 关键帧** = 管**快慢**（哪段运动快、哪段慢）。
- **曲线只在"编辑曲线"工具激活时显示**；切到其他工具（选择/移动/旋转…）曲线自动隐藏，不干扰正常编辑与预览。
- 画完曲线 → **bake 成一串摄像机关键帧**（铺满 0→总时长帧）；曲线源 `cameraPath` 保留不消失，可随时进"编辑曲线"工具改形状。

两条路线对比：

| 候选 | 做法 | 评估 |
|------|------|------|
| A. 曲线实时绑定（nomi 式） | 新增 trajectory 引擎 + 运行时 store + 注册表，播放时实时 `getPointAt` 采样 | ❌ 重、双真相源、与现有 `keyframes`/撤销栈/导出冲突，**不采用** |
| **B. 画曲线 → bake 成关键帧（选定）** | 曲线是"形状源"，bake 出的关键帧是"时间节奏"，两者并存分工 | ✅ 完全复用现有 `keyframes`/`cameraAtFrame`/Timeline 拖拽，零新概念 |

### 2.1 为什么选 B、淘汰 A
- 我们的真相源本就是 `keyframes[]`，播放/导出/预览/Timeline 全消费它。bake 成关键帧 = 直接落在现有管线上，**零适配**。
- 用户"拖关键帧改快慢"是 Timeline 已有能力，bake 后天然可用，不用新做"速度"控件。
- 曲线作为独立 `cameraPath` 存着不消失，负责"位置/方向"，与关键帧"快慢"互不打架。
- 不引入 nomi 的运行时注册表/绑定态，撤销栈、导出、克隆 shot 全部自动兼容。

## 3. 最终架构：曲线源（cameraPath）+ bake 成关键帧

### 3.1 数据模型

```js
// project.js —— 相机运动路径（"形状源"，不消失、可隐藏、可重编辑）
CameraPath = {
  id: string,
  points: { id: string, position: [x,y,z] }[],  // 任意数量控制点（≥2），CatmullRom 过所有点
  closed: boolean,
  tension: number,                              // CatmullRom 张力，默认 0.5
}
```

- `cameraPath` 进 `shot` 一等字段（与 `keyframes` 并列）。它是**位置/方向的真相源**，只在"编辑曲线"工具下渲染显示。
- **bake 出的关键帧就是普通的 `keyframes[]`**（现有模型，零改动），是**时间节奏的真相源**，由 Timeline 负责快慢。
- 两者并存：改曲线 → 重新 bake（覆盖由该曲线生成的那批关键帧）；改快慢 → 直接拖 Timeline 关键帧。

### 3.2 曲线 → 关键帧的 bake（核心纯函数）

```js
import * as THREE from 'three'

export function buildCameraPathCurve(path) {
  const pts = path.points.map(p => new THREE.Vector3(...p.position))
  if (pts.length < 2) return null
  const curve = new THREE.CatmullRomCurve3(pts, path.closed, 'catmullrom', path.tension)
  curve.updateArcLengths()   // 只在控制点变化时重算，非每帧
  return curve
}

// 把曲线沿弧长均匀 bake 成一串关键帧，铺满 [0, totalFrames]
// 每个关键帧的 frame 从 0 到 totalFrames；position 来自曲线弧长采样；
// rotation 用切线 lookAt 算（防欧拉甩头）；focalLength 取当前相机焦距。
export function bakePathToKeyframes(path, totalFrames, focalLength) {
  const curve = buildCameraPathCurve(path)
  if (!curve) return []
  const N = Math.max(2, Math.round(totalFrames / 12))  // 约每 12 帧一个关键帧
  const keys = []
  for (let i = 0; i <= N; i++) {
    const u = i / N
    const pos = curve.getPointAt(u)
    const tan = curve.getTangentAt(u).normalize()
    // 用切线算朝向（lookAt pos+tan），转成 rotation 存关键帧，避免欧拉甩头
    const m = new THREE.Matrix4().lookAt(pos, pos.clone().add(tan), new THREE.Vector3(0,1,0))
    const e = new THREE.Euler().setFromRotationMatrix(m)
    const frame = Math.round(u * totalFrames)
    keys.push({
      frame,
      position: [pos.x, pos.y, pos.z],
      rotation: [e.x, e.y, e.z],
      focalLength,
      interpolation: 'smooth',
    })
  }
  return keys
}
```

- **起止帧**：默认 `0 → totalFrames`（= `durationSeconds × fps`，默认 0→15 秒即 0→360 帧）。即"起始帧是 0，终点帧是总时长"。
- **快慢由关键帧的 frame 间距决定**：bake 时均匀铺，所以默认匀速；用户拖 Timeline 关键帧 → 某段关键帧间距变小则变快、变大则变慢。**无需额外速度控件**。
- `totalFrames` 来自 `settings.durationSeconds × fps`（project.js:223-228），改 shot 时长，bake 范围随之变化。

### 3.3 曲线只在"编辑曲线"工具下显示

- 新增 `editMode === 'path'`（与现有 `transformMode` 移动/旋转/缩放同级）。
- `Viewport` 仅在 `editMode === 'path'` 时渲染 `<PathEditor>`（曲线 + 控制点 + 命中管）；其他工具下 `PathEditor` 不挂载 → 曲线隐藏，视口干净。
- 预览/播放时永远隐藏曲线（只看相机运动结果）。

### 3.4 字段传播

`cameraPath` 进 `shot` 一等字段，同步：
- `project.js`：`PROJECT_VERSION`（当前 16）加字段则 +1；`normalizeShot` 加 `cameraPath` 默认值（旧工程无此字段 → `null`）；`projectData` 透传；`cloneProjectValue` 自然覆盖 `addShot`/`duplicateShot`/`applyShotState`。
- `App.jsx`：`cameraPath` state + 与 `activeShot` 同步的 set/clear；"编辑曲线"工具切换 `editMode`。

## 5. 落地任务拆分（按"曲线源 + bake 成关键帧"方案）

1. `project.js`：`CameraPath` 模型 + `normalizeShot`/`projectData` 加 `cameraPath` 字段；`buildCameraPathCurve`/`bakePathToKeyframes` 纯函数（§3.2）。
2. `App.jsx`：`cameraPath` state + 与 `activeShot` 同步；新增 `editMode==='path'`；工具栏"编辑曲线"按钮 → 进 path 模式；"画完松手"时调用 `bakePathToKeyframes` 写入 `keyframes`（默认铺满 0→totalFrames）；`PathEditor` 仅在 path 模式挂载。
3. `Viewport.jsx`：`PathEditor`（拖出曲线 / 拖点 / 双击补点 / 右键删点 / 实时预览）；曲线只在 `editMode==='path'` 显示。
4. `Timeline.jsx`：bake 出的关键帧就是现有摄像机轨道关键帧，拖拽改快慢**零改动即可用**；无需新增 path 段轨道带。
5. `Inspector`：相机选中时"镜头"区块内可设 `focalLength`（已有）；朝向用曲线切线自动算（无需用户手设）。**不新增独立侧栏/面板**。
6. P2：闭合轨迹、targetId 注视、曲率把手、语义运镜 builder、确定性抖动。

## 6. 剩余风险（明确标注）

- **R1 重 bake 覆盖手调快慢**：用户拖过 Timeline 关键帧改快慢后，若再进"编辑曲线"改形状并重 bake，会**覆盖掉手调的快慢**。→ 缓解：重 bake 时**保留现有关键帧的 frame 分布比例**（按弧长重采样到现有 frame 位置，而不是重新均匀铺），或提示"重 bake 将重置快慢"。首版可简单提示。
- **R2 欧拉甩头**：bake 用 `lookAt` 算 `rotation`（欧拉），长曲线若越过万向锁仍可能甩头。→ 缓解：关键帧内 `cameraAtFrame` 现有 `lerpAngle` 已逐分量插旋转；极端环绕可后续升级 quaternion slerp（P2）。
- **R3 版本迁移**：`PROJECT_VERSION` 加 `cameraPath` 字段需 +1，`normalizeShot` 对旧工程给 `cameraPath:null`。
- **R4 闭合轨迹**：`closed:true` 时末帧==首帧，`loopPlayback` 需确认末帧≠首帧避免定格（P2）。

### 8.3 Timeline 关键帧（bake 出来的就是普通关键帧）

bake 出的关键帧直接进现有摄像机轨道，**沿用现有菱形方块（金 `#e0b55e`）渲染，零新增 UI**：
- 用户**拖关键帧改快慢**：把某几个关键帧往后拖 → 那段运镜变慢；往前拖 → 变快。完全复用现有拖关键帧能力（App.jsx `selectedKeyframe`）。
- 上下轨道分工清晰：**3D 曲线管位置/方向，Timeline 关键帧管快慢**，互不干扰。
- 不需要 nomi 那种独立的 path 段轨道带——曲线形状在 3D 视口里看，节奏在 Timeline 里调。

### 8.4 交互（极简：拖出一条曲线，所见即所得）

设计原则（用户原话）：用户只要①画条能编辑的线、②摄像机沿它运动。**不要侧栏、不要"生成"按钮、不要"先建 2 点再插点"的分步繁琐。** 分工：上面 3D 曲线管位置/方向/距离，下面 Timeline 关键帧管快慢；**曲线只在"编辑曲线"工具激活时显示**。

**入口交互（参考上传背景图按钮的做法）**：工具栏"编辑曲线"按钮**不是一点就进模式**，而是**点一下弹出一个小下拉菜单**（类似 `AssetMenu` 的 `asset-menu-panel` 弹出面板，点击外部关闭），菜单里让用户先设参数（时间范围、采样密度），确认后再进 path 模式拖曲线。比直接进模式更友好——用户先定"画多长、多密"。

| 操作 | 效果 | 视觉反馈 |
|------|------|---------|
| **点工具栏"编辑曲线"** | 弹出小下拉设置菜单（见 §8.6） | 菜单浮在按钮下方，含时间范围 + 采样密度；点外部关闭 |
| **菜单内确认"开始绘制"** | 进入 `editMode='path'`，曲线显示、OrbitControls 让位 | 顶部 `.viewport-mode-help` 提示"按住拖动画一条运镜路径" |
| **按住地面拖动** | 实时画曲线；松手时按弧长**自动采样成一串控制点**（相邻 <0.3 去重，约 12~24 点），并**立即 bake 成一串关键帧**（铺满 0→总时长帧） | 拖动中曲线以 **X 轴色 `#d7675b`** 实时显现；控制点小球依次出现 |
| **拖曲线上任意点** | 改形状（位置/方向/距离）；可离地（y≠0）做升降 | `invalidate()` 实时预览，hover **Z 轴色** 蓝晕；选中 **Y 轴色** 绿 |
| **在线段上双击**（可选） | 补一个控制点，让某段更细致 | 非必须；插点处小球闪 **Y 轴色** |
| **右键控制点** | 删该点（保底 2 点，曲线不塌） | 确认用 `--danger` 红 |
| **到 Timeline 拖关键帧** | 改快慢：关键帧间距小→快、大→慢 | 完全复用现有拖关键帧能力 |
| **切到其他工具（选择/移动…）** | 曲线**隐藏**，视口只显示相机与场景 | 回正常编辑/预览视角，不被曲线干扰 |
| **Esc / 点"选择"** | 退出编辑曲线模式 | — |

> 为什么"拖出曲线"比 nomi 分步加点更好：nomi 需双击地面逐个放点、再插点，把实现细节暴露给用户。我们一次拖拽即得"有点的曲线"，**松手即 bake 成关键帧**——用户立刻能在 Timeline 看到一串关键帧拖快慢。曲线源保留不消失，随时回"编辑曲线"工具改形状。控制点数量由拖拽长度自动决定，不受限。

### 8.5 工具栏按钮（唯一入口，无侧栏）

在 `App.jsx:1137 viewport-toolbar` 加一个按钮（图标 `Spline`/`Route`，快捷键 `T`），与"移动W/旋转R/缩放E"同级，**点击弹出小下拉设置菜单（§8.6），确认后进入编辑曲线模式**。参考"上传背景图"按钮（`App.jsx:1147`）的触发式交互与 `AssetMenu.jsx` 的 `asset-menu-panel` 弹出 + 外部点击关闭做法，复用同一套 popover 样式，**不新增独立面板/侧栏**。曲线仅在 `editMode==='path'` 显示，切其他工具即隐藏。

### 8.6 设置下拉菜单（时间范围 + 采样参数）

点击"编辑曲线"按钮弹出的小面板，参考 `asset-menu-panel` 风格（深色浮层、贴按钮下方、点外部关闭）。两项用户可直接设：

| 设置项 | 控件 | 作用 | 默认 |
|--------|------|------|------|
| **时间范围** | 「从 __ 秒 到 __ 秒」两个数字输入 | 决定 bake 关键帧的 frame 区间（起秒×fps → 止秒×fps）。即你确认的"起始帧=0、终点帧=总时长"的可调版 | 从 `0` 到 `durationSeconds`（默认 15s） |
| **采样密度** | 三档：少/中/多 | 决定曲线自动采样控制点数量 + bake 关键帧数 `N`（少≈每24帧、中≈每12帧、多≈每6帧一个） | 中 |

底部「开始绘制」按钮 → 写入 `cameraPath.startFrame/endFrame/sampleDensity` → 进入 `editMode='path'`。放在弹菜单而非 Inspector，因进入画线流程时顺手设参数最自然（如上传背景图），且只这两项不堆选项。

## 9. 性能审计（bake + 纯函数曲线）

### 9.1 播放/导出（每帧复用现有管线，零新增成本）
- bake 后关键帧就是普通 `keyframes[]`，播放/导出走现有 `cameraAtFrame` + `PreviewCameraController`，**无任何曲线实时采样开销**。
- 比"实时采样"路线更省：连 `getPointAt` 都不在播放期调用，纯吃现有插值。

### 9.2 编辑态画线（成本关口，但可控）
- 视口 `frameloop="demand"`，静止零渲染。画线/拖点用 `invalidate()` 驱动（与骨骼拖拽 `models.jsx:352/370` 同套路）。
- 控制点数量**不受限**；曲线可见几何 `<Line>`/`getSpacedPoints(64)` 固定 64 段，顶点数不随控制点增长；`CatmullRomCurve3` 构建成本线性、微秒级。
- `bakePathToKeyframes` 只在松手/重 bake 时跑一次，生成 ~12~30 个关键帧，成本可忽略。
- 曲线**仅在 `editMode==='path'` 渲染**，其他工具不挂载 `<PathEditor>`，零常驻开销。
- **裁决：编辑态成本 ≈ 现有手拖相机，无性能陷阱。** 大场景可临时 `performanceMode` 降级。

> **别学 nomi 另建 trajectory 引擎**。我们用最贴合现有系统的方案：**画曲线（"编辑曲线"工具，仅在此时显示）→ 松手即 bake 成一串普通关键帧**（铺满 0→总时长帧）。分工清晰——**上面 3D 曲线管位置/方向/距离，下面 Timeline 关键帧管快慢**（拖关键帧即改快慢，复用现有能力）；曲线源保留不消失，随时回工具改形状。完全复用现有 `keyframes`/`cameraAtFrame`/Timeline/导出/撤销，零新概念。画线 UI 照搬 nomi 交互结构、配色用属性栏 XYZ 轴色（`#d7675b`/`#76a96c`/`#5d87c7`）适配深色背景。
