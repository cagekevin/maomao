## 一、现状盘点：存储键的真实分布

`src/**` 里存储键的使用有 **3 种风格并存**，但**已经存在两份「准集中登记」**（`LS_KEYS`），并非完全无管理。

### 风格 A：直接硬编码字符串（绕过任何常量，最危险）
| 文件:行 | 键 | 介质 |
|--------|-----|------|
| `src/App.jsx:1019` | `'shortcuts-config'` | localStorage/插件 |
| `src/components/AgentPanel.jsx:188,191` | `'agent_input_mode'` | 同上 |
| `src/components/VideoExtractNode.jsx:305,315` | `'mutiwindow-clipboard'` | 同上 |
| `src/components/base/conversationStore.js:123,132` | `'agent_conversations'` / `'agent_active_conversation_id'` | 同上（**遗留旧固定键**，见 §三.4） |

### 风格 B：各模块自管常量（值多为裸键，由 storageAdapter 自动加 `yimao:` 前缀）
| 常量 | 值 | 文件 |
|------|-----|------|
| `GEN_PARAMS_KEY` | `'canvasAgentGenParams'` | `useCanvasAgentTools.js:29` |

| `STORAGE_KEY` | `'shortcuts-config'` | `ShortcutSettings.jsx:12` |
| `AGENT_CHAT_MODEL_KEY` | `'agent_chat_model'` | `agentModelStore.js:12` |
| `STORAGE_KEY` | `'yimao_accounts'` | `accountsStore.js:15` |
| `STORAGE_KEY` / `RECENT_KEY` | `'yimao_preset_prompts'` / `'yimao_preset_recent'` | `promptManager.js:16,17` |
| `STORAGE_KEY` | `'yimao_node_prefs'` | `nodePrefs.js:37` |
| `PROJECTS_KEY` / `LAST_OPENED_KEY` | `'projects'` / `'lastOpenedProject'` | `projectStore.js:15,16` |

> ⚠️ 同一个名字 `STORAGE_KEY` 在 5 个文件里被复用（值不同）：`shortcuts-config` / `yimao_accounts` / `yimao_preset_prompts` / `yimao_node_prefs` / `yimao_asset_library`。纯靠模块作用域隔离，**极易复制粘贴串键**。

### 风格 C：统一抽象层（方向正确，但只覆盖画布场景）
- `kvStore.js:22` → `CANVAS_STATE_PREFIX = 'canvas-state-v1-'`（`isKvKey` 用 `startsWith` 判断分流到 localTool KV，见 `kvStore.js:51`）
- `storageAdapter.js:68` → `KEY_PREFIX = 'yimao:'`（`sGet/sSet/sRemove` 自动加前缀，见 `storageAdapter.js:91,101,123`）

### 已有的「准集中登记」：两份 `LS_KEYS`（重要，收口要复用）
- `cloudSync.js:231` 的 `LS_KEYS`：`projects / app_settings / agent_skills / agent_skill_usage / agent_chat_model / yimao_preset_prompts / yimao_preset_recent / yimao_node_prefs / yimao_accounts`（共 9 项，带「含隐私不同步」注释）。
- `backupStore.js:29` 的 `LS_KEYS`：`projects / lastOpenedProject / app_settings / agent_skills / agent_skill_usage / agent_chat_model / yimao_preset_prompts / yimao_preset_recent / yimao_asset_library / yimao_node_prefs / yimao_accounts`（共 11 项）。
- 两者**未覆盖**的 localStorage 键（即「真正未收口」）：`shortcuts-config`、`agent_input_mode`、`mutiwindow-clipboard`、`GEN_PARAMS_KEY(canvasAgentGenParams)`、director 三键、conversation 动态键。
- ⚠️ **两份 `LS_KEYS` 本身也是脏数据来源**：其值写的是 `yimao_accounts` 等带 `yimao_` 前缀的字面量，而 `storageAdapter.sGet` 会自动加 `yimao:` 前缀 → 实际落盘/读取键变成 `yimao:yimao_accounts`。收口时这两份清单的值**也必须从带 `yimao_` 改为裸键**（见 §五.3）。

### 已暴露的脏数据问题
`storageAdapter` 给所有非 KV key 自动加 `yimao:` 前缀，但 `promptManager` / `nodePrefs` / `accountsStore` / `assetStore` 自己在值里写了 `yimao_`，导致实际落盘键变成 **`yimao:yimao_accounts`**、`yimao:yimao_preset_prompts` 等——**双重前缀**。详见 `05` §4 的 KV 脏数据排查。

## 二、问题归纳（为什么要收口）

1. **双登记风险**：`LS_KEYS` 已存在两份且**不完全一致**（cloudSync 缺 `lastOpenedProject`/`yimao_asset_library`，backupStore 缺 `agent_conversations` 动态键），新增键容易只填一处或两处都漏。
2. **风格 A 硬编码字符串**：`shortcuts-config` 等裸写在调用处，无常量、无类型、无登记。
3. **同名局部常量 `STORAGE_KEY`**：5 处复用、值各不同，复制粘贴必串键。
4. **双重前缀脏数据**：业务模块自写 `yimao_` + 适配层再加 `yimao:`。
5. **动态键无集中工厂**：`conversationStore` 的 `convKey`/`activeKey`、`director` 的 `getDirectorSceneStorageKey` 各自实现拼接，未统一到登记文件。
6. **KV 字典键不在 `LS_KEYS`**：`canvas-state-v1-*` 由 `kvStore` 单独管理，登记清单未体现，导致 `backupStore`/`cloudSync` 只能特判遍历。

---

## 三、收口方案：中央登记表 `storageKeys.js`（合并 LS_KEYS）

**原则**：
- 底层存储实现（`storageAdapter` / `kvStore` 的分流逻辑）**不动**。
- 现有 `cloudSync.js` / `backupStore.js` 的 `LS_KEYS` **改为 import `storageKeys` 的 LIST**，消除双登记。
- 所有裸键、动态键工厂集中到一处；新键必须先登记。

### 3.1 文件结构（与真实代码对齐）

新建 `src/components/base/storageKeys.js`：

```js
// 介质域：LOCAL = 浏览器/插件本地（storageAdapter 自动加 yimao: 前缀）；KV = localTool KV（跨端）
export const StorageDomain = { LOCAL: 'local', KV: 'kv' }

// 所有键集中登记，VALUE 为「裸键」（不带 yimao: 前缀；KV 项已是完整前缀）
export const StorageKeys = {
  // —— 项目 / 画布（KV 跨端）——
  CANVAS_STATE:        'canvas-state-v1-',          // 拼 projectId
  CANVAS_STATE_VERSION:'canvas-state-v1-',          // 拼 projectId + '_version'
  ACTIVE_API_ENDPOINT: 'active_api_endpoint',       // KV 跨端读当前主供应商

  // —— 项目元数据（双写：localStorage 兜底 + /api/projects 权威源）——
  PROJECTS:          'projects',
  LAST_OPENED_PROJECT:'lastOpenedProject',

  // —— 账号 / 设置 / 本地偏好（LOCAL，裸键）——
  ACCOUNTS:          'accounts',                     // 原 yimao_accounts，去掉重复前缀
  PRESET_PROMPTS:    'preset_prompts',
  PRESET_RECENT:     'preset_recent',
  NODE_PREFS:        'node_prefs',
  ASSET_LIBRARY:     'asset_library',                // 原 yimao_asset_library
  SHORTCUTS:         'shortcuts-config',
  APP_SETTINGS:      'app_settings',
  AGENT_INPUT_MODE:  'agent_input_mode',
  MULTIWINDOW_CLIPBOARD:'mutiwindow-clipboard',
  AGENT_GEN_PARAMS:  'canvasAgentGenParams',

  // —— Agent（LOCAL）——
  AGENT_SKILLS:      'agent_skills',
  AGENT_SKILL_USAGE: 'agent_skill_usage',
  AGENT_CHAT_MODEL:  'agent_chat_model',

  // —— Agent 会话（LOCAL，动态拼 agentKey）——
  AGENT_CONVERSATIONS_PREFIX:'agent_conversations_',          // + agentKey
  AGENT_ACTIVE_CONV_PREFIX:  'agent_active_conversation_id_', // + agentKey
  LEGACY_AGENT_CONVERSATIONS:'agent_conversations',           // 遗留旧固定键（迁移用，见 conversationStore）
  LEGACY_AGENT_ACTIVE_CONV:  'agent_active_conversation_id',  // 遗留旧固定键

  // —— 3D director（LOCAL）——
  DIRECTOR_LIBRARY:  'storyai-3d-director-local-model-library',
  DIRECTOR_SCENE:    'storyai-3d-director-desk-demo',          // 无 scope 时
  DIRECTOR_SCENE_PREFIX:'storyai-3d-director-desk-demo:',      // + scopeId
}

// —— 动态键工厂（禁止调用处手拼模板串）——
export const canvasStateKey   = (id) => `${StorageKeys.CANVAS_STATE}${id}`
export const canvasVersionKey = (id) => `${StorageKeys.CANVAS_STATE}${id}_version`
export const conversationKey  = (agentKey) => `${StorageKeys.AGENT_CONVERSATIONS_PREFIX}${agentKey}`
export const activeConvKey    = (agentKey) => `${StorageKeys.AGENT_ACTIVE_CONV_PREFIX}${agentKey}`
export const directorSceneKey = (scopeId) =>
  scopeId ? `${StorageKeys.DIRECTOR_SCENE_PREFIX}${scopeId}` : StorageKeys.DIRECTOR_SCENE
export const withSuffix = (key, suffix) => `${key}${suffix}`

// —— 供 cloudSync / backupStore 复用的权威清单（替代原 LS_KEYS）——
// 仅含「纯 localStorage 配置/用户数据键」（不含 KV 画布、不含动态会话键）
export const LS_KEYS = [
  StorageKeys.PROJECTS, StorageKeys.LAST_OPENED_PROJECT, StorageKeys.APP_SETTINGS,
  StorageKeys.AGENT_SKILLS, StorageKeys.AGENT_SKILL_USAGE, StorageKeys.AGENT_CHAT_MODEL,
  StorageKeys.PRESET_PROMPTS, StorageKeys.PRESET_RECENT,
  StorageKeys.ASSET_LIBRARY, StorageKeys.NODE_PREFS, StorageKeys.ACCOUNTS,
]
// cloudSync 额外排除（隐私/本机偏好）：LAST_OPENED_PROJECT、ASSET_LIBRARY
export const CLOUD_SYNC_EXCLUDE = [StorageKeys.LAST_OPENED_PROJECT, StorageKeys.ASSET_LIBRARY]
```

### 3.2 使用约定（强制规则）
1. **禁止**业务代码直接写存储字符串字面量（`sGet('xxx')` / `storageSet('xxx')`）。必须 `import { StorageKeys } from '.../storageKeys'`。
2. **禁止**新键自写 `yimao_` 前缀——`storageAdapter` 已统一加；登记只写裸键。脏数据键（历史 `yimao_xxx`）迁移后删除。
3. **新键必须先登记**：在 `StorageKeys` 加一项 + 注明 `StorageDomain`，再使用；同时确认是否进 `LS_KEYS`。
4. **动态键**统一走 `canvasStateKey` / `conversationKey` / `directorSceneKey` / `withSuffix`，调用处不得手拼。
5. **删除同名局部常量** `STORAGE_KEY` / `GEN_PARAMS_KEY` 等，改用 `StorageKeys.XXX`。
6. **`cloudSync.js` / `backupStore.js` 的 `LS_KEYS` 改为从 `storageKeys` import**（见 §3.1 `LS_KEYS` / `CLOUD_SYNC_EXCLUDE`），消除双登记。

### 3.3 与底层分流的衔接（不变）
```
StorageKeys.XXX
  ├─ 域 = KV    → kvStore.kvGet/kvSet/kvDelete   （CANVAS_STATE 前缀自动命中 kvStore 分流）
  └─ 域 = LOCAL → kvStore.storageGet/Set/Delete  （storageAdapter 自动加 yimao: 前缀）
```
> `kvStore` 的 `CANVAS_STATE_PREFIX` 建议改为 `import { StorageKeys } from './storageKeys.js'` 复用，避免前缀改一处漏一处。

## 四、介质域决策表（新增键时对照）

| 数据特征 | 走哪 | 例 |
|---------|------|-----|
| 跨端共享、按 key 存取、需刷新恢复 | **KV**（`StorageDomain.KV`） | 画布快照、active_api_endpoint |
| 结构化、需查询/排序的业务数据 | **后端业务表**（`/api/projects`、`/api/tasks`） | 项目列表、任务 |
| 纯本机单端、无需跨端 | **LOCAL**（localStorage/插件） | 账号、设置、Agent 会话、快捷键、director |
| 体积大 / base64 图片（嵌画布快照内） | 经 KV 自动外置到 `/files/` | 画布快照内嵌图 |

> 判断原则（源自 `05`）：能 LOCAL 就不上 KV，避免 KV 表膨胀 + 跨端串扰。

## 五、落地步骤（建议顺序）

1. **建表**：新建 `src/components/base/storageKeys.js`（§3.1），含 `LS_KEYS` / `CLOUD_SYNC_EXCLUDE`。
2. **改底层复用**：`kvStore.CANVAS_STATE_PREFIX` 改 import `StorageKeys.CANVAS_STATE`；`storageAdapter.KEY_PREFIX` 维持。
3. **消除双登记**：`cloudSync.js` / `backupStore.js` 的 `LS_KEYS` 改为 `import { LS_KEYS, CLOUD_SYNC_EXCLUDE }`，删除本地数组；**同时把原清单里带 `yimao_` 前缀的值改为裸键**（原 `yimao_accounts` → `accounts` 等），消除双重前缀脏数据（见 §一「准集中登记」警告）。
4. **逐模块迁移**（风险从低到高）：
   - LOCAL 小模块：`ShortcutSettings`、`accountsStore`、`promptManager`、`nodePrefs`、`assetStore`、`agentModelStore`、`skillStore`、`appSettings`、`useCanvasAgentTools`、`AgentPanel`、`VideoExtractNode`。
   - 动态键：`conversationStore`（`convKey/activeKey` → `conversationKey/activeConvKey`）、`directorStore.ts`（`getDirectorSceneStorageKey` → `directorSceneKey`）、`projectStore`（`PROJECTS/LAST_OPENED/canvasStateKey`）、`App.jsx`（`SHORTCUTS`/`canvas-assistant-` 参数）。
5. **修脏数据**：`yimao:yimao_*` 双重前缀键，迁移后做一次别名搬迁（读旧键→写新键→删旧键）。
6. **加 lint 护栏**（可选）：`CODING-STANDARD.md` 写明「存储键必须经 `StorageKeys`」；eslint 拦截 `sGet(`/`storageSet(` 后接字符串字面量。
