## 一、一句话结论

**不是个别越界，是系统性的「后端只承担了存储，业务流程基本都在前端」。**

- 34 个登记的 `STORAGE_KEYS` 里，只有 **8 个（23.5%）** 真源在后端，26 个真源在浏览器本地。
- 后端 5 张表（`kv` / `tasks` / `resources` / `projects` / `project_meta`）里**没有** preset / skill / prefs / settings / prompthub / asset-library 任何一张。
- 生图链路的「提交 → 轮询 → 落盘 → 超时 → 重试 → 并发限流」**整套在前端**，且 `system.ts:267-269` 显示后端是**主动放弃**异步转同步。
- **画布内容守住了后端唯一真源**（`canvas-state-v1-*` 走 KV）；**项目元数据没有**。

|---|---|---|

| `size` | **无此列** | 前端虚构 |
| — | `source`/`is_favorite`/`page_url`/`page_title` | 前端无 |

**消费者分裂**：`AssetLibrary.jsx:4,139` / `GeneratedView.jsx:4,137` / `ScriptBoxAssetPicker.jsx:3,37` 读后端 `/api/resources`；`LeftPanel.jsx:31` 订阅 `useAssets`（读 localStorage）但**赋值后全文未使用**（死订阅）。

**确定性的不同步场景**：

- `assetStore.js:293,298` 删素材 → 只清 localStorage，不调 `/api/resources/delete` → 前端没了、后端还在
- `resources.ts:292` 面板删除 → 只删 DB 行 + GC，不清 localStorage → 后端没了、前端条目变坏链
- `resources.ts:349` 改名 → 改写 kv/tasks 引用，但**不改写 localStorage** → 前端旧 URL 404
- `assetStore.js:216-231` blob 分支 → 落盘成功但 store 存 `blob:`，刷新即失效
- `assetStore.js:35-42` seed 6 条演示素材（picsum/w3schools）→ 后端表内永远没有

### 补充：KV 降级影子副本

`kvStore.js:103` KV 写失败时 `sSet(key, ...)` 落 localStorage。虽 `:97` 成功后清理，但失败期间后端 `kv` 表与 localStorage 会同时存在同一 key 的两份值。**8 个 KV 键全部受影响**。

## 五、D 类：已违反既有红线（任务中心权威源）

> 红线原文（`useNodeGeneration.js:40-48`，**L48**）：`4. 方向单向：写只走本契约，刷新后任务中心 → 节点回填，节点不回写任务中心。`

**守住的**：节点侧（`src/components/nodes/**`）零反向回写——grep `patchTask|saveTask|reportGenerate|setTaskPollId` 在节点目录**无任何命中**；写入方只有 `taskStore.js` / `pollTask.js` / `proxyGenerate.js` / `scriptBoxEngine.js` / `useNodeGeneration.js`。

**违反处**：

### D1 僵尸任务（严重）：`taskStore.js:183-184`

```js
const old = tasks.find((t) => t.nodeId === nodeId && (t.status === 'running' || t.status === 'pending'))
tasks = tasks.filter((t) => t !== old)   // ← 只改内存，无 deleteTask(old.id)
```

- 对比 `removeTask` `:265-269` **有** `deleteTask(id)`（`:268`）——删除通路存在，此处**故意没调**。
- 后果：后端留 `status='running'` 的僵尸行 → 刷新后 `initTasks()` `:35-41` 从后端全量拉回 → 僵尸「生成中」任务**永久复活**（`pollTask.js:95-97` 每轮还把它当候选）。

### D2 平行双写：`taskStore.js:110-134`

`resource:renamed` 事件里前端自改内存 `resultUrl`，**只 `notify()` 不 `persist()`**（`:130-133`）。而后端 `resources.ts:427` → `database.ts:295-320` **已经**改写过 tasks 表（注释 `:289` 明确覆盖范围 `kv.value + tasks 各 url 承载列`）。分叉后任何 `patchTask`（`:240-252`）会把整个 task 对象 upsert 回后端 → **分叉固化为持久态**。

### D3 绕过唯一写入口：`scriptBoxEngine.js:346-351`

```js
// 任务中心上报（对齐 Prompt 节点 useNodeGeneration 契约）   ← 注释自认是"对齐"而非"复用"
```

- **缺 `claimNodeRun`/`releaseNodeRun` 互斥**（对比 `useNodeGeneration.js:107,197`）→ 批量（`:417-439` 滑动窗口并发 4）同资产可并发生图。

## 七、校验盲区：为什么门禁没拦住

| 脚本 | 覆盖 | **不覆盖** |
|---|---|---|
| `check:api`（`scripts/check-api-contract.cjs`，挂 `prebuild`/`pretest`） | apiRegistry 的 **path / method / envelope** ↔ `router.ts` routes 互检；fn 导出存在性 | **登记表之外的任何常量值**；`RESERVED` 条目无导出时仅 info（`:16`），永不失败 |
| `check:keys`（`check-storage-keys.mjs`） | `STORAGE_KEYS` 裸 key 拦截 | 非存储类常量 |
| `check:events` | `EVENTS` 发布/订阅两面自洽 | — |
| `check:node-types` | `NODE_TYPES` 裸命名空间 | — |

**本文 A/B/C/D 四类问题全部落在盲区**：

1. **枚举镜像** —— 无任何脚本比对 `providerProtocols.js` 与 `protocolAdapters.ts`。`check:api` 只比对 URL 路径，**不看常量值**。
2. **模型清单** —— `config.js:79-85` `DEFAULT_AGENT_MODELS` 硬编码 5 个模型名、`TextNode.jsx:104` 硬编码默认模型；无校验。
3. **配置/阈值** —— 完全无校验，且后端无下发端点，属"契约未定义"而非"契约违反"。
4. **返回结构解析** —— `envelope` 只是登记字符串，`stream/sse/raw/probe/stub` 豁免（`:38`），组件里实际怎么解包**不校验**。
5. **素材双索引 / cookie 白名单 / `EXT_BY_TYPE`** —— 无校验。

> 补充实测：返回结构解析其实**合规**（`GeneratedView.jsx:139-142`、`AssetLibrary.jsx:141-144`、`taskStore.js:37`、`ScriptBoxAssetPicker.jsx:38` 都正确走 `code-data` / `items`），无 `data[0]` 直取、无 envelope 绕过。这一项不是问题。
