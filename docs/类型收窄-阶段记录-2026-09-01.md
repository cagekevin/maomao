> 说明：阶段一与「测试 any 清理」在同一 commit 边界，src 收窄是其后新增工作。

### 1. conversationState.ts（核心，约 19 处 any）

- 接口字段 `any[]` → `unknown[]` / `Record<string, any>` → `Record<string, unknown>`：
  - `ConversationMemory.facts/notes` → `unknown[]`、`lastPlan` → `Record<string, unknown> | null`
  - `WorkflowState.steerQueue` → `unknown[]`
  - `PendingRefState.attachments` → `unknown[]`
  - `Conversation.messages` → **`ConversationMessage[]`**、`skills/attachments/aiUndoStack` → `unknown[]`、
    `pendingGenerations` → `unknown[] | null`、`pendingMemorySuggest` → `Record<string, unknown> | null`
- 新增**宽松反序列化形态**（归一化入口用）：
  - `RawMemory` / `RawWorkflow` / `RawPending` / `RawConversation`
  - 数组字段（facts/notes/nodeIds/steerQueue/attachments/messages/skills…）用 `unknown[]`，
    使 `normalize*` 内部 `.map` / `.slice` / `.push` 可直接类型化。
- `ConversationMessage`：新定义的消息形状，字段全可选且以 `unknown` 承载 + 索引签名。
  - 原因：真实会话消息含流式中间态（id/streaming 占位）、体积降级字段（lastResults）、历史遗留字段，
    常被 `Record<string, unknown>` 直接赋值；用 unknown 消除 any 且保留结构提示。
- `normalizeConversation / normalizeWorkflow / normalizePending / normalizeMemory`：
  入参 `any` → `unknown` + `as Raw*` 断言，函数内用 typeof / Array.isArray 收窄，返回 `as 精确类型`。
- `makePendingRef` 参数 `attachments?: any[]` → `unknown[]`。
- 水化反序列化 `as any[]` → `as unknown[]`。
- 落盘 `applyConversationBudget` 边界一次断言（volumePolicy 的 ChatMessage.content 是 string 窄类型）。

### ⚠️ 保留的必要 any（泛型约束）

`base/utils.ts` 的 `DebouncedFn` / `ThrottledFn` / `RafBatchFn` 泛型约束
`T extends (...args: any[]) => void`（共 6 处，含 debounce/throttle/createRafBatch 签名）：

- **不可替换**：曾尝试 `(...args: never[])` / `(...args: unknown[])`，两者都会让 `Parameters<T>`
  推断失真（返回函数参数被解析成 `never[]`），导致 11 处调用方（ImageZoomDialog / CustomHandle /
  GridSplitNode / VideoProcessNode 等）报"Argument of type 'number'/'any' is not assignable to 'never'"。
- 这是 `any[]` 在**泛型函数签名约束**中的合法且必要用途（用于保留调用方函数的精确参数）。
  已回退，保留 `any` 并在此注明，不计入"应消除的宽泛 any"。

### 阶段三补充处理

- `base/clipboard.ts`：`buildNodesFromClipboard` 返回从 `unknown[]` 改为精确接口
  `ClipboardNode` / `ClipboardEdge`（id/type/position/data/selected + 索引签名），
  测试与消费方访问字段类型化。
- `buildCanvasAgentTools(ctx)`：`ReturnType<typeof useReactFlow>` → **最小 `CanvasAgentCtx`**
  （`getNodes/getEdges` 必填返回 `CanvasNodeLike[]`/`CanvasEdgeLike[]` + 索引签名承载其余能力），

### ⚠️ 保留的必要 any（信封语义）

`base/toolRegistry.ts` 的 `ToolResult.data?: any`：

- **不可替换**：曾尝试改 `unknown`，引发 75 处测试连锁（canvasAgentTools.test.ts /
  useCanvasAgentTools.test.ts / clipboard.test.ts 等全部访问 `res.data.xxx`）。
- 这是「工具执行结果信封」的有意设计（注释明确：调用方按需读 data，不强约束二选一），
  收窄成 `unknown` 破坏信封语义、引爆全部消费方。已回退保留 `any`，不计入应消除的宽泛 any。
- 附带：`localTool/` 子项目由另一 AI 负责（本次不触碰、不 stage）。
