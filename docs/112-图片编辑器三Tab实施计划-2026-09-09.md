## 3. 架构（继承 111 §3，此处只列红线）

```
editorDoc（唯一真源，不可变更新）
  ├─ layers: Layer[]        ← 当前只有 [baseLayer]，但必须按数组遍历，禁止写死单画布
  ├─ size: { w, h }         ← 画布尺寸
  ├─ background: string     ← 底（透明 / 纯白 #ffffff）
  └─ view: { zoom, offset } ← 仅视图态，不参与出图
```

**红线（违反即返工）**：
1. ❌ 禁止 `getImageData` / `putImageData` 做画布变换或当数据源
2. ❌ 禁止就地改活画布尺寸（裁剪/扩图必须**新建游离 canvas + `drawImage`**）
3. ❌ 禁止全画布像素快照撤销栈（用 `editorDoc` 快照，上限 10 步，存 `Blob`/`ImageBitmap` **非 dataURL 字符串**）
4. ✅ 唯一数据流：`action → editorDoc → composite → 画布`；画布不反向驱动 state
5. ✅ 绘制源一律 `compressImage(url, {keepOriginalFormat:true})` 同源 dataURL → 画布永不被污染
6. ✅ 吸管 `getImageData` 必须包 try/catch

## 7. 明确不做（避免范围蔓延）

| 不做 | 原因 |
|---|---|
| 多图编辑（合成器） | 独立功能，另有 mockup |
| 宫格裁剪 `CustomGridEditor` | 与既有 `GridSplitNode` 重叠，且一进多出不同构 |
| 模型选择 / prompt / provider | 不接 AI，只输出一张图，后续由用户决定 |
| 引入 `framer-motion` | 本仓库已有 `FullscreenModal` |
| 引入 `@iconify/react` | 本仓库统一 `lucide-react` |
| 动 `InlineImageCropper` | 场景不同（随手裁 vs 精细调），已验证可用 |
| 扩图透明底 | 不接 AI，透明底当素材易出问题；维持纯白 |
| 扩图倍率放宽到 4 倍 | 维持 `factor ≤ √2`（2 倍面积） |
