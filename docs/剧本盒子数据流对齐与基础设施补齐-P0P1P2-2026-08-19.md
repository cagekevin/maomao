## 0. 架构总判（先读这段）

我们与官方的**数据流骨架已对齐且局部更优**：单一数据源 `node.data` + 引擎回调注入 + 纯函数层单向依赖 + 并发滑动窗口（MAX_CONCURRENT=4 / START_GAP_MS=500）+ AbortController 真中止 + `@资产` 引用匹配。这些**禁止在补功能时重构**。

真正差距只有一个本质：**数据契约不完整 + 一条链路断了**。

| 维度 | 现状 | 架构结论 |
|---|---|---|
| 数据契约 | 缺 `imageNegative/videoNegative`、尾帧连续性子字段未定义 | P0 收口唯一 schema，全量归一化 |
| 上传链路 | `onUploadAllVideoAssets` 是 `setTimeout` 假成功，数据流断 | P0 真化：接侧边栏素材库 `assetStore`（已是真实落盘通道） |
| 连续性链路 | 尾帧变体→下一镜视觉起点，官方核心能力，我们完全没有 | P1 打通，前置验证抽帧能力（已有 `VideoExtractNode`） |
| 质量层 | 叙事约束密度、分通道 negative 弱于官方 | P2 纯提示词补强，不改数据流 |

**唯一编号纪律**：全文只用 `P0 / P1 / P2` 章节编号，功能内联其中（如 `P0-2 资产图真上传`）。§6 仅作「功能→条目」反查索引，杜绝双套语言。

**三栏纪律**：每条目必写 ① 契约（字段+类型+默认值）② 通道（谁写/谁读）③ 测试点。

## 2. P0 —— 数据契约收口（地基的地基）

> P0 不实现任何"花哨功能"，只把**数据的形状、默认值、读写通道、归一化点**定死。所有后续功能只能在 P0 声明的字段上生长。

### P0-0 权威 schema 与归一化（整份计划的地基，必须先做）

**问题**：当前字段散落在 UI 表单、`useScriptBoxEngine` 注入、`onGenerateScript` 归一化三处，无单一真相源；旧画布里 ScriptBoxNode 缺新字段时打开即漂移。

**契约**：新建 `src/components/base/scriptBoxSchema.js`（或并入 `scriptBoxEngine.js`），导出：
- `defaultScriptBoxData()`：返回含全部顶层/子字段默认值的对象。
- `normalizeScriptBoxData(raw)`：读旧数据时补齐缺省字段（向后兼容迁移），所有读取 `node.data` 前必经此函数。

**通道**：UI 表单只渲染 schema 声明字段；引擎注入前先 `normalizeScriptBoxData`；序列化随画布快照（`canvas-state-v1-{projectId}`），不另立存储键（防双写漂移，见 `contracts.js` 注释）。

**测试**：`scriptBoxEngine.test.js` 新增 `normalizeScriptBoxData` 用例——缺字段旧数据归一化后不丢、不抛、默认合法。

### P0-1 顶层字段补齐（分通道 negative + 尾帧角度）

**契约**（类型/默认值）：
| 字段 | 类型 | 默认 | 用途 |
|---|---|---|---|
| `imageNegative` | string | `''` | 仅作用于生图 prompt 的负面词（高优先级） |
| `videoNegative` | string | `''` | 仅作用于生视频 videoPrompt 的负面词 |
| `tailFrameAngleIds` | string[] | `['forward','closeup','rotateLeft45']` | 尾帧变体默认角度（P1 用） |

**通道**：`GearSettings.jsx` 表单登记 → `normalizeScriptBoxData` 写入默认 → `onGenerateScript` 注入 → `assembleShotUser`（P2-4）拼入。

**测试**：字段默认值为 `''`/`['forward',...]`；表单提交写入后被 `normalize` 保留。

**UI 承载**：`scriptbox/GearSettings.jsx` 基础 Tab「全局约束」区（当前 `GearSettings.jsx:138-144`，含图片/视频/自定义三栏）新增 `imageNegative` / `videoNegative` 两栏 textarea，本地态 `useState(d.imageNegative||'')` / `useState(d.videoNegative||'')`，`save()`（`GearSettings.jsx:64-80`）写回 `imageNegative` / `videoNegative`。不新增 Tab，复用现有「全局约束」分组，避免 UI 膨胀。
  - **参考位置**：`GearSettings.jsx:138-144`（约束区）、`:64-80`（save 写回）。

### P0-2 资产图真上传（去假，接素材库）—— 用户已感知假成功，优先级最高

**契约**：`assets[].videoStatus` 状态机枚举 `'idle' | 'uploading' | 'uploaded' | 'failed'`；`failed` 必带 `videoError: string`。

**通道**：
- 写：`onUploadAllVideoAssets` / `onRetryVideoAssetUpload` 改为调 `assetStore.sendToAssetLibrary(asset.imageUrl, { name: asset.name, folder: assetFolderOf(asset.category) })`。
  - **参考位置**：当前假实现在 `scriptBoxEngine.js:534-543`（`setTimeout 600ms` 直接标 `uploaded`）；`sendToAssetLibrary` 定义在 `assetStore.js:151`；目录映射 `assetStore.FOLDERS` 在 `assetStore.js:54-61`。
- `assetFolderOf(category)`：单一映射函数 `character→migrated/人物`、`scene→migrated/场景`、`prop→migrated/道具`（收口在 `assetStore.FOLDERS` 语义，剧本盒不自己拼路径）。
- 落盘成功 → `videoStatus='uploaded'` 并保留本地化 URL（`sendToAssetLibrary` 经 `saveInlineToLocal` 返回 `/files/...`）；失败 → `'failed'` + `videoError`。
- 读：下游视频节点引用素材库 URL（即 `asset.imageUrl` 改写后的本地 URL）。

**测试**：mock `sendToAssetLibrary` 成功/失败两路，断言 `videoStatus` 走 `uploading→uploaded` / `→failed+videoError`，且无 `setTimeout` 假标。

**UI 承载**：`StepAssets.jsx` 的 `AssetCard` 已渲染 `videoStatus`（`StepAssets.jsx:159-164`，uploading/uploaded/failed 三态文案+图标），引擎真化后 UI 自动生效，无需改渲染；仅需在 `more` 菜单（`StepAssets.jsx:171-180`）确认「上传视频 / 重试上传」调用的是 `onRetryVideoAssetUpload`（已接，`:174-175`）。素材落盘后用户可在侧边栏 `AssetLibrary` 面板看到（经 `rescanResources`），无需剧本盒内额外 UI。

### P0-3 资产图字段分离（imageUrl / thumbnailUrl）

**契约**：`assets[]` 明确 `imageUrl`（原图或本地化图）与 `thumbnailUrl`（缩略图）两字段，类型 `string`，默认 `thumbnailUrl = imageUrl`（过渡期兼容，P2-2 再真生成）。

**通道**：UI 列表渲染统一读 `thumbnailUrl`；引擎写回时两字段分别处理。

**测试**：归一化后 `thumbnailUrl` 缺省回退 `imageUrl`，不 `undefined`。

**UI 承载**：`StepAssets.jsx` 的 `AssetCard` 缩略图渲染（`StepAssets.jsx:149-153`）改为读 `asset.thumbnailUrl || asset.imageUrl`（当前已用 `asset.imageUrl`，加 fallback 即可）。`AssetPanel` 编辑面板无需改。P2-2 真生成缩略图后 UI 自动切换。

### P0-4 存储键登记

**契约**：剧本盒数据随画布快照走 `canvas-state-v1-{projectId}`，**不新增 STORAGE_KEYS**。在 `contracts.js` `NODE_TYPES` 旁注释：ScriptBoxNode `data` 全部子字段属快照一部分，禁止独立持久化（防漂移）。

**通道**：仅文档约束，无代码行为。

**测试**：无（属规范，靠 review 把关）。

## 4. P2 —— 链路接实 + 质量做厚

### P2-1 资产图本地化落盘（接素材库，含目录分类）

**契约**：生图后 `imageUrl` 改写为本地 `/files/migrated/{人物|场景|道具}/...`（经 `saveInlineToLocal` / `sendToAssetLibrary`）。

**通道**：`onGenerateAssetImage` 生图返回后调 `sendToAssetLibrary(asset.imageUrl, { folder: assetFolderOf(category) })`，写回本地化 URL。与 P0-2 共用同一落盘通道，不另写。

**测试**：生图 mock 后断言 `imageUrl` 变为 `/files/migrated/...` 本地路径。

### P2-2 缩略图真实生成

**契约**：`thumbnailUrl`（P0-3 已分离）接 localTool 缩略图接口（官方 `bi(url,{maxDim:480,quality:75})` 等价）。

**通道**：落盘（P2-1）后生成缩略图写回 `thumbnailUrl`；UI 列表渲染读 `thumbnailUrl`。

**测试**：mock 缩略图接口，断言 `thumbnailUrl !== imageUrl` 且为 480px 级。

**UI 承载**：`AssetCard` 缩略图（`StepAssets.jsx:149-153`）已改读 `thumbnailUrl || imageUrl`（P0-3），真生成后自动切换，无需额外改动。

### P2-3 叙事约束密度升级（纯提示词）

**契约**：`assembleShotUser` 补：镜头位置语义（开场/中段/结尾镜+叙事功能）、剧情承接、下一镜预告钩子、出场分工（核心/压迫位/背景位）、眼线锁定、风格锚定（焦段/窄高光/材质微动作）、环境音三层。**不改数据流**。

**通道**：仅 `scriptBoxPrompts.js` 纯函数，读现有字段。

**测试**：断言输出含对应叙事段关键字；旧用例不回归。

**UI 承载**：无（纯提示词，不改 UI）。

### P2-4 分通道 negative 拼入

**契约**：`imageNegative` 仅拼入 prompt，`videoNegative` 仅拼入 videoPrompt（高优先级）。

**通道**：`assembleShotUser` 读 P0-1 字段。
