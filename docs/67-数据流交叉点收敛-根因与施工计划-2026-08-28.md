| 根因 | 问题 | 映射原稿 # | 优先级 |

| **B** 无统一 envelope/URL 解析器 | 信封剥离、图片 URL 提取散落 ≥5 处 | 2 | P1 |

| **E** 跨发起方并发无锁 | Agent / 用户手动生成打架 | 5 | P1 |
| **F** 存储降级/双真相无清理 | KV 本地副本残留、`native` 语义空洞 | 6 | P2 |
| **G** 画布无拓扑触发引擎 | 透传只"拉"不"驱动"，聚合结果双份 | 8,9 | P2 |

## 三、施工计划

> 每项统一四段：**现状 · 改法 · 影响面 · 验收**。改法必须可直接落到签名，验收可用命令/行为证明。

### P0-A · 根因 A —— task 关联改"请求级上下文"

**现状**
- 全局单例：`currentTaskId` 定义 [taskStore.js:30-32](file:///g:/01画布项目/maomao/src/components/base/taskStore.js#L30-L32)。
- 写：`useNodeGeneration.js:110`、`scriptBoxEngine.js:336` 各 `setCurrentTaskId(taskCtl.taskId)`。
- 读：`proxyGenerate.js:47`（`__buildProxyPayload` 塞 `payload.taskId`）、`:61/:408`（日志）、`:172`（`setTaskPollId(getCurrentTaskId(), …)` 回填轮询 id）。
- 现状签名链：`generateImage({...}, onProgress, signal)` → `imageProxy({provider, genBody, onProgress, signal})` → `__buildProxyPayload`。`onProgress`/`signal` 已是贯穿透传，task_id 也应同路。

**改法（建议）**
1. 取消全局读写。给 `generateImage` / `generateVideo` 增加第 3 个透传参数（复用 `onProgress` 同位置的口径）：
   `generateImage(ctx, onProgress, signal, runMeta)`，其中 `runMeta = { taskId }`。
   更稳的落点是**并入现有 `ctx`**，避免再加参数位：
   ```
   generateImage({ provider, prompt, ..., taskId }, onProgress, signal)
   → imageProxy({ provider, genBody, onProgress, signal, taskId })
   → __buildProxyPayload / logger / setTaskPollId 全部改用入参 taskId
   ```
2. `useNodeGeneration.start()` 与 `scriptBoxEngine.js` 在调 run 前把 `taskCtl.taskId` 写入 runMeta。
3. 删除 `setCurrentTaskId`/`getCurrentTaskId` 导出，DOM 引用全清。

**影响面（实测，必须全量覆盖）**
- 读方：`proxyGenerate.js:20,47,61,172,408`
- 写方：`useNodeGeneration.js:2,110`、`scriptBoxEngine.js:10,336`
- 测试 mock：`tests/unit/{imageApi,videoApi,useNodeGeneration}.test.js`
- 文档引用：`docs/03-任务ID全链路*` `CONTRACTS-2026-08-16.md` `spec/横切基础设施分层.md`（备注性，不改逻辑）

**验收**
- 双节点并发（一 SSE、一 async 轮询）：各自请求体 `payload.taskId` 与 `setTaskPollId` 回填的 record 一一对应，互不覆盖。
- 现有单测改完 redis 语义后绿（`getCurrentTaskId` mock 移除）。
- `grep -rn "getCurrentTaskId\|setCurrentTaskId" src tests` 返回 0。

### P0-C · 根因 C —— 单向写纪律 + 消除双落盘

**现状**
- 成功路径落盘两次：[useNodeGeneration.js:134](file:///g:/01画布项目/maomao/src/components/base/useNodeGeneration.js#L134) `await saveResultToTasks(rawUrl,…)`；随后 `taskCtl.done(rawUrl)` → [taskStore.js:199-200](file:///g:/01画布项目/maomao/src/components/base/taskStore.js#L199-L200) 内部再 `saveResultToTasks(resultUrl,…)`。
- 写 node.data 统一经 `useNodeData.patchData`（方向单向已在契约注释，未强制）。

**改法**
1. `taskStore.done(resultUrl)` **去掉落盘职责**：只写内存 `status:'completed' / resultUrl` + 落库任务记录（resultUrl 为占位或最终 url）+ 广播完成。
2. 落盘唯一出口放 `useNodeGeneration.start()` 成功路径：落盘→得 `persistedUrl`→`taskCtl.done(persistedUrl)` 回填任务中心最终 url。
3. 从 `taskStore.js` 移除 `saveResultToTasks` import，物理杜绝双落盘。

**影响面**
- `taskStore.js`（done 逻辑）、`useNodeGeneration.js`（成功路径）、依赖 done 语义的测试与调用方（`runNodeGeneration`/Agent 链路仍拿 start 返回的持久 url，不受影响）。

**验收**
- 生成一张图，网络面板 `saveResultToTasks`（`/api/files/...` 或落盘端点）只出现 1 次。
- 任务中心与 node.data 均为同一持久 /files/ URL。

### P1-B · 根因 B —— 统一 envelope/URL 解析器

**现状（≥5 处并存，相互不共享）**
- `proxyGenerate.readSseUrl:125`（SSE `evt.results[0].url ?? evt.result.images[0].url`）
- `proxyGenerate.extractImageUrl:213` / `extractVideoUrl:219`（JSON 直返/轮询）
- `pollTask.extractResultUrl:39`（网关 task_view 按 type 提 url）
- `agentRuntime.parseSSEChunk`（Agent 流）

**改法**
1. 新增单一模块 `src/components/base/resultUrlExtractor.js`，导出：
   ```js
   extractResultUrl({ data, json, type })   // type ∈ image|video|audio，统一字段表
   ```
   字段映射收敛：`results[0].url` / `result.images[0].url` / `result.videos[0].url` / `result.url` / 顶层 `video_url`；数组可包时统一取 `[0]`。
2. `readSseUrl`、`pollUntilDone`、`pollTask.extractResultUrl` 全部委托之；`agentRuntime` 视需要接入（若共用形态一致）。
3. **type 判定规则与 `useConnectedInputs.resolveKind`（[useConnectedInputs.js:42-55](file:///g:/01画布项目/maomao/src/components/base/useConnectedInputs.js#L42-L55)）同源**：生产方 `.mediaType` 优先，否则按扩展名 classify——消灭"video 被当 image"静默误分类。

**附注（doneUrl 取舍）**：本稿建议**补齐生产者**（imageApi/videoApi 返回 `doneUrl` 给任务中心用），或显式移除消费端 `r.doneUrl || r.url`。二选一，须在本项施工时定死，不留悬空契约。

**验收**
- 加入 5 处同一响应样例（SSE / 图片直返 / 图片轮询 / 视频轮询 / 网关 task_view），单一解析器输出一致。
- `grep -rn "result.images\|results\[0\].url\|result.videos" src/components/base` 只命中解析器模块。

### P1-D · 根因 D —— 任务完成信号 + 事件纪律统一

**现状**
- `agent:task-completed` **已登记** `EVENTS`（[contracts.js:50](file:///g:/01画布项目/maomao/src/components/base/contracts.js#L50)），但两发布点（`taskStore.js:209`、`pollTask.js:88`）**各自拼 payload、无校验**。
- `CREDIT_GATE_EVENT`（[contracts.js:29](file:///g:/01画布项目/maomao/src/components/base/contracts.js#L29)）定义存在但无 import 引用，发布/订阅用裸串。

**改法**
1. 新增薄模块 `taskCompletionBus.js`：
   `publishTaskCompleted({taskId,nodeId,resultUrl,type,status})` —— 内部校验（`status==='completed'`、`resultUrl` 非空字符串）后 `publish('agent:task-completed', payload)`。两发布点改为唯一入口。

3. `emitAssetSent`/`onAssetSent` 收口为 `publish/subscribe` 到 `EVENTS` 新登记项（无平行裸回调桥）。
4. 事件表补登 `yimao:remove-edge`（[App.jsx:1105](file:///g:/01画布项目/maomao/src/App.jsx#L1105) 目前是 window 事件未登记）。
5. `contracts.js:72` `project:import` 的"订阅方写法非 subscribe 字面量，待核对"——按实测改 note（已是标准 subscribe）。

**验收**

### P1-E · 根因 E —— 跨发起方并发锁下沉到契约层

**现状**
- 组件级 `runningRef`（[useNodeGeneration.js:96](file:///g:/01画布项目/maomao/src/components/base/useNodeGeneration.js#L96)）只防**同一组件实例**重入。
- Agent 单飞锁 `executingPlan`（canvasPlanExecutor）只防 Agent 内部。
- 全局 `genActive`（[taskStore.js:303](file:///g:/01画布项目/maomao/src/components/base/taskStore.js#L303)）只做**任务数上限**，不锁节点。

**改法**
- 在 `registerTaskRetry(nodeId, runFn)` 层维护 `nodeRunning: Map<nodeId, Promise>`：同节点已有进行中 → 后到返回"进行中/待生成"，**不并发生成**。`runNodeGeneration(nodeId)` 与用户手动 `start()` 都经此 Map。
- 与 `genActive` 关系：`genActive` 仍管全局并发数，Map 管单节点互斥，两层不冲突（上层先占任务槽，再按节点去重）。

**验收**
- 同一节点被 Agent 与手动同时触发，只发生 1 次真实生成请求；第 2 次得明确"进行中"结果（不静默）。
