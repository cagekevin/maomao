### 1.4 hook：挂/恢复/继承（`useLocalPatchContext.js`）
- 提供给**融合节点**：读取直接上游的上下文（走 `useConnectedInputs` 返回的 images，每张图带 `cropContext`）。
- 提供给**生成节点**：下游产出时把上游 context 继承到输出（关键：这需要侵入节点生成链路）。

> **审计定案（2026-08-20）——「中间生成节点自动继承」是核心功能，必做，非可选项**：
> 插件核心工作流是「提取选区 → **任意生成节点处理局部图** → 融合回原图」。若跳过自动继承，局部图经过生成节点后 cropContext 丢失，融合必失败，功能不可用。
> **实现路径（唯一，禁止另起方案）**：
> 1. 在 `useNodeGeneration.js` 的 `onSuccess` 回调**之前**，注入一个通用步骤：取当前节点的**直接上游** images（经 `useConnectedInputs`），用 `applyInheritedContext(新产出, 上游images)` 计算继承上下文；
> 2. 把继承结果写回 `node.data`（`data.cropContext` 或 `data.cropContextConflict`）；
> 3. 同时 `rememberContextMetadata` 登记结果 URL→context。
> 此步骤做成 `useLocalPatchContext` 提供的 hook，`useNodeGeneration` 调用方按需启用（不强制所有节点，只对图片产出节点）。**若某个生成节点不接此钩子，局部图经它处理后上下文丢失，视为该节点未接入，需在批 5 收口清单标注。**

## 二、M4 后端算法（`localPatchOps.ts` + `localPatch.ts`）

### 2.1 算法纯函数（翻译插件 `local_patch_ops.py`，Jimp 实现）

| 函数 | 对应插件 | Jimp 实现要点 |
|------|---------|--------------|
| `fileFingerprint(path)` | `file_fingerprint` | 流式 SHA-256，1MB 分块 |
| `loadOrientedRgba(path, maxPixels)` | `load_oriented_rgba` | Jimp.read + EXIF 旋转（Jimp `exifRotate`）+ 像素上限校验 |
| `computePaddedRect(rect, imageSize, ratio=0.1)` | `compute_padded_rect` | 外扩 10%，钳制在图内，校验越界/尺寸 |
| `cropLocalPatch(...)` | `crop_local_patch` | 选区 ≥32px、源尺寸校验、裁 paddedRect、生成 cropContext（指纹算一次） |
| `buildFeatherMask(rect, padded)` | `build_feather_mask` | smoothstep 羽化：内部实心 255、边缘渐变 + 高斯模糊 0.8 |
| `applyLimitedColorMatch(origPatch, patch, ring)` | `_apply_limited_color_match` | 环带均值差 ±24 限幅，逐通道 offset |
| `mergeLocalPatches(originalPath, patches, colorMatch, maxPixels)` | `merge_local_patches` | 逐张校验（指纹/尺寸/宽高比≤1%）→ 缩放回 paddedRect → 颜色匹配 → 羽化 → alpha_composite 合并，多图按顺序后覆盖前 |

> ⚠️ **Jimp 实现注意（具体 API，照做）**：
> - **EXIF 旋转**：Jimp 载入后调 `img.exifRotate()`（对齐 Python `ImageOps.exif_transpose`），再 `img.getWidth()/getHeight()` 读修正尺寸。裁剪源尺寸校验用修正后的尺寸。
> - **无 `alpha_composite`**：Jimp 用 `base.composite(patch, x, y)`。但要先给 patch 合成羽化 alpha：把羽化 mask（单通道灰度）作为 patch 的 alpha 通道。做法：`patch.scan()` 逐像素把 `patch.getPixelColor` 的 alpha 乘上 mask 对应值，或 Jimp `patch.mask(maskImg)`（0.22 支持 `mask`）。
> - **颜色匹配**：无 `ImageStat`。用 `region = orig.clone().crop(rect.x, rect.y, rect.w, rect.h)`，`region.scan()` 累加 RGB 算均值；patch 同理；offset = clamp(orig均值 - patch均值, -24, 24)，逐通道 `patch.scan()` 加 offset 钳制 0-255。仅对 **ring 环带**（paddedRect 内 rect 外）算，可简化成对整个 paddedRect 算均值（插件用 ring mask 更精确，先按整个 padded 算，差异可接受，单测锁）。
> - **羽化 mask**：用纯 JS 生成单通道灰度（内部实心 255、边缘 smoothstep 渐变），再 `Jimp` 构造后 `blur(1)`（对应高斯 0.8）。不需要 Jimp 原生滤波。
> - **多图合并**：`result = original.clone()`，逐 patch：`result.composite(带alpha的patch, paddedRect.x, paddedRect.y)`，后一图覆盖前一图（Jimp composite 后者在上）。
> - **`scan()` 回调性能**：大图（100MP 上限）逐像素 `scan` 慢。若超时，评估：羽化/颜色匹配只对 **paddedRect 区域**做（裁剪出小区域处理再 composite），避免全图 scan。**实现时优先区域化处理。**
> - **先写单测锁契约再实现**（TDD，锁 `local_patch_ops.py` 的语义）。

### 2.2 接口契约（`localPatch.ts`，对齐 `backend.py`）

| 接口 | 入参 | 出参 | 错误 |
|------|------|------|------|
| `POST /api/local-patch/crop` | `{ source_url, selection:{x,y,w,h,source_width,source_height}, padding_ratio=0.1, crop_node_id? }` | `{ file:{ url,name,kind:'image',natural_w,natural_h,cropContext } }` | 409 源变 / 400 校验 |
| `POST /api/local-patch/merge` | `{ original_url, patches:[{patch_url,crop_context}], color_match=true, feather_mode='smoothstep' }`（或单 `patch_url+crop_context`） | `{ file:{ url,...,localPatchFullImage:true,localPatchContextReset:true }, warnings:[] }` | 409 源变 / 400 校验（含 >16 张） |
| `POST /api/local-patch/fingerprint` | `{ source_url }` | `{ fingerprint, size }` | 400 |

- 落盘：裁剪 `local_crop_<hex>.png`、融合 `local_merge_<hex>.png`，都走 `getUploadDir()` 的 output 子目录，返回 `/files/...` URL。**不覆盖源图**。
- **源图 URL 解析**：`source_url` 为 `/files/<subfolder>/<name>` → `getUploadDir()` + 相对路径映射磁盘（对齐 `handleThumbnail` 的 `replace(/^\/files\//,'')`）。
- 错误码语义见 `docs/18 §5.5`：409=源变、400=校验、500=兜底。错误信息真实透传。

## 三、M2 选区提取（`LocalPatchExtract.jsx`）

### 3.1 交互
- 复用 `ImageEditor` 的 **`react-image-crop`** 裁剪交互（已有现成选区/比例/缩放/拖动）。
- 提供**独立裁剪弹层** `LocalPatchExtract`（不硬侵入既有 ImageEditor，遵循「重构边界铁律」）：图片节点 hover 工具栏加「提取选区」按钮 → 打开本弹层 → ReactCrop 框选 → 确认。
- 选区换算 `displaySelectionToNatural`（对齐插件 `local-patch-core.js`）：
  ```
  sx = naturalWidth / displayWidth; sy = naturalHeight / displayHeight
  x = round(selection.x * sx); ... sourceWidth = naturalWidth; sourceHeight = naturalHeight
  ```
  **naturalWidth/Height 用源图 EXIF 修正尺寸**（C2.2）。

### 3.2 裁剪落盘 + 上下文注入（C2.3，原子）
1. 前端调 `POST /api/local-patch/crop`（经 `httpRequest`，`API_BASE`）。
2. 成功 → 后端返回 `{ file:{ url, cropContext } }`。
3. 前端建新 `imageNode`（`useReactFlow setNodes` 或既有建节点链路），`data` 挂 `cropContext`（+ `url`/`imageUrl`）。
4. 注册表 `rememberContextMetadata` 登记该 URL→context。
5. 失败 → 透传错误（409/400）到 toast，**不建节点**。

### 3.3 入口收敛（C2.1）
- ImageNode hover 工具栏加「提取选区」按钮（`show: type==='image'`）。
- 复用 `ImageEditor`？→ 评估：插件是加「提取选区」模式进编辑器。本项目为最小侵入，**用独立 `LocalPatchExtract` 弹层**（含裁剪 + 确认提取），不污染现有裁剪/标记工具。

## 四、M3 融合节点（`ImageMergeNode.jsx`）

### 4.1 节点范式（C3.1，NEW-NODE-GUIDE 三同步）
1. `NodePalette.jsx` `paletteNodes` 加 `{ type:'imageMergeNode', label:'图像融合', icon:<Blend/>, cat:..., component:ImageMergeNode, builtin:true }`
2. `useConnectedInputs.js` `NODE_OUTPUTS` 加 `imageMergeNode: (d) => ({ images: d.imageUrl ? [{ id, url: d.imageUrl, label:'融合结果' }] : [] })`
3. `contracts.js` `NODE_TYPES` 加 `imageMergeNode: 'imageMergeNode'`

### 4.2 端口（C3.2）
- **NodeShell 自定义端口**（`CustomHandle`）：
  - 左 `in` 端口（original）→ 收完整原图，**单连线**（重复连线替换）
  - 右 `in` 端口（patch）→ 收局部图，**多连线**（每条独立 connectionKey + 独立选择索引）
- 用 `useConnectedInputs(id)` 拿直接上游 images（每张带 `cropContext` / `cropContextConflict`）。
- 多图选择：每条 patch 连线一个 `data.patchChoices[connectionKey]` 索引，缩略图左右按钮切换。

### 4.3 融合编排（C3.3/C3.5）
1. 收集原图（`originalChoice`）+ 各 patch（`patchChoices`）。
2. **前端预校验**（C3.5）：
   - patch.role==='mask' → 拒
   - patch.cropContextConflict → 拒「包含冲突的裁剪上下文」
   - patch 无 cropContext → 拒「缺少上下文，请重新提取选区」
   - patches 数 >16 → 拒
3. 调 `POST /api/local-patch/merge`（`httpRequest`）。
4. 后端做溯源校验（指纹/尺寸/宽高比）返回错误 → 透传展示。

### 4.4 结果与「新原图」语义（C3.6/C3.7）
- 成功 → 后端返回 `file`（含 `localPatchFullImage:true, localPatchContextReset:true`）。
- 前端建新 `imageNode` 挂 `data.localPatchFullImage=true + localPatchContextReset=true`，**删除 cropContext**。
- 结果节点附 `data.comparisonOriginalUrl`（原图 URL）→ 预览支持「对比原图」滑杆（C3.7）。
- 结果可再作为新原图提取（因为已清局部上下文、标记完整图边界）。

### 4.5 融合节点生成契约（审计定案，2026-08-20）

> **融合节点是「本地算法」非「外部生成」**：结果由后端 localPatch 算法落盘 `/files/` 持久 URL，**不走 `useNodeGeneration`**（它不是外部生图/生视频，不接 taskStore 任务中心）。但它满足项目「结果落盘 + 刷新不丢」要求的方式，对齐 **ImageNode** 而非 PromptNode：
> 1. 后端 `/merge` 已把结果落盘到 `/files/`（持久 URL），前端建节点时 `data.imageUrl = 结果URL` → 随画布快照落盘，刷新不丢。
> 2. **不需要 `onRecover`**（无任务中心回填），结果本体就在 `data.imageUrl`（对齐 ImageNode 的 `uploadFileToLocal` 路径）。
> 3. 融合节点自身的「开始融合」按钮是普通异步交互（`httpRequest` + loading/error state），不套 `useNodeGeneration` 的 `run/onSuccess` 契约，但**错误必须透传展示**（C3.8）。
>
> **结论**：融合节点参照 `ImageNode` 的「本地结果落盘」范式，**不接 useNodeGeneration、不接 taskStore**。若后续发现需要任务中心记录，再评估，本阶段不做。

## 五、前端请求封装

在 `localPatchContext.js` 或单独 `localPatchApi.js` 封装（**经 `httpRequest`，不裸 fetch**）：
```js
import { httpRequest } from './httpClient.js'
import { API_BASE } from './config.js'

export async function cropLocal(srcUrl, selection, opts) {
  return httpRequest(`${API_BASE}/api/local-patch/crop`, {
    method:'POST', headers:{'Content-Type':'application/json'},
    body: JSON.stringify({ source_url: srcUrl, selection, padding_ratio: 0.1 }),
    retries: 0, // 业务错误不重试
    label: 'cropLocal',
  })
}
export async function mergeLocal(originalUrl, patches, colorMatch) { /* 同上 */ }
export async function fingerprintLocal(srcUrl) { /* 同上 */ }
```
> ⚠️ `httpRequest` 默认对 4xx 不重试（只网络/超时重试），符合「业务错误不重试」红线。错误信息取 `HttpError.data.error||data.detail`，透传展示。

## 七、实施顺序（建议分批，每批输出约束对照表）

| 批 | 模块 | 内容 | 验证 |
|----|------|------|------|
| **批 1** | M4 后端算法 | `localPatchOps.ts` + `localPatch.ts` + `router.ts` | `cd localTool && npm test` |
| **批 2** | M1 上下文契约 | `localPatchContext.js` + `useLocalPatchContext.js` + 单测 | vitest 单测 |
| **批 3** | M2 选区提取 | `LocalPatchExtract.jsx` + ImageNode 入口 + API 封装 | 手动 + build |
| **批 4** | M3 融合节点 | `ImageMergeNode.jsx` + 三处注册 + 组件测试 | smoke/regression/build |
| **批 5** | 收口 | 中间生成节点自动继承收口、对比原图、多图选择、错误透传、CONTEXT/contracts 登记 | `npm test` 全量 |

> **M1 传播边界（审计定案，2026-08-20）——中间生成节点自动继承是必做核心，不是增强项**：
> 插件核心工作流「提取 → **生成节点处理局部图** → 融合回原图」依赖它。若跳过，局部图经生成节点后 cropContext 丢失，融合必失败。**实现路径（唯一）**：
> - 在 `useNodeGeneration` 的 `onSuccess` 写回 `node.data` 之后，注入 `useLocalPatchContext` 的通用步骤：取直接上游 images，`applyInheritedContext` 计算继承，写回 `data.cropContext`/`data.cropContextConflict` + `rememberContextMetadata`。
> - 该步骤做成 hook，图片产出节点按需启用（见 §1.4）。
> - **不接入的节点视为半成品**，批 5 收口时逐节点核对「局部图经过它是否保留上下文」。
>
> ⚠️ **风险提示**：局部图经生成后「文件指纹可能变」（生成输出新文件），注册表按指纹恢复可能失效。**核心恢复路径是「随节点 data 传播 + 注册表按 URL 恢复」**，指纹恢复只是补充（对齐插件 `localPatchFingerprint` 随图带）。写码时以「节点 data 传播」为主锚点。
