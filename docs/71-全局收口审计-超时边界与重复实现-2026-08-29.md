## 一、一句话结论

同一类缺陷在全库存在多个副本：**超时只覆盖「等响应」、不覆盖「读响应体」**，以及**已有统一出口却各起炉灶**。已修 3 轮（§二），尚存 4 处真 bug（§三）、6 组重复实现（§四）、2 项设施不统一（§五）。

## 三、P0：仍存在的真 bug（用户可见故障）

### 3.1 `useLocalToolStatus.js` —— 连接轮询会自杀，断线后永不恢复 ✅已复核

```94:98:src/components/base/useLocalToolStatus.js
function restartPoll() {
  if (pollTimer) clearInterval(pollTimer)
  pollTimer = null
  schedulePoll()
}
```

`schedulePoll()` 开头是 `if (disableLocalTool || pollRunning) return`（`:86`），而 `pollRunning` **从未在 `restartPoll` 里重置**——只有所有订阅者都卸载时才置 false（`:113`）。

时序：首次订阅 → `schedulePoll()` 置 `pollRunning=true` 并起 5s interval → 连上后 `isConnected` false→true 触发 `useEffect`（`:123-125`）→ `restartPoll()` 杀掉 interval → `schedulePoll()` 被 `pollRunning=true` 挡回 → **新 interval 永不创建**。

- **影响**：localTool 连上之后，前端的断线检测彻底失效。之后关掉 localTool，界面永远显示"已连接"。
- **修法**（净减 5 行）：把「清旧 timer」并入 `schedulePoll` 使其重入安全，删掉 `restartPoll`，`useEffect` 里直接调 `schedulePoll()`。

### 3.2 `proxyGenerate.js:361` —— responses 生图分支 `res.json()` 无超时 ✅已复核

```361:361:src/components/base/proxyGenerate.js
      const imgUrl = parseResponsesJson(await res.json())
```

同一函数里 392 行的 SSE 分支**包了** `withTimeout(..., GEN_TIMEOUT)`，就这个 responses 分支漏了。与 §二 `89f4a0b` 修的 `chatProxy` 是同一个病：响应头先到、body 悬挂 → 生图节点永久 loading。

- **修法**：`await withTimeout(res.json(), GEN_TIMEOUT, '生图超时', signal)`，与 392 行对齐。

### 3.3 `upstreamLink.js:39` —— 下游触发失败被全吞 ⚠️待复核

`runNodeGeneration(target).catch(() => {})`：下游自动重算失败时零日志零提示，且外层 `try/catch` 捕获不到这个 rejection。

- **影响**：用户看到"下游就是不生成"，排查无任何痕迹。
- **修法**：`.catch(e => logger.warn('拓扑', '[G1] 下游触发失败', { target, error: e?.message }))`。

### 3.4 `useNodeGeneration.js:149` —— 落盘失败却报成功 ⚠️待复核

`.catch(() => null)` 吞掉 `saveResultToTasks` 失败，随后照样 `taskCtl.done()` 报成功。

- **影响**：用户以为图存好了，刷新发现没了。违反 §5.5.1「任务中心为结果权威源」红线。
- **佐证**：同语义的 `scriptBoxEngine.js:379` 落盘失败有 `logger.warn`，`:392` 却静默——同一文件内两种处理。
- **修法**：改 `reportDegrade({ layer: 'useNodeGeneration', key: 'saveResultToTasks', e })`。

## 六、沉淀的准则（防止再犯）

1. **超时要包住"整段任务"，不是"单次请求"。** 响应体读取（`res.json()` / `res.blob()` / SSE `reader.read()` 循环）位于 `httpClient` 超时闸门**之外**，是最容易漏的一环。新增任何前置 `await`（图片归一、落盘）同理。收口方式：在任务边界（`runAbortable`）加总闸，一处覆盖所有环节，未来新增 `await` 自动受保护——不要在每个内部点逐个补（打地鼠）。
2. **阈值一律进 `config.js`，且用已有常量推导**（如 `SCRIPT_TEXT_TIMEOUT = CHAT_TIMEOUT + 60000`），不写裸数字。改一处即全库生效。
3. **建了统一出口就必须拆掉旧实现。** `asyncGuard.js` 早就写着"替代 faceMosaic.loadImage"，但拖了很久没拆，期间又新长出两份无超时的私有 `loadImage`——**收口半途而废比不收口更危险**（文档说已统一，代码没有）。拆时先比对语义差异（`resolve(null)` vs `reject`），必要时在统一出口补宽容版（如 `loadImageOrNull`），不要硬套。
4. **同语义两套数值是 bug 不是风格问题。** 会话水化超时 8s/5s 并存即为一例，会出现"一边已放弃、另一边还在等"。
5. **loading 状态的复位路径要覆盖所有分支**，尤其"提前 return"和"异常"两条。优先让状态派生自单一数据源（如 `data.genMask`），而不是组件本地 state——后者会在切步骤/关弹窗卸载时丢失。
