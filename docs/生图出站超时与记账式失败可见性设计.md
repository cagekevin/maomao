# 生图出站超时与记账式失败可见性设计

> 目标：生图请求"发不出去"时，前端**尽早明确失败**，而不是毫无感知地卡死。
> 红线（不可违背）：**绝不允许重发导致重复生图**；长生成（SSE/轮询）不受影响。

---

## 1. 当前链路事实

生图请求统一由 `src/components/base/api/proxyGenerate.ts` 的 `__proxyFetch` 经 `httpRequest` 出站。该调用约定为 `retries: 0`（防止传输层自动重试把同一生图请求发两遍、造成供应商侧双扣费/双图）。

### 1.1 超时覆盖现状

| 阶段 | 超时配置 | 说明 |
|------|----------|------|
| 出站握手（建连 + 响应头） | `PROXY_CONNECT_TIMEOUT = 30000`（`config.ts`） | 注入 `httpRequest` 的 `timeoutMs`，替代原 `timeoutMs: 0`；只掐"连不上/接住不回头"，不覆盖生图本体 |
| 响应体/流读取（长生成） | `GEN_TIMEOUT = 300000`（5 分钟） | 覆盖 SSE 同步分支（`withTimeout(readSseUrl(...), GEN_TIMEOUT)`）、`responses` 分支（`withTimeout(res.json(), GEN_TIMEOUT)`）、异步轮询总时长（`pollUntilDone` 的 `timeoutMs`） |
| 异步提交响应体首字节 | `PROXY_CONNECT_TIMEOUT` 包住 `res.json()`（`pollUntilDone`） | 建连成功但不吐 body 时，30s 内判失败 |
| 异步轮询响应体首字节 | `PROXY_CONNECT_TIMEOUT` 包住 `pr.json()`（`pollInFlight`） | 同上，补齐轮询挂死点 |

`PROXY_CONNECT_TIMEOUT` 与 `GEN_TIMEOUT` 互不冲突：握手毫秒级完成，30s 连接超时不会误伤正在进行的生图；体读取仍由 `GEN_TIMEOUT`(5min) 保护。

### 1.2 两类"发不出去"

1. **挂死（握手/body 不回头）**：代理接住连接但不回响应头/不吐 body。现由 `PROXY_CONNECT_TIMEOUT` 在 30s 内判 `TimeoutError`，不再永久卡死。
2. **瞬时抖动直接失败**：硬性断网（`TypeError`/`NetworkError`）因 `retries:0` 秒级判失败，任务进 `failed` 态，可见但无自动重试（仅手动"再来一次"）。

### 1.3 失败如何到达前端

`__proxyFetch` 抛错 → facade（`imageProxy`/`pollUntilDone`/`pollInFlight`）捕获后经 `classifyError` 归类 → 返回 `{ ok:false, error }`（`fail(...)`）→ 上抛至 `useNodeGeneration` 的 `start().run` catch：`taskCtl.fail(msg)` + `showToast` + 节点红字 + `logger.error`。

**结论**：前端"显示失败"的机制本来就在；握手/body 阶段现已能真正失败，挂死不再无法感知。

## 2. 架构约束与设计要点

### 2.1 握手/响应体超时兜底（已实现）

- `config.ts` 的 `PROXY_CONNECT_TIMEOUT = 30000` 注入 `httpRequest` 的 `timeoutMs`；`retries` 维持 `0`。
- 三处"建连成功但 body 不流动"的裸读（`pollUntilDone` 的 `res.json()`、`pollInFlight` 的 `pr.json()`、`responses` 分支的 `res.json()`）均包进 `withTimeout`。
- `withTimeout` 的超时分支**不传任务级 `signal`**：超时只 `reject`，不 `abort` 用户取消信号，以免被 `AbortError` 分支误判为"已停止"。悬挂连接随任务结束回收。
- 只 `abort` 底层死连接、不重新提交，守住 `retries:0` 红线。

### 2.2 记账态机与"不可重发"约束（现状）

- 前端贯穿全链的 `payload.taskId` 与回收字段 `pollTaskId`（`setTaskPollId(...)`，供 `pollTask` 刷新后恢复）已实现。
- **网关无幂等**：`apimart-gateway/_do_submit` 每次提交都新建 `thread_id`（网关侧 `task_id = "task_" + thread_id`），前端传入的 `taskId` 不被当作幂等键。因此"挂死后用同一 taskId 重发"会**再建一个线程 → 双生图/双扣费**。
- 因上述约束，**当前不实现"提交失败自动重发"**。失败仅暴露给前端（任务中心失败态 + 红 toast + 节点红字 + logger），由用户手动"再来一次"（用户主动操作，且非幂等风险由用户已知）。
- 安全恢复路径（待实现，非当前架构）：补前端 `x-task-id` 头透传 + localTool 按 `frontTaskId` 持久化 `thread_id`，改为"按已有 thread 续查"而非重发。

### 2.3 前端感知（复用既有机制）

失败展示已具备（`taskCtl.fail` + `showToast` + 节点红字）。本设计让握手/body 阶段真正失败，并把"提交失败"与"生成失败"在提示上区分。无新增通知通道。

## 3. 红线校验（当前架构事实）

| 红线 | 是否满足 | 说明 |
|------|----------|------|
| 不重发导致重复生图 | ✅ | `retries:0` 保持；连接/body 超时只 `abort` 死连接，不重新 POST；且不实现自动重发（网关无幂等） |
| 长生成不受影响 | ✅ | `GEN_TIMEOUT`(5min) 对 SSE/轮询体读取原样保留，握手/body 首字节超时不替代它 |
| 用户取消仍生效 | ✅ | `signal`/`AbortController` 透传链路不变；`withTimeout` 超时分支不污染同一 `signal`，取消与超时互不误判 |
| 流式能力不变 | ✅ | `parseJson:false` 保留（流式必需），仅给握手 + 响应体首字节加超时 |
| 既有轮询恢复不破 | ✅ | `pollTaskId` / `pollTask` 机制不变 |

## 4. 当前实现清单

1. `src/components/base/config.ts`：`PROXY_CONNECT_TIMEOUT = 30000`。
2. `src/components/base/api/proxyGenerate.ts`：
   - `__proxyFetch` 内 `httpRequest` 的 `timeoutMs` 为 `PROXY_CONNECT_TIMEOUT`（保留 `retries: 0`）。
   - `pollUntilDone` 的 `res.json()`、`pollInFlight` 的 `pr.json()`、`responses` 分支的 `res.json()` 均包进 `withTimeout(...)`（不传任务级 signal）。
3. `src/components/base/taskStore.ts`：`pollTaskId` / `setTaskPollId` 支持刷新后恢复轮询。
4. 失败透传：经 `useNodeGeneration` 同帧上抛 节点红字 + 任务中心失败态 + 全局红 toast + `logger.error`。

---

## 5. 验证要点

- **挂死**：localTool 接连接不响应 → 30s 内任务中心标红 + toast，不再永久卡死。
- **正常生图**：本地起服跑一张图，SSE/轮询正常完成，30s 握手超时未误伤（头毫秒到达）。
- **用户取消**：生图中点取消 → 任务进入取消态（"已停止"），不误把超时当取消。
- **不双生图**：因网关无幂等且不实现自动重发，挂死后不会静默触发第二次有效生成。
