# 架构收口 Master Plan（2026-08-19）

> 基于四路并行架构扫描（状态管理/错误处理/技术债/契约分散）汇总。目标：**一次性制定总图，避免"今天改完明天又冒新债"**。
> 所有结论为只读分析。落地原则：测试先行 + 最小差异 + 单 commit 单关注点。

---

## 〇、核心判断（为什么之前是零散改）

之前几次改动（真相源契约、自查表）只解决了"生成结果写哪"这一个切面。但四路扫描暴露：**真正会让你反复返工的根因不在某条规则，而在两处基础设施缺失**——

1. **契约登记表是"文档"不是"代码"**：`contracts.js` 的 `STORAGE_KEYS`/`EVENTS` 没有任何业务文件 import，全靠人工 grep 维持红线。改一个 key/事件名无编译期拦截 → 明天必漏。
2. **节点没有统一写入口**：`patchData`/`setNodes` 样板在 12 文件 30+ 处散落，每个节点各自写"结果回写/错误回写/防抖/供应商加载"。新节点每加一个就复制一遍 → 一致性永远靠人记。

**只要把这两处基础设施补上，后续所有收口都变成"机械替换"，无需再动节点逻辑。** 所以 master plan 以"先修基础设施、再机械替换"为主线。

## 三、P0-基础（必先做，本计划地基）

### P0-1：契约强制化（让红线可编译）
- 把 `contracts.js` 的 `STORAGE_KEYS` / `EVENTS` 从"文档表"改为**强制导出常量**，全工程 grep 替换裸字符串为 `STORAGE_KEYS.xxx` / `EVENTS.xxx`。
- 修正 `canvas-state-v1-` 双定义（`contracts.js:112` vs `kvStore.js:22`）→ 单一来源 `kvStore.CANVAS_STATE_PREFIX`。
- 加 lint/eslint 规则：禁止裸 `localStorage` key 字符串、禁止裸 `publish('xxx')` / `useNodePrefs('xxx')` 字面量（强制引用常量）。
- **修正 `mutiwindow-clipboard` 拼写**（趁此统一，否则固化进契约更难改）。
- 节点 `type` 裸字符串（20+ 处）抽 `NODE_TYPES` 常量表强制 import。
- 信封格式 `t.data[0].url` / `r.data` 散落读取抽 `envelope.js` 单一函数。
- 产出：1 个 commit（`contracts` 强制化 + lint 规则），全量单测验证。

### P0-2：节点统一写入口（消除样板根）
- 抽 `useNodeData(id)`：封装 `patch`/`patchDebounced`（统一 200ms 窗口）、防抖窗口提 `config.js` 常量，返回供节点单调用。消除 12 文件 30+ 处 `setNodes` 样板。
- 抽 `useGenerateNode({ type, resultField })`：封装"选 provider→组参数→双写 prefs→onSuccess 写回→onRecover 回填"，覆盖 Prompt/Text/Template/DiscountVideo + 未来节点。
- `providerStore` 加懒加载（首次访问自动 load），删 4 处节点内 `useEffect` 加载样板。
- `useNodeGeneration` 内部收到 `agent:task-completed` 自动 `patchData({[resultField]:resultUrl})`，节点不再各自写 `onRecover` 样板（原 3 处删除）。
- 产出：1-2 个 commit，已接 4 节点先回改验证，全量单测验证。

### P0-3：依赖版本错配（立刻修，否则类型问题永改不完）
- **`@types/react@18` / `@types/react-dom@18` 配 `react@19` 大版本错配**（package.json 第49–50行 vs 36–37行）。类型定义落后运行时一整代，React19 的 `Ref`/`use()`/JSX 命名空间差异在 IDE/tsc 持续误报；叠加 `tsconfig` 的 `skipLibCheck:true`+`strict:false` 让问题长期看不见。
- 修：`@types/react`/`@types/react-dom` 升 `^19` 重装；后续 `tsconfig` 逐步开 `strict`（至少核心 `.js` 开 `checkJs`）。
- **Duplicate zustand**：业务 `4.5.7` vs `@react-three/fiber`/`drei` 嵌套 `5.0.15`（package-lock 第1068/1145行）。在 `package.json` 加 `overrides` 收敛，避免双实例订阅偶发 bug。
- 产出：1 个 commit（依赖修正 + lock），`npm run test:unit` 验证类型不再误报。

### P0-4：前后端死路由 / 跨端数据对齐（防"前端改完后端炸"）
- **后端死路由**：`localTool/src/routes/` 下 `official.ts`/`platform.ts`/`admin.ts`/`agentChat.ts` 大量端点前端零调用（`/api/public/platform/models`、`/api/agent/:id/chat` 等）。在 `contracts.js` 或路由表标记「预留/上游转发」，避免后端改契约前端无感知。
- **数据源二选一**：`/api/public/platform/models` 与前端 `providerModels.js` 的本地 `buildAllModels` 是两套模型源，须统一（留其一）。
- **跨端数据无迁移**：画布 KV 快照 schema 演进无 migration，读旧 `projectId` 直接套旧结构易崩；`projects`/`tasks` 存储格式无版本号。补 schema 版本号 + 兼容读取（旧结构默认字段）。
- **后端地址 4 处硬编码**（`config.js`/`background.js`×2/`useLocalToolStatus.js`），且 `localhost`/`127.0.0.1` 写法不一。抽单一常量统一引用。
- 产出：1 个 commit（死路由标注 + schema 版本号 + 地址常量化）。

> **P0 完成标志**：① 加节点不再写 `patchData`/`setNodes`/`onRecover`/供应商 effect；② 改任意存储 key/事件名编译报错；③ `@types/react` 与 react 同代、无类型误报；④ 前后端模型源唯一、跨端数据有版本兼容。

## 四、P1（P0 之后，按依赖顺序）

### P1-1：本地节点状态契约
- `node.data` 定义统一 `status: idle|running|failed|done` + `error` + `progress`（与 taskStore 字段对齐）。
- 提供统一 helper：`setNodeStatus(id, status, {error, progress})`，所有节点（含未接 hook 的 13 个）错误/成功态走它，刷新不丢、外部可查。
- 旧 `errorMessage` 字段做兼容映射（读取时归一）。

### P1-2：取消/超时/重试收口
- 本地重计算节点（VideoExtract/FaceMosaic/GridSplit/GridMerge）套 `withTimeout`（复用 VideoProcess 已有）+ 可取消 token，消除永久 loading。

- VideoProcess 自带的 `withTimeout`/`ProgressController`/`AbortController` 适配进 `useNodeGeneration` 的 `run({signal,progress})`，删第二套实现（原 R-02）。
- ScriptBox 引擎外层统一 `catch → toast + genMask 复位`（原 R-03）。

### P1-3：降级透明度（轻量，可与 P1-1 同批）
- 集中降级日志 `reportDegrade(layer, key, e)`；关键降级（画布 KV→localStorage）弹一次 toast。

### P2-4：撤销/重做一致性（已核实：两处真缺口）
- **加载画布快照不重置 history（P1 真缺口）**：`src/App.jsx:96-139` 加载 effect 只 `setNodes/setEdges`，`既不 clear 也不 record`；而 `clear` 只在显式切换/新建项目（`App.jsx:313,327`）调用。走 `project:import`/`initProjects`/外部 `activeProjectId` 重载路径时，旧栈残留 → 首次 Ctrl+Z 用**旧项目整图**污染当前画布。修：加载成功分支开头 `history.clear()`。
- **生成结果回填不在 undo 栈（P1）**：`patchData`（`TemplateNode.jsx:126-128`）只 `setNodes` 不 `record`，而 history 快照是**含 node.data 全量**的整图（`App.jsx:252`）。生成后再做结构操作、连续 Ctrl+Z 到生成前快照，会把已生成图/视频一起回滚成空。修：评估关键 data 回填是否 atomic `record` 或显式排除。
- **任务中心状态不进 history（P2，设计预期）**：`taskStore.js:23` 独立模块态，与 nodes/edges 解耦，不被撤销影响——符合预期，仅需文档澄清。

### P2-5：objectURL 内存泄漏（已核实：两处真缺口）
- **`VideoExtractNode` 创建不释放（P1）**：`VideoExtractNode.jsx:208` `previewUrls.create(file)`，全文件无 `release/revoke`（`:282` 函数结束无释放）。重复上传处理累积泄漏。修：`startExtract` 的 `try/finally` 或卸载 cleanup 中 `previewUrls.release(src)`。
- **`previewUrls.clear()` 无调用点（P1）**：`previewUrl.js:50-55` 定义 clear() 兜底，但删除节点（`groupNodes.js:117`）/切换项目（`projectStore.js:190`）/清空画布**均未调用**。修：在画布生命周期边界（switchProject / deleteNodesWithCascade / 清空）统一收口 `clear()`。
- 注：`VideoProcessNode.jsx:859` 的 `URL.createObjectURL(gif.blob)` 不走 previewUrl，按 `previewUrl.js` 注释属"持久节点源降级"（刷新失效），可登记统一回收。
- **节点重渲染已治理（误报，勿动）**：17 节点均 `React.memo`；写回均不可变 `setNodes` 只换目标节点引用；仅 `PanoramaNode.jsx:54` 带 selector 订阅。此项不需修复，新节点保持该范式即可。

### P2-6：全局错误兜底 + 环境配置源（已核实）
- **全局未捕获错误/未处理 rejection 无兜底（P1）**：`ErrorBoundary`（`main.jsx:14` + `ErrorBoundary.jsx`）已包裹根组件且 `componentDidCatch` 已接 `logger→/api/logs`（`ErrorBoundary.jsx:29`），渲染期崩溃可上报。但 `window error/unhandledrejection` 监听**全 src 零命中**——异步回调/非渲染期 JS 异常完全无兜底、无上报，线上报错"用户不反馈看不见"。修：`main.jsx` 加全局 `error`/`unhandledrejection` 监听，统一 `logger.error` 上报。
- **API 地址硬编码不读 env（P1）**：`config.js:15` `API_BASE='http://127.0.0.1:18080'` 硬编码，`.env.example:8` 的 `VITE_API_BASE` 全 src **0 命中**（死配置）。修：`API_BASE = import.meta.env.VITE_API_BASE || 'http://127.0.0.1:18080'`，让 env 生效。
- **127.0.0.1 vs localhost 分裂（P2）**：`background.js:3` 默认 `localhost:18080`、`:93` 上传又写死 `127.0.0.1`（且未用 L3 的 `getLocalToolBaseUrl()`）——自相矛盾。修：统一抽单一 `LOCAL_TOOL_BASE` 常量源，background 上传改用 `getLocalToolBaseUrl()`。

## 六、执行纪律（防反复）

1. **P0 不动节点逻辑之外的重构**——只建基础设施 + 机械替换。
2. **每波单 commit 单关注点**，commit 信息标注波次（如 `refactor(contracts): P0-1 强制化 STORAGE_KEYS/EVENTS`）。
3. **每 commit 跑 `npm run test:unit` + `test:smoke`**（pre-commit 已自动），P0-2 回改后重点看 4 个生成节点测试。
4. **新节点一律走 `useGenerateNode` + `useNodeData`**，老节点冻结不回改（除非 P1 明确需要）。
5. **CLAUDE.md / CONTEXT.md 同步**：P0 完成后把"节点必须走 useNodeData/useGenerateNode""契约必须 import 常量"补进红线。

## 七、风险与权衡

- **最大风险**：P0-2 动 `useNodeGeneration` 契约层，回归面覆盖全部生成节点。缓解：已合规 4 节点先回改验证 + 1389 单测兜底 + 不在 P0 动 13 个未接节点。
- **不要做的事**：不要一口气把 13 个老节点全接入 hook（触发 regression 雷区）；不要先拆上帝模块再补基础设施（拆完仍散）。
- **收益拐点**：P0 完成 = 后续 P1/P2 从"逐节点手术"变"批量机械替换"，且红线可编译保障，明天不会再因"改 key 漏网/新节点漏写回"返工。
