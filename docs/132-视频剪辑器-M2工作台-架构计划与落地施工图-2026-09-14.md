## 〇、一句话结论

**M2 = 在 M1 基座上方长出一个工作台（监视器 + 检查器 + 两种新轨），M1 的每一颗按钮一位不移。**
它的复杂度**不在 UI**，在**三处地基收窄**：
1. `Clip` 的四个 `unknown` 字段**收窄成真实类型**（只改类型、无数据迁移 —— 这是 M1 刻意留的地基缝）；
2. **渲染路径分叉**：M1 的 `renderFrameAt` 只做「contain 一帧」，M2 要拆成**预览（实时、可丢帧）与导出（逐帧、确定）共用同一套变换求值器**，否则必然漂成两份（C8 母体）；
3. **片段种类从 3 → 4**（新增 `text`），牵动 `routeClipToTrack` / `normalize` / 各判据的**单点**。

### 2.2 变速：**已取证的正确性分析**（★重写 2026-09-14，前一稿判断错误）

用户口径「2x = 时长减半，轨道上片段实时变短」与 M1 的**时间纪律 T2** 冲突：
```
T2：duration = sourceEnd - sourceStart，且 clipEnd = timelineStart + duration —— 两者都是「派生量，不落盘」。
```

**★前一稿的错误**：我把口径 B 描述成「破 T2 + **5 处**源时刻换算全要改，逐处改必漏」。
**取证后推翻**：那几处**不是**各自独立的换算，而是**同一个映射**（已下沉的共用原语
`base/utils/timeline/sourceTime.ts::sourceTimeAt`）。只要改原语一处，全部跟随。

**但取证同时暴露了真问题**（这才是必须的前置）：
> **该原语在剪辑器内 0 采纳** —— 7 处全是内联重写（`timelineOps` ×4 / `composite` 渲染 ×1 /
> `PlaybackSink` ×1 / `mixClip` 源窗口 ×1）。根因是 `check-arch` 规则 4 的白名单**只放行
> `base/core/idGen.ts`**，`core/` 调不到 `base/utils/timeline/`。
> ⇒ **若不先收口，变速要改 7 处，漏 1 处 = 静默错**（画面位置漂、声音对不上）。

**故已先执行「计划前收口」（§八 P-1，2026-09-14 完成）**：7 处内联 → 8 处调用原语。
**收口后，变速的正确性落点收成 3 处**：

| # | 落点 | 内容 |
| --- | --- | --- |
| 1 | `base/utils/timeline/sourceTime.ts` | **唯一映射实现**：`sourceTimeAt` 内部乘 `speedOf(clip)`（曲线则按点求值）；`timelineTimeAt` 为其反函数。**预览 / 导出 / 播放 / 混音 全部只问它** |
| 2 | `core/timelineOps.ts` | `clipDuration` = `(sourceEnd - sourceStart) / speedOf(clip)`；`splitAt` 等 4 处**已调原语**，自动跟随 |
| 3 | `core/routeClip.ts::needsCompositing` | 补 `clip.speed !== undefined` → 变速**必走合成**（否则被无损直通静默忽略 —— §三.4） |

> **`speedOf` 是 `magneticOf` 同型的唯一读值处**（`speed` 缺省 = 1），禁止各调用点内联 `?? 1`。

**曲线形状（用户已定）**：**点可增删**，横轴取**归一化位置 ①**（推荐并被采纳）：
```ts
speed?: number | { points: { t: number; v: number }[] }   // t ∈ [0,1] 片段内百分比；v = 倍速
```
- **归一化的理由（正确性）**：`t` 与真实时长解耦 ⇒ **变速本身改变时长，不会破曲线**（若用绝对秒数，每次变速都要重算全部点，拖完即错位）；
- 求值 = 相邻点线性插值（`points` 已按 `t` 排序；单点 = 常数倍速，等价于 `number` 形态）；
- 拖点 = 改该点的 `(t, v)`；增删点 = 增删数组项。**至少 2 点**（1 点为常数，用 `number` 表示更诚实）。

**复杂度位置（用户口径「保证复杂度在合适的位置」）**：
`speed` 的语义**只活在映射层**（`sourceTime.ts` + `timelineOps`）；预览 / 导出 / 混音 / UI
**只问映射结果，不各自解释 `speed`**。⇒ 曲线有多复杂（点数、插值、拖拽），都不会外溢。

### 3.3 真缝隙 A：右键菜单的**坐标基底**（M2 顺手要收的口）

### 3.4 真缝隙 B：`needsCompositing` 的判据缺口（**正确性，非结构**）

`routeClip.ts:104-111` 判 ⑤ 时**不看 `clip.speed`** → 变速片段会被判「可直通」，而 `runDirect`（`pipeline.ts:249`）**原样搬运已编码分组** → **变速被静默忽略**，用户拿到的成片速度没变。
**处置**：⑤ 补 `clip.speed !== undefined`（与 transform 同一条「M2 加工 → 必合成」）。**这是 7 步法 Step 4 的「禁假成功」**。

### 8.6 ★修正：`mixClip` 的改法不是最优（收口时暴露的真 bug）

**第一版改法**（等价改写）：
```ts
const timeInClip = timelineTimeAt(wrapped.timestamp, clip) - clip.timelineStart;  // 加回来
const startSample = Math.round((clip.timelineStart + timeInClip) * MIX_SAMPLE_RATE); // 又减掉
```
**两行互相抵消** = 纯噪音。**更严重的是它在变速下会算错**：
- `duration`（= `sourceEnd - sourceStart`）是**源侧**的量；
- `timestamp - sourceStart` 也是**源侧**的量；
- 但输出缓冲的样本位是**时间轴侧**的量。M1 两侧同刻度故无差别；**变速后差一个倍率** ⇒ 音频写错位置。

**修正**：整段走时间轴侧 —— `timelineTimeAt(ts)` 直接落样本位；越界判定也改为比较
`timelineTime >= clip.timelineStart + duration`（同一侧的量，变速后仍成立）。

> **教训（记入方法）**：收口的目标不是「让两处代码长得一样」，而是**「问这个消费方真正需要哪条映射」**。
> 我把「等价改写」当成了目标，于是写出 `- x + x` 这种自己被自己抵消、却在变速下失效的代码。
> 这正是 Step 3 说的「搬新家 ≠ 消灭复杂度」的一个变体：**形式归一了，语义没归一**。

> **#4 / #16 / #5 / #6 / #12 / #17 —— 全部是「二分判据」在第三种 kind 出现时的失效。**
> 它们现在写的是 `kind === 'audio' ? A : B` 或 `kind === 'video'`，
> **加第三种时，这些二分不会报错，只会静默走错分支**。

**⇒ 提出一条前置建议（P-3 产出，待你定）**：

**把二分判据改成「显式穷举」形态** ——
```ts
// 现在（加第三种静默失效）
return clipKind === 'audio' ? 'audio' : 'video';

// 改为（加第三种时 TS 报错，强制处理）
const ROUTE: Record<ClipKind, TrackKind> = { video: 'video', audio: 'audio', image: 'video' };
return ROUTE[clipKind];
```
- **收益**：`ClipKind` / `TrackKind` 加值那天，**编译器点名所有需要处理的点**（不再是静默错分支）；
- **代价**：`Record` 比三元略长；

### P-4 · `dockContract` 守卫改「按形态」的方案验证 ✅ 已完成

**问题（取证）**：守卫的 `describe` 名是「**常驻层**不得登记 modalLayer」，
但**实现**是「扫 `panels/dock/` 整个目录」。M2 工作台（`panels/workbench/`）**需要** portal
（要盖住顶栏），若放进 `dock/` 就撞守卫 —— 而它**并不常驻**，本不该受此约束。

**改法：按**形态**判，不按**目录**判**（与 P-1 同款手法）：

| | 实现 |
| --- | --- |
| 标记形态 | 11 个 `dock/` 文件各带一行**注释 token** `// DOCK_IS_PERSISTENT` |
| 守卫判据 | `collectEditorFiles()` 递归扫 `videoEditor/**` → `isPersistent(file)` 读原文找 token → 只对这些文件断言「不含 portal / FullscreenShell / document.body」 |
| 有效性保险 | 新增断言「**`dock/` 每个文件都必须带标记**」—— 防「新文件忘声明 ⇒ 守卫静默失效」 |

**为什么标记是注释、不是常量（三次试错的结论）**：

| 试过的形态 | 撞什么闸 |
| --- | --- |
| `export const DOCK_IS_PERSISTENT = true` | ❌ `check:dead-code`（knip 报未使用导出，11 条） |
| `const DOCK_IS_PERSISTENT = true` | ❌ `check:type-check`（`noUnusedLocals` 报 TS6133，不读即错） |
| **`// DOCK_IS_PERSISTENT`（注释 token）** | ✅ 零运行时成本、零导出、`check:catch` 的「strip 后判」也不受影响 |

> **结论：标记必须是「纯声明」** —— 它不该是代码，只是给守卫看的一枚坐标。
> 这反过来印证了 P-4 的立意：**守卫应该读「声明」，而不是读「代码里有没有某个符号」**。

**探针（先红后绿 · 2 项）**：

| 探针 | 注入 | 实测 |
| --- | --- | --- |
| A | 给带标记的常驻文件追加 `const probeBody = document.body;` | ✅ 精确红：`声明为常驻的文件不用 portal` |
| B | 删掉某文件的标记（模拟新文件忘声明） | ✅ 精确红：`【守卫自身有效性】dock 层每个文件都带常驻声明` |

### P-6 · 判据「可穷举化」+ 直接落地 `text` 类别 ✅ 已完成（2026-09-14）

#### 6.1 机制先行：三类「静默失效」的判据全部改造

| 手法 | 用在哪 | 为什么 |
| --- | --- | --- |
| **`Record<K, V>` 穷举** | `TRACK_OF_CLIP` · `TRACK_ID_PREFIX` · `TRACK_DEFAULT_NAME` · `DEFAULT_OVERLAY_OF` · `ORDINAL_PREFIX` · `TRACK_ORDINAL_CLASS` | 三元表达式在新增 key 时**不报错、静默归位**；`Record` **缺键即 TS2741**。刻意**不用 `switch`+`default`** —— `default` 就是「兜底」，正是要消灭的东西 |

| `new Set([...])` | ❌ 推出 `Set<string>` ⇒ 同样宽化 |
| **`as const` 数组 + `kindSetOf()`** | ✅ 保住窄字面量联合 |
