## 2. ⚠️ 核心发现：按错误数排序会误判优先级

handoff §4 的 M4 策略是「**按错误数从大到小**逐个解」。在 strict 视角下这条会踩坑：

| 文件 | 总错 | 噪音 | **真实** |
|---|---:|---:|---:|
| `accountsStore.test.ts` | 95 | 95 | **0** |
| `providerStore.test.ts` | 92 | 92 | **0** |
| `logger.test.ts` | 62 | 62 | **0** |
| `scriptBoxEngine.deep.test.ts` | 52 | 52 | **0** |
| `inputStateMachine.test.ts` | 48 | 48 | **0** |

**错误数最多的 5 个文件（合计 349 错）真实隐患为 0**，全是隐式 `any` 噪音。
若按 handoff 的排序，前几批会全部耗在这批「看着吓人、实则无隐患」的文件上。

> 修正建议：**优先级改按「真实错误数」排**，噪音型放到最后统一批量加标注。

## 4. 对 handoff M3 的细化修正

handoff §6c 提交十把 `useAgentChat.hook` 与 `canvasAgentTools` **并列**为「M3 深化、待 src 收口」。
探针显示两者**性质完全不同，不该并列处理**：

| 文件 | 真实错 | 主导错误码 | 结论 |
|---|---:|---|---|
| `canvasAgentTools.test.ts` | 86 | **TS2322×49**、TS2339×20、TS18048×14 | 94% 是真实类型不匹配 → **确实是 src 收口问题，M3 靶心成立** |
| `useAgentChat.hook.test.ts` | 21 | **TS7005×40**、TS7006×20 | 75% 是隐式 `any` 噪音 → **src 收口收益低，应先补测试侧标注** |

> 即：handoff 的 M3 判断对 `canvasAgentTools` 完全正确；
> 但 `useAgentChat.hook` 的 84 错里 63 个只是没写标注，不应占 M3（动 src）的额度。

## 5. 本轮已修（3 个「只差 1 处」的低风险文件）

挑选原则：**优先 TS18047/TS18048/TS2339 真实隐患**，跳过纯隐式 `any` 噪音。

| 文件 | 问题 | 修法 |
|---|---|---|
| `GridSplitNode.test.tsx` | `closest('button')` 可能 `null`，直接读 `.disabled` | 可选链 `btn?.disabled` |
| `ImageNode.test.tsx` | `querySelector` 可能 `null`，直接调 `getAttribute` | 可选链 `img?.getAttribute(...)` |
| `pendingRecovery.test.ts` | `r.attachments` 类型上可选，直接读 `.length` | 可选链 `r.attachments?.length` |

三处都是「上一行已有 `expect(x).toBeTruthy()` 断言存在」的场景：
加可选链后**运行时行为完全不变**，但万一元素/字段真的缺失，会由那行断言给出明确失败原因，
而不是被 TypeError 顶掉。修复后这 3 个文件在 strict 探针下**已 0 错**。

## 6. 给 M3/M4 的建议（按本轮数据修正）

1. **不开 strict**（4309 错会让门禁长期红灯），继续走 handoff 的渐进路线。
2. **排序口径改按「真实错误数」**，别按总错误数——Top5 重灾文件真实隐患为 0。
3. **先吃「准干净」文件**：当前 134 个有错文件里约 **23 个只差 1~2 处**，几乎零风险，可一把清零。
   ```bash
   npx tsc -p tests/tsconfig.strict.probe.json --noEmit 2>&1 \
     | grep -oE '^tests/unit/[^(]+' | sort | uniq -c | sort -n | head -30
   ```
4. **M3 动 src 的靶心聚焦 `canvasAgentTools`**（86 真实错、TS2322 主导，与 handoff 判断一致）；
   `useAgentChat.hook` 先按测试侧补标注处理，别占 M3 额度。
5. 噪音型 2593 错最后统一处理，可考虑批量加标注的机械改动。
6. 复判标准沿用 handoff 踩坑 #17：**IDE `read_lints`（真实文件）+ `vitest` 实跑**，
   而非任何"复制副本后扫描"的数字。
