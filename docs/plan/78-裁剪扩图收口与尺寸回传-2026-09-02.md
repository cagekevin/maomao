## 背景与痛点

全屏 `ImageEditor` 内有「裁剪」和「扩图」两个独立动作。当前存在三个问题：

1. **PromptNode 节点比例不跟（核心 bug，ImageNode 正常）**：裁剪/扩图保存后，`handleEditorSave` 已把画布真实尺寸 `dims` 作为第 2 参透传给 `onImageReplaced(dataUrl, dims)`，但 PromptNode 的 `onImageReplaced` **忽略了 dims**（只 `patchData({ imageUrl })`）→ `aspectRatio` state 从不更新 → `NodeShell.useSizeSync(area-fixed)` 收不到新比例 → 节点框停留在旧画幅，新图被 `object-cover` 裁切，表现成「图换了、框没换」。ImageNode 因 `onImageReplaced` 消费 dims（走 `fitByRatio`）而正常。二者共用同一保存出口，差异只在各自对 dims 的消费端（详见文末复盘）。
2. **默认外扩量不该是 50%**：`outpaintAmount` 初始值写成了 `0.5`，需求是默认 `0`（无白边、原图铺满、即 `toOutpaintZoom(0)=1`）。
3. **底图用完即焚，链路断裂**：`applyCrop` 与 `applyOutpaint` 确认后都执行 `imgRef.current = null`。扩图依赖 `imgRef.current`（原始图）重画，一旦先裁剪把 `imgRef` 置空，再进扩图就拿不到底图（用 placeholder 1×1），流程不可重复。

## State 1: 定契约（输入/输出/边界）

### 核心需求
- 裁剪、扩图保存后，节点比例都要按真实画布尺寸自动变（与裁剪现有行为一致）。
- 扩图默认外扩量 = 0。
- 裁剪 ↔ 扩图可任意先后、可重复，互不吞底图。

### 输入源
- 用户在 `ImageEditor` 内的裁剪选区（`completedCrop`）/ 扩图参数（`outpaintRatioKey`, `outpaintAmount`, `outpaintOffset`）。

### 输出目标
- `canvas` 像素（裁剪裁切 / 扩图画白边）。
- `handleSave` 回传 `{ dataUrl, width, height }`。
- `ImageNode` 写回 `data.imageUrl/url` 并按 `{width, height}` 调 `fitByRatio` 自适应形状。

### 副作用
- 节点 `data` 不可变更新（`setNodes`）。
- `imgRef.current` 底图状态在裁剪/扩图后「回填结果图」，而非焚毁。

## State 2: 定数据流（链路 / 唯一入口）

```
[ImageEditor]
  applyCrop / applyOutpaint
    └─ commitCanvasToImgRef()
         canvas.toDataURL('image/png') → new Image() → imgRef.current = img
         （唯一底图真相源，统一回填，消除两处 `= null` 分叉）
    └─ canvas 已是最终结果像素
  handleSave（唯一保存出口，不分支）
    └─ onSave({ dataUrl: canvas.toDataURL('image/jpeg',0.9),
                width: canvas.width, height: canvas.height })
         ↓
[useImageHoverActions.handleEditorSave]（透传，不改链路）
    └─ onImageReplaced(dataUrl, width&&height ? {width,height} : undefined)
         ↓
[ImageNode.replaceImage]（落点）
    ├─ setNodes 不可变更新 data.imageUrl/url
    └─ if (dims) fitByRatio(dims.width, dims.height)   ← 绕过缩略图尺寸还原
```

### 唯一入口判定
- **底图真相源**：`imgRef`，统一由 `commitCanvasToImgRef` 收口（消除「裁剪置 null / 扩图置 null」两处分叉）。
- **写回**：`onImageReplaced`（既有，已扩展 `dims?`；`PromptNode` 消费 dims → fitByRatio + 置 Auto，`ImageNode` 消费 dims → fitByRatio）。
- **比例自适应**：`fitByRatio`（既有唯一函数，必须在 `ImageNode` 解构出来，否则 `ReferenceError`）。

### 边界 / 失败拦截
- `commitCanvasToImgRef` 用 `img.onload` 异步回填。极端时序下（确认后立刻再开扩图），`imgRef` 可能尚未回填 → `renderOutpaint` 增加兜底：底图为空时回退用 `canvasRef.current` 当前内容（`drawImage(canvas, ...)`），避免卡空白。
- 数据流向单向：`ImageEditor → hook → Node`，无循环依赖；`imgRef` 仅 ImageEditor 内部消费，不外泄。

## 复盘：为什么裁剪/扩图后节点比例不跟？（2026-09-02 补）

### 关键发现
> **ImageNode 正常，PromptNode 异常** —— 两者共用 `useImageHoverActions.handleEditorSave`，差异只在各自 `onImageReplaced` 的消费方式。

### 根因（系统性，深）
`handleEditorSave` 已经把画布真实尺寸 `dims({width,height})` 透传给 `onImageReplaced(dataUrl, dims)`（唯一出口，没断）。两个节点消费 dims 的方式不同：

| 节点 | 节点框比例机制 | `onImageReplaced` 对 dims 的处理 | 结果 |
|---|---|---|---|
| **ImageNode** | `useFitNodeRatio.fitByRatio(w,h)` 直接改节点宽高 | 消费：`if (dims) fitByRatio(dims.w, dims.h)` | ✅ 比例跟随 |
| **PromptNode** | `NodeShell.useSizeSync(area-fixed)` 由 `aspectRatio` 字符串驱动 | **忽略 dims**（设计文档 46/171 行明确写了「忽略 dims」），只 `patchData({imageUrl})` | ❌ 比例不跟 |

**PromptNode 的 `aspectRatio` state 从不更新** → `NodeShell` 的 `useSizeSync` 收不到新比例 → 节点框停留在旧画幅（如 16:9）→ 图片 `object-cover` 填满旧比例框被裁切，看起来「没根据裁剪/扩图后的图片来」。

### 修复（补上 PromptNode 消费 dims 的落点，且不污染生图比例）
初版方案是把 dims 归一成 `'W:H'` 写回 `aspectRatio`。但这是错的：`'W:H'` 会把节点锁死在自定义比例，且**污染后续生图的比例选择**（用户选 3:4 却显示成别的）。

最终方案改为：**编辑保存后用 `fitByRatio(dims)` 直接改节点框跟随图片，并把 `aspectRatio` 置 `'Auto'`**——Auto 下节点框尺寸由媒体真实比例决定（见 `useSizeSync` 的 Auto 不干预改动），既不锁死比例、也不污染生图。配套两处改动：

```ts
// hooks.ts —— Auto/无比例不干预节点尺寸（把节点框释放给媒体真实比例）
useEffect(() => {
  if (!ratio) return   // Auto 不再重置为 defaultHeight 默认方框
  // ... 原按比例重算逻辑
}, [id, ratio, ...])

// PromptNode.tsx —— 编辑保存：fitByRatio 跟随 + aspectRatio 置 Auto；<img> 绑 onLoad 自动跟随
const { fitFromImage, fitByRatio } = useFitNodeRatio(id)
onImageReplaced: (dataUrl, dims) => {
  setImageUrl(dataUrl)
  if (dims?.width && dims?.height) {
    const w = Math.round(dims.width), h = Math.round(dims.height)
    if (w > 0 && h > 0) {
      editedRatioRef.current = true // 防「切 Auto」effect 用旧图覆盖 dims 结果
      fitByRatio(w, h)              // 节点框跟随编辑后真实比例（等价 ImageNode 消费 dims）
      setAspectRatio('Auto')        // 不写死 'W:H'，避免污染生图比例
      patchData({ imageUrl: dataUrl, aspectRatio: 'Auto' })
      return
    }
  }
  patchData({ imageUrl: dataUrl })
}
```

配套 `<img onLoad={fitFromImage}>`：Auto 下节点框跟随图片本身尺寸；用户手动切 Auto 且有图时，`useEffect` 读当前图真实尺寸 `fitByRatio`（`<img> src` 未变不触发 onLoad，需主动读）。

### 为什么之前「改动没用」的排查结论
- 单点测试全绿（`computeOutpaintTarget` dims 正确、`computeSizeSync` 支持任意比例、`useSizeSync` aspectRatio 变化会重算节点框）——说明**每个环节单独都对**。
- 但 **PromptNode 压根没接 dims**（`onImageReplaced` 第二参被忽略），所以整条链路在「消费端」断掉，表现为「图换了、框没换」。
- 教训：**「出口统一传参」不等于「两端都消费」**。`handleEditorSave` 传了 dims，ImageNode 接了，PromptNode 漏接 → 必须逐个落点核对，不能只信出口。

### 测试锚点（实现一变必红）

- 出口：`useImageHoverActions.handleEditorSave` 把 dims 作为第 2 参传给 `onImageReplaced`。
