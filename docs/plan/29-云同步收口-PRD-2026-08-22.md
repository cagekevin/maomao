## 一、定位（理解问题）

`maomao` 是 Chrome 扩展 + 浏览器双端可运行的画布工作流应用。核心价值是**跨设备同步配置、账号环境（cookie）、项目与画布**，并支持多开账号 cookie 注入激活。

本 PRD 统一收口三件事，并补齐云同步链路中的版本传递缺口：

1. **账号环境（cookie）同步修复**：`yimao_accounts` 在 Chrome 插件环境因 `initStorage` 异步加载竞态读空，云下载后多开列表不显示、无法激活。**已实现**（`waitStorageReady` + `reloadFromStorage` + 挂载重读），纳入基线。
2. **项目 + 画布快照一体同步**：项目（名字）已走云同步，画布快照尚未进云同步。纳入画布，做成"项目 + 画布"**一体可开关**的同步单元。
3. **跨设备画布版本仲裁**：两台电脑 localTool 独立，画布版本号（`Date.now()`）不可比，需云端权威版本仲裁（后改覆盖先改）。

**收口缺口（核实发现）**：
- 项目版本号（`project_meta.version`）在云同步链路**未传递**：`restoreLocal` 调 `saveProjects` 未传 version → 后端并发保护静默失效。
- 画布快照版本号**未进云同步**。
- cookie 修复中 `reloadFromStorage` 用 `JSON.stringify` 全量比较（性能细节，低优先）。

## 二、模块拆解（互不重叠）

|---|---|---|

| **M2 项目画布一体同步** | 项目（含版本号）+ 画布快照作为一体单元进云同步，受开关控制 | 待实现 |

- M1 独立（local 键读取通道，与 M2/M3 的 KV 通道分离）。

## 三、翻车点（识别陷阱）

1. **跨设备时钟不可比**：项目/画布版本号现用 `Date.now()`，两台电脑时钟不同步时仲裁会错。必须用云端单调递增权威版本，不能依赖本地时间戳。
2. **项目并发保护静默失效**：`restoreLocal` 调 `saveProjects` 未传 version，后端 `typeof body.version === 'number'` 为 false → 不拦截。若只"带上项目版本"而不修正调用链，等于没修。
3. **画布数据契约升级兼容 + 体积**：`cloud_config` v4→v5 需向后兼容（旧云端无 `canvas` 字段优雅跳过）；画布快照可能较大，需评估体积边界并复用 `sanitize` 避免带 ReactFlow 运行时态。

## 四、约束清单（设计路径）

### M1 账号同步
- **C1.1** 插件环境读取 `yimao_accounts` 前须等 storage 缓存就绪（`waitStorageReady`），避免初始竞态读空。
  - 验证：插件环境云下载 → 刷新 → 进多开页能显示云端账号卡片。
- **C1.2** 本机变更走 `accountsStore` 自身 state 刷新（`saveEnvs`/`saveEnvironment`），**不做响应式订阅**（cookie 低频、本机自更新）。
  - 验证：新增/删除/编辑环境后列表即时刷新（现有行为不回退）。
- **C1.3** 云下载后重读一次（挂载时触发 `reloadFromStorage`）。
  - 验证：云下载 → reload → 进多开页显示云端账号。
- **C1.4**（低优先）`reloadFromStorage` 避免 `JSON.stringify` 全量比较。
  - 验证：性能不回归（不强求本期）。

### M2 项目画布一体同步
- **C2.1** 新增开关 `syncProjectAndCanvas`（默认开，进 `settingRegistry`），控制"项目 + 画布快照"整体是否参与云同步；关＝两者都不同步。
  - 验证：开关关后，云上传/下载均不含 projects 与 canvas。
- **C2.2** 项目与画布作为**一体单元**，只此一个开关，不拆成两个。
  - 验证：UI 只有一个开关。
- **C2.3** 上传时遍历所有项目，读本地画布快照（复用 `loadCanvasState`）打包进 `data.canvas[projectId] = { version, nodes, edges }`。
  - 验证：云端数据含 `canvas` 字段。
- **C2.4** 下载时按 M3 仲裁写回画布（复用 `saveCanvasState` / 新增 `writeCanvasState`）。
  - 验证：下载后画布节点/连线恢复。

### M3 画布版本仲裁 + 项目版本传递
- **C3.1** 版本仲裁**不依赖本地 `Date.now()`**，云端维护单调递增权威版本。
  - 验证：两台电脑时钟不同步，仲裁结果仍正确（后改覆盖先改）。
- **C3.2** 上传侧：本地画布更新才上传，云端版本单调递增；云端已更新则本地上传不覆盖。
  - 验证：云端更新时，旧本地上传被跳过。
- **C3.3** 下载侧：云端版本 > 本地才覆盖写回，并把本地版本同步为云端版本。
  - 验证：本地更新时，云端旧版下载不覆盖本地。
- **C3.4**（收口缺口）`restoreLocal` 调 `saveProjects` 时**传递 version**，让项目并发保护在云下载覆盖时生效。
  - 验证：下载覆盖不丢新项目。

### 跨模块约束
- **X1** M2 的画布上传/下载必须经 M3 仲裁判断（`shouldUpload`/`shouldDownload`）。
  - 验证：cloudSync 的画布读写调用 M3 判断函数。
- **X2** 所有画布读写复用 `projectStore` 唯一入口，不重造。
  - 验证：cloudSync 不出现裸 `contentGetAsync(canvas-state-...)` 拼装。
- **X3** `cloud_config` 升级 v4→v5 向后兼容——旧云端无 `canvas` 字段时优雅跳过。
  - 验证：旧数据下载不报错、不丢既有配置。
- **X4** 领域开关作为 `cloudSync.js` 内部开发者配置（`SYNC_DOMAIN_SWITCHES`），不进 UI、不随云同步。
  - 验证：改代码常量即切换，上传/下载同步读取同一份开关。

## 六、M1 账号同步（已细化 · 可交付）

### 6.1 边界对齐
cookie 环境（`yimao_accounts`）插件环境正确读取 + 云下载后重载。不涉及画布读写（X2）、不动 `saveProjects`（X1 无关）、不升级 `cloud_config` canvas 字段（X3 无关）。

### 6.2 子模块
- M1-S1 存储就绪等待：`storageAdapter.waitStorageReady()`（已实现）
- M1-S2 账号重载：`accountsStore.reloadFromStorage()`（已实现）
- M1-S3 挂载触发：`AccountsSettings` 挂载时重载（已实现）
- M1-S4 数据校验/清理：`accountsStore.load()` 演示假数据清理（已存在）

### 6.3 翻车点
1. 挂载早于 cache 就绪仍可能读空（时序）。
2. `reloadFromStorage` 用 `JSON.stringify` 全量比较（性能）。
3. `load()` 演示数据清理可能误删真实账号（低概率）。

### 6.4 约束 + 验证
- **C1.1** 读取前等 storage 就绪。验证：插件云下载→刷新→进多开页显示云端卡片。支撑 X3（local 键读取不受 cloud_config 升级影响）。
- **C1.2** 本机自更新不做响应式。验证：本机新增/编辑后列表即时刷新。
- **C1.3** 挂载重读一次。验证：云下载→reload→进多开页显示。
- **C1.4**（低优）避免 `JSON.stringify`。验证：性能不回归。

**判定**：约束 4 条可验证 → **M1 可交付**。

## 七、M2 项目画布一体同步（已细化 · 可交付）

### 7.1 边界对齐
项目（含版本号）+ 画布快照作为一体单元进云同步，受**领域开关**控制。依赖 M3 仲裁（X1）、`projectStore` 唯一入口（X2）、`cloud_config` v5（X3）。

**设计演进（2026-08-22 确认）**：不再单独做"项目+画布"开关进 UI，而是把云同步**所有同步项做成按领域分组的可开关清单（开发者配置，`cloudSync.js` 内常量，不进 UI）**。每个领域一个开关（`SYNC_DOMAIN_SWITCHES`），想开就开、想关就关。项目（projects 领域）默认关，其余领域默认开。

### 7.2 子模块
- M2-S1 领域开关（`cloudSync.js` 的 `SYNC_DOMAIN_SWITCHES` + `DOMAIN_KEYS`）
- M2-S2 上传收集（遍历项目读画布打包，受领域开关过滤）
- M2-S3 下载写回（经 M3 仲裁，受领域开关过滤）
- M2-S4 体积/降级（localTool 未连时跳过画布）

### 7.3 翻车点
1. 画布体积大塞进 GAS payload 可能超限。
2. 开关关时须同时排除 projects + canvas（不是只排 canvas）。
3. 上传读画布时 localTool 未连 → KV 读不到 → 需降级跳过。

### 7.4 约束 + 验证
- **C2.1** 领域开关表 `SYNC_DOMAIN_SWITCHES`（开发者配置常量）控制所有同步项：`projects`/`accounts`/`apiConfig`/`aiModel`/`skills`/`prompts`/`nodePrefs`/`appSettings`，默认 projects 关、其余开。验证：关某领域后上传/下载均不含该领域键。
- **C2.2** 上传遍历所有项目读 `loadCanvasState`，打包 `data.canvas[projectId]={version,nodes,edges}`。验证：云端数据含 canvas 字段。支撑 X2（复用唯一入口，无裸拼装）。
- **C2.3** 下载经 M3 仲裁写回（复用 `saveCanvasState`/`writeCanvasState`）。验证：下载后画布节点/连线恢复。支撑 X1。
- **C2.4** 领域开关关时，`LS_KEYS` 过滤该领域键且不打包对应 canvas。验证：上传 payload 无已关领域的键。
- **C2.5** 画布体积控制：复用 `loadCanvasState` sanitize（不带 ReactFlow 运行时态）；localTool 未连时画布降级跳过不阻塞配置同步。验证：payload 不含 selected/dragging 等运行时字段；localTool 断开时配置仍同步。

**判定**：约束 5 条可验证 → **M2 可交付**。

## 八、M3 画布版本仲裁 + 项目版本传递（已细化 · 可交付）

### 8.1 边界对齐
云端权威版本仲裁（后改覆盖先改）+ 补项目版本在云同步的传递。是 M2 的支撑能力；`saveProjects` version 补传属 cloudSync 链路修复，仍走 projectStore/saveProjects 唯一入口（X2）。

### 8.2 子模块
- M3-S1 画布版本读写能力（`projectStore` 暴露）
- M3-S2 上传仲裁（shouldUpload）
- M3-S3 下载仲裁（shouldDownload + 版本对齐）
- M3-S4 项目版本传递（saveProjects 补 version）

### 8.3 翻车点
1. 云端权威版本单调递增：每次云端更新 +1，不能靠本地时间戳。
2. 下载后本地 `key_version` 须对齐云端版本，否则下次上传误判。
3. `saveProjects` 补 version 后，后端 `project_meta` 版本更新逻辑需确认不误拒。

### 8.4 约束 + 验证
- **C3.1** 云端维护单调递增权威版本，不依赖本地 `Date.now()`。验证：两电脑时钟不同步，仲裁结果仍正确（后改覆盖先改）。
- **C3.2** 上传侧：本地画布更新才上传，云端版本单调递增；云端已更新则本地上传不覆盖。验证：云端更新时，旧本地上传被跳过。
- **C3.3** 下载侧：云端版本 > 本地才覆盖写回，并把本地 `key_version` 同步为云端版本。验证：本地更新时，云端旧版下载不覆盖本地。
- **C3.4**（G1）`restoreLocal` 调 `saveProjects` 时传递 version，让项目并发保护在云下载覆盖时生效。验证：下载覆盖不丢新项目。
- **C3.5** 画布版本读写能力：`projectStore` 暴露 `readCanvasVersion(projectId)` + `writeCanvasState(projectId,{version,nodes,edges,viewport})`。验证：cloudSync 能读版本、能按指定版本写回。

**判定**：约束 5 条可验证 → **M3 可交付**。
