
# 域归位 · 改名与搬迁操作手册

> **一句话**：这篇只管「怎么把名字 / 位置改对」。
>
> - **该放哪（归属判据）** → `ADR-0040`
> - **该叫什么（命名规范）** → `ADR-0039`（N1–N9）· 字符串改名边界 → `ADR-0038`
> - **施工批次与件级清单** → `docs/plan/域归位-最终执行计划.md §4`
> - **符号级 / 字符串级改名（ast-grep）** → `docs/节点重命名安全操作手册-2026-09-08.md`
>
> **改名** = 改符号名 / 文件名。**搬迁** = 改所在目录（路径）。两者常同时发生：文件搬家时往往还要改文件名。

---

## 1 · 决策树：改名？搬迁？还是别动？

```
① 放错域了吗？（判据：ADR-0040 —— 界面位置 + 数据落点）
   ├─ 是 → 需要「搬迁」（换目录）
   └─ 否 → 看 ②

② 名字误导吗？（名字暗示的域 ≠ 实际归属；或撞名 ADR-0039 N1）
   ├─ 是 → 需要「改名」（符号名 / 文件名）
   └─ 否 → 别动 —— 纯位置搬动无判据依据则不做（收益不可测，徒增 churn）

③ 会不会制造规则 2 违规？（关键！）
   ├─ 会（消费方落在 base/{core,utils,ui,api,storage}）→ 改判留原地，或先解耦消费方依赖
   └─ 否 → 按 ①② 执行
```

### 三条铁律（改前必答）

1. **它凭什么成立？** 引用登记/计划的描述前必须自证（ADR-0001）。本轮 4 次判错：
   `base/prompt` 当一域 · `editors` 当独立域 · `agentKeys` 当横切契约（前提是假的：`backupStore` 消费数 = 0）· `ResourceStrip` 归素材域。
2. **会不会撞名？** 改名后是否与别的域产生同名目录 / 同名导出。本项目已栽过三次：
   - `base/prompt/` vs `components/prompt/`
   - `components/editors/` vs `image/editors/`
   - `base/core/ui/` vs `base/ui/`
   ⇒ **旧目录必须消失，不留同名空目录。**
3. **归属看位置与数据，不看名字**（ADR-0040 L2）。改名不能改变归属判断 —— 名字是结果的表达，不是依据。

## 2 · 命名规范速查（ADR-0039）

| # | 规则 | 要点 |
| --- | --- | --- |
| N1 | 域专用导出带**域前缀**（camelCase，域名原词不缩写） | **判据 = 撞名**（同名 ≥2 处且分属不同域）。不是"所有导出都加前缀"！ |
| N2 | 文件名 = 主导出名；纯类型文件 `<域>Types.ts` | |
| N3 | `*Store.ts` **仅状态真源** | 非状态真源不许叫 Store |
| N4 | `Contract` 一词**专属** `core/contracts.ts` | |
| N5 | ⛔ **已作废（2026-09-20）** | 原「域目录**必须有 `index.ts` 门面**」不再成立 ⇒ 门面按**用例**建、**非必需**（ADR-0044 §3-b/§7/§8/§9）；跨域只走门面（域门面**或能力片门面**） |
| N6 | **横切层不放域专用物**；通用物**不装进域** | ADR-0040 L4 的依据 |
| N7 | 前缀用**域名原词**（`videoEditor` ✅ / `ve` ❌） | |
| N8 | 改名只保证「符号名 + 文件路径」一致；**运行时字符串默认不改** | → ADR-0038：键名/事件名/节点类型串/uploads 子目录/URL 冻结 |

**例外（禁重审）**：`director3d` · 可编辑元素判据（ADR-0031 · TD-18-10~13）· 提示词域三件（TD-18-39）· `filesApi` 落盘域（TD-02-66）。

## 3 · 搬迁（换目录）完整流程

### 3.1 前置核查（**不做必炸）

```bash
# ① 决定性的：看 check-arch 的横切集合（只看这一条就够）
sed -n '403,404p' scripts/check-arch.mjs
# BASE_CROSS_CUTTING = {core,utils,ui,api,storage}; BASE_HOST_LAYER = {panels}
# ⇒ base/store · base/media 不在里面（它们是域容器，出向依赖合法）

# ② 它的消费方里有没有横切 5 目录的文件？
node scripts/mv-sync-refs.mjs refs <要搬的文件>
# 看「① 模块引用」段里有没有 src/components/base/{core,utils,ui,api,storage}/*
# 有 ⇒ 搬走会制造规则 2 违规 ⇒ 改判留原地，或先解耦。

# ③ 会不会撞名？
ls src/components/<目标域>/ ; ls src/components/base/<目标域>/ 2>/dev/null
```

### 3.2 执行

```bash
# 单文件（推荐 —— 逐件可控）
node scripts/mv-sync-refs.mjs move <当前路径> <新路径>

# 整目录（⚠️ 只搬源码文件，且会写坏被搬文件的兄弟导入 ⇒ 见 3.3）
node scripts/mv-sync-refs.mjs move-dir <当前目录> <新目录>
```

> 🔴 **禁止对 `canvas/nodes/` 用 `move-dir`** —— 它会把 `GroupNode` · `GhostTargetNode` · `Director3DNode` · `_template/` 一起搬走（机制节点必须留下）。**逐件 move。**

### 3.3 后置工序（**已知的三类必做**）

| 工序 | 为什么 | 做法 |
| --- | --- | --- |
| **① 删旧路径残留副本** | 工具按旧路径回写会留未跟踪副本 ⇒ 出现两份 | `ls <旧目录>` / `git status` 查，删残留 |
| **② 还原被写坏的兄弟 import** | `move`/`move-dir` 会把被搬文件自身的 `./X` 写成指向旧目录的别名路径 | 跑 `tsc`，逐条把 `'@/components/<旧域>/X'` 改回 `'./X'` |
| **③ 补非源码文件** | **`move-dir` 只认源码，不搬 `.css` / `.json` / `data/`** | 手工 `git mv` 补齐。⚠️ 没补就被 `rm -rf` 误删过一次（27 行 CSS，靠 `git show HEAD:<路径>` 恢复） |

### 3.4 同步门面

- 若搬进/搬出一个**有门面的域** ⇒ 更新 `域/index.ts`（路径变了要跟着改）。
- 若新域还没有门面 ⇒ 建 `域/index.ts`（ADR-0039 N5 强制）。
- **子域 ≥3 件才可建子域门面**；不足 3 件不许硬凑（toolRegistry 就是 1 件 ⇒ 留域根）。
- 域外消费方改走门面（跨域只准走门面）。
- **例外要写在门面头**：代码分割需要的字面量动态 import（如 `lazyNode` 的 `import('.../PanoramaNode')`）属装配期配置，不经门面。

## 4 · 改名（符号 / 文件名）

### 4.1 符号改名
用 **`docs/节点重命名安全操作手册-2026-09-08.md`** 的 ast-grep 流程（那份是权威）：
1. `sg scan --rule <规则>` 预览（只读）
2. `sg scan --rule <规则> --update-all` 应用（本版本参数是 `--update-all`，不是 `--rewrite`）
3. **每批改名后必查 `grep -rn "vi.mock.*<被改模块>" tests`** —— ast-grep 不改名 `vi.mock` 的对象键 ⇒ mock 静默失效（Handoff 硬坑 #1）

### 4.2 文件名改名

```bash
git mv <旧名.tsx> <新名.tsx>
# 然后同步 import（工具不改名 ⇒ 手工 / 脚本批量替换路径片段）
grep -rln "<旧名>" src tests scripts | xargs sed -i '' 's#<旧名>#<新名>#g'   # macOS 用 sed -i ''
```

⚠️ **文件名改名 ≠ 归属改名**：先按 §1 判完归属，再定文件名（ADR-0040 L2：名字是结果表达，不是依据）。

## 5 · 闸与测试的硬编码路径同步（**A8，非可选 —— 本轮踩了 4 次**）

每次搬迁/改名后，以下**必须**同步：

| 位置 | 硬编码内容 | 不同步的后果 |
| --- | --- | --- |
| `scripts/check-arch.mjs` | `MEDIA_SSOT` 豁免清单（如 `skillStore` 是 Skill 白名单真源 TD-16-8） | 豁免失效 ⇒ 闸报「媒体类型内联重写」 |
| `scripts/_smoke_checks.cjs` | nodeTypes 候选目录 · `canvas/NodePalette` · `canvas/lazyNode` | palette 读不到 ⇒ **nodeTypes 注册 FAIL** |
| `scripts/check-node-data.mjs` | 节点目录路径 | 假绿（扫不存在的目录还算通过） |
| `scripts/check-node-handles.mjs` | 节点目录路径 | 同上 |
| `scripts/dead-code-baseline.json` | 全量基线路径 | 基线失效 ⇒ 假绿 / 误报 |
| 测试里的 `vi.mock` / `vi.importActual` **字符串路径** | 字符串（工具不改写，F2） | `tsc` 直接报「Cannot find module」 |
| 测试里**写死目录**的扫描（如 `nodePrefsRegression.test.ts` 的 `root`） | 单目录 | 已**两次**因搬迁变红 ⇒ 改成 `NODE_DIRS` **多目录探测**：<br>`['canvas/nodes','image/nodes','text','video/nodes']` |

**原则：凡「测试/闸自己写死目录」的写法，一律改成多候选目录扫描**（以后再搬也不会红）。

## 6 · 验收（**真跑并贴结果，不照抄「✅」** ADR-0052 M3）

```bash
npx tsc --noEmit                 # 类型（查不出 CSS）
npm run check:arch                # 规则 2 —— 搬完才可能炸，必跑
npx vite build                    # ⚠️ CSS 副作用 import 只有它能查
npm run test:smoke                # nodeTypes 注册 / JSX / 关键依赖
npx vitest run <受影响的测试>      # 手工点名跨 stem 的 mock 测试（test-affected 会漏）

# 残留复扫（F2 铁律）
grep -rn "<旧路径片段>" src tests scripts --include={*.ts,*.tsx,*.mjs,*.cjs,*.json}
# 期望输出：0 命中
```

**额外（改名类）**
```bash
grep -rn "vi.mock.*<被改模块>" tests     # mock 是否跟着改名
```

## 7 · 硬坑清单（改名 / 搬迁专项）

1. **`move-dir` 不搬 `.css`/`.json`/`data/`，且写坏被搬文件的兄弟导入** ⇒ 三类后置工序（§3.3）必做。
2. **CSS 副作用 import 指向旧目录 ⇒ `tsc` 查不出，只有 `vite build` 炸** ⇒ 碰 CSS 的批次必跑 build。
3. **`@public 跨边界消费者` 注释必须放进 JSDoc 块内** —— 插到 `*/` 外 ⇒ eslint 解析失败，commit 被钩子拦下。
4. **闸硬编码路径**（§5 表格，本轮 4 处）。
5. **测试硬编码目录** ⇒ 改多目录探测。
6. **`vi.mock` / `vi.importActual` 字符串** 工具不改写 ⇒ 手改。
7. **本环境同一条命令会被执行两次** ⇒ 重复提交 / 「nothing to commit」是第二次运行的正常回显 ⇒ 提交后 `git log` 核对 HEAD 内容。
8. **验证脚本自己也要先自检**（本会话验证脚本错 2 次：前缀漏配 / 扩展名漏配）。
9. **计数/清单断言须机器复算**（本文件件数栽 3 次：563→564→491→504）。

## 8 · 最小可行模板（复制即用）

```bash
# 1) 前置：判归属 + 查横切消费方 + 查撞名
node scripts/mv-sync-refs.mjs refs <要搬的文件>

# 2) 搬
mkdir -p <目标目录>
node scripts/mv-sync-refs.mjs move <旧路径> <新路径>

# 3) 后置：删残留 · 修兄弟 import（tsc 会告诉你）
npx tsc --noEmit 2>&1 | head
#   对每条 "Cannot find module '<旧路径>'" ⇒ 改成相对路径 / 新路径

# 4) 同步门面 + 闸 + 测试（§5 + §3.4）
grep -rn "<旧路径片段>" src tests scripts --include={*.ts,*.tsx,*.mjs,*.cjs,*.json}   # 期望 0 命中

# 5) 验收（真跑，贴结果）
npx tsc --noEmit && npm run check:arch && npx vite build && npm run test:smoke

# 6) 提交 + 回填进度表 + DATAFLOW §十六 登记
```
