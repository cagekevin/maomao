## 3. 目标界面

### 3.0 分类的**职责**与出现条件（2026-09-22 用户裁定 + 复审）

> **用户原话（裁定）**："我的分类管理是为了让用户自己能够管理，让自己的分组有分组而已，**不是说让 AI 有分组**，
> 我只是为了方便我自己管理而已。不然我好多好多技能并不想同时出现在下拉列表里边，我同时出现在下拉列表里边，
> 我也不好选。"
>
> ⇒ **分类的存在理由是"缩短选择面"**（技能多了，下拉里全平铺就选不动），**不是"视觉整理"，也不是给 AI 的分组**。

**因此两条硬规则**：

1. **分类是界面概念，不进模型上下文**：块①（清单）/ 块②（正文）**不体现分类**，发给 AI 的文本保持扁平
   （AI 不需要知道"我的分组"）。
2. **分类的主战场是选择器**（对话里 `/` · `+` 那个下拉），维护页只是"管理分组本身"的地方。

**出现条件（渐进披露）**：选择面短的时候不需要分组。

| 状态 | 界面 |
| --- | --- |
| **默认**（技能少 且 没建过分类） | 一页平铺行：行 + 虚线拖入条 + ⋯。**没有分类表头** |
| **选择面变长**（技能 > N 或用户自建了分类） | **分组表头出现**（平铺分区，一页到底，**不进层**）；选择器同时开始**按分类分区** |

判据是**选择面**（下拉里有多少条要扫），不是"好看"。N 见 D5。

> **I4（新增判据）不许引入"进出层级"**：卡片 + 文件夹格子要求"进分类 / 返回上级"（用户否掉的原话：
> "我想返回上一级，还麻烦"）⇒ **分区用表头，不用钻入**。折叠可以（用户点表头），但**折叠 ≠ 换页**。

> **两个轴不许混**（现状把两者写在一句话里 ⇒ 用户以为"分类 = 可见性控制"）：
> | 轴 | 管什么 | 表现 |
> | --- | --- | --- |
> | **启用开关** | 这个技能**能不能用**（关了真的用不了，`/` 也搜不到） | 卡片右下角开关 |
> | **分类** | 技能**怎么被找到**（下拉里的分区/筛选，缩短选择面） | pill / 分类格 / 下拉分区 |

### 3.1 技能库（唯一管理面）—— **一页清单（平铺 + 分区）**

**为什么不是卡片/文件夹格子**：那套要"进分类 / 返回上级"（用户否掉的原话），而列表**把所有技能摊在同一平面**、
用**分组表头**分节 ⇒ **没有进出层级这回事**，一屏还能多看几行。

```
┌ 技能 ──────────────────────────────────── [✚ 新建] [⋯] ┐  ← ✚ = 新建技能；⋯ = 打开技能库 / 新建分类 / 重新扫描 / 高级
├─────────────────────────────────────────────────────────┤
│  ⬒  拖入 .md 或技能文件夹（拖文件夹 = 整包导入）             │  ← 虚线一条 = **唯一**加技能的入口
├─────────────────────────────────────────────────────────┤
│  绘画  3                                       [全开]   │  ← 分组表头 = 分类（分区，不是文件夹；可点折叠）
│    漫画生成     按网点风格出图          ⚠未就绪  ⬤  ⋯    │  ← 行 = 名字 + 一句话 + [异常小字] + 开关 + ⋯
│    网点练习     三种网点对比                    ⬤  ⋯    │
│  文案  2                                       [全开]   │
│    爆款标题     给标题起 10 个候选               ⬤  ⋯    │
│    详情页文案   卖点排序                        ○  ⋯    │
│  未分类                                        [全开]   │
│    随手记的     临时写的                        ⬤  ⋯    │
└─────────────────────────────────────────────────────────┘
```

- **行**：`名字 + 一句话 + [异常小字] + 开关 + ⋯` ⇒ **两个常显控件**（开关、⋯），符合 §3.6 I1。
- **分组表头** = 分类（磁盘一级目录 = 真相源）：措辞 + 数量 + **组级全开/全关**（现成的三态）；默认展开，折叠由用户点。
- **拖拽归组**保留：把一行拖到另一个表头下 = 换分类；**等价入口** = 行 ⋯ →「移动到…」（触屏/键盘不可拖拽）。
- 点行主体 = 进右栏详情（编辑正文等）——沿用现有右栏，不新造。
- **开关** = `row.enabled`（写 `setSkillsEnabled`，唯一入口），`stopPropagation`，不连带进详情。
- **异常行**：`state !== 'ok'` 时行尾一句小字 + 一个动作（**动作按 §8/A2 分两类**，不是一个万能"修复"）。

### 3.2 高级（默认折叠；用户"不必懂但不许没有"的都在这里）

- 「让 AI 自动知道有哪些技能」= 现 `catalogToModel`，**默认关**（用户裁定）；说明写"开启后每轮多约 500 字"。
- 「内容长度上限」= 现三个预算输入，默认档 = **自动**；展开才见数字，附一句"超了会在发给 AI 的文本里注明已截断（不静默丢）"。

### 3.3 对话里（**下一批，本方案不改**）

输入框 `/` 搜技能 + `+` 选技能 / 传文件（现有 chip + 下拉继续用）。

### 3.4 【新】选择器：分类的**主战场**（下一批，但本方案必须把它定下来）

既然分类是为了"**缩短选择面**"，它就必须在选择器里服务这个目的——否则分类只是个装饰：

| 场景 | 现在的选择器 | 目标 |
| --- | --- | --- |
| 5 个技能 | 平铺一列，没问题 | 不变（**不显示分区**，别加噪声） |
| 30 个技能 | **全平铺** ⇒ 用户"不好选"（用户原话） | 按分类**分区**；默认只展开**上次用的那个分类**；输入即全局搜（搜索跨越分类） |
| 只记得大概 | 只能滚动找 | `/` 直接搜名字/用途；搜到就选（不要求先选分类） |

**判据**：① 分区**出现**条件与 §3.0 一致（选择面短就不分区）；② 搜索**永远跨分类**（不许"先选分类才能搜"——
那是把分类变成关卡）；③ 分区只影响**怎么找**，不影响**能不能用**（能用与否永远只看启用开关）。

### 3.5 【新】按钮归位：**6 条放置判据** + 现状逐条裁定

**判据（先立规矩，再判按钮）**：

| # | 判据 | 含义 |
| --- | --- | --- |
| P1 | **一个动作一个入口** | 同一动作不许在两处各摆一份（两份就会漂移/不一致） |
| P2 | **就近** | 作用于一个技能的贴那一行（行 ⋯）；作用于全库的在顶层 ⋯；作用于分类的在分组表头 |
| P3 | **频率定去留** | 低频收进 ⋯；高频常驻。**但要先问"它属于哪个页面"** —— 高频动作放错页面照样是错 |
| P4 | **危险动作隔离** | 删除 / 丢弃这类不可逆的，不与常用动作相邻，且二次确认 |
| P5 | **名字 = 行为** | 一个按钮不许因数据不同（如内置只读）而换语义 |
| P6 | **异常才出现** | 排障动作与状态解释不许常驻（正常态零状态） |

> 本节的**裁定结果表**（19 条，逐控件）在 §3.5.1。

### 3.6 【新】动作**图标化** + **⋯ 收纳**（用户裁定 2026-09-22）

> **用户原话**："你那些编辑什么的，不应该就放到那个编辑。我觉得很多都应该变成一个图标，
> 一些不常用的都应该变成三个点缩起来。"

**三条硬规则**：

| # | 规则 | 为什么 |
| --- | --- | --- |
| **I1** | **一行最多两个常显控件**：行尾**开关** + 行尾 **⋯** | 超过两个就必须靠"记位置"，一行就不是"一眼一物"了 |
| **I2** | **行上只用图标（开关/⋯）；⋯ 里允许"图标 + 文字"** | 行是扫视面（图标够）；⋯ 是"我正在找它"（文字才认得出） |
| **I3** | **每个图标必须有 `title` + `aria-label`**，且文案与动作一致（P5） | 图标化的代价就是认不出——靠这两样兜 |

**动作归位表（行 / 详情 / 顶层）**：

| 动作 | 频率 | 现在的样子 | 归位 | 形态 |
| --- | --- | --- | --- | --- |
| **启用开关** | 高 | 行内开关（+ 组头三态） | **行尾**开关 | 开关（唯一常显控件之一） |
| **编辑正文** | 高 | 行内「编辑」**+** 右栏「编辑」两份 | **点行主体**进详情 | **不给图标**（否则就三个控件了） |
| **用这个技能** | 高，但**属于对话页** | 设置页右栏 `:1501` | 对话里（§3.4） | —（见 D7） |
| **导出** | 低 | 右栏文字按钮 | 行 **⋯** / 详情 ⋯ | ⋯ 内一行（图标 + 文字） |
| **删除** | 低·**不可逆** | 右栏，与「保存」同排 | 行 **⋯**（二次确认） | ⋯ 内 |
| **打开该包 / 打开技能库** | 低（排障） | 行内 + 右栏 + 顶栏**三处** | 行 ⋯ / 顶部 ⋯ | ⋯ 内 |
| **重新扫描**（原「从磁盘重读」） | 低 | 顶栏文字 | 顶部 **⋯** | ⋯ 内 |
| **新建技能** | 低 | 顶栏文字 | 首行「✚ 新建技能」 | 一行（见 D8） |
| **新建分类** | 低 | 顶栏表单（`分组名（= 磁盘上的文件夹）`） | 顶部 ⋯「新建分类」→ **就地命名** | ⋯ 内 |
| **高级**（预算 / 清单） | 极低 | 顶栏折叠区 | 顶部 ⋯ → 高级 | ⋯ 内 |
| **补齐 id / 恢复 / 丢弃 / 重读** | 仅异常 | 行内 + 右栏各一份 | **异常行**点开后的动作（按 A2 分"可自动"与"要你选"） | 行尾一句小字 + 一个动作 |

⇒ 页面上的**常显控件**从 12 类降到：**行（开关 + ⋯）· 拖入条 · 分组表头（含组级开关）· 顶部 ⋯ = 4 类**。

### 3.7 【新】预算 / 额度：**机制保留、旋钮下沉、可见性上浮**（2026-09-22 用户提问后定）

> **用户提问**："我预算上限，一次最多发几个？这些是有必要的吗？"

| 参数 | 现状（用户可见） | 判断 | 新落点 |
| --- | --- | --- | --- |
| `maxExplicitBindings`（默认 4） | 高级里一个数字输入 | ⚠️ **它存在的唯一原因是"能多选"** —— 而多选本身要删（见 §3.7.1） | **参数消失** |
| `singleSkillChars`（12000） | 高级里一个数字输入 | 用户**没有判断依据**（"12000 字"谁也说不清）；是**唯一真正需要的上界** | 高级「自动」档的常数（默认不露数字） |
| `expansionTotalChars`（24000） | 高级里一个数字输入 | 同上（"合计"）；**单选之后"合计" ≡ "单个"** | **参数消失** |
| `SKILL_LIMIT_SUGGESTED_MAX` + 超界警告 | 一张建议上界表 + 一段"等于没有防线"文案 | **旋钮下沉后它失去存在理由**（它唯一的作用是"教育用户别调太大"） | **删除**（表 + 文案 + 判断分支 + 它的测试） |

#### 3.7.1 【裁决】**一次只用一个技能**（2026-09-22 用户提问后定）

> **用户原话**："用户一次只能选一个，那么怎么可能一次能带 4 个？难道用户一次可以同时发 4 个技能？
> 这有啥意思？"

**取证（三条，都指向同一个方向）**：

| 事实 | 出处 | 含义 |
| --- | --- | --- |
| **内置技能只有 1 个**（`skill_ecommerce_detail`） | `skillBuiltins.ts:31` | 连"默认可用"的技能都只有一个，谈不上组合 |
| 多选的**下游成本**已真实存在 | `readSkillResource(..., skillRef?)`：`pool = ref ? filter(byIdOrName) : turnBindings` + 工具描述要教模型"多个 Skill 时用 id 指明" | 多选逼出一条**歧义消解链**（参数 + 分支 + 提示词） |
| 产品 Owner 的心智模型 = **单选** | 用户原话 + 早前回答"就这次对话用一下" | 界面不该要求用户理解"组合语义" |

**裁决**：**一次发送只用一个技能**（`activeSkillId: string | null`）。**连带删除**：

1. `maxExplicitBindings`（个数上限——不存在"几个"）
2. `expansionTotalChars`（合计上限——"合计" ≡ "单个"）
3. `readSkillResource` 的 `skillRef?` 消歧参数 + `pool` 分支 + 工具描述里那句"多个 Skill 时用 id 指明"
4. UI 的 `activeSkills: string[]` → 单个选中；chip 从"多个可点掉"变"一个"

**唯一留下的额度参数 = `singleSkillChars`**（单技能正文上限），且不露给用户。
⇒ 净减：**参数 3 → 1 · 消歧链整条消失 · UI 多选变单选 · 尾注里的"另有 N 项未注入"消失**。

**代价与诚实边界**：

- **"组合"这条路要绕**：需要"风格 + 流程"一起时 ⇒ **把两段写进同一个技能**（这本身也是大厂的最佳实践："按用途组织，而不是一个万能技能"的反面——**一个用途一个技能**）。
- **留痕存量形状**：旧会话里 `bindings` 是数组 ⇒ **写入端收窄**（长度只会是 0 或 1），**读取端保留数组兼容**（不回改历史数据）。
- **如果将来真要组合**：改回来要有**真实用例**支撑（ADR-0053：不提前预留）；届时"消歧链"也要一并设计。


**核心理由（三条）**：

1. **机制必须有（有界性）**：技能正文是用户 / 外部导入的**任意文本**，没有上界就可能把上下文顶爆（费用与效果都受损）。
   大厂也一样有界，只是**不给用户看**（Anthropic 官方文档里 Skill 没有任何配额/预算类配置项）。
   > ⚠️ **形态差异（诚实边界）**：Claude 是**模型按需读**正文 ⇒ 它没有"一次带几个"这个问题；
   > 我们是**手动选中 + 直接注入** ⇒ **个数上限必须有**。这是我们的形态带来的，不是抄漏了。

   （现状那句"调到这个量级等于没有防线"），那它就不该出现在用户面前。
3. **可见性必须上浮（本节最重要的一条）**：

**🔴 审计发现（取证：`skillInject.ts:61-109`）**：`freezeSkillTurn` 返回

| --- | --- | --- |

### 3.8 【裁决·用户授权"你定"】**建分类只留一个入口**

> **用户原话**："建分组现在有两套入口：工具栏「分组」按钮（建一个空目录）vs 编辑器里在分组框输一个新名字
> （保存时移动到该新建目录）。功能上不重复（一个建空目录、一个随保存创建），但用户未必分得清。
> 要不要收成一个，**你定**。"

**裁定：收成一个** —— 唯一入口 = **⋯ →「新建分类」**（就地命名，和 §3.1 一致）。

| 入口 | 现状 | 裁定 |
| --- | --- | --- |
| 工具栏「分组」按钮（`:904` + `分组名（= 磁盘上的文件夹）` `:921`） | 建空目录 | **改**：收进 ⋯「新建分类」（就地命名，不再叫"分组"、不再提"文件夹"） |
| 编辑器里的「分组」输入框（`:1385`/`:1390` `留空 = 未分组`） | 输新名字 ⇒ **保存时在磁盘上建一个新目录** | **改**：只能**选已有分类**（下拉/选择器），**不许在这里输新名字** |

**理由（三条）**：

1. **P1 一个动作一个入口**：两个入口做同一件事（建目录），用户分不清（用户原话），代码里也是两条创建路径。
2. **顺手消掉一处真成本**：编辑器里随手输错一个字 ⇒ **磁盘上长出一个垃圾目录**（现状注释自己写着"= 磁盘上的文件夹"）。
   磁盘目录是**真相源**，让它被随手输入污染，代价比"少一步操作"大得多。
3. **拖拽/归位的语义要求"落点先存在"**：所以"先建分类、再归位"本来就是主流程；编辑器不是主流程。

**引导文案**（替代"留空 = 未分组"）：编辑器那一行写明「没有想要的分类？右上 ⋯ → 新建分类」。

### 3.9 【基准形态】对齐同行（WorkBuddy AI 技能页 · 2026-09-22 用户给图）

> **用户原话 + 截图**（`Screenshot - 2026-09-22 08.16.30.webp`）："我们跟别人比起来其实就多，
> 只是多了一个分组而已，就是第 A 组、B 组。"
> ⇒ **同行形态就是基准**；**分组是我们唯一的增量** ⇒ 它必须**最轻**（不能因为"多一个分组"把整页做重）。

**同行页面（逐元素取证）**：

| 元素 | 同行（WorkBuddy AI v5.5.2） | 我们现状 |
| --- | --- | --- |
| 标题 + 数量 | `我安装的 34` | ✅ 芯片计数（可收成一行） |
| 搜索 | **右上「搜索已安装的技能」** | ❌ **没有**（旧裁定"技能就几个，搜索是噪声"—— 而他们 34 个） |
| 批量操作 | 勾选 → `已选 N 项 · 全选 · 清空` + `开启 / 关闭 / 卸载 / 取消` | 仅组头三态；**没有勾选式批量** |
| 卡片 | **字母头像（首字母彩底）+ 名字 + 【套件】徽章 + 右上开关 + 一句话** | 名字 + 描述 + 开关；**没有头像/徽章** |
| 布局 | **一页平铺（3 列），无文件夹、无"进入/返回"** | 左栏 rail + 列表（有分组导航 ⇒ 钻层） |
| 分组 | **没有** | ⭐ **我们多出来的就是它** |

**据此定三条**：

1. **形态基准 = 卡片平铺**（照图）。⚠️ 这**不违反 I4**：图上没有任何钻层 —— 上一轮否掉的是
   "**文件夹格子 + 进出层级**"，不是卡片本身。
2. **分组必须最轻**（我们唯一的增量）：
   - 卡片上一个小**标签**（`A 组` / `B 组`）；
   - 顶部一个**分组筛选行**（`全部 · A 组 · B 组 · ＋`）；
   - **拖卡片到分组 pill = 归组**（落点就是这个 pill；不换页、不需要文件夹格子）；
   - 等价入口（触屏/键盘）：卡片 ⋯ →「移动到…」。
3. **搜索 + 批量选择是"技能多了"的配套**（与分组同源，都服务"技能一多就不好找/不好管"）：
   - 搜索：一页内过滤，**跨分组**；
   - 批量：勾选 → `启用 / 停用 / 删除`（同行的"卸载" = 我们的删除）。
