### 撤回项 A（原「拍板①」）：图片预算取多少 —— **撤回，我的理解错误**

**用户质疑（2026-09-22 16:0x）**：「图片不是 5 分钟么」。

**我错在哪（两条）**：

1. **数值早已裁定**（规划 §2.1：用户裁定「图片 5min / 视频 10min / chat 按前端」）。我把「有数据支撑的已定值」当成了「待重新拍板的值」—— **数据是支持性证据，不是重开的理由**。
2. **我把"可恢复的停止等待"说成了"放弃"**。按 `relayProxy.ts:274-286`：前端预算用尽 ⇒ 返回 `{ok:false, pending:true}` —— **非终态**，消费方保持任务 `running` 并交给恢复轮询续 attach 到真终态。**§1.2 那条 482.3s 的样本就是实证**（`status=completed` + `result_url` 非空）。所以那不是"放弃/损失"，是"**前端停止等待一次，后端继续，结果可补回**"。

⇒ **修正后的事实**：`GEN_TIMEOUT = 300_000` **= image 的 p99**（295.8s，n=478）⇒ 覆盖 **99%** 的实测任务。对一个**可恢复**的失败形态，取 p99 是站得住的。**决议② 维持 5 分钟，不改。**

**唯一残留代价（记录，不构成拍板项）**：约 **0.84%（4/478）** 的图片任务会让用户看到一次"超时"提示，随后由恢复轮询补回结果。若将来这个比例不可接受，再按实测重新评估。

> ⚠️ **口径声明（两个偏差方向相反，故只当量级看）**：
> - **偏大**：该比例用 `created_at → completed_at` 近似前端的等待窗口，而 `relayAttachUntilDone` 的计时从 **submit 返回后**才起算 ⇒ 分子略偏大。
> - **偏小**：幸存者偏差（§1.2，表内只有 `completed` 行）⇒ 分子略偏小。
> ⇒ 两个方向相互抵消，**只保证量级（≈1%）**，不保证小数点。这个精度足以支撑"300s = p99、形态可恢复"的结论。

### 撤回项 B（原「拍板③」）：5 条存量断言的处置 —— **撤回，我的理解错误**

  ```ts
  export const DEFAULT_BUDGET_MS = { chat: 180_000, image: 300_000, video: 600_000 } as const;

  /** 唯一入口：override（调用方本次耐心） > 后端默认。override 不是默认真相。 */
  export function budgetMsFor(capability: 'chat'|'image'|'video', override?: number): number {
    return override ?? DEFAULT_BUDGET_MS[capability];
  }
  ```
  - `image: 300_000` —— **已裁定，不再重开**（= 实测 p99，覆盖 99%，见 §1.2 与 §2 撤回项 A）。
  - ⚠️ `video: 600_000` 保留，但**注释里必须写明"无实测支撑（n=6, max 250s），待补"**（诚实声明，禁把 600s 写成"实测够用"）。
  - ⚠️ `chat: 180_000` —— 对应 `CHAT_TOTAL_TIMEOUT`（**不是** `CHAT_TIMEOUT=120s`，后者是"等上游响应"**段**的值，见规划 §2.3）。
- **验收**：单测三模态各返对应值；`override` 优先于默认。

## 5. 不做清单（本批明确不做，防顺手扩面）

| 不做 | 理由 |
| --- | --- |
| 不把 `maxDurationMs` 从协议 schema 删掉 | ADR-0053 四关全不过（§1.4/S0） |
| 不把四处"打开外部"统一成一个形态 | Windows `start` 是 cmd 内建，`index.ts:500` 必须走 shell（`index.ts:497-499` 已写明） |
| 不把前后端 `3000` 轮询间隔合并 | 同名不同义（规划 §4.1） |
| 不把 `MAX_CONSECUTIVE_POLL_ERRORS`（前端 5 / 后端 30）合并 | 同名同语义但**载体不同**（规划 §4.1 第二例） |
| 不预建空的 `DEFAULT_BUDGET[provider]` 层 | ADR-0053 ①「不许为设想的消费方铺路」 |
| 不动 `src/**` 里没人让改的文件 | SOUL 边界 |
| 不改前端数值本身（只改"从哪读"） | 规划 §2.1 用户裁定 |
