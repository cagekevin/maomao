# relay 与 proxy 合流 · 一次性全迁设计（chat/SSE/生图都走 relay）

> 状态：设计（范围已定：一次性全迁）。决策树：relay 未接前端 → 不恢复旧路由 → 改后端配置型 provider（96 号已落地）
> → 现在定「生成链路 relay 与 proxy 怎么结合」= **前端全迁到 relay，proxy 最终删除**。
> 铁律（docs/91 C0 + docs/90 §5）：协议执行不绕 ai-relay kit；落盘不依赖 kit；**能力零退化**（进度/取消/参考图/错误/刷新逐个兜住才允许切）。

---

## 0. 目标形态（全迁后）

```
前端 base/api（唯一语义门面，对外签名不变）
   ├─ chatCompletions / generateImage / generateVideo
   └─ 内部选路：一律走 relay（不再有 /api/proxy）
         chat  → /api/relay（kit chat / streamChat，同步/流式）
         image → /api/generate（后端 pollWorker：submit→轮询→落盘 /files/→写 DB result_url→GET attach）
         video → /api/generate（同上）
   provider 配置 = config/providers/<id>.json（96 号已做）+ key 进 .env
```

全迁后 proxyGenerate / pollTask / ensurePolling / taskStore 前端恢复落盘全部删除；`/api/proxy` 前端零消费 → registry 删/标 RESERVED，check:api 归零。

## 1. 为什么选「全迁到 relay」而非双轨

- **根治丢结果**：丢结果根因 = result_url 写库真源在前端一次性窗口。relay 把「轮询 + /files/ 落盘 + 写 DB」移到 localTool 进程（可 attach/重启恢复），根治。
- **避免长期两套语义**：双轨会让 proxy(前端驱动) 与 relay(后端驱动) 长期并存两套「进度/取消/落盘/错误」语义，维护成本高、易漂移。一次性全迁（配合能力零退化小步切）收敛更快。
- **provider 已配置型**（96 号）：relay 出站天然吃 config/providers + ai-relay 内置目录，proxy 的 providerProtocols/requestModes 前端拼装层可整体退役。

## 2. proxy 全能力 → relay 承载对账（必须先对清再切）

### 2.1 chat（`chatProxy` → relay `chat`/`streamChat`）
| proxy 分支 | 现状能力 | relay 承载 | 需补 |
|---|---|---|---|
| 非流式 chat/completions | 完整文本 | kit `chat()`（L42） | kit 无 `stream` 参数语义（chat() 硬编码 stream:false）——够用 |
| 流式 chat | SSE 逐 token 累积 content | kit `streamChat()` 的 `parseStream`（onEvent） | 前端是「累积 content 一次性回」，需 adapter 把 onEvent text.delta 拼回；`responses` 形态(parseResponsesChatJson) kit 无 → **需补 responses chat 协议** |
| responses 形态 | output[] content[].text | kit 无 | **需补**（requestModes.parseResponsesChatJson 逻辑要能喂 kit 或保留适配） |
| 嵌套错误/Httperror 信封 | 取上游 message | kit chat() 已抽 error.message | 信封 {ok,content?|error?} 由前端 relay adapter 归一 |

### 2.2 image（`imageProxy` → relay）
| proxy 分支 | 现状能力 | relay 承载 | 需补 |
|---|---|---|---|
| sync-SSE（?wait=1） | 同步读 SSE 到 succeeded | kit generateImage sync(json) 或 async | relay 侧统一**改走 /api/generate async**（后端 kit 提交+轮询），前端不再有 sync 分支 → 需**把 sync 语义在后端改成 async 落盘**（多数平台本就是 async） |
| async（image_mode==='async'） | 提交+前端轮询 | `/api/generate`（已做） | 无（本仓库已实现 relay-poll） |
| responses 形态（image_request_mode='responses'） | parseResponsesJson | kit 无 | **需补 responses image 协议**或保留适配 |
| 参考图归一（image_urls/base64） | imageApi 先归一 | relay-poll 后端 resolveLocalImages（已做） | 对齐 refFormat |
| 取消 AbortSignal | proxy fetch abort | relay `/api/generate/:id/cancel`（已做）+ relayPoll signal | relayGenerate 已带 signal |
| 进度 onProgress | 轮询/SSE 映射 | relay GET attach progress（relay-poll 已写） | relayGenerate 已映射 |

### 2.3 video（`videoProxy` → relay）
| proxy 分支 | 现状 | relay 承载 | 需补 |
|---|---|---|---|
| 强制 async 轮询 | 提交+前端轮询 | `/api/generate`（已做，capability='video'） | 无 |

### 2.4 横切（前端 contract 层）
| 项 | proxy | relay 后 |
|---|---|---|
| 前端「成功双写 taskStore.done + node.data」 | useNodeGeneration 自落盘+done | backend 已写 DB；前端 GET attach 到 result → done（跳过自落盘，saveResultToTasks 已对 /files/ no-op） |
| 刷新恢复 | pollTask/initTaskRecovery 前端轮询 | **前端加载读 DB running 任务 → GET attach 同一句柄**（R6，需新建 recovery：读 /api/tasks 里 running+poll_task_id → 逐个 GET /api/generate/:id） |
| 删除面 | — | proxyGenerate 轮询段 / pollTask / ensurePolling/initTaskRecovery / 前端恢复落盘 |

## 3. 施工顺序（依赖驱动，每步 tsc+测试+真机，别一次全铺）

> 前提真源：96 号 provider 配置层已落地（config/providers + 后端 6 端点）。relay-poll 后端 + /api/generate（本仓库已实现）。

- **P0（已做）**：后端 `/api/generate` submit+GET attach+cancel+重启恢复；kit `pollModelProtocolOnce`；relayProxy 客户端；saveResultToTasks /files/ no-op；provider 配置型（96 号）。
- **P1 · relay 后端补 chat/responses 语义**：给 relay.ts 补 `/api/relay` 的 chat 流式（走 kit streamChat）+ responses 形态，或明确 image/video 全走 /api/generate、chat 走 /api/relay 同步。先让后端能力对得上 proxy 各分支（§2.1-2.2 的"需补"列）。
- **P2 · 前端 relay adapter 归一语义**：`imageApi/videoApi/chatApi` 内加 `relayCapable(provider)` + adapter，把 `{ok,url/content/error,aborted,progress}` 归一到 `GenerationResult`；`useNodeGeneration` 的落盘对 /files/ 跳过。
- **P3 · 刷新恢复 R6**：前端加载读 running 任务 → GET attach（替代 pollTask/initTaskRecovery）。
- **P4 · 逐平台验通**：先 lovart image/video/chat 真机验证（9004 + /api/relay + /api/generate），再扩其他平台协议。
- **P5 · 退役 proxy**：前端零消费后，删 proxyGenerate 轮询段 / pollTask / ensurePolling / taskStore 恢复落盘；`/api/proxy` registry 标 RESERVED→删；check:api 归零。

## 4. 关键红线
- **能力零退化**：每个 P 步校验——进度条、取消、参考图归一、错误中文降级、CLI 平台、刷新恢复，逐个有人兜住才允许删/切（docs/90 §5）。
- **chat/responses/SSE 是最难兜的**：kit 目前缺 responses chat/image 形态。全迁前必须先明确「这些形态是补 kit 协议，还是前端保留适配」——**不能静默丢失 responses 语义**（GPT-5.6/gemini 走 responses 的现实链路）。
- **provider 出站字段**：proxy 时代前端 provider 的 `protocol/image_request_mode/refFormat/volcengine_*` 决定出站；relay 时代由 config/providers + kit 协议 preset 决定。**config/providers/<id>.json 必须把决定出站的字段固化**，否则全迁后模型按错协议出站。
- **落盘零依赖 kit**：后端 /api/generate 落盘走 saveRemoteUrl，不依赖 kit（已做）。
- **key 只进 .env**（96 号红线）。
