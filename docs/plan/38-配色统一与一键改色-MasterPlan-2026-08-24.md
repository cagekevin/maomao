# 38- 配色统一与一键改色 MasterPlan

- 创建日期：2026-08-24
- 状态：规划（待确认实施）
- 目标：建立"改一处即可全站调色 / 一键换肤"能力，消除当前 4 套配色体系并行的混乱。
- 原则：**全程视觉零变化**（只换底层机制，不改任何观感）。

---

## 一、现状与问题

maomao 前端目前存在 **4 套并行且不一致的配色体系**：

| 体系 | 定义位置 | 覆盖范围 | 问题 |
|------|----------|----------|------|
| **A. tailwind 语义 token** | `tailwind.config.js:55-91` | 72 文件（nodes/base/panels/scriptbox） | 值是**字面 hex**，不是 CSS 变量 |
| **B. director3d 自建变量** | `src/components/director3d/styles.css:6-21` | 仅 3D 浮层 | 文字色与 A **值对不上**（用了 tailwind 原生 gray-400/500） |
| **C. 原生 tailwind 灰/状态色** | `text-gray-200/400/500` 等 | 58 文件 + 56 文件状态色 | 第三套灰阶，无 token 归口 |
| **D. 组件私服灰阶** | `VideoProcessNode.jsx:1149` 等 | 个别大组件 | `#1b1b1b/#202020/#272727…` 10 个值全不在任何色板 |

### 关键证据（已核实）
- `tailwind.config.js:55-91` 颜色**全部字面 hex**，搜 `var(--` = 0 匹配，无任何变量化。
- `src/index.css:46-47` 写死 `background:#0f0f0f; color:#e5e5e5`，这两个值**不在 tailwind 色板**，凭空第四组。
- `director3d/styles.css:13-15` 的 `--text #e5e5e5` / `--text-dim #9ca3af` / `--text-faint #6b7280`，注释声称"对齐 maomao token"，实际对应 A 体系的 `#dddddd`/`#aaaaaa`/`#888888`，**注释与值不符**。
- 裸 hex 方括号（`bg-[#1b1b1b]` 等）约 49 处、内联 style / JS 变量 hex 约 45 文件，散落无法被 tailwind 管控。
- 项目已在 `NodeShell.jsx:90`、`TemplateNode.jsx:101` 立"禁止裸色值"规范，但 `VideoProcessNode` 等大量违例，未执行。

### 改一个全局色现在的成本（举例）
- 改"节点背景 `#1a1a1a"` → 至少 **8 个点**：token 源、director3d 变量、director3d 绕过变量的硬写、AgentPanel 的 `to-[#1a1a1a]`、OverlayEditor 内联 style，另加一堆近似不同值（`#1b1b1b/#191919/#171717`）。
- 改"全局文字色" → `text-primary(#ddd)` 与 `text-gray-200(#e5e7eb)` 分散 58 文件，需逐文件替换。
- 改"画布底 `#0d0c0c"` → 4 处（`tailwind.config.js:56`、`index.css:54`、`index.css:61`、`App.jsx:1310`）。

### 好消息（改造抓手）
- 语义命名**已经做完**（`surface-*`/`text-*`/`edge-*` 层级清晰，`tailwind.config.js:40-54` 注释完整）。
- `src/index.css:11-27` 的 `@layer components`（`.node-btn-primary`/`.node-btn-settings`）已证明"集中定义 + 组件引用"在本项目可行，注释明说"改一处全生效"。
- 因此只需把"字面 hex"升级为"CSS 变量引用"，即可获得真正的一键改色能力，**无需重命名任何类名、不碰组件代码**。

## 二、目标架构

```
:root (src/index.css)          ← 真值唯一来源（一键改色入口）
   ├── --mao-canvas / --mao-surface / --mao-surface-1 …（背景）
   ├── --mao-text-strong / primary / secondary / muted …（文字）
   └── --mao-edge / edge-strong / edge-faint …（边框）

tailwind.config.js colors      ← 改为 var(--mao-*) 引用（零视觉变化）
   surface: 'var(--mao-surface)', primary: 'var(--mao-text-primary)', …

director3d/styles.css          ← 变量改为引用同一批 :root 变量（与 A 对齐）
   --bg: var(--mao-surface); --text: var(--mao-text-primary); …

组件 / 节点                     ← 维持现有 tailwind 类名不变（A 体系）
   bg-surface-muted / text-primary / border-edge …
```

改造后：改 `:root` 一个变量值 → 全站（用 token 的 72 文件 + director3d 浮层）立即跟着变；再加 `html[data-theme="light"]` 即可一键换肤。

## 三、分阶段实施计划（低风险、可随时停下）

### 阶段 1 — 建立 `:root` 变量层（基石，零视觉变化）⭐ 先做

> ⚠️ 关键约束（审计修订）：
> - **必须用 RGB 三段式 + `<alpha-value>`**，否则 `bg-blue-500/15`、`text-blue-300`、`border-blue-500/60` 这类带透明度修饰符的颜色会失效（Tailwind v3 无法从 `var()` 字符串解析 RGB 通道）。
> - **`index.css:46-47` 的 `#0f0f0f`/`#e5e5e5` 必须保留专属变量**，不能并入 `canvas(#0d0c0c)`/`primary(#dddddd)`——两者值不同，并入即引入观感变化，违背"零视觉变化"。

1. 在 `src/index.css` 顶部全局区新增 `:root`，变量用 **RGB 三段式**存储：
   ```css
   :root {
     --mao-canvas: 13 12 12;        /* #0d0c0c */
     --mao-surface: 26 26 26;       /* #1a1a1a */
     --mao-surface-1: 34 34 34;     /* #222222 */
     /* … 其余 30+ 个按 tailwind.config.js:55-91 原值转换 … */
     --mao-app-bg: 15 15 15;        /* #0f0f0f 仅用于 html/body/#root 底色，专属保留 */
     --mao-app-text: 229 229 229;   /* #e5e5e5 仅用于 html/body/#root 文字，专属保留 */
   }
   ```
2. 把 `tailwind.config.js:55-91` 的字面 hex 改为 `rgb(var(--mao-xxx) / <alpha-value>)` 形式：
   ```js
   canvas: 'rgb(var(--mao-canvas) / <alpha-value>)',
   surface: 'rgb(var(--mao-surface) / <alpha-value>)',
   primary: 'rgb(var(--mao-text-primary) / <alpha-value>)',
   // … 全部 30+ 个
   ```
3. `src/index.css:46-47` 的 `background:#0f0f0f; color:#e5e5e5` 改为 `background: rgb(var(--mao-app-bg)); color: rgb(var(--mao-app-text));`（值不变，仅改为变量引用）。
4. 同时把 `index.css:14,22` 的 `@layer components` 里 `hover:border-gray-500`/`text-gray-200` 纳入阶段 3 处理（此处不动）。
- **交付物**：构建验证通过、视觉零变化、已具备"改 `:root` 即全局调色"能力。
- **风险**：低（机制替换，需确认透明度色仍生效）。

> 说明：原生 tailwind 调色板（`blue-500`、`gray-500` 等）**不纳入此变量层**，保持原样（状态色/语义灰留待阶段 3 区分处理），阶段 1 只管 `colors:{}` 里那 30+ 个自定义 token。

### 阶段 2 — 收编 director3d（体系 B）
1. `director3d/styles.css:6-21` 的 20 个变量改为引用 `:root` 的同一批 `--mao-*` 变量，消除与 A 的文字色偏差（`#e5e5e5→#dddddd` 等）。
2. 顺带清理该文件内 113 处绕过自身变量直写的 hex（改为引用变量）。
- **交付物**：3D 导演台与画布文字/背景彻底统一。

### 阶段 3 — 清理散落（体系 C/D，可渐进、不阻塞前两步）

> ⚠️ 范围限定（用户 2026-08-24 补充）：
> - **本轮只动「背景色」和「文字色」两类**。强调色 / 状态色（blue / live / danger / red-400 / emerald 等）、边框（edge-*）、纯渲染内容（canvas / three.js 材质 / 媒体占位）**全部推迟到最后一轮**，本轮一律不动。
> - **图标 + 文字成组优先、且必须一起改**（用户 2026-08-24 补充）：按钮 / 图标组是「背景底色 + 文字色 + 图标色」三者耦合。收编时：
>   1. 先识别成组元素（一个 lucide 图标 + 一段文字在同一 button / 行 / 标签里）；
>   2. 改文字色 token 时，**必须确认图标色走 `currentColor` 跟随文字**（或一并改为同一 token），禁止只改文字而图标脱节；
>   3. 改背景底色时，若该组内有文字 / 图标，背景、文字、图标三者要一起评估，不能只改其一。

1. **区分装饰灰 vs 语义灰再处理**（审计修订）：`gray-*` 既用于纯装饰（可重映射 `text-primary/secondary/muted`），也用于语义场合（如 `text-gray-400`=禁用、`bg-gray-800`=代码块），不可无差别替换。先扫描归类，装饰灰重映射，语义灰保留或建专门 token。
2. 把约 49 处裸 hex 方括号（`bg-[#1b1b1b]` 等）换成 token 类名。
3. `VideoProcessNode.jsx` 等"私服灰阶"收编进 token。
4. 内联 style / JS 变量 hex（canvas、three.js 等无法用 tailwind 管的部分）统一从 `:root` 读取或抽常量为一处。
5. `index.css:14,22` 的 `@layer components` 里 `hover:border-gray-500`/`text-gray-200` 一并收编。
- **交付物**：全站无裸色值，符合 `NodeShell.jsx:90` 既有规范。
- **说明**：此阶段工作量大，可按目录分批做，不影响 1/2 已获得的"一键改色"能力。

### 阶段 4 — 多主题 / 换肤（终极）
1. 在 `:root` 变量层基础上，增加 `html[data-theme="light"]`（或换肤面板）覆盖一组变量。
2. 提供换肤 UI 或配置项。
- **交付物**：用户要的"后期一键修改颜色 / 换肤"完全成立。

## 四、验收标准
- [ ] 阶段 1 后：修改 `:root` 任一变量，全站（含 director3d 浮层）对应颜色实时变化；构建通过、视觉无回归。
- [ ] 阶段 2 后：director3d 文字色与画布 token 完全一致（不再有 `#e5e5e5` vs `#dddddd` 的偏差）。
- [ ] 阶段 3 后：全仓 `grep` 裸 hex 方括号 / `text-gray-*` 命中降至 0（或仅剩 JS/canvas 必要处且已集中常量）。
- [ ] 阶段 4 后：切换 `data-theme` 即可整体换肤。

## 五、建议执行顺序
**阶段 1 → 阶段 2 →（阶段 3 分批）→ 阶段 4**。
阶段 1 单独做完即已满足"一键改色"核心诉求，后续阶段可择机推进。
