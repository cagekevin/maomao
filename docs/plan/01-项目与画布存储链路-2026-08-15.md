# 01 功能：项目与画布存储链路

> 日期：2026-08-15
> 本文档梳理「项目 / 画布 / 持久化」的完整逻辑，并说明与官方（reference-1mao）实现对齐情况。

## 一、存储层架构（3 层）

```
浏览器 localStorage                 localTool (127.0.0.1:18080, SQLite)      跨端
├─ yimao:projects          项目列表  ├─ /api/projects        项目列表(同步)
├─ yimao:lastOpenedProject 最近打开  ├─ /api/kv/*            画布快照 KV
└─ (自动保存/配置)                   └─ canvas-state-v1-<id>  各项目画布快照
                                     └─ canvas-state-v1-<id>_version  版本号
```

- **项目列表**：前端 localStorage 是本地快照；localTool `/api/projects` 是权威源（跨端同步，以它为准）。
- **画布快照**：走 KV（localTool SQLite），key 前缀 `canvas-state-v1-` 自动分流。
- **lastOpenedProject**：localStorage + localTool 双写。

## 二、启动流程（挂载时）

1. `main.jsx` → `initStorage()`。
2. `projectStore` 模块初始化：`projects` = 读 localStorage，`currentProjectId` = 读 `lastOpenedProject`（无则回退 `default`）。
3. **App 首次渲染**，ReactFlow 用 `key={activeProjectId}`。
4. **加载 effect**（依赖 `activeProjectId`）：
   - `loadCanvasState(getCurrentProject().id)` 读 KV 对应项目快照 → `setNodes/setEdges`。
   - 无快照（新项目）→ 保留空画布。
5. **`initProjects()`**（异步）读 localTool `/api/projects`：
   - 若后端有项目 → 覆盖 `projects`，`currentProjectId` = 后端 `lastOpened` → **`persist()` 同步 localStorage** + `notify()`。
   - `notify()` → `activeProjectId` 变化 → **加载 effect 重跑** → 加载正确项目画布。

> 修复：`initProjects` 覆盖后若不同步 localStorage，刷新会读旧值短暂闪 default 再跳正确项目。已补 `persist()` 同步。

## 三、项目切换 / 新建

- **切换项目**（`handleSwitchProject`）：`persistCanvas(旧id)` 保存旧画布 → `switchProject(targetId)` 改 currentProjectId → `key` 变 → ReactFlow **重挂载** → 加载 effect 加载目标项目。
- **新建项目**（`handleCreateProject`）：ProjectSelector 传 `prevProjectId`，先 `persistCanvas(prevProjectId)` 存旧画布 → `setNodes([])` 清空 → `key` 变重挂载 → 新项目空画布。

> 修复：之前用 `getCurrentProject().id`（已被 `createProject` 切到新项目）导致旧节点误存进新项目 key → 新项目=旧内容。现已改为用旧 id 保存。

## 四、自动保存（节点变化）

- 节点/连线变化 → `canvasLoaded` 为 true → **600ms 防抖** → `persistCanvas(getCurrentProject().id)`。
- `persistCanvas` → `saveCanvasState(projectId, nodesRef.current, edgesRef.current)`：
  - **空画布跳过保存**（防空覆盖历史）。
  - **版本冲突检测**：远程 `_version` > 本次 `Date.now()` → 拒绝（防多端旧覆盖新）。
  - 通过 → 写 `<id>` 快照 + `<id>_version`。
- 保存后 `BroadcastChannel` 广播 `CANVAS_SAVED`（多窗口冲突提示）。

## 五、删除项目

- `deleteProject(id)`：删项目列表 + 画布快照 `<id>` + `<id>_version`。

## 六、与官方（reference-1mao）对齐情况

| 机制 | 官方实现 | 我们现状 | 状态 |
|---|---|---|---|
| 项目切换重挂载画布 | `key={Z}`（Vr.jsx L3683） | `key={activeProjectId}` | ✅ 已对齐 |
| 画布自动保存 | 1800ms 防抖（拖拽中跳过） | 600ms 防抖 | ✅ 已实现（时长不同） |
| 新建项目保存 | 不手动保存，靠自动保存 + key 重挂载 | 先存旧画布再切 | ✅ 已修复 |
| lastOpenedProject 持久化 | `useEffect [Z]` 每次切项目即存（Vr.jsx L1104-1108） | `persist()` 在 switch/create + initProjects 时存 | ✅ 已对齐 |
| 空画布跳过保存 | `nodes.length===0` 跳过（shared.js L1405） | 已实现 | ✅ 已对齐 |
| 版本冲突检测 | `_version` 比较（shared.js L1416） | 已实现（`<key>_version` 走 KV） | ✅ 已对齐 |
| 多窗口冲突横幅 | 有 `canvasConflict` + 恢复 | 有 `canvasConflict` 状态 | ⚠️ 冲突拒绝后无恢复引导 |
| `_migration_backup` 迁移备份 | shared.js L1437 | 未移植 | ⚠️ 按需（无 localforage 迁移场景） |

## 七、边界情况 / 风险点

1. **本机时钟慢于旧数据时间戳** → 版本冲突可能误拒保存。极低概率，官方同样存在。
2. **空画布跳过保存** → 用户删光所有节点后刷新，会恢复历史（官方设计取舍，非 bug）。
3. **多窗口同时编辑同一项目** → 较旧窗口保存会被版本冲突拒绝，但当前实现没有 UI 提示恢复（官方有冲突横幅 + 恢复按钮）。我们已有 `canvasConflict` 状态，冲突拒绝后未引导用户用远程版本。
