# 表格预览确认后提示"已写入"但表格为空 —— 系统性排查

> 现象：AI 助手返回表格预览卡 → 点「确认写入表格」→ 顶部提示「已写入「xxx」」→ 但左栏表格里什么都没有（行/列均为空）。
> 排查日期：2026-09-07
> 范围：仅针对"预览有内容 + 提示成功 + 表格空"这一组合，不涵盖"预览本身就空 / 解析失败报错"的情况。

---

## 一、确认写回的完整链路（代码级）

| 阶段 | 代码位置 | 做什么 |
|------|----------|--------|
| 1. 探测命中 | `AgentPanel.tsx` ~L441 `tryParseAssistantTableJson` → `acceptTablePreview` | AI 回复被解析成 JSON，调用 `buildPreviewResult` 一次性算好"操作后最终表" |
| 2. 存预览 | `tableWorkspaceState.ts:217` `acceptTablePreview` | 把 `resultCols / resultRows`（即最终表）存进 `state.preview` |
| 3. 渲染卡片 | `AssistantTablePanel.tsx:605-615` | 卡片 `rows` 直接由 `preview.resultRows` 映射、`columns` 由 `preview.resultCols` 映射 |
| 4. 用户点确认 | `tableWorkspaceState.ts:303` `confirmTablePreview` | 读 `state.preview` → 调 `setTabTable(tabs0, targetTabId, {columns,rows})` 写回 → `setCurrentAssistantTabs` → `switchTableTab` → `showToast('已写入…')` |
| 5. 落盘 | `conversationAiState.ts:135` `setCurrentAssistantTabs` | 写入当前对话 `memory.assistantTables` 并 `commit` 落盘 |

**关键事实**：卡片显示的内容（`resultRows`）与真正写回的内容（`p.resultRows`）是**同一个对象**（见 `tableWorkspaceState.ts:236` 与 `:323`）。因此"卡片有、落盘没有"这种情况在代码层面不成立——只要卡片显示了行，`resultRows` 就一定非空。

→ 所以根因一定在 **第 4 步写回** 或 **第 5 步读回/渲染**，而不在"预览推导"。

---

## 二、最可能原因（按可能性排序）

### 原因 1（高）：`targetTabId` 对不上任何 tab → 写回静默 no-op，但成功提示照样弹

`confirmTablePreview`（`tableWorkspaceState.ts:303`）的逻辑：

```ts
const targetTabId = p.targetTabId || getActiveTab(tabs0)?.id || '';
if (!targetTabId) { ... return ok:false }          // 仅当空字符串才拦
...
let tabs1 = setTabTable(tabs0, targetTabId, { columns: p.resultCols, rows: p.resultRows });
```

- `setTabTable` → `updateTab`（`assistantTable.ts:769` / `:752`）**只更新 id 匹配的 tab**；若 `targetTabId` 在当前 `tabs0` 里**不存在**，`updateTab` 原样返回 `tabs0`，即**什么都不写**。
- 但此时 `targetTabId` 是**非空字符串**，绕过了上面的 `if (!targetTabId)` 守卫，代码一路走到成功分支：
  - `setCurrentAssistantTabs(tabs1)` 把**未改变的 tabs** 写回（数据被丢弃）；
  - `switchTableTab(targetTabId)` 把 `activeTabId` 设成不存在的 id，`normalizeAssistantTabs` 读时回退到**第一张表**（通常为空）；
  - `markMessageTableResolved('confirmed')` + `showToast('已写入「xxx」')` 照常触发。

**结果**：提示"已写入"，但表里什么都没有——与现象**完全吻合**。

触发条件（`targetTabId` 在确认时已失效）：
- 预览生成后、确认前，目标表被**删除**（`deleteTab` 若未同步清 `state.preview`）；
- 预览生成后、确认前，目标表被**重建/替换**导致 id 变化；
- 其它任何让 `p.targetTabId` 与当前 `tabs0` 中真实 tab id 集不一致的路径。

验证方法：
1. 复现后立刻看 `console` / `logger` —— 该路径**不会**打 `logger.warn`（只有"无列/无目标 tab 空串"才会），属于**完全静默**的丢失；
2. 在 `confirmTablePreview` 写回前加一句：若 `getTab(tabs0, targetTabId) == null` 则 `logger.error` 并 `showToast` 报错（见第四节修复建议）。

### 原因 2（中）：数据其实写进去了，但写到了"另一张 tab"，用户看的是空的那张

- 成功写回后 `switchTableTab(targetTabId)` 会把视图切到目标 tab；**但若 `targetTabId` 无效**（见原因 1），`normalizeAssistantTabs` 回退到第一张表，用户落在空表。
- 即便 `targetTabId` 有效，若用户后续手动切回其它 tab，也会误以为"没写进"。

验证方法：确认后依次点一遍所有 tab（表1 / 表2…），看数据是否在其中某张。

### 原因 3（低）：`commit` 未触发视图重渲（状态写了但没刷新）

- 写回走 `setCurrentAssistantTabs`（`conversationAiState.ts:135`）→ `commit(...)`；随后 `switchTableTab` 又 `setActiveTableTab` → 再次 `commit`。
- 左栏 `useActiveAssistantTable`（`useActiveAssistantTable.ts:39`）用 `useStoreSelector(subscribe, getState, ...)` 订阅 `conversationState`，`commit` 应通知订阅者重渲。
- 若 `commit` 的通知被某处吞掉 / 选择器 `shallowEqual` 误判相等，会出现"内存已有数据但表格不刷新"。

验证方法：写回后**切换对话再切回**，或刷新页面 —— 若数据出现，说明是渲染/订阅问题而非写入问题（落盘成功）。

### 原因 4（低）：`normalizeAssistantTabs` 落盘时把数据当脏数据丢弃

- `setCurrentAssistantTabs` 在落盘前会再 `normalizeAssistantTabs(tabs)`（`conversationAiState.ts:149`）。
- `buildPreviewResult` 产出的 `TableRow`/`TableColumn` 都带 `generateId`，结构合法，正常不会被丢。
- 仅当 `resultRows` 中某行缺 `id`/`values` 等才可能在 `normalizeTab` 阶段出问题——当前代码路径不会产出这种结构。

## 三、已排除的原因

| 怀疑点 | 为什么排除 |
|--------|-----------|
| 卡片渲染与写回用了不同数据源 | 卡片 `rows` 直接来自 `preview.resultRows`（`AssistantTablePanel.tsx:611`），写回也是 `p.resultRows`（`tableWorkspaceState.ts:323`），同源。 |
| `buildPreviewResult` 把行过滤空了 | `replace` 路径只在"当前表无列"时丢全空行（`rowHasText`），但那种情况卡片也会是空的，与"卡片有内容"矛盾。 |
| 写错存储键（写了 legacy `assistantTable`） | `setCurrentAssistantTabs` 明确写 `memory.assistantTables`（`conversationAiState.ts:149`），读也读 `assistantTables`（`useActiveAssistantTable.ts:45`），键一致。 |
| 切对话串表 | 切对话 `AgentPanel` 会调 `resetTableWorkspace`（`AgentPanel.tsx:469`）清掉 `preview`，预览不会跨对话残留。 |

## 四、建议的修复（待确认后再动手）

1. **在 `confirmTablePreview` 增加 `targetTabId` 存在性校验**（堵原因 1 的根）：
   ```ts
   const target = getTab(tabs0, targetTabId);
   if (!target) {
     logger.warn('AI助手', '表格确认写回失败：目标 tab 不存在', { targetTabId, messageId: p.messageId });
     markMessageTableResolved(p.messageId, 'confirmed');
     setState({ ...state, preview: null });
     showToast?.('写入失败：目标表格已不存在，请重试', { type: 'error' });
     return { ok: false, mode: p.opKind };
   }
   ```
2. **删除/重建 tab 时同步清 `state.preview`**（防 `targetTabId` 失效）：在 `deleteTab` / 任何改变 tab 集合的操作里，若 `state.preview?.targetTabId` 不再存在，调用 `setState({...state, preview: null})`。
3. **写回后强制 `switchTableTab` 落到真实存在的 tab**：`setActiveTabId` 应校验 id，无效则回退第一张，避免用户停在空表误判。
