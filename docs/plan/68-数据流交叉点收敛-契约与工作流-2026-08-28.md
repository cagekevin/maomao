## 贰、工作流（Workflows）

工作流 = 契约的时间序实例化。

### W1 生成成功链路（A + C 交织）

```
[发起方]                [task_id 贯穿]        [落盘唯一出口]            [done]
useNodeGeneration.start  opts.taskId=C-A ──▶ saveResultToTasks(C-C) ─▶ taskCtl.done
scriptBoxEngine          opts.taskId=C-A ──▶ localize→saveResultToTasks(C-C) ─▶ taskCtl.done
   ↑ 两者并发 → taskStore.runNodeGeneration 的 nodeRunning Map(C-E) 保证单节点只发一次
```

### W2 任务完成广播（D 唯一入口）

```
done 成功 / poll 刷新恢复
   └ publishTaskCompleted({taskId,nodeId,resultUrl,type,status:'completed'})
        └ 校验通过 → publish('agent:task-completed')
             └ 精准回填 node.data（useNodeGeneration onRecover，d.nodeId === nodeId）
```

### W3 信封解析（B 委托）

```
readSseUrl / pollUntilDone / pollTask.extractResultUrl
   └ 统一调 extractResultUrl({data,json,type})
        └ resolveMediaType(url, mediaType) 先判型再取值，防 video 被当 image
```

### W4 并发锁（E）

```
runNodeGeneration(nodeId)：
  genActive 占槽（上层全局并发） → nodeRunning 查重（单节点互斥）
     ├ 无进行中 → 真生成 → finally 释放两把锁
     └ 有进行中 → 返回 { ok:false, inFlight:true }
```

### W5 上游驱动下游（G，安全网，默认关）

```
上游 done → publish('upstream:updated',{sourceNodeId})
   → useConnectedInputs 找 edge.target===直接下游
   → 若开关开 → 自动触发一次；否则保持待生成
   → NODE_OUTPUTS 编译期 check 未声明类型 → warning（G2）
```

## 伍、验收口径

1. **task_id 不再全局串扰**：任意并发下请求体 `payload.taskId` 与任务记录一一对应。
2. **URL 提取单一**：≥5 处委托一个解析器，同一样例输出一致，grep 只命中解析器模块。
3. **结果落盘单向**：任一生成仅 1 次落盘出口；`taskStore.done` 不再落盘、不 import `saveResultToTasks`；剧本盒 tasks+素材库两目录都不缺。
4. **事件纪律收敛**：`agent:task-completed` 唯一发布入口；`CREDIT_GATE_EVENT` 全走常量；asset 发送无平行裸回调桥；事件表无"待核对"。
5. **并发锁生效**：Agent 与手动同节点并发只 1 次真请求，第 2 次得明确"进行中"。
6. **存储无双真相**：KV 恢复后降级副本被清；`d3dPersistence` 登记与实相符。
7. **拓扑有安全网**：上游完成可按配置驱动直接下游；未声明产出类型构建期有 warning。
8. **云同步透明**：cloudSync 无裸 URL；账号/ApiKey 加密且不随请求体明文。

## 陆、翻车点审计（落地前必读）

### F1 〔高·最需注意〕A 与 C 都改 scriptBoxEngine 同一文件
- scriptBoxEngine:336（C-A 写 task_id）与 :376（C-C 补落盘）在同文件紧邻。若 A、C 分两批改，第二批容易漏看第一批改动而对同一段重写 → 回归。
- **缓解**：P0-A 与 P0-C 同批次施工；改动后立即跑"剧本盒批量生成资产图"回归（tasks 目录 + 素材库目录 + 并发不串）。

### F2 〔高〕移除 done 落盘会改变 done 的返回时机契约
- done 现在是"落盘完成才广播 persistedUrl"（[taskStore.js:200-209](file:///g:/01画布项目/maomao/src/components/base/taskStore.js#L200-L209)）。改后 done 立即广播（用传入的最终 url），**广播时机提前**；onRecover 回填的 resultUrl 必须是已持久 url（由调用方落盘后传入）。
- **缓解**：所有广播前 `resultUrl` 必须是持久 `/files/` URL 的校验写进 `publishTaskCompleted`；回填逻辑不受影响。

### F3 〔中〕B 的 doneUrl 取舍若悬空 → 半成品契约
- 附录里 `r.doneUrl || r.url` 有消费无生产，若 C-B 施工时不二选一定死，仍保留"悬空契约"。
- **缓解**：C-B 内强制执行 B1/B2 二选一，并把结论写进 imageApi 头部注释。

### F4 〔中〕E 的 nodeRunning Map 与 start 的 runningRef 双重防线
- 若 `runNodeGeneration` 用 Map 拦截，但 `useNodeGeneration.start` 内部 `runningRef` 已先就位，会出现"start 返回 false，而 runNodeGeneration 期望真生成"的歧义。
- **缓解**：`runNodeGeneration` 触发的是节点的 start（`retryRegistry` 回调），Map 拦截应发生在调用 start **之前**、返回 `{inFlight:true}`；并明确 `{inFlight:true}` 与 start 的 `false`（重入/校验失败）语义区分，不静默。

### F5 〔中〕D 的事件表 from/to 行号漂移
- contracts.js 事件表行号靠人工维护（[contracts.js:41-47](file:///g:/01画布项目/maomao/src/components/base/contracts.js#L41-L47) 自述会漂移）。D5 清"待核对"后改的不是行号而是事实，仍须以 grep 复核为准，禁止只看表。
- **缓解**：D 落地用 grep 实测结果反写 from/to，不手工猜行号。

### F6 〔低〕F2 的 d3dPersistence 是独立 KV 通道，非 contentStore
- `d3dPersistence.writeProject` 直写 localTool KV 并自带降级（[d3dPersistence.js:188-217](file:///g:/01画布项目/maomao/src/components/base/d3dPersistence.js#L188-L217)），不经 contentStore/storageSet。F2 要"登记进 STORAGE_KEYS + getBackend 返回登记值"只解决"语义空洞"，**不接管其读写通道**——别误当成要把它迁进 contentStore。

### F7 〔低〕G 直接下游定位依赖 useConnectedInputs 只接一层
- `edge.target === nodeId` 已按边目标取直接上游（[useConnectedInputs.js:149](file:///g:/01画布项目/maomao/src/components/base/useConnectedInputs.js#L149)）。G1 反查"直接下游"要按 `edge.source === 节点` 且 `edge.target !== 自身`，注意 group 聚合出口（[:155](file:///g:/01画布项目/maomao/src/components/base/useConnectedInputs.js#L155-L165)）不在此自动触发范围。
