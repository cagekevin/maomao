# 46 · 配置开关生效机制与"持续循环"收口 PRD

> 日期：2026-08-25
> 范围：`src/components/director3d/`（3D 导演台）
> 目标：把"所有可配置的勾选 / 开关类项"按"生效机制"分类收口——**勾选即生效**的开关应独立于时间轴关键帧，不能被关键帧录制覆盖；需要动画变化的属性仍走关键帧。定位 `continuousMotion` 的基础层病灶并给出收口方向。
> 状态：**调研 + 方案（未实施）**

---

## 一、问题背景

用户预期：**"勾选 / 点亮一个开关，它就应该在播放时生效"**。但当前存在一个反直觉的坑：

- 人物勾选"随时间轴循环动作"（奔跑），若**先打过动作关键帧、后勾选**，则一播放人物**不走**——因为关键帧里录的是打帧那一刻的 `continuousMotion=false`，播放求值时被关键帧值覆盖，对象级勾选（基线 `true`）失效。

这不是孤立 bug，而是**数据模型层"持续循环"语义没有独立存储位置**——它寄生在"动作关键帧快照"里。本文件先把所有开关类项找全、分类，再给收口方案。

---

## 二、全部可配置勾选 / 开关类项清单

按"生效机制"分两大类。

### A 类 · 对象级开关（应"勾选即生效"，独立于关键帧）

控制的是**对象自身状态 / 约束 / 配置**，不是"随时间变化的动画量"。

| # | 属性 | 适用对象 | UI 入口 | 数据落点 | 是否参与关键帧求值 | 现状判定 |
|---|---|---|---|---|---|---|
| A1 | `continuousMotion` | 人物 | Inspector `随时间轴循环动作` 勾选框 (`Inspector.jsx:117`) | 对象基线 `objects[].continuousMotion`；同时被 `objectKeyframeFromObject` 录进 action 通道关键帧 (`project.js:471,903`) | **是**（被 action 通道覆盖） | ❌ **病灶**：关键帧值优先级高于基线 |
| A2 | `footLock` | 人物 | Inspector `脚底锁定` 勾选框 (`Inspector.jsx:147`) | 仅对象基线 `objects[].footLock`；不在 `ENTITY_CHANNELS` 任何通道 | 否 | ✅ 安全（不参与求值，播放不会被冲） |
| A3 | `locked` | 非镜头对象 | Inspector 头部锁图标 (`Inspector.jsx:54`) | 对象基线 `objects[].locked`；不在通道清单 | 否 | ✅ 安全 |
| A4 | `visible` | 参考图 | ReferenceOverlay | 对象基线 `reference.visible` | 否 | ✅ 安全 |
| A5 | `includeInExport` | 参考图 | ReferenceOverlay `进入导出` (`ReferenceOverlay.jsx:59`) | 对象基线 | 否 | ✅ 安全 |
| A6 | `targetMode` / `targetId` | 镜头 | Inspector `始终面向对象` 下拉 (`Inspector.jsx:91`) | 镜头基线 `camera.targetMode/targetId`；在 `setCameraAtFrame` 与导出恢复处**强制保留合并** (`App.jsx:682,684,1250`) | 否（求值端显式保留） | ✅ **正确范式**：开关始终来自镜头对象，不被 `cameraAtFrame` 冲掉 |

> 备注：A3/A4/A5 是"编辑期约束 / 显示开关"，本身就不该进时间轴，当前安全。
> 备注：`proportionalScale` / `scaleAxisLocks`（缩放比例锁定）属于对象级变换约束，也不在通道清单，播放安全，未列入开关表（属变换子配置）。

| B4 | `seamlessBackground` | 无缝背景 | 全局设置 `无缝背景` (`GlobalSettingsPanel.jsx:73`) | 运行时 state | ✅ 纯显示 |

### C 类 · 必须打关键帧才能产生动画的属性（正确依赖关键帧，**不**属于开关）

这些不是开关，列出是为了划清边界——它们本就该靠关键帧驱动，不应改成"勾选即生效"：

- **transform 通道** (`project.js:163`)：`position` / `rotation` / `scale`
- **action 通道**里的 `pose`（动作切换）/ `poseTime`（相位）：状态切换靠关键帧在段间硬切 / 插值，这是正确的
- **skeleton 通道**：`rigRoot` / `joints`
- 镜头运动路径 `paths`（独立位置来源，替代位置关键帧）

**结论**：整个 3D 导演台里，唯一承担"勾选即持续循环"语义的本质属性是 **A1 `continuousMotion`**；A6 `targetMode`/`targetId` 是另一个"勾选即生效"的对象级开关且已实现正确。其余开关要么是编辑约束（安全），要么是全局维度（无冲突）。

## 三、核心病灶：`continuousMotion` 为何不灵

### 3.1 数据流（当前）

```
对象基线 objects[].continuousMotion (Inspector 勾选改这里)
        │
        │ addObjectKeyframe 时 objectKeyframeFromObject 录快照
        ▼
characterKeyframes[id].action[].fields.continuousMotion  ← 冻结为"打帧那一刻"的值
        │
        │ 播放/拖帧：objectsAtFrame → objectAtFrame → synthesizeObjectState
        ▼
evaluateActionChannel (project.js:791)
   motionEnabled(key) = poseCanLoop(pose) && (field(key,'continuousMotion')===undefined ? 基线 : 关键帧值)
   ↑ 关键帧有值就用关键帧，忽略基线
        │
        ▼
result.continuousMotion = action.continuousMotion   ← 覆盖基线
        │
        ▼
Viewport → MixamoPersonModel：continuousMotion && preset.loopable ? 循环 : 静止
```

### 3.2 病灶定性

1. **职责错位**：`continuousMotion` 是"对象/状态级开关"，却被注册进 `action` 通道 (`project.js:164`) 与 `pose` 一起被关键帧录制、覆盖。
2. **求值端压制基线**：`evaluateActionChannel` 对有关键帧的字段用关键帧值，导致对象级开关失效（先打帧后勾选的场景）。
3. **录制时刻冻结**：`objectKeyframeFromObject` 把当时基线快照进关键帧，之后改基线不回写关键帧。

### 3.3 对照正确范式（A6 `targetMode`）

`targetMode` 在 `setCameraAtFrame`（`App.jsx:678`）中：

```js
const interpolated = cameraAtFrame(keyframes, frame, current.aspectRatio)
return { ...interpolated, targetMode: current.targetMode, targetId: current.targetId } // 强制保留基线开关
```

即：**插值的变换量可以来自关键帧，但"始终面向人物"这个开关永远从镜头对象自身取，不被覆盖。** 这正是 A1 应该对齐的做法。

## 四、收口方案（对齐 A6 范式，不打补丁）

### 4.1 原则

> **"勾选即生效"的对象级开关，其真值在播放/拖帧/导出时一律从对象（或镜头）基线取，不被关键帧通道覆盖。需要被关键帧动画化的，只有"量"（位置/旋转/缩放/pose/poseTime/joints），不是"开关"。**

### 4.2 `continuousMotion` 改造（唯一方案：求值端强制保留，同时撤销通道注册）

**方案 · 求值端强制保留（对齐 `targetMode`）**
- 在 `synthesizeObjectState` 合成 `action` 之后，**用对象基线 `continuousMotion` 覆盖求值结果**（与 `setCameraAtFrame` 保留 `targetMode` 同构）：
  ```js
  // synthesizeObjectState 内，action 处理之后
  if (object.type === 'person') {
    result.continuousMotion = Boolean(object.continuousMotion) && poseCanLoop(result.pose)
  }
  ```
- 同时把 `continuousMotion` 从 `ENTITY_CHANNELS.person.action`（`project.js:164`）移除，使其**不再被关键帧录制**（撤销冗余存储与误导）。
- 这样无论是否打过关键帧、打帧时开关状态如何，只要基线勾选 + 当前 pose 可循环，播放即循环。

> **行为变化（决定采纳，非回归）**：强制沿基线后，`continuousMotion` 不再随关键帧变化，因此依赖"冻结关键帧"实现的**同段循环、跨段静止**式差异化循环策略被取消——持续循环从"随段可变"变为**整段恒一**。这正是本文件要根治的病灶语义，且旧工程无需兼容，故判定为预期结果，不视为兼容负担。

> **承接**：本方案是"点修"；把该类规则**集中沉淀**为三层注册表机制、避免今后每次加开关都手写保留逻辑，见 `docs/47-属性归属三层注册表设计`。二者一致指向 `continuousMotion` 撤销通道 + L2 沿基线覆盖。

### 4.3 顺带核对（已确认安全，无需改）

- `footLock` / `locked` / `visible` / `includeInExport` 均不在 `ENTITY_CHANNELS` 通道清单，不被 `objectAtFrame` 接管，播放安全。
- `targetMode/targetId` 已在 `setCameraAtFrame` 与导出恢复两处保留，安全。
- 全局开关 B1–B4 维度独立，安全。

### 4.4 规则沉淀（供后续新增开关遵守）

新增"勾选即生效"类属性时：
1. **不要**把它放进 `ENTITY_CHANNELS` 的任何通道（否则会被关键帧录制/覆盖）；
2. 在相应"写回帧求值结果"的入口（`setCameraAtFrame` 对应物为对象侧的 `objectAtFrame` 合成器 / 或 `animatedObjects` 计算处）**显式保留基线值**；
3. Inspector 开关直接改对象/镜头基线即可，无需触碰关键帧。
