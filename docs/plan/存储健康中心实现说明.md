> 入口组件：`src/components/settings/StorageHealthCenter.tsx`
> 磁盘扫描服务：`src/services/fs/storageHealth.ts`
> 浏览器配额服务：`src/services/storageQuota.ts`

本文从「功能契约」到「数据源」完整梳理该功能的实现链路，说明它扫什么、数据从哪来、如何计算可释放空间，以及它与「自动保存失败」的联动关系。

---

## 1. 功能概述

存储健康中心用于检测**两个独立维度**的存储状况：

1. **浏览器存储配额**（IndexedDB）—— 画布结构化数据（节点、连线、项目元数据等）存在浏览器 IndexedDB 中，配额用尽会导致**自动保存失败**。
2. **本地磁盘占用**（Tauri 文件系统）—— 媒体素材文件存在项目数据目录里，占用的是真实磁盘空间。

两者是「两笔账」，UI 中分别展示。

UI 提供「重新扫描」按钮，扫描后展示：

- 总占用空间与可释放空间（含 SVG 圆环图、按类别的占比）
- 各项目占用空间（条状图）
- 回收站残留（`.trash`）、孤儿文件、重复文件三类「可优化空间」，并提供**逐项/批量清理**操作

## 2. 功能契约（数据模型）

所有类型定义位于 `src/services/fs/storageHealth.ts`。

### 2.1 单项目磁盘占用

```ts
interface ProjectStorageInfo {
  projectId: string;
  projectName: string;
  dataDir: string | null;   // 项目数据目录路径；不可用时为 null
  fileSize: number;         // 目录内文件总大小（不含 .trash）
  fileCount: number;        // 文件数量
  categories: Record<string, { count: number; size: number }>; // 按类别统计
}
```

文件类别由扩展名判定（`getFileCategoryName`）：

| 类别 | 扩展名 |
| --- | --- |
| 图片 | `.png .jpg .jpeg .gif .webp .svg .bmp` |
| 视频 | `.mp4 .webm .mov .avi .mkv` |
| 音频 | `.mp3 .wav .ogg .aac .flac` |
| 文本 | `.txt .md .json .csv .xml .html` |
| 其他 | 其余全部 |

> 注意：storageHealth 内部分类为硬编码子集，与 `fs/core.ts` 的 `CATEGORY_EXTENSIONS` 不共用同一常量表，后续如需收敛可抽取。

### 2.2 三类「可优化空间」

```ts
/** .trash 回收站残留 */
interface TrashInfo {
  projectId: string; projectName: string;
  trashDir: string;      // .trash 目录路径
  trashSize: number;     // 总大小
  fileCount: number;
}

/** 孤儿文件：存在于磁盘但未被任何节点 data.filePath 引用 */
interface OrphanFileInfo {
  path: string; name: string; size: number;
  projectId: string; projectName: string;
}

/** 重复文件：按 size+name 组合键分组，同组 >=2 份 */
interface DuplicateFileGroup {
  key: string;  // `${size}|${name}`
  files: { path: string; name: string; size: number; projectId: string; projectName: string }[];
  reclaimableSize: number;  // 保留 1 份，其余可删：size * (len - 1)
}
```

### 2.3 扫描报告

```ts
interface StorageHealthReport {
  projects: ProjectStorageInfo[];   // 各项目占用
  trashes: TrashInfo[];             // .trash 残留
  orphans: OrphanFileInfo[];        // 孤儿文件
  duplicates: DuplicateFileGroup[]; // 重复文件组
  offlineFolders: ExternalFolderStatus[]; // 离线外部文件夹（当前调用传空数组）
  scannedAt: number;                // 扫描时间戳
  totalSize: number;                // 总占用（各项目 fileSize 之和）
  reclaimableSize: number;          // 可安全释放（trash + orphan + duplicate 累加）
}
```

## 3. 数据源

### 3.1 项目与节点（来源：Zustand store）

`StorageHealthCenter` 从 `useAppStore`（`src/store/useAppStore.ts`）以 `useShallow` 订阅：

```ts
const { projects, nodes, showToast } = useAppStore(
  useShallow((s) => ({
    projects: s.projects,        // CanvasProject[]
    nodes: s.nodes,              // 当前画布节点
    showToast: s.showToast,
  })),
);
```

- `projects`：`CanvasProject[]`（类型见 `src/types/index.ts`），是扫描各项目的**清单来源**。
- `nodes`：当前项目的画布节点，用于**收集已被引用的文件路径**，从而判定孤儿文件。

> 注意：`nodes` 取自 store 的当前项目节点。因此**孤儿判定仅覆盖当前项目**的引用集；其余项目没有传入各自的节点引用，会按「当前项目引用集」比对，跨项目时可能产生误报。当前实现下这是已知边界。

### 3.2 节点引用路径（孤儿判定）

```ts
export function collectNodeFilePaths(
  allNodeData: Array<{ data?: Record<string, unknown> }>
): Set<string> {
  const paths = new Set<string>();
  for (const node of allNodeData) {
    const fp = node.data?.filePath as string | undefined;
    if (fp && typeof fp === 'string') paths.add(fp);
  }
  return paths;
}
```

它只收集节点 `data.filePath` 字段。扫描出的磁盘文件若**不在该集合内**，即判定为孤儿。

### 3.3 项目数据目录（来源：fs/core）

每个项目在磁盘上对应一个数据文件夹，路径由 `getProjectDataDir(projectId)`（`src/services/fs/core.ts`）解析：

```
{baseDataDir}/{项目名-短ID}
# 或回退到系统应用数据目录
{appDataDir}/data/{项目名-短ID}
```

- 文件夹名 = `sanitizeFolderName(项目名) + '-' + 短ID`（`buildProjectFolderName`）。
- 短 ID = projectId 去连字符后取前 8 位。
- 用户可在设置里自定义 `baseDataDir`，未设置时回退到 `appDataDir/data`。
- 旧项目可能只有 projectId 命名的目录，`resolveProjectFolder` 会回退到 projectId。

### 3.4 浏览器存储配额（来源：navigator.storage）

`src/services/storageQuota.ts`：

```ts
export async function estimateBrowserStorage(): Promise<StorageEstimate | null> {
  if (typeof navigator === 'undefined' || !navigator.storage?.estimate) return null;
  const { usage = 0, quota = 0 } = await navigator.storage.estimate();
  return { usage, quota, ratio: quota > 0 ? usage / quota : 0 };
}
```

- `usage`：当前 origin 已用的存储（**含 IndexedDB 与 Cache Storage**）。
- `quota`：当前 origin 的总配额（浏览器分配，一般远大于实际用量，如界面中的 `10.00 GB`）。
- `ratio`：已用比例，`STORAGE_PRESSURE_RATIO = 0.85` 为预警阈值。

> 用户界面中显示的 `164.4 KB / 10.00 GB (0.0%)` 即来自此接口。

## 4. 扫描流程（scanStorageHealth）

```ts
export async function scanStorageHealth(
  projects: CanvasProject[],
  nodeFilePaths: Set<string>,
  assetFolders: { path: string; label: string }[] = [],
): Promise<StorageHealthReport>
```

完整执行顺序：

1. **逐项目扫描** `scanProjectStorage`：递归 `readDir` 得到 `ScanFileEntry[]`（跳过 `.trash`、`AppData`），用 `stat` 取每个文件大小，按 `getFileCategoryName` 归类累加。汇总进 `report.totalSize`。
2. **扫描 `.trash` 残留** `scanTrashDirs`：对每个项目检查 `{dataDir}/.trash`，递归统计大小，计入 `reclaimableSize`。
3. **扫描孤儿文件** `scanOrphanFiles`：把数据目录内所有文件与 `nodeFilePaths` 比对，未被引用者计入 `orphans` 与 `reclaimableSize`。
4. **扫描重复文件** `scanDuplicateFiles`：跨所有项目收集全部文件，以 `${size}|${name}` 为键分组，组内 >=2 份即视为重复，`reclaimableSize += size * (len-1)`。
5. **检测离线外部文件夹**：对 `assetFolders` 逐项 `exists` 探测；不存在则标记 `offline`。**当前 UI 调用传空数组，此环节实际不产生结果。**

全程有 `isTauriEnv()` 守卫——在**纯浏览器/Web 环境**下直接返回空报告，磁盘扫描只在 Tauri 桌面环境生效。

## 5. 清理操作

| 操作 | 函数 | 说明 |
| --- | --- | --- |
| 清空单个 `.trash` | `clearTrashDir(trashDir)` | 递归删除目录内文件后删除目录本身 |
| 清空全部 `.trash` | `handleClearAllTrash`（UI） | 遍历报告逐项清空 |
| 删除单个孤儿 | `deleteOrphanFile(path)` | `remove(path)` |
| 删除全部孤儿 | `handleDeleteAllOrphans`（UI） | 遍历报告逐个删除 |
| 删除重复文件 | `deleteDuplicateFile(path)` | 仅删除第 2 份起（索引 >0） |

所有删除函数均带 `isTauriEnv()` 守卫。UI 中删除单个孤儿/重复文件需要**悬停行**才出现按钮（`opacity-0 group-hover:opacity-100`）。

清理动作执行完后会重置 `scannedRef.current = false` 并重新 `handleScan()`，让界面数据刷新。

## 6. 与「自动保存失败」的联动

### 6.1 保存失败归因（storageQuota）

自动保存（`saveCurrentProject` / `saveCurrentProjectSilent`，`store.projects.ts`）失败时，会调用 `describeStorageError` 把晦涩的底层错误翻译成用户可读的中文：

| kind | 判定 | 提示文案 |
| --- | --- | --- |
| `quota` | `QuotaExceededError` / `NS_ERROR_DOM_QUOTA_REACHED` / code 22 / 正则含 quota·配额 | `浏览器存储配额已用尽（已用 X / Y），请到「设置 → 存储健康中心」清理` |
| `disk-full` | `no space left` / `os error 28` / `ENOSPC` / `磁盘已满` 等 | `磁盘空间不足，无法写入项目文件` |
| `unknown` | 其余 | 截断前 120 字符的错误消息 |

- `isQuotaError`：识别 IndexedDB 配额耗尽（各浏览器命名不一）。
- `isDiskFullError`：识别 Tauri 侧写文件失败（磁盘写满）。
- `estimateBrowserStorage` 在保存失败时再次读取配额，把实际用量拼进提示。

### 6.2 配额预警

- `STORAGE_PRESSURE_RATIO = 0.85`：用量比例达到 85% 时视为「受压」。
- `isStorageUnderPressure()`：供保存前预警使用（返回 `null` 表示未受压）。

在 UI 的「浏览器存储配额」卡片中：

- `ratio >= 0.85` 时卡片变橙色（`border-amber-500/40 bg-amber-500/10`），进度条变琥珀色，文案变为「配额即将用尽，自动保存可能失败，建议清理下方可释放空间或导出并删除旧项目」。
- 未受压时文案为「项目画布数据存放在浏览器存储中，配额用尽会导致自动保存失败」。

## 7. 依赖关系与调用链

```
StorageHealthCenter (UI, settings/)
  ├─ scanStorageHealth            ← services/fs/storageHealth.ts
  │     ├─ getProjectDataDir      ← services/fs/core.ts
  │     ├─ scanDirRecursive       ← @tauri-apps/plugin-fs readDir/stat
  │     └─ collectNodeFilePaths   ← 遍历 store.nodes[].data.filePath
  ├─ estimateBrowserStorage       ← services/storageQuota.ts → navigator.storage.estimate()
  ├─ clearTrashDir / deleteOrphanFile / deleteDuplicateFile
  │                                ← services/fs/storageHealth.ts
  └─ projects / nodes / showToast ← store/useAppStore.ts (Zustand)

store.projects.ts (自动保存)
  └─ describeStorageError         ← services/storageQuota.ts
        └─ isQuotaError / isDiskFullError
```

### 环境守卫（关键约束）

- **所有磁盘扫描/删除**都受 `isTauriEnv()` 保护：Web 模式下返回空结果，**不产生任何磁盘 I/O**。
- **浏览器配额**在 Tauri 与 Web 下都可用（基于 `navigator.storage`），但它统计的是 IndexedDB/Cache 用量，**不是磁盘上媒体文件的大小**。

## 8. 已知边界与说明

1. **两类存储口径不同**：浏览器配额（IndexedDB 画布数据）与磁盘占用（媒体素材文件）是两个独立维度，UI 分开展示，不要混为一谈。
2. **孤儿判定只覆盖当前项目引用**：`nodes` 取自当前项目，跨项目比对时其它项目的文件可能被误判为孤儿。
3. **重复文件判定是「启发式」**：仅按 `size + name` 分组，不校验内容哈希，存在**同名同大小但内容不同**被误报为重复的可能。
4. **外部文件夹检测当前未启用**：`StorageHealthCenter` 调用时 `assetFolders` 传空数组，`offlineFolders` 恒为空。
5. **分类常量未复用**：storageHealth 的 `getFileCategoryName` 与 `fs/core.ts` 的 `CATEGORY_EXTENSIONS` 是两套定义，扩展文件类型时需两处同步。
