# 域内深构 · 能力片规划（2026-09-20）

> **对象 = 能力片**（域内的小能力），**不是域**。判据真源 = `docs/adr/ADR-0042`（窄接口 · 厚实现 · 被**边界之外**消费；粒度 = 能力片；识别三形态见 D6）。
> **与域收口的关系**：**域收口是先决**（`docs/adr/ADR-0044`：域根清零 + 门面唯一出口 + 门面门槛）—— 否则能力片收口了也没用：消费者仍从**深路径直插**内部件（实证：`generate/lib/generate.ts` 被 7 个域外件深路径直插）。
> **两件事一张表推**：先把域的「地理边界」收干净，再把域内能力逐个变深。**域还会继续演化，能力边界比域边界稳定** —— 所以深构的落点是能力片。

## 1 · 识别三形态（怎么发现"该深的还没深"）

| 形态 | 判据（可执行） | 本轮实证 |
| --- | --- | --- |
| ① **同语义多份** | 同一能力 **>1 个定义处** | 本轮未命中（本仓已过"收口期"）；历史先例 = `setCrossOriginForReadable` 曾 3 份手拼 |
| ② **一入口多动词** | 一个模块导出**同族多个动词**，消费者**必须挑** | `base/api/filesApi.ts`：`saveInlineToLocal` · `uploadFileToLocal` · `persistUrlToUploads` · `saveResultToTasks` **4 个落盘动词**，合计 **98 处站点 / 8 文件** |
| ③ **杂物间** | 一个文件装**多个不相关能力**（导出面横跨多关注点） | `base/core/utils.ts`（deepClone/debounce/fileNameFromUrl/dataUrlToBlob…）· `base/utils/net/clipboard.ts`（**剪贴板 + 下载**两片混住） |

**验收三指标**（改完怎么算成了）：① 导出面符号数 ↓ ② **同一能力的入口数 == 1** ③ 消费者**不必知道内部分支**（不看实现就能选对入口）。

## 5 · 其余 13 域：每个域照做三步

1. **域根清零**（ADR-0044 D1）：域根散件按 D3 职责名表归类（`contract/data/store/lib/hooks/shell/parts/nodes/ui/…`）；**单件域合法**（ADR-0044 §6）。
2. **能力片盘点**（本规划的核心产物）：逐件跑 `node scripts/mv-sync-refs.mjs refs <件>` + 读文件头 ⇒ 填三列「**能力片 → 入口 → 边界外消费者**」；按 §1 三形态标注。
3. **定门面出口面**：域门面**只导出边界外真实需要的符号**（不是全量 re-export）；域内内部件不进域门面（否则门面变宽接口）。

**顺序（先小后大 · 先无门面后有门面）**：`generate` → `text` · `task` · `prompt` · `resource` → `creative` · `settings` · `image` · `video` → `canvas` · `agent` → `scriptbox` →（`videoEditor` · `director3d`：用户裁定**域内自理**）。

## 7 · 可修改性验收（做深构"**别做死**"的四条硬约束）

> 用户 2026-09-20 的原话：**「别搞得让这个东西以后不可修改，那我们就做反了」**。以下四条是"做对了"的判据 —— 任何一步做完都能自证没牺牲可修改性。

| # | 约束 | 怎么验（可执行） |
| --- | --- | --- |
| 1 | **门面按能力片建**（能力边界比域边界稳）：域内重构（搬件/改名/拆子目录）**不改域外任何文件** | 随机搬一个件 → `grep -rn "<旧路径>" src` 应为空（工具自动改写）；域外对域门面的 import 数不变 |
| 2 | **出口面由消费者实测反推**：新增域外需求 ⇒ 门面**加一行 export** 即可，**不需重新论证**；`export *` 只许出现在**能力片门面** | 域门面导出面逐项能指到"哪个消费者用它"；出现"没人用"的导出 ⇒ 摘掉（ADR-0042 D4） |
| 3 | **结构门槛不进闸**：`≥3 件才建子目录` / 门面门槛只写在 ADR；**闸只守依赖方向与门面存在性**，不守具体目录名 | `scripts/check-arch.mjs` 里 grep 不到"具体子目录名清单"（否则调整结构就得改闸 = 做死） |
| 4 | **每步可逆**：门面是**新增文件**（删之即回原状）；搬迁一律 `mv-sync-refs move`（可反向）；验证三件套 = `tsc` + `check:arch` + 受影响测试 | 单域回退 = `git checkout -- src/components/<域>`（本轮 settings 改动即处在此可回退状态） |

**反面实证（本轮踩到并修正）**：第一版把 UI（`SettingsFrame`）与 store 能力片并集进**同一个域门面** ⇒ `base/store/appSettings.ts` 被拉入 UI 链路 ⇒ **成环（会 TDZ）** + 测试 `buildDefaults is not a function`。这正是"做死"的形态：**门面越胖，消费者越被迫依赖它不关心的链路，改一处动全身**。改按能力片分门面后：交扯 10 → 4，环消失。
