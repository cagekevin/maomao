## 〇 · 硬性约束（先看黑名单）

### 0.1 禁止写这些话（出现即视为"没做完"）

| 禁止措辞 | 为什么禁 |
| --- | --- |
| `⚠️ 已知缺口：… 待连同调用方一起改` | 契约**已经改了**、调用方**没改** ⇒ 仓库处于**半坏状态** |
| `保留旧签名为省改动半径` | 省的是**你的**成本，欠的是**下一个人的债** |
| `本轮不动（避免半改）` | 不动可以；**改一半不是"不做"**，是留雷 |
| `TODO / 暂时 / 先这样 / 下轮再说` | 除非**同步**登记进 `scripts/debt.mjs`，否则禁止 |
| `后续优化` | 同上 |

**唯一允许的"不做"**：**完全不动**（连签名都不碰），并把理由写进轮次文件 + 账本。
**绝对禁止**：改一半。

> **本会话实证（血）**：我把 `saveInlineToLocal` 的**内部**改成了判别联合，却"保留公开签名 `string|null`"，
> 还在注释里写「⚠️ 已知缺口…待连同调用方一起改」。结果：**失败原因仍被压平**，
> 而注释让下一个人以为"这里已经处理过了"。**这是用注释代替施工** —— 比不改更坏。

### 0.2 三种掩盖手法（禁止）

**① `as any` / `as unknown as` 让 tsc 闭嘴**
除非 `docs/类型诚实性审计-假收窄清单.md` 有登记，否则禁止。
（本会话我确实写过一处多余的 `null as string | null`，被审出来后删掉 —— 多余断言也是掩盖。）

**② 形式合规、实质兜底**（最隐蔽，重点查）

```ts
const r = tryParse(() => JSON.parse(s));
if (!r.ok) return '';        // ← 判了 ok，实质上还是「失败 → 默认值」，r.error 直接丢
```

判据**不是**"有没有判 `ok`"，而是 **失败分支有没有被有意义地消费**：

- ✅ 允许：默认值**确有语义**（"取不到文件名 → 空串"），**且**该失败不需要让用户知道。
- ❌ 禁止：丢掉的 `error` 里可能藏着**自己的 bug**。
  例：拖拽载荷不是合法 JSON ⇒ **写入侧有 bug** ⇒ 必须 `logger.warn`（本会话已补）。

**③ 拿"改动半径太大"当不做的理由** —— 见 §2。

### 0.3 一条对偶纪律（和"失败必须可见"配对）

> **成功判据必须取自「结果对象」，禁止取自「输入」或"没抛错"。**

- ❌ `if (!res?.skipped) count++`（"没被跳过"≠"写成功"）
- ❌ `toast.success(\`已转换 ${items.length} 个\`)`（`items.length` 是**输入**）
- ❌ `ok: true` 恒真字面量
- ✅ 只取 `r.changes` / `res.success` / `r.linked.length` 这类**结果事实**

## 一 · 「彻底」的判据（Definition of Done）

一次契约变更，**必须同时**满足 7 条：

1. **产生层**：失败携带可展示信息 —— 判别联合 `{ok:true, …} | {ok:false, message}`，**不归一 `null`**。
2. **中转层**：**只转发**（不加工、不自己编原因、不重复留痕、不吞）。
3. **UI 层**：把生产者的判词**原样**呈现给用户（**禁止**自己编"操作失败"）。
4. **调用方全量**：`tsc --noEmit` **0 错**（有错 = 有调用方没改完）。
5. **测试**：断言同步到新契约（新断言要**更强**，例如锁住 `message` 存在）；**不许**加 `any` 买绿。
6. **闸**：`npm run check:arch` 通过。
7. **无半成品**：仓库任一时刻都**可运行** —— 不存在"签名已改、调用方待改"的中间态。

## 二 · 遇到"改动半径很大"怎么办

**不是"不做"**，而是**分阶段，但每阶段的边界必须是"完整的一条链"**：

| ✅ 正确 | ❌ 错误 |
| --- | --- |
| 阶段 1：把链 A 的**全部**调用方改完（可运行）→ 落账 | 阶段 1：改了链 A 签名，调用方用 `as any` 顶着 |
| 一次**只开一条链**，开完就关 | 同时开 5 条链，每条都差一点 |
| 阶段 2：链 B 同上 | 链 A 的 10 个调用方改了 8 个，剩 2 个"下轮" |

**半径 ≥ 10 的标准做法**：改契约 → `tsc` 列**全部**错点 → **一次改完**。
> 本会话实证：`uploadFileToLocal` **11 个调用点**（跨 9 文件）+ `saveInlineToLocal` **7 个**
> + 测试 mock **8 处** —— 一次做完**是可行的**，只是花 token。**"累"不是判据。**

**唯一可退回的情况**：发现"这一层**本来就不该**是这个契约"（判据错）。
退回到"完全不动"，并把**为什么不该改**写进轮次文件。

## 三 · 标准作业流程（SOP · 照做）

### Step 0 · 取证（禁凭记忆）

- `node scripts/debt.mjs show <ID>` 取原始描述 ⇒ **不要相信它**，先取证再动手。
  （本会话证伪了 **11 处**"清单说是债、实测不是"。）
- 用 `search_content` 拿**完整**清单：`headLimit` 要够大，**不采信截断输出**。
- **行号会变**：改过文件后禁止复用旧行号，**重读**。

### Step 1 · 判据三问（决定做不做）

1. 拿得出**硬证据**吗？（用户症状 / 死代码 / 数据损坏）
2. 能不能**不**加东西解决？（结构 / 类型 / 唯一入口 / 对账测试）
3. 加了它，**用户能做哪件做不到的事**？

⇒ 三问过不了 ⇒ **改判非债**，并在轮次文件**留下证伪记录**（防后人重走）。

> ⚠️ 常见误判：**探测原语**（`isChromeExtension()`）返回 `boolean`、**能力降级**返回 `null`
> 且下游有降级路径 ⇒ **不是**"把失败压成默认值"。判据是「**失败是否被伪装成成功**」。

### Step 2 · 契约设计

- 判别联合，**失败分支必须带 `message`**（生产者给的）。`{ok:false}` 不带信息 = 和 `null` 一样扔信息。
- **复用**同文件既有类型（`UploadOutcome` / `PersistOutcome` / `SaveTasksOutcome`），不要新造相似类型。
- 明确区分**「真失败」与「无需操作」**（如 `skipped:true`）—— 两者混成一个值就是旧病复发。

### Step 3 · 改契约 + tsc 驱动

```powershell
npx tsc --noEmit -p tsconfig.json 2>&1 | Select-String -Pattern "error TS" | % { $_.ToString() }
```

- **逐个**改错点，直到 **0 错**；改一批**立刻**再跑（不要攒）。
- ⚠️ **tsc 有盲区，契约变更后必须补 grep**：
  - `tests/**/_nodeMocks.mjs`（`.mjs` 不受 tsc 检查）
  - `vi.mock` 工厂返回 `any` / `unknown`
  - `as never` / `as any` 断言


### Step 4 · 测试红了怎么办（**先假定自己越界**）

**禁止**第一反应"改断言 / 加 any"。逐个**定性**：

| 现象 | 定性 | 处置 |
| --- | --- | --- |
| 断言是 `toBeNull()` / `toBe(url)`（旧契约形态） | 测试断言**旧契约** | 改测试到新契约（新断言要**更强**） |
| 断言 `toHaveLength(1)` 但实际 `[]`；或时序/行为变了 | **我改坏了** | **回退我的改动**，教训写进轮次文件 |
| `Error: No "X" export is defined on the "…" mock` | mock **缺导出** | 用 `importOriginal` 取真实实现（**别手写形状**） |
| mock 返回旧形态（`'http://…'` / `null`） | mock **未同步** | 改成新契约形态 |

> **本会话实证（必读）**：`ImageBoxNode.test`「从上游连线导入」变红。
> 真因：我把 `makeThumb` 的 `loadImageWithTimeout` 换成了 `loadImageOrNull` ——
> 后者是**批量语义**（坏图降级 **＋ 两级重试**：先带 crossOrigin、失败再去掉重试）。
> 用在**单张**缩略图上：多一次加载 + 失败时序改变 ⇒ 测试挂住。
> **教训：「长得像」不等于「语义相同」。** ⇒ 已回退。
