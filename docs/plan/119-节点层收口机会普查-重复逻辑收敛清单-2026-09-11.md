## 一、背景与目标

前期已完成四块收口：

- **落盘策略收口**：`resolveNodeImageUrl` / `showThenPersistInline` 成为文件→落盘→URL 的单一出口；
- **媒体判型唯一真值源**：`src/components/base/utils/mediaType.ts` 取代散落正则；
- **输入框落盘样板收口**：`useNodeField` 统一文本/输入框的防抖落盘；
- **清理死 hook**：移除未使用的 `_` 方法。

本普查回答一个问题：**还有没有值得收口的？** 结论是有，且集中在「节点组件层」——同一段逻辑在多个节点里被手抄复制。

## 三、高优先级（纯 extract，建议先啃）

### H1. `disconnectSource`（断连线）在 5 个节点逐字重复

同一段「删除某来源节点指向当前节点的连线」逻辑：

```ts
setEdges(es => es.filter(e => !(e.source === sourceNodeId && e.target === id)));
```

位置：`ImageGenerate.tsx:188`、`TextGenerate.tsx:65`、`VideoGenerate.tsx:105`、`TemplateNode.tsx:220`、`ScriptBoxNode.tsx:117`，依赖均为 `[id, setEdges]`。

**建议**：抽 `src/hooks/useDisconnectSource.ts`：

```ts
export function useDisconnectSource(id: string) {
  const { setEdges } = useReactFlow();
  return useCallback((sourceNodeId: string) =>
    setEdges(es => es.filter(e => !(e.source === sourceNodeId && e.target === id))),
  [id, setEdges]);
}
```

5 处统一替换为 `const disconnectSource = useDisconnectSource(id)`。

---

### H2. 「下游结果节点 spawn」范式在 ~9 处重复

模式均为：取自身节点位置 → 偏移（右移 60 + 自身宽度）→ `buildSpawnNodes` + `spawnAndCommit` 原子提交。

- `VideoProcessNode.tsx:956-1029`：`spawnVideoNode`/`spawnAudioNode`/`spawnGifNode` 三胞胎几乎完全一样，仅 `mediaType` 与 `style` 尺寸不同；
- `VideoProcessNode.tsx:976/1001/1026`（×3）、`GridSplitNode.tsx:654`、`GridMergeNode.tsx:469`、`Director3DNode.tsx:109/189`、`LoopNode.tsx:252`、`PanoramaNode.tsx:443`、`TextGenerate.tsx:253`；
- `depthVideo/spawn.ts:45` 的 `spawnDepthVideoNode` 头注释明写「照抄 VideoProcessNode.spawnVideoNode 的范式」；
- `AssetNode.tsx:163-212` 与 `ImageGenerate.tsx:419-468` 的 `handleCameraStudioGenerate` 同范式（新建 `imageGenerateNode` + `injectNodePrefs` + `addNodes` + `addEdges`）。

**建议**：在 `src/components/base/canvas/deriveNodes.ts` 新增两个出口，把「偏移计算 + buildSpawnNodes + spawnAndCommit 原子提交」收敛为单一实现：

```ts
spawnDownstreamAssetNode(id, { url, name, mediaType, size, sourceHandle }, ctx)
spawnImageGenerateNode(id, { prompt, ... }, ctx)
```

`VideoProcessNode` 三胞胎、`spawnDepthVideoNode`、`handleCameraStudioGenerate` 全部委托之，消除「复制后改漏一处」的漂移风险。

---

### H3. 放大 / 查看大图的 `<dialog>` 打开模式在 4–5 个节点同构

模式均为：`zoomRef` + `openXxx = (url) => { setXxxUrl(url); requestAnimationFrame(() => zoomRef.current?.showModal()); }` 再渲染 `<ImageZoomDialog ref={zoomRef} .../>`。

位置：`ImageGenerate.tsx:222`、`ImageBoxNode.tsx:85`、`GridMergeNode.tsx:141`、`VideoGenerate.tsx:158`（`openVideoZoom` 同构）、`FaceMosaicNode.tsx:107/381/386`、`AssetNode.tsx:84/397/417`（后两者直接用 `dialogRef.current?.showModal()`）。

**建议**：抽 `useZoomDialog()`：

```ts
export function useZoomDialog() {
  const zoomRef = useRef<HTMLDialogElement>(null);
  const [zoomUrl, setZoomUrl] = useState<string>('');
  const openZoom = useCallback((url: string) => {
    setZoomUrl(url);
    requestAnimationFrame(() => zoomRef.current?.showModal());
  }, []);
  return { zoomRef, openZoom, zoomUrl };
}
```

调用方只 `openZoom(url)` 并渲染一次 `<ImageZoomDialog ref={zoomRef} url={zoomUrl} />`。

## 四、中优先级（消除与共享 helper 的漂移）

### M1. `AssetNode.handleDownload` 内联文件名逻辑，与共享 `resolveDownloadFilename` 重复

`AssetNode.tsx:135-154` 自己写了一套 `extMap`（image→png/video→mp4…）+ `/\.[a-z0-9]{2,5}$/i` 正则 + URL 文件名提取；而 `ImageGenerate.tsx:406`、`VideoGenerate.tsx:258` 已统一调用 `clipboard.ts:323` 的 `resolveDownloadFilename`。

**建议**：`AssetNode.handleDownload` 改为 `downloadUrl(url, resolveDownloadFilename(data.label, url, { ext: <按 type 取默认>, fallback }))`，删内联 `extMap` 与正则。同时让 `VideoExtractNode.tsx:603`（`frame-${idx+1}.jpg`）、`ImageBoxNode.tsx:434/564/829`（裸 `label` 当文件名、无扩展名兜底）也走同一 helper。

### M2. 「文本文件 → 读取为 text」逻辑两处重复

- `AssetNode.tsx:218-243`（`handleFileSelect` 的 text 分支：`FileReader`+`readAsText`+`setNodes` 写 `text/mediaType/imageUrl/url` 全清空）；
- `useAssetDropPaste.ts:140-147`（`createNodeFromFile` 的 text 分支：`FileReader`+`readAsText`+`addNode('textGenerateNode', …)`）。

语义不同（一替换当前节点、一新建议节点），但「读 File 为文本」样板相同。

**建议**：抽纯函数 `readFileAsText(file): Promise<string>`，两处共用（职责差异仍留在各自调用点）。

### M3. `insertAssetRef` / `insertMention` 富文本插入胶水在 4 个节点完全相同

```ts
const insertAssetRef = useRef<((a: AssetMention) => void) | null>(null);
const insertMention = (a: AssetMention) => { if (typeof insertAssetRef.current === 'function') insertAssetRef.current(a); };
```

位置：`ImageGenerate.tsx:145`、`TextGenerate.tsx:145`、`VideoGenerate.tsx:152`、`TemplateNode.tsx:212`。

**建议**：抽 `useInsertMention()` 返回 `{ insertAssetRef, insertMention }`，4 处统一替换（`insertAssetRef` 仍经 `onReady` 上抛）。

### M4. 生成类节点基座 hooks 仍可收口为 `useNodeBase`

现状：每个节点都手动逐个调用 `useReactFlow()`、`useNodeResize(id)`、`useNodeData(id)`、`useNodeExpanded(id, data.expanded)`、`useConnectedInputs(id)`、`useMediaDegrade()`、`useRenderImageResolver()`、`useNodePrefs(...)`。这 5–8 个「基座必需件」在 17 个节点里逐字重复（以 `TemplateNode` 为蓝本手抄），存在「漏接某 hook 导致行为漂移」风险。

**建议（较大但低风险）**：新增 `useNodeBase(id, data)` 一次性返回 `{ patchData, patchDebounced, expanded, toggleExpanded, connected, isHidden, render, … }`，把常用 hook 聚合成一个；差异项（`prefs`/`type`/`useGenerateNode`）仍由节点自行调用。

### M5. 非生成型结果写回缺少统一出口

已收口：`ImageGenerate/VideoGenerate/TemplateNode/TextGenerate` 经 `useGenerateNode` 的 `resultField` 写回。

残留：`VideoProcessNode`、`VideoExtractNode`、`Director3DNode`、`PanoramaNode`、`LoopNode`、`FaceMosaicNode`、`GridSplitNode`、`GridMergeNode` 等「处理/拆分/产出」节点各自手写 `setNodes(ns => ns.map(n => n.id===id ? {...n, data:{...n.data, <字段>: ...}}))`（例 `VideoProcessNode.tsx:948` 写 `errorMessage`）。写回方式不统一，结果字段名也不统一（`imageUrl`/`videoUrl`/`resultUrl`/`gifResult`）。

**建议**：补轻量 helper `patchNodeResult(id, field, value)`（或复用 `useNodeData` 的 `patchData`），至少统一「结果字段名」与「写回方式」，避免重演 `data.url` / `data.imageUrl` 双写漂移（即 `nodeImage.ts` 文档记录过的旧坑）。

## 五、低优先级（整洁度 / 死代码）

### L1. `VideoGenerate.tsx` 的「上传」按钮是死代码（真实功能缺陷）

`VideoGenerate.tsx:256` `const onUpload = () => fileRef.current?.click();`，工具栏 `upload` 按钮 `onClick: onUpload`（`:270-273`），但隐藏的 `<input type="file">`（`:324-329`）**没有 `onChange` 处理器**，也未被其它处读取 `fileRef`。点击「上传图片、视频或音频素材」会弹文件框、选完什么都不发生（与 `AssetNode`/`ImageGenerate` 修过的「选完不读」同类缺陷）。

**建议**：要么补 `onChange`（复用 `resolveNodeImageUrl` 落盘 + `setVideoUrl`/建素材节点），要么删除该按钮与 `fileRef`/`onUpload`。**这不是清理，是 bug，建议优先。**

### L2. 大量 `_` 前缀的未使用解构（死变量）

- `ImageGenerate.tsx:184` `getEdges: _getEdges`；
- `ImageGenerate.tsx:472-473` / `AssetNode.tsx:120-121` `editor: _editor, setEditor: _setEditor`（来自 `useImageHoverActions` 返回值，未用）；
- `useImageHoverActions.tsx:63,66` 入参 `id: _id, label: _label`（声明但未使用，该 hook 只用 `onImageReplaced`）；
- `VideoProcessNode.tsx:284` `onMainBoxResize: _onMainBoxResize`；
- `FaceMosaicNode.tsx:64` `getNodes: _getNodes`。

**建议**：清理多余解构；`useImageHoverActions` 可考虑把 `id/label` 从入参移除（或标注为真正依赖），避免误导后续维护者。

### L3. 文件名默认扩展名散落多处

`VideoProcessNode.tsx:123-128`（`url.startsWith('data:') → 'video.mp4'`）、`VideoExtractNode.tsx:153`（`'base64_video.mp4'`）、`ImageBoxNode.tsx:434`（`'image-${Date.now()}.png'`）、`AssetNode.tsx:152`（`'image-${type||'content'}${ext||'.png'}'`）。

**建议**：在 `mediaType.ts` 增加 `defaultExtFor(kind: MediaKind): string`（与现有 `EXT_KIND` 表同源），统一取代这些散落字面量。

### L4. `toastError('上传失败')` 的 null → 报错守卫重复 3 处

`AssetNode.tsx:248`、`ImageGenerate.tsx:516`、`useAssetDropPaste.ts:155`：都是 `resolveNodeImageUrl(...) === null → toastError('上传失败')`。

**建议（可选）**：让 `resolveNodeImageUrl` 在失败时内部 `toastError` 并返回 `null`（或返回 `{url, ok}` 信封），消除三处重复守卫。`useImageHoverActions.tsx` 内 `toastError(e?.message || '压缩失败')` 同构，可一并考虑。
