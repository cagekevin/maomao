# 20 - AI 图生图参考图「自动连线」优化备忘

> **状态：🟡 待实施（体验优化，非 bug，可延后）**
> **日期**：2026-08-21
> **性质**：画布视觉一致性 / 数据流统一优化。**当前功能完全正常，不改也能用**，仅"画布上少一条直观的线"。
> **关联代码**：`useAgentChat.js`（发送层）、`useCanvasAgentTools.js`（execute_plan 工具层）、`canvasPlanExecutor.js`（执行器建节点）、`PromptNode.jsx`（参考图合并渲染）

---

## 1. 问题现象

AI 助手做图生图时，生图节点上**能显示上游参考图**（缩略图），但画布上**没有从源节点连过来的线**。

用户视角：节点像是"凭空带了一张参考图"，看不到数据来源连线，交互上略别扭。

## 2. 根因（现状数据流）

参考图在链路中只被写成 `data.images`，**从不创建连线**：

```
AI 面板附件(url + nodeId)
   ↓ useAgentChat.send / sendImageMode
   setCurrentReferenceImages(urls)   ← 只保留 url，nodeId 被丢弃
   ↓ execute_plan 工具
createGenNode 把 url 写进节点 data.images
   ↓ PromptNode 渲染
refImages = connected.images(连线) + data.images(塞进去)   ← 只走了 data.images 分支
```

关键结论：
- **智能对话 与 图像模式 在参考图处理上完全一致**——都是塞 `data.images`，都不连线。差异仅在触发方式（LLM 调 execute_plan vs sendImageMode 直接构造 generation）。
- `nodeId` 在 `AgentPanel` 的 `selectedImageNodes` / `confirmPendingImages` 里**本来就有**，但到 `setCurrentReferenceImages(imgAtts.map(a => a.url))` 时被丢掉，导致后续想连线也连不了。

## 3. 影响评估（为什么"不改也行"）

- ✅ 图生图照常生成，参考图正常生效（`data.images` 传给上游）
- ✅ 缩略图可见，可点 × 移除
- ❌ 仅缺一条视觉连线 + 断开方式不是"断连线"

**不是 bug，是体验优化。**

## 4. 修复方向（最小侵入，约 20~40 行，2~3 个文件）

打通 `nodeId → 自动连线`，仅当**参考图来自画布节点**时补线；本地上传图片（无 nodeId）维持 `data.images`：

| # | 文件 | 改动 |
|---|------|------|
| 1 | `useAgentChat.js` | `setCurrentReferenceImages` 改为存 `{url, nodeId}`，不再只丢 url |
| 2 | `useCanvasAgentTools.js` | `executePlanTool` 把参考图的 `nodeId` 映射传给 `executePlan` |
| 3 | `canvasPlanExecutor.js` | `createGenNode` 建节点时，对每个带 nodeId 且画布存在的参考图 `addEdges` 一条 源→生图节点 的连线 |
| 4（可选） | `PromptNode.jsx` | 连线后 `useConnectedInputs` 已能读到上游图，需考虑 `data.images` 是否保留，避免**同一张图重复显示两次**（连线 + data.images） |

## 5. 注意事项（改前必读）

- **两套机制并存**：`useConnectedInputs`（连线读上游 data.imageUrl）与 `data.images`（隐式塞参考图）目前是并存设计（见 `canvasPlanExecutor.js` 头注释：独立批塞 data.images、依赖批才连线）。改动时要保持兼容，不要破坏既有 Wave1/Wave2 分区逻辑。
- **上传图片无法连线**：参考图若来自本地上传（不在画布），连线无意义，只能走 `data.images`。修复要区分 `nodeId` 是否存在。
- **历史反复记录**：`useAgentChat.js` 头注释明确写了多条"参考图优先级搞反/自动挂历史图"的踩坑记录，改参考图链路时**勿推翻已有的 attachment_indices / direct_refs 优先级约定**。
- 新增/改动若涉及存储键、事件、节点契约，先在 `contracts.js` 登记（项目架构红线）。

## 6. 决策状态

- 当前：**暂不实施**。功能可用，仅视觉不爽。
- 后续：用户想动时，按 §4 最小改动方案执行，优先只补连线、不动整体结构。
