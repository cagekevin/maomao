## 0 · 一句话定位

**这一页 = 技能库的"文件管理器 + 正文编辑器"**：**列表里的每一行就是磁盘上的一个包**，
在界面里点保存 = **直接写那个包**（整包原子写），不存在"先存到别处再同步"。

- **用户不该知道"缓存"这个词。** 索引（`agent_skills`）只是渲染与注入用的投影，不是第二份真相。
- 页面里**没有两个列表**：磁盘包是列表，索引只负责给行**补状态**。

## 1 · 真相与投影（谁写什么）

```
人（Finder / VS Code） ──写──▶  磁盘 <分类>/<名>/SKILL.md  ──重读/hydrate──▶ 索引(agent_skills) ──▶ 列表渲染 + 注入正文
                                        ▲                                          │
                                        └──── 界面保存（整包原子写，写盘成功才回写索引）────┘
       启用态 / 注入预算 / 清单开关 ──▶ UI 自己的状态键（agent_skill_enabled / agent_skill_config）
```

| 东西 | 真相源 | 谁写 |
| --- | --- | --- |
| 名称 / 描述 / 正文 / 分组（=目录名） | 磁盘 `SKILL.md` | **人（文件系统）与界面保存** —— 两者等价：界面做的事，人在 Finder 里也能做，结果一样 |
| `id`（UUID，写在 frontmatter） | 磁盘 | **程序**（人写不出 UUID）⇒「补齐 id」是唯一的程序写 frontmatter 动作 |
| 启用态 / 注入预算 / 清单开关 | UI 状态键 | **界面**（它就是唯一真相源，与磁盘无关） |
| 索引 `agent_skills` | ——（投影） | 只由"读完磁盘之后"写：`hydrate` 或**一次成功的界面保存** |

**索引的定位**：渲染加速 + 注入用的正文副本 + `contentHash` 基线。它**永不**作为列表骨架（否则"磁盘上已删的包"会以正常行出现——那正是当下的幽灵条目）。

## 3 · 行的状态全集（**状态在行上，不在另一个列表里**）

| 状态 | 判据 | 行上表现 | 可用动作 | 能用于对话？ |
| --- | --- | --- | --- | --- |
| **正常** | 磁盘有 · 有 id · 索引有 | 名字 + 启用开关 | 编辑 / 打开该包 / 导出 / 删除 / 在 AI 助手里使用 | ✅（且需启用） |
| **缺 id** | 磁盘有 · frontmatter 无 id | `⚠ 缺 id` | **补齐 id**（唯一程序写 frontmatter 的动作） | ❌（未纳入索引） |
| **仅索引** | 磁盘**已无**该包 · 索引里还有（含正文） | `⚠ 仅索引（磁盘上已删除）` | **恢复（写回磁盘）** / **丢弃（移出索引）** | ❌ |
| **无描述** | 磁盘有 · 有 id · `description` 为空 | `⚠ 无描述（不进清单）` | 编辑（补描述）/ 其余同上 | ✅ 正文可用，但**不进「可用清单」**（TD-11-33 的替代形态） |
| **引用缺失** | 正文引用的资料包里没有 | `⚠ 引用缺失 2` | 编辑 / 打开该包（详情里列差集） | ✅（但模型读资料会失败，行上先说了） |
| **分组游离** | 索引的 `category` 指向磁盘上不存在的组 | 归入一块 `⚠ 分组已不存在` | 编辑里改分组 / 重读收敛 | ✅ |
| **页面级 · 未决** | 后端读不到 | 顶部横幅（原文 message + 重试） | 重试 / 按索引显示（明确标注"未决"） | —— |

**唯一写盘动作只有三个**：① 补齐 id（程序写 id）② 恢复（把索引正文写回磁盘）③ 保存编辑器（整包原子写）。
三者**都是显式动作**，都写**磁盘**。**没有"保存的副作用会顺带重建已删的包"这条路**（当下的静默复活来自 `skillPersist.ts:160-165`：能编辑的行必须磁盘上存在 ⇒ 那条路径在界面上不可达）。

## 4 · 保存语义 = 直接编辑磁盘（含**冲突检测**）

1. 保存前：`saveSkillToDisk` 已会**先读整包**（`scope=package`，含 `scripts/**`）——复用它做冲突检测：
   **磁盘当前正文的 `contentFingerprint(body)` ≠ 本行渲染时的 `contentHash`** ⇒ 说明**有人在别处改过这一版**。
2. 冲突时**不静默覆盖**：弹「磁盘上这一版已被外部改动 → ① 用我的覆盖 ② 放弃我的改动、加载磁盘版」。
   （这是"界面直接编辑磁盘"必须付的成本：两个写者都真实存在。）
3. 无冲突：整包原子写 → **成功才回写索引** → 重读该行状态。失败：原样报错、索引一个字都不改。
4. 编辑器**只对"正常 / 无描述"两类行开放**（磁盘必有）。缺 id、仅索引行只给各自的按钮。

## 5 · 工具条（替掉整个「磁盘技能库」面板）

`全部分组⌄ · 导入⌄（.md 文件 / 技能包文件夹）· 新建 · ⟳ 重读 · 📂 打开文件夹 · 注入预算⌄ · 芯片（磁盘 12 包 · 启用 5/12）`

> **不做搜索**（用户裁定 2026-09-22：技能就几个，搜索框是噪声）。分组切换 + 一屏可见足够；
> 将来技能数真上量再说 —— 不预留输入框（ADR-0053）。

- **新建** = 用模板建包：名称（必填）+ 描述/分组（可选）→ 写 `<组>/<名>/SKILL.md`（含新 `id`）→ 直接进编辑器。写的是磁盘，不引第二个真相。
- **重读** = 磁盘 → 索引（`hydrate`），结果**三态如实报**：已更新 N 条 / 与索引一致 / **未决**（磁盘没给出可写的结论）。
- **注入预算⌄**：折叠态只显示摘要（`清单 关 · 单篇 12,000 字 · 合计 24,000 字 · 一次最多 4 个`），展开才可改（含超界警告）。
- **迁移**（旧 localStorage ➜ 磁盘）：仅当检测到待迁移时出现在工具条，完成后消失。

## 10 · 验收项

1. **行数 == 磁盘包数 + 内置数**（不是索引数）——面板级用例。
2. 四类状态行的动作与可编辑性：缺 id 只给「补齐 id」；仅索引只给「恢复/丢弃」；无描述可编辑但进不了清单。
3. 保存：磁盘变 **且** 索引同步；失败时索引一字不改（不谎报）。
4. **冲突不静默覆盖**：外部改过 → 弹选择（覆盖 / 放弃并加载磁盘版）。
5. 「仅索引」条目**不会**出现在 AI 面板下拉里（可用性判据与列表同源）。
6. 重读三态文案（已更新 / 一致 / 未决）。
7. 三态组开关：全开/部分/全关**在控件上**可区分。
8. 预算条三档（正常 / 接近 / 超限）颜色与文案。
