## 〇、TL;DR（执行者先读这段）

- 现状：画布节点里的"持续展示"（生成遮罩动画、处理中转圈、视频播放）**全部零散、各管各的**，没有统一的状态拥有者，也没有任何集中调度。复制的克隆节点与原节点**共享同一个 `node.data` 对象引用**，是"复制后互相干扰"最贴合机制层的根因。
- 收口按**三个阶段**推进，阶段一最小最安全，先做：
  1. **阶段一 · 复制深拷贝**（治最直接根因，改动 1 个函数 + 补 1 个测试）
  2. **阶段二 · 进行中/生成中状态统一**（治"loading 存储分裂"，收敛到统一 hook + node.data 单一真相源）
  3. **阶段三 · 媒体播放互斥调度**（可选、将来按需；收口稳定后才安全，本轮不预埋）
- 执行者若只想先消掉用户报的 bug，**只做阶段一即可验证是否已消除**；阶段二、三是"彻底收口、防再犯"的治理。
- 禁止提前设计全局"停别人"逻辑——现状没有该机制，现象不是它造成的，先修散点耦合，再决定要不要互斥。

## 一、问题本质（证据先行）

### 1.1 用户现象
Ctrl+D 复制一个节点 → 在复制的第二个节点点「生成按钮」→ 第一个节点的"动画"结束。

### 1.2 全库现状盘点（只读调查结论）
见本文档引用的代码位置，均为**当前仓库真实现状**：

| 类别 | 现状 | 关键证据 |
| --- | --- | --- |
| **复制节点** | 克隆节点与原节点**共享同一 `node.data` 对象引用**（浅拷贝，未重开 data） | `src/components/base/canvas/groupNodes.ts` `duplicateSelectedWithEdges` 内 `{ ...n }` 后未 `data: { ...n.data }` |
| **生成中遮罩** | 纯 CSS 动画（`npbShimmer/npbGlow/npbSpin`），何时渲染由外层节点 `loading` 决定；`loading` 大多数节点是组件独立 `useState` | `src/components/base/ui/GeneratingOverlay.tsx`；`src/hooks/useNodeGeneration.ts` `const [loading]=useState(false)` |
| **processing 转圈** | `VideoProcessNode` 的 `loading` **存在 `node.data.loading`**（非组件 useState） | `src/components/nodes/VideoProcessNode.tsx` `const loading = data.loading` |
| **视频播放** | 无 autoplay/loop；播放态散在组件 `useState` + `<video>` DOM（`.play()/.pause()` 只作用自身 videoRef）；无全局"正在播放的是谁" | `VideoThumbnail.tsx` `useState(playing)`；`DiscountVideoNode` `onActivate={() => videoRef.current?.play()}`；`VideoProcessNode` `useState(isPlaying)` + `data.loading` |
| **事件总线** | eventBus 是"瞬时广播、不存状态"，明确**不做统一 context 调度器**；无 `media:*` / `play:single` 类事件 | `src/components/base/core/eventBus.ts` 文件头声明 |
| **生成并发锁** | 只按 **nodeId** 键控（同节点不并发），不同节点可并行；只有数量上限 `GEN_MAX_CONCURRENT` | `taskStore.ts` `claimNodeRun/releaseNodeRun`（`Map<nodeId,true>`） |

### 1.3 根因定性与"缺什么"
**现象不是某个设计好的全局"停别人"逻辑造成的**（全库 grep 无任何会 pause 其它节点 video 的代码）。它来自**状态被意外共享 + 状态拥有者分裂**这两类散点耦合：

1. **复制共享 data 引用**（`groupNodes.ts`）——克隆节点与原节点指向同一 `data`，任何读/缓存引用 data 的位置都可能两节点联动。
2. **同一语义"loading/processing"两种存法**（组件 `useState` vs `node.data.loading`）——复制带 `data.loading` 的节点时，半个进行中标志被复制走。
3. **无集中媒体播放态**——没有"一个时刻谁在播/谁在生成/谁在轮询"的单一事实，想加规则也无处挂。

因此用户的判断"缺一个控制收口"是**准确的**：收口的本质是给这些"零散动画/进行中状态"一个**统一的状态拥有者 + 明确边界**，复制/并行时不再互相污染。

## 二、收口目标与边界（防止扩大化）

### 2.1 目标
> 让画布节点里所有"需要持续渲染或需要互斥的瞬态"（生成中遮罩、处理中进度、视频播放/暂停）都有一个**明确的、可追溯的、可被复制安全隔离的**状态拥有者；消除"复制后互相干扰 / 状态存储分裂"这类散点耦合。

### 2.2 明确不做（边界，防止过度设计）
- ❌ **不建全局"一个时刻只生成一个节点"的调度器**——现状按 nodeId 并发锁已满足，且并发生成是合理需求。
- ❌ **本轮不为"点 A 停 B 的播放"预埋事件或调度**——现状无此需求方，且在前两阶段收口稳定前预埋只会制造新的零散。作为**阶段三**可选设计保留，等有真实需求再上。
- ❌ **不把纯 CSS 的加载动画本身搬进 JS 管理**——`GeneratingOverlay` 动画无需收口，要收口的是**"它何时显示"（loading 布尔）这一状态的归属**，不是动画实现。
- ❌ **不改事件总线语义**（eventBus 明确不做调度器）。将来若需互斥，走新增状态 store 而非往 eventBus 加语义。

## 三、收口架构（三层落点）

按"状态归属 + 复制边界 + 可选互斥"分三层，对应三个阶段。

### 层级总览
```
┌─ 层3（可选，将来）媒体播放互斥调度 ──────────────────┐
│   唯一入口：playMedia(ownerId, url) / pauseAll()     │
│   不预埋；收口稳定后按需加入                          │
└───────────────────────────────────────────────────┘
┌─ 层2 瞬态状态统一拥有者 ─────────────────────────────┐
│   node.data 单一真相源（status / loading / playState）│
│   唯一写入口：统一 hook（收编 useNodeGeneration       │
│   + VideoProcess 的 data.loading + 播放态）            │
└───────────────────────────────────────────────────┘
┌─ 层1 复制安全隔离（本轮最优先）─────────────────────┐
│   duplicateSelectedWithEdges → data 深拷贝           │
│   复制一个"在生成/在播放"的节点 = 产生干净副本        │
└───────────────────────────────────────────────────┘
```

### 层1 · 复制安全隔离（阶段一）
**改动**：`duplicateSelectedWithEdges` 克隆节点时把 `data` 重开成独立对象，使克隆体与原节点不再共享同一 data 引用。

**为什么能消 bug**：复制后两节点各自持有独立 data，任何"读 data 做动画/媒体判断"的位置都不会再因共享引用而联动。

**最小实现示意**（执行时以函数现有结构为准）：
```ts
// groupNodes.ts — 克隆节点时：{ ...n, id:newId, ...(数据字段) , data: { ...n.data } }
//   ↑ 现为 { ...n } 直接复用 n.data；补 `data: { ...n.data }` 即断掉共享引用
```
> ⚠️ 注意：`node.data` 内可能含嵌套可变对象（如 `images[]`/`texts[]`/`outputs` 等数组）。若后续发现这些数组仍被写者共享导致串扰，需把 `data` 内**会被原地修改的集合字段**也一并浅拷贝成新数组（递归深拷贝默认不必需，只处理写者会改的顶层集合）。

**验证**：新增单测断言「克隆节点 data !== 原节点 data 且不等价污染」，跑 `npm run test:unit` + `npm run type-check` + `npm run build` + `npm run test:smoke`。

### 层2 · 进行中/生成中状态统一（阶段二）
**问题**：同一语义两种存法——
- 生成节点（PromptNode/DiscountVideoNode/TextNode…）`loading` = 组件内 `useState`（`useNodeGeneration` 返回）；
- `VideoProcessNode` `loading` = `node.data.loading`。

**收口目标**：全部归一为**一个 hook 统一拥有瞬态**，且以 `node.data` 为唯一真相源（现状大部分 data 字段本就走画布快照落盘，瞬态若入 data 会随快照被持久化与复制——见下"设计决策 A"待确认）。

**收口方案**：
1. 新增/收敛一个统一 hook（建议在 `useNodeGeneration` 之上薄封装或抽公共状态层），统一暴露 `{ loading, error, progress }`，内部以 **nodeId** 为键把瞬态集中进一个轻量 store（内存级，挂 nodeId → 状态映射），**不再由各组件各自 `useState`**。
   - 为什么内存级而非 `node.data`：loading/error/progress 是**纯瞬态**，落盘无意义、被复制会造成新干扰。用内存 map 天然规避"复制复制走 loading"问题。
2. `VideoProcessNode` 的 `data.loading` 迁出为同一瞬态层，`node.data` 只保留**持久**字段。
3. 各生成节点渲染遮罩时，改从统一瞬态层读取本节点 loading（对外接口 `loading` 不变，节点代码几乎不动）。

> **设计决策 A（需用户在动手前拍板）**：瞬态存**内存 map（推荐）** 还是 **node.data**？
> - 内存 map：不入快照、复制天然隔离，推荐；需处理"节点删除/卸载时清 map 条目"。
> - node.data：随快照落盘可"刷新后仍显示进行中"，但会被复制污染、写盘频繁；不推荐。
> 文档默认推荐**内存 map**，如与你现状预期冲突请在执行前确认。

**验证**：复制一个"正在生成"的节点，克隆体不得出现生成中遮罩；`npm run test:unit` + `test:regression` + `test:smoke` + `npm run build`。

---

### 层3 · 媒体播放互斥调度（阶段三 · 可选 · 不预埋）
**保留设计（先记录，不实现）**：
- 若将来需求明确为"同一时刻只播一个视频 / 点某节点动作时停掉其他节点播放"，则引入一个**内存级播放调度器**（唯一入口 `playMedia(ownerId, url)` / `pauseAll(exceptId?)`），所有走 `<video>` 的节点（VideoThumbnail / DiscountVideoNode / VideoProcessNode 等）统一经它启停。
- 前提：层1、层2 已落地，状态归属清晰，才可安全叠加互斥。
- **不要现在做**：现在做会引入新零散，且需求未确认。
