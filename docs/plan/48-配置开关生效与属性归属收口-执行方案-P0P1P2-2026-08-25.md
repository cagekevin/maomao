## 2. P0 · 修复 `continuousMotion` 病灶（止血，独立可上线）

### 2.1 定契约（改什么、不改什么）

- **改**：`continuousMotion` 从 `ENTITY_CHANNELS.person.action`（[project.js:164](file:///Users/kevin/Documents/maomao/src/components/director3d/project.js#L164)）移除，不再进 action 通道、不再被录制。
- **改**：`synthesizeObjectState` 在 action 通道合成（[854-871](file:///Users/kevin/Documents/maomao/src/components/director3d/project.js#L848-L879)）之后，对 `type==='person'` 用基线 `object.continuousMotion` 覆盖求值结果：
  ```js
  // action 处理后、skeleton 处理前（person 专属，P1 会收进通用 L2 覆盖）
  if (object.type === 'person') {
    result.continuousMotion = Boolean(object.continuousMotion)
  }
  ```
- **不改**：`normalizePerson`(461-471) 对基线的防御归一化保留；`app.jsx` 相机 `setCameraAtFrame`(678-685) 的 targetMode/targetId 特判**不动**；`models.jsx:215` 渲染端 `continuousMotion && preset.loopable` 抑制**不动**（它是循环与否的最终兜底）。
- **明确的行为变化（预期，非回归）**：持续循环不再随关键帧变化，"同段循环、跨段静止"式差异策略取消，整段恒一。旧工程不计入。

### 2.2 构思测试（先写好再写码）

- 场景覆盖：
  1. **先打帧后勾选**：先录动作关键帧（此时 continuousMotion=false），再勾选基线=true → 播放应循环。← 原 bug
  2. **先勾选后打帧**：基线=true 再录关键帧 → 播放应循环。
  3. **无关键帧直接勾选** → 播放应循环。
  4. **非循环 pose + 基线=true** → 求值结果 `continuousMotion=true`，但渲染端被 `preset.loopable` 抑制 → 静止（断言求值端行为与模型渲染行为解耦）。
  5. `objectKeyframeFromObject` 产物中**不再含** `continuousMotion` 字段。
- 落在纯逻辑单测（复用 `tests/unit/` 的 project 纯函数域），能脱离 UI 跑。

### 2.3 定数据流与施工

1. 从 `ENTITY_CHANNELS.person.action` 的数组移除 `'continuousMotion'`。
2. `synthesizeObjectState` 加 person 专属覆盖（§2.1）。
3. 确认 `objectKeyframeFromObject`（[903](file:///Users/kevin/Documents/maomao/src/components/director3d/project.js#L893-L907)）不再产出 `continuousMotion`（移出通道后由 `snapshotToChannelKeys` 天然不落）。

## 3. P1 · 三层注册表机制化（核心收口）

> P1 把 P0 的"person 专属覆盖"泛化成"所有实体的 L2 通用覆盖"，并把通道登记收敛为派生。**前提关卡**：派生出的 `ENTITY_CHANNELS` 必须与现有结构逐字段相同——否则说明把 43 的契约改坏了。

### 3.1 定契约

- 新增**单一声明源** `PROPERTY_REGISTRY`（`project.js`），覆盖 `person`/`object`/`camera` 三实体，每字段标 `layer:`（`animatable`/`objectState`/`config`）+ L1 额外标 `channel:`。字段清单与归属严格按 `docs/47 §3`（含决断：`locked→config`、`continuousMotion→objectState`、`targetMode/targetId→objectState`）。
- 用普通 `for` **派生** `ENTITY_CHANNELS`（保留旧名、旧形状 `{channel:[...]}`、锁注册顺序），**弃用 `Object.groupBy`**（ES2024 运行时，esbuild 不 polyfill）；对"`animatable` 漏标 channel"显式 `throw`。
- 模块初始化预编译 `OBJECT_STATE_FIELDS`（每实体 L2 字段名数组）。
- `synthesizeObjectState` 末尾：`for (const f of OBJECT_STATE_FIELDS[object.type]||[]) result[f] = object[f]`——这一步**取代 P0 的 person 专属覆盖**，并可为其它 L2（`footLock`）提供同类规范性覆盖。
- **相机例外**：`cameraAtFrame`（[881](file:///Users/kevin/Documents/maomao/src/components/director3d/project.js#L881)）无基线参数，`targetMode/targetId` 仍由 `App.jsx:setCameraAtFrame`(678-685) 特判保留，**不删、不走 L2**（理由见 47 §4.5）。
- **归一化不被动摇**：注册表只管"进通道 + 求值覆盖"，`normalizePerson`/`normalizeObjectField`/`normalizeCameraField` 的防御归一化（`Boolean()`/clamp）**保持现状**，不允许"按 layer 跳过归一化"。

### 3.2 构思测试

- **前置关卡**：写一段纯逻辑断言，比对"注册表派生的 `ENTITY_CHANNELS`"与"当前手写 `ENTITY_CHANNELS`"**逐元素相等**；提交前必须绿（=43 契约未被破坏）。
- 场景覆盖：
  1. P0 的全部场景（P1 后行为不回归）。
  2. `footLock`（L2）求值 = 基线值（含基线缺省时回落默认）。
  3. `locked`/`color`/`name`（L3）不进通道、不被求值器覆盖。
  4. `targetMode` 仍由 `setCameraAtFrame` 保留（相机回归）。
  5. 派生校验：构造一个"animatable 漏标 channel"的注册表 → 断言 `throw`。
- **对 43 已交付测试的影响**：凡断言 `action` 通道含 `continuousMotion` 的旧测例需同步更新（P2 一并收口，但 P1 提交时不能有红测）。

### 3.3 定数据流与施工

1. 新增 `PROPERTY_REGISTRY` + 派生 + 预编译（`project.js` 顶部，紧邻现 `ENTITY_CHANNELS`）。
2. 先跑 §3.2 断言 0（派生===现有），确认契约无损。
3. 把 `continuousMotion` 从 `person.action` 注册移到 `objectState`。
4. `synthesizeObjectState` 用 L2 通用覆盖替换 P0 的 person 专属覆盖。
5. 删除/标记手写 `ENTITY_CHANNELS` 为兼容快照（出让给派生）。
6. 全量单测回归 + `check:jsx` + `build`。

**P1 验收**：`PROPERTY_REGISTRY` 是唯一登记入口；`git grep` 确认无人直接手写新通道字面量；派生断言绿；P0 场景全绿。

## 7. 顺序与风险管理

- **P0 风险（低）**：改动集中在 `project.js` 两处，纯逻辑、有单测锚；唯一的语义变化（整段恒一）已在上游判为预期结果。
- **P1 风险（中）**：派生破坏 43 契约、相机 targetMode 退化、归一化被连带砍——分别用 R3/R4/R5 和 §3.2 前置断言兜底。其中"派生===现有"是提交红线。
- **P2 风险（低）**：全为断言/文档/可选 UI，不碰核心链路。

**只有 P1 完成，才算"收口"真正落地**：P0 只是止血，若不进 P1，下次加一个对象级开关仍会手写漏掉获得不入注册表。故 P1 是本方案的主交付，P0 是安全前置。
