# AI 助手执行模型精简 —— 施工交接规格（奥卡姆·核心收敛）

> **用途**：交给另一个 AI 照此执行，无需用户再解释背景。
> **权威依据**：改动 AI 助手执行模型前，先读本文件 + `docs/分镜协作-AI助手内嵌工作区-可执行方案-2026-09-05.md`（表格方案）。
> **前置已做**（本会话已完成，勿重复/勿回滚）：已删 promptFlow 逐条确认通道、demoPlan 假引擎、`imageModeLooksLikePerReferenceEdit`/`buildPerReferenceGenerations`（多图分别改）、`promptLearning`「学」、6 个 AI 画布工具。
> **本次目标**：AI 助手收敛为"**完全自主（auto）+ credit 积分闸**"一种模式，去掉"AI 自己规划多个 generation / Skill 三阶段批量 / 策划确认弹卡"这套高层批量编排；批量由将来表格承接。

---

## 〇、一句话目标

AI 助手只保留 `auto`（完全自主）一种运行模式：用户（可带 Skill 让 AI 理解需求）跟 AI 聊，AI 完全自主建节点/生成/操作画布，中间不弹"分步策划确认"、不自己规划 N 个 generation 批量执行；真烧积分时由 credit 闸拦一下。批量生成交给将来表格（表格承载 N 行内容 → 用户确认 → 逐行/整表触发生成，走"单内容→建节点→生成"底层）。

---

## 一、红线：以下【绝对不删】（删了 AI 就废 / 用户明确要）

| 机制 | 原因 |
|---|---|
| `inputStateMachine`（按钮态推导 idle/planning/running/steer/...） | AI 基础运行时骨架，非批量专属 |
| `workflowState` + `steerQueue`/`wfNextSteer`（运行中可插话补充） | 同上，是"对话式 AI 能接收补充指令"的基本能力 |
| `execute_plan` / `canvasPlanExecutor` **底层单 gen 执行** | auto 完全自主时 AI 建节点/单张生成/操作画布仍依赖它。**保留接受单 generation**；只去掉"引导 AI 造 N 个 generation 数组"的高层 |
| **credit 积分闸**（creditSwitch + creditGate + 对应确认） | 用户明确保留（真烧积分前确认的安全闸） |
| **多会话**（新建/切换对话列表） | 用户明确要 |
| **Skill 本体**（skillStore、AgentPanel 应用 Skill、把 Skill 内容注入 LLM） | Skill = "发给 AI 让 AI 理解需求"的输入，用户明确要。只改它"三阶段批量引导"那层 |
| **参考图**（选中画布图→附件→发 AI） | 用户明确要 |
| **确认卡 UI / AgentConfirmCard / presentPlan / show_plan_for_confirm** | **先保留 UI 框架**（将来给表格"确认后生成"复用）；只改注释注明改造方向 |

> ⚠️ 施工中若发现某个"以为要删"的符号被红线机制或 UI 真实消费，**退回核对，不得硬删**。宁可多留，不可把 AI 基本功能砍废。

## 分块 1：runMode 收敛成只留 `auto`

**意图**：删掉 `direct`（直接生图：输入最终提示词→send 第一行 bypass LLM 直连 execute_plan）和 `step-confirm`（分步确认：AI 出策划卡你确认），让 AI 永远走 `auto` 完全自主。

**涉及文件与动作**：

### 1a. `src/components/agent/runtime/runModeRegistry.ts`
- `RUN_MODE_IDS`：只留 `AUTO: 'auto'`；删 `DIRECT`、`STEP_CONFIRM`。
- `WorkMode` 类型 = `'auto'`（收窄）。删 `step-confirm`/`direct` 相关分支。
- `WORK_MODE_DEFS`：只留 `auto` 一项；删 `direct`（systemPrompt:null）、`step-confirm` 项。
- 删 `STEP_CONFIRM` 相关导出；`getSystemPromptForWorkMode` 等归一函数只处理 auto。
- 删 `resolveInputMode`（image/agent 概念随 direct 消失）或其收窄为恒 'agent'；删 `isAgentWorkMode`（或恒 true）。
- `LEGACY_WORK_MODE_MAP` / `deriveFromLegacy`：历史迁移（旧 image→direct、semi→step-confirm）——**全部归一到 auto**，保留"读到旧值也回写 auto"的幂等即可。

### 1b. `src/components/agent/runtime/useAgentChat.ts`
- **删 `direct` 分流**：`send` 里 `if (!isAgentWorkMode(getWorkMode())) return runDirectBranch(...)` 这行（约 L471）删掉——不再 bypass LLM。
- **删 `runDirectBranch` 整个 useCallback**（约 L682-~800，"直接生图分支"，含 sendImageMode/direct 直生逻辑）。删前用 grep 确认它只被 send 的 direct 分流调用。
- `agent/index.ts` barrel 与 `UseAgentChatReturn` 接口里若有 direct 相关导出，同步删。
- 顶部一大段"图像模式直连生图 / 三态 workMode"的**注释**（约 L169/179-213）改写成"AI 助手恒走 auto 完全自主"的简短说明，删掉已不存在的 direct/step-confirm/三态描述。

### 1c. `src/components/panels/AgentPanel.tsx`
- **删三态选择器 UI**（约 L859-880 的 workMode 切换区）：删 `workMode` state、`applyWorkMode`、`WORK_MODE_STORAGE_KEY` 订阅，三态按钮组。
- 删 `getWorkMode/setWorkMode/RUN_MODE_IDS/DEFAULT_WORK_MODE/isAgentWorkMode` 相关解构与引用。
- 若 `AgentPanel` 因删三态失去某 prop/handler 依赖，一并清理。**保留** credit 开关 UI、发送/停止、Skill、参考图、对话列表。

### 1d. 连带收敛
- `conversation` 里 runMode 兼容字段（`conversationAiState` 的 `get/setCurrentRunMode`、`normalizeConversation` 的 runMode 归一、runModeRegistry 的 `registerRunModeSync`/`registerLegacyRunModeReader`）：**保留字段但永远 auto** 或删掉（若确认无 UI/credit 消费）。credit 卡消费 runMode 的地方（若只判 step-confirm）改恒 auto 行为。
- 跑测试时重点：`tests/unit/runModeRegistry.test.ts`、`creditGateModes.test.ts`、`useAgentChat.hook.test.ts`、`AgentPanel.test.tsx` —— 这些断言 direct/step-confirm/三态会红，需同步改/删对应用例为"恒 auto"。

**验证**：AI 助手仍能"跟 AI 聊 → 建节点 → 生成一张图"（auto 路径），credit 闸仍拦烧钱。build/tsc/smoke/单测全绿。

## 分块 2：Skill 三阶段批量 → 改单阶段

**意图**：Skill 不再引导 AI"阶段1 规划一整批 generation + 阶段2 等确认 + 阶段3 批量 execute_plan"。Skill 只作为"让 AI 理解需求的输入文本"，AI 在 auto 下按对话方式产出/执行。批量交给表格。

**涉及文件与动作**：

- `src/components/agent/agentConfig.ts`：`SKILL_EXECUTION_RULES`（"【Skill 驱动的批量生图（三阶段...）】"一段长 system 提示）→ **删除/改写**。Skill 注入 LLM 的规则改成一句："Skill 是你理解用户需求的参考，按它理解并执行用户请求；需要生成时按对话方式产出，不要规划一整个 generations 批量。"（具体措辞由施工者组织，但语义如此。）
- 检查 `resolveSkillExecutionRules`（`agentCore.ts`，按 runMode 动态追加确认粒度）→ runMode 已恒 auto，这段"按三态追加确认粒度"的规则可简化为固定 auto 语义或删确认粒度分支。
- 确认无 Skill 三阶段的"阶段2 等待确认卡"残留对 `awaiting_confirm` 的强依赖（若有，让 Skill 不再设 awaiting_confirm；credit 闸的 awaiting 是另一回事，保留）。
- 相关测试（`runModeRegistry`/`creditGateModes`/`useAgentChat.hook` 里断言 Skill 三阶段）同步改。

## 分块 3：删 AI 多 generation 批量规划引导

**意图**：去掉"引导/驱动 AI 输出一整批 generations 数组去批量执行"的高层，保留 execute_plan 接受单 generation 落地（auto 建单节点/单生成仍用）。

**涉及文件与动作**：

- `agentConfig.CANVAS_RULES` / `SKILL_EXECUTION_RULES` 里引导 AI"生成一整个 generations 数组 / 分多步"的措辞删掉，改成"一次对话聚焦用户当前要的那一张/那件事，需要多张就让用户用表格组织"（语义如此）。
- `agentCore.buildRequestMessages` / `parseGenerationsFromReply`：确认 `parseGenerationsFromReply`（从回复解析 plan+generations）仍用于 auto 单 gen 落地则保留；若它专为"解析一批 generations"且删掉后无使用者，可删（**施工者用 grep 确认无其他消费者再删**）。
- **不动**：`execute_plan` 工具本身、`canvasPlanExecutor` 对单 generation 的执行、taskStore 触发。
- 相关测试（`canvasAgentTools.test`/`useAgentChat.hook` 里 execute_plan 多 gen 断言）同步核对——单 gen 用例保留，多 gen 批量用例删/改。

## 四、回退触发点（施工中发现再评估）

- 删 direct 后，用户"快速直接生图（不给 AI 规划）"入口消失且 auto 体验明显变差 → 保留 direct 作为快捷入口（不删 direct，只删 step-confirm）。
- 发现某个要删符号被红线机制/credit/UI 真实消费 → 退回分块边界核对，不硬删。
- Skill 若用户确需"AI 按 Skill 一次产出多行内容" → 该能力由表格的"需求+Skill 生成整表"承接（见分镜表格可执行方案 §1.6），不在 AI 助手跑批量 generation。
