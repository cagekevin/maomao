# 网页拖图到画布：问题、方案演进与风险分析

> 日期：2026-08-23
> 状态：决策记录（待用户定最终方案）
> 相关代码：`src/components/base/useAssetDropPaste.js`

## 一、问题背景

用户从**网页**（Chrome 中打开的任意网站）拖一张图片到画布上时，出现两种现象：

1. **画布的加号（drop 光标）出现，但图片没放进来** —— 拖拽被识别，但节点没建。
2. **图片放进来了，但瞬间变破图** —— 节点建了，但图片加载失败。

### 现状梳理（改动前）

`useAssetDropPaste.onDrop` 处理拖入 URL 时，只读了 `text/plain`：

```js
const files = e.dataTransfer?.files
if (!files || files.length === 0) {
  const text = e.dataTransfer?.getData('text/plain')  // 只读 text/plain
  if (text) { ... 建节点 }
  return
}
```

**根因**：从网页拖图时，图片 URL 通常不在 `text/plain`，而在 **`text/uri-list`**（拖拽 URL 的标准 MIME）。代码没读 `text/uri-list` → URL 读不到 → 没建节点。而 `onDragOver` 已设置 `dropEffect='copy'`，所以加号出现但 drop 后无动作。

### 第一次修复（已做）

`onDrop` 同时读 `text/uri-list` 和 `text/plain`，取第一个非空 URL 候选，图片 URL → 建 imageNode。这一步解决了"加号出现但没放进来"。

## 二、方案演进（破图问题）

图片能拖进来了，但**破图**仍存在。破图原因：网页图常因**防盗链（Referer 检查）**或**跨域（CORS）**导致 `<img>` 加载失败。

### 方案 A：先下载落盘（本地化）→ 再显示

拖入网页图 URL 时，先 `httpRequest` 下载 → `uploadFileToLocal` 落盘成 `/files/` 持久 URL → 节点用本地 URL。

- 优点：本地 URL 稳定不破图、刷新不丢、发送/压缩可用。
- 缺点：网页图跨域/防盗链导致**前端 `httpRequest` 下载常失败**（受 CORS 限制），下载失败就兜底用原 URL → 仍破图。且引入延迟和副作用。

### 方案 B：立即显示原 URL + 后台本地化

同步用原 URL 建节点（无延迟），后台异步下载成功后再替换成本地 URL。

- 优点：无显示延迟。
- 缺点：**后台下载仍受 CORS 限制，跨域网页图依然下载不了**，替换不成功 → 仍破图。复杂度更高。

### 方案 C（当前采纳）：直接用原 URL 显示

`addImageNodeFromUrl` 直接用原网络 URL 同步建 imageNode，不做下载/本地化。

- 优点：简单、无延迟、不引入依赖和副作用。
- 缺点：**能显示就显示，防盗链的破图不阻塞导入**；部分功能因跨域受限（见下）。

> 关键结论：前端单靠 `<img>` 显示 + `httpRequest` 下载，**都无法完全绕过防盗链/跨域**。
> - `<img>` 显示：受防盗链（Referer）限制。
> - `httpRequest` 下载：受 CORS 限制。

## 三、方案 C（当前实现）的风险分析

直接显示原 URL 的节点，**只能"看"，很多操作会因跨域失效**：

| 风险 | 影响 | 严重度 |
|------|------|--------|
| **破图** | 防盗链/失效的网页图加载失败，节点显示破图图标 | 中（用户已知） |
| **发送到素材库 / 图生图失败** | `localizeAndStoreToLibrary(url)` 或发送时 `httpRequest` 下载跨域图 → 失败 → 丢图/发送失败 | **高** |
| **右键压缩/裁剪失效** | `useImageHoverActions` 用 `<canvas>` 读图，跨域图污染 canvas → `SecurityError` | **高** |
| **刷新后失效** | `blob:` 或一次性签名 URL，刷新后节点破图 | 中 |
| **无本地副本** | 节点只存 URL 不存内容，离线/原图被删后节点空 | 中 |
| **历史/快照依赖网络** | 画布快照存网络 URL，失效后恢复即破图 | 低 |

## 四、决策选项

### 选项 1：维持方案 C（直接 URL 显示）—— 当前状态

- 适用：只想把网页图拖进来看/当轻量素材，接受破图和部分功能受限。
- 无需改动。

### 选项 2：扩展端下载（最可靠，改动大）

你的画布是 **Chrome 扩展**（`manifest.json` 有 `<all_urls>` 权限）。扩展端 `fetch` 可以：
- **设 `Referer` 头** → 绕过防盗链。
- **不受页面 CORS 限制** → 能下载跨域图。

流程：扩展端下载 → 落盘成 `/files/` 本地 URL → 节点用本地 URL。这样：
- 显示稳定不破图。
- 发送/压缩/裁剪都能用。
- 刷新不丢。

改动面：`useAssetDropPaste`（拖拽流程）+ 扩展 background/权限 + 本地化工具。**风险中等，但能真正解决问题**。

### 选项 3：中间方案（先显示 + 尽力后台下载）

立即用原 URL 显示，后台尽力尝试下载（`httpRequest`），成功则替换成本地 URL，失败则保持原 URL。

- 优点：有本地副本时功能完整，无副本时也不阻塞显示。
- 缺点：**跨域图后台下载仍大概率失败**（受 CORS 限制），对最需要解决的防盗链/跨域图无效。复杂度高于方案 C。

## 五、建议

- 若**网页拖图是高频核心功能** → 选**选项 2（扩展端下载）**，真正解决破图和功能受限，一劳永逸。
- 若**只是偶尔拖图、能看就行** → 维持**选项 1（方案 C）**，接受限制，不做扩展下载。
