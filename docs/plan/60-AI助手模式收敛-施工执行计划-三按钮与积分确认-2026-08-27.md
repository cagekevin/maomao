## 1. 目标 / 非目标

### 目标
- 把「智能/图像 × 全自动/半自动」+ 隐藏「有 Skill 强制半自动」收敛为三态入口：`直接生图` / `分步确认` / `完全自主`。
- 加**通用高消耗积分闸** `creditSwitch`（全局、默认开）：任何模式下，真正烧积分那下（image/video 生成）都先确认。
- 保持 `send` / `sendImageMode` / `execute_plan` 主链路结构尽量不动，收敛判定到 `execute_plan` 一处。

### 非目标
- 不做按操作类型（effect）的策略引擎。
- 不做生成节点的 ghost 生命周期回收。
- 不改「改画布/改布局」这类零成本操作的确认策略（由三按钮决定，不归积分闸）。

## 3. 已拍板设计决策（执行者不得更改）

| # | 决策 | 说明 |
|---|---|---|
| D1 | 两条门禁是两个独立状态 | `awaitingConfirm`（分步确认，show_plan 设）；**积分闸**（完全自主/直接生图 + 开关开，executePlanTool 设）。**不是同一个 needConfirm**。 |
| D1b | **积分闸是「节点已 ready + 待点生成」态** | credit 命中 → `executePlan(autoRun=false)` **已建好全部节点（status='ready'）**，缺的只是「点生成/点发送」那一下。补跑 = 画布上对已建 ready 节点触发生成，**与手动点节点生成按钮同心智**，不需要 agent 工具循环的通道。 |
| D2 | 分步确认不叠积分闸 | `runMode==='semi'` 时**不**置积分闸（plan 确认已覆盖媒体），避免让用户确认两次。 |
| D3 | credit 判定 = `runMode!=='semi' && creditSwitch` | execute_plan 路径下“含媒体”基本恒真（P9），判定简化为上述式，**不做逐步媒体探测**。 |
| D4 | credit 命中 → 强制 `autoRun=false` | 只建节点（免费）+ 置积分闸；**绝不放行 LLM 的 `auto_run:true`** 直接跑。 |
| D5 | 补跑 = `runExisting` 模式（路线①，已定） | 复用 `executePlan`，跳过 appendNode，按已连依赖边触发已建 ready 节点。**不重呼 execute_plan**（防重复建节点）。 |
| D5b | **runExisting 只分 Wave 批、不抄复杂前序分析** | 依赖传递已靠「画布连线 + useConnectedInputs 读上游」完成（建节点时 Wave2 已连线）。runExisting 只需 `等 Wave1 全完成 → 触发 Wave2`，参考图由连线自动给下游。**不重抄 `prevOk/resolved/realIdToIdx` 那套**。 |
| D6 | 映射只取自同一次 execute_plan | `steps↔nodeId` 映射用执行器返回的 `entries`，随 per-conv 持久化，补跑据此对号，不重定位。 |
| D7 | 删除 `hasSkillNow` 强制项 | show_plan 判定改为 `needConfirm = runMode==='semi'`；但「完全自主 + 有媒体 + 开关开」仍被积分闸拦。 |
| D8 | 补跑唯一入口 | `runExistingPlanTool`（useCanvasAgentTools.js 新增），供 AgentPanel 确认按钮与 sendImageMode/executePlanDirect 确认回调共用。禁止任何路径手写 setNodes/逐节点触发。 |
| D9 | 直接生图在开关开时也拦 | sendImageMode / executePlanDirect 都汇入 executePlanTool 判定，命中即返回「待点生成」，不再 `auto_run:true` 直出。 |

## 4. 数据流总图

```
发起（三路）：
  A) agent 工具循环 execute_plan    B) sendImageMode(:664)    C) executePlanDirect(:792)
  └─▶ executePlanTool(execute_plan.execute, useCanvasAgentTools.js:886)
       │  判定 credit = `runMode!=='semi' && creditSwitch`
       │  · 命中 → 强制 autoRun=false，executePlan 建好全部节点（每 entry status='ready'）
       │          返回 { ok:true, data:{ awaited:'credit', steps:entries } }
       │          节点已在画布上，只差「点生成/点发送」那下
       │  · 未命中 → 走原 autoRun（烧积分），行为不变
       写 per-conv：creditGate={ pending:true, gens, map:(stepId→nodeId) }
       └─▶ send 工具循环（:555）加停点 getCreditGate()?.pending → break（防 LLM 再触发/重复建节点）
           · sendImageMode/executePlanDirect 兼容「已建节点、待点生成」返回，不声称“已生成”

用户点「确认生成」→ runExistingPlanTool()
       └─▶ 校验 creditGate?.pending===true 且 map 存在（否则拒绝，幂等防线）
           executePlan({ generations: creditGate.gens, autoRun:true, mode:'runExisting', nodeMappings: creditGate.map })
            · 跳过 appendNode；节点已在画布；只分 Wave 批（等 Wave1 全完成→触发 Wave2）runNode → 真正烧积分
           ├─▶ 成功 → 清 creditGate（pending=false/null）
           └─▶ workflow running→completed/failed（对齐现链路）
```

### 5.2 `conversationSkillState.js` + `conversationState.js` —— per-conv 运行态（第 2 阶段）

**改什么**
- `conversationState.js` 归一化补默认：`creditGate`（null）。
- `conversationSkillState.js` 照 `awaitingConfirm`/`pendingGenerations` 同模式新增：

**边界**：字段 per-conversation；**`creditGate` 是单对象** `{ pending:false, gens:object[], map:object(stepId→nodeId) }`（既承载待确认态、也带映射，一条数据、一个读写清入口）。刷新/切会话后仍可恢复（与 awaitingConfirm 同机制）。

**失败处理**：读写异常按既有 conversation 落盘机制处理（不新增静默路径）。

**验证**：单测断言 set→get 往返一致；归一化后从未设置过的会话读到默认 null。

### 5.3 `canvasPlanExecutor.js` —— `runExisting` 模式（第 3 阶段，先独立落地不接 credit）

**改什么**：把 `executePlan` 的「建节点」与「触发」解耦，新增 `mode:'normal' | 'runExisting'`：
- `normal`：保持现有行为完全不变（建节点 + 按 autoRun 触发）。**diff 必须只是新增分支，不改存量逻辑**。
- `runExisting`：
  - **跳过 appendNode**（不重复建节点；节点已在画布 ready）；用入参 `nodeMappings`（stepId→nodeId）定位每步节点。
  - **只分 Wave 批**：等 Wave1（独立批）全部触发完成 → 触发 Wave2（依赖批）（D5b）。依赖参考图**由画布既有连线 + useConnectedInputs 自动给下游**，**不重抄 `prevOk/resolved/realIdToIdx` 前序分析**。
  - 每步触发走既有 `runNode`（内部 `runNodeGeneration`，带超时 + 写回 data.imageUrl）。
  - 返回 `{ workflow, entries }` 结构同 `normal`（entries 带 status/resultUrl/nodeId/error）。

**边界**：runExisting 入参 `nodeMappings` 缺失或与 `generations` 对不上 → 明确报错拒绝（幂等防线，不猜测）。

**失败处理**：复用全局单飞锁 + `EXECUTING_PLAN_TIMEOUT` 兜底；逐步失败透传 `entries[].error`，不吞。

**验证**：先做纯 `runExisting` 分支，用手动已建的一批节点走一次补跑，确认不重复建节点、能按 Wave 批触发、能返回逐步结果。**这一步必须本地手动验证 OK 才进第 4 阶段。**

### 5.4 `useCanvasAgentTools.js` —— `executePlanTool` credit 判定（第 4 阶段，收敛唯一入口）

**改什么**
- `show_plan_for_confirm`（:807）：`needConfirm = runMode==='semi'`（删 `hasSkillNow`；D7）。
- `execute_plan.execute()`：
  - 在 `autoRun` 计算后（:913）追加：`credit = (runMode!=='semi' && creditSwitch)`。
  - 若 credit 命中 → `autoRun = false`；执行 `executePlan({..., autoRun})`（**节点建好、status='ready'**）后，从返回 `entries` 提取 `steps↔nodeId` 映射 → `setCreditGate({ pending:true, gens, map })`；返回 `{ ok:true, data:{ awaited:'credit', steps: entries, note:'节点已建好，生成待积分确认，确认后自动生成' } }`（**不声称“已生成”**）。
  - 未命中 → 原逻辑不动。

**边界**：三路（agent 循环 / sendImageMode / executePlanDirect）都经此工具，故判定只写这一处。

**失败处理**：executePlan 返回无 `entries` → 置 workflow failed、原样透传错误，**不置 creditGate**（避免 fake 待确认态）。

**验证**：断『credit 命中 → 强制 autoRun=false、节点建好 ready、creditGate.pending=true 且映射持久化、返回 awaited:'credit'』；『未命中 → 行为与改动前一致』。

### 5.5 `useCanvasAgentTools.js` —— 新增 `runExistingPlanTool`（第 5 阶段，补跑唯一入口）

**改什么**：新增工具/导出 `runExistingPlanTool`：
- 前置校验：`getCreditGate()?.pending===true` 且 `map` 存在，否则返回 `{ok:false, error:'无待点生成的计划'}`（幂等防线，连点只生效一次）。

**失败处理**：复用执行器单飞锁与超时；entries 逐步失败透传；补跑失败不静默清状态。

**验证**：单元 + 手动：确认按钮补跑不再建节点、只烧积分（对已建 ready 节点触发）、成功后 creditGate 清空；连点不重复计费。

## 6. 关键防线（红线，任何一条破防都算翻车）

1. **不重定位节点**：runExisting 必须用持久化映射，绝不按 generations 重新猜 nodeId / 重建节点。
2. **不重复计费**：单飞锁前置校验；creditGate.pending 必须 true 且 map 存在才允许补跑；缺失拒绝。
3. **不分步漏确认**：分步确认（semi）不置积分闸（D2），避免用户确认两次；但完全自主/直接生图在开关开时必须被拦。
4. **放行语义**：credit 命中时**绝不**执行 `auto_run:true` 真生成（D4）；节点建好、只等确认（点生成那下）。
5. **不新造状态源**：creditGate 一律走 conversationSkillState per-conv；不引模块级变量、不拆两个字段。
6. **异步不挂**：所有触发路径带超时（runNodeGeneration / 单飞锁 EXECUTING_PLAN_TIMEOUT）；不引入新的无限等待。
7. **失败可见**：逐步 status 与错误原样透传；creditGate 置位/清除成对，成功清、失败保留。
8. **不改存量 diff**：canvasPlanExecutor 的 normal 分支零改动，只新增 runExisting 分支；execute_plan 未命中分支零改动。
9. **补跑=点生成**：runExisting 只触发已在画布的 ready 节点，不做任何画布/计划重建（与手动点节点生成同心智）。
