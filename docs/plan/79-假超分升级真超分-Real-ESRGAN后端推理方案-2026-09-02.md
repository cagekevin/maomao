# 79-假超分升级真超分 + 新增抠图 - Real-ESRGAN/RMBG 后端推理方案

> 日期：2026-09-02
> 目标：
> 1. 把 maomao 当前的「canvas 插值放大」（不补细节，假超分）升级为「Real-ESRGAN 真 AI 超分」；
> 2. **新增一个「AI 抠图」按钮**（主体识别/去背景），走真模型推理。
> 本文档只描述方案、改动点与流程，**不修改任何源代码**。

---

## 0. 背景与结论

- 现状超分是 `src/components/base/imageUpscale.ts` 的 `upscaleImageDataUrl`：canvas `drawImage` + bicubic 插值放大 2×，再叠 USM 锐化。它**只是平滑变大，不补细节**，所以叫「假超分」。
- 现状**没有抠图能力**（节点 hover 栏只有 crop/edit/compress/upscale，无 matting）。**本次要新增一个「AI 抠图」按钮。**
- 两个能力都需要本地模型推理：
  - 超分：`realesrgan-x4.onnx`（约 **67MB**）
  - 抠图：`rmbg-1.4.onnx`（约 **176MB**，比超分还大两倍多）
- maomao 已有本地后端 `localTool`（Node/TS，监听 `127.0.0.1:18080`）。**两个能力都走后端推理**：前端传图 → localTool 加载模型推理 → 返回结果图。前端零模型、零下载。
- 关于「换电脑 / GitHub 同步」：模型文件（67MB + 176MB）超过 GitHub 单文件 50MB 限制，**不要 commit 进仓库**。仓库只同步「下载地址 + 下载脚本」，模型本地放置并 `.gitignore` 忽略。

> 参照：AI-Canvas-tauri 的抠图也是本地模型（`useImageNodeOnnxActions.ts` 中 `subjectMatting(filePath, out, 'rmbg-1.4.onnx', taskId)`，未装模型时弹 `mattingDownloadPrompt` 让用户前端下载 176MB）。我们要做的是后端化版本——用户不下载模型。

## 1. 现状链路（梳理，不改）

前端入口与实现（仅梳理）：

- 超分：
  - 入口：`src/components/base/useImageHoverActions.tsx` 的 `handleUpscale`
  - 实现：`src/components/base/imageUpscale.ts`（`upscaleImageDataUrl` / `unsharpMask`）

- hover 操作栏按钮注册处：`src/components/base/useImageHoverActions.tsx` 的 `imageButtons` 数组（约第 121 行起）。`ImageNode.tsx`、`PromptNode.tsx` 都通过 `...imageButtons` 展开——新按钮加进 `imageButtons` 即可，两个节点自动都有。
- 前端调本地后端统一走 `src/components/base/proxyGenerate.ts` 的 `httpRequest` + `API_BASE`（`http://127.0.0.1:18080`）。
- localTool 既有图像路由范式参考：`src/routes/localPatch.ts`（裁剪/融合），落盘工具 `src/utils/fileStore.ts`（`writeUploadBufferAt`、`writeGenBufferAt`），路由注册 `src/router.ts`。

## 2. 模型获取（下载 + 放置）

两个模型文件：

| 能力 | 文件名 | 大小 | HuggingFace 地址 |
|---|---|---|---|
| 超分 | `realesrgan-x4.onnx` | ~67MB | `https://huggingface.co/AXERA-TECH/Real-ESRGAN/resolve/main/onnx/realesrgan-x4.onnx` |
| 抠图 | `rmbg-1.4.onnx` | ~176MB | `https://huggingface.co/briaai/RMBG-1.4/resolve/main/onnx/model.onnx` |

国内镜像（访问慢/被墙时，把 `huggingface.co` 换成 `hf-mirror.com`）：

```
https://hf-mirror.com/AXERA-TECH/Real-ESRGAN/resolve/main/onnx/realesrgan-x4.onnx
https://hf-mirror.com/briaai/RMBG-1.4/resolve/main/onnx/model.onnx
```

下载方式（任选）：

- 浏览器直接打开上面链接自动下载；
- PowerShell：`curl -L -o <文件名> "<上面地址>"`；
- 写一个 `localTool/scripts/download-models.mjs`，一次拉两个模型，换电脑跑一次即可。

放置与忽略：

- 放到 `localTool/data/models/`（`realesrgan-x4.onnx`、`rmbg-1.4.onnx`）；
- 在 `localTool/.gitignore` 增加 `data/models/`，**不要**把模型提交进 Git。

> 换电脑：新机器 `git pull` 拿到代码和下载脚本 → 跑 `node scripts/download-models.mjs` 拉一次（共约 243MB）即可。与 AI-Canvas-tauri 用户换电脑重新下载的代价**打平**（他也是超分 67MB + 抠图 176MB 各自重下），不更差。

## 3. 后端改造（localTool，需新增依赖）

新增依赖（写入 `localTool/package.json`）：

- `onnxruntime-node`：在 Node 端加载 ONNX 模型做推理（需 `npm install` 并按平台装原生二进制）。

### 3.1 超分路由 `localTool/src/routes/superRes.ts`（范式对齐 `localPatch.ts`）

- `POST /api/super-res`
- 入参：`{ image: dataURL 或 base64, scale?: 2|4 }`
- 流程：
  1. 首次调用时懒加载 `realesrgan-x4.onnx`（全局缓存 `InferenceSession`，避免重复加载）；
  2. base64 → 解码为 RGBA 张量（用 `jimp` 或 `sharp` 解码，注意通道顺序与归一化）；
  3. `session.run(...)` 推理，得到放大后张量；
  4. 张量 → PNG buffer；
  5. 用 `fileStore.writeGenBufferAt` 落盘，返回文件 ID / URL。
- 错误处理：模型不存在时返回明确错误（提示先跑下载脚本），不要静默降级成插值。

### 3.2 抠图路由 `localTool/src/routes/matting.ts`（新增，本次重点）

- `POST /api/matting`
- 入参：`{ image: dataURL 或 base64, returnMode?: 'rgba' | 'mask' }`
  - `rgba`：返回去背景后的透明 PNG（默认）；
  - `mask`：返回蒙版（供后续二次编辑）。
- 流程：
  1. 首次调用时懒加载 `rmbg-1.4.onnx`（全局缓存 `InferenceSession`）；
  2. 解码为张量 → `session.run(...)` 得到 alpha 蒙版；
  3. 用蒙版合成透明 PNG（或返回蒙版）；
  4. `fileStore.writeGenBufferAt` 落盘，返回文件 ID / URL。
- 错误处理：模型不存在时返回明确错误。

### 3.3 路由注册

在 `localTool/src/router.ts` 的 `routes` 数组中注册 `super-res` 与 `matting`（对齐现有范式）。

## 4. 前端改造

### 4.1 超分（升级现有）

`src/components/base/imageUpscale.ts`：

- 新增 `upscaleViaBackend(dataUrl, scale)`：用 `httpRequest`（来自 `proxyGenerate.ts`，走 `API_BASE`）`POST /api/super-res`，拿到返回图后回写画布。
- 保留 `upscaleImageDataUrl` 作为**极端兜底**（后端不可用时降级）。

`useImageHoverActions.tsx` 的 `handleUpscale`：改为调 `upscaleViaBackend`，失败降级并 toast「已用本地轻量放大」。按钮「AI 2x」文案保持。

### 4.2 抠图（新增按钮，本次重点）

`src/components/base/useImageHoverActions.tsx`：

- 新增 `handleMatting`：用 `httpRequest` `POST /api/matting`，拿到透明 PNG 后替换当前节点图片（回写 `onImageReplaced`）。
- 在 `imageButtons` 数组中**新增一个按钮**（图标 + 文案「AI 抠图」），`onClick` 指向 `handleMatting`。因 `ImageNode`/`PromptNode` 都 `...imageButtons` 展开，**两个节点自动出现该按钮**。
- 推理中按钮置灰 / 显示 loading；失败 toast 提示（区分「后端未起」与「模型未下载」）。

> 参照 AI-Canvas-tauri：`useImageNodeOnnxActions.ts` 的 `subjectMatting` 是抠图推理核心，`MattingToolbar.tsx` 提供蒙版画笔/橡皮擦二次编辑。若后续要支持「抠图后手动修边」，可再加 `MattingToolbar`（二期，不在本期）。

## 7. 与 AI-Canvas-tauri 的对比小结

| 维度 | AI-Canvas-tauri | maomao（本方案） |
|---|---|---|
| 超分模型 | 用户本机（前端下载 67MB + 弹窗） | 本机 localTool 后端推理，前端零下载 |
| 抠图模型 | 用户本机（前端下载 176MB + 弹窗） | 本机 localTool 后端推理，前端零下载 |
| 前端是否下载模型 | 是（共 243MB） | 否，前端只传图收图 |
| 换电脑 | 重新下载 243MB | 重新跑下载脚本拉 243MB（打平） |
| 超分/抠图质量 | Real-ESRGAN / RMBG 真模型 | 同模型，质量一致 |

结论：在「本机 localTool」前提下，我们**不比他差**；真超分/真抠图质量一致，且前端当次使用更轻（无下载弹窗、无 243MB 下载）。换电脑代价打平。抠图为本次新增能力，原 maomao 无此功能。
