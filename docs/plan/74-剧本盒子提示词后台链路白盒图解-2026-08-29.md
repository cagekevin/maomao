# 剧本盒子·提示词后台链路白盒图解（2026-08-29）

> 只讲后台：每次点「生成」，**是哪一次模型调用、system 是谁、user 怎么拼、返回解析后落到哪个字段、下一步拿它当什么**。
> 代码依据：`src/components/base/scriptBoxEngine.js`（引擎）、`scriptBoxPrompts.js`（拼装）、
> `scriptbox/scriptBoxWorkflows.js`（默认提示词唯一来源）、`scriptBoxPromptResolver.js`（读取层）、
> `nodes/PromptNode.jsx`、`nodes/DiscountVideoNode.jsx`（下游真实生成）。

---

## 一、后台一共只有 6 次模型调用

| # | 调用 | 引擎函数 | system 来源 | user 来源 | 产出落到哪 |
|---|---|---|---|---|---|
| ① | 生成剧本 | `onGenerateScript` :196 | playbook.`script` + 固定 JSON 格式 | 你的剧情原文 | `shots[]`、`assets[]` |
| ② | 资产生图 | `onGenerateAssetImage` :331 | 无（生图不传 system） | `assets[i].prompt` 原文 | `assets[i].imageUrl` |
| ③ | 分镜提示词 | `onGenerateShotPrompts` :449 | playbook.`shot` + playbook.`qg` | `assembleShotUser()` 拼的本镜资料 | `shots[i].prompt` / `videoPrompt` |
| ④ | 关键帧类提示词 | `onGenerateShotImage` :608 | playbook.`imageGenTemplates[type].sys` | `buildShotImageUser()`（吃 `description`） | `shots[i].imgGen.prompt` |
| ⑤ | 审计改写 | `onReviewShotPrompt` :658 | playbook.`audit` | `buildAuditUser()`（吃**当前那条**提示词） | 只回传文本，确认后写回 `shots[i].prompt` 或 `videoPrompt` |
| ⑥ | 合并视频提示词 | `onGenerateMergedVideo` :954 | `MERGE_VIDEO_SYSTEM`（内置常量） | `buildMergedVideoUser()`（吃各镜 `description`） | 新视频节点 `data.prompt` |

**第 7 步没有提示词工程**：画布上的生图/生视频节点把 `data.prompt` **原样**发给图像/视频模型，不加任何 system
（`PromptNode.jsx:214-225`、`DiscountVideoNode.jsx:183-189`）。资产图作为 `images`（参考图）随请求一起发，不进提示词文本。

## 二、数据怎么从一步流到下一步

```
 ┌──────────────────────── node.data（唯一状态池）─────────────────────────┐
 │ story / globalStyle / playbookId                                        │
 │ shots[]  ├ description  ←──┐ 文本流：给模型看的「发生了什么」+ @资产名   │
 │         ├ prompt        ←──┼ 提示词流：生图最终发出的那条                │
 │         ├ videoPrompt   ←──┼ 提示词流：生视频最终发出的那条              │
 │         └ imgGen.prompt ←──┘ 旁路：关键帧/四宫格，需手动「应用到生图」    │
 │ assets[] ├ name / description / prompt                                  │
 │          └ imageUrl     ←── 图像流：作参考图垫给下游模型                 │
 └────────────────────────────────────────────────────────────────────────┘

 ① 剧本调用 ──┬─→ shots[].description ──────→ ③ 的 user 文本（@名字 + 剧情）
              ├─→ shots[].duration ─────────→ ③（时长格式）、⑥（合并时长累加）
              └─→ assets[].prompt ────→ ② 直接发出生图 ─→ assets[].imageUrl ──→ ⑦ 参考图

 ③ 分镜提示词调用 ──→ shots[].prompt ─────→ ⑦ 生图节点 data.prompt（原样发出）
                  └─→ shots[].videoPrompt → ⑦ 生视频节点 data.prompt（原样发出）

 ③ 的输入里没有图：refAssets 只取 name/category（:491-492），图只在第 ⑦ 步按名字匹配后垫进去。
```

**一句话**：名字走文本流，图走图像流，提示词走提示词流；三条线只在最后一步（⑦）汇合。

## 三、每一步的装配公式（可直接对照改文案）

### ① 生成剧本 —— `onGenerateScript`

```
system = resolveSystem(playbookId,'script')        // workflows.manga.script，齿轮可编辑
       + SCRIPT_WRITER_FORMAT                       // 固定 JSON 输出契约，:26，永远追加、不可改
       + 【镜头数量要求】约 N 镜 / 自动             // :222-224
       + 【统一视觉风格】globalStyle                 // :226-228，填了才加，并要求模型原样回吐 globalStyle
user   = data.story + "\n\n" + data.upstreamStory    // :203
images = data.upstreamImages（上游图片，给模型看图理解产品外观）// :240

返回 JSON → parseJsonText → shots[] (:254-275)、assets[] (:291-309)
assets[i].prompt = ZgPrompt(category, description, globalStyle, 资产模板)   // :301
                 = "[视觉风格：X]" + description + "。" + playbook.assetTemplates[category]   // prompts.js:73-79
```

### ② 资产生图 —— `onGenerateAssetImage`

```
prompt = assets[i].prompt（非空直接用；为空才用 name+description 现拼 ZgPrompt）  // :342-344
→ generateImage({ prompt, model, size, aspectRatio, n:1 })     // :361
→ 成功写回 assets[i].imageUrl / thumbnailUrl                   // :383-389
```

### ③ 分镜提示词 —— `onGenerateShotPrompts`（每镜一次，并发 4、间隔 500ms）

```
system = resolveSystem(playbookId,'shot') + "\n\n" + resolveSystem(playbookId,'qg')   // :466-468
user   = assembleShotUser(shot, refAssets, globalStyle, opts)      // :501，定义 :1230-1339
       + 【生图强制约束】playbook.constraints.image                 // :510
       + 【生视频强制约束】playbook.constraints.video                // :511
       + 【videoPrompt 格式】必须以「【时长 N秒】」单独一行开头        // :512
       + 【用户本次修改意见】feedback                                // :513

assembleShotUser 内部依次输出（:1241-1336）：
  镜头编号 / 时长 / 景别 / 光影 / 运镜 / 统一风格
  位置：第 N 镜 / 共 M 镜（开场镜 / 中段镜 / 结尾镜）
  画面描述：shots[i].description
  【剧情上下文】视觉起点（尾帧）/ 上一镜承接 / 本镜剧情职责 / 下一镜钩子
  【出场分工】@角色（核心 / 压迫位 / 背景位）、@场景、@道具       ← 来自 refAssets，只有名字
  【风格锚定】焦段 / 光影落位 / 材质微动作
  【眼线锁定】≥2 角色时
  【对白/旁白】+【环境音三层】
  【负面黑名单】通用 + playbook.negative.image / video
  尾部格式约束：prompt 只写画面，videoPrompt 补运动与声音

返回 JSON {prompt, videoPrompt} → 写回 shots[i].prompt / videoPrompt   // :563
```

### ④ 关键帧 / 四宫格 / 九宫格 / 俯视调度图 —— `onGenerateShotImage`

```
system = playbook.imageGenTemplates[type].sys     // :615，type = keyframe/grid4/grid9/topdown
user   = 【图类型】【全局风格】【镜头画面描述】【景别】【光影】【运镜】【时长】【对白】【音效】【可用@资产】
       注意：吃的是 shots[i].description，不是 shots[i].prompt        // prompts.js:500-517
产出   = shots[i].imgGen = { type, label, prompt, ts }               // :640
消费   = 不自动进下游！只能「复制」或点「应用到生图」→ 覆盖 shots[i].prompt（StepPrompt.jsx:135）
```

### ⑤ 审计改写 —— `onReviewShotPrompt`（你双击哪一格，就审计哪一条）

```
入参 field = 'prompt' | 'videoPrompt'（双击生图那格 → prompt；双击生视频那格 → videoPrompt）
system = resolveSystem(playbookId,'audit')        // workflows.manga.audit（三框架：导演/表演/美术）
user   = buildAuditUser(shot, field, feedback, assetNames)   // prompts.js:56-70，顺序固定：
        【用户修改意见（必须严格遵循）】
        【本镜画面描述】        shots[i].description
        【对白/旁白】
        【可用 @资产】
        【时长】（仅 videoPrompt）
        【当前生图/生视频提示词（待改写）】  ← 就是 shots[i][field] 的当前值

产出   = 单条中文文本（不是 JSON），先回传给弹窗预览，点「应用」才写回 shots[i][field]
纪律   = 只改意见触及的部分，另一条（prompt / videoPrompt）完全不动
```

**所以「审计的是哪一条提示词」的答案：你双击的那一格里当前显示的文本，即 `shots[i].prompt` 或 `shots[i].videoPrompt`；
它不是拿剧本模板去重写，而是把「当前这条 + 你的意见 + 本镜资料」交给审计模板做最小必要改写。**

### ⑥ 合并视频 —— `onGenerateMergedVideo`

```
system = MERGE_VIDEO_SYSTEM（内置常量，prompts.js:528，不随 playbook 变）
user   = buildMergedVideoUser(picked, assets)：逐镜列出【画面描述/景别/光影/运镜/对白/音效】
        ← 吃的是各镜的 description 等结构字段，**不是** videoPrompt（prompts.js:542-562）
images / seconds = mergeShotsForVideo()：参考图合并去重 + duration 累加（prompts.js:378-399）
产出   = 新建 discountVideoNode，data.prompt = 合并后的单条视频提示词，selectedSeconds = 总秒数
```

### ⑦ 下游节点真实生成（出图 / 出片）

```
promptNode.data.prompt      ← shots[i].prompt（原文，一个字不加）
promptNode.data.images      ← collectAssets(shot, assets)：按 @名字 匹配到的、已生图的资产
→ generateImage({ prompt: chipResolved.text, images: refUrls })     // PromptNode.jsx:214-225
   （@小红帽 是纯文本，不是芯片语法 @{id:label}，所以原样保留；图走 images 参数）

discountVideoNode 同理：prompt = shots[i].videoPrompt，images = 同上的资产图   // :183-189
```

## 五、容易踩空的四个点

1. **第 ③ 步的输入里有名字没图**：图是在第 ⑦ 步才垫的。资产没生图 → 提示词照出，但下游没参考图。
2. **④ 关键帧提示词是旁路**：存在 `imgGen.prompt`，不自动覆盖 `prompt`，也不自动进下游。
3. **⑤ 审计只动一条**：改 prompt 不动 videoPrompt，反之亦然；且改完要点「应用」才落库。
4. **⑥ 合并视频吃的是结构字段**（description/景别/光影/运镜/对白/音效），不是各镜的 videoPrompt；
   各镜 videoPrompt 只在 `mergeShotsForVideo` 里被拼装，而合并流程只取它的 `images` 和 `seconds`（:965）。
