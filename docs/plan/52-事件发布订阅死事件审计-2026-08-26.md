- **`persist:failed`**

  - 顺带建议：确认 `App.jsx:442-446` 的节流 toast 是否真的消费了 `persist:failed`（防止"订阅了但没处理逻辑"的新形式死事件）。

全量 `publish`/`subscribe` 调用均能在 EVENTS 表找到对应 key，**无表外游离事件**。说明事件命名约定执行得不错。

## 五、治本已落地（防 AI / 人工误判的根因封堵）

审计暴露的核心治理缺口——"EVENTS 表靠人工维护、会行号漂移 / 登记滞后"——**已通过 `scripts/check-events.mjs` 的双向自洽校验治本**：

1. **脚本能力**：`node scripts/check-events.mjs`
   - ① 正向：代码中 `publish('x'` / `subscribe('x'` 的裸字面量必须在 EVENTS 登记（防漏登记 / 拼错）。
   - ② 反向：EVENTS 表的 `to` / `from` 必须与代码实测的 `subscribe` / `publish` 位置自洽。
     - 表 `to: []` 但代码实测有 `subscribe` → 报「to 滞后于代码」（**即本次 `persist:failed` 误判根因：表标无订阅方、实际已被订阅**）。
     - 表 `to/from` 列了 `file:NN` 但代码该行/文件名不匹配 → 报「指向 stale / 行号漂移」。
   - 扫描范围：`src/components` 子树 + `src` 根目录关键文件（如 `App.jsx`，否则其订阅会被漏扫导致误报）。
   - 零新依赖（复用已装的 esbuild）。

2. **CI 门禁接入**：`package.json` 的 `prebuild` 与 `pretest` 已追加 `&& npm run check:events`，与 `check:api` 对称，构建/测试前自动拦截。

3. **登记表已修正（与脚本实测对齐）**：
   - `persist:failed` 的 `to: []` → `to: ['App.jsx:446']`（消除"假死事件"误导源）。
   - `agent:task-completed` / `presets-changed` 的行号漂移全部对齐到实测（taskStore 191→209、pollTask 80→88、useNodeGeneration 163→211、promptManager 88→83、PromptLibrary 40→48）。
   - EVENTS 表头部新增**铁律注释**：禁止仅凭 `to: []` / "待核对"判定死事件，必须以代码实测为准。

4. **验证结果**：`node scripts/check-events.mjs` 当前输出「事件契约校验通过 ✔（已扫描 209 个文件，登记表与代码双向自洽）」。

> **下一个 AI 的防误判保障**：即便它仍去读 `contracts.js`，① 表头铁律注释明确禁止照 `to:[]` 下结论；② 即便表再有滞后，`check:events` 在 CI 会红，不会让"表里写的"被当成事实真相。误判根因已双层封堵。
