# 架构收口 Master Plan（2026-08-19）

> 基于四路并行架构扫描（状态管理/错误处理/技术债/契约分散）汇总。目标：**一次性制定总图，避免"今天改完明天又冒新债"**。
> 所有结论为只读分析。落地原则：测试先行 + 最小差异 + 单 commit 单关注点。

## 〇、核心判断（为什么之前是零散改）

之前几次改动（真相源契约、自查表）只解决了"生成结果写哪"这一个切面。但四路扫描 + 后续顶级架构师复核暴露：**真正会让你反复返工的根因不在某条规则，而在五处基础设施缺失（其中①②为原四路扫描结论，③④⑤为 2026-08-19 基础设施复核新增）**——

1. **契约登记表是"文档"不是"可编译红线"（已修正认知，2026-08-19 二次核查）**：原以为仅"运行时 warn、无编译期拦截"。实测**三件套编译期拦截已全部落地**——① 存储键：`scripts/check-storage-keys.mjs`（挂 `npm run check:keys`/`check:health`）+ `contentStore.checkRegistered` dev 环境未登记字面量 key 直接 throw；② 事件：`scripts/check-events.mjs`（挂 `npm run check:events`）静态拦截 `EVENTS` 裸事件名（publish/subscribe 必须用 contracts.js 登记名）；③ 节点类型：`scripts/check-node-types.mjs`（挂 `npm run check:node-types`）拦截 `useNodePrefs` 裸命名空间。三者均零新依赖、不恢复全量 eslint，P0-1 契约强制化**已全量收口**，无待补项。
2. **节点没有统一写入口（含 `resultKey` 自动回写）**：`patchData`/`setNodes`/`onRecover` 样板在 12 文件 30+ 处散落；`useNodeGeneration` 实测**仍无 `resultKey`**，4 节点各自手写 `patchData({imageUrl})`/`patchData({resultUrl})`。新节点每加一个就复制一遍 → 漏写即刷新丢结果。
3. **全局异步异常兜底为零**：`window error`/`unhandledrejection` 全 src 零命中，异步异常无上报，用户侧报错只能手动加日志复现。
4. **`useSyncNodeData` 是新增样板未并入收口**：要求每节点手写 `useSyncNodeData(data,{field:setState})` 映射，若收口 `useGenerateNode` 不把它一并收进，会新增一套平行样板。
5. **依赖版本错配（已随 08-19 pull 收敛）**：原 `@types/react@18` 配 `react@19`、`zustand` 双实例已随最新依赖升级解决；残留为"依赖同代纪律未固化"，须写进红线防漂移回归。

**只要把这几处基础设施补上，后续所有收口都变成"机械替换"，无需再动节点逻辑。** 所以 master plan 以"先修基础设施、再机械替换"为主线。
