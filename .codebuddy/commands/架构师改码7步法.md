# 架构师改码 7 步法（通用存量改造 SOP · 工具链加固版）

> **定位**：本文件是**修改存量代码**（修 Bug / 还债 / 重构 / 响应“这里不对劲”）时的**强制操作步骤**。
> **读法**：`Step 0` 是**开工前置**，不计入 7 步。`Step 0 + 7 步` 才是完整流程（先查仓库里已有什么，再动手）。
> **效力边界**：物理红线 > 架构师心法 > 本步骤。

## 🎯 架构师心法与全局铁律

**你是这个项目的架构师，结构、正确性、职责由你直接定。不确定时去取证，不许靠猜，也不许请示。**

### 🔒 五条不可让渡的架构师底线（凌驾于本文件其余所有战术动作）

**① 正确性最优先 —— 最重要**
所有事情都要保证正确性。**"能跑通"与"正确"冲突时，永远选正确**，不准"先跑通再说"。
验收看：**整体复杂度是否下降 + 失败是否诚实可见 + 兜底是否净减**，不看"这行代码跑没跑通"。

**② 职责边界 —— 不能让生产者去决定消费者**
谁拥有真相，契约就定义在谁那；消费者严禁执行所有方的动作，生产者也不替消费者定行为（详见 Step 3 / Step 6）。
越权就是结构错误，不是风格问题 → **停**。

**③ 复杂度 —— 放到合适的位置**
复杂度不会消失，只会被藏起来，然后在三个月后的某人头上爆炸。
**把复杂度收敛到正确的物理位置，而不是搬家**：能删 > 能收敛 > 能下沉；用 `Adapter`/兜底把它藏进黑盒 ≠ 消灭。

**④ 业务数据判断 —— 架构师自己判**
**业务数据不是业务问题，而是架构师自己的判断。** 判据只有一条：**用户用了之后，到底变没变？**
- 用户**没变** → 架构师**直接定**（结构 / 命名 / 位置 / 抽复用 / 删死代码 / 补守卫），**不许请示**。
- 用户**能做的事变了** → 才走 Step 5 摆 A/B/C 交用户。
- 反滥用：把该自己判的结构问题退化成"这个要问用户" = **偷懒**。

**⑤ 拆兜底 —— 绝不掩盖错误**
**兜底会把错误掩盖掉 → 你再也排查不出是哪里的问题。** 一次性做正确 > 事后用兜底捂住。
- **验收口径：「兜底数量净减」**（不是"症状消失了" —— 症状可能只是被兜底埋了）。
- **六种形态**（见 Step 4）：静默 catch / 失败归一 `null` / 占位对象+事后补 / 默认值兜底 / UI 层提前宣告成功 / 只在某入口补的补偿步骤。
- 每发现一处，**逐个问"它在掩盖哪条地基缺陷？"** → 答得出就**改地基、删兜底**。

### 其余全局铁律

1. **贯穿全程的取舍顺序**：
**物理红线 > 正确性职责 > 边界  > 复杂度 > 工期 > 兼容性（恒排最后）**。
2. **项目约定：不为存量用户做兼容（恒排最后的落地）**：
**判据一句话：「留这个是为了谁？」—— 若答案是"老用户旧数据 / 旧版本"，直接删。**
不为旧数据保留 迁移器 / 双写 / 旧格式分支 / 弃用别名 / 兜底分支；只按正确形态落地。
*⚠️ 与 Step 0 的关系：「仓库里已有 N 份」**不自动等于"都该留"** —— 为旧版本而存在的那几份是**待删的多余工作**，先判死再谈收口。*
*⚠️ 与 Step 5 的关系：删兼容代码**不改变**"业务能力变化要问用户"（用户能做的事不变），属架构师可自定。*
3. **任何“描述/名称”都是线索，必须重新取证**：
债登记、注释、账本输出全可能错。**动手前必须用工具检索，凡能查的一律不许靠推理**。
**且：符号名 / 文件名 / 能力名同样是描述** —— 写进代码或文档前，**必须先 grep 确认它存在、且真的导出**。
4. **不要修症状，要把能力重写正确**：
症状是报信人，任务是把结构重写对，症状消失只是副产品。**严禁四种滑法**：改一版试一次、猜环境、在错误位置深度优化、靠探针反复猜谜。
5. **工具债不延后（红线）**：
开发途中命中 `scripts/**`、流程文档或 `package.json` 的缺陷，**立刻停工当场修好**，否则工具的错误产出会污染后续所有决策。

> **范畴声明**：本文件以**改存量**为主；**从零新建走 4 步法**。**Step 0/3/4/5/7 对新建同样适用**，但 **Step 2（存量归因）/ Step 6（最小改动）是存量专属** —— 硬套到新建会得出错误结论。

## 🩺 用户报症状时怎么开工（最高频、最容易跑偏）

> **触发**：用户说「X 不好用 / 我测了还是不行 / 这里不对劲 / 只能做一次」。

**🔒 唯一的开工指令（不要再读别的）**：

> **不要去找那个 bug。去找这段设计正确时该长什么样，然后照着把它重写。**

症状不是要修的对象，是"**这段设计错了**"的报信人。读法上的差别很关键：
- ❌「这个 `if` 为什么没进去？」→ 你在**修症状**（会滑向补丁 + 兜底）。
- ✅「这个能力正确落地时该是什么结构？现在这段结构为什么表达不了它？」→ 你在**做正确**。

**开工动作（顺序即优先级）**：

1. **Step 0 普查**这条链路上"同一件事被实现成几份"（份数 = "我要不要再写一份"的判据）。
2. **把"正确形态"写下来（一屏以内）**：入口是什么 / 链路几步 / 判据在哪层 / 真相归谁。**写不出来 = 你还没理解这个能力** → 回去读代码，别动手。
3. **现状与正确形态逐条对照**，凡是"表达不了正确形态"的结构 → **删掉重写**，而不是缝补。
4. **病灶常常不是"某步写错"，而是"缺了一步"** —— 例：落盘 ≠ 入库，缺"归位"这一步。
5. **把判据与契约放回它该在的层**：谁拥有真相，契约就定义在谁那。
6. **检查"代码里写了、UI 上出不来"的东西**：结构写对了却看不见/点不动，几乎总是**结构或布局层面的错**，不是"功能没写完"。
   必查：非法嵌套（Tooltip 套 Tooltip）· 塌陷高度链（`flex-1` 缺 `h-full`）· 被 `disabled`/`pointer-events:none` 吞掉的入口 · 被上层盖住的图层。
7. **只读实测取证**，且**用与真实调用一致的口径**（用错参数探测会得出相反结论）。

**⛔ 四种"修症状"的滑法**（识别出来就退回做第 2 步）：

| 滑法 | 它为什么是错的 |
| --- | --- |
| **改一版试一次**（改 A → 没变 → 改 B → 再试） | 你在用试错代替设计。每猜一次都在加一层兜底，症状被埋得更深。 |
| **猜环境**（缓存 / 没重启 / 环境问题） | 环境解释几乎总是错的，且它会让你去加"兜底"而不是改结构。 |
| **在错误的位置做深度优化** | 例：病灶是"这动作不该由菜单承载"，却去优化菜单封装 —— **越"正确"离解越远**。 |
| **靠探针反复证伪假设** | 探针是**证明"我改对了"**的工具，不是"我猜对了吗"的猜谜机。定位靠**读代码 + 问用户关键观察**。 |

> **总闸（自查）**：**如果你的下一步动作是"先试试看"，就已经错了。**
> 正确的下一步永远是：**回去把这个能力的正确形态写清楚。**

**判据：什么时候算"做完了"**：

| 口径 | 修症状的"做完" | 做正确的"做完" |
| --- | --- | --- |
| **症状** | 不出现（**可能是被兜底埋了**） | 不出现（且**兜底数量净减**） |
| **该能力** | 还是 N 份判据 | **1 份**判据 |
| **链路** | 缝补后更长/更绕 | **更短、更直**（环节数下降） |
| **契约** | 散在各层、靠猜 | 定义在**拥有真相的那层** |
| **结构** | 非法嵌套 / 塌陷布局仍在 | **逐条对照正确形态清掉了** |
| **失败** | 仍是假成功 / 静默 | 判别联合 + 根部炸开 + 读者正确 |
| **证据** | "我试了，好像好了" | **用户实测通过** + 只读实测 + 闸/测试 |

> **一句话**：**不要服务那个症状，要服务这段能力的正确性。**
> 交付物 =「结构对照正确形态重写 + 判据收口为 1 份 + 契约在正确层 + 兜底净减 + 入口可见可点」。

**弯路留痕（强制）**：改错的弯路必须写进轮次文件，与结论同等对待。
- **记三件事**：① 当时的推理链 ② 为什么它是错的 ③ 是否已完整回退（含"假绿"测试要删）。
- **理由**：弯路的**思路往往非常有道理**（否则你不会走进去），后人极易重走 —— 只留结论、不留弯路，等于丢掉最贵的经验。
- **判据**：锁着"已被撤销设计"的**假绿测试必须删掉** —— 测试通过 ≠ 那件事存在，留着就是给后人"这个契约存在"的假象。

## Step 0 · 普查 —— 仓库里已经有什么？（开工前置）

> **目标**：防止造出系统里的第 N+1 份重复逻辑。

**动作**：

1. **枚举能力**：把要做的事拆成独立能力项。
2. **全库检索（必须使用工具）**：
   - 查引用/残留：`node scripts/mv-sync-refs.mjs refs <file>`
   - 查前人弯路（防截断）：`node scripts/extract-detours.mjs`
   - 查账本解法：`node scripts/debt.mjs search <机制名|症状词>`
3. **判种类**（与 Step 3 同款判别，提前用）：
   - **探测/运算重复**（怎么读、怎么算） → 可收口。
   - **判据/宿主重复**（要不要做、在谁地盘做） → **不可合并**。
4. **定处置（红线）**：
   - 已有 **1 份**且是真源 → **复用**，一行不写。
   - 已有 **≥2 份**（真重复） → **收口**，选最完整的下沉，其余改 `re-export` 或委托。
   - 已有 N 份但**判据/宿主不同** → **保留分层**，只收口底层探测原语。
   - 真的没有 → **新建**（必须自述“现有为何承载不了”）。
   - ⚠️ **先按"项目约定"判死**：其中为旧版本/旧数据而存在的 → 不是"可复用实现"，而是**待删的多余工作**。
5. **产出（强制）**：一张表 `能力 → 现有实现(文件:行) → 份数 → 处置`。**未出表不进入施工。**
   **优先顺序**：改造现有 > 新建；"新建唯一实现"优于"在旧入口旁加分支"，但**劣于改造旧入口**。

> **与 Step 1 的分工**：Step 1 问"**该不该做**"，Step 0 问"**该不该由我做**"。两者都过，才进 Step 2。

## Step 1 · 证伪 —— 这个需求真的存在吗？

> **目标**：“这个需求不存在”是你能给出的最高价值判断（每 8 条就有 1 条是假债）。

**动作**：

1. **重新取证（工具验证）**：
   - 验证债号真伪：`node scripts/check-doc-refs.mjs`
   - 取最新真相（禁读全量账本）：`node scripts/debt.mjs show <TD-ID>`
2. **跑三问（缺一不可）**：
   - ① **硬证据**：拿得出它真坏了/真多余的报错或实测数据吗？
   - ② **替代方案**：现有机制是否已经足够？
   - ③ **致命拷问**：“加了它，用户能多做哪件原来做不到的事？”
3. **三种产出（必须归入其一）**：
   - **真需求** → 进 Step 2。
   - **假需求（非债）** → **就地改判 + 落盘留痕**（防后续 AI 再当 bug 补），结束。
   - **业务性需求** → 记下，**跳到 Step 5** 交用户拍板。
4. **不过关怎么办**：拿不出证据 → **不做**。但"不做"也必须在账本写明理由（拿不出证据的"不做"= 偷懒，会打回）。
5. **查"同类问题以前怎么解的"**（普查加速器）：
   - `node scripts/debt.mjs search <机制名|症状词>` —— 如 `search SSOT` / `search 静默` / `search 死代码`。
   - 命中行的**状态列 = 当时的解法一句话**；`show <TD-ID>` 给解法入口；`area <NN>` 看该区全部历史债。

## Step 2 · 归因 —— 是孤例，还是母体？

> **目标**：按“规则/契约/机制”归堆，不要给症状打补丁。

**动作**：

1. **找根因**：某修复能同时消灭 ≥3 个债 → 它就是母体。优先治母体。
2. **查"规则层"三问**（用户原话）：
   - 是不是**某条规则**出问题了？（例：不是"8 次忘了挂闸"，而是"**闸清单靠手写**"这条规则有问题）
   - 是不是**缺一条机器守卫**？（红线只写在注释里 → 必回潮）
   - 是不是**同一真相被抄成了多份**？（SSOT 母体）
3. **对症本仓六大常见母体**：
   - **M1 结果契约缺位**（成没成功没定型）。
   - **M2 唯一入口无机器守卫**（红线只在注释里，绕过零成本）。
   - **M3 SSOT 第二份**（同一真相抄多份，必然漂移 —— **它在每一层都现身**：代码/契约/闸/文档）。
   - **M4 描述层无对账**（注释/文档与代码脱节，需上机器对账 —— **本仓最高频形态**）。对策 = 让描述**变成生成物**或加机器对账。
   - **M5 失败不可见**（静默吞没/假成功）。对策 = 判别联合替代 `null`/`boolean`；降级必留痕。
   - **M6 幽灵预留**（为将来铺路的零消费代码 → 查 fan-in 为 0，直接删，不许补消费方）。
4. **三种产出**：
   - **母体** → 设计"一次消灭 ≥3 症状"的收口方案（进 Step 3）。
   - **孤例** → 按最小改动处理，但记下"是否该升为规则"。
   - **症状群但无母体** → 老实登记为 N 个债（**不要编造母体**）。

## Step 3 · 定位 —— 复杂度该落到哪个物理位置？

> **目标**：找到改动半径最小的位置（下沉、收敛、删除）。

**动作**：

1. **职责归属**：该数据所有方是谁？我是不是所有方？（消费者严禁执行所有方的动作 → 停）。
2. **真源在哪**：谁产生这个数据？（产生方 = 真相源，消费方只能派生）。
3. **变化速率**：变化快的和变化慢的**不该同居**（真缝隙的判据）。
4. **有几种实现**：只有 1 种实现的接缝 = **假接缝**（禁抽象）。
5. **改动半径**：改动要碰几个文件/几层？**改动半径最小处 = 最优位置**。
6. **接口窄不窄**：窄接口 + 厚实现 = 深模块（好）；宽接口 + 薄实现 = 泄漏（坏）。

**判真假接缝**：
- **探测重复**（怎么读数据） → 强制收口为底层纯函数。
- **判据重复**（要不要放行/动作） → 严禁合并，必须保留在拥有真相的层级（合并会削掉某层的必要能力，如异步兜底）。

**最小半径校验（不过关怎么办）**：若下沉/收敛后改动半径没变小（动了 ≥10 个消费方），说明只搬了家 —— 先问**"能不能让旧入口 `re-export`"**，让消费方零改动。**收敛前必须先分辨上面两种重复**，否则会削掉必要能力。

## Step 4 · 定契 —— 正确性与“错误透传”怎么设计？

> **目标**：失败必须诚实，错误必须在根部炸开。

**五条禁令（违反即打回）**：

| 禁令 | 反例（本仓真实） |
| --- | --- |
| **禁静默吞** | `.catch(() => {})` 零日志 → 已用 `check:catch` 闸封死 |
| **禁假成功** | 缩略图失败用原图冒充（TD-03-7）→ 失败必须返 `null` / `500` |
| **禁错误→错误结果** | 失败时产出"看起来成功但语义相反"的输出 |
| **禁重分类** | 代码 bug 的 `TypeError` 被当"网络错误"重试（TD-03-12）→ 按文案白名单区分 |
| **禁为过闸而重复** | 闸拦住收口时，把同一语义抄成 N 份买绿灯 → **闸在生产它本要禁止的行为**。正解 = 改闸（收窄不放宽） |

### 🔒 拆兜底（本仓最痛的一条 —— 兜底会掩盖错误，让你排查不出问题）

> **核心因果**：兜底让症状"消失"了 → 你会以为修好了 → 但错误被埋得更深 → **真正的问题再也排查不出来**。
> **所以：一次性做正确 > 事后用兜底捂住。**

**兜底的六种形态**（看到自己在写这些 → 停，问"我在掩盖什么"）：

| 形态 | 说明 |
| --- | --- |
| **静默 catch** | `.catch(() => {})` 零日志 |
| **失败归一 `null`** | 把各种失败全压成一个 `null`，调用方无从判别 |
| **占位对象 + 事后打补丁** | 先塞个假对象让它跑通，再在别处补 |
| **默认值兜底** | 拿不到就给个默认值，假装成功 |
| **UI 层提前宣告成功** | 上层先显示"成功"，下层其实还没落盘 |
| **只在某一入口补的"补偿步骤"** | 哪里报错补哪里，而不是改结构 |

**强制动作**：每发现一处兜底，**逐个问"它在掩盖哪条地基缺陷？"** —— **答得出 → 改地基、删兜底**；答不出 → 说明你还没理解它，别加到第 8 种形态。
**验收口径：「兜底数量净减」**（不是"症状消失了" —— 症状可能只是被兜底埋了）。

**动作与红线**：

1. **成功信号必须诚实**：在**类型层**定型（如判别联合 `{ok:true}|{ok:false, error:xxx}`），禁止消费方靠猜。
2. **根部抛错，禁静默吞**：必须在根因发生地抛错或红日志，**严禁把 Catch 埋在三公里外的 UI 层**。
3. **规范结构性空 Catch**：预期内失败必须显式标 `// catch-ok: <理由>`，**写之前必须回读代码验证，严禁手写未验证理由过闸**。
   - ⚠️ `// catch-ok:` 是**自由文本、闸只判"标记是否存在"** → 一句话即可绕过（实测：99 处标记中 7 处贴在非空 catch 上）。故 ——
     1. **写前必回读被 catch 的代码**，确认失败真的不需要可见。**禁写未验证的理由**。
     2. **优先"收口原语"而非逐处标记**：同一"吞"语义手写 ≥3 次 → 收口成原语（自带理由 + 测试 + 唯一实现），别复制第 N 份。
     3. **禁止用守卫替代 catch**：守卫只管 **contract 违约 → fail-fast**；**运行时可预期失败（IO/网络/解析/浏览器 API）一律 `catch + reportDegrade / logger.warn`**。用"前置守卫"预防运行时意外 = **假守卫**（代价更高、还防不住）。
4. **失败可见性给对读者**：开发者 → `logger`（可查）；用户 → toast（瞬时反馈）或 UI 状态（持续状态）。**不混用**（拿 logger 当用户可见性 = 给错读者；拿 toast 表达持续状态 = 逝去即失明）。但也不为"我觉得该有提示"而加（先过 Step 1 三问）。

## Step 5 · 定权 —— 我自己改，还是问用户？

> **判据**：改完后，用户能做的事变了吗？

**唯一判据**：**结构怎么摆 = 架构师直接判；跟业务相关 = 一定问用户。**

| | 架构师**直接定** | 架构师**必须问用户** |
| --- | --- | --- |
| **对象** | 代码结构、函数位置、删重复/死代码、抽 helper、改注释、补守卫、命名 | **删需求、砍功能、增减业务能力、改交互、改对外契约与持久化格式、引入重依赖** |
| **判据** | 改完**功能不变**，只是结构更少/更对 | 改完**用户能做的事变了** |
| **动作** | 直接做，账本记"还债" | 摆成带成本的 A/B/C 选项 + 推荐项 |

**强制提问格式**：必须先写 `问前取证：...`，写不出 = 不许问。选项必须呈递：
```
方案 A（推荐）：<做法> —— 成本 <X>，收益 <Y>，风险 <Z>
方案 B：<做法> —— ...
方案 C：不做 —— 后果是 ...
请决策。
```
- 必须给"不做"选项；选项**禁止退化成问答题**；也**禁止用"复杂度高"单方替用户决定不做**。

## Step 6 · 施工 —— 最小改动，删比改便宜，不留尾巴

**动作**：

1. **只改真风险点**：不为“强迫症一致性”改无风险旧代码。
   - 判据：**"改了它，系统整体复杂度下降了吗？"** 答不上 → 别改。
   - **不要用"成本更低"保留双名/双态** → 先**实测改动点数量**（本轮"多处"实测只有 7 处）。
2. **删旧先证死**：删前必须用 `refs` 证实**零消费**。
   *（注：若 0 引用/文件不存在，`mv-sync-refs.mjs` 会自动查 git 历史，直接告诉你何时被删，省去瞎搜）*
3. **清剿尾巴**：
   - 加新注释 → 必删被取代的旧注释。
   - 换了实现 → 必删旧实现（不要留着“以防万一”）。
   - 删字段 → 同步删接口、解构、派生变量及死分支。

**施工完自查（6 条）**：
- [ ] 我新加的东西**降低**了整体复杂度，还是把它**藏进了新黑盒**？
- [ ] **兜底数量净减了吗**？我有没有新写一处兜底（静默 catch / 归一 null / 默认值 / 提前宣告成功）？
- [ ] 操作的数据所有方是谁？该动作的所有方是不是我？（我是所有方还是消费者；越权 → 删）
- [ ] 有没有留下"两名指一物"/"两处维护同一真相"？（= 我自己在批的 SSOT 第二份）
- [ ] 有没有 `_` 前缀变量 / 未被读取的 state（死代码信号）？
- [ ] 注释里描述的东西，**代码里还存在吗**？

## Step 7 · 验证与落账 —— 探针、测试、门禁与账本（最重的一步）

### 7.1 探针（先红后绿） —— 严禁当猜谜机

> 🔒 **探针是"证明我改对了"的工具，不是"我猜对了吗"的猜谜机。** 这是本节红线。
> **正确顺序**：读懂代码 → 写出正确形态 → 按它改 → 用探针证明我改的那点被测到。
> **熔断**：写不出一句话"正确形态该是什么" → **停手别跑探针**；下一步若是"先试试看" → **已经错了**。
> （定位根因靠**读代码 + 问用户关键观察**，探针只用于**证明修复**，不是证伪假设。）

**为什么必须做**：不做探针的测试 = **自证式测试**（断言实现细节，测了个寂寞）。

**强制执行标准：统一走 `probe.mjs`，严禁手改源码（防假绿、防忘还原）。**

1. **拿真实断言串**：`node scripts/probe.mjs --run "<命令>" --suggest-out`（不要猜断言）。
2. **执行探针命令**（结论块直接粘入日志）：
```bash
node scripts/probe.mjs --label "TD-xx 验证" \
  --file <相对路径> --find "<旧实现>" --replace "<新实现>" \
  --run "<闸 / 单测命令>" --expect-exit 1 --expect-out "<精确关键词>"
```
*说明：此脚本强制三件事 —— ① **注入点唯一**（0 处/多处即拒，防"红的不是那点"）；② **还原 sha256 自校验**（防忘还原 = 假账）；③ **journal 兜底**（`.probe/` 存原文，被打断也能自愈还原）。`--dry` 可先看注入 diff（注入前先确认注入点对不对）。*
3. **反向探针**：若收口导致既有测试变红，先假定“我的收口越界破坏了原有语义”，切勿急于改测试买绿灯。
*口诀：**测试红 ≠ 测试错；测试红 = 既有语义被破坏**。*
4. **若"先红"没红** → 是你的断言没测到那一点，回去重写断言（别跳过）。**但先自查**：这个环境能不能承载这个语义？（例：jsdom 测不出浏览器手势栈 / `pointer-events` → 那是"测不了"，改用手工/用户实测并写明）。
- ⚠️ **"没红"还有一个隐蔽原因：兜底把错误接住了** —— 注入的违规被某处 catch / 默认值吞掉，所以行为没变。**别急着改测试**，先查是不是有兜底在掩盖（那正是要拆的东西）。

### 7.2 门禁与测试

- **只跑相关的测试**，严禁为了小改动连续跑全量（浪费资源且掩盖真实错误）。
- **跑与改动相关的闸**：`check:catch` / `check:arch` / `check:any` / `tsc` / `lint`。
- **改了契约表 / 存储键 / 事件 → 必跑对应闸**（`check:events` / `check:keys`）。
- **新增测试的判断**：修的是**正确性问题**（数据丢失/失败伪装） → **必须**加行为断言；纯结构重构（无行为变化） → 现有测试覆盖即可。

### 7.3 落账规范（不留假账）

1. **债账操作（命令管理，禁手改）**：
- 登记新债：`node scripts/debt.mjs add ...`
- 看待办：`node scripts/debt.mjs list [--area NN] [--status 待还]`
- 结清：`node scripts/debt.mjs resolve <TD-ID> --note "..."`
- 归档：`node scripts/debt.mjs archive`（已完成项移入归档，**主表只留待办**）


2. **落点（各写什么）**：
- **区域日志**：改动、度量（改前/改后）、探针结果、**债描述被修正处**；跨区 → **只写一份** `<触发区NN>-跨区-<主题>-<日期>.md`。
- **`index.md`**：**只改状态 + 日志列链接**（≤2 行），**禁写"说明段"**（结论唯一落点 = 区域日志）。
- **DATAFLOW**：链路有变**就地改现状图**；**禁追加 `更新(<日期>…)` 叙事段**。
- **工具债**：**不延后 → 当场修**（`node --check` + 实跑 + 先红后绿 + 账本一行 `已解决`）。


3. **摘要红线（触发器防腐）**：
- **摘要 ≤ 120 字**（一行一债）。
- **禁裸竖线 `|**`（用 `／` 代替，防撑破 Markdown 表格）。
- 锚点指向必须是已存在的 `<NN>-<区域>-<日期>.md`。


4. **记录弯路留痕与回改原文**：
- 弯路必须记在区域日志（当时的推理链、为何错、假绿测试已删）。
- **修正事实必须回改原文**。只记在新文档里 = 亲手制造 SSOT 漂移。

5. **度量（强制）**：落账必须给出**改前/改后可比**的口径 —— 改动半径 / fan-in / 跨层跳跃 / 认知单元 / 重复份数。"复杂度下降"不许凭感觉宣称。

| Step 3/6 | 收口后**既有测试变红** | 退回 Step 3：很可能把"判据重复"误当"探测重复"合了 → 只收口探测、恢复判据分层 |
| Step 7 探针 | "先红"没红 | 退回重写测试；**测试不红 = 没测到东西** |
| Step 0 普查 | 同类能力已有 ≥2 份，我正准备再写一份 | **退回 Step 0**：先定共用层，否则我就是第 N+1 份 |
| 任何一步 | 引用的**符号/文件/能力不存在**（或未导出） | 退回当前步重新取证（A1/A2） |
| Step 7 落账 | 修正只记在本轮文档、不回改原文 | **退回**：回改原文，否则制造 SSOT 第二份（A7） |
| 任何一步 | 命中 `scripts/**` · 流程文档 · `package.json` 缺陷 | **不停工：当场修**（A10） |
| Step 3/6 | 最优位置/收口**被闸拦住** | **别绕**：结构偏好闸 → 直接改闸（收窄不放宽）+ 闸探针先红后绿；红线闸 → 交用户。**禁止就地重写 N 份** |
| Step 7 落账 | 想在 `index.md` 写"说明段"、或为每个根因区各开一份日志 | **删/并**：结论只写**一份**轮次文件 |
| **任何一步** | **发现"需求"本身不存在** | **退回 Step 1**（最常见也最该退的一步） |

### 附：速查决策树

```
拿到一个问题/债/需求
  │
  ├─ Step 0 仓库里已有什么？──── 同类已 ≥2 份 → 先定共用层（下沉/re-export），不做第 N+1 份
  ├─ Step 1 它真存在吗？──────── 否（假需求）→ 改判非债 + 留痕，结束
  │                             └ 是业务性 → Step 5 问用户
  ├─ Step 2 孤例还是母体？────── 母体 → 一次收口（≥3 症状）
  ├─ Step 3 该放哪？─────────── 先判数据/动作所有方 → 删 / 下沉 / 收敛
  │                             （分清"探测重复=收口 / 判据重复=保留"）
  ├─ Step 4 失败怎么诚实？────── 判别联合 + 根部炸开 + 读者正确
  ├─ Step 5 我改还是问？─────── 结构 → 自己定；业务 → 摆 A/B/C 选项
  ├─ Step 6 最小改动不留尾巴（含兜底净减自查）
  └─ Step 7 探针先红后绿 → 相关测试 → 闸 → 落账 + 度量（含回改原文）
       ├ 命中 `scripts/**` 工具债？→ 当场修、不延后（只留一行"已解决"）
       └ 想在 index 写说明段 / 开多份区域日志？→ 删/并（结论只写一份轮次文件）
```

> **一句话总结**：**先普查，再证伪，后归因，再定位，定契，定权，施工，验证。**
> 其中**最容易跳过、代价最大的是 Step 1** —— "这个需求不存在"是架构师能给出的最高价值判断，也是最难给出的判断（因为它要求你**否定手上已有的东西**）。
