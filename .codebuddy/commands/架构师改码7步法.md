# Step 0 · 普查 —— 仓库里已经有什么？（**开工前置**）

> **对应心法** 铁律 5（不虚构）/ §一.2（空间收敛）/ 本文件 Step 1 的"重新取证"
> **为什么排在最前**：Step 1 证伪的是"**这个需求**是否存在"；Step 0 问的是**更前一层** —— "**这件事，仓库里是不是已经有人做了**"。
> 不先问这一层，动手就必然长出新的一份（本仓实测：抽帧 **9 份**、时间轴刻度 **2 份**、历史栈 **5 份**）。

**要回答的问题**：我要的这项能力，**仓库里已经存在几份？真源在哪？我该复用、改造现有、还是新建？**

**动作**：
1. **枚举能力**（不是枚举文件）：把要做的事拆成能力项（"抽帧" / "时间↔像素换算" / "历史栈" …）。
2. **全库找实现**：每项用 `grep` / `refs` 找**全部**实现点，记 `文件:行` + 符号名 + 达成程度。
3. **数份数**：这份数就是"我要不要再写一份"的判据。
4. **判种类**（沿用 Step 3 的判别）：**探测/运算重复**（怎么读、怎么算）可收口 · **判据/宿主重复**（要不要做、在谁的地盘做）不可合并。
5. **定处置**：`复用` / `改造现有`（含**下沉 + 原处 re-export**，让消费方零改动） / `新建`。

**判据（红线）**：

| 情形 | 动作 |
| --- | --- |
| 已有 **1 份**，且它就是真源 | **复用**，一行都不写 |
| 已有 **≥2 份**（真重复） | **收口**：选最完整的那份**下沉**为唯一实现，其余 re-export / 分域迁入 |
| 已有 **N 份但判据/宿主不同** | **保留分层**，只收口底层探测原语 |
| 真的**没有** | 才**新建**；且必须写出"**现有为什么承载不了**"——写不出 = 你正在造第 N+1 份 |

**产出（强制）**：一张表 `能力 → 现有实现(文件:行) → 份数 → 处置`。**未出表不进入施工。**

**优先顺序**：**改造现有 > 新建**；"新建唯一实现"优于"在旧入口旁加分支"，但**劣于改造旧入口**。

**本仓实证（2026-09-13 视频剪辑器第 0 步，产出 `docs/124`）**：

| 能力 | 份数 | 结论 |
| --- | --- | --- |
| 抽帧 / 缩略图 | **9** | 不先下沉 `captureFrame`，剪辑器胶片条就是**第 10 份** |
| 时间↔像素 / 刻度 | **2**（+待建=3） | 收口到 `base/utils/timeline/`（3 域共用） |
| 历史栈 | **5** | **复用**泛型 `HistoryStack<T>`，不新写第 6 套 |
| 编码器探针 | 1（散在 3D 域） | 已有先例 → 收口共用，**不新写** |

> **与 Step 1 的分工**：Step 1 问"**该不该做**"，Step 0 问"**该不该由我做**"。两者都通过，才进 Step 2。
> **先例**：`docs/119-节点层收口机会普查-重复逻辑收敛清单` · `docs/124-视频剪辑器-能力重叠普查与时间轴真源裁决`。

# Step 1 · 证伪 —— 这个需求真的存在吗？

> **对应心法** §零.5 偷懒判据 / §五 自检「溯源」

**要回答的问题**：如果这个需求消失，我想写的代码还有存在价值吗？

**动作**：
1. **重新取证**：不看描述，直接读代码 / 跑 `refs`，确认"问题"在当前代码里**真实存在**（不是上一轮已修、不是描述漂移）。
2. **跑三问**（§零.5，缺一不可）：
   - ① **根因证据**：拿得出"它真的坏了/真的多余"的硬证据吗？（能复现的失败 / 死代码的零引用计数 / 实测数据）
   - ② **替代方案**：现状（已有机制）是否**已经足够**？我加的这段是否**只是换个说法**？
   - ③ **决策者的选择**：若涉及业务能力变化 → 必须交用户（Step 5）。
3. **问一句致命的话**：**"我加了这个，用户/系统能多做哪一件原来做不到的事？"** 答不出 → 假需求。

**三种产出（必须归入其一）**：

| 结论 | 动作 |
| --- | --- |
| **真需求** | 进入 Step 2 |
| **假需求（非债/伪需求）** | **就地改判 + 落盘留痕**（防后续 AI 再当 bug 补），流程结束 |
| **业务性需求** | 记下，跳到 Step 5 交用户拍板 |

**不过关怎么办**：拿不出根因证据 → **不要做**。但"不做"必须在账本里写明理由（拿不出证据的"不做"= 偷懒，会打回）。

**真实案例**：
- ✅ 正确证伪：TD-05-11 我提议"给 `HubEmpty` 加失败文案"，被质疑后复核 → 失败**已有 toast + logger**，加文案**不改变用户可行动作** → 改判**非债**。
- ❌ 失败证伪：TD-06-8 我继承"现无实害"直接开修 → 实测**有实害**（对照）。

# Step 2 · 归因 —— 是孤例，还是母体？

> **对应心法** §零（复杂度目标）/ §一.2（空间收敛）
> **用户明确要求**：**看到一堆问题时，第一反应必须是"是不是某条规则出问题了 / 它们的底层根因是什么"，先找根因。**

**要回答的问题**：我手上是 N 个独立问题，还是 1 个母体的 N 个症状？

**动作**：
1. **按"它为什么会产生"归堆**（**不是**按症状表面分类）。把同类症状放一起，问：它们共享哪一条**规则/契约/机制**？
2. **判据：某修复能同时消灭 ≥3 个债 → 它就是母体。** 母体几乎总在**契约层/规则层/机制层**，不在"某一行代码"。
3. **查"规则层"的问法**（用户原话）：
   - "是不是**某条规则**出问题了？"（例：不是"8 次忘了挂闸"，而是"**闸清单靠手写**"这条规则有问题）
   - "是不是**缺一条机器守卫**？"（例：红线只写在注释里 → 必回潮）
   - "是不是**同一真相被抄成了多份**？"（SSOT 母体，见下）
4. **母体优先**：先治母体（一次收口），再用母体给出的契约去清存量症状——**不要逐个打补丁**。

**三种产出**：
| 结论 | 动作 |
| --- | --- |
| **母体问题** | 设计"一次消灭 ≥3 症状"的收口方案（进入 Step 3） |
| **孤例** | 按最小改动处理，但记下"是否该升为规则" |
| **症状群但无母体** | 老实登记为 N 个债（**不要编造母体**） |

**本仓三大母体（可直接复用这条经验）**：

| 母体 | 一句话 | 覆盖债 |
| --- | --- | --- |
| **M1 结果契约缺位** | 操作"成没成功/降没降级/真源在哪"未在类型层定型 | TD-02-15/19/24/25 → 一个 `StorageOpResult` 全清 |
| **M2 唯一入口无机器守卫** | 红线只在注释里，绕过零成本 | TD-03-5/02-1/04-15 回潮链 → 补 AST 闸 |
| **M3 SSOT 第二份** | 同一真相被抄成多份，靠"约定"同步 | 代码层(store vs cache) / 契约层(5 种返回形状) / **闸层(清单手写)** / **记录层(规则指向死档案)** |

> **M3 的可怕之处**：它**在每一层都现身**。凡"同一真相被抄成多份"，无论抄在代码、契约、闸还是文档里，**都会漂移**。

# Step 3 · 定位 —— 复杂度该落到哪个物理位置？

> **对应心法** §一.2（空间收敛法则）/ 铁律 5（不虚构）/ 铁律 6（可逆性）

**要回答的问题**：这个复杂度**应该住在哪**？是下沉、收敛、还是删除？

**动作 —— 五问定位置**：
1. **真源在哪？** 谁产生这个数据？（产生方 = 真相源，消费方只能派生）
2. **变化速率？** 变化快的和变化慢的**不该同居**（真缝隙的判据）。
3. **有几种实现？** 只有 1 种实现的接缝 = **假接缝**（禁抽象，铁律 5）。
4. **改动半径？** 放这里，改动要碰几个文件/几层？**改动半径最小处 = 最优位置**。
5. **接口窄不窄？** 窄接口 + 厚实现 = 深模块（好）；宽接口 + 薄实现 = 泄漏（坏）。

**三种动作（按优先级）**：
| 动作 | 何时用 | 例 |
| --- | --- | --- |
| **删** | 死代码 / 死参数 / 死 state（零消费） | 本轮删 `_error` 死 state、`presetPrompts` 死 prop |
| **下沉** | 实现只依赖更底层的叶模块 | TD-06-7 → `toAbsoluteFileUrl` 下沉 `core/utils`（环消除，40+ 消费方**零改动**） |
| **收敛** | 同语义 N 处 → 1 处（真复用，非假抽象） | `matchPatternEntry` 合一；`StorageOpResult` 统一 5 函数 |

**关键判断（防"搬新家而非消灭复杂度"）**：
> **下沉/收敛后，我得给出"改动半径"的改前/改后对比。** 若半径没变小，我只搬了家。

**收敛前必须先分辨"重复的种类"（TD-04-21 教训）**：
> 看到"同一件事写了两遍"**不要直接合一** —— 先问它是哪一种：

| 种类 | 特征 | 处置 |
| --- | --- | --- |
| **探测重复**（怎么读数据） | 两处都在回答"这是不是图片 / 是不是 JSON / 是不是在编辑区" | ✅ **收口**为单一原语（纯函数） |
| **判据重复**（要不要放行 / 做什么动作） | 两处看似同一判断，但**所处层级、可用数据不同** | ❌ **不可合并**：合并会削掉某一层的必要能力（如异步兜底） |

> 实证：`useGlobalPaste`（window 层，只看**同步** `items`）与 `onPaste`（items 为空时**必须继续**走 `navigator.clipboard.read()` **异步兜底**）的放行判据**必须不同**；能收口的只有底层探测原语。
> **收口探测、保留判据** —— 且差异要在注释里写明"为什么不同"，否则下一个人会再试图统一一次。

**不过关怎么办**：若"最优位置"需要动 ≥10 个消费方，先问 **"能不能让旧入口 re-export"**（本轮 TD-06-7 正是如此：改 3 文件，40+ 消费方零改动）。

# Step 4 · 定契 —— 正确性与"错误透传"怎么设计？

> **对应心法** §零.4（正确性 > 复杂度）/ 铁律 2（类型与边界的绝对诚实）
> **取舍顺序**：物理红线 > **正确性/安全** > 复杂度 > 工期。

**要回答的问题**：失败怎么**诚实**表达？错误在**哪一层炸开**？

**四条禁令（违反即打回）**：
| 禁令 | 反例（本仓真实） |
| --- | --- |
| **禁静默吞** | `.catch(() => {})` 零日志 → 已用 `check:catch` 闸封死 |
| **禁假成功** | 缩略图失败 `copyFileSync` 原图冒充缩略图（TD-03-7）→ 失败返 `null` / `500` |
| **禁错误→错误结果** | 失败时产出"看起来成功但语义相反"的输出 |
| **禁重分类** | 代码 bug 的 `TypeError` 被当"网络错误"重试（TD-03-12）→ 按文案白名单区分 |
| **禁为过闸而重复** | 闸拦住收口 / 下沉时，把同一语义抄成 N 份去买绿灯 —— **闸在生产它本要禁止的行为**（TD-22-7：`videoEditor/core` 导不进纯函数层 → 内联重写 7 处 → **漏 1 处 = 静默错**）。正解 = 按心法 §零.4.3 三步**改闸**（定性 → 清单转反向判据 + 只收窄 → 闸探针先红后绿） |

**动作 —— 三问定契约**：
1. **成功信号诚实吗？** 一次操作的"成没成功 / 降没降级 / 真源在哪"必须在**类型层**可判别。
   - 正解形态：**判别联合**（`{ok:true, source:'kv'} | {ok:true, source:'local', degraded:true} | {ok:false, error:'rejected'}`）
   - 反形态：返回 `unknown` / `'a'|'b'` / `{value, from}` 各发明信号 → 消费方靠脑补 → 复杂度漏进散落 catch
2. **错误在哪炸开？** 必须在**根因发生地**（源头：API 边界 / 表单提交 / 存储入口）**抛错或红日志**。
   - **禁止**把 `catch` 埋到三公里外的 UI 层兜底（那是把复杂度搬家）。
   - 唯一例外：**结构性空 catch**（锁链防断 / logger 防递归 / 浏览器 API 预期不可用）→ 必须显式标 `// catch-ok: <理由>`。
   - ⚠️ **豁免通道口径（2026-09-14 修正 · TD-02-26）**：`// catch-ok:` 目前是**自由文本**、闸只判"标记是否存在" → **理由从不被验证、一句话即可绕过**（实测：全 src **99 处**标记中 **7 处贴在非空 catch 上**，`标记量 ≠ 豁免量`）。
     - **① 写 `catch-ok` 前必须回读被 catch 的代码**，确认失败**真的不需要可见**。**禁写未验证的理由** —— 实测 7 处 `contentSet 内部已分类/留痕` 是错的（`contentStore` 持久化失败**不抛**，catch 实吞的是 bug 级异常）。
     - **② 优先"收口原语"而非逐处标记**：同一"吞"语义手写 ≥3 次即应收口成原语（原语自带理由 + 测试 + 唯一实现），别复制粘贴第 N 份。
     - **③ 禁止用守卫替代 catch**：守卫只管 **contract 违约 → fail-fast**；**运行时可预期失败（IO/网络/解析/浏览器 API）一律 `catch + reportDegrade / logger.warn`**。用"前置守卫"去预防运行时意外，就是**假守卫**的成因（代价更高、还防不住）。
3. **失败可见性给对读者了吗？**
   - **开发者** → `logger`（可查）
   - **用户** → toast（瞬时动作反馈）或 UI 状态（持续状态）
   - ⚠️ **不要混用**：拿 logger 当"用户可见性"= 给错读者；拿 toast 表达"持续状态"= 逝去即失明。**但也不要为"我觉得该有提示"而加**（见 Step 1 三问——先证明用户真的需要）。

# Step 5 · 定权 —— 我自己改，还是问用户？

> **对应心法** §零.5（权限边界）/ 铁律 1（依赖也是决策）

| | 架构师**直接定** | 架构师**必须问用户** |
| --- | --- | --- |
| **对象** | 代码结构、函数位置、删重复/死代码、抽 helper、改注释、补守卫、命名 | **删需求、砍功能、增加/减少业务能力、改交互、改对外契约与持久化格式、引入重依赖** |
| **判据** | 改完**功能不变**，只是结构更少/更对 | 改完**用户能做的事变了** |
| **动作** | 直接做，账本记"还债" | **摆成带成本的 A/B/C 选项 + 推荐项**，交用户拍板 |

**禁止**：把真决策退化成问答题；也禁止用"复杂度高"单方面替用户决定不做。

**本仓真实对照**：

- ✅ 交用户拍板：素材 label 化改造（业务能力）/ TD-01-8 生成链路 contract（业务能力）/ "刷新按钮"是否加（交互）

# Step 7 · 验证与落账 —— 探针 / 测试 / 闸 / 账本

> **对应心法** §零.3（度量口径）/ 铁律 2（诚实）

## 7.1 探针（先红后绿）—— 证明"我的修复真的有用"

**为什么必须做**：不做探针的测试 = 自证式测试（实现断言，测了个寂寞）。

**做法**：
1. **写行为断言测试**（不是"函数被调用"，而是"给定输入 → 期望的可观察结果"）。
2. **先红**：把修复**临时改回旧实现**（或注入违规），**确认测试变红**，且**精确命中**我修的那一点。
3. **后绿**：恢复修复，确认转绿。

> 🔧 **"临时改回 / 注入"一律走 `node scripts/probe.mjs`，禁手改源码** —— 改文件这个动作本身就是风险源。
> 它把「注入 → 跑 → 断言 → 还原」收成一条命令，并强制三件事：
> **① 注入点唯一**（0 处 / 多处即拒 → 防"红的不是那点"）；**② 还原 sha256 自校验**（防忘还原 = 假账，见附录 A8）；
> **③ journal 兜底**（`scripts/.probe/` 存原文全文，被 Ctrl+C / 崩溃打断也能在下次启动自愈还原）。
> ```bash
> node scripts/probe.mjs --label "TD-xx 负例" \
>   --file <相对路径> --find "<旧实现>" --replace "<新实现>" \
>   --run "<闸 / 单测命令>" --expect-exit 1 --expect-out "<精确关键词，如 x.ts:384>"
> ```
> 结论块（含 exit / 命中行 / 已还原 sha）**直接粘贴进区域日志**当"先红后绿"证据。`--dry` 可先看注入 diff。

**本仓范例**：
- `check:catch` 探针 → 注入 `catch {}` → 闸精确报该行
- TD-06-8 探针 → 还原对象形式 → `expected '#000000' to be '#ffffff'`（**精确证明用户改动被覆盖**）
- TD-02-17 探针 → 注入坏正则 → 加载时带键名抛错
- **2026-09-14 `probe.mjs` 首次自检**：抹掉 `resourceStore.ts:384` 的 `catch-ok` 标记 → 闸精确报 `resourceStore.ts:384`，跑完工作区零污染（`git status src` 空 + journal 已清）

> **反例警示**：如果"先红"步骤没红，说明**我的测试没测到真东西** —— 回去重写，不要跳过。

> **反向探针（TD-04-21 新增）**：**既有测试 = 行为契约**。
> 做「统一 / 收敛 / 合并判据」这类改动时，把既有测试当探针用：
> 改完跑相关测试 → **若变红，先假定"我的收口越界了"，而不是"测试该改了"**。
> 实证：我抽 `shouldPassContentEditablePaste` 两处共用 → `useAssetDropPaste.test.tsx` 立即 1 红
> （CE 内 `items:[]` + `read()` 返回内容的兜底用例被"提前 return"掐死）→ **回退判据统一，仅保留探测收口**。
> 口诀：**测试红 ≠ 测试错；测试红 = 既有语义被破坏。**

## 7.2 测试 —— 只跑相关的

**禁止**：为了一次小改动跑全量（浪费；且全量绿会给你"很安全"的错觉）。
**做法**：跑**受影响的测试文件** + 受影响链路的关键测试。
**新增测试的判断**：我修的是**正确性问题**（数据丢失/失败伪装） → **必须**加行为断言；纯结构重构（无行为变化） → 现有测试覆盖即可。

## 7.3 门禁

跑与改动相关的闸（本仓：`check:catch` / `check:arch` / `check:any` / `tsc` / `lint`）。
**改了契约表/存储键/事件 → 必跑对应闸**（`check:events` / `check:keys`）。

| Step 7 落账 | 修正**只记在本轮文档**、不回改被修正的原文 | **退回 7.4**：回改原文——否则制造新的 SSOT 第二份（附录 A7） |
| **任何一步** | 命中 `scripts/**` · 流程文档 · `package.json` scripts 的缺陷 | **不停工**：当场修 —— 细则与"修完硬要求"三件全在 **附录 A10**（唯一真源） |
| Step 3 定位 / Step 6 施工 | 最优位置 / 收口动作**被某道闸拦住** | **别绕**：按心法 §零.4.3 三步裁决 —— ① 定性（红线闸 or 结构偏好闸，查 `CLAUDE.md` 级证据）② 结构偏好 → **直接改闸**（清单→反向判据、**只收窄不放宽**）+ 闸探针先红后绿 ③ 红线闸 → 交用户。**禁止**退化成"就地重写 N 份" |
| Step 7 落账 | 我想在 `index.md` 写本轮"说明段"，或为每个根因区各开一份区域日志 | **删 / 并**：结论只写**一份**轮次文件（跨区 → `<触发区NN>-跨区-<主题>-<日期>.md`），index 只留状态 + 链接 |
| **任何一步** | **发现"需求"本身不存在** | **退回 Step 1**（这是最常见也最该退的一步） |

# 附：速查决策树

```
拿到一个问题/债/需求
  │
  ├─ Step 0 仓库里已有什么？───── 同类已 ≥2 份 → 先定共用层（下沉/re-export），不做第 N+1 份
  ├─ Step 1 它真存在吗？────────── 否（假需求）→ 改判非债 + 留痕，结束
  │                              └ 是业务性 → Step 5 问用户
  ├─ Step 2 孤例还是母体？──────── 母体 → 一次收口（≥3症状）
  ├─ Step 3 该放哪？───────────── 删 / 下沉 / 收敛（先分清"探测重复=收口 / 判据重复=保留"）
  ├─ Step 4 失败怎么诚实？──────── 判别联合 + 根部炸开 + 读者正确
  ├─ Step 5 我改还是问？───────── 结构→自己定；业务→摆A/B/C选项
  ├─ Step 6 最小改动不留尾巴
  └─ Step 7 探针先红后绿 → 相关测试 → 闸 → 落账+度量（含回改原文）
       └ 途中命中 `scripts/**` 工具债？→ **当场修、不延后**（只留一行"已解决"）
          途中想在 index 写说明段 / 开多份区域日志？→ **删/并**（结论只写一份轮次文件）
```

> **一句话总结**：**先普查，再证伪，后归因，再定位，定契，定权，施工，验证。**
> 其中**最容易跳过、代价最大的是 Step 1** —— "这个需求不存在"是架构师能给出的最高价值判断，
> 也是最难给出的判断（因为它要求你**否定手上已有的东西**）。
