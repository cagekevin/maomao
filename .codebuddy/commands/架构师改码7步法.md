# 架构师改码 7 步法（通用存量改造 SOP · 工具链加固版）

> **定位**：本文件是**修改存量代码**（修 Bug / 还债 / 重构 / 响应“这里不对劲”）时的**强制操作步骤**。
> **读法**：`Step 0` 是**开工前置**，不计入 7 步。`Step 0 + 7 步` 才是完整流程（先查仓库里已有什么，再动手）。
> **效力边界**：物理红线 > 架构师心法 > 本步骤。

## 🎯 架构师心法与全局铁律

**你是这个项目的架构师，结构、正确性、职责由你直接定。不确定时去取证，不许靠猜，也不许请示。**

### 🔒 五条不可让渡的架构师底线（凌驾于本文件其余所有战术动作）

**① 正确性最优先 —— 最重要**
所有事情都要保证正确性。**"能跑通"与"正确"冲突时，永远选正确**，不准"先跑通再说"。
验收看：**整体复杂度是否下降 + 失败是否诚实可见 + 兜底是否净减**，不看"这行代码跑没跑通"。

**② 职责边界 —— 不能让生产者去决定消费者**
谁拥有真相，契约就定义在谁那；消费者严禁执行所有方的动作，生产者也不替消费者定行为（详见 Step 3 / Step 6）。
越权就是结构错误，不是风格问题 → **停**。

**③ 复杂度 —— 放到合适的位置**
复杂度不会消失，只会被藏起来，然后在三个月后的某人头上爆炸。
**把复杂度收敛到正确的物理位置，而不是搬家**：能删 > 能收敛 > 能下沉；用 `Adapter`/兜底把它藏进黑盒 ≠ 消灭。

**④ 业务数据判断 —— 架构师自己判**
**业务数据不是业务问题，而是架构师自己的判断。** 判据只有一条：**用户用了之后，到底变没变？**
- 用户**没变** → 架构师**直接定**（结构 / 命名 / 位置 / 抽复用 / 删死代码 / 补守卫），**不许请示**。
- 用户**能做的事变了** → 才走 Step 5 摆 A/B/C 交用户。
- 反滥用：把该自己判的结构问题退化成"这个要问用户" = **偷懒**。

**⑤ 拆兜底 —— 绝不掩盖错误**
**兜底会把错误掩盖掉 → 你再也排查不出是哪里的问题。** 一次性做正确 > 事后用兜底捂住。
- **验收口径：「兜底数量净减」**（不是"症状消失了" —— 症状可能只是被兜底埋了）。
- **六种形态**（见 Step 4）：静默 catch / 失败归一 `null` / 占位对象+事后补 / 默认值兜底 / UI 层提前宣告成功 / 只在某入口补的补偿步骤。
- 每发现一处，**逐个问"它在掩盖哪条地基缺陷？"** → 答得出就**改地基、删兜底**。

### 其余全局铁律

1. **贯穿全程的取舍顺序**：
**物理红线 > 正确性职责 > 边界 > 复杂度 > 工期 > 兼容性 > 既有约定（恒排最末）**。
*⚠️ 「既有约定」比"兼容性"还低 —— 它连"要保的东西"都不是，只是**待验证的线索**（见铁律 6）。*
2. **项目约定：不为存量用户做兼容（恒排最后的落地）**：
**判据一句话：「留这个是为了谁？」—— 若答案是"老用户旧数据 / 旧版本"，直接删。**
不为旧数据保留 迁移器 / 双写 / 旧格式分支 / 弃用别名 / 兜底分支；只按正确形态落地。
*⚠️ 与 Step 0 的关系：「仓库里已有 N 份」**不自动等于"都该留"** —— 为旧版本而存在的那几份是**待删的多余工作**，先判死再谈收口。*
*⚠️ 与 Step 5 的关系：删兼容代码**不改变**"业务能力变化要问用户"（用户能做的事不变），属架构师可自定。*
3. **任何“描述/名称”都是线索，必须重新取证**：
债登记、注释、账本输出全可能错。**动手前必须用工具检索，凡能查的一律不许靠推理**。
**且：符号名 / 文件名 / 能力名同样是描述** —— 写进代码或文档前，**必须先 grep 确认它存在、且真的导出**。
4. **不要修症状，要把能力重写正确**：
症状是报信人，任务是把结构重写对，症状消失只是副产品。**严禁四种滑法**：改一版试一次、猜环境、在错误位置深度优化、靠探针反复猜谜。
5. **工具债不延后（红线）**：
开发途中命中 `scripts/**`、流程文档或 `package.json` 的缺陷，**立刻停工当场修好**，否则工具的错误产出会污染后续所有决策。

6. **既有约定 ＜ 正确性 · 既有约定 ＜ 合理性（用户裁定 2026-09-18）**：
**「仓里一直这么写」不是理由。** 既有约定只是**待验证的线索** —— 它**未必是对的，可能正是我们要消灭的对象**。
**判据（引用任何既有约定之前，先问）：「它凭什么成立？」**
   - 答得出（有物理红线 / 类型层 / 唯一入口 / 对账测试支撑）→ 可沿用；
   - 答不出（只是"历来如此"）→ **它就是要被消灭的对象**，按正确形态重写。
⚠️ **反滥用**：不许拿「既有约定」当挡箭牌；也不许拿「正确性」当借口做**无证据**的重写 —— 两边都要取证。
📌 **落点**：被推翻 / 被确立的约定记入 **`docs/adr/`**（索引 `docs/adr/README.md`）；**读债、普查之前先过一遍 ADR 索引**。

> **范畴声明**：本文件以**改存量**为主；**从零新建走 4 步法**。**Step 0/3/4/5/7 对新建同样适用**，但 **Step 2（存量归因）/ Step 6（最小改动）是存量专属** —— 硬套到新建会得出错误结论。

## 🚦 交付四闸 —— 改完代码必须同时满足（缺一即退回重写）

> **判据**：**如果改完代码不能同时满足以下四条标准，说明你只是在「修症状」和「打补丁」—— 必须退回重写**，不许交付。
> **读法**：四条是同一件事的四个切面（**收口 · 净减兜底 · 实减复杂度 · 诚实失败**），**必须一起成立**（只满足三条 = 不合格）。
> **与 Step 的对应**：**一归**（判据归一）主责 **Step 3 定位**（判真假接缝），收口落在 **Step 6 清剿尾巴**；**一诚实**（失败诚实）主责 **Step 4 定契**；**减一**（兜底净减）主责 **Step 4 拆兜底**，并在 **Step 6 施工自查**；**减二**（复杂度实减）主责 **Step 6 施工**，**度量口径落在 Step 7.3**。**Step 7 落账必须逐闸给出证据，答不出即退回。**

| 闸 | 名称 | 标准（一句话） | 一眼判（不合格信号） |
| --- | --- | --- | --- |
| **一归** | 判据归一（SSOT 绝对收口） | 同一能力的判断逻辑必须从 **N 份收口为 1 份** | 仍是 N 份判据 / 新增了第二份真相 |
| **减一** | 兜底净减（拒绝捂盖子） | 兜底代码**不仅不能增加，且必须实现数量净减** | 为了让代码跑通而新增了兜底 |
| **减二** | 复杂度实减（拒绝复杂度搬家） | 整体复杂度**真实下降**，链路**更短、更直**（环节数下降） | 答不上「复杂度降在哪」 |
| **一诚实** | 失败诚实可见（根部炸开） | 所有的失败**不能伪装成成功**，必须诚实可见 | 仍有假成功 / 静默吞没 |

### 一归 · 判据归一（SSOT 绝对收口）

**标准**：同一能力的判断逻辑必须从 **N 份收口为 1 份**。

**验收**：
- 契约必须定义在**真正拥有真相的那一层**。
- **严禁**留下「两名指一物」或「两处维护同一真相」的结构。
- **所有重复的实现必须被抽为唯一实现，其余全部改为委托。**

**不合格信号**：同一能力的判据在 ≥2 处各写一份；契约定义在消费方而非真相方 → **退回重写**。
（执行面 → Step 3「判真假接缝」/ Step 6「清剿尾巴」）

### 减一 · 兜底净减（拒绝捂盖子）

**标准**：系统里的兜底代码**不仅不能增加，且必须实现数量净减**。

**验收**：
- **严禁**为了让代码跑通而新增**静默 catch、默认值兜底或假装成功**。
- **每发现一处报错，必须去改地基、删旧兜底**，而不是加个新兜底把症状埋得更深。

**不合格信号**：新增了静默 catch / 默认值 / 假装成功；兜底总数未降 → **退回重写**。
（形态清单与处置 → Step 4「🔒 拆兜底」）

### 减二 · 复杂度实减（拒绝复杂度搬家）

**标准**：整体复杂度必须**真实下降**，链路必须**更短、更直**（**环节数下降**）。

**验收**：
- **把复杂度藏进 `Adapter` 黑盒不叫消灭。**
- 改完必须能拿出**可比的度量数据**：**改动半径变小、fan-in 减少、跨层跳跃变少、重复份数下降**。
- **答不上「复杂度降在哪」，就不许改。**

**不合格信号**：环节数没降 / 拿不出改前改后度量 / 只把复杂度搬进新黑盒 → **退回重写**。
（度量口径 → Step 7.3「度量（强制）」）

### 一诚实 · 失败诚实可见（根部炸开）

**标准**：所有的失败**不能伪装成成功**，必须诚实可见。

**验收**：
- **错误必须在根因发生地抛出（根部炸开）。**
- 在**类型层**使用**判别联合**替代容易引发假成功的 `null` 或 `boolean`。
- 失败的**可见性必须给对读者**（**开发者看 logger，用户看 UI 状态**）。

**不合格信号**：仍是假成功 / 静默吞没 / 错误被 Catch 埋在三公里外的 UI 层 → **退回重写**。
（执行面 → Step 4「动作与红线」）

> **一句话**：**四条同时成立才叫「改完」；有一条答不出证据，就是补丁，退回重写。**

## 🩺 用户报症状时怎么开工（最高频、最容易跑偏）

> **触发**：用户说「X 不好用 / 我测了还是不行 / 这里不对劲 / 只能做一次」。

**🔒 唯一的开工指令（不要再读别的）**：

> **不要去找那个 bug。去找这段设计正确时该长什么样，然后照着把它重写。**

症状不是要修的对象，是"**这段设计错了**"的报信人。读法上的差别很关键：
- ❌「这个 `if` 为什么没进去？」→ 你在**修症状**（会滑向补丁 + 兜底）。
- ✅「这个能力正确落地时该是什么结构？现在这段结构为什么表达不了它？」→ 你在**做正确**。

**开工动作（顺序即优先级）**：

1. **Step 0 普查**这条链路上"同一件事被实现成几份"（份数 = "我要不要再写一份"的判据）。
2. **把"正确形态"写下来（一屏以内）**：入口是什么 / 链路几步 / 判据在哪层 / 真相归谁。**写不出来 = 你还没理解这个能力** → 回去读代码，别动手。
3. **现状与正确形态逐条对照**，凡是"表达不了正确形态"的结构 → **删掉重写**，而不是缝补。
4. **病灶常常不是"某步写错"，而是"缺了一步"** —— 例：落盘 ≠ 入库，缺"归位"这一步。
5. **把判据与契约放回它该在的层**：谁拥有真相，契约就定义在谁那。
6. **检查"代码里写了、UI 上出不来"的东西**：结构写对了却看不见/点不动，几乎总是**结构或布局层面的错**，不是"功能没写完"。
   必查：非法嵌套（Tooltip 套 Tooltip）· 塌陷高度链（`flex-1` 缺 `h-full`）· 被 `disabled`/`pointer-events:none` 吞掉的入口 · 被上层盖住的图层。
7. **只读实测取证**，且**用与真实调用一致的口径**（用错参数探测会得出相反结论）。

**⛔ 四种"修症状"的滑法**（识别出来就退回做第 2 步）：

| 滑法 | 它为什么是错的 |
| --- | --- |
| **改一版试一次**（改 A → 没变 → 改 B → 再试） | 你在用试错代替设计。每猜一次都在加一层兜底，症状被埋得更深。 |
| **猜环境**（缓存 / 没重启 / 环境问题） | 环境解释几乎总是错的，且它会让你去加"兜底"而不是改结构。 |
| **在错误的位置做深度优化** | 例：病灶是"这动作不该由菜单承载"，却去优化菜单封装 —— **越"正确"离解越远**。 |
| **靠探针反复证伪假设** | 探针是**证明"我改对了"**的工具，不是"我猜对了吗"的猜谜机。定位靠**读代码 + 问用户关键观察**。 |

> **总闸（自查）**：**如果你的下一步动作是"先试试看"，就已经错了。**
> 正确的下一步永远是：**回去把这个能力的正确形态写清楚。**

**判据：什么时候算"做完了"**：

| 口径 | 修症状的"做完" | 做正确的"做完" |
| --- | --- | --- |
| **症状** | 不出现（**可能是被兜底埋了**） | 不出现（且**兜底数量净减**） |
| **该能力** | 还是 N 份判据 | **1 份**判据 |
| **链路** | 缝补后更长/更绕 | **更短、更直**（环节数下降） |
| **契约** | 散在各层、靠猜 | 定义在**拥有真相的那层** |
| **结构** | 非法嵌套 / 塌陷布局仍在 | **逐条对照正确形态清掉了** |
| **失败** | 仍是假成功 / 静默 | 判别联合 + 根部炸开 + 读者正确 |
| **证据** | "我试了，好像好了" | **用户实测通过** + 只读实测 + 闸/测试 |

> **一句话**：**不要服务那个症状，要服务这段能力的正确性。**
> 交付物 =「结构对照正确形态重写 + 判据收口为 1 份 + 契约在正确层 + 兜底净减 + 入口可见可点」。

**弯路留痕（强制）**：改错的弯路必须写进轮次文件，与结论同等对待。
- **记三件事**：① 当时的推理链 ② 为什么它是错的 ③ 是否已完整回退（含"假绿"测试要删）。
- **理由**：弯路的**思路往往非常有道理**（否则你不会走进去），后人极易重走 —— 只留结论、不留弯路，等于丢掉最贵的经验。
- **判据**：锁着"已被撤销设计"的**假绿测试必须删掉** —— 测试通过 ≠ 那件事存在，留着就是给后人"这个契约存在"的假象。

## Step 0 · 普查 —— 仓库里已经有什么？（开工前置）

> **目标**：防止造出系统里的第 N+1 份重复逻辑。

**动作**：

1. **枚举能力**：把要做的事拆成独立能力项。
2. **全库检索（必须使用工具）**：
   - 查引用/残留：`node scripts/mv-sync-refs.mjs refs <file>`
   - 查前人弯路（防截断）：`node scripts/extract-detours.mjs`
   - 查账本解法：`node scripts/debt.mjs search <机制名|症状词>`
   - **查既有约定真伪（防沿用待消灭对象）**：过一遍 `docs/adr/README.md` 索引 —— 哪些约定已被**推翻**、哪些被确立（铁律 6）
3. **判种类**（与 Step 3 同款判别，提前用）：
   - **探测/运算重复**（怎么读、怎么算） → 可收口。
   - **判据/宿主重复**（要不要做、在谁地盘做） → **不可合并**。
4. **定处置（红线）**：
   - 已有 **1 份**且是真源 → **复用**，一行不写。
   - 已有 **≥2 份**（真重复） → **收口**，选最完整的下沉，其余改 `re-export` 或委托。
   - 已有 N 份但**判据/宿主不同** → **保留分层**，只收口底层探测原语。
   - 真的没有 → **新建**（必须自述“现有为何承载不了”）。
   - ⚠️ **先按"项目约定"判死**：其中为旧版本/旧数据而存在的 → 不是"可复用实现"，而是**待删的多余工作**。
5. **产出（强制）**：一张表 `能力 → 现有实现(文件:行) → 份数 → 处置`。**未出表不进入施工。**
   **优先顺序**：改造现有 > 新建；"新建唯一实现"优于"在旧入口旁加分支"，但**劣于改造旧入口**。

> **与 Step 1 的分工**：Step 1 问"**该不该做**"，Step 0 问"**该不该由我做**"。两者都过，才进 Step 2。

## Step 1 · 证伪 —— 这个需求真的存在吗？

> **目标**：“这个需求不存在”是你能给出的最高价值判断（每 8 条就有 1 条是假债）。

**动作**：

1. **重新取证（工具验证）**：
   - 验证债号真伪：`node scripts/check-doc-refs.mjs`
   - 取最新真相（禁读全量账本）：`node scripts/debt.mjs show <TD-ID>`
2. **跑三问（缺一不可）**：
   - ① **硬证据**：拿得出它真坏了/真多余的报错或实测数据吗？
   - ② **替代方案**：现有机制是否已经足够？
   - ③ **致命拷问**：“加了它，用户能多做哪件原来做不到的事？”
3. **三种产出（必须归入其一）**：
   - **真需求** → 进 Step 2。
   - **假需求（非债）** → **就地改判 + 落盘留痕**（防后续 AI 再当 bug 补），结束。
   - **业务性需求** → 记下，**跳到 Step 5** 交用户拍板。
4. **不过关怎么办**：拿不出证据 → **不做**。但"不做"也必须在账本写明理由（拿不出证据的"不做"= 偷懒，会打回）。
5. **查"同类问题以前怎么解的"**（普查加速器）：
   - `node scripts/debt.mjs search <机制名|症状词>` —— 如 `search SSOT` / `search 静默` / `search 死代码`。
   - 命中行的**状态列 = 当时的解法一句话**；`show <TD-ID>` 给解法入口；`area <NN>` 看该区全部历史债。

## Step 2 · 归因 —— 是孤例，还是母体？

> **目标**：按“规则/契约/机制”归堆，不要给症状打补丁。

**动作**：

1. **找根因**：某修复能同时消灭 ≥3 个债 → 它就是母体。优先治母体。
2. **查"规则层"三问**（用户原话）：
   - 是不是**某条规则**出问题了？（例：不是"8 次忘了挂闸"，而是"**闸清单靠手写**"这条规则有问题）
   - 是不是**缺一条机器守卫**？（红线只写在注释里 → 必回潮）
   - 是不是**同一真相被抄成了多份**？（SSOT 母体）
3. **对症本仓六大常见母体**：
   - **M1 结果契约缺位**（成没成功没定型）。
   - **M2 唯一入口无机器守卫**（红线只在注释里，绕过零成本）。
   - **M3 SSOT 第二份**（同一真相抄多份，必然漂移 —— **它在每一层都现身**：代码/契约/闸/文档）。
   - **M4 描述层无对账**（注释/文档与代码脱节，需上机器对账 —— **本仓最高频形态**）。对策 = 让描述**变成生成物**或加机器对账。
   - **M5 失败不可见**（静默吞没/假成功）。对策 = 判别联合替代 `null`/`boolean`；降级必留痕。
   - **M6 幽灵预留**（为将来铺路的零消费代码 → 查 fan-in 为 0，直接删，不许补消费方）。
4. **三种产出**：
   - **母体** → 设计"一次消灭 ≥3 症状"的收口方案（进 Step 3）。
   - **孤例** → 按最小改动处理，但记下"是否该升为规则"。
   - **症状群但无母体** → 老实登记为 N 个债（**不要编造母体**）。

## Step 3 · 定位 —— 复杂度该落到哪个物理位置？

> **目标**：找到改动半径最小的位置（下沉、收敛、删除）。

**动作**：

1. **职责归属**：该数据所有方是谁？我是不是所有方？（消费者严禁执行所有方的动作 → 停）。
2. **真源在哪**：谁产生这个数据？（产生方 = 真相源，消费方只能派生）。
3. **变化速率**：变化快的和变化慢的**不该同居**（真缝隙的判据）。
4. **有几种实现**：只有 1 种实现的接缝 = **假接缝**（禁抽象）。
5. **改动半径**：改动要碰几个文件/几层？**改动半径最小处 = 最优位置**。
6. **接口窄不窄**：窄接口 + 厚实现 = 深模块（好）；宽接口 + 薄实现 = 泄漏（坏）。

**判真假接缝**：
- **探测重复**（怎么读数据） → 强制收口为底层纯函数。
- **判据重复**（要不要放行/动作） → 严禁合并，必须保留在拥有真相的层级（合并会削掉某层的必要能力，如异步兜底）。

**最小半径校验（不过关怎么办）**：若下沉/收敛后改动半径没变小（动了 ≥10 个消费方），说明只搬了家 —— 先问**"能不能让旧入口 `re-export`"**，让消费方零改动。**收敛前必须先分辨上面两种重复**，否则会削掉必要能力。

## Step 4 · 定契 —— 正确性与“错误透传”怎么设计？

> **目标**：失败必须诚实，错误必须在根部炸开。

**五条禁令（违反即打回）**：

| 禁令 | 反例（本仓真实） |
| --- | --- |
| **禁静默吞** | `.catch(() => {})` 零日志 → 曾用 `check:catch` 闸封死；**该闸已于 2026-09-17 按用户裁定删除** —— 它要求的"豁免标记"允许一句话合法通过（贴 `// catch-ok:` 比真正改造便宜），**在生产它本要禁止的行为**。现判据 = 「错误必须由产生它的那层以**判别联合**透传（含可展示信息）；消费者只转发、禁止自己显示/加工」 |
| **禁假成功** | 缩略图失败用原图冒充（TD-03-7）→ 失败必须诚实返回判别联合 `{ok:false, error}`（或 HTTP 500），**绝不许返 `null` 冒充**——"失败归一 null" 本身就属兜底形态（见拆兜底），正是要拆的东西 |
| **禁错误→错误结果** | 失败时产出"看起来成功但语义相反"的输出 |
| **禁重分类** | 代码 bug 的 `TypeError` 被当"网络错误"重试（TD-03-12）→ 按文案白名单区分 |
| **禁为过闸而重复** | 闸拦住收口时，把同一语义抄成 N 份买绿灯 → **闸在生产它本要禁止的行为**。正解 = 改闸（收窄不放宽） |

### 生产者 ↔ 消费者 三铁律（给全 · 只转发 · 不越权）

> **一句话**：**生产者给全信息，消费者只转发，消费者永远不替生产者做任何决定。**
> **效力**：用户裁定 2026-09-17（「消费者你不可以越权」「只有生产者才有权呈现错误」）在 7 步法内的展开。红线原文见 `CLAUDE.md §5.1`，本节约展开、判据与实证，**不另立文**。
> **验收口径**：消费者侧**零自造**（不写判据 / 不拼文案 / 不 new 兜底 / 不替生产者决定可见性）＝ 与**一归 / 减一 / 一诚实**三闸同时对齐。

| # | 铁律（用户原话） | 一句话判据 | 本仓实证 |
| --- | --- | --- | --- |
| **① 给全** | 生产者要提供**所有的信息** | 消费者需要的成功/失败/可展示文案/原因/证据，生产者**一次给全**；给不全 = 生产者缺契约，**不是消费者的错** | 结果契约 `{ok,data}|{ok:false,error}` 钉死成功与失败；`reportDegrade` 每次失败必 `logger.warn` 并原样交出 toast |
| **② 只转发** | 消费者**只做转发** | 原样透传生产者的信息；不翻译、不加工、不重分类、不自造 | `degrade.ts` 从「转发＋替生产者决定可见性」改成**纯转发**；`ErrorBoundary` 只陈述自己生产的「已重试 N 次」 |
| **③ 不越权** | 消费者**禁止替生产者做任何决定，也无权干涉** | 判据 / 重试 / 降级 / 呈现频率 / 因果结论 —— **全归生产者**；消费者复制或改写 = SSOT 第二份 | `reportDegrade` throttle 单槽越权持窗口；`ErrorBoundary` 全屏因果文案被撤；TD-16-39~46 消费者自造 canonical 能力 |

**① 生产者给全 —— 给全什么（生产者出口自检清单）**

- **成功契约**：`ok:true` + 结果证据（`res.changes` / `res.linked.length`），不许只有恒真 `ok:true`。
- **失败契约**：判别联合 `{ok:false, error}`，`error` 含**可展示文案 + 原因 + 降级标记**。
- **状态证据**：缺的 / 跳过的 / 失败的各自列出（`missing[]` / `skipped[]` / `failed[]`），**不许把失败计进成功数**。
- **业务判据**：该不该做 / 放不放行 —— 留在生产者层**导出**，不许写进消费者。
- **可选字段**：没给就是**真空**，消费者静默才是正确 —— 禁止消费者因"缺可选字段"自行告警 / 呈现。

> **给不全怎么办**：**回生产者补契约**（补 `error` 字段 / 可展示文案 / 证据），不许让消费者"自己拼"。消费者拿不到比生产者更全的真相 —— 越靠下游补，越是在**拼第二份不完整的真相**。

**② 消费者只转发 —— 允许什么、禁止什么**

允许（只有这三件事）：
1. **原样透传**生产者的判词（`message` / `reason`），按读者分流（开发者看 `logger`，用户看 UI 状态）。
2. **呈现自己生产的事实**（如「本组件发起的第 N 次重试」）。
3. **统一聚合展示**（一屏收口是聚合，不是再产生）。

禁止（写任何一个 = 违规）：
- ❌ 自己拼错误文案 / 翻译错误 —— 转发者的因果说明**长着系统的脸**，但没有任何生产者信息支撑。
- ❌ `try/catch` 后 `new` 假成功对象 / 塞默认值。
- ❌ 重分类（`TypeError` 当网络错误重试）。
- ❌ 替生产者决定「失败要不要让用户看见、多频繁」。
- ❌ 写因果判断：「问题出在 X / 说明数据坏了」。

**③ 消费者不越权 —— 什么算"替生产者做决定"**

- **复制业务判据**：能调用生产者导出的函数却不调，自己重写一份（SSOT 第二份）。
- **mutate 生产者数据**：组件直接改 props 传入对象 / store 内部状态。
- **决定策略**：重试策略、降级策略、呈现频率、窗口合并 —— 全部归生产者。
- **下因果结论**：替生产者断言原因（实证：`ErrorBoundary` 全屏页曾写「仍失败说明问题来自画布数据或运行环境」被撤 —— 没有任何生产者提供该结论，且与"渲染里必然抛的 bug 也重试必败"矛盾）。

**违规处置顺序（唯一正确动作）**：
1. 发现消费端「乱写」→ **第一动作不是改消费端**，先查生产者是否给全（失败契约 / 判据 / 证据）。
2. 生产者缺 → **回 Step 4 补生产者基建**，不在消费端写第二份（写第二份 = SSOT 第二份 + 兜底净增，**双违规**）。
3. 生产者已给全、消费者仍自造 → 删消费端重写，改**委托 / 转发**，一行新逻辑不写。

**消费者落笔前自查 3 问**：
- [ ] 这句话断言的事实是**谁**生产的？不是我 → 不许断言，只能转发。
- [ ] 我能不能**只调用**生产者导出的函数？能 → 必须调，禁止自造第二份。
- [ ] 我在替生产者决定什么吗（可见性 / 频率 / 重试 / 默认值）？在 → 越权，删。

**本仓实证对照（消费者自造 / 越权，均已登账）**：

| 实证 | 形态 | 处置 |

### 🔒 拆兜底（本仓最痛的一条 —— 兜底会掩盖错误，让你排查不出问题）

> **核心因果**：兜底让症状"消失"了 → 你会以为修好了 → 但错误被埋得更深 → **真正的问题再也排查不出来**。
> **所以：一次性做正确 > 事后用兜底捂住。**

**兜底的六种形态**（看到自己在写这些 → 停，问"我在掩盖什么"）：

| 形态 | 说明 |
| --- | --- |
| **静默 catch** | `.catch(() => {})` 零日志 |
| **失败归一 `null`** | 把各种失败全压成一个 `null`，调用方无从判别 |
| **占位对象 + 事后打补丁** | 先塞个假对象让它跑通，再在别处补 |
| **默认值兜底** | 拿不到就给个默认值，假装成功 |
| **UI 层提前宣告成功** | 上层先显示"成功"，下层其实还没落盘 |
| **只在某一入口补的"补偿步骤"** | 哪里报错补哪里，而不是改结构 |

**强制动作**：每发现一处兜底，**逐个问"它在掩盖哪条地基缺陷？"** —— **答得出 → 改地基、删兜底**；答不出 → 说明你还没理解它，别加到第 8 种形态。
**验收口径：「兜底数量净减」**（不是"症状消失了" —— 症状可能只是被兜底埋了）。

**动作与红线**：

1. **成功信号必须诚实**：在**类型层**定型（如判别联合 `{ok:true}|{ok:false, error:xxx}`），禁止消费方靠猜。
2. **根部抛错，禁静默吞**：必须在根因发生地抛错或红日志，**严禁把 Catch 埋在三公里外的 UI 层**。
3. **规范结构性空 Catch**：预期内失败必须显式标 `// catch-ok: <理由>`（注：`check:catch` 闸已于 2026-09-17 删除，标记已无机器校验，纯靠人工回读），**写之前必须回读代码验证，严禁手写未验证理由**。
   - ⚠️ `// catch-ok:` 是**自由文本、无任何机器校验**（`check:catch` 闸已于 2026-09-17 删除，不再有"判标记是否存在"的闸）→ 一句话即可伪装成"已评审"，实则零保护（实测：99 处标记中 7 处贴在非空 catch 上）。故 ——
     1. **写前必回读被 catch 的代码**，确认失败真的不需要可见。**禁写未验证的理由**。
     2. **优先"收口原语"而非逐处标记**：同一"吞"语义手写 ≥3 次 → 收口成原语（自带理由 + 测试 + 唯一实现），别复制第 N 份。
     3. **禁止用守卫替代 catch**：守卫只管 **contract 违约 → fail-fast**；**运行时可预期失败（IO/网络/解析/浏览器 API）一律 `catch + reportDegrade / logger.warn`**。用"前置守卫"预防运行时意外 = **假守卫**（代价更高、还防不住）。
4. **失败可见性给对读者**：开发者 → `logger`（可查）；用户 → toast（瞬时反馈）或 UI 状态（持续状态）。**不混用**（拿 logger 当用户可见性 = 给错读者；拿 toast 表达持续状态 = 逝去即失明）。但也不为"我觉得该有提示"而加（先过 Step 1 三问）。

## Step 5 · 定权 —— 我自己改，还是问用户？

> **判据**：改完后，用户能做的事变了吗？

**唯一判据**：**结构怎么摆 = 架构师直接判；跟业务相关 = 一定问用户。**

| | 架构师**直接定** | 架构师**必须问用户** |
| --- | --- | --- |
| **对象** | 代码结构、函数位置、删重复/死代码、抽 helper、改注释、补守卫、命名 | **删需求、砍功能、增减业务能力、改交互、改对外契约与持久化格式、引入重依赖** |
| **判据** | 改完**功能不变**，只是结构更少/更对 | 改完**用户能做的事变了** |
| **动作** | 直接做，账本记"还债" | 摆成带成本的 A/B/C 选项 + 推荐项 |

**强制提问格式**：必须先写 `问前取证：...`，写不出 = 不许问。选项必须呈递：
```
方案 A（推荐）：<做法> —— 成本 <X>，收益 <Y>，风险 <Z>
方案 B：<做法> —— ...
方案 C：不做 —— 后果是 ...
请决策。
```
- 必须给"不做"选项；选项**禁止退化成问答题**；也**禁止用"复杂度高"单方替用户决定不做**。

## Step 6 · 施工 —— 最小改动，删比改便宜，不留尾巴

**动作**：

1. **只改真风险点**：不为“强迫症一致性”改无风险旧代码。
   - 判据：**"改了它，系统整体复杂度下降了吗？"** 答不上 → 别改。
   - **不要用"成本更低"保留双名/双态** → 先**实测改动点数量**（本轮"多处"实测只有 7 处）。
2. **删旧先证死**：删前必须用 `refs` 证实**零消费**。
   *（注：若 0 引用/文件不存在，`mv-sync-refs.mjs` 会自动查 git 历史，直接告诉你何时被删，省去瞎搜）*
3. **清剿尾巴**：
   - 加新注释 → 必删被取代的旧注释。
   - 换了实现 → 必删旧实现（不要留着“以防万一”）。
   - 删字段 → 同步删接口、解构、派生变量及死分支。

## Step 7 · 验证与落账 —— 探针、测试、门禁与账本（最重的一步）

### 7.1 探针（先红后绿） —— 严禁当猜谜机

> 🔒 **探针是"证明我改对了"的工具，不是"我猜对了吗"的猜谜机。** 这是本节红线。
> **正确顺序**：读懂代码 → 写出正确形态 → 按它改 → 用探针证明我改的那点被测到。
> **熔断**：写不出一句话"正确形态该是什么" → **停手别跑探针**；下一步若是"先试试看" → **已经错了**。
> （定位根因靠**读代码 + 问用户关键观察**，探针只用于**证明修复**，不是证伪假设。）

**为什么必须做**：不做探针的测试 = **自证式测试**（断言实现细节，测了个寂寞）。

**强制执行标准：统一走 `probe.mjs`，严禁手改源码（防假绿、防忘还原）。**

1. **拿真实断言串**：`node scripts/probe.mjs --run "<命令>" --suggest-out`（不要猜断言）。
2. **执行探针命令**（结论块直接粘入日志）：
```bash
node scripts/probe.mjs --label "TD-xx 验证" \
  --file <相对路径> --find "<旧实现>" --replace "<新实现>" \
  --run "<闸 / 单测命令>" --expect-exit 1 --expect-out "<精确关键词>"
```
*说明：此脚本强制三件事 —— ① **注入点唯一**（0 处/多处即拒，防"红的不是那点"）；② **还原 sha256 自校验**（防忘还原 = 假账）；③ **journal 兜底**（`.probe/` 存原文，被打断也能自愈还原）。`--dry` 可先看注入 diff（注入前先确认注入点对不对）。*
3. **反向探针**：若收口导致既有测试变红，先假定“我的收口越界破坏了原有语义”，切勿急于改测试买绿灯。
*口诀：**测试红 ≠ 测试错；测试红 = 既有语义被破坏**。*
4. **若"先红"没红** → 是你的断言没测到那一点，回去重写断言（别跳过）。**但先自查**：这个环境能不能承载这个语义？（例：jsdom 测不出浏览器手势栈 / `pointer-events` → 那是"测不了"，改用手工/用户实测并写明）。
- ⚠️ **"没红"还有一个隐蔽原因：兜底把错误接住了** —— 注入的违规被某处 catch / 默认值吞掉，所以行为没变。**别急着改测试**，先查是不是有兜底在掩盖（那正是要拆的东西）。

### 7.2 门禁与测试

- **只跑相关的测试**，严禁为了小改动连续跑全量（浪费资源且掩盖真实错误）。
- **跑与改动相关的闸**：`check:arch` / `check:any` / `tsc` / `lint`（`check:catch` 已于 2026-09-17 删除）。
- **改了契约表 / 存储键 / 事件 → 必跑对应闸**（`check:events` / `check:keys`）。
- **新增测试的判断**：修的是**正确性问题**（数据丢失/失败伪装） → **必须**加行为断言；纯结构重构（无行为变化） → 现有测试覆盖即可。

### 7.3 落账规范（不留假账）

> **入账判据**：债位只留给**设计缺陷**（结构／契约／规则）；一次性操作疏漏（删文件未清引用、漏改一处常量）→ 改代码 + 日志一句，**不入账**。

1. **债账操作（命令管理，禁手改）**：
- 登记新债：`node scripts/debt.mjs add ...`
- 看待办：`node scripts/debt.mjs list [--area NN] [--status 待还]`
- 结清：`node scripts/debt.mjs resolve <TD-ID> --note "..."`
- 归档：`node scripts/debt.mjs archive`（已完成项移入归档，**主表只留待办**）


2. **落点（各写什么）**：
- **区域日志**：改动、度量（改前/改后）、探针结果、**债描述被修正处**；跨区 → **只写一份** `<触发区NN>-跨区-<主题>-<日期>.md`。
- **`index.md`**：**只改状态 + 日志列链接**（≤2 行），**禁写"说明段"**（结论唯一落点 = 区域日志）。
- **DATAFLOW**：链路有变**就地改现状图**；**禁追加 `更新(<日期>…)` 叙事段**。
- **工具债**：**不延后 → 当场修**（`node --check` + 实跑 + 先红后绿 + 账本一行 `已解决`）。


3. **摘要红线（触发器防腐）**：
- **摘要 ≤ 120 字**（一行一债）。
- **禁裸竖线 `|**`（用 `／` 代替，防撑破 Markdown 表格）。
- 锚点指向必须是已存在的 `<NN>-<区域>-<日期>.md`。


4. **记录弯路留痕与回改原文**：
- 弯路必须记在区域日志（当时的推理链、为何错、假绿测试已删）。
- **修正事实必须回改原文**。只记在新文档里 = 亲手制造 SSOT 漂移。

5. **度量（强制）**：落账必须给出**改前/改后可比**的口径 —— 改动半径 / fan-in / 跨层跳跃 / 认知单元 / 重复份数。"复杂度下降"不许凭感觉宣称。

#### 三、建闸前必答 6 问（**任一答不出 → 不建**）

1. **守什么**：拿得出 `CLAUDE.md` 级红线证据吗？（拿不出 = 默认值 → 不做闸）
2. **能不能不建**：结构 / 类型 / 唯一入口 / 对账测试里，有没有更根本的手段？（**有就用那个**）
3. **它上次会拦住什么**：能举出一个**已发生的真实案例**吗？（举不出 → 空转风险）
4. **红了之后作者知道做什么吗**：闸的输出里带「怎么修」吗？（不带 → 他必然绕）
5. **合法通过成本落在哪个动作上**：落在**高频动作**上（每加一个节点 / 每写一次 xxx 都要登记）→ **必被绕，直接不建**
6. **"我覆盖多少"可机器验证吗**：这句声索是**闸自己算出来的**，还是人写的？（人写的 → 覆盖不足时必被改声索，见形态④）

#### 四、判定要建之后的三条硬约束

1. **反向判据优先**（禁白名单清单）；
2. **申诉口三问必须齐**（脚本头，缺一即"形式主义闸"）；
3. **自带基数自检 + 负例探针**（证明它会红）。**没有负例探针的闸 = 未验收**。

#### 五、删闸也是合法动作（且必须删干净）

- **删闸不是失败**；**留一道假护栏才是**。当"覆盖不足"时你有两条路：**补覆盖** 或 **删掉它** —— **唯一不允许的是改声索**。
- 删闸按"删旧不留半态"办：闸脚本 + 闸清单（`gates.manifest.json`）+ 元层登记（扫描根/自检表）+ `package.json` script + **所有引用它的文档与代码注释逐处回改**（否则就是亲手造 SSOT 漂移）。
- 删完必须**写明代价**："这条红线退回只写在注释里"，并登记"可能回潮"。

# TS+React 异常&容错代码禁止项
原则：禁止静默吞异常、隐藏失败状态；失败与正常数据必须在类型上区分；所有异常必须可观测（日志/监控）

1. Promise相关
❌ 禁止空catch：.catch(()=>{}) / .catch(e=>{})，捕获错误必须写日志或上报；**唯一例外**是经回读校验的"预期内失败"，须显式标 `// catch-ok: <理由>` 并 `reportDegrade/logger.warn` 留痕（该标记无自动校验、写前必回读，详见 Step 4 动作与红线③）。
❌ 禁止裸fetch不校验 !res.ok，必须手动throw HTTP错误。
❌ 禁止直接调用async函数不捕获异常（useEffect、onClick、setTimeout里），产生unhandledRejection。
❌ 禁止Promise.allSettled不判断status直接读取value。
❌ 禁止在.finally回调内抛出未捕获异常。

2. 同步容错工具 tryParse / tryRun / safeStringify / safeDecode
❌ 禁止捕获异常后直接return null / 默认值 / 空字符串，不记录错误。
❌ 禁止返回 T|null 单一类型；必须返回判别联合 `{ok:true, data?} | {ok:false, error}`（以 `ok` 字段区分成败，禁止用 null 冒充，与 Step 4 契约一致）。
❌ 禁止仅使用 as T 做类型转换，缺少zod/守卫函数运行时校验。
❌ 禁止调用 tryParse/tryRun 后不判断 `ok`，直接读取 data。

3. Hooks与副作用
❌ useEffect异步请求必须使用AbortController，禁止竞态请求覆盖state。
❌ 禁止组件卸载后执行setState。
❌ useEffect清理函数内异常必须try/catch，禁止裸抛。
❌ useMemo/useCallback内危险计算，禁止不捕获异常直接向上抛出。

4. 类型断言与空值兜底
❌ 禁止双重类型断言 as unknown as T。
❌ 禁止滥用非空断言 !。
❌ 禁止使用 ?? / || 强行填充默认值掩盖缺失字段，无法区分空值和数据缺失。

5. 定时器、DOM事件回调
❌ setTimeout / setInterval 内async回调必须try/catch。
❌ DOM事件回调禁止空catch吞掉异常。

6. 接口与错误边界
❌ HTTP 200时，禁止跳过业务错误码判断直接使用返回数据。
❌ ErrorBoundary不能设置fallback=null；捕获组件错误必须上报监控，禁止静默隐藏。

7. Promise异步补充
❌ 禁止在.then回调内写裸async函数，不处理内部抛出的Promise异常（会游离变成unhandledRejection）。
❌ 禁止catch捕获错误后人为resolve伪装成功对象制造假成功。
❌ 禁止丢弃Promise.reject返回值，不做捕获。
❌ 禁止用抛出Error来处理可预期业务失败；业务失败必须使用判别联合返回，异常仅用于程序不可预期错误。
❌ 禁止函数返回 T | Error 混合类型；必须使用 `{ok:true,data?}|{ok:false,error}` 判别联合（与 Step 4 契约一致）。

8. 对象、解构、参数默认值兜底
❌ 禁止解构就地使用对象/字面量数组作为默认值，掩盖字段缺失同时制造不稳定引用。
❌ 禁止使用对象展开 {...obj, key: defaultVal} 静默补全缺失字段，无日志无校验。
❌ 禁止函数参数大对象字面量默认值 function fn(opt={})，带来引用不稳定并且掩盖调用方问题。

9. React状态与副作用
❌ 禁止catch捕获错误后直接setState写入残缺/占位模拟数据，掩盖真实失败。
❌ 禁止useEffect依赖数组直接写入内联对象、内联数组，制造隐形依赖漂移。
❌ 禁止渲染阶段直接执行可变副作用（localStorage、接口调用）。
❌ 禁止仅靠isMounted布尔标记代替AbortController处理请求；isMounted只能阻止setState，不会终止网络请求，属于伪兜底。

10. 序列化、重试、浏览器原生API
❌ 禁止重试工具无条件重试全部错误，不区分业务错误、程序错误、网络错误，禁止把程序bug当成网络异常重试。
❌ 禁止重试逻辑丢失原始error cause，只保留自定义message，丢失原始堆栈。

11. try‑catch块范围约束
❌ 禁止超大try块包裹多段无关逻辑，所有不同根因异常全部归一返回null。
❌ 禁止catch捕获异常后，不中断主业务流程，继续向下执行业务逻辑使用已经损坏的上下文。

12. SSOT职责边界
❌ 禁止消费方复制真相源的业务判据，不调用导出的源函数，制造第二份判据。
❌ 禁止组件直接mutate修改props传入对象，消费者越权修改生产者数据。
❌ 禁止同一套业务规则，TS静态类型与运行时if判断两套不一致逻辑。

13. 标记、测试相关
❌ 禁止滥用 `// catch-ok:` 注释标记（`check:catch` 闸已于 2026-09-17 删除，标记已无任何自动校验，纯属约定，不再有"绕过闸"一说）；写标记前必须回读校验被捕获代码；同一语义出现>=3次，必须收口为原语，禁止到处复制标记（收口原语自带理由+测试+唯一实现）。
❌ 禁止为了单测能跑通，在业务代码新增专门适配测试的兜底分支（兜底净减原则）。

审计规则：任意一条命中 → BUG，写明根因，对照7步法兜底形态/SSOT原则；全部满足 → PASSED

生产者给全信息、消费者只转发、消费者不替生产者做任何决定（三铁律 · 见 Step 4）！
错误必须由产生它的那层以判别联合透传（含可展示信息）；消费者只转发、禁止自己显示/加工！
降级必须留痕，显示可见。如果生成者缺了内容，那应该去补生产者的基建，而不是在消费端随意乱写！！
