# 架构师新建 4 步法 · **V2**（从零构建 SOP）

> **版本**：本文即 **V2**（原地取代 V1；V1 原文见 git 历史，不再维护）。
> **共用部分**：与 `架构师改码7步法.md` 共用的判据 / 命令 / 模板，**唯一真源 = `架构师共用判据.md`**（本文引用处只写节号，不复制正文）。

**核心心法**：改码是「治病排雷」，新建是「优生防御」。新建没有历史病灶可对照，
必须靠**前置模型设计 + 机器门禁**杜绝把新代码写成明天的技术债。
**全局铁律**：**先想清最优解 → 再定真相 → 再设防腐 → 死磕失败 → 最后画 UI。** 敢从 UI 组件往下写，一律打回。

### 0.3 红线 还是 结构偏好（写规则前先问）

> 取自 ADR-0025：**撬不动 ⇒ 红线；撬得动但要有代价 ⇒ 判据/偏好**。
> 本文每条标准都标了类别。**红线不可让步；偏好可在"写下理由"后背离**（写理由即可，不需批准）。

### 0.4 本文判据的写法要求（**V2 的硬约束**）

每条标准必须同时给出三件事，缺一不许写进本文：

1. **红线**（禁止什么）；
2. **验收**（合规时长什么样）；
3. **🔍 违反时怎么发现**（`grep` 命令 / 可执行步骤 / 代码形态）—— **答不出 ⇒ 这条是口号，删或降级为建议**。

### 0.5 不变量下沉（**本文第一原则 —— 决定规则有没有用**）

> **规则写在文档里 = 没有强制力。** 写任何规则前先问：**它能下沉到哪一层？**

| 层 | 强制力 | 手段 | 成本 | 用途 |
| --- | --- | --- | --- | --- |
| **L0 文字** | **无** | ADR / 文件头 / 注释 | 极低 | **只解释"为什么"**，不作防线 |
| **L1 类型层** | **编译期报错** | 必填字段 · 判别联合 · `as const` + 穷尽分支 | 低 | **优先** |
| **L2 唯一入口收口** | 结构上绕不过 | 单一出口 + **内部分流**（`filesApi` / `contentSet` / `httpRequest`） | 中 | 同一能力只留一个出口 |
| **L3 闸** | CI | `check:keys` / `check:events` / `check:node-types`… | 高 | **默认不建** |

**判据：能下沉就下沉；停在 L0 的规则必然会漂移。**

- **实证（2026-09-19，同一份文件里 L0 与 L1/L2 打架）**：`filesApi.ts` 头写「失败一律返回 `null` 不抛」，
  实际已是 `UploadOutcome` 判别联合；头写 `persistUrlToUploads` 是★唯一原语，
  实际 `uploadFileToLocal` 被 **11** 处消费、它只有 **4** 处 ⇒ L0 那半边没人强制，于是背离。

**与 `架构师心法` 的对应**（本表即把心法映射成"新建时的落地顺序"）：

| 心法 | 对应本表 |
| --- | --- |
| Phase 2 筑基与定海（划定**不变式**与**唯一真相**） | **L2** 唯一入口收口 |
| 三.2 捍卫**类型**与边界的"绝对诚实" | **L1** 类型层 |
| 零.4.1 **闸不是红线本身** + 成本守恒律 | **L3**（闸 ≠ 红线；能用 L1/L2 守住的**不许建闸**） |

> ⚠️ 心法零.4.1 的反例：`check:catch` 因「贴一句 `// catch-ok:` 的**合法通过成本低于真正改造**」

## 1 · 交付金标准：四零一毁

### 1.1 数据 0 副本（状态绝对收敛）—— **结构偏好（强）**

- **红线**：同一个真相（SSOT）在物理内存只能有一份；UI 不许 `useState` 复制核心业务数据。
- **边界**：
  - **核心业务数据** = 会在别处被读/被落盘/被别人改的（如 items 列表、选中 id、落盘结果）⇒ **必须住 store**；
  - **纯 UI 状态** = 只在组件内用、不落盘、无他人关心（受控输入草稿、折叠展开、hover、局部筛选）⇒ **允许 `useState`**。
  - 判据问句：**「这个 state 删掉，别处会失忆吗？」** 会 ⇒ 是业务数据，不许放组件。
- **🔍 违反时怎么发现**：
  - `grep -n "useState" <组件>` 且该 state 初值来自 store/props ⇒ 副本嫌疑；
  - 出现 `useEffect(() => setLocal(x), [x])` 式**双向同步** ⇒ 铁证；
  - 手测：改 store 的值，UI 局部 state 不同步 ⇒ 已分裂。

### 1.2 异常 0 猜测（类型逼迫处理）—— **🔴 红线**

- **红线**：契约自带强迫性，不让调用方猜。禁止 `Data | null` / 隐式 `throw Error`；
  失败分支必须带**可展示文案**（否则消费者只能自己编话术 —— 那是"编造真相"）。
- **契约形状 / 字段口径（`code` + `message`）/ throw 边界 / 🔍 违反时怎么发现** ⇒ **真源 = `架构师共用判据.md` §2**（ADR-0002 / 0003 / 0021；本文不再复制）。
- **ACL 侧**：第三方 / 浏览器 API 的 throw 必须在**边界**转成判别联合（模板见 §3.2）。

### 1.3 UI 0 业务（无脑视图）—— **结构偏好**

- **红线**：UI 只做「状态投影仪 + 指令发射器」；业务条件由 core 算完，只吐视图指令。
- **本仓真实例子**（本仓**无角色系统**，勿套用"权限判断"类举例）：
  - ❌ **反例（真实发生过）**：首屏加载失败时，UI 写 `if (items.length === 0) return <空态/>`
    ⇒ **把"加载失败"渲染成"该目录暂无素材"**（失败被伪装成空）。
  - ✅ **正例**：`base/panels/ResourceLibrary.tsx` —— 数据层给出 **`state.phase`（`ok`/`failed`）**（`:104` 按 phase 投影文本）；
    且首屏失败 `loadError` 与翻页失败 `loadMoreError` **分开两个 state**（`:151-154`），
    注释写明原因：**「两者的重试动作不同（重试第 1 页 vs 续下一页），共用一个状态会把重试接到错的动作上」**。
- **🔍 违反时怎么发现**：
  - 组件里出现对**数据层字段的语义推断**（`length === 0` 当"没有"、`!x` 当"失败"）⇒ 越权；
  - 组件里出现跨实体判断（额度/权限/状态机/重试语义）⇒ 越权。

### 1.4 架构 1 键毁灭（可废弃性）—— **结构偏好，且只适用于业务模块**

- **红线**：新业务可随时安全切除：删掉业务目录 + 改路由/注册表 1~2 行，项目零错跑通。
- **⚠️ 适用范围**：这条**只约束"业务模块"**，**不适用于横切地基**
  （`logger` / `contentStore` / `idGen` / `contracts` / `httpClient`…）。地基本就该被依赖，
  拿"能不能删"量它们 ⇒ 得出错误结论（会去拆地基）。
- **🔍 违反时怎么发现（可执行）**：删目录 + 改注册 ⇒ 跑 `npx tsc --noEmit` 必须 **0 错**；
  再跑 `npm run check:arch` + `npm run check:dead-code`（确认没留孤儿引用）。

## 2 · 施工 4 步法

### Step 0 · 先写最优解 + 普查拦截（唯一开工前置）

> 🔒 **第一动作不是"查"，是"先写出最优解"**（真源：`架构师改码7步法` Step 0 + A14）。

**0.1 一屏以内写出「正确落地时长什么样」** → **判据 / 写法 / 表①模板见 `架构师共用判据.md` §1.1、§1.3**（本文不再复制）。

**0.2 新建三问**（存量改造不会有）：
1. **真的需要"新"吗**？（新建模块是最贵的选项，能加几行就别建）
2. **边界在哪**？（哪些**确定**属于它、哪些**确定**不属于；模糊 ⇒ 会长成万能模块）
3. **一键毁灭点在哪**？（需要它不与谁耦合）

**0.3 普查（三查）**：查原语（§5-B 速查表）→ 查相似链路 → **🔥 横向盘查**（同需求在别入口怎么满足的）。
→ **判据 / 表②模板 / 🔍 发现手段见 `架构师共用判据.md` §1.2、§1.3、§1.5**（本文不再复制）。

**0.4 放行判据（红线）** → **见 `架构师共用判据.md` §1.4**。
**产出**：表①最优解（一屏）· 表②入口对照表 —— **未出不进 Step 1**。

### Step 1 · 定真相与边界

1. **SSOT**：锁定核心数据的唯一物理位置。
2. **所有权**：生产者/消费者划分；**消费者严禁执行所有方的动作**，只能发指令。
3. **禁幽灵预留（YAGNI）** —— **本文定义段，其余处只引用本节**。
   - 只为当前真实需求写接口；禁为"以后可能"预留 `interface AbstractX` / 无效参数。
   - 判据：**指不出"现在谁在什么场景用它" ⇒ 删**（本仓实证 TD-05-16：`onApply` 的 `fragment` 参数三处上抛恒等于 `item.prompt`）。
   - 🔍 **怎么发现**：`grep -rn "<新符号>" src` ⇒ **除定义处外 0 命中** 即为幽灵预留；
     `grep -n "interface Abstract\|TODO\|以后" <新模块>` 抓"为未来预留"的痕迹。
4. **钉死模型**：强类型写死，消灭 `any` 与无意义 `Record<string, unknown>`。
   - **类型权威下沉到"最低变化速率层"**（纯逻辑层，无 React/存储依赖）；快照层/节点 props/UI **引用它**。
   - 判据：**具名类型没人 import ⇒ 权威虚设**（实证 TD-05-18）。
   - 🔍 **怎么发现**：`grep -rn "import .*<MyType>" src` 是否 **0 命中**；
     `grep -rn "Record<string, " src` 是否各处仍在手抄（手抄 = 权威没下沉）。
5. **🔥 建了原语 ≠ 完成 —— 必须同时规定「谁必须调它」**（本仓最痛教训 · TD-05-12 母体）
   **本节为定义段；Step 4 第 3 条 / 自检 / 审计 prompt 第 8 条只引用本节。**

   每个新增原语写两行：**① 谁必须调它（路径清单，必须穷尽）② 验收方式**。
   - **只列一条 = 假接线**（实证 TD-05-13：漏了 Agent 路径，单测照样绿）；
   - 验收 = **生产消费 > 0**（`grep` 除定义处外真有命中；**只有测试命中 = 幽灵预留**）；
   - 能用类型就别用力（`as const` + 穷尽 switch ⇒ 忘接线**编译期报错**）。

### Step 2 · 定契约与防腐层

1. **ACL 防腐层**：外部/旧接口/第三方数据**必须在边界洗脱**，转成 Step 1 的纯净类型后才准进 core。
   - 🔍 **怎么发现**：`grep -n "as unknown as" <新模块>` / `grep -n "as any" <新模块>`（绕过类型洗脱）；
     core / adapter 之外出现 `Record<string, unknown>` 形参 ⇒ 脏类型已进 core。
2. **失败契约（判别联合）**：见 §1.2（**`code` + `message`**）。
   - 🔍 **怎么发现**：`grep -nE "\): (Promise<)?[A-Za-z]+ \| null" <新模块>`（`T | null`）· 逐个看 `ok:false` 分支是否带 `message`。
3. **切断默认值兜底**：查不到 ⇒ 抛错或 `NotFound`；**严禁私自塞 `""` / `{}` 让逻辑跑通**。
   - 🔍 **怎么发现**：`grep -nE "\?\? *([\"']{2}|\{\}|0)" <新模块>`（静默补默认值）· `grep -n "?? \[\]" <新模块>`。
4. **异常也要洗脱**：第三方/浏览器 API 的 **throw 在 ACL 转成判别联合**
   （`try { … } catch (e) { return { ok:false, code:'InvalidPayload', message: String(e) } }`），不许把裸 throw 放给 core。
   - 🔍 **怎么发现**：`grep -n "throw " <新模块>` ⇒ 逐个确认是「不该发生」的编程错误（ADR-0005 那种根部抛），
     凡是"预期会失败"的分支都必须改成判别联合返回。

### Step 3 · 核心组装与 UI 投影

1. **纯化运算**：「怎么算」抽成无外部依赖的纯函数（可单测）。
   - 🔍 **怎么发现**：`core.ts` 里出现 `use*`（hook）、`from 'react'`、直接读 store ⇒ 已被污染。
2. **中心调度黑盒（Store / Core）**：收敛数据与规则，对外**窄接口**；外部"无脑传参"，不在外部拼业务逻辑再调。
   - **store 选型见 §4.3**（两种模式，**按域一致**）；真源 + 快照引用稳定（`projectStore.ts:286`）。
   - 🔍 **怎么发现**：`grep -n "^export" store.ts` 看导出面是否过宽（理想只剩「指令 + 1 个视图 hook」）；
     `grep -rn "<新模块>" src` 看调用方有没有"先拼一段业务逻辑再调"（拼装逻辑应在 core）。
3. **UI 极致降级**：UI 只做投影 + 派发（见 §1.3）；横切出口见 §4.6 表。
4. **生命周期 / 并发 / 取消**（V1 完全没有，V2 补齐 —— 新业务最容易忽视的一类）：
   - **订阅必须可退订**：`useSyncExternalStore` / `contentSubscribe` 的退订函数要在 effect cleanup 里释放；
   - **落盘要节流**：高频写入用 `createDebouncedPersist`（`contentStore.ts:990`），
     不要每次 mutation 都直接 `contentSet`；
   - **异步必须可取消 + 有超时**：`AbortController`（本仓 9 处在用）+ `withTimeout`（`asyncGuard.ts:92`）；
   - **并发**：本仓**没有通用并发锁原语**（`withLock` 仅 `projectMemoryStore.ts:66` 内部私有）
     ⇒ 需要串行化时要么复用该模式、要么明确论证"不会有并发"，**不许口头假设**。
   - 🔍 **怎么发现**：`grep -n "useEffect" <新模块>` ⇒ 每个订阅是否都有 cleanup；
     `grep -n "await " <新模块>` ⇒ 每个长任务是否都有超时或取消路径。

### Step 4 · 机器验收与落闸

1. **测试闭环**：核心纯函数 + Core 边界必须覆盖；**只测黑盒输入/输出**；**失败分支必须断言**。
   **🔒 禁自证式断言**（真源：`架构师共用判据.md` §5）：判据 —— **把被测实现改坏，断言仍绿 ⇒ 它是装饰，删**。
   验收入口 = **探针先红后绿**（真源：`架构师共用判据.md` §6）。
   - 🔍 **怎么发现**：对每条断言跑一次探针（改坏实现 ⇒ 必须红，见共用 §6 命令与**退出码**坑）。
2. **落闸**：**默认不建**；先过「建闸前置评审」（真源：`架构师共用判据.md` §7 · 心法 §零.4）。能用**结构 / 类型 / 唯一入口 / 对账测试**守住的，**不许用闸**。
   - 🔍 **怎么发现**：该闸脚本头部是否有【申诉口】三问（可 `grep "★闸的申诉口" scripts/`）；是否登记在
     `gates.manifest.json`；**没登记 = 从没跑过**（本仓实证：曾有两道闸不在 manifest 里、躺着真实违规）。

### 4.1 目录（物理隔离 + 一键删除）

```

├─ adapter.ts    # Step2 ACL（数据 + 异常 双重洗脱）
```

**import 约定**：外部只 `import { x } from '@/components/<域>/index.ts'`（禁直指内部文件）；

**命名强制项 —— 域专用物必须带域前缀**（用户裁定 2026-09-19，**强制，非可选**）：

> 凡是**只服务某一个域**的导出（原语 / 适配壳 / 常量 / 组件），**名字里必须带该域名**。
> 目的：避免与通用原语**撞名** ⇒ 调用方 `import { x }` 出现两个来源，误引且难查。
> - ❌ 反例（本仓实证）：`videoEditor/lib/logger.ts` 导出的也叫 `logger`，与统一 `base/core/logger` 撞名 ⇒ **TD-18-42**。
> - ✅ 正例：`videoEditorLogger`（域适配壳）、`scriptBoxEngine` / `scriptBoxPlaybookStore`（域前缀 + 域内聚）—— 名字自带域名。
> - ⚠️ **反例**：`canvasHost` 名里**没有**域前缀（它只在 Agent 域用，却叫通用名）⇒ 应改名或至少在文档里写明作用域（见 §5-B 与 TD-18-34）。
> 🔍 **怎么发现**：`grep -rn "export \(const\|function\|class\) <通用名>" src` 若**命中 ≥2 处**且分属不同域 ⇒ 违规（需加前缀或证明是同一实现）。
> 相关：完整前缀与目录规范见 **TD-18-41**。

### 4.4 adapter.ts（数据 + 异常 双重洗脱）

```ts
export function mapExternalToMyItem(raw: unknown): BizResult<MyItem> {
  if (typeof raw !== 'object' || raw === null) return { ok:false, code:'InvalidPayload', message:'外部数据格式非法' };
  const r = raw as Record<string, unknown>;
  // ⚠️ 必填字段缺失 = 失败；**不许 `?? ""` / `?? 0` 静默补**（那正是本文禁的默认值兜底）
  if (typeof r.id !== 'string' || typeof r.title !== 'string' || typeof r.count !== 'number')
    return { ok:false, code:'InvalidPayload', message:'字段类型不符' };
  return { ok:true, data:{ id:r.id, title:r.title, count:r.count } };
}
```

### 4.5 io.ts（不裸 fetch / 不裸 throw / 不吞错）

```ts
export async function fetchMyList(): Promise<BizResult<MyItem[]>> {
  try {
    const body = await httpRequest('/api/my-list', { label: 'fetchMyList' });   // 禁裸 fetch
    // ⚠️ 先校验**形状**再逐个过 ACL：**不要把整个数组塞给单元素 mapper**
    // （数组 `'id' in []` 为 false ⇒ 那样写会永远返回 ok:false —— 本模板前一版就犯过这个错）
    if (!Array.isArray(body)) return { ok:false, code:'InvalidPayload', message:'响应不是数组' };
    const items: MyItem[] = [];
    for (const raw of body) {
      const r = mapExternalToMyItem(raw);
      if (!r.ok) return r;                    // 生产者给全 ⇒ 只转发，不重编话术
      items.push(r.data);
    }
    return { ok:true, data: items };
  } catch (e) {
    const message = e instanceof HttpError ? e.message : String(e);
    logger.warn('myBusiness', 'fetchMyList 失败', { message });                  // 给开发者
    reportDegrade({ layer:'myBusiness', key:'fetchMyList', e: e as Error,
                    toast:'列表加载失败，请重试' });                               // 给用户（两个读者分开）
    return { ok:false, code:'Timeout', message };
  }
}

/** 落盘 —— 本仓新业务**最常见的收尾动作**：写 + 自确认，绝不吞失败 */
export function saveMyItems(items: MyItem[]): boolean {
  const outcome = contentSet(MY_KEY, items);          // 返 PersistWriteOutcome（判别联合）
  return confirmPersist(outcome, {                    // 仅在 landed ∈ {local,kv} 时 true
    layer:'myBusiness', key: MY_KEY,
    toast:'保存失败（本地存储不可用）',
  });
}
```
> ⚠️ `MY_KEY` **必须先在 `base/core/contracts.ts` 的 `STORAGE_KEYS` 登记**（否则 `check:keys` 闸红；
> `contentSet` 内部 `checkRegistered` 也会拦）。返回 `boolean` 是给调用方的**真话**：落盘失败就是 `false`，
> 不许无条件 `return true`（那会让 UI 宣布"已保存"）。
