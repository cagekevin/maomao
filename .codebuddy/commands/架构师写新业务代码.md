# 架构师新建 4 步法（从零构建 SOP · 终极优生版）

> **定位**：本文件是**从零开发新业务、新链路、新模块**时的强制操作步骤。
> **核心心法**：改码是“治病排雷”，新建是“优生防御”。新建时没有历史病灶可查，必须靠**前置模型设计**与**机器门禁**杜绝将新代码写成明天的技术债。
> **全局铁律**：**先定真相，再设防腐，死磕失败，最后画 UI。** 敢从 UI 组件往下写，一律打回重做。
> 
> 

## 🎯 第一部分：架构交付金标准（“四零一毁”）

写完的新代码如果不符合以下四条标准，说明这 4 步法你只走了形式，必须打回重构：

1. **数据 0 副本（状态绝对收敛）**
* **红线**：同一个真相（SSOT）在物理内存中只能有一份。
* **验收**：禁止在 UI 组件里用 `useState` / `props` 互相传抄、同步核心业务数据。UI 只能拥有“衍生计算”或“纯粹映射”。


2. **异常 0 猜测（类型逼迫处理）**
* **红线**：契约必须自带强迫性，绝不让调用方“猜”错误。
* **验收**：禁止返回 `Data | null` 或隐式 `throw Error`。必须使用**判别联合类型**（如 `{ ok: false, reason: 'TIMEOUT' }`），让编译器逼迫调用方写出异常分支，不处理就编译报错。


3. **UI 0 业务（极度降级的无脑视图）**
* **红线**：UI 组件必须像一个纯粹的“木偶”，剥离所有商业逻辑。
* **验收**：UI 组件内严禁出现 `if (user.role === 'admin' && flag.isOpen)`。Core 层算好后，只向 UI 抛出 `isDisabled`, `warningText` 等纯视图指令。


4. **架构 1 键毁灭（绝对物理隔离）**
* **红线**：新业务必须随时能被安全切除（可废弃性）。
* **验收**：如果业务下线，只需删掉该业务文件夹并在路由/注册表删掉 1~2 行引入即可，项目必须零错误直接跑通。拔出萝卜带出泥 = 架构失败。

## 🛠️ 第二部分：施工 4 步法

### 🚦 Step 0 · 普查拦截（唯一的开工前置）

**不要因为是“新需求”，就觉得一切都要“新建”。**

1. **查原语**：新功能底层是否已有纯函数计算或探测原语可复用？
2. **查相似**：是否有 80% 相似的既有链路？（判别是该下沉公共层，还是维持物理隔离防假接缝）。
3. **放行判据**：只有当 `refs` 查不到可用真源、且强行复用会导致判据错乱时，才允许往下走。

### Step 1 · 定真相与边界 —— 确立 SSOT 与反过度设计

1. **确立真源 (SSOT)**：锁定核心数据的唯一物理位置（URL、LocalStore 或指定 Store）。
2. **定所有权 (Ownership)**：划分生产者与消费者。**消费者严禁执行所有方的动作**，只能发指令，绝对不能直接修改数据源。
3. **禁幽灵预留 (YAGNI 原则)**：
* **只为当前真实发生的需求写接口。**
* 严禁为了“以后可能加字段/多态”而提前写 `interface AbstractX` 或预留无效参数。预留的零消费代码 = 未来的死代码。


4. **钉死核心模型**：对象结构、必填/可选项全部用强类型（如 `types.ts`）写死，全面消灭 `any` 和无意义的 `Record<string, unknown>`。

### Step 2 · 定契约与防腐层 —— 拒绝脏数据与掩盖错误

1. **建立防腐层 (ACL - Anti-Corruption Layer)**：
* 当新模块需读取旧接口、旧缓存或第三方数据时，**必须在边界进行“洗脱”**。
* 严禁把“脏类型”直接引入新 Core 层，必须写 `Mapper/Adapter` 转换为 Step 1 定义的纯净强类型后再放行。


2. **设计失败契约 (Discriminated Unions)**：
* 抛弃 `boolean`/`null`。凡涉及 IO、校验、复杂处理，强制返回判别联合类型：`{ ok: true, data: T } | { ok: false, error: ErrorCode, msg: string }`。


3. **切断默认值兜底**：
* 查不到数据必须抛错或返回严格的 `NotFound` 态。
* **严禁私自塞默认值（如 `""` 或 `{}`）让逻辑强行跑通。**



### Step 3 · 核心组装与 UI 投影 —— 逻辑纯化与 UI 降级

1. **纯化运算逻辑**：“怎么算”（转换、过滤、解析）必须抽成无外部依赖的 `utils` 纯函数。
2. **搭建中心调度黑盒 (Store / Core)**：
* 将洗脱后的数据和业务规则收敛在唯一的调度层，对外提供**窄接口**。
* **防泄漏检查**：外部调用时只需“无脑传参”，不需要在外部拼装一段业务逻辑再去调用。


3. **UI 极致降级**：
* UI 层只做“状态投影仪”和“指令发射器”。所有的条件分支必须在 Core 层算完，UI 层只接收具体的视图映射。



### Step 4 · 机器验收与落闸 —— 限制未来的破窗

1. **测试闭环（先证明，再交付）**：
* Step 3 抽离的**核心纯函数**和**Core 黑盒边界**必须覆盖单元测试。
* **纪律**：只测业务黑盒输入/输出，不测 UI 渲染细节；确保所有的失败契约（error 分支）都被明确断言。


2. **强制落闸（Machine Guards）**：
* 核心层禁止引用 UI 层？写进 `eslint` 规则或 `check:arch` 白名单中。
* 严禁绕过唯一入口？在 AST 检查工具里加上对底层 API 裸调用的拦截。


3. **全局登记**：
* 链路有全局影响 → 更新到 `spec/DATAFLOW.md`。
* 新增持久化存储键、全局事件名 → 去对应的中心登记表报到。

## 2. types.ts｜模型定义（Step1 定真相边界）

> 
> 规则：不为未来预留字段；不写抽象空基类；必填 / 可选显式；拒绝 `Record<string,unknown>`；定义**失败判别联合契约**。

```
// src/features/my‑business/types.ts

// 业务实体：只写当前真实需求字段，禁止幽灵预留
export interface MyItem {
  readonly id: string;
  readonly title: string;
  readonly count: number;
}

// 错误码枚举，不要裸字符串
export enum MyBizErrorCode {
  NotFound = "NotFound",
  Timeout = "Timeout",
  InvalidPayload = "InvalidPayload",
}

// ✅ 标准判别联合契约（强制调用方处理成功/失败，编译器帮忙把关）
export type BizResult<T> =
  | { ok: true; data: T }
  | { ok: false; error: MyBizErrorCode; msg: string };

// 视图指令类型：core算完直接吐给UI，UI不再做业务判断
export type MyViewState = {
  readonly items: MyItem[];
  readonly isDisabled: boolean;
  readonly warningText: string | null;
  readonly loading: boolean;
};
```

❌ 禁止写法：

- `interface AbstractMyItem { ... }` 预留给以后扩展（YAGNI）
- `Record<string, unknown>` 当做业务对象
- 返回 `MyItem | null` 代替 `BizResult<MyItem>`

## 3. adapter.ts｜ACL 防腐层（Step2 拒绝脏数据入侵 Core）

> 
> 外部接口、localStorage、第三方返回脏类型，**绝不直接流入 core**，必须经过 mapper 转换为本模块 types；遇到脏数据返回 BizResult 失败，**禁止私自填充 {} / "" 兜底**。

```
// src/features/my‑business/adapter.ts
import type { BizResult, MyItem } from "./types";
import { MyBizErrorCode } from "./types";

// 把外部API的脏DTO 👉 内部纯净模型
export function mapExternalToMyItem(raw: unknown): BizResult<MyItem> {
  // 运行时校验（zod / valibot /守卫函数，不依靠as断言）
  if (
    typeof raw !== "object" || raw === null ||
    !("id" in raw) || typeof (raw as Record<string,unknown>).id !== "string"
  ) {
    return {
      ok: false,
      error: MyBizErrorCode.InvalidPayload,
      msg: "外部数据格式非法",
    };
  }

  const r = raw as Record<string,unknown>;
  return {
    ok: true,
    data: {
      id: r.id as string,
      title: (r.title ?? ""),
      count: typeof r.count === "number" ? r.count : 0,
    },
  };
}
```

> 
> 重点：解析失败返回 `ok:false`，**不要偷偷返回一个构造出来的假 MyItem 让流程跑通**。

## 4. IO 工具示例｜判别联合，不裸 throw，不吞错误

> 
> 所有 IO、解析、网络操作，返回 `BizResult<T>`；**不在业务层裸 throw；不在业务层返回 T|null；禁止空 catch**。

```
// 示例：请求数据，不裸抛异常，不吞错误
import type { BizResult, MyItem } from "./types";
import { MyBizErrorCode } from "./types";

export async function fetchMyList(): Promise<BizResult<MyItem[]>> {
  try {
    const res = await fetch("/api/my‑list");
    // fetch必须校验ok，符合之前禁止项
    if (!res.ok) {
      return {
        ok: false,
        error: MyBizErrorCode.Timeout,
        msg: `http status:${res.status}`,
      };
    }
    const rawData = await res.json();
    // 走ACL防腐转换
    const mapped = mapExternalToMyItem(rawData);
    if (!mapped.ok) {
      return mapped;
    }
    return { ok: true, data: [mapped.data] };
  } catch (err) {
    // catch必须留日志，禁止空catch
    console.error("fetchMyList failed", err);
    return {
      ok: false,
      error: MyBizErrorCode.Timeout,
      msg: (err as Error).message,
    };
  }
}
```

## 5. core.ts + store.ts｜核心层（SSOT 真源，数据 0 副本）

> 
> 规则：
> 
> 
> 1. store 是唯一真源；UI 组件**不许 useState 拷贝核心业务数据副本**，只能派生。
> 2. 消费者不能直接 mutate 状态；只能调用 store 对外暴露窄指令函数。
> 3. 业务 if 判断全部收敛 core；输出**视图指令 MyViewState**，UI 直接消费。

```
// core.ts 纯运算逻辑，无副作用，纯函数
import type { MyItem, MyViewState } from "./types";

// ✅纯函数：业务规则全部在这里，方便单元测试
export function computeViewState(items: MyItem[], loading: boolean): MyViewState {
  // 所有业务条件全部收敛于此，UI不需要再写 if(user.role && flag)
  const isDisabled = items.length === 0;
  const warningText = items.length > 10 ? "条目过多，请检查" : null;

  return {
    items,
    isDisabled,
    warningText,
    loading,
  };
}
```

```
// store.ts 唯一状态真源
import { makeStore } from "@/lib/store";
import type { MyItem, BizResult } from "./types";
import { fetchMyList } from "./core";
import { computeViewState } from "./core";

type State = {
  items: MyItem[];
  loading: boolean;
};

const initial: State = { items: [], loading: false };

export const useMyBizStore = makeStore<State>(initial)((set, get) => ({
  // 对外窄指令：消费者只能调用函数，不能直接修改内部state
  async load(): Promise<BizResult<MyItem[]>> {
    set({ loading: true });
    const result = await fetchMyList();
    if (result.ok) {
      set({ items: result.data, loading: false });
    } else {
      set({ loading: false });
    }
    return result;
  },
  // 对外直接吐出已经算好的视图指令，UI直接拿
  getView(): MyViewState {
    const { items, loading } = get();
    return computeViewState(items, loading);
  },
}));
```

```
// index.ts 只暴露窄公共API，隐藏内部实现
export { useMyBizStore } from "./store";
export type { MyItem, BizResult, MyViewState } from "./types";
export { MyBizErrorCode } from "./types";
```

## 6. React UI 组件｜UI0 业务，纯粹木偶投影

> 
> 铁律：**组件内部禁止写业务判断逻辑**，全部由 core 输出`MyViewState`；组件只做渲染 + 派发事件指令；禁止在组件 useState 复制核心业务数据副本。

```
// components/MyBusinessView.tsx
import { useMyBizStore } from "../index";

export function MyBusinessView() {
  const store = useMyBizStore();
  // ✅ 直接拿core已经算好的视图指令，组件不再做业务if
  const view = store.getView();

  return (
    <div>
      {view.loading && <div>加载中…</div>}

      {/* 只消费view字段，没有 if(xxx.role && flag) */}
      {view.warningText && <div className="warning">{view.warningText}</div>}

      <button
        disabled={view.isDisabled}
        onClick={() => {
          // 只派发指令，不写业务逻辑
          void store.load();
        }}
      >
        刷新列表
      </button>

      {view.items.map((item) => (
        <div key={item.id}>{item.title}:{item.count}</div>
      ))}
    </div>
  );
}
```

❌ UI 禁止写法：

```
// ❌ 不要在组件复制一份业务数据副本（制造数据副本，违反0副本）
const [localItems, setLocalItems] = useState(view.items);

// ❌ UI层写业务规则判断，业务逻辑泄漏到视图
{ items.length>10 && user.role==="admin" ? <Warning/> : null }
```

## 7. 单元测试示例（Step4 机器验收）

> 
> 只测 core 纯函数、adapter、IO 返回契约；**必须覆盖 ok:false 失败分支**；不测 UI 渲染细节。

import { computeViewState } from "./core";

describe("computeViewState", () => {
