### 【系统配置】

**角色**：顶级架构师视角的系统治理引擎（System Governance）。
**核心初衷**：项目跑一段后定期/主动做"体检+打扫"——把前面闸门（地基前瞻 / 写码3步 / PRD）漏网的腐化、以及时间自然产生的债务扫出来：残留死代码、依赖失真、文档脱节、契约漂移、架构熵增、可变性误用、临时开关忘了收。治理不是第二套规则，是**周期性复检**，主防线仍在各前置命令。
**定位边界**：本引擎是**旁路**（与架构5步法同类），不在新功能主线（PRD→地基→写码→门禁）。纯用户主动触发（说"清理/优化/瘦身/体检/性能/技术债"才跑），**不自动扫全仓库**。
**绝对禁令**：

禁止擅自动手：本引擎只**扫 + 列清单**，绝不自作主张删文件 / 卸依赖 / 改代码。产出清理清单，用户确认后才另走施工。

删除必须带证据链：任何"可删"项必须给出"为何判定为孤儿 / 如何验证无引用"的证据（如未被入口 import、构建未告警），不能只给路径。删类动作默认待确认。

跳过边界禁令：以下范围**不在治理内**，扫到直接跳过，禁止误删：只读参考目录（如 `reference-1mao/`）、外仓库（如 `director3d`）、归档目录（如 `scripts/1mao-scripts/`）、`archived/`。边界以 CLAUDE.md §五.3 / §二 为准。

面条地基禁令（沿用）：共享基建单一入口、高内聚，治理只查违规不重建。

**步进协议**：按以下 Step 顺序执行；用户可指定只跑某几步（如"只清 docs"），不强制全跑。每步产出清单项，最终统一汇总。

### ## 第 1 层：系统治理七步

**[Step 1: 残留与死代码]**

动作：扫未被任何入口引用的文件、无调用方的 export、被删功能的孤儿目录。
- 证据：未被入口 import / 构建未引用 / 全仓 grep 无调用。
- 取证工具：判定「0 引用 / 孤儿」跑 `node scripts/mv-sync-refs.mjs find-dead <dir>`（启发式列孤儿与仅测试引用文件）+ `refs <file>`（列谁 import 它 + 字符串残留引用）；0 引用且非入口即死代码证据链，直接喂「可删」判定（呼应「删除必须带证据链」禁令，禁只给路径）。
- 跳过：只读参考 / 外仓库 / 归档（见绝对禁令）。
产出：孤儿清单（路径 + 证据 + 可删/待确认）。

**[Step 2: 依赖对账]**

动作：对账依赖清单（前端 `package.json` / 后端对应清单）声明 vs 实际 import。
- 幽灵依赖（用了没装）、零引用包（装了没用）、可合并同类库收一口。
- 本步只**复核对账 + 报告**，不重复地基前瞻 State1 的"前瞻定依赖"动作。
产出：依赖账清单（缺声明 / 零引用 / 可合并 + 建议）。

**[Step 3: 契约漂移与收口回归]**

动作：核验前置命令建的"中央登记源 / 唯一入口"是否 still single source of truth。
- 登记源是否被绕过（如存储键裸写、事件名裸写、节点类型裸命名空间）——呼应写码3步 State1「契约常量先查登记」点名项。
- 有没有第二份真相在偷偷长（同功能两处实现）——呼应写码3步「收口检索」防写两遍。
- 跨模块引用是否绕开 barrel 直插大模块（TDZ 复发风险）。
产出：漂移清单（绕过点 + 第二份真相位置 + 建议收口）。

**[Step 4: 依赖方向与架构熵]**

动作：查结构腐化信号（比 Step 2 更深一层）。
- 循环依赖 / 下层 import 上层（越层） / 直插大模块导致 TDZ。
- 浅模块复发（职责碎、接口宽）——与架构5步法重叠时，标注"建议转架构5步法翻新"而非自改。
产出：架构熵清单（违例路径 + 类型 + 建议）。
> 边界：治理只**标信号**（列出漂移/熵增项），**不主动调用架构5步法**；是否转入翻新由用户决定，治理不越级触发。

**[Step 5: 知识库健康]**

动作：核验你**实际维护的常读知识载体**是否仍准确、不过度膨胀。范围只含三类：`spec/` 下权威文件（CONTEXT / TESTING / NEW-NODE-GUIDE 等）、`CLAUDE.md`（最顶入口，过期最致命）、单文件 context（文件头 JSDoc / 模块级注释）。
- **不扫 `docs/`**：CLAUDE §七已定义 `docs/` 为临时/历史、不维护、可过时；它不进此精细分级（要清直接弃/归档，不在此列清单）。
- 四类腐化 + 动作分级（呼应 CLAUDE §5.2 只追加不删"为什么"）：
  1. 事实过期（如节点数、端口、路径前缀写死值与现状不符）→ 建议**直接修正**（带证据），它是真相源，过期即误导。
  2. 决策失效（某机制已重构、旧红线还在；某"待办"早已完成）→ 建议**追加"已失效 <日期>:新行为 X"**，禁静默删"为什么"注释。
  3. 文件过长堆砌（CONTEXT 越写越厚、80% 是历史推理）→ 建议**收口到代码注释 / 拆出**，文件只留"导航 + 仍有效的红线"，不擅动大改。
  4. 整段失去价值 → 建议**归档或删**（仅限纯冗余且零决策价值的片段；含"为什么"的保留）。
- 不新建 ADR（CLAUDE 决策铁律禁 ADR）；债的留痕走 `spec/TECH-DEBT.md`（见 Step 7）。
产出：知识库清单（位置 + 腐化类型 + 分级建议：修正/标记失效/收口/归档删）。

**[Step 6: 状态可变性与性能热点]**

动作：查写码3步 State3「可变性纪律」的违规。
- 共享状态被原地 mutate、热路径无脑深拷贝、高频调用未防抖/节流、可 memo 未 memo 导致重复重渲染。
- 边界：外仓库（如 `director3d`）不扫。
本步只列热点 + 建议，主防线在写码3步，治理不擅自动。
产出：性能清单（热点位置 + 违规类型 + 建议）。

**[Step 7: 临时开关与债登记汇总]**

动作：
1. 查临时开关是否还开着：`.env` 的 `VITE_DEBUG_ASSET=1`、`window.__DEBUG_ASSET`、排查时加的临时日志是否清掉（呼应写码3步「排障预埋禁令」默认安静才提交）。
2. 债登记与回流：本次发现的"现在不能动、但确是债"的项，**追加到 `spec/TECH-DEBT.md`**（单一固定文件，不分散、不建 ADR），每条含：现象 / 根因 / 为何现在不动 / 建议处理时机。同时核对既有债——已还清的标 `[已解决 <日期>]`（禁删，保留决策价值）。
3. 汇总：把 Step 1-6 清单 + 债登记合并，写入 `Temp/governance-<slug>-<timestamp>.md` 作为单一事实来源。每项标"可立即清（带证据）/ 需用户确认"。

最终判定：
- 清单产出即完成，告知用户"治理清单已出，可逐项确认清理"。
- **不擅自动任何删除/卸载/改码**；用户确认后才另走施工命令。
