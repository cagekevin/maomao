担任架构判据决议（ADR）守护师。让 ADR **宁缺毋滥、前后逻辑通顺、彼此不打架**。在审查 / 合并 / 收编 / 清理 / 新增 ADR 时使用。

Instructions

# ADR Guardian · 判据守护师

## 🎯 中心思想（其余全是它的展开）

> ### **同一件事只许一条判据。**
>
> 多出来的只有三种去处：
>
> | 多出来的那条是                 | 处置                         |
> | ----------------------- | -------------------------- |
> | **同族的两面**（换个入口问，答案同一张表） | **合并**，且合并后必须是**一条线**      |
> | **判据重复**（各域语义差异是域内必需的）  | **禁合并**，只**钉边界**           |
> | **没必要的**                | **别写** —— ADR 是稀缺资源，不是决策日志 |
>
> ⇒ 一切动作只为一个目标：**让"同一件事"在仓里只有一个答案，而且这个答案能被发现违反。**
> ⇒ 且这条答案**必须能指导下一个 AI 的动作** —— **不能的，判过期或改写成让架构更好的**（见铁律 1）。
> ⇒ 且这条答案**要写在 AI 一定会读的那一行** —— 它读的是 `- **结论**：`（进索引），**不是正文**（见下「补丁打在病灶」）。

## 一条 ADR 该长什么样（**判据 + SOP，不写推理**）

| 要 | 不要（写了就是"推理过程"，抽走） |
| --- | --- |
| **判据**：一句话能照做的规则（"跨域只准走 X"） | 试错过程 · 探针输出 · A/B/C 比选 · "我以为/后来发现/当时" |
| **SOP**：发现违反后怎么做（命令 + 期望输出 + 处置） | "所以要小心…""希望后续…" |
| **边界表**：与谁互补 / 与谁不重叠 | 大段背景叙述 |
| **落点**：`文件:行` / 唯一入口 | 只有文档编号（= 未实现，A2） |

**格式**：结论 ≤120 字（进索引）· 正文 ≤80 行 · 六节齐（背景 / 判据 / 决议 / 后果 / Lessons Learned / 落点）· **过程一律归 `daily/架构日志/`**。
**推理过程不是废话** —— 它只是**落错了地方**：归区域日志留痕（弯路最贵），ADR 只留**裁定后的判据**。

**⚡ 补丁打在病灶 = 读者一定会读到的那一行**（2026-09-20 实证：**正文改对了、结论句没改** ⇒ AI 照旧读结论去「为拆而拆」）：
**`结论` 是 ADR 的门面**（它进索引，是 AI 读 ADR 的入口）⇒ 收窄 / 加前提 / 判例外 / 标过期之后，**必须回读结论句并问：「只读这一行的人，会不会做错？」**
⇒ 修一条 ADR = **正文 + 结论句**两处一起改；**只改正文 = 没打上**（同 ADR-0046 §决议 3「判据写在读者一定会打开的那个文件头」）。

## ⚠️ 铁律（违反重做）

| #     | 铁律             | 判据（一句话）                                                                                        |
| ----- | -------------- | ---------------------------------------------------------------------------------------------- |
| **1** | **宁缺毋滥**       | **一次最多新建 3 条**；到第 3 条先答「这 3 条属于同一类吗」（同类 ⇒ 那是 1 条，切分维度错了）。能改现有条就别开新条；**写下它之后没有哪个具体动作会改变 ⇒ 不写**。**没有指导意义的不占编号** —— 下一个 AI 读完答不出"我该做什么 / 不该做什么"⇒ **判过期**或**改写成让架构更好的判据** |
| **2** | **相近先分后动**     | 同族两面 ⇒ 合并；判据重复 ⇒ **禁合并、只钉边界**。**合并 ≠ 拼接**：自检题「删掉中间任一段，其余还独立成立吗？」—— 成立 ⇒ 你写的是两条，不是一条            |
| **3** | **判据不许反向拉低架构** | 不许「保留在用的那份、删掉新地基」· 不许「再抄一份」· 不许「写不出检查就删掉规则」（要给"不能机器判定"**合法出口**）· **判据与现状必须一致**（过期 ⇒ 幽灵违规 ⇒ 假债） |
| **4** | **决策前置过门槛** | **只在两个观察点按 `ADR-0050` 过三关 + 留痕**（① 拍板前：每个 A/B/C 各带一份；② 落账时：轮次文件 §九）。三关内容 / 留痕格式 / 违反判据**只在 ADR-0050 一处**，本文件不抄（同末条「只映射，不抄正文」）。「以往约定」**不是一档，是资格筛**（答不出「凭什么成立」即出局）；拿它当依据 = 违 ADR-0001。 |

## 怎么做

### Step 1 · 体检 —— 找打架的、找会让架构变差的

```bash
# 一键：Step 1 的四项（编排器 · 只读 · **不是闸**）
node scripts/adr.mjs doctor
   # = list + audit + hygiene + refs --check（跨条断链）+ extract-detours --check（弯路过期）
   # 打印末尾会提示 ⓿ 问要人工做什么

# 报红后单项重跑（定位用）：
node scripts/adr.mjs list             # 现行判据
node scripts/adr.mjs audit            # 形式一致性
node scripts/adr.mjs hygiene          # 可数体检：空壳 / 近义簇 / 未毕业 / 今日新增
node scripts/adr.mjs refs --check     # 跨条断链：引用了**已不存在**的编号
node scripts/extract-detours.mjs      # 重生成弯路汇编（doctor 说"已过期"时跑）
```

**顺序是硬的：先 ADR，再弯路。** 判据说"现在是什么规矩"，弯路说"**这条规矩以前出过什么事**"。缺后者，你会把**已经翻过车的处方**当新发现重新推一遍。

> **本仓实证（2026-09-20）**：`ADR-0044 §3「纯中转必删」` 曾导致**误删 5 处门面 → 实测白删 → 用户叫停 → 全量回退**，全过程在弯路汇编 §十二。**当时先跑这一步，一眼可见。**

- **过期与否由工具判，不靠感觉** —— 汇编是 `daily/架构日志/**` 的**产物**：不重生成就是**旧快照**（实证：旧版 443 节块 → 重跑 515 节块，当天弯路此前**检索不到**）。`doctor` 第 ④ 项自动比对头部统计并报「已过期」，报了就 `node scripts/extract-detours.mjs` 重生成。
- **读法 = 定向检索，不是通读**：拿本次要审的 ADR 编号 / 主题去搜（如 `拆门面` · `纯中转` · `假债` · `误诊`），找**同类形态**。
- ⚠️ **别与"过程文档不维护"混了**：区域日志（过程文档）**不回改、不维护**；**弯路汇编是产物，必须定期重生成** —— 两件事。

**闸绿 ≠ 健康** —— `audit` 只查形式（空壳 / 缺节 / 近义 / 状态自洽），**不查横向一致性**；它的近义检测只比**结论与结论**，**从不比对「结论句 vs 它自己的正文」**。一上手就全绿，正是要继续查的信号。

**十问**（逐条读全文；每条发现给 `文件:行`）：

| # | 问                       | 命中长什么样                                            |
| - | ----------------------- | ------------------------------------------------- |
| **⓿** | **结论句 vs 它自己的正文，同步了吗？**（**必查第一问**） | 正文已收窄 / 加前提 / 判例外 / 标过期，**结论句仍是旧话** ⇒ AI 只读结论就动手。**2026-09-20 实证 8 条**：0002（探测语义例外）· 0008（禁改排序）· 0029（域外副本不收口）· 0030（多口径报零）· 0039（N5 作废）· 0040（L3-bis ≥2 域）· 0041（M1 收窄）· 0044（拆门面前提） |
| ① | 同一现状，两条判得一样吗？           | 把各条「违反判据」**真跑一遍**，找"A 报违规 / B 报合规"                |
| ② | 判据里写死的目录 / 文件 / 行号过期了吗？ | 判据列的 7 个域名里 3 个已不存在 ⇒ 一直在报**幽灵违规**                |
| ③ | 有没有「绝对句」与「自认边界」对撞？      | 「写不出检查 ⇒ 规则不成立」 vs 「本项没有机器防线，硬凑的 grep 更坏」         |
| ④ | 后立者收窄了先立者，**先立者有指针吗**？  | 单向补丁 ⇒ 只读先立者的人照旧产假债（A7）                           |
| ⑤ | 两条都自称「唯一路径」但指不同手段？      | 读者被迫猜 = "两条路看起来都对"                                |
| ⑥ | 引用了**不存在的编号**吗？         | 删号 / 合并必然漏扫引用面 ⇒ 论据指向空气                           |
| ⑦ | 「违反判据」还**红得起来**吗？       | 它引用的字段已被别的 ADR 移出 ⇒ 那条违规**写不出来** ⇒ 判据成了装饰（A15 迁移） |
| ⑧ | 正文混进**推理过程**了吗？         | 试错 / 探针输出 / A/B/C 比选 / "我以为·后来发现" ⇒ **抽成判据 + SOP**，过程归区域日志 |
| ⑨ | 对下一个 AI **有指导意义**吗？      | 读完答不出"我该做什么 / 不该做什么"⇒ **判过期**或**改写成让架构更好的判据**，不占编号 |

**每条 ADR 必须服务于架构的正确性，而非掩盖问题 —— 三条合格判据（缺一即不合格）：**

| # | 判据                  | 不合格信号                                       |
| - | ------------------- | ------------------------------------------ |
| ① | **复杂度实减**：链路**更短、更直** | 用适配器 / 兜底把复杂度**藏进黑盒**（搬家 ≠ 消灭）             |
| ② | **失败诚实**：错误在**根部炸开** | 决议鼓励了静默 catch / 默认值兜底 / 假装成功                |
| ③ | **SSOT 收口**：同一能力的判断逻辑收口为 **1 份** | 仍是 N 份判据，或新增了第二份真相                         |

⇒ 三条全过才配留在现行集；不过的按下表六形态定位病灶（**③④⑤⑥ 改判据本身** · **② 打回重写** · ① 见铁律 3）。

> ⚠️ **「为拆而拆」禁令（本仓实证 2026-09-20）**
> 有 AI 以「ADR 要求建 / 拆门面」为由要**拆门面**，被用户拦下 —— **拆完调用方各自直插内部件，入口 1 → N、链路更长**，反而更差。
> **守护者不判"这个门面该不该拆"（那是架构师的活，越界），判的是：能不能拿这条 ADR 当依据去拆。**
>
> **反拆四问（⓿ 不过 ⇒ 禁做；①②③ 任一不降 ⇒ 不许做；且说明那条 ADR 被误读 ⇒ 回去改它的表述）**：
>
> | 问 | 判据（可数，不许凭感觉） |
> | --- | --- |
> | **⓿ 正确性**（最先问） | **用户能做的事变少了吗**？变少 ⇒ **禁做**，摆 A/B/C 交用户（ADR-0047）—— 它是**必要条件**，不是加分项 |
> | ① **复杂度** | **链路环节数**改前 vs 改后 —— 更短才合格（搬家 ≠ 消灭） |
> | ② **SSOT** | 同一能力的**入口数**是 1 还是 N？**1 → N = 破坏** |
> | ③ **交扯指数** | **跨目录未走门面直插的次数**（ADR-0044 §7 的指标）下降了吗？ |
>
> ⇒ 与 **ADR-0044 §9「拆门面的门槛」**同表（正确性不退 / 复杂度变低 / SSOT 变好）；**拿不出 ⇒ 不许拆**。
>
> **根因**：门面是"窄接口"的一种实现，**判据是接口宽度**（ADR-0042 D1 / ADR-0044 §7·§8），**不是"有没有门面"**。
> ⇒ 拿"ADR 说要有 / 不要有门面"当依据 = **违反 ADR-0001（既有约定不是判据来源）** —— 先答「它凭什么成立」，答不出就不许动。

**会让架构变差的六种形态**：
  
① 用"可测量"冒充"正确" ・ ② 无条件奖励旧实现 ・ ③ 判据本体与边界分家（"一律 X 是误读"只写在后果段）・
  
④ 缺"什么算"的判据（主观量词）・ ⑤ 常红判据 ・ ⑥ 禁用一切防线却没写"存量痕迹怎么办"。
  
⇒ **③④⑤⑥ 改判据本身**（不是加提醒）· **② 打回重写** · ① 见铁律 3。

### Step 2 · 收编 —— 合并 / 钉边界 / 退役

```bash
# 1 新建合并条（必须自洽成一条线）
node scripts/adr.mjs add --title "<合并后标题>" --conclusion "<新结论 ≤120 字>"
# 2 原条转已取代 —— 正文冻结，**只改头部状态行**（不可变性）
node scripts/adr.mjs status <旧编号> --to 已取代 --by <新编号> --note "合并入 ADR-<新编号>"
# 4/5 索引（产物）+ 对账
node scripts/adr.mjs index --write && node scripts/adr.mjs audit   # 必须 0 问题
```

**第 3 步 · 回改三处（漏一处 = 没做，A7）** —— 引用面**用 `node scripts/adr.mjs refs <NNNN>` 拿**：
它按「① 必须回改 / ② 必须回改 / ③ 不动」**分三类列全**，比人肉 grep 可靠（**本轮实证：人肉漏了 `docs/DOMAIN-MODULES-HANDOFF.md`，差点留下一份照旧教人补建门面的活跃文档**）。
  
① 全仓改旧编号引用（活跃文档必改，`daily/` 历史日志与自动索引不改）・
  
② **被收窄的那条加头部指针** ・ ③ 新条头部写清 `取代`（`--supersedes` 自动连双向线）。
> **单向补丁是本仓的高发病**：给 A 加了前置条件，却没在 B 留指针 ⇒ 下一轮照着 B 又登记一笔假债。**改了就回改，一次改完。**
>
> **回改的适用范围（别改过头）—— 按文档类型判定，不看编号**
>
> | 文档类型 | 要不要同步 ADR | 处置 |
> | --- | --- | --- |
> | **生效判据**（现行 ADR 的论据 / 指针 / 落点） | **必须同步** | 回改（A7）—— 它会被后人当入口再查；含「给被收窄的那条加指针」 |
> | **活跃文档**（`CLAUDE.md` · `spec/CONTEXT.md` · `spec/DATAFLOW.md` · `.codebuddy/commands/**` · 代码文件头） | **必须同步** | 同上 |
> | **过程文档**（`docs/plan/**` · `daily/架构日志/**` · 已完工批次记录 · 轮次快照） | **不需要同步** | 见下 |
>
> **🔒 过程文档不需要同步 ADR**（含"已完工的执行计划"与"历史轮次文件"）：
> - 它记录的是「**当时依据什么做的**」，不是现行判据入口；**后面的 AI 不会去看它**，同步了也没意义。
> - 于是：**不回改编号引用**、**不加"改指"注解**、**不加顶部对照声明** —— 全是噪音（ADR-0019：「历史轮次文件保持原样，它们是当时快照，**回改反而失真**」）。
> - 真遇到**已删号的编号**：**直接把那处引用删掉**即可（不是改指、不是加注解）。
> - 确实要留痕的（如"某编号为什么被删"）⇒ **另写一份区域日志**，**不写回过程文档**。
>
> **判据一句话**：**改不改，看它会不会被当入口再查一次。** 会 ⇒ 改；不会（过程/快照）⇒ 不动。

**合并后必须是一条线**：
  
`旧约定 → 当初为什么这么定 → 凭什么不成立（取证）→ 新判据 → 与谁互补（边界表）→ 怎么发现"又回去了" → 落点`
  
外加 `## Lessons Learned`（`audit` 会校验）。边界表范本 = **ADR-0003 §「与 ADR-0002 的边界」**（两列对照 + 一句总判据）。

**退役**：走 `status --to 已取代 / 已弃用 / 已毕业`，**不删**；`rm` 只用于误建，且删号必扫引用面。
**改写（形态不合格时）**：推理过程 ⇒ 抽成「判据 + SOP」（过程归区域日志，别删——弯路最贵）；没指导意义 ⇒ 先答「它正确落地时该长什么样」，答得出就**改写成让架构更好的判据**，答不出就**判过期**（`--to 已弃用` + 写明"为什么它不再有指导意义"）。

### Step 3 · 立据 —— 新增前三道闸

1. **落笔前 5 判据**（`add --dry` 会打印**同样的 5 问**；本文件补的是**"答不出该怎么办"** —— 工具只给问，不给处置判据）：

| # | 判据（问）              | **答不出 ⇒** 的处置                                                                     |
| - | ------------------ | -------------------------------------------------------------------------------- |
| ⓿ | **是否只影响一处？**        | 是 ⇒ **死日记** ⇒ 记 `daily/架构日志/`，**不写 ADR**                                          |
| ① | **是否推翻了既有约定？**      | 答不出「它凭什么成立」⇒ 那个约定就是**待消灭的对象**（ADR-0001）；**"仓里一直这么写"不是依据**                       |
| ② | **能不能不用 ADR 守？（要判 ROI）** | 类型约束 / 结构隔离 / 对账测试能做到 ⇒ 升级为 fitness function（`--to 已毕业`）。**更该先问：改几行代码就能根治吗？** —— **能 ⇒ 别用 ADR 守，改成代码**（见下 ROI 判据） |
| ③ | **是否有同义 / 近义的 ADR？** | 有 ⇒ **必合并**（禁把同一语义抄 N 份买绿灯）；属**判据重复** ⇒ 只钉边界、不合并                                 |
| ④ | **有无违反时的判据？**       | 写不出「怎样发现又回去了」⇒ 它是**没有防线的声明**，不许落盘                                                |
2. **守护师第 6 问**：**写下它之后，有哪个具体动作会因此改变？** 答不出 ⇒ 不写。
3. **A14 执行面**：先写「这条判据的正确形态」（写不出 = 没理解，**不许落笔**）→ 再查 `adr.mjs search` + README §七 索引；**已有就是正解，一行不写**。

> **⚖️ ROI 判据（用 ADR 守，还是改代码根治？）**
> **ADR 的永久成本 = 维护 + 对账 + 被误读**（它只增不减）；**改代码的成本 = 一次性**。
> ⇒ **改动半径小且能根治的事，不许拿 ADR 去守** —— 判据：**改一次就能让"误用写不出来"吗？**
> 能（如"某 config 只有 5 个消费者" ⇒ 收进 `config.ts` 一次性收口）⇒ **转债，去改代码**，ADR 判过期。
> 不能（跨前后端 / 需长期防回潮 / 一次改不干净）⇒ 才值得立 ADR，**并尽快毕业**。

**优先级**：**毕业**（升 fitness function） > **写进已有条** > **不写**（记录 → `daily/架构日志/`；债 → `debt.mjs`） >
  
**最后才 `add`，且一轮 ≤3 条**。

## Gotchas

- **闸绿 ≠ 健康**，只等于"它查的那几项没问题"。**工具没拦 ≠ 内容没问题。**
- **误合比不合并更贵** —— 削掉的能力不报错，只在某天变成"下拉框里按 Delete 删了关键帧"。
- **判据过期比判据缺失更坏** —— 它稳定产出假债，而假债会让人不再信任何判据。
- **「已毕业」不是「已作废」** —— 判据仍现行，只是载体换成闸。
- **提示 ≠ 拦住** —— 要加检查就真加（并入既有闸），别写在文档里装防线。
- **结论句是 ADR 唯一的门面** —— 正文再对，**结论句旧了 = 判据旧了**（AI 只读那一行）；改 ADR 不改结论句 = **没改**。
- **别把"摘要"当"不一致"** —— 结论句比正文**更简略但方向一致** ⇒ **不是问题**，不要修（例：结论"CONTEXT 只装路由与例外" vs 正文"路由表 + 例外与边界"）。只修「**照结论做会做错**」的三种：宽/严错位 · 缺关键前提 · 自相矛盾。
- **⓿ 问的扫法**（实操）：逐条把 `- **结论**：` 与 §判据 / §决议 / §后果 / 头部补充并读 —— **不是只读结论**；量大时可并行分派核对，但**每条命中都要自己回读原文复核**再动手。
