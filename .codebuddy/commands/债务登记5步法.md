# 债务登记 5 步法（低脑力 SOP）

> **只管一件事**：把一笔债登记下来，并让这块区域**越审越清楚、不被反复重审**。
> **触发**：用户说「审计 <区域> / 排查架构 / 维护架构日志 / 数据流过期了 / 登记债务」。
> **分工（别混）**：本文件 = **审**（发现 + 登记，**只读**）· `架构师改码7步法.md` = **改**（施工还债）· `系统治理5步法.md` = **旁路复检**。
> **效力边界**：`CLAUDE.md` 物理红线 > `架构师心法.md` > 本步骤。
> **精简留痕**：2026-09-16 删去论证 / 沿革 / 案例（原文见 git 历史），只留可执行步骤。

---

## 🚫 禁令：只读，不改一行代码

**为什么**：债往往同源（同一条规则 / 契约生出来的），逐条就地改易**改错 / 改重** → 统一交决策架构师一次收口。

**唯一例外 = 工具债**：`scripts/**`（闸 / 账本 CLI / 审计工具）· `.codebuddy/commands/**`（流程文档）· `package.json` 的 `scripts` 条目 → **当场修**，不留成待还债；**判不准 → 只登记**。
工具债"怎么修、修完交什么"的唯一真源 = `架构师改码7步法.md` 附录 A10（本文件不重复规定 —— 写进来会让只读流程被当成施工流程）。

**本流程的唯一产出 = 轮次文件（探债 + 覆盖度表）+ 账本一行。**

## 🔒 铁律：任何"描述"都只是线索，不是结论

债登记、注释、issue、**上一轮结论、覆盖表里的"深审"**都可能是错的。**动手前必须重新取证**（`refs` + 读真实代码）。把描述当"去哪儿看"，不当"是什么"。

## 方向：从最底层出发

**类型 / 契约 / 定义 → 纯函数 utils → store / core → hook 编排 → 节点 / UI → 后端。**

从 UI / 功能往下钻只能看到**症状**；债的根几乎总在更底层。**底层一条债，抵上层十条。**

# Step 0 · 覆盖度账（"不重复查"的唯一机制）

在轮次文件里按本表登记每个文件：

| 文件 | 层 | 覆盖状态 | 灯 | 轮次/日期 | 证据(refs/行号) | 债/裁定 |
| --- | --- | --- | --- | --- | --- | --- |

**覆盖状态只允许 5 个**：`未审`（会再查）· `抽审`（欠一轮深审）· `深审`（只有代码变了才回查）· `已裁定非债`（**禁再当 bug 补**）· `有债待还(TD-xx)`。

1. **开审前先读它**：只审 `未审` / `抽审` / `回查`；`深审` 不重查（除非代码被改过 → 标 `回查`）。
2. **`已还清` ≠ 覆盖完备**：表里还有 `未审` 行，就**不许**写"该区审完"。
3. **表是增量账**：只登记本轮**新纳入 / 状态变化**的行，未变的原样保留、**不重抄**。

# 数据流覆盖地图（灯的定义）

**细粒度（文件 → 灯）只写在本节的覆盖度表里**；**粗粒度（区域 → 灯）由 `index.md` 从各轮次文件 §七 状态自动派生** —— `spec/DATAFLOW.md` **已不放灯**（2026-09-16 收口）。

| 灯 | 含义 | 对应覆盖状态 |
| --- | --- | --- |
| 🟢 | 已审、无债 | `深审`（无债）/ `已裁定非债` |
| 🟡 | 已审、有持平 / 待裁定 | `深审` + 持平债 |
| 🔴 | 有债待还 | `有债待还(TD-xx)` |
| ⚪ | 未审 / 抽审（欠深审） | `未审` / `抽审` |

**读起点的两步**：先看 `index.md` 的灯选"该动哪个区" → 再看该区最新轮次文件的覆盖度表选"该动哪个文件"。
已被改动过的 🟢 文件 → **在覆盖度表里**标 `回查`（不是去改 DATAFLOW）。

# Step 1 · 定起点

**要回答**：登记哪个区、起手第一个文件、哪些文件这轮不用审。

1. 读 `daily/架构日志/index.md`（**机器生成，勿手改**），取状态为 `待审计` / `审计中` 的区（都没有 → 按「层」列从底到顶选一个）。
2. **先读 `spec/DATAFLOW.md`** 该区链路 —— 它**已不放灯**；细粒度进度看该区**最新轮次文件的覆盖度表**（🔴⚪ 优先）。
3. 找出该区**最底层文件**（类型定义 / 契约表 / 常量登记表 / 纯函数）。
4. 列出该区文件清单（**按层从底到顶排序**），对照覆盖度表筛出本轮要审的；不审的写明原因。
5. **查本区历史债**：`node scripts/debt.mjs area <NN>` —— 看 ① 要审的文件是否已被旧债判过（别重审）② 同类问题是否**复发**（复发 = 上次没治根）。跨区找同类先例：`debt.mjs search "<机制名>"`。

**产出**：文件清单（底→顶 + 覆盖状态 + 灯）；第一个文件 = 本轮起点。
**不过关**：找不出"底层文件" → 区域边界没定清，先定边界再开审。

# Step 2 · 取证

**要回答**：这条链路真实长什么样？DATAFLOW 过期了吗？

1. 对起点文件跑 `refs`（可一次传 Step 1 的多个文件），看 **fan-in**（谁 import 它）。
2. 读真实代码：**类型 / 契约 / 不变式 / 唯一入口**在哪。
3. 沿 fan-in **逐级向上**核实"谁产生 → 经过谁 → 谁消费 → 落哪"，标出 DATAFLOW 与实际不符处。
4. 疑似死代码 → `find-dead` + `refs` 双证（0 引用且非入口）。

**产出**：真实链路快照（贴 `refs` 输出）+ 覆盖证据（每个文件挂 `refs` / 行号）。
**不过关**：拿不出 `refs` 证据 → 这不叫取证，别下结论。**自证式审计 = 没审**（证据要能让别人独立复现）。

# Step 3 · 找债（只登记，不动手）

**要回答**：孤例还是母体？是债还是有意设计？归到哪一类？

## 3.1 先归因

1. **按"它为什么会产生"归堆**（不是按症状分类）：它们共享哪条**规则 / 契约 / 机制**？
2. **判据：某个修复能同时消灭 ≥3 个债 → 它就是母体。** 母体几乎总在**契约层 / 规则层 / 机制层**。
3. 查规则层三问：是不是**某条规则**出问题？是不是**缺机器守卫**（红线只写在注释里 → 必回潮）？是不是**同一真相被抄成多份**？
4. 产出：`母体` → 登记为一个母体债（一收全消），症状挂它名下；`孤例` → 独立债；`症状群但无母体` → 登记 N 个债（**不编造母体**）。

## 3.2 五问（每层只问这 5 句）

1. 同一真相是否被抄成 **≥2 份**？（SSOT 第二份，最高频母体）
2. 有没有**绕过唯一入口**？
3. 错误被**静默吞**了吗？（零日志 / 失败伪装成功）
4. 有没有**死代码 / 死参数 / 假护栏 / 假收窄**？（死代码须 `refs` 0 引用 + `find-dead` 双证）
5. **注释与实现一致**吗？

| 是债 | 不是债 |
| --- | --- |
| 同一真相多处维护、靠"约定"同步 | 有意设计（有理由 + 注释已固化） |
| 绕过唯一入口 / 假护栏（守卫恒真） | 为一致性而改（功能不变、收益为 0） |
| 静默吞错 / 失败伪装成功 / 假收窄 | 已在正确位置的复杂业务逻辑 |
| 死代码 / 死参数 / 注释与实现矛盾 | 真缝隙上只有 1 种实现（还没到，不是债） |

## 3.3 标归属

**结构债**（删重复 / 抽 helper / 补守卫 / 死代码 / 注释漂移）或 **业务债**（删需求 / 砍功能 / 改交互 / **改对外契约与持久化格式** / 引重依赖 → 标 `待用户拍板` + 摆 A/B/C 选项）。
**两类都不在本流程施工** —— 归属只决定将来谁决策。

**"不能动"是真红线还是假习惯**：拿不出 `CLAUDE.md` 级证据（端口 `18080` / `{code,data}` / 存储键登记表）→ **假习惯**，债成立；拿得出 → 照常登记 + 备注依据（红线只影响将来怎么改，不影响登记）。

> **证据闸**：每笔债、每个"非债"结论**都必须挂 `refs` 输出或 `文件:行号`**。挂不出 = 无效结论。

**产出**：债候选清单 + 归因（母体 / 孤例）+ 归属。
**不过关**：判"不是债"也必须**留痕**（写轮次文件 + 账本标 `[已裁定 <日期>·非债]`）—— 否则下一个 AI 还会当 bug 补。

## 区域治理规则（清单不是封闭的，架构师自主裁量）

1. **自主加区**：在 `scripts/arch-index.mjs` 的 `AREAS` 加一行（编号顺延 `max(NN)+1`），并在该轮轮次文件写明「为何漏列」。
2. **拆分**：某区实为 ≥2 个关注点 → 拆 `<NN>a`/`<NN>b` 或新编号，原区标「已拆分 → 见 NNx/NNy」。
3. **合并**：两区域实为同一数据流 → 合并，保留低编号，另一标「已并入 NN」。
4. **退役**：对应代码已删 → 标「已退役」，历史文件不删、**编号不回收**（防链接断裂）。
5. **跨区归属**：症状在 A、根因在 B → A 区文件 `@见 B区`，**债 ID 绑根因区**。
6. **状态回退**：已还清区被打回 → 重开新日期文件，§七 写回「有债待还」+ 备注 `回退：<日期> <原因>`。
7. **待翻新 ≠ 债**：需重构但不算债 → §七 写「待翻新」，**不进 `债务.md`**（该索引只收"确是债且现在不能动"）。
8. **单区膨胀**：一轮产出过大 → 按子关注点拆多个轮次文件。
9. **跨区只开一份**：一轮命中 N 个区的根因 → 写 `<触发区NN>-跨区-<主题>-<日期>.md` **一份**（先例 `20-跨区-幽灵预留清偿轮`）。
10. **工具债不延后**：命中 `scripts/**` / 流程文档 / `package.json` scripts 缺陷 → 当场修（细则见 `架构师改码7步法.md` 附录 A10）。
11. **`index.md` 是产物，禁手改**：要改区域/层 → 改 `arch-index.mjs` 的 `AREAS`；要改状态 → 改轮次文件 §七。

## 卡住时怎么办（退回机制）

| 发现 | 退回动作 |
| --- | --- |
| `refs` 说不清链路 | 回 Step 1 重定底层起点 |
| 分不清"债"还是"有意设计" | 回 Step 2，把该层代码 / 契约读完再判 |
| `增债` 写不出偿还计划 | 回 Step 3 重判（多半它不是债，是偷懒） |
| 覆盖表还有 `未审` 却想写"审完" | 状态改「部分覆盖」+ 列出未审清单 |
| 发现"债"根本不存在 | 改判非债 + 留痕，**结束**（最常见也最该退的一步） |
