# 分配任务工作流

> ⚡ 奥卡姆剃刀：如无必要，勿增实体。每句删了能不能完成任务？能，就删。

## 一、角色定义

| 角色 | 做什么 |
|---|---|
| **主 AI（委派者）** | 清旧任务书 → 接收需求 → **判定任务类型** → 写任务书 → 归档 |
| **执行 AI（受命者）** | 按任务书执行，不会回来提问，必须独立完成 |
| **用户** | 给出原始需求 |

**核心纪律**：执行 AI 不会提问。任务书必须自包含，不留模糊空间。

---

## 二、第一步：先判定任务类型（决定要不要行号）

> ⚠️ **动手写任务书前必须先判定类型**。不同类型对「精确行号」的需求完全不同，给错就是返工。
>
> **一句话区别：开放式任务「让 AI 自己发现问题」，限定任务「让 AI 按清单执行」。**

| 类型 | 本质 | 给不给行号 | 给什么 | 举例 |
|---|---|---|---|---|
| **A. 探索/查漏补缺** | 执行 AI 自己去找"哪里该有却没有/该走却没走" | **不给** | 文本要求 + 目标 + 大概文件（**强调不限定只这些，可自行扩展**）+ 判断标准 | "查所有该走 KV 却落 localStorage 的写入点" |
| **B. 精确查细节** | 定位某个具体函数/逻辑/值是什么 | **给** | 文件 + 行号 + 关键词 | "App.js L1287 的变量 a 是干嘛的" |
| **C. 文档/分析** | 重写/写某主题文档，读代码归纳 | **给探索起点**（文件+行号锚点） | 目标 + 探索起点 + 覆盖清单 | "重写会员机制文档" |
| **D. 代码改写** | 重命名/改注释/改具体逻辑 | **必须给** | 三件套（映射表+行号+代码模板） | "把变量 a 改成语义名" |

**判定问题**：
1. 目标是"让 AI 自己发现问题"？→ **A**（探索）
2. 目标是"定位一个已知的东西"？→ **B/C**（精确）
3. 目标是"改某处已有代码"？→ **D**（必须行号）

**铁律：探索类（A）任务永远不给行号。给了行号就变成填空题，AI 不会去找漏缺，只会填格子——这违背探索目的。**

## 三、工作流

### 0. 定目录
去看看了解现状。 `docs/agent 批量任务/`

### 1. 理解需求
确认目标主题、是否禁止参考现有文档、是重写还是新增、**任务类型（A/B/C/D）**。产出：需求摘要 + 类型判定。

> 需求不明确时标记 [信息缺口] 追问，不用假设填空。

### 2. 探索代码基底
- **A 探索类**：不做详细定位。只需列出「大概文件 + 关键词」作为提示，**明确写"不限定只这些文件，可自行扩展"**。
- **B/C/D**：grep 关键词 → 读核心文件 → 定位关键行区。产出：探索起点清单（路径+行号+grep 词+语义）。

### 3. 设计生命周期覆盖
- **A 探索类**：只列「该查的链路/方向」，不枚举具体点（具体点是 AI 自己去找的）。
- **B/C/D**：按项目独特生命周期拆解，枚举"出现的所有地方"。产出：覆盖清单（带路径+行号）。

### 4. 起草任务书
按以下结构组装：项目背景 → 任务类型 → 硬约束 → 探索起点 → 覆盖清单 → 输出规范 → 验收标准 → 铁律。产出：`docs/agent 批量任务/TASK-序号-任务短名.md`。

**结构随类型而变**：
- **A 探索类**：背景 → 判断标准（AI 按此自己找）→ 大概文件（不限定）→ 怎么做 → 输出规范 → 验收标准。
- **B/C/D**：背景 → 探索起点（带行号）→ 覆盖清单（带行号）→ 输出规范 → 验收标准。

#### 4.1 代码改写类任务（D）：必须包含三件套

| 必须给 | 格式 | 不给的后果 |
|--------|------|-----------|
| **变量映射表** | 原名→新名 对照表 | agent 猜错 → 返工 |
| **精确行号** | `App.js L1287` | agent 4.3 万行盲搜 → 写脚本 |
| **代码块模板** | `\| 节点类型 \| 组件名 \|` + 空 ` ```js ```` | agent 丢错位置 → merge 失败 |

> 原则：**D 类 agent 花的每一秒在"探索"而不是"执行"，都是任务书设计失败。** 三件套给齐 = 填空题，缺一样 = 探索题 → 脚本。
> **A 类恰恰相反：让 AI 自己去探索、去发现，才是目的。绝不给行号清单。**

### 5. 归档
扫 `docs/agent 批量任务/` 已有 `TASK-*`，取最高序号+1，写入。

### 6. 交付话术
输出一行，用户直接看文件路径发给对应 AI 即可：

`任务书：docs/agent 批量任务/TASK-XXX-任务短名.md → 发给 AI0X`

## 四、绝对禁令清单

1. **文件名铁律**：每次委派必须指定唯一产出路径 `docs/agent 批量任务/主题.md`，不同 AI 不能写同一文件。
2. **禁止参考**：如要求"不参考现有文档"，硬约束必须写明。
3. **探索起点真实**：B/C/D 类的行号必须来自本次会话的实际 grep，不能复用历史（行号会变）；**A 类禁止编造行号**。
4. **验收标准强制**：每份任务书必须有可自测的验收标准。
5. **序号递增**：编号扫描目录已有 +1，禁止硬编码 `TASK-001`。
6. **不可交互**：任务书禁止出现"如有问题请联系"等假设执行 AI 能提问的表述。
7. **独立文件夹**：每个 AI 的产出放 `docs/agent 批量任务/`，不混入 `docs/模块专题/`。
8. **类型先行**：动手前先判定 A/B/C/D，类型决定是否给行号。

## 五、示例

### 示例 1：探索类（A）— 正确写法
> 用户：安排 AI 查"该走 KV 却落 localStorage"的漏缺。

- 产出：`docs/agent 批量任务/TASK-045-探索-数据存储该走KV却没走KV.md`
- 任务书核心（**无行号**）：
  - 背景：项目有 KV/localStorage 分流，出现过画布快照落 localStorage 撑爆配额。
  - 判断标准：画布/节点核心数据本应跨端共享走 KV，若落 localStorage/只在内存/刷新即丢，是缺口。
  - 大概文件（**强调不限定**）：`src/components/base/` 下存储相关；**你可根据实际需要自行扩展范围**。
  - 怎么做：通读存储模块 → grep 关键写入 → 逐一判断该走哪条路、是否走对 → 找"该有持久化却没实现"的漏缺。

### 示例 2：代码改写类（D）— 正确写法
> 用户：安排 AI 把 App.js 里某混淆变量改成语义化名。

- 产出：`docs/agent 批量任务/TASK-XXX-重命名.md`
- 任务书核心（**必须行号**）：映射表（`a→updateNodeData`）+ 精确行号（`App.js L1287`）+ 代码块模板。

### 示例 3：精确查细节 / 文档（B/C）
> 用户：安排 AI 重写会员机制文档。

- 产出：`docs/agent 批量任务/会员与登录机制-v2.md`
- 探索起点（带行号锚点）：grep `会员 / login / token`；读 `src/services/auth.js`、`src/App.js`（登录 L43849、401 登出 L36143）。
- 覆盖清单：两条通路 → 存储键 → 登录协议 → token 收发 → 会员过期 → 登出。

## 七、多 Agent 并行规则

核心思想：**agent 不知道别人存在，就无从抄袭和互扰。**

### 7.1 自包含任务书
- 任务书内嵌所有需要的参考材料（A 类=判断标准+大概文件；D 类=映射表+行号+模板）。
- agent 只知道自己的产出文件路径，不知道还有几个 agent、他们做什么。
- 不写"本次共分配 N 个 agent"、"你的编号是 X"。

### 7.2 只写一个文件
```
1. 分配：每个 agent 一份自包含任务书
2. 输出：agent 填自己文件的表格/代码块，只在这一个文件里写
3. 合并：你运行合并脚本统一写入（备份→逐条验证→全量 check→失败回退）
```

> 📁 任务书首行写死：`你只能写这个文件，碰任何其他文件视为失败。`

## 八、如何写任务生成脚本

不要在聊天里手写几十个任务文件。写一个 `tmp/gen-xxx.cjs`，跑一次生成全部。

### 8.1 模板
```js
// scripts/gen-xxx.cjs — 一键生成 N 个 agent 任务文件
const fs = require('fs');
const TASK_DIR = 'docs/<task-name>';
fs.mkdirSync(TASK_DIR, { recursive: true });

const items = [...];          // 要分配的任务项列表
const AGENTS = 5;             // agent 数量
const batchSize = Math.ceil(items.length / AGENTS);

for (let b = 0; b < AGENTS; b++) {
  const batch = items.slice(b * batchSize, (b + 1) * batchSize);
  if (batch.length === 0) continue;  // 最后一个为空就跳过
  const num = String(b + 1).padStart(2, '0');

  let md = `# XX${num} — 任务描述（${batch.length} 个）\n\n`;
  md += `> ⚠️ 请勿查看其他 agent 的结果文件。\n\n`;
  md += `## 方法\n...\n\n`;
  md += `## 输出格式\n...\n\n`;
  md += `| # | 项目 | 结果 |\n`;
  md += `|---|------|------|\n`;
  for (let i = 0; i < batch.length; i++) {
    md += `| ${i + 1} | \`${batch[i]}\` |  |\n`;
  }

  fs.writeFileSync(`${TASK_DIR}/XX${num}.md`, md);
}
```

### 8.2 关键点
- **数据源从代码提取**，不手写：`grep` / `fs.readFileSync` / AST 解析
- **每个 agent 独立文件**，不共用
- **输出格式明确**：填表格、代码块、或键值对
- **同步写合并脚本**：生成任务文件的同时，写好对应的 `scripts/merge-xxx.cjs`
- **用 `.cjs` 扩展名**：避免 ESM/CJS 冲突
- **跑完删脚本**：`node scripts/gen-xxx.cjs && rm scripts/gen-xxx.cjs`

### 8.3 已有参考
- `scripts/gen-all-tasks.cjs` — 之前生成 NC/EV/KV 三组任务的脚本（已归档 `scripts/archive/`）
- `scripts/annotate.cjs` — 基于映射表批量更新 App.js 注释
- `scripts/merge-rewrites.cjs` — 合并 agent 输出的函数体重写结果

## 九、踩坑经验（每个坑都返工过）

### 坑 1：把探索类任务写成了"填空题"（最核心的坑）
**错误**：给探索任务配了精确行号清单，让 AI 逐条核对。
**结果**：AI 只填格子，不去找漏缺；本该发现的"该有却没有"被忽略。
**正确**：**先判定类型**。探索类只给判断标准 + 不限定范围的大概文件，让 AI 自己去搜、去找漏缺。只有代码改写类（D）才给死行号。

### 坑 2：没检查就重做
**错误**：看到任务文件里没代码块就标记"未完成"，全部要求重写。
**结果**：有几个 agent 的代码块其实能过 build，白白浪费。
**正确**：**先跑合并脚本看实际结果**。能过的保留，只补失败的。跑脚本比人工判断准。

### 坑 3：Agent 会写脚本（D 类）
**错误**：以为多加禁令就能阻止。铁律第一条写了"不写脚本"，照样违。
**根因**：agent 写脚本是因为手写成本 > 脚本成本。任务书不给映射表+行号 → agent 得先定位函数、猜变量含义 → "不如写个脚本一次性搞定"。
**正确**：让手写比脚本更省力。给齐三样东西：映射表（不用猜）、行号（不用搜）、代码块模板（不用建格式）。手写 5 分钟 vs 写 Babel AST 脚本 30 分钟。

### 坑 4：简单括号匹配提取大函数体会失败（D 类）
**错误**：用正则 + 括号计数从 App.js 提取函数体。
**结果**：含模板字面量 `${}` 的大函数括号计数错乱，提取出错误片段。
**正确**：
- `function Name(){}` 和 `Name = Y.memo(() => {})` 两种模式分别处理
- 大函数不提取全量，改用行号定位 + 映射表就够了
- 如需提取全量，用 `@babel/parser` 而非正则

### 坑 5：铁律藏在不显眼的地方
**错误**：铁律写在 md 文件中部，agent 跳着读忽略掉了。
**结果**：多次违规。
**正确**：铁律放在任务书最顶部，用 `## ⚠️ 铁律（违反重做）` 醒目标题，三条以内，每条一句话。
