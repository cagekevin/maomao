# 逆向学习 SOP（统一入口）

> **一个技能，四条分支。先做「场景分流」，再进对应分支。**
>
> **技能版本**：v1.1.6 · 最后更新 2026-10-10 · 变更记录见 `references/evolution/changelog.md`

---

## 定位与使用边界（先看这条）

本 SOP 的定位是**个人学习 / 复刻研究**，不是生产级交付。在这个前提下：

- **读源码、复现 prompt、抄写实现、记笔记、本地跑通**——都是正常的学习手段，**可以抄，放心抄**，不需要犹豫。
- 产出物默认是**私有学习笔记**：自己看、自己改、自己练手。
- 唯一的边界是"离开个人学习范围"那一步——**对外分发 / 商用 / 公开发布**。只要不跨这一步，抄多细都没问题。
- 抄的时候**顺手标来源**（repo + 文件 + commit）：不是负担，既方便自己回溯，也让笔记更可信。

> 一句话：**学习复刻 = 可以抄；只把它当私有笔记，别当成品对外发。**

## 核心原则（全程适用）

| 原则 | 说明 | 违反后果 |
|---|---|---|
| **先分流再动手** | 先判断目标属于哪条分支，再选工具 | 选错路径，白干几小时 |
| **口径统一** | 每个分类用「唯一键」计数（文件名/函数名/表名），不靠行数/关键词 | 宣称"已覆盖"但实际有遗漏 |
| **分层推进** | 先粗后细：清单 → 入口 → 核心链路 → 逐行 | 上来就逐行读，迷失在细节里 |
| **边界优先** | 先搞清"能做什么 + 参数边界"，再深入实现 | 复刻时因参数超限被上游拒绝 |
| **多视角交叉** | 单一视角一定看漏（只看 AI 能力会忽略状态机/并发） | 架构有盲区，复刻才发现 race condition |
| **业务优先** | 先提炼领域规则，再抄 prompt 文本 | 只抄文本，换模型/场景就失效 |
| **验证驱动** | "对不对"靠可执行验收，不靠肉眼"差不多" | 交付一堆文档却无法证明 |
| **元数据可追溯** | 每个产出标覆盖度/置信度/版本，别把推测当事实 | 交付物无法被信任 |
| **及时交付** | 每挖完一个单元就落盘，不要攒 | 上下文丢失后忘了挖过什么 |

## 一、场景分流（先做这一步）

| 判断依据 | 走哪条分支 |
|---|---|
| 目标**有源码**（`.ts/.tsx/.py/.js` 可读） | **分支 A · 读源码型逆向** |
| 目标**只有编译混淆产物**（`dist/` 里是几 MB 的 `function(e,t){...}` chunk / 有 `.map`） | **分支 B · 编译混淆产物还原** |
| 需要**运行时**抓签名 / 加密参数 / 风控字段，或目标是 **JS 自定义 VM（JSVMP）** | **分支 C · JS 运行时逆向** |
| 目标有 **Electron 壳**（`resources/app/`、`main.js` + `preload.js`） | **分支 D · Electron 应用逆向** |

> 组合情况：Electron 应用的渲染层若是混淆 bundle → **D 先解包定位，再用 B 还原 bundle**。
> 判断产物类型（webpack / JSVMP / obfuscator.io / WASM / V8 字节码）的决策树见 `references/bundle/toolchain.md`。

## 二、通用执行约定（各分支都适用）

1. **预算与停止**：给每个阶段设预算，**超预算不无限深挖**——把剩余项记进台账，转下一步，之后再回补。
2. **拿不到运行时数据**：目标跑不起来时，依赖运行时的结论一律标 `[待验证]` + 写明验证方法。**禁止用推测冒充确证**。
3. **大项目并行**：项目很大（如 > 约 50 个源文件、跨多模块）时，**按单元用子代理并行挖掘**，主上下文只收结论。
4. **产出元数据**：每个产出文档头带 4 项——覆盖度声明 / 置信度分级（`[确证]`/`[推断]`/`[待验证]`）/ 版本锚定 / 进度台账。
5. **开工先注入**：动手前先扫一遍 `references/evolution/lessons.md` 的活跃条目，避免重踩已知坑（优先看标 `[确证]` 的）。
6. **收尾必复盘（自我进化）**：任务收尾过一遍「复盘三问」，把新坑 / 新工具 / 被推翻的结论写进经验库；技能自身的改动必须记账。详见第七节。
7. **先定稿后动手（硬门禁）**：**文档未出齐、架构与契约未定稿前，禁止写任何实现代码**（含搭骨架、定目录、写类型、写 mock）。逆向产出（`00`~`08`）只是**第一步**；第二步必须**由文档推导**出架构与契约并**定稿**，第三步才动手。违者整段返工——见 `L-0010`。

### 交付门禁（动手前必须全过）

> 由 `L-0010` + `L-0011` 晋升而来。**任一未过 → 不许写实现代码。**

| # | 门禁 | 判据 |
|---|---|---|
| 1 | **文档出齐** | `00-进度台账` ~ `08-验证用例` 九份齐全，每份含元数据（覆盖度 / 置信度 / 版本） |
| 2 | **文档已回源核验** | 见下方「回源核验怎么做」；产出 `09-校验记录.md`（校验结论 + 修正清单），且**源文档已按清单改完** |
| 3 | **未决项清零** | 台账「超预算挂起项」中**阻塞实现的项**已关闭或明确接受（含 `[待验证]` 的验证方法） |
| 4 | **契约定稿** | 冻结边界（宿主接口 / 数据格式 / 协议）逐条列明，并给出「哪些能改、哪些不能」边界表 |
| 5 | **架构定稿** | 分层 / 模块边界 / 状态归属 / 依赖方向**书面确认**，且经过一次**质疑复审** |
| 6 | **验收先定** | 每个待实现模块的验收用例（判据 + 容忍度）已写进 `08-验证用例.md` |

#### 回源核验怎么做（门禁 2 · 由 `L-0011` 晋升）

**为什么**：文档是**转述产物**，必然有损耗；自动分类的正则是**拟合**出来的，存在不可消除误差。**doc-vs-doc 比对不能自证**——必须回源。

**四步**：

1. **列「架构依赖的关键事实」**（约 10~15 组）——不是全部内容，只列**错了会导致架构错**的那些：
   宿主接口集 / 冻结数据格式 / 数据模型字段 / 状态归属 / 模块边界 / 依赖方向 / 迁移逻辑 / 错误分类 / 协议
2. **逐条回源核对**——**能脚本化的绝不人眼比**（方法集差集、键名枚举、常量抽取、正则表抽取）
3. **量化误差**——给出比例而非"看起来差不多"（例：`canvas` 桶 53 个声明中 **14 个（26.4%）**归属错误）
4. **修正源文档**——校验的价值在**改文档**，不是只写一张核对表

**三条铁律**：

- **自动分类/正则推导的结论只能当「起点」**，不可直接当架构依据 → 必须人工复核桶成员
- **跨切面对象单独处理**（如全局 store），不要硬塞进某个业务桶
- **关键词过宽会过度修正**（例：用 `doubao` 做站点判据，把 `doubao-*` 存储键全吸走，canvas 声明数 54→10）→ 收窄成**专有标识**

**实测收益**（豆包画布）：12 组关键事实 → **8 通过 / 6 需修正**，其中 2 项若不修会直接导致架构错误（模块边界误分、降级链多算一条死通道）。

> **反模式**：把"准备工作"理解成"搭骨架"。骨架一旦基于未定稿架构，被质疑就得整段删掉——**先搭后问 = 必返工**。

### 重写阶段的两条硬判据（由 `L-0012` / `L-0013` 晋升）

> 这两条都来自**实测抓到的真 bug**（不是推演），重写阶段必须过。

**判据 1 · 唯一同步点（`L-0012`）**

> **同一份数据不允许有两份拷贝却没有唯一同步点。**

| 现象 | 后果 |
|---|---|
| 画布状态（`nodes/edges/library`）与工程状态（`projects[].data`）**各存一份**，改一份没同步另一份 | **持久化写的是旧数据 ⇒ 刷新即丢**（实测：内存 3 节点 / 落盘 1 节点） |

**做法**：跨 slice（或跨模块）的一致性**只允许一个同步点**，放在**组合处**（如 store 的 `setPartial`）——
**禁止**在多个 slice 里各写一份同步逻辑。

**自检**：任何"两份拷贝"都必须能**指出唯一的同步位置**；指不出 ⇒ 设计错了。

**判据 2 · 端到端脚手架先自检（`L-0013`）**

> **端到端测试报失败时，先怀疑脚手架，再怀疑实现。**

实测踩过的两个**假失败**：

| 假失败 | 真因 |
|---|---|
| "刷新后数据丢了" | `addInitScript` **每次导航都重跑** ⇒ 刷新时把数据重置回种子 |
| "双击不建节点" | 双击坐标**落在 MiniMap 浮层**上 ⇒ 事件没到画布 |

**三条自检**：① 初始化脚本必须**幂等**（判空再写）；② 交互坐标必须**排除浮层与已存在元素**（网格扫描）；
③ 失败断言**不要耦合其它步骤的产物**（否则失败相互掩盖，排查方向跑偏）。

## 三、分支 A · 读源码型逆向（有源码）

**目标**：挖透项目架构，产出可用于复刻的参考资料。

**主线**：Phase -1 启动（探测 + 定界 + 台账）→ 0 全局扫描 → 1 能力分桶 → 2 逐桶深挖 → 3 契约补齐 → 4 多视角交叉（15 视角）→ 5 领域规则提炼 → 6 验证闭环 → 7 产出交付物。

**核心动作**：先扫文件清单 → 按 AI 能力分桶（**按当前项目推导，勿照搬示例**）→ 逐桶挖 prompt/参数/DB/并发 → 补配置契约 → 15 视角交叉验证 → 提炼业务规则 → 定义可执行验收。

**产出**：`00-进度台账` + `01-全局扫描` ~ `08-验证用例`。

**深入**：`references/source/overview.md`（完整 SOP + 验收标准）
**查表**：`references/source/buckets.md`（分桶方法）· `views.md`（15 视角）· `commands.md`（检索命令）· `templates.md`（模板）· `antipatterns.md`（坑）

## 四、分支 B · 编译混淆产物还原（只有 dist）

**目标**：把混淆产物还原成**有结构、可读、能跑**的工程源码。`build 通过` 只是验证手段，不是目的。

**先选路径**（决策树，完整见 `references/bundle/toolchain.md`）：
1. 产物带 **`.map`** → `reverse-sourcemap` 直接还原源码，**可跳过整条流水线**
2. **打包产物**（webpack/vite/rolldown）→ 走下面主线
3. **通用混淆**（obfuscator.io / js-confuser）→ `restringer` / `js-defuser` / `synchrony`
4. **JSVMP** → 分支 C
5. **V8 字节码**（`.jsc` / bytenode / Electron）→ `View8`

**主线（打包产物）**：0 提取输入 → 1 生成工程（webcrack）→ 2 先构建（关卡）→ 3 可读化 → 4 静态冒烟门 → 5 后处理根治（`fix_esm.cjs` 五类修复）→ 6 再构建 → 7 真机验收。

**达成线（三条同时满足即停手）**：能构建 + 能加载 + 真机零应用级报错。
> **不要在"零 warning / 零 error"上无限打地鼠。**

**深入**：`references/bundle/overview.md`
**查表**：`toolchain.md`（工具选型）· `pipeline.md`（流水线）· `esm-fix.md`（五类修复 + 三案例）· `react-single-instance.md`（React 双实例）· `extension-anatomy.md`（浏览器扩展解剖）· `templates.md`（配置模板）· `pitfalls.md`（坑）
**工具链**：`scripts/`（`extract_input.cjs` + `pipeline/` + `verifiers/`）

## 五、分支 C · JS 运行时逆向

**目标**：定位接口签名 / 加密参数 / 风控字段，做页面取证、运行时采样、Node 补环境复现。

**核心原则**：Observe-first · Hook-preferred · Breakpoint-last · Rebuild-oriented · Evidence-first。

**五阶段**：Observe（观察取证）→ Capture（最小侵入采样）→ Rebuild（整理本地材料）→ Patch（按 first divergence 补环境）→ DeepDive（去混淆 / 控制流还原）。

**深入**：`references/runtime/overview.md`
**查表**：`runtime-signing.md`（签名定位 + 补环境 + 证据化输出）· `jsvm-deobfuscation.md`（JSVMP 识别 / opcode 提取 / 运行时捕获）

## 六、分支 D · Electron 应用逆向（最小版）

> ⚠️ 本分支**只收录单项目实证过的做法**，未经过多项目实战。带 `[待验证]` 的条目请自行核对。

**核心动作**：
1. **三层结构**：main（主进程）/ preload（桥）/ renderer（网页，通常是混淆打包的产物）
2. **读 preload 的 IPC 桥**（最有用的入口）：`contextBridge.exposeInMainWorld('api', {...})` 里每个方法 = 渲染层能用的宿主能力
3. **`window.api` mock**：渲染层脱离 Electron 时 `window.api` 为 undefined → 在 `index.html` 注入假 api 让它能跑
4. **原地补丁**：对已安装产物做锚点式替换 + 自动备份 + 幂等（不改源码）

**深入**：`references/electron/overview.md`（§1-2 三层结构与 IPC 桥 · §3-4 mock 与原地补丁 · §5 未覆盖清单）

> 未覆盖（**均未实战验证**）：asar 打包形态、主进程 CDP 交互、Electron 被第三方识别问题。

## 七、自我进化（复盘闭环）

> 本技能不是静态文档：**每次任务都是一次进化机会**。闭环 = 复盘 → 沉淀 → 晋升 → 注入 → 记账。
> 完整机制见 `references/evolution/overview.md`。

**触发点**（三处，任一即触发）：

| 时机 | 动作 |
|---|---|
| **开工前** | 读 `references/evolution/lessons.md` 活跃条目 → 注入已知坑 |
| **任务中途** | 踩到新坑 / 学到新工具 / 发现旧结论被推翻 → **立即**记一条（不必等收尾） |
| **任务收尾** | 过「复盘三问」→ 有新增就落库；无新增就更新命中条目的「命中次数」 |

**复盘三问**：

| # | 自问 | 落库到哪 |
|---|---|---|
| 1 | 哪一步**白干 / 走错路**了？根因是什么？ | 现象 + 根因 + 修法 |
| 2 | 有**新工具 / 新命令 / 新判据**是这次才学会的？ | 修法·判据（可直接复用） |
| 3 | 有**旧结论被推翻**，或 `[待验证]` 被证实 / 证伪？ | 更新原条目置信度 |

**沉淀格式**（一条一记录，**唯一键去重**）：
`references/evolution/lessons.md`，字段 = `ID / 日期 / 分支 / 类型 / 唯一键 / 现象 / 根因 / 修法·判据 / 置信度 / 命中次数 / 状态`。
> 可用 `scripts/evolve.cjs` 自动去重写入：`node scripts/evolve.cjs add --key <唯一键> ...`

**晋升规则**（经验 → 技能正文，满足任一即晋升）：

| 条件 | 动作 |
|---|---|
| 同一唯一键**命中 ≥2 次**且均复现 | 晋升进对应分支的 `pitfalls.md` / `antipatterns.md` / `toolchain.md` |
| 一次命中即造成**路径作废 / 数据损坏 / 不可回滚**级事故 | 高危，直接晋升 |
| 四分支都装不下的场景 | 记 `类型=分支缺口`；命中 ≥2 次则在「场景分流」表**新增分支**，并新建 `references/<新分支>/overview.md`（起步一律带 `[待验证]` 标头） |

**防退化**（技能不许越改越乱）：

| 风险 | 约束 |
|---|---|
| 重复堆积 | 唯一键去重，同键只累加命中次数，不新增行 |
| 表无限增长 | 活跃条目 > 80 行时，`已归档/已废弃` 移入 `references/evolution/archive/` |
| 改坏技能 | 每次只动 1~2 处；改前先在 `changelog.md` 记「意图」；**禁止删除 `.codebuddy` 内容** |
| 新旧结论冲突 | 以有实证一方为准；双方都无实证 → 都标 `[待验证]` 并记「待裁决」 |
| 把推测当经验 | lesson 只写**实际遇到的**，不写「可能会」；置信度必填 |
| 泄漏目标隐私 | 不记密钥 / token / 用户数据，只记方法与现象 |

**记账**：任何对技能自身文件（`SKILL.md` / `references/` / `scripts/`）的修改，写入 `references/evolution/changelog.md`（版本 + 日期 + 改动 + 依据 lesson ID + 回滚点）。

**完成判据（复盘自检）**：

- ✅ 复盘三问过完；有新增则已落库，无新增则已更新命中次数
- ✅ 每条 lesson 有 唯一键 + 置信度 + 日期
- ✅ 动了技能自身文件 → changelog 有对应记录
- ✅ 所有 `[待验证]` 条目都写了「验证方法」

## 九、常见坑（最高频）

> 各分支的完整坑表见对应 `antipatterns.md` / `pitfalls.md`。

1. **选错路径**——先分流；有 `.map` 却去跑整条反混淆流水线是最大浪费。
2. **照搬示例**——分桶、工具选型都要按**当前目标**重新推导，示例只是参考。
3. **把推测当事实**——每条结论标 `[确证]` / `[推断]` / `[待验证]`。
4. **口径漂移**——用唯一键计数，不用行数/关键词。
5. **无限打地鼠**——到达"达成线"就停手。
6. **先搭骨架后问架构**——逆向文档只是**第一步**；**架构与契约定稿前写实现代码 = 必返工**（`L-0010`）。动手前先过「交付门禁」。
