# 常见坑 & 反模式（随时对照）

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | **照搬示例桶** | 直接套用参考项目的 11 个桶，不按本项目推导 | Phase 1 用 `buckets.md` 的校准方法重新推导 |
| 2 | **口径漂移** | 宣称"挖完了 15 个 Skill"但用行数/关键词计数，实际有遗漏 | 每个分类用**唯一键**（文件名/表名）计数，Σ 桶内文件数 = 总数 |
| 3 | **范围失控** | 一次想挖完所有细节，每个文件逐行读，迷失在 10000+ 行里 | 先定界（Phase -1）+ 先粗后细，超预算就挂起 |
| 4 | **跳过配置层** | 只看"怎么调用"不看"调用边界"，复刻时参数超限被拒 | Phase 3 必须做 |
| 5 | **单一视角盲区** | 只看 AI 能力维度，没看状态机/并发模型，复刻时才发现 race condition | Phase 4 必须做 P0 五个视角 |
| 6 | **攒着不落盘** | 挖了 5 个桶才开始写文档，上下文丢了忘了细节 | 每挖完一个桶立即落盘到 `03` |
| 7 | **混淆同步异步** | 把视频提交做成同步 API，用户浏览器超时 | Phase 4 异步边界视角先搞清楚 |
| 8 | **忽略凭证来源** | 复刻时不知道 API key 从哪来，硬编码导致安全问题 | Phase 3 凭证来源必须搞清楚 |
| 9 | **复用过度** | 原项目的四层 hash / CAS claim / revision 防并发全照搬，个人应用不需要 | 按需裁剪 |
| 10 | **只抄 prompt 不提规则** | prompt 全文抄了，但没提炼背后的业务规则，换模型/场景就废 | Phase 5 把 prompt 拆成"模板 + 注入 + 规则" |
| 11 | **没有验证基准** | 复刻完了凭感觉说"差不多"，无法证明一致 | Phase 6 建 golden sample + 判据 |
| 12 | **忽略长任务时间维度** | 复刻时把长任务当同步处理，或没有取消/恢复/进度 | Phase 4 长任务生命周期视角必须先挖 |
| 13 | **成本失控** | 复刻时没看限流/配额，账单爆炸或撞上游限速 | Phase 4 成本与配额视角 + Phase 3 模型边界表 |
| 14 | **硬编码环境差异** | 本地跑通云端挂，密钥/路径/端口写死 | Phase 3 环境可复现性：列出 `.env` 清单 |
| 15 | **只挖 service 漏零件** | 复刻时发现依赖的 util/中间件/基类没记录 | Phase 0 依赖闭包扫描 |
| 16 | **把推测当事实** | 文档里"它应该是这样"和"代码里确实这样"混在一起 | 每条结论标 `[确证]`/`[推断]`/`[待验证]` |
| 17 | **交付物无法追溯** | 文档写得很满，但没说覆盖多少、基于哪个版本、还差什么 | 文档头带覆盖度 + 版本锚定 + 进度台账 |
| 18 | **假设目录结构** | 一上来就按 `backend/services/` 检索，项目结构不同就全崩 | Phase -1 先探测实际路径，写进台账 |
| 19 | **拿不到数据硬编** | 跑不起项目却把猜测写成确证 | 执行约定 2：一律标 `[待验证]` + 方法 |
| 20 | **同一信息写两处** | 元数据/验收标准在 SKILL 和 references 各写一遍，改一处忘一处 | 信息只存一处：规则在 SKILL，模板在 templates |
