# 签名定位与 Node 补环境（五阶段详解）

> 移植自通用逆向库的 `js-reverse`，已剥离 MCP / 路由依赖，工具名做了泛化。

---

## 1. Observe — 观察取证

目标：先确认**目标请求、相关脚本、候选函数**，不猜环境。

动作：
1. 打开目标页面（DevTools / CDP / Playwright）
2. 列网络请求，找目标请求（如登录、下单、带签名的 XHR/Fetch/WS）
3. 回溯 **initiator**（请求是从哪个脚本、哪一行发出的）
4. 列脚本 / 在源码里搜索关键字，缩小可疑脚本范围

必须产出：
- 目标请求 URL 或特征
- initiator 线索
- 可疑脚本 URL
- 初始任务记录

---

## 2. Capture — 最小侵入采样

目标：拿参数样例、调用顺序、运行时证据。

优先级（从高到低）：
1. **请求断点**（在 XHR/Fetch 发送处暂停）
2. **轻量运行时求值**（在控制台调用候选函数、打印入参返回值）
3. **文本断点**（在可疑函数定义处下断）

命中后：先看暂停上下文（调用栈 / 局部变量），再决定下一步。

---

## 3. Rebuild — 整理成本地材料

目标：把页面证据整理成**本地可迭代的 Node 复现材料**。

- 提取目标函数及其依赖链
- 记录它读取了哪些宿主对象（`window` / `document` / `navigator` / `crypto` / `localStorage` …）
- **不允许空想式补环境**——只记录"页面观测确实用到"的对象

---

## 4. Patch — 补环境（核心）

### 补环境规则
- 只补**页面证据已经证明需要**的对象
- 一次补一个**最小因果单元**
- 顺序：**先补值 → 再补函数壳 → 再补返回对象契约**
- 每次补丁后**重新执行**，看 **first divergence** 是否前移

### Node 复现默认顺序
1. 导入目标脚本
2. 最小 shim 宿主对象
3. 跑入口函数
4. 记录**首个异常或 first divergence**
5. 回到页面证据补齐缺口

> 循环 3~5，直到本地稳定跑出与页面一致的目标参数。

---

## 5. DeepDive — 深挖

本地跑通后，若需要**长期复用算法链路**，再做：
- 去混淆（AST 变换 / 字符串数组还原）
- 控制流平坦化还原
- 业务逻辑提纯
- 若目标是 JS 自定义 VM → 转 `jsvm-deobfuscation.md`

---

## 6. 证据化输出

每个任务建议产出：
- **目标**：要复现的请求/参数
- **链路**：initiator → 脚本 → 函数 → 关键分支
- **补丁记录**：每次补了什么、为什么、first divergence 变化
- **验证**：本地输出 vs 页面输出的对比
- **回退**：失败时的回退路径

---

## 7. 常见回退

| 卡点 | 回退方向 |
|---|---|
| 断点命中不了 | 换请求断点；或先 Hook 关键 API 观察 |
| 补环境越补越乱 | 回到页面重新取证，确认遗漏的宿主对象 |
| 算法看不懂 | 先去混淆，再读逻辑 |
| 参数与页面不一致 | 检查时间戳/随机数/环境指纹差异 |
