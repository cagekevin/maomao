# 自我进化（复盘闭环）

> 技能的价值不在"第一次写得多全"，而在"用得越久越准"。本文定义这条进化回路怎么转。

---

## 0. 一句话

**每次任务收尾时，把"这次才学会的东西"写回技能自己身上；下次开工时先读回来。**

没有这一步，技能就只是死文档——同一个坑会踩第二次。

---

## 1. 闭环五步

```
复盘（Review） → 沉淀（Capture） → 晋升（Promote） → 注入（Inject） → 记账（Changelog）
     ↑                                                                      │
     └──────────────────── 下次开工先注入 ←──────────────────────────────────┘
```

| 步 | 做什么 | 落到哪个文件 |
|---|---|---|
| 复盘 | 过「复盘三问」，产出候选条目 | ——（脑内/对话内） |
| 沉淀 | 候选条目按固定字段写进经验库，唯一键去重 | `lessons.md` |
| 晋升 | 达标的条目提炼进分支正文（坑表 / 工具选型 / 判据） | 各分支 `pitfalls.md` / `antipatterns.md` / `toolchain.md` |
| 注入 | 下次开工先读活跃条目 + 相关分支正文 | `SKILL.md` 执行约定 5 |
| 记账 | 技能自身被改动的版本记录 | `changelog.md` |

---

## 2. 触发点

| 时机 | 必须做什么 | 为什么 |
|---|---|---|
| **开工前** | 读 `lessons.md` 的「活跃条目」表 | 已知坑先避开，别用一次任务重新发现 |
| **任务中途** | 出现新坑 / 新工具 / 旧结论被推翻 → 立即记一条 | 上下文一丢就忘了；"及时落盘"同样适用于经验 |
| **任务收尾** | 过「复盘三问」；有新增落库，无新增则命中次数 +1 | 保证回路闭合，且不写空条目 |

> 收尾复盘是**必做项**，不是可选项。它和 Phase 7「产出交付物」同级。

---

## 3. 复盘三问

| # | 自问 | 产出字段 |
|---|---|---|
| 1 | 哪一步**白干 / 走错路**了？根因是什么？ | 现象 / 根因 / 修法 |
| 2 | 有**新工具 / 新命令 / 新判据**是这次才学会的？ | 修法·判据（写成可直接复制的命令或判断规则） |
| 3 | 有**旧结论被推翻**，或 `[待验证]` 被证实 / 证伪？ | 更新原条目置信度（`[待验证]` → `[确证]` / `已废弃`） |

**没有收获怎么办**：不新增空条目，改为对本次命中的既有条目执行 `hit`（命中次数 +1）。命中次数本身就是晋升判据的数据来源。

---

## 4. 沉淀格式（lessons.md）

一条记录 = 一行，字段固定 11 列：

| 字段 | 取值 / 说明 |
|---|---|
| **ID** | `L-0001` 递增，全局唯一，**不复用** |
| **日期** | `YYYY-MM-DD` |
| **分支** | `A` / `B` / `C` / `D` / `G`（G = 全局、跨分支） |
| **类型** | `坑` / `工具` / `判据` / `分支缺口` / `反模式` |
| **唯一键** | **去重与晋升的依据**。形如 `<域>/<短名>`，如 `bundle/webcrack-native-code`、`skill/one-branch-at-a-time`。同键只保留一行 |
| **现象** | 我实际看到什么（报错原文 / 真机表现 / 耗时浪费） |
| **根因** | 为什么会这样 |
| **修法·判据** | 下次怎么绕 / 怎么判（可执行优先：命令、正则、检查点） |
| **置信度** | `[确证]`（≥1 次实证）/ `[推断]`（有依据未实证）/ `[待验证]`（未验证，**必须附验证方法**） |
| **命中次数** | 该键被再次遇到的次数，用于晋升判据 |
| **状态** | `新增` / `已晋升 → <目标文件>` / `已归档` / `已废弃` |

**写入方式**：

```bash
# 推荐：用脚本写入（自动去重 + 自动编号 + 自动累加命中次数）
node scripts/evolve.cjs add --branch G --type 坑 --key bundle/xxx \
  --symptom "现象" --cause "根因" --fix "修法" --confidence 确证

# 无新增、只是又遇到了同一个坑
node scripts/evolve.cjs hit --key bundle/xxx
```

也可以手写表格行，但**必须**与既有行格式完全一致（11 列），否则解析会错位。

## 5. 晋升流程（经验 → 技能正文）

**晋升判据**（满足任一）：

1. 同一唯一键 **命中 ≥2 次**且两次都复现 → 晋升。
2. 一次命中即造成**路径作废 / 数据损坏 / 不可回滚**级事故 → 高危，直接晋升。
3. 结论从 `[待验证]` 变 `[确证]` → 更新原条目置信度，并同步到它所属的分支文件。

**晋升操作（四步，别跳）**：

1. `node scripts/evolve.cjs promote --key <唯一键> --target references/bundle/toolchain.md`
2. 打开目标文件，把这条经验按**该文件的既有体例**写进去（坑表加行 / 工具选型加条目 / 判据加检查点）——**不是把 lessons 整行粘过去**。
3. 若是"工具/命令"类，同时考虑补进 `references/*/commands.md` 或 `scripts/`。
4. 记一笔 `changelog.md`（版本 + 依据 lesson ID + 回滚点）。

> 晋升后 lessons 行**保留**，状态改为 `已晋升 → <目标>`：经验库是历史，正文是成品。

## 6. 分支缺口（技能自身的扩张）

遇到四条分支都装不下的场景（例：PyInstaller / Nuitka 打包的 Python 产物、移动端 App、WASM 反编译）：

1. 先记一条 `类型=分支缺口` 的 lesson，写清"为什么现有分支不行 + 临时怎么凑合"。
2. 命中 ≥2 次，或明确高价值时：在 `SKILL.md`「场景分流」表加一行「**分支 E · …**」，并新建 `references/<新分支>/overview.md`。
3. **新分支起步一律带 `[待验证]` 标头**（沿用分支 D 的做法：只收录实证过的做法，未实证的标注清楚）。
4. 记 changelog（版本号 minor +1）。

---

## 7. 防退化（技能不许越改越乱）

| 风险 | 约束 |
|---|---|
| 重复堆积 | 唯一键去重；同键只累加命中次数，不新增行 |
| 表无限增长 | 活跃条目 > 80 行 → 把 `已归档 / 已废弃` 移到 `references/evolution/archive/lessons-<yyyy>.md`（`node scripts/evolve.cjs archive`） |
| 改坏技能 | 每次只动 1~2 处；改前先在 `changelog.md` 记「意图」；**禁止删除 `.codebuddy` 内容** |
| 新旧结论冲突 | 以有实证一方为准；双方都无实证 → 都标 `[待验证]` 并记「待裁决」 |
| 把推测当经验 | lesson 只写**实际遇到的**，不写"可能会"；置信度必填 |
| 泄漏目标隐私 | 不记密钥 / token / 用户数据；只记方法与现象 |
| 复盘空转 | 无新增时不写空条目，改为 `hit` 累加命中次数 |

## 8. 复盘模板（收尾直接抄）

```
### 复盘（<日期> · 本次主攻分支 X）
- 白干/走错路：<现象 → 根因 → 修法>   → 唯一键 <key>，置信度 <确证|推断|待验证>
- 新工具/新判据：<可直接复制的命令或规则> → 唯一键 <key>
- 被推翻的结论：<旧结论> → 改为 <新结论>（更新 L-xxxx 置信度）
- 命中既有条目：<key1> +1、<key2> +1
- 晋升：<key> → <目标文件>
- 技能自身改动：<改了什么> → changelog v<x.y.z>
```

---

## 9. 边界（不要进化出问题）

- **不改"定位与使用边界"**：本技能始终是个人学习 / 复刻研究用；进化不能把它改成对外分发工具。
- **不写"目标项目业务秘密"**：经验库记的是**方法**，不是目标的数据。
- **不为进化而进化**：一次任务产出 0~3 条高质量 lesson 是正常值；凑数条目比没有更糟。
- **脚本只管机械活**：去重、编号、累加、归档交给 `evolve.cjs`；**判断（是不是坑、值不值得晋升）必须由人/Agent 做**。
