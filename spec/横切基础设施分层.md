# 横切基础设施分层（总纲）

> ⚠️ **过时警示**：本文件属"可选明细，不再扩展新内容"，**部分"现状"描述已与代码不符**。写码决策一律以 `spec/CONTEXT.md`（唯一决策地图）为准，机制以代码注释为准。已知过时处：§⑥ 工具层说 `utils.js` 待建（实际 `genId` 已落 `base/idGen.js`，其余待建）；§④ 持久化层未提 `contentStore` 为横切存储权威入口（见 CONTEXT §二④）。

> 定位：把项目里所有「横切机制」（toast / 日志 / 事件总线 / 存储键 / 错误处理 / 工具能力）组织成**清晰的分层**，让每类机制**只有一个权威入口、一种调用方式**。
> 本文件是**顶层框架**；各层的机制明细见对应文档；**代码事实是 `src/components/base/contracts.js`**（事件/存储键/错误登记表）。
> 写代码时先读本页 → 按层对号入座 → 调唯一入口。

## 一、七块划分（一个机制属于且只属于一层）

| 块 | 管什么 | 唯一入口 | 明细文档 |
|----|--------|---------|---------|
| ① 通信层 | 模块间「瞬时事件」广播 | `src/components/base/eventBus.js`（publish/subscribe） | `docs/实时总线-Event-Bus-全解` |
| ② 表现层 | 用户可见的即时反馈 | `src/components/base/toastStore.js`（toastSuccess/Error/Warning/Info） | `docs/07-Toast分级设计` |
| ③ 观测层 | 记录 + 上报，供排查 | `src/components/base/logger.js`（logger.info/warn/error） | `docs/09-日志系统统一收口` |
| ④ 持久化层 | 数据存取（内存/本地/后端） | `storageAdapter` + `*Store`（useSyncExternalStore） | `docs/08-存储键集中登记` |
| ⑤ 能力层 | 业务能力工具（单一入口，复用优先） | `mediaType` / `clipboard` / `filesApi` / `imageCompress` / `imageUrl` ... | `docs/CODING-STANDARD §一` |
| ⑥ 工具层 | 通用纯工具（ID/时间/拷贝/节流），无业务语义 | `src/base/utils.js`（**待建**：genId/formatTime/deepClone/throttle/debounce） | 本文 §⑥ |
| ⑦ 下载层 | 文件下载/导出（fetch→blob→a.download） | `src/components/base/clipboard.js` 的 `downloadUrl`（已存在，收敛散落调用） | 本文 §⑦ |

**登记表**：`src/components/base/contracts.js` —— 跨切面「单一事实来源」的代码落点（事件注册表 / 存储键登记 / 错误类型登记），各层机制先查/先登记它。

> **分层依据**：⑥ 与 ⑤ 的区别 —— ⑤ 能力层是「有业务/领域语义」的工具（如 `detectMediaType` 判断媒体、`compressImage` 压缩），⑥ 工具层是「纯通用、无领域语义」的（如 `genId` 生成 ID、`formatTime` 格式化时间），任何人任何模块都可能用。分开避免 ⑤ 膨胀。

## 二、各层唯一入口与调用约定（禁止混写）

### ① 通信层 eventBus —— 只广播，不存状态、不做 UI、不记日志
```js
import { publish, subscribe } from './base/eventBus.js'
const off = subscribe('agent:task-completed', (payload) => {})
publish('agent:task-completed', { nodeId, resultUrl })
```
- 事件名统一「领域:动作」，**先登记到 `contracts.js` 的 EVENTS**。
- 发布方/订阅方**须成对**（`to` 为空是显式标注的「预留」，勿当 bug 删）。
- **不做**状态存储（归 store）、**不做** UI 提示（归 toast）、**不做**日志（归 logger）。

### ② 表现层 toast —— 只给用户看的即时反馈，不记日志
```js
import { toastSuccess, toastError, toastWarning, toastInfo } from './base/toastStore.js'
toastError('保存失败')      // 唯一调用方式，勿用 showToast('x', {type:'error'}) 混写
```
- 语义化 4 档（success/error/warning/info），**业务代码只调用这 4 个**。
- 底层 `showToast` 仅供 ToastContainer / 高级场景（`duration:0`、手动关闭）。
- **不做**记录上报（归 logger）。「既提示又记日志」的交互，业务层分别调 toast + logger，二者不互相替代。

### ③ 观测层 logger —— 只记录上报，供排查；封死裸 console
```js
import { logger } from './base/logger.js'
logger.info('生成', 'start', { nodeId, type })
logger.error('保存', 'fail', { error })
```
- **业务代码禁止裸 `console.log/warn/error`**（否则日志格式不统一、不上报后端、排障 grep 不到）。
- 只记录「高价值、不可还原」事件（生成 start/success/fail、错误、项目切换等），不记可从快照还原的结构操作。

### ④ 持久化层 —— 数据存哪，走 store + storageAdapter
- 底层 `storageAdapter`（localStorage / chrome.storage 抽象）是**唯一落盘入口**。
- 上层 `*Store`（taskStore / conversationStore / ...）管理状态 + `useSyncExternalStore`。
- **存储键一律走 `contracts.js` 的 STORAGE_KEYS 登记**（收敛中），**禁止散落字符串字面量**。
- **不做**事件广播语义（那是通信层）、**不做** UI 反馈（那是表现层）。

### ⑤ 能力层 —— 业务能力工具，单一入口，复用优先
- 每个能力一个文件、一个入口（如 `mediaType.detectMediaType`、`clipboard.copyImageToClipboard`）。
- **禁止**业务文件手写扩展名正则 / 手写 URL 拼接 / 手写 canvas 压缩等（见 CODING-STANDARD §一「功能单一入口」）。

### ⑥ 工具层 —— 通用纯工具（无业务语义），集中 `src/base/utils.js`（待建）
> 解决现状：ID 生成散落（`Date.now().toString(36)` ×6、`Math.random().toString` ×25、`crypto.randomUUID` ×3 并存）、时间格式化各写各的、无统一深拷贝/节流。设计为**集中入口**，消除各造各的。

```js
import { genId, formatTime, deepClone, throttle, debounce } from './base/utils.js'
```
- **`genId(prefix?)`**：唯一 ID 生成（内部 `crypto.randomUUID` 或时间戳+随机）。**禁止**业务文件手写 `Date.now().toString(36)` / `Math.random().toString`。
- **`formatTime(date?)`**：统一时间格式（供 logger / 展示）。**禁止**各文件手写 `padStart` 拼时间。
- **`deepClone(obj)`**：结构化深拷贝（`structuredClone` 或 JSON 兜底）。**禁止**手写 `JSON.parse(JSON.stringify(...))`。
- **`throttle` / `debounce(fn, ms)`**：统一节流/防抖。**禁止**各文件自造上报去重/高频抑制（如 logger 里的 `_lastReport`）。
- 原则：**纯函数、无副作用、无 React、无业务依赖**——任何模块都能安全 import。

### ⑦ 下载层 —— 文件下载/导出，唯一入口 `clipboard.downloadUrl`
> 解决现状：`downloadUrl` 已定义在 `clipboard.js`，但 5 个节点（ImageNode/PromptNode/VideoExtractNode/FaceMosaicNode/ImageBoxNode）仍各自 `createObjectURL + a.download` 实现。

```js
import { downloadUrl } from './base/clipboard.js'
await downloadUrl(url, filename)   // fetch blob → a.download
```
- **文件下载/导出一律走 `downloadUrl`**，禁止各节点自写 `createObjectURL + a.download`。
- 若需要"本地文件另存"等更强能力，**扩展 `downloadUrl`**，不要在节点里另起一套。

## 三、协作约定（谁该调谁，禁止越层）

```
业务代码 (components/*.jsx)
   ├─ 要弹提示      → 调 ② toast（只表现，不记日志）
   ├─ 要记日志      → 调 ③ logger（只记录，不弹提示）
   ├─ 要广播事件    → 调 ① eventBus（只广播，不存状态）
   ├─ 要存取数据    → 调 ④ store/storageAdapter
   ├─ 要算/转换     → 调 ⑤ 能力层（有业务语义）
   ├─ 要通用工具    → 调 ⑥ utils（genId/formatTime/deepClone/throttle，无业务语义）
   └─ 要下载/导出   → 调 ⑦ clipboard.downloadUrl
```

**禁止**：
- ❌ toast 里写日志 / logger 里弹 toast（职责串层）
- ❌ 业务代码裸 `console` / 裸 `localStorage` / 手写正则 / 手写 URL 拼接 / 手写压缩 / 手写 ID 生成 / 手写下载（绕过对应层）
- ❌ eventBus 存状态 / store 发事件（状态与事件两套混淆）
- ❌ 手写 `Date.now().toString(36)` / `Math.random().toString` 造 ID（走 ⑥ `genId`）

## 四、契约登记表 `contracts.js`（代码单一事实来源）

`src/components/base/contracts.js` 是横切层的「登记表」，含三块：
- **EVENTS**：事件注册表（事件名 / 发布方 / 订阅方 / 载荷 / 用途）—— 已基于真实代码建立（7 事件）。
- **STORAGE_KEYS**：存储键登记（收敛起点，当前各 store 散落，逐步收拢）。
- **GEN_ERRORS**：错误类型登记（收敛起点）。

**用法**：新增机制（事件 / 存储键 / 错误类型）→ 先在 `contracts.js` 登记 → 再实现。机制文档从它派生，代码与登记表对齐，避免"文档说一套、代码做一套"。

## 五、收敛纪律（渐进，不批量重构）

> 原则（对齐 CODING-STANDARD §四）：**先规范、后重构；渐进收敛、别强行批量。**
- 新增代码一律按本页分层 + 唯一入口写。
- 存量不一致（裸 console / showToast 混写 / 存储键散落）**改到哪个文件顺手收敛哪个**，不为了"清零"强行批量。
- 每收敛一批跑 `npm run test:unit` 验证。

**当前收敛优先级**：
1. 🔴 封裸 console（观测层，10+ 文件）——排障痛点，改法机械
2. 🔴 建 `utils.js`（工具层）并收 ID 生成（⑥，25+ 处 `Math.random` / `Date.now` 散落）——高频、易统一
3. 🟡 收 showToast 混写为语义化 4 档（表现层）
4. 🟡 收节点下载为 `clipboard.downloadUrl`（⑦，5 个节点绕过）
5. 🟡 存储键收拢到 STORAGE_KEYS（持久化层）
6. 🟢 eventBus 强制「先登记再发布」
