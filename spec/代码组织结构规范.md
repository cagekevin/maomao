# 代码组织结构规范（A 数据状态 / B Hooks / C 配置 / D 组件目录）

> 定位：规范「代码怎么组织」的四个层面——**状态放哪、hook 怎么分、配置怎么集中、组件放哪个目录**。与 `docs/横切基础设施分层.md`（横切机制）互补：那篇管"机制怎么调"，这篇管"代码怎么摆"。
> 写代码时先读本页 → 对号入座 → 按规范落位。

---

## A、数据状态层（状态放哪的决策规范）

### 现状
- 全局 store 8 个（taskStore/conversationStore/projectStore/assetStore/backupStore/skillStore/toastStore/kvStore）+ settings 下 4 个。
- **模式不统一**：taskStore/conversationStore/projectStore/assetStore/accountsStore/providerStore 用 `useSyncExternalStore`；backupStore/kvStore/skillStore/toastStore/agentModelStore 不用。
- 18 个 hooks + 各节点组件，状态分散，无统一决策规则。

### 决策规范：状态放哪，先回答这 3 问

```
Q1 这个状态需要「跨组件共享」吗？
   ├─ 是 → 进 store（全局）
   ├─ 否 → Q2
Q2 需要「持久化」（刷新/重启不丢）吗？
   ├─ 是 → store + 持久化层（storageAdapter）
   ├─ 否 → Q3
Q3 只属于单个组件内部、临时？
   └─ 是 → 组件内 useState（局部）
```

**结论矩阵**：

| 状态特征 | 放哪 | 例子 |
|---------|------|------|
| 全局共享 + 需持久化 | **store**（useSyncExternalStore） | taskStore 任务列表 |
| 全局共享 + 不持久化 | **store**（内存态） | toastStore 当前提示 |
| 单组件 + 内部临时 | **useState** | 节点面板展开/收起 |
| 跨组件但单点（桥接） | **hook** 封装 | useConnectedInputs |
| 派生/计算 | 不用 state，`useMemo`/纯函数 | — |

### 新建 store 的规范（统一模式）
```js
// 统一结构：模块级状态 + subscribe + useSyncExternalStore 快照 + 变更通知
let state = []                 // 模块级唯一状态
const listeners = new Set()
function notify() { listeners.forEach((l) => l()) }
function subscribe(cb) { listeners.add(cb); return () => listeners.delete(cb) }
function getSnapshot() { return state }          // 缓存引用，避免无限重渲染
export function useXxx() { return useSyncExternalStore(subscribe, getSnapshot, getSnapshot) }
```
- **遵循**：状态只能经导出函数改（`addXxx`/`updateXxx`），组件不直接改模块变量。
- **快照缓存**：getSnapshot 返回的引用要稳定（变更时才换新引用），否则 useSyncExternalStore 无限重渲染。
- **持久化**：需要落盘的在变更处同步调 storageAdapter（fire-and-forget）。

### 禁止
- ❌ 组件内 `useState` 存「本应全局共享」的数据（会导致多处不一致）。
- ❌ 组件直接改模块级变量（绕过导出函数）。
- ❌ 同一状态既放 store 又用 useState 复制一份（双份真相）。

## B、Hooks 层规范（18 个 hooks 分类落位）

### 现状
`useAgentChat / useArrangeCanvas / useAssetDragToCanvas / useAssetDropPaste / useCanvasAgentTools / useCanvasHistory / useCanvasShortcuts / useConnectedInputs / useContextMenu / useFitNodeRatio / useLocalToolStatus / useLod / useMediaDegrade / useNodeGeneration / useScriptBoxData / useScriptBoxEngine / useSyncNodeData / useVideoPoster` 平铺在 base/。

### 分类规范（每个 hook 属于且只属于一类）

| 分类 | 职责 | 命名/位置 | 例子 |
|------|------|----------|------|
| **数据桥接 hook** | 读 store → 暴露给组件 | `useXxx`（base/） | useConnectedInputs、useSyncNodeData |
| **交互 hook** | 绑定键盘/拖拽/右键/外部点击 | `useXxx`（base/） | useCanvasShortcuts、useContextMenu、useAssetDropPaste |
| **能力 hook** | 封装单一能力（媒体/封面/尺寸） | `useXxx`（base/） | useMediaDegrade、useVideoPoster、useFitNodeRatio |
| **引擎 hook** | 封装某业务引擎（脚本盒/生成） | `useXxx`（base/） | useScriptBoxEngine、useNodeGeneration、useScriptBoxData |
| **状态 hook** | 编排多 store 的高层状态（如 AI 助手会话） | `useXxx`（base/） | useAgentChat |

**规范**：
- 命名一律 `useXxx`，纯逻辑可单测（放 `tests/unit/useXxx.test.js`）。
- **hook 不写业务 UI**，只封装逻辑；组件负责渲染。
- **hook 内部**通过 store 的导出函数读写状态，不经 useState 复制全局状态（见 A 禁止项）。
- 新增 hook 前先看 B 分类表，判断属于哪类、有没有已有 hook 可复用。

## C、配置与环境变量层（集中，禁散落）

### 现状
无集中常量文件；`VITE_*` 环境变量（Agent 模型列表等）、魔法数字（超时、端口、默认值）散落在各文件（logger 的 REPORT_MIN_GAP、toastStore 的 DEFAULT_DURATION、各节点默认值等）。

### 规范：`src/components/base/config.js`（集中配置）

| 配置类别 | 放哪 | 约定 |
|---------|------|------|
| 后端地址/端口 | `apiBase.js`（已有，单一来源） | 禁止改端口 |
| 环境变量（`import.meta.env.VITE_*`） | **集中读一次到 config.js**，各文件 import | 禁止各处直接读 `import.meta.env` |
| 魔法数字/常量 | **config.js 命名常量**（如 `POLL_INTERVAL_MS`） | 禁止散落裸数字 |
| 默认值/超时/阈值 | config.js | 集中可查 |

```js
// src/components/base/config.js（示意）
import.meta.env.VITE_AGENT_MODELS?.split(',')   // 环境变量集中读
export const POLL_INTERVAL_MS = 5000             // 命名常量
export const GEN_CONCURRENCY_LIMIT = 6
```

**禁止**：
- ❌ 业务文件直接读 `import.meta.env.VITE_*`（散落）。
- ❌ 魔法数字裸写（如 `setInterval(check, 5000)` 里的 5000 应命名常量）。

## D、组件目录规范（渐进落位）

### 现状
`src/components/` 顶层平铺：25 个节点组件 + AgentMessage/AgentPanel + Comet 等，与 `base/` 基座混合，无子目录分层。

### 规范（目标结构，渐进迁移，不强制批量）
```
src/components/
├── nodes/         # 业务节点组件（TextNode/ImageNode/PromptNode/...）
├── panels/        # 面板（AgentPanel/设置面板/任务中心 TaskCenter/...）
├── scriptbox/     # 剧本盒子子模块（已有 StepShots/StepAssets/StepPrompt/GearSettings）
├── base/          # 基座组件 + 横切机制（NodeShell/CustomHandle/eventBus/toastStore/logger/...）
├── edges/         # 连线特效（ConnectionLine/CustomEdge/CustomHandle）——已有
└── App.jsx
```
**规范**：
- 新增组件先判断属于哪类，放对应子目录；**不新增平铺在顶层**。
- `base/` 只放「基座/横切」，不放业务节点。
- 存量平铺组件**改到哪个顺手迁到哪**，不强行批量（对齐「渐进收敛」纪律）。

## 四个层面与横切层的关系（总览）

```
组件层 D（放哪）→ 状态层 A（数据放哪）→ Hooks 层 B（逻辑放哪）→ 横切机制（怎么调）
                                            ↑
                                       配置层 C（常量/环境集中）
```

- **A 决定状态归属** → B 决定逻辑封装 → D 决定文件落位 → 横切层决定机制调用。
- C 是所有层共享的"常量真相"。
- 四篇规范 + `docs/横切基础设施分层.md` 构成「代码组织结构 + 横切机制」的完整规范体系。

---

## 收敛纪律（渐进，不批量）
- 新增代码一律按本页 A/B/C/D 落位。
- 存量不一致（store 模式不一 / hooks 平铺 / 魔法数字散落 / 组件平铺）**改到哪个文件顺手收敛哪个**，不强行批量。
- 每批收敛跑 `npm run test:unit` 验证。
