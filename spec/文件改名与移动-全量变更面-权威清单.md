# 文件改名 / 移动：全量变更面（权威清单）

> 状态：生效 · 版本：2.0 · 日期：2026-08-29
> 覆盖度：12 项中 **8 项有断言闭环**、2 项（#4 #5）无测试护栏、**2 项（#6 #7）已知可接受**。
> 适用范围：素材库 / 生成面板里对「本地文件型资源」做**改名（rename）**或**移动归类（move）**时，身份（文件名 / url / 目录）一旦变化，**凡引用它身份的所有地方都必须同步**，否则下游读取 404 / 破图 / 旧引用失效。

## 0. 本文档怎么用

**本文档自身不"权威"，权威来自可执行断言。** 规矩三条：

1. **每条变更面必须落到一处可执行断言**（某个测试用例名 / 某个 `npm run check:*`）。断言不存在 → 该条状态最高只能标 ⚠️，不得标 ✅（见 §2 状态列）。
2. **引用锚点用符号名，不用行号**：`handleMove` / `handleResourcesRename` / `applyResourceIdentityChange` / `rewriteUrlReferences`。行号会漂移，`EVENTS` 登记表里的行号由 `check-events.mjs` 自动校验，不靠人工维护。
3. **改名与移动是同一件事**（都是"资源 url 身份变了"），两条链路必须**对称**。任何一侧多/少一步，先当缺陷处理，直到给出正当理由（见 §3）。

状态符号：

| 符号 | 含义 | 标 ✅ 的前提 |

| ✅ | 已闭环 | 有断言兜底且当前通过 |
| ⚠️ | 已实现但无护栏 | 逻辑对，但无断言，回归时不会报警 |
| 🟡 | 已知可接受 | 已写明代价与"为什么可接受" |

## 1. 核心原则（设计与评审一票否决）

> URL 与文件名强耦合：**只要改了文件名或所在目录，就等于改了这个资源的全量身份**。
> 「改名/移动」不是"改一下磁盘文件名"，而是**触发一次全库 + 全前端内存的 url 引用改写**。

- **后端是唯一权威**：磁盘 + `resources` 表由后端单一持有。身份变更必须一次性把库内所有存了旧 url 的地方改写正确。
- **前端只做一次来自权威的轻量同步**：经 eventBus（`resource:renamed`）通知当前打开页面，改写内存态；**不建第二套权威，不轮询**。
- **唯一入口**：改名与移动共用同一个"改身份"函数，禁止各写一份。
- **改写必须落盘**：sql.js 改的是内存态，不触发 `debouncedSaveDb()` 就不算完成。
- **写入必须判重**：`fs.renameSync` 在 POSIX 上是"目标存在即静默覆盖"，任何直接调它的入口都必须先判目标是否存在。
- 落后目录/存储层新增入口时，先对照本清单；漏一处 = 下游一处 404。

## 3. 唯一入口与对称性

改名与移动是同一件事的两副马甲。**两者必须调用同一个函数，不存在"各实现一遍"的余地**：

```
localTool/src/routes/resources.ts
  export async function applyResourceIdentityChange({ oldRel, newRel, newName? })
```

单次调用完成的六步：

| 步骤 | 说明 |
|---|---|
| 1 | `resolveUploadFile` 解析 src/dst → 非法（含 `.`/`..`/越出 uploads）返回 null → 抛 400 |
| 2 | dst 已存在 → 抛 409（**禁止静默覆盖**） |
| 3 | `ensureDir` + `fs.renameSync` |
| 4 | resources 表：有旧行则迁移（保留 `is_favorite` 等全部元数据，只换身份字段）；无旧行则按 rescan 规则补建 |
| 5 | `rewriteUrlReferences(db, oldRel, newRel)` 改写 kv + tasks |
| 6 | `debouncedSaveDb()` |

调用方只做"解析参数 + 转错误码"：

- `handleResourcesRename`（`resources.ts`）：查行 → 判 `source/type` → 拼新文件名 → 调唯一入口
- `handleMove`（`files.ts`）：取 `src/dst` → 调唯一入口

**错误透传**：唯一入口抛 `HttpStatusError(status, message)`（`helpers.ts`），路由层原样转 `sendError`，禁止改写成泛化消息——前端 `extractErrorDetail` 会把 message 透到 toast。

**依赖方向**：`files.ts → resources.ts → {database, fileStore, orphanGc}`，单向无环。

### 资源 id 规则（硬约束）

`resourceIdOf(relPath)` = `local-${folder}-${name}`（顶层 folder 为空 → `local-${name}`）。

**rescan 录入与身份变更必须共用这一个函数**。若身份变更自造 id，rescan 再扫到同文件时会因 id 不同重复录入 → 素材面板重复显示同一张图。由断言「rescan 不得重复录入」守着。

## 4. 覆盖机制的关键实现点

- **后端统一改写** `rewriteUrlReferences(db, fromRel, toRel)`（`localTool/src/db/database.ts`）
  - 覆盖 `kv.value`（画布/脚本箱/d3d 快照）+ tasks 的 url 承载列。
  - **必须同时改写「原样 / URL 编码」两态**（中文/空格文件名尤其）：`raw 绝对`、`raw 相对 /files/…`、`encodeURI 绝对`、`encodeURI 相对`。
  - 边界：它**不改写 `resources` 表本身**（由唯一入口重建行），也**不落盘**（由唯一入口调用 `debouncedSaveDb()`）。

- **前端内存同步** 两个订阅方共用 `imageUrl.js` 的同一对工具，禁止各写一份：
  - `buildUrlRewritePairs(oldUrl, newUrl)` 生成上述四态 (from,to) 对
  - `replaceUrlDeep(data, from, to)` 递归改写；无变化返回原引用，便于判脏
  - 订阅方 A：`App.jsx` → 改写 ReactFlow `nodes` → `setNodes` 落盘
  - 订阅方 B：`taskStore.js` → 改写内存任务 `resultUrl` → `notify()`
  - 事件名 `resource:renamed`，发布/订阅须在 `contracts.js` 的 `EVENTS` 成对登记。

- **路径安全** `resolveUploadFile(rel)`（`localTool/src/utils/fileStore.ts`）
  - 只做防逃逸，**不做顶层根白名单**：白名单（`UPLOAD_ROOT_ALLOW`）是"新建目录防污染 uploads 根"的落盘侧策略，而移动的对象是**已存在的**目录，且 rescan 收录 uploads 下任意顶层子目录——加白名单会让存量未登记目录无法移动。
  - **不得对既有 basename 用 `sanitizeFilename`**：它会把空格变 `_`，含空格的既有文件会被判"不存在"。sanitize 只用于新产生的文件名。

- **编码解码对账**：静态 `/files/` 服务（`index.ts` handleStaticFile）与缩略图端点（`files.ts` handleThumbnail）都必须在 `url.pathname`/`query` 上 `decodeURIComponent`，与前端 URLSearchParams 的一层编码对账，否则中文/空格文件名双重编码后 404。

## 5. 必查约束（改动相关代码时逐条过）

1. **`renameSync` 有覆盖语义**：任何直接调它的入口必须先判目标存在。覆盖的危险性不止于丢文件——引用仍在（kv/tasks 仍指向该路径），引用感知 GC 判定"有人引用"而不回收，结果是**全库引用静默指向了另一张图的内容**，比 404 更隐蔽。
2. **移动不是"换个目录"那么轻量**：它与改名一样改变资源 url 身份，#2/#9/#10 一件都不能少。
3. **改写必须处理 URL 编码态**：脚本箱参考图存的是编码态（`%E5%A6%B9…`），只替换 raw 会漏。
4. **改完库必须落盘**：`rewriteUrlReferences` 改的是内存态 sql.js。
5. **resources 表必须始终反映磁盘**：不留"磁盘有文件、表内无行"的窗口（无旧行时按 rescan 规则补建）。
6. **新行 id 必须走 `resourceIdOf`**，与 rescan 严格对齐。
7. **改名剥后缀只认字母型**（`/\.[a-z]{1,5}$/i`）：用 `path.extname` 会把「图1.2」切成「图1」。
8. **改了事件发布/订阅侧的文件后必须跑 `npm run check:events`**：它校验行号漂移，且挂在 `pretest` 上——飘了会让 `npm test` 整体失败。

## 6. 代码无法挽回的两种情况

- **在唯一入口落地之前**已改名/移动产生的断引用：那次没触发改写，系统无从回溯「旧路径→新路径」，只能手动重新引用。
- **用户在本地 / 文件管理器 / 后端手动移动**文件（不走前端入口）：系统拿不到映射，旧 url 永久失效，只能重新引用。

## 7. 权威验收：可执行判定

一次改名/移动"真的闭环"，当且仅当：

1. 磁盘文件新位置存在，旧位置不存在。
2. resources 表是新 id/url/folder，且 **`is_favorite` 保留**。
3. 数据库中不再存在「旧 url」的引用（kv + tasks 全无残留，**含编码态**）。
4. 当前页面打开时，画布/脚本箱节点里不再存在旧 url（原样 + 编码态）。
5. 任务中心里的已完成任务，`resultUrl` 不再指向旧 url。
6. 用新 url 请求静态读 / 缩略图均 200。
7. 用这张图做图生图/图生视频能正常把参考图传到后端。
8. 上述 2/3 在**进程重启后依然成立**（验证落盘）。
9. 目标已存在时操作被拒（409），且源文件与目标文件都完好。

对应命令：

```bash
node --test localTool/test/localtool.test.js   # 后端：#1 #2 #3 #9 #10 #11（需先 npm run build，测试导入 dist）
npx vitest run tests/unit/taskStore.test.js    # 前端：#8
npx vitest run tests/unit/useAssetMoveToFolder.test.jsx  # 前端：#4 广播
npm run check:events                            # #12 事件契约（含行号漂移）
npm test                                        # 全量；pretest 会先跑 check:api + check:events
```

> **测试编写的硬约束（改这些断言前必读）**：
> - 落盘断言**不能**用「`closeDb()` 再重开」验证——`closeDb()` 内部会 `saveDb()`，把内存态一并落盘，掩盖"没调 `debouncedSaveDb()`"。
> - 落盘断言前**必须先调 `settleDb()`**：`debouncedSaveDb` 是模块级单例计时器，会跨测试泄漏，上个测试遗留的 500ms 计时器会在下个测试的目录里落盘（getDataDir 运行时读 env）。
> - 落盘断言的验证字符串**用 kv 引用承载**，不要依赖 resources 表行，否则表同步一坏落盘断言跟着红，分不清谁坏了。

| 改了这里 | 必须同步 |
