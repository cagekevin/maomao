# 文件改名 / 移动：全量变更面（权威清单）

> 状态：权威文档 · 版本：1.0 · 日期：2026-08-28
> 适用范围：素材库 / 生成面板里对「本地文件型资源」做**改名（rename）**或**移动归类（move）**时，身份（文件名 / url / 缩略图 / nodeId）一旦变化，**凡引用它身份的所有地方都必须同步**，否则下游读取 404 / 破图 / 旧引用失效。

---

## 1. 核心原则（供设计与评审一票否决）

> URL 与文件名强耦合：**只要改了文件名，就等于改了这个资源的全量身份**。
> 因此「改名/移动」不是"改一下磁盘文件名"，而是**触发一次全库 + 全前端内存的 url 引用改写**。

- **后端是唯一权威**：磁盘 + `resources` 表由后端单一持有；改名/移动 handler 必须一次性把「库内」所有存了旧 url 的地方改写正确（`rewriteUrlReferences`）。
- **前端只做一次来自权威的轻量同步**：通过 eventBus（`resource:renamed`）通知当前打开页面，把内存里的画布/脚本箱节点引用一并改写；**不建第二套权威，不轮询**。
- 落后目录/存储层新增入口时，先对照本清单；漏一处 = 下游一处 404。

## 2. 变更面逐项清单（改名 & 移动都要过一遍）

| # | 必须改动的位置 | 归属 | 改名 | 移动 | 覆盖机制 |
|---|---|---|---|---|---|
| 1 | **磁盘文件本体** | 后端 | `renameSync`（`resources.ts` handleResourcesRename） | `renameSync`（`files.ts` handleMove） | ✅ 原生 |
| 2 | **resources 表**（authoritative 清单：id/url/folder/name） | 后端 | 删旧行重建新行 | 靠 rescan 重录 + 孤儿清理旧行 | ✅ |
| 3 | **库内所有存旧 url 的引用**：画布 KV 快照（`canvas-state-v1-{projectId}`，含节点 data.url/imageUrl/images[].url、**脚本箱参考图 asset.imageUrl**、d3d）、tabtasks 各 url 承载列 | 后端 | `rewriteUrlReferences`（`database.ts`）覆盖 kv.value + tasks 各列，**raw / URL 编码 × 绝对 / 相对 四态** | 同左（`files.ts` 已接） | ✅ 核心 |
| 4 | **当前打开页面内存里的画布节点**（ReactFlow store：data.url/imageUrl/images[]/脚本箱 asset.imageUrl） | 前端 | `resource:renamed` 广播 → `App.jsx` 订阅 → `setNodes` 改写并自动落盘 | 同左（`useAssetMoveToFolder` 也广播） | ✅ 核心（前端 live 同步） |
| 5 | **素材面板当前列表项** | 前端 | `handleRename` 用 rename 返回的新 url 更新 `setItems` | `onRefreshed → reset(true)` rescan 重拉 | ✅ |
| 6 | **前端 textCache**（文字素材按 url 缓存内容） | 前端 | `textCache.delete(旧url)` | （未主动清；仅文字素材场景受影响，属良性） | 🟡 边界 |
| 7 | **缩略图缓存 `.thumbnails/`** | 后端 | 不主动清；卡片走 on-demand 缩略图端点，新 url 请求**现生成** | 同左 | 🟡 边界（非致命） |
| 8 | **其它按 url 做 key 的前端存储**（assetStore localStorage、@chips 里存 thumb/url） | 前端 | 不在本项目权威路径，未逐个对齐 | 同左 | 🟠 已知尾巴（需另行评估） |

### 覆盖机制的关键实现点

- 后端统一改写：`localTool/src/db/database.ts` → `rewriteUrlReferences(db, fromRel, toRel)`
  - 覆盖 `kv.value`（画布/脚本箱/d3d 快照）+ `tasks` 的 url 承载列。
  - **必须同时改写「原样 / URL 编码」两种形态**（中文/空格文件名尤其）：
    `raw 绝对`、`raw 相对 /files/…`、`encodeURI 绝对`、`encodeURI 相对`。
- 前端 live 同步：`src/App.jsx`
  - `buildUrlRewritePairs(oldUrl, newUrl)` 生成上述四态 (from,to) 对，`replaceUrlDeep` 递归改写节点 data。
- 事件登记：`src/components/base/contracts.js` → `EVENTS['resource:renamed']`
  - 发布方：素材面板 `handleRename` + 移动 hook `useAssetMoveToFolder`；订阅方：`App.jsx`。
  - **改名和移动共用同一事件**，因为二者都是"资源 url 变化"。
- 编码解码对账（避免 404 的隐性 bug）：
  - 静态 `/files/` 服务（`index.ts` handleStaticFile）与缩略图端点（`files.ts` handleThumbnail）都必须在 `url.pathname`/`query` 上 `decodeURIComponent`，与前端 URLSearchParams 的一层编码对账，否则中文/空格文件名双重编码后 404。

---

## 3. 落地时必查的"最容易漏"点

1. **移动也必须做前端 live 同步**（不只是改名）。漏掉 → 同一会话内画布节点仍指旧路径 → 图生图 404。
2. **前端改写必须处理 URL 编码态**，不能只改原样字符串——脚本箱参考图存的是编码态（`%E5%A6%B9…`），只替换 raw 会漏。
3. **缩略图端点必须 decodeURIComponent**（对齐静态服务），否则文件名含中文/空格时 `buildThumbnailUrl` 双重编码 → 404、以及"改名后没缩略图"的观感。
4. **数据库层 `rewriteUrlReferences` 的编码对要写全**（raw + encodeURI），否则只改原样、漏编码态。

---

## 4. 代码无法挽回的两种情况（文档留档）

- **修复落地之前**已改名/移动产生的断引用：那次没触发改写，系统无从回溯「旧路径→新路径」，只能手动重新引用。
- **用户在本地 / 文件管理器 / 后端手动移动**文件（不走前端拖拽入口）：系统拿不到映射，旧 url 永久失效，只能重新引用。

---

## 5. 权威验收判断

一个改名/移动操作"真的闭环"当且仅当：
1. 磁盘文件新位置存在，旧位置不存在。
2. resources 表是新 id/url。
3. 数据库中不再存在「旧 url」的引用（kv + tasks 全无残留，含编码态）。
4. 前端当前页面打开时，画布/脚本箱节点里不再存在旧 url（原样 + 编码态）。
5. 用新 url 请求静态读 / 缩略图均 200。
6. 用这张图做图生图/图生视频能正常把参考图传到后端。
