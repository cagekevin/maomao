# AI 助手表格 —— JSON 输出契约规范（标准范式）

> **状态：`现行规范`（2026-09-07 起生效）**
> 面向：任何要往「AI 助手表格」里灌结构化数据的人 / AI / skill 提示词。
> 用途：这是表格「预览 → 确认 → 写回」链路的**唯一数据源契约**。无论谁、用哪种模型、写哪个 skill，
>       只要产出要进入这张表，都按本文输出 JSON。
> 关联代码（真源，改前先读）：
>   - `src/components/agent/assistantTable/assistantTable.ts` → `AssistantTableJson` 接口、`tryParseAssistantTableJson`、`buildPreviewResult`
>   - `src/components/agent/assistantTable/assistantTablePrompt.ts` → `buildRefineRowsUser`

> 关联文档：`AI-ASSISTANT-TABLE-PROMPT-DESIGN.md`（意图与人格设计，互补勿混淆）

---

## 一、这份文档解决什么

表格协作的本质是：**模型对表格唯一能生效的手段，就是输出符合本契约的 JSON**（= 建表 / 改表）。
前端用 `tryParseAssistantTableJson` 探测回复里有没有「表格 JSON」，有才弹预览、才写回；没有就当普通文字。

所以**只要 JSON 不符合本契约，内容再对也不会进表**——这正是「解析不了」的唯一根因类别。
本文把契约钉死，让任何上游（人、AI、skill）有统一范式可学，避免再出现"顶层键叫 `assets` 于是整段被当成普通文字"这类静默失败。

## 二、唯一合法形状（契约）

```json
{
  "globalStyle": "全局统一风格（可选，字符串）",
  "rows": [
    { "列名1": "值1", "列名2": "值2" },
    { "列名1": "值3", "列名2": "值4" }
  ]
}
```

**铁律（少一条即解析失败）：**
1. 顶层必须是**一个 JSON 对象**（`{...}`），不能是数组、不能是字符串。
2. 顶层**必须含 `rows` 字段**，且 `rows` 是**数组**。`rows` 缺失或非数组 → 解析器直接 `return null`（当普通文字）。
3. `rows` 是**唯一**被识别的行数组键。叫 `assets` / `data` / `items` / `table` / `list` 等任何其它名字 → 一律不被识别 → 静默失败（见 §八 反模式 1）。
4. `globalStyle` 可选（字符串）。不给可留空字符串 `""` 或省略；**给了就照抄不改**（用户已有风格时不许擅自重写）。

> 数据层真源类型见 `assistantTable.ts` `AssistantTableJson`：
> `interface AssistantTableJson { globalStyle?: string; rows: Array<Record<string, unknown>> }`
> 即：`rows` 必填、每行是「列名 → 值」的字典。

---

## 三、字段级规范

### 3.1 `globalStyle`（可选，string）
- 整批内容的统一基调（美术风格 / 语气 / 约束），作用于全表。
- 用户已给则**原样照抄**；未给且确实需要时补一个合理默认；没有就留空。
- 若业务要求"纯中文"，则此处也必须是纯中文（不要混入英文术语）。

### 3.2 `rows`（必需，Array<Record<string, unknown>>）
- 行数组。每个元素是一行。
- 数组里**只允许对象元素**；非对象（如裸字符串、裸数字）会被解析跳过。
- 内容为**全空**的行会被丢弃（`rowHasText` 判定：所有单元格 trim 后为空）。

### 3.3 行对象（每行一个 `{ 列名: 值 }`）
- **键 = 列名**，由需求自行设计（表格不限定业务语义：分镜、清单、资产、设定图都行）。
- **值 = 单元格文本**。解析层一律按字符串处理（数字 / 布尔会被 `String(...)` 化），建议上游直接给字符串。
- 列名归一规则（解析层 `normalizeLabel`）：`trim` + **折叠连续空白为单个空格**。
  例：`"类 别"` 与 `"类别"` 会被视为同一列。→ **设计列名时别带多余空格**。
- 整表场景：所有行的列名应一致（首行出现的键决定列；后续行缺的键补空串）。
- 现存表追加 / 修改场景：行对象**只需含要填 / 要改的列**，未提及列保留原值（update 语义，见 §五）。

### 3.4 `_rowIndex`（定位元数据，不是列）
- 仅在「改已有某行」且**确切知道它在现状里的第几行**时使用。
- 值从 **1 起**（第 1 行 = `1`）。解析层 `extractRowIndex` 会剥出它用于精准定位，**绝不会当成一列存进表**。
- 拿不准行号**绝不乱加**（宁缺勿错）；不写时由前端按"当前处理/选中行"落位。

---

## 四、输出格式铁律

1. **纯 JSON，不要 Markdown 代码块包裹**（不写 ` ```json ` / ` ``` `）。
   - 解析器虽会剥围栏、截取首个 `{` 到末 `}`，但写围栏纯属多余且易诱发截断，强烈建议裸输出。
2. **一次回复只产出单个 JSON 对象**（建表 / 改行 / 追加，择一）。
3. **不要在 JSON 前后硬塞解释**：解析器只取 `{...}` 段，外围文字会被 `stripAssistantTableJson` 剥掉当普通对话；
   但若想让对话流额外说话，可放对象外，只是那部分不会进表。
4. 列名即键名：保持稳定、可读、无多余空白；后续同名即同列。
5. 单元格值给字符串；超长文本（如生图 prompt）直接放字符串里，不要拆数组。

## 五、三种输出语义（与 TABLE_RULES 决策对齐）

| 场景 | 输出内容 | 解析 / 写回行为（`buildPreviewResult`） |
| --- | --- | --- |
| **建整表**（当前表无列） | 完整 `rows`，每行含全部列 | `replace`：按 JSON 建列建行；全空行丢弃 |
| **改单行**（有选中行 / 已知行号） | **只输出那一行**对象，可带 `_rowIndex` | `update`：命中行只覆盖提及列，未提及列保留原值 |
| **追加**（往已有表加，无选中） | 按**现有列**输出新行对象（只填现有列名） | `append`：原样追加到末尾，现有列结构全保留 |

> 设计 skill / 写提示词时，按上表让用户意图落到对应语义，不要混（一次只一种操作）。

## 六、标准模板（直接复制给 AI / 写进 skill 提示词）

把下面这段作为你 skill 的「输出格式」段，要求被调用方**严格照抄结构**：

```
只返回可解析的纯 JSON，不要解释，不要 Markdown 代码块，不要在 JSON 前后加任何文字。
顶层对象必须含 "rows" 数组（每行一个对象，键=列名）；"globalStyle" 可选（字符串）。

{
  "globalStyle": "整批统一风格（可选；用户已给则照抄，未给可留空）",
  "rows": [
    { "列名1": "值", "列名2": "值" }
  ]
}

注意：rows 是唯一被识别的行数组键，禁止改名为 assets/data/items 等。
```

## 八、错误 / 反模式（务必避开）

### ❌ 反模式 1：顶层行数组叫 `assets` / `data` / `items` / `table`
```json
// 错误：解析器 tryParseAssistantTableJson 只认 rows → 返回 null → 预览不弹、写不进表
{ "globalStyle": "...", "assets": [ { "category": "...", ... } ] }
```
**根因**：契约硬性要求顶层键为 `rows`。你的领域若天然是"资产列表 / 清单 / 卡片数组"，
**把数组字段名统一叫 `rows`**，每个元素展开成「列名:值」对象即可，不要自创顶层键。

### ❌ 反模式 2：包了 ` ```json ` 代码块
```json
// 不推荐：虽能被剥围栏救回，但易诱发截断、且与铁律相悖，直接裸输出 {...}
```json
{ "globalStyle": "...", "rows": [ ... ] }
```
```

### ❌ 反模式 3：顶层是数组、或一次返回多个 JSON
```json
// 错误：顶层必须是对象；解析器取"首个 { 到末 }"，多对象会拼错
[ { "category": "..." } ]          // 顶层是数组 → 失败
{ ... }{ ... }                     // 多个对象 → 截取错乱
```

### ❌ 反模式 4：把 `_rowIndex` 当普通列填值
```json
// 错误：_rowIndex 是定位元数据，会被剥出，留在值里会成脏数据
{ "rows": [ { "_rowIndex": 2, "_rowIndex说明": "改第二行" } ] }   // 不要把它当业务列
```

### ❌ 反模式 5：行对象是裸值数组（无列名）
```json
// 错误：每行必须是"列名:值"对象，不能是值数组
{ "rows": [ [ "character", "@主角", "描述" ] ] }   // 无列名 → 无法映射到表
```

## 九、如何设计合规的 skill（给 skill 作者）

1. 在 skill 提示词的「【JSON 输出格式】」段，**直接引用 §六 标准模板**，不要自创顶层结构。
2. 你的领域模型若天然是"资产 / 清单 / 卡片 / 设定图数组"：
   - 把数组字段名**固定叫 `rows`**；
   - 每个领域对象**摊平成 `列名:值`**（如 `category`/`name`/`description`/`assetPrompt`）；
   - 多视角排版等"长文本"直接塞进对应单元格字符串，不拆子结构。
3. 列名设计：稳定、可读、无多余空格；跨次对话同名列才能对齐合并（`normalizeLabel` 只折叠空白，不翻译同义）。
4. 需要"精准改某一行"时教模型用 `_rowIndex`（1 起）；拿不准就别加。
5. `globalStyle`：若你的业务有"纯中文"硬约束，模板里写明，避免混入英文术语（见 §3.1）。

## 十、发版 / 交给 AI 前自检清单

- [ ] 顶层是**单个对象** `{...}`，不是数组
- [ ] 含 **`rows`** 数组（键名精确为 `rows`，不是 assets/data/items）
- [ ] 每行是**对象**，键 = 列名，值 = 字符串
- [ ] 没有 ` ```json ` 等 Markdown 围栏
- [ ] 需要精准改行时才加 `_rowIndex`（1 起），且没把它当业务列
- [ ] `globalStyle` 给了就照抄、没给留空；有"纯中文"约束则守中文
- [ ] 一次只做一种操作（建表 / 改行 / 追加）

## 十一、排错（解析不了先看这里）

| 现象 | 原因 | 对照 |
| --- | --- | --- |
| 回复有 JSON 但预览不弹、写不进表 | 顶层无 `rows`（叫了 assets 等）或顶层非对象 | §二 铁律 2/3、§八 反模式 1 |
| 表结构被撑变形 / 列对齐错 | 列名带多余空格、或追加行用了不存在的列名 | §3.3 归一规则 |
| 改行写错位置 | `_rowIndex` 缺失且选中行对不上 | §3.4、`AI-ASSISTANT-TABLE-PROMPT-DESIGN.md` §四 |
| 全空行没进表 | 行内所有单元格为空 | §3.2 `rowHasText` |
