# 闸与工具债（深水区）

## 一 · 先给手段排优先级 —— **闸是最后手段，不是首选**

| 优先 | 手段 | 什么时候已经够用 |
| --- | --- | --- |
| 1 | **结构上不可能** | 把入口收成唯一（接口收窄 / 类型收窄），"写两个真相"在结构上做不到 |
| 2 | **类型层** | 判别联合 / 字面量类型钉死契约，写错**编译不过** |
| 3 | **唯一入口 + 收口原语** | 该做的事只有那一个函数能做 |
| 4 | **对账测试（行为断言）** | 能在测试里跑出红来（含 `probe.mjs` 先红后绿） |
| 5 | **文档留痕（防重复劳动）** | 只是"别让后人再当债补" → 写进区域日志 + 账本足够 |
| 6 | **机器闸** | 以上都做不到，**且回潮代价高** |

**判据：能用 1–4 解决的，不许用 6。** 闸是"结构没守住时的止血带"，不是"结构守不住时的替代品"。

## 二 · 这六种闸**不要建**（每条都有本仓实证）

| # | 形态 | 长什么样 | 实证 |
| --- | --- | --- | --- |
| ① | **空转闸** | 几乎每次跑都是 ✅，谁也记不得它上次红是什么时候。**判别动作：人为注入一次违规，看它红不红**（不红 = 假绿，最危险；确属"几乎不发生" → 降级为注释或删掉） | `check-arch` 规则 4/6 在目录搬迁后**空转很久却照常绿灯**（TD-22-53）；`check-node-data` 解析器被打瞎后长期报「0 缺口」（TD-02-9） |
| ② | **过严闸** | 只认一种写法，**正确动作也被判红** → 把作者逼去写更糟的绕行（为过闸而重复 N 份 / 贴假标记 / 塞白名单文件） | `check:arch` 曾把作者逼到「文件头写严禁重写、正文内联重写 7 处」→ 漏 1 处 = 静默错 |
| ③ | **人人想绕的闸**（成本倒挂） | 合法通过成本 **>** 绕行成本 | 闸只判「标记是否存在」→ `// catch-ok:` 一句话即可绕过（实测 99 处标记中 7 处贴在非空 catch 上） |
| ④ | **声索范围靠人解释的闸** | 判据说"我只覆盖 X 类"，而 X 由**作者自己**解释 → 覆盖不足时最省力的修正是**改声索让它继续绿** | 闸漏 `toBlob` 族时改覆盖声明（"只覆盖同步族"）→ 该闸当日被裁定删除 |
| ⑤ | **把风格偏好包装成红线** | 用"红线"的语气守一个**默认值** | **拿不出 `CLAUDE.md` 级证据的闸 = 默认值，不是红线** |
| ⑥ | **无自检 / 无负例的闸** | 扫到 0 也打印 ✅；从没红过，也没人试过注入 → 绿灯**不构成证据** | TD-22-53 / TD-02-9 同款；`probe.mjs` 存在的全部理由 |

## 三 · 建闸前必答 6 问（**任一答不出 → 不建**）

1. **守什么**：拿得出 `CLAUDE.md` 级红线证据吗？（拿不出 = 默认值 → 不做闸）
2. **能不能不建**：结构 / 类型 / 唯一入口 / 对账测试里，有没有更根本的手段？（**有就用那个**）
3. **它上次会拦住什么**：能举出一个**已发生的真实案例**吗？（举不出 → 空转风险）
4. **红了之后作者知道做什么吗**：闸的输出里带「怎么修」吗？（不带 → 他必然绕）
5. **合法通过成本落在哪个动作上**：落在**高频动作**上（每加一个节点 / 每写一次 xxx 都要登记）→ **必被绕，直接不建**
6. **"我覆盖多少"可机器验证吗**：这句声索是**闸自己算出来的**，还是人写的？（人写的 → 覆盖不足时必被改声索，见形态④）

> **加闸是一次永久成本承诺** —— 此后每一次相关改动都要向它付费。**举证责任在"建"这一方**：说不清为什么要建，就不建。
> **加错闸 > 不加闸**：一道没人信任的绿灯，会让后人**不再查这条路**（假护栏比没有护栏更危险）。

## 四 · 判定要建之后的硬约束 / 闸的判据 / 删闸

**三条硬约束（缺一即未闭环）**：① **反向判据优先**（禁白名单清单）② **申诉口三问必须齐**（脚本头：**守什么**（红线/偏好）· **什么时候该改它** · **怎么改**；缺一即"形式主义闸"）③ **自带基数自检 + 负例探针**（证明它会红）—— **没有负例探针的闸 = 未验收**。

**闸的判据（改它之前先分类）**：

| 类型 | 例子 | 能否自行改 |
| --- | --- | --- |
| **红线闸**（机器化物理契约/唯一入口/安全/登记表一致性） | 端口 `18080` · `{code,data}` · `STORAGE_KEYS`/`EVENTS` 登记 · 循环依赖 · 写回唯一入口 | **不可绕、不可自行放宽** → 放宽须**交用户** |
| **结构偏好闸**（分层/目录白名单/命名） | `videoEditor/core` 可 import 哪些层 · `base/` 反不反向依赖业务域 | **可被"正确性/复杂度"证据推翻 → 架构师直接改** |

- **判据**：**拿不出 `CLAUDE.md` 级红线证据的闸，就是默认值，不是红线。**
- **闸的成本守恒律**：**任何闸的「合法通过成本」必须 ≤ 「绕行成本」**（否则这道闸就在生产它本要禁止的行为）。
- **加闸前先问**：这道闸会不会拦住"**让同一语义份数下降**"的动作（收口/下沉/去重）？**会 → 用反向判据，别用清单白名单**（清单必漏）。

**删闸也是合法动作（且必须删干净）**：
- **删闸不是失败；留一道假护栏才是。** 覆盖不足时有两条路：**补覆盖** 或 **删掉它** —— **唯一不允许的是改声索**。
- 删干净 = 闸脚本 + 闸清单（`gates.manifest.json`）+ 元层登记（扫描根/自检表）+ `package.json` script + **所有引用它的文档与代码注释逐处回改**（否则就是亲手造 SSOT 漂移）。
- 删完必须**写明代价**："这条红线退回只写在注释里"，并登记"可能回潮"。

## 五 · 工具债 A10 执行细则（**唯一真源**）

- **范围**：`scripts/**`（闸 / 账本 CLI / 审计工具 / baseline）· `.codebuddy/commands/**`（流程文档）· `package.json` 的 `scripts` 条目。
- **为什么不能延后**：① 工具**每次被用都收一次利息**（不像业务债只在对应链路生效）；② 工具的产物会被下游**当真相用**（闸假绿 / 账本口径错 → 污染此后所有结论）。
- **红线（例外 ≠ 放开）**：🚫 `src/**` · `localTool/**` · 借机重构工具（"顺手把 X 也整理了"）· 改业务流程 / 对外契约 / 持久化格式。**判不准是不是工具债 → 按业务债处理（只登记，不动手）。**
- **修完三件（缺一即未闭环）**：① `node --check <file>` 通过 + **实跑一次**证明行为已对；② **先红后绿证据**（修复前错误行为 + 修复后正确行为，**同命令同参数**对照，落轮次文件，注入/还原一律走 `probe.mjs`）；③ 账本**一行 `已解决`**（含"怎么修的"一句），**不进主表待办**。

## 六 · 五闸各自的凭证要求（一凭证闸的执行面）

| 闸 | 凭证形态（必须是这个，不许是形容词） |
| --- | --- |
| 一归 | 改前 `grep` 命中的 **N 处 → 改后 1 处**（贴命令 + 输出） |
| 减一 | 兜底**计数对照**（改前 X 处 → 改后 Y 处，Y < X） |
| 减二 | **可比的度量数据**（改动半径 / fan-in / 跨层跳跃 / 重复份数，改前改后并列） |
| 一诚实 | **判别联合的探针结论块**（先红：注入假成功 → 红；后绿：修复后 → 绿） |
| 零炸 | **反向探针结论块**（改前能走的路径仍绿 + 改前会失败的仍红） |
| **一凭证** | **就是上面五条的凭证本身** —— 无凭证即五闸全废 |

> **一凭证是「自查闸」，不是「机器闸」**：不新建任何闸、没有脚本/负例探针/申诉口，成本 = **回读一遍自己的落账**；判定者是回读的架构师自己。**将来若要把它机器化**（如落账模板强制 `命令:` / `输出:` 字段）→ **那一刻才走建闸前置评审**。
