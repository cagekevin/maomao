# 用户报症状时怎么开工（完整版）

> **触发**：用户说「X 不好用 / 我测了还是不行 / 这里不对劲 / 只能做一次」。

## 一 · 唯一的开工指令（不要再读别的）

> **不要去找那个 bug。去找这段设计正确时该长什么样，然后照着把它重写。**

症状不是要修的对象，是"**这段设计错了**"的报信人。
- ❌「这个 `if` 为什么没进去？」→ 你在**修症状**（会滑向补丁 + 兜底）。
- ✅「这个能力正确落地时该是什么结构？现在这段结构为什么表达不了它？」→ 你在**做正确**。

**开工动作（顺序即优先级）**：

1. **Step 0 普查**这条链路上"同一件事被实现成几份"（份数 = "我要不要再写一份"的判据）。
2. **🔥 先把最优解写下来（一屏以内）**：入口是什么 / 链路几步 / 判据在哪层 / 真相归谁 / **它取代或复用什么**。
   **写不出来 = 你还没理解这个能力** → 回去读代码，别动手。**光写"我打算怎么写"不算** —— 要写"**这个能力正确落地时该长什么样**"（独立于你的实现）。
3. **🔥 横向查"同领域别处是不是已经满足了"**（最易漏）：需求常按**入口**提，能力却按**领域**复用 —— 同领域其他入口**可能早已具备更强实现**。
   动作：列出该能力的**所有入口**，逐行填「现在怎么满足这个需求」。**若别处已满足 → 那份就是最优解，本次一行不写**（或改为指向它的指针）；**绝不许"为了统一"再补一份**（= 造第二份更弱实现）。
4. **现状与正确形态逐条对照**，凡是"表达不了正确形态"的结构 → **删掉重写**，而不是缝补。
5. **病灶常常不是"某步写错"，而是"缺了一步"** —— 例：落盘 ≠ 入库，缺"归位"这一步。
6. **把判据与契约放回它该在的层**：谁拥有真相，契约就定义在谁那。
7. **检查"代码里写了、UI 上出不来"的东西**：结构写对了却看不见/点不动，几乎总是**结构或布局层面的错**，不是"功能没写完"。
   必查：非法嵌套（Tooltip 套 Tooltip）· 塌陷高度链（`flex-1` 缺 `h-full`）· 被 `disabled`/`pointer-events:none` 吞掉的入口 · 被上层盖住的图层。
8. **只读实测取证**，且**用与真实调用一致的口径**（用错参数探测会得出相反结论）。

## 二 · ⛔ 五种"修症状"的滑法（识别出来就退回第 2 步）

| 滑法 | 判据 |
| --- | --- |
| **改一版试一次**（改 A → 没变 → 改 B → 再试） | 用试错代替设计，每猜一次加一层兜底 |
| **猜环境**（缓存 / 没重启 / 环境问题） | 会让你去加"兜底"而不是改结构 |
| **在错误的位置做深度优化** | 例：病灶是"这动作不该由菜单承载"，却去优化菜单封装 → 越"正确"离解越远 |
| **靠探针反复证伪假设** | 探针是**证明"我改对了"**的工具，不是"我猜对了吗"的猜谜机。定位靠**读代码 + 问用户关键观察** |
| **🔥 没想清最优解就动手** | 拿到需求先查"我要改的那个点"，**不查"这个能力的最优形态是什么 / 同领域别处是否已有"** ⇒ 最容易造成**重复造一份更弱实现**。判据：**说不出"最优解 + 别处有没有"就动手了** → 退回第 2/3 步 |

> **总闸（自查）**：**如果你的下一步动作是"先试试看"，就已经错了。** 正确的下一步永远是：**回去把这个能力的正确形态写清楚。**

## 三 · 判据：什么时候算"做完了"

| 口径 | 修症状的"做完" | 做正确的"做完" |
| --- | --- | --- |
| **症状** | 不出现（**可能是被兜底埋了**） | 不出现（且**兜底数量净减**） |
| **该能力** | 还是 N 份判据 | **1 份**判据 |
| **链路** | 缝补后更长/更绕 | **更短、更直**（环节数下降） |
| **契约** | 散在各层、靠猜 | 定义在**拥有真相的那层** |
| **结构** | 非法嵌套 / 塌陷布局仍在 | **逐条对照正确形态清掉了** |
| **失败** | 仍是假成功 / 静默 | 判别联合 + 根部炸开 + 读者正确 |
| **波及面** | 顺手改了无关行为、说不清改了什么 | **只碰目标能力**；`git diff` 逐行能说出"为什么必须改它" |
| **证据** | "我试了，好像好了" | **用户实测通过** + 只读实测 + 闸/测试 + **反向探针（没炸别的）** |
| **凭证** | 形容词（"收口了/更短了"），拿不出命令 | **每条结论一条可复现命令 + 结论块**；「先红」**真红过**（一凭证闸） |

> **一句话**：**不要服务那个症状，要服务这段能力的正确性。**
> 交付物 =「结构对照正确形态重写 + 判据收口为 1 份 + 契约在正确层 + 兜底净减 + 入口可见可点 + 波及面 = 1（只动目标能力）+ 每条结论可复现」。

## 四 · 弯路留痕（强制）

改错的弯路必须写进轮次文件，**与结论同等对待**。

- **记三件事**：① 当时的推理链 ② 为什么它是错的 ③ 是否已完整回退（含"假绿"测试要删）。
- **理由**：弯路的**思路往往非常有道理**（否则不会走进去），后人极易重走 —— 只留结论、不留弯路，等于丢掉最贵的经验。
- **判据**：锁着"已被撤销设计"的**假绿测试必须删掉**（测试通过 ≠ 那件事存在）。
