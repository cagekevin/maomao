# 判据本体与实证

## 一 · 五条不可让渡的底线（凌驾于所有战术动作）

| # | 底线 | 内容 | 依据 |
| --- | --- | --- | --- |
| **①** | **正确性最优先** | "能跑通"与"正确"冲突时，**永远选正确**，不准"先跑通再说"。验收看：整体复杂度是否下降 + 失败是否诚实可见 + 兜底是否净减 —— **不看"这行代码跑没跑通"** | 最重要的一条 |
| **②** | **职责边界** | 谁拥有真相，契约就定义在谁那；消费者严禁执行所有方的动作，生产者也不替消费者定行为。**越权就是结构错误，不是风格问题 → 停** | 展开见 Step 3 / Step 6 |
| **③** | **复杂度放到合适的位置** | **把复杂度收敛到正确的物理位置，而不是搬家**：能删 > 能收敛 > 能下沉；用 `Adapter`/兜底藏进黑盒 ≠ 消灭。⚠️ **「能删」有前提**：删掉它**用户能做的事不许变少**（命令/入口/功能/能力/对外契约属"变少了" → 不许删，走 Step 5）。⚠️ **且清偿有时机**：死代码是替换动作的过渡产物 ⇒ **功能写完再清** | 复杂度不会消失，只会被藏起来 |
| **④** | **业务数据判断 —— 架构师自己判** | 判据只有一条：**用户用了之后，到底变没变？** 没变 → 架构师**直接定**（结构/命名/位置/抽复用/删死代码/补守卫），**不许请示**；变了 → 走 Step 5 摆 A/B/C。**反滥用**：把该自己判的结构问题退化成"这个要问用户" = 偷懒 | — |
| **⑤** | **拆兜底 —— 绝不掩盖错误** | 验收口径 = **兜底数量净减**（不是"症状消失了"）。六种形态见 §三 | — |

## 二 · 七条全局铁律

1. **决策前置 —— 只在两个"有观察点"的时机过三关 + 留痕**：拍板前 / 本轮落账时。动作 = 过三关（资格筛 → 门槛·全达 → 择优；任一门槛不过 ⇒ 停）；拍板时每个 A/B/C 选项各带一份留痕；落账时补进轮次文件 `§九 决策留痕`。**判据本体 `docs/adr/ADR-0050`，不复述**（抄 = SSOT 第二份）。
2. **项目约定：不为存量用户做兼容**。判据一句话：**「留这个是为了谁？」—— 答案是"老用户旧数据/旧版本"⇒ 直接删**。不为旧数据保留迁移器 / 双写 / 旧格式分支 / 弃用别名 / 兜底分支。⚠️ 与 Step 0 的关系：为旧版本而存在的那几份是**待删的多余工作**，先判死再谈收口。⚠️ 与 Step 5 的关系：删兼容代码**不改变**"业务能力变化要问用户"，属架构师可自定。
3. **任何"描述/名称"都是线索，必须重新取证**：债登记、注释、账本输出全可能错。**凡能查的一律不许靠推理**。符号名/文件名/能力名同样是描述 —— 写进代码或文档前**必须先 grep 确认它存在、且真的导出**。
4. **不要修症状，要把能力重写正确**：症状消失只是副产品。**严禁四种滑法**：改一版试一次 · 猜环境 · 在错误位置深度优化 · 靠探针反复猜谜。
5. **工具债不延后（红线）**：开发途中命中 `scripts/**`、流程文档或 `package.json` 的缺陷，**立刻停工当场修好** —— 工具的错误产出会**污染后续所有决策**（细则见 `references/01-gates.md` §五）。
6. **既有约定 ＜ 正确性 · 既有约定 ＜ 合理性**：「仓里一直这么写」**不是理由**。既有约定只是**待验证的线索** —— 它未必对，可能正是要消灭的对象。**判据：引用任何既有约定之前先问「它凭什么成立？」** 答得出（有物理红线/类型层/唯一入口/对账测试支撑）→ 可沿用；答不出（只是"历来如此"）→ **它就是要被消灭的对象**，按正确形态重写。⚠️ 反滥用：不许拿「既有约定」当挡箭牌，也不许拿「正确性」当借口做**无证据**的重写。📌 落点：被推翻/被确立的约定记入 `docs/adr/`；**读债、普查之前先过一遍 ADR 索引**。
7. **用户提问优先 —— 先回答，再取证**：用户问的每一句都是判据，也可能是更省的路线。他问「为什么/是不是/核实一下」时，**第一动作 = 回答那句话**（结论 + 一条证据），**不是先把周边查一遍**。自检：**我的下一步，能直接产出他要的那句话吗？** 答不出 ⇒ 我在做他没要的事 ⇒ **停手，先回答**。为什么：用户的问题里带着**他已有的观察与方案**（真实症状/已排除的假设/他心里的解法）—— 那是**探针跑不出来**的输入。⚠️ **不是"少取证"，是"取证的方向来自用户"**：问句 ⇒ **只回答**；指令 ⇒ 才动手，且**只做他点名的那一件**（发现别的只留一行"另开轮次"）。

> **范畴**：本流程以**改存量**为主；**从零新建走 4 步法**。Step 0/3/4/5/7 对新建同样适用，**Step 2（存量归因）/ Step 6（最小改动）是存量专属**。

## 三 · 生产者 ↔ 消费者 三铁律（完整清单）

> **一句话**：**生产者给全信息，消费者只转发，消费者永远不替生产者做任何决定。**
> **验收口径**：消费者侧**零自造**（不写判据 / 不拼文案 / 不 new 兜底 / 不替生产者决定可见性）= 与 **一归 / 减一 / 一诚实** 三闸同时对齐。

| # | 铁律 | 一句话判据 | 本仓实证 |
| --- | --- | --- | --- |
| **①** | **给全** | 消费者需要的成功/失败/可展示文案/原因/证据，生产者**一次给全**；给不全 = 生产者缺契约，**不是消费者的错** | 结果契约 `{ok,data}\|{ok:false,error}` 钉死成功与失败；`reportDegrade` 每次失败必 `logger.warn` 并原样交出 toast |
| **②** | **只转发** | 原样透传生产者的信息；不翻译、不加工、不重分类、不自造 | `degrade.ts` 从"转发＋替生产者决定可见性"改成**纯转发**；`ErrorBoundary` 只陈述自己生产的「已重试 N 次」 |
| **③** | **不越权** | 判据/重试/降级/呈现频率/因果结论 —— **全归生产者**；消费者复制或改写 = SSOT 第二份 | `reportDegrade` throttle 单槽越权持窗口；`ErrorBoundary` 全屏因果文案被撤；TD-16-39~46 消费者自造 canonical 能力 |

**① 给全什么（生产者出口自检清单）**：成功契约（`ok:true` + 结果证据如 `res.changes`/`res.linked.length`，不许只有恒真 `ok:true`）· 失败契约（判别联合 `{ok:false, error}`，`error` 含**可展示文案 + 原因 + 降级标记**）· 状态证据（缺的/跳过的/失败的各自列出 `missing[]`/`skipped[]`/`failed[]`，**不许把失败计进成功数**）· 业务判据（该不该做/放不放行 —— 留在生产者层**导出**）· 可选字段（没给就是**真空**，消费者静默才是正确；禁止消费者因"缺可选字段"自行告警）。
> **给不全怎么办**：**回生产者补契约**，不许让消费者"自己拼"（越靠下游补，越是在**拼第二份不完整的真相**）。

**② 只转发的三允许 / 五禁止**：**允许** —— 原样透传生产者判词（按读者分流）· 呈现自己生产的事实 · 统一聚合展示（一屏收口是聚合，不是再产生）。**禁止** —— ❌ 自拼/翻译错误文案 ❌ `try/catch` 后 `new` 假成功对象或塞默认值 ❌ 重分类（`TypeError` 当网络错误重试）❌ 替生产者决定"失败要不要让用户看见、多频繁" ❌ 写因果判断（"问题出在 X / 说明数据坏了"）。

**③ 什么算"替生产者做决定"**：**复制业务判据**（能调生产者导出的函数却不调，自己重写一份）· **mutate 生产者数据**（组件直接改 props 传入对象 / store 内部状态）· **决定策略**（重试策略/降级策略/呈现频率/窗口合并 —— 全归生产者）· **下因果结论**（替生产者断言原因）。

**违规处置顺序（唯一正确动作）**：① 发现消费端乱写 → **第一动作不是改消费端**，先查生产者是否给全 ② 生产者缺 → **回 Step 4 补生产者基建**，不在消费端写第二份（写第二份 = SSOT 第二份 + 兜底净增，**双违规**）③ 生产者已给全、消费者仍自造 → 删消费端重写，改**委托/转发**，一行新逻辑不写。

**消费者落笔前自查 3 问**：① 这句话断言的事实是**谁**生产的？不是我 → 不许断言，只能转发。② 我能不能**只调用**生产者导出的函数？能 → 必须调，禁止自造第二份。③ 我在替生产者决定什么吗（可见性/频率/重试/默认值）？在 → 越权，删。

## 四 · 拆兜底（六形态全文）

> **核心因果**：兜底让症状"消失" → 误以为修好了 → 错误被埋得更深 → **真正的问题再也排查不出来**。
> **一次性做正确 > 事后用兜底捂住。**

| 形态 | 说明 |
| --- | --- |
| **静默 catch** | `.catch(() => {})` 零日志 |
| **失败归一 `null`** | 把各种失败全压成一个 `null`，调用方无从判别 |
| **占位对象 + 事后打补丁** | 先塞个假对象让它跑通，再在别处补 |
| **默认值兜底** | 拿不到就给个默认值，假装成功 |
| **UI 层提前宣告成功** | 上层先显示"成功"，下层其实还没落盘 |
| **只在某一入口补的"补偿步骤"** | 哪里报错补哪里，而不是改结构 |

**强制动作**：每发现一处兜底，**逐个问"它在掩盖哪条地基缺陷？"** —— 答得出 → **改地基、删兜底**；答不出 → 说明你还没理解它，**别加到第 8 种形态**。
**验收口径**：**「兜底数量净减」**（不是"症状消失了" —— 症状可能只是被兜底埋了）。
