# 架构师改码 7 步法

**用途**：修改**存量**代码。**从零新建走 4 步法** —— 本流程的 Step 2（存量归因）/ Step 6（最小改动）是存量专属，硬套到新建会得出错误结论。
**效力**：物理红线（`CLAUDE.md`）> 架构师心法 > 本流程。
**本文件自足**：跑完整流程所需的全部内容都在这里。`references/` 只在需要**判据本体 / 深水区**时读（见 §5）。

## 0 · 三条不可违反

1. **去取证，不猜、不请示** —— 结构问题自己判；只有"用户能做的事变了"才问用户（Step 5）。
2. **不修症状，修设计** —— 先写出"这段设计正确时该长什么样"，再照它重写。症状是"设计错了"的报信人，不是要修的对象。
3. **下一步若是"先试试看"，已经错了** —— 正确下一步永远是"把这个能力的正确形态写清楚"。

## 1 · 交付六闸（改完必须同时满足，缺一即退回重写）

| 闸 | 标准 | 不合格信号 | 凭证形态（必须是这个，不许是形容词） |
| --- | --- | --- | --- |
| **一归** | 同一能力的判据从 **N 份收口为 1 份**，契约定义在**拥有真相的那层** | 仍是 N 份判据 / 新增第二份真相 | 改前 `grep` 命中 N 处 → 改后 1 处（贴命令 + 输出） |
| **减一** | 兜底**不仅不能增，且必须数量净减** | 为让代码跑通而新增兜底 | 兜底计数 改前 X → 改后 Y（Y < X） |
| **减二** | 整体复杂度**真实下降**，链路更短更直（**环节数下降**） | 答不上「复杂度降在哪」 | 改动半径 / fan-in / 跨层跳跃 / 重复份数（改前改后并列） |
| **一诚实** | 失败**不能伪装成功**，错误在**根因发生地**抛出 | 假成功 / 静默吞没 / 错误被 catch 埋在三公里外 | 判别联合的探针结论块（先红 → 后绿） |
| **零炸** | 只影响目标能力：改前能用的**仍能用**、改前会失败的**仍失败**（不许顺手改好）、不留半态 | 说不清哪些行为被改了 / 顺手动了无关行为 | 反向探针结论块（改前能走的仍绿 + 改前会失败的仍红） |
| **一凭证** | 前五闸每条结论带**可复现凭证**，且「先红」**真红过** | 只有形容词（"收口了/更短了/测过了"）/ 探针没跑 / 断言没红却称验证过 | **就是上面五条的凭证本身** —— 无凭证即五闸全废 |

> 六闸是**交付自查标准**，不是机器闸 —— 不新建 `scripts/check-*.mjs`、不走建闸前置评审。**只有要把某条闸机器化时才走评审**（见 `references/01-gates.md`）。

## 2 · 流程（Step 0 是开工前置，不计入 7 步）

### Step 0 · 普查 —— 仓库里已经有什么

> **本步第一动作不是"查"，是"先写出最优解"（一屏以内）**：入口 / 链路几步 / 判据在哪层 / 真相归谁 / **它取代或复用什么**。
> ⚠️ **写不出 = 你还没理解这个能力 → 回去读代码，不许动手。**
> ⚠️ **"最优解" ≠ "我打算怎么写"** —— 前者独立于你的实现。判据：**换个人来做会写成什么样？我这样是不是最省的？**

**动作**：
1. **枚举能力项**：把要做的事拆成独立能力。
2. **全库检索（必须用工具）**：
   - `node scripts/mv-sync-refs.mjs refs <file>` —— 谁引用它
   - `node scripts/extract-detours.mjs` —— 前人弯路（防截断）
   - `node scripts/debt.mjs search <机制名|症状词>` —— 账本里的既有解法
   - 过一遍 `docs/adr/README.md` 索引 —— 哪些既有约定**已被推翻**、哪些已确立
   - **`ls docs/plan/` 看最新一期** —— 它有没有点名**我要改/要新建的那个结构**？（重写/退役/合并/收口）→ 判据见 Step 3「选落点」
3. **🔥 横向盘查：同一个用户需求在别处怎么满足的**（最易漏）：
   需求常按**入口**提，能力却按**领域**复用 —— 同领域其他入口**可能早已有更强实现**。
   动作：列出该能力的**所有入口**，逐行填「入口 → 现有实现 → 是否已满足 → 处置」。
   **若别处已满足 ⇒ 那份就是最优解，本次一行不写**；**绝不许"为了统一"再补一份**（= 造第二份更弱实现）。
4. **判种类**：**探测/运算重复**（怎么读、怎么算）→ 可收口；**判据/宿主重复**（要不要做、在谁地盘做）→ **不可合并**。
5. **定处置**：已有 1 份且是真源 → **复用**；已有 ≥2 份（真重复）→ **收口**（最完整者下沉，其余 `re-export`/委托）；N 份但判据不同 → **保留分层**，只收口底层探测原语；真的没有 → **新建**（必须自述"现有为何承载不了"）。
   ⚠️ **先按"项目约定"判死**：为旧版本/旧数据而存在的那几份 → 不是"可复用实现"，而是**待删的多余工作**。
6. **产出（未出表不施工）**：① 最优解 ② 入口对照表 ③ 能力份数表（能力 → 现有实现 `文件:行` → 份数 → 处置）。
   优先顺序：改造现有 > 新建；"新建唯一实现"优于"在旧入口旁加分支"，但**劣于改造旧入口**。

> **不过关**：写不出最优解、或说不出"同领域别处是否已满足" ⇒ **不许动手**（本仓认定的最严重错误之一）。

### Step 1 · 证伪 —— 这个需求真的存在吗

> **"这个需求不存在"是你能给出的最高价值判断**（本仓每 8 条债就有 1 条是假债）。

**动作**：
1. **重新取证**：`node scripts/debt.mjs show <TD-ID>`（取最新真相，**禁读全量账本**）。债号真伪**靠逐条取证，不靠闸**。
   - 🔴 **账本的「解法／偿还计划」不是判据**：它是**上一个执行者的假设**，引用前必须自己按「复杂度 + SSOT」重判
     —— 正解常常与它不同。实证（TD-11-75）：账本处方是"参数改可选"，重判发现那只是把**编值**换成
     **危险默认值**（漏传即静默"全部启用"），与同一笔债的另一半（默认值 `'ok'`）**同形** ⇒ 正解是**必填**。
   - 🔴 **先分析再判断**：**不许边想边改**。取舍先摆出来（复杂度一条 / SSOT 一条），再动手。
2. **跑四问（缺一不可）**：
   - ① **硬证据**：拿得出它真坏了 / 真多余的报错或实测数据吗？
   - ② **替代方案**：现有机制是否已经足够？
   - ③ **致命拷问**：加了它，**用户能多做哪件原来做不到的事**？
   - ④ **最优解与防重复**：「这个能力的最优形态是什么」（不是"我打算怎么写"）+「同领域别处是否已满足？我这份会不会是重复？」—— 答不出 → **停手**回去补 Step 0；答得出"别处已有" → 本次一行不写，结束。
3. **三种产出（必须归入其一）**：真需求 → 进 Step 2；**假需求（非债）→ 就地改判 + 落盘留痕，结束**；业务性需求 → 记下，**跳到 Step 5**。
4. **不过关**：拿不出证据 → **不做**；但"不做"也必须在账本写明理由（拿不出证据的"不做"= 偷懒，打回）。
5. **加速器**：`node scripts/debt.mjs search <机制名|症状词>`（如 `SSOT` / `静默` / `死代码`）—— 命中行的状态列 = 当时的解法一句话。

### Step 2 · 归因 —— 是孤例，还是母体

> **按"规则/契约/机制"归堆，不要给症状打补丁。**

**动作**：
1. **找根因**：某修复能同时消灭 **≥3 个债** → 它是母体，优先治母体。
2. **查"规则层"三问**：是不是**某条规则**出问题了？是不是**缺一条机器守卫**（红线只写在注释里 → 必回潮）？是不是**同一真相被抄成多份**？
3. **对症本仓六大常见母体**：

   | # | 母体 | 对策 |
   | --- | --- | --- |
   | **M1** | 结果契约缺位（成没成功没定型） | 判别联合钉死 |
   | **M2** | 唯一入口无机器守卫（红线只在注释里，绕过零成本） | 收窄入口 / 加对账 |
   | **M3** | SSOT 第二份（同一真相抄多份，**每层都现身**：代码/契约/闸/文档） | 收口为唯一实现 |
   | **M4** | 描述层无对账（注释/文档与代码脱节，**本仓最高频**） | 让描述成为生成物，或加机器对账 |
   | **M5** | 失败不可见（静默吞 / 假成功） | 判别联合替代 `null`/`boolean`；降级必留痕 |
   | **M6** | 幽灵预留（为将来铺路的零消费代码） | 查 fan-in = 0 → **直接删**，不许补消费方 |

4. **三种产出**：**母体** → 设计"一次消灭 ≥3 症状"的收口方案（进 Step 3）；**孤例** → 最小改动，但记下"是否该升为规则"；**症状群但无母体** → 老实登记 N 个债（**不许编造母体**）。

### Step 3 · 定位 —— 复杂度该落到哪个物理位置

> **目标**：找到改动半径最小的位置（下沉、收敛、删除）。

**动作**：
1. **职责归属**：该数据所有方是谁？我是不是所有方？（消费者严禁执行所有方的动作 → **停**）
2. **真源在哪**：谁产生这个数据？（产生方 = 真相源，消费方只能派生）
3. **变化速率**：变化快的和变化慢的**不该同居**（真缝隙的判据）。
4. **有几种实现**：只有 1 种实现的接缝 = **假接缝**（禁抽象）。
5. **改动半径**：要碰几个文件/几层？**半径最小处 = 最优位置**。
6. **接口窄不窄**：窄接口 + 厚实现 = 深模块（好）；宽接口 + 薄实现 = 泄漏（坏）。
7. **落点时效**：这个结构**会不会被我手上正在写的方案替换掉**？→ 见下「选落点」。
8. **判据适用面（横向铺开）**：这条判据**还有哪些地方该一起改**？**自检一句话：「我改的是实例，还是规则？」**
   只改实例 = 下一次同形复发（本仓实证：入口名闸只堵规范大小写 ⇒ 两处真实例当场漏检且闸永远绿；
   "取数范围跟判据匹配"只改了一处，云写回还在拉全量）。

   > ⚠️ **第 8 条最容易只做一半：只铺代码，不铺声明。** 判据不只写在代码里 ——
   > **头注释自称的边界** · **用例编号** · **模块 README 的表格** · **方案文件 `docs/plan/*` 的规格块** ·
   > **类型签名**（必填逼调用方编假值 / 默认值 = 危险值），全是"同一条判据的另一份"。
   > 改完代码**回扫这五处**，漏一处 = M3/M4。本仓实证：一次文件拆分后，方案文件 §2.1 补了对账指针、
   > §3.2 没补；门面头注释写"五类用例"而导出面已是七类 —— 全是"改了实例没改规则"。

**判真假接缝**：**探测重复**（怎么读数据）→ 强制收口为底层纯函数；**判据重复**（要不要放行/动作）→ **严禁合并**，必须保留在拥有真相的层级（合并会削掉某层的必要能力，如异步兜底）。

**最小半径校验**：若下沉/收敛后半径没变小（动了 ≥10 个消费方），说明只搬了家 —— 先问"**能不能让旧入口 `re-export`**"，让消费方零改动。

**🔥 选落点（三问）** —— **落点 = 根因所在的结构，不是症状所在的结构；且先判时效**：

| 问 | 判据 | 不过关怎么办 |
| --- | --- | --- |
| **① 时效** | 这个结构会不会被**手上正在写的方案**替换掉？（重写/退役/合并/收口） | **不修它** —— 改投方案要去的落点，或等方案落地（**别在旧结构上打洞**：本仓实证，修在"方案已列退役"的面板上 ⇒ 数小时后产出归零） |
| **② 层次** | 根因住哪一层？（**症状在 UI ⇒ 根因多在契约/类型/唯一入口层**） | **退回 Step 2** 重判母体（症状层修一次，会被下一个方案推翻一次） |
| **③ 收口** | 这次收口搬的是「键」还是「键 **+ 语义**」？ | 只搬键 ⇒ 视为**未完成**：下一轮必出"同一判据两份"，且**新代码的作者是受害者不是责任人** |

**凭证（强制一行）**：报落点时附「**在飞方案检查**」—— `docs/plan/` 最新一期编号 + 该结构是否被点名。**拿不出这一行 = 落点未核**。

### Step 4 · 定契 —— 正确性与"错误透传"

> **目标**：失败必须诚实，错误必须在根部炸开。

**五条禁令（违反即打回）**：

| 禁令 | 反例 |
| --- | --- |
| **禁静默吞** | `.catch(() => {})` 零日志 → 错误必须由产生它的那层以**判别联合**透传（含可展示信息） |
| **禁假成功** | 缩略图失败用原图冒充 → 必须 `{ok:false, error}`（或 HTTP 500），**绝不许返 `null` 冒充** |
| **禁错误→错误结果** | 失败时产出"看起来成功但语义相反"的输出 |
| **禁重分类** | 代码 bug 的 `TypeError` 被当"网络错误"重试 → 按文案白名单区分 |
| **禁为过闸而重复** | 闸拦住收口时把同一语义抄成 N 份买绿灯 → 正解 = **改闸（收窄不放宽）** |

**生产者 ↔ 消费者 三铁律**：**生产者给全信息，消费者只转发，消费者永远不替生产者做任何决定。**

- **① 给全**：成功契约（`ok:true` + 结果证据，不许恒真）· 失败契约（判别联合 + **可展示文案 + 原因 + 降级标记**）· 状态证据（`missing[]`/`skipped[]`/`failed[]`，**不许把失败计进成功数**）· 业务判据（该不该做留在生产者层**导出**）· 可选字段没给 = 真空，消费者静默才对。**给不全 ⇒ 回生产者补契约**，不许让消费者自己拼。
- **② 只转发**：**允许**——原样透传生产者的判词（按读者分流：开发者看 `logger`，用户看 UI 状态）· 呈现自己生产的事实（如"本组件第 N 次重试"）· 统一聚合展示。**禁止**——自拼/翻译错误文案 · `try/catch` 后 `new` 假成功对象或塞默认值 · 重分类 · 替生产者决定"失败要不要让用户看见、多频繁" · 写因果判断（"问题出在 X"）。
- **③ 不越权**：**复制业务判据**（能调生产者导出的函数却自己重写一份）· **mutate 生产者数据** · **决定策略**（重试/降级/呈现频率/窗口合并全归生产者）· **下因果结论**。
- **违规处置顺序**：发现消费端乱写 → **第一动作不是改消费端**，先查生产者是否给全 → 生产者缺 ⇒ 回 Step 4 补生产者基建（在消费端写第二份 = SSOT 第二份 + 兜底净增，**双违规**）→ 生产者已给全、消费者仍自造 ⇒ 删消费端重写为委托，**一行新逻辑不写**。
- **落笔前自查 3 问**：① 我断言的事实是**谁**生产的？不是我 → 只能转发。② 我能不能**只调用**生产者导出的函数？能 → 必须调。③ 我在替生产者决定什么吗（可见性/频率/重试/默认值）？在 → 删。

**拆兜底（本仓最痛的一条）** —— 兜底让症状"消失" ⇒ 误以为修好了 ⇒ 错误被埋更深 ⇒ 真问题再也查不出来。

- **六种形态**（看到自己在写 → 停，问"我在掩盖什么"）：**静默 catch** · **失败归一 `null`** · **占位对象 + 事后打补丁** · **默认值兜底** · **UI 层提前宣告成功** · **只在某一入口补的"补偿步骤"**。
- **强制动作**：每处兜底逐个问「它在掩盖哪条地基缺陷？」—— 答得出 → **改地基、删兜底**；答不出 → 说明还没理解它，别加到第 8 种形态。
- **动作与红线**：① 成功信号**在类型层定型**（判别联合），禁止消费方靠猜。② **根部抛错，禁静默吞**（严禁把 catch 埋在三公里外的 UI 层）。③ 预期内失败要显式标 `// catch-ok: <理由>` —— 该标记**无机器校验**（一句话即可伪装），故**写前必须回读被 catch 的代码**；**优先"收口原语"而非逐处标记**（同一"吞"语义手写 ≥3 次 → 收口成原语）；**禁止用守卫替代 catch**（守卫只管 contract 违约 → fail-fast；运行时可预期失败一律 `catch + reportDegrade/logger.warn`，用前置守卫预防运行时意外 = **假守卫**）。④ **失败可见性给对读者**：开发者 → `logger`；用户 → toast（瞬时）或 UI 状态（持续），**不混用**。

### Step 5 · 定权 —— 我自己改，还是问用户

> **唯一判据**：**结构怎么摆 = 架构师直接判；跟业务相关 = 一定问用户。**

| | 架构师**直接定** | 架构师**必须问用户** |
| --- | --- | --- |
| 对象 | 代码结构、函数位置、删重复/死代码、抽 helper、改注释、补守卫、命名 | **删需求、砍功能、增减业务能力、改交互、改对外契约与持久化格式、引入重依赖** |
| 判据 | 改完**功能不变**，只是结构更少/更对 | 改完**用户能做的事变了** |
| 动作 | 直接做，账本记"还债" | 摆成**带成本的 A/B/C 选项 + 推荐项** |

- **问前必过三关 + 留痕**（判据本体 `docs/adr/ADR-0050`）：每个选项**各带一份留痕**（差异在哪、代价是什么）。**缺留痕 ⇒ 不许问** —— 缺痕 = 把该自己判的退化成问答题。
- **选项形态**（判据本体 `docs/adr/ADR-0051`，二选一，没有第三种）：
  - ① `我判为：<结论> —— 为此放弃：<代价/机会成本>`
  - ② 真备选（代价必须**同类量**、可并排比较）：`方案 A：<做法> —— 成本 X，代价 放弃 Z` / `方案 B：…`
- **禁**：把单一结论包成 A/B/C（"推荐／能接受／别做" = 同一答案的三张脸）· 用"推荐"标注代替论证 · 不给"不做"选项 · 选项退化成问答题 · 用"复杂度高"单方替用户决定不做。必须先写 `问前取证：…`，写不出 = 不许问。
- **反滥用**：把该自己判的结构问题退化成"这个要问用户" = **偷懒**。

### Step 6 · 施工 —— 最小改动，不留尾巴

**🔴 删的前置动作**（判据本体 `docs/adr/ADR-0053`）：
> **先分清时机**：清偿死代码是**收尾动作**，不是准入门槛 —— **先把功能写完、跑通，再清偿**。新增/替换功能时旧实现短暂零消费是必然；**禁止**为让死代码闸变绿而删掉本次新写的代码 / 退回被替代的老实现（**闸不许凌驾正确性**）。正确形态 = **同批完成**：新实现接上 + 旧实现删除。过渡态只许存在于本次施工内，落账前清干净。

**按序走完五步，任一步过不去 ⇒ 停手**：
0. **先答「删了它，能解决什么问题？复杂度下降在哪一项？」** —— 答不出 ⇒ **不删**。
   ⚠️ 实证：删掉 5 处"纯中转"子门面后，父门面暴露面**仍是 25 项**、实际只用 7 项 ⇒ **接口宽度一项没变** ⇒ **白删**。**目标是「深模块 + 窄接口」，不是少一层/少几个文件。**
1. **先问「删的是能力吗？」**（命令/入口/功能/能力/对外契约）⇒ **停手，走 Step 5 摆 A/B/C**（含「加回来/修它/不做」）。
2. **查清"真的没人用"—— 四口径，缺一不算查清**：

   | # | 口径 | 命令 |
   | --- | --- | --- |
   | ① | 模块引用（AST 图） | `node scripts/mv-sync-refs.mjs refs <file>` |
   | ② | 字符串/裸引用 | `grep -rn "<文件名\|符号名>" src/ tests/ docs/ scripts/ *.ts *.json` |
   | ③ | 桶/门面再导出 | `grep -rn "<file>" src/**/index.ts`（有 `export *` 则 `refs` 的 0 失真） |
   | ④ | 运行时字符串 | `grep -rn "<存储键\|事件名\|节点类型串\|上传子目录>"` |

3. **先验工具盲区**：`refs` 报 0 **单独不算证据**。
4. **两关都过 ⇒ 可删；过不去 ⇒ 不许删，改为修。**
   > 反例：`mv-sync-refs.mjs move-dir` 曾被按「删 > 改」整条删掉 —— 它确是"第二份实现"且确有损坏，**但删它 = 用户少一条「一条命令搬整目录 + 一键回退」**，属砍功能。**正解 = 修它**。

**动作**：
1. **只改真风险点**：判据 =「改了它，系统整体复杂度下降了吗？」答不上 → 别改。不为"强迫症一致性"改无风险旧代码。
2. **删旧先证死**：四口径交叉 + 先确认工具没盲区。
3. **清剿尾巴**：加新注释 → 必删被取代的旧注释；换了实现 → 必删旧实现（不留"以防万一"）；删字段 → 同步删接口、解构、派生变量及死分支。

**施工完自查（8 条）**：新加的东西**降低**了复杂度，还是藏进新黑盒？· **兜底数量净减了吗**？· 该动作的所有方是不是我（越权 → 删）？· 有没有留下"两名指一物/两处维护同一真相"？· 有没有 `_` 前缀变量 / 未被读取的 state？· 注释里描述的东西**代码里还存在吗**？· **逐行过 `git diff`** —— 每处改动都能说出"为什么**必须**改它"吗（说不出 = 副作用，撤回）？· 改前能用的还能用吗、改前会失败的还照样失败吗、有没有留半态？

### Step 7 · 验证与落账（最重的一步）

**7.1 探针（先红后绿 + 反向探针）**
> 🔒 **探针是"证明我改对了"的工具，不是"我猜对了吗"的猜谜机。** 定位根因靠**读代码 + 问用户关键观察**。
> **熔断**：写不出一句话"正确形态该是什么" → **停手别跑探针**。
> **强制**：统一走 `probe.mjs`，**严禁手改源码**（防假绿、防忘还原）。

```bash
# 1) 拿真实断言串（不要猜断言）
node scripts/probe.mjs --run "<命令>" --suggest-out
# 2) 执行探针（结论块直接粘入轮次文件）
node scripts/probe.mjs --label "TD-xx 验证" \
  --file <相对路径> --find "<旧实现>" --replace "<新实现>" \
  --run "<闸 / 单测命令>" --expect-exit 1 --expect-out "<精确关键词>"
```
脚本强制三件事：**注入点唯一**（0 处/多处即拒）· **还原 sha256 自校验**（防忘还原 = 假账）· **journal 兜底**（被打断也能自愈还原）。

**反向探针（必做）**：先红后绿只证明"我改的那点被测到"，**不证明我没改坏别的**。收工前再跑**目标之外**的验证：改前能走的路径**仍绿**；改前已知会失败的地方**仍失败**（偷偷顺手改好 = 副作用）。若既有测试变红，**先假定"我的收口越界破坏了原有语义"**，切勿急于改测试买绿灯。**口诀：测试红 ≠ 测试错；测试红 = 既有语义被破坏。**
**判据**：**答不出「我验证过哪些没被我碰的行为」= 零炸闸不合格。**

**"先红"没红怎么办**：是断言没测到那点 → 回去重写断言（**不许跳过**）。先自查环境能不能承载这个语义（如 jsdom 测不出浏览器手势栈）→ 那是"测不了"，**必须改手工/用户实测并写明**，**不许拿环境当免死金牌**。
- 🔒 **一凭证红色线**：**「没红」不是"可以交付"，是"这次验证作废"**。"先红了但我觉得不重要" = 绕过。
- ⚠️ **隐蔽原因：兜底把错误接住了** —— 注入的违规被某处 catch/默认值吞掉 ⇒ 行为没变。**别急着改测试**，先查是不是有兜底在掩盖（那正是要拆的东西）。

**凭证归档三项**（缺 ① = 假账；缺 ②③ 各补一行，**不是新开一张表**）：

| # | 要什么 | 为什么必须留 |
| --- | --- | --- |
| **①** | `probe.mjs` 结论块**原样粘贴**（已含 命令/命中处数/还原 sha/先红结果） | 机器产的真相，唯一来源 |
| **②** | **注入语义一行**（人可读的 `find → replace`） | 机器只报 sha，"注入了什么"只有人能判（防"红的不是那点"） |
| **③** | **还原后的绿**：一条命令 + 结论行 | 机器不打印，且是"我改对了"的反面证伪 |

**禁**：把结论块里的命令/sha/exit 码**再抄一张表**（= 制造第二份真相）· 为"格式完整"逐格填空 · 纯结构改动（无行为变化）硬造探针归档（走现有测试 + 反向探针即可）。

**7.2 门禁与测试**
- **只跑相关测试**，严禁为小改动连续跑全量。
- **跑与改动相关的闸**：`check:arch` / `check:any` / `tsc` / `lint`。
- **改了契约表 / 存储键 / 事件 → 必跑对应闸**（`check:events` / `check:keys`）。
- **零炸闸证据**：落账必须写明**改前的基线行为**（哪些路径能用、哪些已知会失败）+ **改后复验结果**。
- **新增测试的判断**：修**正确性问题**（数据丢失/失败伪装）→ **必须**加行为断言；纯结构重构（无行为变化）→ 现有测试覆盖即可。
- 🔒 **禁自证式断言**：**断言必须能被现实证伪** —— 依赖**被测代码之外的事实**。**把实现改坏/删掉它仍绿 ⇒ 它不是测试，是装饰**（比不写更坏：给"已验证"的假信号）。
  **六种形态**：① 同义反复（`expect(x).toBe(x)`）② 断言实现细节而非行为（私有字段名 / "我调用了某函数"）③ 断言自己刚写进 mock 的值 ④ 只测自己、**全仓零生产消费**（幽灵预留温床）⑤ 断言源码文本/文件存在 ⑥ 只断"没抛错"。
  ⚠️ **边界**：**跨文件规范扫描闸**（扫全仓查"是否遵守某条不变量"）**不属此形态** —— 它断的不是被测实现自身的文本，且注入违规会红（合法性按负例探针判）。
  **合格断言三条**：外部事实驱动 · 可被证伪（改坏实现必红）· 断行为不断实现。
  **自查**：把实现整个删掉/改错，这条断言会红吗？不会 → 删掉它。我断言的**那个值是谁产生的**？我自己写的 ⇒ 自证式。这条断言**改一次实现风格**就红吗？会 ⇒ 改成断行为。这个能力**生产里有消费者吗**？没有 ⇒ 先查是不是幽灵预留，**该删的是能力本身**。
  > 与"假绿测试"的区别：**自证式断言** = 从设计上就不可证伪（写的时候就是装饰）→ **禁止写**；**假绿测试** = 断言本来有效但锁着一个**已被撤销的设计**（弯路产物）→ **必须删**。

**7.3 落账**
> **入账判据**：债位只留给**设计缺陷**（结构/契约/规则）；一次性操作疏漏（删文件未清引用、漏改一处常量）→ 改代码 + 日志一句，**不入账**。

- **债账只用命令**（禁手改文件）：`debt.mjs add ...` / `list [--area NN] [--status 待还]` / `resolve <TD-ID> --note "…"` / `archive`（已完成移入归档，**主表只留待办**）。
- **落点（各写什么）**：**区域日志** = 改动 + 度量（改前/改后）+ 探针结果 + 债描述被修正处（跨区**只写一份** `<触发区NN>-跨区-<主题>-<日期>.md`）；**`index.md`** 只改状态 + 链接（**禁写说明段**）；**`DATAFLOW`** 链路有变就地改现状图（**禁追加"更新(<日期>…)"叙事段**）；**工具债当场修**。
- **度量（强制）**：落账必须给出**改前/改后可比**的口径（改动半径 / fan-in / 跨层跳跃 / 认知单元 / 重复份数）。"复杂度下降"不许凭感觉宣称。
- **摘要红线**：**≤120 字**（一行一债）· **禁裸竖线 `|`**（用 `／`）· 锚点必须是已存在的 `<NN>-<区域>-<日期>.md`。
- **证据只出现一次**：同一份证据在轮次文件里**只许出现一次**；逐闸自查只写「结论 + 指针」（指针必须指向**本文件内真实存在**的那一节）。
- **记录弯路留痕 + 回改原文**：弯路必须记在区域日志（当时的推理链 / 为何错 / 是否完整回退）；**修正事实必须回改原文** —— 只记在新文档 = 亲手制造 SSOT 漂移。

**7.4 落点归位**（每一份文档只放一类内容 · 判据本体 `docs/adr/ADR-0025`）：**落点由「内容属于哪一类」决定，不由「谁先写的」决定。**

| 问 | 落点 | 装什么 | 禁写 |
| --- | --- | --- | --- |
| 它凭什么成立？被谁推翻过？ | `docs/adr/` | 判据本体 + 由来 + 违反判据 | 实现细节（归区域日志） |
| 这条链路怎么走？ | `spec/DATAFLOW.md` | 现状链路图 + 关键边（refs 实证） | 结论/判据/日期/TD 号/叙事段 |
| 撬得动吗？（撬不动） | `CLAUDE.md` | 物理契约、红线 | 可被推翻的判据（归 ADR） |
| 这一处该走哪条路？哪条规则不适用？ | `spec/CONTEXT.md` | 场景→入口的**路由表** + 例外与边界 | 判据正文 · 模块清单/fan-in/链路图 |
| 这个函数怎么用？ | **代码文件头 JSDoc** | 局部机制（改文件必须同步文件头） | 跨模块决策 |
| 怎么做（步骤）？ | `.codebuddy/commands/**` 与本 skill | 流程动作 | 判据本体（归 ADR） |

**落点自检 3 问（Step 7 收尾必答）**：① 我这次落的内容**能说出属于哪一类**吗？说不出 = 放错了。② 我写的这段**别处是不是已经有一份**？（`adr.mjs search <词>` / `grep DATAFLOW`）有 → 改成指针。③ **修正是否已回改原文**？只记在新文档 = 亲手制造 SSOT 第二份。

## 3 · 用户报症状时怎么开工（最高频、最容易跑偏）

> **触发**：用户说「X 不好用 / 我测了还是不行 / 这里不对劲 / 只能做一次」。
> **🔒 唯一的开工指令**：**不要去找那个 bug。去找这段设计正确时该长什么样，然后照着把它重写。**
> ❌「这个 `if` 为什么没进去？」= 在**修症状**（会滑向补丁 + 兜底）。✅「这个能力正确落地时该是什么结构？现在这段结构为什么表达不了它？」= 在**做正确**。

**开工动作（顺序即优先级）**：① Step 0 普查"同一件事被实现成几份" ② **先把最优解写下来（一屏以内）** ③ **横向查"同领域别处是否已满足"** ④ 现状与正确形态**逐条对照**，表达不了正确形态的结构 → **删掉重写**，不缝补 ⑤ 病灶常不是"某步写错"而是"**缺了一步**"（例：落盘 ≠ 入库，缺"归位"） ⑥ 把判据与契约**放回它该在的层** ⑦ 检查"**代码里写了、UI 上出不来**"的东西（几乎总是结构/布局错，不是功能没写完）：非法嵌套（Tooltip 套 Tooltip）· 塌陷高度链（`flex-1` 缺 `h-full`）· 被 `disabled`/`pointer-events:none` 吞掉的入口 · 被上层盖住的图层 ⑧ **只读实测取证**，且**用与真实调用一致的口径**（用错参数会得出相反结论）。

**⛔ 五种"修症状"的滑法**（识别出就退回第 ② 步）：**改一版试一次**（用试错代替设计，每猜一次加一层兜底）· **猜环境**（缓存/没重启）· **在错误的位置做深度优化** · **靠探针反复证伪假设**（探针是"证明我改对了"的工具，不是猜谜机）· **没想清最优解就动手**（判据：说不出"最优解 + 别处有没有"就动手了）。

**"做完了"的判据**：症状不出现（**且兜底数量净减**，不是被埋了）· 该能力**1 份**判据（不是 N 份）· 链路**更短更直**（环节数下降）· 契约在**拥有真相的那层** · 非法嵌套/塌陷布局**逐条清掉** · 失败是**判别联合 + 根部炸开** · 只碰目标能力（`git diff` 逐行能说出"为什么必须改它"）· 证据 = **用户实测通过 + 只读实测 + 闸/测试 + 反向探针** · 每条结论一条可复现命令。

> **一句话**：**不要服务那个症状，要服务这段能力的正确性。**

## 4 · 卡住时退回（速查）

| 在做什么 | 发现 | 退回 |
| --- | --- | --- |
| Step 0/1 | **没写出"最优解"**，或说不出"同领域别处是否已满足" | 回 Step 0 第 0/3 步（**最该退的一步**） |
| Step 0 | 同类能力已有 ≥2 份，我正准备再写一份 | 回 Step 0：先定共用层 |
| Step 0 | 同领域**别处已有**更强实现 | **一行不写**（那份就是最优解） |
| Step 1 | 拿不出硬证据 | 判非债 + 留痕，结束 |
| Step 2 | 找不到共同母体 | 回 Step 1：可能混了假需求 |
| Step 3 | 最优位置要动 ≥10 个消费方 | 重选（下沉 + `re-export`） |
| **Step 3** | **落点结构已被在飞方案点名**（重写/退役/合并） | **退回重选落点**（别在旧结构上打洞） |
| **Step 3** | 判据留在**症状层**，或收口**只搬键不搬语义** | 判据层 ⇒ 回 Step 2 重判母体；只搬键 ⇒ 视为**未完成** |
| Step 4 | 契约形状要改 | 回 Step 3（位置错了契约白定） |
| Step 6 | 签名/结构兜不住需求 | 回 Step 3/4 重定，**禁止硬填** |
| Step 3/6 | 收口后既有测试变红 | 回 Step 3：很可能把"判据重复"误当"探测重复"合了 |
| Step 3/6 | 最优位置被闸拦住 | **别绕**：结构偏好闸 → 直接改闸（收窄不放宽）+ 闸探针先红后绿；红线闸 → 交用户 |
| Step 7 探针 | "先红"没红 | 重写断言；**测试不红 = 没测到东西**（不许拿环境当免死金牌） |
| Step 7.2 | 写了**自证式断言** | **删掉该断言**（还不如不写） |
| Step 7 落账 | 结论只有形容词、拿不出命令 | 补凭证（一凭证闸） |
| Step 7 落账 | 同一份证据出现两次 / 修正只记在新文档 | 留一处 + 指针 / **回改原文** |
| 任何一步 | 引用的**符号/文件/能力不存在**或未导出 | 回当前步重新取证 |
| 任何一步 | 发现"需求"本身不存在 | 回 Step 1（最常见也最该退的一步） |
| 任何一步 | 准备**新增一道机器闸** | 先过「建闸前置评审」6 问（**默认不建**）+ 负例探针 |
| 任何一步 | 你的理由是「仓里一直这么写 / 既有约定如此」 | 先答「它凭什么成立？」；答不出 → **它就是要被消灭的对象** + 落一条 ADR |
| 任何一步 | 命中 `scripts/**` · 流程文档 · `package.json` 缺陷 | **不停工：当场修**（工具债不延后） |
