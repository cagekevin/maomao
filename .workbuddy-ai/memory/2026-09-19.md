## 踩坑留痕（可复用）

8. **`try/catch` 包异步 → 假护栏**：`try { p.finally(cb) } catch {}` **捕获不到** `p` 的 rejection，
   必须 `p.finally(cb).catch(...)`。判断"某 catch 是否生效"要看它包的是不是**同一个** promise 对象
   （派生 promise 是**不同对象**，`===` 比较也会因此恒假）。
7. **localTool 与 src 是两套世界**：localTool 自带 package.json/tsconfig（`"type":"module"` + `.js` 说明符），
   **不能** import 前端原语（如 `asyncGuard.tryParse`）；看到"改调原语"类修法要先确认是不是同一个包。

1. **`debt.mjs add` 校验**：摘要 ≤120 字、禁竖线；`--anchor` **只写 `daily/架构日志/` 下的文件名**
   （含路径分隔符会被拒）。写入口**没有"改摘要"命令** ⇒ 数字写错后用
   `resolve <ID> --status 待还 --note "…"` 把修正写进状态列（禁手改表格行）。
2. **注释里不要抄工具指令的字面量**：在注释里写 `eslint-disable no-unreachable` 会被 ESLint
   当成**指令**生效（实测：整文件的不可达检查被静默关掉）。描述要用自然语言。
   —— 同理，注释里写 `catch-ok: PARSE_FALLBACK` 这类标记字面量会污染未来的 grep 普查。
3. **`noUnusedParameters` + 解构参数**：删掉唯一使用点后会报 TS6198「All destructured elements
   are unused」；本仓 `.eslintrc.cjs` 已配 `argsIgnorePattern: '^_'`，用 `{ text: _text }` 即可
   （**键名不变** ⇒ 调用方零改动）。
4. **判断"导出是否该删"前先看 `knip.json`**：本仓有 `ignoreExportsUsedInFile: true`（有理由：
   TD-22-10），即"同文件内被使用的导出不算死代码" ⇒ 不要顺手去掉这类 `export`。
5. **zsh 陷阱**：`grep -rn "a\|b"` 会静默失败，一律用内置 Grep；`${PIPESTATUS}` 不可用，取退出码别接管道。
