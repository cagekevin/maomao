# 工作日志 — 2026-08-16

> 今日工作：**打通「任务 ID」全链路** —— 让用户在前端任务中心看到的那个 `task_xxx` ID，能一步步查到关联的 Lovart `thread_id`，再直接向 Lovart 查任务状态/结果。同时修掉任务跑不通的两个 bug（前端 url 数组、localTool async 落库）。详见 §一~§五。

---

## 一、背景：任务为什么"跑不通、查不了"

### 现象

- 前端发任务后，任务中心显示一个 ID（`task_msuk85sh_...`），但用户拿它查不到任务状态。
- 更早还报 `i.startsWith is not a function`，任务直接 failed。

### 根因（两个层面）

1. **ID 断链**：前端自造的 task_id **从不发给后端**，而 Lovart 上游只认自己的 `thread_id`（UUID）。两者完全不关联，用户拿前端 ID 无从查起。
2. **两个 bug 导致任务失败**：
   - **前端**：网关返回 `result.images[0].url` 是**数组**（APIMart 规范 `{url:[...]}`），前端 `imageApi.js` 取整个数组当结果 → 传给 `taskStore.done()` → `resultUrl.startsWith('blob:')` 崩 → `i.startsWith is not a function`。
   - **localTool**：`persistThreadId` 里 `const db = getDb()` 没 `await`，而 `getDb` 是 async → 拿到 Promise 无法 upsert → thread_id 静默不落库。

---

## 二、打通任务 ID 全链路（核心）

### 设计：localTool 是关联点

- 前端 ID 和 Lovart ID 只在 localTool 中转时能同时看到（网关不落盘、Lovart 不回显前端 ID）→ **关联必须在 localTool 做**。
- 链路：
```
前端把前端 task_id 带给 localTool → localTool 转发网关拿到 thread_id → localTool 把两者关联落库
→ 拿前端 task_id 用 db-query.mjs 查到 thread_id → 再拿 thread_id 直接问 Lovart 状态/结果
```

### 改动（前端 + localTool + 脚本）

- **前端**：`taskStore.reportGenerate` 暴露 `taskId` + 新增模块级变量 `setCurrentTaskId/getCurrentTaskId`；`useNodeGeneration` 调 `reportGenerate` 后 `setCurrentTaskId(taskCtl.taskId)`；`imageApi.js`/`videoApi.js` 的 `proxyRequest` 读它塞 `payload.taskId`（JSON 形态），FormData 走 `x-task-id` header。
- **localTool**：`/api/proxy`（`system.ts`）读 `body.taskId`，转发网关时透传；响应后 `extractAndPersistThreadId(resBody, frontTaskId)` 从网关返回解析 task_id → 去掉 `task_` 得 thread_id → `persistThreadId(threadId, taskId, {}, frontTaskId)` 落库（以网关 task_id 落一行 + 给前端 task_id 记录补 thread_id）。
- **数据库**：`tasks` 表加 `thread_id` 列 + 迁移；`tasks.ts` 白名单/映射加 `thread_id`。
- **脚本** `db-query.mjs`：`--lifecycle`（thread_id 双键 grep）+ 新增 `--lovart-status` / `--lovart-result`（直连 Lovart，HMAC 签名，**自动走代理**——原生 fetch 不走系统代理，用 `node:net`+`node:tls` 实现 CONNECT 隧道 + 环境变量/探测端口）。

## 三、修 bug 1：前端 `i.startsWith is not a function`

- **根因**：网关 `result.images[0].url` 是数组，前端 `imageApi.js` 取成数组当 `r.url`，`taskStore.done` 里 `resultUrl.startsWith` 崩。
- **修复**：
  - `imageApi.js`：`generateAsync`/`readSseImageUrl` 取 `url` 时 `Array.isArray ? url[0] : url`。
  - `taskStore.done` + `useNodeGeneration`：`done` 只传字符串（`typeof === 'string'` 防御，兜底防再崩）。

---

## 四、修 bug 2：localTool `persistThreadId` 不落库

- **根因**：`const db = getDb()` 没 `await`，`getDb` 是 async（sql.js 首次异步初始化），拿到 Promise 无法 `upsertTask` → 静默失败。
- **修复**：`persistThreadId` 改 async + `await getDb()`；调用点 `.catch()` 吞错（fire-and-forget，不阻断转发）。
