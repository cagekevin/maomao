## 一、apimart-gateway/main.py：分层重构落地（核心提交）

提交 `4b6eb0e`，原作者将 `main2.py` 的完整实现按分层骨架合回 `main.py`，保留参考实现 `main2.py` 不删。

### 架构定位声明（写入文件头）
明确网关是「**纯中转站**」角色，只做三件事：
1. 接收外部 OpenAI 风格请求（`/v1/images`、`/v1/videos`、`/v1/chat`）
2. 做最小必要请求规范化（范围解析、数量限制、模型别名映射）
3. 转发给 Lovart 并回传结果

**不关心**两件事（职责边界）：
- 不关心前端：何种节点、风格、用哪个混淆字段，网关只认「图片/视频/聊天」三种能力
- 不关心 Lovart 内部：项目/工具/生成策略由 `lovart_client.py` 负责，本文件只调用、不侵入

### 三种能力（capability）
- 图片：`category="IMAGE"` → `/v1/images/*`、`/v1/gateway/*`（图片）
- 视频：`category="VIDEO"` → `/v1/videos/*`、`/v1/gateway/generate`
- 聊天：`/v1/chat/completions`（Agent 自选模型，不强约束 IMAGE/VIDEO）

**别名（alias）是中转站正常职责**（见 `_IMAGE_RULES`/`_VIDEO_RULES`）：把前端 model 名翻译成 Lovart 工具名，只翻译不新增复杂度/分支。

### 分层结构（Config / Utils / TaskService / 路由）
- **Config 类**：集中所有环境变量（`LOVART_BASE_URL`、`USER_KEYS`、`OPEN_RELAY`、`AUTO_CONFIRM`、`TASK_RESULT_TTL`、`CHAT_SYNC_TIMEOUT`、`PROJECT_CACHE_FILE` 等）
- **TaskService 类**：封装项目失效自愈、done 翻转防抖、AUTO_CONFIRM 自动/手动确认
- **路由层**：补回 4 个路由 `draw/completions`、`uploads/images`、`gateway/upload`、`balance`

### 统一错误转换
新增 `lovart_err_response`，统一 LovartError→OpenAI 错误 JSON 转换，消除重复构造；`confirm_task` 补 `try/except LovartError` 包裹，与 main2 逐字段对齐。

### 回收的关键注释/能力
- 项目失效自愈（`send_with_project` / `_is_project_invalid`）
- 全链路 traceId（提交打点 + 轮询回读关联）
- `reference_videos` / `reference_audios` 静默丢弃修复
- 路由别名逻辑

### 变更量

## 四之一、网关别名映射子串匹配陷阱（代码审查发现，未改）

审查 `apimart-gateway/main.py` 的 `resolve_prefer_models`（271-279 行）时发现：别名命中用的是**子串包含** `if any(k in m for k in keys)`，而非全等/边界匹配。实测验证（临时探针脚本跑了 16 个用例）结论如下：

### 正常命中（符合预期）
- `seedance-2` / `seedance-2.0-fast` / `kling-v3-omni` / `kling-v3-omni-pro` / `gpt-image-2.5` 等，含未注册名与空串正确返回 `None`。

### 误命中 / 漏匹配（子串贪婪导致）
| 输入 | 实际命中 | 问题 |
|---|---|---|
| `seedance-2.5` | `seedance_v2_0` | 版本号被错误降级成 2.0（若加 2.5 规则还须放 `seedance-2` 之前，否则被截胡） |
| `seedance-2x` | `seedance_v2_0` | `2x` 非 2.0，被错误归一 |
| `kling-v3`（无 `-omni` 后缀） | `<<NONE>>` | 反向漏匹配：前端历史 model 名静默失效 |

### 根因与影响
- 子串匹配是用"放宽容错"换"不加 if 分支"，符合重构"只翻译不新增复杂度"意图，但**版本号边界会被错误归一**，**别名表必须与前端 `BUILTIN_MODELS` 严格对齐**，否则前端传的名在网关表查不到就静默丢模型。
- 已确认 Lovart 侧**无 seedance 2.5**，故不新增该规则。

### 根治方案（暂未实施，用户决定先保持现状）
将 `any(k in m)` 改为**边界匹配** `m == k or m.startswith(k+"-") or m.startswith(k+".")`，并把预处理 `m = model.lower().replace("_","-")` 一并加 `.replace(" ","-")` 以兼容规则里的空格写法（如 `seedance 2.0 fast`）。
- 副作用轻微：近似名（`gpt-image-2.5`、`kling-v3-omni-pro`）不再静默命中 → 更可预测；规则顺序 fast 仍需在前；无"悄悄出错"的回归。
- 评估为低风险，留作后续待办。

## 六、discountVideo 独立通道验证结论（已闭环，原 07-31 待验证项）

经核对 `docs/15`、`docs/16` 与 `main.py`，该项**验证通过**，结论如下：

### 验证证据
1. **`main.py:899` 注释明确**：网关只有三种能力（图片/视频/聊天），**不区分「特惠/普通」视频**。
2. **`docs/16` §2.1（78 行）**：特惠节点用独立私货字段 `discountVideoApiUrl`/`discountVideoApiKey`（非 apiConfigs），但请求仍打向网关统一前缀 `/v1/gateway/*`；后端网关是**统一前缀盲转**，只认 `Authorization` token → 两套凭据在网关层被归一为同一种 Bearer token 直打。
3. **`docs/15` §6.0（229-233 行）调用态分叉表**：普通视频 `m3` 取自 `e3.apiUrl`（选中 apiConfig），特惠视频 `m3` 取自闭包 `u2=discountVideoApiUrl`（固定字段）；**两者最终都到 `/v1/gateway/task`，仅凭据来源不同**。

### 定性
- **后端网关转发层**：discountVideo 通道正确，请求可达 Lovart、走统一盲转、返回结构一致（视频统一返回对象结构，899 行确认）。✅
- **「独立」的本质在前端调用态**（凭据来自 `u2`/`d2` 而非 apiConfig），属设计上的**计费隔离硬隔离**（强制走特惠计费通道），非 Bug。
- **遗留风险（非功能性，属业务开关）**：`docs/16` 指出的两套凭据在网关侧无语义区分，若未来放开第三方进特惠会绕过计费——需业务层用 `allowInDiscount` 白名单控制（见 docs/15 §6.4），非当前通道正确性问题。

→ 该项从「待验证」改为「已验证通过」，移出待办。
