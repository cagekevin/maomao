## 一、图片生成改 SSE 流式，任务中心有实时进度

**背景（用户需求）**：图片生成/绘图节点（`draw/completions`、`images/generations`、`images/edits`）被 localTool 强制 `wait=1` 同步，前端**同步等 OpenAI JSON 结果**，任务中心进度一直卡 0（无中间反馈）。用户希望任务中心能看到进度。

**调研结论（关键）**：前端图片节点 `U` 函数（`H_.jsx` 2786-2868）**本就有**完整的 SSE progress 更新逻辑（收到 `data:{progress:N}` → 更新任务中心进度；收到 `status:succeeded` + `results[0].url` → 取最终图），只是被 `let ie = _shared.R && F.includes(\`*\`)` 的 **`model 不含 *`** 限制卡住 → `ie=false` → 走同步 else 分支，SSE 逻辑被跳过。所以只需放开 `ie` + 让网关/localTool 支持 SSE 透传即可复用前端现成逻辑，**前端仅改 1 行，最安全**。

**改动（前端仅 1 行 + 网关 + localTool）**：

1. **前端 `src/bundle/httpClient-BknZwXjG_components/H_.jsx`（1 行）**：图片节点 `U` 内 `let ie = _shared.R && F.includes(\`*\`)` → `let ie = _shared.R`。放开 `*` 限制，本地图片模型（gpt-image-2 / nano-bn）也走 SSE 流式分支。
2. **网关 `apimart-gateway/main.py`**：`_do_submit` 的 `if(wait)` 同步分支改为返回 `StreamingResponse(media_type="text/event-stream")`：
   - 轮询期间 `yield data:{"progress":N}`（从 `check_and_fire_task` 的 `response.body` 解析 `data.progress`）；
   - 完成 `yield data:{"status":"succeeded","results":[{"url"}]}` + `data:[DONE]`；
   - 超时 `data:{"status":"failed","error":"同步等待生成结果超时"}` + `[DONE]`（保留 P0-4 超时埋点 `[submit:sync-timeout]`）。
3. **localTool `localTool/src/routes/system.ts`**：新增文件级 helper `pipeSseStream(res, fetchRes, logMethod, logUrl)`（检测 `text/event-stream` 则解压 + `createSSEParserTransform` 逐块 pipe，非 SSE 返回 false）；在 `handleProxyFormData` 与 `handleProxyJson` 两处 wait 分支（原本 `fetchRes.json()`）后插入 `if (pipeSseStream(...)) return;`——网关返回 SSE 就流式透传，否则回退 `json()`。

**验证**：`npm test:smoke` ALL PASS → `npm run build` 回灌 dist 成功 → `localTool npm run build`（tsc）编译通过 → 无 lint 错误 → 日志实证图片走 `[proxy:stream] POST /v1/draw/completions | 200 | started`（SSE 生效，非 400）。

**登记**：`docs/01` 变更登记新增 **变更 #12**。

**生效方式**：前端刷新浏览器插件 + 重启网关（9004）+ 重启 localTool（18080）。

## 二、网关补读 `files` 素材透传给 Lovart（图片/视频/音频）

2. **`apimart-gateway/contract.py`** `URL_MERGE_GROUPS` 的 image/video/audio 三组均补上 `files`，保持契约文档一致。

**验证**：无 lint 错误；已提交推送（`f8d7884`）。

## 三、排查：控制台 `/api/proxy 400` 与图片生成慢的根因

**现象**：控制台刷 `POST http://127.0.0.1:18080/api/proxy 400`（`App-BX6o9fW5.js:22` + setTimeout 循环）。

**查日志结论（不是我们引入的）**：

- **localTool 日志**（`localTool/logs/localtool_18080.log`）：400 全部来自 `[proxy] GET .../v1/gateway/task/discountVideoNode-xxx | 400` —— **特惠视频任务遗留轮询**：前端任务中心定时轮询一个**已生成结束/被清理**的特惠视频 task_id，网关对不存在的任务返回 400。与本次改动无关。
- **网关日志**（`apimart-gateway/logs/apimart_9004.log`）：图片生成任务正常提交、正常轮询（`task_2daff3e4...` `[submit:parse] raw_urls=2` → `[poll] poll=0→33` → `lovart_raw=done`），全程无 400。

**修复（同日，localTool）**：前端特惠全局轮询（`Vr.jsx` L1324-1355）**只认 404** 才累计 `notFoundCount` 停止轮询，**400 被忽略 → 无限轮询刷 400**。已在 `localTool/src/routes/system.ts` 的 `handleGatewayTask` 把网关返回 400 归一为 404（`const status = fetchRes.status===400?404:fetchRes.status`），前端正确识别"任务未找到"→ 3 次后停止轮询。属 localTool 后端改动，官方前端更新不用重打。已登记 `docs/01` 变更 #12「另（同日修复·特惠视频 400 遗留轮询）」。

**图片生成慢的根因**：从网关日志看，图片生成 `poll=0→33`（间隔 3s，约 100 秒才 `done`），其中 `lovart_raw=running` 持续约 90 秒——**慢在上游 Lovart Agent 推理**（不可控的大头）；网关层仅有 3s 轮询间隔 + `done` 防抖的轻微固定开销。后续优化方向：缩短轮询间隔、去掉 wait 模式的 `done` 防抖，但收益有限。

## 四、图生图卡死修复：参考图裸 base64 原样透传（2026-08-05 下午）

**现象**：图生图（带参考图）任务在任务中心一直 `running`，5~10 分钟既不成功也不失败；Lovart 后台看不到/无图产出；文生图（不带图）正常。

**排查过程**：曾怀疑 files 读取、AUTO_CONFIRM、SSE，逐一用 git diff / `-S` 核实排除；`git reset --hard` 回退仍无法解决（因前端裸 base64 不经过 files 字段）。

**最终根因（网关调试日志实证）**：
```
[submit:rawurl] traceId=- [0] /9j/4QAYRXhpZgAASUkqAAgAA...   ← JPEG 裸 base64（无 data: 前缀）
[submit:attach] traceId=- [0] /9j/4QAYRXhpZgAASUkqAAgAA...
```
前端把参考图以**裸 base64**（`/9j/...`，无 `data:` 前缀）发出。旧 `resolve_attachments` 只认 `http`/`data:` 前缀，裸 base64 走兜底 `else` **原样透传给 Lovart** → Lovart 无法识别 → 一直 `running` 卡死。

**修复（`apimart-gateway/main.py`）**：重构 `TaskService.resolve_attachments`，统一翻译各种形式参考素材为 Lovart 可用 CDN URL：
- `http(s)` → 直接透传
- `data:` base64 → 解码上传 CDN
- **裸 base64（`/9j/` JPEG、`iVBOR` PNG、`R0lGOD` GIF、`UklGR` WebP、`SUQz` MP3、`AAAA` MP4…）→ 识别魔数 → 解码上传 CDN（核心修复）**
- `blob:`/本地路径/未知 → 丢弃（`[resolve:drop]` 日志），不再透传污染 Lovart

新增：`_B64_MEDIA_MAGIC`、`looks_like_base64_media()`、`_ext_from_b64_magic()`、`_ext_from_data_header()`。

**验证（实测通过）**：任务 `task_3cad7140`（17:40:05）`raw_urls=1 attachments=1` → 约 55s → `lovart_raw=done` → `POST /v1/draw/completions 200 OK`，图生图恢复。

**登记**：`docs/28-图生图卡死-排查记录与回滚.md`（含完整排查与修复 diff）。

**生效方式**：重启网关（9004）。
