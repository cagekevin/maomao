## 一、根因（证据链）

普通视频节点（你用的那个）= `videoNode` → 处理函数 `Gr`（绑定 `onGenerateVideo`）。

### 1.1 前端做了什么（`script/output.js` 函数 `Gr`）

| 位置（参考） | 代码 | 说明 |
|------|------|------|
| `Gr` 内 | `g = m.replace(...)` | `g` = 视频 base，是**网关 apiUrl（变量 `m`）**，不是 localTool 地址 |
| `Gr` 内 | `_ = \`${g}/v1/videos\`` | 提交 URL = `网关/v1/videos` |
| `Gr` 内 | `S = o==='auto' ? ['json','formdata'] : [o]` | **默认先试 JSON，再试 FormData** |
| `Gr` 内 | `w = await Bl(_, {method, headers, body, ...Ee})` | 经 `Bl` 路由（见 1.2） |
| `Gr` 内 | `O = await w.json()` | 取提交响应 |
| **`Gr` 内** | **`A = O.id`** | **关键：前端按「对象」取 `id` 作为轮询键** |
| `Gr` 内 | `Bl(\`${g}/v1/videos/${A}\`, {...})` | **轮询** `GET 网关/v1/videos/{A}` |
| 轮询解析 | `c = i(n.video_url, a.video_url, a.url, n.url, n.result_url, o.video_url, o.url, s.video_url, s.url, n.video, n.result?.video)` | 取视频 URL 的字段候选（`a=n.metadata,o=n.data,s=n.output`） |
| 轮询失败 | 连续失败 5 次 → `查询任务状态失败次数过多` | 最终报错 |

> ⚠️ 注意：`g` 是网关地址（由 `Bl` 经 localTool 代理转发到网关），localTool 地址在 `Ee.localToolBaseUrl`/`Bl` 内部使用，二者不要混淆。

### 1.2 请求如何走到 localTool 代理（决定 wait 注入是否触发）

`Bl(e, t)`（`script/output.js`）：当 `proxyMode==='local-tool'`（默认，`Ee` 中 `proxyMode:'local-tool'`）时对 JSON path 把 URL 塞进 `body.url` 并 POST 到 `localTool/api/proxy`：
- **JSON body**（视频默认先走这条）：`fetch(localTool/api/proxy, {body: JSON.stringify({url: e, method, headers, body})})` → 命中 `handleProxyJson`（**system.ts:249**）。
- **FormData/Blob**（JSON 失败后回退）：`X-Proxy-Url: e` 头 → 命中 `handleProxyFormData`（**system.ts:105**）。

两处的 `ASYNC_PATTERN` 都含 `videos/?$`，所以**视频提交会被注入 `wait=1`/`wait:true`**，强制走网关同步分支。

### 1.3 后端链路实际返回（契约错配）

**网关 `_do_submit`**（`main.py`）：
- 同步分支（`wait=1` 生效）返回 `ok([{"url":..,"status":"completed","task_id":..}])` 或失败数组（main.py:802/814 附近）。
- 异步分支（未注入 wait 时）返回 `ok([{"status":"submitted","task_id":..}])`。
- `ok()` = `{code:200, data:...}`（main.py:117-118），经 localTool 剥信封（system.ts:200-201）后前端拿到的是 **数组 `[{...}]`**。

> 根因要点：视频节点默认走 JSON 路径 → 命中 `handleProxyJson`(249) 注入 `wait:true` → 网关走同步分支 → 返回**数组**；前端 `O.id` 在数组上恒 `undefined`。

### 1.4 错配导致失败（必然）

- 前端 `A = O.id`，但 `O` 是**数组**，`O.id` 永远 `undefined`。
- 轮询 URL 变成 `GET /v1/videos/undefined` → `get_task("undefined")` → `task_id` 不以 `"task_"` 开头 → 返回 `err(400, "Invalid task ID")`（main.py:833-834）。
- 前端轮询非 2xx 即 `Polling failed` → 连失败 5 次 → 报错。

**一句话根因**：普通视频前端按「对象 `{id}`」设计（异步提交 + 轮询 `GET /v1/videos/{id}`），但
(a) `system.ts` 在 `videos/?$` 上注入 `wait=1`（视频默认走 JSON 路径命中 249 行），把提交变同步；
(b) 网关提交响应是「数组 `[{...}]`」而非「对象 `{id}`」；
→ 前端 `O.id` 恒为 `undefined` → 轮询键错误 → 400 → 5 次失败。
（注：G1/G2 的 `GET /v1/videos/{id}` 状态查询路由**已存在**，main.py:933-942，但轮询键是 undefined 所以永远用不上。）

## 二、修复方案（已实施，4 处改动）

> 全部改动均已落地（未提交）。以下为实际落地的代码，非提案。

### 改动 1 · localTool：视频提交不再注入 `wait=1`（两处都改，覆盖普通视频 + sd2Video）
- 文件：`localTool/src/routes/system.ts`
- **两处** `ASYNC_PATTERN` 均移除 `videos/?$` 与 `video/generations`（图片 `images/generations`、`draw/completions` 保留）：
  - `handleProxyFormData`（**system.ts:107**）：正则改为 `/\/(images\/(generations|edits)|draw\/completions)/`
  - `handleProxyJson`（**system.ts:252**）：同上（视频默认先走这条 JSON 路径，**这处才是实际命中点**；sd2Video 提交也走此路径）
- 理由：普通视频节点与 sd2Video 前端均为「异步提交 + 轮询」设计，注入 `wait=1` 会强制造同步、返回结构错位，导致前端取不到 `task_id` 去轮询。
- 影响：图片生成保持同步不受影响；sd2Video（`/v1/video/generations`）**提交经 `Bl`→localTool `handleProxyJson` 代理，原本同样会被注入 `wait` 而失败**——本次一并移除 `video/generations` 后随普通视频走异步修复；其轮询为直连 kkidc（不经 localTool），前端已正确处理其 `{code,data}` 信封，不受影响（详见第三节）。

### 改动 2 · 网关：视频异步提交返回「对象 `{id,...}`」而非「数组」
- 文件：`apimart-gateway/main.py`
- 位置：`_do_submit` 异步返回（main.py:824-829）。
- 实际落地代码（**用 `category == "VIDEO"` 隔离，图片保持数组**）：
  ```python
  if category == "VIDEO":
      # 普通视频取 O.id（Gr），discountVideo 取 P.task_id||P.id（Jr），对象结构二者都能拿到 task_id
      return ok({"id": task_id, "status": "submitted", "task_id": task_id})
  return ok([{"status": "submitted", "task_id": task_id}])
  ```
- `id` 与 `task_id` 同值为 `"task_..."` 形式，满足 `get_task` 的 `startswith("task_")` 校验（main.py:833）。
- 同步分支（802/814）视频不再注入 wait 后不会走到，保持数组不动（图片仍走同步，不可改）。

### 改动 3 · 网关：视频完成时把 URL 显式映射到顶层 `video_url`（必须，非实测项）
- 文件：`apimart-gateway/main.py`
- 位置：`_task_view`（main.py:363-374），在 `d["result"] = result` 之后。
- 为什么必须：Lovart 结果经 `lovart_to_apimart` 后为 `result.videos[0].url[0]`（嵌套），而前端候选列表**第一顺位就是 `n.video_url`**，二者不匹配（前端没有读 `n.result.videos`）。若不映射，`c` 必为空、视频生成"成功却没视频"。
- 实际落地代码：
  ```python
  if result is not None:
      d["result"] = result
      # 视频结果映射：Lovart 返回 result.videos[0].url[0]，前端轮询取 n.video_url（候选第一顺位），
      # 需显式提到顶层，否则视频 URL 取不到。
      if isinstance(result, dict):
          vids = result.get("videos") or []
          if vids and isinstance(vids[0], dict):
              vurl = vids[0].get("url")
              if isinstance(vurl, list):
                  vurl = vurl[0] if vurl else None
              if vurl:
                  d["video_url"] = vurl
  ```
- 前端 `n.video_url`（候选第一顺位）直接命中，无需改前端。

## 三、影响面评估（已核实）

| 节点 | 提交路径 | 是否受影响 | 说明 |
|------|----------|-----------|------|
| **普通视频**（你用的） | `网关/v1/videos` | **修复目标** | 改动 1+2+3 直接修复 |
| sd2Video | 提交 `网关/v1/video/generations`（经 localTool）/ 轮询直连 `ai-api.kkidc.com` | **随普通视频一并修复** | 提交经 `Bl`→localTool `handleProxyJson` 命中改动 1，原会被注入 `wait` 失败；改动 1 移除 `video/generations` 后已修复；轮询直连 kkidc，前端已正确处理其 `{code,data}` 信封 |
| 图片生成 | localTool `/v1/images/generations` | 不受影响 | 仍注入 `wait=1`，保持数组返回 |
| discountVideo | 独立 `discountVideoApiUrl/v1/gateway/generate` + `/v1/gateway/task/{id}` | **已验证：独立且自身正确** | 见下 |

**discountVideo（处理函数 `Jr`，绑定 `onGenerateDiscountVideo`，非文档初版误写的 `Dr`）**：
- 提交到 `discountVideoApiUrl/v1/gateway/generate`、轮询 `.../v1/gateway/task/{id}`，**不走 `/v1/videos`，不经 `videos/?$` 的 ASYNC_PATTERN**，故改动 1 不影响它。
- 取 id 方式 `P.task_id || P.id`（Jr 内），与改动 2 的 `{id, task_id}` 兼容（优先 `task_id`）；改动 3 的 `video_url` 仅是新增字段，不影响它从自有任务表 `jn.current.resultUrl` 取结果的独立逻辑。
- 结论：**独立通道，本 bug 与三处改动均不波及它**，不在本次修复范围。

### ✅ discountVideo 自身正确性：单列验证（已做，结论——无需改动）

针对文档原「其自身正确性需单列验证」这一遗留项，已逐段核对 `script/output.js` 的 `Jr`（`onGenerateDiscountVideo`）与 `localTool/src/routes/system.ts` 的代理逻辑，结论为**自身逻辑自洽、与本次三处改动零耦合，无缺陷、无需改代码**：

| 验证点 | 代码位置 | 结果 |
|------|----------|------|
| 提交是否会被注入 `wait` | `Jr` 提交走 `Bl`→`handleProxyJson`；当前 `ASYNC_PATTERN`（`system.ts:107/252`）= `/\/(images\/(generations\|edits)\|draw\/completions)/` | `gateway/generate` **本就不匹配**，改动 1 移除的 `videos/?$`/`video/generations` 也与它无关 → 绝不注入 `wait` |
| 提交响应解析 | `output.js:49039` `F = P.task_id \|\| P.id` | `system.ts:340-347` 的信封剥离仅在响应同时含 `code`+`data` 时生效；无论剥离与否，`task_id`/`id` 都能取到 → 健壮 |
| 轮询是否会被注入 `wait` | `output.js:49107` `Bl(.../v1/gateway/task/${F})`（默认 GET） | 同上，`gateway/task/...` 不匹配 ASYNC_PATTERN → 不注入 |
| 轮询响应解析 | `output.js:49167` `i = r.status`；结果取 `r.result?.url \|\| r.resultUrl`（外加 `debug_extracted_url` 兜底） | 信封剥离对 `{status, result}` 结构透明，`r.status`、结果 URL 均正确可读 → 健壮 |
| 是否触碰 `apimart-gateway/main.py` | `discountVideoApiUrl` 为**独立网关地址**，非 main.py | 改动 2（`_do_submit` VIDEO 分支）、改动 3（`_task_view` 顶层 `video_url`）均不作用于它 |
| 是否依赖改动 3 新增的 `video_url` | `jn.current` 快路径取 `t.resultUrl`，轮询取 `r.result?.url`；均未引用 `video_url` | 改动 3 对其无副作用 |

> 综合：discountVideo 走独立网关 + 独立提交/轮询契约，三处改动（system.ts 去 `videos/?$`/`video/generations`、main.py VIDEO 返回对象、main.py 顶层 `video_url`）均不触达它；其自有 id/status/result 解析对「是否带 `{code,data}` 信封」均兼容，逻辑自洽。原「需单列验证」项已闭环——**无需任何代码改动**。
