## 三、localTool 出站代理支持（跨平台，零依赖）

**现象**（用户真机走查日志）：`POST /api/files/upload 400` 反复出现，`Failed to sync to local tool: Error: Upload failed`。画布加载时批量转存历史任务的 Lovart 图（`a.lovart.ai/artifacts/agent/*.png`）。

**根因**（实测确认）：
- `a.lovart.ai`（Lovart CDN）在本机**必须经代理 `127.0.0.1:7897` 才能访问**（直连超时 `000`，走代理 `200`）。
- 浏览器配了代理能开；但 **localTool 是独立 Node 进程，原生 fetch 不继承浏览器/系统代理** → `saveRemoteUrl` 里 `fetch(a.lovart.ai)` 超时 → 400。
- 归属：**localTool** `/api/files/upload`（第 3 类职责"上传/资产"）。非前端/网关/官方问题。

**方案**（最优解，满足 CLAUDE.md §3 奥卡姆剃刀，零第三方依赖）：
- 新建 `localTool/src/utils/netProxy.ts` 的 `fetchWithProxy`：
  - 直连优先（本地 `127.0.0.1`/`localhost`/内网、公网直连可达的最优路径）；
  - 直连失败 → 读代理环境变量（`HTTPS_PROXY`>`HTTP_PROXY`>`ALL_PROXY`，大小写兼容）→ 无则探测本机常见代理端口（`7897/7890/1087/1080/8888/8118`）；
  - 用 `node:https` + `tls.connect({socket, servername})` 做 CONNECT 隧道重试。
- `files.ts`：`saveRemoteUrl` 下载改走 `fetchWithProxy`；`handleReadProxy`（`x-proxy-url` 外部代理读）同改。
- `/api/proxy`→`:9004`（本地）、`official.ts`/`passthrough.ts`→官方（直连可达）**不涉及**，保持最小改动。

**实现要点（踩坑记录）**：CONNECT 隧道建立后必须 `tls.connect({ socket })` 包一层 TLS 再发目标请求，否则报「The plain HTTP request was sent to HTTPS port」(400)。`ProxyResponse` 不做 `implements Response`（TS 对 `bytes()` 返回泛型过严），用结构兼容 + `as unknown as Response`。

**验证**（实测通过）：
- 直连失败→代理重试：`fetchWithProxy('https://a.lovart.ai/...')` 返回 **200，3212185 bytes**（与 curl 走代理一致）。
- 端到端 `POST /api/files/upload -F fileUrl=a.lovart.ai... -F subfolder=tasks` → 返回 `{url, path, thumbnailUrl}`，文件 + 缩略图落盘 `~/.maomao-localtool/uploads/tasks/`。

**CLAUDE.md**：§三.2 本地落盘机制补「出站代理」条目（登记本机制与适用点）。
