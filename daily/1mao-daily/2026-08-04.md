## 一、图片生成/聊天节点补齐 baseline 默认模型

**背景（用户需求）**：用户看到特惠视频（discountVideo）节点模型下拉能通过 baseline 注入多个模型，提出「为什么图片生成和聊天不也加上几个默认模型」，并要求确认可行性、尽量不动前端。

**调研结论**：
- 特惠视频能显示多模型，靠「baseline 下发 `discountVideoModel`」+ 前端 `Ki()` 合并；
- 图片生成（`drawingModel`）与聊天（`textModel`）节点的下拉**只读节点上写死的文本字段**（默认 gemini 系列），**不读 baseline**——这是当年只给特惠做了注入、图片/聊天未做的原因，**并非不能加**；
- 前端 `wi()`（loadAppSettings，`Vr.jsx`）**本就有** `if (e.drawingModel)/if (e.textModel)` 分支（约 L838-843），只是 baseline 一直没填这两个字段 → 大部分改动可落在**纯数据层**（baseline），前端仅需 2 行补「无条件覆盖」即可对所有用户生效。

**改动（主体在数据层，前端仅 2 行）**：

1. **`localTool/data/apiConfigs.baseline.json`（纯数据）** 顶层新增两个换行分隔字段（与 `discountVideoModel` 同格式，模型 id **严格取自** `apimart-gateway/main.py` 已支持的本地网关模型，`_IMAGE_RULES`/`_build_models` 逐一核对；**不含任何 gemini**，本地 Lovart 网关不支持 gemini，加了会选不落地）：
   - `drawingModel`：`gpt-image-2-low\ngpt-image-2-medium\ngpt-image-2\nano-bn-pro\nano-bn-2\nano-bn-2-lite`（6 个，全部为本地网关 `_IMAGE_RULES` 支持的图片模型）
   - `textModel`：`lovart-chat`（本地网关 `_build_models` 的唯一聊天模型）

2. **`src/bundle/App-BX6o9fW5_components/Vr.jsx`（前端 2 行）** 在 `discountVideoModel` 无条件覆盖（约 L976）之后补：
   - `if (n?.drawingModel) { Wn(n.drawingModel); }`
   - `if (n?.textModel) { Rn(n.textModel); }`
   - `Wn`/`Rn` 分别为 `drawingModel`(Un)/`textModel`(In) 的 setter（Vr.jsx L595/599）。作用：让 baseline 下发的这两个字段**无条件**覆盖全局默认，与特惠视频对称，确保老用户（本地已有 app_settings）也能看到新模型。

**验证**：
- baseline JSON 解析合法：`drawingModel` split 6 个模型、`textModel` split 1 个模型，全部命中网关 `_IMAGE_RULES`/`_build_models`；
- `npm run test:smoke` **ALL PASS**（契约/React 单实例/chunk 完整，无漂移）；
- `npm run build` 回灌 `dist/` 成功；无 lint 错误（构建期 `Illegal reassignment of import _shared` 警告为 H_.jsx/kl.jsx 等文件**预先存在**，与本改动无关）。

**登记**：`docs/01 长期目标-未来适配方向.md` 四.2 变更登记新增 **变更 #11**。

**生效方式**：重启 localTool（重读 baseline）+ 刷新浏览器插件（加载新 dist 产物）。图片生成/聊天节点模型下拉会出现 baseline 里的默认模型（gpt-image-2 系列 / nano-bn 系列 / lovart-chat），全部为本地网关支持的模型。

**待真机确认（盲点）**：新加的 `gpt-image-2`/`lovart-chat` 等本地模型能否实际调通，取决于对应节点的 API 通道是否指向本地网关（proxyMode=local-tool 下默认即走网关，需真机走查确认）。
