## 一、生成图片「偶发不落盘到资源面板」— 根因实锤（未修，先记录）

### 现象

- 画布上普通图片生成节点，图生成完成、正常显示在画布里；
- 但**有时**资源/素材面板「生成(generated)」tab 里**没有**这条图；
- 是**偶发**，不是必现——同一节点、同一模型，绝大多数正常，个别几次漏。

### 关键事实（后端 DB 实查，`localTool/scripts/db-query.mjs`）

1. **磁盘 `upload/tasks/` 文件数 = resources 表 `folder='tasks'` 记录数 = 448，完全一致** → 只要落盘了 rescan 必入库，无漏。排除"落盘了但库没收录"。
2. **tasks 表 25 条，仅 1 条 `result_url` 是远程 CDN**：`https://a.lovart.ai/artifacts/agent/jT2lW6OVHB1pRbTN.png`（`promptNode-1786670714913-zulz6_1786671546342_0`，gpt-image-2-low）。**其余 24 条全是 `127.0.0.1:18080/files/tasks/...` 本地文件**。
3. 该远程图节点的**前后几次任务都是本地文件**（created_at 1786671538686 和 1786671627257 均本地），同一天、同节点、同模型 → **这就是"偶发"的直接证据**。
4. 画布 default 项目 53 节点，27 个有图：26 个本地 `127.0.0.1:18080/files`，**1 个远程 `a.lovart.ai`**（与第 2 条同一张）。

### 根因定位

生图完成返回 `result_url` 是远程 CDN 地址（`a.lovart.ai`），本应由 `saveRemoteUrl`（`localTool/src/routes/files.ts:96`，CLAUDE.md §四.2「不丢图增强」）下载转存为本地 `127.0.0.1:18080/files/tasks/...`。**那次下载失败（`fetchWithProxy` 超时/VPN 抖动，files.ts:107）→ 前端降级保留远程 CDN URL** → 磁盘无文件 → rescan 扫不到 → 资源面板没有。图仅靠远程 URL 显示在画布上。

**为何偶发**：CDN 可下载就本地化成功（24 次），下载失败就保留远程（1 次），取决于那一刻 `a.lovart.ai` 是否可达/VPN/代理状态 → 时好时坏。

> 与 docs/34 经典场景区分：docs/34 讲的是"AI 节点资产只落盘不入库"（**必现**、设计如此）；本次是**普通生图节点**的图，入库依赖本地化，本地化失败就漏（**偶发**）。

### 可选修复方向（本次未实施）

- **A. 前端提醒（最小改动，前端登记 docs/01）**：生图完成拿到 `result_url` 后判断 URL 形态——是 `127.0.0.1:18080/files/...` 本地还是 `https://...` 远程；远程则 toast 提示"该图未存入本地素材库（网络波动导致转存失败）"。零后端改动，提示时机最准。缺点：只能提醒，不能自动补落盘。
- **B. 后端重试（治本，后端不登记）**：`saveRemoteUrl` 下载加重试退避（如 1s/3s/8s，共 3 次），吸收瞬态失败；每次失败打 WARN。缺点：VPN/网络真断时重试完仍失败。
- **建议**：A+B 都做，先做 A（快、见效），B 兜底瞬态。

> 待办：下次实施时前端改动登记 docs/01 变更 #19（A）；后端改动不登记（B，按约定仅后端）。

## 三、丢图排查"滴水不漏"落地（A 日志留痕 + B 工具，已完成）

> 承接 §一 根因（生图远程 URL 未本地化导致不落盘），本轮把"丢图"从"查不到"变"可追溯"。**前端未改，故 docs/01 无需登记；全部为 localTool 后端 + 工具改动，不登记。**

### A. 日志留痕（`localTool/src/routes/files.ts`，已编译 + 73 项测试全 PASS）

1. **`saveRemoteUrl` 打 `[download]` 日志**：每次下载记 `[download] <时间> | OK/FAIL/SKIP | <url> -> <落盘路径> | 大小`，失败打 `console.error`（含原因）。此前失败只表现 upload 400、日志不记 → 丢图无迹可循。**这是核心留痕。**
2. **`/api/files/upload` 打 `[upload]` 日志**：补响应状态码（`200`/`400` + 原因），此前只记请求不记响应。

> 注：曾考虑在 `[proxy:stream]` 解析 SSE 记 result_url 形态，但侵入流式转发风险大，放弃。saveRemoteUrl 已覆盖"本地化成没成"，足够。

### B. 查库工具扩 3 个命令（`localTool/scripts/db-query.mjs`，已实测）

| 命令 | 作用 |
|---|---|
| `npm run db -- --logs [proxy\|download\|upload\|error\|...]` | 查日志，按前缀/关键词过滤，自动高亮异常（[official] ERR 等） |
| `npm run db -- --task <node_id>` | 同一节点所有任务：status/progress/模型/时间/结果URL形态（本地/远程⚠️），丢图定位 |
| `npm run db -- --lost-check` | **丢图体检**：①tasks 远程URL未落盘 ②失败任务 ③磁盘↔resources 一致性 ④日志下载失败/上传400 |

### 实测（数据说话）

- `--lost-check` 直接命中：`[1] tasks 中结果 URL 为远程 CDN 的: 1 条` = `https://a.lovart.ai/artifacts/agent/jT2lW6OVHB1pRbTN.png`（即 §一 那张丢图，一眼定位）。
- `--task promptNode-1786670714913-zulz6`：9 条任务，1 条标 ⚠️远程URL，其余全"本地文件"。
