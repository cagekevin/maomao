## 一、剧本盒子「编辑已生成提示词」整页白屏崩溃 —— 根因定位

### 现象

- 剧本盒子（`scriptBoxNode`）步骤3「合成提示词」，**编辑已经由 AI 生成的提示词**（single 视图「生图」`prompt` /「生视频」`videoPrompt`，以及 `description`）时，整页白屏（React 整树卸载）。
- 与接口/网关/VPN 无关，纯前端运行时崩溃。

### 根因（源码逐点核对，`src/bundle/httpClient-BknZwXjG_components/c_.jsx`）

分镜字段编辑器 `rt()`（c_.jsx:546）用 **`contentEditable` 内放 React 受控子节点**（`_cmp_a_` 按 `@资产名` 拆成 string+`<span>` 混合数组），叠加两个放大因素，缺一不可：

| # | 因素 | 代码落点 |
|---|---|---|
| ①（原罪） | `contentEditable` 内放 React 受控子节点，浏览器编辑态与 React 虚拟 DOM 双源冲突 | `rt()` L546-606 + `a_.jsx` |
| ② | 每次按键 `onInput` → `He()` → `updateNodeData` → data.shots 新引用 → 整个 2805 行组件全量重渲染 → React 重排该 div 内部 | `rt()` `onInput` → `He()` L231 |
| ③（扳机） | `onKeyDown` 里 `@资产名` 联想/删除直接写 `r.innerText`（`nt`/`go`/`_o`），与 React 重排叠加 | `nt()` L496-543 |

一次按键链路：`onInput → updateNodeData → 全组件重渲染 → React 对"正在被浏览器编辑中的 contentEditable 内部 DOM"做 reconciliation → DOM 突变冲突抛错 → 无 Error Boundary → React 卸载整树 → 白屏`。空字段子节点极简相对安全；内容一变长/含 `@资产`/在 `@` 附近删改即必崩。

## 三、剪贴板粘贴素材「前端显示 2 条」重复修复（变更 #16）

### 现象

剪贴板粘贴一张图片到画布，前端素材 tab 显示 **2 条**（「来自剪贴板」+ `1786429709458-clip-1786429709458.png`），但**落盘文件夹只有 1 个文件**。

### 根因（DB 实查实锤）

`sql.js` 直查 `~/.maomao-localtool/localtool.db` resources 表，确认同一文件两条记录、url 完全一致、id 不一致：

```
id: local-migrated-1786433580909-clip-...png | url: .../files/migrated/1786433580909-clip-....png | source: local-tool | page_title: (空)
id: 1786433580872                            | url: .../files/migrated/1786433580909-clip-....png | source: pasted     | page_title: 来自剪贴板
```

- 「来自剪贴板」：前端 `Vr.jsx` `Ia()` 自造 `id=Date.now().toString()`，`source='pasted'` → `Ar()` → `handleResourcesSave` 落盘 upsert（id 保持时间戳字符串）。
- `1786429709458-clip-...png`：落盘文件被 **rescan**（`resources.ts:126`）用 `id=local-${folder}-${basename}` 再入库一条。
- rescan 去重靠 **id**（`resources.ts:129`），两者 id 不同 → 不跳过 → 同一文件两条记录。
- 磁盘文件名 `1786429709458-clip-...png` = `writeUploadBuffer` 时间戳前缀 `${Date.now()}-` + `resources.ts:223` 的 `clip-${Date.now()}.png` 拼接。

### 修复（仅后端 `localTool/src/routes/resources.ts`）

`handleResourcesSave` dataURL 落盘成功后，把 `body.id` **改写为与 rescan 一致**：`local-${folder}-${path.basename(urlPath)}`。这样 rescan 扫到同文件时 id 相同 → `skipped`，不再新增第二条。

- 前端 `Ar()` 落盘后只用返回触发刷新计数 `et`，**不用返回 id** → 无失联风险。
- 后端无其它依赖 `source='pasted'` 的 id 约定。

### 验证

- `localTool npm run build`（tsc）通过。
- ⚠️ **存量脏数据**（已入库的 `17xxx` + `local-migrated-...` 两条）需 rescan + 手动删一条才收敛；新粘贴立即只 1 条。

## 六、剧本盒子资产不进素材资源库（变更 #17，localTool rescan 递归）

**现象**：剧本盒子生成的资产图**文件已落盘**（`/files/migrated/人物|场景|道具/`），但画布素材/资源 tab 里"人物"文件夹为空、看不到资产图；普通生图节点（`tasks/`）能正常显示。

**根因**：素材 tab 每次打开会自动 rescan（Vr.jsx `xt`：切到 canvas tab 触发 `Pr()`+`kr()`）。但 `localTool/src/routes/resources.ts` 的 `handleResourcesRescan` **只遍历 upload 顶层目录一层**：`migrated/` 下的子目录（`人物/场景/道具`）只录一个 `type='folder'` 条目，**不递归扫文件** → 二级子目录里的 png 从未入库 → 素材 tab 看不到。普通生图节点落盘顶层 `tasks/xxx.png`，rescan 直接扫到 → 正常。前后端本就支持多级 folder（前端 `ft()` 用 `eqOrPrefix` 前缀匹配、后端 `buildPaginatedQuery` 支持 `LIKE 'migrated/%'`），纯后端 rescan 没递归。

**修复**：`resources.ts` 把单层循环改成递归 `scanRescanDir`：① 子目录录 `type='folder'`（`folder=父路径`、`name=子目录名`）后递归进入；② 文件入库 `folder=完整父路径`（如 `migrated/人物`）、`name=文件名`、`id=local-<完整父路径>-<文件名>`。**顶层 id 格式不变**（`local-tasks-xxx.png`）向后兼容；孤儿清理 `path.join(uploadDir, folder, name)` 对多级 folder 仍正确；跳过 `.thumbnails`。影响通用（所有子目录文件都进素材 tab，用户已选"递归扫描所有子目录"）。

**验证**：`localTool` `npx tsc --noEmit` 通过 + `npm run build`（tsc）重编译成功，`dist/routes/resources.js` 确认含 `scanRescanDir` 递归。登记 `docs/01` 变更 #17。

**生效条件**：⚠️ **需重启 localTool**（后端改动已编译进 dist）。重启后切画布素材 tab（自动 rescan）即可看到 `migrated/人物|场景|道具` 下的资产图。

## 六、待研究 🔴：官方模型聊天 404 与「后端接入点」base（未修，先记录）

### 现象

- 用**官方模型**聊天报错：`Cannot POST /api/v1/chat/completions`（404），前端 `Proxy error: 404 ... Cannot POST /api/v1/chat/completions`。
- 日志（`localTool/logs/localtool_18080.log`）：
  ```
  [POST] /api/v1/chat/completions
  [passthrough] ... POST /api/v1/chat/completions | -> www.1mao.cc | 404
  [proxy] ... POST http://127.0.0.1:18080/api/v1/chat/completions | 404
  ```
- 正常聊天对比：`[proxy] POST http://127.0.0.1:9004/v1/chat/completions | 200`（走 9004 Lovart 网关）。

### 已确认的事实（用户实测）

- 在**设置里把「后端接入点」改成主接入点 `https://www.1mao.cc`** → **官方模型聊天恢复正常**。
- 接入点指向 localTool（18080）时 → 官方模型聊天 404。
- 但改回主接入点后，**自研（非官方）链路又不正常**（接入点不同，官方/自研二选一）。

### 接入点约定

- 9004 = apimart-gateway（**Lovart 网关**）。
- 18080 = localTool（自研后端，唯一出口）。
- **官方主接入点**：`https://www.1mao.cc`；备用1：`https://1mao.16iai.com`；备用2：`http://154.219.102.152:3012`。

### 初步根因判断（未验证）

- 前端 `H_.jsx` `Wr`（约 L6773，官方/自建文本模型聊天）用 `s = 官方模型 ? l(官方base) : t(自建base)`，拼 `${s.replace(/\/$/,'')}/v1/chat/completions`。
- 当接入点=localTool(18080) 时，官方模型 base `l` 被设为 `http://127.0.0.1:18080`（或带 `/api`），拼出 `18080/api/v1/chat/completions`（带 `/api`，`Wr` 只剥尾部 `/`、不剥 `/api` 后缀）。
- localTool **无 `/api/v1/chat/completions` 具名路由** → 走 catch-all（`passthrough.ts`）→ 透传官方 `www.1mao.cc/api/v1/chat/completions` → **官方 404**（官方无此 OpenAI 兼容路径）。
- 对比：剧本盒子 `H_.jsx:5224` 用 `.replace(/\/(api|v1)$/i,'')` **剥掉了 `/api` 后缀** → 拼 `18080/v1/chat/completions`（无 api，正常）。`Wr` 这条没剥 `/api` → 多出 `/api` → 404。

### 待研究/待解决方向（下次）

1. 确认 `Wr` 的官方 base `l` 具体来源（哪个 state/配置），以及接入点=18080 时它为何带 `/api`。
2. 是否应对 `Wr` 的 `s` 也做 `.replace(/\/(api|v1)$/i,'')` 后缀剥离（与 `H_.jsx:5224` 对齐），使 base=18080 时拼出 `/v1/chat/completions` 走 localTool 具名路由/转发，避免透传官方 404。
3. 官方模型聊天在接入点=18080 时，**应该走哪**：localTool 具名路由转发官方？还是走 9004 Lovart？需与「官方正常、自研正常」两种接入点配置下都要通的目标对齐。
4. 结论倾向：`Wr` 的 base 拼接与 `H_.jsx:5224` 不一致是嫌疑点；官方模型在接入点=localTool 时不应透传官方 404，应在 localTool 侧有正确转发。**本次未改码，先记录。**
