## 一、内联资源转 URL：从"删图"改为"真正转 URL"（前端）

### 现象

- 粘贴图片到画布 → 图片节点数据是内联 `data:image/...;base64`。
- 点工具栏「清理缓存（将内联资源转为本地URL）」按钮 → **图片直接消失**。

### 根因

`src/App.jsx` 的 `handleClearCache` 原实现是"**删除**"：遍历节点，把 `data:` 开头且 >100KB 的 `imageUrl`/`videoUrl`/`thumbnailUrl` **置空**。粘贴的图片 dataURL 远超 100KB，一按就删图。文案叫"转为 URL"，实现却是删图——语义完全背离。

### 修复（前端）

- **`src/components/base/filesApi.js`** 新增 `saveInlineToLocal(dataUrl, subfolder='canvas')`：
  - dataURL → Blob → POST `localTool /api/files/upload` 落盘；
  - 文件名用 **sha1(base64) 前 16 位 + 扩展名** → 幂等去重（同图重复转不重复落盘，对齐官方后端 `saveBase64ToFile`）；
  - 落盘失败返回 `null`，调用方保留原 base64（**绝不删图**）。
- **`src/App.jsx`** 重写 `handleClearCache`：
  - **深度递归**遍历节点 data，把所有 `data:` 开头的字符串字段都转（不只是 `imageUrl`，还包括 `imageBoxNode` 的 `images[].url`/`thumb`、`videoUrl`、`poster` 等，对齐官方 `externalizeObject` 语义）；
  - **不可变更新**（克隆新对象再替换）；失败字段保留原 base64；
  - **localTool 离线** → 保留原图 + 提示，不做任何删除。

## 二、破图根因：后端 base64 外置返回相对路径（后端）

### 现象

- 粘贴图片后（仍是 base64）**还没点"转 URL"就刷新** → 刷新后图片**变破图**；
- 但**转 URL 后刷新** → 图片正常。

### 根因（关键）

画布**自动保存到 KV** 时，后端 `localTool/src/routes/kv.ts` 会调用 `externalizeBase64InValue`，把内联 base64 **自动外置为 `/files/` URL**。但 `localTool/src/utils/base64Externalize.ts` 的 `saveBase64ToFile` 返回的是 **相对路径** `/files/canvas/xxx.png`，直接存进了节点 `data.imageUrl`。

刷新后 `<img src="/files/canvas/xxx.png">` 在画布运行环境（`localhost:5180` / `chrome-extension://`）下被浏览器解析成**错误源**（`localhost:5180/files/...` 或 `chrome-extension://.../files/...`）→ **404 破图**。

而"转 URL 后刷新正常"，是因为前端 `saveInlineToLocal` 返回的是**绝对 URL** `http://127.0.0.1:18080/files/...`，刷新后可访问。

> 对比：`resources.ts` 早有 `toAbsoluteFileUrl`（相对→绝对），但 `base64Externalize.ts` 漏了这层——是"漏网之鱼"。

### 修复（后端）

- **`localTool/src/utils/base64Externalize.ts`**：`saveBase64ToFile` 现在把相对 `urlPath` 补全为**绝对 URL**（复用 `LOCAL_FILE_BASE`），对齐 `resources.ts` 惯例。新保存的画布快照里都是绝对 URL，刷新不再破图。
- 同步更新测试断言（`localTool/test/localtool.test.js`）：相对 `/files/canvas/` → 绝对 `http://127.0.0.1:18080/files/canvas/`。

## 九、上传视频素材刷新丢失修复（对齐官方）

### 现象

上传视频素材到画布，一刷新视频就没了。

### 根因

`src/components/base/useAssetDropPaste.js` 的 `createNodeFromFile` 用 `FileReader.readAsDataURL` 把文件读成 **base64 dataURL** 存入 `data.imageUrl`。视频 dataURL 巨大（几十 MB），塞进画布快照（KV）后：
1. KV set 请求体过大 → 保存失败/超时；
2. 即使保存，也依赖后端 `base64Externalize` 外置兜底，流程慢且不稳。

刷新时 KV 里没有视频（保存失败）→ 视频「没了」。

### 官方做法（`reference-1mao/H_.jsx:10292-10334`）

官方 onDrop 处理文件时**优先走 localTool 上传成 `/files/` URL**（`hi(file,{subfolder:'canvas/drop'})`），只有上传失败才 fallback 到 dataURL。

### 修复

- **`src/components/base/filesApi.js`**：新增 `uploadFileToLocal(file, subfolder='canvas/drop')` —— 直接 multipart 上传原始文件（避免大视频先转 dataURL 再转 Blob 的两段大内存拷贝），返回 `/files/` 绝对 URL；失败返回 null。
- **`src/components/base/useAssetDropPaste.js`**：`createNodeFromFile` 改为**优先** `uploadFileToLocal` 上传成 URL 建节点；**失败**（localTool 离线）才 fallback 到 dataURL。

### 效果

上传视频 → 立即落盘 localTool `uploads/canvas/drop/` → `imageUrl` 存轻量绝对 URL → 画布快照（KV）不再塞大 dataURL → 刷新后从 KV 读 URL 正常加载，视频不再丢失。与官方行为一致。

### 验证

- localTool `/api/files/upload` 返回 `http://127.0.0.1:18080/files/canvas/drop/xxx.mp4`。
- `detectMediaType` 能识别 `.mp4` 为 video → ImageNode 正常渲染。
- `npm run test:smoke` 全部通过。

## 十一、统一「拖素材到画布」与媒体判断（消除各写一份）

### 背景

用户反馈：不同面板（生成素材 / 任务中心）里「点击放大后能不能拖图到画布」行为不一致，且拖拽发起逻辑各写各的（AssetLibrary/GeneratedView 用 `application/x-yimao-asset`，TaskCenter 用 `text/plain`）。诉求：做成通用的，一处逻辑管所有，不重复。

### 统一方案（`src/components/base/useAssetDragToCanvas.js` 新增）

把「素材 → 画布」拖拽的**发起端**收敛成唯一模块：
- `makeAssetDragProps(asset, opts)`：**纯函数**，返回 `{ draggable, onDragStart }`，统一写 `application/x-yimao-asset`（带 url/name/type/text，比 text/plain 信息全）。非 hook 组件（如 TaskCard）可直接用。
- `useAssetDragToCanvas()`：hook 版，等价返回。
- `fetchText` / `textCache`：文字素材内容异步补全 + 跨面板共享缓存，从本模块统一导出。

接收端不变（`useAssetDropPaste.onDrop` 早已支持 `application/x-yimao-asset`）。

### 改造点（统一调用）

| 文件 | 缩略图 | 放大预览 |
|---|---|---|
| `AssetLibrary.jsx` | 改统一 | — |
| `GeneratedView.jsx` | 改统一 | 补上（原先放大后不能拖） |
| `TaskCenter.jsx` | 改统一（原 text/plain） | 改统一（原 text/plain） |

### 顺带收敛重复

- `fetchText`/`textCache`：AssetLibrary / GeneratedView 各自副本 → 统一到 `useAssetDragToCanvas.js`。
- `isAudio(type,url)`：AssetLibrary / GeneratedView 完全相同的两份 → 统一到 `mediaType.js`。

### 范围边界（刻意不动）

- 画布/编辑器**内部**排序拖拽（OverlayEditor 的 `application/x-yimao-layer`、ImageBox 的 `text/plain index`、GridMerge 的 `application/x-yimao-puzzle`）是 **move 语义**，不是「拖素材到画布」，不混用本模块。
- `URL.createObjectURL` 各处属正常使用，非重复工具。

### 验证

`npm run test:smoke` 全部通过；相关文件 lint 0 错误。

### 标准化建议（供后续遵循）

1. **拖素材到画布** → 一律 `makeAssetDragProps(asset)`（不要各写 setData）。
2. **媒体类型判断**（image/video/audio/text）→ 一律 `mediaType.js` 的 `detectFileType` / `detectMediaType` / `isAudio` / `isAssetUrl`。
3. **文字内容读取缓存** → `useAssetDragToCanvas.js` 的 `fetchText` / `textCache`。
4. **新增面板要支持拖图**：引用 `makeAssetDragProps`，不要复制 onDragStart 逻辑。

### 补充：粘贴也已统一（无需改动，确认记录）

「往画布粘贴素材」本就有唯一入口，与拖拽/上传共用同一套上传逻辑：
- 入口：`useAssetDropPaste.onPaste` + `useGlobalPaste`（window 监听，App.jsx 挂载）。
- 覆盖场景：图片/视频/音频文件 → `createNodeFromFile`（统一上传 localTool）→ imageNode；纯文本 → sanitizePastedText → textNode；URL → imageNode/textNode；画布节点组 / 提取帧 JSON → 重建节点组。
- 与拖拽共用 `createNodeFromFile`，上传端不重复。
- **因此「素材进画布」链路已统一**：拖拽（makeAssetDragProps）→ 画布 onDrop；粘贴（onPaste）→ 画布 onPaste；两者上传端汇聚到 `createNodeFromFile`。

**标准补充**：
5. **粘贴素材到画布** → 一律走画布 `onPaste`（`useAssetDropPaste`），面板不要自建 window paste 监听（除非是节点内部功能，如 ImageBox 往盒子粘图，那是另一语义，不混用）。

## 十四、前端图片 URL 统一机制（系统解决「反复破图 / 后端丢图」）

### 背景

破图反复出现，不是偶发 bug，而是「前端图片 URL 形式不统一」的系统性问题。图片有 4 种形式（绝对 http / base64 / blob / 相对 `/files/`），相对路径在画布环境解析错误 → 破图；blob/相对发给后端 → 丢图。

### 统一模块 `src/components/base/imageUrl.js`（唯一出口）

| 函数 | 用途 |
|---|---|
| `toAbsoluteFileUrl` / `normalizeImageUrl` | 渲染端：相对 `/files/` 补全成绝对 http |
| `blobToDataUrl` / `urlToDataUrl` | blob→data、任意 URL→base64 |
| `normalizeImageUrlForSend(u, opts)` / `normalizeImageUrlsForSend` | 发送端：blob→data、相对→绝对；`preferBase64:true` 全转 base64 |

### 收敛（消除「各写一份」）

- `filesApi.js` 的 `toAbsoluteFileUrl` → re-export 自 `imageUrl.js`。
- `refImage.js` 的 `resolveRefImages` → 委托 `imageUrl.js`。

### 现有代码归一（已核对无遗漏）

- **渲染端**：`LazyImage`（统一）、`ImageNode`、`useConnectedInputs`（上游图统一补全）、GridSplit/FaceMosaic/VideoExtract/GridMerge/PromptNode/TextNode/ImageBox/Director3D、AgentPanel/AgentMessage/GeneratedView/AssetLibrary/OverlayEditor/PromptInput/StepAssets。
- **发送端**：`imageApi`（图生图）/ `chatApi`（聊天）/ `videoApi`（生视频）/ `useAgentChat`（AI 助手附件）全部走 `resolveRefImages` / `normalizeImageUrlForSend`。

### `refFormat:'base64'` 能力预留（未来「只认 base64」的后端）

- `normalizeImageUrlForSend(u, { preferBase64:true })` 把任何形式统一转 base64。
- `imageApi`/`videoApi`/`chatApi`/`useAgentChat` 已读 `provider.refFormat === 'base64'` 自动传 `preferBase64`。
- 当前 provider 不配置 → 走默认 URL（网关 `resolve_attachments` 统一转 CDN）。
- **未来**接只认 base64 的直连 API：provider 加 `refFormat:'base64'` 一行配置即可。

### 规范（新增节点必须遵循）

1. 渲染图片 → `LazyImage` 或 `normalizeImageUrl`。
2. 发送图片 → `resolveRefImages(images, { preferBase64 })`。
3. 存储图片 → `saveInlineToLocal`/`uploadFileToLocal` 落盘成绝对 URL。
4. 新增 URL 处理 → 一律用 `imageUrl.js`。
