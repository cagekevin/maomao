## 六、存储键集中登记与错误重试收敛（docs/08 + docs/09）落地

> **核心**：把「存储键」和「错误重试」两件此前散落/重复/有脏数据的事，各收口成一个单一事实来源 + 一套统一机制。新增两份规范文档，并按规范改造代码。详见 §六.1~§六.6。

### §六.1 存储键中央登记表 `storageKeys.js`（新文件）

- 新增 `src/components/base/storageKeys.js`：`StorageKeys` 枚举（全键单一事实来源）+ `StorageDomain`（LOCAL/KV 介质域）+ 动态键工厂（`conversationKey`/`activeConvKey`/`canvasStateKey`/`directorSceneKey`/`withSuffix`）+ `LS_KEYS` 权威清单 + `CLOUD_SYNC_EXCLUDE`。
- 收口此前**两份并存的 `LS_KEYS`**（`cloudSync.js` / `backupStore.js` 各自硬编码，还带 `yimao_` 前缀脏值）→ 统一从 `storageKeys.js` import。

### §六.2 错误分类 `genErrors.js`（新文件）+ 自动重试 `apiBase.withRetry`

- 新增 `src/components/base/genErrors.js`：`GenErrorType` 枚举（cancelled/network/timeout/upstream/validation/unknown）+ `classifyError` 推导 + `isAutoRetryable` + `errorMessageByType` 文案映射。
- `apiBase.js` 新增 `RETRY` 预算（3 次指数退避）+ `withRetry()`：**仅网络/超时层自动重试**，上游业务失败不自动重试（交给「再来一次」）。
- 删掉各处失效的 `if (/^网络错误/.test(msg))` 判断（真实 fetch 失败文案是 `Failed to fetch` 等，原判断永远不命中）。

### §六.3 API 层收口（imageApi / videoApi）

- `imageApi.js` / `videoApi.js`：fetch 阶段统一包 `withRetry`；失败统一返回 `{ok:false, error, type}`（`proxyRequest` 4xx→VALIDATION、其他非 2xx→UPSTREAM，其余 `classifyError` 兜底）。
- `useNodeGeneration` 接 `type` 决策：失败文案由 `errorMessageByType` 映射（`r.type`/`classifyError` 兜底），节点层禁止自己判断网络错误。

### §六.4 双重前缀脏数据迁移（storageAdapter）

- 根因：早期模块自写 `yimao_` 前缀 + storageAdapter 再加 `yimao:` 前缀 → 落盘成 `yimao:yimao_accounts` 等双重前缀脏键。
- `storageAdapter.migrateLegacyKeys()`：启动（`main.jsx` 的 `initStorage()`）时把历史 `yimao:yimao_*` 搬到裸键 `yimao:*`（仅新键为空才搬，避免覆盖新数据），搬后删旧键。
