# 工作日志 — 2026-09-05

> 今日工作：**富文本垫图引用从裸词改成 Seedance 显式语法 `[img=图片N]`**。解决「图片1」这类裸词在提示词里被大模型当成画面描述词汇、不识别为垫图引用，导致垫图失效 / 凭空重画的问题。已实施并跑通相关单测。

---

## 一、背景：问题在哪

富文本里用户用 `@` 插入的图片，在生成前被统一解析层 `resolvePromptChips` 转成发给模型的文本。原来的行为是**原地替换成裸词 `图片1` / `图片2`**：

```
图片1 左侧是刮痧前……
图片2 右侧是刮痧后……
```

问题是「图片1」长得像普通中文描述，Seedance 等模型不把它当「已上传第 1 张参考图」的引用，容易：不读垫图、重新凭空画新物体 → 垫图失效。

参考图本体早就通过 `images` 数组上传了，缺的只是**文本里一段无歧义的引用标记**。

---

## 二、改动：裸词 → `[img=图片N]`

### 涉及文件

- `src/components/base/prompt/promptChips.ts` —— `resolvePromptChips` 里图片芯片的替换逻辑（唯一生成端解析入口）。

### 改了什么

原来：

```ts
return `图片${idx}`
```

现在：

```ts
return `[img=图片${idx}]`
```

含义：
- 图片芯片 → 输出显式 Seedance 富文本垫图引用 `[img=图片N]`；
- **位置不变**——提示词里 `@` 图放在哪个位置，`[img=图片N]` 就出现在哪，不挪到开头（按用户要求，提示词放哪就放哪）；
- 多张图按 `@` 出现顺序编号（`[img=图片1]`、`[img=图片2]`…），与 `images` 上传数组顺序一一对应，引用映射不破。

### 示例

用户在富文本里：

```
@{imgA:...} 左侧是刮痧前，脸部轻微浮肿
@{imgB:...} 右侧是刮痧后，轮廓线清晰
```

最终发给模型：

```
[img=图片1] 左侧是刮痧前，脸部轻微浮肿
[img=图片2] 右侧是刮痧后，轮廓线清晰
```

## 四、明确没动的部分（重要边界）

| 内容 | 说明 | 是否改 |
|---|---|---|
| UI 显示兜底名 `图片N` | PromptInput / MaterialStrip 缩略图用的 label，是界面显示，不进发送文本 | 否 |
| 剧本盒子 `@图片1` | scriptBoxEngine 的独立语法，模型需输出它作尾帧引用 | 否 |
| 文本芯片 | 仍替换为其 label（纯文本），逻辑不变 | 否 |

## 五、本次状态与遗留提醒

- 富文本垫图引用现已全局输出 `[img=图片N]`（图片节点 / 视频节点 / LLM 文本节点统一生效）。
