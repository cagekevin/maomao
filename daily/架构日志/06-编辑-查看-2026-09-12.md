### 8.1 TD-06-7：URL 归一化两实现 → 环消除 + 两实现合一

**债描述**：「待裁定（抽最底层 URL 原语消环后收口）」——暗示要**新建原语模块**。

**实际取证**：
- `toAbsoluteFileUrl` 的**唯一依赖**是 `API_BASE`（`core/config.ts`，零 import 的纯常量叶模块）
- 它**本不必住在 `assetUrl`（业务层）**
- 40+ 消费方（跨 20+ 文件、3 种 import 路径）—— 若"抽新模块"要动它们，成本极高

**修法（比债登记设想的更省）**：**下沉**到已有的 `core/utils.ts`（纯工具叶模块，`imageCompress` 本就 import 它取 `dataUrlToBlob`）：
- `core/utils.ts` 新增 `toAbsoluteFileUrl`（+ import `API_BASE`）
- `assetUrl.ts` 改 `import + export`（**同名导出面不变 → 40+ 消费方零改动**）
- `imageCompress.ts` 删 `toLoadableUrl`，改调 `core/utils`

**改动半径：3 文件**（而非"抽新模块 + 改 40 处"）。

**验证**：`check:arch` no-circular ✅（`assetUrl → imageCompress → assetUrl` 环消失）；`assetUrl`/`imageCompress` 测试 56 例绿；类型检查 0 错。

### 8.2 TD-06-8：**债描述错误**，且「现无实害」不成立

**债描述**：「派生写成副作用回写（存在 stale closure/隐式时序契约）…**现无实害**」。

**实际取证（先质疑前提）**：
1. **"派生"判词不成立**：该 effect 内是 `await loadImageOrNull`（**异步加载图片取尺寸**）——**必须**是副作用，不存在"改受控派生"的替代方案（债登记的"替代方案"是假的）。
2. **真正的问题是异步 stale closure 回写覆盖**（债没说到点上）：
   - effect deps = `[upstreamUrls.join('|'), canvasWidth, canvasHeight]`，**不含 `state`/`layers`**
   - 内部 `await` 期间用户若改动其他字段（背景色/拖图层）→ 闭包 `state` 仍是旧值
   - 完成后 `onChange({ ...旧state, layers })` → **覆盖用户改动**
3. **"无实害"被实证推翻**（见下）。
