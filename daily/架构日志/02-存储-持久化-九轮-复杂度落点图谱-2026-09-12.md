## 二、新实证（八轮盲点补完）

### 盲点 1：cache 第二真相（TD-02-20）
- `loadFromKv`(L264-268)：`value = await readKvWithFallback(key); cache.set(key, value)`（L266）。
- `readKvWithFallback`(L299-300)：KV 失败时 `const raw = sGet(key); return raw===null?null:tryParse(raw)` —— 返回**本地降级副本**。
- 后果：`cache` 中该键的值标称「已加载的 KV 值」，实际是本地副本，且**无来源标记**。后续 `contentGet`(L365 `if (cache.has(key)) return cache.get(key)`) / `contentGetKeySnapshot`(L638) 命中即返回副本，消费者无法感知「KV 真实不可用 / 此值是降级副本」。
- 与 §五「真相」自检项直接对应：「有没有偷偷创建数据的副本而不做同步？」——**有**，cache 里有一份「看起来像真值、实际是降级副本」的数据，与真源（KV）同步状态对消费者不可见。
- **根因同族**：与 TD-02-15/19 同根——读族对「失败」的语义处理不诚实（TD-02-15 是 `from` 误导，TD-02-20 是 cache 值误导）。复杂度应落在「读族返回值的语义诚实性」这一处（源头收敛：在 `readKvOrFallback` 内统一决定 cache 写入的来源标记），而非散在 cache 各处。

### 盲点 2：模式匹配重复（TD-02-21）
- `findPatternEntry`(L137-148) 与 `isKvPatternKey`(L224-235) 结构重复：均 `for (const [k,v] of Object.entries(KEYS)) { if (!v.pattern) continue; try { if (compilePatternRegex(k).test(key)) ... } catch { /* 忽略无效正则 */ } }`，仅 `isKvPatternKey` 多 `v.backend!=='kv'` 过滤。
- 坏正则静默吞也**重复两处**（L143-144 / L230-231）——与 TD-02-17 同源。
- **修复（复杂度收口）**：抽 `matchPatternEntry(key: string, predicate?: (v)=>boolean): StorageKeyEntry|null`，则 `findPatternEntry = matchPatternEntry(key)`、`isKvPatternKey = matchPatternEntry(key, v => v.backend==='kv') != null`。这是**纯去重**（§一.2 收敛），非「带 5 个开关的统一入口」（符合收敛前提：不会反升复杂度）。

### 盲点 3：CAS 严格族消费端（非债·有意例外，仅备注）
- `projectStore.loadCanvasState`(L310-326)：`contentKvGetVersion` 在 try 内，抛错即跳出 try → 函数上抛。**正确**（fail-closed 上抛由调用方处理）✅。
- `useCanvasSync`(L82-87)：轮询 `contentKvGetVersion` 在 `try { ... } catch { /* 轮询失败静默：不打扰主链路 */ }`。catch **静默但注释明言意图**（仅 3s 远程版本探测，失败不影响本地主链路）。属**有意设计**，非 TD-02-16 类「消音根因」——但若 KV 长期不可用，此处零信号（连 debug 都没有）。记为 TD-02-16 的「有意例外」备注，**不立新债**（避免过度膨胀，且注释已声明权衡）。

## 五、探债（Phase 4）：本轮新债

### TD-02-20（新增 · 中）
- **现象**：`loadFromKv`(L266) 把读族失败时回退的本地副本**无标记**写入 `cache`；同步读者 `contentGet`(L365)/`contentGetKeySnapshot`(L638) 命中即返回，无法区分「KV 真值」vs「降级副本」——违反 §五 真相「偷偷创建数据副本不同步」。
- **归类**：增债（根因 = 读族对失败语义不诚实，与 TD-02-15/19 同根；非偷懒）。
- **爆炸半径**：同步读者 3 处（contentGet/contentHas/contentGetKeySnapshot）。
- **复杂度落点判词**：在 `loadFromKv`/`readKvWithFallback` 写入边界统一给 cache 值打**来源标记** `{value, source:'kv'|'local-fallback'}`（源头收敛），下游据标记决策，无需猜。
- **曾评估被否决**：✗ 直接删 cache 降级副本写入 → 同步读者在 KV 不可用时拿不到任何值，破坏降级语义，否决。
- **偿还计划**：与 TD-02-15/19 同次修复——`readKvOrFallback` 内统一决定 cache 写入的来源标记；同步读者据标记呈现（如 d3d `from` 直接复用标记）。

### TD-02-21（新增 · 低）
- **现象**：`findPatternEntry`(L137) / `isKvPatternKey`(L224) 结构性重复 + 坏正则静默吞重复两处（L143 / L230），与 TD-02-17 同源。
- **归类**：增债（附随复杂度，重复代码）。
- **爆炸半径**：contentStore 内部 2 处重复。
- **复杂度落点判词**：抽 `matchPatternEntry(key, predicate?)` 单一 helper（§一.2 收敛，去重非大一统）；坏正则前移到 `STORAGE_KEYS` 初始化校验（TD-02-17 同修）。
- **曾评估被否决**：✗ 直接删 `isKvPatternKey` 让路由退化 → 破坏 `resolveBackend` 的 kv 启发式兜底（L217），否决。
- **偿还计划**：抽 helper 后两函数合一；坏正则 fail-loud 收口到初始化（与 TD-02-17 一并）。
