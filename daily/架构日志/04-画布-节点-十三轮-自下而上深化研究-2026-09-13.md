## 二、逐模块结论

### A. 选中媒体节点同步链（核心新债 · TD-04-24）

**定海（正向）**：选中带媒体节点 → AI 待引用区的「待确认（pendingMediaNodes）→ 确认」两阶段设计（防误触）本身是合理的产品语义（注释明确对齐大雄 ghost 语义）。

**问题（三层手工同步链 + 删除路径无清理）**：
1. `App.tsx:401` 的 `selectedAssetNodes` 是一份**手工副本**，唯一同步点 = `onNodesChangeForEdges` 内的 `select` 变化(App.tsx:1307)——`App.tsx:400` 注释自承「在 onNodesChangeForEdges 的 select 变化里同步更新」。除 select 之外的任何导致选中集变化的路径都**没有同步点**。
2. `onDelete`(App.tsx:1250-1261) 只 `history.record({nodes, edges})` 过滤被删节点 + 记历史，**完全不碰 `selectedAssetNodes`** → 删除一个「已选中且带媒体」的节点后，`selectedAssetNodes` 仍含该幽灵条目，直到用户下次触发 select 变化才被覆盖；期间 AgentPanel 待引用区显示已删节点的幽灵媒体（误塞附件风险）。
3. `AgentPanel.tsx:630` 的 `pendingMediaNodes` 是**第二份手工副本**——`useEffect([selectedAssetNodes])` 把 `selectedAssetNodes` 复制一遍（字段映射 + filter url）。同一份「选中带媒体节点」状态存在 **App 手工副本 → AgentPanel 手工副本** 两层派生链，二者均非「从 nodes + selection 实时只读计算」。

**反模式关联**：`onNodesChangeForEdges`(App.tsx:1279-1320) 在 `setNodes(updater)` 回调内**做副作用**（`setSelectedAssetNodes(selAsset)` + 嵌套 `setEdges(...)`），属 React「updater 必须为纯函数」反模式，与 TD-04-23（nodePrefs 在 updater 内 loadAll+contentSet）**同型**。

### B. `getNodeMedia` 层位倒置（TD-04-25）

**证据**：`getNodeMedia`(useCanvasAgentTools.ts:290) 是纯函数（`classifyAssetUrlKind` + `getNodeAssetUrl`，无 React/store 依赖），其 JSDoc 自述「供 App 传给 AgentPanel 待发送区」。实测它被 `App.tsx:1295`（base/canvas 编排层）消费，而定义住在 `agent/canvas/useCanvasAgentTools.ts`（agent 层）。

**问题**：base/canvas 是更底层基础设施，agent 层是其**消费者**；把「画布选中链的媒体提取器」放在 agent 层，意味着若要把选中派生抽进 base/canvas（见 TD-04-24 正解），base/canvas 会**反向依赖 agent 层**，依赖方向倒置。正解 = 下沉到 `base/canvas` 或共享 `utils`，`useCanvasAgentTools` 改为 import 引用、不重复实现。

### C. `canvasContextMenu.tsx` 死副作用 import（TD-04-26）

**证据**：`canvasContextMenu.tsx:39` `import './lazyNode.tsx';` 是副作用 import。全文件 0 处引用 `lazyNode` 任何符号——prefetch 走 App 注入的 `ctx.prefetchHeavyNode`，且 `NodePalette` 已传递依赖。副作用 import 一个懒加载模块，与其文件头「无副作用」自述**直接矛盾**，且会**提前触发该模块加载**（违背 lazy 初衷）。

### D. `nodesRef` 同步 hack（TD-04-27）

**证据**：`App.tsx` 用 `nodesRef`/`edgesRef`（提交后 `useEffect` 同步）保存最新节点；事件处理器内同步读 ref 拿到旧值，故 `onNodesChangeForEdges`(App.tsx:1279) 用 `setNodes(updater)` **当观察者**读最新 nodes 再算 selectedIds。

**问题**：以「状态更新回调」当「读最新值」的通道，把派生计算塞进 updater，违背 React 数据流向；且**历史写回路径（undo/redo）不触发该边重算**（onNodesChange 不进 onNodesChangeForEdges → relatedToSelected / selectedAssetNodes 在撤销后陈旧）。正解：选中派生改为「提交后的状态驱动 `useEffect`」计算，脱离该 hack，并自然覆盖 undo/redo 路径（与 TD-04-24 协同）。
