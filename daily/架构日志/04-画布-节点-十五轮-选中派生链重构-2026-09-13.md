## Step 2 · 归因（母体）

**TD-04-24 / 25 / 27 是同一母体**：`selectedAssetNodes` 与边 `relatedToSelected` 都是 `nodes` 的**衍生状态**，却被实现为「独立 state + 单点副作用同步」。

- 衍生状态未做**只读实时派生** → 必须为每个变更路径手工补同步点 → 漏路径即 bug（删除、undo/redo）。
- 载体是 `setNodes(updater)` 内做副作用（`setSelectedAssetNodes` + `setEdges`）——**updater 必须是纯函数**（StrictMode 下跑两次、语义被当读值通道）。
- 层位债（TD-04-25）是这个母体的**前置阻碍**：派生若要落到 `base/canvas`，会反向依赖 agent 层。

> **判据（Step 2 定权）**：这里存在**单一根因**（衍生状态没派生），故合并为一次专项收口；不逐条打补丁。

## Step 3 · 定位（落点选择，结构自决）

| 候选取向 | 判定 |
| - | - |
| A. 派生抽成 `base/canvas` 的 hook | ❌ **过度**：派生**仅 App 一处消费**（铁律 5 真复用才抽象）→ 抽 hook 是为结构而结构 |
| B. 派生留在 App 编排层 + 提取器下沉 base/canvas | ✅ **采纳**：App 本就是 agent 层的消费者，方向正常；提取器（`getNodeMedia`/`getNodeAssetUrl`）下沉 base/canvas 后，**「base/canvas 反向依赖 agent」的倒置前提被消除**，且为将来下沉留出正确层位 |

**结论**：`getNodeMedia`/`getNodeAssetUrl` → 新模块 `base/canvas/nodeMedia.ts`（属画布节点数据读取基础设施）；派生纯函数一并落此模块（**可测**）；App 只做「订阅 + 接线」。

> **TD-04-25 的诚实定性**：本轮**未**把派生抽进 base/canvas，故倒置并未实际发生；但提取器已迁到正确层位 → **倒置前提消除**（未来下沉不再受阻）。这属于「按正确位置搬迁」，非「为消债而造抽象」。

## §5 · 债描述修正（取证推翻的部分）

1. **TD-04-27「删 nodesRef 同步」→ 不删。** `nodesRef` 的正当域未变（事件处理器内读最新值、同 tick 并发安全）。母体修完后它不再承担「当观察者」职责，但仍被 `addNode`/`history`/`persistCanvas`/`handleNodeDragStop`/`deleteNode`/viewport 正常使用。**删之无收益且扩大风险面** → 判定为债描述过宽。

2. **TD-04-24「`pendingMediaNodes` 为第二份手工副本」→ 保留（非独立真源）。** `AgentPanel.pendingMediaNodes` 是「**可被用户编辑的待确认草稿**」（支持移除单条 `AgentPanel.tsx:1577`、移除全部 `:1540`、确认后清空 `:672`）——这是「防误触两阶段」的**产品语义**，不能纯派生（否则用户移除的条目会复活）。它现在是**唯一真源（nodes）投影 + 本地编辑覆盖**，其 `useEffect` 依赖的上游引用因签名短路而**更稳定**（拖动不再无谓重建）。改为「保留 + 定性修正」。
