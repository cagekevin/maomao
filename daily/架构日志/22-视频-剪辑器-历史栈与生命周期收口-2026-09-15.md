## 二、归因（Step 2）

三笔**不是**同一个母体，且**不硬编母体**（7 步法 Step 2：症状群无母体时老实登记 N 个债）。它们各自落在体检轮 §十七 已推出的根规则上：

| 债 | 根规则 | 一句话根因 |
| --- | --- | --- |
| TD-22-27 | **R2 历史栈语义未定义**（引用语义那一支） | 快照与 store 共享引用 → undo 正确性**完全依赖纪律**，无守卫 |
| TD-22-51 | **R2**（"命令粒度"支） | 「批量入栈」判据散在各调用点各写一次 → **必然漏一处**（转场就是漏的那处） |
| TD-22-42 | **R1 生命周期边界无单点** | 「谁拥有这个 audio」当时没有落点 → 每处各建一个、各忘一次清理 |

三笔的共性是一条**可复用的判定法**（不是同一母体）：**"同一件事有几份实现 / 判据有几个落点"** ——
份数 ≥2 且已漂移一次 → 收口为单点；份数 =1 且无守卫 → 补机器守卫。

## 三、定契（Step 3/4：正确形态）

**TD-22-27 —— 不靠纪律，靠守卫。**
普查确认现状 **0 违例**（写路径确实都不可变重建）→ 无需改 15 个命令，按债的推荐补 **AST 闸**：
`check-arch.mjs` 新增「videoEditor 引用纪律」——禁对 `*.elements` / `*.transitions` / `*.tracks`
调数组变异方法（`push/pop/splice/sort/reverse/shift/unshift/fill/copyWithin`）；
合法写法 = **先复制再变异**（`[...x.elements].sort(...)`，`transition-utils.ts:findAdjacentPairs` 正是此形）。
闸自带**解析源 fail-loud**（扫到 0 文件即报错，防 TD-02-9 式假绿）。

> **诚实边界（写进闸注释）**：本闸只覆盖**数组级**原地变异（可静态判定、零误报）；
> 元素**属性级**改写（`el.startTime = x`）无法与合法对象字面量机械区分 → 仍靠不可变重建纪律。
> 闸**不假装覆盖它** —— 假覆盖比不覆盖更坏（会让后人以为已有守卫）。

**TD-22-51 —— 判据进唯一入口。**
`CommandManager.executeBatch({ commands, pushHistory })`：**0 条 = 不入栈 / 1 条 = 直用（不包 Batch，保持与单条操作同形）/ N 条 = BatchCommand**。
`TimelineManager.updateElements` 与 `use-editor-actions`（freeze frame）改为委托；
转场批量应用**整体下沉**为 `TimelineManager.addTransitionsToAdjacentPairs`（判据与命令构造走
私有 `buildAddTransitionCommand` 单点），`transitions.tsx` 只负责"表达意图 + 报结果"。

> **为什么不能留在 UI 层**：UI 层若自己循环，就必须自己判"轨道是不是 video / 元素在不在 / 是否相邻"
> —— 那是**第二份判据**（TD-22-49 改阈值时就得改两处），且必然再漏一次"打包成一条"。

**TD-22-42 —— 从"两处各忘一次"变成"一处拥有"。**
新增 `hooks-cutia/use-sound-preview.ts`：`useSoundPreview()` 是试听播放的**唯一拥有者** ——
创建 / 替换 / 停止 / **卸载释放**在一个生命周期里闭环；两个视图改用它（删掉两份手抄）。
两处细节是行为契约：① 卸载 cleanup **只 pause、不 setState**；② `ended`/`error`/失败回调
**按 id 判等再清**（快速切歌时旧元素的回调不得清掉新歌的播放态）。

## 六、弯路留痕（强制）

**1. TD-22-51 探针连续两次"假红"，两个不同的原因，都不是代码问题。**

- 第一次：`--expect-out "to have a length of 0"` 未命中。
- 第二次：换行号锚点 `veTransitionCommand.test.ts:281`，**仍未命中**。
- 真相拆成两条：
  - ① **工具缺陷（真债）**：`probe.mjs` 比对前**未剥离 ANSI**。vitest 会把「路径行号 / 期望值」
    着色，ESC 序列把目标子串**切断**（实测输出里是 `test.ts:\x1b[2m281:35\x1b[22m`）→
    该命中却报未命中。**已当场修**（加 `stripAnsi()`，登记 TD-17-6 并一行结清）。
  - ② **我选错了锚点**：vitest 2.x 的 `toHaveLength` 失败**只输出 diff**
    （`- Expected / + Received / - 0 / + 1`），**不打印** chai 式 `"expected … to have a length of 0"`。
    那个串**根本不存在于输出里** —— 与 ANSI 无关。
- **教训（写下来防重走）**：探针报"未命中"时，**先问"这个串到底会不会出现在输出里"**，
  再去怀疑测试没测到。两次假红合计白跑约两轮 —— 而它差点被误判成"修饰语没被测到"。

**2. TD-22-27 的处置一度想错方向（A 方案）—— 已回退到债推荐的 B。**

- 最初想「让 `getTracks()` 返回深克隆，从机制上消除共享引用」。推演后否掉：
  - 渲染/UI **每帧**都调 `getTracks()` → 深克隆成本直接进渲染路径；
  - tracks 里含 `AudioBuffer`（storage 层专门有 `stripAudioBuffers` 才能序列化）→
    `structuredClone` 不保证可克隆，手写深拷贝又要递归到 `element.transform`；
  - 退而求其次"只克隆命令快照" → 要改 **15 个命令**，半径大且**当前 0 实害**。
- **改回 B（机器守卫）**：普查证明纪律此刻有效 → 补守卫防回潮即可。
  口诀：**先问"现状有没有实害"，再决定要不要动半径**（无实害的预防性债，守卫 > 重构）。

**3. `executeBatch` 差点引入模块环。**

`CommandManager`（`core/managers/commands.ts`）若从 **barrel** `@videoEditor/engine/commands` 引 `BatchCommand`，
会经 `timeline/transition/add-transition.ts → engine/core/index.ts → managers/commands.ts` 成环，
而 `CommandManager` 在 `EditorCore` **构造期**就 new → 环会埋 TDZ 风险。
→ 改为**直引 `commands/batch-command.ts`**（它只依赖零依赖的 `base-command.ts`），并在 import 处写明原因。
