# 22 视频剪辑器 · 转场点击应用失败排查 · 2026-09-15

## 现象（用户原话）
点素材面板里的「转场」，每次都弹一行看不懂的英文，转场应用不上。
（与 TD-22-47「贴纸/音效/音乐数据源缺失」是不同问题，本笔为转场自身逻辑缺陷。）

## 那行英文是什么
`src/components/videoEditor/ui/editor/panels/assets/views/transitions.tsx:336`
> `No adjacent clips found. Place clips next to each other on a video track first.`
（没找到相邻片段。请先把片段首尾相接放在同一个视频轨道上。）

成功分支应为 `transitions.tsx:338` `Applied ${type} to ${n} junction(s)`，但用户永远落到失败分支。

## 根因（已取证，非猜测）
点击转场 → `applyTransitionToAdjacentPairs`（`transitions.tsx:307`）
→ 对每条 video 轨调 `findAdjacentPairs`（`:321`）
→ `findAdjacentPairs` 用 `areElementsAdjacent` 判定相邻：
`src/components/videoEditor/engine/timeline/transition-utils.ts:17,28`
```
const ADJACENCY_EPSILON = 0.05;
return gap < ADJACENCY_EPSILON;   // 首尾间隔 < 0.05s(约 1~1.5 帧) 才算相邻
```
→ 片段间但凡留 >0.05s 空隙 / 仅 1 个片段 / 在不同轨道 → pairs 为空 → applied===0 → 弹英文。

时间轴上的「+」交界按钮走同一个 `findAdjacentPairs`（`timeline-transition-overlay.tsx:41`），
片段没贴到 50ms 内时该按钮根本不渲染，用户连点都没机会点。

## 判定
- 非数据缺失（区别于 TD-22-47），是 **代码逻辑/可用性缺陷**：
  1) 邻接阈值 `ADJACENCY_EPSILON = 0.05` 过严，不符合手动拖拽实际操作习惯；
  2) 失败提示为英文，未本地化（"搬来"遗留英文 UI）；面板说明 `transitions.tsx:38` 也是英文。
- 归类：业务债 / 可用性债，需用户拍板（阈值放宽值 + 是否中文化）。
- 与 TD-22-40（转场绕过 CommandManager 无 undo/redo）不重复，本笔为新发现。

## 待拍板选项（A/B/C）
- A：放宽阈值（如 0.3~0.5s）并自动吸附相邻片段，失败提示 + 面板说明中文化。
- B：仅中文化提示文案，阈值维持（用户需手动把片段拖到近乎无缝）。
- C：点击转场时若无可应用对，自动把视频轨上所有片段按序首尾相接后再应用（改动较大）。

## 取证入口
- `transitions.tsx:307-340` 应用 + 英文 toast
- `transition-utils.ts:17-48` 邻接判定与阈值
- `timeline-manager.ts:274-313` addTransition（同样调 areElementsAdjacent）
- `timeline-transition-overlay.tsx:41` junction 按钮依赖同一判定
- 关联债：TD-22-40（转场无 undo/redo）、TD-22-47（素材数据源缺失）

# 收口（2026-09-15 · TD-22-49 结清）

## 一、推翻原诊断：**阈值不是根因**

原 `判定` 把症状归为「邻接阈值 `0.05` 过严，手动拖拽几乎永远不满足」。收口前重新取证，**推翻**：

- 片段 `startTime` **一律帧对齐**（`snapTimeToFrame`）⇒ 真相接时 `gap` 恒为 **0**，
  不存在"0.001s 那种差一点点"的状态；
- **拖动片段是有吸附的**：`use-element-interaction.ts:234/244` 调 `snapElementEdge`
  （吸附 ±10px 内的元素边界）⇒ 用户拖到前一段末尾附近会被**吸到精确边界**，落点就是 0；
- 最坏情况（吸附刚好差一帧）也只有 `1/fps`（30fps ≈ 0.033s）< 0.05。

⇒ `0.05` 覆盖「相接」与「差一帧」两种合法态，又不会把「用户故意留的间隔」误判成相接 —— **它是对的**。
按原 A 方案放宽到 0.3~0.5s，反而会产出**跨黑场的错转场**（转场的语义是 A 淡出、B 淡入）。

## 二、真根因：**判据对用户完全不可见**

点转场 → 失败 → **只得到一句英文**「No adjacent clips found」。
用户既不知道判据是什么，更不知道**该把片段拖到多近**。
这不是"阈值错"，是**把内部判据藏起来了** —— 一个不能"问"、只能"试"的功能。

## 三、施工（3 个文件）

| 位置 | 改动 |
| --- | --- |
| `engine/core/managers/timeline-manager.ts` | 新增 `countAdjacentJunctions()`：与 `addTransitionsToAdjacentPairs` **同源**的只读查询。**不让 UI 自己数** —— "哪些轨道参与转场"本身就是判据，UI 再算一遍就是第二份判据（本项目已多次栽在此） |
| `ui/…/assets/views/transitions.tsx` | 面板**实时显示**「共有 N 个可加转场的交界…」；无交界时给出**怎么改**的指引（拖到前一段末尾附近会自动吸附贴齐）。4 处英文 → 中文（面板说明 / 失败 toast / 成功 toast / Tooltip） |
| `engine/timeline/transition-utils.ts` | 给 `ADJACENCY_EPSILON` 补注释：为什么 0.05 够用 + ⚠️**不要为了"点得上转场"而放宽它**（TD-22-49 曾把症状误判为阈值过严） |

**用户视角的闭环**：拖动片段 → 面板数字 `0 → 1` 跳变（= 贴好了，因为吸附生效）→ 点击应用 → 成功。

## 五、弯路留痕（强制）

**① 我的初始假设（"拖动片段没有吸附 ⇒ 用户永远贴不齐"）被取证推翻。**
`grep snapElementEdge` 前我看见 `findSnapPoints` 只出现在 **resize** 里，一度认定"move 漏了吸附"。
实跑 grep 后：`use-element-interaction.ts:173,234,244` 有 `snapElementEdge` 的 start/end 双向吸附。
→ 教训：**"某函数只在 A 处出现"要按 API 名（`snapElementEdge`）查，不能按内部工具名（`findSnapPoints`）查** ——
前者是设计出口，后者只是实现细节。差一步就把"阈值不严"的结论建立在错误前提上。

**② 探针期望串凭印象猜，错了两次。**
第一次猜 `expected 0 to be 4`（vitest 这次用的是 diff 格式 `- 4` / `+ 0`）⇒ 未命中；
第二次改用 `Received` 才命中。
→ 教训：**探针的 `--expect-out` 必须取自实际输出**（先跑一遍看真实格式），不要凭其它测试的印象套用。

**③ 测试 fixture 注释算错交界数**（把 `t1` 的 2 个交界写成 1 个）→ 断言 `expected 4 to be 3` 红。
→ 好消息：这恰好证明**同源契约的断言是有效的**（它把"我以为"和"实际"的差抓出来了）。
