> **触发**：用户看过他人 mockup 后当场否掉我先前的补丁思路：「你根本没好好设计这个区域；两个地方都是死区，

> **母债**：**TD-11-44**（界面层两处并存未收口）。验证口径：只跑相关测试 + 探针串行。

## 一 · 判据（这次设计的地基）

**磁盘的写入口只该有两个：人（Finder/VS Code）与同步程序（补齐 id / 云端写回）；界面只写它自己的状态键。**
界面里的"保存"= **直接写那个包**（整包原子写，写盘成功才更新索引）—— 用户不必知道"索引/缓存"存在。

| 东西 | 真相源 | 谁写 |
| --- | --- | --- |
| 名称 / 描述 / 正文 / 分组（=目录名） | 磁盘 `SKILL.md` | **人** 与 **界面保存**（两者等价：界面做的事，Finder 里也能做，结果一样） |
| `id`（UUID） | 磁盘 frontmatter | **程序**（人写不出 UUID）⇒「补齐 id」 |
| 启用态 / 注入预算 / 清单开关 | UI 状态键 | **界面**（它就是唯一真相源） |
| 索引 `agent_skills` | ——（投影） | 只在"读完磁盘之后"与"一次成功保存之后"更新；**永不作为列表骨架** |

## 五 · 弯路留痕（三条，都是真实的）

   幂等、不改写旧键，只有"真迁了/有失败"才提示）。**"闸抓到我漏"的实例，值得记。**
2. **同批清偿的 7 条死代码**：`skillStore` 的两个同义 API · `skillGroupLabel` 门面导出 · 两个门面类型导出 ·
   `skillMigration` 文件 · `createImeInput`。**其中两条是"因为本页不再用"而暴露的老幽灵** ⇒ 不是本批新写的，
   但"零消费者"就是零消费者（ADR-0053）。
3. **两条终端操作坑（与实现无关）**：zsh 对 `!!` 做**历史展开**（`editable: !!id` 直接报 `unknown file attribute`）、
   以及长命令换行被 shell 折断 ⇒ 探针/命令改用**单引号 + 避免 `!!`**。另外终端一度把历史回显混进输出，
   日志改落到 `/tmp/*.log` 再读。
