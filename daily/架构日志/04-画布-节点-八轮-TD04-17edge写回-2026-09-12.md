## 1. 调查结论：edge.data 写回真实债很小且聚焦
全 src multiline 扫 `setEdges` + `...<x>.data` 样板，命中 **仅 1 处**：

| 位置 | 字段 | 性质 |

| `App.tsx:1291` | `edge.data.relatedToSelected` | ★ edge.data 唯一合并写回（选中联动：与选中节点相连的边标 active → comet + 加亮，见 `CustomEdge.tsx:27`） |

其余 `setEdges` 32 处，绝大多数是 **append（建边）/ filter（删边）/ replace（整体替换）** 语义，非「按字段合并写回」：

**edge 本体字段裸写 2 处**（同构债，顺手收口）：
- `App.tsx:713` `selectAll` 写 `edge.selected:true`
- `App.tsx:729` `duplicateSelected` 写 `edge.selected:false`（按条件）

## 2. 实施（类比 node 版 patchNodeById）
**A 抽通用纯函数 `src/hooks/useEdgeData.ts`**（与 `useNodeData` 同构）：
- `patchEdgeData(e, patch)`：单 edge 纯函数（per-edge 不同值写回用，如 relatedToSelected 重建）
- `computePatchEdgeById` / `computePatchEdgesById`：纯函数版（返回新数组，供先拿结果再 record / 批量按条件用）
- `patchEdgeById` / `patchEdgesById`：经 `setEdges` 的封装

**B App.tsx 三处迁移**：
- `relatedToSelected`（1291）：`{...ed, data:{...ed.data, relatedToSelected:rel}}` → `patchEdgeData(ed, {data:{relatedToSelected:rel}})`（per-edge 不同值）；保留原 `changed` 短路（`next.some((e,i)=>e!==eds[i])` 等价原语义，避免无意义重渲染）
- `selectAll`（713）：`eds.map(e=>({...e,selected:true}))` → `computePatchEdgesById(eds, ()=>true, {selected:true})`
- `duplicateSelected`（729）：`nextEdges.map(...{...e,selected:false})` → `computePatchEdgesById(nextEdges, pred, {selected:false})`

**C 规则5 升级（防回潮）**：
- 检测范围：`setNodes` → **`setNodes` + `setEdges`**（消息与注释同步为 node/edge 通用）
- 字段集保持 `{data, width, height, style}`
- **修复 TD-04-16 遗留的边界 bug**：原 `findSpreadField` 的 `WRITE_CALLS` 边界在入口就命中「最外层 setNodes/setEdges 调用本身」→ 立即 `return false` → 顶层调用的回调内 spread 永不被检查（TD-04-16 当时因裸写恰好在嵌套层才侥幸抓到）。加 `root` 标志，边界仅对**递归进入的嵌套写操作**生效（`root=false`），最外层调用（`root=true`）不被拦截。

## 5. 延伸：node.selected 收口（2026-09-12，用户「一并收口」）
edge.data 收口后，对称把 node 选中态也统一入口。

### 5.1 调查：node selected 真实爆炸半径
multiline 扫 `setNodes` 回调内 `...n, selected:` 样板，命中 **3 处裸写**：
- `App.tsx:713` `selectAll`：`ns.map(n => ({...n, selected:true}))`（直接嵌套 setNodes 回调）
- `App.tsx:728` `duplicateSelected`：`nextNodes.map(n => idSet.has(n.id) ? {...n, selected:false} : n)`（先存变量再 setNodes）
- `App.tsx:827` 粘贴：`beforeNodes.map(x => ({...x, selected:false})).concat(p)`（先存变量再 setNodes）

其余 `selected:true/false` 命中均为**新建对象字面量**（clipboard 重建 / groupNodes 构造新节点），非「按 id 写回」语义，不归本规则管。

### 5.2 关键认知：selected 不是规则5 字段集能覆盖的模式
规则5 原字段集 `{data,width,height,style}` 检测的是 `...<x>.<FIELD>`（spread 旧对象**某字段**再合并）。而 `{...n, selected:true}` 是 spread **整个节点**后附加键，spread 的是 `n`（Identifier，非 `MemberExpression.field`），**不命中任何字段名** → 加 `selected` 到字段集是**无效**的（既不误报也不防漏）。

### 5.3 实施
- **代码迁移**（统一入口）：3 处 node selected 全迁 `computePatchNodeById`/`computePatchNodesById`（`useNodeData` 已有）；顺手把 `App.tsx:828` 粘贴里的 edge.selected 也迁 `computePatchEdgesById`（与 714/730 对称）。
- **规则5 升级**：新增 `findSelectedSpread` 专门检测「含 spread 且含 `selected` 键」的对象字面量，在 `setNodes/setEdges` 子树内扫描（复用 root 标志，嵌套写操作不深入）。回退无效字段集改动。负例探针 `{...n, selected:true}` 验证命中 → 删探针重跑 0 报。
