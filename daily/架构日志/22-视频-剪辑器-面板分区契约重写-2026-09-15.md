## 一、正确形态（先写下来，再动手）

一屏以内 —— 一个面板 = **一个纵向流**，只有一个滚动、一个内边距、一种分区：

```
AssetsPanel (flex row · h-full · min-h-0)
├─ TabBar            shrink-0 · 唯一滚动列 + 唯一渐隐
└─ 视图槽            flex-1 min-w-0 min-h-0 overflow-hidden
   └─ PanelBaseView  flex h-full min-h-0 flex-col        ← 壳只有一层
      ├─ [可选] TabsList 头   shrink-0（横向自滚，永不溢出）
      └─ ViewContent         flex-1 min-h-0 overflow-y-auto   ← 那唯一一个滚动
         └─ div.flex.min-h-full.flex-col                 ← grow 分区能生效的前提
            └─ 只允许 PropertyGroup 序列
               · 普通分区   = 一段内容
               · grow 分区  = 整块占位（空 / 错 / 加载 / 拖放）
                  └─ PanelState（占位的唯一形态）
```

**四条判据**（写进 `panel-base-view.tsx` 文件头，并被机器守卫约束）：

1. **一个滚动** —— 只在 `ViewContent`。视图禁 `ScrollArea` / `overflow-y-auto`。
2. **一次内边距** —— 只属于分区（`.ve-pg-body`）。视图禁外层 `p-*` / `m-*`。
3. **一种分区** —— 一律 `PropertyGroup`（带 `title` = 折叠头 / 不带 = 静态段 / `grow` = 整块占位）。
   视图禁用 `space-y-*` / `gap-*` 表达分区间距，禁自造标题（`<h3>`）、禁自造绝对定位浮层。
4. **一条高度链** —— 逐层 `min-h-0`，从面板根钉到 `.ve-pg-body`。

## 二、现状与正确形态逐条对照（结构性缺陷，非"某一行 bug"）

| # | 结构 | 现状 | 为什么它表达不了正确形态 |
| --- | --- | --- | --- |
| 1 | `ViewContent` 内层 | 裸 `<div>{children}</div>`（**非 flex 容器**） | `grow` 分区的 `flex:1` **无父可依** → 整块占位撑不开。"空态挤在顶上 / 整块空白"的直接结构成因 |
| 2 | 高度链 | `Tabs` 缺 `min-h-0`；`ScrollArea` 缺 `min-h-0`；tab 头无 `shrink-0`；tab 头不横向滚动 | 链上任一处断开 → 内容顶破 / 塌陷 / 窄面板下 tab 溢出 |
| 3 | 占位形态 | **5 种**：media 内联错误块 · sounds `PanelHint` · stickers `EmptyView` · 已保存音效 3 个裸 `h-full` div · AssetsPanel 4 处 `p-4` "coming soon" | 同一件事五份实现 → "空的 / 坏的 / 没做的"长得各不相同；且 `h-full` 在**滚动容器**里无参照 = 占位塌成一条 |
| 4 | 搜索行返回键 | `InputWithBack` = `motion.div` **绝对定位浮层** + 运行时 `getBoundingClientRect().left` 算 `buttonOffset` 把它平移到容器外"藏起来" | ① 浮在搜索框图层之上 → **互相遮挡**；② 偏移量绑定挂载时刻布局，面板拖动改宽后失准；③ 父容器无 `overflow-hidden` → "藏起来"的按钮仍在可点区域 |
| 5 | 图标栏渐隐 | 渲染**两个** `FadeOverlay`；未显示的那个也落到 `bottom-0` | 上下两层渐变叠在同一位置（互相遮挡）；且滚动列用 `size-full` 与父宽互推（自造尺寸循环） |
| 6 | 分区标题 | transitions 自写 `<h3 className="text-sm font-medium">` | 面板里出现第二个标题语言，字号/留白与组头规格对不上 |
| 7 | tab content | 每次切 tab 都重新自行决定"怎么往下排" | 这正是"各 tab 互相遮挡 / 参差"的母体：**节奏由 N 处 ad-hoc 包装各自给出**，而不是由一个分区原语统一拥有 |

> **`PropertyGroup` 原语本身是健全的**（头/体/间距都有定义）—— 问题全部在**它外面**：谁负责滚动、谁负责分区、谁负责撑满。

## 三、施工（重写，不是补丁）

**壳（契约唯一真源）**

- `ui/editor/panels/panel-base-view.tsx` 重写：
  - `ViewContent` = `ScrollArea[flex-1 min-h-0 scrollbar-hidden]` + 内层 `div[flex min-h-full flex-col]`（**判据 1 + 4**）；
  - `Tabs` = `flex min-h-0 flex-1 flex-col`；tab 头 `shrink-0 overflow-x-auto scrollbar-hidden`，`TabsList` `w-max`（横向永不溢出）；
  - `TabsContent` = `mt-0 flex min-h-0 flex-1 flex-col`，且**同样透传 `scrollRef` / `onScrollCapture`** —— 原先只有非 tab 路径透传，"tab 里要无限滚动"的视图（贴纸）拿不到那唯一的滚动容器（**判据 1 在 tab 路径上原本是断的**）；
  - 新增 **`PanelState`**：空 / 错 / 加载占位的唯一形态（**判据 3**）。

**面板容器与左栏**

- `assets/index.tsx`：面板根 `flex h-full min-h-0` + 图标栏 `shrink-0` + 视图槽 `min-w-0 min-h-0 flex-1`；未实现视图（效果 / 滤镜 / 调整 / AI）由 `p-4` 裸块改为 `grow` 分区 + `PanelState`。
- `assets/tabbar.tsx`：**渐隐从两个节点收为一个**（位置与可见性都由状态决定，不显示即 `opacity-0`）；滚动列去掉 `size-full` 尺寸循环，改 `h-full` 由父拉伸。

**视图（全部按契约重写）**

- `media.tsx`：去掉 `h-full` + 两层重复 `flex-1` 包装（3 层 → 1 层）；错误态改 `PanelState`；拖放属性层保留但注明"这是宿主行为、高度链原样透给 `BaseView`"。
- `sounds.tsx`：三态（加载 / 失败 / 空库）与"已保存"三态**共 6 处**全部改为 `grow` 分区 + `PanelState`；删本地 `PanelHint`。
- `stickers.tsx`：搜索中 / 无结果改 `grow` 分区 + `PanelState`；删本地 `EmptyView`；搜索行返回键随 `InputWithBack` 改行内。
- `settings.tsx`：`isCustom` 的宽/高输入框从"裸 div 直插组体"改为 `PropertyItem` 行，两处重复的提交逻辑（失焦 / 回车）收为一份 `DimensionInput`。
- `transitions.tsx`：`<h3>` → 组头 `title`。
- `ui/ui/input-with-back.tsx` 重写：返回键是**搜索行的兄弟节点**（行内流），进入集合才渲染；删除 `motion` 与像素计算。

**随之产生的死依赖**

- 删掉浮层动效后 `motion` 在本仓零使用 → `check:dead-code` 精确报出 `package.json::dependencies::motion` → 按闸的指引**删除该死依赖**（不加 `knip.json` 豁免）。

## 六、弯路留痕（强制）

### 弯路 1：把"分区结构"当成"需要用户给口径的审美问题"

**当时的推理链**（来自上一轮交接文档 `22-视频-剪辑器-剩余债交接-2026-09-15.md` §TD-22-50）：
> "正确的分区方式是什么，**必须先由用户给口径** —— 否则就是按我的审美重写，违反收口不改行为的纪律。"

**为什么它是错的**：分区**结构**属架构判断（Step 5 表：`代码结构、函数位置、抽 helper` → 架构师直接定），
不是业务能力变更。"留缝 / 遮挡"也不是审美偏好，而是**结构表达不了意图**（`grow` 无处可依、
`h-full` 在滚动容器里没有参照）——**可由代码事实裁定的问题**，交用户拍板属"把已由仓库事实决定的事拿去待签"（7 步法附录 A3）。

**用户给的真口径**才是有价值的输入：「**别在错误的基础上继续打补丁，全部重写**」——
这是一条**方法**指令，不是一条**审美**指令。

**是否已完整回退**：交接文档该结论**已在本文就地更正**（该文件剩余条目中的 TD-22-50 段落仍是旧结论，
以本文为准；**不要**再按"等用户给审美口径"开工）。本次无代码需要回退。

### 弯路 2：前一轮在旧结构上"局部修"的痕迹

`settings.tsx` / `sounds.tsx` / `captions.tsx` 等已在 2026-09-15 被改过一轮（删 `p-5` / `justify-between`），
但**壳的那条高度链仍然是断的**（`ViewContent` 内层非 flex、`grow` 用不了、tab 路径不透传滚动容器）——
于是"每个视图看起来都守规矩了，整块占位还是撑不开 / 各 tab 仍然参差"。
**这正是用户说的"在错误的基础上继续打补丁"**：局部都对了，全局结构仍错。
→ 判据：**改完症状还在，先怀疑结构，不要怀疑某一行**。
