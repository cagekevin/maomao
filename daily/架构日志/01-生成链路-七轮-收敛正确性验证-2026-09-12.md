## 正确性地基（自底而上 6 条实证）
1. **L0–L2 已收口且 framework-agnostic**：generate 门面三模态一行别名 wrapper（signal/taskId 贯穿）、任务中心原子方法 + `done`(taskStore:285) 内置 `publishTaskCompleted` 广播、eventBus 纯 TS。
2. **`runAbortable`(scriptBoxEngine:259) 是脚本盒统一运行期脚手架**（7 处复用：资产图/尾帧图/文本/分镜/合并视频…）：
   - AbortController 注册 `abortMap`(:266) → `onStopScriptItem` 真中止，finally 注销(:290)；
   - `withTimeout` 总闸(:272)：超时 abort 同一 signal 真掐断底层请求 + 复位 loading——**双超时（内层响应超时/外层总闸）是有意分层**：内层管「等上游响应」，外层管「读体/SSE 累积/发图前归一/落盘」；
   - catch 走 `classifyError`(:283)：abort→warn 不扰用户，真错→toast+error。
   - **职责边界**：只收敛脚手架，不改业务写回语义（成功/失败分支留调用点）→ **与任务中心合约正交**，收敛只动编排层、不动脚手架。
3. **资产图已 90% 走合约**（reportGenerate/progress/done/fail/localize/commit/saveResultToTasks 全在），唯一断链 = signal（见下）。
4. **persist 顺序铁律两侧已一致**：先落盘（saveResultToTasks=文件落盘层，filesApi:356）→ patch 写回持久 URL → done(持久URL)（任务记录层，P0-C 单向落盘）。两者是两个层面，**非双写冲突**。
5. **recover 是挂载期能力**（useEffect 注册一次 + cleanup unsubscribe，useNodeGeneration:393），与运行期 contract 生命周期错配 → **机制级坐实 recover 不进 contract**；脚本盒靠 data 持久化（六轮已定）。
6. **失败三分支两侧语义已一致**：abort 不 toast、business fail+toast、classifyError 记录——contract 内聚防再漂移。

## contract 设计约束（正确性 R1–R8）
- **R1 signal 贯穿**：contract 的 run 必收 signal 并传底层（修幽灵中止）。
- **R2 patcher 收完整 GenerateResult**（url/error/aborted）：尾帧图需复杂特化写回（prevTailFrameVariants composed 项 + 自动选中 selectedTailFrameVariantId + toast，:1714-1730）。
- **R3 persist 顺序固化在 contract 内**：落盘 → patch(原始) → patch(持久) → done(持久)，禁止调用方乱序（防临时 URL 进任务中心）。
- **R4 mutex 两策略**：节点 `claimNodeRun`/`releaseNodeRun`（finally 配对 :353）；脚本盒伪 nodeId（`{nodeId}-asset-{id}` :505）+ reportGenerate 同 id 自动清理 → 批量互不顶掉(:503-504)。
- **R5 失败三分支语义内聚**（abort/business/classify 记录）。
- **R6 超时双层**：底层 timeoutMs 必传；外层总闸脚本盒已有（withTimeout），节点侧可不加（底层已覆盖 + 落盘有 catch）。
- **R7 文本不强制进合约**：同步、无 resultUrl、`done('')` 不广播（taskCompletionBus 校验空 URL 拒发）→ 进合约仅增任务中心噪音；TD-01-11 维持文档化方向。
- **R8 伪 nodeId 语义保留**（每资产独立任务卡片）。
