## 二 · 新增架构闸（反向判据 · 带负例探针）

`check-arch.mjs` 新增规则「🐚 命令行只许 argv 传递：禁把变量拼进 shell 命令」：`src/**` + `localTool/src/**` 内
`execSync(`/`exec(` 后跟的模板串里出现 `${` ⇒ 违规；豁免 `localTool/src/index.ts`（URL 自拼 + Windows `start`
是 cmd 内置命令，argv 形态会 ENOENT）。

**为什么用闸而不是补字符集**：路径"合法字符集"这条判据天生会漂移（后端 `isSafeSegment` 刻意宽松、前端另有一份更严，
两端分歧本身就是 TD-11-25 的一半）。`execFileSync` 让 shell 不再参与 ⇒ 这一类注入**结构上不存在**，
不依赖"字符集判得够不够严"。**建闸依据**（ADR-0052：拿不出证据不建）＝ 一次 grep 命中 4 处、其中 3 处参数来自
用户/磁盘；且第四处是**真例外**而非漏改。

## 五 · 弯路留痕（两条，都是我的操作问题，不是实现对错）

1. **`!` 触发 zsh 历史展开**：把 `!Buffer.from(...)` 写进 `--find` 后 shell 直接报 `zsh: event not found`
   （命令根本没执行）。⇒ 探针注入点尽量选**不含 shell 元字符**的位置（本轮改用调用点 `const binary = isBinaryBuffer(buf)`），
   要么用单引号包住整条命令。
2. **`--expect-out` 选错串**：`node --test` 的 TAP 输出在断言失败时打印的是 `expected: 'base64'` / `actual: 'utf8'`，
   **不打印** `assert.equal` 的自定义 message ⇒ 我原先按 message 选串 ⇒ "未命中"（探针正确地拒发了假证据）。
   ⇒ 后端探针的期望串要按 TAP 格式选（`expected: …`），别按断言 message 选。
3. 附带：为定位第 2 条，手工注入过一次（`cp` 备份 → 注入 → 跑 → 还原），已用 `grep -c` 复核还原成功；
   **后续一律用 `probe.mjs`**（它自带"注入 + 还原 + 基线校验"），手工注入只为一次性定位，不留作流程。
