## 三 · 深挖：fail-open —— 守卫的输入被兜底成"中立值"（TD-16-25）

### 3.1 判据（为什么这不是"没留痕"那么简单）

给 41 处**加日志**只解决"看不见"。这三处的病是**守卫本身不生效**：

```
volumePolicy.ts:233-238    let bytes = estimateConversationsBytes(projected);
                           const downgraded = bytes > budget;            ← bytes 兜成 0 时恒 false
                           if (bytes > effectiveBudget) { …水位归一… }
                           while (bytes > effectiveBudget && …) { …贪心截断… }
```

⇒ 估算函数一失败，**整条降级链全部短路**，而唯一的留痕挂在 `if (downgraded)` 里面（`conversationState.ts:143`）—— **失败路径连日志都不会有**。
`storageQuota.byteLength` 同理（0 字节 = 报告"更空"）；`contentIdOfBytes` 同理（undefined = 去重判据失效）。

**规则（本轮的产出）**：**阈值型 / 判据型守卫的输入值，不允许来自一个"失败时兜成中立值"的函数**。要么让该函数失败即抛（调用方处理），要么兜底方向取**保守侧**（估算失败 → 按"超预算"处理），并留痕。

### 3.2 同型已登记实例（互为佐证）

- **TD-16-23**：`canvasSource.ts:57` `if (!rawUrl) continue` —— 可见性过滤守卫恒假（`nodeMedia` 保证 type 非空 ⇒ url 非空），**守卫静默不生效**。
- **TD-02-45**（本轮已回退为待还）：失败关闭纪律缺机器守卫。

### 3.3 反面：本仓已做对的两处（不是没有范式）

| 位置 | 做法 |
| --- | --- |
| `base/depthVideo/loader.ts:127` | `catch { hooks.onStatus?.('未拿到高性能显卡，准备改用 CPU。'); return false; }` —— 告知 + 明确降级方向 |

## 四 · 深挖：`TD-02-27` 只收口了「写」半边，读路径仍裸吞（TD-16-26）

### 4.1 现场（同一批 store 里，读与写不对称）

`contentStore.ts:521-532` 的**成文契约**：

> 【失败契约 · TD-02-27】本函数**永不因持久化失败而抛错** … 仅以下**契约违规**会抛错（属 bug，**调用方不应静默吞，应 fail-fast 暴露**）：① 键未登记（dev 抛）② 值无法 stringify ③ 订阅者回调抛错

而读侧（`contentGet`，`:510-519`）**无任何留痕**，且其消费方的 catch 全是裸吞：

| # | 读点 | 兜底 | 后果 |
| --- | --- | --- | --- |
| 1 | `base/store/appSettings.ts:33` `load()` | `{...DEFAULTS}` | **用户全部设置静默回默认**（缩略图开关/主题…），UI 显示默认值，用户以为设置丢了 |
| 2 | `agent/canvas/useCanvasAgentTools.ts:72` `loadGenParams()` | `{...DEFAULT_GEN_PARAMS}` | 生图参数静默回 `Auto/1K` ⇒ 出图用的可能不是用户设的 |
| 3 | `base/creative/promptManager.ts:59` `readJSON()` | `fallback` | 用户自定义预设静默回内置默认 |
| 4 | `base/store/backupStore.ts:81` `readLS()` | `undefined` | 备份导出静默少键（与 #12 的写侧"真处理"形成对照） |
| 5 | `base/store/accountsStore.ts:142` `readEnvs()` | `[]` | 账号环境静默空 |

**不对称的铁证**：`appSettings.ts:41` / `useCanvasAgentTools.ts:79` / `promptManager.ts:65` 三处的**写**路径都写着同一句注释：
「不静默吞（TD-02-27）：contentSet 持久化失败已内部留痕；bug 级异常应 fail-fast」——
⇒ 作者明确知道该留痕，**只在写路径执行了，读路径漏了**。这不是"不知道标准"，是**收口时只做了半边**。

### 4.2 为什么现在才看见

因为 TD-02-27 的验收对象是「`contentSet` 的失败契约」，而 `contentGet` 没有对应的契约段；闸又只判空 catch（本处有 `return`，不在判据面内，见 TD-16-22）——
**两条守卫的交集之外**：写侧有契约、读侧无契约；闸只覆盖空 body。
