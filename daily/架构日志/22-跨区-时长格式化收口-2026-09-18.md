## 二 · Step 1 证伪（债描述部分失准）

1. **① 硬证据**：C 与 D 函数**同名同类**、语义一致（`floor(s/60)` 总分钟 + `floor(s%60)` 补零），
   唯 D 多一层 `Number.isFinite(s) ? … : '0:00'` ⇒ 典型「抄一份后各自演化」。
2. **② 判据比对（这是本轮否决债方解法的地方）**
   - 债拟解法：三处「改 `formatTimeCode({timeInSeconds, format:'MM:SS'})`」。
   - 但 canonical 的 `MM:SS` 是 `minutes = floor((t % 3600)/60)` ⇒ **丢小时**：3661s → `'01:01'`。
   - 而 B 的现输出是 `'1:01:01'`（≥1h 进位）、C/D 是 `'61:01'`（总分钟）—— **三者都不是 `'01:01'`**。
   ⇒ 照债方解法改 = **≥1 小时的时间轴标尺与素材时长显示同时出错**（用户可见回归）。
   ⇒ 正确做法：**收真重复那一对**；B/E 是**不同判据**，不得并入（改判非债）。
3. **③ 致命拷问**：用户不"多做"事 —— 收口后**新增一种时长显示只需调一处**，且非法输入不再撒谎。

## 三 · Step 3 定位

- **判据归属**：C/D 属**时长显示**（human-readable 总分钟）≠ `formatTimeCode` 的**时间码**（帧/厘秒精度）。
  语义不同的两个函数**不该合并**（形态要匹配语义，不是统一就好）。
- **落点判定（唯一共享层）**：消费方分属 `nodes/` 与 `videoEditor/` 两域，而 `check:arch` 规则 2 是
  **反向判据**「base/ 禁反向依赖业务域」⇒ 业务域**可以**依赖 base，**不能**互相依赖
  （App 里亦有明文：「本文件不 import 剪辑器 —— 剪辑器是另一业务域」）。
  ⇒ 唯一合法共享层 = `base/`；两域均有 import `base/core/utils.ts` 的**既有先例**（`canvasToImageDataUrl` / `fileNameFromUrl` 同文件）。
- **同文件族先例**：`formatBytes` / `formatBytesParts`（TD-18-4 / TD-18-8 收口，**唯一实现** + 真空/非法判据 + `'—'` 哨兵）——
  本轮 `formatDuration` 与之**同族同形**落在一处。
