## 一、复杂度错位复述（M9）

`getNodeOutput` 是「上游产出 → 下游参考」的唯一读入口，但它对产出**字段名**的处理是**隐式启发式**：

- 读侧：`genericOutput` 猜三个魔法字段名（优先级 `assetUrl > videoUrl > resultUrl`）+ 按扩展名/`assetType` 判型；
- 写侧：各节点各写各的字段（`assetUrl` / `videoUrl` / `extractedImages[]` / `images[]` / `shots[]`…）；
- 覆盖护栏：`genericOutputOk` 是**第二份手写白名单**（9 个类型），与 `NODE_OUTPUTS` 并列。

错位在哪：**「这个节点产出写在哪个字段」这条契约没有物理位置。** 它一半藏在 `genericOutput` 的代码里（猜测顺序），一半散在各节点组件里（写入点）；`genericOutputOk` 只是"允许被猜"的名单，**不表达字段名**。后果：

1. 节点把结果写到别的字段（如 `myResult`）→ 读侧**静默返回空产出**，无报错无日志，下游只表现为"连了线没数据"；
2. 新增节点漏登记 → 只靠 dev console 一条 warn，**没有测试拦**；
3. 「无产出」与「有产出但没登记」在护栏里是同一个筐（`genericOutputOk` 是白名单，不是语义）。

## 二、收口动作（把契约搬到写侧）

`src/hooks/useConnectedInputs.ts` 现为**三张表 + 一个特判集**，`getNodeOutput` 按其调度：

| 表 | 语义 | 内容 |
| - | - | - |
| `SINGLE_OUTPUT_FIELDS` | **单 URL 产出**（字段名显式，按序取第一个非空） | `assetNode`→`['assetUrl']`；`imageGenerateNode`→`['assetUrl']`；`videoGenerateNode`→`['videoUrl']`（`resultField:'videoUrl'`）；`panoramaNode`→`['assetUrl']`；`director3dNode`→`['assetUrl']` |
| `NODE_OUTPUTS` | **复合产出**（多端口 / 多图 / 数组归一） | `scriptBoxNode`（按 `shot-` 端口）/ `imageBoxNode`（`images[]`）/ `videoExtractNode`·`gridSplitNode`·`gridMergeNode`（`extractedImages[]`） |
| `NO_OUTPUT_NODE_TYPES` | **无自有产出** | `group` / `ghostTarget`（容器·占位）+ `faceMosaicNode` / `loopNode` / `videoProcessNode`（**结果经 spawn 子节点交付**） |
| `SPECIAL_OUTPUT_TYPES` | 特判（读 `node.id`，非纯 data 派生） | `textGenerateNode` |

调度序（`getNodeOutput`）：**无产出 → 单 URL → 复合 → 特判 → 安全网**。
`genericOutput`（三字段猜测）**保留但降级**为「只服务未登记类型的最后安全网」——存量退役节点快照（如旧版 `discountVideoNode`）仍能取到数据，**已登记类型一律不再被猜**。

字段真源 = 逐一核对**各节点实际写回点**（不是照抄旧猜测列表）：
- `AssetNode` 走 `replaceNodeImage`（唯一写入口）写 `assetUrl`（渲染端 `assetUrl || url` 的 `url` 是存量兼容，写侧不再写）；
- `ImageGenerate` `patchData({assetUrl})` / 任务恢复回写 `assetUrl`；
- `VideoGenerate` 由 `useGenerateNode` 的 `resultField:'videoUrl'` 声明式写回；
- `PanoramaNode` 单角度截图写 `assetUrl`（多角度走 spawn 图片盒子）；
- `Director3DNode` 退出导演台写落盘缩略图 `assetUrl`；
- `FaceMosaicNode` 只写输入 `assetUrls`，结果 spawn `assetNode`；`LoopNode` 只写 `splitMethod`，spawn 生图节点；`VideoProcessNode` 只写 `sourceVideoUrl`/`errorMessage`，结果 spawn `assetNode`。

## 三、三个关键判断（含被否决的替代方案）

1. **为什么是三张表而不是「给 9 个节点各塞一条 `NODE_OUTPUTS`」**（`docs/120` 阶段 3 的原始写法）：
   核代码后它们本质是三类——单 URL（5 个）用**数据表**比塞函数简单得多（少一层闭包、字段名一眼可见）；复合（5 个）才需要函数；而 `faceMosaic/loop/videoProcess` 经核实**根本没有自有产出字段**，塞进 `NODE_OUTPUTS` 会写出 `['assetUrl']` 这种**幽灵声明**（自己不写、只为占位）——与 `nodeDataSchema` 里"禁止登记幽灵默认值"是同一原则。
2. **为什么不直接删掉 `genericOutput`**：它保留对**未登记类型**（存量快照里的已退役节点）的兜底。删掉会让这些老节点下游静默断流（比"猜"更糟）。**已登记类型的猜测全部消失**才是本次要治的病——安全网不再承担契约。
3. **覆盖率护栏从"dev console 噪音"改为"可测纯函数"**：导出 `uncoveredOutputNodeTypes()`，`NODE_TYPES` 每个类型必须落在三表 ∪ 特判内；单测断言为空 → **新增节点漏登记即红**。旧实现把这件事交给第二份手写白名单 `genericOutputOk`（删掉它，才真正实现"漏登记必被发现"）。

**行为变更（诚实登记）**：已登记类型不再走三字段猜测，故旧测试里三条**假设性**用例（`assetNode`+`resultUrl`、`imageGenerateNode` 上 `videoUrl/resultUrl` 的优先级）语义改变——它们测的是启发式而非真实契约（这些字段节点根本不写）。已同步更新为：① 断言真实字段契约；② 新增用例锁定"安全网只服务未登记类型"与"无产出类型不进安全网"。`docs/120` 阶段 3 已按此方案落地（见该文件顶部实施记录）。

## 四、度量（改前 / 改后）

| 口径 | 改前 | 改后 |
| - | - | - |
| 「某节点产出写在哪个字段」的物理位置 | 0 处（散在读侧猜测代码 + 各节点写入点） | **1 处**（三张表，字段名可见） |
| 读侧覆盖护栏 | 第二份手写白名单（`genericOutputOk`）+ dev console warn | **纯函数 `uncoveredOutputNodeTypes()` + 单测**（dev warn 并存） |

| 「无产出」的表达 | 与「有产出未登记」混在同一白名单 | 显式独立集合 `NO_OUTPUT_NODE_TYPES` |
| 对账工具（`check-node-data`）读侧解析 | 解析 `genericOutput` 的 `raw` 数组（正则脆弱） | 解析 `SINGLE_OUTPUT_FIELDS` 对象键 + 安全网常量（结构稳定，且进解析器自检） |
