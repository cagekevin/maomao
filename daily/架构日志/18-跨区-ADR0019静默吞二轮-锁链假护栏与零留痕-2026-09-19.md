## 二 · Step 1 证伪（**两笔的债描述需要修正**）

### TD-18-27 —— 债描述**指错了位点**（真债在下一处）

| 命题 | 取证 | 判定 |
| --- | --- | --- |
| 「`:71` `next.catch(() => {})` 静默吞」 | `withLock` 末尾 `return next`（`:81` 原样返回**原始** promise），且两处调用方都是 `await withLock(...)` | ❌ **证伪**：操作失败**对调用方可见**。这是**保护性 catch**（只吞"锁链记账"那一份，防 unhandledRejection）⇒ **判非债**（与 `18-跨区-ADR判据合规横推三轮-2026-09-18.md` 的裁定一致） |
| 「`:77-80` 也是同款保护性 catch」 | `try { next.finally(cb) } catch {}` —— **`try/catch` 包不住 promise rejection** | ✅ **真债（且是假护栏）**：`next` 失败时 `next.finally()` 的**派生** promise **无人处理** ⇒ **unhandled rejection**；注释写的「忽略 finally 隐患」**根本没有做到** |
| （附带）锁清理分支有效吗 | `locks.set(key, next.catch(...))` 存的是**派生** promise，而 `finally` 里比较 `locks.get(key) === next` | ✅ **恒假 ⇒ 清理分支是死代码**（锁条目永不释放）—— 与上一处**同根因**：把"锁链记账"和"操作结果"两个 promise 混用 |

### TD-18-28 —— 债描述**只说了一半**（还有一归问题 + 不能照搬前端判据）

| 命题 | 取证 | 判定 |
| --- | --- | --- |
| 「两处 `catch{/*ignore*/}` 零留痕」 | `:130` / `:276` 是**逐字重复**的同一段逻辑 | ✅ 属实，**且多一条**：同一文件 2 份实现 = **一归违反** |
| 「应改调原语 `tryParse`」 | `assistantStream.ts` 在 **localTool**（独立包、自带 package.json/tsconfig），**不能** import 前端 `base/utils/asyncGuard` | ❌ **证伪**：该修法在此**不可得**。真问题是**丢了上游错误体原文**，不是"没用原语" |
| 「失败被吞了」 | 同分支随即 `onEvent({type:'error'…})` + `throw new Error(errorMsg)` | ❌ **证伪**：失败**已完整上抛**；丢的只是"错误体不是 JSON 时那段原文"（而前端 `httpClient` 自 TD-18-22 起已**保留原文** ⇒ 前后端标准不一致） |

### TD-18-30 —— 债描述**属实，但它自己还撒了个谎**

```
// catch-ok: MIGRATION
/* 与上述存量迁移同款兜底语义 */   ← 假：上面 :363-368 有 logger.warn，这处零留痕
```
⇒ 读者会被这句注释误导，以为这里已经处理过了。**注释撒谎比没注释更贵**。

## 三 · Step 2~5 归因 / 定位 / 定契 / 定权

| 项 | 内容 |
| --- | --- |
| 共同归因 | 「保护性 catch / 探测性 catch」**没有把判据写出来**，于是后来人分不清"合法"与"静默吞"；其中一处甚至用 `try/catch` 造了个**不会生效**的保护（假护栏） |
| 契约 | ① 操作失败 → **对调用方可见**；② 锁链记账的 rejection 可被吞，但**必须真的吞掉**（不能留 unhandled）；③ 上游错误体原文**不可丢**；④ 同域同判据的失败分支**留痕口径一致** |
| 定权 | 三笔均为**结构 / 留痕**问题，**无业务语义变更** ⇒ 架构师自定（Step 5）。唯一用户可感知项见 §七 |

## 七 · 交付六闸自查

- **一归**：错误体解析 2 份 → 1 个 helper；迁移失败的留痕口径与其**同域兄弟分支**一致 ✅
- **减一**：**未新增兜底**——① 是把"没生效的兜底"改成生效的（并删掉假的那层）；③ 是补留痕；② 是减重复 ✅
- **减二**：删假护栏 1 层、删死代码分支 1 个、重复份数 2→1 ✅
- **一诚实**：失败可见性只增不减（迁移失败**首次有迹**；上游原文**不再丢**；锁链不再漏 unhandled）；
  **无判别力的部分如实标注**（探针③ + 本文件 §五）✅
- **零炸**：见下三问 ✅
- **一凭证**：4 块探针 + 门禁 + 7 项 grep 计数 ✅

**零炸三问**：

1. **哪些行为被改了？**
   - ① `withLock`：锁条目**现在会真正释放**（原为永不释放）；操作失败时**不再产生 unhandled rejection**；
     操作失败对调用方**照旧可见**（`return next` 未动）；
   - ② `assistantStream`：HTTP 失败且响应体**非 JSON** 时，错误文案**新增原文片段**（截断 120 字）；
   - ③ `conversationState`：旧键迁移失败**新增一条 `logger.warn`**。
2. **改前能走的路径，改后仍能走吗？** → 是。相关 40 条 + 全量单测通过；`test:localtool` ALL PASS。
3. **改前会失败的，改后仍失败吗？** → 是。`saveProjectMemory` 写失败仍 reject；`parseNonStream` 仍发 error 事件并 throw。

**⚠️ 用户可感知的行为变化（显式声明）**：**仅一处** —— 后端返回**非 JSON 错误体**（网关/代理 502 常回 HTML）时，
AI 失败提示会由「请求失败 (502)」变为「请求失败 (502)：\<原文前 120 字\>」。这是本轮**有意的**一诚实改动
（与前端 `httpClient` 自 TD-18-22 起的标准对齐），已截断防刷屏。
