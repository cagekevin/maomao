# 01 区 · 十轮 — TD-01-12 尾帧综合图接入原语（TD-01-8 母体收尾）

> 日期：2026-09-13 ｜ 触发：**用户拍板"接上尾帧图"**（九轮 TD-01-8 主体完成后的最后一块）。
> 范围：`scriptBoxEngine.ts`（尾帧综合图编排）· `scriptBoxSchema.ts`（伪 nodeId 单源）· `useScriptBoxEngine.ts`（recover 回填）· 3 个测试文件。
> 目标：**尾帧综合图从"完全裸绕任务中心"改为走 `runGenerationContract`** → 任务中心可见（卡片/进度/完成广播/失败分类）+ 生成中刷新可回填；**顺带清掉 TD-01-12，闭合 TD-01-8**。

---

## 一、取证（改前状态）

`onGenerateTailFrameVariants(shotId)`（scriptBoxEngine:1548）：「抽上一镜视频尾帧 → 本地化原版 → 调一次资产生图合成综合图 → 自动选中 composed」。其中：

| 事实 | 证据 |
| - | - |
| **完全裸绕任务中心** | 综合图段只有 `generateImage` + `localizeAndStoreToResourceLibrary` + `patchShot`，**无** `reportGenerate` / `progress` / `done` / `saveResultToTasks` / 失败分类 |
| **中止语义自相矛盾** | 尾帧图 `generateImage(opts, undefined, signal)` 传 signal（可中止），而同文件资产图 Task 不接 signal → 同类两态 |
| **异常时 composed 项卡 loading** | 异常由 `runAbortable` 的 catch 兜底，只执行 `onReset`（复位 shot 级 `tailFrameVariantsLoading`），**不复位** composed 变体自身的 `loading:true` |
| **生成中刷新不回填** | `normalizeScriptBoxData` 对 shot 字段是「默认 + 存量覆盖」，`tailFrameVariantsLoading`/composed.loading 会随刷新保留 → 无 recover 则卡死 |

| 步 | 结论 |

| **Step 2 归因** | 尾帧图是「编排序列」的**第三份非法副本**（前两份 = 节点 hook / 剧本盒资产图）。且它的写回是**复杂特化**（composed 项 + 自动选中 + 成功 toast）→ 正是原语 R2「收完整结果 + settle 回调」要覆盖的场景 |

## 三、施工

### 1. 伪 nodeId 单源（`scriptBoxSchema.ts`）
新增 `tailFrameTaskNodeId(nodeId, shotId)` / `parseTailFrameTaskNodeId(nodeId, taskNodeId)`，与资产图的两个函数同区（区头注释由「资产图任务」扩为「剧本盒多任务的伪 nodeId 契约」）——**引擎上报与 hook 回填共用同一规则，禁各自拼串**（TD-01-9 立的原则，此处沿用）。

### 2. 引擎尾帧段接原语（`scriptBoxEngine.ts`）
把综合图段（原 ~75 行的 `generateImage` + 手写 localize + 两分支 patch）替换为一次 `runGenerationContract(...)`：
- `taskNodeId` = `tailFrameTaskNodeId(nodeId, shotId)`
- `run` = `generateImage(opts, progress, signal)` —— **progress 由原语提供**（任务中心有真实进度），signal 落第 3 位
- `localize` = 落 `migrated/脚本/尾帧变体`（失败降级保留原 URL，由原语 `reportDegrade` 留痕）
- `settle` = 写回 composed 项（url/thumbnail/loading=false/errorMsg=undefined）+ 自动选中 + 成功 toast
- `onFail` / `onAbort` = 复位 composed 项 loading（**修「异常卡 loading」**）并写入 shot 级错误
- 保留「未配置模型」前置分支与「原版尾帧」抽帧/本地化（本地操作，不进任务中心）

### 3. hook recover 回填（`useScriptBoxEngine.ts`）
既有 `agent:task-completed` 订阅（TD-01-9/13 为资产图所建）扩为两条伪 nodeId 分支：
- `asset-` → 回填 `data.assets` + 补落素材库（原逻辑，`return` 收束）
- `tailframe-` → 回填该镜 composed 变体（**占位→改 / 无占位→追加** 两态）+ 自动选中 + `prevShotImageRefUrls` + 复位 `tailFrameVariantsLoading`

## 五、结论与边界

- **TD-01-12 已清**：尾帧综合图接入原语 → 任务中心可见 + 失败分类 + 生成中刷新可回填。
- **TD-01-8 母体闭合**：剧本盒两类生成（资产图 / 尾帧综合图）与节点侧**共用同一份编排**；文本类 R7 有意不进。
- **诚实边界**：尾帧图 recover 的**变体快照**依赖 shot 数据已持久化——若刷新发生在「占位写回之前」，recover 会**追加**一个 composed（不还原 original 项）；判定可接受（罕见窗口 + 图可用）。文本类仍是「生成中刷新不回填」（有意设计，见 TD-01-11）。
