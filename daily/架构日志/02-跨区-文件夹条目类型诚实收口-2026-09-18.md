# 02 · 存储 / 持久化 · 跨区 · 文件夹条目类型诚实收口（TD-02-46 结清）· 2026-09-18

> **性质**：类型诚实轮（主题 = **「列表条目」与「落地媒体」的分层 + 类型不许说谎**）。
> **根因区**：02（存储/持久化）· **跨区**：`base/media` 契约 + `base/panels` 消费方。
> **结论一句话**：素材库 rescan 会把磁盘**子目录**也录成列表条目，它不是媒体 ——
> 而 `MediaRef.type` 只有 image／video／audio 三值，于是 provider **谎报 `type:'image'`**（注释自述「仅为满足类型」）；
> 漏判 `isFolder` 的消费方（如 `mediaRefFactsOf`）会把目录当图片（建出指向**目录**的资产节点）。
> 本轮把它拆成**判别联合**：`MediaRef`（真媒体，必有 `type`）／`MediaRefFolder`（文件夹，**没有** `type`）／
> 列表用 `MediaRefEntry = MediaRef | MediaRefFolder` —— **漏判从运行期隐患变成编译错误**。
> **结论落点**：本文件（唯一写全处）。

- **本区域状态**：`已验证(有债待还)` —— 本轮 **TD-02-46 结清**；该区仍有 4 笔待还。
- **覆盖账**：本轮审 5 文件 / 涉及 5 文件（源 4 + 测试 1）。

## 二 · Step 1 证伪（债成立，且是**潜在**而非现发）

1. **① 硬证据**：`librarySource.ts:76` `type: 'image'`（同处注释自述「**仅为满足类型**」）；
   而 `mediaRefFactsOf`（唯一落地判据）对传入条目产出 `{ type, url }` —— 若收到文件夹，就会给出
   `{ type:'image', url: <目录地址> }`，落地方据此建出**指向目录的"图片"资产**（或把请求打到目录上）。
   **当前未现发**：弹窗在 `:287-288` 先按 `isFolder` 分了段 ⇒ 这是**靠一个消费方记得判**兜住的潜在缺陷。
2. **② 替代方案**：债文给的选项之一是「`MediaRefType` 加 `'folder'`」——**取证后否决**：
   `MediaRefType` **派生自资产类型目录**（`@/types` 里 `mediaRef:true` 的成员），folder **不是资产类型**；
   塞进去会污染类型域，并让 `query.types` 的语义退化成"媒体类型 + 目录"（含混）。
3. **③ 致命拷问**：用户不"多做"事；变的是**「漏判文件夹」从运行期隐患变成编译错误**（`tsc` 直接拦下）。

## 三 · Step 3 定位

- **判据归属**：「这条条目是媒体还是文件夹」的真相在 **provider 读到后端 `type:'folder'` 的那一刻** ⇒ 由 provider 如实产出、由**类型层**承载。
- **落地方不需要判**：`mediaRefFactsOf` / 弹窗 `onPick` / 剪辑器 `linkMediaRefsToProject` 的入参类型就是
  `MediaRef`（媒体）—— 「接收的是媒体」由**签名**保证，**函数体里不需要 `if (isFolder)`**（那才是把判据放到下游 = 越权）。
- **改动半径**：先按最小方案试（保留 `MediaRef` = 媒体、新增 `MediaRefFolder`、列表用 `MediaRefEntry`）⇒
  编译器只报 **3 处**需窄化（弹窗 state ×1 + 测试 ×2）。**若改成 `MediaRef` = 联合，半径会引爆到剪辑器与 App**（见 §六-2）。
- **真假接缝判别**：类型表达 = 同一语义的**两种取值**（媒体／文件夹）⇒ 判别联合；
  不需要为它新造"抽象"或"适配器"。

## 四 · Step 4 定契

```ts
// mediaRefTypes.ts —— 三个类型，一句话分工
export interface MediaRef {        // 真媒体：type 必填；isFolder?: false（判别位）
  ref; source; name; type: MediaRefType; url; thumbnailUrl?; contentId?; projectId?; folder?; meta?;
}
export interface MediaRefFolder {  // 文件夹条目：**没有** type（此前谎报 'image'）
  ref; source; name; url; projectId?; folder?; isFolder: true; meta?;
}
export type MediaRefEntry = MediaRef | MediaRefFolder;  // 列表条目（provider.list／注册表／弹窗网格）

// provider / 注册表签名随之改：list / queryMediaRefs / searchMediaRefs / MediaRefSearchResult 一律 MediaRefEntry[]
// **唯一不变**：mediaRefFactsOf / onPick / linkMediaRefsToProject 仍是 MediaRef[]（只吃媒体）
```

## 六 · 弯路留痕

1. **差点按债文的第一选项（`MediaRefType` 加 `'folder'`）动手** —— 回读 `mediaRefTypes.ts:27-36` 才发现
   `MediaRefType` **派生自资产类型目录**（`mediaRef:true` 的成员）：目录不是资产类型，塞进去会污染类型域
   并让 `query.types` 含混。⇒ 改走判别联合。**债文给的两个选项都要先取证**（铁律 3）。
2. **命名方案二选一，靠"半径"定的**：若把 `MediaRef` 本身改成联合（`Media = MediaMedia | MediaFolder`），
   剪辑器 / App / 注册表的既有签名全要跟着动 ⇒ 半径失控。改为「`MediaRef` 仍 = 媒体、新增 `MediaRefFolder`、
   **列表条目**叫 `MediaRefEntry`」后，编译器只报 **3 处**须窄化 ⇒ 既诚实又不炸半径。
   **留痕理由**：这是「把复杂度放到合适位置」的一次真实权衡 —— 同样"正确"的两种建模，半径差一个量级。
3. **探针的 `--expect-out` 又猜错了**（先写 `toHaveBeenCalledTimes`，再写 `not to contain`；实际是 `to not include 'type'`）——
   两次都是"测试确实红了、关键词没命中"。**根因：我按记忆猜断言文案**（同 A13「引用前必须回读」）。
   正解：跑之前先 `node scripts/probe.mjs --run "<命令>" --suggest-out` 拿**真实断言串**。已按真实文案重跑命中。
