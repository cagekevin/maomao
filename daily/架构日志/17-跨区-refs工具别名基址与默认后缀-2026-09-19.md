## 一 · Step 0 普查（同一件事被实现成几份）

| 口径 | 实测 |
| --- | --- |
| 说明符**解析**实现（spec → 绝对路径） | **1** 处（`resolveSpec`） |
| 说明符**生成**实现（绝对路径 → spec） | **1** 处（`computeNewSpec`） |
| 但**别名基址口径** | **2 种**（解析侧 `getAliasRoot(fromFile)` ／ 生成侧 `currentRoot`；且都与注释「相对所在扫描根」自相矛盾） |
| `DEFAULT_ALIASES` 注释口径 | 「相对所在扫描根」—— 与同文件 `--alias '@proto/:/src/protocol/'` 示例**互相矛盾** |

**真源在哪**：`tsconfig.json` 的 `paths` = `"@/*": ["./src/*"]` ⇒ **别名一律相对仓库根**。

## 三 · Step 2 归因（一处根因，两个位点）

`matchAlias` 返回的 `to` = `'src/'`（**相对仓库根**）。而解析侧写成：

```js
resolve(getAliasRoot(fromFile), m.to, 剩余段)
//      ^^^^^^^^^^^^^^^^^^^^^ 已经是 <root>/src
//                              + 'src/'  ⇒  <root>/src/src/…（不存在）
```

⇒ `resolveSpec` 返回一个**不存在**的路径 ⇒ 该 import 不进引用图 ⇒ 静默丢弃。

生成侧（`computeNewSpec`）**同一根因、相反方向**：基址用 `currentRoot`（`<root>/src`）拼 `m.to`，
`newAbs.startsWith(<root>/src/src)` 永假 ⇒ 走不到别名分支；若勉强走到，产出 `@/../components/…`
（`@/` = `src/`，`src/../` = 仓库根 ⇒ 实际指向 `<root>/components/…`，**解析不到**）。

> **两处必须同修**：只修解析侧 ⇒ 别名 import 第一次进图 ⇒ 改名/搬移**写坏**它们（比不修更坏）。

- **一凭证**：探针结论块 + 两组 dry 复验 + `git diff --stat` + `node --check` ✅

**零炸三问**：

1. **哪些行为被改了？** 仅 `refs` 的**报告内容**（少报 → 全报）与 `rename/move` 的**别名产物写法**
   （`@/../…` 解析不到 → `@/…` 正确）。**未改**：相对 import 分支产物、`convert` 分支、
   `--suffix` 显式取值下的产物、任何业务代码。
2. **改前能走的路径，改后仍能走吗？** → 是。相对引用 dry 场景产出与改前同形（§六表）；
   别名场景本就"解析不到"（改前是**坏的**），改后是好的。
3. **改前会失败的，改后仍失败吗？** → 是。`--suffix js` 仍产出 `.js`；`convert` 的 `.js→.ts` 物理改名逻辑未动；
   `find-dead` / `plan` / `batch` 未动。

**用户可感知的行为变化（显式声明）**：无 —— 本工具仅架构师手工调用，不改产品运行时行为。
