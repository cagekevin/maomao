## 一 · 正确形态（一屏以内 · 施工前先写下来）

**不变式（已存在于 `contentStore`，本轮只是让下游不再违背它）**：

1. **存储读取失败 = throw**。`contentStore` 文件头已明写「失败以 throw 表达是两族共识」：
   `kvReadOp` 对 4xx **原样上抛**、对引擎不可用**降级且已 `logger.warn` + `reportDegrade` 留痕**。
2. **「读到空」≠「读失败」**。前者是正常值（KV 真空 null/undefined），后者是异常。
3. **消费者不得把读失败换算成默认空值再往下传** —— 那会把失败伪装成「数据是空的」。

**链路（改后）**：

```
contentStore.contentGetAsync ──失败→ throw（已在源头留痕）
        │
accountsStore.readEnvs ──不吞──→ 抛出；仅「真空 → []」「形状违约 → warn + []」两种情况由本函数定
        │
   ┌────┴──────────────────────────┐
load()（模块水合·fire-and-forget）   reloadAccounts()（云同步重下）
   ↓ 调用点 .catch                    ↓ 上抛
reportDegrade(logger + toast)      cloudSync.rehydrate 逐个检查结果 → reportDegrade
```

**判据归属**：**「读失败怎么办」是调用方判据**（谁有 UI 谁决定呈现）；
读取函数只负责**把三种状态分清**（真空 / 形状违约 / 读失败）。旧实现在读取层就把三者压成一个 `[]`，等于替所有调用方决定了失败长什么样。
