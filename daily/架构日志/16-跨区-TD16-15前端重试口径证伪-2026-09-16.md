## 一 · Step 1 证伪（**本轮的真正结论**）

债描述说：「`genErrors.classifyError` 对所有 HTTP 判 `retryable:false`，无法区分 429/503/504 应重试 与 401/403/400 不应」。

**取证四条硬证据**（全部 grep / 读码所得，非推理）：

| # | 事实 | 证据（`文件:行`） |
| - | - | - |
| 1 | `classifyError().retryable` **从未被用于任何重试决策** | 全库 4 个消费点——`FaceMosaicNode.tsx:168` · `VideoExtractNode.tsx:331` · `VideoProcessNode.tsx:1222/1232` · `generationContract.ts:179/202`——**全部只把它塞进 `logger` 日志对象**；grep `if (retryable)` / `retryable &&` 全库仅命中 `httpClient.ts:265`（见下条），无一处用 `cls.retryable` 分支 |
| 2 | **真正的重试决策点在 `httpClient.ts:261-269`**，且它**根本不看 HTTP 状态** | 判据＝`e instanceof NetworkError \|\| isTimeoutError(e) \|\| (e instanceof TypeError && isFetchNetworkTypeError(e))`；`HttpError`（含 429/503）**两侧都不在重试集** |
| 3 | 且**是刻意**不重试 HTTP | `httpClient.ts:259` 注释明写「业务错误（HttpError）不重试」；`contracts.ts` GEN_ERRORS 原注释「业务失败不重试（防封号）」 |
| 4 | 后端 `isRetryableHttpStatus` **服务的不是前端** | 位于 `localTool/src/ai-relay/httpTransport.ts:37`，消费点 `providers/lovart/index.ts:291` → 服务的是**服务端轮询上游 Lovart 任务**，与前端发起的请求是**两个域** |

**推论**：债描述隐含前提「前端缺一个『按状态码决定重试』的判据」**不成立** ——
不是「判据写错了」，是**这个能力不存在，且没有代码需要它**。
把 `GEN_ERRORS.http.retryable` 改成区分 429/503，**不会改变任何行为**（因为没有读者）。

**归类**：与 `TD-04-30`、`TD-01-15`、`TD-01-18` 同母体 ——
**外部借鉴 / 跨端对照类债，须先问「对方机制要防的那件事，在我方能不能发生」**（7 步法 Step 1 ⛔）。

> ⚠️ **弯路留痕**：本债被登记时（`08-跨区-外部画布踩坑对照`）的推理链是
> 「后端已收口 `isRetryableHttpStatus` 细化状态码 → 前端 `genErrors` 不 consult → 口径漂移」。
> 这一步推理**看起来严密**（也有真实行号锚点），但它**跳过了「前端到底有没有这个机制在读这个字段」的取证**。
> **这正是 7 步法元规律①：「每一个弯路都是推理代替了取证」。**

## 二 · 附带发现真形态：TD-16-16

**`retryable` 是一个「看起来像决策依据、实则只进日志」的字段**，它自身在持续制造误判（本债就是被它误导产生的）。

| 位置 | 现状 | 处置 |
| - | - | - |
| `contracts.ts` `GEN_ERRORS[*].retryable`（5 处） | **全库零读者** —— 唯一被消费的是 `.label`（`genErrors.ts:61` `timeoutMessage`） | **删**（M6 死字段） |
| `genErrors.ts` 头注释 `retryable：仅 timeout/network 可自动重试` | **失实** —— 它不驱动重试 | **回改**为「观测字段」并写明真决策点 |
| `classifyError` 返回值的 `retryable` | 4 处真在写日志 → **有真实观测用途** | **保留**，但注释改口径 |
| `tests/unit/genErrors.test.ts:8`「与 retryable 决策」 | 同款失实描述 | **回改**（锁的是字段取值，非重试行为） |

**历史溯源**（为什么会有这个字段）：`docs/28:36` 原设计「可重试判定（`GEN_ERRORS.retryable`）」、
`docs/27:134` 更明确「network/timeout（retryable）**供「再来一次」入口**」——
**但该入口从未实现**（grep 全仓无「再来一次」按钮，只有 toast 文案里的「请稍后重试」字样）。
即：字段是**为将来铺路**（M6）而留，路没修，字段成了误导源。
