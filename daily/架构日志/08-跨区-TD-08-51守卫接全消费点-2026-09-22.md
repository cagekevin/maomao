## 一、弯路留痕：我把「边界」划错了

**当时的推理链**（上一轮 `08-跨区-capability收口-TD-08-59`）：
> 「TD-08-59 = **定义副本**收口；守卫缺失是 TD-08-51 的**行为面** ⇒ 已登记的另一笔债
> ⇒ 本轮只销定义副本、不改守卫 ⇒ **未顺手改好（零炸闸）**，边界清晰。」

**为什么它是错的**：ADR-0057 第 2 步的单位是**消费点**，不是**载体类**。守卫原语（`isRelayCapability`）建成后，
`capability` 的运行时判定共有 **3 条路径** —— ① HTTP 边界（`routes/generate.ts`）② GET attach（`capabilityFromRow`）
③ **恢复扫描**。前两条接了、第三条没接 ⇒ **同一症状原样保留**，而载体账上"看起来已收口"。

⇒ **"另开一轮"本身不是错，错在把它当成"可以不管"**：它属于**同一次收口动作的未完成部分**，
必须在同批追平，或在 ADR 层写清"第 2 步要逐消费点回扫"。

**回改**：上一轮文件 §五 的边界段已加"该划分随后被判不当"的指针（A7 —— 修正必须回改原文）。

## 二、施工（一处守卫，覆盖两条重建路径）

`initRelayPoller` 的两条重建路径（待提交 `registerHandle` / 已提交 `registerHandle`）**都落在
`const core = snap?._relayPoll; if (!core) continue;` 之后** ⇒ 守卫插在该处**一次即覆盖两条**：

```ts
      const core = snap?._relayPoll;
      if (!core) continue; // 无 relay 快照，跳过
      // 【TD-08-51】快照 `capability` 必须过守卫才能进 `registerHandle` —— 它来自 `JSON.parse`，
      //   类型层（`RelayPollSnapshot`）管不到运行时。域外值会让 `budgetMsFor` 返 `undefined`
      //   ⇒ `handle.budgetMs = undefined` ⇒ `runOnce` 的 `now - startedAt > timeoutMs` **恒 false**
      //   ⇒ 任务**永不判死**（且 GET 同报 undefined ⇒ 前端也不掐点 = 双侧静默互等）。
      //   处置：**留痕跳过**（不重建 —— 重建出来就是个空转的僵尸句柄）。下方两条重建路径都经本处。
      if (!isRelayCapability(core.capability)) {
        console.warn(
          `[relay-poll] 恢复跳过 ${frontTaskId}：快照 capability 非法（${String(core.capability)}）—— 重建也只会得到一个永不判死的句柄`,
        );
        continue;
      }
```

**为什么是"跳过"而不是"编个默认值"**：编值 = 兜底（`ADR-0057` / 7 步法 Step 4「默认值兜底」形态）——
它会把"快照脏了"这件事继续埋掉。跳过 + 留痕 = **失败诚实可见**（ADR-0035 点名"最坏失败形态"是静默卡死）。
