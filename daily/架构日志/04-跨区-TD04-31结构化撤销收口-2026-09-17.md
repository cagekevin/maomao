## §二 · 取证补充（Step 0 普查 —— 纠正了一个隐含前提）

债描述暗示「撤销会回退位置/尺寸/内容」。取证后发现**这只对了一半**：

| 检查 | 取证结果 |
| --- | --- |
| `history.record(...)` 在哪些地方调用？ | **全部是结构操作**：`addNode` / `deleteNode` / `commitRename` / `copySelectedNodes` / `groupSelected` / `ungroupSelected`（`App.tsx:716/733/763/794/807/821/1089/1097`） |
| 拖动位置会 record 吗？ | **不会**（`onNodesChange` 不接 history） |
| 改内容会 record 吗？ | **不会**（走 `patchNodeDataById`，不 record） |

⇒ **「只有结构变化才入栈」这一半已天然满足。** 真缺口在**另一半**：**栈内快照的形状**
—— 存的虽是「结构操作时的快照」，但快照本身是**全量 Node[]**（顺带存了 position/width/height/data）。
后果 = ① 撤销时**把当时的位置一并带回**（过捕获）；② 快照体积随 data 膨胀。

## §三 · 正确形态（Step 3/4）

### 落点：新建 `base/canvas/structuralSnapshot.ts`

**职责归属**：「撤销一次该退多少」这份知识**没有物理位置**（散在 `useCanvasHistory` 的类型里）。
参照同目录 `canvasSnapshotSchema.ts`（「什么字段会被持久化」的唯一物理位置）的先例，建同构模块。

### 契约（三条，写进 JSDoc 并锁死）

1. **只留结构字段**：节点 `id/type/parentId` + 边 `id/source/target/sourceHandle/targetHandle`。
   位置/尺寸/普通 `data` **不进快照** → 体积只与节点数相关。
2. **恢复 = 以当前画布为底做结构增删**（**红线**）：`applyStructuralSnapshot` **不得**整体替换 nodes
   —— 那会把位置带回旧值。对「快照里仍存在」的节点**保留当前对象**（当前位置/尺寸/内容）。
3. **结构相同不入栈**：`isSameStructure` 按序比较（顺序 = 渲染叠放顺序，属可见结构）。

### 接线（最小半径）

| 文件 | 改动 |
| --- | --- |
| `base/canvas/structuralSnapshot.ts` | **新增**（提取 / 判等 / 应用 三个纯函数） |
| `hooks/useCanvasHistory.ts` | 栈泛型 `CanvasSnapshot` → `StructuralSnapshot`；`record` 内提取结构 + 相同不重复入栈；undo/redo 改走 `applyStructural` |
| `App.tsx` | **零改动**（`record` 签名与 `apply` 签名均未变） |

## §四 · 施工中抓到的真 Bug（测试先于修复红了）

`structuralSnapshot.test.ts` 第 8 例「撤销一次删除 → 节点被重建」**红**：

```
AssertionError: expected undefined to be 'a'
  ❯ expect(out.nodes[1].parentId).toBe('a')
```

**根因**：重建分支（`materialize` 未传时的缺省路径）**漏带 `parentId`** —— 归属是结构的一部分，
漏了会让「撤销删除编组子节点」后它变回顶层节点（坐标语义从「相对父节点」漂成「绝对」）。

**修法**：改**实现**（`structuralSnapshot.ts` 重建分支补 `parentId`），**不是改测试**
—— 这正是「测试先红 = 实现有洞」的正常形态，非自证式测试。

### 弯路②：TD-14-1 同款（外部有 X ≠ 我方缺 X）

**推理链**：`scriptbox` grep `digest` = 0 命中 → 判真缺口。

**为什么错**：`digest` 要防的是「脚本改版后旧任务还写回」。但**我方 scriptbox 是同进程内存脚本引擎**
（`scriptBoxEngine.ts`），生成是**当场跑完**的，**不存在"改版后旧任务还在跑"这个窗口** ——
对方是**原生插件注册表**（可装/卸/停用/后台跑），两架构面不同。⇒ **改判非债**。

> **共同教训（值得入 SOP）**：外部借鉴类债的证伪，**不能问"我方有没有同名符号"**，
> 要问 **"这个机制要防的那件事，在我方能不能发生"**（同 `00-跨区-借架构机会16债复检` §三）。

### 弯路③：`useCanvasHistory.test.ts` 两条断言红，先假定是自己越界

按 Step 7「测试红 = 既有语义被破坏，先假定收口越界」，先复核这两条测的是**契约**还是**实现细节**：
