## 一、决策（用户拍板）

采纳十一轮推荐次序 **B → C**：

- **B** 显式化语义（把「boolean = 未触发 · 对象 = 结果」写进类型与注释）；
- **C** 只删 taskStore 的死兼容分支（`非 thenable → true` 那半条）。
- **未采纳 A**（不统一为单一结果类型、**不改** taskStore 三处 `false` 的「未触发」语义）——沿用 `docs/生成链路收口-L3c-类型与判定-施工方案.md` 的判定：「`NodeGenerationStartResult` / `NodeGenerationRunResult` 强行合一要改字段名 + 扫全部调用点，**无收益**」。

## 二、Step 1 取证（复核十一轮前提，补齐消费方细节）

| 项 | 结论 |
| - | - |
| `retryRegistry` 唯一生产注册方 | `useNodeGeneration.start`（`async` → 恒返回 thenable）⇒ `runNodeGenerationNow` 的 `: true` 分支**不可达** |
| `start` 的布尔真身 | 只有两个 `return false`（`loading` 守卫 / validate 失败）→ **只会是 `false`，从无 `true`** ⇒ `| boolean` 里 `true` 一态是**伪造值** |
| 消费方（3 处） | `useCanvasAgentTools.ts`（`res === true ? null : res` 死判定）· `canvasPlanExecutor.ts`（`!res \|\| res === true` 死判定）· `upstreamLink.ts`（只 `.catch()`，读不读值无影响） |
| 既有测试 mock | **无**任何 mock 返回裸 `true`/`false`（全部返回对象）⇒ 收窄不会误伤测试面 |

> 关键发现：`false` 与 `{ok:false}` **语义相反方向**——`false` = **没触发**（无 nodeId / 并发上限 / 未注册回调）→ 应"待生成"；`{ok:false}` = **触发了但失败**。这正是 B 要在类型里写清的东西。

## 三、施工

### B — 语义显式化（类型 + 注释）

**`taskStore.ts`**
- 新增 `NodeGenerationOutcome = false | NodeGenerationRunResult`，文档化两态语义；
- `runNodeGeneration` 返回类型 `Promise<boolean | NodeGenerationRunResult>` → **`Promise<NodeGenerationOutcome>`**；
- `NodeGenerationRunResult` 补注「结构上是 `NodeGenerationStartResult` 的读取子集；不跨层 import 以免 taskStore 反向依赖 hook 层」；
- `TaskRetryFn` 文档更新（唯一生产注册方恒返回 promise）。

**`useNodeGeneration.ts`**
- `NodeGenerationApi.start` / `start` 实现：`Promise<NodeGenerationStartResult | boolean>` → **`Promise<NodeGenerationStartResult | false>`**（去掉 `true` 一态）；
- `NodeGenerationStartResult` 补注「另有 `false` 一态 = 未触发，与 `{ok:false}`（已触发但失败）有别」。

### C — 删死分支

**`taskStore.ts` · `runNodeGenerationNow`**
```diff
-      const p = fn();
-      const thenable =
-        p && typeof (p as PromiseLike<unknown>).then === 'function'
-          ? (p as Promise<boolean | NodeGenerationRunResult>)
-          : null;
-      return thenable ? await thenable : true;
+      // 【TD-01-6】直接 await：注册方 start 是 async → 恒为 promise。旧「非 thenable → 返回 true」的
+      // 兼容分支已删（死代码：无同步注册方；且 await 非 promise 亦安全，不会抛）。
+      return (await fn()) as NodeGenerationOutcome;
```
> 顺带修掉一个**伪造语义**：旧分支会把「同步回调返回 `false`」**改写成 `true`**（把"未触发"谎报成"已触发"）。

**连带清死判定**（`tsc` 收敛后强制暴露）：
- `canvasPlanExecutor.ts`：`if (!res || res === true)` → `if (!res)`；`typeof res === 'object' ? res.resultUrl : ''` → `res.resultUrl || ''`；
- `useCanvasAgentTools.ts`：删 `const run = res === true ? null : res;`（`true` 不可达）→ 直接 `res.ok` / `res.resultUrl`。

## 六、诚实边界

1. **A 未做**（有意）：仍存在两个近亲类型（`NodeGenerationStartResult` / `NodeGenerationRunResult`），`false` 仍是「未触发」的统一信号（三义未分名）。若日后需要「一个类型 / 区分三种未触发原因」，再评估 A。
2. **`TaskRetryFn` 仍为 `() => unknown`**：注册表只做「按 key 存/取」，不收紧各注册方返回形态（生产恒 promise，测试注册同步空函数仅探活）。
3. **一条与本轮无关的既有 WIP lint warning**：`tests/unit/VideoExtractNode.test.tsx:84 'FakeVideo' is defined but never used`（HEAD 无此声明，属本会话期间他处 WIP 编辑）——仅 warning、不阻断；不由本轮引入，故未擅自改。
