## 二 · Step 1 证伪（债描述精化 —— 「意图持久化」这个提法不准确）

债文写「自动归类步骤**无意图持久化**，靠 recover 侧盲补…收口：归类意图持久化**或**明确补库为唯一路径」。逐条取证：

| 债文所称 | 取证结果 |
| --- | --- |
| 「意图未持久化」 | **不成立**：归档所需的**意图**（`category` / `name`）**本来就持久化**在 `node.data.assets` 里（随画布快照落盘）。真正缺的是**「这一步做完了没」的状态** |
| 「靠 recover 侧盲补」 | **成立且比债文更严重**：`taskStore.done()` **总会**广播（`:358`）⇒ 同会话里生成路径 `localize` 已归档 + recover handler **又补一次**；判据只是内存 ref |
| 「正确性靠 sha1 幂等兜住」 | **成立**，且这是**补偿步骤形态**的教科书样本：正确性论证写在注释里（「幂等：后端按 sha1 去重…」） |

① **硬证据**：`generationContract` 的 R3 顺序里 `localize` 先归档 → `taskCtl.done(finalUrl)`（`taskStore:358`）**必然**广播 → `useScriptBoxEngine` handler 对同一资产再调一次 `localizeAndStoreToResourceLibrary`（重复网络往返 + `rescanUploads` + `relocateToFolder` + `emitResourceSent`）。
② **替代方案**：`imageStatus === 'uploaded'` **这个状态位本来就在**，另两条归档路径（手动上传 / 从素材库选图）都在写它 ⇒ 生成与 recover 不写 = **同族已写、本处漏改**。
③ **致命拷问**：用户不"多做"事；变的是**同一份图不再被归档两遍**，且「素材库少了一张」终于可判（看状态位，而不是推测三条路谁跑了）。

## 三 · Step 3 定位

- **判据归属**：「这一步做完了没」的真相在**做过它的那一步**。归档动作发生在三条路（生成 settle / 手动上传 / recover 补库），
  故状态位必须由**三条路共同写**、判据只认它 —— 内存 ref 只是"本会话是否已经补过"的**在途去重**，不是"已归档"的真相。
- **生产者给全**：「本地化是否真的发生」只有契约自己知道（它 catch 了 `localize` 的失败）⇒ **回生产者补契约**，
  不许让消费方靠"URL 像不像本地地址"反解析（**ADR-0004 明禁**）或盲补。
- **改动半径**：源 3 文件 + 测试 3 文件；`settle` 全仓仅 **3 个实现点**（剧本盒 asset / 剧本盒尾帧 / useNodeGeneration），
  新增第 4 参对后两者**零改动**（JS 允许少收参数）。
- **真假接缝判别**：状态位写入 = 同一语义**多实现收口**（4 路共写一个字段）⇒ 强制；
  recover 补库**保留**（刷新中断确实需要它）⇒ 只换判据，不禁用。

## 四 · Step 4 定契

```ts
// ① 生产者给全（generationContract）
localize 失败降级 ⇒ localized = false（如实），成功 ⇒ true
if (url) settle?.(url, r, taskCtl, { localized });   // 新增第 4 参

// ② 生成路径：只有真归档才标状态位（不许谎报）
settle: (url, _r, _taskCtl, { localized }) => commit(... imageStatus: localized ? 'uploaded' : a.imageStatus ...)

// ③ recover 补库：判据 = 状态位（不再盲补）
const needsArchive = asset?.category && asset.imageStatus !== 'uploaded';
if (needsArchive && !recoveredAssetsRef.current.has(assetId)) { …归档… .then(() => 写 imageStatus:'uploaded') }
//   recoveredAssetsRef 只做「同会话在途去重」（补库是 fire-and-forget，状态位落盘前可能再来一条广播）
```

## 六 · 弯路留痕

1. **被债文的提法带偏一次**：先去查「归类**意图**为什么没持久化」，准备给 asset 加一个意图字段 ——
   回读才发现**意图早就在**（`category`/`name` 在 `node.data.assets`），缺的是**「做完了没」的状态**。
   ⇒ 债描述是线索不是判据（铁律 3 / A2）：**这条债的名字本身就是近似描述**。
2. **债文给的选项 B（"明确补库为唯一路径"）被否决**：推演过「删掉生成路径的 `localize`，让广播 handler 单点归档」——
   链会**更长**（settle 先写原始 URL → 广播 → 归档 → 再回写 URL，多一跳），且会**打乱 R3 固化顺序**（本地化必须在 `settle` 之前）。
   ⇒ 走选项 A（状态位）。**留档防重提**。
3. **差点写出 ADR-0004 明禁的东西**：初版想「在 recover 侧判断 URL 是否已在 `migrated` 目录」来跳过补库 ——
   那是**从显示串反解析**（ADR-0004 明禁）⇒ 立刻放弃，改为让契约把 `localized` **结构化**交出。

## 十二 · 工具债当场修（A10 · 不延后）

> **触发**：本轮收尾时发现 `index.md` 仍把**区域 01** 标成 🔴「有债待还」，而本轮已把它清零 —— 追下去是**工具让它自己的产物静默失真**。

实测 **16 份**轮次文件写的是 `本区状态`（少一个「域」字）⇒ 该文件**不被认作状态源**，`readState` **静默回退**到更旧的轮次文件。

**修（三件套）**：
1. **回改原文（A7）**：16 份轮次文件的状态行标签 `本区状态` → `本区域状态`；并把 `12-文件管理-十轮` 那处**中置**的状态

2. **让漂移可见**：新增 `RE_STATE_DRIFT` 检测，`--write` 与校验模式**都报红**；**不**放宽 `RE_STATE` 去认它 ——
