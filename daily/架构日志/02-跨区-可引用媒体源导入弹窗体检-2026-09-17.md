## 二 · 溯源（症状 vs 病根）

1. **用户撞到的 3 个 bug 都不在「业务逻辑」层，而在「层与层的约定」上**：
   - 布局 bug 的病根 = `.cl-main` 是 flex **row**（为「左栏 + 右列」设计），消费方把它当内容容器用 → 两个网格各半宽。
   - 底栏间距 bug 的病根 = 共用外壳件 `.pk-list-foot` 只在「纯文本一行」的假设下成立（无 flex/gap），第二种形态（文字 + 按钮）没有间距来源，且 JSX 空白会被剔除 → 零间距。
   - 「素材库 ≠ 全部」的病根 = 「默认分类」这条知识**不在 provider 契约里**，只有 provider 自己知道 `categories[0]` 是「全部」的语义。
2. **是否存在「末端打补丁」**：三个 bug 的修法都不是补丁（分别回到**正确的层**：内容列 `.cl-col` / 外壳件语义 / 契约默认值），本轮体检在此基础上继续往下钻找同类。
3. **撤掉某需求还有价值吗**：`MediaRefQuery.folderExact`（精确匹配）只为「全部 = 未归类区」而在；用户 2026-09-17 再次确认该语义（**「全部就是 = 未归类区，这是用户敲定的」**）⇒ 它是**裁定过的需求**，不是债。
