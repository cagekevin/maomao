# 架构日志 · 22 跨区 · 帧率探活收口 + 幽灵可编辑判据 · 2026-09-19

> **触发债**：TD-22-66（`videoEngine` `computePacketStats` **三处** `.catch((): null => null)` 静默吞
> fps 探活失败 · ADR-0019 形态④「失败归一 null / 默认值兜底」）—— **母体**（3 症状同根因）。
> **并记**：TD-11-14（`AssistantTablePanel.tsx:449` 幽灵死代码 · ADR-0029）—— **判据不同，不并入同一母体**，
> 只是同一次施工。
> **结论落点**：本文件（唯一写全处）。
> **一句话**：帧率探活失败被静默归一成 `null`、下游再 `?? 0` ⇒ **"探不到帧率"被伪装成"帧率 = 0"**
> （一个物理上不成立、却长得像合法值的形态）。修法是**降级保留 + 留痕 + 收口**，**不是**让它上抛 ——
> 帧率是**探活项**，为一个探活项把整段视频解析判死是过度反应。

- **本区域状态**：`已验证(有债待还)` —— 本轮 **TD-22-66 / TD-11-14 结清**。

## 八 · 结论与下一步

- TD-22-66 / TD-11-14 **结清**。
- **债描述的补正（A7）**：TD-22-66 只说了"三处静默吞"，**漏了两条**：
  ① 三处下游默认值**互不一致**（`?? 0` / `?? 0` / `?? 30`）；
  ② 另有一处**同语义却相反口径**的实现（`mediabunny.ts:34` 不 catch、诚实上抛）。
- **未纳入本轮（观察，不入账）**：
  1. 三处默认值 `?? 0` / `?? 0` / `?? 30` 的统一 —— 会改变产出帧率，属**业务决策**，需用户拍板；
  2. `mediabunny.ts:34` 与 `videoEngine` 的跨域口径不一致（一处抛、一处降级）—— 跨域收口要定"谁是唯一实现"，
     超出本轮半径；
  3. 静默 catch **仍无任何闸**覆盖（本轮是第 3 次撞到这个盲区：TD-17-20 / TD-18-15 / 本轮）——
     补闸需定义"哪些兜底算违法、如何枚举"，属闸体系设计。
