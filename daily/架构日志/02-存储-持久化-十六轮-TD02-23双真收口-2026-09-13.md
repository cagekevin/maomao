## 一、Step 1 取证

| 项 | 实测 |
| - | - |
| 债内容 | `projectStore` module 态 `projects` 与 contentStore **同键**（`'projects'`）的 cache 是**两份内存真相**，靠「每改必 contentSet」的**纸面约定**同步 |

> 关键：读方为 0 ⇒ 不能说"有故障"；但「约定同步 + 无守卫」本身就是 M3（SSOT 第二份）+ M2（唯一入口无机器守卫）的典型。

## 三、Step 6 施工

**`projectStore.ts`**
1. 新增 **`writeProjects(next, { persist = true })`**：唯一的 module 态写点（赋值 + `persist()` + `notify()`）。6 处赋值全部收进（载入路径传 `persist:false`；`__resetForTest` 保留直改并标 `// write-ok: <理由>`——仿 `catch-ok:` 例外惯例）。
2. `persist()` 拆为 **cache 即时写**（`contentSet` × 2）+ **仅后端保存防抖**（`saveBackendDebounced`）——消除 300ms 窗口；`flushPersist()` 同步补 `contentSet`。

**`scripts/check-arch.mjs`（新规则 9，M2 加固）**
把这条红线机器化：① 非 `projectStore` 文件**禁直读** `contentGet('projects')`（应走 `getAllProjects()` / `useProjects()` / `getCurrentProject()`）；② `projectStore` 内 `projects` 赋值**必须**落在 `writeProjects` 内或带 `// write-ok:` 豁免。

## 五、顺带修正：TD-01-8 收口**漏同步的 3 例测试**（@见 01 区）

全量跑发现 `tests/unit/useNodeGeneration.test.ts` **3 例红**——根因是**九轮 TD-01-8 收口**（抽出共享原语 `generationContract.ts`）改了可观测细节，但**没同步该测试**（九轮验证没跑这个文件）：

| 断言 | 旧契约 | 收口后实现 | 处置 |
| - | - | - | - |
| 业务失败日志消息 | `'fail'` | `'contract·fail'` | **测试同步**（共享原语统一 `contract·` 前缀） |
| 异常日志消息 | `'fail'` | `'contract·error'` | **测试同步**（异常走外层 catch，消息不同） |
| `reportDegrade` 的 `layer` | `'useNodeGeneration'`（**模块名**） | `logTag`（= `'生成'`，**日志标签**） | **改实现**：契约新增 `degradeLayer`（缺省回退 `logTag`），`useNodeGeneration` 传模块名 |

> 第 3 条没跟着改测试，是因为**`layer` 与 `logTag` 是两种读者**（Step 4 三问③）：`logTag` 供日志检索，`layer` 供降级观测/存储健康按「层」归组——拿日志标签当层标识是**读者错位**。故给契约加一个显式参数（窄接口），而不是把测试改成错的。

**测试隔离**：cache 不随 `localStorage.clear()` 清 → `projectStore.test.ts` 的 `beforeEach` 补 `contentClearCache()`（`backupStore.test.ts` 已有先例）。

## 七、诚实边界

1. **cache 读方当前为 0** ⇒ 本轮属**面向未来**的收口（不是修现行故障）；价值在「结构保证 + 机器守卫」，不在"修了 bug"。
2. **不删 store 态**（未做）：删它属**业务能力**变更（同步渲染 / 读 API 依赖），且不必要——收口后两份已无窗口、无分叉路径。
3. **顺带修的 3 例红**是**九轮 TD-01-8 的漏同步**（非本轮引入）；已在 §五 记录，并按「测试红 ≠ 测试错」的先假定原则区分了「该改测试」与「该改实现」两种情形。
4. **守卫只覆盖显式字面量**：`contentGet('projects')`；若有人把键名放变量里间接读，规则 9 抓不到（当前无此写法）。取舍：AST 规则保持简单可读，代价是这条例外——已在规则注释里说明判定边界。
