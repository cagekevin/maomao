> 范围：`scriptBoxEngine.ts`（signal）· `scriptBoxSchema.ts`（伪 nodeId 单源）· `useScriptBoxEngine.ts`（recover 订阅）· `contracts.ts`（事件登记）· 2 个测试文件。

## 一、用户问题的七步法结论（"要不要收口到跟节点同一套"）

### Step 1 · 证伪：「同一个东西」拆成两种可能

| 可能 | 判定 |
| - | - |
| 让剧本盒用 `useNodeGeneration`（节点那个 hook） | ❌ **物理不可行**：它靠 React 挂载生命周期做 recover（`useEffect` 订阅/退订），而剧本盒是**纯 TS 引擎**（无组件实例）+ **一节点 N 任务**（伪 nodeId 每资产一张卡），不是"一节点一任务" |
| 让两边共用**纯 TS 编排原语** | ✅ 可行（七轮实证：任务中心原子方法 / eventBus / `runAbortable` 均零 React 依赖）→ 即 **TD-01-8** |

### Step 2 · 归因：三类分开，不能一锅收

判据是**代码事实**：`publishTaskCompleted` 硬校验 `if (!resultUrl) return false`（`taskCompletionBus.ts:34-35`）→ **无 resultUrl 的任务永不广播**。

| 类 | resultUrl | 异步 | 现状 | 该收口？ |
| - | - | - | - | - |
| 资产图 | ✅ | ✅ | 已 90% 走合约，缺 signal、缺 recover | **该** |
| 尾帧图 | ✅ | ✅ | signal 已贯穿（:1699）；仍缺 recover | **该**（本轮未做） |
| 文本 ×4+ | ❌ | ❌ 同步 | 直写 `shots` | **不该** |

### Step 3–6 · 定位与施工策略
- 编排原语（若收口）应落 `base/store` 纯 TS；React 专属（loading / recover 订阅）留 hook。
- **本轮只做"小而准"的体验修复**（用户目标），**不启动** 2171 行引擎的收口重构：收口是"防漂移"的结构收益，且应以本轮确立的**伪 nodeId 单源 + recover 判据**为地基。

## 二、落地

### ① TD-01-10 幽灵中止 → signal 贯穿

**症状（用户可见）**：资产图生成中点「停止」→ `onStopScriptItem` 把 `loading` 置 false（**看起来停了**），但请求照跑、成功后**照样 commit 写回** → "我停了，图又冒出来"。

改：`async () => {}` → `async (signal) => {}`，并 `generateImage(opts, onProgress, signal)`（**第 3 位**，与尾帧图 :1699 同口径）。
中止路径正确：`generateImage` 抛 AbortError → `runAbortable` 走 `classifyError=abort` → `logger.warn`（不打扰用户）✓
顺带更正原注释「用户要求『停止』不做」——事实是停止入口存在，只是资产图不响应它。

### ② TD-01-9 剧本盒「生成中刷新」丢图 → recover 订阅

**症状**：任务中心 pollTask 找回 resultUrl 后广播 `agent:task-completed`；节点侧 `useNodeGeneration` 按 nodeId 精准回填，**剧本盒此前不订阅** → 刷新后"生成中"的资产图**永不回来**（任务中心显示已完成，剧本盒格子空着）。

改：
1. **伪 nodeId 规则单源**：`scriptBoxSchema.assetTaskNodeId / parseAssetTaskNodeId`（引擎上报与 hook 回填**共用**，禁各自拼串）；
2. `useScriptBoxEngine` 新增订阅：反解伪 id → `assetId` → 回填 `data.assets`（`loading:false/has/assetUrl/thumbnailUrl`）；
3. `contracts.ts` 的 `EVENTS['agent:task-completed'].to` 补登记新订阅者，并注明**两订阅者判据不同**（节点=等值 / 剧本盒=前缀反解）。
4. **边界补齐（用户澄清设计意图后）**：剧本盒生图的意图是「生成完**自动归类进素材库**的人物/场景/道具」以省用户手动拖；而「落素材库」是生成流程的一步、**随刷新中断** → recover 时**同口径补一次** `localizeAndStoreToResourceLibrary`（folder 由 `asset.category` → `resourceFolderOf` 派生；ref 防重复触发，后端 sha1 幂等）→ 连"生成中刷新"也不缺图。
   （测试：正例断言"补归类被调一次且 folder='migrated/人物'"；反例断言"不回填也不落素材库"；素材库通道在测试内 mock 隔离。）

### ③ TD-01-11 文本进任务中心 → **改判非债**

七轮 R7 + 本轮实证：文本无 resultUrl → `done('')` 被拒发 → **无法 recover**；进任务中心唯一效果是"多几条没有结果的卡片"，而剧本盒自身已有 loading（`genMask`/`promptLoading`/`imgGenLoading`）→ 收益≈0、噪音>0。
→ 维持「文本不上任务中心」并文档化。

> **撤回上一轮的口头结论**：我此前说"文本进任务中心能恢复"是错的（没吃透 R7）。已在对话中更正。
