## 二~四、三模块逐项结论（溯源 / 定海 / 切割）

### A. `useAssetDropPaste.ts`（551 行）— **发现 1 真实运行时 bug**

**职责**：素材库拖入 / 文件拖入 / URL 拖入 / 粘贴（图片·文本·节点组·提取帧）/ 右键上传，共 6+ 条「上画布」入口。全部经注入的 `addNode` 收口 → 与 TD-04-2「四条建节点路径」不冲突（它们是 addNode 的多个**调用点**，非独立实现）。

**定海**：判型 → `assetType`；清洗 → `clipboard.ts`（用户 6 条硬约束已固化在文件头）；落盘 → `filesApi.resolveNodeAssetUrl`；data 写回 → `patchNodeDataById`；建节点 → `addNode`。SSOT 清楚。

**切割缺口（TD-04-20，真 bug）**：`onPaste` 的 contenteditable 分支用 `as unknown as DataTransferItem[]` 强转后调用 `ceItems.some/every`。但真实浏览器的 `clipboardData.items` 是 **`DataTransferItemList`（数组式接口，无 `some`/`every`）** → 在 PromptInput（真实 contenteditable，见 `PromptInput.tsx:667`）内粘贴**图片或节点组 JSON**时抛 `TypeError: ceItems.some is not a function`。测试所有 mock 的 `items` 都是**数组**，故长期绿灯掩盖。**同文件 `useGlobalPaste` 却正确用了 `Array.from(...)`** → 同语义第二实现 + 假收窄。

### B. `useConnectedInputs.ts`（143 fan-in）— **健康，无需改**

- 类型诚实标杆：`str`/`objField`/`arrayImages`/`genericOutput` 全用 **typeof 控制流收窄**（非 `as`），注释显式「防假收窄」；产出项定型为**真实运行时形态**（`NodeOutputItem` 全可选 string）。
- SSOT：`NODE_OUTPUTS` 产出声明表 + 通用兜底 + 文本特判，三层调度清晰；剧本盒唯一业务依赖（`collectAssets`）收敛在声明表一行。
- 边界 Guard：**G2 dev 期 schema 校验**（产出节点 ⊆ 声明/兜底/无产出集合，缺口即 warn）实测完整。
- 性能契约：P0-B 三段式窄订阅（edges 引用 + upstreamEqual 按 data 引用判等 + useMemo），注释固化 F1 约束（禁原地 mutation）。
- 判：**合格深模块**（二轮「不切」结论经本轮逐行验证成立）。

### C. `ui/NodeShell.tsx` 本体 — **健康**

- 尺寸契约：`useNodeWidth/Height` 拆两个原始值 selector（防 zustand 新对象每帧重渲），根 div `width` 精确跟 `node.width`、`minHeight` 走内容自适应。
- 收口良好：`useSizeSync`（比例）、`NodeResizer`、`ErrorBoundary variant="node"`（单节点崩溃隔离）、端口统一在主框内渲染、`overlayHandles` 解决「相对整节点居中」的定位基准问题（且注释解释了为何不用 createPortal）。
- **系统确认**：全库 grep「只写 `style` 不写 `width/height`」的尺寸写回 = **仅 `useArrangeCanvas` 一处**（TD-04-19，九轮已修）。→ TD-04-19 爆炸半径**完整无遗漏**，NodeShell 的「width 优先」契约无其它破坏点。
