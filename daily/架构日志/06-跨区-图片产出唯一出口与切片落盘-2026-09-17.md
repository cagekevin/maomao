## 四、母体与病灶（Step 2／3）

### 母体 M-A：**canvas 产物不校验 → 假成功**（≥4 现身：压缩／放大／切片／合成）

```
1) 画布尺寸或内存超本机上限 → canvas 分配失败
2) canvas.toDataURL() 返回 "data:,"      ← 规范允许，且是【真值】
3) 各处只判 !dataUrl → 全部放行
4) dataUrlToBlob("data:,") 产出 0 字节 Blob 且不抛错
5) 空图写回节点 / 送给模型 → 用户看到"成功"
```

**归因**：不是某个 `if` 写错，而是**「产出」与「校验」被拆成两个动作**，且校验没有任何一处真正实现（3 处 `!dataUrl` 是假判据——挡不住 `"data:,"`，只给假信心）。
**定位**：判据必须落在**产出 dataURL 的物理位置**（canvas 出口），而非散在消费方。唯一位置 = `core/utils.ts` 的 `dataUrlToBlob` 旁（同域：dataURL 语义；已是 dataURL→Blob 唯一收口；叶模块零依赖无环）。

### 母体 M-B 的第二现身：`GridSplitNode`

1. **格式打架**：同一节点 `clipShape` 用 PNG、grid／manual 分支写死 `'image/jpeg', 0.85` → 带透明源图切出来变黑底，且二次有损（节点 UI 自己宣称"切刀（任意形状 + 透明通道）"）。
2. **把"派生"当"产出"**：`extractedImages = f(源图, cells)` 是派生结果，却挂在 `hLines/vLines/lassoShapes` 上逐帧重算 → 拖一次切割线 = 全量重切 N 张 + N 次编码。
3. **绕过唯一落盘出口**：base64 直写 `patchData` → N 张 MB 级 dataURL 进画布快照 / CAS 上报（与 TD-06-6 同族；06 区已确立"图像入节点必落盘"不变式）。

## 五、定契（Step 4）

| 项 | 契约 |
|---|---|
| 产出 | `canvasToImageDataUrl(canvas, format, quality?)` —— **产出与校验是同一个动作**；产物非 `data:image/*`（含 `"data:,"`）→ **根部抛出** |
| 消费方 | 禁止再写第二份 `startsWith('data:image/')` 判据；禁止把任意异常重分类成"跨域" |
| 切片 | `extractedImages: string[]` 语义与类型**零变更**，值由 base64 改为 `/files/` 持久 URL；落盘失败走 `persistInlineOrKeep` 统一降级（保留内联 + 一次可见提示） |
| 失败可见 | 切片派生失败 → `logger.error` + **toast**（此前只落日志，用户点「批量切分」只得到"没有可用的切片"，误导） |
| 收口边界 | 函数头**诚实标注**已收口 8 处 / 未收口 13 处（见 TD-06-10），**不宣称"全库所有 toDataURL"** |

## 九、弯路留痕（与结论同等重要）

### 9.1 我把 canvas 产物校验的改动半径说成「7 处」，实测 ~20 处 → 按 Step 3 退回重选位置

- **当时的推理链**：grep `toDataURL` 时只统计了我已读过的文件（imageCompress／imageUpscale／ImageEditor／InlineImageCropper／GridSplitNode／GridMergeNode／useImageHoverActions／assetUrl），得出"7 处，半径可接受"。
- **为什么错**：全库实跑一次 `toDataURL` 命中 **20+ 处**（缩略图／视频海报／director3d／videoEditor 引擎／scriptbox／FaceMosaicEditor／PanoViewer／OverlayEditor 遮罩 …）。SOP「若下沉/收敛后动了 ≥10 个消费方 = 只搬了家」→ 原方案越线。
- **处置**：**退回 Step 3 重选边界** —— 只收口「图像入节点 / 送模型」主路径（8 处），其余登记 TD-06-10；并把边界**写进函数头**（而不是宣称"全库唯一出口"让注释说谎），全部收口后才加"`toDataURL` 只允许出现在 `core/utils.ts`"的**反向判据闸**。
- **是否已完整回退**：是（未按原方案横扫 20 处，无残留）。

### 9.2 外部参考实现的两个技术细节是**形状误配**，差点当成本仓缺口

- `HoverToolbar` 反缩放：AIFISHER 的 `transform: scale(max(zoom,0.8)/zoom)` 看起来"更专业"，但本仓答不出"用户少了哪件做不到的事"，且半径横跨 17 个节点的共享组件 → 非必需。
- `fit()` 保选区：AIFISHER 用**像素坐标**裁剪，故窗口 resize 必须按比例重算选区；本仓 `ReactCrop` 用**百分比**坐标 + 画布 CSS 缩放 → 天然不丢。**照搬会把"不需要做的事"写进代码**。
- **规程**：外部仓库是"参考实现"，不是"本仓缺口的证据"（SOP 附 A5）。引用前必须先在本仓实测语义。

### 9.3 「已收口 8 处 / 未收口 13 处」这条边界本身是错的（第二段开工前纠正）

- **当时的推理链**：收口唯一出口时，我把边界定为"图像入节点 / 送模型主路径"，并按**我已读过的文件**划出 8 处；其余笼统记为"缩略图 / 截图等内部产物，危害面小"。
- **为什么错**（第二段 Step 0 重新取证后发现）：
  ① 这条边界**不可机器判定**（"是否写回节点"是运行时行为），因此它无法被任何闸守卫 —— 一处不可守卫的边界等于没有边界；
  ② 它**已经漏判**：`FaceMosaicEditor:274`（打码保存 → 写回节点）、`VideoExtractNode:174`（抽帧 → 写回节点）、`ImageBoxNode:141`（缩略图档）**都在受害面内**，却被归进了"其余 13 处"；
  ③ 后果是我亲手在 `canvasToImageDataUrl` 函数头写了一句**暗示存在分界线**的描述（"其余 13 处尚未收口"）—— 这正是本仓在批的 M4 描述层漂移，只不过这次作者是我。
- **处置**：边界改为**唯一可判定的一条**——`src/**` 里所有 canvas 产物一律走唯一出口；13 处全部收口，并加"`toDataURL(` 只允许出现在 `core/utils.ts`"的反向判据闸守住这条边界；回改函数头描述（§6.2 末行）。
- **是否已完整回退**：是（上轮那句"未收口 13 处"的描述已从源码中删除，不是留一半）。
- **元教训**：**划边界时先问"这条边界能不能被机器判定"**——判不了的边界，写进注释只会变成下一轮的漂移源。

## 十二、本轮的诚实边界与遗留（用户追问「ROI 与是否催生新问题」后当场补齐）

> 本节是**用户追问后重新取证**补的，不是施工时的结论。记下来是因为它比结论更重要：
> 上面 §十"收口完成"那句话在写下的当时**是过宽的**。

### 12.1 闸的覆盖边界：只守了同步族，异步族是同类缺口（TD-06-14）

- 施工时我把"canvas 产出"当成**一件事**，实际是**两族**：
  | 族 | 失败语义 | 本轮是否收口 | 是否被闸覆盖 |
  |---|---|---|---|
  | 同步 `canvas.toDataURL()` | **抛错** 或返回 `"data:,"` | ✅ 21 处全收口 | ✅ |
  | 异步 `canvas.toBlob(cb)` / `OffscreenCanvas.convertToBlob()` | 回调收到 **`null`**（不抛错） | ❌ 未审未收口（≥6 处） | ❌ |
- 两族的失败形态**同源**（都是"失败归一成一个能被当成真值的空值"），所以修了同步族就宣称"画布产出已守住"= **假安全感**。
- 处置：① 闸头 + manifest desc **当场补写覆盖边界**（不许读成全覆盖）；② 6 处登记 TD-06-14。
  ⚠️ ①的写法后来被用户判定为**错**：那不是"补边界"，是**闸覆盖不全时改描述让闸继续绿**（= 绕过，只是换了体面的形式）→ ③ 整个闸已按用户裁定删除，见 §13。

### 12.2 `GridSplitNode` 的 300ms 防抖加剧了一个既有竞态

- 现象：用户改完行列（或拖完切割线）后 **300ms 内**点「批量切分」，`handleSplit` 读到的 `data.extractedImages` 还是**上一轮**的切片。
- 诚实定性：这个竞态**改之前就存在**（预切是异步的，改完立刻点也会读到旧值）；本次加防抖把窗口从"一次 IO 时间"**拉长到"IO + 300ms"**。属**加剧**，不是新增。
- 未修的原因：正解需要"派生版本号"（把 `cells` 与 `extractedImages` 绑成一个可对账的版本），属独立小设计，本轮不顺手改（避免把两件事混在一个 commit）。**留作已知边界**：改完行列请等一拍再点切分。

### 12.3 13 处里只有 3 处补了失败路径，其余 10 处沿用了原有静默降级

- 补了：`director3d/project`（reject）· `OverlayEditor`（不写坏值 + logger）· `FaceMosaicEditor`（toast，隐私相关）。
- **没补**：`useVideoPoster` / `thumbnails` / `ImageBoxNode` 等 10 处 —— 它们的 `catch` 本来就是**静默归空**（`catch { return '' }` / `catch { return undefined }` / `catch-ok: BROWSER_API`）。行为上等价（都归空），但**失败原因仍不可见**。
- 后果：今天若某类缩略图/海报集体变空，排查难度与改前**完全一样**。本轮只保证了"不会拿坏值当真值"，**没有保证"失败可见"**。

### 12.4 ⚠️ §12.3 本身也是错的（同一段文字，两次错）
