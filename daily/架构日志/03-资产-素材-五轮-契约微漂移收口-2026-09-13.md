## Step 3 · 定位 + 施工

### ④ 假收窄 → 诚实收窄（正确性优先，先做）

抽 `fileNameOf(file: File | Blob): string`：
```ts
function fileNameOf(file: File | Blob): string {
  return file instanceof File ? file.name : '';
}
```
替换两处 `(file as File).name`。**行为零变更**（Blob 时旧代码同样是 undefined → 落 `'upload'`）。

### ② 死参数 → 统一为一个名字

```ts
// 原：part 名 `result_${Date.now()}.${ext}` + filename 字段 `safeName('generated', ext)`（两个不同名字）
// 现：fd.append('file', blob, safeName('generated', ext));  // 删掉 filename 字段
```
**依据**：后端只从 `saveName` 取 **ext**（最终物理名 = `contentHashName(sha1(bytes))` 内容哈希）；
part 名与 filename 字段**提供同一个 ext** → 删字段**零行为变化**，且消除「两处各起一个名字互相误导」。

### ①③ 文档更正（不改行为）

- **①**：注释改为说明后端 `applyResourceContextMove` 是 **context-only**（原「重试会撞 src 404」理由已不成立）；**显式标注 `retries:0` 原样保留、本次只更正文档**。
- **③**：文件头改为「**默认值**取自 `UPLOAD_DIRS`；`subfolder` 参数接受**任意合法相对路径**（素材库按分类动态传 `migrated/人物` 等），后端 `normalizeSubfolder` 以**顶层根白名单**校验」；并明确**本模块内**仍成立的纪律（不散写字面量、目录名不改）。

> **同一条纪律**：**只改文案不改行为**时，必须在注释里显式写明「行为未变」——否则下一个读者无法判断这是"修 bug"还是"改语义"。
