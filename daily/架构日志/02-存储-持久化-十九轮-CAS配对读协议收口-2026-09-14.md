## 三、Step 3–4：定位与定契

**原语该住哪？** → **`base/core/contentStore.ts`**（= KV CAS 协议的真相所在）。
判据：① 它是"版本读 + 条件写"这套协议的**已存半套**（`contentKvGetVersion` / `contentKvSetCas` 已在同文件）；② 放业务域（projectStore / videoEditor）会造**层位倒置**（两个平级域互相依赖）。

**契约（只做探测，不做判据）**：

```ts
export interface KvVersionedRead<T> { value: T | null; version: number }
export async function contentKvReadWithVersion<T = unknown>(
  key: string, { retries = 2 }: { retries?: number } = {},
): Promise<KvVersionedRead<T>>
```

- **不吞错**：读失败原样上抛（与严格族 fail-closed 一致）
- **不硬编码重试**：`retries` 由调用方按场景给
- **不解析业务结构**：返回 `unknown`，归一化属各域自己的 `normalize*`
- `value === null` = 合法状态（键不存在），**不是失败**
