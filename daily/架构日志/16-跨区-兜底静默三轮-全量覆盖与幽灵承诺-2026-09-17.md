## 一 · 方法学撤回（诚实优先 · 本轮最重要的一条）

### 1.1 现象

| 判据 | 命中 | 处置 |
| --- | --- | --- |
| `catch` 体内无 `logger/reportDegrade/throw/catch-ok` | **186** | ❌ **作废**（假阳性） |
| 同上，再加 `toast/showToast/setError/postMessage/failures/broken/console/reject/onStatus/status:` | **129** | ❌ **作废**（假阳性） |
| `catch` 体内仅 `return <空默认值>` 且单语句体 | **43**（+ 二轮 `true` 补扫） | ✅ **成立**（已逐条打印上下文核对） |

### 1.2 根因（为什么作废）

扫描用的切片正则 `catch\s*\{([^}]*)\}` 用 `[^}]*` 取"body" ⇒ **遇到嵌套块（`if {...}` / 内层 `try {...}`）就在第一个 `}` 处截断**。
留痕往往写在**嵌套块之后**（例：`videoEditor/stores/sounds-store.ts` 的 `const errorMessage = …` + `setErrorMessage(...)`），于是被截断在视野之外 ⇒ 判成"静默"。
⇒ 该口径**系统性高估**，且**越是结构化处理错误的代码越容易被误判**（恰与意图相反）。

### 1.3 由此确立的判据（写给下一个人）

> **「静默 catch」不可 grep 计数。** 只能逐条读上下文判定 —— 因为"失败是否到达用户/调用方"是**语义问题**（toast / error state / 判别联合 / 返回值 / 上报 都算到达）。
> 可 grep 的只有**退化子集**：「单语句 `catch { return <空默认值>; }`」这一形态（本次 43 处即此子集）；**报数时必须写明这是子集，不得说"全仓静默 catch 有 N 处"**。
