## 二 · 收口设计：只把**真差异**开成参数

新增 `src/hooks/useInlineNameEditing.tsx`（唯一实现），调用方只声明三件事：

| 参数 | 为什么必须由调用方给 |
| --- | --- |
| `createFolderPath: (name) => string` | 唯一真正的域差异：GV 在 `tasks` 域走 `tasks/<name>`、其余走 `<folder>/<name>`；RL 恒走 `<currentFolder>/<name>` |
| `logTag: string` | 日志按域区分（`'生成视图'` / `'素材库'`） |
| `refresh: () => void` | 各面板自己的列表重载（都是 `reset(true)`，但是**各自的** `reset`） |
| `connected` / `setItems` | 直传（布尔 + state setter，天然稳定） |

**出口**：`openCreate()` · `openRename(item)` · `renderInputs()`（两条输入条在调用点相邻，故合并为一个出口）。

**为什么不把 `createFolder`/`handleRename` 留给调用方**：那样收口就只剩"抽了段 JSX" ——
两条**最容易漂移的业务判据**（建目录的路径语义、重命名后如何就地改列表）仍各存两份。

## 七 · 方法沉淀（可复用）

1. **债原文给的是线索，不是尺寸** —— 本轮债写"36 行"，实测 **≈85 行**。
   施工前必须**自己重新取证**（逐段 `diff`），否则收口会漏掉一半重复面（漏掉的那半将来照样漂移）。
2. **收口时只把"真差异"开成参数，其余一律内收** —— 本轮只开 `createFolderPath` / `logTag` / `refresh`
   三个参数；把 `createFolder`/`handleRename` 留给调用方等于"只抽了段 JSX"，两条最易漂移的业务判据仍存两份。
3. **收口会顺带解掉 memo 击穿** —— 内联箭头集中到 hook 内 ⇒ 一处 `useCallback` 全部稳定。
   这是"改结构"比"逐点补 `useCallback`"更根本的又一例（后者会把重复**越修越多**）。
4. **给"唯一实现"补它自己的测试** —— 收口前这套逻辑两处**都没有测试**；收口后它错了就是两个面板一起错
   ⇒ 唯一实现必须有自己的测试，这是收口的**交付物之一**，不是可选项。
5. **写稳定性断言时，测试自己必须喂稳定入参** —— 本轮第一次跑该断言是**假红**：
   我把 `base()` 写在 `renderHook` 回调里 ⇒ 每次渲染新建 `createFolderPath`/`refresh`/`setItems`。
   真实调用方这三个都是 `useCallback`/setter ⇒ 测试要用**模块级常量入参**才忠实。
   （同族：测试桩不忠实会让断言假红 —— 上一轮 TD-04-53 的教训。）
