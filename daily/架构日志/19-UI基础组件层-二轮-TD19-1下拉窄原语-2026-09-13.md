## 一、Step 1 取证（先证伪，再决定抽多少）

| 事实 | 证据 |
| - | - |
| 两处下拉**确为逐字重复** | 面板类名尾部、行 chrome 类名在 `Select.tsx`/`ModelSelect.tsx` **完全相同**（`git show HEAD` 对比确认）；上下弹定位三元表达式亦相同 |
| 但**差异也真实** | 宽度令牌不同（`min-w-[10rem]` vs `min-w-[17rem]`）、`ModelSelect` 另有 badge/费用/iconOnly/divider/showDivider/labelMaxWidth、空态文案与内边距略异 |
| 消费半径 | `Select` ← 1 处（`scriptbox/GearSettings`）；`ModelSelect` ← 5 处（TextGenerate / TemplateNode / ImageGenerate / VideoGenerate / AgentPanel） |
| **两组件均无专属测试** | `tests/unit` 无 Select/ModelSelect 测试 → 抽取须自建安全网 |
| 同类模式实际有 16 处 | `useOutsideClick` 的 16 个消费文件多为**各自 bespoke** 的下拉/浮层 → 说明本仓的下拉并**不是**统一抽象 |

**判定（Step 1/3）**：真债（同一视觉原子两份实现，改样式必漂移），但**只抽逐字相同的部分**：
- **抽**：面板 chrome + 定位三元；行 chrome + 选中态 + 点选协议。
- **不抽**：宽度令牌（刻意的产品差异 → 由调用方传入）；`ModelSelect` 的 badge/费用/iconOnly 等特化；**更不做** `renderTrigger/renderItem` 宽基座（= "宽接口薄实现"假基座，且会把 2 处「同款」变成 1 处基座 + 14 处 bespoke 的第三种形态）。
- **不动**其余 14 个 bespoke 下拉（越界）。

## 四、结论与边界

- **TD-19-1 已清**（窄抽取方案）；两处「同款下拉」的 chrome 与定位现为单一真源，样式改一处即两处生效。
- **诚实边界 / 刻意不做**：
  1. **未抽宽基座** —— 理由见 §一（会造"宽接口薄实现"的假基座）。
  2. **未合并触发按钮与空态** —— 两处触发按钮 chrome 相近但**不完全相同**（`Select` 有 `disabled:*`、`ModelSelect` 有 iconOnly 分支），空态文案与内边距亦不同 → 强行合并会把差异塞进 prop，得不偿失。
  3. **未动其余 14 个 bespoke 下拉** —— 不在本债范围；若将来要做统一，应以本原语为起点另立方向（须先量化）。
