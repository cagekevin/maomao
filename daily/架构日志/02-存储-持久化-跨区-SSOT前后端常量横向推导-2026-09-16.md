## 二、溯源（横向推导主线）

母体 **M7（SSOT 第二份）** 在区域 02/04/05/12/22 反复出现。本轮验证该母体在**「前后端跨边界常量」**这一未被扫到的子类仍有漏网：

前端 `src/components/base/utils/assetUrl.ts` 与后端 `localTool/src/routes/files.ts` 各自**独立**定义了一份完全一致的「缩略图可编码格式」白名单，仅靠注释「与后端 SUPPORTED_THUMB_FORMATS 一致」手工同步，无机器闸：

| # | 写点 | 实证行 | 内容 |
| - | ---- | ------ | ---- |
| ① | `src/components/base/utils/assetUrl.ts` | :88 | `const SUPPORTED_THUMB_FORMATS = new Set(['png','jpg','jpeg','gif','bmp','tiff'])`（注释「与后端 SUPPORTED_THUMB_FORMATS 一致」） |
| ② | `localTool/src/routes/files.ts` | :49 | `const SUPPORTED_THUMB_FORMATS = new Set(['png','jpg','jpeg','gif','bmp','tiff'])` |

两端是**独立构建树（src vs localTool）**，没有共享常量模块可引用 —— 于是同一份事实被抄成两份，靠「约定 + 注释」同步。任一方新增/删除一个格式而另一方未同步 → 静默分歧：前端传 `format=x` 被后端白名单拒 → 回退源扩展名（功能降级但不报错），或反之。这正是 M7 母体的典型形态（同源、两份、靠约定）。

**附带同源发现（已裁定非债，不另立案）**：`uploadDirs.ts`（`UPLOAD_DIRS`）与 `localTool/src/utils/fileStore.ts`（`UPLOAD_ROOT_ALLOW`）同样是「上传根目录」这一事实的两份抄写，靠双注释同步。但此处的对账闸 `scripts/check-upload-dirs.mjs` **已于 2026-09-15 经用户裁定删除**（理由：两端各 5 个手写根、一年最多动一次、性价比不合格），改由双注释承担。属**用户明示的有意设计（注释已固化 + 裁定留痕）** → 非债，本轮只留痕、不新立债（避免推翻既有裁定）。
