## 二、溯源（Phase 1：症状 vs 病根）

- assetStore 之死不是丢失，是**域收敛**：素材库 SSOT 已被 `resourceStore`（区域 12）承接，当初按旧目录命名的「store/assetStore」已无数据流。病根处置 = 按治理规则 4 把该子域标**已退役（并入 12）**，而不是给一个不存在的文件写审计。
- filesApi 健康度总体高：失败契约（「失败一律 null + logger.warn、不抛、调用方降级」）在 8 个落盘函数逐个核实一致；防重复落盘双闸（`downloadRemoteToLocal` / `saveResultToTasks` 的 `isLocalFileUrl` 拦截）有回归测试钉住（filesApi.test.ts L231-250「素材拖画布→uploads/web 重复文件」护栏）。

## 三、定海（Phase 2：不变式 / 唯一真相源）

- SSOT：文件域唯一单点 = filesApi（后端唯一落盘端点 `POST /api/files/upload`，multipart/JSON 双模式）；素材库 SSOT = resourceStore（区域 12）；subfolder 顶层桶中央表 = `utils/uploadDirs`；均无第二份实现。
- 契约诚实度（铁律 2）盘点：
  - ✅ `localToolApi` 边界自述与实现一致（逐行核实，无「注释说收口了、实际还留着」）；
  - ✅ 落盘失败契约全函数一致（null + warn，无 `catch {}` 全静默）；`openFileDir` 空路径短路返回 undefined、`moveFile`/`createFolder` 抛错由调用方 catch + toast（useResourceMoveToFolder:126 实证）——契约成立；
  - 🔴 3 处化石注释与事实不符：① `moveFile`「成功但响应超时的重试会撞 src 已不存在 404」——后端已 context-only，重试幂等，理由失效；② `saveResultToTasks` data 分支 file part 名 `result_${Date.now()}.${ext}` 被后端 `fields['filename']` 优先级压死（死参数）；③ 文件头「subfolder 一律取自 UPLOAD_DIRS 中央表」与动态 `migrated/<分类>` 实流不符（TD-03-6）；
  - 🔴 `(file as File).name` ×2（filesApi L202/L207）：Blob 无 name，运行时靠 `|| 'upload'` 兜住——消费端单方声称形状的轻度假收窄（videoEngine:606 同模式但带了诚实注释）（TD-03-6④）。
- 观察项（**非债登记**，勿当债清）：`saveResultToTasks` http 分支文件名带秒级时间戳 → 挫败后端 `existsSync` 快路径，同一 URL 重复落盘会重新下载远程文件，靠 contentId 查重兜住「磁盘不重复」——代价是带宽不是正确性，换来可读文件名，不改。
- 健康项：「图像入节点统一落盘策略」（`showThenPersistInline`/`persistInlineOrKeep`/`resolveNodeAssetUrl`）为唯一降级策略 + 测试钉住，TD-06-6（GridMerge 裸绕）已还；本轮全库消费方核实无第二套降级。
