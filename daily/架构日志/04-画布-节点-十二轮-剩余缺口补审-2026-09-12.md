## 二~四、逐模块结论

### A. `canvas/nodePrefs.ts` — 设计好，2 处低息问题

**定海（正向）**：SSOT = `yimao_node_prefs` 结构化键 + `PREFS_FIELDS`（data 键 ↔ 记忆键映射）；**「记忆只在新建那一刻注入（`injectNodePrefs`），绝不反向改写存量节点」** 是干净的源头收敛（组件 `useState(data.x ?? 常量)`，不读记忆回退）。

**问题**：
1. **默认值两处维护**：`PREFS_DEFAULTS`（模块内）与各节点 `useNodePrefs(type, {...})` 的 defaults 是两份——实测当前值一致，但改一处忘另一处即漂移（TD-04-23）。
2. `useNodePrefs.set` 在 `setPrefs` 的 **updater 内做副作用**（`loadAll` + `contentSet`）——React 要求 updater 为纯函数；StrictMode/并发下 updater 可能重放，且同 tick 两个不同 type 的 set 存在「各自读旧快照 → 后写覆盖先写」的竞态（低概率）。

### B. `hooks/useCanvasShortcuts.ts` — 健康（补 JSDoc）

守卫链完整且语义正确：`e.repeat`（防 Q/W/E 连发爆发）→ `hasModalLayer()`（全屏层让位）→ `isEditableTarget(e)`（输入框跳过）→ `hasSelectionText()`（有文本选中时跳过 Ctrl+A/D/L，但 **Ctrl+G 编组除外**，语义合理）。
**修复**：JSDoc「守卫条件与源码一致：」后原有 3 行空洞残骸 → 已补全四条守卫说明。

### C. `hooks/useAssetDragToCanvas.ts` — 设计好（唯一发起端收口），1 处待验证

**定海（正向）**：把「拖到画布建节点」的发起端收口为一份（统一 MIME `application/x-yimao-asset` + `assetPayload` 信封 + 模块级 `textCache`），并说明「与内部排序拖拽（move 语义）不混用」；`useResourceCardDragProps` 一次 dragstart 写两套 MIME（move + asset）——注释记录了 d7ac136「只写 move MIME 导致拖图跑进 web 目录」的根因。
**待验证（观察）**：文字素材的**异步补全** `fetchText(url).then(t => e.dataTransfer.setData(...))` —— 在 `dragstart` handler 返回**之后**再 `setData`，Chrome 的 drag 数据处于 protected mode 会忽略（规范限制）。首次拖拽（`textCache` 未命中）时文字内容可能丢失。需实机验证；若成立，应在卡片渲染期预取 text（使缓存命中，同步可读）。

### D. `canvas/lod.tsx` — 深模块好，但有「假实现字段」+ 类型标注缺失

**定海（正向）**：合并原 LodProvider/useLod/LodListener 三碎片为深模块；内部监听 `transform[2]` 自动算 `lodLevel`（0/1/2/3）并驱动 `.react-flow` 的 `lod-1/2/3`/`zoomed-out-lod` class（与 `index.css` 契约）。
**问题（TD-04-22）**：
- **假实现字段**：context 声明的 5 个字段中，**仅 `lodLevel` 被消费**；`viewportMoving:false`、`useThumbnail:false` **恒为 false**（Provider 不产出真值），`nodeCount`/`handleFollowLimit`/`edgeFxLimit` **无任何消费端读取**。
- 因 `tests/unit/lod.test.tsx` / `assetTools.test.ts` / `useAssetDegrade.test.ts` **断言这些字段存在**（视为「默认 context 提供完整 LOD 字段」的预留契约），**未删**；改为**加类型标注 + 注释标注假实现状态**。
- **`LodProvider` props 此前零类型标注（隐式 any）**——与画布区「`as any` 0 处」的诚实基调不符（隐式 any 是更隐蔽的不诚实）。**已补 `LodProviderProps`**。
