## 一、Step 1 取证 —— 债描述**一半不成立**

**核验（读 `start` 全貌 + 全仓查 `updateNodeRuntime`）**：

| 结论 | 证据 |

## 四、TD-01-6：审计已完成，**属改 P0 生成契约 → 呈用户决策**

**审计问题**（原债待裁定项）：「`retryRegistry` 注册方是否仍有非 React 旧回调；无则收口为单一 `NodeGenerationRunResult`」。

**审计结论**：

| 项 | 结论 |
| - | - |
| `retryRegistry` 注册方 | **唯一**是 `useNodeGeneration.start`（React hook，`async` → 恒返回 thenable）⇒ taskStore `runNodeGenerationNow` 里「非 thenable 旧回调」分支（`return thenable ? await thenable : true;` 的 `: true`）**实为死代码** |
| **但 boolean 并未消亡** | `start` 自身仍有两个 `return false`（`loading` 守卫、validate 失败）→ 经 `runNodeGeneration` 上传；**Agent 侧真实消费**：`useCanvasAgentTools.ts:1054-1063` 显式处理 union、`upstreamLink.ts:14` 依赖「无回调→`false` 静默跳过」、`canvasPlanExecutor.ts:568` await 其结果 |
| 另 | `runNodeGeneration` 的 `false` 还承担**三种"未触发"语义**（无 nodeId / 并发上限 / 无注册回调），与 `{ok:false}`（失败）**不同义** |

**为何不擅自做**：收口 = 改 `start()`/`runNodeGeneration()` 的返回契约 + 同步改 **3 处** Agent 消费方 → 按七步法 **Step 5 定权**（改对外契约）＋原债自注「P0 契约故先呈用户」→ **交用户拍板**。

**选项**：
- **A**：统一为单一结果类型（`NodeGenerationStartResult`）—— 并把 taskStore 三处 `false`（无 nodeId / 并发上限 / 无回调）改为 `{ok:false, reason}`，同步 3 消费方判定。**收益**：一个类型、无 union 分支；**成本**：动 P0 契约 + 3 消费方。
- **B**：维持 union，仅在类型与注释写清「boolean = 未触发 · 对象 = 结果」并给 `false` 的三义各自命名。**收益**：零风险、语义显式；**成本**：类型仍是两种。
- **C**：只删 taskStore 的死兼容分支（`: true` 那半条），`start` 仍可返回 boolean。**收益**：最小改动、去掉已死代码；**成本**：union 与两处 `return false` 保留。

> 推荐次序：**B → C**（先让语义显式、再删死代码），**A** 留到确实需要"一个类型"时再做（现在 4 方调用里 3 方忽略返回值，union 未构成实际认知负担）。
