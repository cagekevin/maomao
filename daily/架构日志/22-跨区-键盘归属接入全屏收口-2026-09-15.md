## 一、Step 0 · 普查：宿主已经有什么？

**已存在的收口机制（不需要新建）**：

| 机制 | 位置 | 作用 |
| --- | --- | --- |
| `isCanvasSuppressed()` | `base/core/modalLayer.ts` | **画布激活位判据唯一真源**。文件里原话：「将来剪辑器（或任何"激活位"域）接入时，**只在这里 `||` 一项**，全部消费方自动跟随」 |
| `subscribeModalLayer()` | 同上 | 给「把开关声明成 props」的宿主（React Flow `deleteKeyCode`）订阅让位 |
| `useCanvasShortcuts` 的让位 | `hooks/useCanvasShortcuts.ts` | 查询式让位（执行前问一次 `isCanvasSuppressed()`） |
| `FullscreenShell` / `useFullscreenEditorKeys` | `base/panels` / `modalLayer.ts` | 全屏层登记入口（`ImageEditor` / 3D 导演台 / 全景漫游都用它） |

**结论：收口机制齐备，缺的是「剪辑器没接进去」+「画布侧键盘注册没有统一入口」。**

## 二、Step 1 / 2 · 根因：判据没跟着形态变

**母体两条，同源**：

1. **判据没跟着形态变**。剪辑器 2026-09-14 从「非模态常驻底部基座」（自建 `VideoEditorDock`）
   换成挂载 cutia 版 `EditorShell` —— `App` 里渲染成 **`fixed inset-0 z-modal` 全屏层**。
   但让位判据仍是给底部基座写的：「只让 Delete / undo / redo 三个键」（`editorKeyAction`）。
   后果之一尤其隐蔽：**`deleteKeyCode` 的订阅只订了 `subscribeModalLayer`**，
   而剪辑器**不登记 modalLayer** ⇒ 剪辑器打开后它**根本不触发** ⇒ 在里面按 Delete 仍删画布节点。
2. **画布侧键盘注册没有统一入口**。谁要挂 window 监听就自己挂，"要不要查让位判据"由各自决定 ——
   查了的对，没查的漏，而且这是一张"新增组件要记得加"的清单。

## 三、Step 3 / 4 · 定位与契约

**① 判据接入唯一真源**（`modalLayer.isCanvasSuppressed`）：
```ts
return hasModalLayer() || isEditorSessionOpen();
```
—— 正是文件里写好的那句「只在这里 `||` 一项」。**删除** `isEditorActive()` / `editorKeyAction()`
与 `EditorKeyAction`：它们服务的是**已不存在的底部基座形态**，而且会放行 Q/W/E、⌘A/D/G/L
落到被全屏盖住的画布（= 错误能力，不是能力削减）。

**② 订阅口与判据同源**：新增 `subscribeCanvasSuppressed()` = `subscribeModalLayer` + `subscribeEditorSession` 两源合并。
理由：判据有 2 个来源，若订阅方只订其一，就会出现「判据对了、订阅没醒」的错配 —— **正是 TD-22-19 的形态**。
让订阅口与判据同源，订阅方就不需要知道有几种压制来源。

**③ 画布侧注册入口收口**：新增 `base/core/canvasHotkeys.ts::useCanvasKeydown` ——
画布内组件注册 window 键盘监听的**唯一入口**，内部强制让位。判据仍单点（本文件不得自己判断有没有层打开）。

## 六、弯路与判断留痕

| # | 判断 | 结果 |
| --- | --- | --- |
| ① | 一上手想给那 6 处监听**逐个加** `if (isCanvasSuppressed()) return;` | 用户提示「宿主有全屏收口」→ 回到 Step 0：收口机制已存在，**根因是判据没接进去**。改成"接入判据 + 收口注册入口"，6 处里有 5 处经取证根本不该动 |
| ② | 给 `useCanvasKeydown` 加了 `capture` 选项，想把 `AssistantTablePanel` 也迁进来 | **加了又删** —— 唯一潜在消费者（表格面板，capture 阶段 + `stopPropagation`）经评估**不该迁移**（它调同一个判据函数，单点未破、无漏让位风险），于是 `capture` 变成**无消费者的死参数**（违反铁律 5：不为假设需求加参数）。最终不迁移，并在 hook 文件头写明"已知例外 + 理由" |
| ③ | 差点把 `PanoramaNode` 也当"画布内组件"改掉 | 取证发现它的漫游层是 `FullscreenShell` ⇒ **它自己就是压制源**。若用 `useCanvasKeydown` 会**自废**（打开漫游后自己的 1/2/3/截图键全失效）。**先分清"画布内"与"全屏层内部"** 再动手 |
| ④ | 想保 `editorKeyAction` 的"只让三键"能力 | 它是给**底部基座**的；基座形态 2026-09-14 已不存在。留着它 = 在剪辑器里放行 Q/W/E 落到被盖住的画布（错误能力）。**删除不是能力削减** |

## 七、结论与遗留

- **TD-22-19 结清**，且边界被证伪：真债 1 处（`VideoProcessNode`），另 4 处经取证为「全屏层内部 / 元素级 / 已自查」，**不该动**。
- 交付物是**判据接进唯一真源 + 画布侧注册收口为一个入口**：此后新增画布内组件只要用 `useCanvasKeydown`，
  让位是入口行为而非"记得查"；新增压制来源（第三类层）只需改 `isCanvasSuppressed()` 一处。
- **遗留（登记待办）**：
  1. `AssistantTablePanel` 仍自己挂监听（已自查判据）—— 判据单点未破，**非债**，已在 `canvasHotkeys.ts` 注明例外与理由。
  2. `PanoramaNode` / `director3d` / `ImageEditor` 等**全屏层内部**监听 —— 非债（它们自己就是压制源）。
- **下一轮建议**：**M-A 手抄形状族**（TD-22-28/30/35/36/39，5 笔低息、机械但成片），或 TD-22-47（贴纸/音效数据源，业务债待用户拍板）。
