## §一 · 症状与只读取证

用户：AI 助手发来网络图 `https://a.lovart.ai/artifacts/agent/BpZRZ69epKJBZevT.jpg`，拖到画布成 assetNode 后**破图**。

只读取证（与真实调用同口径 —— 后端走 `fetchWithProxy`，故经 7897 代理）：

```
curl -x http://127.0.0.1:7897 -o NUL -w "%{http_code} %{content_type} %{size_download}" <url>
→ 200 · image/webp · 28134
```

**URL 声明 `.jpg`，字节真相是 webp。** 这是本轮全部结论的起点：浏览器按字节嗅探能显示（AI 面板正常），
而落地链路把「URL 名后缀」当成了格式声明 → 磁盘出现「名 .jpg ／ 字节 webp」的假图。

## §二 · 正确形态（先写下来，再动手 —— 7 步法第 2 条）

**能力：外部媒体 URL → 画布资产节点（持久、可发送、可编辑）**

- **入口唯一**：`addImageNodeFromUrl(pos, url)` —— 拖入 / 粘贴 / 导入三个宿主只调它。
- **链路 3 步**：① 先显示（`addNode('assetNode',{assetUrl})`）→ ② 本地化（`persistUrlToUploads` 判别联合）
  → ③ **归位**（落盘返回的 contentId 写回 `node.data`）。
- **判据层级**：是不是媒体 = `assetType` 真源；**格式是什么 = 字节 / 响应 Content-Type**；落盘成败 = `filesApi` 判别联合。
- **真相归属**：`/files/` 文件 + `resources` 行（contentId）是真相；`node.data` 只是渲染缓存副本。
- **失败诚实**：本地化失败 → 保原 URL 降级 + 一次可见提示；渲染失败 → 有可见态，不静默裂图。

## §四 · Step 2 归因 —— 三个独立母体（不是三个孤例）

| 母体 | 现身点（份数） | 能一次消灭 |
| --- | --- | --- |
| **M-A 格式真相被 URL 名顶替** | ① 落盘命名 `doSaveRemoteUrl`（已拿到 Content-Type 却因 URL 有后缀而丢弃）② 缩略图 `handleThumbnail`（`isJimpEncodableExt(srcExtRaw)` 为真即短路，不读字节）③ 内联 base64 `resolveLocalImages`（按扩展名配 MIME）= **3 处** | 落盘名说谎 ／ 缩略图按名解码 ／ 送模型 MIME 错标 |
| **M-B 缺「归位」：身份与内容不同源** | ① 后端 `recordUploadedFileRow` 算 sha1 却不回传 ② 前端 `contentIdOfBytes` 重算 = 3 处调用 | 前端 fetch 整图重算 ／ 节点持 contentId 而库无对应行 |
| **M-C 失败不可见** | ① `downloadRemoteToLocal` 归一 `null` ② `AssetNode` 裸 `<img>` 无 `onError` ③ 后端注释两处承诺「前端 `onError` 回退原图」——代码里不存在 = **3 处** | 归一 null ／ 裸 img 无回退 ／ 注释承诺未落地 |

三者**不可合并**：格式是「内容事实」、身份是「内容身份」、失败是「结果契约」，三种语义各自所有方不同。

## §五 · 施工（本轮）

### 5.1 M-A · 格式真相收口（TD-08-27）—— `localTool/src/routes/files.ts`

| 动作 | 改前 | 改后 |
| --- | --- | --- |
| 格式判据 | `needsExt = !path.extname(stableName)`；URL 有后缀 → 丢弃已拿到的 Content-Type | `mimeToExt(mime) \|\| path.extname(fileNameFromUrl(fileUrl)) \|\| ''`（**响应头优先，URL 名仅回退**） |
| 落盘命名 | 自造 `${sha1(url)前16位}_${basename}` | 委托唯一权威 `writeUploadDedup`（内容寻址 `sha1(字节)`） |
| 去重/幂等 | `fs.existsSync` 免下载快路径 + 自算 sha1 查 resources | contentId 去重（同字节命中 → 不写盘） |
| 结果信封 | `{url, path, thumbnailUrl}` | **+ `contentId`**（后端回传，前端不必重算） |
| 两处调用 | formData / JSON 分支各抄一份同语义代码 | 收口 `respondRemoteUrlUpload`（唯一实现） |
| `saveRemoteUrl` 形参 | `(subfolder, fileUrl, filename?)` | `(subfolder, fileUrl)` —— 物理名由内容寻址决定，不接受调用方命名 |

**刻意取舍（写清，不为存量兼容）**：删掉「同一 URL → 同一文件名 → existsSync 免下载」快路径。
物理名改由字节内容决定、下载前不可预知，故幂等改由 contentId 去重承担；代价 = 同 URL 重复请求多一次下载，
换来「名实相符 + 跨入口（multipart / base64 / 远程下载）同一权威」。

### 5.2 M-C · 失败回退补另一半（TD-04-33）—— `src/components/nodes/AssetNode.tsx`

`<img>` 补 `onError` 两段回退：`thumb`（按需小图）→ `original`（原图 url）→ `failed`（显式破图占位）。
至此后端 `handleThumbnail` 注释里承诺的「前端 `<img onError>` 回退原图」才真正闭环；
图片源变化（替换/编辑/重生成）自动重置回退态，否则上一张的 `failed` 会粘住新图。

### 5.3 连带修正 —— `src/hooks/useAssetDropPaste.ts`

本地化调用补传 `filename: fileNameFromUrl(url)`。**这是修我自己在 5.1 引入的退化**：
物理名改内容寻址后不含原名，而 resource 行的可读显示名必须由发起方显式声明，否则素材库/下载只见哈希名。

### A. `[thumbnail] resize 失败 … 500`（存量名实不符文件）—— **不合理，已修正**

日志里的 `55c5c59875e8cec0_3oFHEEav4ZIO2PwD.jpg` 是**旧命名遗留**（名 `.jpg` / 字节 webp）。

**修正**：resize 失败后**再判字节真相**，把两种语义分开：

### B. `GET /user-avatar.jpg → 502` —— 一行已修（一次性疏漏，**改判非债**）

## §十三 · 第七波（同日 · TD-08-28 收口）—— 稳定身份只有一份算法：生产者给全，消费者只转发

### 形态（Step 2/3）

`contentId`（`sha1:<hex>(字节)`）此前在**两侧各算一份**：后端落盘权威 `writeUploadDedup` 产出并回传
（`localTool/src/routes/files.ts:175` multipart / `:410` fileUrl），而前端 3 个创建点仍自算：
`nodes/AssetNode.tsx:273`、`hooks/useAssetDropPaste.ts:233`（File 拖入）、`:282`（网页图本地化）。
其中 `:282` 一处**为拿这个值还要 `fetch(localUrl)` 再下一次整图** + WebCrypto 重算 sha1。

**判据**：身份 = 内容，只能有一份算法（后端 `sha1(字节)`）。前端 WebCrypto 是**第二套实现** ——
两套一旦在编码/算法细节上差一点，同一文件就会有两个 contentId（去重静默失效、
`contentId→resource` 解析查不中 ⇒ 破图/重复行）。这不是"重复代码"而是**正确性**问题，故按 M3 SSOT 收口。

### 施工（Step 6）

- **生产者给全**（`components/base/api/filesApi.ts`）：`UploadOutcome.ok` 增 `contentId?: string`；
  `uploadFileToLocal`（multipart）与 `uploadRemoteUrl`（fileUrl）把后端回传的 `contentId` 原样上浮；
  `PersistOutcome.ok` 同步增 `contentId?: string`（失败侧对称带 `contentId?: undefined` 键），
  `persistUrlToUploads` 三条成功分支各自透传（`inline` / `already-local` 如实为 `undefined` 并就地写明原因）。
- **消费者只转发**：`AssetNode.tsx` → `const contentId = up.contentId;`；`useAssetDropPaste.ts` 文件拖入 →
  `up.contentId`；**网页图本地化** → `r.contentId`（**同时删掉那次 `fetch(整图)`**）。
- **删零生产消费的原语**：`assetUrl.ts` 的 `contentIdOfBytes` 连同 JSDoc 删除（3 个消费者已全部改向），
  原地留痕写清"为什么删而不是留"（防后来者重造第二份身份计算）。
