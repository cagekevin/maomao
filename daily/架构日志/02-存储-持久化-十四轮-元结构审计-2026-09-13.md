# 02 区 · 十四轮（元结构轮）— 审计机制自身的债：闸无闸、索引反结构、规则指向死档案

> 前两轮（十二/十三）在**代码层**找母体（结果契约 / 入口红线 / 失败可见性）。本轮把镜头拉到**审计机制自身**——因为「母体之母」不在代码里，在**我们用来治理代码的那套机制**里。
> 心法依据：§零（唯一目标降复杂度——**审计机制本身也是系统的一部分**）；§一.2（源头收敛）；铁律 4（不预设前提：连"审计流程"也不是红线）。
> 全部结论**先实证后落盘**，非凭记忆。

## 一、元母体 1（最高杠杆）：闸自己没被闸守 —— 13 个闸中 8 个没挂

### 1.1 实证

```
scripts/ 下 check 脚本：13 个
prebuild/pretest 挂载：api, events, node-handles, any, catch   → 5 个
mount 缺失（既不进 prebuild 也不进 pretest）：jsx, keys, node-types, node-data,
                                              arch, strict-src, upload-dirs, targets  → 8 个
```

**最刺眼的一条**：`check:upload-dirs` 与 `check:catch` 是**架构师当天刚立的闸**——立完就漏挂。
**这直接证伪了"手工往 prebuild 字符串里追加"这条机制**：它结构上必然漏。

### 1.2 结论

> 我在十二轮说过"没有机器守卫，任何收口必回潮"。本轮发现：**这句话应验在了闸自己身上**
> ——闸是守卫，但"闸有没有被跑"没有守卫。

### 1.3 修复（源头收敛）

- 新增 `scripts/gates.manifest.json` = **闸清单唯一真源**（id/cmd/phase/desc）。
- 新增 `scripts/gates-run.mjs` = **派生运行器**（读 manifest → 按 phase 执行，fail-fast，含"清单为空即 fail-loud"自检）。
- `prebuild` / `pretest` / `check:health` **三处全部改为从 manifest 派生**，npm script 里**不再出现任何闸列表**。
- 效果：**加闸只需登记 manifest 一次**，三处自动生效 → **"漏挂"从结构上不可能**。

### 1.4 负例探针（先红后绿）

临时在 manifest 加一个 `node -e "process.exit(1)"` 的假闸 →
`npm run prebuild` **自动执行它并阻断**（`❌ 闸失败: check:probe`）→ 恢复后 12 道全绿。

## 三、元母体 3：审计规则指向已废弃的真源

### 3.1 实证

`index.md` 中三处仍写"追加到 `spec/TECH-DEBT.md`"：
- §审计闭环 第 6 条（记债）；
- §区域治理规则 第 5 条（跨区归属）；
- §区域治理规则 第 7 条（待翻新）。

而 `spec/TECH-DEBT.md` 已于 **2026-09-11 废弃只读**（其自身头部有废弃声明）。

### 3.2 结论

这是 **M3（SSOT 第二份）母体在"记录层"的第四次现身**：债的"真源"在架构日志，但规则还指着旧档案 →
后来者按规则记债 → **债进了死档案，索引与真源分叉**。

### 3.3 修复

三处规则改为指向 `daily/架构日志/<NN>-<区域>-<日期>.md` 的「探债」段 + `债务.md` 索引，并显式标注 TECH-DEBT 已废弃。

## 七、结论：元母体与代码母体的同构

三轮下来，一个清晰的结构浮现——**同一个母体在不同层反复出现**：

| 层 | M3「SSOT 第二份」的现身 |
| --- | --- |
| 代码层 | `projectStore` module 态 vs `contentStore` cache（TD-02-23） |
| 契约层 | 5 个 KV 函数各发明返回形状（TD-02-24） |
| 闸层 | 闸清单抄在 prebuild/pretest/health 三处（**MD-14-1**） |
| 记录层 | 债的规则指向废弃 TECH-DEBT（**MD-14-3**） |

> **这就是"母体之母"**：**凡"同一真相被抄成多份"，无论抄在代码、契约、闸还是文档里，都会漂移。**

架构师的动作因此是**同一个动作重复使用**：**找到真相的物理位置，让其余各处从它派生**——
- 存储真相 → `contentStore` 单一内核（十二轮）；
- 失败真相 → `reportDegrade`/`check:catch`（十三轮）；
- 闸真相 → `gates.manifest.json`（本轮）；
- 记录真相 → 区域文件 + `债务.md`（本轮）。
