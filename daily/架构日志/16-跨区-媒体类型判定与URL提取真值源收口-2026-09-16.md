### ⑧ 孤儿 GC 的 URL→路径（TD-08-16 的**第二实例**，回读 08 区覆盖度表时发现）

| 站点 | 改动 |
| --- | --- |
| `localTool/src/utils/orphanGc.ts` | `toUploadRelPath` 正则 `/\/files\/(.+)$/` → 委托 `relativePathFromFilesUrl`（剥 `?#`），**保留** decode 失败容错（宁可少删盘） |

**【为什么这是高利息】**`toUploadRelPath` 服务于**孤儿 GC 的引用集合**（`collectReferencedRelPaths`）——
它不剥 `?#` ⇒ `…/a.png?token=1` 被当成磁盘名 `a.png?token=1` ⇒ `existsSync` 恒 false ⇒
**该引用不计入 referenced ⇒ 仍被使用的文件可能被删除**（用户可见：图片消失）。
★ **该站点在 08 区覆盖度表里已被自己标为 `🔴 有债待还(TD-08-16)`，但代码从未改** ——
「登记了债」≠「修了债」；本轮**回读覆盖度表**才发现它仍活着（**覆盖度表要读，不能只读 §五 探债表**）。

## 六 · 弯路留痕（强制 · 与结论同等记录）

### 弯路①：`relativePathFromFilesUrl` 首版用 `new URL(url)` 无 base → 打挂 8 个既有测试
- **当时的推理链**：直接照抄 `resources.relativePathFromFileUrl` 的实现（`new URL(url).pathname`）
  下沉到 helpers —— 认为「后端 URL 都是绝对的（rescan 写入的 `toAbsoluteFileUrl`）」。
- **为什么错**：`resolveLocalImages` 的消费方（出站图片回读）**大量传相对 `/files/...`**
  （`resolveLocalImages('/files/sub/a.png')` 是它的主用例）。不带 base 的 `new URL` 对相对路径**抛错**
  → `relativePathFromFilesUrl` 恒返 null → 该模块 8 个用例全红。
- **修法（已完整回退错误形态）**：改 `new URL(url, 'http://localhost')` —— 既支持绝对也支持相对，
  且两者都自动剥 `?#`。前端 `fileNameFromUrl` 同样加 base（对称）。
- **教训**：**下沉原语前必须看全部消费方的入参形态**，不能只看「真源那处的调用者」。

### 弯路②：规则 13 首版判据过宽 → 误报域专用表
- **当时的推理链**：任何 `\.(a|b|c)` 式的扩展名列举都算「抄真值源」。
- **为什么错**：`director3d/App.tsx:1471` 的 `\.(glb|gltf)$` 是 **3D 模型扩展名**，
  与 `EXT_KIND`（image/video/audio/text）**零交集** —— 它不属本母体，误报会让闸变成假守卫
  （「闸拦住了它不该拦的」= 心法 §零.4 闸成本守恒被破坏）。
- **修法**：加 `EXT_KIND_MEMBERS` 交集判定 —— 列举里须命中真值源成员 ≥2 个才算违规；
  并加**反例探针**（注入 `glb|gltf` → 期待闸**仍绿**）证明「没放过头」。
- **教训**：**反向判据也会过宽**；宣称「反向判据」不等于「判据正确」，必须配反例探针。

### 弯路④：读上游文档时发现**两轮判定互相矛盾**（非债 vs 债），差点按「更新的那份」草率采信
- **当时的推理链**：`08-localTool后端ext-kind真值源分裂横推` 的补遗判 `lovart_attachments` **非债**
  （理由「文件头明承照抄 main.py 1:1 镜像 ⇒ 外部对齐」）；而 `08-跨区-lovart附件...` 判其为**债**（TD-08-22）。
  两份同一天、结论相反 → 直觉是「取时间较晚的那份」或「以已登记债为准」。
- **为什么这样想是错的**：两者都是「描述」，而铁律说**任何描述（含债登记）都是线索**。
  正确做法是**用证据自行裁定**，不是看谁更新/谁已登记。于是写复核脚本实测：
  `audio/aac`/`ogg`/`flac`/`wma`/`opus` → 全 `.mp3`；`video/mpeg` → `.mp3`；`image/avif`/`svg` → `.png`。
  ⇒ **客观缺陷真实存在**，「非债」判定错误。
- **为什么「外部对齐」这个理由不成立**：「照抄 main」是真的，但**照抄了一个有缺陷的实现 ≠ 有意设计**。
  「外部对齐」只在**该行为本身正确**时才构成豁免；否则它只是**把 bug 的来源从本仓搬到 upstream**。
- **修法**：收口代码 + **按 A7 就地回改**那份错误的「非债」判定（留痕对比，而非只在本文档记修正表）。
- **教训**：**判定冲突时，唯一裁判是取证，不是时间戳或已登记状态**。

### 弯路⑤（更早）：`extFromMime` 首版只 split `;` 未剥 `data:` 前缀 → 静默回退 png
- **当时的推理链**：`mimeToExt(mime.split(';')[0].trim())` —— 以为入参是裸 MIME。
- **为什么错**：`bytesFromDataUrl` 传进来的是**完整 header 段**（`data:image/jpeg`），带 `data:` 前缀；
  `mimeToExt('data:image/jpeg')` 查表**恒 null** → 全部回退 `'png'`（**比原实现更糟**：连 png 都对不了了）。
- **怎么发现的**：新增的 4 个行为测试**全红**（`image/jpeg → .png`）—— 这正是「测试服务于是我改对了什么」
  而非「我猜对了吗」的价值：它当场抓住了一个我引入的回归。
- **修法**：`mime.replace(/^data:/i, '').split(';')[0].trim()`（先剥前缀再剥参数）。
- **教训**：**下沉/委托原语前，必须确认入参的**真实**形态**（含前缀、参数），不能凭「看名字像裸 MIME」假设。

### 弯路⑥：把 TD-08-19 判成「遗留」——理由在本轮内就被自己推翻了
- **当时的推理链**：TD-08-19（跨栈常量双写）要加机器对账，而对账需闸脚本**读 `localTool/` 源码**，
  而 `check-arch` 当时只扫 `src/` ⇒ 「超出本闸范围」→ 记遗留。
- **为什么错**：我在**同一轮内**为了防后端复发（TD-08-22）就把 `check-arch` 扩成会扫 `localTool/src` 了。
  ⇒ **写下那个理由时它已经失效**。判「遗留」等于**用一个自己刚拆掉的约束当借口**。
- **修法**：按 Step 1 重新求证 → 代码不改（双写是跨构建的结构必然）→ 补规则 14「跨栈契约常量对账」→ 结清。
- **教训**：**「超出范围」这类理由要写清"范围是什么"，并在收尾时回读一遍** ——
  否则它只是把「我不想做」包装成「做不了」（与偷懒判据 §零.5 同类）。

### 弯路③：`helpers.ts` 一度加了 `path` import 的「保留位」`void path;`
- **当时的推理链**：`fileNameFromUrl` 取代了 `path.basename`，担心删 import 影响未来。
- **为什么错**：这正是本仓明令的 **M6 幽灵预留**（「为将来铺路」的零消费者代码）+ 死代码信号；
  且 `old_str` 未唯一导致一次编辑失败。
- **修法**：直接删 `path` import 与 `void path;`（不留尾巴）。
- **教训**：**「以后可能会用」不构成保留理由**（铁律 5）。
