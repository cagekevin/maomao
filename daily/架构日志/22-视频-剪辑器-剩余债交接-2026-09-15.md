## 四、本会话踩过的坑（直接复用，别重踩）

1. **闸类代码最危险的失败是"静默少扫"**：新建「扫目录型」规则后，**第一件事看"已扫描 N"是不是 0**
   （我今天把路径前缀写重了一次，闸照样打印 ✅ 通过）。
2. **`probe.mjs --find` 不要传含 `< > { }` 的串**（会被 shell 吃掉，报"0 处匹配"但文件里明明有）
   ⇒ 选**只含字母数字连字符**的唯一锚点。
3. **`--expect-out` 必须取自实际输出**：vitest 对 `toBe` 有时用 **diff 格式**（`- 4` / `+ 0`）而非
   `expected X to be Y`（我因此猜错两次）⇒ 稳妥用 `AssertionError`。
4. **测试拿不到数据时，先查"被测路径有没有被走到"**（加一轮临时 `console.log` 就看清），
   别顺着现状改断言 —— 那会造出"永远绿、什么都不校验"的假测试。
5. **`vi.mock` 工厂提升会打坏整个模块的 import 绑定**，表现极具误导性（所有 import 都 `not defined`）
   ⇒ 优先**给依赖加注入点**（样本：`TransformV1ToV2Options.loadLegacyTracks`，见 `veMigrationDefaults.test.ts`）。
6. **构造 fixture 前先读"入场守卫"**（如 `transformTextTrack` 的 `element.type !== 'text'` 会**静默丢弃**元素）。
7. **"0 命中"的下一步是查 git 历史**，不是换关键词重搜
   （`git log --all --name-only --diff-filter=AD | grep <文件>` 一句就能看出"曾存在、何时被删"）。
8. **工具输出与文档记载不一致时，先怀疑记载**（工具会跑，文档不会）—— 今天正是 `refs` 报 2 处、
