## §二 · 溯源（谁产生 → 谁消费 → 落哪）

- **产生**：`MediaManager.addMediaAsset` / `loadProjectMedia` / `setAssets` 维护 `assets: MediaAsset[]`（`media-manager.ts:11/29/89/140`）。
- **消费**：`timeline-element.tsx` `ElementContent` 按 `element.mediaId` 查 `mediaAssets`（:98-103）决定片段视觉。
- **落哪**：`MediaAsset` 形状 = `file: File` + `url?`（`types/assets.ts:5-8`）；持久化形 `MediaAssetData`（`engine/services/storage/types.ts:15-29`）只有 `url?`/`thumbnailUrl?` 可选，**无任何 availability/status 字段**。
- **失败路径**：`loadProjectMedia` catch 仅 `logger.error`（:91-92），`this.assets` 保持为空或旧值 → 时间轴元素仍带旧 `mediaId` 引用 → 渲染成 `!mediaAsset` 空白（与 TD-22-43 同根，但 TD-22-43 范围是"加载层静默空面板"，本债是"时间轴渲染层空白"，表面不同）。

## §三 · 定海（不变式 / 红线）

- **期望不变式**：时间轴片段引用的素材"找不到 / 源不可用"时，应渲染明确的"缺失 / 断链"指示（红框 + 图标 + 名称），让用户能区分"缺失素材片段"与"正常空片段"。
- **现状**：该不变式被违反——所有"源不可用"分支坍缩为仅显示 `element.name` 的小字或留白画布，视觉上即"一片空白"。
- **红线冲突**：无。不涉及端口 `18080` / `{code,data}` 契约 / 存储键登记表等 CLAUDE 级红线。

# 收口（2026-09-15 · TD-22-48 结清）

## 一、按当天代码重新取证（原日志行号已漂）

| 原文记载 | 当天实测 |
| --- | --- |
| 坍缩点在 `timeline-element.tsx:426-431/454/469` | ✅ 同一组分支，现位于 **`:426 / :433 / :475`** |
| "Audio unavailable" 先例在 `audio-waveform.tsx:138` | ✅ 现位于 **`:137-146`** |

**3 个坍缩点**（各自 `return <span className="text-foreground/80 truncate text-xs">{element.name}</span>`）：
1. audio 无解码缓冲且无 `url`
2. `!mediaAsset`（mediaId 断链）
3. video 有 asset 但 `file` 缺 / image 有 asset 但 `url` 缺（兜底）

## 二、施工（3 个文件 + 1 新组件）

**新增 `missing-media-indicator.tsx`** —— 时间轴**唯一**的"素材不可用"表达：
虚线红框 + `AlertTriangle` + 原因文案（`role="alert"`，与仓内 `ui/alert.tsx` 同惯例）。

**关键设计：按"补救动作"分两种 `kind`**，而不是笼统一句"不可用"：

| kind | 场景 | 用户该做什么 |
| --- | --- | --- |
| `missing-asset` | 素材**记录**都不在了（被删 / 加载失败 / 切项目重置） | **重新导入** |
| `source-unavailable` | 记录在、**源取不到**（本地服务未起 / 文件丢失） | **查本地服务 / 重新上传** |

两种故障混成一句 = 用户不知道下一步做什么。

| 位置 | 改动 |
| --- | --- |
| `timeline-element.tsx` | 3 个坍缩点 → `<MissingMediaIndicator …>`（1 处 `missing-asset` + 2 处 `source-unavailable`） |
| `audio-waveform.tsx` | error 态改用同一组件（**消灭"同一种失败两种说法"**：它原本是本文件独有的英文 `Audio unavailable`） |

## 四、弯路留痕（强制）

**① `probe.mjs --find` 传含 `< > { }` 的串会被 shell 吃掉。**
第一版探针写 `--find '<MissingMediaIndicator kind="missing-asset" name={element.name} />'`，
工具报"0 处匹配"（文件里明明就是这一行）。改用**无特殊字符的锚点**（`missing-asset`）后正常。
→ 教训：**探针的注入点要选"只含字母数字连字符"的唯一串**；含 JSX/引号/花括号的串交给 shell 会变形。

**② 探针第一次"未命中"暴露了守卫盲区（真收获）。**
第一版守卫只数「指示块出现 3 次」—— 于是"把 `missing-asset` 写成别的 kind"能让探针**全绿通过**，
即"两种缺失被说成同一种"这个**本债要消灭的缺陷**反而逃过守卫。
补上 `kind="missing-asset"` 恰 1 次 / `kind="source-unavailable"` 恰 2 次 的断言后才红。
→ 教训：**"数量对"不等于"内容对"** —— 计数型守卫要配一份"分布型"守卫。

**③ 断言串误伤注释。**
`expect(waveformSrc).not.toContain('Audio unavailable')` 一开始红：文件里**注释**还留着
"此前是本文件独有的英文 Audio unavailable"。改成断言 JSX 文本 `'>Audio unavailable<'` 才对。
→ 教训：源码扫描型断言**要锚在语法结构上**（`>…<`），不要锚在自然语言片段上。

**④ 仓内没有 `@testing-library/jest-dom`**（`toHaveTextContent` 不存在）。
改用原生 `expect(el.textContent ?? '').toContain(...)`。**不要引新依赖**（既有 .tsx 测试都这么写）。
