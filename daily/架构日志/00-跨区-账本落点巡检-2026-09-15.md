## 二、判据与刻意划定的误报边界

```js
const LIVENESS_FILE_RE = /`([A-Za-z0-9_][\w./-]*\.(?:tsx?|jsx?|mjs|cjs))(?::[\d\-–、]+)?`/g;
```

| 决定 | 理由 |
| --- | --- |
| 只认**反引号包裹**的 token | 反引号 = 作者在**指代一个具体文件**；裸写的 `xxx.ts` 常是泛指/举例 |
| 只按 **basename** 在仓库里找 | 债描述里的路径常省略 `src/components/...` 前缀（`composite.ts:108`），按全路径匹配会大面积误报 |
| 带行号后缀**忽略**行号（`composite.ts:108` → `composite.ts`） | 行号会随改动漂移，不该参与存在性判断 |
| **只报告、不改状态** | 落点消失有两种成因：① 真随重构/计划改道消失（该结清）；② 描述笔误（该改描述）。处置不同 ⇒ 必须人判 |
| 默认**不开**，须 `--liveness` | `audit` 要能秒回；全仓文件名遍历 + 全量正则只在该开关下付代价 |
| 扫描范围含**归档** | 归档债是"重审时的线索"，落点失效会导致误判"这债还在" |

## 五、弯路留痕（强制）

**① 第一版探针自己写错了 —— 而且错得"很对"。**
我注入 `probe/nonexistent-file.ts` 时**没加反引号**，探针报"未命中"。
第一反应容易是"工具坏了 / 正则太严"，但真因是：**正则会刻意放过裸写的文件名**（这正是 §二 定的
防误报边界）。工具行为**符合设计**，是我的探针没表达"作者在指代一个具体文件"这个语义。
→ 教训：**探针"未命中"时，先怀疑探针本身**；把边界条件写进探针，而不是放宽判据去迁就探针。

**② basename 匹配是一把双刃剑（已知边界，写下来防后人误判）。**
`types.ts` / `index.ts` 这类通用名，只要仓库里**任意一处**存在就放过 ⇒ 可能漏报"这个 `types.ts`
指的是已删的那个"。代价可接受（漏报 > 误报到让人不再看报告），但**它不是"路径级"校验**，
将来若要做路径级，须先解决"债描述普遍省略前缀"这个现实。
