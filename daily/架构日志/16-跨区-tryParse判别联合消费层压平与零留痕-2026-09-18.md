## 二 · 溯源（取证）

### 2.1 生产者侧：确认 `tryParse` 已诚实（证毕）

`asyncGuard.ts:252-264`：

```ts
export function tryParse<T>(parser: () => T): ParseResult<T> {
  try { return { ok: true, value: parser() }; }
  catch (err) { return { ok: false, error: err }; }   // ← 失败携带原始 err
}
```

- 判别联合 `ParseResult<T> = {ok:true,value} | {ok:false,error}`（`:232`）—— 调用方**必须判 `ok`** 才能读 `value`，写错编译不过。✅ 生产者诚实。
- 生产者**故意不打日志**（`:256-260`，两条理由：① `logger → core/utils → asyncGuard` 会成环；② 判别联合已消除静默，留痕应由消费者按"读者"决定）。**这个职责划分本身成立**，故**不把"tryParse 不打日志"记为债**。
- ⇒ 债面**整个落在消费层**。

### 2.4 类型诚实性（主题锚 09 · 病区归 18）

> **归档说明**：本笔主题属 09「类型诚实性」，但病灶文件 `base/core/utils.ts` 按本仓分区归 **18 core 横切基础设施**（前轮 TD-18-4 / TD-18-6 同文件、同为 18 区可证）。

`core/utils.ts:112-114`：

```ts
export function deepClone<T>(value: T): T {
  return (value === undefined ? undefined : JSON.parse(JSON.stringify(value))) as T;
}
```

- 签名承诺 `T`，实现是 **JSON 深拷贝**：丢 `undefined` 字段（`{a:undefined}` → `{}`）、函数丢弃、`Date`→`string`、`Map/Set`→`{}`、循环引用**抛 TypeError**。

- 守卫形态是**注释**（`:111`「含函数/Date/循环引用者请勿用」）⇒ 无机器守卫 = 假护栏。
- 消费点：`director3d/project.ts:28`（`cloneProjectValue` re-export）· `clipboard.ts:322`。

## 六 · 结论

1. **母体检出并坐实**：`tryParse` 是「生产者已诚实、消费者错位」的**样板**。收口做了一半（TD-16-36 只动签名），**诚实性在最后一跳被抹掉**。一个修复（消费层统一留痕口径）可全消 12 处 ⇒ 母体成立，不碎片化登记。
2. **判据沿用仓内自述**（`drag-data.ts:64-66`）：**压平可以，不留痕不行**。本轮全部 4 笔均以此为尺。
