# 跨区 · ADR 判据体检：相互矛盾 / 会让架构变差的条目（2026-09-20）

> **范围**：`docs/adr/` 全 45 条（现行 36 · 已退出 9），逐条读全文，两两比对判据、决议与「📌 违反时的判据」。
> **触发**：用户提问「有没有会让架构变差的，或者相互矛盾的」。
> **性质**：本文件是**体检报告**（过程与证据），不是判据 —— 判据落点见每条「修法」。

## 零 · 先说最要紧的一件事

```
node scripts/adr.mjs audit    → 问题 0 项
node scripts/adr.mjs hygiene  → 空壳 0 · 近义簇 0（只有"未毕业 36/36""今日新增 3"两条预警）
```

**全绿，但下面有 8 处矛盾、5 处会让架构变差。** 这不是工具坏了，是 `audit` 的**职责边界**问题：

| `audit` 查的 | `audit` **不**查的 |
| --- | --- |
| 形式一致性：空壳 / 缺必填节 / 状态与「被取代于/毕业去向」自洽 / 结论近义 / 正文 ≤80 行 | **判据之间的横向一致性**：① 引用的 `ADR-NNNN` 是否还存在 ② 两条 ADR 对**同一现状**是否给出相反判定 ③ A 收窄了 B 的适用范围而 B 没有指针 |

⇒ 母体同款：**「闸绿」不等于「没问题」，它只等于「闸检查的那几项没问题」**（ADR-0041 M2 的原话）。
本轮 13 条发现里，**至少 3 条是可以机器判定的**（见 §三），且都能用负例探针证明会红 —— 按 ADR-0041 M1/M2 应当补上。

## 一 · 相互矛盾（8 条 · 按杀伤力排序）

### M1 · ADR-0039 N5 ↔ ADR-0044 §7：**对"域门面"给出相反判定，且 0039 的机器判据会误报**

| | ADR-0039（生效） | ADR-0044（生效 · 2026-09-20 后立） |
| --- | --- | --- |
| 规则 | **N5**：域目录**必须有** `index.ts` 门面；跨域**只准**走门面（`0039:38`） | **§7**：域门面 = **域级装配入口**；域内每个能力片**各有自己的门面**；**禁止**把能力片并集进域门面；横切消费者（`base/`·`src/hooks/`）**只依赖能力片门面**（`0044:31`） |
| 对"域根没有 index.ts" | 违规 | 正常 |
| 0044 §3 的自述 | —— | 「ADR-0039 N5 约束的是"域对外出口唯一"，**不约束域内层级**」（`0044:19`） |

**实测（2026-09-20）**：现存域里只有 `agent` / `canvas` / `creative` / `video` 有域根 `index.ts`；
`settings` / `image` / `text` / `task` / `generate` / `resource` / `prompt` / `scriptbox` / `director3d` / `videoEditor` **都没有**。

**原样执行 0039 的机器判据②**（`0039:58`）—— 输出 6 行「缺门面」：

```
缺门面:videoEditor  缺门面:scriptbox  缺门面:director3d
缺门面:nodes        缺门面:edges      缺门面:panels
```

- 后三个（`nodes` / `edges` / `panels`）**目录已不存在**（域归位后迁入各域，如 `src/components/image/nodes/`）⇒ 判据在**报幽灵违规**。
- 前三个真缺门面 ⇒ 但按 0044 §7 是**正常**的。
- **判据③**（`0039:60`）会把 0044 §7 **要求**的"横切层只依赖能力片门面"判成"跨域绕过门面"违规。

**讽刺点**：0039 §背景（`0039:11-14`）批判"旧前缀表仍是**目录轴**时代的产物"，而它自己的机器判据② 用的正是**已过期的目录清单**。

**修法**：
1. N5 收窄为「跨域只准走**门面**（域门面**或**能力片门面）」；回改判据②③（②改成从**实测存在的域目录**生成，不写死清单）。
2. 0044 §7 举的范本 `settings/index.ts` **该文件不存在**（`settings/` 根是 5 个散件 + `sections/`）⇒ 换成真实存在的范本。

### M2 · ADR-0041 M1 ↔ ADR-0046：**"写不出检查 ⇒ 该规则不成立" vs 本仓自认"有些判据就是没有机器防线"**

- **0041 M1**（`0041:39`）：每条结构规则**必须附检查命令**，**写不出 ⇒ 该规则不成立**（是声明，不是判据）。
- **0046 §决议4**（`0046:47`）：每个子判据必须给出一条 grep / tsc / 闸 级检查方式，**"否则它没有防线（ADR-0041）"**。
- **0046 §后果**（`0046:61-62`）：紧接着自认 —— **「本条第 3 项没有机器防线」**，并写明「**硬凑的 grep 会把"说这条规矩的句子"自己也抓进去（假防线比无防线更坏）**」。

⇒ 同一份文件里，前一段要求"没检查 = 没防线"，后一段说"这里就是没有，而且硬凑更坏"。**两句直接对撞。**

**按 M1 字面清算现行集**：至少这 9 条明写"无机器判据 / 不建闸 / 只靠纪律 / 尚未毕业"⇒ 全部"不成立"：
`0002`（不加机器闸）· `0006`（只靠纪律）· `0008`（尚未毕业）· `0009`（无机器闸）· `0011`（机器：无）·
`0025`（不建闸）· `0031`（机器：无）· `0032`（机器：无）· `0046`（自己）。

**而这 9 条恰恰是本仓最有价值的判据**（0025 内容落点、0046 让 AI 不猜、0011 禁静默吞）。

**与 ADR-0016 也冲突**：0016 的手段优先级把「**文档留痕**」列为**合法层**（第 5 位，高于机器闸），M1 不承认这一层。

**为什么这条会让架构变差**（见 §二 D1）：它把"规则合不合理"降级为"能不能写成 grep"，净效果是**逼出假防线** + **反向淘汰语义判据**。

**修法**：M1 收窄为 —— 「必须**先答**『这条规则能不能机器判定』：能 ⇒ 写检查 + 负例探针（M2）；**不能 ⇒ 必须写明"不能"，并给出人工判据与落点**」。
这正是 0046 已经做对的形态（它自己承认没有、并说明为什么不硬凑），把它写回 M1 即可。

### M3 · ADR-0030 ↔ ADR-0047：**"fan-in=0 ⇒ 删" 与 "refs 报 0 单独不算证据" 不一致，且 0030 未回改**

| | ADR-0030（生效） | ADR-0047（生效 · 用户裁定 · 2026-09-20） |
| --- | --- | --- |
| 判据 | **看 fan-in**（`0030:21`） | **多口径一致报零**；`refs` 报 0 **单独不成立**（`0047:4`） |
| 处置 | fan-in=0 ⇒ **删**，且**不许补消费方**（`0030:34`） | 查不清 ⇒ **不许删，改为修**；**默认动作是「修对」**（`0047:36`） |
| 举证 | —— | **举证责任在"删"这一方**（`0047:36`） |

**0047 正文点名了 0030**：「盲区下的 0 会直接诱导删活代码（**ADR-0030 的删码判据就是 fan-in**）」（`0047:29`），
并给出该工具的两次真实盲区（`@/…` 别名 import 被静默丢弃 · 仓库根级件不在扫描根）。

**但 0030 的结论句与判据段没有任何指针** ⇒ 只读 0030 的人仍会拿一个 0 直接删 —— 这正是 0047 要堵的路径。

**修法**：0030 头部加一行指针（本仓先例 = 0032 对 0011 的处理：**正文冻结、只改头部/加指针**）：判据改为「**多口径一致**零消费」。

## 二 · 会让架构变差的（5 条）

### D1 · ADR-0041 M1 —— **用"可测量"冒充"正确"**（元层，杀伤最大）

M1 的净效果有三个，全部是**反方向**的：

1. **逼出假防线** —— 0046 已自证（"硬凑的 grep 会把讲这条规矩的句子也抓进去"）。这正是本仓最贵的教训（形态④）。
2. **反向淘汰好判据** —— 0025（内容落点）、0046 判据3（"须推断"）**根本写不成 grep**，按 M1 应当"不成立"。它们是本仓最有价值的判据。
3. **与 0046 的手段相反** —— 0046 说落点四选一（**目录 / 类型层 / 唯一入口 / 删**），核心是"让误用**写不出来**"；M1 的落点是"**写个 grep**"。grep 是**声明**，不是**结构** —— 正是 0046 要禁的"停在文档层"。

**修法**：见 M2 的修法（M1 加"不能机器判定"这一合法出口）。

---

### D2 · ADR-0030「fan-in=0 ⇒ 删；**不许补消费方**」—— 后半句会**奖励内联实现、淘汰新地基**

`fan-in=0` 有两种成因，0030 当成同一件事：

| 成因 | 正确处置 |
| --- | --- |
| ① 幽灵预留（为设想的消费方先建） | **删** ✅ 0030 对 |
| ② **接缝没接上**（消费方本该改道、还没改） | **让消费方改道**（这正是 ADR-0045「摆正依赖方向」要求的动作） |

而 0030 §决议2（`0030:36`）**无条件**规定：「同一件事已有一份在用的实现时，收口方向 = **保留在用的那份**、删掉没接上的那份」。
它举的两例（`audioPeaks` vs 内联 `extractPeaks`；`rulerTicks` vs 引擎 `ruler-utils`）**正是"抽出来的地基 vs 内联实现"**——
0030 一律选**内联**。而本仓另外两条现行判据方向相反：

- **ADR-0045**：修结构只有一条合法路径 —— **消除依赖倒置**，"**禁止**新增中转模块 / 裁剪门面出口来绕开"；
- **ADR-0042 D5**：新建能力**默认按深模块形态设计**，先答"谁在它边界之外用它"。

**与 0042 合起来的净效果** = "先建能力片、建完没人用就删" ⇒ **域内深构（Stage 2）寸步难行**：
能力片天然是"先抽出来、再让消费者改道"，而 0030 把"改道"叫"补消费方"并**禁止**。

**修法**：
1. 处置加一档：`fan-in=0` **且**同一能力已有在用实现 ⇒ **先按 0042/0045 判哪一份是正确形态**，再决定删哪一份；**不得默认保留内联那份**。
2. 「不许补消费方」收窄为：「不许为**设想的**消费方补；**已存在的消费方改道不算补**」。

### D3 · ADR-0011「不可恢复 + 禁标记 + 只靠判据守」—— **洞在"存量标记的处置"没人写**

- 0011 §后果自认（`0011:47`）：**「禁静默吞退回只写在注释与判据层（无机器守卫）→ 回潮成本低，是新登记债的高发形态」** ——
  即"已知防线不存在，且禁止重建任何形式"。
- **实测**：`src` 里 `catch-ok` 注释**存量 43 处**，**全部无机器校验**。
- ⇒ 它们从"假防线"变成"**纯装饰**"：后人看到满仓 `catch-ok:` 会以为**有机制在管**；而 0032 记录的事故是相反的误读（9 处 `catch-ok: BROWSER_API` 被当**违规**登记）。
  **同一批注释，同时支撑"有机制"与"有违规"两种错误结论。**
- 0011 §决议只说 `// catch-ok:` 仍可写，**没有说存量 43 处怎么办**（保留？删？改写成理由注释？）。

**修法**：不必恢复闸（0016 已论证删得对）。补两条即可：
1. **存量标记处置判据**（留 / 删 / 改写三选一，写明理由）；
2. 一条 grep 对账：**数量只能降不能升**（新增即违规）—— 成本极低，且能真红。

### D4 · ADR-0039 N1「域专用导出带域前缀」—— **把命名钉在最不稳定的东西上**

- 0039 §判据2（`0039:24`）：前缀**不另起词表**，**域清单真源 = `spec/DATAFLOW.md` 的链路**。
- 而 0042 §判据2（`0042:21`）自己说：**「域是地理边界且**仍会演化**，能力边界比域边界稳定」**。
- ⇒ 用**会演化的边界**当**符号名**的判据 = 每次域调整都要改符号；而改名又受 0038（运行时字符串冻结）约束
  ⇒ 产生**永久性的符号／键双词汇表**（0038 §后果自认"读者会误以为忘了改"），
  且**没有任何检查能区分"这处不一致是故意的还是漏改的"**（正命中 0046 信号①）。
- **判据本体与边界分家**：N1 的**判据句**写的是"带前缀"，而"**一律加前缀是误读**"只写在 §判据6 的**反证**与 §后果的**提醒**里。
  本仓自己立过条治这个：0016「**提示 ≠ 拦住**，提示是文案，检查才是防线」、0046 信号③「只写禁止、不写替代」。

**修法**：把 N1 的判据句改成「**域专用导出必须能唯一归属到域**（手段：**撞名时**加域名原词前缀；域内已唯一者**不加**）」——
即把判据 6 的反证**升进决议本体**，而不是留在后果段。

### D5 · ADR-0033「禁止裸写魔法数字」—— **缺"什么算魔法数字"的判据，且自带一条长期常红的判据**

- §判据3 的边界是"**含义不明**的裸数字（超时/阈值/上限）"（`0033:64`）—— **主观量词**（0046 信号②），不可判定
  ⇒ 实际执行会滑向"所有字面量都要命名常量"（本仓另有 0042 D2「行数不作判据」、0036「算/转换归工具层」在反方向）。
- §违反判据1（`0033:62`）：`grep import.meta.env src` 命中文件 **> 1 即违规** ——
  而 ADR 自己承认**存量 4 处违反未清**（`0033:55`）⇒ **这条判据按定义长期常红** ⇒ 警告疲劳（形态②：跑了但没人看）。

**修法**：
1. 给出**可判定**边界（如：**跨模块复用 / 参与判据比较 / 与外部契约对齐**的数字才算；单文件局部常量不算）。
2. 把判据 1 拆成「**新增**违规为 0（存量另立债）」—— 让它在存量清完前不常红。
