## 二、施工（三步，每步验证）

### Step A · 抽原语（零风险）
新增 `src/components/base/store/generationContract.ts`：`runGenerationContract(args)` —— 纯 TS，无 React。
覆盖序列：`reportGenerate → progress(5,'准备中…') → run → localize?(降级保留原 URL) → settle(显示URL) → saveResultToTasks(失败降级不判败) → onPersisted(持久URL) → done(最终URL)` + 失败三分支（业务 fail / abort / 异常，均 classifyError 分级 + 落日志）。
**接口窄**：调用方只提供 `run` + 三个回调（`localize/settle/onPersisted`）+ 两个落点（`onFail/onAbort`）。
配套 **10 例单测**（含 R3 顺序断言：`['settle','save','onPersisted','done']`）。

### Step B · 剧本盒资产图接入
`onGenerateAssetImage` 的**手写 5 步**（report→progress→generateImage→localize→commit→saveResultToTasks→done/fail + `taskSettled` 防御）整体替换为一次 `runGenerationContract(...)` 调用；引擎侧只留 loading 状态与两个回调。
连带清理：`reportGenerate` / `saveResultToTasks` / `reportDegrade` 三个 import 变死 → 删除。

### Step D · 节点侧接入
`useNodeGeneration.start` 的编排段（原 ~105 行）替换为 `runGenerationContract(...)`；hook 保留 React 专属：`claimNodeRun` 互斥 / `runningRef` 防重 / `validate` / `nodeRuntime` loading / `AbortController` / `finally` 释放。
`settle` = 原「resultKey 自动 patchData + onSuccess 特化」，`onPersisted` = 原「持久 URL 覆盖写回」→ **顺序与语义逐一对齐**。
