### 3.1 归属判定依据（为什么是业务债不是结构债）

- 五问套用：同一真相是否抄多份？否。绕过唯一入口？否（代码调的是正确的接口，只是接口背后无服务）。静默吞错？**是**（`sounds.tsx:131` `catch` 只 `logger.error` 不提示用户"服务不可用" → 用户只看到空白，无法区分"真没资源"vs"后端挂了"）—— 但这是**表层症状**，根因是后端缺失，不是前端吞错。
- 改对外契约 / 引重依赖 / 接外部服务 = 业务债定义命中 → 归 `业务债 · 待用户拍板`。
- 音乐 tab 死占位 = 已知未实现功能（与 `assets/index.tsx` 的 `effects/filters/coming soon` 同类）→ **非债**，不登记。

### 3.2 用户拍板选项（业务债必附 A/B/C + 推荐项）

- **A（推荐 · 自建轻量音效/贴纸服务）**：在 `localTool` 加 `/api/sounds` 路由（代理 Freesound 或内置音效包）+ 在 vite `server.proxy` 加 iconify 转发；音乐 tab 接同一服务或本地曲库。优点：工程内闭环、可控、离线可用。
- **B（直连第三方公共 API）**：音效直连 Freesound 公开 API（需 API key）；iconify 维持公网直连（需确认网络可达）；音乐接公开曲库 API。优点：零后端开发。缺点：依赖外网 / key / 速率限制 / 跨域。
- **C（内置本地素材包）**：把贴纸（iconify 子集）/ 音效（打包 wav/mp3）/ 音乐（打包曲目）作为静态资源随工程发布，前端改读 `/public/...`。优点：完全离线、无后端。缺点：体积大、需准备资源文件。

## 六、结论

- 本次"空"的根因 = **搬项目只搬了前端，漏带对方的后端数据源 / 外部服务接入**（音效后端 + iconify 代理 + 音乐服务）。属接入缺失，**非代码架构债**。
- 登记一笔业务债 **TD-22-47**（高息 · 待用户拍板），附 A/B/C 三方案（推荐 A 自建轻量服务）。
- 音乐 tab 死占位 = 已知未实现功能 → 非债（与 `coming soon` 同类）。
- 贴纸能否工作取决于公网是否可达 `api.iconify.design`：可达则本身可用（TD-22-47 仅条件命中）；不可达则需随 A/B/C 一并补代理。
- 本流程不改码；修复交用户拍板后由决策架构师统一接入。DATAFLOW §十 面板节点灯随本轮结论更新（见收口）。
