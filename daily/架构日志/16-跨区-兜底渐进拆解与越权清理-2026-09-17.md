## 一 · 正确形态（一屏 · 施工前先写下来）

**唯一判据**：**谁拥有真相，失败语义就定义在谁那；消费者只消费，不重定义。**

| 位置 | 是所有者还是消费者 | 正确动作 |
| --- | --- | --- |
| `contentStore` 的 `contentGet/GetAsync` | **所有者**（存储真相源） | 已定型：**失败 = throw**（只对契约违约抛，须 fail-fast） |
| `storageAdapter.sGet` / `asyncGuard.*` 原语 | **所有者**（环境/边界真相源） | 定义「读不到 → null」「释放失败 → 吞」；豁免收口在**原语内部**一处 |
| `appSettings` / `promptManager` / `backupStore` / `cloudSync` / `agentModelStore` / `AgentPanel` … | **消费者** | **删掉自己的 catch**（`contentGet` 对已登记键不抛 → catch 不可达，纯属越权 + 掩盖契约违约） |
| `volumePolicy` / `storageQuota` / `assetUrl` 的估算函数 | **所有者**（估算真相源） | 兜底方向必须**朝保守侧**（估算失败 → 按"超预算/不可信"处理 + 留痕） |

**手写 `catch-ok` 的处理判据**（本轮新增，写给下一个人）：

| 形态 | 判据 | 动作 |
| --- | --- | --- |
| catch 体**非空**却仍贴标记 | 标记已退化成「备注」（`catchOk.ts` 头注释已批过） | **删标记** |

## 二 · 弯路留痕（**强制** · 本轮唯一弯路，思路极有道理，后人极易重走）

### 2.1 我做了什么

按 TD-16-32 的登记（"seek 赋值失败 → 静默 `draw()` 当前帧 = 产假帧"），我把
`captureFrame.ts:200-204` 改成 **fail-loud**（`fail(...)` 直接 reject），理由是"不能产出时间点错误的假帧"。

### 2.2 为什么它是错的（反向探针命中）

跑相关测试 → **既有单测变红**，两处：

```
× currentTime 赋值抛异常 + 尺寸可用 → 直接绘制当前帧（catch → draw，不是静默失败）
    → seek not allowed
× currentTime 抛异常 + 尺寸为 0 → 以 dimensions 拒绝（缺口证据：无"就绪但 0 尺寸"防御）
    → expected 'captureFrame: zero dimensions' but got 'seek not allowed'
```

关键取证（`tests/unit/captureFrame.test.ts:273-301`）：**单测明确断言 `catch → draw`**，且测试名写着
「**不是静默失败**」⇒ "seek 失败降级绘制当前帧"是**被测试锁定的契约**，不是遗漏的兜底。

**⇒ TD-16-32 的登记本身失真**：它写"本文件头与单测均自述『失败即 reject，不产出假帧』"——
单测**恰恰相反**。我把**契约**当**债**改了。

### 2.3 处置与教训

- **完整回退** fail-loud 改法；改为**行为不动 + 补留痕**（`logger.warn`，见 §三 C 类），测试恢复绿（21 passed）。
- **教训（写进本文件，防后人重走）**：
  > **`测试红 ≠ 测试错；测试红 = 既有语义被破坏`**（7 步法 §7.1 反向探针）。
  > 当"债的登记"与"既有测试的断言"冲突时，**默认测试是对的** —— 因为测试是**可执行契约**，
  > 而账本描述只是**线索**（可能失真，本轮实证）。
  > 改契约（a.k.a. 让抽帧"可能失败"）属**用户可感知的行为变化** → 必须走 Step 5 交用户，不得架构师自定。
- 假绿测试检查：**无**新增测试被撤销（本轮唯一新增断言在 `accountsStore.test.ts`，是真实契约）。

## 七 · 第二批：Promise Catch 禁止项落地（闸判据面扩展）

> **触发**：用户给出「TS+React 异步 Catch 禁止项」清单，要求**写成机器禁止项**（不是文档口号）。
> **六条逐条过了「能不能机器判定且不误伤」**——按「建闸前置评审」的举证责任在"建"这一方：

| 用户禁止项 | 机器判定？ | 落法 |
| --- | --- | --- |
| ① 禁止空 catch（`.catch(()=>{})` / `.catch(e=>{})`） | ✅ | **扩闸**：原只认**无参** `()` 箭头 → 现覆盖 `()` / `(e)` / `(e,x)` / `e` |
| ② catch 内必须留痕（不可静默丢弃） | ✅ | **扩闸**：`catch { return <空默认值>; }`（行内 + 跨行单语句体）= 捕获后静默换算 → 违规 |
| ③ fetch 必须校验 `!res.ok` | ⚠️ 重叠 | 本仓已禁裸 fetch（统一 `httpRequest` 唯一出口），另建判据 = 第二份真相 → 不建 |
| ④ async 事件 / useEffect 必须 try/catch | ❌ | **不建**：需数据流分析，假阳性爆炸（形态②过严闸） |
| ⑤ 禁 catch 后 `.then` 用可能 undefined 的值 | ❌ | **不建**：语义级，机器判不了 |
| ⑥ throw 必须带 `cause` | ❌ | **不建**：无法区分「重新抛出」与「新建错误」，会误伤所有 throw |
| ⑦ 业务层禁裸写 fetch | ⚠️ | 已有唯一出口 `httpRequest`（`check:arch` 面），不重复建 |

**⇒ 只落地 ①②**（可机器判定 + 零误报），其余进「不建」清单并写明理由 —— **不可机器化的禁止项写进闸只会生产假阳性**。

> **触发**：用户给出「tryParse 禁止项」判据 —— **直接命中本仓 `tryParse` 自身的设计**。
