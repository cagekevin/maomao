# 03 区 · 六轮 — TD-03-13 降级可见性（本地服务不可用不再静默）

> 日期：2026-09-13 ｜ 触发：**用户裁定「加上提示」**（问"本地服务没启动时要不要给用户一次提示"）。

---

## 一、是什么

`filesApi` 的**统一落盘策略**（`filesApi.ts:250-264` 头注）：

> 落盘只是"让图刷新不丢"的**优化**，不是"图能否显示"的**前提**。
> ① File 源先 multipart 上传；② 失败 → 读内联 dataURL 兜底；③ 都拿不到才算真失败（调用方提示一次）。

问题：**②的降级完全静默**。后果链（用户视角）：
- 本地服务（localTool :18080）没启动 → 拖入的图**照样显示**，一切正常；
- 但它只以 base64 临时存在画布快照里 → 项目变大/变卡、**换设备或清缓存后图全丢**；
- 用户**全程收不到任何提示**，直到数据没了才知道。

TD-03-13 原文定性为「设计观察（设计权衡但故障可见性被刻意弱化）」，建议"至少在生产对持久化失败加一次用户可见提示"。

## 二、落地

**复用既有统一降级入口**，不造第二套提示通道：

`base/core/degrade.ts` 的 `reportDegrade({ layer, key, e?, toast? })` —— 内置「logger.warn 留痕 + 可选**节流** toast」，本就是为"降级透明"而设的横切模块（画布 KV→localStorage 降级即走它）。

改动：
1. `filesApi.ts` 引入 `reportDegrade`；
2. 新增 `notifyLocalServiceDegrade()`：**本会话只提示一次**（`localServiceDegradeNotified` 模块级标记）——localTool 未启动是**持续性状态**，反复弹是打扰；日志每次留痕，toast 仅首次；
3. 接入**两个"确实降级为内联"的点**（精确，不在"上传失败但未降级"时误报）：
   - `resolveNodeAssetUrl`：`uploaded` 为空 → 降级内联前提示；
   - `persistInlineOrKeep`：`saved` 为空 → 保留内联时提示（`showThenPersistInline` 同受益）。
4. 文案（warning 级，非 error）：`本地服务未启动，素材已临时保存（换设备或清缓存可能丢失）`

> **为什么不用节流窗口而用"本会话一次"**：`reportDegrade` 的节流是**单槽**（`throttle.key` 会被其它降级覆盖）→ 依赖它做"本会话一次"并不可靠；故用模块级标记（刷新即重置 = 本次会话一次），语义精确。

| - | - | - |
