## 1 · 证伪与归因

**真需求。** 取证：
- 清单只有 Arial / Helvetica / Times New Roman / Georgia —— **四个全西文**，中文用户无可选；
- `fontWeight: 'normal' | 'bold'` —— **仅两档**（不是"没有"，是"只有两档"）。

**根因（母体）**：`font-constants.ts` 文件头记录过一次翻车（旧清单混 5 个 Google 字体、本仓 0 处
`@font-face` → 画布静默回落、下拉 5 项长得一样）。本轮**没有重蹈**，而是沿用它定下的纪律：
**只允许出现"用户机器上可能存在"的名字**。

## 2 · 定位（Step 3）—— 两件性质不同的事

**(a) 中文字体：不是"下载字体"，是"补通用族"**（架构师直接定，不改用户能力之外的东西）
- 判据：**中文字体在用户机器上必然存在**（OS 要显示中文）→ 属文件头纪律里「系统字体 → 直接列」那一类，**零下载**。
- **不存在跨平台同名中文字体**（macOS 苹方 / Windows 微软雅黑 / Linux 思源）⇒ `value` 用**语义名**
  （`中文黑体` / `中文宋体`），具体由 `fallback` 链解析成该机器真实存在的那款。
- 思源（Source Han Sans / Noto Sans CJK，**两个名字都列** —— Adobe 名与 Google 发行名）**只进 fallback**，
  **不单独作为可选项**（否则没装的机器上就是幽灵项）。

**(b) 字重：** 必需一并解决，否则中文字体加进来仍是"选了没反应"：
- `ctx.font` 对**字体没有的字重→静默取最近档**；
- 字重能力**随字体而异**（苹方/思源 6~7 档；Arial/微软雅黑/宋体只有 400/700）；
- ⇒ **禁止"全局 5 档"**（在微软雅黑上选 500 必然静默回落）。**档位必须由字体自己声明**。

## 4 · 弯路留痕（强制）

**弯路：首版 `previewFontFamily` 自己把 `value` 拼在链首，而 `getFontFallbackChain` 不含自身
⇒ `ctx.font` 与 CSS 预览两套口径（一含 value、一不含）。**

① 推理链：中文 `value` 是语义名，预览必须能看到中文 → 就在 CSS 侧手动把 value 拼到最前。
② 为什么错：**同一件"拼族栈"的事出现了两份实现**（一份在渲染层、一份我新写在 constants），
   必然漂移 —— 实测输出正是 `ctx.font` 缺栈首、CSS 预览有，两边不一致。
③ **顺带查出一个潜伏已久的真缺陷**：`getFontFallbackChain` 只返回 `fallback`
   （**不含 `fontFamily` 自身**）⇒ `buildFontFamilyStack` 产出**丢栈首**：
   `Arial` → `"Helvetica", "sans-serif"`（**Arial 没了**，靠 Helvetica 长得像才一直没被发现）；
   而该文件自己的 `@example` 一直写着正确的 `"Arial", "Helvetica", sans-serif`
   —— **文档与实现不一致，正是这条缺陷长期潜伏的原因**。
④ 修法：`getFontFallbackChain` 统一**把 `value` 放栈首**（真实名字与语义名同一形态），
   两处消费方（`ctx.font` / CSS 预览）**共用这一份输出**；`previewFontFamily` 不再自拼。
⑤ 未产生假绿测试（临时校验脚本已删，见 §6）。

## 5 · 未做 / 诚实边界

- **未给"每款字体分别列 6~7 档"** —— 苹方/思源确实有更多档，但**链上最弱平台（微软雅黑/宋体体系）
  只有 400/700**，声明更多档 = 在 Windows 上必然静默回落。**跨平台一致**优先于"档位数字好看"。
  将来若真引入可变字体（下载），再由 `weights` 放开。
- **未做 `queryLocalFonts()` 枚举系统字体** —— 评估见下，属**独立能力**（异步 + 权限门 +
  仅 Chromium + "拿到的名字未必能被 Canvas 渲染"，需逐条 `document.fonts.check()` 实测过滤），
  要单独一轮，且属业务决策（本次用户未点）。
- **未改斜体/下划线** —— 本轮目标只有字体与字重。
