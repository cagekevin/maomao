## 一、TD-02-21：模式匹配结构性重复 → 抽单一实现

**现场**：`findPatternEntry` 与 `isKvPatternKey` **逐字重复**（同遍历 KEYS + compilePatternRegex + 同坏正则吞），仅差 `backend !== 'kv'` 过滤。

**修复**：抽 `matchPatternEntry(key, predicate?)` 单一实现：

```ts
function matchPatternEntry(key, predicate?) {
  for (const [k, v] of Object.entries(KEYS)) {
    if (!v.pattern) continue;
    if (predicate && !predicate(v)) continue;   // ← 差异由 predicate 表达
    try { if (compilePatternRegex(k).test(key)) return v; }
    catch { /* 加载时已 fail-loud，此处仅防运行期炸 */ }
  }
  return null;
}
function findPatternEntry(key) { return matchPatternEntry(key); }
function isKvPatternKey(key) { return matchPatternEntry(key, (v) => v.backend === 'kv') !== null; }
```

→ **两处坏正则 catch 合一**（TD-02-17 的重复面同时消除）。

## 二、TD-02-17：坏正则从"热路径静默吞"前移到"加载时 fail-loud"

**原矛盾**：同文件 `checkRegistered` 对「未登记字面量键」dev 环境**直接 throw**（fail-loud），
却对「正则模板坏了」**运行期静默吞** —— 对拼写错零容忍、对模板坏零感知。

**修复**：新增 `assertPatternRegExpsValid()`，在 `KEYS` 初始化后**模块加载时**集中校验所有
`pattern:true` 模板，坏正则**带键名抛错**：

```
Error: [contentStore] STORAGE_KEYS 中以下 pattern 模板无法编译为正则（键名含非法占位/字符）："*bad-{probe}"。
       请修正 contracts.ts 的模板（如 canvas-state-v1-{projectId}）。
```

→ 复杂度**前移到契约加载源头**（dev 立即炸、生产只炸一次于启动）；热路径 catch 退化为"不该发生的兜底"。

**负例探针**：注入 `*bad-{probe}` pattern 模板 → 模块加载精确抛错（含键名）→ 恢复后全绿。

## 三、TD-02-18：双通道失败零信号 → 留痕 + **一处正确性修正**

### 3.1 `kvWriteOp` 内层（KV + 本地都失败）

原静默（仅 `catch-ok` 标记）。**此刻该键只在内存里，刷新即丢** —— 这是最高危状态，绝不能静默。
→ 改 `logger.warn`（保留"不抛"语义，因内存态为权威）。

### 3.2 `deleteKvWithFallback`（**发现正确性问题**）

原实现：`catch { if (!isEngineUnavailable) throw; sRemove(key) }` —— **引擎不可用时无条件清本地副本**。

**这是错的**：引擎不可用 = 删除**状态未知**（KV 键可能仍残留）。清掉本地副本 → 制造
**「KV 残留真值 + 本地已清」的假删除态**（用户以为删了，重载后从 KV 读到旧数据）。

> 与 TD-02-25「已删**复活**」**正相反**：那里是"KV 删**成功**后本地残留→复活"；这里是"KV 删**失败**却谎报删除"。
> 两者是同一条语义链的两端，本轮一并补齐。

**修复**：KV 状态未知时**不谎报成功**，保留本地副本（两边一致地"没删成功"）+ `logger.warn`。

## 四、TD-02-20：cache 来源标记 → **取最小正确形态（含一次"拒绝照抄"）**

**债登记原话**要求「cache 值带来源标记 `{value, source}`」。

**我先核实消费方，然后拒绝照抄**：

- 降级副本能进 `cache` 的唯一路径是 `loadFromKv`；而 `contentGet` 先查 `cache`（先于 backend 判断）→ 确实会读到。
- **但审计全仓消费方后：没有任何读者需要区分**（画布侧 d3d 已改用 `contentGetKvWithFallback` 的诚实 `vacated` 分支）。
- 给 cache 值加 `{value, source}` 结构 → 破坏 `contentGet` 的 `unknown` 契约、波及**全部**同步读者，**收益为零**。

→ **铁律 5 判词**：为不存在的消费方造类型 = 假抽象。故取**最小正确形态**：
**降级发生时 `logger.warn` 留痕**（使"此刻读到的是副本"可观测），**不动 cache 结构**。

**顺带发现死代码**：改 `loadFromKv` 后 `readKvWithFallback` 零消费者 → **删除**（§零.2「能删就删」）。

## 五、顺手修复：`compilePatternRegex` 转义集缺漏（本轮新发现）

写 TD-02-17 负例探针时**意外发现**：`utils.ts::compilePatternRegex` 的转义集
`/[.+^$()|[\]\\]/g` **漏了 `* ? | { }`** 等正则元字符。

**后果实测**：
- `a*b-{x}` 模板 → 直接抛 `Nothing to repeat`（整个模块加载失败）
- `a|b-{x}` 模板 → 语义变成"或"（键匹配错乱）

**修复**：转义集补齐为 `/[.*+?^${}()|[\]\\]/g`（JS 正则全元字符，对齐通行 `escapeRegExp`）。
验证：`*` 不抛错、`|` 不再变"或"、`+` 字面化、正常模板不受影响 → **补永久测试锁住**。
