## 一、链路快照

```
「视频输出分辨率档位」—— 真源 = 共享层（video 域公共词表，被 2 个节点消费）
  lib/resolutionPresets.ts（新建）
    export type VideoResolution = '480p' | '720p' | '1080p';      ← :12
    export const VIDEO_RESOLUTIONS: readonly VideoResolution[]     ← :15
      ├→ VideoGenerate.tsx:201   resOptions = VIDEO_RESOLUTIONS   （原来：裸数组 ['480p','720p','1080p']）
      └→ VideoProcessNode.tsx:113 SIZE_PIXELS: Record<VideoResolution, {width,height}>
                                 :118 SIZE_PRESETS = VIDEO_RESOLUTIONS.map(...)   （原来：裸数组含 label+像素）
  「档位 → 像素」（854×480 等）：处理节点**独有**需求（本地缩放目标）⇒ 留在该节点，未上移共享层
```

## 二、溯源（为什么两处原本是同一判据）

- 两处成员**完全一致**（480p/720p/1080p）但**各自手写**：`SIZE_PRESETS`（label+像素）与 `resOptions`（仅 label）。
- 用途不同**不代表**判据不同：「**有哪些档位**」是同一词表；「档位→像素」才是处理节点独有。
- 改前后果：增删档位必漏一处 ⇒ 生成节点会出现「UI 能选但处理节点无像素」或反之。

## 三、定海

- 档位值**一字不改**（ADR-0038；改值影响存量 `data.resolution` 与后端透传）。
- **不并入** agent 侧「图像画质档位」（`720p/1080p/2K/4K → 1K/2K/4K` 映射，另一判据，见文件头注释）。
- 登记表原记的「四套机制」中，**editor 7 项**与 **director3d 按宽高比计算**不计（各自功能）；`image` 域零命中。

## 四、切割（载体账 · ADR-0057 第 1 步）

- 开工前：清单定义点 **2 处**（`SIZE_PRESETS` 裸数组 + `resOptions` 裸数组）。
- 改后：**1 处**（`VIDEO_RESOLUTIONS`）；两个消费点均派生。
- **净减 2 → 1**；穷尽性防线 **0 → 2**（处理节点像素表 `Record<VideoResolution,…>` + 生成节点直接引用清单）。

### 弯路留痕（强制）

**弯路一：探针 A 首跑「未命中」—— 是我期望文案写错，不是探针无效。**

- **现象**：`exit=2` ✅（真红了），但 `--expect-out "missing the following properties"` 未命中。
- **原因**：我按 TS2739（复数 `missing the following properties`）写了期望，实际 TS 报的是 **TS2741**（单数 `Property '"1440p"' is missing in type …`）—— 因为缺的是**单个**属性。
- **修正**：改期望为 `is missing in type`，重跑**命中**。
- **教训**：探针失败先分辨「行为没被测到」还是「**期望写错**」—— 前者要回去改代码，后者只需改期望；两者都**不能跳过**。本次属后者，故保留首跑记录。
