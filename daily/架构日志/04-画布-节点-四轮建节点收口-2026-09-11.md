## 一、问题（首轮发现，本轮收口）

画布上有**两类「自建子节点」场景**，此前各写一遍提交逻辑、**行为不一致**：

| 类 | 宿主 | 原实现 | 补结构默认 | 进 undo 栈 |
| - | - | - | - | - |
| A（node 内 spawn） | GridSplit/GridMerge/Loop/TextGenerate/VideoProcess/Panorama/Director3D/`depthVideo` | `spawnAndCommit` | ❌（当时未补） | ✅ |
| B（内联建节点） | `AssetNode`(相机工作室) / `ImageGenerate`(相机工作室+恢复重建) / `useScriptBoxEngine`(剧本盒建下游) | 裸 `addNodes`/`addEdges`/`setEdges` | ❌ 手写 width/height | ❌ 不 record |

**症状**：B 类建的节点与 `App.addNode`/快照还原**字段漂移**（手写 420 与 `nodeDefaults` 单源表不一致）；且 **Ctrl+Z 撤不掉**刚建的节点（用户可感 bug）。

## 二、溯源（Phase 1）

- 这是**同语义（建子节点）多条实现路径**（心法 §二 探界 / CLAUDE §5.4·9），非特例。正解 = 收敛为**唯一原语**，不变量 = 「结构默认补齐 + 原子写 + 记历史」。
- B 类是真缝隙吗？否——B 类宿主场景不同（节点内自建 vs 画布空白建），但**必须满足同一组不变式**，属「同一语义」。

## 三、定海 + 切割（Phase 2/3）

- 在 `deriveNodes.ts` 抽 **`commitNewNodes(payload, handles)`** = 建节点唯一原子原语：
  1. `applyNodeTypeDefaults` 补齐结构默认（单源 `nodeDefaults`）
  2. 原子 `setNodes`/`setEdges`（函数式追加）
  3. `history.record(显式快照)`（顺序红线固化：先算快照→setState→record）
- **`spawnAndCommit` 降为薄包装**：`commitNewNodes({nodes: spawned.childNodes, edges: spawned.edges}, handles)` → 既有 8 处调用签名不变，且**顺带获得结构默认补齐**（安全：`applyNodeTypeDefaults` 只补缺不覆盖）。
- `getEdges` 仅在 `history` 存在时才读（无 history 的宿主/最小 mock 不必提供）。
