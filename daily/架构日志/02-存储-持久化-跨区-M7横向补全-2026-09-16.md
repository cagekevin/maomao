# 02 存储/持久化 · 跨区 · M7 横向补全（裸存储 writer 普查）· 2026-09-16

> **触发**：用户「根据现有债务横向推导还有没有别的债，从底层开始找」。
> 起点 = 最底层契约地基 `contracts.ts` 的 `STORAGE_KEYS` 登记表 + `contentStore` 唯一入口红线（contentStore.ts:4「业务侧禁绕过 contentStore 直调原生 localStorage」）。
> **母体**：M7（工程数据统一契约 · 任何持久化须走 contentStore + 登记 STORAGE_KEYS）。已登记 TD-02-30/32/33 只覆盖了「备份不收剪辑/3D 工程」「StorageMonitor 假陈述 IndexedDB」「剪辑器 hooks-cutia caption 裸 localStorage」三处；本轮沿同一母体往下层穷举**全部裸 localStorage / 裸 IndexedDB writer**，找出未被覆盖的横向同胞。
> **落点**：本文件（唯一写全结论）；债 ID 绑 02；跨区 `@见`。

## 一 · 链路快照（底层实证）

自底向上取证的所有「裸存储写点」清单（grep `localStorage.(get|set|remove)Item` + `indexedDB.open` + `chrome.storage` 全仓，剔除测试/legacy 脚本）：

```

② director3d/storage.ts:23/43/64   writeJson/readJson/removeKey 非工程键 → 裸 localStorage.setItem(key)（RAW key，无 yimao: 前缀）
       └ 消费者：App.tsx:642 writeJson(CUSTOM_POSE_STORAGE_KEY, …) · project.ts:965 readJson(CUSTOM_POSE_STORAGE_KEY, [])

④ videoEditor/engine/services/storage/indexeddb-adapter.ts   IndexedDBAdapter → indexedDB.open
       └ 写方 service.ts:117 savedSounds（'video-editor-saved-sounds'）· :147 mediaMetadata
⑤ accountsStore.ts:381-441  readTabLocalStorage/writeTabLocalStorage  写【目标站点】localStorage（扩展环境切换）  ← 非债
```

**关键判据**：`STORAGE_KEYS` 登记项 ≠ 真实治理。凡「登记在 STORAGE_KEYS 但实际写路径绕过 contentStore」者，登记项即形同虚设（给人「已治理」的假象）。

## 二 · 溯源（为什么会产生）

- M7 母体 = 「任何持久化都该走 contentStore + 登记 STORAGE_KEYS + 受 `check:arch` 规则 6/7/9 机器守卫」。
- 剪辑器/3D 是后接入的子系统，各自带了「独立存储封装」（`director3d/storage.ts` / `videoEditor/.../IndexedDBAdapter`），**没接回 contentStore 唯一入口**，也没在 STORAGE_KEYS 登记（或登记了却没真正走 contentStore）。
- 后果类型一致：① 绕过唯一入口（缺机器守卫）② 第二真相（备份/云同步/跨端全不收）③ 假治理（STORAGE_KEYS 登记项误导）。

---

## 三 · 定海 / 四 · 切割（归属与红线判定）

- 红线证据：contentStore.ts:4 明写「禁止直调原生 localStorage」；`check:arch` 规则 6 拦截绕过 contentStore。director3d/storage.ts 与 videoEditor IndexedDB 均**无此守卫** → 回潮母体。
- 归属：均为**结构债**（修法 = 收口进 contentStore/STORAGE_KEYS 或显式裁定 + 注明），不涉对外契约/持久化格式变更，无需用户拍板。

### 非债留痕（禁止下次当 bug 补 · 已取证）

- **accountsStore.ts:381-441**（`readTabLocalStorage`/`writeTabLocalStorage`）：写的是**目标站点的 localStorage**（扩展环境切换功能，注入到页面 MAIN world），非 maomao 自身存储；contentStore 物理上不可达 foreign origin → **非债**（有意设计）。
- **storageQuota.ts:148**：只读枚举 raw localStorage（`KEY_PREFIX+key`）做配额诊断，与 storageAdapter 同前缀、只读 → **非债**。
- **director3d/storage.ts 工程键路径**（`writeProject` → `d3dPersistence` → KV，docs/45 收口）：已走 contentStore/KV → **非债**；仅「非工程键（custom-poses）」分支绕过（即 TD-02-34）。
- **videoEditor `mediaMetadata` IndexedDB**（service.ts:147）：按 docs/134 T4 有意设计（素材二进制走 localTool /files/、元数据留 IndexedDB），属元数据缓存非用户创作数据；与 TD-02-32（StorageMonitor 假陈述「不使用 IndexedDB」）同源但写路径有意 → **非债**（但同样未进 STORAGE_KEYS/备份，留痕待裁定是否需在 STORAGE_KEYS 注明）。
- **videoEditor/hooks-cutia/storage/use-local-storage.ts**（caption 语言裸 localStorage）：**@见 TD-02-33**（已登，不重登）。
- **扩展 `public/background.js` localforage IndexedDB（transitResources）**：属扩展 service worker 独立持久化面，超出 `src` 审计范围 → 列为**未来扩展区审计候选**，本轮不登。

## 六 · 结论

- 现有 M7 债务（TD-02-30/32/33）**只覆盖了 3 处**，本轮沿同一母体从底层 `STORAGE_KEYS`/`contentStore` 穷举全部裸存储 writer，新发现 **2 笔横向同胞债**（TD-02-39 director3d 姿势库裸 localStorage · TD-02-40 剪辑器 savedSounds 仅 IndexedDB），均绑根因区 02。
- 共性根 = 「后接入子系统自带独立存储封装、未接回 contentStore 唯一入口 + STORAGE_KEYS 登记不全/形同虚设」。修复统一交给最后那位决策架构师按 M7 一次性收口（与 TD-02-30/32/33 同批），**本流程只登记不动手**。
- 覆盖账：本轮审了 6 个底层存储 writer 文件 / 本批相关 8 个扫描命中点；未审 0（扩展侧 `public/background.js` 列为未来候选，不计入本区）。
