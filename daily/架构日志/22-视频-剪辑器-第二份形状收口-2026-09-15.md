## 三、Step 2/3/4 · 母体与各自的收口姿势

**母体 = M3「同一事实的第二份」**（本仓已知会在代码/契约/闸/记录四层现身的那条）。但**五笔的正确收口姿势各不相同** —— 这正是本轮要避免「一刀切」的地方：

| 债 | 姿势 | 为什么是它 |
| --- | --- | --- |
| TD-22-28 | **删** | 事实本身已失效（AI 域删除）→ 无需迁移（旧 JSON 多余键反序列化被忽略） |
| TD-22-30 | **改形状 + 接回唯一路径** | 模板改成 `{ styles: Partial<…> }` 覆盖差（与正向样本 `TEXT_STYLE_PRESETS` 同手法），工厂改走 `buildTextElement` |
| TD-22-35 | **复用既有类型** | 真源已在，只把 3 处内联换成 import |
| TD-22-36 | **删死副本**（不是派生） | 副本零消费者 ⇒ 派生它等于给死代码加逻辑 |
| TD-22-39 | **下沉原语到最小契约** | 抽 `fetchLibraryAudioResponse({ sourceUrl })`（只依赖一个字段），3 处共用；「取回来之后干什么」各自保留 |

**关键判别（Step 3）**：TD-22-39 的 3 份是**探测重复**（怎么取字节）→ 必须收口；
而三处「取回来之后」不同（转 `File` / 转 `arrayBuffer` 解码）是**用途差异** → 不收。
把原语下沉到 `sourceUrl → Response` 这一层，正好卡在这条分界线上。

**定权（Step 5）**：五笔都是结构（删除死字段 / 复用类型 / 收口原语），用户可见行为不变；
TD-22-28 虽动持久化字段，但方向是「读旧数据仍安全、写新数据不带它」⇒ 无需迁移、不需要用户拍板（理由写进 `TProject` 的接口 JSDoc）。

## 六、弯路与教训（本轮真踩到两次）

| # | 事实 | 教训 |
| --- | --- | --- |
| ① | 「源码不含 X」这类断言**与「为何删 X」的说明注释天然冲突**。本轮连踩两次：TD-22-28 的 `agentMessages`（注释里写「已删字段 agentMessages」）、TD-22-30 的 `...elementProps`（注释里写「此前直接展开」） | 写此类断言时，匹配串必须**只匹配代码形态**（如 `/agentMessages\s*[?:,]/`），或断言对象改成正则；**不要用裸词** |
| ② | **加了结构断言却没跑「后绿」**：TD-22-30 那条断言从加上那刻起就是红的（注释含 `...elementProps`），我直接去跑探针（探针红是预期的，掩盖了问题），直到**全量**才暴露 | 按 Step 7.1：**任何新增断言都要先单独跑一次确认绿**，再去做注入探针 —— 否则"红"会被误读成"注入生效" |
| ③ | 探针注入点带反引号（`` `fetchLibraryAudioSource/Clip` ``）在 PowerShell 里被转义 → probe 报「0 处匹配」（它**拒绝执行**，没有静默通过 ✔ 机制是对的） | 注入点选**不含反引号**的代码行；probe 的「0 处即拒」保护了「命令本来就失败被误当命中」（TD-02-9 同款） |

## 七、结论与遗留

- **五笔一次结清**：TD-22-28 / 30 / 35 / 36 / 39。母体 M-A 在本域**成片清零**（该族已无待还债）。
- 交付物是**五条各自正确的最小改动**，不是"统一改法"：删 / 改形状 / 复用类型 / 删死副本 / 下沉原语。
- **遗留（登记待办）**：
  1. `PanoramaNode` 等 `FullscreenShell` 全屏层内部仍有自挂监听 —— 非债（上一轮已判定）。
  2. `subtitle-constants.ts` 现 `import` engine 层（`buildTextElement`）—— 架构闸通过；若将来 `constants` 被要求纯常量，可把工厂挪到 `engine/timeline/element-utils`（本轮不做：消费方只 1 处，且 `createSubtitleFromTemplate` 与模板同文件更易发现）。
- **下一轮建议**：剩余待还里**业务债**占多数（TD-22-47 贴纸/音效数据源·高、TD-22-49 转场邻接阈值·中、TD-22-51 批量命令粒度·中）——需要用户拍板；技术债侧可做 **M-B 音频双后端**（TD-22-13/14/15/29），但它需真实媒体样本才能验证，建议先拍业务债方向。
