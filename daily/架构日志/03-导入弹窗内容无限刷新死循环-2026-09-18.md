## 二、溯源（Phase 1：症状 vs 病根）

- 症状：弹窗内「文件夹 / 图片」内容反复清空重拉、UI 抖动，最终整页卡死。
- 病根（不在入口，在弹窗）：`ImportMediaModal.tsx` 把「初始加载 / 切 tab 触发拉取」的 `useEffect` 依赖写成了 `[tab, navigate, defaultCatKey]`，
  而 `navigate` 的 identity 又经 `queryFor` → `categories` 间接依赖 `items`。于是「拉取」与「加载结果」互相驱动，形成闭环比渲染。
- 这是**单文件结构缺陷**，不是跨模块乱象，无需源头收敛讨论。

## 三、定海（Phase 2：不变式 / 唯一真相源）

- 不变量被破坏：**「拉取动作」不应被「上一次拉取的结果」反向触发**。本组件把 `items`（拉取结果）放进了加载动作 `navigate`/`queryFor` 的依赖上游，
  导致结果一变就重拉，违反「加载是一次性的、仅由用户意图（tab / 分类 / 目录）驱动」的不变式。
- 边界处无运行时校验（非数据脏，是依赖声明错），属 React 规则类缺陷。

## 四、切割（Phase 3：深模块 / 真缝隙 / 收敛口）

- 无「第二份真相」；缝隙在于 effect 的依赖声明把「数据态 `items`」与「动作 `navigate`」错误地耦合。
- 收敛口（偿还方向，不在本流程执行）—— ⚠️ **2026-09-18 施工轮取证后，本条已被证伪，见 §八**：
  ~~让「初始加载 / 切 tab」的 effect 只依赖 `[tab]`，在 effect 内部取默认分类 key 后调 `load`。~~
  **证伪理由（两条，均为读码实测）**：
  ① `defaultCatKey` 本身派生自 `categories(items)` —— 把它挪进 effect **内部**只是把回边藏起来，并没有断掉
     （`items` 一变，effect 内的取值照样变）；
  ② `setTab` 是异步的，在 `onClick` / effect 首帧里读 `tab` 拿到的是**未提交的旧值** ⇒ 会拿旧来源去 `load`（拉错 tab）。
  **真实收敛口（已落地，见 §八）**：让**视图意图自足** —— 选中分类时存**分类对象**（含其 `query`）而非 key，
  拉取侧就不必回查那张派生自已拉到的 `items` 的清单；再把拉取收敛到**唯一一条只依赖意图**的 effect。

### 8.9 弯路留痕（**与结论同等对待**）

**弯路 ①：`setCategory` 在切 tab 的 effect 里写"默认分类对象"，而不是 `null`。**
- 当时的推理链：既然 `category` 是意图状态，那切 tab 时就应该把默认分类**具体地**写进去，这样 `queryFor` 不必有 `?? defaultCategory` 兜底。
- **为什么错**：effect 的依赖里就得带上 `defaultCategory`。第一版我让它 `= categories[0]`（派生自 `items`）⇒ **回边原样复现**（`items` 变 → `defaultCategory` 换新对象 → effect 重跑 → 再拉）。后来才想通：**默认分类只属「来源」，不属「已拉到的数据」**，应该取自 `provider.categories()`（无 entries，契约保证返回静态部分），而不是 `categories(items)[0]`。
- **是否已完整回退**：是。现版本 `setCategory(null)` + `queryFor` 内 `?? defaultCategory`（`defaultCategory` 不依赖 items）。
- **顺带收益**：这样还**少发一次请求**（挂载时 `category` 初值就是 `null`，不会先按"无分类"拉一次再按"默认分类"拉一次）。

**弯路 ②：`activeCatKey` 第一版写成 `category?.key ?? defaultCategory?.key`，漏了「下钻态」。**
- 症状：下钻进目录后，`category` 是 `null` ⇒ 回落到默认分类 key ⇒ **「全部」pill 会亮着**，与文件头铁律「有值（下钻）→ 分类 pill 不选中」矛盾。
- 为什么容易漏：旧实现 `catKey` 在下钻时是 `null`，`null === c.key` 恒 false，**恰好**没亮；换成"null 代表默认分类"之后这个巧合就没了。
- **是否已完整回退**：是（`activeCatKey = openFolder ? null : (...)`），并**补了对账断言**（测试第 4 例），防回潮。
- **另记一笔工具教训**：改这处时探针正在跑，`probe.mjs` 的**原子还原**把它一并回滚了（journal 存的是注入前的原文全文）。⇒ **探针运行期间不要改同一个文件**；本轮已重新落回并复跑验证。
  - ⚠️ 这不只是"用法注意"：该失败是**静默**的（文件被整份覆盖，探针照样打印「✅ 探针命中 / exit=0」）⇒ 结论会建立在**已被覆盖的旧码**上 = **假绿**。按 A10「工具债不延后」**当场修**：`scripts/probe.mjs` 增加**并发编辑守卫**（注入前 / 还原前各校验一次目标文件 sha，不符即**拒绝覆盖** + `exit 2`，窗口②保留 journal 供人工合并）。已登记并结清 **TD-17-18**（先红＝并发写入被静默覆盖且探针报 `exit=0`；后绿＝`exit=2` 且文件未被覆盖；`node --check` ✅ + 正常路径实跑 ✅）。
