# 03 · 资产 / 素材 · 导入弹窗内容无限刷新死循环 · 2026-09-18

> **触发**：用户报 bug —— 画布右键「导入」打开弹窗后，**里面的文件夹 / 图片内容疯狂刷新，直到卡死**。
> 不是 tab 在闪，是 tab 下的媒体网格在无限重拉。
> **性质**：单点 bug 登记轮（用户触发，非全区域扫）。
> **根因区**：03（资产 / 素材 · 导入弹窗 `base/panels/ImportMediaModal.tsx`）。
> **结论一句话**：弹窗的「切 tab / 初始加载」`useEffect` 的依赖链经 `items` 把 `load` 串成自循环 ——
> `load` 每次 `setItems` 改变 `items` 身份 → `categories`/`queryFor`/`navigate` 连锁重算 → effect 重触发 → 再 `load` → 再 `setItems`……无限拉取，直到卡死。
>
> **结论落点**：明细见本文件 §五（探债）/ §六（覆盖度）；摘要进 `债务.md`（TD-03-20）。

## 二、溯源（Phase 1：症状 vs 病根）

- 症状：弹窗内「文件夹 / 图片」内容反复清空重拉、UI 抖动，最终整页卡死。
- 病根（不在入口，在弹窗）：`ImportMediaModal.tsx` 把「初始加载 / 切 tab 触发拉取」的 `useEffect` 依赖写成了 `[tab, navigate, defaultCatKey]`，
  而 `navigate` 的 identity 又经 `queryFor` → `categories` 间接依赖 `items`。于是「拉取」与「加载结果」互相驱动，形成闭环比渲染。
- 这是**单文件结构缺陷**，不是跨模块乱象，无需源头收敛讨论。

## 三、定海（Phase 2：不变式 / 唯一真相源）

- 不变量被破坏：**「拉取动作」不应被「上一次拉取的结果」反向触发**。本组件把 `items`（拉取结果）放进了加载动作 `navigate`/`queryFor` 的依赖上游，
  导致结果一变就重拉，违反「加载是一次性的、仅由用户意图（tab / 分类 / 目录）驱动」的不变式。
- 边界处无运行时校验（非数据脏，是依赖声明错），属 React 规则类缺陷。

## 四、切割（Phase 3：深模块 / 真缝隙 / 收敛口）

- 无「第二份真相」；缝隙在于 effect 的依赖声明把「数据态 `items`」与「动作 `navigate`」错误地耦合。
- 收敛口（偿还方向，不在本流程执行）：让「初始加载 / 切 tab」的 effect **只依赖 `[tab]`**，在 effect 内部取默认分类 key 后调 `load`，
  或把 `queryFor`/`navigate`/`load` 拆成不依赖 `items` 的「当前视图加载」版本，使 `setItems` 不再反推回 effect。
