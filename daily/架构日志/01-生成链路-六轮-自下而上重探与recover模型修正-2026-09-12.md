# 01 生成链路 · 六轮：自下而上重探 + 剧本盒 recover 模型修正（2026-09-12）

## 方法论修正（用户指出）
前五轮是**自上而下**（入口 hook / 脚本盒 → 任务中心一层停住）。本轮按用户要求**自下而上**逐层沉底，反而修正了前几轮的关键误判。

## 自下而上分层实证
- **L0 传输/模型 API 层（`generate.ts`）**：`generateImage/Video/chatCompletions` 全是 `generate()` 一行别名 wrapper（生成门面已收口）；`signal` 三模态全透传、`taskId`(frontTaskId) 三模态贯穿；**abort 双形态**——image/video 抛 `AbortError`（铁律 2 原样上抛）、chat 返 `{ok:false,aborted}` 信封。
- **L1 任务中心原子层（`taskStore.ts`）**：`reportGenerate`(:215) 返回控制器 `{taskId, progress, done, fail}`；**`done`(:285) 内部已内置 `publishTaskCompleted` 广播（framework-agnostic 铁能力）**——发布端天然统一，无需合约补；`runNodeGeneration`(:423) **仅并发限流壳 + retryRegistry 重试触发器，非合约运行器**。→ 底层（generate API + 任务中心原子方法）早已收口且 framework-agnostic。
- **L2 广播层（`eventBus`/`taskCompletionBus`）**：纯 TS；`subscribe('agent:task-completed')` 全库唯一在 `useNodeGeneration:393`。
- **L3 异步恢复层（`pollTask.ts`）**：仅接管 `type==='image'|'video'` 的 running 任务（启动扫描 + 5s 补扫），**文本/生图 sync 不恢复**（注释明确"官方同此，只对视频异步任务恢复"）；恢复完成经 `publishTaskCompleted` 广播。

## 用户质疑驱动的修正：剧本盒 recover 模型
**质疑**：剧本盒全是文档/文字，只做图做文字，需要异步恢复吗？只有一个资源素材库可能需异步恢复。

**自下而上验证**（scriptBoxEngine:548-617 + useScriptBoxEngine:70-78）：
- 剧本盒资产图：**生成成功才** `commit`(node.data.assets.assetUrl) 经 `setNodes` 持久化 + `done`。**已完成结果靠剧本 data 持久化恢复，刷新后正常显示，不需要任务中心异步 recover** → 质疑成立。
- 真实但**窄**的缺口：仅**生成中刷新**窗口——task running、data 未 commit，pollTask 找回 resultUrl 广播，但剧本盒不订阅 → 不回填 data → 丢。非"已完成场景"。
- 文本（chatCompletions）同步，无异步窗口；pollTask 明确不恢复文本。
- **资源素材库**（独立模块）才是真正可能需任务中心异步恢复之处：剧本盒资产图成功后 `localizeAndStoreToResourceLibrary`(:555) 落盘 /files/；素材库自身若有异步生成任务则走任务中心 recover —— 待单独研究（新立 TD-01-13）。

## 对 TD-01-8 / TD-01-9 定性影响
- **TD-01-9 降级**：从「能力不对等·还债铁证」→「**窄边界·待裁定**」——已完成场景靠 data 持久化正常（非缺陷）；仅生成中刷新窗口丢失，是否修取决于产品容忍度（用户倾向不需要）。
- **TD-01-8 修复范围收窄**：recover 订阅**不该**内聚进通用 contract（剧本盒靠 data 持久化、不订阅是合理设计）；正确设计 = `recoverable` 开关（节点 true / 剧本盒 false）。contract 真正要固化的「编排层四能力」：
  1. `taskId` 贯穿（reportGenerate.taskId → generate opts.taskId，底层已支持）
  2. `done/fail` 一致（脚本盒已调，尾帧图 1680 缺失 → 第四形态债）
  3. `localize + commit` patcher（剧本盒已做、节点直存 → localize 开关）
  4. `abort + classifyError`（脚本盒资产图 524 不传 AbortSignal / 老式 /abort/i 匹配已失效；classifyError 纯 TS 单一决策入口 genErrors.ts:24）
- **recover 是节点侧需求，非剧本盒需求**；任务中心异步恢复机制的真正消费方 = 画布节点 + 资源素材库。

## 结论
自下而上研究证明：抽 `runGenerationContract` 的**地基（L0–L2）已结实且 framework-agnostic**，要抽的是薄编排壳；且 recover 不应进通用合约。TD-01-9 严重度下调、TD-01-8 范围收窄。仍待用户拍板翻新方向。
