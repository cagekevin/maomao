# 22 · 视频剪辑器 · 素材导入收口（2026-09-15）

> **触发**：用户报「Video editor 只能导入一个素材，导入第 2 个就导不了了」。
> **用户在过程中 4 次纠正方法**（全部采纳，是本轮真正的工作方式）：
> 1. 「不要修 bug，按正常应该怎么设计，直接把之前的代码改了、删了，重新写」
> 2. 「有错误就找同类东西，先给它收口，做正确就行了」
> 3. 「不要找 bug，找同类东西收口」
> 4. 「老测来测去有啥好测的？把事情做正确，然后检查哪些代码上有、但 UI 显示不出来的东西」
>
> **结果**：用户确认「这次弹出来了」。→ **把代码改正确，bug 自然消失。**

---

## 一、真根因（一句话）

**「导入」按钮把"打开文件选择框"这个动作，挂在了一个 Radix 下拉菜单里。**

`openFilePicker()` 内部是 `input.click()` —— 一个**必须在用户手势同步栈内**执行的命令式动作。
而 Radix 菜单在选项被选中时会**同步执行「关层 + FocusScope 归还焦点」**，该动作随即被判为
"不在手势栈内" → **浏览器静默丢弃** → 文件选择框弹不出来。

叠加一个放大因素：`ui/ui/button.tsx` 基类含 `disabled:pointer-events-none`
—— 按钮一旦 `disabled`，指针**直接穿透**，Radix 连 `pointerdown` 都收不到（菜单根本不打开），
而 `disabled:opacity-50` 在深色主题下肉眼几乎看不出 → 用户看到的就是**"点了毫无变化"**。

**为什么"空的时候能弹、有素材后不行"**：空态用户点的是 `MediaDragOverlay` 自身那个普通
`<button>`（直接调 `openFilePicker`，不经菜单）；有素材后 overlay 消失，只剩这个菜单，
于是必然经过上面那条失效链路。

---

## 二、改法（按「正确设计」，不是打补丁）

### ①「导入」直连文件选择框 —— 不再经下拉菜单
链路从「按钮 → 开关菜单 → 点选项 → input.click()」缩成「**按钮 → input.click()**」，
中间不再有任何 FocusScope / 关层介入。
URL 导入是次要用例 → 给一个**并列的小按钮**（`Link04Icon`），不再挤在菜单里。

### ② 撤销"入口禁用"
删掉「导入」「排序」「切换视图」三个入口按钮上的 `disabled={isProcessing}`，
`MediaDragOverlay` 的 `disabled` 也改为只在**无回调**时生效（处理中改用 `aria-busy` 表达）。
理由：**入口任何时刻都该可用**；"处理中"只应由进度提示表达，不该锁死入口。

### ③ 修非法嵌套
「排序」的 `<Tooltip>` 原先被**嵌在**「切换视图」`<Tooltip>` 的 children 里
（Radix Tooltip 只接受 Trigger / Content）→ 改为**两个并列的独立 Tooltip**。

### ④ 修高度链（对应"代码有、UI 看不到"）
`AssetsPanel` 的 `<div className="flex-1 overflow-hidden">` **缺 `h-full`**：
子视图（`MediaView` 根是 `h-full`）的百分比高度参照父的 `auto` 高度 → 内容为空时**塌成 0**
→ 整块素材区看起来"什么都没有"（这正是用户说"看不到那个拖放区域"的原因）。
改为 `flex-1 h-full min-h-0`。

### ⑤ `drag-data.ts` 收口（同类缺陷，另一条去环路径）
模块级全局 `lastDragData` 同时承担两件事（"本次拖拽有无载荷" + "上次拖拽的载荷副本"），
其 `hasDragData` = `types.includes(MIME) || lastDragData !== null` 会被**上一次拖拽的残留**污染
→ 外部文件拖入被判为非文件拖拽 → 静默丢弃。
**删掉全局**：载荷只存在于 `dataTransfer`；`hasDragData` / `getDragData` 同口径只看本次
`dataTransfer`；`clearDragData` 随之退役，`draggable-item.tsx` 删其引用。
（该副本声称兜底"读不到 `getData()`"，但那种场合它拿到的也是**上一次**的数据 —— 纯负担。）

### ⑥ 删除「URL 导入」死功能（架构判断，未问用户）
**事实**：`engine/lib/media/url-import.ts` 的 `fetchWithProxyFallback` 在直连失败后打
`/api/proxy/download` —— 那是 **cutia（Next）的路由，搬迁到本仓时就不存在**
（本仓多处注释已记「旧 `/api/proxy` 已退役」）。素材是跨域媒体 → 直连几乎必失败 →
走代理 → **必然 404**。**该功能从未成功过。**
**处置**：删掉 `url-import.ts` + 素材面板的「URL」按钮与 Dialog 及 3 个相关 state/4 处死 import。
**依据**：① 唯一消费者就是被删的入口（全仓 `fetchRemoteMediaAsFile` 仅 1 处调用）；
② 它代表的那条路（浏览器直接 fetch 远程）**在本仓是错的** ——
**本仓既有正路是 `localTool` 后端代下载**：`filesApi.uploadFileToLocal` 的 `fileUrl` 模式
→ `saveRemoteUrl` + `fetchWithProxy`（绕 CORS + sha1 幂等）；
③ **留着 = 留一个陷阱**：`docs/125/130/133` 把它记为"画布 URL 桥、直接复用"，
后代会照文档复用它然后踩同一个 404（方案 ≠ 实现，附录 A2）。
**能力不减**：用户仍可先下载到本机再「导入」。将来做画布 URL 桥，走 `docs/125:146` 自己给的
更省事方案 —— **URL-only 资产**（画布素材本就在 `/files/` 已落盘，连 fetch 都不需要）。

## 三、⚠️ 走过的弯路（如实留痕，防后人重走）

**本轮有两次改错，均已完整回退/删除。记下来是因为它们都是"看起来很有道理"的错误。**

### 弯路 1：把 `DropdownMenu` 包一层、把 `onClick` 归一为 `onSelect`
**思路**：读 Radix 源码发现 `Item` 的选中通道是 `onSelect`（且其 `defaultPrevented` 能阻止
`onClose`），而全仓 4 处调用点都挂 `onClick` → 判定"封装层没把语义摆正"，于是在
`DropdownMenuItem` 里做归一、并新增 `DropdownMenu` 包装层持有 `open` 以支持"动作后自行关闭"。
**结果**：**改完仍然弹不出来**，且**新引入一个 bug**（包装层把 `open` 变成受控，
使菜单彻底打不开）。
**教训**：这条推理**方向错了** —— 病灶不是"菜单项的回调通道选错"，而是
**"这个动作根本不该由菜单承载"**。在错误的位置（菜单封装）做深度优化，
越"正确"离解越远。

### 弯路 2：反复写探针去证伪/证实假设
写了 4 个取证/回归测试文件，逐一证伪了
「`useFileUpload` 第二次失效」「React 重渲染重置 `multiple`」「`MediaManager` 覆盖」
「后端内容去重」等假设，又试图用 jsdom 验证 `disabled` / Radix 时序
（**jsdom 测不出浏览器的手势栈与 `pointer-events` 语义**，探针两次"没红"）。
**教训**：用户点名批评「老测来测去」。**测试应服务于"我改对了什么"，不是"我猜对了吗"。**
定位根因的正道是**读代码 + 让用户提供关键观察**（本例中用户的
"按钮外观无变化 / 菜单也没关 / 看不到拖放区 / 十字星光标" 四句话直接锁定病灶）。

### 弯路 1 的遗留已清理
- `dropdown-menu.tsx` —— `git diff` 为空（已完全回退）
- `tests/unit/veDropdownMenuItem.test.tsx` —— **已删除**（它锁的契约随设计撤销而消失；
  留着就是"假绿"：测试通过 ≠ 那件事存在）
