## 一 · Step 0 最优解（先写后做）

**这个能力正确落地时该长什么样**：

- **能力** = 「拿编辑器实例」＋「订阅**自己读的**那些子 store」。
- **唯一实现** = `useEditor(...stores)`（`hooks-cutia/use-editor.ts`）；`stores` 缺省 = 全部 7 个（向后兼容）。
- **判据在哪层**：**订阅面由消费方声明**（它才知道自己读什么）；`EditorCore` 只提供 `subscribe`。
- **它取代什么**：原「无条件合并订阅 7 个 store」——任一 store 变更，48 处调用者**一起重渲**；
  播放期 `playback` **每帧**通知 ⇒ 只读 `timeline` 的组件被**每帧连坐**。

**先证伪「拆成 `useEditorInstance()` + 渲染方」这条路**（债的朴素解法）：实测 36 个消费方**全部**至少引用 1 个 store
（零引用的 = **0 个**）⇒ 「只取实例」没有消费方，加它就是 **ADR-0030 的幽灵预留** ⇒ **不建**。
真正缺的不是"实例 vs 订阅"的二分，而是**订阅面不可声明**。⇒ 正解 = 加 `stores` 参数。

**横向盘查（Step 0 第 3 步）**：仓内已有 `useStoreSelector`（TD-04-44），但它是**值选择器**（从一个 snapshot 里选字段），
而 `useEditor` 是**版本计数**形态（`versionRef`）——没有可选的 snapshot ⇒ **不可直替**（与 M1 评审 §六 的判断一致）。

## 二 · 施工明细

### 2.1 `useEditor(...stores)` —— 订阅面可声明

- `EditorStoreKey` = 7 个可订阅 store（`playback`/`timeline`/`scenes`/`project`/`media`/`renderer`/`selection`）。
- **`command` / `save` / `audio` 不入列**（实测：`CommandManager` 无 `subscribe`；`save-manager` 自己订阅 scenes/timeline、
  `audio-manager` 订阅 playback/timeline/media ⇒ 它们是**派生**件，订阅那 7 个即覆盖）⇒ **不是**订阅缺口。
- 订阅面按**稳定字符串**入依赖（`[...new Set(stores)].sort().join(',')`）⇒ 不会每次渲染换 `subscribe` 引用而解绑重绑（TD-04-45 同款教训）。
- `useEditorInstance()`：**只取实例不订阅**，唯一消费方 = `use-element-selection.ts`（它的选中态已由 `useSelectionSnapshot` 精确订阅 `selection`，
  再走 `useEditor()` 会**重复订阅同一个 store**）。⚠️ 注释里写明「**别拿它当'默认更省'用**」。

### 2.2 48 个调用点的分类迁移（机械 · 取并集）

**判据 = 该文件里 `editor.<store>.*` 出现的 store 全部列上**（渲染期读的、回调/effect 里读的**都算**）。
⇒ **多列安全（只是多订阅），少列会静默不更新** ⇒ 取并集是**上界**，构造上不会欠订阅。

| 订阅面 | 文件数 | 代表 |
| --- | --- | --- |
| 1 个 store | 18 | `timeline-track` / `properties/*` → `timeline`；`draggable-item` → `playback`；`link-media-refs` → `media` |
| 2 个 | 4 | `timeline-element`（timeline+media）· `text.tsx`（timeline+scenes）· `timeline-ruler`（timeline+project） |
| 3–4 个 | 9 | `timeline/index` · `bookmarks` · `use-timeline-drag-drop` |
| 5–6 个 | 5 | `use-preview-interaction` · `preview/index` · `use-editor-actions` |
| instance-only | 1 文件（2 调用点） | `use-element-selection.ts` |

## 三 · 度量（减二 · 可复算）

```
调用点 48（其中 instance-only 2 · 按 store 订阅 46）
订阅总数   改前 48×7 = 336  →  改后 105      降幅 68.8%
不再订阅 playback（免每帧连坐）  28 / 46 个调用点
```

> 复算命令：对 `src/**` 里每个 `useEditor(<args>)` 统计 args 个数、以及 args 是否含 `playback`。
> ⚠️ **粒度边界（诚实声明 · ADR-0046）**：本轮的粒度是 **manager（7 个）**，**不是字段** ——
> 例如只读 `timeline.getTracks()` 与读 `timeline.getZoom()` 的组件仍共享同一个订阅面。
> 字段级需要值选择器（`useStoreSelector` 那条路），而 `useEditor` 是版本计数形态、无 snapshot 可选 ⇒ **本轮不做**，也不假装做了。

## 四 · 弯路留痕

1. **分类脚本第一版把 manager 集合藏了。** 首版输出「有非 manager 引用时只打印非 manager 部分」⇒
   把 `use-editor-actions.ts` 误显示成「零 manager 引用」（它其实有 `editor.project.getActive()` **渲染期读**）。
   **后果**：若照它迁移，会把该文件的订阅面算成空 → **静默不更新**。
   **修正**：改成 manager 与非 manager **并列打印** ⇒ 得 36/36 文件全有 manager 引用。
   **教训**：**审计脚本的输出本身就是"描述"，也要自检**（A13 的镜像面）。
2. **改 hook 的 import 面会打穿 mock 测试。** 把 `use-element-selection.ts` 从 `useEditor` 改到 `useEditorInstance` 后，
   TD-04-45 新写的 `useSelectedElements.test.ts` 里 `vi.mock(...)` 只提供了 `useEditor` ⇒ `useEditorInstance` 为 `undefined`
   ⇒ **3 例红**（全量首跑 1 文件/3 例失败）。**修正**：mock 同步提供 `useEditorInstance`。
   **教训**：**mock 是契约的影子 —— 改被 mock 模块的导出面，必须同步它的所有 mock 点**（本仓 `useAgentChat.hook.test.ts` 曾踩同款）。

## 五 · 未做与理由
