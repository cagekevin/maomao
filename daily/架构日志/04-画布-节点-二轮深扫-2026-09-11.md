## 二、溯源（Phase 1：症状 vs 病根）

- **首轮已定位的病根（端口契约三源漂移）→ 本轮已收口**（见 §五 实施记录）。
- **新病根（类型地基层）**：`NodePalette.ts` 作为**全 17 节点的注册表地基**，其 `paletteNodes`/`getPaletteNode`/`defaultNodeData`/`buildNodeTypeComponents` **全部零类型标注**（裸 `export const paletteNodes = [...]` + 裸参数 `(type)`）。这是画布板块**最底层的类型地基缺失**——下游 `canvasContextMenu.tsx:132` 被迫 `n as unknown as PaletteNodeRef` 假收窄，正是地基未定型的直接症状。
- **文档漂移**：`NodeShell.tsx` 与 `TemplateNode.tsx` 的「新建节点注册流程」仍写「App.jsx 手改 nodeTypes / 4 处注册」——与实际（nodeTypes 单源派生 / 现为 5 处）不符；`spec/NEW-NODE-GUIDE.md` 的「3 处」漏了 `contracts.NODE_TYPES` 与新增的 `NODE_HANDLE_CONTRACT`。

## 三、定海（Phase 2：不变式 / 唯一真相源）

- **SSOT 六项复核**（首轮五项 + 本轮新增一项）：
  1. 节点注册表 = `NodePalette.paletteNodes` ✅ 唯一
  2. 结构默认 = `nodeDefaults.NODE_TYPE_DEFAULTS` ✅ 唯一
  3. 输入面板范围 = `INPUT_PANEL_NODE_TYPES` ✅ 唯一（NodePalette/useArrangeCanvas/App 三处共用）
  4. 参数记忆命名空间 = `contracts.NODE_TYPES` ✅ 唯一（`check:node-types` 守门）
  5. 撤销栈 = `HistoryStack` 纯类 ✅ 唯一
  6. **端口契约 = `contracts.NODE_HANDLE_CONTRACT`** ✅ **本轮新收口**（原三源 → 一源，`check:node-handles` 守门）
- **边界 Guard 复核**：`useConnectedInputs` 的 G2（dev 期产出 schema 校验）**实测覆盖完整**——17 类型 = textGenerateNode(特判) + 5 声明 + 9 genericOutput + 2 noOutput，`covered` 集合无缺口 ✅。
- **类型诚实性**：画布区 `as any`/`as never` **0 处**；`as` 断言均为诚实收窄（`typeof parsed === 'object'` 守、destructuring-rest）；**唯一假收窄 = `canvasContextMenu.tsx:132 as unknown as PaletteNodeRef`**（根因是 §二 的地基未定型，非末端补丁）。

## 四、切割（Phase 3：深模块 / 真缝隙 / 收敛口）

- **`useConnectedInputs` = 合格深模块**（143 fan-in，窄接口 `useConnectedInputs(id)` / `getNodeOutput(node)`，厚实现：入边 WeakMap 缓存 + 编组出口展开 + 产出声明表 + 通用兜底 + G2 校验）。**不需要切**。
- **`useArrangeCanvas` / `useCanvasSync` / `useCanvasShortcuts`**：职责边界清晰（算法 vs 交互决策分离、冲突检测自包含），无第二真相源。
- **收敛口债（类型地基）**：`NodePalette` 应补 `PaletteNodeDef` 接口（type/label/icon/cat/component/data/builtin/badge），使 `getPaletteNode` 返回真类型 → 消 `as unknown as`（TD-04-6）。
- **`TemplateNode` 错位**：文件定位是「新建节点蓝本」，却被 **4 个 registry 当活节点登记**（NODE_TYPES/nodePrefs/INPUT_PANEL/NODE_OUTPUTS），而**唯一该登的 paletteNodes 反而没登** → 蓝本成了「不可创建但四处占位的幽灵」（TD-04-5）。
