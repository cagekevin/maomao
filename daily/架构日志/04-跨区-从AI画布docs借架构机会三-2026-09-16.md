## 一、本轮新增链路快照（对方实现级机制，精简取证）

- **统一媒体落盘边界**（plans/2026-09-02-local-project-media-persistence）：以 `fileService` 作为**唯一媒体落盘边界**，统一处理 `data:`/`blob:`/HTTP(S)，返回可持久化 URL 组；所有节点/批量/轮询入口只回写该 URL 组；项目序列化再迁移内嵌媒体到项目目录；**落盘失败时不得把内嵌媒体降级写入持久化状态**（Task 2.3、Task 4.2 明文）。
- **结构化撤销 + 项目级历史隔离**（plans/2026-07-24-project-scoped-history）：画布撤销只处理节点/连线/分组的**结构变化**，不回退位置/尺寸/普通内容编辑；快照比较仅用结构字段，undo/redo 对现存节点保留当前普通数据；IndexedDB 输出历史按 `projectId` 复合索引隔离、每项目≤16 条；DB 升级兼容旧记录（幂等归属函数）。
- **声明式校验实施纪律**（plans/2026-08-26-video-input-validation-implementation）：能力类型全部可选 → **不需数据库回滚**；删单一校验调用即停拦截；旧配置兼容 + 失败关闭测试。
- **MCP 全控实施纪律**（plans/2026-08-13-mcp-complete-control-implementation）：运行时界面能力经内存服务桥接，**不进入持久化层**；截图遮盖敏感元素并压缩；每个写操作校验 `projectId`+`revision` 且只提交一次历史快照；复用 Store Action，**不接受任意路径/密钥/完整配置对象**。
- **开发指南规约**（doc/开发指南.md §3.3）：节点组件用 `React.memo`；**禁止在节点组件内直接改 store，必须经 Store Action**（`useAppStore.setState` 禁止）。
- **history 归档踩坑纪律**（doc/history/2026-09-07）：发现阻塞标 `[!]`，**不得静默跳过安全/权限/持久化/恢复要求**；回滚**不得降低 IndexedDB 版本、不得删除用户历史、不得放松安全策略**；密钥/绝对路径/完整敏感正文**不进日志**（`sanitizePersistentSummary` 脱敏）；文件全文/网页全文/密钥/临时结果**禁止进入记忆**（脱敏 + 500 字符上限）；**只接受完整 `tool.call.final`，流式参数不得触发执行**；工具 schema **禁止未知字段**；已成功步骤再次调用返回**幂等结果不重复付费**，失败不自动重试。

## 三、第一类：能提升我们架构（可落地机制，grep/读码证实我方缺失）

1. **统一媒体落盘边界 `fileService` + 落盘失败不降级** — plans/2026-09-02。抽唯一落盘边界，统一 `data:`/`blob:`/HTTP(S)→ 可持久化 URL 组；所有生成/编辑入口只回写 URL 组；落盘失败**禁止**把内嵌媒体降级写持久化。直治 `blob:` 散落（51 文件）与静默吞/SSOT 第二份。→ 登记 **TD-02-新（中）**（后确认为 **TD-02-44**）。
   > ⚠️ **【TD-02-44 已改判非债 · 2026-09-16 复检】** 本条**前提不成立**，勿据此施工。取证：① 本仓**已有唯一落盘边界** —— `filesApi.ts` 导出 13 个落盘函数（`uploadFileToLocal`／`saveInlineToLocal`／`showThenPersistInline`／`saveResultToTasks`／`persistUrlToUploads`／`downloadRemoteToLocal`…），文件头明写"唯一下载入口，禁止调用方另写"（`filesApi.ts:405`）；② grep 实测 `createObjectURL`／`toDataURL` = **30 文件（非 51）**，且多为**编辑器本地预览**（videoEditor／director3d 的 canvas 预览）而非落盘；③ "落盘失败回退内联"是**有意设计**（CLAUDE §5.4.9 已登记为唯一实现，统一降级 = 不阻断不回滚）。详见 `00-跨区-借架构机会16债复检-真债与假需求-2026-09-16.md §二A`。
2. **结构化撤销（快照只结构字段）** — plans/2026-07-24。把 `CanvasSnapshot` 改为结构相等判定（节点 ID/type/parentId、连线端点、分组成员），undo/redo 对现存节点保留当前位置/尺寸/普通数据，仅恢复结构字段；提交跳过结构相同的快照。治过捕获导致的意外回退与快照膨胀。→ 登记 **TD-04-31（中）**。
   > ⚠️ **【TD-04-31 状态：真债保留但须问用户 · 2026-09-16 复检】** 取证确认：`historyStack.ts:17` + `CanvasSnapshot = { nodes, edges }`（`App.tsx:455-461`）确为**全量快照**（含 `position`／`width`／`height`／普通 `data`），撤销过捕获**属实**。**但"改撤销粒度"改变的是用户能做的事（撤销一次退多少）= 业务能力变化** → 须走 Step 5 摆选项交用户拍板，架构师不得自行改。
   > ✅ **【TD-04-31 已解决 · 2026-09-17 · 用户裁定完全版】** 用户拍板：**按对方原版做完全版结构化撤销**（只存结构字段、撤销不回退位置/尺寸/内容），不做"只降内存保行为"的折中版。落地：新建 `base/canvas/structuralSnapshot.ts`（结构快照提取/判等/应用的**唯一物理位置**）+ `useCanvasHistory` 栈泛型改 `StructuralSnapshot` + undo/redo 改「以当前画布为底做结构增删」。取证补充：`history.record` **本就只在结构操作调用**（addNode/deleteNode/rename/copy/group/ungroup），拖动位置与改内容从不 record ⇒「只有结构变化才入栈」已天然满足，本债补齐的是**栈内快照形状与恢复语义**。详见 `04-跨区-TD04-31结构化撤销收口-2026-09-17.md`。

## 四、第二类：对架构有启发（战略/纪律，可直接内化 SOP）

- **阻塞标 `[!]` 不得静默跳过安全/权限/持久化/恢复**（history 归档）→ 固化进我们"架构师改码 7 步法"的阻断处理（呼应 doc 53/72 静默吞治理）。
- **回滚三不**：不降级 DB 版本、不删用户历史、不放松安全策略 → 通用升级/回滚伦理。
- **日志脱敏 + 记忆数据最小化**（密钥/路径/敏感正文不进日志与记忆）→ 我们密钥日志已守，但"记忆/导出"层可加 `sanitize` 闸（与 TD-01-14 凭据线同线）。
- **流式参数不得触发执行 / 工具 schema 禁止未知字段** → Agent/Canvas 工具边界严格化（呼应 TD-14-1 能力暴露）。
- **成功步骤幂等不重复付费、失败不自动重试** → 批执行/链路口径（呼应 ADR 0001）。
- **组件内禁止直接改 store（经 Store Action）** → 我们仅 `App.tsx`/`ErrorBoundary.tsx` 两处 `setState`，整体守得不错，写入规约固化即可（呼应 TD-04-30 绕过入口）。
