## 二、TD-04-14 收口实证（方案 A，2026-09-12 已解决）

**根因**：group 早年用 `data.name` 显示名，其余节点用 `data.label` → `useNodeRename` 无法复用，group 改名走 `App.tsx` 的 `name` 特判分支。属于「字段级特例」末端收敛。

**方案 A（源头收敛）**：把 `data.name` 收敛为全画布通用 `data.label`，复杂度在**数据模型层**死掉，而非在改名弹窗/写回处留 if-else。

**实证（refs 实证 2026-09-12，已落地）**：
```
src/components/nodes/GroupNode.tsx
  · 引入 useNodeRename；显示名 = data?.label ?? data?.name ?? '编组'（读侧 label??name 兼容旧快照）
  · NodeShell 接 onRename={rename}  → 编组现在也能双击/右键改名
src/components/base/canvas/nodeDefaults.ts
  · 删两处 group 特判：expandedWidth/expandedHeight 历史折叠兜底（折叠态已整体下线）
  · data.name 兜底 → label ?? name ?? '编组'
src/App.tsx
  · openRenameDialog / commitRename 不再对 group 走 name 分支，统一写 data.label
  · 读侧 label ?? name 兼容旧档
src/hooks/useNodeRename.ts（既有，无需改）→ 对 group 直接复用，无特例
```
**兼容性**：旧快照 group 用 `data.name` 的，读侧 `label ?? name` 兜底，名字不丢；`nodeDefaults` 重载时自动收敛进 `label`。

**验证**：三文件 lint 全绿；`npm run test:smoke` ALL PASS。

**结论**：`TD-04-14` 已从源头收敛（字段模型统一），非「加补丁」。标记 **已解决 2026-09-12**。

## 三、TD-04-15 深挖（Phase 1–4）

### Phase 1 · 溯源（症状 vs 病根）
症状：VideoProcessNode / Director3DNode 内 `setNodes(ns => ns.map(n => n.id===id ? {...n, data:{...n.data, ...patch}} : n))` 手写样板。
病根：**不是「不能用 setNodes」**（`patchNodeDataById` 内部也是 `setNodes`）——而是「节点内部不该再手写这坨不可变局部更新样板」。唯一写回入口 `patchNodeDataById` 早已存在（被 `useNodeRename` / `useNodeExpanded` / `App.patchNodeData` 复用），这两节点**没迁**，是历史样板残留（当时 patchData 还没收口，迁改半途）。若需求撤回「节点要写 data」，这坨代码毫无存在价值 → 是喂症状的残留，确为债。

### Phase 2 · 定海（不变式）
- **不变式**：节点 data 的「不可变局部更新」语义（浅 spread + 按 id 命中）只有一个实现真源 = `patchNodeDataById`（`src/hooks/useNodeData.ts:13`）。
- **SSOT**：节点 data 写回入口唯一；手写样板 = 第二份真相（若将来 patch 语义升级——加不可变校验 / 接 history 钩子 / 加 dev 告警——手写处不跟随）。

### Phase 3 · 切割（Depp Module / 唯一实现）
- 唯一实现已就绪：`useNodeData(id).patchData`（`useMemo` 防抖实例）/ `patchNodeDataById(setNodes, id, patch)`（纯函数，跨节点写也适用）。
- Director3D 95/175 行是「写**别的**节点 data」（`boxId`/`targetId`），`patchNodeDataById(setNodes, otherId, patch)` 完全适配，不需裸 `setNodes`。
