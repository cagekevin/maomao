## 四、localTool 的 7 处断言：逐处修复（用户裁定「不建闸，修代码」）

| # | 位置 | 旧写法 | 新写法 | 为什么这样修（不是删掉断言了事） |
|---|---|---|---|---|
| 1 | `utils/netProxy.ts#proxyResponse`（3 处） | 对象字面量 + 双重断言伪装 `Response`；`body` 用 `Readable.from()` 冒充 Web 流 | `new Response(bytes, { status, statusText, headers })` | 手写 mock **本身就是 bug**：`passthrough` 拿到它后调 `.body.pipeTo()`，而 Node Readable 没有该方法。真 `Response` 的 body 是真 Web 流，`bodyUsed`/`clone()`/`bytes()` 由平台保证，零断言。附带处理：204/205/304 按规范必须空 body（构造器会对非 null body 抛错）；1xx 不是 fetch 可表示的终态 ⇒ 兜底 502；`Buffer` 的 backing store 是 `ArrayBufferLike`，不满足 `BodyInit` ⇒ 拷进普通 `Uint8Array`（响应体本已整体缓冲，量级不变） |
| 2 | `routes/passthrough.ts:222` | `req as unknown as ReadableStream` | `Readable.toWeb(req)` | Node 官方适配器。旧写法运行时把 `IncomingMessage` 当 Web 流传，`getReader()` 不存在 —— 与 #1 是同一类「断言掩盖了类型不成立」 |
| 3 | `ai-relay/providers/lovart/lovart_client.ts:166` | 内联复刻了一遍信封剥离 + `as any` | 复用 `parseEnvelope(json, UPLOAD_FAILED, '上传失败')` | 该文件其它接口本来就走 `parseEnvelope`，上传路径是**第二份实现**。改成参数化 `errType`，错误分类仍是 `UPLOAD_FAILED`，同时消掉 13 行重复 |
| 4 | `db/database.ts:451/468`（2 处） | `stmt.bind(params as any[])` / `db.run(sql, params as any[])` | `stmt.bind(params)` / `db.run(sql, params)` | `db` 形参本身是 `any`（**sql.js 不带类型声明**）⇒ 这两处转型是**空操作**，只是让"我在做类型转换"看起来成立。删掉行为不变；真正定型需要装 `@types/sql.js`（要动依赖，未做） |
