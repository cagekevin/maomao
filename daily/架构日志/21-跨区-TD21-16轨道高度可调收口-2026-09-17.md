## §二 · 正确形态（Step 3/4 复核）

### 做法：倍率制，不是绝对像素

- **真相归属**：轨道基准高度是 `TRACK_HEIGHTS`（分类型常量）**单一真源**；
  用户可调的只是**倍率** `TTimelineViewState.trackHeightScale`（与 `zoomLevel` 同一真源、同一持久化）。
- **为什么不存绝对像素**：Video 60 / Text 25 / Audio·Sticker 50 基准各不同 —— 存倍率才能让
  「同一次拖拽」按各类型**等比缩放**；且将来改基准不会让存量视图失真。
- **缺省 = 1** ⇒ 与「不可调」时代**完全一致**，存量工程零回归。

### 唯一入口

`getTrackHeight({type, scale})` 是**唯一高度入口** —— 渲染 / 拖拽命中区 / 累计高 / 总高**全走它**，
**禁止直连 `TRACK_HEIGHTS`**（否则"显示按倍率、命中按基准"会错位）。
边界判据收口 `clampTrackHeightScale` **一处**（非法输入退 1，**不静默取边界**）。

## §三 · 本轮施工（补完半成品）

**病灶**：`TimelineTrackContent` 已接收并下传 `trackHeightScale`，但下游三层**没接**：

```
TimelineElementProps        ← 缺 trackHeightScale
  └ TimelineElement         ← 缺解构
      └ ElementInner        ← 缺透传
          └ ElementContent  ← 缺 scale，line 460 getTrackHeight({type}) 未传 scale
```

**修复**（4 处 props 线程 + 1 处判据）：

| 位置 | 改动 |
| --- | --- |
| `timeline-element.tsx` `TimelineElementProps` | 加 `trackHeightScale?: number` |
| `TimelineElement` 解构 | 加 `trackHeightScale` |
| `ElementInner`（props + 解构） | 透传 |
| `ElementContent`（props + 解构） | 透传 |
| `ElementContent` 胶片条高度 | `getTrackHeight({type})` → `getTrackHeight({type, scale: trackHeightScale})` |

> **最后一条是真 Bug**（不只是类型补齐）：不传 `scale` 时，轨道变高了、**胶片条仍按基准高度渲染** → 错位。

**新增测试**（`tests/unit/trackHeightScale.test.ts` · 5 例行为断言）：
