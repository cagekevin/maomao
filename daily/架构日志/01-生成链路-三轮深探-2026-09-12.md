# 01 生成链路 · 三轮深探（能力不对等 + 爆炸半径实证）· 2026-09-12

> 关联：二轮深探（TD-01-8 立根因债）。本轮目标：把根因钻透——合约真源到底几处？任务中心方法能否被非 React 复用？第二入口是「重复」还是「能力不对等」？文本第三形态规模？抽 `runGenerationContract` 的爆炸半径与可行性。**本轮只登记债务，不改源码。**

## 一、实证（refs + 读源码）

### 1.1 合约真源严格 2 处（非 3 处）
- `reportGenerate` 调用方全库仅 **2**：`src/hooks/useNodeGeneration.ts:228`（React 入口）+ `src/components/scriptbox/scriptBoxEngine.ts:506`（非 React 第二入口）；定义 `src/components/base/store/taskStore.ts:215`。
- `src/hooks/useGenerateNode.ts:155` 仅 `useNodeGeneration({...})` 委托，**未重复**合约序列（它是干净适配层：provider/model/默认回填/ctx 注入/useSyncNodeData 收编）。
- `grep reportGenerate|saveResultToTasks|generateImage|generateVideo|patchData` 在 `src/components/director3d` → **0 命中**：3D 模块零接触任务中心，抽 contract 不影响。
- 结论：合约真源 = 2，与二轮一致；`useGenerateNode` 是适配壳非债。

### 1.2 任务中心原子方法 framework-agnostic（可被非 React 复用）
- `reportGenerate`（`taskStore.ts:215-309`）返回的 `TaskController.progress/done/fail` 仅操作内存 `tasks` + `persist` + `publishTaskCompleted`（eventBus）。**纯 TS、零 React import**。
- 故抽 framework-agnostic `runGenerationContract(opts)` 可行：两入口都能调用，合约不必寄生 React。

### 1.3 第二入口不是「重复」而是「能力不对等」（核心深化）
- **recover 订阅不对等**：`subscribe('agent:task-completed', handler)` 全库唯一在 `useNodeGeneration.ts:393`（刷新/跨实例后把 `resultUrl` 自动写回 `node.data[resultKey]`）。`scriptBoxEngine` 资产图路径（506-617）**完全不订阅** → 剧本盒资产图任务完成后，刷新/其他实例无法经任务中心广播自动恢复显示（hook 侧有、scriptBox 侧无）。
- **abort 语义不对等**：`useNodeGeneration.start` 有真中止（`abortRef` + `stop`，line 358-361，abort 传到 imageApi/videoApi 中断 fetch/轮询）；`scriptBoxEngine.ts:524` 注释「用户要求停止不做——不传 AbortSignal、无中止分支」→ 第二入口生成中不可取消。
- 结论：TD-01-8 从「重复」升级为「重复 + 能力不对等」。抽 contract 必须把 **recover 订阅 + abortable 开关内聚进合约**，否则第二入口永远缺这俩能力。

### 1.4 文本第三形态泛滥（绕任务中心）
- `chatCompletions` 全库 8 处：scriptBoxEngine 5（353/770/931/1042/1507）+ TextGenerate:210 + agent runtime:149（无关）。其中 scriptBox 4+ 处（353/931/1042/1507 + 770 分镜提示词）走 `enqueuePatch` 直接写剧本 `shots`/内部字段，**不经任务中心** → 无进度/完成广播/recover。
- 落点差异：文本类结果落 `shots` 而非 `node.data[resultKey]`，故第三形态本质是落点不同；但「无任务中心可视化」是体验/一致性债。

## 二、深化债登记

### TD-01-8（升级：根因债，从「重复」→「重复 + 能力不对等」）
- **现象/证据**：合约序列（report→progress→run→save→done/fail→recover 订阅）嵌 React hook `useNodeGeneration`，致非 React `scriptBoxEngine` 手写重复（资产 506-617≈115 行）+ 缺 recover/abort 两能力；文本第三形态绕任务中心（1.4）。
- **爆炸半径实证**：合约真源严格 2 处；`useGenerateNode` 干净适配壳；`director3d` 0 接触；任务中心原子方法纯 TS 可复用（1.2）→ 抽 contract 仅动 2 入口，可行性高。
- **根因**：复杂度未源头收敛——合约天生含 React 态订阅（recover），被锁进 hook，非 React 入口只能手写且天然缺该能力。
- **设计要点（登记不实施）**：抽 `runGenerationContract(opts)`，固化 6 步序列，opts 参数化 `recoverPatcher`(hook=patchData/node.data；scriptBox=commit 闭包) + `abortable` + `resultKey` + `recoverable` + `retryable`；recover 订阅内聚进合约→顺修 TD-01-9。`useNodeGeneration` 退化薄壳（持 `useNodeRuntime` 瞬态 + `useEffect` 订阅 + Abort），`scriptBoxEngine` 两处改 ≈15 行调用。
- **防回潮**：`check:arch` 加规则「第二入口不得手写 `reportGenerate`+`saveResultToTasks` 合约序列」（AST 检测同文件出现即违规）。
- 归类：还债（源头收敛·设计+重构）；利息：中；状态：**待翻新（三轮已实证爆炸半径 + 任务中心纯 TS + 能力不对等 3 项 + 设计要点已立；待用户拍板抽 `runGenerationContract`）**。

### TD-01-9（新：recover 能力不对等——独立可见缺陷）
- **现象**：scriptBoxEngine 资产图（506-617）不订阅 `agent:task-completed`，刷新/跨实例后资产结果无法自动恢复显示；hook 侧有（393）、scriptBox 侧无。
- **证据**：`subscribe('agent:task-completed')` 全库唯一 `useNodeGeneration.ts:393`；scriptBoxEngine 内 0 订阅。
- **归类**：还债（即使不抽 contract 也应先补——TD-01-8 未收敛导致的单边能力缺失）。
- **利息**：中（刷新丢图体验；但脚本盒 data 经 `commit` 落库，刷新后脚本盒自身能恢复，仅「跨实例/任务中心面板恢复」缺失——脚本盒 data 持久化范围待确认）。
- **状态**：待还（随 TD-01-8 抽 contract 一并修；单独修则 scriptBox 侧补 `subscribe` + `commit` 回填）。

### TD-01-10（新：abort 语义不对等）
- **现象**：hook.start 有真 abort（stop→abortRef，358-361，abort 传 imageApi/videoApi 中断 fetch/轮询）；scriptBoxEngine 资产图（524 注释）「用户要求停止不做——不传 AbortSignal、无中止分支」，生成中不可取消。
- **证据**：`useNodeGeneration.ts:358-361` vs `scriptBoxEngine.ts:524`。
- **归类**：还债（不对等；属 contract 抽出后 `abortable` 开关的论证来源）。
- **利息**：低（剧本盒资产图无中止——用户曾明确「停止不做」，但属「缺失能力」非「文档化有意设计」；若后续要中止则必补）。
- **状态**：待裁定（是否补中止；补则随 TD-01-8 `abortable` 开关）。

### TD-01-11（新：文本/提示词类生成绕任务中心——第三形态泛滥）
- **现象**：scriptBoxEngine 内 chatCompletions 4+ 处（353/931/1042/1507 + 770 分镜）走 `enqueuePatch` 直接写剧本 data，不经任务中心 → 无进度可视化/完成广播/recover。
- **证据**：`chatCompletions` grep 8 处，scriptBox 占 5；文本类落点非 `node.data[resultKey]` 而是 `shots`/内部字段。
- **归类**：持平（文本类落点不同，本就不该走资产合约——合理；「无任务中心可视化」是体验债）。
- **利息**：低。
- **状态**：待裁定（评估 contract 以 `patcher` 回调统一文本/资产两类——文本类 patcher 写 shots、资产类写 `node.data[resultKey]`；或维持「文本类不上任务中心」有意为之仅文档化）。

## 三、复杂度归位结论（回应「把复杂度放对位置」）
- **错配点**：合约序列（含 recover 订阅）嵌 React hook → 非 React 入口只能手写且天然缺 React 态订阅能力。
- **正确位置**：framework-agnostic `runGenerationContract`（协议层），参数化 `recoverPatcher` + `abortable` + `resultKey` + `recoverable` + `retryable`。固化 recover 订阅进合约→顺修 TD-01-9。
- **度量**：改 done→save 顺序/recover 行为 → 改动半径 2 文件→1 文件；合约真源 2→1；形态 3→1+开关。
- **防回潮**：`check:arch` 加规则禁第二入口手写合约序列。
