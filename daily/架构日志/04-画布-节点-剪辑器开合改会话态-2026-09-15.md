# 04 · 画布 · 剪辑器开合改为会话态（2026-09-15）

> **触发**：用户报「现在默认我打开画布，Video editor 就打开了。我要点按钮才能打开，
> 不能默认就把它打开。」
>
> **处置**：先取证 → 判定根因是**设计错误**（不是值错了）→ 把这个状态**迁出持久化设置**。

---

## 一、根因：不是"值错了"，是"它根本不该被持久化"

`videoEditorOpen` 原先登记在 `settingRegistry` 的 `app_settings` 里：

```ts
{ key: 'videoEditorOpen', type: 'boolean', default: false, ui: false, ... }
```

而 `app_settings` 这个键**整键持久化 + 随云端同步**（`contracts.ts` 的 `app_settings` 条目明写）。
后果是一条完整的错误链：

1. 用户打开一次编辑器 → `setSetting('videoEditorOpen', true)` → **写盘 + 同步云端**
2. 刷新页面 → `appSettings.load()` 读回 `true` → **编辑器自动打开**
3. 还会**同步到其他设备** → 在新设备上凭空弹出编辑器

用户报的"一打开画布 Video editor 就开着"，就是第 2 步。

**注意**：默认值本来就是 `false`，所以"改默认值"这条路无效 ——
脏的是**已被持久化的那个 `true`**，以及"它会被读回来"这个机制本身。

## 二、判据：什么该进设置、什么该是会话态

| 类别 | 例子 | 刷新后 | 该持久化吗 |
| --- | --- | --- | --- |
| **用户偏好** | `minimapOn` · `performanceMode` · `debugOn` · `thumbnailOn` | 保持 | ✅ 是 —— "刷新后仍生效"正是用户想要的 |
| **界面开没开** | 剪辑器展开 · （同类的 `agentOpen`） | 应回默认 | ❌ **否** —— 用户从没表达过"我要它永远开着" |

**判据一句话**：*用户主动选择的一种长期状态* → 设置；*一次开合动作的即时结果* → 会话态。
持久化后者，只会把"上次不小心留着"变成"**永远弹**"。

**仓内既有先例**：整个 `modalLayer`（全屏模态层登记表）从设计起就是**纯会话态、从不持久化** ——
同一个道理（都是"层开合"）。剪辑器的开合与之同族。

## 三、改动

### 新建 `base/core/editorSession.ts`（会话态，唯一真源）
与 `modalLayer.ts` **同构**（模块级状态 + 查询式读 + 订阅式通知），但**明确不持久化**：

| 出口 | 用途 |
| --- | --- |
| `isEditorSessionOpen()` | 查询式 —— 快捷键在执行前问一次（`isEditorActive()` 用） |
| `subscribeEditorSession(fn)` | 订阅式 —— 给把"开关本身"声明成 props 的宿主（React Flow `deleteKeyCode`） |
| `setEditorSessionOpen(bool)` | 唯一写入口 |

### 接线
- `App.tsx`：`videoEditorOpen` 由 `useAppSettings()` 改为 `useSyncExternalStore(subscribeEditorSession, isEditorSessionOpen)`；
  2 处 `setSetting('videoEditorOpen', …)` → `setEditorSessionOpen(…)`
- `modalLayer.ts`：`isEditorActive()` 由 `getSetting('videoEditorOpen')` → `isEditorSessionOpen()`，
  **断掉 `core → store/appSettings` 的依赖**
- `settingRegistry.ts`：删掉该设置项（连带死 import `Film`）
- `contracts.ts`：`app_settings` 的 note 去掉 `videoEditorOpen`，并注明已迁出与去处

### 存量脏值
存储里那个 `videoEditorOpen: true` **不动**（已读不到 = 无害）。
**不加"启动时删除"的迁移代码** —— 那是在为一个已死的字段增加代码。
`contracts.ts` 的 note 已记明它已迁出；将来若有人清理 `app_settings` 的键，顺手即消。

## 四、度量

| 口径 | 改前 | 改后 |
| --- | --- | --- |
| 该状态的持久化 | 写 localStorage + **随云端同步** | **不落任何存储** |
| 刷新后行为 | 保持上次（→ 永远自动开） | **回默认（关）** |
| 跨设备影响 | 会同步过去 | **无** |
| `core/` → `store/appSettings` 依赖 | 1 条（`isEditorActive` 读设置） | **0**（改读同族会话态） |
| 该状态的写入口 | `setSetting`（任意处可写） | **`setEditorSessionOpen`（唯一）** |
