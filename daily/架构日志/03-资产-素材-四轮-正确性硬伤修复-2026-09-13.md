# 03 区 · 四轮（实施轮）— 正确性硬伤修复：6 债全清

> 三轮审计（2026-09-12）落盘 7 债待还，其中 **TD-03-7/8 为正确性硬伤**。本轮实施修复，**6 债全清**（TD-03-11 已在 02 区十三轮修）。
> 心法依据：§零.4（正确性 > 复杂度）；铁律 2（诚实——失败不得伪装成成功/错误结果）；§一.2（源头收敛）。

---

## 一、溯源（Phase 1）：7 债其实是**一个母体**

把三轮登记的 7 债并列，看到同一个病：

| 债 | 现场 | 本质 |
| --- | --- | --- |
| TD-03-7 | `if (!ok) fs.copyFileSync(...)` | **失败 → 伪造一个"成功"的输出**（原图当缩略图） |
| TD-03-8 | `ext: path.extname(saveName)`（mimeType 手边有却不用） | **输入不全 → 用残缺输入产出残缺结果** |
| TD-03-9 | `sha1(base64文本)[:16]` vs canonical `sha1(bytes)` | **同一内容两个物理名**（命名权威分裂） |
| TD-03-10 | 注释称"DB 唯一约束"（已被 DROP） | **注释声称一个不存在的保证** |
| TD-03-11 | `res.json().catch(()=>({}))` | **失败 → 清空真实报文**（已在 02 区十三轮修） |
| TD-03-12 | `e instanceof TypeError` 无差别当网络错 | **代码 bug 被伪装成网络故障** |
| TD-03-13 | filesApi 失败 return null 无信号 | 设计权衡（维持登记） |

**母体判词**：**「不完整的输入 / 失败的信号」被兜底加工成「看似成功的输出」。**
这正是 02 区十二轮在存储层治过的同一个病（失败语义不诚实），只是这里发生在**文件落盘层**。

→ 修复原则统一为：**让失败原样暴露，让信息物尽其用**（不用手边的 mimeType 是浪费；把失败加工成假成功是欺骗）。

## 二、定海（Phase 2）：先确认契约，再动手

- `resizeImage` **返回值契约不改**（`Promise<boolean>`）：它有**三个调用方**，其中 `resolveLocalImages.ts`（图生图参考图压缩）用 `boolean` 是**正确语义**（失败保留原图 = 诚实降级）。
- **病在两处缩略图调用方**——它们把 `false` 加工成"复制原图假装成功"。
- 故修法：**不动 `resizeImage`，改两处调用方**（这才是把复杂度放在正确位置）。

## 三、切割（Phase 3）：逐债修复

### TD-03-7｜不再伪造缩略图

| 调用方 | 修前 | 修后 |
| --- | --- | --- |
| `tryGenerateThumbnail`（上传/下载自动缩略图） | `if (!ok) fs.copyFileSync(filePath, thumbPath)` | `if (!ok) { warn; return null }` → 前端用原图 URL（**缩略图是优化非前提**的正确表达） |
| `handleThumbnail`（显式缩略图端点） | 同款 copyFileSync | `return sendError(res, 'Thumbnail generation failed', 500)`（**显式失败**，前端 `onError` 回退原图） |

### TD-03-8｜扩展名回退链（两入盘路径）

```ts
// multipart（handleUploadFormData）
const ext = path.extname(saveName) || mimeToExt(fileData.mimeType) || '';
// 远程（doSaveRemoteUrl）：原来 mimeToExt(mime) || '' → 补 URL 路径后缀再试
const ext = needsExt
  ? mimeToExt(mime) || path.extname(new URL(fileUrl).pathname) || ''
  : path.extname(stableName);
```

### TD-03-9｜命名统一为 canonical

`saveBase64ToFile`：`sha1(base64文本)[:16]` → `contentHashName(sha1(bytes), ext)`
（与 `writeUploadBuffer`/`writeUploadDedup` 同口径：同字节 → 同物理名）。

### TD-03-10｜注释更正为真实机制

「DB contentId 唯一约束」→ 「content-hash 文件名写入幂等 + `inflightDownloads` 并发锁」（`database.ts:330` 已 DROP 该索引）。

### TD-03-12｜TypeError 诚实分类

新增 `isFetchNetworkTypeError(e)`：**只认各引擎 fetch 网络失败的固定文案**
（`Failed to fetch` / `NetworkError when attempting to fetch resource.` / `Load failed` / `fetch failed` / `Network request failed`）。
代码 bug 的 TypeError → **原样上抛、不重试、不重分类**（保留 stack）。
