# 08-跨区-文件 URL 查询串口径错位横展（2026-09-16）

> **触发**：用户要求「从历史已有债务深入推导，未登记 没有被发现的债务」。
> **方法**：取现有债中两条相关母体 —— ① 前端 `assetType` 查询串剥离根因（`assetType.ts:61` 注释记载 `a.mp4?token=1` 误判旧案）② `TD-02-6` 把「`/files/` URL → 磁盘相对路径」收口为 `orphanGc.toUploadRelPath` 唯一实现 —— 反向横推 localTool 出站 / 回收侧解析是否仍与「剥查询串」口径一致；自底向上取证。
> **结论一句话**：localTool 内两套 `/files/ → 磁盘路径` 解析（`resolveLocalImages.resolveLocalPath` + `orphanGc.toUploadRelPath`）均未剥 `?query`/`#fragment`，与同仓静态服务（`handleStaticFile` 走 `pathname`）、入库正则（`extractFilesUrls` 止於 `?`）、前端 `assetType`（已剥）口径错位；且 `resolveLocalPath` 私自重实现、绕过 `TD-02-6` 已收口单实现。共 1 母体债（TD-08-16，双症状），其余同源点判非债 / 已饱和。

## 一 · 链路快照（本轮实证 · grep / refs）

- `resolveLocalImages.ts:35` `SELF_FILE_URL_RE = /^https?:\/\/(?:127\.0\.0\.1|localhost|::1)(?::\d+)?(\/files\/.*)$/i` —— 捕获组 `(/files/.*)$` **含 `?query`**。
- `resolveLocalImages.ts:40-53` `resolveLocalPath`：`rel = u.slice('/files/'.length)` 取裸 URL 剩余（**含 query**）；仅 `decodeURIComponent`，**不剥 `?`/`#`**；`fs.existsSync` 落空 → 返回 null → URL 原样透传。
- `orphanGc.ts:45` `toUploadRelPath`：`url.match(/\/files\/(.+)$/)` 贪婪 `(.+)` **含 `?query`**，未剥。
- 对照（已对齐 · 非债）：
  - `index.ts:177-188` `handleStaticFile` 用 `urlPath` = `url.pathname`（**自动排除 query**）✅
  - `base64Externalize.ts:197` `extractFilesUrls` 正则 `/files/([^"'\s)\]]+)/g` 遇 `?` 即止 ✅
  - `assetType.ts:61` `classifyAssetUrlKind`：`lower.split('?')[0].split('#')[0]` 已剥 ✅

## 三 · 定海（应守的不变量）

localTool 任意「`/files/` URL → uploads 磁盘相对路径」解析必须：① 与静态服务 / 入库 / 前端一致地 **剥 `?query`/`#fragment`**；② 经 `TD-02-6` 收口的 `toUploadRelPath` **唯一实现**，禁私自重实现。

## 四 · 切割（在哪破）

- **破点 1**：`resolveLocalImages.resolveLocalPath`（`resolveLocalImages.ts:38-54`）自持解析、未调 `toUploadRelPath`（**第二份**，绕过 `TD-02-6`），且 `u.slice('/files/'.length)` 连同 `?query` 一并进磁盘路径；`SELF_FILE_URL_RE`（line 35）捕获组含 query。
- **破点 2**：`orphanGc.toUploadRelPath`（`orphanGc.ts:45`）`/\/files\/(.+)$/` 贪婪含 query，未剥；虽是 `TD-02-6` 唯一实现，但自身未剥查询串。
- **对照（已对齐，非债）**：`handleStaticFile`（`index.ts:177-188`）走 `pathname` ✅；`extractFilesUrls`（`base64Externalize.ts:197`）正则止於 `?` ✅；`assetType`（`assetType.ts:61`）已剥 ✅。

## 六 · 结论

**母体债 TD-08-16**：localTool 两套 `/files/ → 磁盘路径` 解析未与「剥查询串」口径对齐，且 `resolveLocalPath` 私自重实现绕过 `TD-02-6` 单实现。双症状同源：

1. `resolveLocalImages.resolveLocalPath` 不剥查询串 → 带 `?query` 的 `/files/` 图在出站 base64 内联时 `fs.existsSync` 落空、参考图退化为原 URL（AI 读不到本机图，图生图静默退化）；虽 `console.error` 留痕，但链路已退化。
2. `orphanGc.toUploadRelPath` 不剥查询串 → 带 `?query` 的引用 URL 解析出的相对路径含 query，与磁盘真实文件名不匹配 → 该文件被误判为孤儿、有被 `runReferenceGc` 真删风险（数据丢失，比 ① 更重）。

同源已对齐点（`handleStaticFile` / `extractFilesUrls` / `assetType`）判非债、维持现状；本轮不重审。
