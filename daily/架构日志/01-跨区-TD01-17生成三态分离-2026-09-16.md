## 一、债描述 vs 取证真相

> **TD-01-17（中）**：生成未分「生成成功/取消/保存」三态，保存失败静默退化为再次生成，缺统一 `generationRuntime`。
> 对方：ADR 0005 §48「生成成功但项目落盘失败时保留原始结果地址，并把『生成成功』和『保存失败』分开报告」。

**取证**（A1/A2：先读真实代码）：

| 债描述断言 | 取证真相 | 裁定 |
| --- | --- | --- |
| 「未分三态」 | **成立**：`generationContract.ts` 只有 `done`（completed）/ `fail`（failed）/ abort 三分支；**没有「生成成功但保存失败」态** | 属实 |
| 「保存失败静默」 | **成立**：`generationContract.ts:138-142` 落盘失败走 `.catch(→null)` + `reportDegrade({layer,key,e})`（**无 `toast`**）→ 用户不可见 | 属实 |
| 「退化为再次生成」 | **不成立**：全仓 grep 无「保存失败 → 触发重生成」路径（`registerTaskRetry` 删除于 2026-09-12）。真实形态是**假成功**：`taskCtl.done(finalUrl)` 用**原始（可能临时）URL**标 `completed`，用户以为成功 | **描述需修正** |

## 三、Step 1 证伪 —— 真债成立（有实害）

**三问**：

### ① 根因证据：有可复现的「假成功」
- 落盘失败时 `taskCtl.done(finalUrl)`（`finalUrl` = 原始 URL，可能是 `blob:` / 上游临时 http）→ 任务中心标 **`completed`**，节点显示该 URL。
- 用户**以为已保存**；刷新后 `blob:` URL 失效 / 上游 URL 过期 → 结果消失，**无任何提示**。
- 落盘失败仅 `logger.warn`（`reportDegrade` 无 `toast`），**用户不可见**。

### ② 替代方案：现状**不**足够
- 「`null` 兼两义」使调用方**无法**区分「无需保存（blob: 本地预览）」与「保存失败」—— 正是 M1「结果契约缺位」的使能根因。
- 同模块 `persistUrlToUploads` 已证明正确形态存在（判别联合）→ 属**收口**，非新造。

### ③ 决策者的选择
- **契约形状**（判别联合）+ **失败可见**（保留 URL + 用户可见提示）→ 改完用户**能做的事不变**（仍看到结果），只是**不再被误导** → **架构师可直接定**（Step 5）。
- **新增 TaskStatus `'save-failed'` 态**（任务中心第三态 UI）→ 改变用户可见状态机 → **本债不要求**（债要的是「分开报告」而非「新增状态机」），**不做**（避免范围膨胀）。

### 致命一问
> **「我加了这个，用户/系统能多做哪一件原来做不到的事？」**
> **答**：用户从「以为保存成功、刷新后才发现丢失」变为「**当场看到『已生成，但未能保存到本地（结果地址保留）』**」→ 可立即**重新保存 / 复制结果 / 排查本地服务**。系统从「假成功」变为「诚实降级」。**真债成立。**

## 四、Step 3/4 —— 定位与契约

**定位**：判据属**文件域**（`filesApi` = 全站文件域单点），沿用同模块已有的 `PersistOutcome` 判别合同族（不新造类型、不新建模块）。

**契约（三问定契）**：
1. **成功信号诚实**：`saveResultToTasks` 返回判别联合，区分三态——
   - `{ ok: true, url, skipped: true }` — 无需落盘（blob: / 已是本机 /files/）
   - `{ ok: true, url, skipped: false }` — 落盘成功（新持久 URL）
   - `{ ok: false, reason, message? }` — 落盘失败（**保留原始 URL 供调用方降级**）
2. **错误在哪炸开**：落盘失败**不抛**（保持既有「不阻断主流程」语义），但**必须用户可见**（`reportDegrade` 带 `toast`）——「不抛」是动机，「零信号」才是病。
3. **失败可见性给对读者**：用户 → `toast`（瞬时动作反馈）；开发者 → `logger`（已有）。
