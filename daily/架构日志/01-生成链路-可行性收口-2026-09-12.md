## 验收前提 A：任务中心原子链是否 framework-agnostic
- `eventBus.ts`：`import { logger }` —— **零 react**；`subscribe`/`publish` 为纯函数（`Map<string, Set<fn>>` 实现，同步调用）。
- `taskCompletionBus.ts`：`import { publish } from '../core/eventBus.ts'` —— **零 react**；`publishTaskCompleted` 纯函数 + 前置校验（status=completed 且 resultUrl 非空才发）。
- `taskStore.ts:20` `import { useSyncExternalStore } from 'react'` —— **仅用于 React 订阅 hook `useTasks`**；`reportGenerate / progress / done / fail / saveResultToTasks` 均为纯函数（直接改内存 `tasks` + fire-and-forget 后端持久化），调用它们**不触发任何 React 渲染**。
- 实证：脚本盒已在纯上下文调用任务中心方法且工作正常——`scriptBoxEngine:506 reportGenerate`、`:580 saveResultToTasks/reportDegrade`。
- **结论 ✅**：任务中心原子链 framework-agnostic，contract 调用它们无 React 依赖。

## 验收前提 B：recover 订阅在脚本盒侧能否真正生效
- `useNodeGeneration:393 subscribe('agent:task-completed', …)` 来自纯 TS `eventBus`（无 react 依赖）。
- 脚本盒引擎 `createScriptBoxEngine` 由 `useScriptBoxEngine:82-84` 在 **React 树内创建**（ref 缓存、跨 render 稳定）；引擎本身纯 TS（`scriptBoxEngine:157` 的 `deps` 注入模式、无 UI 依赖）。
- 因此：把 `subscribe('agent:task-completed', recoverPatcher)` **内聚进 `runGenerationContract`** → 脚本盒调用 contract 时即自动获得订阅能力 → 刷新/跨实例后从任务中心持久 `resultUrl` 恢复显示（**TD-01-9 真修复，非纸面**）。
- **结论 ✅**：recover 订阅内聚进 contract 在脚本盒侧可生效。
