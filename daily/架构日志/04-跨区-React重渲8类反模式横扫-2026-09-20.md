## 六 · 结论

1. **画布重渲的头号放大器不是节点本身，是宿主**：`App.tsx:1494/1504` 两个内联字面量 ⇒ 每次宿主重渲都往
   ReactFlow store 多打一次 `setState`（库级证据 `index.mjs:216/230/318`），全画布 selector 陪跑一轮。
   而 `App.tsx:213-219` 的注释声称这条已修 —— **注释假收口**。
2. **第二放大器是 Context**：`CanvasEdgesContext` 是全仓 12 处 Provider 里**唯一**没 memo 的，且它的
   消费者是画布上的 11 种节点 ⇒ App 每帧 = 全部节点重渲。
3. **`React.memo` 在本仓大面积空转**：20 处调用点把内联 JSX / 数组 / 箭头直接喂给 memo 组件
   （NodeShell icon ×11 最典型），memo 从未命中过。这是最大的**母体**（M1）。
4. **三处 hook 写了却没接上**（`App.tsx:444-446`）+ **一处 useMemo 写了却没人用**（`Director3DNode.tsx:43`）
   —— "写了等于没写"，比不写更贵（读者误以为已优化）。
5. **0 命中**：类别 4（组件内定义组件）全仓 0 命中；类别 8 的"渲染期 DOM 读写"与"未 memo 大数组计算"在重点区 0 命中。
6. **无一处构成无限重渲死循环**：已逐点取证 `getSnapshot` 返回值引用稳定（`appSettings.settings` /
   `nodeRuntime.DEFAULT_STATE` / `SelectionManager.visibleElements` / `use-editor.versionRef`）。
