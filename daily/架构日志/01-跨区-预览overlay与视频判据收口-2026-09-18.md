## 三 · Step 3 定位

- **判据归属**：「这条素材是不是视频」的真相在**媒体类型目录**（`assetType.ts` 的扩展名表 / mime 前缀）⇒ 判据定义在 `assetType.ts`，
  面板只**委托**。**不是**让每个消费方各写一份内联（那正是本债成因）。
- **预览归属**：两块面板预览的是**同一形状的 `ResourceItem`**、同一份 UX ⇒ 真相在「资源预览」这一层，
  故新建 `panels/ResourcePreview.tsx`（与 `TaskCenter` 的 `Task` 域**不同形状**，见 §六-2）。
- **改动半径**：源 4 文件（2 面板 + `assetType` + 1 新模块）+ 1 新测试；**对外签名零变化**（`ResourcePreviewOverlay` 是新增内部组件，
  两面板的 props / 对外行为不变）⇒ 消费方（画布拖拽、事件总线）零改动。
- **真假接缝判别**：
  - 预览 overlay / `TextPreview` / 视频框 ref+effect = **探测与渲染重复** ⇒ **强制收口**；
  - 视频判据 = 同域**运算重复** ⇒ 收口为纯函数；
  - `TaskCenter` 的 `taskMediaKind` = **不同域**（`Task.type`）的**判据**，与 `ResourceItem.type` 无关 ⇒ **不合并**（合并会造出跨域的第二份真相）。

## 四 · Step 4 定契

```ts
// utils/assetType.ts —— 与 isAudio 同族同形（type 直判 / mime 前缀 / URL 扩展名兜底）
export function isVideoResource(type: string | null | undefined, url: string | null | undefined): boolean {
  return type === 'video' || (!!type && type.startsWith('video')) || classifyAssetUrlKind(url) === 'video';
}

// panels/ResourcePreview.tsx —— 资源预览唯一实现
export function ResourcePreviewOverlay(props: {
  item: ResourceItem | null;
  onClose: () => void;
  assetDragProps: AssetDragProps;   // 由调用方注入（沿用各面板既有的 useResourceCardDragProps）
}): JSX.Element | null
//   · text → TextPreview；audio → 播放器卡片；其余（image）→ 可拖到画布的大图；
//   · video → 委托 ImageZoomDialog（唯一媒体放大原语）；禁止在本组件再写一份判据。
```

**为什么 `assetDragProps` 走 props 而不是组件内调 hook**：两面板的拖拽上下文（`connected` / `onRefreshed`）归各自所有，
组件内再取一次会**反向依赖**面板上下文；且会让既有的**部分 mock**（`GeneratedView.refresh.test.tsx` 只桩了模块内两个导出）当场崩
——与本债第一阶段 `contentSet` 桩同款隐患（见 §七-1）。注入式**接口更窄**，也让组件成为纯展示单元。
