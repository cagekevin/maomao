### 1.1 症状实证：同一条规则，写族遵守、读族背叛

| 函数 | 是否接入守卫 | 与自陈 |

## 二、§二 Phase 2 筑基：`StorageOpResult<T>` 判别联合（不可逆决策，一次到位）

铁律 6：契约形状被下游消费后难改 → 属不可逆 → 慢做、先筑基。落地定义：

```ts
type StorageOpResult<T> =
  | { ok: true; value: T; source: 'kv'; degraded?: false }      // KV 真值
  | { ok: true; value: T; source: 'local'; degraded: true }     // 仅引擎不可用才出现
  | { ok: false; error: 'engine-unavailable' }                  // 网络/超时/5xx
  | { ok: false; error: 'rejected'; status?: number };          // 4xx，必须上抛
```

**铁律（写入文件头 L19-22）**：
- `source:'local'` **仅在引擎不可用**出现；KV 真空是 `source:'kv'` + `value:null`（非降级）。
- 4xx 拒收 → `{ok:false,error:'rejected'}`，**绝不可当作降级/迁移依据**。

### 2.1 新增迁移许可信号（正确性必需）

`contentGetKvWithFallback` 额外返回 `vacated:true` + `fallback`，供「KV 真空 → 一次性迁移」判定：

| KV 状态 | 返回 | 是否许可迁移 |
| --- | --- | --- |
| 命中非空 | `{ok, value, source:'kv'}` | ❌ |
| **真空 + 本地有副本** | `{ok, value:副本, source:'kv', vacated:true, fallback:副本}` | ✅ **唯一许可** |
| 真空 + 本地也空 | `{ok, value:null, source:'kv', vacated:true}` | — |
| **引擎不可用** | `{ok, value:本地副本, source:'local', degraded:true}` | ❌ **禁** |
| **4xx 拒收** | `{ok:false, error:'rejected'}` | ❌ **禁** |

**下游迁移判定铁律**：只认 `vacated === true`；`source:'local'` / `rejected` 一律禁止写回 KV。

### 2.2 内核收口（TD-02-22 顺势结清）

抽 `kvOpMeta(key)` / `withKvTimeout(op,...)` / `kvReadOp(key)` / `kvWriteOp(key,value)` 四个内核原语，
4 处字面复制的样板（`resolveMeta/timeout/keepFallback/sRemove`）收口到一处。读族/写族共用内核，差异由判别联合分支表达。

## 三、§二 Phase 3 切割：消费方改造（影响面实证极小）

`tsc --noEmit` 实测：契约变更**只报 2 处编译错**（均在本轮内修）——证明影响面极小。

| 消费方 | 改造 | 说明 |
| --- | --- | --- |
| `d3dPersistence.hydrateProject` | `from==='local' && value!=null` → 迁移，改判 `res.vacated && res.fallback != null` | **TD-02-25 正确性故障当场堵死** |
| `d3dPersistence.hydrateProject` | 新增 `!res.ok` 分支：4xx 拒收 → 不加载、不降级 | 铁律 2 诚实 |
| `projectStore`（严格族） | **零改动** | 证明严格族消费干净，契约改造不伤它 |

**删除语义修正**（TD-02-25 子类「已删复活」）：`deleteKvWithFallback` 原「成功即 return 不清副本」→ 改为**成功也清本地副本**。理由：`keepFallback=true` 的键（d3d）KV 删除成功后本地镜像残留 → 下次 hydrate 读「真空+本地有」→ 迁移写回 → **已删工程复活**。删除是明确用户意图，保留副本即违背意图（与写入的镜像策略不同）。

## 五、§三 铁律复核

- **铁律 2（诚实）**：4xx 不再被伪装成「引擎不可用」；`rejected` 分支显式暴露；`source:'local'` 不再伪造。
- **铁律 5（不虚构）**：`StorageOpResult` 由**已存在的 5 种异构形状**驱动，非「将来可能用」——是收敛真复用，非假抽象。`vacated` 字段由**已存在的迁移消费方**（d3d）驱动。
- **铁律 6（可逆性）**：契约形状 = 不可逆 → 一次到位；内部实现（内核原语）= 可逆 → 直接抽。
- **§五 自检·真相（SSOT）**：`source` 使「KV 真值 vs 降级副本」在类型层可区分，消除「偷偷创建不同步副本」。
