## 一、Phase 1 探因：剩余债只剩两个母体（不是十六个债）

把 `债务.md` 剩余待还项按「它为什么会产生」归堆，得到：

| 母体 | 一句话本质 | 覆盖债 |
| --- | --- | --- |
| **M-A 失败的"分类出口"没到场** | 失败被 catch 后**没经过任何分类器**就地消失（不是分类错，是分类器没来） | TD-02-16/17/18、TD-03-11/12/13、TD-05-7、TD-06-7 |
| **M-B 唯一入口只在注释里，机器守不到** | 红线写在 JSDoc/CLAUDE，无 AST 闸，绕过零成本 | TD-03-5、TD-12-4、TD-04-23、TD-05-4、TD-12-2 |

**关键判断**：M-A 的病根不是"缺 reportDegrade"，而是**"静默吞"这个动作没有任何机器会拒绝**。
证据=审计时登记 TD-02-16 已写明"改 logger.warn 与同链路对齐"，但**12 天无人改**——因为没有闸。
凡收口无闸必回潮（本仓 02-1/02-12/04-15 四度实证）。故本轮**先落闸，再清存量**。

## 二、Phase 2/3 落地：两道闸

### 2.1 `check:catch` —— 让"静默吞"在写下当轮就编译不过（母体 A）

新增 `scripts/check-silent-catch.mjs`，挂 `prebuild`/`pretest`。

**核心区分（关键设计，非一刀切）**：不能禁所有空 catch——有些是**结构性必需**：
- 锁链防断（`next.catch(() => {})` 保证 locks promise 永不 reject）
- logger 自身防递归（上报失败不能调 logger 报错）
- 浏览器 API 预期不可用（`new URL(data:...)` 抛、`video.load()` 抛、`ImageBitmap.close()` 抛）

故**不用白名单**（白名单=假护栏，本仓已批），而用**显式标记 `// catch-ok: <理由>`**：
标记本身是代码（可查），理由另说。空 catch 无标记 → 违规。

**闸比人眼强（实证）**：人工 grep 以为 37 处，闸实际抓出 **58 处**（跨行块 + `agent/` 目录 21 处人眼漏）——
两次扩展（58→25→4→0）都由闸而非人眼发现遗漏。

**处理结果**：
- **真债 7 处 → 改为留痕**（`reportDegrade`/`logger.warn`）：
  `taskStore:336/686/693`（后端删除/清空失败）、`resourceStore:530`（重扫失败）、
  `projectStore:598`（快照残留）、`relayProxy:189`（取消失败→后端续跑）、`lazyNode:140`（预取失败）。
- **结构性空 catch 51 处 → 加 `catch-ok` 标记**（逐条人工核理由，非机械批处理）。

### 2.2 母体 B 两道闸

**规则 8（`check:arch`）——实现层深路径禁绕行**：
- **裁定（不强行统一，划清真边界）**：审计实测 `base/api/*` 深路径与 barrel **指向同一模块**，
  绕 barrel 不绕过任何实现；且 22 个测试按「模块名 `api/filesApi.ts`」mock 是**既定契约**
  （改 mock barrel 需列全 barrel 导出 → 测试脆弱度↑、收益 0）。故 `base/api/*` 深路径 = 合法契约边界，**不纳规则**。
- 真危险的是绕**实现层**深路径（`base/storage/<impl>`）——那才是"改内部实现打爆外部"的真风险。
  规则 8 即守此，把原注释级红线变机器红线。
- **TD-03-5 改判**：从「待还·绕行」→「**已裁定：契约边界，非债**」。理由=强行统一改动半径 22 测试、
  收益 0，属"为一致性而一致性"（§零 拒绝）。

**`check:upload-dirs` —— 双白名单对账（TD-12-4）**：
- 前端 `UPLOAD_DIRS` 顶层根集 vs 后端 `UPLOAD_ROOT_ALLOW`：**后端为真源**，前端须一致。
- 静态读取两端常量做集合对账，**不引入运行期跨端依赖**（前端不 import 后端）。
- 带解析器自检 fail-loud（解析为空 → 报错而非假绿，教训来自 TD-02-9）。
