## 五、追加裁定：闸时机合并（单一验证阶段）

> 触发：用户在我登记「CI 只接 1 道闸、其余闸仍只在本机 husky」后裁定：**「提交和推送这两个我可以看成一个。只要最后推送不出去…就可以了，不需要反反复复把这两个东西一起跑。」**

**做法**（七步法 Step 3 定位 = 收敛到单一执行点）：

| 面 | 改前 | 改后 |
| - | - | - |
| 阶段 | `build` / **`commit`(4 道)** / **`push`(3 道)** / `health` | `build` / **`push`(7 道)** / `health` |
| 本地 pre-commit | lint-staged + **`check:commit`(闸)** + 改动测试 + SSR 快守卫 | lint-staged + 改动测试 + SSR 快守卫（**不再跑闸**） |
| 本地 pre-push | `lint` + `check:push`(3 道) | `lint` + `check:push`(**7 道**) |
| CI | `type-check` 步（**零闸**） | **`npm run check:push`(7 道)** + `test:coverage` |
| `pretest` / `check:commit` | 存在（`npm test` 附带跑闸） | **删除**（避免第二执行点） |

- 闸清单唯一真源仍是 `scripts/gates.manifest.json`；`gates-run.mjs` 自检 phase 集合改为 `build/push/health`。
- **净效果**：一次「提交 → 推送」只等**一轮**闸；CI 与本地跑的是**同一份清单、各一次**（不重复）。
- **取舍（诚实标注）**：commit 阶段不再拦类型/卫生问题 —— 最晚在 `push` 被拦（用户明确接受："提交不了或推不出去就行"）。

**验证**：`npm run check:gates` → push 层 **7 道**；`npm run check:push` → **7 道全绿**（type-check / any / catch / events / strict-src / arch / dead-code）；`pretest`/`check:commit` 已从 package.json 移除（脚本自检查无残留引用）。
