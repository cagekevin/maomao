## 四、施工（借债还债）

### ① 收口 `getElementPlaybackRate`（TD-22-14 母体）

三行判据原先在 4 处手写 —— 它们**必须**给出同一个数，否则"画面按一个倍率、声音按另一个"即静默失步：

```ts
'playbackRate' in element && typeof element.playbackRate === 'number' ? element.playbackRate : 1
```
落点：`use-element-resize`（拖拽边界）· `split-elements`（切开换算）· `getElementSourceDuration`（源总长）·
`lib/media/audio.ts`（混音取源）。→ 收成 `element-utils.getElementPlaybackRate`（**4 → 1**）。

**刻意不做**：不在读取侧夹进 `MIN/MAX_PLAYBACK_RATE` —— 取值域校验属 **UI 写入侧**
（`speed-utils.clampPlaybackRate`）；读取侧若也夹，会把"存档里的越界值"悄悄改成别的倍率。
渲染与混音应当**如实按存档值播**（已写成行为锁）。

### ② 音频调度的源偏移接到唯一时间域原语（TD-22-14 母体）

```ts
// 旧：手写同一式子 —— 改一处忘另一处 = 变速下声画失步
const sourceOffset = clip.trimStart + elapsed * rate;
// 新：直接调画面取帧用的那个原语
const sourceOffset = getVisualSourceTime({ timelineTime: Math.max(clip.startTime, time), ... });
```

混音（`mixAudioChannels`）是**样本域**（`sourceStep` 逐样本增量），刻意**不**改成逐样本调函数
（热路径 O(n) → O(n·常数)），改为**注释互指** + 断言"两边描述的是同一条源时间线"。

### ③ 三类守卫（`tests/unit/veRenderTreeContract.test.ts`，8 例）

| 守卫 | 断言 |

→ 教训：**工具输出与文档记载不一致时，先怀疑记载**（工具会跑，文档不会）。
