### 一.3 选中态的唯一载体 = 富文本胶囊

**裁决**：唯一真源是 `prompt` 正文里的胶囊；**不设** `data.creativePresets[slot]` 那套 slot 结构（那是 AIFISHER 的，与「胶囊即正文」重复）。

| 项 | 定义 | 锚点 | 状态 | 验证 |
| --- | --- | --- | --- | --- |
| 胶囊序列化 | `@{cp_style-643:暖阳赛璐璐CG}` | `promptChips.ts:51` | 已有 | 复用现有正则，**零改动** |
| id 命名空间 | 用**下划线前缀**而非冒号 | 本文裁定 | — | 见下方「为什么不用冒号」 |
| 芯片渲染 | 走既有 `buildChipEl`，`kind='preset'` 新增一档 | `promptChips.ts:158` | 待建 | `tests/unit/prompt/chips.test.ts`（已有文件，追加用例） |
| 字典 | `data.creativePresets: Record<id, {kind,name,prompt}>` | `nodeDataSchema.ts:93` | 待建 | `npm run check:node-data` |

**为什么 id 用 `cp_` 前缀而不是 `style:643`**
现有正则 group1 是 `[^:]+`（**禁冒号**）：`promptChips.ts:51`。若把命名空间写成 `style:643`，会被解析成 `id='style'` + `label='643:暖阳…'`，显示即错。改正则 = 动字符串契约（序列化格式），要同步 `serializeDOM` / `renderPromptToNodes` / `resolvePromptChips` 三处并重跑旧数据回归。改用下划线前缀，**三处零改动**。

**字典与胶囊的一致性（唯一易漏点）**

> 风险：用户删掉胶囊后，字典里留下孤儿条目并随快照落盘。

| 契约 | 内容 | 落点 | 状态 |
| --- | --- | --- | --- |
| `syncCreativePresets(prompt, dict)` | 扫 `prompt` 里 `cp_*` id 集合，返回只含被引用项的字典（**纯函数**） | `creativePresets.ts` | 待建 |
| 调用时机 | 任何写 `prompt` 的路径（节点 patchData / Agent `update_node_any_field`） | 节点内 + 快照裁剪 | 待建 |

**验证**：`tests/unit/creative/gc.test.ts`（待建）—— 输入「删胶囊后的 prompt + 旧字典」，断言输出键数 = 胶囊数。

### 一.4 合成原语

```
resolvePromptChips(rawPrompt, refImages, refTexts, presets?) → { text, refImages }
```

| 项 | 定义 | 锚点 | 状态 |
| --- | --- | --- | --- |
| 签名扩展 | 第 4 参 `presets`（`Record<id, {prompt}>`），缺省 = 行为与今天完全一致 | `promptChips.ts:249` | 已有 |
| 新分支 | id 以 `cp_` 开头 → 命中 presets → 替换为该条 `prompt`；未命中 → **替换为空** | `promptChips.ts:262` | 待建 |
| 顺序 | **胶囊在正文中的位置决定片段插入位置**（不同于 AIFISHER 的「统一拼在尾部」） | 本文裁定 | — |
| 与摄影参数的关系 | `applyCameraSettingsToPrompt` 仍**最后追加**，现行为不变 | `cameraPrompt.ts:71` | 已有 |

**为什么不照抄 AIFISHER 的 `composeCreativePrompt`**
它的顺序是「所有 prefix → 正文 → 所有片段」（`CreativeLibrary.tsx` 侧），因为它的 tag 不在正文里、只存在于 `creativePresets`。我们的胶囊在正文里，若再统一拼尾，用户把胶囊挪到句首就无效——**位置即语义**，这是选胶囊方案的必然结果。

**验证**：`tests/unit/prompt/chips.test.ts` 追加 3 例：① 命中替换 ② 未命中置空 ③ 三参调用（老签名）输出逐字节不变。

### 二.4 素材分发裁决（待 G0 定，数据已备）

**实测体积（2026-09-15）**

| 目录 | 文件数 | 体积 |
| --- | --- | --- |
| `creative-presets/`（风格 217 + 滤镜 17 图 + 运镜 51 封面 + 51 mp4） | 336 | **75.8 MB** |
| `mj-styles/`（493 组 × preview + thumb） | 986 | **31.2 MB** |
| 合计 | 1322 | **107.0 MB** |

**运行形态约束**：本仓是 Chrome 扩展（MV3，`public/manifest.json`），体积直接影响安装与更新体感。

| 路线 | 做法 | 代价 |
| --- | --- | --- |
| **A 全量打包** | 107 MB 进 `public/` | 扩展包体翻一个量级；商店审核与更新变慢 |
| **B 目录打包 + 预览远程** | 两个 JSON（几百 KB）打包；图/视频走 CDN + 本地缓存 | 需改 `manifest` `host_permissions` + CSP（`img-src` / `media-src` 放行）；离线不可用 |
| **C 目录 + 样图打包，其余懒加载** | 每类带少量样图（mockup 现在就是这个：223 文件 / 16.9 MB） | 实现最复杂，但首屏与离线都兼顾 |

**倾向 C**，判定阈值：若 `.mp4` 与 webp 压缩后整体 < 40 MB 则改用 A。**待补**：`creative-presets/` 里 mp4 单独占多少（本轮未测）。
