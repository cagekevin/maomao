交互 点「指令」→ 面板贴着按钮向上弹（388px，不遮画布）→ 切 tab 找 → 点图卡即追加。 追加到提示词末尾并自动补「，」，追加后输入框末尾高亮新片段——看一眼就知道加进去了，不需要 toast。
没有 footer 「点一下 = 追加并关闭」是看一眼就懂的事，写下来就是常驻噪音；「管理指令」入口也删了 —— 管理动作全部落在这一个面板里（hover 图卡出 ✎ = 编辑 / tab 行右上角 ＋ = 新建），不需要第三个去处。
滚动 格子数不封顶，超出就滚；不做截断。滚动对规模不敏感 —— 攒到几百条，操作方式也不变。 排序靠行为：每次追加都是一次投票，用得多的自然浮在前面，不需要拖拽、不需要整理。
tab = 分类 分类用户自己建，一条可打多个，打了「风格 + 人像」就在两个 tab 里都出现。 「常用」是虚拟分类（最近使用），「全部」不过滤。

技术附录 这一屏是落地用的技术链路，不是界面稿。 结论：不用引入第三方图床。现成的 filesApi.uploadFileToLocal（POST /api/files/upload）就是本机图床； 跨设备那份靠 极小内联缩略图 走已有 cloudSync。两级加起来覆盖全部场景，新增依赖 = 0。

落地口径（改代码时照这个来）
1. 数据形状：Preset 加 3 个可选字段 —— tags: string[]（分类名数组，至少一个、可多个）、thumbUrl（本机 256px）、thumbInline（96px base64）。 老的 type 字段（text/image/video）不再作为界面字段暴露，只做隐式过滤（生图节点只显示通用 + 生图类）—— 它一旦出现在表单里，用户就会亲手造出「在某些节点里找不到的指令」。 新指令一律不写 type（createPreset() 保持默认 'all'），这条过滤便只作用在老数据上、随时间自然收敛； 老数据不动，缺字段 = 降级为「无图 + 未分类」，无需迁移。
2. 存储键：不新增键，只用 yimao_preset_prompts。分类不单独存 —— tab 列表由所有指令的 tags 求并集派生（deriveTags(presets) 纯函数，放 promptManager.ts）。 没有「空分类」「分类排序」这些只在独立表里才需要的概念。改名 = 遍历 presets 替换 tags 中的该名字（几十条，成本可忽略）。
3. 排序：不存顺序字段。默认视图按最近使用排 —— 复用现成的 recordRecent(id)（promptManager.ts:113，每次追加时已经写了），追加即排序。 老字段 type 保留但只用于隐式过滤。
4. 落盘目录：需在 base/utils/uploadDirs.ts 中央表登记 presets（禁止散写字面量目录名），上传走 filesApi.uploadFileToLocal 唯一入口。
5. 组件：PromptLibraryButton 由「弹全屏」改为「弹 388px 九宫格 popover」，popover 内原地切换浏览态 / 编辑态 （一个组件两种状态，不新建页面、不走 portal、不套 FullscreenShell）。 PromptLibrary.tsx 不删文件，但去掉全屏外壳与遮罩，整体降级为编辑态的表单内容。不做只读模式。
6. 交互语义：点图卡 = onAppend(prompt) + 立即 onClose()（一次只加一条，不做多选、不做「已选中」态）；追加到末尾 + 自动补「，」，追加后高亮新片段。 点 ✎ = 切编辑态（不追加）；点 tab 行右端 ＋ = 新建。删除只在编辑态，不在九宫格热区里。 去掉 onUse（新建节点）分支。
7. 相对 v1 删掉的东西（都是判据「不属于三者、也不服务于三者」的产出）： tab 数字徽标、ⓘ 常显角标、整个 footer（引导文案 + Esc 提示 + 「管理指令」入口）、拖拽排序 grip、 备注字段、适用节点字段、「从画布取 / 从素材库选」两个快捷图源、三行上传说明、独立的标签管理弹窗、 「取消」按钮（即时生效模型下语义矛盾）、「改动即时生效」文案。
