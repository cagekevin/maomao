★ 盒子是天然的多图入口
展开态下：已选 N 张 → 直接作为 N 个图层；未选则全部送入。
入口定在哪：图标用 lucide Layers，紧跟「标记」——两者都是「打开全屏编辑器」的重操作，同类相邻； 而压缩/超分是一键完成的结果型操作，放后面。
为什么不动按钮形态：hover 栏是 rounded-full 胶囊 + 26×24 图标位（规范 §〇）。新增按钮必须同尺寸同形态， 不能为了「突出新功能」塞一个带文字的宽按钮进去——那会让这一栏从「一排图标」变成「不整齐的一排」。
可发现性怎么解决：首次上线可在图标右上角加一个 --accent 小圆点（3px），点过一次后落 localStorage 消失； 不做强制性的「新功能」气泡提示。

★ 画布尺寸不给「画质档位」（外包有 720p/1K/2K/4K，本仓库砍掉）： 那个档位在外包里只做一件事——决定画布长边像素数。它存在的前提是「合成结果要送进生图模型，尺寸得和模型输入对齐」， 本仓库没这个环节。而且它把视频单位（720p）和图片单位（1K/2K/4K）混在一个枚举里，本身就不自洽。
改为：画布尺寸 默认 = 主图原始分辨率（第一张进来的图，不放大也不缩小，避免 512 的图被吹成 2K 假高清、 或 4096 的图被压到 2K 掉细节）；改比例时保持长边像素守恒；想要精确尺寸直接手填右下角宽高； 长边超 4096 由状态条提示——上限是系统保护，不是用户选项。

★ 画布属性全在一处：比例、宽高、背景是同一个东西的三个面，合成一块放在右栏最顶—— 先定画布再摆图层，且不用滚到底才找到。外包把「比例+画质」放底部命令栏、「宽高+背景」放右栏末尾， 同一个属性拆成两处，改个画布要两头看。

布局为什么是这样：外部包是「中央画布 + 底部命令栏 + 右侧属性面板」。 本仓库 ImageEditor 重构后统一为 header(Tab/标题) → 上下文工具条 → 画布 → 底部状态条， 所以这里把外部包的底部命令栏上提为工具条，与「涂鸦/裁剪/扩图」编辑器完全同构，不再出现第二套骨架。
★ 左栏是本仓库特有的适配：外部包把「取图」塞在底部工具栏的下拉里（画布上所有 ai-image 节点）。 但本项目的数据流是 连线 + 图片盒子（useConnectedInputs / ImageBoxNode.images）， 取图是高频动作，值得占一条常驻左栏；同时它也是「多图编辑」这个名字的由来——图从哪来，是这个功能的入口，不是附属功能。
不做的部分：外部包的「识别主体（抠图）」依赖 Tauri + ONNX（subjectMatting / rmbg-1.4.onnx）， 本仓库没有这套服务，P2 暂不接入；右栏「调整（调色）」为 P1，可随首版一起但非阻塞。
砍掉「黑白 / 怀旧 / 反相」三个一键效果：它们是手机修图 App 的滤镜，在这里是冗余自由度—— 黑白用饱和度拉到 -2 即可，色调由色相滑杆负责，怀旧在 AI 生图流程里几乎无人用。 留着只是给面板加一行永远不会点的按钮。

我修正了自己一处错放：第一版把「圆角」塞进了常驻的变换数值网格，它在选中图片时是死控件——已移进「形状」区。

外部包 → 本仓库 落地映射
入口：hover 栏 compose 按钮 → useImageHoverActions.imageButtons 加 1 项（AssetNode / ImageGenerate 同时生效）
取图：画布上所有 ai-image 节点下拉 → useConnectedInputs + ImageBoxNode.images + 上传
保存：saveDataUrlToProjectData(Tauri) → saveInlineToLocal(本仓库 filesApi)
结果：loading 节点回填 → spawn 新 imageNode + 自动连线
状态：useAppStore(zustand) → 编辑器内部自持（不进全局 store，关闭即销毁）
依赖风险：外部包基于 konva / react-konva，本仓库无此依赖
渲染层怎么选（这是唯一需要拍板的）：
方案 A · 引入 konva + react-konva：能力最全（自由变换、滤镜缓存、吸附、Transformer 全白送），外部包改造量最小； 代价是新增约 150KB 运行时依赖，且 Konva 的图层模型要在本仓库节点体系里再包一层。
方案 B · 沿用本仓库既有 canvas 直写：ImageEditor / OverlayEditor 已经是原生 canvas + DOM 图层， 「多图编辑」本质就是把 OverlayEditor 的单图层扩成多图层——变换框、拖拽、层级、导出都可复用， 新增的只有「多图层列表 + 吸附 + 图层变换矩阵」。推荐先按 B 出 MVP（多图摆放/缩放/层级/透明底导出）， 若后续要做实时调色滤镜与大量图层再评估 A。
不做的事：不新增全局 store slice、不接 ONNX 抠图、不提供「覆盖原节点」选项（规范 §3.2 已定死：生成新内容 = 新建节点）。
