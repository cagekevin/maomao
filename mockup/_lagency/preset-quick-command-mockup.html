删除标签不会删指令，只把该标签从指令上摘掉。 标签来自指令本身 —— 建标签在指令表单的 chips 里点「＋ 新建标签」，所以这里没有「添加」也没有「排序」。
标签管理 只做两件事：改名 / 删除。新建标签在指令表单的 chips 里点「＋ 新建标签」—— 那里建的标签必然有指令用。
为什么是标签不是分类 分类逼你给每条指令选唯一归属（「胶片颗粒」算风格还是人像？）；标签允许同时属于多个， 前端点哪个 tab 就显示含该标签的指令，不用做 AND/OR 选择器 —— 交互成本和多归属兼得。
图床 结论：不用引入第三方图床。现成的 filesApi.uploadFileToLocal（POST /api/files/upload）就是本机图床； 跨设备那份靠 极小内联缩略图 走已有 cloudSync。两级加起来覆盖全部场景，新增依赖 = 0。

落地口径（改代码时照这个来）
1. 数据形状：Preset 加 4 个可选字段 —— tags: string[]（标签名数组，可多个）、desc（备注/tooltip）、thumbUrl（本机 256px）、thumbInline（96px base64）。老的 type 字段（text/image/video）继续保留，用于按节点类型过滤（生图节点只显示生图+通用类）。缺字段 = 降级为「无图 + 未打标签」，无需迁移。
2. 存储键：不新增键，只用 yimao_preset_prompts。标签不单独存 —— 面板的 tab 列表由所有指令的 tags 求并集派生（deriveTags(presets) 纯函数，放 promptManager.ts）： 没有「空标签」「标签排序」这些只在独立表里才需要的概念，也就不用为它登记新键、不用管它和指令的同步。 改名 = 遍历 presets 替换 tags 中的该名字；删除 = 遍历移除（几十条，成本可忽略）。
3. 落盘目录：需在 base/utils/uploadDirs.ts 中央表登记 presets（禁止散写字面量目录名），上传走 filesApi.uploadFileToLocal 唯一入口。
4. 组件：PromptLibraryButton 由「弹全屏」改为「弹 388px 九宫格 popover」；PromptLibrary.tsx 全屏弹窗不删，改造为编辑界面（传图 / 改标签 / 改内容）。 只有两个界面：九宫格 + 编辑表单；不做只读模式 —— 九宫格角标 ⓘ 与「管理指令」都打开同一个编辑表单，字段始终可编辑，新建只是传空初始值。
5. 追加语义：点击图卡 = onAppend(prompt) + 立即 onClose()（一次只加一条，不做多选、不做「已选中」态）；追加到末尾 + 自动补「，」，追加后输入框末尾高亮新片段。 onAppend 各节点现成传入（ImageGenerate / VideoGenerate / TextGenerate 已有），去掉 onUse（新建节点）分支。
