多图编辑（ImageComposer）· 与本仓库匹配的 Mockup

参考 ai-canvas-composer（AI-Canvas-tauri v0.9.5 抽取包：图像节点 hover 栏 compose 按钮 → 全屏多图层合成器）， 按本仓库的 NODE-DESIGN-SPEC §〇 视觉 DNA、useImageHoverActions 入口机制、 连线 / 图片盒子数据流重做外形。 落点：hover 栏加一个「多图编辑」按钮 → 打开全屏多图层编辑器 → 合成为透明 PNG → spawn 新 imageNode 并自动连线（规范 §3.2「生成新内容」）。
v2 改的是空间排布：左栏 = 对象侧（我要操作谁），右栏 = 属性侧（把它改成啥），并按使用频率排序； 工具条归一为「纯工具」；高频操作长到画布上的选中物身上。功能一个没加，入口砍掉 6 个。

★ 盒子是天然的多图入口
展开态下：已选 N 张 → 直接作为 N 个图层；未选则全部送入。
入口定在哪：图标用 lucide Layers，紧跟「标记」——两者都是「打开全屏编辑器」的重操作，同类相邻； 而压缩/超分是一键完成的结果型操作，放后面。
为什么不动按钮形态：hover 栏是 rounded-full 胶囊 + 26×24 图标位（规范 §〇）。新增按钮必须同尺寸同形态， 不能为了「突出新功能」塞一个带文字的宽按钮进去——那会让这一栏从「一排图标」变成「不整齐的一排」。
可发现性怎么解决：首次上线可在图标右上角加一个 --accent 小圆点（3px），点过一次后落 localStorage 消失； 不做强制性的「新功能」气泡提示。

★ v2 改的是空间排布，功能一个没加。核心一句：左栏回答「我在操作谁」，右栏回答「把它改成啥」—— 导航（选谁）和修改（改啥）必须分开，且导航不能随选中变化、不能被滚走。

左栏拆成两段：上段「图层」常驻（max-height:44%，超出自身滚动），下段「素材来源」可滚。 这两段是同一个闭环的两面：下段点 + → 素材移入上段成为图层；上段删图层 → 素材回到下段可选。 v1 用 opacity:.45 表示「已加入」，读起来像禁用；改成物理上换位置就顺了。 图层列表原先夹在右栏中部，导致切一次图层要滚两趟（滚到图层区选中 → 滚回上面改变换），这是 v1 最不顺手的一处。
工具条归一为「纯工具」：文字 / 形状本质是绘制工具（在画布上画出来），归进工具胶囊； 上传是文件导入，下沉到左栏（那里本来就有上传按钮）——v1 里它俩并列在工具条上， 空间位置就预测不了功能了。工具条上只剩「当前用什么工具 + 这个工具的参数」，与 ImageEditor 涂鸦 Tab 同构。
右栏按使用频率倒序，不按数据层级：v1 的 画布 → 图层 → 变换 → 外观 → 调整 是数据结构顺序 （从大到小，工程师直觉），但用户频率恰好是倒过来的——进来就在摆位置，改画布通常只有开头一次。 改后 变换 → 外观 → 调整 → 画布(收起)，实测右栏总高从 ≈924px 降到 ≈547px， 而可用高度是 648px —— 首次实现一屏不滚动，这是本次改动最大的收益。
画布上补「直接操作」：8 柄（v1 只有 4 个角柄，无法单向拉伸）、拖动时跟随的 size-tag、选中框上的就近「上移 / 下移 / 删除」——手不用离开画布。 画布右下角那条常驻教学文本删了（那是新手 App 的标志），快捷键改由状态条常驻。
层序只留一条主路径（v3 收口）：v2 里「改图层顺序」有三套入口——左栏列表旁的 4 个箭头按钮、 画布选中框上的上移/下移、以及 ⌘] / ⌘[ 快捷键。同一件事三条路径，用户要先选一条再记住它，认知成本反而更高。 v3 删掉左栏那 4 个箭头按钮，保留两条互补路径：画布上就近操作（手不离画布，处理「这张压住那张」的即时调整） + 列表拖拽行换序（处理「背景 → 中景 → 前景」的长距离大挪动，也是图层列表的标配手势）。 左栏 layer-tools 因此只剩「上传图片为图层」。
「适配画布」不再复活（v3 收口）：v2 已把它从工具条删除（列为重复入口第 1 项）， 但画布左下角浮层里又画了一遍——同一个功能换了个位置又出现，等于没砍。 v3 从浮层中一并删除，视图控制只留「缩小 / 34% / 放大」； 需要适配时走 ⌘0（状态条常驻快捷键列表已列）。
修饰键定死三个且互不冲突：空格=平移、⌘=临时移动、Alt=从中心。 v1 的「⌘ 拖旋转」已被删——⌘ 在画布编辑里的通用语义是「临时切换 / 加选」，用它做旋转既误触又和变换框上的 rot 手柄重复。
数值统一到画布坐标系：X/Y 从 96/86 改为 279/250（96px ÷ 0.344），缩放比 68% 改为 34%（660 ÷ 1920）， 文字层框宽 1152 改为 727（250px ÷ 0.344）。v1 把「屏幕像素」和「画布像素」写在同一格里，照着填会错位。
砍掉的 7 个重复入口：适配画布（工具条 + v3 补删画布浮层那份）、上传（工具条）、header 的 ✕（与「取消」同义）、 header 标题里的动态元数据（与画板标签、状态条三处重复）、右栏的「复制 / 删除图层」整行（图层行内已有 ✕、状态条已有 ⌘D）、 「明度」滑杆（与亮度语义重叠）。
状态条换血：删掉「撤销栈 12 步」（用户只关心能不能撤）和「显存 84/256 MiB」 （方案 B 是 canvas 直写，没有显存概念，是假信息）。换成随操作变化的：选中图层 + 尺寸、光标坐标、缩放比。
吸附整个砍掉：原设计是「常驻的洋红画布中线 + 图层中线」。它既不是 PS 的 Guides（用户从标尺拖出、青色常驻、可锁可清）， 也不是 Smart Guides（仅拖动时出现、洋红、带 24 px 距离数值与等距标记）——是个四不像。 而且它只有「对画布中线」这一档目标，把最有价值的对象↔对象对齐和等距分布提示漏掉了。 要做就得两套参考线 + ⌘ 临时忽略 + 容差一起上，那是一个独立模块； MVP 阶段手动摆放 + 数值输入已经够用，不做，不留半成品。

画布上的两个交互（外包有、我第一版漏了）：文字双击就地编辑、图片拖入即加图层。 这两个都是「作用在画布上」而不是「作用在面板上」，必须在画布区展示，不能塞进右栏。
图层行补的三件事：删除、双击改名、拖拽换序——外部包都有，属于图层列表的标配操作。 也正因为列表本身支持拖拽换序，列表旁不再放一套箭头按钮（v3 已删）：换序走「拖行」或「画布上就近按钮」， 两条路径各管一种场景，不再有第三、第四条。「复制 / 删除」不再单列一行：图层行内有删除，复制走 ⌘D。

外部包 → 本仓库 落地映射
入口：hover 栏 compose 按钮 → useImageHoverActions.imageButtons 加 1 项（AssetNode / ImageGenerate 同时生效）
取图：画布上所有 ai-image 节点下拉 → useConnectedInputs + ImageBoxNode.images + 上传
保存：saveDataUrlToProjectData(Tauri) → saveInlineToLocal(本仓库 filesApi)
结果：loading 节点回填 → spawn 新 imageNode + 自动连线
状态：useAppStore(zustand) → 编辑器内部自持（不进全局 store，关闭即销毁）
依赖风险：外部包基于 konva / react-konva，本仓库无此依赖
渲染层怎么选（这是唯一需要拍板的）：
方案 A · 引入 konva + react-konva：能力最全（自由变换、滤镜缓存、Transformer 全白送），外部包改造量最小； 代价是新增约 150KB 运行时依赖，且 Konva 的图层模型要在本仓库节点体系里再包一层。
方案 B · 沿用本仓库既有 canvas 直写：ImageEditor / OverlayEditor 已经是原生 canvas + DOM 图层， 「多图编辑」本质就是把 OverlayEditor 的单图层扩成多图层——变换框、拖拽、层级、导出都可复用， 新增的只有「多图层列表 + 图层变换矩阵」。推荐先按 B 出 MVP（多图摆放/缩放/层级/透明底导出）， 若后续要做实时调色滤镜与大量图层再评估 A。
不做的事：不新增全局 store slice、不接 ONNX 抠图、不提供「覆盖原节点」选项（规范 §3.2 已定死：生成新内容 = 新建节点）。
