摄影参数

四项全「自动」= 不施加任何摄影参数，与从未打开过面板等价。

场景分层（自上而下 13 层，全部为纯填充，无滤镜）： 天空渐变 → 星点 → 落日+光晕 → 远山（鱼眼时换弧形） → 近山 → 城市剪影+窗光 → 地面/公路透视线 → 景深雾霭 → 光斑 → 拖影/光轨 → 残影 → 主体（坐姿橘猫：投影/尾/耳/头/腮/口鼻垫/虎斑/梨形身/胸白/前腿/眼/鼻/ω嘴/胡须/轮廓光） → 曝光/暗角/画框
四个下拉的选项文案与顺序按参考包 1:1 保留（焦距 8 档 / 快门 4 档 / 光圈 8 档 / 曝光 11 档）。 右上角「全部自动」= 一次性清空四档（onChange(undefined)），等价于从未打开过面板。 右侧是同一份精灵的 560px 大图——矢量的，放大不需要第二套资源。

预览是趋势示意，不是真实曝光计算：焦距只改主体大小（透视），光圈只改光斑/雾霭（景深）， 快门只改残影与拖影，曝光时间只改整体明暗。四者可叠加，互不换算。 每个实例只有 <use href="#cam-scene"> 一行 + 几个变量。
性能取舍（为什么值得改）： 原实现用 feGaussianBlur 做背景虚化 —— 每动一次下拉就要重算一遍高斯模糊，是这一屏最贵的开销， 且同屏多实例时是 N 份滤镜通道。现在全场景 0 个 filter：虚化改由 径向渐变光斑（自带柔边，比「硬边圆 + 模糊」更省也更好看）+ 雾霭叠加（低对比远景）+ 低饱和远山渐变 三件事共同表达；其余全是纯填充与描边。图元总量控制在 ~55 个，且只定义一次。
复用方式（推荐照抄）： ① 精灵 <symbol id="cam-scene"> 挂在应用根节点一次（同 icon sprite 的做法，React 里就是一个 <CameraPreviewSprite />，返回 null 之外的那份 defs）； ② 每个用到预览的地方只写 <svg class="cam-prev" style="--subj:…;--bk:…"><use href="#cam-scene"/></svg>； ③ 变体全部走 CSS 变量（--subj / --bk / --bkop / --haze / --dim / --bri）与 display 开关 （--macro-d / --fish-d / --motion-d / --trail-d …）——自定义属性会继承进 <use> 的影子树， 所以「一份定义、N 种状态」成立，改外观只改精灵一处。 ④ 万一目标环境对影子树变量支持有坑，兜底是把精灵内容直接内联渲染（变量与开关名不变，替换成本极低）。
刻意不做：真实曝光/景深计算（预览只表达趋势）、自定义焦距输入（只给 8 档预设）、 给光斑加逐帧动画（会持续占用合成，收益不抵开销）。
与现有能力的边界：本仓库已有 CameraStudioPanel（3D 摄影棚：球面拖拽机位 + 打光）。 它和这里是两套独立功能：摄影棚改「机位与布光」并新建节点，本面板改「当前节点这一次的成像参数」， 因此按钮不进 hover 工具条，只落在展开面板的参数行。
