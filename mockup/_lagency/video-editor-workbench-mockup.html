M1 基座已落地（装配与试听：素材从画布点选入轨 / 播放出声 / 导出）。本图是 M2 工作台的第一张图。 按 docs/120 §0.8 的定论：M2 的真正定义是「画面」，不是「窗口」 —— M1 缺的正是画面（M1 没有监视器，只能盲剪），所以 M2 = 大监视器 + 检查器（能改的东西） + 精轨（叠加轨 / 文字轨）；基座收成时间轴，仍是同一份 tracks 的两个视图（不修改 M1 数据契约）。
本轮检查器范围（用户圈定的最基本件）： ① 文字 —— 描边（颜色 + 宽度）· 字号 · 字间距 · 颜色 · 位置；② 贴图 / 图片 —— 大小 · 位置； ③ 透明度（文字 / 贴图 / 视频通用）。旋转顺带进变换组（同一份数据，不加面板成本）。
全页四屏：① 主形态（监视器 + 文字检查器 + 四轨时间轴）· ② 检查器三面板（贴图 / 视频片段 / 描边交互细节）· ③ 画布直接操作（所见即所得）· ④ 数据契约与范围表。
两条纪律不改：素材仍从画布来（贴图入口 = 画布图片节点清单，守 C11）； 预览与导出走同一条 renderFrameAt（C8）—— 描边 / 透明度在导出里长什么样，预览里就是什么样。

新主形态 —— 点基座「展开工作台」后的样子。 抬头左 = 收起工作台（回基座，工程不丢）；右 = 导出 split button（沿用 M1 定稿，导出不被工作台扣为人质）。 中间 = 监视器（画面来源 / scrub / 走带三层，沿用旧 mockup 审计定稿）；右栏 = 检查器（属性 / 文字 / 转场）； 底部 = 四轨时间轴（V1 主视频 · V2 叠加 · T1 文字 · A1 音频，轨道头沿用 C7.4 图标网格）。
本屏定格在：标题字幕选中 → 检查器自动切到「文字」面板 —— 选中什么，检查器就给什么。

为什么检查器三 Tab 是「属性 / 文字 / 转场」：它按选中的东西是什么分，不按「功能模块」分 —— 选中视频或贴图 → 「属性」（变换 / 取景 / 音量）；选中文字 → 「文字」（内容 / 样式 / 描边）；点时间轴接缝 → 「转场」。 没有选中时 Tab 显示但面板是空态提示（「选中一个片段开始编辑」），不预填第一个片段的属性（旧 mockup 审计结论：那会误导「改了只影响一个」）。
「+」菜单里贴图为什么还是从画布来：C11 的「素材从画布来」不随 M2 改 —— 贴图的来源就是画布上的图片节点清单， 点选后落叠加轨（而不是 M1 的主视频轨）。文字是唯一凭空创建的素材（画面上本来就没有的东西），默认 3s、落在播放头处。
沿用检查器的另外三态。 主屏画的是「文字片段选中」；这一屏补齐：选中贴图（属性面板）、选中视频片段（属性面板 · 取景解决黑边 C12.2）、 以及描边开关的收合交互（关掉时整组只剩一行，不常驻占一屏）。

白字 + 黑描边是视频字幕的默认样式（任何底色上都读得清）—— 新建文字自带这组值， 用户第一次改的往往是颜色而不是「要不要描边」。
控件口径三条： ① 大小用「缩放百分比」不用宽高两格 —— 等比是默认语义，拉伸场景只属于视频 fit； ② 位置用画布归一化坐标（X/Y），与工程分辨率解耦 —— 改工程比例时贴图位置不漂移； ③ 不透明度三态共用一条滑杆（0 = 全隐，等同于隐藏该片段），它是变换的一部分，不单独立「效果」组。
新画布直接操作 —— 检查器数值与画面手柄双向同步。 「改位置 / 改大小」的最高频路径是直接在画面上拖，检查器是精调与精确数值的第二路径 —— 两者改的是同一个 clip.transform，不存在「两处不同步」。 与旧 mockup 舞台 2 的定稿一致：变换也能在画面上直接做，数值与画布双向同步。

拖动 = 位置 · 角柄 = 大小 · 顶部圆柄 = 旋转 · 双击 = 改内容
角柄拖大 = 字号变大：框高直接映射字号（22px → 拖到 44px 框即 44 号）， 检查器「字号」数值跟着走 —— 用户不需要理解「缩放 vs 字号」两个概念。
双击进入编辑：光标落在文字上，输入即改「文字内容」； Esc / 点空白退出。不在画面上放常驻输入框。
拖动 = 位置 · 角柄 = 大小 · 不透明度在检查器
贴图无「字号」概念：角柄映射的是缩放（等比），与检查器「大小 100%」同源 —— 同一套手柄，文字映射字号、图片映射缩放，交互手感染不到差异。
拖出画框不裁剪：贴图允许停在画框外（半出画是常见构图）， 选中时画框外部分降透明度提示，导出自然裁掉。
为什么「旋转」顺手进了变换组而不单独立项：旋转柄已经在变换框上（kit 的 .rot）， 数据上与位置 / 大小同属一份 transform；不给它一个检查器行，用户就得用柄凭手感转 —— 半行成本换精确数值，值。 描边没有画布手柄：它是「样式」不是「几何」，画面上没有自然的拖拽隐喻 —— 一律在检查器里改（这也是它被圈定为核心需求却没有画布交互的原因）。
数据契约对齐 —— 每个检查器控件落到哪份工程数据（M1 留的 unknown 字段在 M2 收窄，只改类型、无数据迁移）
能力 入口 数据落点（core/types.ts） 说明
描边（文字） 文字 Tab · 描边组（开关 / 宽度 / 颜色 / 预设） clip.textStyle.stroke = {enabled, width, color} M2 新增字段。白字黑边为新建文字的默认值；预览与导出走同一条 renderFrameAt（C8），描边所见即所得
字号 / 颜色 / 字间距 / 对齐 文字 Tab · 样式组 clip.textStyle = {content, font, size, color, letterSpacing, align} 字号同时被画布角柄映射（框高 = 字号）；行高暂不暴露（用户未圈定，需要时加一行即可）
大小 / 位置 / 旋转 / 透明度 画布直接操作 + 属性 / 文字 Tab · 变换组 clip.transform = {scale, x, y, rotation, opacity}（M1 存的 unknown 字段，M2 收窄为该形状） 文字 / 贴图 / 视频三态共用同一份形状；预览用 CSS transform 叠加，导出走 computeDrawRect 同源换算（C8.1）
取景（黑边） 属性 Tab · 取景（适应 / 裁满 / 拉伸） clip.transform.fit = 'contain' | 'cover' | 'stretch' C12.2 的 M2 解；默认 contain（与 M1 行为一致），改比例后的黑边用「裁满」吃掉
贴图 时间轴「+ ▾」→ 画布图片节点清单 kind:'image' 片段 → 叠加轨（自由时间位置，不磁吸） 来源仍是画布节点（C11 / C3：URL 走 resolveClipSource 唯一出口）；M1 的「图片入主视频轨」规则不变，叠加轨是显式动作
文字 时间轴「+ ▾」→ 文字（或文字 Tab 空态按钮） kind:'text' 片段 → 文字轨（紧凑轨 26px） 唯一凭空创建的素材；新建即选中（直接开始打字），默认 3s、时长在轨道上拖，不在面板里填秒数
轨道头三态 沿用 C7.4 图标网格（锁 / 眼 / 喇叭） track.locked / hidden / muted（M1 已有） 叠加轨 / 文字轨同样吃三态；「锁定轨拒绝编辑变换」由 isClipLocked 统一判（C7.3）
历史栈 — 整份 tracks 快照（C6 沿用） 拖动变换 = begin() 于 pointerdown、end() 于 pointerup —— 一次拖动只落一张快照，不炸栈
本轮不做（有位置，后补不返工）： 文字阴影 / 背景框 / 气泡样式 · 入场出场动画 · 关键帧（位置 / 透明度随时间变化）· 音量包络 · 变速 · 滤镜调色 · 多选批量变换。
为什么这些不做也不堵路：它们全是「往 textStyle / transform / clip 上加字段」或「加面板分区」， 不动轨道结构与渲染管线 —— 检查器的 Tab 骨架（属性 / 文字 / 转场）和「选中什么给什么」的规则先立住，后续是填空不是翻修。
渲染红线：描边 / 透明度 / 叠加顺序在预览与导出必须是同一份代码（C8）—— 预览走 DOM/CSS 叠加、导出走 renderFrameAt，两者共享 computeDrawRect / evaluateTransitionAlpha 与本表的同一份数据，禁止出现「预览有描边、导出没有」。
